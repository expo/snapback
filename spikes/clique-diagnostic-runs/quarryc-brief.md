# Build `quarryc`: a Quarry → TypeScript front end for Snapback 2

You are working in a git worktree of the snapback repo (cwd). All work goes
under `snapback2/` (its own Cargo+Bun workspace; read `snapback2/AGENTS.md`
and `rules/RULES.md` first — file-size caps bind). Create branch
`s2/quarryc` and commit there. Do NOT push.

## Goal

A compiler `quarryc` that lets an app author its Snapback 2 backend in the
Quarry notation and emits the existing TypeScript authoring surface, so the
unchanged packaged toolchain (`snapback2 check/dev/test`, the client, the
React hooks) runs it. This enables an executed benchmark lane that authors
Quarry instead of TS. Quarry is a paper notation from LLP 0329.014.009/.010;
its reference is `spikes/quarry-clique-paper/spec/quarry-spec-v0.2.md`.
Idiomatic examples: `spikes/quarry-clique-paper/lanes/*/M*.md` and
`spikes/quarry-clique-paper/grading/` (read for shapes of real programs).

## Placement and CLI

- New package `snapback2/packages/quarry` (TypeScript, Bun; mirror the
  compiler package's conventions). Bin: `quarryc`.
- `quarryc <appdir>`: compiles every `<appdir>/snapback-quarry/*.q` to
  `<appdir>/snapback/<name>.q.ts` (generated files carry a header comment
  `// GENERATED by quarryc from snapback-quarry/<name>.q — do not edit`),
  leaving hand-written `.ts` files (seed.ts, tests/) alone. Exit nonzero
  with sited refusals (`<file>.q:<line>:<col> — message`) on any error.
- Every emitted statement carries a trailing `// q:<file>:<line>` comment
  so platform refusals can be mapped back by eye.

## Source language: Quarry v0.2 subset (the spec file is authoritative for
syntax; these are the pinned lowering semantics — all provisional, pending
v0.3, so record each in the README)

- EXCLUDED (refuse with a clear message): `maintain` declarations and
  `#agg[...]` reads (platform has no maintained aggregates); `use assets` /
  `asset` columns; effects; `merge(...)`; device/oblivious anything.
- Schema: `table name:` blocks → `table({ columns, indexes, rules })` with
  `t.*` column builders (`text <=N` → `t.text(N)`, `int` → `t.int()`,
  `time` → `t.time()`, `bool` → `t.bool()`, `enum(...)` → `t.enum([...])`,
  ref columns `col: otherTable` → `t.ref(otherTable)`, `?` suffix →
  `t.optional(...)`). `by a, b` (optionally named) → an index; `unique a, b`
  → a unique index. Every table gets its id implicitly (platform provides).
- Rules: lower `read/insert/update/delete` rule lines to the packaged
  `rule.*` combinators (`eq/ne/and/or/not/exists/viewerIs/field/literal/
  public/allow/deny`). REFUSE (sited) any rule expression the combinator
  surface cannot express (e.g. point-read field chains like
  `journals[r.journal].owner = viewer`) with a message telling the author
  to restructure (this matches what the TS surface can do — parity is the
  point, do not extend the platform).
- Channels: `channel name(args): publish <- ... / subscribe <- ... / ttl Ns`
  → the `channel({ args, publish, subscribe, ttlMs })` combinator, same
  rule-expression limits.
- Programs: `query name(args): ...` / `mutation name(args) -> T: ...` →
  `export const name = query({...}, ({ db, ctx, args }) => { ... })` /
  `mutation(...)`. Arg types like column types; `[users] <=50` →
  `t.list(t.ref(users), { max: 50 })`; `?` suffix → `t.optional`.
- Reads: `t[expr]` point get → `db.get(t, expr)`; unique-key get
  `t[a, b]` → `db.get(t.byUniqueIndexName, [a, b])`; `t[col = e]` names
  the index; `exists t[...]` → `db.exists(...)`. Range reads
  `t[prefix] first N` / `last N` (+ optional `by name`, `after e`,
  `before e`) → `db.scan(t.indexName, [prefix...], { order, take: N,
  after })` — `first` = asc, `last` = desc; lower `before e last N` as
  desc + `after: e` and document that choice. Index selection: match the
  keyed prefix against declared orderings; refuse ambiguity (name it).
- Auto-deref: a ref used as a row (`x.author.name`, shape on a ref) emits
  an explicit `db.get` chain with a local; absence propagates via
  generated null checks (`?.`-style). `??` → `??`.
- Absence semantics (pin): a comparison where either side is
  null/undefined is false; `x!` → bind + `db.require(x !== null, CODE)`
  (default code NOT_FOUND); `match t[k]: some x: ... / none: ...` →
  get + `if (x !== null) {...} else {...}`; a `match` in final position
  yields its arms' values via a result local.
- Shapes: `{ a, b: expr, * }` on a row → object literal (bare name =
  field of the focal row; `*` = spread of the row); on a page → a for-of
  loop building an array. Nested shapes re-focus `.` — compile with
  explicit locals.
- Writes: `+t { ... }` → `db.insert(t, { id: ctx.newId(), ... })`
  (returns the row object — bind a local with the inserted fields
  including id); `~t[k] { ... }` → `db.update`; `+~t[k] { ... }` →
  `db.upsert`; `-t[k]` → `db.delete`. `require cond else CODE` →
  `db.require(cond, "CODE")`.
- Clocks/builtins: `now` → `ctx.now()`, `commit` → `ctx.commitTime`,
  `viewer` → `ctx.viewer`, `new` → `ctx.newId()`; `sorted(a,b)`,
  `tokens(s)` → `mentionTokens`, `range`, `min`, `max` map to platform
  builtins. `walk t[seed] up .col depth N` → `recurse(seed, step,
  { depth: N, fanout: 1 })`.
- Control: `if/else`, `for x in <page|list>:` → for-of. No while, no
  recursion (refuse).

   shapes, rules via combinators) that compiles and checks green.

   rule the combinators can't express, `while`) each produce one clear,
   sited refusal.

   (generated TS + the template's seed/tests) passes `snapback2 check` and
   `snapback2 test` using the repo toolchain. Script it as a package test
   or a `scripts/` step and include its green output in your final report.
5. `snapback2/scripts/test.sh` stays green. Respect file-size caps (split
   the compiler if needed).
