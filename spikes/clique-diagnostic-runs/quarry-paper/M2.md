# Clique on Quarry — M2: Posts and the follow graph (text-only)

```schema
use identity                          -- (M1) email+password, sessions, logout revocation; provides `viewer`

table users:                          -- (M1, unchanged)
  displayName: text <=50
  handle: text <=20
  bio: text <=200 ?
  location: text <=50 ?
  link: text <=200 ?
  unique handle
  read r <- public
  insert r <- r.id = viewer
  update (old, next) <- old.id = viewer

table userStats:                      -- NEW (whole table): hand-kept counters (maintained aggregates are off-limits)
  user: users
  followers: int
  following: int
  unique user
  read r <- public                    -- declared disclosure: counts show on public profiles
  insert r <- r.user = viewer and r.followers = 0 and r.following = 0
  update (old, next) <- next.user = old.user
    and next.followers >= 0 and next.following >= 0
    -- any signed-in principal may bump counters: a follow must touch the OTHER
    -- user's row, and column-granular authorization is not expressible. The
    -- permissiveness is quarantined here — this table holds nothing but counters.

table posts:                          -- NEW (whole table)
  author: users
  body: text <=500
  parent: posts ?                     -- present = this post is a reply (replies never enter feeds)
  at: time
  by parent, at                       -- thread: direct replies, chronological
  read r <- public                    -- declared disclosure: posts and threads are world-readable
  insert r <- r.author = viewer
  -- immutable: no update rule (counters live in postStats), no delete in this product

table postStats:                      -- NEW (whole table): hand-kept counters, same quarantine pattern
  post: posts
  likes: int
  replies: int
  unique post
  read r <- public
  insert r <- r.post.author = viewer and r.likes = 0 and r.replies = 0
  update (old, next) <- next.post = old.post and next.likes >= 0 and next.replies >= 0

table follows:                        -- NEW (whole table)
  follower: users
  followee: users
  at: time
  unique follower, followee
  by follower, at                     -- the viewer's complete fan-in source list (following capped at 200)
  read r <- public
  insert r <- r.follower = viewer and r.follower != r.followee   -- no self-follow edge, ever
  delete r <- r.follower = viewer

table feedEntries:                    -- NEW (whole table): one row per feed occurrence (original post or repost)
  actor: users                        -- the author (kind 'post') or the reposter (kind 'repost')
  post: posts
  kind: enum('post', 'repost')
  at: time                            -- post time, or repost time
  unique actor, post, kind            -- doubles as the repost toggle's one-per-user-per-post key
  by byActor: actor, at               -- Following fan-in prefixes + profile post lists
  by byKind: kind, at                 -- Global fan-in (two prefixes cover the whole table)
  read r <- public
  insert r <- r.actor = viewer
    and ((r.kind = 'post' and r.post.author = viewer) or r.kind = 'repost')
  delete r <- r.actor = viewer and r.kind = 'repost'   -- un-repost; 'post' rows are permanent

table likes:                          -- NEW (whole table)
  post: posts
  user: users
  at: time
  unique post, user                   -- one like per user per post, enforced at commit
  read r <- public
  insert r <- r.user = viewer
  delete r <- r.user = viewer
```

```programs
-- ==================== M1 surfaces, carried forward ====================

mutation claimProfile(displayName: text <=50, handle: text <=20,   -- CHANGED: now seeds the counter row
                      bio: text <=200 ?, location: text <=50 ?,
                      link: text <=200 ?) -> users:
  require displayName != '' else EMPTY_NAME
  require matches(handle, '^[a-z0-9_]{3,20}$') else BAD_HANDLE  -- INVENTED: no length/charset predicate in the language
  u = +users { id: viewer, displayName, handle, bio, location, link }
  +userStats { user: viewer, followers: 0, following: 0 }
  u

mutation updateProfile(displayName: text <=50 ?, handle: text <=20 ?,   -- unchanged from M1
                       bio: text <=200 ?, location: text <=50 ?,
                       link: text <=200 ?) -> users:
  u = users[viewer]! else NO_PROFILE
  require (displayName ?? 'x') != '' else EMPTY_NAME
  require matches(handle ?? 'aaa', '^[a-z0-9_]{3,20}$') else BAD_HANDLE  -- INVENTED
  ~users[u] {
    displayName: displayName ?? .displayName,
    handle:      handle ?? .handle,
    bio:         bio ?? .bio,
    location:    location ?? .location,
    link:        link ?? .link,
  }
  users[viewer]! else NO_PROFILE

query me():                            -- CHANGED: profile header now shows counts
  users[viewer] {
    *,
    stats: userStats[.] { followers, following },
  }

query profile(u: users):               -- CHANGED: counts + follow state
  users[u]! else NOT_FOUND {
    *,
    stats: userStats[.] { followers, following },
    followedByMe: exists follows[viewer, .],
  }

query profileByHandle(handle: text <=20):   -- CHANGED: same shape as profile
  users[handle = handle] {
    *,
    stats: userStats[.] { followers, following },
    followedByMe: exists follows[viewer, .],
  }

-- ==================== posts, replies, likes, reposts ====================

mutation createPost(body: text <=500) -> posts:
  require body != '' else EMPTY_POST
  p = +posts { author: viewer, body, at: now }
  +postStats { post: p, likes: 0, replies: 0 }
  +feedEntries { actor: viewer, post: p, kind: 'post', at: now }
  p

mutation reply(parent: posts, body: text <=500) -> posts:
  require body != '' else EMPTY_POST
  ps = postStats[parent]! else NOT_FOUND       -- also proves the parent exists
  r = +posts { author: viewer, body, parent, at: now }
  +postStats { post: r, likes: 0, replies: 0 }
  ~postStats[ps] { replies: .replies + 1 }
  r                                            -- no feedEntries row: replies never enter feeds

mutation toggleLike(p: posts) -> bool:
  ps = postStats[p]! else NOT_FOUND
  match likes[p, viewer]:
    some l:
      -likes[l]
      ~postStats[ps] { likes: .likes - 1 }
      false
    none:
      +likes { post: p, user: viewer, at: now }   -- concurrent double-like -> unique refusal, count stays exact
      ~postStats[ps] { likes: .likes + 1 }
      true

mutation toggleRepost(p: posts) -> bool:
  post = posts[p]! else NOT_FOUND
  require not exists posts[post.parent] else CANT_REPOST_REPLY   -- absent parent -> exists is false -> passes
  match feedEntries[viewer, p, 'repost']:
    some e:
      -feedEntries[e]
      false
    none:
      +feedEntries { actor: viewer, post: p, kind: 'repost', at: now }
      true

mutation toggleFollow(u: users) -> bool:
  require u != viewer else SELF_FOLLOW
  mine   = userStats[viewer]! else NO_PROFILE
  theirs = userStats[u]! else NOT_FOUND
  match follows[viewer, u]:
    some f:
      -follows[f]
      ~userStats[theirs] { followers: .followers - 1 }
      ~userStats[mine]   { following: .following - 1 }
      false
    none:
      require mine.following < 200 else FOLLOW_LIMIT   -- keeps the Following fan-in complete (see notes)
      +follows { follower: viewer, followee: u, at: now }
      ~userStats[theirs] { followers: .followers + 1 }
      ~userStats[mine]   { following: .following + 1 }
      true

-- ==================== feeds ====================
-- Feed item shape (repeated verbatim below — the language has no named shapes):
--   kind, at, actor (attribution), post with author, counters, viewer toggles.

query followingFeed():
  sources = follows[viewer] first 200            -- complete: following is capped at 200
  merge(feedEntries[f.followee] for f in sources,   -- INVENTED: merge over a bounded dynamic prefix set;
        feedEntries[viewer]) last 20 {              -- the reference's merge takes enumerated prefixes only
    kind, at,
    actor: .actor { displayName, handle },
    post: .post {
      *,
      author: .author { displayName, handle },
      stats: postStats[.] { likes, replies },
      likedByMe: exists likes[., viewer],
      repostedByMe: exists feedEntries[viewer, ., 'repost'],
    },
  }

query followingFeedBefore(cursor: time):
  sources = follows[viewer] first 200
  merge(feedEntries[f.followee] for f in sources,   -- INVENTED (same form)
        feedEntries[viewer]) before cursor last 20 {
    kind, at,
    actor: .actor { displayName, handle },
    post: .post {
      *,
      author: .author { displayName, handle },
      stats: postStats[.] { likes, replies },
      likedByMe: exists likes[., viewer],
      repostedByMe: exists feedEntries[viewer, ., 'repost'],
    },
  }

query globalFeed():
  merge(feedEntries['post'], feedEntries['repost']) last 20 {   -- two byKind prefixes = the whole table, in-spec
    kind, at,
    actor: .actor { displayName, handle },
    post: .post {
      *,
      author: .author { displayName, handle },
      stats: postStats[.] { likes, replies },
      likedByMe: exists likes[., viewer],
      repostedByMe: exists feedEntries[viewer, ., 'repost'],
    },
  }

query globalFeedBefore(cursor: time):
  merge(feedEntries['post'], feedEntries['repost']) before cursor last 20 {
    kind, at,
    actor: .actor { displayName, handle },
    post: .post {
      *,
      author: .author { displayName, handle },
      stats: postStats[.] { likes, replies },
      likedByMe: exists likes[., viewer],
      repostedByMe: exists feedEntries[viewer, ., 'repost'],
    },
  }

-- ==================== profile post lists ====================

query profilePosts(u: users):
  feedEntries[actor = u] last 20 {               -- originals + that user's reposts, attributed
    kind, at,
    actor: .actor { displayName, handle },
    post: .post {
      *,
      author: .author { displayName, handle },
      stats: postStats[.] { likes, replies },
      likedByMe: exists likes[., viewer],
      repostedByMe: exists feedEntries[viewer, ., 'repost'],
    },
  }

query profilePostsBefore(u: users, cursor: time):
  feedEntries[actor = u] before cursor last 20 {
    kind, at,
    actor: .actor { displayName, handle },
    post: .post {
      *,
      author: .author { displayName, handle },
      stats: postStats[.] { likes, replies },
      likedByMe: exists likes[., viewer],
      repostedByMe: exists feedEntries[viewer, ., 'repost'],
    },
  }

-- ==================== threads ====================

query thread(p: posts):
  posts[p]! else NOT_FOUND {
    *,
    author: .author { displayName, handle },
    stats: postStats[.] { likes, replies },
    likedByMe: exists likes[., viewer],
    inReplyTo: .parent { id, body, at, author: .author { displayName, handle } },  -- absent for originals
    replies: posts[parent = p] first 50 {
      *,
      author: .author { displayName, handle },
      stats: postStats[.] { likes, replies },
      likedByMe: exists likes[., viewer],
    },
  }

query threadRepliesAfter(p: posts, cursor: time):
  posts[parent = p] after cursor first 50 {
    *,
    author: .author { displayName, handle },
    stats: postStats[.] { likes, replies },
    likedByMe: exists likes[., viewer],
  }
```

```boundary
identity / live transport / client custody: as M1 — live queries make acceptance items 1, 2, 4, 5, 6 push-updated with no data-plane polling.
feed dedup: when Following holds both an original and a followed user's repost of it, collapsing to one card is client presentation; the data plane serves both rows.
timeline clock: feed order is the stored client intent clock (`at: now`); cross-client skew reorders near-simultaneous posts — accepted product behavior, seed staggers timestamps.
schedules / channels / effects: still none needed in M2.
```

```notes
1. WORKAROUND (no maintained aggregates) #1: userStats/postStats side tables, bumped by every follow/like/reply mutation. Side tables rather than columns on users/posts because column-granular update rules are inexpressible — the permissive "anyone may bump" rule is quarantined in tables holding only counters, and users/posts keep strict owner-only/immutable rules.
2. WORKAROUND #2: `maintain rows` fan-out is also banned, so Following is query-time fan-in — `merge` over the viewer's follow prefixes plus self. Chose fan-in over fan-out deliberately (the reference asks): unfollow must retro-hide older posts "on next load", which fan-in gives free and fan-out would pay for with unbounded retro-deletion.
3. The fan-in must be COMPLETE to be correct, so following is capped at 200 accounts (FOLLOW_LIMIT, enforced via the hand-kept counter). A visible product limit forced by boundedness.
4. `merge` over a dynamic prefix set is not in the reference — the one place I had to invent syntax (`for f in sources` inside merge, marked INVENTED at both use sites).
5. Global feed: the language cannot range-read a whole table (no empty-prefix bracket), so `merge` over the two `kind` prefixes of the byKind ordering covers everyone, fully in-spec.
6. feedEntries doubles as the repost store: unique(actor, post, kind) IS the repost toggle; replies get no entry row, so "replies never appear in feeds" holds by construction, not by filtering.
7. Pagination cursors are single-column (`before`/`after` on the ordering's final column); two rows sharing an `at` can straddle a page boundary since composite (at, id) cursors are inexpressible. Known limit; seed staggers timestamps.
8. Optional-cursor branching is impossible — `match` covers point reads only, and `before (cursor ?? now)` is a type error because `now` is time!intent — so every paged surface is two programs (first page + Before/After variant). 4 extra programs total.
9. Predicates over absent values are false, which makes `not exists posts[post.parent]` a correct "is an original" test — pleasant once trusted.
10. Product calls: repost count not tracked (brief never shows one); reposting a reply refused (CANT_REPOST_REPLY); posts/likes/follow edges are declared-public reads (counts already disclose them).
11. Milestone migration: backfill one userStats row per M1 user and nothing else; posts/postStats are born together from M2 on.
```
