# Clique on Quarry — M3: Messaging core

```schema
use identity                          -- (M1)

table users:                          -- (M1, unchanged)
  displayName: text <=50
  handle: text <=20
  bio: text <=200 ?
  location: text <=50 ?
  link: text <=200 ?
  unique handle
  read r <- public
  insert r <- r.id = viewer
  update (old, next) <- old.id = viewer

table userStats:                      -- (M2, unchanged)
  user: users
  followers: int
  following: int
  unique user
  read r <- public
  insert r <- r.user = viewer and r.followers = 0 and r.following = 0
  update (old, next) <- next.user = old.user
    and next.followers >= 0 and next.following >= 0

table posts:                          -- (M2, unchanged)
  author: users
  body: text <=500
  parent: posts ?
  at: time
  by parent, at
  read r <- public
  insert r <- r.author = viewer

table postStats:                      -- (M2, unchanged)
  post: posts
  likes: int
  replies: int
  unique post
  read r <- public
  insert r <- r.post.author = viewer and r.likes = 0 and r.replies = 0
  update (old, next) <- next.post = old.post and next.likes >= 0 and next.replies >= 0

table follows:                        -- (M2, unchanged)
  follower: users
  followee: users
  at: time
  unique follower, followee
  by follower, at
  read r <- public
  insert r <- r.follower = viewer and r.follower != r.followee
  delete r <- r.follower = viewer

table feedEntries:                    -- (M2, unchanged)
  actor: users
  post: posts
  kind: enum('post', 'repost')
  at: time
  unique actor, post, kind
  by byActor: actor, at
  by byKind: kind, at
  read r <- public
  insert r <- r.actor = viewer
    and ((r.kind = 'post' and r.post.author = viewer) or r.kind = 'repost')
  delete r <- r.actor = viewer and r.kind = 'repost'

table likes:                          -- (M2, unchanged)
  post: posts
  user: users
  at: time
  unique post, user
  read r <- public
  insert r <- r.user = viewer
  delete r <- r.user = viewer

table conversations:                  -- NEW (whole table)
  kind: enum('dm', 'group')
  name: text <=50 ?                   -- groups only
  description: text <=200 ?           -- groups only
  createdBy: users
  createdAt: time
  memberCount: int                    -- hand-kept: bounds the 2–50 rule and proves the send fan-out bounded
  read r <- exists members[r, viewer]           -- members only; removal cuts access immediately
  insert r <- r.createdBy = viewer and r.memberCount = 0
  update (old, next) <- exists members[old, viewer]
    and next.kind = old.kind and (next.name ?? '') = (old.name ?? '')
    and (next.description ?? '') = (old.description ?? '')
    and next.createdBy = old.createdBy and next.createdAt = old.createdAt
    and next.memberCount >= 0 and next.memberCount <= 50
    -- i.e. a member may adjust memberCount and nothing else

table members:                        -- NEW (whole table): membership + receipt watermarks + chat-list ordering
  conv: conversations
  user: users
  role: enum('member', 'admin')
  joinedAt: time
  activityAt: time                    -- last message time in conv (denormalized; drives the chat list)
  deliveredUpTo: time                 -- receipt watermark: every message at-or-before is delivered to this member
  readUpTo: time                      -- receipt watermark: … read by this member
  unique conv, user
  by conv, joinedAt                   -- roster
  by chatlist: user, activityAt      -- the viewer's conversation list, most-recently-active first (read `last`)
  read r <- exists members[r.conv, viewer]
  insert r <- (r.conv.createdBy = viewer or members[r.conv, viewer].role = 'admin')
    and r.deliveredUpTo = r.joinedAt and r.readUpTo = r.joinedAt
    -- joiner watermarks start at joinedAt: prior messages never wait on a late joiner (send-time recipient set)
  delete r <- r.user = viewer or members[r.conv, viewer].role = 'admin'
  update (old, next) <- next.conv = old.conv and next.user = old.user and next.joinedAt = old.joinedAt
    and next.deliveredUpTo >= old.deliveredUpTo and next.readUpTo >= old.readUpTo   -- receipts are monotonic
    and (
      (old.user = viewer and next.role = old.role)                                  -- own watermarks / activity
      or (exists members[old.conv, viewer] and next.role = old.role
          and next.deliveredUpTo = old.deliveredUpTo and next.readUpTo = old.readUpTo)  -- co-member activity bump on send
      or (members[old.conv, viewer].role = 'admin' and next.role = 'admin'
          and next.activityAt = old.activityAt
          and next.deliveredUpTo = old.deliveredUpTo and next.readUpTo = old.readUpTo)  -- promotion, one-way
    )

table dms:                            -- NEW (whole table): at most one DM channel per user pair
  lo: users                           -- the pair in sorted() order
  hi: users
  conv: conversations
  unique lo, hi                       -- concurrent opens collapse via commit-time refusal
  read r <- r.lo = viewer or r.hi = viewer
  insert r <- (r.lo = viewer or r.hi = viewer)
    and r.conv.createdBy = viewer and r.conv.kind = 'dm'

table messages:                       -- NEW (whole table)
  conv: conversations
  sender: users
  body: text <=2000
  quoted: messages ?                  -- quoted reply: pointer to the quoted message
  at: time
  by conv, at
  read r <- exists members[r.conv, viewer]      -- removed members lose new messages instantly
  insert r <- r.sender = viewer and exists members[r.conv, viewer]
    and (r.quoted.conv ?? r.conv) = r.conv      -- a quote must point into the same conversation
  -- immutable: no edit or delete in this product

channel typing(conv: conversations):  -- NEW: ephemeral, no rows, no history
  publish   <- exists members[conv, viewer]
  subscribe <- exists members[conv, viewer]
  ttl 5s                              -- the brief's "expires within 5 s of the last keystroke" is the ttl
```

```programs
-- M1/M2 programs carry forward UNCHANGED: claimProfile, updateProfile, me,
-- profile, profileByHandle, createPost, reply, toggleLike, toggleRepost,
-- toggleFollow, followingFeed(+Before), globalFeed(+Before),
-- profilePosts(+Before), thread, threadRepliesAfter.
-- Below: every program the messaging screens need.

-- ==================== opening conversations ====================

mutation openDM(u: users) -> conversations:
  require u != viewer else SELF_DM
  require exists users[u] else NOT_FOUND
  (lo, hi) = sorted(viewer, u)
  match dms[lo, hi]:
    some d:
      d.conv                                   -- the existing channel, always
    none:
      c = +conversations { kind: 'dm', createdBy: viewer, createdAt: now, memberCount: 0 }
      +dms { lo, hi, conv: c }
      +members { conv: c, user: lo, role: 'member', joinedAt: now,
                 activityAt: now, deliveredUpTo: now, readUpTo: now }
      +members { conv: c, user: hi, role: 'member', joinedAt: now,
                 activityAt: now, deliveredUpTo: now, readUpTo: now }
      ~conversations[c] { memberCount: .memberCount + 2 }
      c

mutation createGroup(name: text <=50, description: text <=200 ?,
                     invitees: [users] <=49) -> conversations:
  require name != '' else EMPTY_NAME
  c = +conversations { kind: 'group', name, description, createdBy: viewer,
                       createdAt: now, memberCount: 0 }
  +members { conv: c, user: viewer, role: 'admin', joinedAt: now,
             activityAt: now, deliveredUpTo: now, readUpTo: now }
  ~conversations[c] { memberCount: .memberCount + 1 }
  for u in invitees:                           -- capped list: bounded loop
    require u != viewer else INVITED_SELF      -- duplicates among invitees -> unique(conv,user) refusal
    +members { conv: c, user: u, role: 'member', joinedAt: now,
               activityAt: now, deliveredUpTo: now, readUpTo: now }
    ~conversations[c] { memberCount: .memberCount + 1 }
  g = conversations[c]! else NOT_FOUND         -- re-read own writes for the size check
  require g.memberCount >= 2 else GROUP_TOO_SMALL
  g

-- ==================== group management ====================

mutation addMember(c: conversations, u: users) -> bool:
  g = conversations[c]! else NOT_FOUND
  require g.kind = 'group' else NOT_A_GROUP
  me = members[c, viewer]! else NOT_MEMBER
  require me.role = 'admin' else NOT_ADMIN
  require g.memberCount < 50 else GROUP_FULL
  +members { conv: c, user: u, role: 'member', joinedAt: now,   -- adds are immediate; re-add of a member -> unique refusal
             activityAt: now, deliveredUpTo: now, readUpTo: now }
  ~conversations[c] { memberCount: .memberCount + 1 }
  true

mutation promoteAdmin(c: conversations, u: users) -> bool:
  g = conversations[c]! else NOT_FOUND
  require g.kind = 'group' else NOT_A_GROUP
  me = members[c, viewer]! else NOT_MEMBER
  require me.role = 'admin' else NOT_ADMIN
  t = members[c, u]! else NOT_MEMBER
  ~members[t] { role: 'admin' }
  true

mutation removeMember(c: conversations, u: users) -> bool:
  g = conversations[c]! else NOT_FOUND
  require g.kind = 'group' else NOT_A_GROUP
  me = members[c, viewer]! else NOT_MEMBER
  require me.role = 'admin' else NOT_ADMIN     -- acceptance 6: a non-admin refuses here
  require u != viewer else USE_LEAVE
  t = members[c, u]! else NOT_MEMBER
  ~conversations[c] { memberCount: .memberCount - 1 }   -- patch BEFORE delete: the update rule needs a live member
  -members[t]                                  -- watermark row gone -> they drop out of receipt aggregates
  true

mutation leaveGroup(c: conversations) -> bool:
  g = conversations[c]! else NOT_FOUND
  require g.kind = 'group' else NOT_A_GROUP    -- DMs cannot be left (product call)
  me = members[c, viewer]! else NOT_MEMBER
  ~conversations[c] { memberCount: .memberCount - 1 }   -- same ordering subtlety as removeMember
  -members[me]
  true

-- ==================== messages and receipts ====================

mutation sendMessage(c: conversations, body: text <=2000,
                     quoted: messages ?) -> messages:
  me = members[c, viewer]! else NOT_MEMBER
  require body != '' else EMPTY_MESSAGE
  require (quoted.conv ?? c) = c else QUOTE_OTHER_CONVERSATION   -- absent quote coalesces to pass
  m = +messages { conv: c, sender: viewer, body, quoted, at: now }
  for mem in members[c] first 50:              -- bounded fan-out: member cap is 50 by construction
    ~members[mem] { activityAt: max(.activityAt, m.at) }         -- floats the conv in every member's chat list
  ~members[me] { deliveredUpTo: max(.deliveredUpTo, m.at),       -- sender's own receipts are instant
                 readUpTo: max(.readUpTo, m.at) }
  m

mutation markDelivered(c: conversations, upTo: time) -> bool:
  -- client calls with the newest fetched message's .at whenever the live
  -- subscription hands it new messages
  me = members[c, viewer]! else NOT_MEMBER
  ~members[me] { deliveredUpTo: max(.deliveredUpTo, upTo) }      -- max() keeps receipts monotonic under races
  true

mutation markRead(c: conversations, upTo: time) -> bool:
  -- client calls when the conversation is open/viewed; read implies delivered
  me = members[c, viewer]! else NOT_MEMBER
  ~members[me] { deliveredUpTo: max(.deliveredUpTo, upTo),
                 readUpTo: max(.readUpTo, upTo) }
  true

-- ==================== conversation screens ====================

query chats():
  members[user = viewer] last 30 by chatlist {
    activityAt,
    conv: .conv {
      *,                                       -- kind, name, memberCount for the row header
      latest: messages[.] last 1 { body, at, sender: .sender { displayName } },
      roster: members[.] first 50 { user: .user { id, displayName, handle }, role },
      -- roster names the DM counterpart client-side; groups use .name
    },
  }

query chatsBefore(cursor: time):
  members[user = viewer] before cursor last 30 by chatlist {
    activityAt,
    conv: .conv {
      *,
      latest: messages[.] last 1 { body, at, sender: .sender { displayName } },
      roster: members[.] first 50 { user: .user { id, displayName, handle }, role },
    },
  }

query conversation(c: conversations):
  conversations[c]! else NOT_FOUND {           -- non-members refuse here without leaking existence
    *,
    roster: members[.] first 50 {
      user: .user { id, displayName, handle },
      role, joinedAt, deliveredUpTo, readUpTo, -- the client folds min() over these for the receipt ticks
    },
    recent: messages[.] last 50 {
      *,
      sender: .sender { displayName, handle },
      quoted: .quoted { id, body, at, sender: .sender { displayName } },   -- excerpt = client truncation
    },
  }

query olderMessages(c: conversations, cursor: time):
  require exists conversations[c] else NOT_FOUND   -- read rule makes hidden = absent
  messages[c] before cursor last 50 {
    *,
    sender: .sender { displayName, handle },
    quoted: .quoted { id, body, at, sender: .sender { displayName } },
  }
```

```boundary
identity / live transport / client custody: as M1 — the conversation query's live subscription is what makes messages, roster changes, and receipt ticks appear without refresh.
typing channel: declared in schema; client publishes a small {user, displayName} struct at most every 2 s while keys are down; ttl 5s is the expiry — no durable rows, no history, engine-owned fan-out.
receipt fold: the per-message tick and the group "slowest member" indicator are min() over the ≤50 roster watermarks served by `conversation` (excluding the sender; late joiners auto-pass via joinedAt init); the final fold is client-side because page reductions are count/sum only.
delivered semantics: the client calls markDelivered(upTo = newest fetched .at) on receipt of pushed messages, markRead on conversation open — receipt truth is server rows, the trigger is client behavior.
removed-member history: pre-removal messages stay only in the removed client's local cache (custody); the server refuses all further reads the moment the member row is deleted.
seed: a client script; idempotence by probe-first (if handle 'alice' already resolves, skip all seeding), because group creation is deliberately NOT idempotent — identical membership sets may coexist per spec.
schedules / effects: none in the whole app — typing expiry is channel ttl, session expiry is the identity kind, and nothing else is time-triggered.
```

```notes
1. WORKAROUND (no maintained aggregates) #3 — receipts: per-member watermarks (deliveredUpTo/readUpTo) instead of per-message receipt rows or counters. Aggregate = min over ≤50 current members. This also solves "leavers drop out" for free (row deleted -> out of the fold); per-message counters could not, since decrementing every historical unread message on leave is an unbounded write.
2. "Membership at send time" falls out of initializing joiner watermarks to joinedAt: a message with at <= joinedAt is already covered by the joiner, so old aggregates never regress when someone joins.
3. The final min() fold is client-side: reductions are `count`/`sum` only and bindings cannot accumulate across `for` iterations. The single place I most wanted `page | min .col` in the language.
4. WORKAROUND #4 — memberCount is a hand-kept int on conversations; it enforces 2–50, proves the send fan-out bounded, and doubles as group-info display. Leave/remove must patch it BEFORE deleting the member row, or the members-only update rule refuses the patch. Order-of-writes-as-authorization is subtle; a compiler would not catch it — only a reviewer.
5. Chat-list ordering: an ordering's sort key must live on the ordered table, so send fans activityAt out to ≤50 member rows (bounded by the same cap).
6. DM pair identity is `sorted(viewer, u)` + `unique lo, hi` — three lines, race-free by construction; the builtin exists exactly for this.
7. createGroup cannot count its capped-list argument (reductions apply to pages), so min-size-2 is enforced by re-reading memberCount after the inserts — assumes a transaction reads its own writes.
8. Rules that read tables (exists members[...]) are assumed to evaluate with the engine's eye, as the reference's channel rules do — otherwise members.read is circular. Flagged as an interpretation.
9. members.update is 13 lines of enumerated unchanged-columns arms — the price of no column-granular rules; `?? ''` sentinels reappear in conversations.update because equality over two absent optionals is false.
10. Product calls: DMs cannot be left; demotion doesn't exist (promotion is one-way); a group may shrink below 2 or end up adminless via leaves (brief constrains creation only); no unread badges (not in brief — would be one bounded watermark diff per row, same pattern).
11. Quoted replies: pointer + same-conversation integrity in the insert rule; a quote of a message the viewer cannot read is impossible since both live in the same conversation.
12. `typing` is the app's only channel and there are zero schedules — the brief's every timing requirement landed in a kind (ttl, session expiry), never in a rule comparing clocks.
```
