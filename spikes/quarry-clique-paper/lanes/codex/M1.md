```schema
use identity
  -- Built-in, in-system email/password auth with unique emails and password length >=8.
  -- Stores only provider-managed adaptive password verifiers; credentials never enter app tables or logs.
  -- Issues expiring sessions, provides viewer, and rejects revoked sessions after server-side logout.

use assets
  -- Authenticated image upload and delivery; provides asset references while bytes remain outside the data plane.

table users:
  displayName: text <=50
  handle: text <=20
  avatar: asset ?
  bio: text <=200 ?
  location: text <=50 ?
  link: text <=2048 ?
  public
  insert r <- r.id = viewer.id
  update (old, next) <- old.id = viewer.id and next.id = old.id
  unique handle
```

```programs
-- Sign-up, sign-in, session restoration, and logout are operations of `use identity`,
-- not Quarry programs.

query me():
  u = users[viewer]! else PROFILE_NOT_FOUND
  u {
    id,
    displayName,
    handle,
    avatar,
    bio,
    location,
    link,
  }

query profile(u: users):
  u {
    id,
    displayName,
    handle,
    avatar,
    bio,
    location,
    link,
  }

query profileByHandle(handle: text <=20):
  users[handle = handle] {
    id,
    displayName,
    handle,
    avatar,
    bio,
    location,
    link,
  }

mutation createProfile(
  displayName: text <=50,
  handle: text <=20,
  avatar: asset ?,
  bio: text <=200 ?,
  location: text <=50 ?,
  link: text <=2048 ?
) -> users:
  require not exists users[viewer] else PROFILE_EXISTS
  +users {
    id: viewer,
    displayName,
    handle,
    avatar,
    bio,
    location,
    link,
  }

mutation updateProfile(
  displayName: text <=50,
  handle: text <=20,
  avatar: asset ?,
  bio: text <=200 ?,
  location: text <=50 ?,
  link: text <=2048 ?
) -> users:
  u = users[viewer]! else PROFILE_NOT_FOUND
  ~users[u] {
    displayName,
    handle,
    avatar,
    bio,
    location,
    link,
  }
  users[u]! else PROFILE_NOT_FOUND
```

```boundary
- Identity — Built-in in-system auth validates password length ≥8, enforces normalized email uniqueness, securely verifies passwords, issues expiring tokens, restores valid sessions, and revokes tokens server-side on logout.
- Assets — Accepts authenticated fixture-image uploads, returns `asset` references, serves referenced images, and manages replacement/orphan lifecycle without exposing bytes to Quarry.
- Client session storage — Persists only the opaque identity session token across app restarts; it cannot make an expired or revoked token valid.
```

```notes
- Identity credentials and email deliberately do not appear in `users`; `viewer` links the authenticated principal to the row with the same id.
- Profile creation follows identity registration; Quarry cannot atomically compose an identity operation with `createProfile`.
- A handle collision is refused at commit by `unique handle`; this also covers concurrent create or edit attempts.
- `me` is suitable for live subscription, so profile edits propagate to other signed-in clients without refresh.
- Optional profile arguments let the client clear avatar, bio, location, or link by supplying absence.
- Quarry enforces all specified maximum text lengths but has no length or pattern predicate for display-name non-emptiness or handle `[a-z0-9_]`/minimum length.
- Quarry has no URL type or parser, so `link` is bounded text and its “one URL” syntax cannot be server-validated in this language.
- No channel, schedule, or external effect is required for M1.
```
