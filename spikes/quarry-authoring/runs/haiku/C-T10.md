```quarry
table users:
  name: text <=80

table rides:
  driver: users
  seats: int
  departsAt: time

table passengers:
  ride: rides
  user: users
  at: time
  by ride, at
  unique ride, user

maintain passengerCount = count passengers by ride

mutation joinRide(rideId: rides) -> passengers:
  ride = rides[rideId]! else RIDE_NOT_FOUND
  existing = passengers[ride, viewer]
  match existing:
    some p:
      p
    none:
      require #passengerCount[ride] < ride.seats else RIDE_FULL
      +passengers { ride: ride, user: viewer, at: now }
```

The mutation checks if the viewer is already a passenger (idempotent), then guards on an exact maintained count before inserting. The guard at the point of insertion—after the upsert decision—catches overbooking races even with concurrent joins, since the maintained count is exact at commit and all writes are atomic.
