The trap is that Quarry forbids unbounded reads—every range must specify a bound. The viewer's recipes are efficiently keyed by the `by owner, createdAt` ordering, so I use that index to read the last (newest) N recipes. I've chosen 100 as a reasonable page size for typical recipe lists.

```
table users:
  name: text <=80

table recipes:
  owner: users
  title: text <=200
  createdAt: time
  by owner, createdAt

query myRecipes():
  recipes[viewer] last 100
```
