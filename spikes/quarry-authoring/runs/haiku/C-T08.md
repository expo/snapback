```quarry
table users:
  name: text <=80

table journals:
  owner: users
  title: text <=200

table entries:
  journal: journals
  at: time
  text: text <=8192
  by journal, at
  read e <- journals[e.journal].owner = viewer
            or exists coaches[e.journal, viewer]

table coaches:
  journal: journals
  user: users
  unique journal, user

mutation addEntry(journalId: journals, entryText: text <=8192) -> entries:
  require journalId.owner = viewer or exists coaches[journalId, viewer] else NOT_ALLOWED
  +entries { journal: journalId, at: now, text: entryText }
```

The mutation enforces the authorization guard upfront: only the journal's owner or a coach may append entries. The `require` statement refuses the entire transaction with `NOT_ALLOWED` if neither condition is met, and inserts the entry with the current intent clock only if authorized.
