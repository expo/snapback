The trap is Rule 4: you cannot compute a reduction (like finding the maximum) over a `privateTable` whose read visibility is not uniform to the caller—that would leak facts about rows the caller cannot see. The solution is a maintained aggregate, which declares to the engine that we explicitly want to expose the maximum score per contest as a public, structural fact.

```ts
const users = table("users");
const contests = table("contests");
const entries = privateTable("entries");
                                       // { id, contestId, bakerId, score, at }
                                       // readable only to the entry's own baker until the contest closes
                                       // index entries.byContestScore: (contestId, score)
const topScores = maintained("topScores", entries);

export const topScore = query({ contestId: scalar() }, ({ db, args }) => {
  const agg = db.get(topScores, args.contestId);
  return agg?.score ?? null;
});
```

The maintained aggregate tracks the maximum score for each contest. Individual entries stay private to their bakers; the aggregate makes only the top score public as an intentional disclosure.
