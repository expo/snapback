I'll use the `walk` construct with bounded ancestor traversal to follow the manager chain upward from the employee. Since the schema allows up to 12 levels and the `manager` column is absent at the top, `walk` will naturally stop there.

```
table employees:
  name: text <=80
  title: text <=100
  manager: employees          -- absent at the top

query chain(e: employees):
  walk e up .manager depth 12
```

The `walk` statement traverses the reference column upward from the given employee, yielding each row in the chain (employee, then manager, then manager's manager, etc.) until either reaching the top (where `manager` is absent) or exhausting the depth bound of 12 levels.
