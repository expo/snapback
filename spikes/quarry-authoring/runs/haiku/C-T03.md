Looking at this task, I need to:

1. Get the viewer's (employer's) newest 20 postings using the `by employer, createdAt` ordering
2. Count applications for each posting

The key insight is that the ordering `by employer, createdAt` allows me to range-read postings filtered by employer, and I should use a maintained aggregate to efficiently count applications by posting (rather than trying to fit all applications into a bounded page read).

```quarry
table users:
  name: text <=80

table postings:
  employer: users
  title: text <=200
  createdAt: time
  by employer, createdAt

table applications:
  posting: postings
  applicant: users
  at: time
  by posting, at
  read a <- a.applicant = viewer or postings[a.posting].employer = viewer

maintain appCount = count applications by posting

query dashboard():
  postings[employer = viewer] last 20 {
    *,
    applicationCount: #appCount[.]
  }
```

The query filters postings by the viewing employer and orders descending by creation time (newest first), returning each posting's columns plus its application count from the maintained aggregate.
