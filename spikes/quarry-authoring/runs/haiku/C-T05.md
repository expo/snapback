```
table users:
  name: text <=80

table promos:
  code: text <=32
  discount: int
  expiresAt: time
  unique code

table redemptions:
  promo: promos
  user: users
  at: time
  unique promo, user

mutation redeemPromo(code: text <=32) -> redemptions:
  p = promos[code = code]! else PROMO_NOT_FOUND
  require p.expiresAt > commit else PROMO_EXPIRED
  require not exists redemptions[p, viewer] else ALREADY_REDEEMED
  +redemptions { promo: p, user: viewer, at: now }
```

The key to this solution is using `commit` (the engine's clock at commit) rather than `now` (the client's intent clock) for the expiration check—this prevents a client from bypassing time-based access control with a backdated timestamp. The mutation looks up the promo by code, guards against expiration and duplicate redemption, then records the redemption for the calling user.
