# Snapback data programs — API reference (TypeScript)

Snapback backends are written as TypeScript modules of **data programs**:
queries (read) and mutations (read + write). A module declares its schema
handles at the top, then exports programs.

## Module shape

```ts
const users = table("users");            // ordinary table
const audits = privateTable("audits");   // restricted-visibility table
const cardCounts = maintained("cardCounts", cards); // engine-maintained aggregate over `cards`

export const myQuery = query({ someArg: scalar() }, ({ db, ctx, args }) => { /* ... */ });
export const myMutation = mutation({ someArg: scalar() }, ({ db, ctx, args }) => { /* ... */ });
```

## Argument declarators

`scalar()` — any scalar; `id(table)` — a row id; `text({ max: N })`; `int()`;
`time()`; `optional(t)`; `list(t, { max: N })` — a list argument with a
declared maximum length.

## The db API

```ts
db.get(tbl, key)                       // Row | null — point read by id
db.get(tbl.byUnique, [a, b])           // Row | null — unique-index read
db.get(maintainedName, key)            // MaintainedRow | null — read a maintained aggregate
db.exists(tbl.byIndex, [a, b])         // boolean
db.scan(tbl.byIndex, [prefix...], { order?: "asc"|"desc", take?: N, after?: v })
                                       // Page: an array with .hasMore
db.insert(tbl, row)                    // insert; inserting a duplicate into a unique index is refused by the engine
db.update(tbl, key, patch)             // patch fields of one row
db.upsert(tbl, key, patch)             // update if present, insert if absent
db.delete(tbl, key)
db.require(cond, "CODE")               // refuse the whole transaction with a stable code unless cond
```

Indexes are referenced as `tbl.byName([...prefixValues])`; the column order of
each index is listed with the schema. A scan's prefix pins the leading index
columns; `order`/`after` apply to the next column. Maintained aggregates are
declared with `maintained(name, sourceTable)` and read with
`db.get(name, key)` — the engine keeps them exact and up to date at commit.

## Context

`ctx.viewer` — the calling principal's user id. `ctx.newId()` — mint a row id.
`ctx.now()` — the client's intent-time clock (ms). `ctx.commitTime` — the
engine's clock at commit (ms). `ctx.readTime` — bucketed display time for
queries.

## Helpers

`range(a, b)`; `recurse(seed, step, { depth: D, fanout: F })` — bounded
traversal from a seed row along a step function; `concat(...)`, `min(...)`,
`max(...)`, `divmod(a, b)`; `mentionTokens(text)` — tokenize a message body.
Arrays support `map`, `filter`, `sort(comparator)`, `slice`, `push`,
`some`, `reduce`, `count()`, and `countCapped()` (returns
`{ count, atCap }`). `Map` and `Set` are available.

## Worked examples

A chat thread — the newest 3 messages with each author and any @-mentioned
users:

```ts
const users = table("users");            // { id, name, handle } — unique index users.byHandle: (handle)
const messages = table("messages");      // { id, conversationId, authorId, body, at }
                                         // index messages.byConvTime: (conversationId, at)

export const thread = query({ conversationId: scalar() }, ({ db, args }) => {
  let result: any[] = [];
  for (const message of db.scan(messages.byConvTime, [args.conversationId], { order: "desc", take: 3 })) {
    let author = db.get(users, message.authorId);
    let mentions: any[] = [];
    for (const handle of mentionTokens(message.body)) {
      mentions.push(db.scan(users.byHandle, [handle], { take: 1 }));
    }
    result.push({ message, author, mentions });
  }
  return result;
});
```

Sending a message, membership-guarded:

```ts
const memberships = table("memberships"); // { id, conversationId, userId, lastReadAt }
                                          // index memberships.byConvUser: (conversationId, userId)

export const send = mutation(
  { conversationId: scalar(), body: text({ max: 4096 }), at: time() },
  ({ db, ctx, args }) => {
    db.require(db.exists(memberships.byConvUser, [args.conversationId, ctx.viewer]), "NOT_MEMBER");
    const messageId = ctx.newId();
    db.insert(messages, {
      id: messageId,
      conversationId: args.conversationId,
      authorId: ctx.viewer,
      body: args.body,
      at: args.at,
    });
    return messageId;
  },
);
```


# The checker — rules every program must satisfy

Snapback compiles each program to a bounded IR and refuses anything it cannot
statically certify. Your submission is checked as written; there is no repair
round. The rules:

1. **Every read is bounded.** A `scan` must carry a literal `take` (or an
   argument with a declared max). Loops may only iterate a page, a bounded
   list argument, `range(a, b)`, or a `recurse(...)` result. `while` and
   recursion are refused (`E_UNBOUND_SCAN`, `E_BOUND`). Pick real bounds; a
   page's `.hasMore` tells the client there was more.

2. **No ambient anything.** `Date`, `Math.random`, `fetch`, timers, and I/O do
   not exist in data programs (`E_AMBIENT_TIME`). The only clocks are
   `ctx.now()` and `ctx.commitTime`; the only id source is `ctx.newId()`.

3. **Two clocks, two jobs.** `ctx.now()` is the *client's intent clock* — use
   it only as a stored timestamp value. Any comparison that grants or denies
   something (expiry, deadline, window) must use `ctx.commitTime`, the
   engine's clock at commit. Comparing `ctx.now()` against a deadline is the
   classic wrong program: the client's clock is attacker-controlled.

4. **Structural facts must be declared.** A reduction — `.count()`, `.sort(...)[0]`
   as a max, a loop tally — over rows whose read visibility is not uniformly
   true for the caller is refused (`E_STRUCTURAL_COUNT`): it would leak a fact
   about rows the caller cannot see. The admitted route for a population fact
   (a total, a maximum, a rank) is a **maintained aggregate**
   (`maintained(name, source)`, read with `db.get`) — exact, complete, and a
   declared disclosure.

5. **A page reduction is never a total.** `.count()` over a bounded page counts
   *the page*, not the population — even over public rows. For display counts
   use `.countCapped()` and render "N+" at the cap; for a real total, maintain
   it. An exact reduction with no bound is refused (`E_UNBOUND_COUNT`).

6. **Absence is a value.** `db.get` returns `null`; handle it. On a
   restricted table (`privateTable`), null does not distinguish "absent" from
   "hidden" — do not branch existence-claims on it.

7. **Writes are guarded explicitly.** The engine enforces read visibility;
   mutations enforce their own authorization with `db.require(cond, "CODE")`
   before writing. Refusal codes are stable SCREAMING_SNAKE strings.

8. **Unique indexes are constraints.** An insert that would duplicate a unique
   index key is refused by the engine at commit — rely on that rather than
   racy check-then-insert where a unique key exists.
