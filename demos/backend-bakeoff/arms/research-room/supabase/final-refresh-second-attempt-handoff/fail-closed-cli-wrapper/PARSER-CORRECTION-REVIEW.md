## Source evidence and diagnosis

The official status source defines the complete default environment field set
at
[`internal/status/status.go` lines 30–47](https://github.com/supabase/cli/blob/v2.110.0/apps/cli-go/internal/status/status.go#L30-L47).
The first parser revision misspelled `STORAGE_S3_URL` as `S3_STORAGE_URL` and
omitted `REST_URL`, `MCP_URL`, `FUNCTIONS_URL`, and `S3_PROTOCOL_REGION`.
Because every unknown assignment is intentionally fail-closed, any of these
fields makes `unexpected_parser_key` true.

There is a second, start-specific mismatch. The `start` command calls status
with `OutputPretty` unconditionally at
[`internal/start/start.go` lines 48–57](https://github.com/supabase/cli/blob/v2.110.0/apps/cli-go/internal/start/start.go#L48-L57),
so the global `--output env` flag does not change its final credential display.
The current pretty labels are `Project URL`, `Publishable`, `Secret`,
`Access Key`, and `Secret Key`, as defined at
[`internal/status/status.go` lines 245–283](https://github.com/supabase/cli/blob/v2.110.0/apps/cli-go/internal/status/status.go#L245-L283).
The first parser expected `API URL`, `Publishable key`, and an authentication
`Secret key`; therefore it could neither satisfy the required carrier groups
nor classify the authentication `Secret` row.

No raw live output was inspected or recovered for this diagnosis.

## Narrow correction

- Replace the non-carrier environment ignore set with exactly the
  source-defined fields: `REST_URL`, `GRAPHQL_URL`, `STORAGE_S3_URL`, `MCP_URL`,
  `FUNCTIONS_URL`, `DB_URL`, `STUDIO_URL`, `INBUCKET_URL`, `MAILPIT_URL`,
  `JWT_SECRET`, and `S3_PROTOCOL_REGION`.
- Retain only source-defined carrier defaults and the previously reviewed
  explicit Supabase carrier aliases. `SUPABASE_URL`, `SUPABASE_ANON_KEY`,
  `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_PUBLISHABLE_KEY`, and
  `SUPABASE_SECRET_KEY` are generated by the official start/function paths at
  [`internal/start/start.go` lines 1319–1332](https://github.com/supabase/cli/blob/v2.110.0/apps/cli-go/internal/start/start.go#L1319-L1332)
  and
  [`internal/functions/serve/serve.go` lines 142–150](https://github.com/supabase/cli/blob/v2.110.0/apps/cli-go/internal/functions/serve/serve.go#L142-L150).
  Unsourced `SUPABASE_API_URL` and Supabase-prefixed S3 aliases were removed.
- Add exact current pretty mappings: `Project URL` to `api_url`, `Publishable`
  to `publishable_key`, `Secret` to `secret_key`, `Access Key` to
  `s3_access_key_id`, and `Secret Key` to `s3_access_key_secret`.
- Keep every other assignment and every unknown credential-shaped table label
  fail-closed.

The synthetic suite now includes both the complete 18-field environment form
and the exact current start pretty form. All nine containment cases pass; no
real target was started with this corrected revision.
