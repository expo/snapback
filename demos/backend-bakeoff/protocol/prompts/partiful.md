# Neutral build prompt: Partiful-shaped event application

Build the frozen event shell with the assigned backend's idiomatic data model,
auth, authorization, transactions, realtime, storage, scheduled work, effects,
secrets, and deployment path. Do not reuse the earlier comparison matrix's
normalized gateways and do not add a shared provider abstraction.

Use Alice as host, Bob as guest/cohost as each scenario specifies, and Mallory
as outsider. Implement public preview plus private controls, invitations,
yes/no/maybe RSVP and plus-one count, distinct host/cohost/guest/outsider
authority, independently configurable guest-list visibility, concurrent
capacity enforcement, burst-live wall posts and RSVP totals, authenticated
event-art upload/delivery, a scheduled reminder with inspectable idempotent
attempt, and an external notification effect with retry and ambiguous-outcome
evidence.

The local external delivery may be deterministic, but hosted acceptance must
prove the provider's secret/configuration and effect boundary. A fake is never
reported as hosted delivery. Revocation and event removal must stop future
protected delivery and describe retained data honestly.

Run every scenario in `acceptance/partiful.v1.json`; preserve authoritative
receipts, target identity, expected count, transport attribution, effect
attempts, and narrowly scoped cleanup. Stop on an LLP 0102 Stop-class defect.

The timed diagnostic budget is 480 active minutes and 400 tool calls, followed
only by a separately labeled untimed extension.
