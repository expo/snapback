# Guide gap: npm-only Expo app typecheck includes unavailable Exact contract import

**Status:** Open
**Area:** Guide / codegen / npm authoring
**Found while:** Building `demos/tiny-triumphs` from Snapback 0.1.20 npm packages

## Problem

After successful codegen, a normal strict `tsc --noEmit` includes generated
files under `snapback/generated/contract/`. Those files import
`@exact/contract/exports`, but `@exact/contract` is not available from the
public npm registry. An Expo app using only the Snapback React surface therefore
fails typecheck even though its generated API and runtime binding are valid.

## Current workaround

Exclude `snapback/generated/contract` in `tsconfig.json` when the app does not
consume the optional Contract surface.

## Desired guide/codegen outcome

Document the npm-only setup explicitly, or make optional Contract metadata
typecheck-safe without an unavailable dependency. Add a clean-room npm fixture
that runs codegen followed by broad strict TypeScript checking.

## Proposed resolution

Treat the documentation change as mitigation and the generator behavior as the
root defect. Exact-dependent `.contract-meta.ts` sidecars should be a
deterministic, explicit Contract codegen output rather than an unconditional
part of an ordinary React/headless generation. Contract-neutral artifacts —
including `contract-data.manifest.json`, generated function references, and
runtime-link modules that do not import Exact — may continue to be generated by
default.

Contract-enabled projects must opt into the Exact-dependent sidecars through a
committed codegen option or project declaration. Generation must not branch on
whether `@exact/contract` happens to be installed: dependency-presence probing
would make identical source inputs produce different artifact sets.

This is the codegen application of LLP 0021's “Exact should be optional for
core Snapback work” rule. Record the landed output-mode choice as a dated LLP
0021 implementation note; a new LLP is not required unless implementation
uncovers a shared artifact-identity decision that LLP 0021 does not already
cover.

## Acceptance

- A clean external Expo/React fixture installs only public Snapback packages,
  runs codegen without Contract output enabled, and passes broad strict
  `tsc --noEmit` without excluding `snapback/generated/contract`.
- The same fixture's normal lint command does not require an unavailable Exact
  package or a one-off ignore added after generation.
- A Contract-enabled fixture deterministically emits the metadata sidecars and
  still passes the Exact project check and Snapback Contract descriptor tests.
- Generated artifact inventories and freshness hashes distinguish the two
  declared output sets; package presence alone never changes them.
- The guide documents both the explicit Contract opt-in and the temporary
  directory-exclusion workaround for published versions that predate the fix.
