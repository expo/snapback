## Required publication

Publish one matched qualified closure containing every composition owner and
consumer: runtime/CLI, codegen, client, Contract/custody, React, Expo, and the
Familiar/umbrella entrypoints. Bind the external evidence to the exact package
version vector and qualification digest. A source-checkout or mixed
published/local install does not qualify.

## Clean external application matrix

From empty repositories with no package-source inspection, complete the whole
journey in both Explicit and Familiar profiles:

1. install only the published matched closure and scaffold/generate normally;
2. render the ordinary first-party provider and anonymous-ready entry UI;
3. sign up, retain the one-time recovery return deliberately, sign out, sign
   in, and complete a protected read;
4. reload the browser or terminate/relaunch a Phase-2-qualified native process
   and restore the same principal without credential reissuance;
5. sign out, switch users, prove predecessor protected state is blank, and
   exercise recovery consumption/rotation with the exact public return
   contracts.

Retain separate browser Explicit, Expo Explicit, browser Familiar, and Expo
Familiar receipts. A native row may claim only an OS already admitted by the
Phase 2 ticket; otherwise record the expected typed refusal rather than using
custom custody.

## Clique M1 reruns

Rerun the relevant Clique M1 auth lanes against that closure. The application
and agent may not inspect package source and may not introduce an application
`AuthCoordinator`, custom custody adapter, bearer prop/setter, or ordinary
`adoptAuthority` call. Record any correction that requires one of those as a
product failure, not benchmark glue.
