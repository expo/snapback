# 0044 L1-01: asset system tables and storage layer

**Status:** OPEN. **Authority:** LLP 0044 §Internal model, §Publication
and crash recovery; LLP 0007 dated amendment (2026-07-31).

Add the seven Snapback-owned system tables with the 0044 record shapes:
asset (owner, intent id/hash, delivery+access policy, availability,
primary-rendition id, lifecycle/policy generations), upload_attempt
(single-current invariant fields, staging key, transfer facts, closed
states), blob (opaque physical key, SHA-256 digest + algorithm tag,
canonicalization policy, refcount, condemned flag; uniqueness on
(app, algo, digest, policy)), rendition (variant key, blob id, recipe
version, closed states incl. retired), reverse_reference_edge,
publication_record (planned/staged/committed/condemned + retirement),
asset_work_ledger (L1-11 owns semantics). Application schemas cannot
declare or shadow these names. Include the local filesystem store root
under the instance directory (staging/ and blobs/ namespaces, opaque
keys, no app-derived names).

Done when: tables migrate on startup like other system tables, refuse
app-schema collisions with a structured diagnostic, and unit tests cover
the uniqueness constraint and refcount transitions.
