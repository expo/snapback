# Phase-1 D5 evidence receipt carries three stale source hashes

**Status:** Open
**Severity:** P3 (provenance hygiene; no content drift)
**Systems:** Testing, Documentation
**Date:** 2026-08-07
**Related:** LLP 0129 Phase 1,
`tests/acceptance/fixtures/write-lane/phase1-d5-evidence.2026-08-03.v1.json`

## Problem

The retained Phase-1 D5 evidence receipt pins nine `sourceHashes`. Three no
longer match `main` (`data-tier-corpus.mjs`, `derived-overlay.test.mjs`,
`data_tier_corpus_v0.rs`) because of incidental later edits. A full
regeneration at `origin/main` HEAD on 2026-08-06 (Lane-B verification,
detached worktree at `e99d2a328`) reproduced the receipt byte-identical
except for exactly those three hash strings: 37/37 Rust-vs-JS exact, 5/5
multi-table, corpus manifest digest unchanged (`sha256:ec6968a6...`). So
the drift is provenance-only, not substantive.

## Done when

Per the immutable-first-attempt rule, do NOT rewrite the dated v1 receipt.
Land a fresh dated re-verification receipt
(`phase1-d5-evidence.YYYY-MM-DD.v2.json`) generated by the retained script
at a current commit, plus a one-line pointer from the v1 write-up, and
close this ticket. Requires a bootstrapped runtime build; fold into the
next lane that builds one rather than paying a build for this alone.
