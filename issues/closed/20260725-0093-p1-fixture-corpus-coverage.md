`schemas/live.wire-fixtures.v1.json` (generated by
`src/wire_fixtures.rs::wire_fixture_corpus()`, drift-gated through
`artifact_instances()`) seeds the durable-envelope families, the fact-2b
`durable_bytes` case, connection-wide resync, lane-P wrapper framing, the
acknowledged-batch malformed item, and the first two tolerance negatives.
The remaining classes LLP 0093 enumerates are deferred:

- **Malformed capability offers** (coordinate with P-0, which owns the
  offer matrix — these fixtures exercise `direction: client_to_server`
  refusal behavior, a direction the seeded corpus doesn't carry yet).
- **Cancelled/duplicated drains**: duplicate tolerance across the LLP 0059
  ownership cut — needs a multi-step fixture shape (drain, cancel,
  re-drain with overlapping entries), i.e. a `steps` array the v1 format
  should grow compatibly.
- **Arm-mismatch transitions**: attempting `poll/hosted`; hosted subscribe
  before socket establishment (`SNAPBACK_CONNECTION_SOCKET_REQUIRED`);
  socket loss mid-subscribe.
- **Grant-loss recovery**: `SNAPBACK_CONNECTION_TOKEN_INVALID` after local
  idle reap and after hosted grant expiry, asserting LLP 0095 §4.4's
  re-open-and-re-establish-everything semantics.
- **Wrapped/unwrapped parity** for every durable family (today only
  `live_replace` has both framings).
- **Heartbeat/freshness/backoff timing fixtures** — need a virtual-time
  notion the v1 fixture format does not define; growing the format is part
  of this ticket, additive-only (`formatVersion` bumps on any incompatible
  change).

Each addition: extend `wire_fixture_corpus()`, regenerate
(`cargo run --bin snapback-schemagen`), and extend
`tests/wire_fixtures_v1.rs`'s seeded-class census.

## Resolution (2026-07-30)

All six deferred classes landed as **fixture-format v3** (16 new fixtures,
corpus 21 → 37; the P-3 profile classes extend it further in the companion
commit). Design decisions, recorded in LLP 0095 §2.1:

- **`direction: "client_to_server"`** fixtures carry
  `request` (`{method, route, headers?, subprotocols?, body?}`) plus
  exactly one of `refusal` (`{status, code}` — pinned to the shipped
  refusal registry: `SNAPBACK_WIRE_VERSION_{UNSUPPORTED,REQUIRED}`,
  `SNAPBACK_AUTH_INVALIDATION_PROTOCOL_UNSUPPORTED`,
  `SNAPBACK_CONNECTION_SOCKET_REQUIRED`,
  `SNAPBACK_CONNECTION_TOKEN_INVALID`) or `response`; `family` validates
  the request body. Covers the malformed-capability-offer row (both
  open-time body offers and the socket subprotocol offer set, both arms
  verified) — the auth-profile offer negatives ride the same slice in the
  P-3 ticket.
- **Cancelled/duplicated drains**:
  `poll.drain_cancel.redelivered_duplicates_tolerated` — a three-step
  fixture whose redelivered entry is gate-enforced byte-identical.
- **Arm-mismatch**: `arm.hosted_subscribe_requires_socket` (409 refusal),
  `arm.live_hosted_drain_declared_empty_blackout` (T-BLACKOUT, the
  declared-empty `[]` drain), `arm.socket_loss_mid_subscribe` (a
  `client_lifecycle` fixture with the new `{"event": {"kind":
  "socket_lost"}}` step form; the in-flight subscribe resolves DROPPED).
- **Grant-loss**: `grant.connection_token_invalid_reopens_everything` —
  one fixture for both reap and expiry (the refusal is
  origin-indistinguishable, LLP 0095 §4.4), recovery pinned to
  reopen + resubscribe-all + clear-retained.
- **Wrapped/unwrapped parity**: wrapped fixtures for `live_delta`,
  `resync_required` (both scopes), and `current_as_of`, each gate-enforced
  to carry the byte-exact envelope of its core sibling. `durable_bytes`
  deliberately has no wrapped form (it *is* Lane-L framing; its Lane-P
  analogue is the acknowledged-batch malformed item).
- **Virtual time landed** (it fit as an honest format extension — the
  numbers were already normative in LLP 0095 T-HB/T-LOSS): `clock:
  "virtual"` fixtures with `{"advanceVirtualTimeMs": N}` steps and the
  §2.1 rule-4 interval judgment (exact action *set*; timer actions repeat;
  `expect.pacing` bounds spacing). Three fixtures pin 5 s ping, 15 s
  freshness budget, and the 250 ms → 10 s backoff envelope.

`formatVersion` bumped 2 → 3 (a v2 consumer's feed-every-frame judgment
would misjudge the new directions — exactly the incompatible-change case
this ticket reserved the bump for). Consequence: the Swift
`FixtureHarness` accepts 1–2 only and now refuses the corpus at load;
follow-up filed as `issues/20260730-swift-fixture-harness-format-v3.md`.

Verification: `cargo test --test wire_fixtures_v1` (6/6),
`cargo test --test artifact_schemas_v0` (dk7 corpus gates pass; the 3
pre-existing fresh-worktree failures — missing gitignored generated demo
manifests — are unchanged from HEAD), `./ref-check --verbose`.
