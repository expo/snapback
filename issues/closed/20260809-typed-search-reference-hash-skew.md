# Typed `client.search()` refuses same-release generated resource-scoped search references (contract-hash skew in 0.1.15)

**Status:** Resolved
**Severity:** P2 (published-release defect; workaround exists)
**Systems:** Search, Headless client, Codegen, Qualification
**Date:** 2026-08-09
**Related:** LLP 0073, LLP 0136, LLP 0189 (qualification), LLP 0208
(pilot evidence, G-register origin)

## Problem

In published 0.1.15, the typed `client.search()` helper refuses a
generated resource-scoped search reference produced by the **same
release's** codegen:

```
SNAPBACK_SEARCH_REFERENCE_INVALID (contract-generation hash mismatch)
```

Plain `client.query('searchMessages', {args: {conversationId, query: ast}})`
executes the identical search successfully, so the search surface itself
is fine — the typed wrapper's contract-hash binding is skewed against
generated references within a single published version.

Found by the LLP 0201 P2 pilot (snapback lane, M5): a
membership-visible message search declared with `defineSearchQuery` +
`resourceArg`; the builder fell back to hand-built `term*` ASTs through
`client.query()` for the whole app. Recorded in the pilot run log and
scored as a defect discount on B6. (Pilot record lands under
`benchmarks/records/` at P2 close-out; LLP 0208 cites the moments.)

Version skew *inside one release* is exactly the class of escape the
qualification path exists to catch — nothing currently composes the
typed search wrapper with freshly generated references.

## Done when

- The typed `client.search()` accepts resource-scoped references
  generated by the same release (root cause of the hash mismatch fixed,
  not suppressed).
- A regression test composes codegen output with the typed wrapper for
  both plain and `resourceArg` search references.
- The qualified publication path (LLP 0189 scope) gains a gate that
  exercises the typed search wrapper against generated references, so
  this cannot re-escape.

## Resolution

The wrapper compared every reference's complete `argsContractHash` with the
plain `SearchRequestV1` pin. Codegen correctly includes a membership search's
required `resourceArg` in that complete contract, so its hash necessarily
differs even when codegen and client come from the same release.

Generated search references now carry a dedicated
`searchRequestContractHash` for the unchanged request-grammar portion plus the
generated `searchResourceArg` name. The client exact-compares the dedicated
witness, forwards the resource argument, and leaves full generated argument
validation intact. A real-codegen regression composes plain and membership
references through `client.search()`, including strict type checks and a
pre-I/O skew refusal. The canonical proof runs the same composition as the
`typed-search-wrapper-qualification` gate for client, codegen, packaging, and
publication selections.
