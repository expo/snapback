# Deployment-identity staleness has no commit/CI gate

**Opened:** 2026-07-25
**Systems:** Cloudflare, Deployment, CI

## Problem

The committed manifests `cloudflare/generated/deployment-identity.<app>.json`
(apps: `all-aboard`, `notes`; LLP 0049 source-derived deployment identity) are
regenerated by `node cloudflare/scripts/generate-deployment-identity.mjs` from
the deploy inputs: esbuild-discovered transitive Worker bundle sources, the
All Aboard schema manifest, and normalized wrangler/compat configs.

Enforcement lived only at deploy time — `cloudflare/deploy.sh` runs
`scripts/cf-check-compat`, which recomputes the identities and refuses to
deploy on drift. Nothing failed the offending commit, so any landing that
changed deploy inputs without regenerating silently made main un-deployable;
the failure surfaced later, on someone else's unrelated deploy. This recurred
twice on 2026-07-25 alone (most recently 73023273 landed storage/schema
changes after the last regen and left the all-aboard manifest stale).

## Resolution (2026-07-25)

Freshness is now gated on the offending commit, in the same landing as this
ticket:

- `scripts/verify-local-proof` runs
  `node cloudflare/scripts/generate-deployment-identity.mjs --check` alongside
  the other regen-and-diff drift gates (`check-generated-artifacts`), before
  any cargo work.
- New fast CI lane `.github/workflows/deployment-identity.yml` runs the same
  `--check` on every push/PR with only checkout + node + `bun install
  --frozen-lockfile` (esbuild) — no submodules, no Hermes, no Cloudflare
  credentials — so drift fails within minutes.
- The `--check` STALE message now says what to do: run the generator and
  commit the result.
- The stale `deployment-identity.all-aboard.json` on main was regenerated in
  the same commit so the gate starts green.
- `tests/ci_workflows_v0.mjs` workflow inventory updated; LLP 0049 carries a
  dated Revised note and a §Deployment-identity freshness gate section.

The deploy-time refusal in `cf-check-compat` (also exercised by the
`compatibility` suite in `cloudflare/test/local-suite.mjs`) remains as the
last-line guard.
