## Resolution (2026-09-27, lane FK)

A **product race** was reproduced. With the client's server-time estimate
100 ms ahead, the expiry wake re-reads just before the server expires the
row. `evaluateLocal` rejects the already-expired reply, correctly returning
loading, but its first-attempt server branch discarded the deadline without
leaving a wakeup. No new ephemeral epoch or durable sequence is generated by
expiry, so the watch could stay loading indefinitely. The same branch can
be reached by a response that crosses its deadline in transit.

The original LX log has no component timestamps. This controlled race
reproduces its timeout signature; LX's exact offset/delivery order cannot
be reconstructed from that log.

The fix marks rejected server/composed replies for live recovery. A watch
keeps one request in flight and retries with 25/50/100/... ms backoff capped
at 1 s. The expired value stays withdrawn, and every retry runs the ordinary
query, authority, prediction and publication fences. A valid answer resets
the backoff. Removal, closure and sign-out prevent a delayed continuation
from starting another request. One-shot reads keep their existing behavior.
No engine, meter, durable write, timeout or assertion was changed.

The end-to-end fixture holds an explicit estimate 100 ms ahead by suppressing
header/stream clock resampling. At the deadline it replays the last real row
reply once, so even a scheduler wake that misses the 100 ms window exercises
the expired-reply path. Server rows and deadlines remain real. Every
trial now requires an expired reply, while preserving the original empty
answer, <=500 ms appearance, <=4500 ms disappearance, <=4 ephemeral request,
notification-table and unchanged-sequence assertions. Poll answers are
recorded before client consumption, as in lane EK's corrected timing fixture.
