# 0080: live_replace + LLP 0053 inheritance + retention capability

**Status:** Open
**Severity:** P2
**Systems:** Live Queries, Authorization
**Author:** Claude (Fable 5), directed by Charlie Cheever
**Date:** 2026-07-24
**Related:** Accepted LLP 0080 §4, LLP 0053
**Marker:** step5-impl

Register every relational read (including absent unique lookups) as
snapshot-bound DatabaseCaptured inputs; owner plans auth-scoped and all-public
plans authority-partition-scoped (not authorityIndependent); inherit 0053's
obligations, dispositions, ACKs, reconnect, and denial handling;
table-granular invalidation with no skip or live_delta claim; retention as
the closed default-deny capability (none | opaque-authorized-snapshot-v1
with an authenticated lease; anonymous results retain nothing); capability
artifacts record all of it. M/L-sized.

**Progress (2026-07-25):**

- Input registration reconciled: relational reads run inside one pinned
  snapshot and deliberately capture no Query-kind dependency — the live
  matcher's dedicated relational arm is table-granular over both declared
  sources, so any commit to either table (including the
  absent-unique-lookup direction) resnapshots. Witness:
  `relational_live_replaces_on_both_tables_and_never_claims_delta` (both
  tables trigger `live_replace`; no `live_delta` is ever claimed; the
  previously missing joined row appears in the replacement).
- Scoping: owner plans capture the Auth dependency (auth-scoped);
  `validate_authority_independent` already refuses any relational runtime,
  so an all-public relational plan can never claim `authorityIndependent`
  — now witnessed at load
  (`relational_live_narrowings_hold_at_load`). Obligations, dispositions,
  ACKs, reconnect, and denial handling are inherited by construction: a
  relational subscription is an ordinary live subscription; the
  obligation-fault e2e belongs to the acceptance corpus.
- Retention: default-deny landed with an honest reason — a retainable
  relational declaration refuses at load with
  `SNAPBACK_AUTH_UNDECLARABLE_RETENTION` / `relationalRetentionNone`
  (previously the misleading `opaqueJavaScript`); RQS/resume-token
  eligibility and the lease path already exclude relational plans.
- Capability artifacts: the manifest now carries a `relationalQueries`
  fact block — `{ liveDelivery: "live_replace", retention: ["none"] }` on
  targets that support `relational_query_v1` (local + remote-service),
  explicitly absent on Cloudflare, whose machine-readable refusal stays
  the capability gap. Committed manifests + schemas regenerated.

**Resolution (2026-07-25, flip-closure):** `retention:
'opaque-authorized-snapshot-v1'` is admitted end to end — the
`defineRelationalQuery` `retention` spec field (closed two-value
vocabulary; the lease class requires an owner-visible output and emits
`retainable` + `authorizationDependence ['UserId']` + the relational read
summary), `validate_retainable_query`'s relational admission
(`relationalAnonymousRetention` for all-public plans, summary/dependence
proven), and the authorized-lease capture/sign/reserve path under a real
Sessions authority, with the continuation cursor kept off the lease
envelope. Capability facts record both classes. The obligation-fault e2e
landed: a lost shrinking replacement on an owner-visible relational
subscription is recovered by the level-triggered obligation
(reprojection + managed rerun + exact-ACK discharge), never left as
forbidden visible rows and never a `live_delta`. Witnesses:
`relational_retention_lease_class_admits_and_captures`,
`relational_retention_admission_is_default_deny`,
`relational_shrinking_replacement_is_obligation_backed_and_recovered`.
Remaining here: only the two-instance authority-rotation fencing e2e
variant (single-instance rotation fencing is covered by the 0053
machinery witnesses; the two-instance form rides the hosted arms).
