## Commission

Charlie ratified LLP 0146's D1–D3 first tranche for implementation at
author decision sitting #2. Scope, exactly as the RFC defines the three
decisions:

1. **D1 — declaration/observation conformance**, with the sitting's OQ1
   ruling applied: **strict mode is opt-in for newly generated apps** —
   a newly generated app does not opt in by default; strict-mode
   authoring is the opt-in surface for new and legacy apps alike.
2. **D2 — `snapback verify`, the done-oracle**, as the RFC defines it
   (CLI-orchestrated; not the pinned `acceptance.run` host operation).
3. **D3 — the agent digest**, as the RFC defines it.

The sitting also ruled OQ8: the Cloudflare fan-out stays **conservative
widening** for now — no hosted claim in this tranche is gated on
recovering fan-out precision.

## Boundary — OQ7 was NOT ruled

The sitting deliberately did not rule OQ7 (the CV-14 custody trigger in
the 0062 family). Implementation of this tranche **must not claim CV-14
custody satisfaction** without the custody owner's ratification. Any
D4-adjacent digest/verify work that would imply CV-14 custody stops at
an honest nonclaim.

## Exit

- D1 (strict-mode opt-in authoring), D2, and D3 implemented per LLP
  0146's decision text, with their acceptance obligations as tests.
- Capability/GAP rows updated honestly; no claims for the unratified
  D4–D7 remainder.
- Dated implementation-record amendment in LLP 0146 at landing.

## Progress log

### 2026-08-03 — D1 landed (report + strict-mode opt-in), first slice

**Landed.**

- **D1 surface 1 (report, v0):** `src/conformance.rs` —
  `DeclarationConformance` with the four class-tagged deltas
  (`missingReads`/`missingWrites`/`extraReads`/`extraWrites`) and per-class
  `readProvenance`/`writeProvenance` (`complete`/`incomplete`/`unsupported`),
  scoped to application tables (auth/permission captures and reserved
  projections excluded). Attached to the admin runner's `FunctionRunResult`
  on every arm (queries/mutations `complete` on success, `incomplete` on
  failure and pre-invocation refusals; actions `unsupported` always), to the
  `function.run` host-op envelope (`data.conformance`), and to the
  `app.inspect` recent-invocation ring — **scoped to host-op invocations**,
  the RFC's stated v0 fallback.
- **D1 surface 3 (strict mode, opt-in per app):**
  `defineSchema(tables, { strictDeclarations: true })` →
  `strictDeclarations` on the schema manifest (absent unless true; rides the
  schema hash via the schema evaluation) → enforcement at the two shared
  Ibex runtime seams (`run_ibex_query_with_reads_prepared`,
  `execute_ibex_mutation_prepared`), which every fresh/staged/nested/
  detached invocation path passes through, before result handoff and before
  any commit. Refusals: `SNAPBACK_HANDLER_UNDECLARED_READ` /
  `SNAPBACK_HANDLER_UNDECLARED_WRITE`, details naming function, table,
  declared set, and the declaration's source span. OQ1 ruling honored:
  default off for newly generated apps (test-pinned). HostPlan runtimes are
  exempt by construction (declared sets derive from the plan); declaration
  facts ride `PreparedInvocation` immutably.
- **Tests:** `tests/conformance_v0.rs` (8 tests: undeclared-read report
  with complete provenance; read/write swap reports both classes; action
  `unsupported`; strict read refusal with named code + span; strict write
  refusal with no durable-version advance; declared-conformant handler
  serves under strict; default posture stays evidence) and the
  `strictDeclarations` authoring block in
  `packages/snapback-codegen/authoring-validation.test.mjs`.
- **Docs:** dated implementation record in LLP 0146's Revised header +

**Remaining in the tranche (precise next steps):**

   artifact freshness/identity → runtime readiness receipt → admission +

### 2026-08-04 — D2/D3 v0 implementation, honest partial closeout

**Implemented; tranche remains open for the residue below.**

- **D2 command and receipt:** `packages/snapback-cli/verify.mjs`,
  `verify.d.mts`, and `verify-receipt.schema.json`, wired as
  `snapback verify [backend] [--config ...] [--receipt ...] [--json]`.
  The receipt has the RFC's five fixed stages: source-regenerated artifact
  freshness/identity; LLP 0010 digest-bound runtime-readiness verification;
  schema/function admission plus D1 coverage; capability resolution; and
  registered acceptance profiles. It binds the profile-set identity, the
  config and actual test-file bytes, artifact target/data/authority/seed
  context, stage evidence, profile results, and ordered `next[]` actions.
  `recommendedNext` is emitted only for exactly one failed stage. No code was
  added to the `acceptance.run` host-operation registry.
- **D1 surface 2 choice:** the minimal honest aggregate covers every path an
  acceptance profile explicitly registers, using the closed path classes from
  the RFC and the exact six-field D1 report. A missing report and authoritative
  `missingReads`/`missingWrites` fail. Observed `incomplete`/`unsupported`
  provenance is retained as an explicit partial rather than called conformant;
  over-declaration is a warning only for the intersection of extras over every
  complete class observation for the function, so a conditional read does not
  become a false warning. A
  run with no profiles can pass platform checks but says
  `no-registered-acceptance-paths` and makes no coverage claim. This slice did
  not invent automatic discovery for the repository's heterogeneous existing
  suites because they have no universal profile/path-evidence registry.
- **D3 digest:** `packages/snapback-app-cli/digest.mjs`, `digest.d.mts`, and
  `agent-digest.schema.json`, wired into `snapback-app introspect` with
  `--changed-since`, `--budget-bytes`, and `--budget-items`. The static section
  is keyed by the served envelope hash (or an explicitly named deterministic
  local projection identity) and the cursor carries its item hashes, enabling
  stable minimal item diffs without retained server state. The dynamic section
  is keyed by the cursor, values and raw diagnostic details are excluded,
  ordering is stable, and budget elisions name the omitted section/count and
  how to ask for more. Bare envelope hashes retain LLP 0062 compatibility.
  Unknown and structurally expired cursors degrade to a named full digest.
- **OQ10 v0 choice, visible:** dynamic observation state uses
  `coarse-resolution-v0-no-observation-retention`; the dynamic section is sent
  whole, v0 cursors carry no expiry, and no observation history is retained.
  This appears in every digest, the guide, and LLP 0146's dated implementation
  record; it is not a silent custody choice or a claim that long-term cursor
  custody is settled.
- **Tests:** `packages/snapback-cli/verify.test.mjs` covers the five independent
  failure conditions and next actions, unique/non-unique recommendation,
  identity/test-byte binding, read/write class separation, under-declaration,
  conditional aggregate extras, partial unsupported versus missing coverage, no-profile
  nonclaim, and real fresh/stale regeneration. `packages/snapback-app-cli/
  digest.test.mjs` covers byte identity, stable ordering/value exclusion,
  unchanged/bare/unknown/expired cursors, minimal schema delta, removed keys,
  byte/item elision, coarse dynamic replay, and redacted D1 verdicts. Both are
  registered in the package scripts and canonical 189-file inventory.
- **Capability truth:** `operating.verify` is a new partial local row;
  `operating.declaration-conformance` now names registered-path aggregation
  and its automatic-discovery GAP; `clients.app-cli` names the D3 projection,
  coarse fallback, and unavailable public observations. The pages explicitly
  disclaim live-target admission, hosted scope, `acceptance.run`, product
  completion, and CV-14 custody. D4–D7 remain untouched.

**Honest remainder before this tranche can close:**

- D2 admission and capability resolution currently prove the freshly
  regenerated local artifact set and its generated target profile. They do not
  fetch and bind a live served target's admitted generation/capabilities. The
  receipt states this nonclaim.
- D1 surface 2 aggregates all paths registered in the verify config, but no
  repository-wide adapter automatically registers every legacy/demo
  acceptance path. Unregistered suites are outside the coverage claim.
- The app-data/public inspection plane does not expose per-table row-count
  magnitudes or D1 recent-invocation verdicts. D3 emits stable unavailable
  items with named reasons instead of omitting or fabricating them. Supplying
  those two redacted observations without giving `snapback-app` admin
  authority remains required for the full D3 contents list.
- The existing D1 residue above remains: incomplete `function.run` mutation
  envelope provenance, no app-data-plane invocation ring, and no authoritative
  Cloudflare capture/reporting. Cloudflare does not enforce strict mode; it now
  refuses the opt-in before admission, and v1 has no escape-class vocabulary

### 2026-08-04 — sitting-#3 strict-target refusal implemented

**Implemented.**

- The Cloudflare arm now refuses `strictDeclarations: true` with
  `SNAPBACK_STRICT_DECLARATIONS_TARGET_UNSUPPORTED`. The message names
  `cloudflare-do-sqlite-v8` and directs the author to remove the flag or use an
  enforcing target.
- Both admission seams are covered: the deploy-time compiled schema is checked
  at module load, before any Durable Object or data-plane route can exist, and
  `/app/ensure` checks a posted schema before identity comparison, seeding, or
  any other effect. The All Aboard adapter now carries the generated manifest
  flag into the compiled schema instead of dropping it.
- The shared admission test pins the refusal code/details/message, admission of
  the absent/default flag on Cloudflare, and continued admission of
  `strictDeclarations: true` on the enforcing `local-dev-sqlite-ibex` target.
  Codegen's selectable target profiles remain the local and remote Ibex arms;
  both enforce at the shared runtime seams, so there was no non-enforcing
  codegen admission path to modify. The broader OQ14 capture-authority question
  remains open.
