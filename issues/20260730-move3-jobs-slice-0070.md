LLP 0127 move 3 ("Deterministic re-execution is one substrate") names *slice
3-jobs* as one of two separately named pilots: "the CV-9 jobs slice
(rolled-back mutation provably schedules nothing; injected-clock drain),
owner LLP 0070, startable now with the callee-class decision (0121 OQ2) made
inside it." The RFC's closing enumerates it as startable today with no
author decision. The design is not missing — it is LLP 0070 (durable
background work, Draft), which specifies `ctx.jobs.enqueue` with validation
and insertion in the same database transaction as the mutation's ordinary
writes, `availableAt` delays, attempt policy, idempotency keys, and its own
receipt family (immutable job + append-only attempts) — one-off work gets
0070's receipts, not the cron ledger (0115 open question 2, answered v0.2).
Implementing the slice simultaneously gives 0070 the executable evidence its
Draft status needs.

Work items (per 0115 CV-9 and 0127). (1) Implement the `runAfter` case as
the first slice of LLP 0070's `durable-work-single-process-sqlite-v1`
profile: default queue, `availableAt = now + delay`, transactional enqueue,
host-plan action callee. (2) The deterministic forced-drive test seam 0070
lacks and 0028 has: amend 0028's manual-tick/disable pattern into a sibling
injected-clock `jobs` drain so acceptance never sleeps (the 0028 test-seam
amendment). (3) Name the callee-class decision explicitly inside the slice
(0121 OQ2): whether Dispatch's one-off action-to-mutation shape fits 0070
v1's generated-host-plan-action admission or needs the later broader-action
capability. (4) The enqueue-association receipt as proposed in LLP 0121
option 3 — the job row carries producer `mutationId` and `snapshotVersion`,
or the mutation receipt embeds its enqueues — plus the generated *declared*
job-status query (an ordinary declared operation with an ordinary contract,
not an ambient system table; 0127's proposed answer to 0121's
inspection-surface question). The paved-default-queue conditional and the
inspection-surface question travel with this ticket, per 0121's relationship
section and 0115 §Sequencing 2. Exit per 0115 CV-9, verbatim: "The Dispatch
arm's one-off path uses the new primitive; a rolled-back mutation provably
schedules nothing (0070's own first acceptance bullet); an injected-clock
forced drain claims due one-off jobs with receipts in the job/attempt
ledger, giving one-off work a deterministic seam equivalent to — not
literally identical to — the cron run ledger's."

## Execution record (2026-07-31, in-branch — pending landing)

Implemented in the wave-1 C2 worktree branch. What landed, against the work
items above:

1. **The `runAfter` slice.** `ctx.jobs.enqueue(action, args, {delayMs,
   idempotencyKey, maxAttempts})` from JS mutations; buffered like writes and
   inserted inside the mutation's own SQLite transaction
   (`src/jobs.rs::insert_enqueued_jobs_in_tx`, called from the buffered
   commit in `src/storage.rs`); rollback and dry-run leave no job. Paved
   `default` queue, `availableAt = now + delay` on the frozen invocation
   clock, scoped idempotency keys (identical-reuse returns the existing job;
   divergent reuse fails `SNAPBACK_JOB_IDEMPOTENCY_KEY_REUSED`; commit-time
   race fails `SNAPBACK_JOB_IDEMPOTENCY_KEY_RACED`), bounded attempt policy
   with the RFC's v1 jitter profile, fenced claims, append-only attempt
   receipts, lease-expiry successor claims.
2. **The deterministic drain seam.** `POST /_snapback/api/jobs/drain`
   `{nowMs?, maxWaves?}` — set-based injected-clock claim/execute/publish
   with synchronous receipts; bounded waves (cap 16); claim order pinned
   (availableAt, then job-id bytes); job ids ride the ctx-answer ledger so
   identity is replay-stable; finish/retry clocks reuse the injected drain
   clock. Autonomous worker = its own 1 s loop, `SNAPBACK_JOBS_DISABLED`
   sibling switch (0121 OQ5).
3. **Callee class named (0121 OQ2, decided):** manifest-declared actions of
   both runtime forms (HostPlan and Ibex) under the host envelope — the
   Dispatch action→mutation shape fits; direct mutation/query callees fail
   closed as the later broader-callee capability.
4. **Association + inspection.** Both option-3 halves: job rows carry
   `producerMutationId`/`producerSnapshotVersion`/`producerFunction`; the
   confirmed mutation receipt embeds bounded `enqueues` facts (rejected
   receipts never do — inspectable rollback evidence). Spec text in
   `llp/0070-durable-background-work.amendment-2026-07-31-first-slice.md`
   (proposed amendment; 0070's Draft body untouched). Inspection: generated
   declared job-status live query (`defineJobStatusQuery` →
   `HandlerPlan::JobStatusQuery`) + admin list/show. Capability facts:
   `jobs_one_off_v1`, experimental while 0070 is Draft; codegen emits the
   requirement + acknowledgment; no durable-background-work class claimed.

Exit criteria: rollback-schedules-nothing and injected-clock-drain-with-
receipts are pinned by `src/server.rs` tests
(`rolled_back_mutation_schedules_nothing`,
`forced_drain_claims_due_jobs_exactly_once_with_receipts`), the state-machine
corpus by `src/jobs.rs` unit tests, live job-status delivery by the
`src/local.rs` test, and the codegen surface by
`packages/snapback-codegen/jobs-authoring.test.mjs`. The Dispatch-arm
demo-port itself (the diary-visible rerun evidence) is successor work for the
rerun, per 0115 §Sequencing.
