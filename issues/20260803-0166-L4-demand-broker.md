# 0166 L4 — the multi-context demand broker

**Status:** Open (program: `20260803-0166-impl-program.md`; requires
L2; coordinate with L3/L5 on writer-side files)
**Spec:** LLP 0166 §D2 (The multi-context demand broker — the four
message records and every rule)

Scope:

- The closed message records (`DemandAnnounceV1`, `RegisterForwardV1`,
  `RegisterReleaseV1`, `RegisterOutcomeV1`, `WriterHelloV1`) with
  message-level refusal everywhere.
- Never-reused CSPRNG `contextId`s; per-`(contextId, partition)`
  full-set announces with monotone revisions; heartbeat liveness (15 s
  interval / 45 s expiry; any well-formed message refreshes; empty set
  at higher revision = release).
- The three durable memories + roster: `(contextId, partition)` pair
  roster (64 contexts / 128 pairs), reaped-context memory (256),
  consumed-request memory (1,024, keyed per-context), partition-keyed
  released-registration tombstones (1,024; success-only creation);
  `writerGeneration` echo on durable mutations; 64-byte identifier and
  256 KiB message ceilings.
- Handoff: `WriterHelloV1`, roster reconciliation with **pair-level**
  45-second deadlines (no timeout exit; pair reap ≠ context reap; the
  normative re-announce-on-hello client rule), full suppression of
  demand-derived transitions, suppression-end grace anchoring.
- Carrier qualification: browser cross-tab channel + Web Locks
  presence; the file carrier's honest volatile-online degradation
  (no cross-process channel — 0166 OQ12 stays open).

Done means: S1's broker legs pass in full — two-tab demand protection,
reaping, stale/reaped-id ignores, multi-partition announces,
writer-crash-before-outcome retry from durable state, cross-partition
release refusal, release-before-first-forward tombstone refusal with
the same-id-different-partition non-preemption leg, both named overflow
schedules at exact 1,024/1,025 boundaries, partial-handoff pair-deadline
reap, 129th-pair refusal, malformed-announce nothing-applies; S4 stays
green.
