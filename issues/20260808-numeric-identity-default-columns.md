# No portable numeric identity/default columns (PostgreSQL GENERATED AS IDENTITY)

**Opened:** 2026-08-08 · **Severity:** P2 (schema-surface gap with a measured scale cliff)

The pinned Zerobugs `issue.shortID` is `GENERATED BY DEFAULT AS IDENTITY
START 3000` — not cosmetic (permalinks and notifications require it) — and
Snapback tables have no numeric identity/default declaration. The control's
`W-SHORTID` workaround (bounded first-unused scan) works only under 1,024
rows and now **refuses issue creation entirely at the million-issue store**
(typed refusal `ZBUGS_SHORT_ID_BOUNDARY`; zb5-hot v9/v10 receipts). Any app
porting a relational schema with serial/identity columns hits this.

Ask: a portable server-owned numeric identity/default column declaration
(monotonic, transactional). Removes W-SHORTID and its large-corpus GAP.
Related: `W-ENUM` (stored literal-union domains) is the same class of
"portable relational schema surface" gap — tracked in
issues/20260808-stored-literal-union-enums.md.

## Disposition 2026-08-08 — NOT implemented; author-gated. Ticket stays open.

Orientation found this ticket is already governed, twice over, and building a
`v.serial()`-style column now would have overridden a same-day author ruling
and contradicted an Accepted Spec. Recording the chain so the next session
does not re-derive it:

1. **LLP 0191 §3 already designs this**, and designs it *differently* from the
   obvious reading of this ticket. It calls for "identity columns (server-owned
   monotonic numerics with **sequence** semantics — gaps allowed, rollback
   burns values; a gapless transactional counter would serialize all writes to
   the table and recreate a scale cliff at exactly the store size that exposed
   `W-SHORTID` — and normally a secondary display/permalink identity, with
   client-generable ids remaining the safer canonical key for local-first
   creation)". So "monotonic **and** transactional/gapless" is the wrong target:
   the gapless version reintroduces the very cliff this ticket reports.
2. **Charlie ruled on the structure on 2026-08-08** (LLP 0191 "Author rulings"
   #2, OQ2 — ruled *distributed*): one coordinating identity-architecture
   Decision LLP fixing the identity vocabulary — namespaces, provenance,
   uniqueness, mutability, conversion rules — with implementation distributed
   to owners as amendments, and **this ticket is explicitly named as the schema
   owner's lane** in `issues/20260808-identity-architecture-decision.md`
   alongside declared source keys, defaults, and alternate-key lookup. OQ5's
   ruling sequences that Decision before the schema-surface work, one Zerobugs
   port acceptance corpus covering all three lanes.
3. **Accepted LLP 0135 already owns framework counters** and its v1 fences both
   halves of the ask: §1.1 pins "JavaScript-safe integers, first value 1,
   step 1, **no authored start**, step, or format", and §1.9 lists "any
   cross-scope or **global** counter" as not lifted. A table-level identity
   column is exactly a global counter with an authored start. §1.1 also rejects
   a self-owned second counter authority with rationale (two authorities that
   can disagree about one row's identity), so `_snapback_sequence_counters_v1`
   is the counter substrate any design here must extend rather than duplicate.

### Design groundwork, for the Decision and the schema-owner amendment to consume

Done so the ruling is one decision rather than a research project. Every item
below is a *proposal*, decided nowhere:

- **Substrate.** Extend LLP 0135's `_snapback_sequence_counters_v1` with a
  table-scoped (rather than row-scoped) counter identity, under a successor
  profile version of `sequence_allocation_v1`. Do not mint a second counter
  table. LLP 0135 OQ2 (more than one allocation per invocation) is a
  prerequisite for bulk insert.
- **Semantics.** Sequence semantics per LLP 0191 §3: strictly increasing, gaps
  allowed, an aborted or rolled-back mutation burns its value. This is what
  keeps allocation off the table's write-serialization path; it is also the
  observable difference from LLP 0135's dense, gap-free counters and must be
  spelled in the vocabulary the Decision fixes.
- **Client-supplied values.** PostgreSQL's `GENERATED BY DEFAULT` admits
  explicit values and is a well-known desync footgun. Proposal: **server-owned
  always** — the field is not writable by handlers, and supplying it in an
  insert or patch refuses with a stable code. This is `GENERATED ALWAYS`
  semantics under a `BY DEFAULT` spelling; the deliberate divergence, and the
  legacy-import case it forecloses, belong in the Decision.
- **Bound and exhaustion.** LLP 0007's JavaScript-safe integer profile bounds
  the stream; successor exhaustion refuses fail-closed before the mutation
  tier, mirroring LLP 0135 §1.5 and the commit-version precedent.
- **Uniqueness and indexing.** No implicit index (LLP 0007's Index Contract);
  the author declares one. Note LLP 0110's uniqueness-prefix rule if the value
  is ever stored under a constraint on an incarnation-scoped table.
- **Evolution.** Adding an identity column to a **non-empty** table is the
  interesting case. LLP 0007 §Schema Evolution admits a newly added required
  field only on an empty table "until the schema language gains a portable
  default/backfill expression", so v1 should either refuse on non-empty tables
  with a pointer to LLP 0081's reviewed `AddField` + backfill lane, or ship a
  portable in-transaction backfill ordered by `(_createdAt, _id)` — portable
  across engines, unlike `rowid`/`ctid`. This is the one place the Decision
  should expect real cost.
- **Naming.** `v.serial({ start })` reads correctly to anyone porting a
  relational schema and avoids the codebase's already heavily loaded
  "identity" (auth identity, stream identity, artifact identity, and
  `v.principal()`). The Decision owns the final spelling.

## Author ruling — 2026-08-10

The design groundwork above is endorsed wholesale: extend LLP 0135's
`_snapback_sequence_counters_v1` (no second counter authority); sequence
semantics per LLP 0191 §3 (strictly increasing, gaps allowed, an aborted or
rolled-back mutation burns its value); **server-owned always** (a
client-supplied value refuses with a stable code — `GENERATED ALWAYS`
semantics under the `BY DEFAULT` spelling); v1 refuses adding the column to
non-empty tables; `v.serial({ start })` is the working spelling, with the
final name owned by the Decision. Greenlit now: write the coordinating
identity-architecture Decision
(`issues/20260808-identity-architecture-decision.md`) with this ticket as its
first schema-owner amendment. An import-time escape hatch for preserving
legacy numeric values may be designed later if demand appears; it is out of
v1.
