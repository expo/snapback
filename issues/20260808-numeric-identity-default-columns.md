# No portable numeric identity/default columns (PostgreSQL GENERATED AS IDENTITY)

**Opened:** 2026-08-08 · **Severity:** P2 (schema-surface gap with a measured scale cliff)

The pinned Zerobugs `issue.shortID` is `GENERATED BY DEFAULT AS IDENTITY
START 3000` — not cosmetic (permalinks and notifications require it) — and
Snapback tables have no numeric identity/default declaration. The control's
`W-SHORTID` workaround (bounded first-unused scan) works only under 1,024
rows and now **refuses issue creation entirely at the million-issue store**
(typed refusal `ZBUGS_SHORT_ID_BOUNDARY`; zb5-hot v9/v10 receipts). Any app
porting a relational schema with serial/identity columns hits this.

Ask: a portable server-owned numeric identity/default column declaration
(monotonic, transactional). Removes W-SHORTID and its large-corpus GAP.
Related: `W-ENUM` (stored literal-union domains) is the same class of
"portable relational schema surface" gap — tracked in
issues/20260808-stored-literal-union-enums.md.
