# Inventory: public test-support bypass surface

**Status:** Open — inventory and triage only

**Opened:** 2026-08-24

**Systems:** Rust public API, Cargo features, auth, storage, engine, realtime

**Governing:** LLP 0285, LLP 0290, LLP 0291, LLP 0303
**Audited source:** `2d534c67db0896e2efad7855713122a73c2cb438` (`origin/main` when this checkout was handed over)

This is a source inventory, not an exploit execution record and not a refactor. No Snapback behavior was executed. The classifications below answer whether the public source item itself adds authority beyond the production path; they do not treat a Cargo feature, `#[doc(hidden)]`, or a test-like name as a boundary.

The four review blocks motivating this inventory were a second-database seal accepted by a live coordinator, caller-selected bearer/subject binding, caller-selected exact grants, and admission/attempt restapling. Three names from those in-progress lanes — `bind_email_session_bearer_for_test`, `insert_exact_grant_for_test`, and `with_admission_for_test` — and the cited `Bound*Attempt::for_test` constructors are not present at the audited commit, so they are motivation, not counted rows. The current `insert_email_session_for_test` is present and is counted.

## 1. Method

I enumerated `crates/*/src/**/*.rs` in two independent ways:

1. A lexical `rg` pass found every direct declaration matching public functions or methods whose name ends in `for_test`. It found **254 unique declarations**.
2. A small read-only `syn` syntax walk collected public functions, methods, structs, enums, consts/statics, trait impls, modules, and `pub use` declarations under a `test-support` gate. It propagated gates from parent modules and impl blocks, followed the two feature-gated external public modules (`snapback_engine::test_support` and `snapback_kernel::storage::commit_capsule_prototype`), and separately checked fields, variants, aliases, traits, and associated constants/types.
3. I took the union by source exposure (`file`, declaration line, kind, qualified name), read the declaration/body and its immediate producer/consumer path, then assigned exactly one class. A module or re-export is separate because it is a separate reachability edge; it inherits the strongest authority class it exposes. Mirrored `LocalDatabase`/`ServingDatabase` methods are also separate. I likewise count the 11 fields whose `pub` visibility itself is switched on by `test-support`: Rust does not call a field an item grammatically, but omitting those independently enabled downstream write/read edges would make this attack-surface inventory incomplete.

Classification rules used here:

- **A — inert:** observations, constants, pure validation, or fail-closed instrumentation. Fault hooks are A only when they cannot create authority or a trusted successor state.
- **B — invariant-preserving:** the same caller can obtain the same result through a public production operation, or the item only transforms an opaque/already-admitted input without restapling it to a different owner. The commit-capsule prototype is B because it is database-bound and writes only its `_test_*` prototype tables, for which no production consumer exists.
- **C — bypass:** caller facts, a caller-selected backend/owner, or the invocation itself can create, attach, replace, or durably alter state that a live component treats as authority or trusted state, without the production predecessor that should prove it.
- **D — unclear:** insufficient source evidence. I did not use D merely because a seam is complicated.

The user's approximate per-crate list omitted `snapback-services` and `snapback-runtime`; it also expected three server suffix declarations, while the audited tree has four.

What this may miss:

- public items generated only after macro expansion or `include!` whose declaration is not present as a source item under `crates/*/src`;
- a gate expressed through a project-specific cfg alias rather than a literal `feature = "test-support"` predicate;
- public bypasses with neither a `for_test` suffix nor a `test-support` gate (outside this task's universe);
- in-progress lane code absent from the audited commit.

The scan found no `cfg_attr(...test-support...)` occurrences. Items gated only by `#[cfg(test)]` or another feature are included only when their public function name ends in `for_test`, as required by the first enumeration rule.

## 6. Recommendation by fix shape

The per-row recommendation is in the class-C table. Across the surface, the smallest coherent fix program is:

1. **Derive inputs at the live owner:** identity, session, grant, mode, registry, database, connection, and authority facts should come from a live admitted predecessor, not parallel scalar parameters.
2. **Remove raw parameters:** where a fixed negative fixture is enough, remove caller-selected IDs, identities, hashes, clocks, dispositions, schemas, and backends. Keep the fixture incapable of naming production state.
3. **Seal constructors and consumers together:** make privileged plans/publications/authorities private-field opaque values, bind them to the producing database/controller/registry instance, and have the consuming operation verify that binding.
4. **Move true fixtures to `#[cfg(test)]` in the owning crate:** cross-crate acceptance should drive production ceremonies or use a non-shipping harness process; it should not require a public raw writer on the library type.
5. **Replace aggregate modules with an A/B allowlist:** `snapback_engine::test_support` should not re-export a mixed namespace where observation helpers and authority constructors share the same downstream-enabled feature.

No fixes are implemented by this inventory.
