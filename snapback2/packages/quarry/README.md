# quarryc

`quarryc` is the provisional Quarry v0.2 front end for Snapback 2. It parses
the paper notation, emits the packaged TypeScript authoring surface, and then
gets out of the way: `snapback2 check`, `dev`, `test`, the client, and the React
hooks remain unchanged.

```sh
bun packages/quarry/src/cli.ts ./my-app
# or, when installed as a workspace bin:
quarryc ./my-app
```

Source files live in `snapback-quarry/*.q`. Generated files live in
`snapback/`, carry `// GENERATED by quarryc ...` headers, and attach a
`// q:<file>:<line>` comment to every emitted statement. A refusal is printed
as `<file>.q:<line>:<col> — message`; any refusal makes the command atomic and
nonzero. A generated file may be refreshed, but a hand-written `.ts` collision
is never overwritten. `seed.ts` and `tests/` are therefore untouched.

## The packaged-worker filename bridge

The existing worker requires `snapback/schema.ts` and derives API namespaces
from names such as `snapback/todos.ts`. Quarry's output contract requires
`schema.q.ts` and `todos.q.ts`. Until the worker has an ignore/alias concept,
`quarryc` emits both:

- `<name>.q.ts` is the required, fully generated Quarry output;
- `<name>.ts` is an identical generated compatibility copy used for the
  existing `api.<name>.*` namespace;
- `schema.q.ts` contains the generated schema plus one harmless
  `schema.q.__quarrySource` query, because the unchanged worker refuses every
  top-level `.ts` module that exports no operation.

This means the temporary bridge exposes `.q`-namespaced copies of operations
to the manifest. It is deliberate and tested, but it is a known cost rather
than a new platform contract. Generated code is not committed by the fixture
tests; each test compiles into a scratch app.

## Pinned v0.2 lowering

These rules are provisional pending Quarry v0.3.

### Schema and types

- `table name:` becomes `table({ columns, indexes, rules })`; `id` and `byId`
  remain platform-provided and must not be declared.
- `text <=N`, `int`, `time`, `bool`, and `enum('a', 'b')` become the matching
  `t.*` builders. A table name is `t.ref(table)`. `?` wraps the type in
  `t.optional`. `[users] <=50` becomes
  `t.list(t.ref(users), { max: 50 })`.
- `id` is accepted as a bridge scalar and becomes `t.id()`. v0.2 does not name
  this spelling, but the shipped todos template has a principal-owned
  `ownerId` without an application users table; omitting it would make a
  faithful translation impossible.
- `by a, b` is named `byAB`; `by activity: a, b` keeps `activity`. `unique a,
  b` creates the unique index `byAB`. Duplicate inferred names refuse.
- `use identity` enables both packaged password and guest auth. No identity
  tables are synthesized.
- A `public` line emits `rule.public` with a generated reason. Other rules use
  only `public/allow/deny`, `eq/ne/and/or/not/exists/viewerIs/field/literal`.
  An update rule may inspect the `next` binding, but any `old`/`next`
  comparison refuses because the packaged combinators cannot represent it.
- `channel name(args)` becomes `channel({ args, publish, subscribe, ttlMs })`;
  TTL seconds are multiplied by 1,000. Channel arguments are direct
  `rule.field` terms in admission rules.

### Programs, reads, and indexes

- `query` and `mutation` become inert `query({...}, handler)` and
  `mutation({...}, handler)` descriptors. The final expression is returned.
- `t[x]` becomes `db.get(t, x)` when `x` is a typed reference/id. A complete
  unique key becomes `db.get(t.byName, [keys...])`; `exists` selects the same
  target and calls `db.exists`.
- A named bracket key (`t[col = value]`) matches declared index columns.
  Positional selection matches key types against declared orderings. Multiple
  matches refuse and name every candidate; authors resolve it with
  `by <index>` or named keys.
- A range becomes `db.scan(index, [prefix...], { order, take, after })`.
  `first` is ascending and `last` descending. `before cursor last N` is pinned
  to descending plus `after: cursor`, matching the current platform cursor
  convention. `before ... first` refuses.
- Range bounds are integer literals. Empty or ambiguous prefixes must name an
  index.
- `walk t[seed] up .parent depth N` becomes a bounded `recurse` domain with
  `fanout: 1`, consumed by an explicit for-of loop (the form admitted by the
  packaged compiler).

### Values, absence, and shapes

- `viewer`, `now`, `commit`, and `new` become `ctx.viewer`, `ctx.now()`,
  `ctx.commitTime`, and `ctx.newId()`.
- `sorted`, `tokens`, `range`, `min`, and `max` map to the packaged builtins.
  A two-name `sorted` binding lowers to the compiler's `orderedPair` form.
- Every comparison evaluates each operand once and guards both against
  absence before comparing. The platform normalizes missing program values to
  `null`, so the emitted guard is the concrete implementation of v0.2's
  null/undefined-is-false rule. `??` remains TypeScript `??`.
- `pointRead! else CODE` binds the read and emits
  `db.require(value !== null, "CODE")`; the omitted code is `NOT_FOUND`.
- A final-position `match` creates a result local, emits a null test, assigns
  the value of each arm, and returns the local. A mid-body match runs its
  statements and discards arm-final values; Quarry v0.2 has no `return`.
- A reference used as a row triggers an explicit `db.get`. Nested reference
  access and nested shapes use generated locals and null checks, so absence
  propagates like optional chaining.
- `{ bare, named: expr, * }` focuses a row. A page shape emits a for-of loop and
  builds a bounded result array. Nested shapes re-focus `.` explicitly.

### Writes and control

- `+t { ... }` calls `db.insert` and adds `id: ctx.newId()` unless `id` was
  supplied. Its value is the inserted row object.
- `~t[id]`, `+~t[id]`, and `-t[id]` call `db.update`, `db.upsert`, and
  `db.delete`. Focal patch expressions use a callback; upsert focal access is
  nullable. The current TypeScript/IR write surface accepts only scalar row
  ids, so composite/alternate-key writes refuse with a get-row-then-id
  rewrite message.
- `require condition else CODE` calls `db.require` with the stable code.
- `if/else` and bounded `for` become ordinary TypeScript control flow. For
  domains are limited to pages, capped list arguments, literal lists,
  `tokens`, and `range`.

## Refused surface and known gaps

The compiler deliberately refuses `maintain`, `#aggregate` reads, `use
assets`/`asset`, effects, schedules, `merge`, device/oblivious constructs,
`while`, and user recursion/functions. Point-read field chains and ordering
comparisons in rules also refuse with a restructure message because the
packaged rule surface cannot express them.

Other known gaps are the v0.3 policy and constraint families identified by
LLP 0329.014.010: maintained rows/aggregates, visibility-scan declarations,
fan-out placement, cross-row constraints, retention/disclosure vocabulary,
per-field update grants, unset-optional, composite cursors, reductions and
`capped`, and range patch/delete helpers. Top-level `index`/`unique` syntax is
also not accepted; put it in the table block. There is no watch mode,
sourcemap, IR output, fragment/reuse spelling, or publishing step.
