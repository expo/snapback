# N_PATCH_CLEARS

An omitted optional argument is null, the same as an explicit null: `x = null` is true either way, and no test tells them apart. So in `mutation edit(doc: documents, title: text 1..80, body: text <=2000 ?)`, `update documents[doc] { title, body }` clears `body` whenever a client sends only the title. `check` notes N_PATCH_CLEARS when an `update` patch writes an optional argument straight into a nullable column beside at least one other field the client supplies (an argument), and nothing in the mutation tests the argument (`require`, `if`). To keep the stored value when the argument is omitted, bind the row and write `body: body ?? d.body`; if clearing is meant too, add `clear: bool ?` and write `body: null if clear = true else body ?? d.body` (`guide writes`, Details). An `upsert` (it replaces the caller's record, and its insert arm writes the same null), a one-field setter, an argument the mutation tests, and a value other than the bare argument are not noted; if a null argument always means "clear", nothing changes.
