# N_DELETE_NEEDS_READ

N_DELETE_NEEDS_READ means a mutation deletes a row of a table that other rows reference through `on delete restrict`, `cascade` or `set null`, and its delete rule may admit a caller its read rule does not. Such a delete consults the referencing rows, so since 0.5 it also needs read authority on the row it deletes: a caller the delete rule admits but the read rule does not gets NOT_FOUND, exactly as if the row were absent, and never learns whether rows reference it. Make every deleter a reader (`delete <- <the read rule> and …`, or a delete rule that is the read rule), or mark the references `on delete keep` when deleting the row should not consult them. `check` names the site from the rules' shapes alone, so it can name a delete whose callers are all readers anyway. guide writes.
