# N_DELETE_RESTRICTED

N_DELETE_RESTRICTED means a mutation or job deletes a row that another table references through a reference with no declared action — directly, or through a table its cascades reach. Since 0.5 an undeclared reference is `on delete restrict`: the delete refuses E_REFERENCED while a live row still references the target. Before 0.5 the referencing rows stayed and named a deleted row. Declare what you mean on the referencing column and the note goes away: `on delete cascade` (with `cap N by <column>`) deletes them with the target, `on delete set null` clears an optional reference no rule reads, `on delete keep` keeps them as before, and `on delete restrict` keeps the refusal. Anyone whose insert rule admits a referencing row can hold the target under restrict, so a reference other principals create to your rows is usually `cascade`. A `read through` child is not named: it already refused (E_PARENT_HAS_CHILDREN). guide writes.
