The marker and recovery commits explicitly set `synchronous_commit=on`. PG16.15 otherwise retains `fsync=on`, `synchronous_commit=on`, `full_page_writes=on` and the unchanged `postgresql.conf.delta` resources. The [deploy guide](../../../crates/snapback4-lang/src/guide/deploy.md) documents that visibility window. S uses this **same binary**, G6 bounds and depth, with the URL `commit` setting **unset**; synchronous S remains the shipped default.

**Flush-position witness is enabled throughout the measured E cells.** These are optimized release builds with Cargo override `--config profile.release.package.snapback4-core.debug-assertions=true`, opt-level 3, **no `test-support` feature**. This compiles `early_release::assert_flushed` before each batch certificate can release acknowledgements: the marker's insert-LSN upper bound on the data commit LSN must be ≤ sampled flushed LSN. This is stronger than comparing the exact data commit record. Any failure panics with `E acknowledgement exceeds WAL flush position` and disqualifies the cell. The measured executable contains that assertion text; [binary integrity](./binary-integrity.json) binds its SHA to the build and trial ownership records. **Observed flush assertion failures: 0**. Additional core debug assertions are enabled by this package override; comparison to historical levers S therefore includes a qualification-build difference, while paired E/S use an identical build. The first attempted build enabled `test-support` in ordinary release and was correctly rejected by the fixture guard; zero trials used it. No source was changed to enable qualification.
