# Lane V round 14 — lookup reads a shared correction

Date: 2026-09-26. Branch: `sb4-intent/v-web-start`, based on round 13
`ad9bafb69`. Intended integration: 0.4.3. The supervisor wrote this round,
because the lane's codex session could not authenticate on any host (HTTP 401).
Both round-13 reviews were read in full: Grok READY, and Astra READY WITH CHANGES
with one Medium.

Both round-14 requests are done:

1. **Astra (Medium): stale local history hid a corrected shared receipt**
   (`web.ts:346`). The lookup merged shared history with the device's own,
   and the device's always won. Lookup now applies the rule adoption already
   applies: a verified shared outcome answers over the reader's own
   `E_STORE_REPLACED`, and every other local outcome answers first. One
   predicate, `unknownOutcome`, now defines the replaceable outcome for both
   adoption and lookup.
2. **Grok (mutation):** the shared window's correction rule was tested only
   with a refusal. A new case adopts an orphan whose history is
   `{state: "sent", id, seq: 7}` over a shared `E_STORE_REPLACED`. The window
   updates to `sent` in place, and the orphan is removed. Grok's mutant, which
   adds `write.why.code === "NOT_ADMIN"` to the rule, now fails that case.
