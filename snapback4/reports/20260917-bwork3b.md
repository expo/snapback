## Intended boundary

The generated effect registry binds each handler to the server's named
declaration digest and declared secrets. Its context exposes safe effect and
invocation metadata, a cancellation signal, declared secrets and durable
steps. It does not expose an action's delegated session, arbitrary data
query/mutation, administration, identity minting, raw lease token or write-ID
authority. Existing low-level `runWorker` callers retain their registration
and claim shape. The current deployment-trusted worker model in RFC §16
still applies; draft §17 is not accepted or implemented here.

Generated handlers use declaration-fenced claims and status checks. A known
deadline, cancellation, lease/generation loss, authentication failure or
transport uncertainty must prevent a subsequent top-level settlement.
This is not a guarantee that aborting a request undoes a server commit or an
external provider action. Existing durable-step uncertainty and reconciliation
rules remain binding.

The prior Bwork2 strict live-claim check deliberately returns an opaque lease
refusal before exposing work state. The legacy worker had inferred a queued
state from that refusal; reporting now needs to preserve the actual error
without inventing a queue/terminal state, retrying the provider, or making an
extra status request. The four affected main-branch tests were independently
reproduced on clean main. They are an introduced regression, not the unrelated
S5 device change or the historical fixture-server acquisition failure.

Root accepted one consolidated repair covering all observed failures, the

sufficiency of that one-line repair; it was not sent for a binding review.
Root stopped the patch loop and selected a lifecycle-level change: stop
admitting periodic status checks, drain the already-running check without
suppressing its failure, then make a bounded final confirmation. All
generated fixtures also need a uniform finite-claim/error boundary instead
of timer-only escapes from immediate mock retries.

That changed approach is implemented in source checkpoint
`cf31bad1998a2caa44ff5035ac434aa386f75b1d`, integrated without conflicts as
`2e1a1ceae7` with an identical tracked tree. The shared status poller can
quiesce new checks while draining the active check through its normal loss
callback. A shared abort race bounds both the periodic and fresh final
checks even for injected transports that ignore cancellation. Effect
finalization drains, asserts current authority, performs a fresh bounded
status check, and asserts again before settlement. Existing action callers
do not use quiesce, and their close semantics remain unchanged. New tests
control old response bodies directly, cover successful and failed drains,
and guard mock claims against hot repoll loops. Root read the full four-file
delta and production modules.
