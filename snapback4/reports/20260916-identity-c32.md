## Source and decisions

The integrated product candidate is `3a95cfcd3`, based on main `5f49bbcf9`.
Later review-record commits change no product source. Its final components
include `11ea4d711` (post-writer-lock clock and OIDC recollection help),
`ac95f95f9` (C3.2 typed authority kernel), `4dd0462e4` (synchronized HTTP
route witness), and `906ed04ec` (unpublished mint-receipt fence).

- OIDC Authorization Code with S256 PKCE uses pinned `openid-client` 6.8.8.
  Fixed issuer/client/redirect, browser binding, state, nonce and provider
  verification remain server-runtime responsibilities, not engine protocols.
- The private mint bridge binds the exact current invocation/claim, intent,
  input digest, principal generation, original expiry and session family.
  Explicit lost-delivery recovery replaces the token only within that live
  family. The before-commit cut can create its first binding. Public logout
  closes a live presented token's family; a replaced token cannot close its
  successor. No raw token is stored in the binding or step outcome.
- Both bound mint and public logout sample time once after the immediate
  writer transaction and identity fence, before checking authority. The
  historical unbound mint retains its prior timing. Integration of the typed
  kernel required resolving these two clock/call-site conflicts explicitly.
- C3.2 centralizes authority policy over typed transaction capabilities.
  SQLite remains its current adapter. Borrowed reads use one deferred snapshot
  and end it before expiry cleanup. There is no Postgres authority adapter or
  production-store claim from this extraction.
- Ambiguous one-time token exchange parks. A completed v2 marker permits
  safe discovery retry before the non-reconcilable token phase; completed
  exchange receipts replay without provider availability.
- Unpublished prototype unbound `oidc.mint` receipts are deliberately not
  migrated. The fixed input discriminator `oidc-mint-bound/v1` makes both old
  started and old completed inputs refuse before either mint callback. Their
  old tokens remain untouched; recovery is a fresh login/invocation. Already
  parked old work stays parked. This approach replaced compatibility machinery,
  not the core's legitimate first-binding recovery behavior.
