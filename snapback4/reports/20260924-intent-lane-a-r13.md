# Lane A, round 13 — nullable cursor order and mixed job validation

2026-09-24. Branch `sb4-intent/a-planner`; starting commit `99c5dabd0`.

## Behavior and examples

Empty-search browsing never substitutes a nullable unique key for a declared
id tiebreak. With this schema, browse selects `byTime`; with required `at`,
it may still reuse `byOwnerAt`. Declaration order does not affect the choice.

```quarry
table t:
  owner: principal
  at: time ?
  body: text <=40
  unique byOwnerAt: owner, at
  by byTime: owner, at, id
  by byWords: owner, words(body), at, id
  read <- .owner = viewer
  sync to .owner
query page(q: text <=40, c: cursor ?):
  return t[viewer] matching q first 1 by byWords after c
```

Two `at = null` rows both appear across one-row pages, ascending and descending,
with empty, whitespace-only and nonempty search. The server and reopened
memory/SQLite devices agree and keep hidden rows hidden.

Ordinary predicate, named, membership and projected-view cursor reads also
choose or synthesize a total order, for example:

```quarry
return t where .owner = viewer first 1 by .at after c
```

An explicit nullable unique cursor (`t[viewer] first 1 by byOwnerAt after c`)
refuses with E_CURSOR_INDEX and a compiling column-ordered rewrite. Computed
keys receive a separate-index/read rewrite preserving their parameters. It does
not change or weaken the original unique constraint. A generated Following
feed similarly keeps its old unique indexes and uses a separate byReaderPage
index ending in id. Pending-work completeness and live dependencies remain.

Stored jobs validate every top-level loop before running any chunk. A valid
page sweep mixed with an unsupported DerivedArray loop parks with E_JOB_SWEEP,
zero chunks, zero writes and zero effects, whether the unsupported loop is
before, between or after valid sweeps. Existing supported preludes and inner
loops still run. The ordinary body-filter rewrite from round 12 remains:

```quarry
for row in t:
  if status = null or row.n = status:
    update t[row.id] { n: 9 }
```

## Selection audit and decisions

- Generated browse alternatives require a total declared cursor order even
  when their caller has no cursor. For a nullable unique index missing id,
  a compatible declared page index wins; otherwise ordinary synthesis adds id.
- Ordinary predicate, named, view-branch and value/window-lane planning share
  Requests::read. Cursor-bearing reads now apply the same eligibility check.
  Read requests synthesize a declared id component when reuse is unsafe.
- Explicit ordinary scan cursors are checked again in scan_at; their diagnostic
  never adds id to a unique constraint. Computed keys retain their duration
  and offset in the proposed separate page index. A declared id
  anywhere in the components already uniquely identifies a table row; a
  unique key without id is safe only when all its components are required.
  Calendar components already require a present source time column.
- Exact point/probe selection has no continuation. Its existing declared-key
  resolution and null/authorization semantics did not change. Sync audience,
  cap and expiry enumeration requests likewise are not opaque page cursors.
- Ordinary reads without a cursor retain their existing index-reuse behavior.
  Aggregate and job internal positions use the full physical key. Authored
  merge cursors explicitly append the physical id via merge_suffix; their
  lazy/eager paths already preserve ties and needed no cursor-format change.
- The generated Following expansion happens inside binding and explicitly
  selected a nullable unique key. The audit therefore required a separate
  ordinary page index plus updates to both pending-work hooks. No exception
  to the total-order proof and no unique-constraint weakening was introduced.
- The job guard checks direct top-level For domains, not nested prelude/body
  loops: those already execute inside the normal chunk machinery. Native
  jobs retain their separate runner. No new resumable domain was introduced.

## Regression evidence

- `authored_words_order_disambiguates_browse_independently_of_declaration_order`:
  required/nullable time, both declaration orders and page directions, empty
  and nonempty needles. Required uniqueness remains reusable; nullable ties
  require byTime and every row is returned.
- `every_planned_page_keeps_nullable_unique_ties_and_explicit_unsafe_cursors_refuse`:
  predicate, named, value-lane and view reads retain null ties, with an existing
  safe index and with synthesis. The explicit refusal's rewrite compiles and
  keeps the old unique index's columns/uniqueness unchanged.
- `browse_matches_bucket_duration_and_offset_not_only_column_names`:
  both wrong-duration and wrong-offset indexes spell identical columns and
  sort before the correct candidate. Only zBrowse is selected; rows on both
  sides of bucket boundaries make the page oracle sensitive to either error.
  Temporarily deleting the descriptor comparison made this test fail with
  `aWrongPeriod` versus `zBrowse`; the original source was restored afterward.
- `nullable_unique_cursor_rewrite_preserves_computed_key_definitions`:
  a nullable unique key containing hour(at) or bucket(at, 2h, 30m) refuses with
  a concrete separate-index/read rewrite. Compiling it preserves the original
  unique components and adds id only to the new non-unique page index.
- `engine_parks_an_unrecorded_conditional_sweep_instead_of_skipping_it`:
  extends the raw-IR case with unsupported loops before/between/after two
  valid sweeps. Every case parks before writes/effects. A real compiled job
  with a loop in its prelude and another in its body still executes both.
- `nullable_search_browse_memory` / `nullable_search_browse_sqlite`: held rows
  survive reopen and paginate null ties correctly in both directions, with
  empty/whitespace/nonempty needles and an inaccessible owner's row.
- Existing Following device checks now assert the separate page index and
  original constraint. They still test pending backfill, completion-triggered
  invalidation and prediction on both stores.
