# Lane E round 15 — principal fences and dispatched outcomes

Fixed the reviewed stale-global-logout and outcome-replacement defects on top of
round 14. No public API, Quarry form, refusal code or server protocol was added.

## File-by-file changes

- `packages/snapback4/src/app.ts`: global selection reads the revocations journal
  directly under the existing session lock and merges its principal watermarks
  with inline fences. Completed fences protect later sign-ins even after their
  tombstones have moved into the journal. Reject before choosing a bearer; no
  recursive lock acquisition. Compare the selected session's committed scope,
  not the raw shared/legacy epoch counter. Document I12 beside the invariants.
- `packages/snapback4/src/app-revocations.ts`: reuse the validated, backend-bound
  journal decoder for that read without acquiring another lock or mutating it.
- `packages/snapback4/src/app-client.ts`: keep raw outcomes for calls admitted
  before fencing: mutate, act, upload, refreshSession and receipt lookup. Calls
  beginning after the fence are still refused. Query data, asset reads,
  subscriptions and observations retain their disclosure guards.
- `packages/snapback4/src/client.ts`: closing no longer settles the in-flight
  mutation as failed before its response arrives. Already-dispatched mutation
  and action responses are decoded after close. Cancellation without a receipt
  leaves the mutation id pending; unsent work and new admission remain fenced.
- `packages/snapback4/src/actions.ts`: retain dispatched action outcomes across
  closure instead of replacing a done/failed result with a lifecycle refusal.
- `packages/snapback4/src/app-online.ts`: a failed terminal receipt save reports
  the storage error and retains the durable intent for same-id replay, while
  returning the server-confirmed outcome to the original caller.
- `packages/snapback4/test/app-global-attempts.test.mjs`: strengthen the online
  and local dormant-tab regressions to prove the watermark is in the journal
  and absent from the new session. Add legacy-session journal selection and a
  same-scope peer rotation with an unrelated principal's legacy counter/fence.
- `packages/snapback4/test/app-outcomes.test.mjs`: five facade admission/outcome
  tests, a held real-server mutation across logout with same-id recovery and
  exactly one row, and done/failed online action responses held across close.
- `packages/snapback4/test/helpers/app-session-model.mjs`: model committed write
  receipts independently of returned client results, check I12 including held
  outcomes after hiding, and distinguish admission after hiding from settlement
  after hiding. I9 checks that an already-acknowledged stale global operation
  cannot kill later logins. Failure minimization recognizes I12.
- `packages/snapback4/test/app-session-model.test.mjs`: retain the prior fixed
  regressions; add held mutation/logout, replacement during held rotation, and
  receipt-persistence failure cases. Require I12 coverage across 5,000 seeds.
- `packages/snapback4/test/app.test.mjs`: update the ordinary-close rotation
  assertions and receipt-save failure assertion to pin outcome preservation.
- `packages/snapback4/test/client-lifecycle.test.mjs`: cancellation of a
  dispatched online write now expects pending, since it cannot establish a
  server refusal. The same test still proves abort and closed admission.
- `packages/snapback4/CLIENT-AND-OPERATIONS.md`: describe I12, the admission versus
  delivery distinction, and principal/committed-scope global selection.
- `llp/3000.013-quarry-states-intent.rfc.md` §6: record the implemented selection
  and outcome invariants and the I1–I12 model.
- `JOURNAL.md`: append one dated qualification entry. This report records the
  reproductions, decisions and measurements.

const old = app.client;
const writing = old.mutate(api.add, { body: "one row" }, { id });
// Once the server commits, hold its reply and log out.
await app.auth.logout();
// Release the reply: writing returns sent with the original id.

committed account scope. New calls on a hidden facade never dispatch. There are
no new language forms or guide refusal codes to register.

## Invariants and model coverage

I1–I7 preserve stored-bearer protection, failure atomicity, retirement custody,
principal isolation, committed epochs, coherent public identity and exclusion
of known refused sessions. I8 fences new use of hidden handles and delivered
read snapshots. I9 covers sessions at the global server operation and protects
later logins from a stale acknowledged operation. I10 limits acknowledgement
to its dispatch coverage. I11 limits selection to the caller's account scope.
**I12 preserves a dispatched write's confirmed outcome and original id.**

The standalone model passed **5,000 sequences, seeds 1–5,000**, comprising
**130,000 commands**, plus **28 fixed regressions and a 120-sequence storage
fault sweep**: 30 test cases, zero failures, 52.326 seconds.

Its 25 operations are signup, login, guest, refresh, logout, logoutEverywhere,
close, closeClient, reopen, reopenOffline, query, revoke, revokeCurrent,
holdStore, release, capture, handleQuery, handleMutate, handleRefresh,
observeHandle, readObservation, refreshFault, sibling, retireOffline and
retireOnline. Three real createApp runtimes share a mock server and atomic store.

Measured standalone coverage:

- 583 server write commitments; 556 audited returned outcomes, **95 after the
  facade was fenced**; 117 held mutation responses. Background replay accounts
  for commitments without a corresponding generated caller outcome.
- 4,773 global attempts: 3,967 refused, 806 acknowledged; 639 public successes;
  six calls from an older account epoch and two held acknowledgements delivered
  while a later same-principal token was live.
- 22,793 retirement removals checked against attempt coverage (I10).

  single-operation rotation-save failures. The additional sweep covers indices

- 15,572 captured handles, 5,758 hidden handles, 8,938 checked result settlements,

## Defects found while widening the model

- **Seed 10 / held-write regression:** fixing the facade alone was insufficient.
  Online close resolved the mutation prematurely, and sendPost discarded its
  late committed response. The real-server regression and model now pass with
  both underlying paths fixed.
- **Seed 348:** removing the old raw-counter comparison also removed protection
  against a replacement committed while global logout waited for its rotation.
  Retain a comparison against the selected session's committed scope, separately
  from the requested principal watermark check. The reduced held-rotation case
  fails if that comparison is removed.
- **Seed 1364:** terminal receipt storage failure changed a confirmed result back
  to pending. Preserve the outcome without deleting the durable pending intent;
  recovery still reuses the id. A reduced fixed case covers the failed read.
- Inspection of the analogous action path found another post-await lifecycle
  flip in the lower-level shared action helper; done and failed action regressions
  now cover it.
- **Seed 1832 was an oracle correction:** an offline global attempt had never
  been acknowledged. Its eventual server operation legitimately covers sessions
  minted before that operation. The model now distinguishes this from a stale
  caller after an acknowledged fence; it does not grant an exception for later
  sign-ins after completed global logout.

Eleven negative controls were detected: removing the journal watermark read;
removing the committed-scope comparison; discarding closed-client responses;
prematurely settling the sending write on close; replacing confirmed writes on
receipt-save failure; replacing action outcomes; and each of the five facade
completion flips. Only generated dist files were mutated, then restored.
