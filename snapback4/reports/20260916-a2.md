# A2 declared results and generated server context — qualification

Date: 2026-09-16. Governing contract: LLP 3000.009 §5.1, §5.2, §10.2.
Implementation uses the author-selected Astra xhigh coding lanes, with the
lead owning the core/store/client-contract boundary. No A3 routes, SQL
implementation, production Postgres, control run or publication is claimed.

## Implemented surface

- Declared bounded `returns`, `Action<A, R>` and precise generated handlers;
  result validation is terminal after external I/O. Asset results check actual
  ledger facts/kind/byte bounds; table references remain IDs, not expanded rows.
- Generated `server()` and `ctx.query`, `ctx.mutate`, invocation metadata and
  cancellation signal, declaration-scoped secrets, `ctx.step`, `writeIdFor`.
  Read/Write states and uncertain pending writes remain explicit.
- Durable named steps bind input and a stable provider key before I/O;
  completed outcomes replay, changed inputs refuse, uncertain steps reconcile
  or park. Strict JSON and 1 MiB step bounds, no silent coercion/repetition.
- Per-operation retry/backoff/deadline/cancellation for actions and effects;
  schedules admit actions under declared, statically checked service seats.
  Current SDK effect claims are fenced; legacy unfenced wire compatibility
  remains weaker and is documented.
- Strict Node 24/TypeScript checking without executing handlers, supervised
  `dev` and explicit `serve --worker`, dependency/config recovery watching,
  adoption claim fence, explicit child environment and streaming redaction
  including JSON-escaped secret values. Transitive admission authority fails
  immediately when an ancestor is revoked, not only after a worker poll.

The [server reference](../packages/snapback4/SERVER.md) records compatibility
and limits: TypeScript deployment graphs are **not bundled** by deploy;
effects retain their legacy signature rather than the action context; work
IDs/steps are retained for the store lifetime; there is no automatic ID reuse,
GC or operator resume command. Trusted Node application code is not sandboxed.
