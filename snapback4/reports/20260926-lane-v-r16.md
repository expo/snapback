# Lane V round 16 — local settlement authority and lookup custody

Date: 2026-09-26. Branch: `sb4-intent/v-web-start`, based on `a014b94de`.
Implementation commit: `f026cfff6`. Intended integration: 0.4.3. Read before editing: the round-14 and round-15
reports, `v-r14.grok.md`, `v-r15.grok.md`, and `v-r1415.astra.md`.

All three round-16 requests are implemented. Ordinary receipt reads are strictly
local, absent local history is recoverable through caller lookup, and lookup
rechecks custody after the shared read. Tests cover actual orphan adoption and
local terminal corrections committed between the two history reads.

## Reader audit

| Reader | Authority and reason |
| --- | --- |
| `local.ts` storage adapter `read()` → `WriteHistory.read` | Ordinary `meta write-history`: strictly local. `read` can retry persistence of its already-known local outcome; it must not obtain shared settlement authority. |
| Startup qualified-receipt repair | `history.acknowledged` → local `read`; never sees a shared-only refusal. |
| `flushOnce` qualified path | Same local acknowledgement path. |
| Ordinary replay preflight and final `begin_send` recovery | `recoverReceipt` → local `read` or local `acknowledged`; only that result can be kept/settled. |
| Page-hide refusal check | `history.read(id, true)` is local. `web.ts`'s atomic `settle_exit` checks the raw device's own history and outbox directly. |
| `client.write` with initial or newly adopted custody | Uses local `read` or local `acknowledged`; the latter may perform the existing qualified repair. No overlay receipt is persisted or settled. |
| `client.write` without custody | `history.lookup` asks for `lookup: true` when local history is absent or replacement-unknown. Host merge rereads local history under the device chain, preserving a local authored/sent outcome committed since the first read. A subsequent outbox check catches intervening adoption. |
| Opener `keptWrites` | Explicit lookup view. It needs shared ids to route a caller's retained-id retry to `client.write` instead of admitting a fresh intent; it remembers **only ids**, never receipts or settlement authority. Eviction later produces the existing `E_WRITE_RECEIPT_EXPIRED`. A negative control verifies this choice. |
| Orphan sharing | Reads the source's durable local metadata; merges it into the shared receipt window under its claim before removing the source. Unchanged. |
| `receiptHistory` / `shareReceipts` | Shared-window storage access remains confined to explicit lookup and adoption. Ordinary history reads no longer call it. |
| Online and mock `history.read` | No web shared-history adapter; unchanged and scoped to their existing client histories. |

The recheck is one bounded additional queue read, not a retry loop. Native meta
continues to ignore the host-only `lookup` field. No protocol/storage change.

## Examples and regression evidence

No new Quarry or public API forms were introduced:

- A qualified `{ observed_seq: 7, receipt_store: { success_seq: 7, ... } }`
  with no local history and shared `NOT_ADMIN` remains `sent` 7. The client
  persists its local success; the shared refusal cannot hide it.
- `await client.write(id)` without local history/custody can return a shared
  `sent` or `NOT_ADMIN`. No shared receipt is copied into local history, and
  `client.mutate(op, {}, { id })` recovers the retained result without admission.
- A legacy observed entry with shared `NOT_ADMIN` and no local receipt remains
  pending until its same-id POST to the original bound store returns the actual
  `NOT_ADMIN`. Exactly one replay POST is observed, `replayed: true`; audit stays
  0 and the locally established refusal survives an offline reopen.
- Pause `client.write` after an empty queue read. Actually adopt an orphan,
  remove its source, and verify the destination outbox is committed. Resume:
  the first lookup and the following lookup both return `pending`, with no POST
  and no shared receipt copied into local history. Tested with absent and
  `E_STORE_REPLACED` local history.
- Pause the overlay request after its initial history read. Commit a verified
  local correction through `keep_write`, settle its temporary custody, then
  resume: lookup returns local `NOT_FOUND` or `sent` 7 over shared `NOT_ADMIN`.

Targeted unmutated results: **14/14** browser checks (13 scenarios plus parent),
**98/98** affected legacy/lifecycle/sign-out/durability checks, **19/19** adoption
and shared-window checks. The six newly added standalone race/lookup scenarios
also passed together in a focused run (7/7 including their parent).
