  exclusive settlement ownership synchronously for a keepalive refusal. An
  ordinary owner wins. Hold ownership and active-close tracking until local
  persistence finishes, and publish only after a successful commit.
- `packages/snapback4/src/local.ts` (1,496 lines): ordinary delivery acquires
  that same per-id ownership and releases only its own claim. Delegate exit
  refusal handling to the new helper; check known success, including the

  Include the new operation in read invalidation and media reconciliation.

## Forms and outcomes

No new Quarry or public client form, signature, or refusal code. The existing
calls compile and run unchanged:

```ts
const write = await app.mutate(api.removeMember, { room, principal });
const recovered = await app.client.write(write.id);
```

If A commits the ordinary request while its response is held, and the same-id
keepalive receives `E_STORE_REPLACED` from B, both response orders end with
`write.state === "sent"`, one sent notification and a sent receipt after reopen.
A's audit increases by one, and B's stays zero. No new id is allocated.

An unowned keepalive replacement refusal still produces the named terminal
`failed / E_STORE_REPLACED`. Its receipt and retirement commit together. An
aborted receipt transaction publishes no refusal and leaves the same queued id
recoverable after close/reopen, until a later successful receipt transaction.

## Regression evidence

| Test | What it proves |
| --- | --- |
| A commits; B's refusal response arrives first | The ordinary owner prevents premature failure publication and retirement. Release A: caller, notification, lookup and reopen all report sent. |
| A commits; A's success response arrives first | A late replacement refusal cannot override success. A direct call also verifies the device's conditional transaction ignores an already-settled ID, independently of the transport guard. |
| Ordinary success with its receipt transaction aborted and sync unavailable | Known success survives in memory. Restore persistence, then deliver B's refusal: it cannot overwrite the known result. Reopen replays only the original id to A and remains sent. |
| Keepalive receipt persistence held for 1.2 seconds | The transport's one-second network wait may expire, but no ordinary request passes local settlement ownership. The released receipt batch includes outbox retirement; exactly one failed event follows commit. |
| Abort the real strict IndexedDB receipt transaction | No false terminal event. After close/reopen the original outbox row remains, receipt is absent, and write is pending. Permit a later receipt save: receipt and retirement commit together, then survive another reopen. |
| Queued binding A with newer current-device identity B | Ordinary transport still sends A's binding, preserving the existing fallback only for an unbound legacy/native entry. |

## Scope, choices and open problems

No deviation from the requested settlement or durability guarantees. The
one-second network wait remains bounded so a stalled keepalive response cannot
wedge ordinary recovery or close. Exclusive ownership and the serialized atomic
commit prevent a second transport while receipt persistence is underway; this
satisfies Grok's local-settlement concern without extending a network timeout.

The atomic operation lives in the web host, using the existing wasm operations
and strict persistence transaction. No Rust/server/client-contract redesign,
authorization or disclosure change, meter relaxation, receipt-window expansion,
new language form, or acquisition retuning. Immutable terminal receipts remain
immutable: ownership prevents the contradictory refusal from being stored.

No new cold-acquisition benchmark was required or run in round 8. The previously
recorded acquisition result remains 15.825 s median versus 70.716 s, 4.47× faster;
this round makes no new performance claim. No known open scoped problem. The
review reproductions and their expected outcomes are listed above and automated.
