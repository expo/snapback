The oracle measures viewport arrival, completion/highlight, actual highlighted
time and failure-notice time with **`performance.now()` inside Chromium**.
Playwright only retrieves durable observations with generous state-based waits.
The product's four-second search/settle limits and 1.8-second highlight are
unchanged. The sole product change covers Astra's conditional keyboard edge:
web scrolling keys are captured at the document while a jump owns scrolling,
including after a quote is blurred. Cleanup removes that listener.

## Measurement and bounds

An observer armed before the click records its browser timestamp, the first
in-viewport geometry, the completed/visible/highlighted state, every color on/off
transition, and the first failure notice. It uses both MutationObserver and
requestAnimationFrame; no elapsed assertion subtracts Node timestamps.

| Browser measurement | Assertion |
| --- | --- |
| Tap → first viewport visibility and completed/highlighted visibility | each ≤ **2,000 ms** |
| Highlight duration in the stable visible-original case | actual on-time **1,700–2,300 ms**; first-on to final-off span ≤ 2,300 ms; off at observation |
| Tap → blocked-scroll failure notice | **3,900–4,500 ms** for the four-second product deadline |

The bounds allow the existing 100 ms retry tick and render/measurement latency;
they are fixture acceptance criteria, not new cross-device latency promises.
The highlight can briefly clear and restore during initial layout invalidation.
Each transition retains its original timestamp, and the duration sums **only
on intervals**. A durable sample at 2.5 seconds after first-on records those
intervals and whether the color is still on. Neither subsequent unhighlighted
frames nor a driver pause adds highlighted time. An overlong or endless highlight
also fails. Current completion-marker/viewport assertions remain after retrieval.

Waits remain `hangBudget()` (122 seconds); the full fixture guard is 300 seconds.
The ordinary distant-quote case pauses only the driver for 2.3 seconds. A separate
positive run and **every negative control** pause it after every asserted jump;
the blocked-failure path also takes that pause. These pauses do not change any
in-page timing threshold.

## Keyboard edge

The new regular regression blurs the focused quote, verifies `BODY` focus,
dispatches PageUp there, then releases delayed quote layout. No corrective command
may follow. The list-only mutation proves the assertion rejects the old scope.
Cancellation remains synchronous, does not prevent the key's default action,
and fences in-flight measurements. The listener is web-only and owned by the
current request; settle expiry, failure, cancellation and unmount remove it.

Also reran Astra's trusted-input focus probe, adapted only to lane-local portable
paths (`keyboard-focus-probe.test.mjs`). **6/6 tests pass.** In its explicit-blur
case, a real Chromium PageUp targeted BODY and moved the list **2,188 → 1,670 px**;
corrective commands stayed **28 → 28**, and the highlight cleared. Touch-focused
PageUp also scrolled without correction. Margin and Tab controls did not move
the list; they are not reported as successful scroll witnesses. This remains a
conditional focus-state reproduction, not a newly established common user path.
