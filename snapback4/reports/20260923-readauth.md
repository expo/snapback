## Mechanism

`crates/snapback4-core/src/engine/read.rs::provisional_readable` is the common
read-time guard. Point reads (including program `exists`), scan candidates
(including hoisted/uniform scans, pages, counts and both merge implementations),
`check_rule(Read)` (including write-target reads), rule-probe witnesses and
live maintained-source reads pass through it. SDK watches rerun those queries;
the existing rule-dependency envelope includes authorization tables.

The `Rows::provisional_row` adapter identifies the **current image**, not every
row named in an outbox entry. `history::Reading` recognizes the engine-owned
persisted `pending` bit. `Predicting` checks that bit in the stored image while
continuing to strip it from application values. `Runner::provisional_rows`
tracks current-execution writes, including when the core interpreter is invoked
without a device adapter. No wire or persisted-format change is needed: old
pending images are filtered on the first offline read, without admission,
replay, migration or outbox loss.

The evaluator uses the device principal and the current transaction, which
contains all pending predictions layered over delivered images. Rule probes
reject retained-only witnesses and `Left` witness groups as unknown. Nested
provisional witnesses must themselves be readable. A positive self-membership
rule (`members.read <- exists members[.roomId, viewer]`) can use the same
currently covered row as its existence witness, matching the server's
non-recursive existence semantics. A recursion guard fails other cycles closed.
This preserves `createRoom` without trusting arbitrary cyclic authority.

A denied/unknown provisional row is absent and records unknown coverage;
therefore its absence is not presented as complete. Probes spend the reading
query's meter and preserve its cut. The zero/one-probe tests cover point, scan,
merge, page, count and `exists`; a cut count is zero **with incomplete/cut**, as
in the existing count convention. Unrelated incomplete components do not hide
an independently authorized row. Delivered images retain the existing trusted
read path, including retained history and the existing expiry behavior; a
zero-probe delivered control still returns its row complete.

Removed: `check_prediction_readable`, its end-of-prediction call, and the
final-output `E_PREDICT` queueing rule. The tracked write set now serves only
reads during the current execution. Unreadable outputs predict and remain in
the overlay until settlement. F3 still skips foreign engine-owned copies before
writing them; its evaluator now returns `Result<bool>` and propagates errors,
so only an explicit denial skips a copy.

device. Astra regressions cover a delivered grant whose actual scope tombstone
persists `Left`; mutation A predicting a note/grant followed by B deleting that
grant; and direct construction of old pending row/base/outbox records before
opening the new device. The upgrade cases include the moderation report and a
note with a dependent rule-probe row. The fixtures never call the new predictor
to construct the old images.

the outbox; a nonempty server tick advances the watermark and forces replay.
The positive later-grant case reverses visibility. Outcome tests inspect every
predicted output, including foreign inboxes and maintained rows. Simple-rule
cases assert the whole result vector before and after settlement, and cover
readable updates/upserts as well as inserts. The unknown-grant fixture proves
the server grant is outside the device's acquired horizon.

WASM/memory and process/SQLite implementations with real SDK observers. It
covers revocation, retained grants, direct old moderation row/outbox fixtures,
new moderation predictions and later grants. It observes every listed read
surface through offline reopen and nonempty stream replay where applicable.
