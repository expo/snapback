## Implementation — supervisor round 0

Readability is judged once at the end of a mutation's prediction, against its
final provisional state. `engine/write.rs::Runner::row_changed` records the
(table, id) of each inserted or updated row in `Runner::prediction_rows`.
`engine/local.rs::predict` calls `check_prediction_readable` after the mutation
and its final-exists checks finish. The distinct-key set covers inserts,
updates, both upsert arms and maintained outputs; a final store lookup skips
rows that were subsequently deleted and uses the last image of rewritten rows.
Later membership writes can therefore authorize earlier room writes. Later
revocations can also invalidate earlier writes.

The shared evaluator, `engine/read.rs::prediction_readable`, evaluates the
actual table read rule with the predicting principal, materializes optional
fields, records probe dependencies and consumes real prediction rule probes.
It does not use the delivered-row shortcut. Denial, unknown coverage or an
evaluation error (including an exhausted probe meter) becomes `E_PREDICT`.
Existing admission/replay savepoints roll back the whole mutation and queue it
without predicted rows. Delivered reads, static classification, settlement,
wire forms and IR are unchanged.

`engine/timeline.rs::timeline_insert` keeps F3b's existing foreign-owned-row
`Skipped` outcome through the same rule evaluator. The declared timeline still
predicts the post, event and own inbox copy (three rows); application-authored
foreign fan-out still queues the entire mutation.

The 50-member presence prediction still pays two rule probes instead of the
base's one: one write check and one final read check. Its other six measured
counters are unchanged.
