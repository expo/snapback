# Lane E round 12 — consumed predecessors and irrevocable public handles

Implemented both findings, added I8, and widened the executable model without
changing the public API or server protocol.

## File-by-file changes

- `packages/snapback4/src/app.ts`: retain the one known consumed predecessor
  of an unpersisted rotation. Under the session lock, refusal cleanup may match
  the refused token or that predecessor, while leaving unrelated successors
  untouched. Successful persistence clears that predecessor marker. Every hide
  fences exposed facades before publication; private raw session custody remains
  independent. Rollback exposes a fresh facade. Stale lifecycle methods cannot
  close or log out the private owner or a replacement facade.
- `packages/snapback4/src/app-client.ts`: make each public facade permanently
  revocable. Fence getters, reads, writes, refresh, credentials, callbacks and the local
  runtime's existing sync helper;
  recheck asynchronous completions. Detach underlying observations and notify
  subscribers with refused snapshots after the app publishes its new view.
  Retained handles cannot regain authority when the raw client is reused.
- `packages/snapback4/test/app-handles.test.mjs`: five focused real-server tests
  for predecessor cleanup, unrelated replacement preservation, online/local
  failed global logout, and rollback without reviving old handles.
- `packages/snapback4/test/app.test.mjs`: update the two ordinary-close tests
  for I8. A pending public refresh now returns E_AUTH after its facade is hidden;
  the existing checks still require its successor to be stored and restorable.
- `packages/snapback4/test/helpers/app-session-model.mjs`: capture handles at
  arbitrary points, use them later, retain observations across transitions, and
  inject exactly one rotation-save failure followed by recovery. Hold read/write
  responses as well as auth responses and storage writes. Check I8 at auth/client
  callbacks, observation snapshots, operation completions and wire dispatch.
  Refused-token ancestry includes known consumed predecessors for I7. Private
  custody is tracked from issuance ancestry, not by reading a leaked public
  session after the facade is hidden.
- `packages/snapback4/test/app-session-model.test.mjs`: retain the earlier
  regressions, add both reproductions and a composite-reopen oracle regression,
  require coverage of the added operations, and run 5,000 seeds by default.
- `packages/snapback4/CLIENT-AND-OPERATIONS.md`: document I8, private retry
  ownership, permanent handle revocation, new rollback facades and the pending
  refresh result after close.
- `llp/3000.013-quarry-states-intent.rfc.md` §6: record the implemented I1–I8
  semantics and wider model.
- `JOURNAL.md`: one dated append with changes, measurements and limitations.
- This report records qualification and scope decisions.

## Invariants and coverage

I1–I7 retain their round-11 meaning and documented failure/recovery assumptions.
**I8:** after an account is hidden, no previously issued client facade or
observation can access it again. Public validity is separate from private raw
rotation/logout custody. A failed replacement can restore the old principal
through a new facade without reviving the revoked one. The guarantee concerns
future access through handles; JavaScript values or credentials already copied
by application code cannot be retroactively erased.

The final standalone run passed **5,000 sequences, seeds 1–5,000**, with
**130,000 commands** across three actual createApp runtimes and one mock server
and store. The **22 operations** are signup, login, guest, refresh, logout,
logoutEverywhere, close, closeClient, reopen, reopenOffline, query, revoke,
revokeCurrent, holdStore, release, capture, handleQuery, handleMutate,
handleRefresh, observeHandle, readObservation and refreshFault.

Measured coverage:

- **16,675 captured handles**, **6,077 hidden handles**; subsequent hidden-handle
  calls: **1,032 queries**, **1,022 mutations**, **1,026 refreshes**.
- **5,298 observations**, **5,871 notifications**, including **501 observations
  that held data before their account was hidden**. Captured subscriptions
  received **6,949 session notifications** and **6,077 viewer notifications**,
  with no credential/viewer disclosure after hiding.
- **579 targeted single rotation-save failures**, followed by storage recovery;
  **3,172 get**, **328 set**, **98 delete** indexed faults. The existing separate

- **3,060 held storage writes**, **18,670 peer commands during held storage**;
  **387 held read responses**, **130 held write responses**.
- **4,484 external server revocations**, **6,396 offline fetch attempts**.
  Held auth responses: signup 608, login 76, guest 538, refresh 425,
  ordinary logout 1,842 and global logout 131.

All **18 model tests** pass: the 5,000-sequence run, 16 fixed reduced cases and
one failure sweep. The standalone model suite took **52.220 seconds**, including captured session/viewer callbacks.

The five real-server cases prove:

1. T rotates to S; exactly one session save fails; S is revoked and refused;
   cleanup tombstones the still-stored T, and reopening offline stays signed out.
2. The same refusal cannot delete an unrelated replacement committed while
   the rejected refresh response is held.
3. Online failed global logout preserves the stored bearer and private retry
   credential while captured getters, queries, mutations, refresh, observations
   and lifecycle controls remain fenced; retry revokes a sibling session.
4. The same boundaries hold for a real local client with private replica data.
5. A failed replacement restores the previous guest through a new facade;
   old observations and handles remain refused, and their lifecycle methods
   cannot close or log out the restored owner.

## Discoveries and intentional behavior changes

The handle-focused probes exposed related gaps beyond the two incoming examples:
raw session/refresh and callback methods bypassed facade validity; failed
replacement could revive the same previously hidden facade; captured lifecycle
methods could act on a privately retained or restored raw owner. The facade
fence, fresh rollback facade and exposure checks close those paths. The real
regressions explicitly exercise them.

A final local-tier probe found one further surface gap: the raw `sync()` helper
was copied onto the facade and could still issue `/sync` after a failed global
logout. The real-server local regression failed with that exact dispatch. It now
requires no `/sync`, and the helper uses the same facade guard. Active sync keeps
working in the production offline-shell witness.

The expanded randomized run found **no additional product defect** after these
fixes. Seed 2292 found an oracle error: the composite reopen command first
successfully closed and saved a previously unpersisted successor, then failed
its new open on a get error. The oracle incorrectly compared that failure with
bytes from before the successful close. It now takes the failure-atomicity
baseline between close and reopen; the reduced sequence is retained.

Two existing ordinary-close assertions intentionally changed. Persistence and
reopening still succeed, but a refresh result delivered through an already
hidden facade returns E_AUTH instead of disclosing the successor credential.
That is the I8 boundary; raw rotation ownership and saved-session durability
remain intact.

## Limits and scope

No public method or Quarry form was added. README remains 296/300 lines. No
server, engine rule, disclosure rule, meter, native ABI, package version or
starter changed. The round-11 limits still apply: total failure of durable
refusal fencing followed by loss of every informed runtime cannot support a
stronger offline exclusion guarantee; unknown refresh successors and lost global
revocation acknowledgements require server recovery receipts. This round does
not change those protocols or claim to erase data already returned to callers.
No new unresolved product defect is known within the documented assumptions.
The first full-run final-read failure above was not reproducible in 160 targeted
runs; its original refusal/cause remains unqualified rather than being attributed
to a proven transport defect.
No push or publication.
