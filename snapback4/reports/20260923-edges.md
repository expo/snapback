## Fixes

1. **Unknown input before meter exhaustion queues the write.**
   `crates/snapback4-core/src/engine/local.rs` preserves `E_BOUND` when
   prediction has no genuine missing fact. When an unknown fact selected a
   counterfactual arm, the existing prediction failure rolls back speculative
   rows and admission keeps the write unpredicted in the outbox. Existing
   untaken-presence-arm handling is unchanged.
   `crates/snapback4-device/tests/readauth/round2.rs` exercises a provisional
   check authorized by a retained note, followed by 8,192 point reads only on
   the apparent absence branch. Both stores cover zero-work and expensive
   unknown branches, a held positive witness, and a covered absence that must
   still refuse with `E_BOUND`. Admission goes through the JSON dispatcher.

2. **Aggregate existence combines witnesses existentially.**
   `crates/snapback4-core/src/engine/read.rs` resets the witness verdict to
   known when a covered live source establishes existence, even after an
   uncertain retained source. It does not recursively authorize raw witnesses.
   `crates/snapback4-device/tests/readauth/round2.rs` tests retained `a` plus
   pending `z` and retained `z` plus pending `a` on both stores. Retained-only
   sources remain unknown; adding the provisional source makes the check
   readable and complete, including through JSON query dispatch.

3. **Device-only authority work consumes a separate prediction allowance.**
   `crates/snapback4-core/src/rows.rs`,
   `crates/snapback4-core/src/engine/recorded.rs`,
   `crates/snapback4-device/src/device.rs`, and
   `crates/snapback4-device/src/device/recorded.rs` pass the same meter through
   attribution coverage (corrected in review round 1 to use the separate
   allowance, never the server-equivalent mutation meter). Membership pages cannot exceed the remaining
   examination allowance; metered store scans prepay fetched row/key storage,
   and key construction, materialization and cursor decoding are charged.
   Exhausting that allowance queues the write without predicted rows, even
   after an earlier coverage check succeeded. The original claim that every
   resource failure after established coverage remains an ordinary refusal
   was wrong: successful coverage had already spent device-only work against
   the mutation meter, making a later server-equivalent read refuse early.
   `tests/maintains/recorded_membership.rs` reproduces 9,000 unswept expired
   memberships followed by one live replacement, through JSON admission on
   both stores. No source/aggregate prediction remains and no membership is
   swept. Unit coverage tests separately pin the examination cut, heap cut,
   and successful 9,001-examination control on both stores.

4. **JSON prediction requires an integer clock; clock-less intents queue.**
   `crates/snapback4-device/src/call.rs` rejects an omitted, null, wrong-type,
   fractional or out-of-i64 clock for direct `predict`. The round-3 author
   ruling corrects the earlier strict guard on `admit` and `enqueue`: those
   entries now clear `predictable` and `predicted` and queue for the server.
   An invalid clock is normalized before typed decoding; the unused stored default
   cannot trigger replay because eligibility is false. Explicit integer clocks
   remain supported. `tests/maintains/recorded_membership.rs` exercises owned
   JSON and JSON-text dispatch on both stores, verifies that rejected direct
   predictions leave no rows or outbox entry, and distinguishes live and expired
   membership clocks. Queue tests preserve IDs without speculative rows.
   The existing direct Runner missing-clock test stays in the core suite.

**Server-equivalent point reads.** During prediction, every non-system point
read reserves the server's static read-rule probes on the mutation meter,
before its lookup, including trusted synced rows and missing rows. Provisional
read authorization receives that prepaid reservation. Additional physical
witness work uses the device allowance. Queries retain their prior reservation
and authorization behavior.

**Physical witnesses.** While the prediction's device allowance is active,
`lookup_live` uses `scan_metered`, including its non-expiring single-candidate
path. Both the expired-sibling walk and the aggregate-source walk limit each
fetch to the remaining examination allowance, stop before fetching another row
when empty, and prepay materialization, cursor decoding and group-key allocation.
Aggregate evaluation steps are charged as well. Existing query/server rule
probes retain their accounting. The active allowance is shared by nested work
and restored on all ordinary error paths.

Authorization returns only a verdict; its fetched images and cursors are
already dropped. Their temporary heap reservation is released then, while
examinations, steps and probes remain charged across all authorizations.
Any once-only SQLite reservation released with that scratch is made payable
again, so later probes cannot reuse an uncharged reservation. This keeps the
8,191-read success case within the ordinary ceilings without accumulating
thousands of dead witness buffers. Allocation exhaustion still queues the
whole mutation unpredicted and rolls back its speculative insert.

The prediction guide records the reservation/physical-work distinction.
The existing zero-probe prediction assertion in `nested_read_ladder` now
expects the server-equivalent `Bound`, as required by this round's ruling;
its query assertions are unchanged. Its test Rows adapter forwards metered
scans, as required to exercise physical authorization on both stores.

### Context and correction

Read-only `llp-orient` scoped to `call.rs`, durable outbox imports and prediction:
LLP 3000 is the root; LLP 2000.000 §7.2–7.3 governs durable intents, preserved
client IDs and authoritative server execution; LLP 3000.001's repair C governs
adoption's preservation of IDs and order; LLP 3000.007.003 §3.2 requires live,
covered attribution targets and permits unpredicted queueing. All are in
`llp/current/`; Snapback 1 foundation gates do not apply here. The prediction
guide was read and updated. The explicit round-3 ruling supplies the clock
fallback policy. No new LLP or workflow apparatus; hand-off: none.

`admit` and `enqueue` share a queue decoder. A missing, null, wrong-type,
fractional or out-of-i64 `now` clears `predictable` and all `predicted` keys
before device admission or enqueue. Replacing an invalid clock in place with
the same unused zero that missing clocks decode to allows typed decoding of
the durable intent; that value is never used for prediction because eligibility
