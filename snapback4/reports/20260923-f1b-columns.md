## Clock

`Engine::new_at`, `adopt_at`, `open_at`, and `attach_release_at` pass a pinned
activation time to the activation runner. Existing entry points default to wall
time. Release deployment, which has no dev clock, keeps that default.

- Dev startup (including fresh memory) supplies `Clock::now()`, incorporating
  `--clock-offset`; startup retries sample that clock again.
- Release `serve` supplies its clock through release attachment, including the
  legacy derived-state repair path.
- Dev watcher adoption and generation-refusal reopen supply `shared.now()`.
- CLI `run` supplies its resolved `--now` to store-open activation, before
  invoking the operation.
- There is no server HTTP `/adopt` endpoint in this tree. HTTP clients obtain
  `/schema` after the watcher activates; their `adopt` dispatcher installs the
  projected backend locally and does not run server activation. The live HTTP
  regression covers that server watcher path.

The engine regression covers both `host_now < expiresAt < wall_now` and its
converse, through explicit adoption and store reopen. A SQLite trigger forbids
writing the host-expired parent. A dev-server regression covers `--clock-offset
-2h` through live watcher adoption and startup; it also checks CLI `run --now`.
