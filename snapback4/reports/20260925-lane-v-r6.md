## Changes by file

- `packages/snapback4/src/web-journal.ts`: one `journalStoreBinding` decision
  governs every journaled handoff. An unidentified destination defers a bound
  intent; a different destination retires it; only the matching store permits
  delivery. Only an absent binding retains pre-journal legacy custody. Own-tab
  recovery, fresh admission, transfer fencing and transport checks use this
  decision. Identity inspection uses `capture: false`, preserving request and
  snapshot metadata. Fresh admission checks the captured store before allocating a
  submission. Refusals reuse `E_ADMISSION`, with a site and concrete rewrite.
- `packages/snapback4/src/web.ts`: orphan adoption applies that decision to
  every transfer, including fresh writes, before enqueueing. Unknown destinations
  preserve source custody. Store restoration/adoption and observed-store changes
  fence mismatches. Exit and ordinary send gates check the intended ID and its
  binding against the current device identity. Transfer metadata and the outbox
  continue to commit atomically; transport stays outside admission locks.
- `packages/snapback4/src/local.ts`: pass the intended mutation ID into
  `begin_send`, allowing the web device's ordinary transport to check that exact
  entry. Native dispatch retains its behavior; the additional field is ignored
  by its existing dispatcher. This file remains 1,477 lines.
- `packages/snapback4/src/session-authority.ts`: write a migration only when
  the legacy mirror epoch advances the maximum authoritative marker/session
  epoch. Otherwise repair the mirror best-effort without allocating a separate
  authoritative epoch record. Absence repair deletes the mirror key. Reopening
  a committed session with exhausted localStorage therefore succeeds.
- `packages/snapback4/test/store-reset-idb.test.mjs`: explicitly declare the
  fixture's in-flight request instead of relying on a binding inspection to
  create it. All strict rollback assertions remain intact.
- `packages/snapback4/test/web-durability.test.mjs`: likewise declare the real
  request explicitly, then require reopening to abandon it without recovery
  manufacturing another capture. Retain the full durable-state equality oracle.
- `packages/snapback4/test/web-admission-review.test.mjs`: add two-tab replacement
  tests for ordinary and exit sending, checking no enqueue, no queued entry,
  no request and no replacement audit increment, including after close. Add
  unknown-destination deferral followed by same-store delivery of the original
  ID. Add the mutant deleting both orphan checks; refresh existing mutant sites
  for the shared binding implementation.
- `packages/snapback4/test/web-session-authority.test.mjs`: add actual Chromium
  quota exhaustion and reopen, plus synchronous mutation refusal under that
  quota. Extend migration cases to mirror 10 / IndexedDB 9, requiring epoch 10
  through login, captured stamp and a successful mutation. Add unconditional
  allocation and higher-mirror-discard mutants.
- `packages/snapback4/CLIENT-AND-OPERATIONS.md`: document the common binding
  rule, unknown-destination custody, and restoration without an epoch allocation.
- `../llp/3000.013-quarry-states-intent.rfc.md`, section 6: record those same
  guarantees in the governing design.
- `JOURNAL.md`: append one dated entry; prior entries are unchanged.
- `reports/20260925-lane-v-r6.md` and `reports/20260925-lane-v-r6-evidence/`:
  this report and raw qualification logs.

## Forms and behavior

No public signatures or Quarry forms changed. Existing forms run as follows:

```ts
const app = createApp({ url, device: webDevice(),
  sessionStore: localStorageSessionStore() });
await app.ready; // restores a committed session even when localStorage is full
```

A new `app.mutate(api.removeMember, { room, principal })` still synchronously
returns a failed `E_ADMISSION` write if quota prevents journal capture. A
previously admitted write in another tab stays bound to its original store:
closing that tab cannot enqueue or execute it on a replacement backend.

With a legacy mirror epoch 10 and IndexedDB epoch 9,
`await app.auth.login(email, password)` followed by
`await app.mutate(api.click, {})` succeeds with epoch 10. Lower mirror values
cannot decrease the authoritative epoch.

## Tests and evidence

All tests use real Chromium, IndexedDB/Web Locks and real password-auth backends.

- Ordinary orphan replacement: tab 2 commits a fresh, unsent write for A; tab 1
  adopts B; tab 2 closes. Tab 1 never enqueues that ID, and B's audit stays 0.
- Exit orphan replacement: the same sequence with tab 1 hidden also keeps B's
  audit at 0 through close. A's audit stays unchanged in both cases.
- Unknown destination: a fresh device with no store identity leaves the bound
  orphan in its source outbox. Matching sync later delivers the original ID
  once, advancing A's audit by exactly 1.
- Full storage: fill actual localStorage to its quota (5,241,876 characters of
  filler in the first run), prove an epoch-key write raises QuotaExceededError,
  then navigate and restore the same committed viewer and acquired client.
  No epoch mirror is allocated. A new mutation refuses synchronously with
  E_ADMISSION and leaves no journal record.
- Higher mirror: mirror 10 wins over present IDB epoch 9; login, stamp,
  authoritative marker, mirror and successful mutation agree on 10.

## Decisions, deviations and open problems

No deviation from the round-6 design and no unresolved problem in its scope.
Two existing fixtures deliberately changed: the reset and durability tests now
explicitly create their in-flight requests. A binding read no longer creates request capture
metadata; neither the rollback oracle nor its required fixture assertions were
relaxed.
Pre-journal unbound custody retains its existing behavior; every journaled
transfer uses the common binding decision. Tests observe the forbidden enqueue
as well as the audit, so later send guards cannot mask a broken orphan handoff.
The original ID remains durable while identity is unknown.

The additional per-write ordinary send field is internal and requires no wire
or native protocol change. Authorization, row disclosure, engine meters, bucket
ceilings, snapshot page sizes and transaction durability are unchanged. No new
refusal code or language form was introduced. No push or publication occurred.

not a new measurement: 13.298 / 15.825 / 18.703 seconds, versus 70.716 seconds
per-row (median 4.47x).
