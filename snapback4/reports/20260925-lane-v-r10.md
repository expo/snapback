# Lane V — round 10

The round-9 Astra and Grok findings are addressed. An acknowledgement in the
outbox resolves an earlier unknown-outcome `E_STORE_REPLACED` as `sent`, including
when the refusal became durable before sync applied the acknowledgement.
`NOT_ADMIN` and other authored refusals retain their existing receipt custody.

## Implementation, file by file

- `packages/snapback4/src/writes.ts`: select the acknowledged sequence before
  retrying a speculative replacement receipt; remove an unpersisted replacement
  refusal and repair a persisted one through the device receipt writer.
- `packages/snapback4/src/local-receipts.ts`: retry preflight selects positive
  acknowledgement evidence before terminal-history lookup and settlement.
- `packages/snapback4/src/local.ts`: use that selection in ordinary flush,
  final send preflight and `write(id)` lookup. A failed correction save retains
  the known success. The file remains below the 1,500-line ceiling.
- `crates/snapback4-device/src/device/store_identity.rs`: explicitly replace an
  existing `E_STORE_REPLACED` row only for an individual sent receipt whose
  sequence matches `sent_seq` or `observed_seq` in the same transaction's
  outbox. Preserve the receipt's position in the 256-entry window. An adopted
  history list, missing acknowledgement, mismatched sequence or authored
  refusal does not authorize this overwrite.
- `packages/snapback4/CLIENT-AND-OPERATIONS.md` and
  `../llp/3000.013-quarry-states-intent.rfc.md`: record the narrow positive-
  acknowledgement exception to terminal receipt immutability.
- `crates/snapback4-device/tests/write_authority.rs`: memory and SQLite coverage
  for both acknowledgement fields, missing/mismatched evidence, authored
  refusal preservation and reopen.
- `packages/snapback4/test/acquisition.test.mjs`: an aborted replacement receipt
  is dropped before any persistence retry when success is acknowledged.
- `packages/snapback4/test/web-admission-review.test.mjs`: real-browser lost-
  response/replacement-refusal/sync-acknowledgement recovery and the pending
  changes rewind interleaving. Both verify durable original success after
  reopen. Provider and response gates establish the ordering; committed-batch
  observations prove that the refusal was stored and then acknowledged.
- `packages/snapback4/test/client-seams.test.mjs`: keep sync temporarily
  unavailable until the HTTP replay receipt arrives, making the existing wire
  replay test deterministic while retaining every original assertion.
- `JOURNAL.md`: append-only round-10 qualification entry. This report and its
  evidence directory preserve the test results and intentional fault failures.

## Forms

No new Quarry syntax, refusal code or public API was introduced. Existing
`app.mutate(ops.remove, args, { id })` and `await app.client.write(id)` retain
their signatures. In the lost-response regression, lookup returns
`{ state: "sent", id, seq, replayed: true }` using A's original sequence,
including after reopen; A's audit advances once and B's remains zero.

## Decisions, deviations and failures

No design deviation. Receipt correction is implemented in the shared device
writer so its proof and overwrite share one transaction on both device stores.
The existing `observe_store` barrier needed a regression, not a production
change. No page size, storage bucket, authorization rule, durability setting or
meter changed; cold acquisition was not remeasured for this receipt-only round.

Development test failures were in the new harness: the first rewind poll
predated `begin_send` and was correctly rejected as obsolete; an immediate
`createApp.sync()` call had not yet crossed asynchronous authorization when the
held response was released, so retry could settle before the intended sync.
The final test waits for the current poll capture and actual local sync entry.
The first full browser run reported 47 passes and two failures (the new child
and its parent); its evidence is retained in `browser-all.log`. The deliberate
fault variants exit nonzero by design. The supplied baseline log's cargo
failure was inspected before attributing failures.

The first full qualification ended `== 1 failure(s) in 716 s` (`client tests`;
exit 1). Its 78 model checks passed. It found an existing wire-replay assumption in
`client-seams.test.mjs`: the process-device immediate lost-reply case required
exactly two HTTP responses even when sync could settle the acknowledgement
first. This is classified as ours: receipt selection made that permitted order
visible. The fixture now keeps `/sync` unavailable until the second HTTP reply,
so it still tests the exact replay body, request identity, one server effect and
one value-free terminal receipt. The corrected 55-test seam suite passes.

No open problem or stopped part. No push or publication.
