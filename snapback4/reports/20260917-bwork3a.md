## Behavior

The generated-worker declaration digest covers the generic-value validator
tag, exact effect name and full declared work policy. It excludes individual
payload and release provenance. The previously persisted row-contract bytes
are unchanged; this adds no column, payload migration or second identity model.

An optional `declarationContract` claim field requires a named, fenced claim.
The host validates present fields before taking the engine mutex. Inside one
writer transaction the core samples current service authority once and
compares the current named declaration before expiry, queue selection,
presence cleanup or attempt mutation. A mismatch returns
`E_EFFECT_GENERATION`; it does not claim or maintain work. Successful strict
claims include the server-derived declaration digest. Omitting the request
field preserves the low-level compatibility path.

`POST /effects/<encoded-id>/status` requires current service authority and
exactly one nonempty lease header. The transaction checks the admitted row
contract, then requires the running row's claiming service and exact lease.
It may finalize only that target's deadline/cancellation, but does not requeue,
reclaim or create successor authority after lease loss. Existing terminal
evidence remains intact. The HTTP answer exposes only `id`, `attempt`,
`state`, `deadline`, `cancelled` and `errorCode`.
