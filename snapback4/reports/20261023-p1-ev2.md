# P1-EV-2 — Postgres ordinary value-domain evolution

Branch `sb4-pg/p1-ev2`, starting at `19ac8b7e47`, on expo-build-450a.
Implementation commits: `89406f6675`, `286b89fa87`, `d6fb3662bf`.

The common engine admits ordinary type/bound, requiredness, default and text/cap
constraint changes, including edited dormant definitions and required/contextual
default columns. Missing historical required values refuse `E_ADOPT`; explicit
nulls can become dormant. Incompatible images and transitive referencing rows
remain uncoerced in `_dormant_narrow_rows`; later widening restores compatible
subsets. Partial row restoration keeps unused cells. Unique/cap conflicts roll
back rows, keys, retained state, metadata, catalog, generation and release history.

EV-3 backfills, EV-4 authority/lifetimes, EV-5 renames and EV-6 destructive/operator
surfaces retain their existing refusals before preparation. Other unadmitted
constraint kinds keep their prior family. Expiring capped populations remain
EV-4: SQLite uses `_cap_counts` only for those populations. Ordinary EV-2 caps
compare live indexed groups and the empty physical ledger; temporal narrowing
is not claimed. Retained column records preserve kind/default, ownership/capture,
delete policy and text constraints exactly until cells are consumed.

production is unchanged. SQLite verdicts also govern sparse default changes,
explicit-null requiredness, required/context-default additions to empty versus
populated tables, edited retained definitions, and dev `E_ADOPT` refusals.
