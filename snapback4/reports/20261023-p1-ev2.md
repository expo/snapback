# P1-EV-2 — Postgres ordinary value-domain evolution

Branch `sb4-pg/p1-ev2`, starting at `19ac8b7e47`, on expo-build-450a.
Implementation commits: `89406f6675`, `286b89fa87`, `d6fb3662bf`.

The common engine admits ordinary type/bound, requiredness, default and text/cap
constraint changes, including edited dormant definitions and required/contextual
default columns. Missing historical required values refuse `E_ADOPT`; explicit
nulls can become dormant. Incompatible images and transitive referencing rows
remain uncoerced in `_dormant_narrow_rows`; later widening restores compatible
subsets. Partial row restoration keeps unused cells. Unique/cap conflicts roll
back rows, keys, retained state, metadata, catalog, generation and release history.

EV-3 backfills, EV-4 authority/lifetimes, EV-5 renames and EV-6 destructive/operator
surfaces retain their existing refusals before preparation. Other unadmitted
constraint kinds keep their prior family. Expiring capped populations remain
EV-4: SQLite uses `_cap_counts` only for those populations. Ordinary EV-2 caps
compare live indexed groups and the empty physical ledger; temporal narrowing
is not claimed. Retained column records preserve kind/default, ownership/capture,
delete policy and text constraints exactly until cells are consumed.

The evolution target now has 47 cases, including 12 EV-2 scenarios. The latter
compare raw active/dormant/narrowed bytes, source definitions and causes, retained
reference evidence, indexes, occupancy, interpreted rows and query meters,
inventory, release summaries/items and failed-activation snapshots. SQLite
production is unchanged. SQLite verdicts also govern sparse default changes,
explicit-null requiredness, required/context-default additions to empty versus
populated tables, edited retained definitions, and dev `E_ADOPT` refusals.

## Fix round 1 — 2026-10-23

Blind reviews `/tmp/p1ev2-review-sol.md` and `/tmp/p1ev2-review-grok.md`
requested changes to retained-definition admission and group refusals.

- **Sol P1:** the Postgres narrowed-row cursor no longer adds 64 times the
  retained definition size to its row payload reservation. Ordinary SQLite
  restoration does not charge that definition as live-activation provenance.
  The dual-store witness puts a 300 KiB literal default in v1 with `n=99`,
  hides it under v2's `n: int 0..10`, restores exact matching bytes in v3,
  then succeeds on an unrelated v4 release. Against unchanged production
  source from `33d0c5120b`, SQLite restores at v3 while Postgres refuses
  `E_BOUND`: heap 59,981,832 / 16,777,216 bytes at `adopt stored rows`.
- **Grok Medium:** dev unique/cap conflicts now return the same `E_ADOPT`
  schema step, specific rewrite and population evidence as SQLite. Release
  conflicts share SQLite's group formatter and bounded sample helpers,
  including bridge/inspect guidance and active/restored origins. Postgres
  spills counts/conflicting ids to transaction-local tables. No population
  buffer or request-path call is added. Before the fix, new uniqueness over
  duplicate item values and cap 2 → 1 return Postgres `E_CONSTRAINT` versus
  SQLite `E_ADOPT`; retention-enabled variants return different message text.
  A six-group restoration conflict also fails the old text comparison and
  now compares exact text through SQLite's five-group/five-id sample limits.

The requested cap 1 → 0 scenario cannot reach `adopt_at` store dispatch:
Quarry text rejects zero, and the typed schema API returns `E_SCHEMA`
(`tables.notes.constraints[0]: cap needs a positive maximum`) on both stores.
Separate dev/release witnesses pin this equal refusal and unchanged state.
The smallest valid tightening, 2 → 1 over two matching rows, reproduces and
regresses the reported adoption defect without changing schema validation.

Failing-before evidence uses the new witnesses with all four production files
restored from `33d0c5120b`: **14 passed, six failed**, exactly the new retained
lifecycle, dev/release unique/cap and restoration-text cases. Both zero-cap
parity guards and all 12 prior EV-2 scenarios pass before the fix. The fixed
55-case evolution target passes with no ignores. Raw logs and recorded process
identities stay outside Git under `/tmp/sb4-p1ev2-fix1/`.

The separate maintained-column scope exposed a defensive adapter fixture that
activates below public schema admission with no programs. SQLite skips successor
assessment on that path and returns its physical `E_CONSTRAINT`. Postgres now
selects adoption diagnostics only from public activation; the test-only physical
entry point keeps SQLite's original code and text. Public adoption behavior is
unchanged by this follow-up, and the existing maintained fixture is unchanged.

Dev successor-step selection also skips newly added additive literal-default
columns, matching SQLite: a conflicting new unique index is diagnosed at its
index step. The same unique-refusal test now covers that combination too.
