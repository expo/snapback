## Accepted and executed forms

```quarry
query overdue(c: cursor ?):
  return tasks where .orgId = viewer and .due < now first 50 by .due after c
query open(c: cursor ?):
  return tasks where .orgId = viewer and .status != 'done' first 50 by .createdAt after c
query assigned(c: cursor ?):
  return tasks where .assignee = viewer and exists memberships[.orgId, viewer] and .status in ['todo', 'doing'] first 50 by .createdAt after c
```

The first form is an exclusive-null seek. All four comparisons, reversed
operands and residual scans obey the same null rule. The second has identical
schema and executable IR to `in ['todo', 'doing']`. In the third, membership
supplies discovery lanes and the displayed remaining predicate is
`.status in ['todo', 'doing']`, not `false`.

## Engineering choices and limitations

Nullable enums remain residual, as expressly permitted. Larger enums also
remain residual. Complement extraction handles literals and stable bound
names. Other computed exclusion expressions remain under their original
predicate guards: hoisting a helper containing `10 / d` out of a preceding
`d != 0` guard would introduce an error, repeating the earlier aggregate
regression. This conservative optimization boundary is documented and tested.
No requested example remains blocked. The only existing fixture update is
the census block-number shift described above; no authorization expectation
changed.
