## Adoption hook points

- `schema.rs` and `engine/validate.rs` retain F1a's implicit-zero materialization
  and validation; index-key construction and CLI SQL project the same zero. The
  field has no `ColumnDefault::Literal`. Old images validate during the store's
  assessment and activation walk.
- `successor.rs` gives the required maintained-column addition its named
  `Additive` exception; it still reports ordinary parent narrowing, and the
  parent is never a maintain target. Resolved source dependencies compare type,
  optionality, default and recorded interpretation, in addition to the maintain
  definition.
- `store/activation.rs` removes the interim refusal. `engine/mod.rs` uses the
  resolved rebuild trigger and records the parent barrier even with no writes.
- New `engine/column_activation.rs` computes affected parents, including removal
  and resolved parent expiry changes; rebuilds private totals; then scans live
  parents in 256-row pages and mirrors each differing field in place. The
  parent expiry pointer and the named field's type/default/optionality are
  compared. Initial zero parents remain physically untouched; nonzero-to-zero
  redefinitions write 0. Other ordinary and maintained fields survive.
- `engine/maintains.rs` suppresses per-contribution mirrors during a private
  rebuild; `engine/columns.rs` supplies the shared final mirror pass to imports
  as well as activation. Activation scopes `event_free` around private rebuild
  and mirror only. Ordinary maintain activation retains its existing events.
- Removal uses the store's existing table removal; re-addition rebuilds from
  source. Private storage never appears in commit table names or public schema.
- Existing projected derivation metadata makes addition/redefinition differ
  under `keeps_literal_default_images`. Both device stores discard old confirmed
  images and refuse local reads during snapshot reacquisition. No old parent
  image can be served with a newly inferred zero.

## Current-generation composition and surface

`column_cost.rs` bounds this form's own whole-parent events from the resolved
schema, per recipient. A source attempt reserves one application write plus
four private/mirror writes per maintained column, with up to two old/new parent
puts per column. One column permits at most 204 such source transitions under
the unchanged 1,024-row mutation ceiling; other operations/meters may reduce
that number. Output names the parent and column, private stream bytes (zero),
activation event bytes (zero), and snapshot recovery. Application event bytes,
acknowledgements and the reply envelope are explicitly excluded from the
own-derived bound. A checked CLI sample with `body: text <=4000`, `at`,
`id` and `likeCount` reports 16,417 B per parent event and 6,698,136 B own
derived bytes per mutation; its source and actual output are recorded in
[`column-cost.q`](20260922-f1b-columns/column-cost.q) and
[`column-cost.log`](20260922-f1b-columns/column-cost.log). Unbounded asset metadata is reported as an unknown wire
bound, not a fabricated number.

A real HTTP test moves 204 distinct sources between 408 distinct parents with
42,000-byte bodies: **17,136,000 parent body bytes** compose in one commit. The
limit-one stream refuses with `E_BOUND` and a snapshot-restart instruction;
both SQLite and wasm devices recover correct counts at generation 1, watermark
16. The maximum delivered recovery response is 42,487 bytes. No new write-time
byte guard is introduced. A separate Rust fixture uses 4,000-character Unicode parents and the production
HTTP codec: 204 source moves produce 408 parent events (6,566,728 B against a
6,688,752 B derived bound), and a complete reply of 6,584,511 B. It asserts the
205th attempt rolls back; [the measured test output](20260922-f1b-columns/column-commit.log)
records the 10,192,705 B remaining reply headroom. The cost report also uses the
8,192-row ceiling for job chunks, allowing up to 1,638 source attempts for one
column before other work reduces that bound.

`why posts` describes each column's source and parent residency.
`test --residency` reports acquired parent-value counts and compact value bytes
already included in the parent payload, without separate device rows.

## Retired interim and rewritten notes

The maintain value-index suffix is again exactly `value, id`, after an optional
prefix of group fields. Its refusal points to `likeCount: count likes by postId`
and `by byLikes: likeCount, at, id`. Aggregate-copy diagnostics lead with that
column form, then pinning both insert and update rules for a derivation the
column cannot express. The maintains card removes W15c's interim exception and
F1a's fresh-store-only boundary.

The feeds card now uses one merge over 25 hour lanes of
`by byHourLikes: hour(at), likeCount, at, id`. Zero-like parents participate
naturally; ties use post time and id. There is no copied `postAt`, public score
write, or zero-fill query. Simulator and both device-store fixtures use the
card itself and compare against independent source counts/time ordering,
including moving keys and cursor cuts. The indexes, rules and language cards
explain adoption too. `guide::CODES` removes the retired interim activation
code; no new diagnostic code was needed.

The retirement ticket is resolved under `issues/closed/` with this report's
pointer. Historical F1a/W15c reports remain historical records.
