## RT3b rebase

P1-CE and both RT3a/RT1/RT2 fix rounds. Store facts retain RT3b's reusable SQL/row
projection with RT3a's miss-only discovery and retry. SQLite ingress retains its
anchor cursor during discovery/retry, preserving one implicit snapshot without
extra transaction framing. Postgres unknown-storage ingress misses discard the
initial probe and repeat through the dedicated authority snapshot, which checks
generation and publishes committed storage availability. Transactional callers,
including final mutation checks, use the discovery helper. Fork flags and
Postgres savepoint rollback re-probes remain unchanged.

RT3a's raw-NUL absence replaces RT3b's bind refusal at facts fetch and ingress.
The existing zero-query guards at `resolve_session_tx` and both session snapshot
openers survive. No §3.1 boundary requires a NUL refusal: public bearers hash to
a digest, and NUL is an absent internal optional lookup key. Admission of stored
identity strings remains fail-closed. A second semantic choice retains RT3b's HTTP 503 for a foreign activation at
the query generation boundary in place of RT1's old separate-auth-walk 401.
The committed mutation still returns 200 and wakes subscribers; the next query
refuses E_GENERATION, now with no unauthenticated generation/head/store id.
The combined regression asserts that behavior explicitly.

Both sides' test hooks survive. Query handoff argument decoding and fail-fast
metadata survive, including the memory fallback; an early handoff argument
refusal authenticates its fresh metadata cut. No store facts are disclosed on
a failed authority read.
