The old blanket refusal prevented a mutation from manufacturing a hidden
expired population or authorization verdict and measuring it through an
abort. A never-predicting mutation's wholly read-only initial statements
cannot manufacture that state. The implementation admits uniform plain
expiring scans only there, using original scan identity and the existing
recursive effect checker. Any write or emit anywhere in an enclosing
statement ends that phase before the entire statement, even in an untaken
arm. Matching, merges, predicting expiring scans, and the prior disclosure
attacks still refuse. Engine `E_BOUND`, clocks, meters, receipts and budgets
are unchanged.

The builder can now bind the live blocker before changing receipt state:

```quarry
mutation delivered(conversation: conversations, from: int, through: int): server
  -- Read member/chat and merge runs into low/high without deleting.
  -- prefix is max(me.deliveredOrdinal, me.joinedOrdinal).
  if prefix + 1 < low:
    blocker = first(messages where .conversation = conversation and .ordinal > prefix and .ordinal < low first 1 by .ordinal)
    prefix = blocker.ordinal - 1 if blocker != null else low - 1
  -- Then delete merged intervals and update the prefix or insert the run.
```

This is an excerpt; the complete compiled program is
[`delivered.q`](../experiments/er-expiring-pages/delivered.q). Both that
program and the receipts card now require a free slot with `RUNS_FULL`,
before a disjoint run's prefix update and insertion. They cannot silently
return success with all 64 slots full.

## Alternatives and measurement limits

| Alternative | Counterexample / disposition |
| --- | --- |
| Remove expiry refusal from every uniform server scan | A blind update transfers and expires an unreadable row; retained ordinal 1 versus 2 yields `E_BOUND` versus `STOP`. Hidden gates and transitive maintain writes supply further attacks. The initial phase is required. |
| Use the current schema cap alone | Cap 4 permits three expired waves with 12 physical unswept rows. A live cap does not bound physical examined work. A new physical cap would block insertions behind expired rows and still needs a population-independent reservation. |
| Sweep rows in the mutation | 10,000 deletes exceed the 1,024-write ceiling, rollback restores the backlog, and retry makes no progress. Free or independently committed deletion would weaken metering or atomicity. |
| Reorder the ordinary index around expiry | `(conversation, ordinal, expiry)` still walks backlog; expiry-first ordering can select live ordinal 2 before ordinal 1. A bounded summary index remains a separate, unbuilt design. |
| Skip expired rows for free | Ten million expired candidates followed by one live row make a one-row result unbounded. SQL filtering does not erase work. |
| Query first and pass selected ids as absence proof | A partial horizon, incomplete answer, changed membership or untrusted caller can omit a live blocker. Selected ids do not prove a gap. |
| Predict the scan because the live group is capped | A device-only unswept backlog can fail initial admission even after the server has swept; output caps prove neither equal work nor complete coverage. |
| Precise dependency closure / evaluation-order analysis | It must protect the page table, hidden gates and transitive maintenance, including expression writes and repeated filters. The sufficient initial-phase rule avoids that larger analysis; it remains declined. |
