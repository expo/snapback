## Result

A legacy sequence proves a server decision, not its outcome. Unqualified
`observed_seq` and legacy-promoted `sent_seq` remain pending without known
terminal history. Their original id is replayed against the original store;
its idempotency record supplies the success or refusal. Neither a sequence
nor a replacement refusal can manufacture success.

New snapshot/stream replies carry an additive `sent: { id: sequence }` map.
The device saves that success qualification with the receipt's store binding,
including across private acquisition pages, and exposes it only when the
matching sequence is published. Existing acknowledgement maps remain compatible.
A replay from the original store can correct an unknown `E_STORE_REPLACED`
outcome in place, including to a real refusal. The device checks the bound
store in the history transaction; receipt retries retain that proof after
aborted saves. Authored failures remain immutable. Native modules must advertise
`receipt_outcomes`; mismatched JavaScript/native versions refuse startup with
the existing `E_DEVICE_VERSION` and a concrete rebuild instruction.

The final `begin_send` check returns `recoverReceipt()`'s known outcome.
Unqualified web custody still invalidates an in-flight sync before same-id
replay. All mutation requests retain their original server-enforced binding.

## Running forms and reproductions

No new Quarry form or public API. Existing `client.mutate(op, args, { id })`
and `await client.write(id)` now agree after an upgrade:

- Old `{ observed_seq: 3, receipt_store: { id: A } }`, no history, A's `_ops`
  contains `NOT_ADMIN`: offline lookup/retry stays `pending`; reconnect POSTs
  the same id with `store_id: A`, returns `failed / NOT_ADMIN`, audit stays 0,
  and reopen retains the failure. The same test runs with legacy `sent_seq`,
  with stored `E_STORE_REPLACED`, and on both memory and SQLite stores.
- New `{ acknowledged: { id: 7 }, sent: { id: 7 } }` qualifies success. A
  matching outbox acknowledgement corrects a stored replacement refusal.
- Gate `begin_send` after initial preflight; install a legacy acknowledgement
  and the real server's `NOT_ADMIN` receipt; release the gate. Mutation,
  notification and lookup all return the refusal, with no client POST.

Negative controls deliberately fail: `legacy-success` returns `sent` instead
of `pending`; `final-preflight` returns `sent` instead of `failed`; `only-admin`
turns `NOT_FOUND` and `CONFLICT` into `sent`. These are assertion failures,
not setup errors. Commands and raw output are in the evidence directory.

## Failure accounting and decisions

Development failures belong to this change: the first upgrade test's nullable
boolean `require` needed `= true`; older Rust fixtures assumed bare sequences
were success; one browser startup fixture made the same assumption; an empty
new map changed a frozen serialization fixture. Corrected by using the typed
condition, retaining legacy custody, qualifying positive fixtures, and omitting
empty maps. The first full run also exposed missing `sent` fields in direct
Rust reply constructors and ten client fixture failures (two replacement
transport cases; eight memory/process × staged/deferred × head 20/25 cases).
These success fixtures now qualify their simulated outcomes; their behavioral
assertions remain. One intermediate constructor edit also touched a function
signature and was corrected; the complete test-artifact build then passed.
Initial wasm experiments exceeded the old ratchet; the final
measured reason accompanies the adjustment. Deliberate mutants remain red.

Engineering choices where the brief was silent: an additive success map rather
than historical result data; qualification retained with existing receipt
binding; a native capability guard to prevent an old device core erasing legacy
custody; private same-store proof on receipt persistence. The proof is removed
before storage and never becomes a public receipt field. No authorization or
disclosure change, no unbounded scan, and the 256-id/window bounds remain.

No acquisition retuning or scale remeasurement in this receipt-only round.
No push, package publication or version bump. Open scoped problems: none known;
both requested findings and Grok's additional mutation gap are covered.
