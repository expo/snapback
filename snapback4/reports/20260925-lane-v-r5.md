# Lane V — round 5 review fixes (2026-09-25)

All findings from `v-r4.astra.md` and `v-r4.grok.md` are addressed.
This round preserves IndexedDB session authority, synchronous localStorage
capture, recovery before sync, validated exit transport, and wrapped stores.

## Changes by file

- `packages/snapback4/src/web-journal.ts`: retain every queued write's transfer
  marker, including fresh admissions; dequeue every transfer bound to a different
  observed store. The marker continues to share the atomic row/metadata/outbox
  transaction. After a rejected authority check releases its session lock,
  schedule the app's authorization check to fence stale observations.
- `packages/snapback4/src/admission-authority.ts`: add the internal `recheck`
  capability to the app-owned admission context. No public API or new code.
- `packages/snapback4/src/app.ts`: supply the recheck callback and reconcile
  epochs under the session lock before restoration or sign-in opens a scope.
  The in-memory scope uses the reconciled authoritative epoch.
- `packages/snapback4/src/session-authority.ts`: migrate the greatest legacy
  mirror, IndexedDB marker and committed session epoch into the IndexedDB epoch
  record and mirror. Ordinary authorization still reads only IndexedDB. Missing
  authority now deletes its mirror. Read repair restores committed session A
  over a speculative session B. Migration does not erase the old mirror fence
  before commit, and restores that fence if its transaction aborts.
- `packages/snapback4/test/web-admission-review.test.mjs`: check a fresh click
  during a held replacement probe after releasing sync, inspecting both audit
  and persisted outbox through `read()` and a fresh `load()`. Check the audit
  again after close. Add faults for recovered-only fencing and early cleanup.
- `packages/snapback4/test/web-session-authority.test.mjs`: hold a private
  observation while another tab logs out, then capture against a stale mirror.
  Assert synchronous journal capture, eventual E_AUTH, no send/outbox entry,
  signed-out auth, null viewer, lost acquisition and withdrawn observation.
  Add migration, absence, crash repair and aborted-migration regressions and
  fault switches that prove the assertions are sensitive to these fixes.
- `packages/snapback4/CLIENT-AND-OPERATIONS.md`: document all-write store binding,
  post-refusal observation fencing, migration and mirror repair.
- `../llp/3000.013-quarry-states-intent.rfc.md`, section 6: record the same
  session and custody guarantees in the governing design.
- `JOURNAL.md`: append one dated round-5 entry; existing entries are untouched.
- `reports/20260925-lane-v-r5.md` and `reports/20260925-lane-v-r5-evidence/`:
  this report and raw qualification evidence.

## Forms that run

No Quarry forms or public client signatures changed. The existing paved forms
now cover these cases in real Chromium against the real password-auth backend:

```ts
const app = createApp({ url, device: webDevice(),
  sessionStore: { ...localStorageSessionStore() } });
await app.ready;
await app.auth.login(email, password); // works with a legacy .epoch = "5"
const write = app.mutate(api.click, {}); // captures synchronously, then sends
```

A click captured during a held probe remains bound to its original store:
`app.mutate(api.removeMember, { room, principal })` cannot execute on a replacement
backend after sync/adoption. Its mismatched outbox entry is retired.

For a stale mirror after peer logout, `const write = app.mutate(api.click, {})`
first journals; `await write` returns `failed` with `E_AUTH`. The locked recheck
also withdraws the old scope's `client.observe(api.privateNotes, {})` snapshot,
viewer and acquisition state. A transient mirror mismatch retains its existing
confirmation semantics; it does not by itself revoke a valid scope.

## Tests and measurements

Real-browser additions/extensions prove:

1. Fresh capture during a held replacement probe cannot cross store identity,
   even after releasing sync; replacement audit stays 0 and no durable outbox
   entry remains.
2. Real peer logout plus a stale localStorage getter captures the click but
   refuses it with E_AUTH. A held change poll cannot preserve private observed
   rows, viewer, auth or acquisition after confirmation.
3. A leftover epoch "5" with no IDB record survives migration; login and a
   successful mutation use epoch 5. With IDB epoch "9", they use epoch 9.
   The mirror, authoritative marker, session and captured stamp agree.
4. Missing IDB authority deletes the legacy credential mirror and requires
   sign-in; credentials are never imported from the mirror.
5. Reopen with committed A and speculative mirror B restores A, repairs the
   mirror, synchronously captures a mutation and executes it successfully.
6. Aborting migration preserves the legacy epoch 5; a later open migrates it
   and successfully submits a write with that epoch.

## Decisions, deviations, open problems

No deviation from the round-5 design. The epoch migration uses the existing
`.epoch` record as the durable high-water mark rather than importing or changing
credentials; subsequent locked checks take the maximum of that record and the
committed session epoch. Migration runs only while opening scopes, so ordinary
authorization cannot elevate a transient mirror value into authority.

Retaining fresh transfer markers until dequeue is necessary to implement the
requested fence: changing the fence predicate alone cannot protect a queued
write whose marker was already cleaned up. Committed outbox custody remains
unchanged for the same backend across logout/reopen. No source rule, meter or
bucket limit was weakened. No push or publication was performed.

No unresolved problem remains in the requested scope. The six negative tests
above are reproductions of fixed findings, not unhandled failures.
