## Rulings mapped to files

1. **Retained absence:** `crates/snapback4-core/src/engine/timeline.rs` checks
   point coverage with the actual lookup key after `get`, before accepting
   presence or absence. `timeline_scan` scans first, then checks the range and
   returned rows, marks the recorded prefix unknown, and calls `timeline_known`.
   `crates/snapback4-device/tests/timeline/round2.rs` covers absent tombstones,
   author modes and follow edges on memory and SQLite, both at admission and
   on replay after `Left`, then persisted reopen. Held controls establish that
   empty tombstones/follower scans predict, while a held missing author mode
   really refuses. Left coverage instead yields `RuntimeError::Prediction`,
   names the actual table/index/key, keeps the write queued, and leaves zero
   predicted rows. Replay preserves the write ID, arguments and event-ID supply.
2. **One retained predicate:** `crates/snapback4-device/src/device/history.rs`
   owns `retained(Coverage::{Row, Range})`. Reading and Predicting both delegate
   to it (`device.rs`). It requires sync plus delivered-history, resolves the
   audience key, and checks the same persisted membership. The public empty
   audience uses the ordinary encoder; its `Left` marker covers the whole
   table. The point/scan test reads the same public author group and checks
   both component retention decisions before and after leave. Existing
   point-versus-range read completeness semantics are preserved.
3. **Denied owned row:** `timeline.rs::timeline_insert` returns
   `TimelineInsert::{Written, Skipped}`, with no row image in either variant.
   Every caller was checked: registration (activation and profile creation),
   feed/broadcast copying, tombstones, and online pull-route/count creation.
   None needs a returned row. Registration now returns unit; server-only slot
   accounting cannot take the device skip branch. No caller can embed or reuse
   an unwritten private image.

Read-only orientation: LLP 3000 §1/§4/§7, LLP 2000.000, and
LLP 3000.007.003 §3.3/§5; existing `@ref`s still apply. The current feeds and
timelines cards were read. No new LLP decision or hand-off is needed.

The guide changes clarify that *any input actually read* must be current.
Profile deletion reads no mode and leaves it unchanged; adding a mode read
would change the agreed transition. Residency metadata now states the retained
rule explicitly and gives edge transitions their unconditional queue rewrite.
