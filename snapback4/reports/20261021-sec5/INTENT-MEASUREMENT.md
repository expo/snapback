# SEC5 intent elicitation and fresh-builder measurement

The implementation replaces proposed invariant alternatives with a questionnaire:
per-role row questions, per-role questions for each column, and actual relationship
and enum/category context. Restatement advice names each admitted branch, its role
and its row/image conditions, asks the builder to compare them with the product
specification, and explicitly allows retaining confirmed simple owner intent.

Advisory comparison recognizes logical mirrors, weaker copies using enforcement's
own atoms, named-key probe implications and current-read self-id rewordings. These
reductions are confined to advice: they never supply proof assumptions or change
runtime rules. Denied gates do not generate vacuous restatement advice. Independent
new audience alternatives remain quiet. Scoped role discovery requires an observed
caller probe; an ordinary event's kind and author do not invent role audiences.

the sibling invariant-free note implementation because its files were staged at

## Method

Ten fresh `codex exec` sessions use gpt-6.1-sol with high reasoning and disabled
ancestor-project documentation. Each sees only the installed package's README and
CLI guides, its copied authored Quarry, and the product portion of the original
BRIEF. The prompt supplies no known findings, probe output, bakeoff analysis or
repository source. Builders may only add, replace or remove single-line invariant
declarations; the collector verifies every other byte. They answer the installed
questions, run check, test and audit, and retain unknown/timeout results honestly.

Original wave-20 lanes are read-only. TemporaryDirectory owns each cohort's
installed packages and mutable copies and removes them when all sessions finish.
Original/final authored Quarry, prompts, product specs, transcripts, source hashes,
command statuses and builder reviews are durable evidence under builders/ and
builders-extra/. Six pointer files reserve queued original paths for the second
cohort before any duplicate session can start. Original two plus extra three
sessions run concurrently; there are no repeated attempts selected for favorable
results. The per-session bound is 480 seconds.

The packed source field b340bf157b is a reference point, not an exact-commit
qualification: the first binary build also contained then-uncommitted sibling
changes. Actual client/platform/binary SHA256 values identify the measured input.
The coordinator's final pack qualification is separate. This is a focused review
exercise on completed apps; it is not a randomized comparison against wave-20
original app-building behavior and cannot isolate a causal effect of the docs.

Count read declarations separately from nonmirror candidates and manually assess
whether a candidate follows explicit specification requirements. Repeated
column declarations can encode the same audience decision; report both rather
than treating every repeated declaration as an independent insight. Unsupported
temporal assertions are not checker successes. An empty test or audit file after
a timeout is not a passing result. Manual findings and concrete checker refutations
are distinct outcomes.

non-invariant byte is preserved. Two sessions finish normally; eight reach the
480-second session bound. That cutoff and the original packed test/audit timeouts
