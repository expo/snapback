# Lane E round 16 — delivered local outcomes

The local transport preserves terminal mutation and action responses delivered
across close. Mutation settlement retains its waiter and durable device until
receipt processing finishes. Read disclosure remains fenced. The model now runs
against actual local clients as well as online clients, and generates both
accepted mutations and authoritative nonretryable refusals.

## File-by-file changes

- `packages/snapback4/src/local.ts`: track dispatched mutation settlement
  independently of network submission. Close resolves unsent work as pending,
  lets dispatched work process its response, and resolves any remaining uncertain
  waiters after draining it. Decode delivered mutation/action responses after
  close, skip follow-up acquisition, and track action transport through device
  closure. Keep query-response and admission guards.
- `packages/snapback4/src/app.ts`: local session notifications no longer repeat
  the local client's session save. A single failed rotation save cannot silently
  commit on a second notification save while returning failure to its caller.
- `packages/snapback4/test/app-local-outcomes.test.mjs`: ten held-response cases
  across actual Wasm and native clients through createApp. Each tier covers sent
  and failed mutations, done and failed actions, and a late query. Mutations
  reopen with their durable receipt and exactly one accepted row or no refused
  row. Close waits for the held work; old handles cannot admit a new mutation;
  late query data is not disclosed.
- `packages/snapback4/test/app-local-session.test.mjs`: a real-server local
  rotation with one failed session save preserves the old bytes, holds the
  successor in its live runtime, and persists/restores it on ordinary close.
  A second real-server test proves that a query encountering its own rotation's
  consumed predecessor waits and retries with the delivered successor.
- `packages/snapback4/test/client-lifecycle.test.mjs`: the Wasm and native
  applying-acknowledgement tests now require sent after close. Their old pending
  expectation deliberately pinned the behavior this round changes.
- `packages/snapback4/test/helpers/app-model-device.mjs`: production Rust/Wasm
  device with memory persistence, modeled backend/sync wire data, and virtual
  retry/backoff timers. Await initial Wasm compilation before generating a
  sequence. Client, interpreter, outbox and receipts are not stubbed.
- `packages/snapback4/test/helpers/app-session-model.mjs`: retain I1–I12, the
  three-runtime session store, external sessions and fault schedules; run either
  client tier; generate authoritative terminal mutation refusals and compare
  their exact original id and refusal with the independently recorded server
  outcome. Audit accepted/refused results after fencing separately. Keep each
  logical simulated backend's locks separate and advance local cleanup timers
  before checking quiescence.
- `packages/snapback4/test/app-session-model.test.mjs`: 5,000 seeded sequences
  per tier, eight fixed delivered-outcome cases (tier × sent/failed ×
  close/logout), two local session cases, all 28 prior fixed model cases, and the
  existing 120-sequence fault-index sweep. Require both terminal states after
  fencing and evidence of real local schema/sync use.
- `packages/snapback4/CLIENT-AND-OPERATIONS.md`: document local I12 settlement
  ownership and the expanded test evidence.
- `llp/3000.013-quarry-states-intent.rfc.md` §6: record local outcome custody and
  the two-tier model.
- `JOURNAL.md`: one appended dated qualification entry. This report records the
  implementation, coverage, decisions and limits.

## Existing forms exercised

No new API or Quarry form was introduced. The existing local form now preserves
its delivered receipt through close:

```ts
const app = createApp({ url, device: webDevice(), sessionStore });
await app.ready;
await app.auth.guest();
const writing = app.mutate(api.add, { body: "one row" }, { id });
// Hold the response after dispatch, begin close, then deliver the response.
const closing = app.close();
const receipt = await writing; // sent or authoritative failed, with the same id
await closing;
```

`app.client.act(api.work, args, { id })` likewise retains a delivered done/failed
outcome. A held query still requires the live view when it returns. Cancellation
without a delivered terminal outcome remains pending for same-id recovery.

## Invariants, generator and limits

I1 protects the stored bearer; I2 preserves failed-operation atomicity; I3
maintains retirement custody; I4 isolates principals after epoch observation;
I5 advances epochs only on commit; I6 keeps published identity coherent; I7
excludes known refused sessions; I8 fences captured handles and observations;
I9 checks global revocation and protects later logins; I10 binds retirement to
acknowledged attempts; I11 limits operations to their account epoch; I12 keeps
the original terminal outcome and id of dispatched writes, including refusals.

The 25 generated operations remain signup, login, guest, refresh, logout,
logoutEverywhere, close, closeClient, reopen, reopenOffline, query, revoke,
revokeCurrent, holdStore, release, capture, handleQuery, handleMutate,
handleRefresh, observeHandle, readObservation, refreshFault, sibling,
retireOffline and retireOnline. Storage get/set/delete failures target generated
indices 1–12; a separate sweep covers indices 1–40. Responses, dispatch and
storage can be held while peers act. Rotation saves also receive single-operation
failures, then recovery. Fair recovery delivers held work, restores storage and
network availability, retries logout and reopens to drain durable custody.

Each tier runs seeds 1–5,000: 10,000 randomized sequences and 260,000 generated
commands in total. There are 38 fixed model cases and 120 additional fault-sweep
sequences. The local model uses empty replicated tables with server-routed viewer
queries and nonpredicting mutations; it exercises the real Rust/Wasm outbox,
receipt and persistence paths, not full generated application schemas. Separate
real-server/device tests cover private rows and native settlement. Action replies
in the new tests are controlled wire fixtures, not evidence of a real action
worker execution. The model is bounded regression evidence, not an exhaustive
proof. Previously documented process-loss/total-storage-failure limits remain.

## Additional finding and oracle corrections

The local model's seed 6 reduced to signup followed by one failed rotation save.
The local client saved once, reported the failure, then its session notification
caused createApp to save again successfully. The second save violated I2. Remove
that duplicate local save; online notifications still own their required save.
The fixed model case and a real-server regression both cover it.

The broader local run also exposed model assumptions that did not represent
local scheduling. Sequences now use distinct simulated backend URLs so late
cleanup from a completed sequence cannot own the next sequence's lock. Virtual
timers allow local close/retry cleanup to finish before a quiescence assertion. A negative control also exposed an unawaited
cold Wasm compilation: the first fixed case could race its own setup. The harness
now completes that host initialization before generating any operation; the
previously surviving duplicate-save control now fails with I2.
A local read's refusal for its own consumed predecessor while the rotation reply
is held is obsolete: the client waits for rotation and retries the read rather
than delivering a session refusal. I7's oracle now distinguishes that pending
case from a delivered current-session refusal. A refusal of the successor still
excludes its consumed predecessor, including after a failed save. The original
sequence is retained, and a real-server regression verifies the deferred read.
An attempted blanket transport-level cleanup was rejected during development
because it cancelled an ordinary close's owned rotation on a background obsolete
refusal; that production change was removed. No disclosure guard was weakened.

real-device outcome cases. The model's obsolete-refusal distinction and host
compilation/timer setup are described above, rather than claimed as production
fixes. No public API, Quarry form, refusal code, rule, engine meter, starter,
README, shell cache policy or package version changed.
