## Frontend changes

Production recipes are guide assets in the installed package, no longer
emitted by ordinary init. The recipe files account for 130 lines in retained
React projects and 142 in Expo projects; retained native-smoke files are
separately counted proof support and remain functional. All 44 retained recipe
frontend files match their init templates modulo a local port (22 App files
exact, 22 client files with only the local-port difference; recipe-origin.json). Removing unused
recipes alone gives a counterfactual median of 141, so the entire raw gap
must not be attributed to hooks. Config/entry glue, app scope and source
formatting also differ. A residual line is not proof of extra functionality.

useQueryData(op,args) makes an ordinary data read as short as the compared
Convex hook. Refusals throw QueryRefusal with original typed why; an inline
useQueryResult returns data, why and the precise read. Neither creates extra
observations or grants completeness/freshness. SignedIn is the one-line auth
gate under AppProvider. Existing precise hooks are unchanged. The packed client
reference contains executable short-screen examples; the guide's first line
and README point to them within existing documentation budgets.

Three source copies are reproduced with rewrite.py. Every form, label, role
branch, mutation, upload and paginated list is retained; only point-read/render
boilerplate changes. In 026, denied states now show their refusal and partial
rows/complete empty lists render as data rather than an endless loader.

The original lane directories are read-only. These are three selected rewrites,
not a rerun of fifty fresh builders or evidence of a new population median.

## Time

hourOfDay(t) returns UTC 0..23 without changing hour(t)'s epoch ordinal.
It lowers to the existing Calendar/hour/day arithmetic, evaluates its input
once and introduces no wire enum or device capability. Tests include pre-epoch,
midnight/hour boundaries, i53 extremes, arity and required-time typing.
N_SWEEP_DEADLINE names timed scheduled status changes and mutations using
those statuses, or testing/writing another flag also tested by the sweep,
without a matching direct row-time comparison. It asks for the
intended opening/closing direction and equality, never invents a guard. The
approximation, unrelated-row/branch correlations and helper/alias limitations
are explicit; it is not a safety proof.
KIT4 owns clock caps/session time; SEC owns stronger invariant verification.
