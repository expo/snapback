## Findings and implementation

1. **Settled admissions retain their issued floor.** The device admission
   transaction now writes `client:server-clock-floor` alongside its outbox entry.
   It stores the maximum prior/admitted time and survives retirement. Startup
   restores this record before issuing time, then also recovers older pending
   entries. Web journal capture still happens synchronously; no asynchronous
   JavaScript metadata write precedes capture. The same transaction serves Wasm
   and native SQLite. One bounded metadata read/write is added per admission.

2. **Slow samples cannot poison issued time.** Samples rank short measured RTTs
   (at most 1,000 ms), provisional receipt stamps, then longer measured RTTs.
   Within each class, minimum RTT wins, with newest ties. A lone slow sample may
   change unfloored estimated server time; it cannot change the offset used by
   issued device time or device timers. Both offsets survive forks and offline
   reopening. Existing 60-second/32-sample bounds remain. Notifications report
   the larger correction across both offsets, so a short confirmation still
   wakes device watches when the estimated offset itself did not change.

3. **Freshness is versioned wall time.** New writes and reads use
   `syncedAt:wall:1`. Ambiguous unversioned values are omitted until successful
   resync. Local, remembered server, composed and retained-observation answers
   clamp future `since` values at publication to `Date.now()`, including after a
   wall rollback. Existing fault-injection and retention tests now address the
   versioned metadata key without changing their behavioral expectations.

4. **Composition deadlines are both exercised.** Controlled tests give the
   retained device component and remote answer distinct, non-null deadlines.
   Each ordering publishes at 300 ms and again at 600 ms. Removing the composed
   device deadline fails both tests; no composition implementation change was
   needed beyond freshness clamping.

## Forms and compatibility

No new public API, Quarry spelling or refusal code was added. The existing clock
fixture continues to compile and run these forms:

- Default timestamp: `at: time default now` in `clockMessages`.
- Explicit clock expression: `return { at: now, connections: connected[viewer] }`.
- Expiry: `expire at .expiresAt` in `clockTyping`.
- Latest page: `return clockMessages where .conversationId = conversationId last 20 by .at`.
- Held observation: `query heldTyping(conversationId: conversations) held:`.
- Device/render clock: `client.now()` and existing `useNow(deadline)`.
- Dev controls: `snapback4 dev --clock-offset +25h` and the existing
  `POST /dev/clock/advance` with `{"duration":"2m"}`.

The browser/wire fixture is `packages/snapback4/test/fixtures/server-clock.q`.
