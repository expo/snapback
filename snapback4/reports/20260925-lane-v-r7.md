## Forms and behavior

No new Quarry or app API forms. Existing mutation calls keep their signatures:

```ts
const write = await app.mutate(api.removeMember, { room, principal });
const receipt = await app.client.write(write.id);
```

Both ordinary and keepalive delivery now send the original identity:

```json
{"id":"01M3CHH4SJ7K28HG51XRHQTMFM","args":{"room":"room","principal":"user:other"},"newIds":[],"store_id":"original-store-A"}
```

If the endpoint becomes B after A was validated, B refuses with
`E_STORE_REPLACED`; the receipt is `failed` and that write is retired. This
remains true if both client transport guards are removed. The client does not
rebind that intent to B or generate a replacement mutation id.
