# Lane E round 14 — epoch selection and per-attempt acknowledgements

Fixed both round-13 regressions, added I10/I11 and widened the executable model.
The public API and server protocol are unchanged.

## File-by-file changes

- `packages/snapback4/src/app.ts`: while holding the session lock, reject global
  selection of a stored bearer whose epoch differs from the calling scope.
  A peer's rotation remains adoptable within the same epoch. A later login of
  the same principal remains untouched. Document I10/I11 beside the invariants.
- `packages/snapback4/src/app-revocations.ts`: capture an immutable credential
  snapshot for each dispatched global attempt. Cleanup uses that snapshot,
  including after a failed cleanup write. Credentials attached later remain
  durable individual retirement obligations instead of being erased by the
  earlier acknowledgement. Completed generation markers still prevent stale
  global promotion.
- `packages/snapback4/test/app-global-attempts.test.mjs`: four real-server cases:
  the late login under a held acknowledgement, the same case with a failed
  cleanup write/retry, and dormant-tab epoch refusal on online and local clients.
- `packages/snapback4/test/helpers/app-session-model.mjs`: record global operation
  IDs, their calling epochs, dispatched attempt IDs, coverage and acknowledgements.
  Add requests held before issuance and independent retirement-network failure
  and recovery. Check retirement removals against acknowledged attempt coverage
  (I10), and fence creation/bearer selection against the operation's epoch (I11).
  Correct two oracle timing boundaries: asynchronous storage delivery and public
  promise settlement. A Node promise hook observes settlement without modifying
  the client or its returned values.
- `packages/snapback4/test/app-session-model.test.mjs`: add both reviewer
  sequences, both reduced oracle cases and a held-result I8 control. Require
  coverage of the new operations, failure modes, epochs and attempt boundaries;
  preserve all earlier fixed cases and the 120-sequence fault sweep.
- `packages/snapback4/CLIENT-AND-OPERATIONS.md`: document I10/I11 and explain
  same-epoch rotation adoption and per-attempt retirement.
- `llp/3000.013-quarry-states-intent.rfc.md` §6: record the implemented constraints
  and the wider I1–I11 model.
- `JOURNAL.md`: one dated append with changes, measurements and limitations.
- This report records qualification, reproductions and decisions.

## Existing forms exercised

There are no new public forms, Quarry syntax or refusal codes. These existing
calls now distinguish a rotation from a later login:

```ts
await tabA.client.refreshSession();
await tabB.auth.logoutEverywhere(); // Can select A's successor in the same epoch.
```

```ts
await tabB.auth.logoutEverywhere();
await tabB.auth.login(email, password);
await tabA.auth.logoutEverywhere(); // E_AUTH; B's later account epoch stays intact.
```

When a sign-in was held before dispatch, was minted after another runtime's
remote global revocation, and then lost its epoch comparison, the resulting
token remains journaled. Reopening with working transport individually revokes
it. The earlier global acknowledgement cannot claim that token was covered.

## Invariants and coverage

I1–I9 retain their documented meaning and recovery assumptions.

- **I10:** an acknowledgement retires only credentials its attempt covered.
  The coverage snapshot is taken at dispatch, not recomputed from the journal
  when the response arrives or cleanup retries.
- **I11:** an operation cannot select a newer account epoch than its calling
  scope. Matching principals do not authorize adopting a later login.

## Regression evidence and model corrections

Before the production changes, all three initial real-server regressions failed:
the held acknowledgement erased the live late token's durable custody, and both
online/local dormant callers successfully revoked the later login. All four
final real-server cases pass, including the additional cleanup-retry variant.
Five negative-control runs fail as intended:

1. Recompute coverage at acknowledgement: both real-server attempt cases fail.
2. The same mutation fails the model with I10.
3. Remove the account-epoch comparison: both dormant-tab client tiers fail.
4. The same mutation fails the model with I11.
5. Remove the public refresh completion guard: the model still fails I8 after
   the promise-settlement correction.

The expanded model found two oracle errors, not additional product defects:

- **Seed 445:** a held refresh and replacement allowed a raw client callback
  between entry into the backing store's get and delivery of that get's result.
  The model had already marked the new epoch observed. The adapter now returns a
  native Promise and marks observation after delivery to the awaiting consumer.
  The reduced sequence remains a fixed case.
- **Seed 432:** a refresh promise fulfilled while its handle was valid, then
  hiding occurred before the model's queued `.then` callback. The model treated
  the already-returned result as a new disclosure. It now samples handle validity
  at actual promise settlement, using the documented
  [Node promise hook](https://nodejs.org/api/v8.html#promisehooksonsettledsettled).
  A second fixed case and negative control require refusal when hiding actually
  precedes settlement. No runtime disclosure guard was removed or relaxed.

The final expanded run found no further product defect. The earlier affected
run's single failure was seed 445; the next model-only run exposed seed 432.
These model failures were ours and were corrected, not classified as baseline
or environmental exceptions.

## Decisions, deviations and open limits

No requested fix was omitted. The attempt snapshot and ordinary retirement of
later credentials implement the requested boundary without changing the wire
protocol. No public export, package version, README, starter, web shell, engine
authorization/disclosure rule or meter changed. No push or publication.

No unresolved round-14 reproduction remains. The transient full-run store-reset
failure above remains an unqualified observation in pre-existing code; its
reproduction command was `scripts/test.sh`, with the failed log retained at
`/home/ccheever/sb4-intent/lane-e-r14-test.log`. Its separate rerun passed.
Existing documented limitations
remain: lose every persistence/revocation attempt and kill the only holder of an
unpersisted minted token, and the client cannot reconstruct it; lose a successful
logout-all response and its runtime before receipt persistence, and a consumed
bearer cannot prove the result on retry. Likewise, complete refusal-fence failure
followed by process loss leaves old bytes indistinguishable during offline
reopen. Stronger crash recovery requires server receipts or recovered durable
storage; this round makes no stronger claim.
