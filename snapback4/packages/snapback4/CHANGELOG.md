- Authorization recipes cover private sheets/counts, mutable parents, publication/ballots, expiring media grants, enrolment presence and hidden-parent entry. - Client runtime: useRelease() reactively exposes the authenticated served catalog on both tiers, refreshes across generation/credential changes and withdraws on sign-out. Generated op.available(release) checks name/kind/argument shape, not authority. Generated api.ts is self-contained at runtime, including in Exact and Node seed scripts: package imports are type-only and availability is inline. Generated server.ts also imports only types; pass the application’s `startServer` import as `server(startServer, handlers, options?)`. Opt into snapback/client-compatibility.json for optional new fields/arguments and baseline result types; existing applications keep their default generation. Keep drafts above release gates and use a bridge release when rollback would hide a safety dependency.
- Previews list dormant rows a target operation cannot see, alongside disjoint row/cell/index counts. Proved equivalent/tighter clauses get notes; wider or unproved rules and requirements keep warnings with old/new clauses. Rollback remains directional. deploy --help includes --schema; generated verb help and publication checks prevent announced flags disappearing. Diagnostic trace writers explicitly release file locks so forked subprocesses cannot retain them.
- Client recipes: useAuth() continues to expose state, viewer, why, signup, login, guest, logout and logoutEverywhere (no session member). matchReadList adds list partial fallback while denial stays explicit. Bare operation strings explain generated api.op handles. Expo exports secureStoreSessionStore with injective keys. /auth/config reports development so apps can hide persona UI on serve.
- Fixtures resolve aliases recursively in data/match, support subset assertions and typed now-relative times captured once. Cases precede the derived query sweep. check --fix updates reproduced refusal renames; upgrade snapshots compare completeness and print the Exact rebuild command once after a runtime upgrade. - Proof runtime: withBrowser uses caller Playwright over a pipe with independently bounded cleanup; playwright-core is an optional peer. The browser witness global always installs; ?witness=web arms each registration and survives routes. Trusted click/submit and canonical null arguments qualify; unclaimable writes settle E_WITNESS_UNCLAIMED with a reason, and terminal receipt observation survives unmount. Custom Home proofs fail without a write; day2:proof receives saved versions/v1.q and versions/v2.q. renderedText, scoped waitForFresh, frontPage and external logs support honest assertions; packed Linux qualification audits listeners and custom no-write/submit controls.

## 0.4.26

- Client runtime: useMutation().run() now waits for sent | failed; offline it waits for reconnect. Pass { waitSeconds: 0 } for immediate custody (pending), and observe the write receipt separately. The settlement observer survives component unmount.
- Keyed aggregates: a hidden key reads null; an authorized missing count group reads 0. Generated private keyed-count results may change from number to number | null. Use qtySum[room] ?? 0 only when treating hidden/missing values as zero is your application policy.
- A whole service-seat branch can bootstrap the first member of a synced roster. Service probes and table writes still obey the caller's read/write rules (guide deploy).
- Release selection excludes failed adoption candidates; bare rollback selects the previous committed activation, and latest selects the latest successful release. Preview rehearses the actual activation on a private snapshot.
- Upgrade pins core and installed Expo adapters together and compares compiler notes, types and refusals when a successful check snapshot is available. Rebuild native/Exact devices after upgrading their runtime.

History begins at 0.4.26. Older upgrades receive all recorded entries; this file does not reconstruct changes before that version. Compiler deltas remain schema-specific and separate from client runtime history.
