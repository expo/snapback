# Snapback 4 behavior changes

## 0.4.30

- Saved releases: `deploy --schema` resolves compatibility baselines from the original project, preserves module names and deduplicates enum/value unions. Prefer `versions/v1/schema.q`, original-name modules and `versions/v1/fixtures/`; directory and complete-file inputs remain supported. Saved tests prefer contemporary fixtures, name fallback skips and keep explicit fixture selection strict. Deploy/rollback previews group actual guard dependencies and lead with query/count population losses, dependent dormancy and safety effects; literal backfills include exact active-row counts. A bridge-release recipe preserves safety logic as well as data.
- Existing stores retain their rows and ids. P11 makes Rust ids monotonic at equal or regressed clocks within one live mint context, matching the JavaScript module stream; it gives no order across contexts, devices, processes, restarts or commits. Existing same-millisecond ids keep their previous random ordering; use an explicit order column for cross-context business order and `matchSet` for unordered fixture membership. No store rewrite is needed for P11.
- F2 recovery is explicit: `doctor` reports `E_EXPIRY_ORPHAN`; after inspecting/backing up a stopped store, select `doctor --repair-expiry-orphan table:id` (plus `--release dir` for deployed storage). It applies current cascade/set-null/keep actions atomically and refuses restrict/read-through blockers. Upgrade never guesses that a physically absent parent expired or silently deletes legal dangling references.
- Client runtime: `AppProvider` preserves drafts across restoring→signed-out for the same app/viewer and resets them when app/account ownership changes. `useAppReady()` gates writable screens on opening, current sign-in and admission, including recovery after failed initial restoration. `isPresent` narrows non-null data; `isReady` still permits nullable data. Device-less identity options require explicit session storage; Expo examples use `secureStoreSessionStore(SecureStore)`. Rebuild edited starter forms around the documented readiness gate; application-owned files remain yours.
- Proofs: `renderedText` is exact by default with explicit substring/RegExp/scoping; `waitForFresh` reports last evidence and `waitForServer` polls server truth with a deadline. A trusted click producing no durable write settles `E_WITNESS_NO_WRITE` after one second; re-arm and abandoned arms also settle, while a claimed write gets its full separate deadline. Observation never cancels a real write. Logs default to project `logs/`; token/secret stdout stays in memory. Browser witnesses start before app scripts; custom `startDev` arguments keep its memory default; request persistence explicitly through the proof helper (guide testing).
- Starters bake init-time port ranges, print the written defaults and support later launcher overrides. Expo dependencies pin before adapter resolution; zero-sync Expo uses the online tier. `init --adapt` previews inherited proof repairs; `--apply` writes them while preserving business assertions and routes. Generated frontend proofs build their own dist after validating ports; day-two templates require a real business assertion and pass saved-version directories themselves.
- Fixtures and operations: `check` and `test` share typed relative-time and literal-escape conversion; malformed times report `E_FIXTURE_TIME`. Per-query sweep personas, `matchSet`, `loadFixtures`, reset-time conversion and live-instance memory-dev discovery cover the same forms. Help/usage/flag admission share one table, ignored modes refuse, token quiet/JSON and empty `data --json` work, and deployments record source/version/time provenance. Worker failures invoke `onError` once per recorded failed attempt and remain visible in dev/doctor.
- Authorization recipes execute offline supervisors, quantified consent, mutable workflows, publication mirrors, timed peer counts, expiring grants with owner history and role transitions. Refusal guidance distinguishes input/hidden lookup/table authority/authored guards; developer evidence names failed update images without changing hidden-client envelopes. Asset recipes share immutable home references and fail closed on scanner failures. These recipes add no language capability marker.

- Quarry: unique membership lanes filter one point and keep the page's merge order. Indexed negative membership and capped online parent/child groups can report exact exhaustion with a prepaid authorization walk; older devices need `branch-pages-v5`. Unsupported copied-scope dependencies keep explicit scope predicates.
- `check` preserves working immutable updates/upserts: `N_IMMUTABLE_PATCH` explains readable runtime equality; only proven changes or fresh clock/id patches in readable conflicts refuse. Exact-equal and proven insert-only payloads stay quiet. Non-null `where` predicates refine loop and shape snapshots; a proved immutable parent audience narrows private maintained counts. `not before` infers its boundary index. Median disclosure remains an explicit design choice; use authorized public measurements with private attribution for the fuel-board shape.
- Delete-action caps are required only when a declared source can delete the parent; dormant edges get a note. Required-cap rewrites explain the product limit and heap formula. Diagnostics distinguish statement position and atomic fanout, name nullable Boolean operands, preserve descending cursors, and show source-level sync/job/reference repairs. Cursor and ordered-delete notes recognize enforced whole-group bounds; long rule expansions abbreviate outside verbose/JSON.
- Authorization recipes/refusal layers: RULES3 owns the related 0.4.30 changes.

- Expo starters and snapback4-expo now use Expo 57.0.30 / expo-modules-core 57.0.23; the shared config plugin repairs ExpoModulesJSI cache invalidation when switching SDKs, and native preparation accepts Xcode 27.1 as well as 27.0 with matching iOS SDKs. Regenerate iOS and rebuild the native app after upgrading. Qualification records the producing Xcode build and iOS SDK.

## 0.4.29

- CLI repairs: web-shell appears in help and accepts both help spellings without files or builds; retired init recipes explain --web/--expo and --template chat. witness web loads the optional playwright-core peer only when running, with an install command if missing. clock advance and reset discover the persisted dev's port, with --port overriding it. Starter frontend proofs refuse a one-port range before launching; day-two/backend-only proofs still accept one port. Implicit downgrade refusal now names the registry's version and installed version clearly.

- Expiry now applies declared cascade, set-null and restrict actions atomically, including replacement and final retirement. Existing stores whose expired parent images remain gain these actions on the next sweep: cascading children are removed, nullable links clear, and restrict retains expired physical parents while reads exclude them. Private or incomplete device evidence queues the write for the server. Parents already physically swept by 0.4.28 cannot trigger these actions; 0.4.30 doctor provides inspection and explicit recovery. Rebuild native/Exact devices after upgrading.
- Maintained aggregate rows now use domain-separated 64-character digest keys. Existing 0.4.28 stores rebuild derived rows transactionally on adoption, translating active/dormant references, indexes, caps and sequence history; long user: principals no longer block adoption. Ordinary aggregates require maintained-id-sha256-v1; private maintained-column aggregates are omitted from device projections. Older devices refuse unsupported markers. Rebuild clients rather than persisting or constructing aggregate ids yourself.
- Quarry reserves now/viewer/commit/new bindings and refuses duplicate identity declarations. Ungrouped totals, guarded non-null aggregates, email formats, enum search and explicit-scale rounded decimal division are supported. Bounded equality-product, principal/status and vacancy pages gain completeness where proved; unsupported or hidden absence stays partial. Diagnostics give checked rewrites, caller-readable probe context and reviewed-disclosure notes.
- Authorization recipes cover private sheets/counts, mutable parents, publication/ballots, expiring media grants, enrolment presence and hidden-parent entry. N_WRITE_DENIED and N_LOOKUP_NEVER_VISIBLE prove bounded caller/table-rule contradictions without changing authority. Hidden uniformly denied pages are complete/empty; nonuniform scans may remain partial.
- Client runtime: useRelease() reactively exposes the authenticated served catalog on both tiers, refreshes across generation/credential changes and withdraws on sign-out. Generated op.available(release) checks name/kind/argument shape, not authority. Generated api.ts is self-contained at runtime, including in Exact and Node seed scripts: package imports are type-only and availability is inline. Generated server.ts also imports only types; pass the application’s `startServer` import as `server(startServer, handlers, options?)`. Opt into snapback/client-compatibility.json for optional new fields/arguments and baseline result types; existing applications keep their default generation. Keep drafts above release gates and use a bridge release when rollback would hide a safety dependency.
- Previews list dormant rows a target operation cannot see, alongside disjoint row/cell/index counts. Proved equivalent/tighter clauses get notes; wider or unproved rules and requirements keep warnings with old/new clauses. Rollback remains directional. deploy --help includes --schema; generated verb help and publication checks prevent announced flags disappearing. Diagnostic trace writers explicitly release file locks so forked subprocesses cannot retain them.
- Client recipes: useAuth() continues to expose state, viewer, why, signup, login, guest, logout and logoutEverywhere (no session member). matchReadList adds list partial fallback while denial stays explicit. Bare operation strings explain generated api.op handles. Expo exports secureStoreSessionStore with injective keys. /auth/config reports development so apps can hide persona UI on serve.
- Fixtures resolve aliases recursively in data/match, support subset assertions and typed now-relative times captured once. Cases precede the derived query sweep. check --fix updates reproduced refusal renames; upgrade snapshots compare completeness and print the Exact rebuild command once after a runtime upgrade. Testing documents seed/reset, clock controls and raw HTTP envelopes.
- Proof runtime: withBrowser uses caller Playwright over a pipe with independently bounded cleanup; playwright-core is an optional peer. The browser witness global always installs; ?witness=web arms each registration and survives routes. Trusted click/submit and canonical null arguments qualify; unclaimable writes settle E_WITNESS_UNCLAIMED with a reason, and terminal receipt observation survives unmount. Existing proofs must use the visible registered write and inspect sent/failed rather than custody.
- Starters preserve package name/version, read port ranges at execution and finish with one explicit npm install line. init --adapt previews without writes and prints the exact --apply command. Custom Home proofs fail without a write; day2:proof receives saved versions/v1.q and versions/v2.q. renderedText, scoped waitForFresh, frontPage and external logs support honest assertions; packed Linux qualification audits listeners and custom no-write/submit controls.

Nullable references, sparse filters and private ownership proofs suppress only proved-safe notes; syntax refusals give checked repairs and direct why-code commands.

- Client runtime: run() still awaits terminal sent | failed, including reconnect while offline; { waitSeconds: 0 } still returns custody. The development offline warning changes no delivery behavior. useSignedInViewer retains its non-null type and now names the restoring/signed-in render gates. - Starters and recipes: init --web --online selects browser journal writes/server reads without a web device. Named indexes normalize speculatively; rejected plans retain the authored scan. Online membership search provisions its reverse and scoped word indexes together. Readable lifetime-free negative points and finite enum complements can certify pages; hidden/timed absence cannot. ## 0.4.26

- Client runtime: useMutation().run() now waits for sent | failed; offline it waits for reconnect. Pass { waitSeconds: 0 } for immediate custody (pending), and observe the write receipt separately. The settlement observer survives component unmount.
- Keyed aggregates: a hidden key reads null; an authorized missing count group reads 0. Generated private keyed-count results may change from number to number | null. Use qtySum[room] ?? 0 only when treating hidden/missing values as zero is your application policy.
- A whole service-seat branch can bootstrap the first member of a synced roster. Service probes and table writes still obey the caller's read/write rules (guide deploy).
- Release selection excludes failed adoption candidates; bare rollback selects the previous committed activation, and latest selects the latest successful release. Preview rehearses the actual activation on a private snapshot.
- Upgrade pins core and installed Expo adapters together and compares compiler notes, types and refusals when a successful check snapshot is available. Rebuild native/Exact devices after upgrading their runtime.

History begins at 0.4.26. Older upgrades receive all recorded entries; this file does not reconstruct changes before that version. Compiler deltas remain schema-specific and separate from client runtime history.
