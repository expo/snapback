## M1 — Accounts and profiles
Built password signup/login, persistent sessions, logout revocation, complete editable profiles and uploaded avatars using the frozen UI kit. The Quarry schema compiled on its first check. Built-in identity and typed asset placement were easy; there was no auth service or upload endpoint to implement. The first browser suite caught my own extra-field payload mistake: passing a profile row as mutation arguments instead of selecting editable fields. The copied harness retained read-only permissions and depended on its neighboring metering directory; both needed environment repair. React and Expo familiarity saved screen-wiring time. I wanted a fuller React asset return example, although the runtime behavior was straightforward. Relative to familiar Convex/Supabase approaches, the schema combined validation, permissions, asset ownership and device sync in very little code. This milestone does not yet demonstrate scale or offline convergence. M1 suite and choreography passed; iOS Hermes exported.

## M2 — Social posts and follow graph
Built image/video/text posts, public and Following feeds, follow counts, likes, attributed reposts, threads, and 20-item cursor pagination. The action-log seed uses real user clients and uploads, and can run twice without duplicating content. Indexed pages and maintained counts were compact. Most friction was my client wiring: a native-only image helper on web, hidden Expo Stack routes with duplicate test IDs, and a test that incorrectly equated mounted virtualized rows with loaded pages. The frozen harness made these mistakes concrete. Prior React experience helped isolate navigation from data; I had no prior Clique code. Quarry's named keys repaired an ambiguous index selection cleanly. The compiler explicitly warned about unbounded public synchronization and a wide follow merge; those remain performance risks for M6, not a proven scale success. Compared with Supabase, joins and live local query wiring were simpler here; compared with Convex, explicit sync residency adds an architectural obligation that an online function model does not impose. Suite, choreography, and iOS Hermes export passed.

## M3 — Messaging core
Built deduplicated DMs, distinct group entities, admin membership controls, typing expiry, quoted replies, chronological history, and per-account delivered/read cursors. Message recipient sets are captured at send time. A monotonically increasing conversation ordinal orders messages; it is not a visible-message counter and does not implement M7's backfill. Quarry compiled the first schema draft, including a receipt helper over a bounded recipient list. The most revealing failure was lifecycle-shaped: the harness navigated immediately after removal, before the replica mutation had been submitted, so the server still had Dave as a member. Online admin changes now use the SDK's online client with a keepalive transport; message writes stay on the durable local client. The complete rerun passed removal cutoff and retained-history checks. Prior knowledge of browser navigation and fetch lifetimes helped more than prior backend habits here. The same local query preserving departed-group history is a useful difference from a typical online Convex/Supabase screen, but it demands careful lifecycle testing. No missing platform capability was established. Suite, choreography and Hermes export passed.

## M4 — Message media, reactions, edit/delete
Built photo/video upload and playback, arbitrary emoji reactions, editable text/captions, and tombstones with asset revocation. Production and shortened window files generate Quarry helper constants; all checks compare the message's server timestamp with `now`. Clearing the typed asset column was enough to revoke its URL, and the suite independently fetched it as Bob to verify refusal. Additive schema evolution preserved the existing messages without a migration script. Client rendering caused the correction loops: empty-string JSX produced a React Native diagnostic toast over the attachment control, and the video viewer needed a stable container around its asynchronous player. Familiarity with React did not prevent those cross-platform mistakes. Relative to storage policies and signed URLs in a conventional Supabase build, asset revocation felt much more direct. Compared with an online function backend, the same mutations predicting into the device remains useful, though not yet a fully tested offline guarantee. Suite, full choreography, and Hermes export passed.

## M5 — Ephemeral content, chat settings, search
Built disappearing messages, per-recipient view-once photos, group identity/color/background settings, and people, in-chat and grouped global message search. The server's expiry field did the work that often becomes a scheduled cleanup function plus read filtering elsewhere: a direct authenticated probe after the actual deadline returned null while the browser pages remained closed. The harness then reopened both devices and found no expired message. View-once used a distinct typed asset column and was never passed to an ordinary asset hook. Search stayed a Quarry words index and ran against the synced partition warm-offline. The exact enum type in the configuration helper needed a first-pass correction; there was no implicit enum-to-text conversion. My prior backend knowledge mostly helped identify what to test, rather than supplying implementation code. Compared with a separate search/cache subsystem, the same query interpreter on the device removed integration work. The price remains learning precise language types and understanding which reads are complete at a sync horizon. Suite, every implemented choreography check, and Hermes export passed.

## M6 — 1789411480
Built durable offline messaging, push seam, documented HTTP API, a headless demo, and the full action-log replay adapter with checkpoint verification/probes. The SDK queue and persisted replica needed no custom queue. The first push implementation fought prediction: the published presence recipe and the generated classification disagreed. Splitting a durable effect request from a service-only Quarry dispatch kept all business decisions in Quarry. A redundant existence check also crossed the history horizon and suppressed prediction; stable mutation IDs made that guard unnecessary. Prior familiarity with outbox delivery and optimistic replicas helped diagnose the symptoms. I missed a diagnostic that connects the presence recipe directly to its prediction limitation. Convex would need a separate offline layer; Supabase would require more queue and authorization plumbing. Here the offline substrate is unusually strong, but small authoring choices can change its behavior dramatically. Scale execution is separately clocked and not counted as a completed proof yet.

## M8 — 1789412818
Built the six server-maintained lifetime totals, seven UTC day buckets, exact indexed trailing-day Trending, a config-driven digest schedule with transactional emission receipts, and multi-device offline convergence. Maintains made counts straightforward and constant-size on the wire. Daily jobs and durable effects made the no-client digest and restart proof easy to express. The most difficult issue came from scaling an earlier feature: an early return inside the receipt helper cleared the outer history cursor. Isolating projections and rewriting the helper restored full paging. Reaction summaries became a small transactional cache to avoid nested page work. A final regression exposed the starter script's reliance on a removed existence guard, which installation receipts fixed. Prior knowledge of materialized aggregates, keyset pagination, and transactional outboxes helped; knowledge of Quarry's runtime edge cases did not transfer automatically. The missing diagnostic was a warning that a helper could alter a caller's continuation. Compared with Convex, the replica and SQL-like constraints are more integrated; compared with Supabase, less transport and cache code was necessary, but the language offers fewer escape routes. The full scale state verified exactly and all implemented choreography passed. One strict search mid-curve timing bound missed in the builder probe; it remains reported as a miss.
