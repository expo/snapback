# Essay — building Clique on Snapback explicit

Snapback's pitch is a complete application backend with one authoring loop: declare tables and functions, generate clients, run a supervised dev server, and consume live queries, sessions, and uploads from first-party React/Expo bindings. Building Clique M1–M3 against that loop, on the default explicit profile, felt closer to Convex than to Supabase or a hand-rolled Postgres+Express stack — until the lifecycle and the Expo web carrier disagreed about identity.

On Convex I would sketch a schema, write query/mutation functions that close over the module, and get reactive subscriptions almost for free. Snapback's explicit profile is the same shape with a stricter grammar. `defineTable` plus `.index(..., { unique: true })` expressed handle uniqueness directly. `defineLiveQuery` gave the feed and profile screens a Convex-like `useSnapbackQuery`. Password auth was not an add-on: `defineAuth` with `kind: 'password'`, `identifier: 'email'`, and `minimumLength: 8` wired through `signUpWithPassword` / `signInWithPassword` / `signOut`, and logout was server-side. That is better than rolling bcrypt and session cookies in Express, and more opinionated than Firebase's client SDK soup. It is also stricter than Convex: inline handlers may not capture a top-level `const`, structured `v.array` fields are opaque, and omitting `auth` on a sessions function is an advisory you should not ignore.

Where Snapback pulled ahead of Supabase for this app was the absence of a separate RLS policy language. Authorization lived next to the mutation (`auth: 'authenticated'`, `ctx.auth.userId`, `ctx.refuse('HANDLE_TAKEN')`). Follow/like/repost as idempotent set-state intents mapped cleanly onto unique pair indexes plus a boolean `set` argument. Uploads were not signed-URL ceremony: a generated `defineAssetUpload` plus `defineCommand` made avatar attach one client call. Firebase Storage plus Security Rules would have been more moving parts for the same M1 checkbox.

Where it lagged Convex was diagnostics at the Expo seam. Convex's `npx convex dev` also regenerates and reloads, but I have never had a successful schema successor leave the web client permanently bound to the *previous* descriptor identity. Here, `snapback dev --expo --expo-platform web` did the right backend thing — `startup-successor-activated`, accounts and sessions preserved, new schema hash — and the wrong client thing: Metro/Expo had baked an integration receipt at first start, and with the owner's stdin attached to `/dev/null` there was no supported reload. That is not a missing feature in the data model; it is a hole in the "one supervisor" story the skill describes. Firebase's emulator suite has its own sharp edges, but a rules or function redeploy does not usually make the hosting emulator refuse the app for identity mismatch.

Compared with hand-rolled Postgres+Express, Snapback still saved a week of session cookies, CORS, and websocket fan-out for M1. I did not write a migration SQL file for M2; I added tables and the watcher loaded them. I did write a replay adapter, because the fixture log is backend-neutral and Snapback's `defineReplay` JSONL is not that grammar. That felt fair. What did not feel fair was discovering durable custody cannot run on the Node `memory` platform (the template's own acceptance uses `expo-web` plus fake-indexeddb), or that Chromium on this host needed a user-prefix of `.deb` extracts before Playwright could exist. Those are environment taxes, not Snapback taxes, but they ate the same wall clock.

The explicit profile's value was honesty: I always knew I was on `schema.mjs` / `functions.mjs`, not a TypeScript `query()` dialect. The cost was ceremony (result contracts, refuse allowlists, asset intent names that must exist in the same generate as the table fields) and a generated directory I was forbidden to edit. If the Expo web arm rotated its receipt when the backend did, I would score this closer to Convex's DX and well above Firebase for a two-client social app. As launched, M1 was a good Snapback day and M2 was a reminder that "the supervisor owns Metro" only helps if you can still talk to the supervisor.
