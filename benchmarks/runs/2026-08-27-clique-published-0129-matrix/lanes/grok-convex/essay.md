# Essay — Clique on Convex 1.45.0, after a web-only M1–M6+M8 run

I came into this lane treating Convex as a product I already liked on paper: TypeScript in one repo, queries that rerun when the write set changes, a local backend you can actually point a port at. After building Clique against the frozen Snapback 0.1.29 instrument, that paper liking mostly survived, and the places it broke were specific.

The comparison that matters here is Snapback, because that is the instrument's home backend and the one this app was specified against. Snapback's posture is a local qualified binary plus a sqlite file you can throw away. Convex anonymous local is the closest Convex gets to that: `CONVEX_AGENT_MODE=anonymous`, `--local-cloud-port 48201`, a sqlite under `.convex/local/default/`. Once that process was up, the day-to-day loop felt closer to Snapback than to a hosted BaaS. I was not waiting on a dashboard login, not provisioning a cloud project, not fighting TLS. The mutation/query/http split mapped cleanly onto Clique's "own write path" rule. I never needed a second query language.

What Snapback still has that Convex did not give me for free: an obvious "this is a fresh instance" gesture. The public CLI will start a local backend; it will not, in the docs I had, say "here is the sqlite, here is how to clone it onto another port pair without the dashboard stealing 6790." I found `--local-cloud-port` / `--local-site-port` in package source, then patched the dashboard default into the lane's 48200–48219 box. That is a small thing and also the first hour of the run. Snapback's story is "one binary, one db flag." Convex's story is "the CLI knows, if you read the CLI." I like Convex more when I am already inside a `convex/` directory. I like Snapback more at minute zero of a cold machine.

Against Supabase and PocketBase, the difference is the programming model. Supabase would have been Postgres plus RLS plus Realtime plus Storage, each a product, each with a policy surface I would have been typing by hand for DMs, group membership, view-once, and Insights. Clique has a lot of "this user may see this row only if they are in this membership and the message has not expired." Expressing that as Convex `requireUser` plus an index, in the same language as the client, was the part that felt like shipping. PocketBase would have been faster to click into existence and worse the first time a live two-client proof needed a typed join. Convex's live queries are why M3 typing, M4 reactions, M6 offline flush, and M8's second Alice context were not a polling project. I did not write a websocket. Bob's bubble appeared because the query subscribed.

The other backend I kept in my head was a boring Node-plus-Postgres app. That would have made the scale envelope more familiar (SQL counts, `EXPLAIN`, a real wipe). It would have made the two-client choreography worse. Clique is a choreography-shaped app. The instrument does not grade your schema diagram; it grades whether Carol's background preview changes without a reload. Convex is good at that and mediocre at "please delete every document so I can replay 167k actions against a virgin corpus." I ended up writing `wipeBatch` because `collect()` of a large table is not a reset story.

Two concrete moments I will remember.

First: registering a user is a mutation that bcrypt-12 hashes in process. That is the honest write path the fixture pack asked for, and it is also a load generator Convex did not try to hide. There is no "please hash on the edge" escape hatch in the local backend. I respect that. I also felt it. A thousand scale registrations are not a footnote; they are the first minutes of O5.

Second: celebrity fan-out. Timeline-on-write is the right following-feed design for a 500-follow probe user. It is the wrong write path for an account with 900 followers if the mutation stays on the request. Convex will let you insert 900 timeline rows in one handler; it will not make that as cheap as a five-follower author. I had to decide, in this run, to stop fanning out above 64 followers and merge those authors at read time. That decision is the product. Snapback would have forced the same decision; SQL would have made the 3× degradation rule easier to see in a query plan. Convex made it a TypeScript `if`.

What fought me was not Convex's data model. It was the frozen UI kit on RN-web. `accessibilityValue` does not become `aria-valuetext`. Like buttons did not look "unliked." Chat background preview `src` lives on a child `<img>`, not on the testID node. None of that is a Convex defect, but it ate the same clock as the backend because this is a full-app benchmark. A backend that is pleasant in isolation can still lose a day to Playwright strict mode if the kit contract and the DOM disagree. I vendored the kit because the instrument tree is read-only and `file:` installs failed. That workaround is about the bench, not Convex, and I am recording it so I do not blame the database for a selector.

The scale envelope, when I finally ran it, felt like the same product rather than a different backend. I wiped the anonymous sqlite with a mutation I had to write myself, replayed starter, then the derived log, and the named fixtures were just index lookups. Celebrity writes stayed in the same mutation shape as a five-follower author because I had already made the fan-out decision. What I did not love was discovering that “reset” is not a CLI verb, and that a loopback probe of a denormalized Insights row can still fail a mid-curve rule because two milliseconds of jitter is, numerically, growth. That is not Convex being slow. That is Convex being so fast on a local socket that the safety gate is measuring the stopwatch.

I would use Convex again for a product that is live, typed, and local-first in development. I would not pick it because I wanted operational theater: inspect, dump, clone, reset, compare two sqlite files. Snapback and PocketBase still win that. I would not pick Supabase unless I already needed Postgres for something Clique does not. The thing Convex actually sold me, on this run, is that once the schema indexes existed, the two-client proofs were the app. That is a high compliment for a messenger, and it is why the holistic feeling of this lane is warmer than the dashboard-port patch would suggest.
