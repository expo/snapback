**Outbox and navigation claim.** C essay lines 74–84 assert a mutation admitted locally can evaporate before an IDB flush on navigation. Final report #1 explicitly records the prior `memoryPersistence()`→`indexedDbPersistence()` switch, and final `lib/client.tsx:24–31` uses IndexedDB. Published README lines 847–849 identifies the durable outbox as restart authority; lines 865–870 describes orphaned tab write adoption and says memory persistence keeps nothing. The inspected published SDK establishes an awaited durability boundary: `local.js:915` awaits device `admit`; `web.js:41–48` serializes a call and awaits `settle`; `:28–31` awaits persistence; IndexedDB `save:206–217` waits for transaction completion (`done:176–179`). Only after admission does `mutate` return `pending` when offline/closed, or await a terminal outcome/4s pending timeout (`local.js:926–935`). Store failures return a named `E_STORE` failed outcome whose message calls admission unknown. Orphan adoption is implemented in `web.js:137–159`, subject to lock/persistence capabilities. This source does not support equating a started call, optimistic appearance, or unawaited handler with a completed durable admission.
