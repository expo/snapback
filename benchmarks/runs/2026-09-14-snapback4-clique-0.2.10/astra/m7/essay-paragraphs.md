# M7 closing-essay paragraphs

The day-two task exposed the value of a legible inherited application. A documented token API, an idempotent starter replay, and existing offline behavior let me establish a trustworthy starting point before changing the schema. Polls mostly extended an existing message model: immutable choices, a durable set-state vote, and UI controls whose selected and pending states were already observable. The conversation count required more care because it had to account for tombstones, expiry, and old rows, rather than merely counting new sends.

Snapback's advantage here was that backend declarations carried through to the local device. I did not build another queue or a separate optimistic voting algorithm. Its disadvantage was that product-simple changes sometimes required learning a compiler-specific proof shape. A backfill needed nullable staging before the required numeric aggregate, and deleting a poll's option labels needed bounded point operations instead of the loop I first wrote. Those were recoverable authoring costs, with diagnostics that usually explained the constraint.

The more consequential event was an accepted, engine-generated aggregate identity preventing a later schema adoption. Restoring the old schema reopened the store, and a small independent reproduction confirmed the failure boundary. Replacing that derived cache with indexed counts over preserved votes resolved it without rewriting user data. This is why I would distinguish a successful migration from a frictionless migration: the final browser and snapshot proofs are strong evidence for this artifact, while the adoption defect remains relevant evidence about the backend.

My own execution was also part of the cost. A PID-ledger mistake broke a restart proof and forced another unchanged regression run, and I caught a small visual duplication only during screenshot review. The final result should therefore be read alongside the failed receipts and correction log. The feature works, the previous suites still pass, and the migrated data compares correctly at the recorded migration boundaries; that does not turn this starter-state exercise into a migration-at-scale or native-runtime claim.
