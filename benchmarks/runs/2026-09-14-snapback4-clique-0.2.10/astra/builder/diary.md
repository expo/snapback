No assertions skipped. General React familiarity helped; no prior Snapback implementation was consulted. Compared with my knowledge of Convex or Supabase, the backend auth/asset wiring was compact, while the replica setup and bundler wasm placement needed explicit choices. The docs covered those choices. Native evidence is a compiled Hermes artifact, not a simulator run.

The suite, final choreography, and Hermes export pass. Most Quarry declarations compiled on the first try, and server-arrival timestamps and unique keys fit the domain well. The big friction was a reproducible platform/doc mismatch: delivered-history combined with a message sync horizon returned an empty device history after removal. The recipe for access plus local retention was easier to discover than designing a separate offline store against Supabase, but this interaction required a real browser counterexample and a schema tradeoff. With Convex I would expect to author the offline history policy separately. General messaging knowledge helped choose recipient sets and monotonic per-account acknowledgement watermarks. Native proof remains a Hermes export only.

## M5 boundary
Built view-once image consumption, server-expiring messages and reaction rows, synced chat colors/backgrounds/disappearing settings, and indexed people and message search. The suite and frozen choreography passed, including all-clients-closed expiry and warm offline search. The iOS Hermes export is retained.

The principal difficulty was ordinary client lifecycle work: a closed React Native Modal briefly retained its image node, so the viewer now unmounts immediately and revokes its object URL. Familiarity with React state and browser asset lifetimes saved more time here than backend familiarity. The served asset/expiry guides supplied the necessary backend contracts; no missing platform capability was established at this step. Compared with a conventional Supabase client I know, this avoided separately wiring local search and an expiry worker. Compared with Convex, the cache and asset rules are more tightly integrated, while Quarry's constrained syntax still takes deliberate checking. These comparisons are qualitative familiarity, not a parallel experiment.

## M6 boundary
Built the provider log, service dispatch, token/API documentation and dependency-free demo, all thirteen replay verbs, state-level 50-action conformance, and the fresh-scale runner with checkpoint verification. The required suite and frozen choreography pass. Browser proof additionally verifies cold backend-offline history/search and two ordered queued messages reaching read; the Hermes export exists. Native simulator proofs are not claimed.

The local queue was already largely present through the SDK, and its cold reopening worked without an application outbox. Familiarity with HTTP protocols and idempotency helped make the custom API small. The surprising friction was `connected`: the guide describes a conservative prediction value, but the classifier makes a mutation reading it non-predictable. Splitting a durable candidate from service-only Quarry dispatch preserves prediction, at the cost of evaluating presence slightly after the original commit. This is a documented semantics tradeoff, not exact commit-time notification eligibility. The worker contains transport/logging only; business decisions remain Quarry.

A retry also taught the published protocol's deliberate omission of historical mutation results; the adapter now resolves an existing DM through its query. Compared with Convex or Supabase plus an app outbox, there was less queue code, but more time understanding classifier and wire semantics. The scale runner is authored and sampled inside M6; execution is intentionally on its own clock after M8 so analytics exist at all three corpus sizes. No scale-performance result is claimed yet.

## M8 boundary
Built server-maintained lifetime totals and seven UTC daily buckets, a 24-hour expiring ranking index, configured daily/two-minute digest scheduling, and multi-device/offline proofs. The final required suite and frozen choreography pass. Digest evidence covers all clients closed, exact authorized counts, deletion exclusion, restart before the boundary, a quiet persona, and a quiet following period. Web restart evidence additionally covers durable messages and reactions, viewed ordinary media, consumed view-once media, ordered flush and read receipts. Both final web and iOS Hermes exports are retained; no simulator claim is made.

Maintained aggregates and chunked scheduled jobs were straightforward once I stayed within their declarative shape. The digest job is longer than a SQL aggregate query, but its transactionally persisted sweep cursor and schedule ledger remove application retry bookkeeping. Its scans are explicit and potentially costly as a production corpus grows; replay mode disables the schedule for fair scale loading.

Two pieces fought harder. An eligible `upsert` reaction queued without any local predicted row; explicit existence/update/insert branches restored local behavior and survived a restart. Separately, my original timestamp-plus-UUID ordering failed a burst test when several server commits shared a millisecond. A transactional per-conversation arrival clock now orders history and precise delivery/read watermarks; a 30-message concurrent proof verifies it. This latter defect was mine, not the platform's. Quarry also correctly rejected multiplying a time directly, so the order clock converts milliseconds to an integer first.

The frozen M8 read-state check assumes its base URL is a chat list. Pointing the supported CHOREO_BASE_URL input at this same app's /chats route resolved it without modifying or skipping a check. Earlier root-based segments remain unchanged. Familiarity with pagination, idempotency, SQL validation and React lifecycle debugging saved time; no prior Snapback checkout or run was consulted. Compared with backend patterns I know, Snapback reduced the amount of offline infrastructure substantially but made residency and prediction classification central to application design. The scale replay follows on its own clock; performance is not yet claimed here.
