# Clique custom-client API

The local lane backend is `http://127.0.0.1:49360`. Use HTTPS for a deployed backend. The API is the published Snapback 4 JSON protocol; no app UI or service credential is required. Queries and mutations always run as the bearer’s user and enforce membership and ownership. Install `snapback4@0.4.1` if using the optional Node client or `mintId()` helper. Generated operation types are in `snapback/generated/api.ts`, regenerated by `npx snapback4 check`.

## Authentication

`POST /auth/login` or `/auth/signup`, JSON `{ "email": "…", "password": "…" }`, returns `{ "session": { "principal", "kind", "token", "expiresAt" } }`, or `{ "denied": { "code", "message", … } }`. Passwords must be at least eight characters. Signup creates an account; the `saveProfile` mutation creates its public profile. Pass `Authorization: Bearer <token>` on subsequent requests. Never put bearer tokens in URLs or logs.

A token belongs to one user. Password sessions normally expire after seven days; the returned `expiresAt` (epoch milliseconds) is authoritative. `POST /auth/refresh` under the current bearer rotates the token and invalidates its predecessor. `POST /auth/logout` with `{}` revokes that token’s session family. `POST /auth/logout-all` revokes every session for that user. Revoked or expired tokens are refused by the backend; local storage does not restore their authority. The browser app deliberately uses localStorage for its session; native custom builds use SecureStore.

## Queries, paging, and conversation lookup

Send `POST /q/<operation>` with `{ "args": { ... } }`. Successful responses contain `data`, `complete`, `next`, and `seq`; refusals contain `denied`. A partial result is not proof of absence. Pass an opaque `next` value unchanged as argument `c` until it is null. Keep the same arguments and ordering throughout a traversal. Never decode or manufacture cursors.

- `whoAmI`, `{}`: authenticated principal.
- `apiConversations`, `{ "c": null }`: up to 50 memberships, each with `conversationId`, `room`, `peers` (including handles), membership read/delivery watermarks. To find a named group, walk the pages and match `row.room.name`; names are not unique, so retain `conversationId`. For a DM match a peer’s `profile.handle`.
- `apiHistory`, `{ "conversationId": "…", "c": null }`: newest 50 messages in server ordinal order, then older pages. **The latest message of a named conversation is the first element of the first history page**, after resolving that conversation through `apiConversations`.
- `apiMessageById`, `{ "messageId": "…" }`: one authorized live message or null.
- `roster`, `{ "conversationId": "…" }`: members and profiles, at most 50.
- `searchChat`, `{ "conversationId": "…", "q": "cof", "c": null }`; `searchMessages`, `{ "q": "cof", "c": null }`; `people`, `{ "q": "car", "c": null }`: Unicode NFC/case-insensitive word-prefix search. Message searches return newest first; an empty needle returns no message results. Global results include `room` for grouping.

For example, with an issued token:

```js
const base = 'http://127.0.0.1:49360';
const token = process.env.CLIQUE_TOKEN;
async function query(name, args) {
  const r = await fetch(`${base}/q/${name}`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', Authorization: `Bearer ${token}` },
    body: JSON.stringify({ args })
  });
  const answer = await r.json();
  if (!r.ok || answer.denied) throw new Error(JSON.stringify(answer.denied));
  return answer;
}
let c = null, chosen;
do {
  const page = await query('apiConversations', { c });
  chosen = page.data.find(row => row.room.name === 'Weekend Plans');
  c = page.next;
} while (!chosen && c);
if (!chosen) throw new Error('Conversation not found');
const page = await query('apiHistory', { conversationId: chosen.conversationId, c: null });
console.log(page.data[0] ?? null);
```

## Message field manifest

`apiHistory` and `apiMessageById` expose these fields for every message:

| Field | Meaning |
|---|---|
| `id`, `conversationId`, `senderId` | Stable backend IDs and sender principal |
| `at`, `ordinal` | Server timestamp in epoch milliseconds and per-chat arrival order |
| `type` | `text`, `photo`, `video`, or `view-once` |
| `text` | Text or optional media caption; cleared on tombstones |
| `mediaReference` | Null or asset facts including `id`, MIME `type`, `bytes`, dimensions, and duration |
| `edited`, `editedAt` | Edited flag and server edit timestamp |
| `tombstone`, `deleted` | Delete-for-everyone state |
| `replyTo`, `quote` | Original message ID and currently readable excerpt; null when unavailable |
| `reactions` | `{ emoji, count, mine }` per emoji; `mine` is this caller’s own selection |
| `receipt` | For caller-owned messages: `sent`, `delivered`, or `read`; otherwise null |
| `expiresAt` | Captured deadline, or null; expired messages are absent |

Receipt state is the slowest remaining original recipient; leaving/rejoining cannot regress old receipts. Retained departed-chat history is a device feature: the server never grants departed members fresh access. The app’s device history query is separate from the richer online API shape.

## Mutations and receiving new messages

`POST /m/<operation>` takes `{ "id": "<write ID>", "args": {...}, "newIds": [] }`. Use `mintId()` from `snapback4/client`: IDs are 26 uppercase Crockford base32 digits with a first digit from 0–7. Mint once per intent, keep it until settlement, and retry that same ID with identical arguments. A response is `state: "sent"` with `result`, or `state: "failed"` with `why`. Replayed success has `replayed: true` and omits the historical result; read the entity by its explicit ID. `pending` is not authoritative success when using the local SDK.

`send` arguments are `{ messageId, conversationId, text, replyTo? }`. Mint `messageId` separately. Text is at most 2,000 characters, media captions 500. Server ordinal and timestamp cannot be supplied. `markReceipt` takes `{ conversationId, ordinal, read }`: after receiving history, acknowledge the highest received ordinal with `read: false`; when the user actually opens it, send `read: true`. Watermarks only advance.

This API documents **polling** for incoming messages: every second, query the first `apiHistory` page, merge by `id`, and use `ordinal` to order. Follow older pages when the last seen ordinal is no longer on page one, so bursts cannot create gaps. Reconcile edited/tombstoned rows by ID; on reconnect reload held ranges and remove expired rows. The app itself uses the SDK’s live replica stream.

For media, `POST /assets` sends raw image/video bytes under the same bearer and returns `{ asset }`. Pass `{ id: asset.id }` as `send.photo`, `send.video`, or `send.oncePhoto`; only one is allowed. Fetch `GET /assets/<id>` with the bearer. The home row controls access: missing/revoked/expired assets return 404, a consumed view-once asset returns 410. View-once bytes must never be cached. `editMessage` takes `{ messageId, text }`; `deleteMessage` takes `{ messageId }`; `setReaction` takes `{ messageId, emoji }`, where null clears. Edit/delete deadlines are server-enforced; see `CONFIGURATION.md`.

## Executable example

After `npm install` and backend startup, use an issued token:

```sh
CLIQUE_TOKEN='<issued token>' node scripts/custom-client-demo.mjs
```

Or supply `CLIQUE_EMAIL` and `CLIQUE_PASSWORD`; optional `CLIQUE_CHAT_NAME` chooses a named conversation, and `CLIQUE_URL` chooses the backend. The demo authenticates, lists conversations, walks history, sends a message, retries its ID safely, and receives it by polling. It prints only non-secret evidence. Fixture credentials belong to the read-only fixture pack, not the client bundle.
