Picking up this app cold made the boundary between product logic and backend machinery unusually visible. Polls were a small extension because the existing application already had an authenticated, durable mutation path and a membership-scoped local replica. A vote could be expressed as the desired option in one row. The same rule executed on the server and predicted on the device, and the browser could display its pending state without a new persistence mechanism. That is a meaningful simplification for day-two work: the feature inherited offline behavior from the application architecture rather than adding offline behavior afterward.

The backfill was the more revealing task. An arrival counter already existed, but treating it as a visible-message count would have hidden the migration requirement and failed on deletion. A separate message contribution and maintained sum made the semantics explicit. The successful result depended on ordinary migration discipline: freeze a real authenticated baseline, expand the schema, backfill the stored data, tighten the contract, and compare the old externally visible fields. The declarative backend reduced the amount of aggregate and synchronization code, but it did not remove the need to reason about old rows, deployment state, or the ordering of operational steps.

The main friction was the migration control surface. The published local job command and the deployed store belonged to different operational paths, and a scheduled job was the workable bridge. Compared with the explicit migration runners I associate with relational systems, that procedure was harder to discover and less direct to execute. Once the stages were correct, the engine handled the aggregate rebuild and normal forward maintenance cleanly. The fair conclusion is specific: this backend made the feature's steady-state behavior compact, while the day-two migration still required careful operational choreography and evidence that the existing data survived.

The final evidence also has a clear boundary. Browser choreography proves live tally convergence and offline vote settlement, and the original acceptance suites protect the inherited behavior. Snapshot equality proves preservation of the actual starter state, including the fields that happen to be empty there; it should not be described as a populated message-media or reaction migration benchmark. Recording that distinction, the unsuccessful setup attempts, and the validation gap found during review is part of making a timed evolution result useful rather than merely presenting a green endpoint.
