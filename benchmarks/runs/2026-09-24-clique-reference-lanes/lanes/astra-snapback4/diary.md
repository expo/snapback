## M1 — Accounts and profiles

Built password signup/login, public live profiles, unique handles, every profile field, avatar upload/render, persisted sessions and logout using Quarry plus the published client. Built-in auth and policy-bound assets felt easy: no password implementation or upload server. Client routing fought me: optimistic onboarding unmounted its form, receipt completion and navigation needed an explicit boundary, and Stack retained duplicate hidden profile nodes. Prior React familiarity supplied the functional state-update and Router Slot fixes; it did not eliminate them. The README supplied a usable account recipe and the generated types caught an option I incorrectly attributed to createApp. Compared with known Convex patterns, this used less auth and storage glue; compared with Supabase, no SQL or bucket policy was necessary. These are qualitative familiarity comparisons, not measurements of other lanes. Native Hermes export succeeded; no simulator proof is claimed. The frozen choreography passed all three M1 checks.

## Final scale and regression pass
The full corpus changed which implementation choices were acceptable. A direct Home projection ran out of heap for sparse users, and an exact unread aggregate exhausted the read meter in the busiest chat. Returning Home to the documented materialized feed and making the inbox use an indexed existence check fixed those paths; the UI now shows a truthful unread dot. The final fresh persistent replay verified every declared invariant at both checkpoints and completion, and its diagnostic probes returned data without meter cuts. This felt more like learning a constrained query planner than repairing a general-purpose database. Prior SQL experience helped recognize the distinction between an aggregate and an existence predicate, while the package's diagnostics supplied the actual bounds.

Offline media also exposed an integration detail: fetching one's optimistic upload before placement yielded an unplaced preview, which did not enter viewed-media retention. Waiting for committed placement made ordinary media survive a cold offline reload while view-once stayed absent. The docs could explain this optimistic-placement interaction more directly. A later typing regression first revealed dev-server/browser clock divergence, then unnecessary per-keystroke outbox writes; the clock cause remains unverified, while the write frequency was an application correction. Compared with Convex or Supabase, much less replica infrastructure was handwritten, but keeping query cost, pending state, and server time visible remained essential product work.
