For an original with charge `max(staged_bytes, finalized bytes or 0)`, the resulting classification is:

| Ledger state | Locator | Release timestamp | Reclaiming | Pending slots | Byte charge |
|---|---|---|---|---:|---:|
| Receiving, including reserved finalization growth | None | Any | Either | 1 | Original charge |
| Ready, never claimed | None | Null | False | 1 | Original charge |
| Ready, successfully released | None | Present, including zero | False | 0 | Original charge |
| Ready, claimed or claimed again | Present | Normally null | False | 0 | 0 |

| Failed | None | Any | Either | 0 | 0, inherited exclusion |

There is no new persisted counter or historical-state inference. Receiving custody wins even if a non-null release timestamp is present. Ordinary never-claimed ready uploads continue to count; merely returning an asset from a successful mutation is not a claim.
