# Public argument format audit — read-only

Confirmed silent dropped authored constraints, not an established column-only restriction. The packaged guide at snapback2/packages/snapback2/guide/quarry.md:22–27 explicitly introduces "Columns and arguments", permits format handle/url, and says "minimums and formats are enforced". grammar.md:25 likewise says text may add a format, while explicitly marking other features column-only or operation-only. No analogous format restriction is stated. LLP1004's implementation record mentions ranges/formats but does not establish a column-only boundary.

An independent public Quarry project compiled successfully under frozen e6c46a2aca7c3fa014ce365dadce667b5e13e509. It declares the same three arguments on query, mutation, job and channel: handle:text1..20 format handle, link:text<=2048 format url?, and items:[text<=20 format handle]<=2. All four declarations emit Text descriptors containing max/min only, with no format and no generated validation body. All optional/list wrappers survive, but their format annotations disappear. Exact fixture, script and full compilation response are preserved in fixture/, probe.ts and result.json. This is pure compilation, not an API execution claim.

The same fixture's direct table columns retain Constraint.Text entries: handle has min1/format handle and optional link has min0/format url. Existing Rust engine/runner_ops.rs:520–560 applies those constraints on insert/update and skips null/absent optional fields. Handle validation accepts only lowercase ASCII a-z, digits and underscore. URL validation requires http:// or https://, a nonempty suffix, and no whitespace/control characters; it is this existing validator's definition, not a claim of full URL parsing. Query return/unused job args/channel publish or subscribe do not pass through those column-write constraints.

Cause: the parser's common text type parser (quarry/parser.ts:502–517) accepts/stores format at every position; argument typeCode/lowerArgType emits only max/min, while emitSchema separately generates top-level column constraints. Active ArgType.Text has no format field or corresponding argument admission check. e6 repaired minimum propagation but intentionally did not expand format semantics.

Scope decision required before implementation: either support the documented format constraints coherently in recursive argument descriptors and native/twin admission (including jobs/channels, with identity coordination), reusing the precise column format semantics; or explicitly refuse format annotations in argument positions and correct the public guide's promise. Silently dropping accepted syntax is not a faithful third option. No product/guide/engine/twin edits were made by this audit, and the moving Q4 writer is unaffected. Broader nested-column format behavior was not executed in this scoped audit.
