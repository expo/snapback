## Expiry

`messages.send` binds `ttl = expiresAt`, then binds another `ttl` inside nested
if blocks. The insert reads the outer value. Three grader sends stored null;
an explicitly dated control expired, isolating the failure from the scheduler.

Compute the chosen deadline as one expression or an expression function with
explicit branches, then pass it into the insert. Preserve immutable lexical
bindings and `proc` hygiene. Cover off/24h/7d, explicit deadline precedence,
and the corresponding media sends. Read configured durations, not literal
shortened benchmark windows. Keep deadline selection server-authoritative.
Test stored deadlines, scheduled purge with clients closed, emitted tombstone
and offline reconnect eviction. Guide text should teach branch value flow;
do not add mutable assignment as a workaround.

## Following-post activity

`bumpNewPostForFollower` is defined in access.q and imported in posts.q but
never invoked by text/image/video creation. A helper definition has no effect.

Compute following-post activity at digest emission through indexed period
reads, with current follow/visibility checks. Do not wire the per-follower
helper into post creation: the 900-follower celebrity must keep write p95
within three times the five-follower control. Remove the unused helper/import
once the replacement is qualified. If maintained per-author period inputs
help, their write cost must not scale with follower count.

Count each eligible new post once. Explicit-ID and ordinary-ID creation agree;
replies, retries, reposts and rejected creations cannot inflate the count.
Check the 500-follow read envelope and certificates; never repair a refusal
by increasing a for-loop cap without bounded evidence.

## Period digests

`digestSweep` ORs standing unreadMessageTotals/unreadChatCounts into eligibility,
including when there is no period bucket. Five consecutive digests were logged
without new period activity. The period uniqueness check works, but it only
prevents duplicates within one period.

Derive each payload field from eligible activity in `[periodStart, periodEnd)`:
new followers, newly visible following posts and unread messages/chats with
eligible new-period messages. Do not use lifetime unread totals as new activity.
Authorize at emission: departed/hidden chats and expired/tombstoned content do
not count. The recipe must emit without a connected client, skip all-zero
periods, honor replay mode, and be idempotent for user/period across retry and
owner restart. Preserve atomic record-plus-effect admission and provider
idempotency; storage uniqueness alone cannot promise exactly-once external I/O.

Test two active periods separated by a quiet period with standing unread data,
exact boundary timestamps, reads/deletions/expiry/membership changes before the
sweep, replay mode, retry and restart. Configure period duration consistently
with the schedule; fixture shortening must not alter the algorithm.

## Push preview

`afterSend` writes its preview argument into `pushLog` and emits it unchanged;
the schema permits 2,000 characters. The grader stored all 223 characters.

Apply one shared 80-character definition before the stored preview and provider
payload diverge. Rust and the twin already implement IR Slice over Unicode
scalars, but Quarry exposes no spelling at the baseline. Expose that existing
primitive through a bounded pure `slice` builtin with sound type/length checks;
update LLP 1011's word inventory and the one-line scope trade in NOT-DOING.
This is an authoring spelling, not a new language profile or runtime primitive.
The root chose this over the reviewer's effect-plus-then alternative because
the data transaction can bound both stored and emitted fields once, without
moving application log creation into an asynchronous callback. Keep Unicode
scalar semantics (not UTF-16 units or grapheme clusters) consistent in both
engines. Media-only payloads retain Photo/Video, view-once never includes
hidden body text, and target/chat/sender fields are unchanged.

Test lengths 0/79/80/81/223, multibyte text and emoji at the boundary, media
fallbacks and retry. The stored row and captured provider payload must agree.
Use a local declared effect fixture; do not contact a real push provider.
