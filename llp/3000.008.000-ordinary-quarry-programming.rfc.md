## Summary

Routine computation should be straightforward in Quarry while authorization,
completeness and metering remain sound. The proposed language forms already
shipped through [LLP 3000.007](./3000.007-relaxed-quarry-and-explicit-residency.rfc.md).
This child now owns the remaining product verification, not another rollout.

## 1. Current evidence

The [compiled language card](../snapback4/crates/snapback4-lang/src/guide.rs)
and [published reference](../snapback4/packages/snapback4/README.md) include
same-type reassignment, accumulation, `continue`, `else if`, text concatenation,
Euclidean `/` and `%`, helpers, list operations, seeks and `where` predicates
that may read. Reassignment resets refinements; growth is metered at runtime.
The original single-assignment/absent-filter description was historical and
is no longer the current surface.

[LLP 3000.007 §19](./3000.007-relaxed-quarry-and-explicit-residency.rfc.md#19-the-next-landing-presence-that-decides-effects-a-helpers-return--2026-09-14)
already commissions presence classification, helper-return pagination and the
`==` mechanical rewrite. That program retains ownership; this family consumes
its landing. The 0.2.12 calibration found the helper's lost cursor to be a real
correctness defect, not a reason to add another language feature.

## 2. Proposed outcome

A builder can calculate day buckets, accumulate a digest, compose a preview
and filter an indexed page without auxiliary arithmetic tables. Those forms
remain one spelling on every host. Jobs and native computation retain their
existing role for work outside the bounded interpreter.

## 3. Semantics that must be settled

These semantics are **settled** by LLP 3000.007 and the current card:

### Locals, inference and evaluation

Reassignment keeps a compatible inferred type and resets refinements. Helper
returns end the helper. List operations charge actual work and allocation;
meter exhaustion aborts a mutation atomically. Integer division/remainder use
the existing Euclidean convention and refuse zero divisors. No floats,
recursion or unbounded loops are added here.

### Filtering, completeness and cursors

Predicates run after authorization and may perform metered reads. A full
page positions after its last returned row; a cut positions after the last
**rule-visible** examined row, including a rejected visible candidate, never
an unreadable key. Non-uniform scans retain truthful incompleteness. Existing
uniform-prefix mutation restrictions and disclosure regressions remain in force.
This child does not reopen hidden-row continuation or authorization policy.

### Aggregation and ranking

An aggregate covers its input page. Sorting and slicing it cannot turn that
page into an exact larger domain. The feeds card's trailing-day recipe examines
up to 8,192 candidates and must report incomplete beyond its ceiling. Its
neighboring ranked projection has a refresh cadence; a time-decay ranking is
not automatically exact trailing-day likes ranking.

The ceremony's small seed lets first-200/first-1000 implementations pass. That
is a useful bounded counterexample to test, not evidence for a new ranking
engine. Put winners after candidate 200 and 1000, then verify the exact IDs
within the admitted domain and truthful incompleteness beyond its ceiling.

## 4. Implementation scope and sequence

Reuse existing compiled-guide, language, simulator and device tests. Add the
ranking counterexample to the appropriate existing acceptance surface and
repair a reproduced completeness defect or misleading recipe if found.
Consume the separately owned §19 fixes without copying their lanes. No parser
expansion, SQL application reads or new ranking subsystem is authorized.

## 5. Acceptance examples

1. Current guide examples compile; delivered ordinary forms are referenced as
   implemented rather than re-proposed.
2. The existing §19 landing demonstrates helper pagination without missing or
   duplicated rows, and the presence exception stays restricted to effects.
3. An exact bounded ranking includes a winner beyond the first 200/1000
   candidates. A domain beyond the actual ceiling is explicitly incomplete;
   sorting/slicing does not conceal that fact.
4. Existing authorization, meter rollback, cursor and both-store tests remain
   intact. A passing small-seed ceremony is not substituted for example 3.

## 6. Open decisions

The accepted increment ends at these residuals. Further language growth needs
a concrete application requirement and its own decision. Full cold-builder
reruns remain evidence with the instrument's stated scope; they are not a
new blocking gate for this regression.
