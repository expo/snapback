# LLP 3000.008.000: Ordinary Quarry programming

**Type:** RFC
**Status:** Draft
**Systems:** Snapback 4 Quarry parser and binder; IR; interpreter; metering; completeness; pagination; generated types; guide and diagnostics
**Author:** Codex (for Charlie Cheever)
**Date:** 2026-09-14
**Revised:** 2026-09-14 (initial; first gap in the holistic assessment)
**Related:** [LLP 3000.008](./3000.008-holistic-product-excellence.rfc.md), [LLP 3000.007](./3000.007-relaxed-quarry-and-explicit-residency.rfc.md), [LLP 2000.000](./2000.000-keep-the-core-flip-two-substrates.rfc.md), [LLP 3000.005](./3000.005-native-jobs.rfc.md)

## Summary

Make routine computation straightforward in Quarry while preserving the
properties that justify using Quarry. A builder should be able to calculate
a digest, assemble a short list, filter an indexed page and compose a preview
without introducing a work table solely to carry a local counter.

[LLP 3000.007 §5](./3000.007-relaxed-quarry-and-explicit-residency.rfc.md#5-the-language-re-derived)
already proposes the syntax changes. This child extends their rationale and
acceptance contract. It does not create a second syntax specification or
accept every proposed form as safe merely because an IR instruction exists.

## 1. Current evidence

The [language card](../snapback4/crates/snapback4-lang/src/guide.rs) and
[published reference](../snapback4/packages/snapback4/README.md#queries-mutations-and-jobs)
document single-assignment locals, nested conditionals in place of `else if`,
literal ranges and `divmod` rather than `/` and `%`. The binder rejects
duplicate locals and the parser refuses `where`. The interpreter supports
assignment, push, continue and concatenation at the IR level.

The [0.2.6 builder essay](../benchmarks/runs/2026-09-13-snapback4-clique-0004/astra/essay.md)
records both the cost of unfamiliar filtering and the benefit of refusing an
incomplete mutation fan-out. The earlier full-brief run and LLP 3000.007
record arithmetic and accumulation workarounds. This supports targeted
relaxation, not removal of every restriction.

Some restrictions are consequences of retired static pricing. Others are
semantic choices, implementation limits, authorization requirements or scope
decisions. Label each accurately when amending LLP 3000.007; treating all of
them as the same cause would obscure the decisions still required.

## 2. Proposed outcome

Use one language on every host under the existing deterministic meter. Start
with same-type local reassignment and accumulation, `continue`, `else if` and
text concatenation. Evaluate arithmetic sugar with explicit integer semantics.
Treat indexed filtering as a separate semantic change because it affects
coverage, cursor progress and information disclosure.

| Ordinary task | Desired authoring property | Property that must survive |
| --- | --- | --- |
| Build seven day buckets | A short loop produces a list without seven copied expressions. | Deterministic order, inferred element type and metered allocation. |
| Sum a recipient's digest | Locals carry totals inside a chunk without a temporary table for arithmetic. | The traversal's coverage determines whether the total is exact. |
| Skip an irrelevant item | `continue` expresses the control flow directly. | No skipped accounting, cleanup or mutation validation. |
| Form a notification preview | Bounded text composes in the program. | Heap/output charging and the existing text/value contract. |
| Filter an indexed page | A row-local predicate participates in page selection. | Authorization, ordering, honest completeness and safe continuation. |

Jobs remain appropriate for work that spans bounded transactions or runs on
the server's schedule. Native jobs and reads remain appropriate for compute
that needs their capabilities. Neither should be required just to express a
counter or ordinary control flow.

## 3. Semantics that must be settled

### Locals, inference and evaluation

Reassignment preserves a local's inferred type. Branches and loops need an
explicit initialization and scope rule; assigning in one branch does not
make a value available on every path. Reassignment invalidates a previous
null-narrowing fact when the new value may be null. Helpers must retain their
existing evaluation order and binding hygiene.

List growth needs element inference, empty-list behavior and alias semantics.
An append optimization must preserve observable value semantics and charge
actual allocation and work before growth exceeds the limit. A cheap IR
instruction is not permission to construct an unmetered intermediate value.

For `/` and `%`, settle the quotient/remainder convention for negative inputs,
division by zero and integer boundaries, consistently with `divmod`. Familiar
punctuation with surprising numeric behavior may not be a net ergonomic gain.
This proposal introduces no floating-point value model.

### Filtering, completeness and cursors

Start with predicates over the candidate row's declared fields. Reads inside
a predicate remain a later decision, with their probe cost and authorization
semantics stated before admission. A predicate is applied only after the row
is readable; it does not replace the read rule or expand the sync audience.

LLP 3000.007 §5.1 proposes advancing a capped filtered page after its last
examined row. That must be reconciled with [LLP 3000 §7's current completeness
and cut policy](./3000-snapback4.explainer.md#7-decisions-during-execution).
Exhausting a range or finding N matches does not make a non-uniform server
scan complete if its authorization class cannot establish that fact. Likewise,
a device cannot assert knowledge beyond its acquired coverage.

For a uniformly readable range, consider advancing across rejected visible
rows so repeated requests make progress. A continuation involving hidden rows
needs the existing disclosure-sensitive review: repeated cursors and empty
pages must not expose a hidden population or turn a terminal cut into an
unbounded drain. Keep the current conservative behavior until that design is
settled. The acceptance cases distinguish these two situations.

### Aggregation and ranking

Accumulation over a page produces a page aggregate. It becomes a global or
window aggregate only when the input coverage proves that claim. The same
rule applies to sorting: sorting 200 recent posts and taking ten does not
establish the ten highest-scoring posts in a day containing more candidates.

The Trending illustration in LLP 3000.007 §5.2 therefore needs an explicit
domain restriction, incomplete result or maintained/materialized ranking before
it replaces the exact product feature. Easier syntax must preserve the result
the application asked for, not substitute a convenient sample.

## 4. Implementation scope and sequence

Amend LLP 3000.007 with the chosen forms and semantic rules. Then implement
the low-interaction forms through the parser, binder and existing IR, followed
by expression and growth behavior. Resolve filtered pagination separately
before implementing it in the shared scan path.

Update the language card, diagnostics and generated types with each admitted
form. Every new current-surface guide example enters the existing compiled
guide tests. Retain useful refusals and their rewrites for still-unsupported
forms. Do not leave the guide's exclusion list contradicting the parser.

The implementation touches the language crate and shared interpreter as needed;
it creates no second interpreter, arbitrary server-code path or static
byte-pricing subsystem. It uses the current suite and corpus entry points.

## 5. Acceptance examples

1. The day-bucket, digest-total and preview tasks compile and execute through
   the ordinary published surface with no arithmetic-only work table or
   hand-unrolled repetition. Their outputs match the full intended domain.
2. Assignment after narrowing, branch-only initialization, nested helpers,
   aliases and repeated list growth have the same outcomes on the server and
   both device stores. Meter exhaustion rolls back a mutation completely.
3. A uniformly readable filtered range with a rejected run longer than one
   request's examined budget either progresses under the accepted continuation
   policy or reports its explicit terminal limit. It never loops on the same
   cursor while claiming progress.
4. A non-uniform scan, hidden rows, ties in ordering and a device horizon
   preserve the accepted completeness and disclosure contract. Filling a page
   is not used to manufacture stronger authority.
5. A ranking fixture places the winning item outside the first 200 candidates;
   an exact Trending operation still returns it, or an explicitly partial
   operation reports the restricted domain rather than claiming exactness.
6. Cold builders perform the named tasks through the package and diagnostics.
   Record total corrections and the forms that caused them, including mistakes
   attributed to the builder; self-attribution alone is not an ergonomics score.

## 6. Open decisions

Recommend admitting the simple control-flow and accumulation forms first,
with filtering following the settled cursor policy. Decide arithmetic sugar
on its complete value semantics. Keep `while`, recursion, union sync audiences,
SQL reads and worker-action syntax outside this child's initial scope.

The criterion for retaining a restriction is the property or scope decision it
protects and its observed application cost. This document is Draft and changes
neither today's language card nor the disclosure contract by itself.
