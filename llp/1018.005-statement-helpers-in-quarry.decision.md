# 1018.005 Statement helpers in Quarry: `proc`

**Type:** Decision
**Status:** Draft
**Systems:** Quarry language and compiler (`packages/compiler/src/quarry`), the chat recipe (`templates/chat/snapback`), the Quarry guide and grammar pages, compiler checks
**Author:** Claude (Fable 5.1), with the author; implementer: the same agent, 2026-09-08
**Date:** 2026-09-08
**Revised:** 2026-09-08
**Related:** LLP 1018.000 §7 (expression-only `fn`), LLP 1011 (Quarry ergonomics; the `fn` ledger), LLP 1004 (Quarry), LLP 1012 §7 (the fan-out that replay re-executes fresh), issue `20260907-snapback2-media-sends-produce-no-delivery-rows`

## Summary

`fn` made the chat recipe's predicates and bounded reads reusable, and it
was scoped to expressions on purpose: no writes, statements, commit time,
allocation, or `require`, so a helper means the same thing in a query, a
shape, and the twin. The recipe's one remaining repetition is a block, not
an expression. Delivery fan-out, a bounded loop that inserts one `deliveries`
row per member, is written six times across two modules, and the two media
mutations that should also write it do not, which is the open ticket. `fn`
cannot reach it, and it should not: giving `fn` a block form would fork its
meaning by body shape.

This decision adds one construct: **`proc`**, a named, typed block of
statements declared at module level, imported like `fn`, and elaborated at
each call site into the caller's program under the caller's own context.
Whatever the caller may do, the body may do; whatever it may not, refuses at
the authored line naming both sites. The only new refusal is `return` inside
a proc. Nothing below the bound tree changes: no engine, IR, twin, wire, or
certificate-schema change, because a proc call lowers to the statements the
author would have written by hand plus one binding per argument. The recipe
gains `proc deliver` in `access.q`, used eight times, which closes the media
ticket in the same landing.

## Context

### The repetition

```q
for m in conversationMembers(conversationId):
  insert deliveries { recipient: m.principal, conversationId, messageId: row.id, kind: 'message', at: now }
```

This loop, with `kind` varying, appears in `post`, `unsend`, `edit`, and
`purgeMessage` in `deliveries.q` and in `send` and `sendOncePhoto` in
`messages.q`. `sendPhoto` and `sendClip` insert their message and stop, so
the delivery-log thread never shows a photo or a clip; that is the ticket
filed from the LLP 1018.003 implementation review. Copy-paste produced the
gap, which is the argument for a construct rather than a fix.

### Why `fn` stays expression-only

LLP 1018.000 §7 lists what a helper body may not contain: statements,
writes, `emit`, `require`, `! else`, mutation-only `new`, commit time, and
capture. Those refusals are what let one `fn` be used from a query, inside a
named shape, and by the twin's local evaluation with one meaning. A block
body would need writes and commit time, and then `fn isMember` and
`fn deliver` would be two different kinds of thing under one keyword. The
same section names "general statement functions" as outside its slice and
cites a seven-path update duplication as evidence for later statement
composition. This is that later step, kept as narrow as the evidence.

### What the compiler already has

`fn` is elaborated on the bound tree by `ExpressionBinder.functionCall`: it
resolves the declaration through a module registry, types each argument
against the parameter, evaluates arguments once into fresh
`BoundArgumentSymbol`s, binds the body with a scope holding only those
symbols, tracks expansion frames for cycles and depth, and produces an
`invoke` expression whose lowering binds one `Const` per argument. Statements
are bound by `statements()`, which already handles nested blocks with scope
save and restore for `if`, `for`, and `match`, and lowered by
`lowerStatements`, which scopes bindings by symbol id. A statement-level
helper is those two pieces joined.

## Options

**A. `fn` with a block body.** One keyword, two meanings. Rejected for the
reason above.

**B. `proc`: a statement helper elaborated at the call site under the
caller's context.** Chosen. It is `fn`'s machinery applied to a block, with
the caller's program kind deciding what the body may do.

**C. A dedicated fan-out construct**, for example `deliver deliveries to
conversationMembers(c) with { ... }`. Solves exactly today's repetition and
nothing else; LLP 1018.000 §7's cited evidence is a different shape of
repetition. Rejected as too narrow.

**D. Leave the repetition and fix the two media mutations by hand.** The
ticket would close and the next copy would drift again. Rejected.

## Decision

### 1. Grammar

```q
proc deliver(c: conversations, messageId: messages, kind: enum('message', 'edit', 'removed', 'expired')):
  for m in conversationMembers(c):
    insert deliveries { recipient: m.principal, conversationId: c, messageId, kind, at: now }
```

A `proc` declaration is the keyword, a name, a parenthesized typed argument
list in the same syntax as a program's, a colon, and an indented block of
statements. `proc deliver from access` imports it, exactly as `fn` and
`shape` import. A call is a statement on its own line, `deliver(conversationId,
row.id, 'message')`. `proc` joins `shape`, `fn`, and `cursor` as a reserved
binding name and joins the parser's top-level declaration set for recovery.

A proc used in expression position refuses `E_QUARRY_TYPE`: "proc deliver is
a statement; call it on its own line". A `return` anywhere in a proc body,
including nested blocks, refuses `E_QUARRY_PLACEMENT`: "a proc has no value;
return from the mutation after the call". A proc that needs to produce a
value is a `fn`, or the caller binds a value after the call.

### 2. Elaboration

At the bound tree, a call resolves the declaration through a registry with
the same shape as `fn`'s: module-local names, imports by module, duplicate
and cycle refusals, and one name space with `fn`, so a module cannot declare
a `fn` and a `proc` of the same name. Arguments type against the parameters
and evaluate exactly once, left to right, into fresh argument symbols, with
the same contextual typing and row-to-id coercion `fn` applies. The body
binds with a scope holding only the parameters: caller locals are invisible
inside, body locals are invisible after, and a parameter named like a
context builtin resolves by identity, all as for `fn`.

What differs from `fn` is the context. The body binds under the **caller's**
program: `viewer`, `now`, `commit`, and `new` mean what they mean in the
caller; writes, `emit`, and `require` bind exactly where the caller allows
them, so a proc called from a query refuses at the write with both sites
named, and a proc called from a job refuses at an `emit` the same way. A
`require ... else CODE` inside a proc refuses the caller with `CODE`. That
is a deliberate difference from `fn`'s "callers own their refusal": a proc
is the caller's statements, and a fan-out's guard belongs with the fan-out.
The focal row of a schedule or table rule does not reach a proc body.

Procs may call `fn`s and other procs. Import and call graphs are acyclic;
expansion shares `fn`'s depth limit of 8 and node budget of 4,096. Each call
instantiates distinct symbols and read sites, charged to the caller's
certificate; there is no cost sharing between call sites. Diagnostics carry
the definition site and the use site.

### 3. The bound tree and its lowering

`BoundStatement` gains one member, `invoke`, holding the argument bindings
in `fn`'s shape and a body of bound statements. Lowering reuses the
expression invocation's binding setup, one `Const` per argument with the
row-to-id coercion, then lowers the body with those bindings in scope and
restores the scope after. The IR is therefore what an author would write
with an explicit `x = value` line per argument followed by the block.
Nothing in the engine, the certificate schema, the twin, or the wire
changes. Plan hashes of the migrated mutations change, because their IR
gains the argument bindings; that is a recompile, not a migration.

### 4. The recipe

`access.q` gains `proc deliver` as written in §1. The six loops become
calls, and `sendPhoto` and `sendClip` gain the call they lacked, so a photo
or clip fans out like a message. That closes the media ticket; the
real-owner media test asserts that a photo send produces a delivery per
member and that the thread lists it. The compiler's fixture copy of the
recipe mirrors the change where it carries these files.

### 5. Surface

`guide/quarry.md` gains a `proc` paragraph beside `fn`'s, within its byte
limit, which means trimming elsewhere on the page; `guide/grammar.md` adds
`proc` to the reserved bindings. LLP 1011's `fn` ledger notes `proc` as the
statement counterpart, and LLP 1018.000 §7's "outside this slice" sentence
gets a pointer here.

### 6. Checks

A new `quarry-proc-checks.ts` in the compiler suite covers: declaration,
import, and call; a proc calling a `fn` and another proc; hygiene in both
directions and the builtin-named parameter; arguments evaluated once
including a mutation-only `new` in an argument; row-to-id coercion; `return`
refused inside a body; expression-position use refused; a cycle refused; the
shared depth budget; a query caller refusing at the body's write with both
sites; a `require` inside a proc refusing the caller with its code; and
certificate parity, a proc-using mutation certifying with the same bounds as
its hand-inlined twin. The chat template compiles and its existing
journeys, screen suites, and the browser witness pass unchanged in
behavior; the media test gains the fan-out assertion.

## Sequencing

1. Parser, AST, registry, binder, lowering, and the checks, with the chat
   recipe migrated in the same change so the construct is proven on its
   motivating case.
2. Guide, grammar, LLP 1011 and 1018.000 notes, the ticket closed.
3. Astra reviews the design blind before 1; Astra reviews the integrated
   implementation after 2; the compiler suite, the Rust guide and init
   tests, the JS suites that compile the template, and the browser witness
   run before landing.

## Consequences

- The recipe's fan-out is written once and used eight times; the media
  mutations are corrected by using it.
- Quarry gains one keyword and one refusal. `fn`'s contract is untouched.
- The compiler grows by a registry, a statement binder branch, a bound
  statement member, and a lowering branch, roughly 200 lines; `bound.ts` is
  at 1,277 lines against the 1,500 cap.
- Plan hashes of the migrated mutations change.

## Non-claims

- No recursion, no return values, no first-class or generic procs, no
  default arguments.
- No new capability: a proc body can do exactly what its caller could have
  written in place.
- No engine, IR schema, twin, wire, or certificate-schema change.
- No fan-out keyword, no cross-module hidden authorization, no cost sharing.

## Open questions

1. The keyword. `proc` is the conventional name for a statement helper and
   is distinct from `fn` at a glance; `do` and `step` were considered and
   read worse at the declaration. The reviewer may prefer another.
2. Whether `require` inside a proc should instead be refused, keeping
   `fn`'s rule that callers own their refusal codes. The draft allows it for
   the reason in §2.
