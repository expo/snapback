# LLP 3000.015: The shared baseline for Snapback 5 — field-level write authority, engine sequences, row-keyed maintained views

**Type:** Spec
**Status:** Draft
**Systems:** Snapback 4 — Quarry (parser, binder, schema IR), the read/write paths, rules and caller accounting, partition images and projection, maintained aggregates, prediction, the guide
**Author:** Claude Fable 5.1, at Charlie Cheever's request (LLP 4000 §9.6 step 3, commissioned 2026-09-24)
**Date:** 2026-09-24
**Revised:** 2026-09-25 (B3 live-basis row views integrated with B1 and B2); 2026-09-25 (B1 sealed disclosure integrated over B2 whole-rule authorization); 2026-09-25 (whole-rule expiry timelines and one request-wide physical authorization allowance); 2026-09-25 (bounded expiring cap scans, successful-predicate expiry dependencies, raw-storage token fence, exact walk boundary); 2026-09-25 (author restores bounded walks; every effect prepays whole rules; required authorization token); 2026-09-25 (one prepaid authorization scan, compound rules, cap and payload matrix, JSON counter descriptions); 2026-09-24 (initial)
**Related:** [LLP 4000](./4000-snapback5.rfc.md) §3.3 and §8 (the additions and why they land in Snapback 4 first), [LLP 3000.007](./3000.007-relaxed-quarry-and-explicit-residency.rfc.md) §5 (the language re-derived), [LLP 3000.007.001](./3000.007.001-maintained-columns.rfc.md) (maintained columns), [LLP 3000.013](./3000.013-quarry-states-intent.rfc.md) (`view`, streaming aggregates, self-chunking work), [LLP 3000.014](./3000.014-a-child-reads-through-its-parent.rfc.md) (`through`, not part of this baseline)

## Summary

LLP 4000 judges Snapback 5 against a Snapback 4 that carries the same
additions, so that the only difference between the arms is derived
residency. This spec is those additions, landed in Snapback 4 as ordinary
language and engine work, each reviewed on its own. Three of them are here;
`through .ref` is LLP 3000.014 revision 2 and is not part of this baseline.

1. **`written by .col`** on a column: field-level write authority, with
   private projection by default and `readable by audience` to opt out.
2. **`sequence by <ref>`** on a column: an engine-assigned, dense,
   per-parent integer, assigned at commit, provisional under prediction.
3. **A maintained view keyed by another table's row:** `view name: count T
   by U u where <predicate over T's fields and u's fields>`, maintained per
   `U` row, with a bounded background recount when a `u` field the predicate
   reads changes by more than the meter allows in the writer's transaction.

Together they let Clique's read marks, unread counts and message ordering
leave the application's hand-written helpers without a per-message receipt
row. The receipt table itself stays (LLP 4000 §3.3).

## 1. `written by`

```quarry
table members:
  conversationId: conversations
  principal: principal
  readUpTo: int default 0 written by .principal
  read <- exists members[.conversationId, viewer]
  update (old, next) <- exists members[conversationId = old.conversationId, principal = viewer, role = 'admin']
                     and next.readUpTo = old.readUpTo
```

- **Authority.** The value of a `written by .p` column may be written only
  by the principal named in column `p` of the same row. An insert sets it
  to its declared default; a supplied value is refused with
  `E_FIELD_AUTHORITY` unless the inserter is that principal. A patch that
  touches the column is authorized for that column by that principal, and
  for every other field by the row's `update` rule. The owner may patch the
  column alone with no row `update` rule; the row's `update (old, next)`
  rule may still constrain the transition (monotonic marks), as above.
- **Projection.** By default the column is **private to its owner**: it
  never appears in a log image, a query row, a shape, a cursor or a write
  result delivered to any principal other than the owner. The owner sees
  it on every device. `readable by audience` on the column makes it an
  ordinary column for reads. The implementation must deliver the private
  value to the owner's devices through the owner's own partition, not by
  filtering the group image per reader, because group images are shared
  by audience.
- **Caller accounting law.** The caller-visible meter charges exactly two
  kinds of quantity: fixed reservations derived from declared bounds (column
  bounds, index arity, page size, and the rule's witness count), and the
  disclosed result after row-read and field authorization both succeed.
  Candidate decoding, rule evaluation, witness probes, and materialization
  of unreadable rows run on an internal ledger under that reservation; no
  actual charge from that ledger enters the caller's receipt or cut.
  `authorized_scan` is the shared B1/B2 boundary: admission precedes candidate
  access, and every return restores the caller's ledger, ceilings and cut
  policy. B1 adds transient declared decoder/witness scratch around this
  boundary for point reads, scan candidates and write-target resolution.
  Candidate materialization, expiry filtering, row authorization and private
  projection finish inside that scope; only surviving `AuthorizedRow` images
  can be charged afterward. `Disclosed` alone has no pricing authority.
  Rule witnesses export verdict/coverage and the complete-rule deadline
  defined in §2 (including simultaneous and correlated alternatives). Public, non-expiring tables with
  no private fields or recorded captures prove row authority before access and may use actual-size
  decoder admission, including a short value under a large declaration. System maintenance owns its own ledger,
  and device physical authority work retains its separate uncertainty budget.
- **Observable noninterference.** Private input changes must leave an
  unauthorized principal's results, refusal envelope, meter, changes table
  set, sync images/watermarks and maintenance sequence unchanged. Projection
  copies only disclosed fields and missing ordinary-field defaults; it never
  reinstates an omitted private default. Private fields cannot supply public
  derived values, including Following mappings and predicates under either
  spelling. Non-uniform server scans of a table with private fields require
  a readable audience scope in B1; B2's authorized scan supplies the shared
  page-reservation implementation for the combined baseline.
  Hidden delete and absent upsert field-authority refusals use the ordinary
  `NOT_FOUND` attempt boundary. Direct inserts and readable write targets
  keep their detailed errors. A named transition cannot test another owner's
  private value to decide an ordinary patch: require the field's owner, except
  for value-independent comparisons of an untouched field with itself. A patch
  retaining an unreadable row's fields or a non-owned private payload charges
  declared column copy bounds, never hidden lengths. Ordered self-comparisons of nullable private fields
  are value-dependent; equality/inequality and required numeric
  self-comparisons can be folded before evaluating omitted device values.
  Decoder reservations cover UTF-8/escaping, map and array growth, recursive
  list/JSON bounds, bounded asset facts and the 144-byte identity admission
  bound. SQLite lends its stored JSON during decode. A large declaration can
  exceed the heap even for an empty value; both worlds then refuse identically.
  No runtime ceiling is raised. The raw retained-row `Value::heap_bytes` API
  and `Context`-minted system token are removed. The system projection token has a private
  runner-only constructor; PostgreSQL raw cache pricing charges an opaque
  internal ledger that exports no price. Raw scalar and serialized-storage
  prices are opaque `InternalPrice` values, accepted only with an internal
  scope; metered adapter scans require that scope too. Exact retained-image
  pricing requires sealed row-read evidence, and expression pricing keeps its
  private evaluator capability. Supplied write values carry sealed input
  provenance through defaults, key completion and immutable-field removal;
  retained old fields use declared copy bounds. Authorized result keys and
  evaluated cursor/input keys retain their separate evidence. There is no
  writer helper that accepts a raw old value and returns a caller price.
  Compile-fail tests cover raw materialization, fabricated system/row authority,
  unproven field projection, raw owned scalar charging with and without a scope,
  and an unscoped metered storage call.
  Owner delivery prepays one step and the rule's static witness count per
  declared private-field slot and row image; exact recipient checks use an
  internal ledger. Mutation receipts count private-table events by table and
  row, independent of recipient fanout. The generated paired worlds cross
  unreadable witness tables with private fields, compound rules, hidden
  presence, repeated operations through the default probe ceiling, expiry,
  and different observers, alongside the existing type/population cases.
  Wildcard shapes select private fields through the same optional access as
  explicit selection: a non-owner receives null. Successful delete, group/sort,
  private-token searches and equal-length escaping variants also have paired
  controls. Round 7 crosses elapsed time (at/past expiry), owner-visible
  private payload, page/wildcard/count/sum scans, successful hidden witnesses
  with different deadlines, and expiring deletes with the shape/delete
  templates. Devices also expire previously acquired owner payload offline
  and after reopen. This is bounded regression evidence, not universal
  noninterference proof.
- **Prediction.** A write to an own `written by` column is a point write to
  a held row and predicts under the existing rules.
- **Diagnostics.** `E_FIELD_AUTHORITY` (a non-owner supplied or patched
  the column), with a rewrite naming the owner column; a `check` line per
  such column stating its visibility.

## 2. `sequence by`

```quarry
table messages:
  conversationId: conversations
  ordinal: sequence by conversationId
table members:
  conversationId: conversations
  joinedAt: sequence by conversationId
```

- **Assignment.** One counter per parent row (here, per `conversations`
  row), shared by every column in any table that declares `sequence by`
  that parent. The engine assigns the next value at commit, dense and
  monotonic per parent, inside the write's transaction, in every store
  (memory, SQLite, Postgres) with the same transactional discipline as cap
  occupancy counts. A client-supplied value is refused with
  `E_SEQUENCE_SUPPLIED`. The column is immutable by construction.
- **Disclosure.** Sequence insertion requires read authority established from
  the supplied/defaulted image independently of the allocated ordinal. The
  generated paired-world harness compares refusals (including text), every
  logical meter field, expiry deadlines (`next_expiry` / `nextExpiry`), pages/cursors, changes, stream/snapshot images and
  watermarks, and device prediction, admission, reopened outboxes and settlement.
  Its guarantees depend on the principal's authority:
  - A **blind principal** with neither insert nor read authority is refused
    before allocation-independent insert denial can consult a read witness.
    Varying an unreadable sibling, witness or counter history changes none of
    those observations.
  - An **insert-only principal** whose candidate is unreadable receives generic
    `E_RULE` (upsert insert arm: `NOT_FOUND`) before counter allocation,
    uniqueness or cap checks. Ordinal-dependent read rules cannot authorize an
    allocation by evaluating the missing ordinal as null. Deferred insert
    authorization reserves its static probe/counter work and actual image copy
    before the read guard; denied direct inserts restore their meter. Refusal
    equality includes the default ceilings after 512 scratch writes × 32 indexes.
  - A **self-readable principal**, including the writer, may see the ordinal
    assigned to a successful insertion; that value intentionally reflects the
    shared counter. An upsert addressed by a sequence key returns `NOT_FOUND`
    with the same restored meter for absent and unreadable refused targets,
    even when its candidate would be readable. An owned target retains its
    ordinary update-authority diagnostic. A directly supplied ordinal in an
    insert or patch is `E_SEQUENCE_SUPPLIED` before lookup.
  - A **witness-dependent principal** cannot distinguish hidden grants through
    an independently denied insert or a denied deferred allocation. Grant
    presence that actually establishes both insert and read authority may
    change refusal to success: authorization itself is an intended observable.
    An unheld witness remains device uncertainty; the durable outbox leaves
    the decision to the server.
  Every effect reserves its complete static rule-probe allowance before
  evaluating any witness, including short-circuited compound write rules.
  Sequence preflight reserves only checks still pending, without reserving an
  independently authorized insert rule a second time.
  Every authorization-dependent lookup/scan uses one `authorized_scan` helper.
  Authorization lookups and rule probes require a borrowed token minted only
  inside the storage guards; `Runner` itself is not a rule probe. Its store
  facade holds the raw transaction privately and implements neither `Rows` nor
  `Deref`; get/lookup/scan/count/counter reads require the token. Ordinary
  metered operations use a token scope that preserves their meter unchanged;
  private authorization uses the prepaid, restoring scope.
  Repeated unchanged point lookups share one request-local decoded-candidate
  cache, invalidated by every row write. This avoids making an otherwise
  redundant hidden witness select exhaustion at the logical probe boundary;
  actual storage fetches still share the same physical allowance and every
  logical read still prepays its complete rule.
  It charges the declared logical allowance before fetching an occupant, marks
  that paid meter, runs private authorization work, and restores the paid mark
  on success or refusal. The caller's ceiling can cut only the reservation,
  never work selected by a hidden row. Cap groups reserve their declared N
  candidates and read-rule probes; complete unique keys reserve one rule tree;
  a predicted uniform page reserves the server's full rule tree even when
  delivered evidence avoids evaluating it locally;
  counter reads reserve one index entry.
  **Physical allowance:** one request's authorization work shares a single
  8,192-row physical allowance through `authorized_scan`, including nested
  witness alternatives, expired-witness walks and maintained-source walks,
  and exhaustion fails closed with the same generic `E_RULE` without
  hidden-dependent logical charges.
  The store facade owns this allowance, so neither a nested authorization
  scope nor a later check in the same request replenishes it; a cap update
  spends the same allowance as an insert. The budget counts fetched
  authorization candidates; public data reads keep their ordinary meter,
  system execution has no viewer authorization, and the non-expiring public
  cap's scalar count retains its declared cap bound without fetching rows.
  Main's transactional physical occupancy is also retained as an upper bound:
  below a non-private cap it proves room without a scan; when saturated the
  bounded live scan decides. Private sequence caps still authorize occupants.
  This supersedes LLP 3000.013 §11.1's conservative unswept-cap semantics
  while keeping its counter custody, adoption and device deferral.
  A single unchanged witness answer may be reused while still paying each
  declared logical probe; every row write invalidates it, and prediction's
  separately metered authority work does not use that cache.
  **Expiry:** `next_expiry` is the earliest instant at which removing every
  row expiring at that instant changes the complete bound rule's current
  verdict, considering all witness alternatives within the rule's allowance.
  The shared rule evaluator combines complete expiry timelines, including
  simultaneous and correlated branches: a later matching witness keeps an
  existential true, stable ownership needs no witness deadline, and `A or
  not A` never changes verdict. Failed predicates and denied rows publish
  no expiry, and independently returned row lifetimes still apply.
  The server point read, ordinal page, provisional evaluator and release
  `nextExpiry` all use this definition. Point reads reserve one examined unit
  and the rule's full probe tree. Non-uniform pages reserve one examined unit
  and `(page size + lookahead) × rule probes` before candidate discovery,
  including compound rules and ordinary integer indexes. Only readable
  candidates reach page payload charges, filtering, lookahead or cursors.
  Word discovery likewise prepays its 33-word allowance and admits only words
  with an authorized candidate; hidden-only words cannot consume that bound.
  A readable row consumes the page's initial examined unit; later readable
  candidates cost one each. Private walks have a separate 8,192-candidate
  ceiling, shared across the request including word discovery and nested
  authorization, with a prepaid logical allowance independent of the hidden
  population. Physical traversal stops at that
  ceiling. Device-only work over its held state retains its separate physical
  allowance and queues on exhaustion; it cannot spend the server-equivalent
  mutation allowance or return a false authorization verdict.
  **Accepted residuals:** (a) a cap group containing an unreadable occupant refuses
  with generic `E_RULE` before cap constraint text, even for a readable new
  candidate. This can disclose “someone unreadable is here”, but no occupant
  identity, ordinal, count or values. The harness compares differing hidden
  occupants after that bit is fixed. Ignoring those occupants would make the
  cap bypassable. (b) A caller's row behind at least the walk bound of
  unreadable siblings is unreachable by paging in that direction. The page is
  empty with no cursor, identically in every world beyond the bound; neither
  the hidden stop key nor population-dependent charges are exposed.
  Successful assigned ordinals and actual authority changes
  above are intended disclosures, not additional hidden-refusal exceptions.
- **Prediction.** A predicted insert carries a **provisional** value
  (greater than every settled value the device holds for that parent); the
  settled write replaces it, and any page ordered by the column reorders
  when the settled image arrives. The device never publishes a provisional
  value as settled. Indexed selection observes pending ordinals even when a
  requested range is empty, including author-directed write-target lookups and
  `after insert` postconditions at literal sequence keys; dependent refusals
  queue, survive store reopen and settle from the server result. Implicit unique/cap checks
  observe the ordinal only on collision/refusal, so an unrelated later refusal
  remains terminal. Adding a missing `pending` marker charges the map copy and
  insertion before allocation; an already-present marker shares its map.
- **Ordering.** `last N by .ordinal` over a sequence column is a total
  order per parent, which `by .at` is not.
- **Diagnostics.** `E_SEQUENCE_SUPPLIED`; `E_SEQUENCE_PARENT` when the
  parent reference is missing or not a table reference.

## 3. A maintained view keyed by another table's row

```quarry
view unread: count messages by members m
  where .conversationId = m.conversationId and .ordinal > m.readUpTo
    and .senderId != m.principal and not .tombstone
```

- **Meaning.** One maintained value per `members` row: the number of
  `messages` rows satisfying the predicate against that row. Readable under
  the `members` row's read rule (the count is about the member, and
  discloses nothing the member could not count).
- **Maintenance on `T` events** (insert, update, delete, expiry of a
  `messages` row): the delta is applied to every `U` row whose predicate
  the event affects. For the shapes the predicate admits (an equality on a
  reference to `U`'s parent plus comparisons against `u`'s fields and `T`'s
  own fields), the affected `U` rows are found by the reference equality
  (the conversation's members), bounded by the parent's cap.
- **Maintenance on `U` field changes** (`m.readUpTo` moves): the delta is
  the count of `T` rows in the range the change uncovers or covers. When
  that range fits the writer's meter (an index range scan on
  `(conversationId, ordinal)`), it is applied in the writer's transaction.
  When it does not, the write commits the field change, the view's value
  for that row is marked **pending** (non-expiring counts read with
  `complete: false`; expiring counts certify their live basis as below),
  and a bounded background recount (self-chunking, as LLP 3000.013's
  streaming aggregates and delivery work) settles it. The writer is never
  refused for opening a large chat.
- **Disclosure and count basis.** A member reader must be authorized for the
  entire counted parent group. Admission conservatively proves this when the
  source is public, both rows use the same parent-only `exists` grant, or the
  member itself witnesses the source's `exists members[parent, viewer]` rule
  and its read rule is the corresponding owner equality. The latter requires
  a non-expiring member and an exact unique membership key. Other combinations
  refuse with `E_VIEW_KEY` at compilation, raw server schema admission and
  device open/adoption. In particular, independent member ownership plus source
  `.senderId = viewer`, `deny`, or an unrelated access grant is unsupported.
  A private `written by` member field may parameterize the count only when
  the member read rule requires that field's owner (an owner equality, including
  a required conjunct). Other audiences must declare the input `readable by
  audience`; raw schema admission enforces the same rule. This composes §1's
  field disclosure with the inherited row audience: a count cannot disclose
  another owner's private mark indirectly.
  **Recount work is selected only from an image the writer can read; a writer
  who cannot read the member row it is updating never triggers
  population-dependent work.** At the single member-write decision point in
  `row_view_member`, every non-system insert/update must have a readable new
  member image, including over a public source. Check that image first, then
  its destination source group's readability, before selecting any recount.
  Otherwise refuse with `E_VIEW_KEY`: make the member row readable to its
  writers before marking. An ordinary server mutation retains its caller; it
  grants no additional authority. Public sources have no exemption.
  This covers blind non-owner marks whose unchanged private parent would
  otherwise select between unequal public populations, as well as blind owner
  marks and moves under matching access grants. A deletion needs no recount.
  This is the interim audience limit, not support for secret recount traffic:
  the commit sequence and `/changes` are global. Filtering view puts would not
  hide the number of recount commits. No principal-specific log protocol is
  introduced here.

  For an admitted member-row reader, hidden rows outside its counted domain and
  born-expired rows cannot change that member's count, its writer's reserved
  meter, or its recount sequence through quiescence. Parent moves discard the
  previous count; an unfinished destination recount publishes zero/pending.
  A settled fallback is retained only in its original parent domain. Member
  writes that make a member readable discard the unreadable old image and
  recount from the readable new one. Unscoped private-view scans refuse with `E_VIEW_KEY`; use an audience
  predicate or a member key. Refresh presence does not depend on a hidden delta.

  Sources already expired at the commit clock are physically retired in that
  transaction before contribution maintenance. Formerly-live unswept sources
  are equally absent from the count basis. Marks, chunks and reads seek only
  the null and `until > now` ranges of the generated parent/expiry index;
  none walks the expired input range. Reads certify that live basis on §1's
  internal ledger with one fixed examined/step reservation, including pending
  reads. Writer certification uses the same reservation and live basis.
  Certification scans the current live basis identically for stored pending
  and settled values, including bases larger than the writer's 1,024-row bound.
  The historical pending bit never selects completeness or writer refusal.
  Expiring reads are certified immediately; their stored count is a private
  cache. Background work reconciles that cache in bounded durable chunks,
  drained without publishing redundant commits, sequence increments or log
  images. Non-expiring pending values retain their bounded public recount.
  The server's internal certification scan may traverse the whole live group;
  this is the existing settled-read policy, now also applied to pending reads.
  Snapshots and catch-up use the same certification. Devices recompute from
  covered live input; missing coverage stays pending.

  A stored count has an internal basis timestamp, written atomically with the
  count. Source-event deltas, including physical sweeps, test liveness at that
  timestamp, so an input excluded by a new basis cannot be subtracted again.
  Recount cursors follow the expiry index, and edits adjust only the counted
  prefix. Work records carry their basis time and earliest contributing expiry;
  if that expiry passes between chunks, restart from the current live ranges.
  Each completed prefix advances its basis time. Member changes cancel the old
  work and basis in the same transaction. Adoption rebuilds atomically when
  the member table, predicate dependencies, expiry field, or its type/default/
  recorded interpretation changes. A legacy absent field must not be evaluated
  under a new default against an old count basis.

  Pure existence witnesses read only member id/expiry index metadata under a
  fixed key reservation using `authorized_scratch`/`authorized_scan`; no member
  payload is fetched. Full count reads fetch the member on that internal ledger,
  require its read verdict, then charge the sealed authorized result. Declared
  decoder bounds reserve scratch before fetching, including for empty values;
  the actual authorized member is transient and its peak/cut survives release.
  This is §1's accounting law, shared with B1, not a separate meter policy.
  Witness metadata feeds the single evaluator and complete-rule expiry law
  in §2, including provisional read authorization; it never directly sets a
  response deadline.

  **Residual:** Global activity by other principals is observable through the
  shared sequence, `/changes`, watermarks and snapshot cursors. Hiding it
  requires changing the shared sequence/log contract.
- **Admitted predicate shape.** Exactly one equality between a `T`
  reference and a `U` reference to the same parent (the key), any
  comparisons between `T` fields and `u` fields, and `T`-only conditions.
  Anything else refuses with `E_VIEW_KEY` and a rewrite.
- **Prediction.** A device holding the `U` row and the covered `T` range
  predicts the value; otherwise it reads the settled value.
- **Diagnostics.** `E_VIEW_KEY`; a `check` line stating the key and the
  bound on the writer-side recount.

## 4. Verification

Each addition lands with: language tests (parse, bind, diagnostics with
rewrites, `explain_code`), engine tests on memory and SQLite (and Postgres
where the store is touched), device tests for prediction and projection
(no wire message to a non-owner carries a private value; a provisional
sequence never publishes as settled), a guide card, a JOURNAL entry, and
the wasm measurement with a ratchet reason if the budget moves. Two blind
reviews (Astra, Grok) per addition before landing.

## Non-claims

This spec does not define `through` (LLP 3000.014), engine-derived
delivery receipts (withdrawn from LLP 4000 to a future LLP), or any
residency change. It adds three forms to Snapback 4 that stand on their
own product merit whatever Snapback 5's outcome.
