## Summary

LLP 4000 judges Snapback 5 against a Snapback 4 that carries the same
additions, so that the only difference between the arms is derived
residency. This spec is those additions, landed in Snapback 4 as ordinary
language and engine work, each reviewed on its own. Three of them are here;
`through .ref` is LLP 3000.014 revision 2 and is not part of this baseline.

1. **`written by .col`** on a column: field-level write authority, with
   private projection by default and `readable by audience` to opt out.
2. **`sequence by <ref>`** on a column: an engine-assigned, dense,
   per-parent integer, assigned at commit, provisional under prediction.
3. **A maintained view keyed by another table's row:** `view name: count T
   by U u where <predicate over T's fields and u's fields>`, maintained per
   `U` row, with a bounded background recount when a `u` field the predicate
   reads changes by more than the meter allows in the writer's transaction.

Together they let Clique's read marks, unread counts and message ordering
leave the application's hand-written helpers without a per-message receipt
row. The receipt table itself stays (LLP 4000 §3.3).

## 1. `written by`

```quarry
table members:
  conversationId: conversations
  principal: principal
  readUpTo: int default 0 written by .principal
  read <- exists members[.conversationId, viewer]
  update (old, next) <- exists members[conversationId = old.conversationId, principal = viewer, role = 'admin']
                     and next.readUpTo = old.readUpTo
```

- **Authority.** The value of a `written by .p` column may be written only
  by the principal named in column `p` of the same row. An insert sets it
  to its declared default; a supplied value is refused with
  `E_FIELD_AUTHORITY` unless the inserter is that principal. A patch that
  touches the column is authorized for that column by that principal, and
  for every other field by the row's `update` rule. The owner may patch the
  column alone with no row `update` rule; the row's `update (old, next)`
  rule may still constrain the transition (monotonic marks), as above.
- **Projection.** By default the column is **private to its owner**: it
  never appears in a log image, a query row, a shape, a cursor or a write
  result delivered to any principal other than the owner. The owner sees
  it on every device. `readable by audience` on the column makes it an
  ordinary column for reads. The implementation must deliver the private
  value to the owner's devices through the owner's own partition, not by
  filtering the group image per reader, because group images are shared
  by audience.
- **Caller accounting law.** The caller-visible meter charges exactly two
  kinds of quantity, subject to the paging residual below: fixed reservations derived from declared bounds (column
  bounds, index arity, page size, and the rule's witness count), and the
  disclosed result after row-read and field authorization both succeed.
  Candidate decoding, rule evaluation, witness probes, and materialization
  of unreadable rows run on an internal ledger under that reservation; no
  actual charge from that ledger enters the caller's receipt or cut.
  `authorized_scan` is the shared B1/B2 boundary: admission precedes candidate
  access, and every return restores the caller's ledger, ceilings and cut
  policy. B1 adds transient declared decoder/witness scratch around this
  boundary for point reads, scan candidates and write-target resolution.
  Candidate materialization, expiry filtering, row authorization and private
  projection finish inside that scope; only surviving `AuthorizedRow` images
  can be charged afterward. `Disclosed` alone has no pricing authority.
  Rule witnesses export verdict/coverage and the complete-rule deadline
  defined in §2 (including simultaneous and correlated alternatives). Public, non-expiring tables with
  no private fields or recorded captures prove row authority before access and may use actual-size
  decoder admission for reads, fetches, lookups and writes, including a short
  value under a large declaration. Their patch copies price the sealed public
  image, without reserving the declaration's maximum payload. System maintenance owns its own ledger,
  and device physical authority work retains its separate uncertainty budget.
- **Observable noninterference.** Subject to the three residuals stated in
  §1–§3, private input changes must leave an
  unauthorized principal's results, refusal envelope, meter, changes table
  set, sync images/watermarks and maintenance sequence unchanged. Projection
  copies only disclosed fields and missing ordinary-field defaults; it never
  reinstates an omitted private default. Private fields cannot supply public
  derived values, including Following mappings and predicates under either
  spelling. Non-uniform server scans of a table with private fields require
  a readable audience scope in B1; B2's authorized scan supplies the shared
  page-reservation implementation for the combined baseline.
  Hidden delete and absent upsert field-authority refusals use the ordinary
  `NOT_FOUND` attempt boundary. Direct inserts and readable write targets
  keep their detailed errors. A named transition cannot test another owner's
  private value to decide an ordinary patch: require the field's owner, except
  for value-independent comparisons of an untouched field with itself. A patch
  retaining an unreadable row's fields or a non-owned private payload charges
  declared column copy bounds, never hidden lengths. Ordered self-comparisons of nullable private fields
  are value-dependent; equality/inequality and required numeric
  self-comparisons can be folded before evaluating omitted device values.
  Decoder reservations cover UTF-8/escaping, map and array growth, recursive
  list/JSON bounds, bounded asset facts and the 144-byte identity admission
  bound. SQLite lends its stored JSON during decode. A large declaration can
  exceed the heap even for an empty value; both worlds then refuse identically.
  No runtime ceiling is raised. The raw retained-row `Value::heap_bytes` API
  and `Context`-minted system token are removed. The system projection token has a private
  runner-only constructor; PostgreSQL raw cache pricing charges an opaque
  internal ledger that exports no price. Raw scalar and serialized-storage
  prices are opaque `InternalPrice` values, chargeable only to an opaque
  `InternalMeter` handle lent by `InternalLedger`; retaining a caller's `Meter`
  inside that closure cannot redirect the charge. The handle exposes neither
  `Deref` nor counters, and consuming the ledger cannot return its meter.
  Metered adapters require the handle and authorization scope too. Exact retained-image
  pricing requires sealed row-read evidence, and expression pricing keeps its
  private evaluator capability. Supplied write values carry sealed input
  provenance through defaults, key completion and immutable-field removal;
  retained old fields use declared copy bounds. Authorized result keys and
  evaluated cursor/input keys retain their separate evidence. There is no
  writer helper that accepts a raw old value and returns a caller price.
  Compile-fail tests cover raw materialization, fabricated system/row authority,
  unproven field projection, raw owned scalar charging with and without a scope,
  and an unscoped metered storage call.
  Owner delivery prepays one step and the rule's static witness count per
  declared private-field slot and row image; exact recipient checks use an
  internal ledger. Mutation receipts count private-table events by table and
  row, independent of recipient fanout. The generated paired worlds cross
  unreadable witness tables with private fields, compound rules, hidden
  presence, repeated operations through the default probe ceiling, expiry,
  and different observers, alongside the existing type/population cases.
  Wildcard shapes select private fields through the same optional access as
  explicit selection: a non-owner receives null. Successful delete, group/sort,
  private-token searches and equal-length escaping variants also have paired
  controls. Round 7 crosses elapsed time (at/past expiry), owner-visible
  private payload, page/wildcard/count/sum scans, successful hidden witnesses
  with different deadlines, and expiring deletes with the shape/delete
  templates. Devices also expire previously acquired owner payload offline
  and after reopen. This is bounded regression evidence, not universal
  noninterference proof.
- **Residual — paging examined counts.** Some range-page paths charge an
  examined candidate before rejecting it. Within the physical walk bound,
  expired or unreadable candidates can therefore change examined counts and
  meter cuts. This is not a claim of full page-meter equality.
- **Prediction.** A write to an own `written by` column is a point write to
  a held row and predicts under the existing rules.
- **Diagnostics.** `E_FIELD_AUTHORITY` (a non-owner supplied or patched
  the column), with a rewrite naming the owner column; a `check` line per
  such column stating its visibility.

## 2. `sequence by`

```quarry
table messages:
  conversationId: conversations
  ordinal: sequence by conversationId
table members:
  conversationId: conversations
  joinedAt: sequence by conversationId
```

- **Assignment.** One counter per parent row (here, per `conversations`
  row), shared by every column in any table that declares `sequence by`
  that parent. The engine assigns the next value at commit, dense and
  monotonic per parent, inside the write's transaction, in every store
  (memory, SQLite, Postgres) with the same transactional discipline as cap
  occupancy counts. A client-supplied value is refused with
  `E_SEQUENCE_SUPPLIED`. The column is immutable by construction.
- **Disclosure.** Sequence insertion requires read authority established from
  the supplied/defaulted image independently of the allocated ordinal. The
  generated paired-world harness compares refusals (including text), every
  logical meter field, expiry deadlines (`next_expiry` / `nextExpiry`), pages/cursors, changes, stream/snapshot images and
  watermarks, and device prediction, admission, reopened outboxes and settlement.
  Its guarantees depend on the principal's authority:
  - A **blind principal** with neither insert nor read authority is refused
    before allocation-independent insert denial can consult a read witness.
    Varying an unreadable sibling, witness or counter history changes none of
    those observations.
  - An **insert-only principal** whose candidate is unreadable receives generic
    `E_RULE` (upsert insert arm: `NOT_FOUND`) before counter allocation,
    uniqueness or cap checks. Ordinal-dependent read rules cannot authorize an
    allocation by evaluating the missing ordinal as null. Deferred insert
    authorization reserves its static probe/counter work and actual image copy
    before the read guard; denied direct inserts restore their meter. Refusal
    equality includes the default ceilings after 512 scratch writes × 32 indexes.
  - A **self-readable principal**, including the writer, may see the ordinal
    assigned to a successful insertion; that value intentionally reflects the
    shared counter. An upsert addressed by a sequence key returns `NOT_FOUND`
    with the same restored meter for absent and unreadable refused targets,
    even when its candidate would be readable. An owned target retains its
    ordinary update-authority diagnostic. A directly supplied ordinal in an
    insert or patch is `E_SEQUENCE_SUPPLIED` before lookup.
  - A **witness-dependent principal** cannot distinguish hidden grants through
    an independently denied insert or a denied deferred allocation. Grant
    presence that actually establishes both insert and read authority may
    change refusal to success: authorization itself is an intended observable.
    An unheld witness remains device uncertainty; the durable outbox leaves
    the decision to the server.
  Every effect reserves its complete static rule-probe allowance before
  evaluating any witness, including short-circuited compound write rules.
  Sequence preflight reserves only checks still pending, without reserving an
  independently authorized insert rule a second time.
  Every authorization-dependent lookup/scan uses one `authorized_scan` helper.
  Authorization lookups and rule probes require a borrowed token minted only
  inside the storage guards; `Runner` itself is not a rule probe. Its store
  facade holds the raw transaction privately and implements neither `Rows` nor
  `Deref`; get/lookup/scan/count/counter reads require the token. Ordinary
  metered operations use a token scope that preserves their meter unchanged;
  private authorization uses the prepaid, restoring scope.
  Repeated unchanged point lookups share one request-local decoded-candidate
  cache, invalidated by every row write. This avoids making an otherwise
  redundant hidden witness select exhaustion at the logical probe boundary;
  actual storage fetches still share the same physical allowance and every
  logical read still prepays its complete rule.
  It charges the declared logical allowance before fetching an occupant, marks
  that paid meter, runs private authorization work, and restores the paid mark
  on success or refusal. The caller's ceiling can cut only the reservation,
  never work selected by a hidden row. Cap groups reserve their declared N
  candidates and read-rule probes; complete unique keys reserve one rule tree;
  a predicted uniform page reserves the server's full rule tree even when
  delivered evidence avoids evaluating it locally;
  counter reads reserve one index entry.
  **Physical allowance:** one request's authorization work shares a single
  8,192-row physical allowance through `authorized_scan`, including nested
  witness alternatives, expired-witness walks and maintained-source walks,
  and exhaustion fails closed with the same generic `E_RULE` without
  hidden-dependent logical charges. Every nested raw lookup, expired candidate
  and witness alternative draws from that allowance on server and device;
  restoring the logical meter never restores physical work. Enumeration must
  finish within the bound before returning a verdict, even after a permanent
  witness. Compound branch visits depend only on rule structure and verdicts,
  never on witness lifetimes. Complete-rule timelines visit remaining witness
  alternatives in both the finite and permanent worlds; only a decisive
  invariant result (such as a field comparison or an absent witness) can skip
  them. An absent witness stays absent as rows expire; positive probes, including
  `created` with extra predicates, cannot establish invariance from their lifetime.
  Timeline combination uses no further storage reads. A full shortened batch
  is exhaustion, not proof of end-of-data.
  Maintained sources with a selected expiry index obtain their last lifetime
  from two key-only seeks (null and latest future expiry), not decoded payloads.
  Both seeks spend the same allowance. Rule evaluation reserves its static
  probe count once; executed `exists` leaves add no caller charges.
  The store facade owns this allowance, so neither a nested authorization
  scope nor a later check in the same request replenishes it; a cap update
  spends the same allowance as an insert. The budget counts fetched
  authorization candidates; public data reads keep their ordinary meter,
  system execution has no viewer authorization, and the non-expiring public
  cap's scalar count retains its declared cap bound without fetching rows.
  Main's transactional physical occupancy is also retained as an upper bound:
  below a non-private cap it proves room without a scan; when saturated the
  bounded live scan decides. Private sequence caps still authorize occupants.
  This supersedes LLP 3000.013 §11.1's conservative unswept-cap semantics
  while keeping its counter custody, adoption and device deferral.
  A single unchanged witness answer may be reused while still paying each
  declared logical probe; every row write invalidates it, and prediction's
  separately metered authority work does not use that cache.
  **Expiry:** `next_expiry` is the earliest instant at which removing every
  row expiring at that instant changes the complete bound rule's current
  verdict, considering all witness alternatives within the rule's allowance.
  The shared rule evaluator combines complete expiry timelines, including
  simultaneous and correlated branches: a later matching witness keeps an
  existential true, stable ownership needs no witness deadline, and `A or
  not A` never changes verdict. Failed predicates and denied rows publish
  no expiry, and independently returned row lifetimes still apply.
  The server point read, ordinal page, provisional evaluator and release
  `nextExpiry` all use this definition. Point reads reserve one examined unit
  and the rule's full probe tree. Non-uniform pages reserve one examined unit
  and `(page size + lookahead) × rule probes` before candidate discovery,
  including compound rules and ordinary integer indexes. Only readable
  candidates reach page payload charges, filtering, lookahead or cursors.
  Word discovery likewise prepays its 33-word allowance and admits only words
  with an authorized candidate; hidden-only words cannot consume that bound.
  A readable row consumes the page's initial examined unit; later readable
  candidates cost one each. Private walks have a separate 8,192-candidate
  ceiling, shared across the request including word discovery and nested
  authorization, with a prepaid logical allowance independent of the hidden
  population. Physical traversal stops at that
  ceiling. Device-only work over its held state retains its separate physical
  allowance and queues on exhaustion; it cannot spend the server-equivalent
  mutation allowance or return a false authorization verdict.
  **With 0.4.2 (LLP 3000.013 §13, merged 2026-09-25):** every read 0.4.2 added
  is under this law — a read-through child's parent lookup, capture and
  physical-children probes, the parent verdict, event-slot witnesses and live
  recounts all draw from the same request-owned allowance and price only
  disclosed results. Deadlines are carried by 0.4.2's scoped `Expiry`
  (LLP 3000.014 §5): the complete-rule timeline isolates each witness leaf
  in the current frame, a raw write check owns no deadline, and an authorized
  row carries its deadline as pending until the page or point read emits it.
  Admission still precedes candidate access; on a device a point read that
  cannot examine a card under a sync horizon is withheld as unknown rather
  than answering a hole (LLP 3000.016 §2.2). The non-uniform page reservation
  above also governs pages over inherited aggregates, where 0.4.2's tests had
  asserted per-row probe charges.
  **Residual — cap occupancy:** a cap group containing an unreadable occupant refuses
  with generic `E_RULE` before cap constraint text, even for a readable new
  candidate. This can disclose “someone unreadable is here”, but no occupant
  identity, ordinal, count or values. The harness compares differing hidden
  occupants after that bit is fixed. Ignoring those occupants would make the
  cap bypassable.
  A caller's row behind at least the walk bound of unreadable siblings is
  unreachable by paging in that direction. Exhaustion between siblings or
  inside their nested witnesses returns the same empty page without a cursor;
  mutations keep the same cause-neutral E_RULE with the operation's table and
  effect. Direct denied sequence inserts also restore their logical meter on
  physical exhaustion. Successful assigned ordinals and actual authority
  changes above are intended disclosures.
- **Prediction.** A predicted insert carries a **provisional** value
  (greater than every settled value the device holds for that parent); the
  settled write replaces it, and any page ordered by the column reorders
  when the settled image arrives. The device never publishes a provisional
  value as settled. Indexed selection observes pending ordinals even when a
  requested range is empty, including author-directed write-target lookups and
  `after insert` postconditions at literal sequence keys; dependent refusals
  queue, survive store reopen and settle from the server result. Implicit unique/cap checks
  observe the ordinal only on collision/refusal, so an unrelated later refusal
  remains terminal. Adding a missing `pending` marker charges the map copy and
  insertion before allocation; an already-present marker shares its map.
- **Ordering.** `last N by .ordinal` over a sequence column is a total
  order per parent, which `by .at` is not.
- **Diagnostics.** `E_SEQUENCE_SUPPLIED`; `E_SEQUENCE_PARENT` when the
  parent reference is missing or not a table reference.

The authoring path for expiring-message receipt gaps is `guide sequences`:
`ordinal: sequence by conversationId` with `unique conversationId, ordinal`,
then a never-predicting receipt mutation that reads the first live blocker
between the member's delivered prefix and a validated received run before
deleting runs or writing. LLP 3000.025 §3 admits a uniform plain expiry scan
only in the initial wholly read-only source statements; a write or emit
anywhere in an enclosing statement ends that phase. Unswept rows still spend
the examined ceiling and can refuse atomically with E_BOUND. For shapes that
remain refused, bounded unique probes are the fallback. The compiler preserves
the prediction/source-boundary repair first, then offers that helper using
the refused scan's ordering coordinate and a
covering unique key with the pinned required reference, in either key order;
no covering key means plain refusal advice. A uniform parent scope proves one
read verdict, not readability. The helper's prefix justifies receipt advancement
only after the caller's authority check (membership or a readable-message anchor).
A dominating authority check is not inferred from rule syntax. Both forms stop
at a live blocker and retain disjoint runs; the probe fallback saves partial
prefix progress at its bound. Repeating
an already-recorded run must reach the helper again rather than returning early;
only a run already within the delivered prefix can take that early return. This replaces manual allocation,
not the delivery protocol. A row-keyed count answers the separate badge question
and is not proof that a message was received. The compiled guide compares the
manual allocator and the engine sequence; the runtime tests cover expired holes,
live blockers, the shared membership position, and bounded resumption. The other
calibration-23 data-modeling charge, Following over populated sources, now uses
[LLP 3000.026 §4](./3000.026-following-over-a-populated-store.rfc.md#4-atomic-launch-adoption)'s
atomic launch contract. Its read-only `check` shares runtime preflight: dev gets
a located launch note with copies and lock time, deploy needs
`--allow-feed-adoption`, and exceeding 5,000,000 copies refuses with the estimate.
This does not alter the receipt-gap recipe or mutation-page admission above.

### 2.1 First membership and developer refusal detail

Lane MP, commissioned 2026-09-28, reproduces calibration 24's first member
insert: its insert rule accepts `created conversations[.conversation]`, but
its read rule requires an already existing membership. It therefore fails
before allocating an ordinal. `check` now reports `N_SEQUENCE_READ` at the
sequence column with this exact cause and the manual receipt allocator.
This is a note, so existing programs retain their compilation and behavior.
Round 1 limits the categorical note to a self-table witness whose selected
index maps the sequence-parent column to that same row's parent term.
Round 2 also accepts a residual equality on that exact parent column and term,
including a literal-key witness without `viewer`; it requires no existing
member to belong to the viewer, only to the same parent group. Merely
finding `.parent` elsewhere in the key proves nothing: `access = .parent`
can find a witness in another parent group and admit its first insertion.
Unproved forms receive no categorical note. The rewrite names the declared
sequence column and its parent; it does not invent a message table or ordinal
column in a members-only schema. The guide holds the shared-counter recipe.

A provably fresh counter contains no hidden history, so allocating its first
ordinal would disclose nothing. Neither `created parent` nor an empty live
child group proves that fact in the current model. An ordinary reference
(including a sequence parent) is not a lifetime-enforcing foreign key. The
counter is shared across participating tables, survives deleted children and
parent identities, and can have history before this parent insertion. Even
an empty physical group may therefore reveal past allocations. Testing the
hidden counter for zero and allowing only that case would itself be a probe.
This lane does not add such an exception or reset a counter. Preserve the
membership audience with the guide's manual parent field, initialized on the
new parent and updated atomically by every sender; alternatively an explicitly
owner-only membership model may use its own read authority. That alternative
changes the roster audience and is not an automatic repair.

The exact refusing clause is developer evidence, separate from `Refusal`.
A host must opt in to a native-only, per-execution in-memory collector. The
collector records schema clause, table, execution site and generation, never
arguments, row images, row keys, credentials or hidden counts. It does not
perform reads, reevaluate rules, change admission, consume/refund meters, or
change receipt serialization. Authorization-budget exhaustion records that
cause, not a guessed false rule. The recorded phase is the authorization actually
executing: capture exhaustion maps to the child's `read through` declaration,
not its unevaluated insert rule. Query readers retain their source map together
with the checked-out engine generation across adoption.

Only `snapback4 dev` opts in. After releasing the engine lock and sending the
response, the host hands each response record to a bounded nonblocking writer queue.
The shared JSON response layer covers every refusal envelope, including asset
authorization refusals (HTTP 404, E_ASSET_UNKNOWN), receipt replays and paths
with no collector. Every record carries operation, code, an instance-scoped
request ID or job ID, wall-clock Unix time in milliseconds, and a shared
sequence. Without an evaluated cause it says `cause not instrumented`; it
never leaves a previous request's cause standing for this refusal. A filtered
read cannot supply the cause of a later terminal refusal in the same request.

**Supervisor scope ruling, round 3 (2026-09-28):** `why recent` records
requests or job steps that the platform refused. Visibility filtering in sync
and reads is successful product behavior, not a refusal, and is not recorded;
recording every filtered sync would flood this bounded stream. Its scope text
names refusals of mutations, queries, asset requests and jobs, and directs
visibility questions to `why TABLE` (read rules and sync residency) and
`guide rules`. Operation, request/job identity and time distinguish older
evidence from a later successful sync/read. This supersedes round 2's
FILTERED_READ records. The read collector still observes evaluated verdicts
and allowance exhaustion; successful responses with a nonterminal filtering
cause do not enter the stream. **DX round 0 decision (2026-09-29, calibration #26):** ordinary empty answers
are not refusals. Superseding the round-3 fallback, unknown empty/null query
answers (including fields in composed results) are neither printed nor recorded
by default. They do not construct records, advance the evidence watermark, enqueue
work, format console lines or rewrite the refusal store. `dev --trace-empty`
opts into EMPTY_READ records in `why recent` only, never console notices. The
stream identity records `traceEmpty`; the guide/why EMPTY_READ card supplies
rule, coverage and horizon investigation commands and states that this evidence
does not prove denial. No caller bytes change. Real refusal envelopes, including
an application-authored EMPTY_READ code, keep their existing evidence path.
Successful visibility filtering remains excluded even with the opt-in.

A parked job is a terminal refusal even though no HTTP refusal envelope is
returned. Dev maintenance submits the job name, job ID, saved refusal code,
time and fallback cause through the same sequence, watermark and bounded
writer as request refusals, after releasing the engine guard. No new job
collector or reevaluation is needed; the saved job error does not provide an

## 3. A maintained view keyed by another table's row

```quarry
view unread: count messages by members m
  where .conversationId = m.conversationId and .ordinal > m.readUpTo
    and .senderId != m.principal and not .tombstone
```

- **Meaning.** One maintained value per `members` row: the number of
  `messages` rows satisfying the predicate against that row. Readable under
  the `members` row's read rule (the count is about the member, and
  discloses nothing the member could not count).
- **Maintenance on `T` events** (insert, update, delete, expiry of a
  `messages` row): the delta is applied to every `U` row whose predicate
  the event affects. For the shapes the predicate admits (an equality on a
  reference to `U`'s parent plus comparisons against `u`'s fields and `T`'s
  own fields), the affected `U` rows are found by the reference equality
  (the conversation's members), bounded by the parent's cap.
- **Maintenance on `U` field changes** (`m.readUpTo` moves): the delta is
  the count of `T` rows in the range the change uncovers or covers. When
  that range fits the writer's meter (an index range scan on
  `(conversationId, ordinal)`), it is applied in the writer's transaction.
  When it does not, the write commits the field change, the view's value
  for that row has private **pending** work (non-expiring counts read with
  `complete: false`; expiring counts certify their live basis as below),
  and a bounded background recount (self-chunking, as LLP 3000.013's
  streaming aggregates and delivery work) settles it. The writer is never
  refused for opening a large chat.
- **Disclosure and count basis.** A member reader must be authorized for the
  entire counted parent group. Admission conservatively proves this when the
  source is public, both rows use the same parent-only `exists` grant, or the
  member itself witnesses the source's `exists members[parent, viewer]` rule
  and its read rule is the corresponding owner equality. The latter requires
  a non-expiring member and an exact unique membership key. Other combinations
  refuse with `E_VIEW_KEY` at compilation, raw server schema admission and
  device open/adoption. In particular, independent member ownership plus source
  `.senderId = viewer`, `deny`, or an unrelated access grant is unsupported.
  A private `written by` member field may parameterize the count only when
  the member read rule requires that field's owner (an owner equality, including
  a required conjunct). Other audiences must declare the input `readable by
  audience`; raw schema admission enforces the same rule. This composes §1's
  field disclosure with the inherited row audience: a count cannot disclose
  another owner's private mark indirectly.
  **Recount work is selected only from an image the writer can read; a writer
  who cannot read the member row it is updating never triggers
  population-dependent work.** At the single member-write decision point in
  `row_view_member`, every non-system insert/update must have a readable new
  member image, including over a public source. Check that image first, then
  its destination source group's readability, before selecting any recount.
  Otherwise refuse with `E_VIEW_KEY`: make the member row readable to its
  writers before marking. An ordinary server mutation retains its caller; it
  grants no additional authority. Public sources have no exemption.
  This covers blind non-owner marks whose unchanged private parent would
  otherwise select between unequal public populations, as well as blind owner
  marks and moves under matching access grants. A deletion needs no recount.
  This is the interim audience limit, not support for secret recount traffic:
  the commit sequence and `/changes` are global. Filtering view puts would not
  hide the number of recount commits. No principal-specific log protocol is
  introduced here.

  For an admitted member-row reader, hidden rows outside its counted domain and
  born-expired rows cannot change that member's count, its writer's reserved
  meter, or its recount sequence through quiescence. Parent moves discard the
  previous count; an unfinished destination has no numerical cache and reads zero/pending.
  A settled fallback is retained only in its original parent domain. Member
  writes that make a member readable discard the unreadable old image and
  recount from the readable new one. Unscoped private-view scans refuse with `E_VIEW_KEY`; use an audience
  predicate or a member key. Refresh presence does not depend on a hidden delta.

  Sources already expired at the commit clock are physically retired in that
  transaction before contribution maintenance. Formerly-live unswept sources
  are equally absent from the count basis. The ordinary walk for marks, chunks
  and reads seeks only the null and `until > now` ranges of the generated
  parent/expiry index when the source can expire; otherwise it uses the parent
  index. The bounded predicate-index alternative below may inspect
  expired candidates, but never counts them. Reads certify that live basis on §1's
  internal ledger with one fixed examined/step reservation, including pending
  reads. Writer certification uses the same reservation and live basis.
  Certification proves the current live basis for stored pending and settled
  values, including bases larger than the writer's 1,024-row bound. The incremental
  procedure below may reuse a settled basis with unchanged versioned inputs;
  pending values retain the full walk.
  The historical pending bit never selects completeness or writer refusal.
  Expiring reads are certified immediately; their stored count is a private
  cache. Background work reconciles that cache in bounded durable chunks,
  returned one chunk at a time as private progress, counted against the
  maintenance allowance with the engine lock released between chunks, without
  publishing redundant commits, sequence increments or log images. Only counts
  whose source and member both cannot expire retain bounded public recounts.
  The server's internal certification scan may traverse the whole live group;
  this is the existing settled-read policy, now also applied to pending reads.
  Snapshots and catch-up use the same certification. Devices recompute from
  covered live input; missing coverage stays pending. If local writer
  certification cannot finish, the mutation queues without a predicted result
  and the server settles it; an already settled cache does not make that
  device limit a structural refusal.

  A stored count has an internal basis timestamp, written atomically with the
  count. For non-expiring members, source-event deltas, including physical sweeps,
  test liveness at that timestamp, so an input excluded by a new basis cannot be
  subtracted again. For expiring members, source events invalidate the count and
  restart work: the previous basis or prefix can have missed arbitrary deltas.
  Recount cursors follow the source expiry index when present, otherwise the
  parent index; eligible incremental edits adjust only the counted prefix.
  Work records carry their basis time and earliest contributing expiry;
  if that expiry passes or the clock moves below the saved work time between
  chunks, discard the prefix and restart from the current live ranges.
  Each completed prefix advances its basis time. Member changes cancel the old
  work and basis in the same transaction. Adoption rebuilds atomically, with
  query and sync readers using the previous committed generation while the
  writer builds (LLP 3000.019 §3.6), when
  the member table, predicate dependencies, expiry field, or its type/default/
  recorded interpretation changes. A legacy absent field must not be evaluated
  under a new default against an old count basis.

  Pure existence witnesses read only member id/expiry index metadata under a
  fixed key reservation using `authorized_scratch`/`authorized_scan`; no member
  payload is fetched. Full count reads fetch the member on that internal ledger,
  require its read verdict, then charge the sealed authorized result. Declared
  decoder bounds reserve scratch before fetching, including for empty values;
  the actual authorized member is transient and its peak/cut survives release.
  This is §1's accounting law, shared with B1, not a separate meter policy.
  Witness metadata feeds the single evaluator and complete-rule expiry law
  in §2, including provisional read authorization; it never directly sets a
  response deadline.

  With read-through tables, every lifetime above is the **effective inherited
  deadline** (LLP 3000.014 §5), not just an authored `expire` column. Member
  lifetime/recipient indexes and existence witnesses, source live-range
  indexes, count dispatch, recount cursors and basis subtraction all use that
  same classification. A member's inherited deadline participates in the
  complete-rule timeline even when the witness never fetches its payload.

  **Residual:** Global activity by other principals is observable through the
  shared sequence, `/changes`, watermarks and snapshot cursors. Hiding it
  requires changing the shared sequence/log contract.
- **Admitted predicate shape.** Exactly one equality between a `T`
  reference and a `U` reference to the same parent (the key), any
  comparisons between `T` fields and `u` fields, and `T`-only conditions.
  Anything else refuses with `E_VIEW_KEY` and a rewrite.
- **Prediction.** A device holding the `U` row and the covered `T` range
  predicts within its local allowance. A missing or oversized live basis queues
  a count-dependent mutation without a predicted result. Only non-expiring
  counts retain a settled fallback without source coverage; expiring counts
  remain pending until live input can be certified.
- **Diagnostics.** `E_VIEW_KEY`; a `check` line stating the key and the
  bound on the writer-side recount.

For a receipt near the head, certification may first probe a necessary
indexed predicate range after authorizing the member and its source group.
At most 65 stored keys decide whether the range contains at most 64 rows.
When the public schema/budget leaves insufficient room for that bounded
probe, use the ordinary bounded recount without probing first.
An empty range certifies zero; a small range crosses the same authorized
candidate boundary and evaluates expiry and the full predicate. A larger
range retains the shared live-expiry walk. Probes, candidate decoding and
predicate evaluation consume the internal ledger; the public reservation
does not vary with private counts. An abandoned probe's examined work is
deducted from the fallback recount allowance, retaining publication headroom;
if certification cannot fit, the member write commits with a pending recount.
This bounded alternative prevents a
one-position unread suffix from walking the entire message history without
introducing an unbounded walk over expired storage (Lane RG, 2026-09-28).

Cold acquisition bypasses the optional small-range probe and shares the live
basis walk across each admitted member group. Its sealed storage boundary may
fetch 32 candidates after reserving 32 declared decoder bounds, both result
vectors and rule scratch. The group selects and reserves that page against the
saved finite caller heap (including bytes already occupied), before entering
the prepaid certification scope. Nested certification uses the same saved
caller allowance, and releases its reservation on success or failure. If the
page does not fit, it reserves the original one-candidate amount instead:
`decode_reservation + rule_scratch`, including private witness decoding;
if even that cannot fit, it refuses before storage access. Batching must not
reject a declaration that fits the original procedure. The regression observes
the actual requested scan limit and allocations for 256 KiB payloads, including
nearly spent and nested scopes; a restored post-call heap peak alone cannot
prove admission (HV rounds 2–3). A real SQLite witness with `exists members[...]`
on a non-uniform table, an 80,000-byte witness and 256 KiB source payload also
checks actual allocation. A caller missing any of the single-candidate
reservation must refuse before any scan or lookup, including in nested prepaid
scopes. The earlier decoder-only fallback under-reserved that private witness.
Every candidate still crosses the same expiry, row-rule and field-disclosure
checks; only the authorized projection is priced as a result. It uses the same
read transaction, pinned clock and internal certification ledger. This removes
repeated one-row scan planning, not certification, authority or expired-row checks
(HV, 2026-09-29).

**Busy-group live propagation (BG round 0, 2026-10-02).** Stream delivery uses that same

**Incremental certification (BG round 1, 2026-10-02).** A completed expiring
row-keyed count's private `$basis` record now includes its earliest contributing
deadline and a digest of the maintain declaration plus source/member table
semantics: predicate, defaults, effective expiry, rules, audience and field
disclosure. The digest also carries an implementation version tag; changes to
certificate validity semantics must advance that tag. Count and evidence commit together. The existing writer delta
certifies only the changed source against each bounded recipient predicate;
it lowers the deadline for a new contributor. Removing or changing the earliest
source may refresh a conservative minimum through the parent/expiry index.
This minimum may include non-contributors, so it is never later than the true
contributing deadline. No expiry decision waits for the physical sweep.

Delivery first authorizes the current member and the complete source group,
exactly as before. It then reads the **current transactional** count and basis,
never the count in a historical log image. For a non-expiring member table, a
settled basis with matching version, a non-future basis timestamp and no due
deadline requires no source walk. Expiring member tables retain the live walk.
Scalar server reads use the same evidence. Pending, absent, legacy, differently
versioned or due evidence takes the existing authorized full live walk (including
the optional bounded predicate probe). Cold acquisition retains its shared full
walk. Restart needs no in-memory cache: the private evidence is durable. A
source/member or private-evidence schema change rebuilds the count and basis
in the adoption transaction. New evidence fields are optional during legacy
row validation; missing evidence never certifies a read. No mismatched digest
is used, including in a store opened without that rebuild.

Authority is factored out of the retained numerical proof. No viewer verdict or
witness-row result is persisted: every delivery proves member and group authority
in its own transaction at its pinned clock, including the complete-rule witness
deadline. For a uniform source rule this freshly proves the verdict for every
source in the domain. Changes to grant rows therefore re-certify authority
immediately without repeating source predicates. Row-dependent private source
fields, recorded source or member fields, read-through sources, aggregate sources and non-uniform
source rules keep the full path: a group verdict cannot certify their per-row
disclosure. The stored digest versions the authority **definitions**; the fresh
transaction owns the authority **facts**. This avoids an unsound global table
revision that would both miss transitive facts and invalidate every count when
an unrelated receipt mark changes.

Private member predicate fields already require an owner-only member read rule
at schema admission (including raw schemas), so every admitted reader sees that
input. Recorded member fields are omitted by the query projection; reuse refuses
them conservatively and preserves the full recount over the disclosed member.

Both paths retain the same fixed public examined/step reservation. Private
count/basis decoder scratch is admitted against the saved finite caller before
access, reusing (not adding to) the source-walk scratch lifetime. If its scratch
does not fit, certification uses the original walk. Nested authorization keeps
its physical allowance. No meter, heap ceiling, wire contract, device prediction
policy or retained-answer lifetime changes. The 10k/100k work regression measures
source certifications and public work, and the seeded state-machine test compares
against both an independent model and the full authorized recount after each step.


**Clock rollback and admission (BG round 2, 2026-10-02).** Numerical reuse is
restricted to **non-expiring member tables**, including effective inherited
expiry in that classification. Source maintenance visits only live recipients;
an expiring member can miss inserts, edits, moves, deletes or sweeps while absent,

This declaration-only rule avoids scanning an unbounded expired-member backlog or
adding a store clock ledger. Non-expiring server members receive every source delta;
a failed transaction retains neither the delta nor its evidence. Device-only skips
cannot produce server certificates. Fresh grant authority still owns witness expiry.

A field selection is checked against the receiver's static type and an explicit
returned-data position. A maintained row retains its nominal table type through
object fields, list elements, projections, aliases, helper results, `first`,

maintenance-bearing input: project ordinary fields before inspecting it. Selecting an ordinary wrapper

covers comparisons, set membership, distinct keys/JSON encoding, merge ordering,
conditions, read keys, write/effect payloads and non-query results. A null equality
or inequality is a non-inspecting presence test; ordering against null is refused.

field first. New builtins default to inspecting until explicitly allowed, and a
test obtains the enum's complete variant census from its derived deserializer,
requiring a specimen and explicit inspecting/non-inspecting decision for every
variant. No flat provenance or scalar taint is reintroduced. This policy changes admission only, not status
reconstruction or count certification. Native engine activation/adoption and Memory/SQLite device
opening/adoption enforce it; web retains its server-admitted-backend boundary.

The class consists of public `recountPending` and prediction `pending`, plus
private `$basis`/`$recount` state: `id`, `cursor`, `total`, `parked`, `at`,
`deadline`, `version`. Private rows cannot be read at all. Private-column names
on a view and all other undeclared names (including `$private`) refuse even in
data position. This is nominal typing, not a global name blacklist: ordinary
object fields and declared copied member columns such as `total` remain ordinary
values. Quarry cannot spell `$private` as a dotted identifier; its string sort
key and raw IR field spellings receive `E_VIEW_KEY`.

Conservative limits: dynamic JSON/unknown receivers, heterogeneous type joins
and recursively growing raw types widened after 16 structural levels cannot
prove a receiver type; their field selection refuses, including output position.
Helper blocks, intermediate status projections and ordered view projections
containing maintenance selections also refuse. Move the status selection to the
final query shape, or return the row itself. This deliberately does not infer
arbitrary scalar flows as returned data. Indexes over `value` remain independently
refused because a stored ordering cannot certify a live count.
The generated property enumerates every admitted view column for read and insert
rules against independent model facts; the admission matrix separately covers
maintenance and private fields across all four effects, delivery and programs.
Absent/legacy caches cannot supply a value predicate before private settlement.
The CLI cost certificate uses the same joint source/member lifetime dispatch and
classifies only `value` predicates as count probes, never pure existence.

**Composed count-rule deadlines (BG round 5).** A count equality can become true
when sources expire, then become false at a later count or member transition.
The shared witness path certifies at each future dependency boundary within the
same read transaction, retaining the original clock on success or failure and
sharing the existing physical authorization allowance. Scratch for transitions
is reserved before allocation. Conservative basis deadlines select rechecks,
not truth transitions. Only actual predicate changes enter the complete rule
timeline, which composes negation, alternatives and correlations before choosing
`nextExpiry`. Ordinary expiring aggregate value rules remain refused; row-keyed
value predicates now use this certified path, including through links and HTTP.
A complete future proof that cannot fit fails closed under existing allowances.
Every evaluated row-view read reserves the member lookup plus either live
certification or the durable private-work key lookup; the latter costs one
examined unit even when there is no pending work. Page/point receipt regressions
check that the certificate covers this cost on durable and expiring members.

The device scan's continuation comes from the stored index position, independent
of an authorized or rejected row payload. It checks a capped read immediately
after the candidate boundary, before evaluating fields. A rule-probe exhaustion
therefore returns an incomplete meter cut, including the durable-source /
expiring-member branch, never `E_TYPE` from dereferencing a rejected `Null`.
Memory and SQLite device properties cover prediction metadata, exact deadlines,
clock expiry/rollback and 0–32 remaining probes, including the three/four-probe
review boundary. The wasm wire regression separately checks full reconstructed
rows, predicted identities and withdrawal for durable messages / expiring members.

The valid `count-basis-v2` proof is unchanged. Its required `at` must actually be
an integer no later than the reader's clock; a missing/malformed timestamp is
missing evidence, never implicit zero. The version and deadline must also parse,
and the current count must contain a literal false pending bit and a nonnegative
integer value in the supported range. Corrupted-field tests remove or mistype
each field independently while retaining a matching version and poisoned count.
They require authorized recomputation. This enforces the existing v2 contract;
no previously well-formed proof changes interpretation or needs a new digest tag.

A recount's saved `at` is the latest clock used to build its prefix. If `now < at`,
restart the cursor, total and deadline together; a skipped earlier-expiring row may
have become live before the old cursor. Forward movement retains the prefix only
while its contributing deadline remains future. For non-expiring recipients,
source edits adjust the prefix at its saved time, so the next chunk's
rollback/deadline check covers their effects as well. Expiring recipients instead
restart work on source edits, since a prior skipped delta can invalidate any prefix. Completed evidence keeps the existing future-basis rejection. The evidence
tag is `count-basis-v2`, also stored on pending work: old certificates or prefixes
can already be incomplete. A missing/mismatched work version restarts the prefix;
a certificate mismatch takes the live walk. The optional private work version
allows legacy validation before adoption rebuilds changed work/basis schemas
atomically. No source delta upgrades an old certificate or prefix tag.

Release serving samples `SystemTime` through `now_ms()` for operation time. NTP
steps or wall-clock corrections around a VM resume can therefore be observed;
resume alone need not move backwards. The process-local dev clock uses `Instant`
elapsed time and permits only positive `clock advance` values, so that control
cannot rewind a running process. Restarting dev with a different `--clock-offset`,
or invoking `run --now` with an earlier absolute value, can rewind between durable
operations. Core callers also supply `Context::at` and recount times directly.
Each transaction pins its own supplied time; no monotonicity across transactions
is assumed (`dev_clock.rs`, `serve_maintenance.rs`, core `now_ms`).

Decoder-page and certificate admission use the saved caller **ceiling** and the
**currently occupied** heap, including vectors, member images and output already
reserved inside a prepaid scope. They never restore the older saved usage to make
room. The exact page boundary is tested one byte below, at and one byte above for
direct and nested callers, both empty and partly occupied outer heaps. Scalar
certificate selection follows the same current-occupancy rule. No ceiling changes.

## 4. Verification

Each addition lands with: language tests (parse, bind, diagnostics with
rewrites, `explain_code`), engine tests on memory and SQLite (and Postgres
where the store is touched), device tests for prediction and projection
(no wire message to a non-owner carries a private value; a provisional
sequence never publishes as settled), a guide card, a JOURNAL entry, and
the wasm measurement with a ratchet reason if the budget moves. Two blind
reviews (Astra, Grok) per addition before landing.

## Non-claims

This spec does not define `through` (LLP 3000.014), engine-derived
delivery receipts (withdrawn from LLP 4000 to a future LLP), or any
residency change. It adds three forms to Snapback 4 that stand on their
own product merit whatever Snapback 5's outcome.
