## Material issue 1: spread refusal is over-broad and unnamed

[release_bridge_hiding.rs:28-31,58-60](/tmp/rel4/review1/snapback4/crates/snapback4-lang/src/release_bridge_hiding.rs) refuses any `Write` on a hidden table containing any spread, without naming the hidden column.

Counterexample false refusal: `rollback 1 hides jobs where price = null` with current write `insert jobs {price: 100, ...rest}`. Hidden value is explicitly authored and wrappable, spread covers only other fields, yet the code emits `intentional rollback hiding cannot adapt a spread write` with no `jobs.price`, forcing removal of hides or spelling out unrelated fields.

Counterexample missing name when refusal is correct: `insert jobs {...input}` where `price` can arrive via spread. Diagnostic still says only `cannot adapt a spread write`, violating §5 requirement to refuse with the named column. The outer `rollback_views.rs:183-191` wrapper adds the visible-view and `--exact --check` repairs, but the column name never appears.

Minimal fix: collect `hides` for that table, only refuse when a hidden column is not explicitly bound (`!fields.iter().any(|f| f.name == hidden && !f.spread)`), and include `table.column` list plus both repairs in the inner diagnostic.

## Material issue 2: migration compositions writing hidden columns are not refused or wrapped

`hide_nulls` walks only `ast::Expr::Write` in programs. It never inspects `doc.backfills` / `doc.downfills`, while `release_bridge_rules.rs:391-404` carries current backfills into the view.

Counterexample: current source has `backfill jobs fix(p: int ?): {price: p}` or any backfill/downfill object writing hidden `jobs.price`. The view narrows `price` to required and wraps program writes with `ROLLBACK_NULL`, but the carried migration value is neither wrapped nor refused. A null-bearing migration can then populate the narrowed column without the mandated metered assertion, breaking the §5 invariant that only explicitly declared null-hiding changes the null domain and all authored write values refuse null.

Minimal fix: in `hide_nulls`, reject any backfill/downfill whose table is hidden and whose object fields reference a hidden column (or whose value is not a fixed object proving absence), naming `table.column` and offering the same two repairs: drop the hide for a visible optional view, or preview exact source.
