## 20. Visible rollback views (ROLL)

Implementer: Codex for Charlie Cheever, 2026-10-22; commissioned for 0.4.39.
This amendment replaces opt-in bridging for domain widenings. The remaining
retention, authority, metering, atomic activation and source immutability laws
continue to apply. SEC7 owns ordinary `check` security gates and ranking;
ROLL owns deploy presentation and release selection.

A deploy compares every selectable ordinary predecessor with its candidate.
If current-source values widen a predecessor column and no authored `down`
represents them, it compiles a loosened target bridge before admission. The
bridge keeps the predecessor's operations and incorporates current authored
requirements for affected operations. An unsupported guard dependency,
incompatible type, native or worker dependency, or failed compilation refuses
registration; no guard, null default, zero payment or business meaning is
invented. Old nullable result fields are listed for UI review. Bridges may
retain newer tables under current rules without promising old operations
expose them. Removing a defaulted old column requires an authored truthful
cross-table `down` or explicit acknowledged absence; silently showing a
misleading old default is forbidden.

Compiled bridge source is immutable. A new deployment carries a manifest
mapping each original release to its prepared numeric bridge identity and
source digest. Registration becomes usable only when that deployment's CAS
activation commits. Prepared views cannot become ordinary latest releases or
match unchanged forward deploys; failed deployments remove their prepared
views, and interrupted uncommitted parents cannot authorize their use.
Later deploys recompute the views, including earlier selectable originals;
rollback does not discard the newest committed registration. Selecting
`rollback --to N` resolves the registered view and prints original and actual
release identity. `--exact` selects original source and explicitly reports
its hidden rows. Cold and hot activation, previews and restart use the same
immutable bridge source. Selection restores dormant names implicitly.

An author may instead declare `rollback N hides TABLE where COLUMN = null because
'REASON'`. This first form admits only an existing nullable column and an
original nonnullable predecessor column; the predicate is exactly null equality,
never arbitrary text or a blanket table exemption. The generated view retains
that column's predecessor type while joining all other widened domains; the nonempty reason and predicate travel with its immutable
source. This acknowledges only the named target/table/predicate, never an
unrelated hiding/defaulting hazard. Preview reports the declaration and exact
currently hidden population; every selection of that original target repeats
the reason. Existing data outside the declared predicate must not be hidden
under this acknowledgment. No acknowledgment changes storage preservation,
read/write authority, or permits an invalid migration.

For an in-place transformed output edited under its declaring source, rollback
uses an applicable declared `down` on the assembled current image; otherwise a
bridge that admits its exact current value preserves that value. The receipt
retains the actual newer image, original predecessor, selected old view and
physical presence separately. Forward validates the old view before restoring
the newer image; unchanged historical inputs preserve authored newer output.
Changed old-source inputs require deterministic agreement or a real conflict
with all competing values printed. Projected field edits, invalid parent
lifetimes, pruned evidence and meter cuts continue to refuse atomically.
Unedited transformed outputs retain exact-preimage precedence, and receipts
state explicitly when rows therefore read stale under the older release until
forward. Repeated cycles and partially retired outputs obey the same law.

Human deploy output starts with a verdict, including security FIX count and
test status, followed by adoption/rollback facts. Result advice groups each
changed source column once with its affected operations. The security notice
is last, scoped to changed tables and operations, ranked and limited to five
advisory findings; reachable FIX evidence is never capped or suppressed by
scope. The trailing verdict repeats the outcome for `tail` users. JSON retains
all compatibility details, full security report, test status and view manifest.
Finite tests are evidence, never a universal security proof. Strict reachable
refutation remains a refusal.

Reference-column `renamed from` moves the identical physical cell and its
reference lifetime bindings, including retained/narrowed images, using the
existing alias relation. It never recaptures a deleted/reused parent or moves
a captured/engine-owned field; both aliases at once and unequal destination
cells refuse. Nominal reference target, nullability, bounds, on-delete and
capture shape must remain compatible. This is not a reference conversion.

Asset child extraction is a separate declarative migration, not a cross-table
rename or a user-callable operation. It creates one deterministic child per
source row with explicitly mapped fields and a unique reference to that source,
and moves the asset's single home with its immutable bytes and authority.
The spelling is `extract CHILD from PARENT via REFERENCE: {newField: oldField}`.
Mapped assets must have identical full types and the new parent declaration
must remove their source columns. Other mapped fields may only copy immutable
scalar source fields; mutable, captured and nominal-reference copies refuse.
The child reference is required and targets the declared parent. Initial
children take their parent's id in the child table's namespace; independent
history at that destination refuses. Extra required child fields need an
explicit default. Newer rows without receipts reverse only when exactly one
child supplies the old asset; ambiguity refuses and never picks an arbitrary
photo. Read authorization follows the currently selected home row's rules.
Preview runs the identical transaction on a private snapshot. Independent
child history, duplicate destinations, ambiguous reverse selection, invalid
lifetimes and missing bytes refuse. Returning to old source moves the current
asset home back only where the one-child mapping remains unambiguous; additional
v2 children remain newer-only facts. Receipts bind source and child lifetimes;
delete/id reuse cannot inherit them. Schema capabilities fence child extraction and reference renames; store
format 9 fences edited-output receipt custody from older runtimes. Legacy
format 8 opens and upgrades only on successful adoption. Device projections
omit all migration metadata. Qualification records which portions have passed.

Readiness requires blind Muse and fresh Codex reviews on the same semantic
revision, retained verbatim with provenance under llp/reviews/. Tests cover
repeated down/forward cycles, genuine conflicts, nullable money, image/file
homes, reference deletion/id reuse, view registration failure/CAS/restart,
all scoped bakeoff copies, and packed guide cases. This record makes no
publication claim and authorizes no push or version bump.

### 20.1 Review clarifications and closed initial forms

The trigger is the static successor comparison of declared domains, not the
presence of a sampled widened value. The compatible join is §8 of LLP
3000.000.000.002: optionals, integer bounds, text bounds with identical format,
enum union, identical-policy image/file/video byte limits and recursively
joined bounded lists; nominal references join only across declared identity
renames. A declaration of scalar `down` takes precedence; disjoint writer and
missing-point/meter laws still apply. Unsupported conversions refuse. All
predecessor views prepare successfully or the whole deploy refuses.

Automatic guard transport is deliberately closed. A copied current `require`
needs identical argument/local-binding meaning through its entire transitive
binding/helper closure, including lookup predicates and helper calls. Changed
conditional/loop/as paths and requirements depending on writes need an authored
guarded workflow; compiling a similar-looking guard is insufficient. Current
table rules, column read rules and field ownership for shared fields must match
the generated view after identity alignment, or registration refuses rather
than broadening confidentiality/authority. Current newer-only tables keep their
current rules. No old helper is assumed equivalent merely because its name or
signature matches. The operator can still select explicit `--exact` source;
its old confidentiality/safety differences are reported under §19.2. SEC7's
strict reachable refutation blocks admission, not merely its presentation.

The authoring declaration lives in candidate Quarry; N is the immutable
original target id. The column must be nullable there and nonnullable under N,
with identical table/column spellings; rename combinations need authored source
adaptation. Only the nullability restriction is retained in the bridge: its
nonnull domain is still the full join (0..100 plus nullable 0..1000 becomes
required 0..1000, never 0..100). Acknowledgment admits null rows and the engine's
actual hidden-reference closure from those rows. Every other hidden old-table
row refuses atomically. Previews count that closure and show bounded privileged
samples separately from newer-only rows, never as a per-viewer result guarantee.
At actual activation the writer captures the before image, runs adoption and
checks every retained hidden row against the same policy before committing.
This closes the race between an advisory snapshot and ordinary served writes.
Removed defaulted columns have no acknowledgment form in this initial grammar:
they require an authored truthful `down`. The suggested cross-table expression
is advice, never an inferred business mapping or fabricated default.

Each view manifest entry includes original target, actual numeric view id,
parent id, executable digest, changed columns/nullable result fields, carried
guards and exact hiding reason. The immutable parent bundle's control digest
includes this manifest; the view's complete control digest includes its own
metadata. Resolve the newest committed manifest containing an entry for the
original id, under the release-command lock, then bind actual source digest,
expected current release and activation revision to the existing CAS. Any
later activation, including ABA/equal-content switches, changes revision.
`releases` labels prepared views and original/actual provenance. A bridge can
be the database's actual current release, but never the ordinary `latest`
forward target. Restart and cold/hot/check use that exact actual source id.

Retained-source reactivation, unchanged deploy and `--exact` preserve the
committed registry. The one bootstrap exception to §16's source-id reuse is
an unchanged legacy deploy which lacks a required rollback registration: it
creates an ordinary registration-bearing parent release before exposing any
view. Thereafter equal content stays a no-op. A definitive failed parent removes
its prepared numbered views and stage. An admitted control request with an
unknown outcome preserves parent and views for history-authoritative recovery;
no uncommitted parent authorizes selection. A later successful deployment may
replace entries, but rollback never revokes the newest committed registration.
Implicit dormant restoration supplies intent only; full data, authority,
constraint, lifetime, native and worker validation remains mandatory.

An edited migrated output never acquires native birth status. Its original
preimage, actual authored newer value, saved computation and physical old-view
receipt are separate evidence. Fresh recomputation checks point/existence
lookups even when explicit arguments match. Preserving an authored output
requires unchanged arguments AND unchanged computed patch; otherwise exact
agreement with its actual authored image is required, or a two-writer conflict
refuses with the competing values. Every projected field's physical
absence/null/default and lifetime evidence must still agree before restoration.
Unedited outputs retain exact-preimage precedence and their stale-old-view
receipt appears in preview and activation output; operator retained-image
inspection continues to distinguish source images rather than invent a history.

Extraction creates one receipt-owned initial child per parent; it does not
impose unique-parent on all future children. Independent active or dormant
same-id destination history refuses. A native row without a receipt reverses
only if exactly one current child exists AND its private parent-lifetime anchor
is valid. Those anchors are captured on child writes while the declaration is
active, including recording absent parents as unqualified, and unchanged writes
never recapture an invalid anchor. The parent reference requires `on delete
cascade` or `restrict`; kept/set-null references are outside this initial form.
Older independently existing relationships cannot be retroactively qualified.
Deletion/id reuse invalidates the anchor; a numeric id match never suffices.
All extra v2 children remain retained newer-only facts on old-source selection.

Asset transfer removes the former home's actual asset cell, including dormant
cell overlays, while changing the ledger home in the same transaction. Reverse
transfer removes the child's asset cell; the retained child identity/scalars
remain without a second asset home. Forward uses the current old-source asset,
including a replacement or explicit optional clearing, and never revives
released bytes from the earlier receipt. Missing bytes, changed parent binding,
independent child history or ambiguous reverse selection refuses. Immutable
scalar copies mean fields explicitly covered by an immutable constraint;
references/captured/engine/maintained fields never qualify. Other required child
columns need authored defaults. Full asset type identity includes nullability,
list cardinalities, size/MIME/once policy and nominal asset kind.

Store marker `snapback4-release-store-9` is written transactionally whenever
edited-output, reference-rename or extraction custody first needs the new law,
and survives selecting old source. Version 8 reads/opens and upgrades only with
successful adoption; older runtimes refuse 9. Capabilities are
`release-child-extraction-v1` and `release-reference-renames-v1`; device schemas
omit migration metadata. Failed adoption rolls back evidence, format upgrades,
ledger homes, views, generation and selection together. Human security output
states the recorded test campaign's matching/stale/missing/incomplete status
and age. Its bounded summary always names omitted advisory counts and points
to the full JSON evidence. Added/removed tables, renames and extraction facts
are separate adoption groups, alongside per-column result advice.
