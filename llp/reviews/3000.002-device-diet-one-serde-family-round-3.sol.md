## Overall assessment

The merge resolutions are correct, and the native-depth, provenance, raw-store, and emitted-family changes are sound. However, the new source census and route probe still admit concrete false-green mutants. The enforcement claim is therefore not ready.

All citations below refer to `e4d0cc833b`.

1. **FIXED — merge resolutions.** The composition response routes `components` through `encoded`, hence `snapback4_core::json_codec::to_value`, at `snapback4/crates/snapback4-device/src/call.rs:88-95`. Manual inspection found no direct typed `serde_json` call introduced by the retained-read merge on a current web path. The harness still runs the component differential at `snapback4/crates/snapback4-device/tests/device.rs:56-63` and sends `apply`/`observe_store` through `call_text` at lines 65-67.

2. **NOT FIXED — source census.** Its device coverage is broad, but it lists only five core files at `snapback4/packages/snapback4/test/wasm-codec-census.test.mjs:13-14`. Many unconditional web modules are omitted: `schema`, `wire`, and others are declared at `snapback4/crates/snapback4-core/src/lib.rs:7-28`; `engine/local.rs`, `read.rs`, and related modules are unconditional at `engine/mod.rs:18-32`. A typed call can hide there. The regex at `wasm-codec-census.test.mjs:30` also misses `use serde_json::from_value;`, renamed imports, and `use serde_json as sj`. The four production allowlist entries are presently justified: their functions are all `cfg(feature = "sqlite")`, including `groups_now`, `stream`, and `expand_joins`. However, the exceptions are matched only by file/text/count, not by the enclosing cfg item, and exact consumption is not checked.

3. **FIXED — `unbounded_depth`, with a bounded trust caveat.** The sole feature enablement is target-gated at `snapback4/crates/snapback4-core/Cargo.toml:37-40`. The workspace uses resolver 3, the shipped build selects only `snapback4-device` with `web`, the core dependency disables defaults, and no other manifest enables this feature. Dev-dependencies are not active in that build. Only native `from_owned_text` calls `disable_recursion_limit` at `json_codec.rs:54-66`; web remains bounded.

   There is no current untrusted server/process route to an arbitrarily deep owned tree: the process device and FFI enter through bounded `call_text`, and the server has no production `json_codec::from_value`/`to_value` call site. Public Rust callers can pass arbitrary prebuilt `Json` directly to `call`; such an embedding could stack-overflow on extreme depth, but that was also the old `serde_json::from_value` trust boundary rather than a newly exposed wire path.

4. **NOT FIXED — route probe and global family check still miss mutants.**

   - Route mutant: inside the fast branch, parse `Json` with `from_text`, call `json_codec::from_value` directly to obtain `PageArgument`, then call `page_call`. The assertions at `tests/codec/route.rs:10-15` still see one page call, zero fallbacks, and zero “owned conversions,” because that counter exists only in the local `parse` wrapper at `call.rs:29-32`.
   - Family mutant: import `serde_json::to_value` under an alias and call it on a `String` in a web path. The source regex misses the alias, while the artifact checker explicitly accepts the owned `String` serializer at `scripts/attribute-wasm.mjs:89-107`. A fully inlined second family is also invisible by construction at lines 68-72. The emitted-symbol checker correctly handles visible std containers, but cannot close these holes without the source census.

5. **PARTLY — product behavior.** The delta intentionally changes native behavior: programmatically constructed owned trees deeper than serde’s text limit now pass `from_value` and `to_value`; web behavior is unchanged. The counters, census, tests, and measurement changes are non-product. Dirty provenance now includes both the toolchain pin and budget at `scripts/measure-wasm.sh:9`, and family checking precedes measurement at line 14. SQLite compatibility now compares every raw row before and after open at `tests/codec/old_store.rs:141-170`.

## Findings

- **Medium — incomplete and alias-evadable census**  
  `snapback4/packages/snapback4/test/wasm-codec-census.test.mjs:13-14,30`  
  Scenario: change `call.rs::parse` to use `use serde_json::from_value as decode; decode(value)`, or add a direct typed call in `schema.rs`. The blocking suite remains green while the owned family returns.  
  Smallest fix: include every unconditional web-linked core module and reject imports/aliases of the typed serde entry points, preferably with Rust syntax parsing rather than another path regex. Bind exceptions to cfg-gated items and require every exception count to be consumed.

- **Medium — conversion probe counts one wrapper, not conversions**  
  `snapback4/crates/snapback4-device/src/call.rs:29-32`; `tests/codec/route.rs:10-15`  
  Scenario: the fast path constructs a whole `Json` and invokes `json_codec::from_value` directly before `page_call`; every route assertion still passes.  
  Smallest fix: instrument the adapter itself, or statically enforce that every device `json_codec::from_value` call goes through the counted wrapper; add this exact mutant.

- **Low — allowlist regression test can pass for the wrong error**  
  `snapback4/packages/snapback4/test/wasm-codec-census.test.mjs:63-71`  
  Scenario: the altered supposedly allowlisted `from_str::<Backend>` remains wrongly accepted, while the separately appended `from_value` supplies the single error needed by `errors.length >= 1`.  
  Smallest fix: mutate the allowlisted line alone and assert that exact line is reported; test the additional forbidden call separately.

**Did this delta introduce a new problem?** Yes: the new guards create false confidence through incomplete coverage and wrapper-specific instrumentation. I found no new runtime correctness or data-compatibility defect.

**Is there a regression test in this delta that would also pass without the change it claims to test?** Yes. The allowlist test can pass because of an unrelated appended violation, and the route test passes when the owned conversion bypasses its counted wrapper.

Questions: none.

Verdict: NOT READY
