## Blocking finding

**Empty-string destinations bypass the witness gate** in the proposed `stage_columns.rs`.

- Proposed code ([stage_columns.rs](/home/ccheever/sb4-loop/sec10-w28-r37-proposal/snapback4/crates/snapback4-lang/src/bind/security/derived/stage_columns.rs), lines 87–91): the emptiness check runs on the *unfiltered* destination set, and empty strings are filtered only when extending `states`:
  `if destinations.is_empty(){continue;}` passes for `{"''"}`, then `states.extend(...filter(!empty))` adds nothing, but execution still falls through to `observations.extend(states)` with the guard literals intact.
- Frozen code ([stage_columns.rs](/home/ccheever/projects/sb4-b26-sec10/snapback4/crates/snapback4-lang/src/bind/security/derived/stage_columns.rs), line 84) required `!value.is_empty()` up front, so an empty write contributed nothing.
- Reachable case: a `text` column with `update docs[d] {workflow:''}` under a multi-state guard (`require d.workflow='a' or d.workflow='prepped'`) is now classified as a lifecycle discriminator from guard states alone, with no witnessed non-empty destination. That wrongly triggers admission omission in `admissions`, the exact approval-evidence erosion §12 forbids ("empty-string validation do[es] not establish this classification"; "real material evidence [must] remain protected").
- Fix: filter empties *before* the emptiness check, e.g. collect the non-empty destinations into a set and `continue` when that set is empty. The same slip covers the retained cross-op path (literal `''` destination still populates `states` via exclusions, then passes the pre-filter check).
