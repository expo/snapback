## Findings

**1. Blocker — §4 "Pages pinned by the parent".** One parent verdict does not decide a narrowed page.

§3.1 defines the substituted rule as the parent's rule with columns renamed. §2 allows `read <- readable issues[.issue] and .author = viewer`. §4 then evaluates that substituted rule once from the live parent and says the page is complete.

Scenario. Alice can read issue `X`. She queries `comments where .issue = X first 20 by .at`. The parent verdict is true. Bob's comment is in that incarnation, and its `.author` conjunct would refuse Alice. The one verdict still returns Bob's body. The other literal reading is as wrong: fold `.author = viewer` into the one-shot rule, the parent image has no `.author`, `term()` yields null, and Alice's own page is empty.

Smallest change. A pinned page is uniform only when every conjunct is decided by the parent lookup. A conjunct that reads a child column keeps today's per-row verdict and completeness class. Do not retire `N_NEVER_COMPLETE` for it.

**2. Blocker — §1 and §4 "Aggregates".** The column that motivated the RFC still mixes incarnations.

`N_MAINTAINED_COLUMN_DISCLOSURE` is the maintained-column note. On insert, `birth_columns` loads the private total with `maintained_id(&[parent id])` and stamps it on the new row. The maintains card says a recreated parent comes back with the current total. §4 specifies a separate view. It never mentions this mirror.

Scenario. Issue `X` in org A has five comments. Delete `X` and insert it again in org B. The new row's id is `X`, so birth reads A's total and B's issue shows 5. Retiring the disclosure note, which §4 tells the implementer to do for an unnarrowed source, makes that count look authorized.

Smallest change. Say the §1 form is a column. Its total is this incarnation only. Birth of a new incarnation stores 0 and does not read the previous id's total. Orphan contributions stay in the dead group and are not mirrored. Apply the same rule to the view's `commentCounts[X]` lookup.

**3. High — §3.3 and §5.** Evaluating the parent rule over null captures does not refuse a missing parent, and it is not a uniform charge.

`term()` turns a missing field into null. `Allow` and `Public` are true. `Ne` is true for `null != false`. `exists` is a real probe only when the stamped key is non-null. `target_attempt` restores the meter only for `NOT_FOUND`, not for `E_RULE`.

Scenario. Issues are `read <- .visibility != 'staff'`, visibility immutable, default `'members'`. Insert a comment whose issue id is absent. The stamped visibility is null, `null != 'staff'` is true, and the insert commits. The captured null keeps the comment world-readable. A present staff-only issue correctly refuses. Absent and unreadable are different results, which is the existence oracle §5 says is closed. The same split hits a pinned page: §4 makes an absent parent an empty complete page, and a present unreadable parent pays the membership probe §4 never reserves.

Smallest change. A null incarnation is not readable. Refuse it with the same `E_RULE` as a present unreadable parent, before the rule runs. Reserve the parent point-read and the substituted rule's static probe allowance either way, and do not add `capture_recorded`'s hit-only `heap_bytes` charge. The pinned page and `commentCounts[X]` use that same empty, complete, prepaid result for absent, expired, and unreadable. Do not treat a true rule over nulls as success.

**4. High — §4 "Sync".** The invertible form does not get through `audience_binding`, and "implies" is the unsafe direction.

Recorded fields are required to be optional (`schema.rs` validation). `audience_binding` rejects an optional prefix because a null cannot name a partition. The sync card requires the read rule to be exactly `public`, `.col = viewer`, or one `exists`, and refuses an extra conjunct.

Scenario. Comments are `read <- readable issues[.issue]` and `sync`. The substituted rule is the invertible `exists members[.$issue.org, viewer]`. The capture is optional, so `audience_binding` returns the required-group-key error and the table does not sync. The natural repair is to accept a named `sync to members[.$issue.org]` for `readable issues[.issue] and .author = viewer`, because that rule implies membership. Delivery then sends every member every comment, including other authors' rows, and the captures ride along. That is the conjunct the sync card refuses.

Smallest change. Committed captures are total; null exists only on the refusal image inside the writing transaction. `audience_binding` treats those prefixes as required group keys. A substituted rule syncs only when `device_audience_rule` is exactly one of the three forms. A named `sync to` must equal that inference. Delete "an audience that the rule implies."

**5. High — §6.** Activation as written can publish a half-bound audience.

`activate` drops any stored field that is not in `table.columns`, then commits one generation. `capture_activation` fills only paths the previous schema lacked, and it never rewrites an existing path. `$incarnation` is not a `reference.column` recorded field, so nothing puts it in `columns`.

Scenario. Add `readable` to a table that already has an orphan comment, and another whose hand-copied `org` is A while its issue is in B. The bullet says to scan live parents. That scan never visits the orphan, the missing-parent count stays 0, and the generation publishes. The hand-copy row is recaptured into B and "reported," which is the silent move the last review forbade. The next schema change then strips `$incarnation` because it is not a column, and every pinned page loses its binding.

Smallest change. Scan child rows, not parents. Any missing, expired, or hand-copy-disagreement row fails the activation by table and count; nothing is published. `$incarnation` and the captures are engine columns, so the projection keeps them. Recapture runs in this transaction even when the path name already existed. This override of "a recorded value is never re-resolved" applies only to audience captures, not to public attribution paths.

**6. High — §4 "Pages" and "Devices".** "Absent, so the page is empty and complete" is false on a device, and a provisional parent is not a covered one.

`fetch` records unknown when a device miss sits past a horizon. `recording_covered` is false unless the group's coverage state is Held. A predicted row can still be the local `tx.get` hit.

Scenario. The device holds a horizon of issues, not issue `X`. `comments where .issue = X` does not find a parent and, by §4, returns an empty complete page. The server has comments. The client will not ask. The same claim is wrong for a predicted issue with a provisional incarnation: the local page is complete and omits the server's children of the committed incarnation. A refused prediction is safe only after replay deletes it; until then it is still a local hit.

Smallest change. Empty and complete only when parent absence is proven: the server, or a device partition that is fully Held. A horizon miss, an online-only parent, and an unknown membership probe stay unknown. A provisional incarnation is disjoint from committed ones and does not make a page complete. Predicted children still capture only through `recording_covered`, and a refused parent withdraws those predictions on replay.

**7. Medium — §4 cursors.** "Hidden fields never enter cursors" contradicts a correct resume.

`CursorScope.prefix` is inside the base64url token. The synthesized index is `(issue, $issue.incarnation, …)`.

Scenario. Page 1 is incarnation I1. The issue is deleted and recreated as I2. A cursor that does not carry I1 resumes inside I2 and skips or repeats. A cursor that carries `$issue.org` publishes the audience input the section just banned.

Smallest change. The scope may carry the caller’s parent id and the resolved incarnation. It must not carry captured audience inputs.

**8. High — §4 "A scan of such a view".** Visiting every dead or other-tenant group discloses how many there are.

The group key is `(issue, incarnation)`, not the audience columns. Sync inheritance only happens when those audience columns are bare group keys, so the view does not inherit sync. A server scan still has no audience prefix to seek.

Scenario. Alice can read nothing. She scans comment counts. Every group is skipped after a parent point-read, and the result is empty. The examined charge, and `E_BOUND` under a tight ceiling, is the number of groups in other orgs plus dead incarnations. `get()` restores the meter so a hidden point-read and a miss cost the same. This scan does the opposite, on purpose.

Smallest change. This revision serves `commentCounts[X]` only. Refuse an unbounded scan until the captured audience columns lead the index and the prefix verdict is uniform. Skipped other-tenant groups must not be visited.

## What is sound

The term is a required top-level read conjunct, the reference is a required immutable id, and write rules do not capture. Within one incarnation, immutable inputs copied in the writing transaction match the live parent. Chains copy the parent's stored captures, including middle conjuncts, and do not walk to a live grandparent. Id reuse is a new incarnation for a view lookup and for a pinned page that actually filters on it. The three sync forms, unchanged `grant_guard`, and the service strip are the right reuse of §6.6. Device insert coverage, per-table revocation, and refusing a §5.2 job are right. The dependency identity is the right answer to default and rule changes, once activation actually recaptures.

A smaller design with the same result: keep the capture, the incarnation, the insert reservation, and atomic activation. In this revision, do not claim a pinned page is complete when a child conjunct remains, do not scan aggregate groups, and do not sync anything `infer_audience` would refuse. That is still enough for the issue tracker, a four-level chain, and a same-mutation receipt.

**Overall verdict: NOT READY.**
