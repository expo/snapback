## The bug: generated native write-result structs reject audience-omitted cells

§22.1 promises: "Native Rust row and write-result structs use `Option<T>` for protected required columns and accept omitted cells on deserialization."

In [emit/rust.rs](/home/ccheever/projects/sb4-b19-colr/snapback4/crates/snapback4-lang/src/emit/rust.rs) (lines 53–64) the row structs got both halves — `Option<T>` **and** `#[serde(default)]` — but the write-result structs got only `Option<T>` with no `#[serde(default)]`:

```rust
// row structs (correct):
if kind.is_optional() || table.read_optional(column) { out.push_str("    #[serde(default)]\n"); }
// write structs (missing default):
for (column,field) in fields { out.push_str(&format!("    #[serde(rename = {})]\n    pub {field}: {},\n", ...)); }
```

`from_row` ([snapback4-native/src/lib.rs:198](/home/ccheever/projects/sb4-b19-colr/snapback4/crates/snapback4-native/src/lib.rs:198)) is plain `serde_json::from_value`, and serde errors on a missing field without a default even when the field is `Option`. Reachability chain, all confirmed in code: valued insert/update returns the `ProjectFields` image (`project_insert` wraps whenever `column_reads` is non-empty), `into_value` omits denied cells (asserted by the new `insert_and_insert_if_absent_bindings_never_expose_denied_cells` test), so any denied write on a table that has both maintained columns (the write-struct filter) and a protected required column produces JSON the generated `*Write` struct cannot deserialize. The new `generated_native_rows_decode_audience_omissions` regression test compiles and runs `from_row` only against the row struct, so the suite stays green while write structs are broken. Fix is one line: mirror the row-struct `#[serde(default)]` condition onto write-struct optional fields.
