# DORM §19 immutable design snapshot

## 19. Dormant visibility and migration (DORM)

Implementer: Codex for Charlie Cheever, 2026-10-19; target 0.4.35. This is a
proposal until its implementation and two independent READY reviews are
recorded. It amends §9.1's prohibition on value substitution only for an
explicit, previewed, reversible projection. No inferred coercion is added.
The wave-19 day-two evidence distinguishes 21 affected old-client records
from retained facts in ten newer-only tables; no row deletion was found.

### 19.1 Declared old views and renames

A reverse projection belongs to the newer source and runs when that
declaration is left. It reads the assembled newer source under activation's
system authority and ordinary job meters, before projection or narrowed
visibility closure can hide its inputs. Typed inputs and deterministic point
reads follow LLP 3000.000.000.002; simultaneous projections read one snapshot
and cannot consume each other's new results. A reverse-only declaration is
first-class: moving a legacy field to a related table must not require a
dummy forward transformation. Output fields are validated against the
selected target schema. Identity, reference lifetime, captured authority,
asset and engine-owned fields retain their existing safety boundaries.

The spelling is `down extensions legacyReason(id: id):` followed by
`{reason: (explanations[extension = id] ! else MISSING_REASON).explanation}`.
Typed inputs describe the current newer row; outputs describe the selected
older view, so an old output field need not remain in the newer table.
`explanations.extension` must have a unique point index. A declaration is
self-contained and immutable by table/name across retained history.
Point-read syntax is inherited from LLP 3000.000.000.002 §2: a bare unique
`explanations[extension = id]` returns a nullable row, not a scalar field
or a silent field fallback. Field access requires the normal non-null
proof or `! else CODE`. An explicitly nullable scalar projection can use
`{reason: (explanations[extension = id] ! else MISSING_REASON).explanation
if exists explanations where .extension = id else null}`. The existence
probe is metered on the same source snapshot; its cut refuses instead of
selecting the null branch. No new nullable lookup syntax is introduced.
This version has no per-release selector for a down declaration: applicability
is solely whether the selected same table has the output field. Two writers
for that table/field therefore co-apply whenever either can apply; different
intended release numbers do not disambiguate them. Reverse output sets on
a table are disjoint, including implicit rename writers. Reject overlapping declarations before any adoption work, naming
the declarations and field; types do not establish target applicability.
Each surviving target cell has at most one reverse writer after saved
forward-preimage/non-null-retained precedence. A declaration applies only when the selected target
contains its named output; absent target outputs remain retained, not
physically introduced into that release.
Both raw-schema admission and every activation recheck this condition for
the actual candidate/target pair. Computed down outputs are scalar old-view
cells only: no reference, asset, collection, identity, captured/maintained,
engine-owned or source lifetime output is admitted. A column rename may
only move existing lifetime evidence unchanged; it cannot create a binding.

Rows with saved forward-backfill predecessor preimages use those exact
preimages. Non-null native legacy cells also win over a standalone `down`.
A retained value synthesized by an earlier `down` remains owned by its
receipt, not a native predecessor preimage. On each later rollback it must
be recomputed from current declared newer inputs (including changed point
dependencies), with a fresh P receipt. A prior synthesized image never
suppresses that recomputation or becomes current truth by precedence.
The old synthesized image must still match its receipt before replacement;
a conflicting edit aborts rather than silently keeping a stale image.
A standalone `down` explicitly supplies missing/null old-view cells; nulls
materialized and retained by earlier old-source rollback do not suppress it.
This is declared synthesis, not a claim about a legacy row's birth release.
An asserted lookup for an intentionally null old cell can therefore refuse;
authors use an explicitly nullable expression when null is the truthful
old view and newer source data is absent. Rows born
with the newer representation may use the declared reverse projection.
Retain the exact newer projected cells and their reverse result in the same
transaction. Compatible forward restores those cells rather than deriving
an approximation of their authored value. Unrelated edits under the older
source survive. A changed projected cell or a changed dependency that would
make its restoration ambiguous refuses atomically with a bridge repair.
Deletion/expiry ends the lifetime and clears the corresponding evidence;
id reuse never inherits it. Prune previews these private images and leaves
reversal-unavailable identities when values are explicitly discarded.
Missing lookups, meter cuts and invalid reference/authority evidence refuse,
never become false absence. A value with no truthful old representation
retains ordinary narrowed dormancy; zero observations do not silently become
one observation. The declaration is not a claim that different product
meanings are equivalent. All indexes, constraints, read-through validation,
maintained data, generation and release selection commit with the projection.

The outcomes are disjoint. A saved forward predecessor preimage wins. Otherwise an
eligible row evaluates the declared expression: an asserted missing point
executes its authored refusal and aborts activation; an ordinary nullable
point may return null only where the expression explicitly allows it.
There is no implicit missing-lookup fallback. A successfully computed value
that does not fit the old type follows narrowed dormancy. Invalid/corrupt
evidence and authority/lifetime failures abort. A meter cut aborts the entire
transaction with the ordinary bounded-work refusal; retrying unchanged
inputs is not promised to succeed, and an indexed bridge is the repair.
Exact retained native cells win on re-entry; an older-source edit to their
declared dependencies that conflicts with that native image refuses rather
than deriving over it. Pruned evidence requiring discarded values refuses
explicitly, including in later previews; it never fabricates null/default.
For each row, let P be exactly the fields actually down-projected after
preimage precedence. Its receipt stores each field's newer value or physical
absence and its old-view result. Forward first verifies every field in P
still equals that old-view result (including absence/default interpretation),
then restores only P. Fields outside P keep the current old-source values.
Any conflicting field aborts the entire activation; a disjoint field edit
does not authorize overwriting a conflicting projected field.

A column rename is declared, never inferred from similar names or types.
The spelling `newName: Type renamed from oldName` names its old column;
both directions preserve the
authoritative cell and lifetime evidence through the same reversible
adoption. A conflicting already-present target value refuses rather than
choosing a winner. Required fields do not acquire invented defaults. Client
argument compatibility is distinct from result shape compatibility: an old
query's result field cannot be promised merely because stored data moved.
Old operation wrappers/projections and the compatibility report must reflect
the actual exposed result shape. Devices execute no migration metadata;
semantic capability/store fences refuse runtimes that cannot interpret the
new declarations or retained evidence.

The rename is strictly within the same table and row lifetime; its grammar
names a column, never another table/row/parent. Cross-parent and cross-table
moves are not renames. Identical cell types means the full structural type
including numeric/text bounds, enum members, nullability and nominal target,
not merely its base kind. Existing default/constraint validation still
applies to the selected schema; the rename never invents a missing cell
from a new default, truncates or coerces it. A type conversion needs
a separately declared transformation; the rename itself never converts.
A missing required source cell without saved evidence/default is E_ADOPT,
not an invented optional value. Old and new target schemas validate their
respective view in each direction.

### 19.2 Forward and captured read-through authority

Selecting a newer retained source after older-source writes re-enters its
declared backfills. Newly written old-source rows receive required outputs;
changed old-source inputs or lookup dependencies catch up under the existing
cohort/preimage conflict rules. Native newer outputs remain authored values.
This is not a continuously running trigger and does not synthesize a missing
application side-table fanout job. A schema that needs such reconciliation
must declare/prove it or retain a compatible bridge; it cannot claim required
labels have been supplied merely because retained rows returned.

Changing only a read predicate, including narrowing it then selecting the
older predicate, must not itself make captured read-through rollback refuse.
The reference identity, parent lifetime and authority provenance remain
bound. Reusing another parent, resurrecting an expired capture, or changing
capture structure does not qualify as a predicate-only change. Preserve old
captures; do not recapture a broader grant as a side effect of rollback.
Actual target read rules still authorize every read and the preview warns
when selecting older rules restores broader confidentiality exposure.
The operator is the existing same-UID filesystem owner, already capable of
editing the deployment database directly; activation is not a lesser data
role. This amendment adds no new capability/confirmation for selecting old
rules. Predicate-only means unchanged reference/capture structure and
bound parent lifetime/provenance; only the parent read predicate differs.
Writing the down declaration explicitly authorizes its old-view synthesis;
it is not inferred from a type match. Previews list transformed reverse
cells/rows separately from restoration and display lost confidentiality
clauses. Target rules are the selected source's rules: choosing old source
can intentionally broaden access, as before this amendment. The author's
commission does not introduce a second acknowledgment flag or an audience
containment proof for an explicitly authored operator migration.

### 19.3 Exact visibility before mechanical diffs

Rollback preview leads with `N records visible under release C will be
hidden from release T users`. Count only before-active authoritative rows
that become retained dormant in a table T has; show each table and bounded
ids in JSON. Separately count surviving target-visible cells that become
null/default or newly lack a retained legacy cell, and rows in tables T
does not have. The empty-cell category separates newly empty/defaulted cells
from restored empty legacy cells; the latter are not claimed as lost text.
Legacy stores cannot distinguish intentionally null old cells from nulls
materialized by an earlier rollback. Report the exact view without inventing
that provenance. This category counts cells, not distinct records across columns.
Actual expiry/deletion and rebuilt private caches are excluded from dormant
loss. Counts precede read rules and are table populations, never a promise
about a particular viewer's query results. Legacy stores lack reliable
row-birth release provenance, so the preview says `visible under`, not
`created under`. An old column newly shown as null is a factual view change;
the tool does not infer which related business text the application wanted.
Hidden-row counts and surviving-cell counts are disjoint by row presence;
newer-only rows have a table absent from T and cannot also be old-table
losses. No jobs or expiry run on dormant rows (§4). On reactivation the
original source deadline still applies: an expired lifetime can retire then,
and retention never promises that expired records revive indefinitely.

Each affected class names reverse projection or an expand/contract bridge
as the repair. Rule/guard/operation diffs follow it. Deploy preflight also
warns before future writes to new tables, widened domains or missing old
fields can make a later rollback hide rows or show empty/defaulted cells.
For these three syntactic risk classes the warning is conservative: no
false negatives for new tables, widened value domains and removed old fields;
a fitting authored projection may make a warning a false positive.
Exact reverse adoption on the post-deploy snapshot reports current effects
separately from conservative future-write risks. Previews use MAIN tables
in their private disk snapshot: read-through's connection-local temp-store
configuration cannot erase their before image. All scratch disappears on
success or refusal. Nothing changes live rows, pointers, history or time.

### 19.4 Operator inspection and retained identity

`sql --dormant --release DIR` and `sql --all-releases --release DIR` are
mutually exclusive read-only operator views under one pinned SQLite read
snapshot. The first contains retained whole/narrowed rows and retained cells;
the second includes active and retained images. Removed table names and
retained column names are queryable through generated logical application
relations; internal namespaces remain unavailable to submitted SQL. Factual
state/source metadata distinguish active rows, dormant rows and dormant
cells. A retained-cell record contains its id and retained cells, with
unprovided columns null. Conflicting images are separate labelled records,
never an arbitrary winning value. Inspection-mode reserved-name collisions
refuse instead of shadowing application columns. These modes bypass read
rules as existing owner-only SQL does; they add no HTTP/client namespace.
`all-releases` means every image still retained, not time-travel snapshots
or one invented version of every row per historical release.
`_snapback_columns` is the JSON array of actually provided application cells
on each inspection record, so a retained null is distinguishable from an
unprovided SQL NULL. This is provenance, not a missing-value substitution.

Equivalent retained executable source remains selectable across compiler
upgrades. Compiler reports or equivalent old/new packaging metadata do not
change source identity; actual source, native and worker behavior remain
identity-bearing and full control-request integrity still covers all files.
Ordinary refused deploys leave neither numbered candidates nor stages.
This is a source-bundle identity, not a frozen compiler-binary identity or
a proof of behavior equivalence between compiler versions. Activation
recompiles retained source with the selected runtime and revalidates every
data/authority constraint. Actual compiler semantic fixes can change
execution without minting a new source id; version negotiation and the
normal upgrade/publication qualification remain independent fences.
Backfill/reverse definition identity still includes its normalized typed
IR. Recompilation that changes that historical definition cannot reuse its
old receipts: immutable-name checks refuse and require an explicit new-name
bridge. Selecting the source id across an upgrade is supported; success of
an incompatible historical migration after an arbitrary semantic compiler
change is not promised. Removing the source-identity trap does not bypass
these admission checks.

### 19.5 Argument aliases and review evidence

`explanation: text 1..500 alias reason` declares one canonical argument and
one accepted old spelling on a Quarry query/mutation. Normalize the old
spelling to the canonical value before typed execution, including local
device execution. Both spellings supplied at once refuse E_INPUT even if
equal. Alias names must be unique and cannot collide with canonical args;
deprecated/aliased combinations refuse. Canonical default/null validation
semantics are unchanged. Generated TypeScript accepts either spelling and
rejects both; capability comparison recognizes the old shape accepted by
the alias. Compatibility advice for renamed same-typed inputs recommends
mapping with an alias. It never recommends accepting and dropping the old
value with `deprecated` as a rename repair.

Every changed guide fence/starter runs as written against a freshly packed
tarball. Qualification includes regression stores, actual old callers,
reverse/native/preimage conflicts, forward old-source writes, inspection,
hot/cold/check parity and copied wave-19 dormant lanes. Full test and
differential results and any external qualification limits belong in
WORKSTREAM-REPORT.md. Reviews are mutually blind Muse and fresh Codex
sessions on one immutable semantic revision, retained verbatim with
provenance. A READY verdict records review readiness, not author acceptance
or a publication receipt. No version bump or push is authorized.
