## New defects in the repairs

### N1 — Medium: horizon advice now disables prediction for ascending mutation pages

**Location:** [horizons.rs:18](snapback4/crates/snapback4-lang/src/bind/residency/horizons.rs:18).

The narrowed suppression excludes every ordinary page. Consider an uncapped, publicly synced `archive` with `byTime`, and an eligible mutation that reads `archive first 20 by byTime` and inserts copies into another synced table.

The new note recommends `sync public last 500 by byTime`. Following it makes every ascending scan mark horizon coverage unknown—even when all existing rows were acquired—and the mutation loses prediction. [read.rs:648](snapback4/crates/snapback4-core/src/engine/read.rs:648), [local.rs:70](snapback4/crates/snapback4-core/src/engine/local.rs:70)

The new regression checks only static `predicts: eligible`, which does not establish successful runtime prediction. [residency_notes.rs:489](snapback4/crates/snapback4-lang/tests/residency_notes.rs:489)

**Smallest fix:** retain the growth warning, but suppress or explicitly qualify the horizon rewrite when an eligible mutation’s scan order/index is incompatible with it. Add a before/after prediction test on both stores.

### N2 — Low: an empty module argument can rename a foreign schedule target

**Location:** [recipe.rs:85](snapback4/crates/snapback4-lang/src/recipe.rs:85).

Call `prefix_module(source, "feed", "")` on source declaring local `purgeRemoved` but scheduling `other.purgeRemoved`. Because the foreign-qualifier check is disabled when `module` is empty, the result targets `other.feedPurgeRemoved`. This either fails compilation or schedules the wrong job if that foreign operation exists.

**Smallest fix:** compare qualified targets against an explicit source-module identity even when the output module argument is empty; do not treat empty as a wildcard. Extend the external-target test to that case.
