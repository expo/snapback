`ServerError` extends `GiveUp`, and unfinished-step reconcile parks generic `GiveUp` (`server-json.ts:5-11`, `server-steps.ts:65-68`). ## Exchange (v2 split)

New complete attempts admit `oidc.exchange.v2.marker` `{ protocol: "oidc-exchange/v2" }` before discovery. Outer reconcile’s marker callback is `ParkStep` and the marker step has **no** reconcile option, so an unfinished legacy outer step, a missing marker, or a lost marker-begin ack cannot open discovery/token (`identity.ts:406-415`). That is fail-closed availability, not a second code POST.

Discovery is reconcilable and returns a closed public-metadata whitelist (`identity.ts:196-273`, `417-441`). `discoverProvider` maps network/timeout failures to `Retry`, which is **not** `GiveUp`, so a pre-token 503/timeout/unreadable discovery can retry under a new claim without parking.

Token phase has no reconcile callback. Uncertain grant/JWKS outcomes `ParkStep`; a later begin without reconcile parks (`identity.ts:443-474`, `server-steps.ts:63`). Known `invalid_grant` / validation refusals complete `{ ok: false }` and become terminal `E_OIDC_EXCHANGE`. Completed outer `oidc.exchange` replays stored claims and never enters `runV2Exchange`.

Reconstruction is `new Configuration(serverMetadata)` plus the same `customFetch`, timeout, loopback policy, `ClientSecretPost`, and `enableNonRepudiationChecks`, then `authorizationCodeGrant` / `tokens.claims()` (`identity.ts:302-329`, `450-453`). No new JWS parser. Hostile `none` / HS256 / kid cases still go through that library path in the protocol double (`identity.test.mjs:423-451`).
