### 2. Schema in v0

No `principal()`, `optional`, enum, `lastHolder`, host-stamping, or `maintain.max` in v0. Principals are `id()`. Unset optionals are `0` / a zero id (`UNSET`). `tree` / `interval` / `exclusion` unused. Mixed-direction rank is *not* an index; close sorts a `cap`ped page.

### 3. Operations in v0

Helpers (pure; inlined at `check`):

```ts
function compareIds(a: string, b: string) { return a < b ? -1 : a > b ? 1 : 0 }

function rankCommitments(rows: BidCommitment[]) {
  return rows.slice().sort((a, b) =>
    (b.maximumAmount - a.maximumAmount)
    || (a.rankedAt - b.rankedAt)
    || compareIds(a.rankKey, b.rankKey))
}

function replayProxyRuns(revisions: BidRevision[], reserve: number, increment: number) {
  const ordered = revisions.slice().sort((a, b) =>
    (a.submittedAt - b.submittedAt) || compareIds(a.rankKey, b.rankKey))
  const maxima = new Map<string, { bidderId: string, maximumAmount: number, rankedAt: number, rankKey: string }>()
  const runs = []
  let price = reserve
  let previousLeader: string | null = null
  for (const revision of ordered) {
    maxima.set(revision.bidderId, {
      bidderId: revision.bidderId,
      maximumAmount: revision.maximumAmount,
      rankedAt: revision.submittedAt,
      rankKey: revision.rankKey,
    })
    const ranked = Array.from(maxima.values()).sort((a, b) =>
      (b.maximumAmount - a.maximumAmount) || (a.rankedAt - b.rankedAt) || compareIds(a.rankKey, b.rankKey))
    const leader = ranked[0]
    const runnerUp = ranked[1]
    const target = runnerUp
      ? Math.max(reserve, Math.min(leader.maximumAmount, runnerUp.maximumAmount + increment))
      : reserve
    if (target > price || leader.bidderId !== previousLeader) {
      const increase = Math.max(0, target - price)
      const q = increase === 0 ? 0 : (divmod(increase, increment).r === 0
        ? divmod(increase, increment).q
        : divmod(increase, increment).q + 1)
      runs.push({
        causedByRevisionId: revision.id,
        leaderId: leader.bidderId,
        fromAmountExclusive: price,
        toAmountInclusive: target,
        increment,
        stepCount: q,
        ordinal: runs.length + 1,
      })
      price = target
      previousLeader = leader.bidderId
    }
  }
  return { runs, price }
}
```

`Math.max`/`Math.min` are not in the banned list (only `Math.random`). If `check` treats `Math` as `E_OPAQUE`, rewrite to ternaries.

```ts
export const placeMaximumBid = mutation({
  auctionId: id(auctions),
  walletId: id(wallets),
  maximumAmount: int(),
}, ({ db, ctx, args }) => {
  const now = ctx.now()
  const a = db.get(auctions, args.auctionId)
  db.require(a !== null, 'AUCTION_NOT_FOUND')
  db.require(a.state === 'open', 'AUCTION_NOT_OPEN')
  db.require(now < a.closesAt, 'AUCTION_CLOSED')
  db.require(a.sellerId !== ctx.viewer, 'SELLER_CANNOT_BID')
  db.require(args.maximumAmount >= a.reserve && args.maximumAmount <= a.maxBidAmount, 'BID_OUT_OF_RANGE')

  const revAgg = db.get(auctionRevisionCount, args.auctionId)
  db.require((revAgg?.count ?? 0) < 512, 'REVISION_LIMIT')

  const wallet = db.get(wallets, args.walletId)
  db.require(wallet !== null, 'WALLET_NOT_FOUND')
  db.require(wallet.ownerId === ctx.viewer, 'WALLET_NOT_OWNED')

  const existing = db.get(bidCommitments.byAuctionBidder, [args.auctionId, ctx.viewer])
  if (existing === null) {
    const bidders = db.get(auctionBidderCount, args.auctionId)
    db.require((bidders?.count ?? 0) < 128, 'BIDDER_LIMIT')
  } else {
    db.require(args.maximumAmount > existing.maximumAmount, 'MAXIMUM_MUST_INCREASE')
  }

  const delta = args.maximumAmount - (existing?.maximumAmount ?? 0)
  db.require(wallet.availableCents >= delta, 'INSUFFICIENT_FUNDS')
  db.update(wallets, wallet.id, w => ({
    ...w, availableCents: w.availableCents - delta, heldCents: w.heldCents + delta, updatedAt: now,
  }))

  const rankKey = ctx.newId()
  let holdId: typeof existing extends null ? never : string
  let commitmentId: string
  let revisionNo: number
  if (existing) {
    const hold = db.get(fundingHolds, existing.holdId)
    db.require(hold !== null && hold.state === 'active' && hold.walletId === wallet.id, 'HOLD_INVARIANT')
    holdId = hold.id
    commitmentId = existing.id
    revisionNo = existing.revisionNo + 1
    db.update(fundingHolds, hold.id, h => ({ ...h, authorizedAmount: args.maximumAmount, updatedAt: now }))
    db.update(bidCommitments, existing.id, c => ({
      ...c, maximumAmount: args.maximumAmount, rankedAt: now, rankKey, revisionNo,
    }))
  } else {
    holdId = ctx.newId()
    commitmentId = ctx.newId()
    revisionNo = 1
    db.insert(fundingHolds, {
      id: holdId, auctionId: a.id, bidderId: ctx.viewer, walletId: wallet.id,
      authorizedAmount: args.maximumAmount, capturedAmount: 0, state: 'active', updatedAt: now,
    })
    db.insert(bidCommitments, {
      id: commitmentId, auctionId: a.id, bidderId: ctx.viewer, walletId: wallet.id, holdId,
      maximumAmount: args.maximumAmount, rankedAt: now, rankKey, revisionNo: 1,
    })
  }
  db.insert(bidRevisions, {
    id: ctx.newId(), auctionId: a.id, bidderId: ctx.viewer, commitmentId, holdId,
    revisionNo, maximumAmount: args.maximumAmount, submittedAt: now, rankKey,
  })
  // cap() also refuses the 129th bidder / 513th revision (K6). require above is the stable code.

  const extendsAuction = a.closesAt - now <= a.antiSnipeWindowMs
  db.update(auctions, a.id, row => ({
    ...row,
    closesAt: extendsAuction ? row.closesAt + row.extensionMs : row.closesAt,
    closeGeneration: extendsAuction ? row.closeGeneration + 1 : row.closeGeneration,
  }))
  return { commitmentId, closesAt: extendsAuction ? a.closesAt + a.extensionMs : a.closesAt,
           generation: extendsAuction ? a.closeGeneration + 1 : a.closeGeneration }
})
```

**Corrected form** (still client-callable — v0 has no `callable: 'system'`):

```ts
export const closeAuctionTx = mutation({ auctionId: id(auctions) }, ({ db, ctx, args }) => {
  const a = db.get(auctions, args.auctionId)
  if (a === null || a.state === 'closed') return { outcome: 'unchanged' }
  if (a.state !== 'open') return { outcome: 'stale-generation' }
  db.require(ctx.now() >= a.closesAt, 'CLOSE_NOT_DUE')

  const expected = db.get(auctionBidderCount, args.auctionId)?.count ?? 0
  const commitments = db.scan(bidCommitments.byAuction, [args.auctionId], { take: 128 })
  const revisions = db.scan(bidRevisions.byAuctionTime, [args.auctionId], { order: 'asc', take: 512 })
  db.require(!commitments.hasMore && !revisions.hasMore, 'CLOSE_SET_TOO_LARGE') // E_FANOUT if ignored
  db.require(commitments.length === expected, 'CLOSE_INCOMPLETE')
  // ↑ program-level completeness. A user with N>1 hidden peers fails here.
  // A user on a 0-bid or sole-bid auction succeeds. That is permissionless
  // trivial finalization, not the design's "public after deadline" closer.

  if (commitments.length === 0) {
    db.update(auctions, a.id, row => ({ ...row, state: 'closed', closedAt: ctx.now() }))
    return { outcome: 'closed-no-bids' }
  }

  const ranked = rankCommitments(commitments)
  const winner = ranked[0]
  const runnerUp = ranked[1]
  const clearingPrice = runnerUp
    ? (winner.maximumAmount < a.reserve ? a.reserve
       : (runnerUp.maximumAmount + a.increment < a.reserve ? a.reserve
          : (runnerUp.maximumAmount + a.increment < winner.maximumAmount
             ? runnerUp.maximumAmount + a.increment : winner.maximumAmount)))
    : a.reserve
  const proxy = replayProxyRuns(revisions, a.reserve, a.increment)
  db.require(proxy.price === clearingPrice, 'PROXY_DRIFT')

  let releasedAmount = 0
  let rank = 0
  for (const c of ranked) {
    rank += 1
    const hold = db.get(fundingHolds, c.holdId)
    const wallet = db.get(wallets, c.walletId)
    db.require(hold !== null && wallet !== null && hold.state === 'active'
            && hold.authorizedAmount === c.maximumAmount, 'HOLD_INVARIANT')
    const isWinner = rank === 1
    const released = isWinner ? hold.authorizedAmount - clearingPrice : hold.authorizedAmount
    releasedAmount += released
    db.update(wallets, wallet.id, w => ({
      ...w,
      availableCents: w.availableCents + released,
      heldCents: w.heldCents - hold.authorizedAmount,
      spentCents: w.spentCents + (isWinner ? clearingPrice : 0),
      updatedAt: ctx.now(),
    }))
    db.update(fundingHolds, hold.id, h => ({
      ...h,
      capturedAmount: isWinner ? clearingPrice : 0,
      state: isWinner ? 'captured' : 'released',
      updatedAt: ctx.now(),
    }))
    db.insert(revealedBids, {
      id: ctx.newId(), auctionId: a.id, rowKind: 'standing', bidderId: c.bidderId,
      sourceId: `standing:${c.id}`, revisionNo: c.revisionNo,
      maximumAmount: c.maximumAmount, submittedAt: c.rankedAt, finalRank: rank,
    })
    db.insert(auctionNotices, {
      id: ctx.newId(), auctionId: a.id, recipientId: c.bidderId,
      kind: isWinner ? 'won' : 'lost', createdAt: ctx.now(),
    })
  }
  for (const r of revisions) {
    db.insert(revealedBids, {
      id: ctx.newId(), auctionId: a.id, rowKind: 'revision', bidderId: r.bidderId,
      sourceId: `revision:${r.id}`, revisionNo: r.revisionNo,
      maximumAmount: r.maximumAmount, submittedAt: r.submittedAt, finalRank: 0,
    })
  }
  for (const run of proxy.runs) {
    db.insert(revealedProxyRuns, { id: ctx.newId(), auctionId: a.id, ...run })
  }
  const settlementId = ctx.newId()
  db.insert(settlements, {
    id: settlementId, auctionId: a.id, winnerId: winner.bidderId, winnerHoldId: winner.holdId,
    chargeAmount: clearingPrice, releasedAmount, state: 'settled', createdAt: ctx.now(),
  })
  db.update(auctions, a.id, row => ({
    ...row, state: 'closed', hasWinner: true, winnerId: winner.bidderId,
    winnerMaximum: winner.maximumAmount, clearingPrice, closedAt: ctx.now(), settlementId,
  }))
  return { outcome: 'closed' }
})

schedule(closeAuctionTx, { at: a => a.closesAt, key: a => a.id, principal: 'system' })
```

Under `system`, read rules on commitments/holds/wallets are true (hoisted `principal.kind`). Writes to foreign wallets pass only because those update rules contain `|| principal.kind === 'system'` — which also admits **any other** scheduled mutation that patches any wallet. §7’s sentence “writes are bounded owner rows selected by the schedule key” is a comment, not a rule checker: wallet keys are shape-from-scan, not the schedule key.

Certificate (system): examined ≤ 1+128+512+128+128+2 = 899; writeSites ≤ 1+128+128+128+128+512+512+1 = 1538; `maxSteps` includes 512 inner sorts of ≤128 (**`E_STEPS` risk**, default G unspecified **[inferred]**). Prediction n/a (schedule). If a client predicted it: **partial** (hidden commitments absent from the receipt).

`All<T,128>` does not, as written, require proving the read rule is tautologous on the `cap` group. That is the hole.

### 6. Language delta

Ranked by what this app actually needed.

1. **`E_STRUCTURAL_RANK` / `All` only when the read rule is hoisted-true on the `cap` group.** Today a `Page`/`All` reduction (`sort`, `take 1`, `[0]`) is exact over *authorized* rows and may be written back as a *resource* fact. Smallest addition: refuse a reduction of a scan whose read rule is not tautologous for `principal.kind !== 'system'` unless the result is not written to a public/resource row; diagnostic paste = “schedule this mutation; `require(page.length === maintain.count)` is not a substitute for admission.” General. Amends §4.4, §9. (This is the K2-class finding.)

2. **Update predicates over `(old, new)` and/or per-field / per-mutation write grants.** One `update` expression per table cannot be simultaneously: seller publish, bidder anti-snipe, system winner, hold amount-increase-only, hold state system-only. Smallest addition: `update: (old, neu) => ...` plus `immutableExcept({ fields, principal: 'system' })`. General. Amends §3, §2 constraints.

3. **System-only (non-client-callable) mutations.** `schedule` invokes a named mutation; mutations are client-callable by default **[inferred]**. Smallest addition: `mutation({ ..., callable: 'system' })` or `schedule` of an anonymous body. General. Amends §1, §7.

4. **Schedule: live `at`, composite key, `if` guard, args from trigger row.** Spec example keys by `a.id` and generation-fences *schema* successors. Anti-snipe needs `at` to move, `if: a => a.state === 'open'`, optional `args: a => ({ generation: a.closeGeneration })`. Smallest addition: those three fields; define same-key enqueue as *reschedule*, not no-op. General, this app is the example. Amends §7. (Auction-specific: treat `closeGeneration` as a schedule generation, not only schema succession.)

5. **Named mutation call inside a program** (`db.run(closeAuctionTx, { auctionId })`) with summed certificates. Repair otherwise duplicates close or becomes a non-atomic effect. General. Amends §4.2.

6. **`maintain.max` / mixed-direction indexes are not the fix** (and `maintain.max` is not in §2). If added, they still fail seal-then-reveal (time-independent `readable`). Do **not** amend §4.4 by adding `argMax`. Strike the auction sentence instead. General.

7. **Nullable columns, principal type, enum/transition constraints, `int` checks (`>= 0`).** Smallest: `id({ optional })` / `int({ min: 0 })` / `text({ enum: [...] })` with declared transitions. General. Amends §2.

8. **Write-amplification / `maxSteps` defaults published as numbers.** Close is ~900 reads, ~1500 writes, 512×sort(128). Without G, class is un-certifiable. General. Amends §5.

9. **Outbox as a declared effect subscription** if “notify” is push. Smallest: `effect` already exists; add `onInsert(auctionNotices, pushNoticeDelivery)`. General. Amends §1/§8-adjacent.

App-specific (do not add): eBay-style proxy engine, card capture in the SQLite tx, clock-gated `read` rules.

### 8. Where the design is wrong

Not taste. Exposed by forcing v0 spelling.

1. **Public/client `closeAuctionTx` plus elevated ranking is not a “hand-audited exception”; under v0 it is an admitted wrong program.** Completeness of `scan(take: 128)` is authorized-row completeness. Confirming observation: as bidder B, invoke the naive close on an auction A is winning; if `check` emits a plan, the commit writes `winnerId = B` and public standings of size 1.

2. **Winner, deadline, and occupancy live on one `update` surface shared by seller, bidder, and system.** The design treats Snapback owner-policy + JS as if field grants existed. v0 rules make `placeMaximumBid`’s anti-snipe patch legally the same as `closesAt += 1e12` or `state = 'closed'`. Confirming observation: admit a second mutation `stall(auctionId)` that only patches `closesAt`; a losing bidder prevents close forever without violating a rule.

3. **§7 schedule as specified does not implement the design’s generation-carrying job.** `key: a => a.id`, args `{ auctionId }`, “generation-fenced” = schema succession. Anti-snipe correctness then hangs on an unstated reschedule-on-`at`-change. Confirming observation: bid in the anti-snipe window; inspect the pending run; if `at` is still the old `closesAt`, the primary closer never fires at the new time and only the 1m repair closes (or an in-flight run that did not OCC the auction row reveals early).
