## Material concerns + remedy

1. **§§1,6 — feasibility unproven.** Transport alone cannot explain 30s→3s given dev CPU profile; §6 lists "reuse immutable images, batch index changes" with no mechanism, proof, or byte cost. Remedy: gate §6 on production profile; enumerate at most 2–3 candidate hot paths with invariant (validation preserved, cold-rebuild equivalence, byte budget each), or explicitly scope this plan to transport+ack milestone and keep 2–3s objective open per §8 without claiming it.

2. **§§3–4 — chunk/batch/commit ambiguity.** §3 batches ≤16 pages; §4 says "bound local commit group accordingly, even when transport batch contains more pages" plus "one transaction per chunk." If a batch splits into N commits, checkpoint atomicity, continuation cursor, and failure resume are undefined. Remedy: define `batch` (wire) vs `commit-group` (one `commitMany` + one checkpoint write); require checkpoint per commit-group; state resume replays from last committed group idempotently.

3. **§3 — authority inside batch.** "Reauthenticate each request; if yields, recheck" leaves inter-page revocation within one owner action ambiguous. Remedy: require no yield inside a batch, or recheck authEpoch/generation/schema + revocation between complete executions before executing next page; stale mid-batch pages must abort batch, not commit.

4. **§3 — byte accounting.** "Accumulate lengths once including framing" risks O(n²) reserialization warned against in owner audit. Remedy: require incremental encoded-length counter, no re-serialization of growing array; oversized-first-page exception already stated — keep it and test it.

5. **§5 admission — fencing and size.** "Up to 16 ops in one turn/transaction" omits generation/program single-read, ledger-lock scope, grant-increment shape, and key-byte bound. 16×50=800 events may overflow 256 KiB journal. Remedy: read grant/bounds/program once under ledger lock, capture lifecycle generation before admission and recheck immediately before commit, never hold lock across I/O, preserve follower/foreground order via existing serial order; add key-byte bound and split rule; state whether one grant increment with consecutive offsets or N increments.

6. **§5 settlement — "sufficiently current" tail undefined.** Grouped settlement of nonempty-effect terminals with one tail is the highest-risk correctness point; unrelated global seq is not effect arrival. Remedy: give exact predicate (authority match for every terminal, seq covers every relevant effect range, no overlay/prediction, rechecked in atomic swap); enumerate which proofs permit grouping vs require separate tails; preserve per-intent waiter notification only after durability.

7. **§§1–6 — byte/source budget without plan.** New drain-batch form, framing, checkpoint, admission batch, replay-batch form, prefix settlement + §6 work cannot fit in 976 B without deletions. Plan says "fund by deletion" but names none and drops the 1,500 source-line constraint from context. Remedy: add per-mechanism byte budget + named deletion candidates (duplicate decode/normalize passes, redundant copies, single/many unification) measured by canonical five-root check; restore source-line cap; keep "no automatic new baseline."

8. **§7 — experiment gaps.** "Require all 20 samples" contradicts "report censored bounds"; production vs dev bundling not restated in §7; timestamp definitions missing. Remedy: qualification requires 20 uncensored samples with exact row hash, all acks settled, receipts true; censored runs disqualify and are reported as bounds; require identical production bundling/app/compiler/fixture/host for both variants plus retained dev control; define first-useful-view / foreground-admission / query-readiness / heap / durable-bytes timestamps; require fully-unreceived fixture comparison in identical cohorts only.

## Simplify / delete

* Prefer existing persisted page chain over new private checkpoint if it gives same safe resume; require equivalence note before code, not "before code review."
* Delete prefetch from v1; allow at most one bounded prefetch only as follow-up with proven cancellation/authority guards.
* No new route, no streaming framework, no second index schema, no speculative caches, no whole-acquisition React suppression — already excluded; keep excluded.
* Unify single/group ack admission and terminal paths into one implementation; do not keep parallel bulk worker lifecycle.

Ready when: chunk/commit scope fixed, admission fencing + tail predicate exact, byte budget with deletions named, §6 bounded or rescoped to milestone, and §7 censored-sample/production-pinning clarified.
