## 8. Wave-21 release evolution

Implementer: Codex for Charlie Cheever (EVOL), 2026-10-21; target 0.4.37.
This amendment supersedes the insert-only input policy in §3. Ordinary
writes while the exact declaration is active refresh existing native input
fingerprints. They do not create native birth evidence for migrated rows.
Active forward receipts refresh only actually edited, currently authored
non-output inputs and their reference lifetime bindings. Overwritten historical
inputs, original output preimages, omission interpretations on unrelated
writes, inactive receipts and immutable definitions retain their custody.
An older-release edit does not receive this refresh. At re-entry a changed
input is compatible when deterministic recomputation over the assembled source
produces the exact stored output; an incompatible edit without accepted native evidence still refuses.
Valid native outputs written under the owning declaration remain authored
values, even when they differ from the historical transform. Refresh replaces
the fingerprint, rather than accumulating old accepted images.

Rename destination conflicts consult only physically present or retained cells.
An absent optional destination is absent; interpreting it as null or a default
cannot manufacture a conflict. Explicit present null is still a real cell.

SEC6 owns rule-changing deploy review items, write intent, projection privacy
and client session validation; EVOL does not change those contracts.


A table declares `table observations renamed from behaviors:`. It moves the
same numeric table identity and row/reference lifetimes, never copies rows or
merges independent histories. Both names cannot appear together in a selected
schema. The durable name relation permits old-source rollback and older-source
writes to return under the newer name. Existing independent destination storage
refuses atomically. Indexes, retained type definitions, asset homes and migration
receipts follow that identity; literal values and operation names do not change.
Store format 8 and the release-table-renames-v1 capability fence the new metadata.

`rollback --check --bridge DIR` now writes the selected target's complete source,
loosening only differing compatible value domains to their union with current
source and retaining new authoritative tables with their current rules. It lists
changes and target operations reading affected tables. It never changes immutable
source or activates automatically. The generated bridge is a new deployable
release, subject to ordinary compilation/adoption. Incompatible nominal types,
new business logic, current guards absent from v1, and old UI assumptions about
null require explicit review; diagnostics and the app-specific checklist remain
visible. A retained new table does not claim a frozen v1 operation exposes it.
No reverse projection fabricates an asset, reference, list element or missing
table. Scalar `down` remains the answer for a truthful scalar substitution;
loosened bridges cover nullable files/images, empty image lists and optional
money without invented placeholders.

Preview causes are recorded by the actual narrowed-population closure: a column
and incompatible value category, or a typed reference to a hidden parent. Counts
may overlap across causes and are schema populations before read rules. New-table
rows have a separate cause. Foresight consults declared reverse writers rather
than calling their old output absent. SEC6 owns review-item resurfacing.

Asset columns (`file`, image/video and asset lists) use `renamed from` as an
identity move, rather than computed scalar forward/down substitutions. The
active and retained physical cells and the ledger's one home move together;
selecting old source changes the public name back, preserving current values.
Both aliases cannot be active together; a conflicting physical/retained cell
refuses atomically. Reference/captured/engine field renames remain excluded.
Older runtimes refuse store format 8; device projections omit migration metadata.

Cross-table historical existence and unique point reads are first-class
backfill inputs under §2's assembled-source, metered system authority. A guide
example must include the source index and explicit row input rather than an
application reconciliation loop. Outputs remain disjoint scalar patches and
all declarations observe the same pre-patch snapshot.

`fileText(file)` is a migration-only deterministic input, accepted in backfill
and down expressions, including through pure helpers. It reads the immutable
retained file named by the ledger, as UTF-8. It never reads an application path
or URL, unverified bytes, arbitrary ids, or a device's filesystem. The runtime
requires an internal migration context and charges the job heap and step meter
before reading at most the ledger byte length plus one. Absent bytes, released
assets, length disagreement, invalid UTF-8 or meter exhaustion refuse the whole
adoption. Preview reads the same original immutable asset root while writing
only its private database snapshot. The feature creates no user-callable
migration operation and does not make arbitrary file contents readable to users.
`nonemptyLines(text)` counts trimmed nonempty lines, including repeated entries
separately; CRLF and whitespace-only lines have their ordinary text meaning.
It is a pure scalar transform; an empty textual list counts zero. A generated
scalar is reversible through the existing output-preimage/evidence custody;
fileText never mutates the bytes or their home. Ordinary new-order byte validation
is outside this release-migration primitive; it receives no invented enforcement
claim from a historical backfill.


### EVOL review clarifications

“Exact declaration” means its normalized typed-IR digest, not a release number.
A declaration can be carried in later source. “Currently authored” means a
column present in that selected schema whose interpreted value actually changes
in an application write; hidden inputs and overwritten migration arguments are
excluded. “Older-release edit” means a write while this exact declaration is
absent. Replacing accepted non-output inputs intentionally forgets their previous
live values: this is live data, not a history of every application write. It
never forgets an overwritten output's reversal preimage. For migrated rows the
parent's dependency/output comparison still applies, with exact recomputation
agreement added for both transformed and fully reversed cells. Native rows with
matching refreshed non-output fingerprints and valid complete outputs preserve
their authored images. A fingerprint mismatch needs full recomputation agreement
or refuses; it never authorizes overwriting a different authored image.

A helper inherits the migration context transitively when expanded. Calling a
helper containing fileText outside a backfill/down refuses during compilation;
raw IR also refuses at execution without the unforgeable internal context/root.
Failure in a forward migration, down, or exact preview aborts that entire
transaction. Preview has the identical job precharge and file validation.
File-read failures never print raw bytes. Output scalars are deliberately
authored data under their destination rules; an author copying file text into
a readable text column must choose its audience explicitly, as for any backfill.
No automatic output or diagnostic exposes the input bytes. Asserted missing
points refuse the whole operation. Nullable points preserve §2's ordinary
nullable semantics only through the author's explicit expression; no missing
point becomes an invented preimage. The database snapshot pins ledger and point
reads; asset bytes are immutable under their ledger id, read at exact length.

Rename conflicts compare a destination cell not owned by the moving alias in
the same surviving row lifetime. They do not compare the source cell against
itself or consult dead row lifetimes. Table moves keep their numeric identity;
independent destination identities cannot be merged. Asset renames never revive
a released asset. A selected schema still validates every moved asset against
the ledger/type. Reference, captured and engine-field renames are diagnosed
before activation, rather than silently losing their bindings.

The bridge's compatible joins are: identical underlying types with optionality
union; same-format text with the lower minimum and higher maximum; enum member
union; lists with recursively compatible element types, lower minimum and higher
maximum. Other nominal/type conversions are not guessed; they remain target
domains, are listed for explicit typed repair, and receive no promise of complete
visibility. Existing compiler diagnostics and the checklist expose operations
needing adaptation; readers AND writers on affected tables are listed. The
bridge never executes a scalar asset projection: it changes only the selected
schema's value domain over the same retained actual cells. Old nullable UI
assumptions remain an application compatibility check, not a claimed guarantee.
It keeps one alias for a renamed table, selecting the target's spelling; the
other name remains only in the durable identity relation. That spelling routes
old reads/writes to the same numeric row lifetime. It never adds both aliases as
independent tables. Existing target rule/intent text remains byte-identical;
new tables retain current rule text. Ordinary deploy preview reports current
safeguards the target lacks. SEC6 owns rule-review resurfacing; EVOL adds no
blocking review gate or invented safety guarantee.

A cause is either `(table,column,incompatible-value-category,target-type)` or
`(table,column,hidden-parent-table)`. Activation first hides incompatible rows,
then iterates typed reference edges until no additional dependent hides. Only
previously active rows contribute to these preview counts. A row may have more
than one cause, so cause counts are explicitly non-additive; total hidden rows
are distinct. New-table rows are counted separately. Static foresight compares
possible future domains and declared reverse writers; exact preview runs the
actual activation against current data. Both are privileged local operator
outputs, never per-user query results or public HTTP metadata. Private preview
writes are removed, never published to the live database or generation.
