1. **N1 — High: the conjunct pre-check exposes a hidden probe that row evaluation would never execute.**

   Use this rule, with one unchanged message owned by Bob:

   ```quarry
   read <- .principal = viewer and exists permits[.roomId, viewer]
   ```

   Alice reads room `r`. W0 lacks the permit; W1 contains an unreadable permit, expiring at future time T. Keep inputs, readable rows, clock and sequence equal.

   Previously, the first conjunct denied the candidate before probing permits. Now [rules.rs:36](snapback4/crates/snapback4-core/src/engine/rules.rs:36) extracts the later probe, and [read.rs:73](snapback4/crates/snapback4-core/src/engine/read.rs:73) executes it first.

   With ample budgets, both worlds return `[]`, `complete: false`, `next: null`, no cap, identical `tables = ["messages","permits"]`, and no error. But their meters differ:

   | Read | W0 → W1 |
   |---|---|
   | Plain page, Cap | `examined`: 0 → 1 |
   | Plain page, Abort | `examined`: 1 → 2 |
   | Matching page, Cap | `examined`: 0 → 1; `index_entries`: 0 → 2 |
   | Matching page, Abort | `examined`: 1 → 3; `index_entries`: 0 → 2 |

   For a direct single-scan IR using literal `r` and `cof`, with the hidden message containing `coffee`, matching also adds two steps and seven heap bytes in W1. Plain-page steps and heap remain equal. In all four cases, `rule_probes` stays 1, `output_bytes` remains equal, and `rows_written` stays 0.

   More seriously, **`nextExpiry` changes from null to T on the public response**: the partial true verdict retains the probe expiry, and subsequent row denial restores that already-contaminated mark. See [read.rs:569](snapback4/crates/snapback4-core/src/engine/read.rs:569) and [serve.rs:900](snapback4/crates/snapback4/src/serve.rs:900).

   At an examined ceiling of zero under Cap, only W1 sets `capped_at`; at a ceiling of one under Abort, W0 succeeds and W1 returns `E_BOUND`. A direct matching read with a malformed cursor also succeeds in W0 but reaches cursor validation and refuses in W1: denial precedes the generated merge’s validation at [read.rs:373](snapback4/crates/snapback4-core/src/engine/read.rs:373).

   The new paired regression keeps the denying permit absent and varies message population; it does **not** construct this reversed-conjunct pair ([read_verdict/mod.rs:107](snapback4/crates/snapback4-core/tests/read_verdict/mod.rs:107)). Early decisions need a proof that their inputs are readable, or equivalent observations across their outcomes.

2. **N2 — High: a statically true self-probe becomes a false pre-check.**

   With a total unique `(roomId, principal)` index:

   ```quarry
   read <- exists messages[.roomId, .principal] and .body = 'coffee'
   ```

   A real `coffee` row witnesses its own probe. However, `prefix_decision` includes the self-probe because `uniform` includes `decided_true`; it then evaluates it against a synthetic room-only row. The missing principal becomes null, the probe fails, and both plain and matching reads incorrectly return no rows, under either cut mode.

   Evidence: [rules.rs:68](snapback4/crates/snapback4-core/src/engine/rules.rs:68), [rules.rs:129](snapback4/crates/snapback4-core/src/engine/rules.rs:129), and [read.rs:74](snapback4/crates/snapback4-core/src/engine/read.rs:74). No added regression constructs this case. Proven-true conjuncts must be simplified away rather than executed against an incomplete image.

3. **N3 — Medium: fixing #9 loses retained history when it contributes to the returned result.**

   Extend the two-room fixture to:

   ```quarry
   query both():
     leftRows = messages['left'] last 50 by byTime
     heldRows = messages['held'] last 50 by byTime
     return { left: leftRows, held: heldRows }
   ```

   The device has 25 retained left rows and 25 of 26 held rows. The new classification sets `retained: false` because the held read is unknown. Whole-query fallback then returns `{left: [], held: [26 rows]}`, discarding retained history from the displayed answer. Offline, the left rows reappear.

   The classification remains query-wide: [local.rs:111](snapback4/crates/snapback4-core/src/engine/local.rs:111), [device.rs:547](snapback4/crates/snapback4-device/src/device.rs:547), and [local.ts:658](snapback4/packages/snapback4/src/local.ts:658). The new tests return only the held result. They do not establish result/read-site provenance or preserve a returned retained component.

4. **N4 — Medium: SQL default substitution uses the literal’s variant instead of the column’s projection format.**

   Adopt `meta: json <=100 default false`. An old absent field projects as SQL integer `0`; an explicitly stored equivalent value projects as tagged JSON text `{"Bool":false}`. SQL equality and grouping therefore distinguish two logically identical values. With `default 'Null'`, the old value is additionally converted to SQL null.

   The default branch unwraps scalar literals even when the declared column uses the compound/tagged projection: [sql.rs:51](snapback4/crates/snapback4/src/verbs/sql.rs:51). Such JSON literal defaults are admitted by [defaults.rs:27](snapback4/crates/snapback4-lang/src/bind/defaults.rs:27) and [validate.rs:110](snapback4/crates/snapback4-core/src/engine/validate.rs:110). The inspection regression covers scalar-typed columns, not JSON.

The dependency-list registration itself now handles the original short-circuit pairs. Explicit `WordRead` arguments also remove the original nested-read inheritance mechanism in both cut modes.
