Material counterexample: relocated-adapter detection only matches named `ImportSpecifier` forms, so a namespace (or default, or re-export) consumer passes `check` with a stale default asset.

I verified this against the built binary with a scratch project (nothing in the repo touched):

```sh
# app/app.json: {"typescript":{"sources":{"backend":"../snapback/generated","replica":"../renamed"}}}
# renamed/snapback.ts:
import * as web from './web.ts';
export const x = web.webDevice;
# renamed/web.ts:
import * as gen from './generated/device.ts';
export const y = [gen.initSync, gen.WebSnapback];
# app/assets/snapback4.wasm: leftover unstamped bytes
check: ok — 0 tables (0 synced), 1 operations, no problems
status=0
```

The equivalent named-import form (`import { webDevice } from './web.ts'` + `import { initSync, WebSnapback } from './generated/device.ts'`) correctly fails with `E_DEVICE_VERSION`. The namespace form loads the same runtime modules and references the same device exports, so it is an actual device consumer under the spec ("gate actual device consumers"), but `source_literals` drops it: `ImportNamespaceSpecifier`/`ImportDefaultSpecifier` hit the `_ => self.names.is_none()` arm, which is false when filtering for `webDevice`/`initSync`/`WebSnapback`. `export { webDevice } from './web.ts'` re-export chains miss for the same reason (only `ImportDeclaration` is visited). The shipped [wire.md](/home/ccheever/projects/sb4-w10-gate/snapback4/crates/snapback4-lang/src/guide/wire.md) overclaims here ("relocated device adapters are recognized by their runtime web-device imports"), which reads broader than named-only.

- Any single Oxc diagnostic discards all literals from that file; documented as "left to Exact's compiler," but a broad threshold for a security-relevant discovery.

Fix suggestion: treat namespace/default specifiers and `export ... from` re-exports with matching module sources as runtime-establishing for the two-step relocated signature, and add the namespace/default/re-export forms as regressions alongside the existing type-only negatives.
