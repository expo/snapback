## Findings by area

**Clock reports.** Sound and already corroborated in-tree: `schedule_report` partitions every schedule into fired/held (`outcomes()`), the serve reply retains `schedules` additively ([serve_maintenance.rs](/home/ccheever/projects/sb4-b20-dx5/snapback4/crates/snapback4/src/serve_maintenance.rs:448)), `ClockAdvance {now, fired, held}` exists in `proof.ts`, the CLI prints the whole JSON body (additive, existing consumers kept), and `SESSION_NOTICE` already avoids dev-door instructions. The equal-boundary case is covered (`saved >= current` yields `saved-boundary`, printed by both CLI and helper). Reply-size doubling from the partition sits under existing byte budgets plus the 64 MiB exchange bound. No public-API break, no new authority.

**Source diagnostics / existence oracle.** The runtime already satisfies the key invariant, so this block is advice-plus-tests, not a behavior change — good for privacy scope. Verified: hidden unique conflicts hit `visible_collision` → generic `Rule` refusal before any authored `else CODE` is consulted ([write.rs](/home/ccheever/projects/sb4-b20-dx5/snapback4/crates/snapback4-core/src/engine/write.rs:800)); authored codes return only after the conflict passes the readability check; and the public `E_RULE` text is already uniform across ordinary denial and hidden collision ([error.rs](/home/ccheever/projects/sb4-b20-dx5/snapback4/crates/snapback4-core/src/error.rs:387)). The advice is static source-level (allowed per §15.2), names no row/key/meter, and the paired hidden/ordinary equality tests directly pin the oracle shut. One clarification worth one sentence at implementation: at a required read of an update/delete-target table meeting lane-001, both `N_LOOKUP_HIDDEN` and the extended `N_LOOKUP_FILTERED` could fire; the "one note … duplicate HIDDEN avoided" sentence reads as FILTERED-wins, but stating precedence explicitly (and the consequent §15.2 touch-up) would remove implementer guesswork. Noise-level, not safety-level — either choice is static advice with no row disclosure.

**Upgrade reaches old CLIs.** The mechanism hangs together: old-CLI `upgrade.js` resolves the post-install `check` in a fresh process from the project root, so after package replacement it executes the *new* wrapper — which is exactly why a wrapper-side first-check warning backfills old CLIs whose pre-install scan lacks the `data --json` candidates. Constraints are coherent (stderr-only, JSON stdout preserved, fail-open on marker errors, baseline excluded). Two small implementation notes: the per-installed-version marker needs a name/location distinct from the runtime-history receipt (design implies but never names it), and the post-install `check()` that `upgrade.js` spawns will itself count as an "ordinary check," so users will see the warnings twice (pre-install + first-check) unless the post-install invocation carries a suppress flag. UX wart, not a correctness blocker; acceptance tests as specified will catch marker bugs.

**Frontend/starter custody.** `ReadState` is fully determined by the existing contract: partial/stale answers are already data (`useQueryData` docs), empty array is data, `denied` throws `QueryRefusal` — so the four-state mapping has no precedence gap, and "no subscription/cache/authority" follows from taking the read/PageHook as a prop (both types exist). Expo items are sound: the pnpm hazard (transformer resolving upstream from its own package dir instead of the consumer's) is correctly named, CJS matches existing starters, `withSnapback` encapsulating the current config mutations is straightforward. Adapt replacing only untouched todo proofs into a refusal-scaffold (custom proofs never rewritten, detection machinery exists in `adapt.rs`/`proof_advice.rs`) plus testing the expected refusal is the truthful shape; copies-not-originals for the metrics is the right call.

**Proof truthfulness.** Strong throughout: packed-tarball qualification, old-CLI-vs-new-package tests in an isolated registry with an explicit ban on new-helper-only claims, expected-refusal assertions. No `test.sh`/publish/push authorization.
