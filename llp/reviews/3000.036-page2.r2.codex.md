**Overall: NOT READY.** PAGE2 has one admission-contract inconsistency; timed disclosure has three material gaps.

**PAGE2 (§15): NOT READY**

1. **The admission conditions contradict the promised nullable-unique case.** Condition 1 requires the selected probe to use `id` or a declared **total** unique. The preceding paragraph nevertheless admits a nullable unique when discovery has an applicable cap.

   Counterexample: `members.parent` is optional, `unique parent, principal` is nullable, and `cap 50 by principal` bounds discovery. A document’s required parent supplies a non-null probe argument. The nullable-unique paragraph admits this shape, but numbered condition 1 rejects it regardless of the cap. Planner, validator and Lean emitter therefore have no single specified admission rule.

   **Fix:** condition 1 should require an exact plain unique probe, allowing nullable uniques. Condition 2 should separately require the selected point to be total, discovery to be a fully pinned total unique, or discovery to have an applicable cap. Retain the explicit no-witness treatment of null point components.

The uncapped discovery fence, heap admission, row-id ordering, shared cursor and capability refusal otherwise form a coherent design. I found no additional material PAGE2 gap.

**Time audiences and timed disclosure: NOT READY**

2. **A mutation can remove an unprocessed opening without publishing its membership join (§§3.2–4).**

   Concrete sequence:

   - A membership is stored with `opensAt = 10`.
   - At server time 11, the bounded advancement processes an earlier prefix and leaves this membership pending.
   - An authorized mutation directly updates its opening to 9, returning no row.
   - Under the specified time-based predicate, both stored images are already live: accounting takes `live -> live`, rather than establishing the unpublished membership.
   - Its new opening is before the pinned floor, so pending-index maintenance removes the old entry without scheduling another opening.

   No boundary transaction remains to establish the group join and acquisition. Server authorization can recognize the membership while incremental device delivery lacks its acquisition.

   The read-unavailability rule does not resolve this: the proposal explicitly permits internal write-target resolution, and this mutation needs no application read.

   **Fix:** explicitly gate mutations on unfinished advancement for their affected tables and authorization dependencies, or transactionally reconcile an addressed pending opening before ordinary image accounting. Publication status must remain distinguishable from mathematical liveness until reconciliation finishes.

3. **Never-live entries can change public availability, contrary to §4’s guarantee.**

   Compare an empty table with the same table containing more than one advancement batch of rows whose `expire <= not_before`. At their opening time, the second world exhausts the advancement ledger while discarding entries. Its due cursor remains behind, so the specified table gate makes a read unavailable; the empty world returns a complete negative answer.

   This reveals an otherwise invisible population through availability and retries, despite the explicit promise that never-live entries produce no availability change.

   **Fix:** keep provably never-live entries outside the publication backlog, maintaining that classification transactionally across writes and adoption. Define the availability gate using unfinished work that can establish a logical transition. Alternatively, explicitly relax the disclosure guarantee and specify the resulting channel.

4. **The guarantee that every opening fits an empty batch lacks an admission mechanism (§4).**

   A single future membership can serve as the audience witness for many synced content tables. Its insertion publishes no joins, but its eventual opening requires one join per affected table. An accepted schema can therefore make one opening exceed the fixed accounting-work or serialized-event limit.

   Committing a smaller prefix cannot help when that opening is the first entry. Retrying cannot make it fit, leaving a permanent backlog obstruction.

   **Fix:** define and enforce opening admission at schema adoption and future-row insert/update. The bound must include the complete event envelope, audience fanout, private-owner deliveries and accounting scratch. Refuse an oversized shape before accepting pending work, with a located diagnostic. Include schema changes that increase an existing pending row’s fanout.
