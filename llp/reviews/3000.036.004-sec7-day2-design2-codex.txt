# llp-orient

<!-- @ref https://github.com/ccheever/llp/blob/v0.5.2/llp/0008-distributed-agent-skills.rfc.md#the-skills--core-five-plus-flags — skill contract -->
<!-- @ref https://github.com/ccheever/llp/blob/v0.5.2/llp/0000-linked-literate-programming.explainer.md#2-reference-syntax — the grammar this reads -->

Load the design rationale governing the area you're about to touch, before touching it. This is the consumption side of LLP — orienting first is what turns `@ref` from a possibility into a habit.

Invoke as `/llp-orient <path-or-task>` (file, directory, subsystem, or task description). With no argument, use the current change scope (`git diff --name-only`).

## Trigger

Start of a coding task that touches an area with documented design. The orient-first *rule* lives in the repo's always-loaded `AGENTS.md`; this skill is the detailed form that rule routes to for non-trivial work — don't rely on ambient description-match alone.

## Invariants

- MUST be read-only: never edit code or LLP documents.
- MUST scope to the task: pull the constraints that bind this change, not a corpus summary.
- MUST cite, not restate: reference policy as `LLP NNNN#anchor` rather than paraphrasing sections.
- MUST NOT invent constraints. If something isn't documented, say so.
- MUST NOT guess the rationale behind a broken `@ref` — report it and hand off to `llp-maintain`.

## Workflow

> **Recipe (advisory)** — corpus root = nearest `llp/` walking up from the path in scope (LLP 0001 §Unit of adoption); "no corpus" is an empty walk, not cwd-relative absence. Read `llp/foundation/` first (the kernel; the root LLP is there once `Active` — on a fresh adoption it is still `Draft` and sits in `current/`), then skim `llp/current/` (the declared working set); both hold relative links — symlinks, or small files containing the relative path — so `ls` answers and either form resolves. Then the root LLP's systems vocabulary. `Grep '@ref'` over the files in scope and `Read` each target — these are the highest-signal context. `Grep` the `**Systems:**` headers across `llp/` for LLPs governing the subsystems touched; read the governing ones (Spec, Decision, Principles, relevant RFCs). Follow `Related:` and nearby `@ref` targets one hop out; stop there unless something is clearly load-bearing. Stale-pin nudge (skip offline): read the installed tag from the skills receipt (or a `source:` pin), compare `git ls-remote --tags <origin>` — if upstream is newer, say so in one line ("skills at v0.3.0, upstream v0.5.2 — run /llp-adopt update") and move on; never update from here.

## Artifact

A context pack with these sections, faster to read than the documents it points at:

- **Scope** — files / subsystems queried
- **Governing LLPs** — numbered list, one-line gloss each; mark which are in `foundation/` and which are in `current/` (in-flight — its guidance may still move)
- **Active constraints** — bullets, each citing `LLP NNNN#anchor`
- **Relevant rationale** — the *why*, same citation form
- **Open questions / risks** for this area
- **Likely doc updates** if the change lands
- **Hand-off** — one of `none | llp-adopt | llp-create | llp-review | llp-maintain`

## Hand-offs

- No corpus (no `llp/` walking up from the path in scope) → `llp-adopt`.
- The task needs a decision no LLP covers → `llp-create` (or `llp-review` if proposal-shaped).
- An `@ref` target or anchor doesn't resolve → `llp-maintain`.

# LLP 3000.036.004: Security invariants and exposure

**Type:** RFC
**Status:** Accepted (SEC design revisions 3/5 and SEC2 amendment/implementation round 5: Muse and fresh Codex READY; qualification in progress)
**Systems:** Snapback 4 Quarry authorization, check, audit, generated security tests, validation
**Author:** Codex for Charlie Cheever (SEC)
**Date:** 2026-10-18
**Revised:** 2026-10-22 (SEC7 §16 design: Muse and fresh Codex READY; implementation qualification in progress); previously 2026-10-21 (SEC5 §14 and SEC6 §15; both independently reviewed; SEC6 scoped qualification complete; code snapshot4578e98bed)
**Related:** [LLP 3000.036](./3000.036-what-the-app-farm-asks-of-the-rule-language.rfc.md), [LLP 3000.035](./3000.035-quarry-semantics-in-lean.plan.md), [LLP 3000.014](./3000.014-a-child-reads-through-its-parent.rfc.md), [LLP 3000.038](./3000.038-file-assets.rfc.md)

## 1. Contract

The wave-16 bakeoff found rules enforced correctly but policies encoded wrongly.
A declaration of intent is independent of the rules implementing it. `check`
reports each declaration as **proved**, **refuted**, or **unproved**. Refuted
means a concrete, replayed database/rule counterexample, never merely a Boolean
assignment. Unproved names the unsupported path or incomplete search. Neither
unproved nor a finite passing test campaign may be described as proved.

Implementer: SEC in this worktree, starting 2026-10-18. The author commissioned
this semantic extension and two independent design reviews. No version bump
or publication is part of this lane. STAGE owns provisioning/password dev doors;
RULES5 owns live-parent rule semantics; FRONT owns general diagnostic triage.

## 2. Surface

Use the existing rule vocabulary rather than invent a second policy language:

```
invariant notes.read only .patient = viewer or .clinician = viewer
invariant requests.update only .requester != viewer
invariant members.role write only exists roles[viewer, role = 'owner']
invariant photos always .image != null
```

The first target is a table, the second component an effect (`read`, `insert`,
`update`, `delete`) or a column followed by `write`. `write` checks insert and
update, including both images for ordinary updates; delete authority has its
own declaration. A column invariant only concerns writes to that column, but
must include every effective admission path. Owner-only field patches bypass
an ordinary table update rule; invariants affected by `written by` stay
unproved until that bypass is modeled. An implication from a denied table
rule must never prove such an owned-field claim.
`always` is a row-integrity assertion. Predicates parse as ordinary Quarry
expressions; unsupported policy expressions are reported unproved with the
reason. Unknown tables/columns/effects are authoring errors. Multiple source
files and multiple declarations are supported. For update intent `.field` means both old and next images for mutable
columns; named transitions require an explicit reviewed reduction or stay
unproved. Once-judged immutable/id rules need a proved equal-image reduction
or stay unproved. Both upsert arms and `insert if absent` are included, with
their own collision/refusal observations. `always` quantifies over every
committed row image from insert/update/upsert and trusted seed/import/restore/
activation, not merely mutation inserts. Constraint-based row proof must use
the actual validation on every ingress, including defaults and the exact
non-whitespace minimum function, or stay unproved.

No declaration changes runtime
authority or replaces a rule. No implicit service-seat exemption is added.

The proof fragment uses bound rule predicates. A row assertion can be proved
from its required column type/constraints (not an optional type), or otherwise
remains unproved. Aggregate/transition/temporal assertions outside that fragment
remain explicitly unproved, not syntactically discarded. Syntax with `now`,
counts, or other program expressions must retain that reason. This is a safe
extension point, not a claim of a complete solver for arbitrary Quarry.

## 3. Sound proof boundary

For a table effect, prove `admission => policy` for **every database snapshot**,
row image, ordinary authenticated viewer (including service seats) and clock.
The engine system principal is explicitly outside this quantification: it is
the trusted seed/import/job boundary, never an ordinary user or an implicit
service-seat exemption. Tables touched by system/native/job/worker paths remain
unproved absent a reviewed reduction, and audit lists those writers. This overapproximates every reachable history:
an old assignment and a changed current role are independent facts. Grant
creation never proves a current role. Required role predicates must be true at
the access boundary. No fixture-specific assumption enters a proof.

Translate Boolean connectives compositionally, retaining true/false/unknown
truth for atomic predicates. Unknown never admits and `not unknown` is unknown.
Atomic facts are keyed by their full bound structure, including table, index,
keys, named equalities and old/next image. Symmetric equality may canonicalize by operand reordering only, preserving
Value variants (Id is not Text), table, index, keys, image and predicate kind;
other equalities and probes stay independent. A finite exhaustive implication
check over this abstraction is sound because it includes every concrete
valuation, even impossible ones. Cap atoms/work; cap exhaustion is unproved.
Do not add database consistency axioms without a separate soundness argument.
Never drop, assume true/false, or simplify an unsupported admission atom;
keep it opaque with its full identity or report unproved. Concrete leaf
semantics are the current `evaluate_leaf`/`term`, not stale Lean open points:
null equals null, null differs from a non-null literal, Id differs from Text,
noninteger ordered comparison returns false, and a missing live reference
marks unknown (including under negation). Missing ordinary fields currently
load null; missing reference and missing image are not conflated. Any semantic
mismatch with the independent model is named, never normalized away. Runtime
errors do not establish an admitted result; probe/storage/schema failure
cannot be used as a successful counterexample or a proof fact.

The Lean addition proves a three-valued Kleene kernel with admission only
on Readable and the exact theorem: exhaustive checking implies that for every
valuation, eval(admission) = Readable implies eval(policy) = Readable; the Quarry-to-kernel translation and runtime boundary remain reviewed
Rust obligations, not a claim of whole-platform formal verification.

For read intent, admission includes the ordinary read rule and every bypass:
- point/list/view/filter/count/exists and live refetch use ruled reads;
- sync acquisition and publication authorize at their own server snapshot. An
  offline device cannot know a later server revocation, even with until-revoked.
  A synced read invariant therefore reports the device access path unproved
  for current-server-role intent, separately from its server proof. Delivered
  history has an additional explicit retained-history blocker. No stale local
  role is treated as a current server role;
- inherited read-through rules are checked in their bound form, including
  captures; live-parent semantics remain RULES5's responsibility;
- valued write targets already reread through `get` before returning, and
  generated insert results also use an ordinary ruled read. Verify those
  reductions against the bound IR; any escaping image without that reduction
  is a blocker or must satisfy the implication `effective write admission => read intent` for that image;
  otherwise the declaration stays unproved;
- maintained aggregates/columns and row views may expose source changes under
  different rules: report such source claims unproved unless a reviewed exact
  reduction proves them; projections narrow payload only; existence/count disclosure follows the
  derived path's own rules, so each derived path needs its own reduction or
  stays unproved;
- table-rule probes see raw target rows, unlike program `exists`. Follow
  reverse dependencies into every other table's read/write rules: the presence
  of a marker row or a successful write can disclose the protected target's
  existence or named fields without returning that target. Source privacy
  intent remains unproved for such raw-probe observations unless a reviewed
  reduction proves authorization or the policy explicitly permits disclosure;
- incoming `on delete cascade` and `on delete set null` effects bypass child
  delete/update rules. Report child delete/update/column-write invariants
  unproved when affected, including transitive cascades, until initiating
  authority and child-image policy are modeled. Enumerate these edges in audit;
- asset reads inherit their owning row privacy, while upload/write authority
  belongs to insert/update intent; applicable private-field authorities must be conjoined with owning-row
  admission for asset reads;
- jobs, schedules, native jobs, actions and external effects are trusted system
  or worker boundaries. Read claims affected by opaque outputs/side effects
  remain unproved. Job writes do not prove ordinary-user write authority;
- refusal codes are observations: an authored difference between an absent
  lookup and later denial is a reported exposure. A privacy proof must not
  ignore that path. Unmodeled constraint/refusal observations remain unproved.

Observer boundary: this verifies row payload and logical existence/refusal
observations, not physical timing, runtime cost or all resource side channels.
The platform's documented examined-count/meter-cut observations are explicitly
excluded and reported as exclusions, not full noninterference. Read intent
includes all logical exposures above. A component may be proved while the
whole declaration remains unproved because another path is blocked.

The implementation must build a closed-world census of bound IR read/write
forms and schema-triggered paths. An unclassified form is a blocker, never
silently omitted. Census includes sequence allocation/read admission, online
and device query paths, ephemeral paths, owner fields, maintained writes and
referential actions. System/job/action/native/external touched tables default
unproved without a reviewed reduction, and are listed as grant-column writers.
Every `read` declaration covers all enumerated logical paths, not just its
direct rule. Authenticated viewer classes use engine operations; signed-out
cases run only against HTTP/auth admission, never a fabricated principal.
Retained-history observations are classified by leave policy and reported
separately; they cannot refute the platform's retention contract or prove a
current-role declaration. Test output names unsupported device freshness.

The report enumerates the paths checked and blockers. A proof is never awarded
just because the direct table rule passed while an indirect path is unmodeled.
Conservative rejection/notes are acceptable; false proof is not.

## 4. Counterexamples and generated tests

Generate deterministic challenges from schema types, policy atoms and fixture

-- Daily sweep: suspend active flagged permits whose reinspection window
-- lapsed, and expire permits past their 365-day life.
job sweepPermits(periodStart: time, periodEnd: time):
  for p in permits:
    if p.status = 'active' and p.flagged and p.failedAt < periodEnd - 10d:
      update permits[p.id] { status: 'suspended', flagged: false }
      insert suspensions { permit: p.id, owner: p.owner, reason: 'No passing reinspection within ten days of the failed inspection.', suspendedAt: periodEnd }
      upsert operatorFlags[p.owner] { operator: p.owner, suspended: true }
    if p.status = 'active' and p.expiresAt <= periodEnd:
      update permits[p.id] { status: 'expired', flagged: false }

## Individual security review

Default check puts likely holes before result inventories and restating questions.
Questions about retained role grants and uploads with an explicit mandatory-media
contract require a repair or an individual disposition. They fail check without claiming an invariant refutation.
Read the note, compare it with the specification, then use
`check --ack-security ID --reason 'specification rationale'` with its current ID
from check or check --json. Bulk --ack-notes cannot clear these gates.
Commit snapback/security-reviews.json when the decision should travel with source.
Every Quarry edit, changed diagnostic or security analyzer revision requires review
again; the record never grants authority or proves safety. Audit retains the full
notes and dispositions. Declared refutations still fail and cannot be acknowledged.
Deploy --strict retains its refutation gate; run check in acceptance before deploy.

Optional arguments and optional columns are valid, including deliberate loosening.
A required child media column validates an existing attachment; it does not require
a child row. Guarded optional attachments need no acknowledgment. When independent
parent integrity intent requires a child, require evidence before creating that
parent. Without such intent, a conditional child is an advisory spec question. Reasons use text 1..N when nonempty justification is required; optional
money and constant payment/approval flags need independent specification review.
Transition advice asks whether a generic setter can bypass a stricter decision or
whether eligibility checked at creation must be rechecked at approval. Different
duration windows on one column may be deliberate: confirm them against the spec.
Role-wide write questions ask whether a global role may write every resource.
Model the owner of this particular wall; see `guide rule-recipes --section "Wall ownership"`.

### N_CREATE_EDIT_ASYMMETRY

N_CREATE_EDIT_ASYMMETRY: An argument-supplied column has a specific change guard on edit that creation does not imply. The question names that column, editor and guard, rather than a table-wide permission. Confirm creation authority against the specification; enforce the change guard at creation when required and test independent column write intent with non-null input. Exact changed-field comparisons are supported; mixed conditions, intervening writes and early-return equivalents remain outside this heuristic, with generic insert inventory retained when applicable. Absence of advice is not a safety proof.

### N_PRIVATE_CREATE_EDIT_ASYMMETRY

N_PRIVATE_CREATE_EDIT_ASYMMETRY: A caller can initialize a private column without its change guard and outside its column read audience. This question ranks above ordinary asymmetry because the caller supplies private agency data it cannot read. Confirm who may supply this field at creation; enforce the guard when required and test independent column write intent with a non-null value. Read privacy alone does not define write authority; the question is advisory.

### N_EVIDENCE_REMOVAL

N_EVIDENCE_REMOVAL: Delete, detachment or explicit clearing can remove parent-linked media evidence. The question names removing operations and the parent reference, grouping the evidence columns. Required child fields alone do not require a surviving child; confirm last-child retention against the specification. -- Staff rent a machine to a contractor. Only the branch manager may rent to a
-- contractor with an unpaid balance, recording the reason.
mutation rent(machine: machines, contractor: principal, days: int 1..30, overrideReason: text <=200 ?, checkoutPhoto: image <=10000000 ?, checkoutNote: text <=500 ?):
  isManager = exists roles[principal = viewer, role = 'manager']
  isStaff = isManager or exists roles[principal = viewer, role = 'yardhand']
  require isStaff else NOT_STAFF 'Only yard staff can check out machines.'
  m = machines[machine] ! else NOT_FOUND
  require m.status = 'available' else NOT_AVAILABLE 'This machine is not available to rent.'
  owed = unpaidOwed[contractor] ?? 0
  if owed > 0:
    require overrideReason != null and isManager else UNPAID_BALANCE 'This contractor has an unpaid balance; only the branch manager may rent to them, recording a reason.'
  r = insert rentals { machine, contractor, dailyPrice: m.dailyPrice, deposit: m.deposit, startsAt: now, dueAt: now + days * 1d, overrideReason, checkoutNote }
  insert invoices { rental: r.id, contractor, kind: 'rental', amount: m.dailyPrice * days }
  if checkoutPhoto != null:
    insert rentalPhotos { rental: r.id, kind: 'checkout', photo: checkoutPhoto }
  update machines[machine] { status: 'out' }
  return r

-- Staff take a machine back. Returned more than one day late, the contractor
-- is charged another day at the rental's daily price.
mutation returnMachine(rental: rentals, damageFound: bool, damageNote: text <=500 ?, returnPhoto: image <=10000000 ?):
  isStaff = exists roles[principal = viewer, role = 'yardhand'] or exists roles[principal = viewer, role = 'manager']
  require isStaff else NOT_STAFF 'Only yard staff can take returns.'
  r = rentals[rental] ! else NOT_FOUND
  require r.returnedAt = null else ALREADY_RETURNED 'This rental was already returned.'
  update rentals[rental] { returnedAt: now, damageFound, damageNote }
  update machines[r.machine] { status: 'returned' }
  if returnPhoto != null:
    insert rentalPhotos { rental: r.id, kind: 'return', photo: returnPhoto }
  if now > r.dueAt + 1d:
    insert invoices { rental: r.id, contractor: r.contractor, kind: 'late', amount: r.dailyPrice }
  return null

-- Staff bill damage found on the return walkaround. Only within seven days of
-- return; afterwards the deposit is refunded instead (see settleDeposits).
mutation billDamage(rental: rentals, amount: int 1..):
  isStaff = exists roles[principal = viewer, role = 'yardhand'] or exists roles[principal = viewer, role = 'manager']
  require isStaff else NOT_STAFF 'Only yard staff can bill damage.'
  r = rentals[rental] ! else NOT_FOUND
  rt = r.returnedAt
  require rt != null else NOT_RETURNED 'The machine has not been returned yet.'
  require now <= rt + 7d else BILL_WINDOW_PASSED 'Damage must be billed within seven days of return; the deposit is refunded instead.'
  require not exists invoices[r.id, 'damage'] else ALREADY_BILLED 'Damage was already billed for this rental.'
  insert invoices { rental: r.id, contractor: r.contractor, kind: 'damage', amount }
  update rentals[rental] { depositStatus: 'applied' }
  return null

-- Only the branch manager can waive a bill, recording the reason. Waiving a
-- damage bill releases the deposit back to refunded.
mutation waiveInvoice(invoice: invoices, reason: text 1..200):
  require exists roles[principal = viewer, role = 'manager'] else NOT_MANAGER 'Only the branch manager can waive a bill.'
  inv = invoices[invoice] ! else NOT_FOUND
  require inv.status = 'unpaid' else ALREADY_SETTLED 'This invoice is already settled.'
  update invoices[invoice] { status: 'waived', waiveReason: reason }
  if inv.kind = 'damage':
    update rentals[inv.rental] { depositStatus: 'refunded' }
  return null

-- Contractors pay their own bills.
mutation payInvoice(invoice: invoices):
  inv = invoices[invoice] ! else NOT_FOUND

  require inv.status = 'unpaid' else ALREADY_SETTLED 'This invoice is already settled.'
  update invoices[invoice] { status: 'paid' }
  return null
