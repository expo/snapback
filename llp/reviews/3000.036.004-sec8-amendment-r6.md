## 17. SEC8: actionable evidence, honest campaigns and durable decisions

Implementer: Codex for Charlie Cheever, 2026-10-22. Status: Review. This
wave-24 amendment supersedes the name-list restriction in §16.9 and whole-source
review identity in §§16.2/16.5. DX7 owns upgrade/gate messaging and clock/proof UI.

### 17.1 Presence and lifecycle questions

Optional media stays advisory without independent intent. Both the note and the
specification questionnaire offer `invariant TABLE always .COLUMN != null` only
for permanent integrity, and `invariant TABLE.insert only .COLUMN != null` for
creation-only presence (later redaction remains possible). The upload gate also
recognizes positive non-null conjuncts in independent insert/write intent for
that exact column; OR and unknown predicates cannot establish this gate.
The upload recipe begins with that decision. Never compile the questionnaire or
infer mandatory evidence from natural language. Existing explicit-intent gates
remain the only gates. A parent with an independently attached media child gets
an advisory when a literal enum transition lacks a dominating child existence
requirement; text photo/URL fields are explicitly labelled name-based questions.

Stale eligibility considers any literal enum update distinct from the creation
state, without interpreting words such as filled/confirmed. It still requires
mutable eligibility on the same resource and keeps the exact recheck precision
of §16.9. Approval questions cover approval-named flags ignored by lifecycle
writes, and fields checked by an authorized decision but editable without that
decision's lifecycle restrictions. Evidence replacement after approval is included.
Time questions cover overdue/missed states without a server-clock check,
deadlines bounded against now where a dependent stored deadline exists, and
365-day multiples used as anniversaries. A guard-state question asks whether a
boolean requirement should be consumed by a transition. All these are bounded
structural/name-based questions, never proof, inferred intent or new gates.

### 17.2 Campaign honesty and useful generated roots

Every invariant outside the finite evaluator's fragment is named by target and
source site in default test output with its reason; a separate evaluation-gap
count prevents zero violations being read as full invariant coverage. Static
unproved remains unproved. No unknown evaluation becomes policy false. Inherited
raw read-through child assertions remain explicit evaluation gaps; this amendment
does not add raw evaluator capability. Future support requires §8.1 seed ingress,
committed readback, parent lifetime/retirement and final-exists validation. A
snapshot-only comparison never sets refuted.
Generated required uploads use real verified bytes and actor-owned fresh ledger
entries, satisfying declared byte limits; no argument/type/admission bypass.
Generated creators reserve at most two rows per target table. After an admitted
creator tuple, try a tuple differing in at least one boolean before another actor
can consume the second row slot; this is not complete Cartesian coverage. Keep
the existing 16 tuple/2048 creator-call initialization limits and report omitted
boolean combinations. Directed exploration uses depth 12, 4096 aggregate attempts,
eight argument tuples per operation/world, three distinct successors per operation,
and a five-world beam (at most 16 retained worlds including current/next/successors).
These bounds are shared, not multiplied per creator boolean. Breadth remains 512.
Check retains its shared 512-work/1500ms cap; no new cap confers proof. Report every
cut and retain generated provenance.

### 17.3 Presentation and review identity

Human output collapses restatement and role-wide questions into one questionnaire
per table. Full original diagnostics, audiences and source sites remain available
in JSON and verbose audit. The generated draft remains the complete questionnaire.
Advisories accept the same per-note rationale/disposition command as gates and
print a discoverable route to it; no bulk acknowledgment and no proof promotion.

A review ID binds analyzer revision, diagnostic code, subject and stable semantic
content, excluding line/column locations. Its source binding is a semantic slice:
the relevant rule/column and its dependency closure, or conservatively the source
declaration and referenced/writing declarations for complex flow notes. Comments,
line shifts and independent declarations do not invalidate it. Changing a relevant
rule/column, helper, grant writer, role mutator or independent intent does.
Conservative fallback scope must be explicit and tested; never silently use an
empty dependency set. Existing version-1 records remain readable but become stale
once at analyzer revision change. Keep source-race checks, lock, atomic rename,
invalid-file refusal and no-writing-on-refutation semantics unchanged. Dispositions
remain source-control review records, never application authority.

### 17.5 Review resolutions and exact finite fragments

Each original advisory remains exit-0/display-only and independently addressable
by its JSON securityReviews ID. A collapsed N_TABLE_QUESTIONNAIRE has no review ID;
it is only a human projection. Verbose/JSON retain underlying notes. No change to
refutation, lock, atomic publication or source-race refusal semantics.

Analyzer is `sec8-1`. IDs hash JSON(analyzer, code, source-declaration identity,
normalized diagnostic message, repair), then JSON(base hash, occurrence ordinal).
Declaration identity is schema-relative file, declaration kind and name. Message
normalization removes only numeric source line/column suffixes; literal values,
operation/table/column names, and predicate text remain. Rewording may invalidate
reviews conservatively; this is deliberate. Identical repeated diagnostics get
individual ordinal IDs in deterministic source order; changing their declaration
changes the shared source binding, so removal/reordering cannot transfer an old
acknowledgment across changed write contexts. Tests retain one pending review
after acknowledging only one repeat, including after line shifts.

Bindings are pure source/compiled-schema functions:
- Scalar optional-evidence column notes bind that column's lexer tokens, excluding
  locations/comments and unrelated columns. Complex optional-evidence flows fall
  through to the declaration closure.
- Restatement and role/broad-read notes bind the effective row/column rule, exact
  column type, matching independent intent, transitive dependency schemas and all
  bound programs writing those dependencies. Non-read intent includes write rules
  and field ownership. Source sites are stripped before canonical serialization.
- All other codes, including both gates, bind the containing declaration and every
  declaration named in the note; transitively include referenced declarations,
  all mutations/jobs that write a selected table, and its independent invariants.
  Helper and sibling-write bodies are therefore included. Canonical lexer tokens
  retain values and indentation but exclude comments, locations and newlines.
  This deliberately conservative closure may invalidate another note on the same
  affected resource; it never binds an independent declaration merely for sharing
  a source file. Unlocated unknown notes use an explicitly labelled whole-source
  fallback. Never bind an empty semantic slice. Old analyzer records stay readable
  but cannot acknowledge this analyzer's notes.

The advisory detectors are intentionally finite and may ask unnecessary questions:
- stale eligibility retains §16.9's same-resource/column identity extraction but
  admits any literal mutable enum destination other than its default creation
  value, including rejection/inspection; true approval flags retain the existing
  `approv`/`authoriz` substrings. No claim that every destination needs rechecking.
- approval-not-enforced: a true `approv`/`authoriz` Boolean is authored, and a
  same-table enum updater does not inspect it in its dominating resolved requires.
- edit-after-approval: a media column on an approval/stage-bearing table, or a
  payload inspected by another literal-enum/approval-flag decision, is edited
  without positive equality to the same target's default creation state. A
  negative cancelled-state check does not prove editing precedes approval. This
  does not claim arbitrary approvals or alternative enforcement are unsupported.
- child presence: an authored media-child creator plus a direct parent reference
  and a parent enum updater, without a positive dominating `exists child` conjunct
  keyed to that exact parent reference/target. Negation, another parent and late
  requires do not suppress. Text field substrings photo/image/scan/sketch/url are
  explicitly name-based. This asks for spec intent, never implies a gate.
- missed/overdue/expired literal destinations ask about server-clock enforcement;
  dependent windows compare written Time arguments bounded against now with
  uninspected referenced Time columns named due/deadline/until/expire. Calendar
  questions recognize integer `Nd` literals divisible by 365, N >= 365. They make
  no calendar inference. Unsupported affine forms remain outside these heuristics.
- reusable guards: a dominating Boolean/enum check on a related table, or Boolean
  check on the transitioned table, is not assigned by that operation. This is a
  question about reuse, not an assertion that every guard must be consumed.

helper-expanded writes; grouped column advice binds every represented column,

multi-insert creator. This is exploration pruning, never runtime admission.

### 17.6 Measurement-driven history corrections

The first 13-finding matrix exposed two lost histories: child creation populated
all evidence before observing parent-only roots (008), and nullable approval times
were absent from state signatures (036 F2). Observe the existing validated root
before the first creator taking a reference to an already populated authored
resource, as well as before update/upsert creators. Keep the existing single
pre-derived observation point and shared attempt budgets; no new initial-world
proof or application-reachability claim is introduced.

Directed signatures retain Time values and optional presence, in addition to
status/role/Boolean/relationship state. Optional media/text values contribute only
null/non-null, avoiding upload-ID noise. Time/presence changes receive three
priority points so an approval-only commit can survive to its dependent transition;
this is exploration ordering, never a semantic quotient or proof. Keep old payload
merge coverage warnings. The beam is five, not six: transient successor insertion
plus an optional old-image fork must stay inside the 16-world envelope. Reported
peak counters remain conservative; do not hide a transient allocation by moving
the counter after truncation. Regressions require witnesses for the exact appended
specification invariant, not merely a nonzero count on some other invariant.

The next actual replay exposed the final 036 F2 blocker: a creator's default +1d
event date can never pass a decision requiring 14d lead time. Time arguments now
sample source-derived Add/Sub integer offsets of at least one day from the bound
programs (candidates, never type/proof assumptions). Cache at most 64 distinct
offsets per campaign. Try the furthest future boundary first, keep the existing
+1d/now/-1d controls, then offset boundaries ±1ms on both sides of now; retain at
most sixteen distinct samples and name every cut. Checked arithmetic declines
overflow. Existing 16 creator tuples, 2048 initialization calls, two-row targets,
4096 directed attempts and 512 general argument/breadth bounds remain unchanged.
No lane, operation name or specification literal receives an exception.
