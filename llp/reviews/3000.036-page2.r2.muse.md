Top finding: both proposals are NOT READY — PAGE2 has an uncapped liveness/versioning gap, and time audiences has a floor/cursor correctness gap plus pre-boundary disclosure gaps.

## PAGE2 (§15) — NOT READY

1. **All-heads + uncapped = livelock.** Requiring every discovered id lane to have a head before emitting any row means 10k `shares` for the viewer with `last 50 by .at` needs ~10k point reads per page. An `examined` cut returns empty `complete: false` with no continuation, and retry repeats full discovery. No incremental progress is possible, unlike the §6 frontier. Fix: make the head phase resumable with a safe continuation, or keep a cap requirement for the row-id form.
2. **Cross-principal availability abuse.** Uncapped discovery makes the victim's page cost depend on populations others can inflate. If the `members` insert rule lets anyone add the victim to many parents, the victim's document list becomes permanently empty/`E_BOUND`. §14's cap bounded this. Fix: bound fanout, or add a threat/authority analysis showing the insert path cannot inflate K.
3. **Capability over-publishing.** Publishing both `v1+v2` for every membership operation means a pure §14 capped plan a v1 device could run is now refused. Fix: emit `v2` only for PAGE2 shapes (metered discovery, row-id lanes).
4. **Lifetime composition missing.** §15 says scans use the "ordinary lifetime filter" but omits the due-cursor check. Counterexample: 100 due member openings, one bounded batch advances 10, discovery reports `complete: true` missing 90 lanes. Fix: normatively import the §5 rule — unavailable/`complete: false` while relevant source/target advancement is behind.

## Time audiences — NOT READY

1. **Floor/cursor miss (correctness).** Insertion uses the time floor, advancement uses key-order `(at,table,id)` cursor. Counterexample: floor=100, cursor at `(150,T,a)`, insert `at=120` enters the pending index behind the cursor and is never advanced. Fix: define floor vs. cursor explicitly and compare inserts against cursor time (live-immediate or rewind).
2. **Pre-boundary revision leak.** `absent/future→future` and future reschedules update the pending index — but whether they bump the public sequence/table revision is unspecified. A non-member polling revisions learns hidden scheduling activity before the boundary. Fix: suppress public sequence/revision for no-delivery transitions, or explicitly accept the channel.
3. **Hidden-saturation oracle undeclared.** With `cap 200 by team` filled by hidden futures, a member's live insert is refused and learns hidden saturation. Fix: explicitly accept this 1-bit channel alongside the generic refusal.
4. **Offline scope contradiction.** §3.1 says any operation touching a `not before` table queues offline; §5 allows complete local negatives at the applied position. Fix: scope queuing to writes; reads follow ordinary coverage.
5. **Cursor durability without a commit.** All-stale batches advance the cursor with no logical change — specify a metadata commit or piggyback so a crash cannot reprocess endlessly.

Overall: NOT READY (both NOT READY).
