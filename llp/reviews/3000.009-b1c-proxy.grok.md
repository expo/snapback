## Recommendations (not blocking)

1. **`qualify-b1c.mjs:256-259`** — Teardown `503` is `try/finally` without `catch`. If `writeHead`/`end` throws (socket already gone), the async `createServer` handler rejects. Proof path at `313-316` swallows that. On Node 24 that is an unhandled rejection (stack/paths), not a coded JSON failure. Same shape in the HTTP harness `503` branch. Catch, `destroy()`, do not fail proof-phase.

2. **`proxy-phase.mjs:91-96,115-118`** — `premature()` / `abort()` do not return on `complete`. A late `error` after a finished proof could latch `proxy-proof-request`. Loopback tests that `close()` a successful proof are said to have passed; still a footgun. Guard `if (complete) return`.

3. **`qualify-b1c.mjs:324-326`** — `clientError` calls `failServer` using the **live** phase. Garbage on `:38974` during expected teardown becomes `proxy-expected-teardown-client-error` and fails an otherwise drained proof. Unlikely on the exclusive loopback port; still wider than “proof-origin premature close”.
