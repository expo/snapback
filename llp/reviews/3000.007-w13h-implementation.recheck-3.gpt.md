1. The compiler lowers the append to `Stmt::Push` ([control.rs:75](/Users/ccheever/projects/snapback-w13-review-f/repo/snapback4/crates/snapback4-lang/src/bind/program/control.rs:75)).

3. The new append analysis correctly makes `bag` **`Unknown`**, because the appended value is the raw page (`pages.rs:330–336`). The loop fixpoint preserves that warning.
4. `pages.rs:410–416` then overwrites it with **`Page(P, c, Some({bag_loop}))`**. Counting one push per input row proves cardinality, not absence of embedded raw pages.
5. Return analysis sees only precise shapes of `P`. `ambiguous_pages` therefore disables nothing, and `result_page` unions the shape lineages (`pages.rs:114–115`).
6. On the exhausted request, `ignored` is trimmed to `[]`; `bag` contains `[[a]]`. Its loop performs no reads, so the inherited cap alone does not trim it ([shaping.rs:37](/Users/ccheever/projects/snapback-w13-review-f/repo/snapback4/crates/snapback4-core/src/engine/shaping.rs:37)). Return publication selects `ignored`’s inclusive rewind ([runner.rs:358](/Users/ccheever/projects/snapback-w13-review-f/repo/snapback4/crates/snapback4-core/src/engine/runner.rs:358)). Following `next` returns raw `a` inside `bag` again.

This is the same failure class: possible raw content survives execution but disappears from the continuation analysis. The container controls at `shape_pages.rs:435–442` cover a standalone append and iteration over an already constructed bag; they do not cover this qualifying collector.
