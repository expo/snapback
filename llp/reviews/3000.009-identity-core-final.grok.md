## Bound session and logout contract

**Wire does not downgrade.** `session_mint_wire` in `serve.rs:466-506` selects bound mode if either `binding` or any `x-snapback-action-lease` header is present. Only the neither-present path is legacy. Bound parse uses `deny_unknown_fields`, requires `identity-session/v1` plus a valid `invocationId`, and demands exactly one nonempty lease via `single_header`. Duplicate/empty lease → `E_ACTION_LEASE` (`serve.rs:488-490`); malformed binding/inputs → `E_INPUT`. Lease-without-binding is covered by the bound parse, not `custom_session`.

**Invocation identity and held claim.** `bound_custom_session` (`identity.rs:605-685`) refuses a non-`identity-session/v1` or empty/invalid `invocationId` before taking the writer (`617-621`). After the transaction it rechecks the live service (`629-635`) and `held_claim_authority` on `invocation_id` + worker + lease (`636`, `actions.rs:168-173`).

**Atomic first mint.** The `None` binding arm inserts the session and the `_session_mint_bindings` row in the same transaction (`640-648`): `input_digest` over `{principal, kind, days}`, original `expires_at`, `family`, and `principal_generation`. `replace_lost_delivery` is ignored when no row exists (first mint / before-commit cut).

**Recovery.** Ordinary replay with an existing row and `replace_lost_delivery == false` is `E_INPUT` (`656-657`). Explicit replace requires identical inputs (`651-655`), live original expiry and generation (`659-661`), and a still-live family (`662-668`); then it deletes that family, mints a new token, restores `previous.expires_at` and `previous.family` (`669-680`). Revoked/expired families cannot be recreated.

**No raw token in binding or step receipts.** Binding columns are digests/ints (`identity.rs:38-42`, insert at `644-647`). `_action_steps` stores `claim_digest` and a provider key digest, not the lease or minted token (`steps.rs:7-11`, `46-73`). HTTP mint still returns the token once in the response (`serve.rs:1150-1151`) — that is delivery, not the binding record.

**Public logout vs `close_session`.** `close_session` (`identity.rs:197-200`) is still exact-digest delete with no liveness check. `logout_session` (`206-228`) takes a writer transaction, requires a still-live presented token (`expires_at > now`, plus claim authority for `action` kind), then `DELETE`s the whole family. A stale delivered token is `E_AUTH` and cannot close a successor. HTTP `/auth/logout` is this path (`auth.rs:253-257`).

## Clock injection, locks, late expiry

`Store::transaction` (`store.rs:183-191`) is `BEGIN IMMEDIATE` then the activation identity fence; failure returns before the caller samples time.

Both `logout_session` (`identity.rs:208-211`) and `bound_custom_session` (`625-628`) call the `FnOnce` clock **once**, immediately after `transaction()?`, before service/claim/family/liveness SQL. Pre-transaction validation does not sample. There is no Store-wide ambient clock. `new_session` / `insert_session` / `held_claim_authority` / `live_claim_authority` all use that sampled `i64`.

**Production wiring.** Bound mint: `|| shared.now()` (`serve.rs:1150`) while the engine guard is held. Logout: the same (`auth.rs:256`). `Shared::now` (`serve.rs:79`) locks the **clock** mutex only. Legacy unbound mint still uses a pre-lock snapshot (`serve.rs:1137-1145`), as specified.

**Mutex order / deadlock.** Clock advance already documents engine-then-clock (`serve_maintenance.rs:91-99`). The new closures take clock **after** engine, matching that order. The closure captures `&Shared` and does not reborrow `engine` or the `Tx`. `FnOnce` plus a single `let now = now()` prevents a stale captured timestamp and a second sample. SQLite writer wait happens inside `transaction()` **before** the sample, so wait time cannot keep an expired credential live.

**Busy-handler proof (source, not execution).** `two_connection_writer_block_samples_authority_time_after_the_lock` (`bound_session.rs:286-371`) holds `BEGIN IMMEDIATE` on a second connection, installs a busy handler that barriers on `attempt == 0` (`35-42`, `312-329`, `348-365`), asserts `samples == 0` **before** advancing the atomic clock, then drops the writer. That is SQLITE_BUSY on the second connection, not merely call order. Hang-on-miss (handler never fires) rather than a false pass. After unlock it asserts exactly one sample and late-time refusal (`E_AUTH` vs `E_ACTION_LEASE`) with no binding/mint. Logout is covered the same way (`342-370`).

## Guide mapping and recollection privacy

`actions.rs:25-31` maps failed/parked recollection with `diag::guide_for`. Only when that returns `"services"` **and** the code is not `E_AUTH` does the HTTP `why.guide` become `services`. `guide_for` (`diag.rs:130-170`) sends the ten OIDC codes to `services` and `E_AUTH` to `services`; the `E_AUTH` exclusion keeps generic auth on `actions`. Unknown codes (`E_OIDC_UNKNOWN`, etc.) are not in `guide_for`’s OIDC arm, so they stay `actions`. Settlement still allowlists the same ten codes (`actions.rs:192-206`); anything else is not stored as an OIDC code.

**Privacy:** HTTP `why` is `Refusal { code, family: "action", message, guide }` (`error.rs:12-31`, `serve.rs:695-697`). Recollection does not attach card bodies, `detail`, or rewrite. `guide: "services"` is a keyword only. `why.message` is still the stored worker error, truncated at 2000 characters on refuse (`actions.rs:331`) — **pre-existing** passthrough, not introduced by this delta. Unknown codes are collapsed to `E_ACTION_FAILED` in the code field; a worker can still put a sensitive string in `error`.
