## Question-by-question

### 1. Same wire, same values

`Serialize` for `LaneSource` is the same derived untagged impl as at BASELINE (`ir.rs:321-327`). `lane_source.rs` implements only `Deserialize`. Program bytes and identity digests are `to_text`/`digest` over that serializer (`value.rs:336-345`). Published Quarry programs assert `to_text(&decoded) == bytes` (`tests/lane_source.rs:136-138`). Corpus sources: 60 `null`, 60 `Scan`; 113 compact byte-exact, 7 pretty-printed only by insignificant whitespace (`tests/lane_source.rs:113-116, 247-270`). Compiler List is a separate fixture (`tests/lane_source.rs:221-230`).

Decode vs the private untagged oracle (`tests/lane_source.rs:7-16`):

| Input | New vs old |
|---|---|
| Compiler declaration order; corpus `null` / Scan object | Equal (`Difference::None`) |
| Every key order of Range/List; Scan field in every position with remaining orders reversed; `max` first; unknown `future` in every slot | Equal (`tests/lane_source.rs:160-179`) |
| Duplicate keys, including a duplicate of the first key and `{"max":null,"max":…}` | Both refuse (`tests/lane_source.rs:183-185, 282-285`) |
| `max` `null` / `u32::MAX` / `2^32` / `u64::MAX` / `-1` / `1.5` / `"8"` / `[]` / `{}` | Same accept/refuse (`tests/lane_source.rs:187-192`) |
| Missing required fields; `{}`; `null`; scalars; `[]`/`[1,2]`; `{"future":0}` | Same (`tests/lane_source.rs:181-182, 199`) |
| Mixed Range+List keys | **Stricter refusal** (`MixedDomain`, `lane_source.rs:69-79, 197`) — safe |
| Positional Scan array | **Stricter refusal** (`PositionalScan`, `tests/lane_source.rs:214-217`) — safe; sources are objects |
| Mixed Scan + Range/List keys | **Not always a refusal.** First recognized key wins (`lane_source.rs:39-41`). Untagged oracle still tries Scan, then Range, then List and ignores the other domain’s keys. |
| Malformed unknown subtree (`1e999`, unpaired surrogate, depth) | New may **accept** via `IgnoredAny`; old Content buffer refused (`SkippedUnknown`). `validate_text` still refuses that *command* text (`call.rs:169-171`; `tests/lane_source.rs:55-57, 306-315`). Program JSON loaded by `Engine::open` does **not** go through `validate_text` (`engine/mod.rs:292-293`). |

Unlisted `(old, new)` pairs panic (`tests/lane_source.rs:59`). Listed classes that *do not require a difference* will not: see findings.

Concrete mixed-schema misparse (both `Ok`, different variants):

```json
{"start": {"Literal":{"Int":0}}, "end_exclusive": {"Literal":{"Int":8}}, "max": 8, "site": "s", "table": "t", ...all other Scan fields...}
```

Old untagged: `LaneSource::Scan` (Scan is tried first; Range keys ignored). New: `LaneSource::Range` (`start` is a small key). `compare(..., MixedScan)` skips `assert_eq!` (`tests/lane_source.rs:42-44, 294-297`). No canonical writer emits this; the server and the web device both run the new decoder, so they agree with each other. It is still a silent variant change vs the old decoder, which the brief forbids.

### 2. Field-name discovery

Today `Scan::deserialize` is the derived struct impl, which calls `deserialize_struct`. `FieldNames::deserialize_struct` always returns `Err(ScanFields(fields))`; every forwarded method hits `deserialize_any` → `Err(ScanFields(&[]))` (`lane_source.rs:21-29`). `unwrap_err()` cannot panic on this type.

Later shapes:

- `#[serde(rename)]` / `rename_all`: the derive’s field *list* is the serialized names, so matching still works.
- `#[serde(alias)]`: aliases are not in that list. An alias that is not one of the four small keys is skipped as unknown (dropped). An alias equal to `start`/`value`/`max`/`end_exclusive` takes the small path.
- `#[serde(flatten)]` inside `Scan`: `FIELDS` omits flattened names; Scan decode itself would reintroduce the content reader (census would refuse the flatten on a `Deserialize` derive).
- **Name collision with `start` / `end_exclusive` / `value` / `max`:** `matches!(...)` runs *before* `fields.contains` (`lane_source.rs:39-41`). A new Scan field with one of those serialized names is a **silent misroute** into Range/List, not a loud failure. Nothing compile-fails; the only new-field test is `existence` first (`tests/lane_source.rs:273-281`).

### 3. One reader

`checkFamilies` allows exactly `snapback4_core::ir::Scan deserialize` + `serde map replay (LaneSource first key)` (`attribute-wasm.mjs:115-116`). `wasm-families.test.mjs:91-97` fails `Expr` on that family. Nested Scan field *values* go through `Replay::next_value_seed` → the original map (`lane_source.rs:58`), so they stay on `StrRead`.

`SourceVisitor` is attributed to `LaneSource` so removing the derive does not hide the reader (`attribute-wasm.mjs:50-54`; `wasm-families.test.mjs:101-107`).

Field-identifier visitors (`::__Field` / `::__FieldVisitor`) are dropped before classification (`attribute-wasm.mjs:63`). A second type whose *only* Replay leftover was a field visitor would not trip the allowlist. Duplicate-field refusal through Replay is covered by duplicating Scan’s first key (`tests/lane_source.rs:183-185`) plus `assert!(error.line() > 0)` on every dual-error (`tests/lane_source.rs:49`). Column-accurate nested errors are asserted only for Range (`tests/lane_source.rs:205-208`).

## Did the change introduce a new problem?

On **canonical** programs: no. `Serialize` is the same; server and web both decode with the new impl; corpus/guide/compiler bytes match.

On **any host**, including the server (`Engine::open` `from_str` of stored programs, `engine/mod.rs:292-293`):

1. **Hostile mixed Scan+Range/List maps** can decode as a different variant than the BASELINE untagged decoder (Range if a small key is first; Scan if a Scan key is first). Both hosts agree, but it is a behavior change vs BASELINE for the same JSON.
2. **Unknown-field garbage** (`1e999`, unpaired surrogates, very deep JSON) in a LaneSource object can now be accepted on program load. Only the web *command* path runs `validate_text` (`call.rs:169-171`). Slightly more permissive, not a variant swap.
3. Native apply/open sanity medians moved +3.55% / +1.44% on a loaded host (`JOURNAL.md:32878-32879`); not claimed as a regression and not a functional break.

Nothing correct at BASELINE for compiler-emitted or corpus programs is wrong at IMPL_COMMIT.

## Is there a regression test that would also pass without the change it claims to test?

**Yes.**

`compare(..., MixedDomain | PositionalScan | MixedScan | SkippedUnknown)` often does **not** require a difference:

- `MixedDomain` / `PositionalScan` are called without asserting `Ok`→`Err` (`tests/lane_source.rs:197, 217`). If both succeed with the same value, `assert_eq!` passes.
- `MixedScan` allows both `Ok` and skips equality (`tests/lane_source.rs:42-44, 294-297`). Restoring untagged retry would still pass.
- `SkippedUnknown` (`tests/lane_source.rs:306-315`): if the new decoder also refused, `(Err, Err)` returns `false` and the test still passes; `validate_text` is only checked on the `(Err, Ok)` arm (`tests/lane_source.rs:55-57`).

What *would* fail a revert of the production decoder: the live census (`wasm-codec-census.test.mjs:6-8, 163-166`) and `--check-families` on the artifact. Those test “no derived untagged `LaneSource` / no content family,” not the MixedScan/SkippedUnknown semantics the differential claims to pin.

Family tests (`wasm-families.test.mjs:77-107`) would pass with only the instrument change, without the decoder.

## Findings

### Medium — mixed Scan+domain maps can decode as a different variant

**Where:** `snapback4/crates/snapback4-core/src/ir/lane_source.rs:39-41`; `tests/lane_source.rs:42-44, 289-302`.

**Scenario:** JSON object contains a complete `Scan` *and* `start`/`end_exclusive`/`max`, with `"start"` first. BASELINE untagged → `LaneSource::Scan`. IMPL → `LaneSource::Range` (Scan keys dropped in `small()`). `compare` records `MixedScan` and does not check values.

**Smallest fix:** Treat any Scan field name in `small()` (and any small key after committing to Scan) as a mixed-schema error, same as Range+List (`lane_source.rs:69-79`). Change `MixedScan` so both-`Ok` with unequal values panics, and assert `Ok`→`Err` in `mixed_scan_and_domain_fields_have_explicit_streaming_precedence`.

### Medium — Scan field names colliding with `start` / `end_exclusive` / `value` / `max` silently misroute

**Where:** `snapback4/crates/snapback4-core/src/ir/lane_source.rs:39-41`; `ir.rs:277-301`.

**Scenario:** `Scan` gains `pub start: ...` (or `#[serde(rename = "start")]` / `alias = "start"`). A Scan object whose first serialized key is `"start"` becomes `LaneSource::Range` (or fails as a partial Range), not `Scan`. Canonical field order is `site` first *today*, so current corpus still works; the next field add is unprotected.

**Smallest fix:** After `let fields = Scan::deserialize(FieldNames).unwrap_err().0`, refuse (debug-assert / `const` / test) if `fields` intersects `{"start","end_exclusive","value","max"}`. Keep `matches!` only for names *not* in `fields`.

### Medium — difference-class tests do not require the differences they document

**Where:** `snapback4/crates/snapback4-core/tests/lane_source.rs:38-60, 197, 217, 289-315`.

**Scenario:** Restore derived untagged `Deserialize` on `LaneSource` (ignoring census) or drop the MixedDomain refusal. `generated_field_orders_...`, `typed_errors_...` positional case, `mixed_scan_...`, and `skipped_unknown_...` still pass.

**Smallest fix:** `assert!(!compare(...))` for MixedDomain/PositionalScan/MixedScan; `assert!(compare(...))` for SkippedUnknown (requires `(Err, Ok)` plus `validate_text`). Dual-error should not satisfy SkippedUnknown.

### Low — content-family classification skips `__Field` symbols

**Where:** `snapback4/scripts/attribute-wasm.mjs:63, 67, 115-116`.

**Scenario:** A second type instantiated on Replay or Content only as `Type::__FieldVisitor` would be ignored; `checkFamilies` would not see it. Unlikely as the sole leftover (Scan’s counted duplicate is `visit_map` at 3,951 B).

**Smallest fix:** Classify `__Field*` *when* the family is `replayFamily` or `contentFamily`, or stop skipping those symbols for those families.

### Low — census refusal always cites LaneSource’s +33,460 B

**Where:** `snapback4/packages/snapback4/test/wasm-codec-census.mjs:189`.

**Scenario:** `#[derive(Deserialize)] #[serde(flatten)]` on some other web-reachable type is refused with “LaneSource measured +33,460 B gzip”. Cause is right; the figure is not that type’s.

**Smallest fix:** Keep the LLP pointer; drop the LaneSource-specific number from the generic diagnostic.

## Questions

- Is program JSON in the store ever hand-edited such that mixed Scan+domain keys could appear, or is the compiler the only writer `Engine::open` will see?
- Should `Engine::open`/`activate` run `json_codec::validate_text` on stored program bytes so SkippedUnknown cannot widen program admission off the web command path?
- Precise `column` through `Replay` is untested; is Range `line()==2` considered enough for the adapter claim?
