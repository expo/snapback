## Findings

### Suggestion — `snapback4/packages/snapback4/src/identity.ts:101`

`loopback()` compares `url.hostname === "[::1]"`. After `new URL(...)`, IPv6 hostname is `::1` (`host` is `[::1]` or `[::1]:port`). `http://[::1]:…` with `allowInsecureLoopback` therefore throws `E_OIDC_CONFIG`, and discovered `[::1]` endpoints fail `assertProviderMetadata`. This is fail-closed (it does not admit non-loopback HTTP). `SERVER.md` still promises literal `[::1]`, and the config test only rejects `localhost`, so the advertised IPv6 development path is dead code. Production HTTPS and the 127.0.0.1 Keycloak witness are unaffected.

**Suggestion:** compare `url.hostname === "::1"` (and keep `127.0.0.1`); add an acceptance case for `http://[::1]`.

### Test gap, not a product defect — JWKS outage after a consumed code

Token-endpoint 503/unreadable/malformed paths park without a second POST. There is no sibling case where the token POST succeeds and JWKS then 503s/hangs. Classification would likely park (same `ClientError`/`{body}` story as token HTTP), but it is not witnessed. Not counted against READY.
