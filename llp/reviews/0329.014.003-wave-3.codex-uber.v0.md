### 2. Schema in v0

Encodings forced by v0: coordinates are signed microdegrees; speed/accuracy are scaled integers; surge is integer hundredths; enums are bounded text checked by rules; optional times use `0`, and optional references degrade to bounded text with `''`. That last workaround loses reference integrity; `optional(t)` belongs in §6.

`SYS` and `SYS_AO` each spell all four effects. `supportActive` is a shape-keyed probe of `supportAgents`, an active trip, and an SOS row.

**4–5: quote and request.**

The literal first attempts call `fetch` inside mutations and receive `E_OPAQUE`. There is no corrected v0 code because §1 names effects but supplies no trigger/read/idempotency ABI. The safe split is:

```ts
BeginFareQuote -> effectOutbox(geocode_route) -> FinalizeFareQuote
BeginRideRequest -> effectOutbox(preauthorize) -> FinalizeRideRequest
```

`BeginRideRequest` validates and reserves the rider/quote, but does not create a dispatchable trip. The effect uses one provider idempotency key. `FinalizeRideRequest` creates the trip/event/work only after a durable `preauthed` result; failure releases the reservation. “Finding your driver” cannot appear before that finalizer.

**7: offer response.**

The fixed design’s two-CAS body is corrected to one rollback-capable transaction:

  const at=ctx.transactionTime†
  const o=db.get(offers,args.offerId)
  db.require(o!==null && o.driverId===ctx.viewer,'OFFER_NOT_FOUND')

    db.require(t.state==='offering' && t.currentOfferId===o.id,'TRIP_CLOSED')

### 8. Where the design is wrong

1. **The idle cache has no 10-second closer.** Location publication inserts `hexIdleDrivers`; the only named watchdog closes the session after 20 seconds. Dispatch rechecks freshness, but marketplace recomputation counts the stale idle row. Confirm by stopping one driver’s stream and recomputing at T+11 seconds: dispatch rejects them while supply still includes them.

2. **`RespondToOffer` contradicts its claimed atomicity.** It says steps 1–3 are atomic, then says an offer can remain `accepted` when the trip CAS finds a rider-cancelled trip. Confirm with a barrier race: the only valid outcomes are wholly matched/accepted or wholly cancelled. `offer=accepted, trip=cancelled` proves the design wrong; rollback proves its prose wrong.

3. **The 24-hour rating promise is defeated by immediate counters.** `RateCounterpart` immediately changes profile sum/count while claiming the rating folds into the public average only after 24 hours. Confirm with an existing 5★ rating followed by 1★: the public average must remain 5.0 at T+1 second and become 3.0 at T+24 hours. The fixed design cannot produce both results.
