**NOT READY — two remaining MATERIAL concerns.**

1. **Recursive bounded-text views still reject compatible objects with bounds that cross between fields (§§10–11).**

   Concrete counterexample:

   ```quarry
   query compare(mode: enum('a', 'long'), short: enum('a'), small: enum('x'), wide: enum('x', 'wide'), active: bool):
     left = {mode: mode if active else 'a', tag: small}
     right = {mode: short, tag: wide}
     return left = right
   ```

   Before the precision change, `left.mode` was bounded text; the existing text-to-enum comparison compatibility and `small`’s subset relationship admitted the comparison.

   The proposed recursive view produces:

   ```text
   left:  {mode: text <=4, tag: text <=1}
   right: {mode: text <=1, tag: text <=4}
   ```

   Neither whole object is assignable to the other. Consequently, the current comparison rule still rejects this previously admitted expression. Replacing the return with `left = right` followed by `return left` exposes the same regression in inferred-local rebinding.

   **Required resolution:** define recursive compatibility at corresponding value leaves, preserving the existing outer shape, null and nominal rules. Recursive conversion followed by whole-object bidirectional assignability is insufficient. Add controls with opposing bound directions across fields.

2. **Unconditional enum admission to text-producing operations violates the existing text character domain (§§8–9).**

   Enums may legally contain U+0001; bounded text forbids it. Existing enum-to-text widening explicitly checks this distinction.

   Let `e` have a singleton enum domain containing U+0001. Directly passing `e` to:

   ```quarry
   fn take(t: text <=3): t
   ```

   is correctly refused. Under §8, however, `take(lower(e))` is admitted: `lower(e)` receives type `text <=3`, while its unchanged runtime value still contains U+0001. Writing that result into an otherwise authorized `text <=3` column then fails `E_INPUT`. Concatenation, slicing and joining can similarly preserve forbidden characters while claiming a text result.

   This contradicts the existing total enum-to-text widening restriction; sharing a runtime string representation does not establish membership in the text domain.

   **Required resolution:** retain the character-domain requirement whenever an operation claims a bounded-text result, or specify another sound result/admission rule. Add a control-character enum counterexample alongside the existing length and nullable controls.
