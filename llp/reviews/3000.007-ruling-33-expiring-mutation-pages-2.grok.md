## Assessment

(a), (b) and (d) are the right narrowing. (b) is stable: `predicts: "never"` is a schema fact, admission reads it on every activation, and a device never builds a runner for that class. D(page) is well-defined for every uniform read rule this engine will hoist, and it does close the hidden-gate program when the write is a statement before the scan. A2′ holds for that class; A3’s residual is the same unswept authorized population a query already has; the attempt unit is the documented off-by-one and nothing more.

(c) is statically decidable on this IR, but only as an exhaustive evaluation-order walk of every `Stmt` and `Expr` form, including `Expr::Block`. That is not what `Flow` does today, and it is not what `write_tables` reports. Hand-serialized IR is in scope (`validate_inputs` → `admission::check`). Until the proposal names that walk — and §5 puts a write-before-scan in each nested position, not only a page — (c) is a correct sentence with an incorrect implementation pointer.

## Findings

### High — (c)’s walk is specified as `Flow` / “statement order,” which does not see every write the interpreter can run before a scan

**Design:** §2 (c), the sentence that names `Flow` and “statement order at any nesting depth.”  
**Code:** `admission.rs` 118–120, 161–254 (`Flow` never matches a write form; `Expr::Block` is `Unknown`); `ir.rs` 610–625 (`write_tables` skips expressions, `WriteCondition.setup`, and `Let`/`Return` values); `runner.rs` 452–454; `reads.rs` 112–124; `validate.rs` 117–118.

**Failing program (hand-serialized, loaded through `validate_inputs`):**

```text
gates: hidden, update <- .principal = viewer
typing: expire at …, read <- exists gates[.roomId, viewer, enabled = true]
mutation m(): server
  rows = { update gates[id] { enabled: true }; typing[room] first 50 by … }
  update gates[id] { enabled: false }
```

The scan’s verdict is true only because of the transaction-local enable; abort-versus-commit then reports the unswept population of a prefix no snapshot query by that viewer can read. Quarry helpers with a *block* body would not look like this (they splice into the caller’s statement list, `control.rs` 452–463), which is why a statement-only gate test in §5(c) can go green while this IR is admitted.

**Smallest change:** In §2 (c), replace the `Flow` / “statement order” sentence with: *“can execute before” is the interpreter’s evaluation order over the inlined IR: every `Stmt` and `Expr` form, `Expr::Block` body-then-value, `For` domain then body, shape/object fields in map order, `and`/`or` left-to-right with the right-hand side treated as may-execute, prefix/filter/range of a scan, `WriteTarget` key and patch before the write. A write anywhere in a loop that encloses the scan counts. Any unmatched form refuses the page. Helpers are inlined; that is not a substitute for walking `Block`. `write_tables` is not the write set. The same walk runs from `check_detail`, including via `validate_inputs`.*

### Medium — §5(e) places pages, not writes-before-scan; several (c) shapes have no fixture

**Design:** §5 (e), and the gate-only (c).  
**Code:** `page_admission.rs` (today’s expiry tests are still the refusal); `write_observation.rs` 31–44.

A lane can implement the High walk and still ship only the straight-line gate. Then a filter `Block`, a shape field named so it evaluates first (`BTreeMap` order, `runner.rs` 462–475), a nested page, a `delete` of the probe row, an extra-equality column, or a maintain source write would not be watched.

**Smallest change:** For each nested position in (e), one refused program (write to D(page) before that page) and one admitted program (write after, outside enclosing loops). Add delete-of-probe, extra-equality, maintain-source, upsert insert arm, and “write after the scan inside the `for`.” Keep the gate pair in (c).

### Medium — D(page) is conservative for a decided-true self-probe

**Design:** §2 (c), D(page).  
**Code:** `rules.rs` 162–182 (`rule_true` absorbs a total unique self-probe); `rules.rs` 45–50 (then `prefix_decision` is `None`).

`read <- exists typing[.id]` on a total unique key is decided true without a store read. D(page) still names `typing`, so “for t in typing[room] first N: delete typing[t.id]” is refused as a write inside an enclosing loop. Sound, and the stated positives use a membership probe, not a self-witness. A lane that hits this will think the positive is unachievable.

**Smallest change:** Optionally exclude probes that `rule_true` already absorbed. Not required for soundness.

### Low — `Created` in a hand-serialized read rule is not in D(page)

**Design:** §2 D(page) (“tables named by an `exists` probe”).  
**Code:** `rules.rs` 228–231 (runtime `Schema` error); `schema.rs` 521–527.

Not a silent channel (the scan errors). Include `Created` tables in D(page) or refuse `created` in a read rule at `check_detail`, so serialized IR cannot depend on the error.

### Low — `Display` of `Bound` still names `actual`; §A’s landing note is the right fix, not a silent close

**Design:** §A Grok 3, §5 landing note.  
**Code:** `error.rs` 115–116 vs 245–249; `receipt.rs` 30–39.

No viewer-facing path should print `Display`. The note is sufficient if the lane greps call sites.
