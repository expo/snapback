## Other instrument-failure hazards (not false-green)

1. **Startup ordering race (known, fail-closed).** Proxy is listened before `startEngine` assigns `engine` (`qualify-b1c.mjs:337–342`). Worker claim/mint HTTP goes through `qualificationFetch` immediately (`qualification-fetch.ts:30–32`; `worker.ts:128–129`). A request in that window hits `engine?.identity ?? fail(...)` and fails the qualification. No ownership waiver. Can prevent a green run; cannot mint a green run.

2. **`stopChild` hangs after signal death (known).** `stopChild` treats “still running” as `exitCode !== null` (`qualify-b1c.mjs:171–178`). After a signal exit Node keeps `exitCode === null` and the `exit` listener will not fire again, so the final `await exited` can hang. The required parent 5-minute cap is what stops that hang from becoming success. This fixture’s README command (`README.md:100–109`) does not mention that envelope.

3. **Browser and proxy upstream fetches have no local timeout (known).** `keycloak-browser.mjs:38–41`; proxy `fetch` at `qualify-b1c.mjs:274`. Parent cap is the hang bound.

4. **Aggressive worker `lease: 1`.** `server.b1c-qualification.ts:25` sets a 1s claim so reclaim after `SIGKILL` is fast. `completeOidc` still does live discovery/token I/O (`identity.ts:444–452`, openid-client timeout 10s) under that lease. On a slow loopback exchange this flakes red (reclaim / second token POST / `initial-wire` fail), not green.

5. **Binary is digest-pinned; the JS package is only a path.** `qualify-b1c.mjs:528–537`. Wrong `SNAPBACK4_PACKAGE_DIR` is a parent-executor error; this script will not silently accept an unbound 0.2.26 helper (bound-wire asserts would fail), but it does not hash the package.
