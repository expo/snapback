**Totals (48 named; 0 design-supplied seeds):** query **16** · mutation **21** · schedule **7** · effect **5** · channel **0**.

Classes: **plan 33** (including 7 `refused→rewrite → plan`) · **refused (stays refused) 1** (`prefixBucketRanks` at stated scale) · **schedule 7** · **effect 5** · **product-change 0 as a coverage class** (concessions in §7; several plans are honest only after those concessions) · **`E_BOUND` risk 4** (purchase `n=150`, seat materialize ×500, score/settle/payout shards ×500, prefix over distinct scores).

The twelve “hard operations” are not twelve plans. Lobby, purchase, late-swap, withdraw, entry read, one-game lock, feed append, generation **read**, RG, and **bounded shards** are programs. The thing the design treats as one step in §5.8/§5.11/§5.12 (300k fan-out, exact rank, 500k settlement) is an **effect** driving shard mutations plus a **pointer swap**. A silent page-rank over public members is an admitted **wrong number** (§4).

### 2. Schema in v0

Sentinels: no `optional(t)` → `0`/`''` = absent. Enums are `text({ max })`. `set<enum>` eligibility exploded to bools. `json` is opaque to rules and indexes (§2). No `tree` (workspace paths, not an order-statistic). `UserContestUsage.active_entries`, `Contest.active_entry_count`, `WalletBalance` are **not tables**: they are `maintain` rows. `cap.by` as an array is **[inferred]** from `maintain.by`. `time({ commitTime: true })` is **[inferred]** from §4.3.

```ts
    previousState: 'OPEN', newState: 'LOCKED', reason: args.reason,
    actorType: 'system', sourceEventId: '', createdAt: ctx.now(),
  })
  const slate = db.get(slates, g.slateId)
  if (!slate.admissionClosed) {
    db.update(slates, slate.id, r => ({ ...r, admissionClosed: true, state: 'FIRST_LOCKED' }))
  }
  return { kind: 'locked' }
})
schedule(advanceGameLock, { at: g => g.lockAt, key: g => g.id, principal: 'system' })
```

`E≤4; W≤3`. Admission stop is **one slate row** (atomic). 20k contest `OPEN→LIVE|VOIDING` is **not** this transaction (`voidIfUnderfilled` / `closeEntriesAt` keyed by contest). Ordinary users fail the update rule. **`callable:system` is missing**: an operator with `canLock` may invoke this before `lockAt` (design allows a trusted start signal). A client calling it without operator/sys fails writes.

Delay while OPEN: `applyScheduleDelay` patches `lockAt` and appends `gameScheduleVersions`. Whether `schedule.at` **moves** is unspecified (§7 / auction). **[inferred]**

### 8. Where the design is wrong

Not taste. Forced by spelling v0.

1. **§5.8 treats a versioned 300k fan-out plus a publication barrier as the same kind of “steps” as purchase.** Purchase is a bounded mutation. Fan-out is not a plan, and the obvious bounded rewrite (`scan membershipCurrent take 1000`) is **wrong under late swap** (current ≠ snapshot). Confirming observation: run `check` on a 300k `take`; it is `E_BOUND`. Then commit a late swap of player P→Q while a P-shard runs; if that shard reads `membershipCurrent`, an entry that left P is skipped and keeps P’s points (trap 1’s stale-worker observation).

2. **Exact competition rank is specified as a read of a computed ordinal over a changing population, then separately as a generation snapshot.** v0 can pin a generation **read**. It cannot build `higherEntryCount` for 500k distinct totals as a program, and it **will admit** `rank = i+1` on a public page. Confirming observation: publish a generation with 10k ties at the top score; `getLeaderboard` returns ranks `1..100` on the first page. If `check` emitted a plan, I13 is already false.

3. **I8–I9 (“lock at `lock_at`, server commit order, never client time”) is three different mechanisms in v0, and the design writes them as one.** (a) `ctx.now() < lockAt` uses intent time and **wins after lock** on replay. (b) `schedule.at = lockAt` flips `state` within a period — edits in the lag **commit**. (c) Only an `advanceGameLock` update OCC’d with `editLineup` on `games.id` is a real order. Confirming observation: mint an edit 200 ms before `lockAt`, deliver it 200 ms after; if the lock schedule has not committed, the swap of a started player lands. Measure `committedAt - lockAt` on those rows.
