## Findings

### MATERIAL — (e) Byte-estimate omits `GraphServingRegistration`

`query_invocation_estimated_bytes` charges only JSON(`output`) + JSON(`read_dependencies`) (`4622-4626`). The memo retains a full `QueryInvocation`, whose `graph_serving` (`4567`, `4580-4588`) includes:

- `dependencies.reads`: a **second copy** of the captured vector (`crates/snapback-sync/src/graph_captured_read.rs` → `live_matcher.rs:1397` `reads: reads.to_vec()`)
- attachments, `matcher_input`, `structural_work`, `window_ledgers`, and the materialization/partition records already stringified on the key

For `issueListV2`, charged `dependencyBytes` is 2,754,464. The registered copy is about that again, **never added to `estimated_bytes`**. G1’s same formula was drain-cycle-scoped (`1187-1196`). G3-A keeps graph entries until matcher/authority/eviction, so that uncharged payload is now long-lived.

The 256-entry cap still bounds RSS, so this is not literally unbounded, but the declared **256 MiB byte budget does not cap graph memo RSS**. Filling the estimate budget with `issueListV2`-class entries retains on the order of ~2× the declared bytes. Commission deliverable 1 required a declared byte budget with eviction = re-evaluation; a budget that ignores the graph-specific retained allocation is not that bound.

### MINOR — (f) G2-C evidence rewrite is the wrong program-record home

`tests/conformance/graph/served-observations.g2-c.v1.json` declares `format: snapback.graph-served-observations.g2-c.v1`. `0268-COMPLETION-DRAFT.md` is titled as **G2-C completion evidence** and says it does not edit/supersede an LLP. This commit mutates only `groupStateBytes` (~+2.6–2.7 KiB) and the content digest, because `measurementSource` is already `served-retained-live-evaluation-memo` and G3-A keys store full identity JCS.

Those numbers are physically true for this commit. Result/dependency bytes, structural work, captures, and scheduler fence/delivery evidence are untouched. Still: G3-A should have recorded a G3-A-labeled observation (or left this to G3-C) rather than rewriting a G2-C-named freeze so the ratchet stays green. Not a stale-serve defect.

### MINOR — (h) Byte-budget eviction untested; permission-resync does not retire

`graph_scheduler_case_tiny_budget_evicts_oldest_and_reevaluates` sets `max_entries=1, max_bytes=usize::MAX` (`graph_corpus_v1.rs:1793`). It does prove same-key re-evaluation after entry eviction (3 executes, 0 hits, `delivered[0]==delivered[2]`). It does **not** exercise the 256 MiB path or oversize refusal for graph results (opaque G1 still has `live_evaluation_memo_oversize_result_refuses_without_clone_or_sharing`).

`run_permission_resync_turn` (`30297-30335`) emits `resync_required` / `clear_retained` and never calls `retire_subscription`. Graph captures are `graphNode`, so this lane likely does not fire for served graphs; it is still an untested retirement hole if a graph subscription ever carries `CapturedReadKind::Permission`.

### REFUTED-RISK — (a) Spec’d stale-serve paths

I walked the retirement set the spec/G2 machinery implies:

- **Commits / matcher:** non-skip wakes retire the shared entry before evaluation (`32012-32018`). Empty-change refresh is treated as affected (`31884-31887`). Skip leaves an old-cut entry; the next turn samples `db.current_version()` as cut (`30133-30152`, `8242-8246`), so that entry cannot hit.
- **Auth version / fence / instance:** global version retirement plus per-holder retire plus opaque `retire_authority` (`31448-31481`, `31549-31553`). Restoration goes through `invoke_live_subscription_query` and must miss (`1372-1385`). Delivery gate remains (`30920`).
- **Schema/manifest publication, generation activation, reset, teardown:** subscription drop + `retire_subscription` or scheduler replace.
- **Kill switch:** retire-all-graph before lookup (`8356-8369`).
- **Capability undeclare:** `graph_live_evaluation_memo_key` returns `None` if `graph_query_v1_target_declared` is false (`8232-8234`) — no hit; entries linger until eviction (**MINOR** occupancy, not stale-serve).
- **Resync pin:** `already_resynced` skips matcher without retiring (`31917-31927`). Those subscriptions were already processed on the auth path in the same frame. G3-A does not emit deltas, so LLP 0200’s replace-pin is out of scope.
- **Cross-turn lock release** (`30084-30086`): a commit may interleave between N same-key turns. New cut or fence retires/misses; disjoint skip cannot hit the predecessor cut.

No sequence found where a memo hit serves bytes a fresh evaluation at the **same §6 tuple** would not produce, except the owner-incoherence case in (k)/(d).

### REFUTED-RISK — (b) Key weakening

The lookup key is host-recomputed. `canonicalize_input` overwrites `auth` from `PreparedAuthority` (`crates/snapback-sync/src/auth/invocation.rs:2485-2487`). Outer materialization includes app/database/deployment/activation/function (`engine.rs:39890-39915`). Equality is full struct `Eq` (JCS of complete identities **and** hashes). Hash-only lookup is not representable. Insert refuses result/key disagreement.

`function` on the graph key is redundant (`922-924`) but is derived from the rebuilt preimage, not from the caller string. Extra axis, not a weakening.

### REFUTED-RISK — (c) Hit-path divergence vs G2-C frozen accounting

Hits skip the evaluation turn (`invoke_query` / capture / `query result handoff` guard) and skip `evaluations_executed`. They do **not** skip delivery, quarantine/witness issue, watermark/obligation paths, or installing `read_dependencies` / `graph_serving` onto the subscription. Frozen G2-C `resultBytes`, `dependencyBytes`, `structuralWork`, captures, and fence/delivery ordinals are unchanged; only estimated `groupStateBytes` moved. Debug re-eval calls `invoke_query_with_dependencies_prepared_generation` directly, so it cannot seed a second insert.

### REFUTED-RISK — (d) Release correctness depending on the debug assertion

The debug oracle is DK-3-shaped and is not a write barrier. Release stale-serve would require a tuple-preserving input change that no retirement sees. For every spec’d owner axis (matcher cut, authorizationVersion, partition identity, fence, teardown, reset, kill-switch), retirement or key inequality prevents the hit. The residual is (k): if the **owner** mutates evaluation authority inputs without rotating partition identity or authorizationVersion, debug would trip and release would serve stale. That is an owner-incoherence failure of LLP 0209 §2.4’s “equal tuple ⇒ byte-identical results” invariant, not a missing G3-A retirement.

### REFUTED-RISK — (g) Contract drift

Opaque G1 keys, drain-cycle retirement, and `retire_authority` still apply only to `LiveEvaluationMemoKey::Opaque` (`1111-1120`, `1187-1196`). LLP 0200 fence-before-delivery still holds on the served scheduler cases.

### (h) Test strength (non-blocking)

- **N=3 proves one evaluation turn:** `evaluations_executed` delta is 1, `memo_hits` is N−1, `evaluations_started` and `total_deliveries` are N (`graph_corpus_v1.rs:1479-1500`). That is one turn, not merely one map entry. Debug oracles do not bump `evaluations_executed`.

- **Eviction** proves re-evaluation of an evicted same key at unchanged data; it does not prove re-evaluation after a mutation that landed while the entry was gone (eviction-then-miss would still be correct).

## New defects / charged seams

**REFUTED-RISK — non-initial eval seeding or serving the memo.**  
A continuation cannot insert (`from_result` + `key` is `None`) and cannot `get` (stored flag false **or** current demand fails). Subscribe never mutates `input` in place, so the receiver demand check on the delivery path is the live demand. The only `get` is `invoke_live_subscription_query`. A first-page flag cannot appear on a continuation registration: the stamp is computed from that evaluation’s demand (`engine.rs:41193-41194`). Memo hits copy the producer registration, but a receiver must already have `memo_eligible_first_page` to hit, so the flag cannot be laundered onto a continuation.

**REFUTED-RISK — estimator overflow/saturation.**  
Serde failure → `usize::MAX` → oversize refusal before clone. A fitting entry that then exceeds the instance budget is inserted with the newest sequence and `evict_over_budget` drops oldest others (`engine.rs:1072-1088`). `get` may add holder bytes and evict the entry just served; the clone is already in hand (`engine.rs:1013-1027`). `usize` adds saturate; the map never holds a `usize::MAX` entry.

**REFUTED-RISK — permission-resync vs opaque lane.**  
Retirement is the existing whole-entry helper, not a graph-only path. Opaque sharing already dies on matcher wake and drain-cycle roll. Resync of one holder forces siblings to re-evaluate; it does not publish another subscriber’s memo bytes past a `clear_retained` boundary.

**REFUTED-RISK — G3-A artifact internals.**  
Plan hashes and `resultBytes` / `dependencyBytes` match the restored G2-C rows; `groupStateBytes` are the post-F3 `entry.estimated_bytes` (e.g. issueListV2 `6296770` ≈ two copies of `2754464` plus result and registration). All three rows carry `measurementSource: "served-retained-live-evaluation-memo"`. Format is `snapback.graph-served-observations.g3-a.v1`. Runner consumes it via `content_digest` + `assert_eq!(load_json(MEMO_OBSERVATIONS_FILE), memo_observations)` (`graph_corpus_v1.rs:638-642`, `5473-5477`). G2-C still uses the same `measurementSource` string on the **smaller** corpus-era numbers; consumers must key on artifact `format`, which is how the freeze test is split (`SNAPBACK_FREEZE_GRAPH_G2_C` vs `SNAPBACK_FREEZE_GRAPH_G3_A`).
