1. **High — Named-constraint `detail` survives revocation and replay.**  
   Location: [snapback4/crates/snapback4-core/src/error.rs:223](snapback4/crates/snapback4-core/src/error.rs#L223), interacting with [engine/receipt.rs:30](snapback4/crates/snapback4-core/src/engine/receipt.rs#L30) and [engine/receipt.rs:48](snapback4/crates/snapback4-core/src/engine/receipt.rs#L48).

   A visible uniqueness collision places index key values in `why.detail`. `receipt()` replaces only `why.message`; `from_receipt()` also replaces only that message. Consequently the durable receipt and later replay retain the row-derived detail after access is revoked.

   A concrete regression is already almost present: add `else DUPLICATE` to the composite unique index in [write_authority.rs:587](snapback4/crates/snapback4-sim/tests/write_authority.rs#L587). The collision includes the retained `PRIVATE` column, which the mutation did not supply. After revocation, the receipt still contains `PRIVATE` through `detail`, defeating that test’s existing sanitization obligation and LLP 3000.007 §17.

   **Smallest fix:** remove `detail` when creating durable receipts and clear it defensively when decoding historical receipts. Extend the existing revocation observation test to named constraints, including dropped-first-response/retry delivery.

2. **Medium — Residency alone does not prove the positive completeness statement.**  
   Location: [snapback4/crates/snapback4-lang/src/bind/residency.rs:402](snapback4/crates/snapback4-lang/src/bind/residency.rs#L402).

   Take horizon-free messages synchronized through **expiring memberships**, with an unscoped words index and a `held` matching query. Every classified source is `Held`, so `check` prints the positive statement. However, the device must recheck the temporary audience ([read.rs:232](snapback4/crates/snapback4-core/src/engine/read.rs#L232)); the unscoped matching read sets `non_uniform` ([read.rs:395](snapback4/crates/snapback4-core/src/engine/read.rs#L395)), and the shared device evaluator returns `complete: false` even below every meter and word limit ([local.rs:35](snapback4/crates/snapback4-core/src/engine/local.rs#L35)).

   Separately, a horizon-free `held` query returning `first 1` without a cursor still prints the statement with two held rows, although page overflow makes its answer incomplete. The requested suppression for a bound that can bite is absent.

   **Smallest fix:** describe the proven fact as **horizon-free source coverage**, or gate the completeness wording on actual device completeness analysis, including temporary-audience uniformity and truncating pages without continuation. Add both counterexamples on memory and SQLite, plus a positive complete control.

3. **Medium — After-insert attribution crosses declarations sharing a target table.**  
   Location: [snapback4/crates/snapback4-lang/src/bind/residency.rs:83](snapback4/crates/snapback4-lang/src/bind/residency.rs#L83).

   Give one table two after-insert constraints targeting `permits`, one through `byOwner` and one through `byTeam`. Execution facts retain the different indexes, but the location lookup accepts every declaration whose `read.table == target`. It therefore labels the `byOwner` fact with the `byTeam` declaration’s line as well, and vice versa.

   **Smallest fix:** preserve a constraint identity or ordinal through classification and resolve its exact AST site. Matching the target table alone is insufficient. Add a same-target, different-index regression asserting exact locations and absence of cross-attribution.
