## 15. Wave-26 proof ergonomics (DX9)

Implementer: Codex for Charlie Cheever, 2026-10-24. Amendment under review.
This supersedes string exactness in §§1/5 and the DX6 proof default, retaining
the smallest visible composed-text selector and strict ambiguity refusal.
renderedText strings default to normalized substring matching; exact:true
requests equality and regexes retain their own semantics. Independent matches
are errors naming the ambiguity and advising within or exact:true; never pick
first. waitForFresh rejects two within scopes synchronously with E_PROOF_USAGE,
including a locator originally scoped by renderedText. This avoids silently
searching a descendant scope twice. Native locator scoping remains Playwright's.

fillRN retains keystrokes for ordinary React Native text controls. HTML date,
datetime-local, month, time and week controls use Playwright fill, so React
receives ordinary input/change events. File controls use setInputFiles with
paths or file payloads; invalid input/control combinations fail explicitly.
No DOM value assignment or fabricated receipt establishes a proof.

serveUntilSignal(hosts) requires at least one owned host (otherwise
E_PROOF_USAGE) and holds a referenced timer while waiting for SIGTERM or
SIGINT, then stops all supplied owned hosts in reverse acquisition order using
the kit's independent bounded cleanup. It removes timer/listeners on all exits.
Repeated signals during cleanup use the still-installed same handler and do
not start a second cleanup; listeners are removed after cleanup. A successful
signal shutdown resolves normally (exit 0 in the recipe), and
cleanup failures reject. It never installs process.exit handlers or signals
unowned PIDs; supplied hosts retain DX8's process-group custody and idempotent
stop behavior. Recipe startup/failure cleanup uses finally so pre-helper errors
also release hosts. Test real parent/child lifetimes and signal exit status,
not only a mocked signal emitter. Packed recipe tests run the exact fences.

## 29. Wave-26 Quarry ergonomics (DX9)

Implementer: Codex for Charlie Cheever, 2026-10-24. Amendment under review.
elif lowers to the existing nested else-if AST and has identical lexical scopes,
short circuit behavior, branch joins and runtime semantics. A leading elif still
refuses with its required preceding if. Empty list literals accept `[] of TYPE`
to give their fixed element type; TYPE uses the ordinary Quarry type grammar.
TYPE is the ordinary ScalarType argument grammar (scalars, declared reference
IDs, optional scalar values and bounded nested lists). Unknown reference types
refuse E_QUARRY_UNKNOWN. Ty::join_item/assignable_to is the existing common
representation/subtyping rule: int and text conflict; text bounds and enum
alternatives may widen as in ordinary inferred lists. An annotation supplies
inference, not a runtime argument constraint or cast. E_QUARRY_TYPE names an
incompatible item/branch/loop join. The annotation does not fabricate an element, change runtime list allocation,
relax joins, or permit nested recursive accumulator growth. Every use participates in ordinary assignable_to/writable_to checks, including
assignment, initialization, argument, return, append and branch/loop joins;
incompatible representations refuse E_QUARRY_TYPE. Appends and branch/
loop joins must agree with that element type; an untyped [] remains inferable.

Nullable lexical values/fields narrow under != null in if/elif, require and the
right arm of and (and under = null in the opposite arm). Repeated database
field reads may narrow only through the existing stable point-fact domain,
with table/index/key columns and stable key value identities plus field path.
The fact lives in the binder's lexical roots inside one caller/transaction
context: job as-viewer entry/exit clears the existing $point domain; any write,
emit or local rebinding invalidates all point-field facts, without assuming
matching keys are disjoint; branch and loop joins retain
only facts common to every incoming edge. Independent job chunks establish
facts inside their own transaction. This is presence-only typing, never an
admission/visibility fact; a role-name match cannot establish it. A hidden
column or repeated read is never assumed present because a role name matches.
Add missing field fact support to that existing domain; retain conservative
handling for effects and branch joins. No authority or data visibility changes.

Unknown names matching a focal row column suggest `.column` and the exact
scope; unrelated unknown names retain ordinary suggestions. Probe brackets keep
comma-separated named equalities (including extra-column tests); using and
between equalities produces a targeted diagnostic with the comma form. Boolean
argument expressions remain allowed when parenthesized. The cheatsheet shows
the comma form before long sections. Add positive/negative/runtime cases and
the language-semantic short difftest/Lean runs to affected verification.
