## Required behavior

P1: expiration is a server-authored delete trigger. Every scheduled sweep, born-expired row and same-id expired replacement applies declared cascade, set-null and restrict actions atomically. A logically expired root is unreadable and absent from update/delete target lookup while physically retained. Future-but-unexpired write targets remain addressable. Expected restrict or physical read-through blockers are preflighted before closure writes. A read-through child outside a cascade closure may retain it; a read-through child inside the closure is deleted first. Repeated bounded calls, including `limit = 1`, advance across rows and tables; continuation publishes only after commit. Unexpected late errors roll the transaction back. Multiple set-null clears accumulate from current images.

P2: maintained aggregate ids are lowercase 64-character SHA-256 hex over a versioned, domain-separated canonical logical group tuple at every check/read/write/rebuild site. Empty logical tuple `[]` is the identity input for ungrouped views while compiler-owned `$global = true` is only the physical discriminator. Intrinsic aggregate `byId` iteration is opaque digest order; authored queries that need a group-field order declare it. Existing SQLite and evaluation-PostgreSQL stores without the marker atomically translate surviving typed references, rebuild ordinary aggregate targets, publish the marker and advance semantic generation under their writer transaction. Translation reaches a fixed point when an aggregate groups by a reference to another aggregate. A real store written by frozen 0.4.28 reopens with the same values and non-dangling first- and second-level references under digest ids. Schemas require `maintained-id-sha256-v1`; an old device refuses before silently reading a legacy address. Legacy corpus adapter seeds and canonical expected IDs cross this representation seam without changing logical expected values.

Lean evidence must state logical lifetime, sweep action/progress, fixed aggregate-id bound and atomic adoption invariants without claiming to prove SHA-256. Ordinary formal deletes use logical unexpired action witnesses. The physical write model refuses expired update/delete targets, treats expired upsert targets as absent, and models expired same-id retirement as an explicit referential-action transition after insert authority and before remaining uniqueness/physical insertion. Mutation commit retires rows born or updated expired transactionally. Mutation authority remains a proved `Steps` chain. The differential generator executes supported expiry cases; maintained-view evaluation remains explicitly outside the full Lean oracle and has a separate generated invariant.
