### 1. Coverage table

Certificate shorthand uses explicit product ceilings: `M=256` lifetime member accounts per group, `S=256` splits per expense, `J=258` posting lines per journal source, and `N=100` expenses per page. These caps are product decisions, not supplied by the fixed design. “Conditional” means every read key is shape-derived, so prediction becomes exact once the required ranges and rule verdicts are hydrated; none has an intrinsically computed-key site.

| operation | kind | class | missing | certificate | prediction |

| `postEqualSplitExpense` | mutation | plan | — | examined `≤3M+4`; writes `≤3M+3`; stable sort; output one id | conditional |

### 2. Schema in v0

The fixed design assumes a host-managed `users` relation but does not define it **[inferred]**. V0 also promises bounded argument lists and `All<T,N>` semantically without giving their constructor spelling. `Bounded<T,N>` and cap-proven `All<T,N>` below are notation for those promised types, not invented APIs.

`memberBalances` becomes host-maintained, not manually patched. `booksOpen` is derived as `membership.active || memberBalance !== 0`, preventing reopen drift. Closed membership intervals are append-only; the current open interval is represented by `groupMemberships.active/currentJoinedAt`.

```ts
import {
  table, id, text, int, bool, time, ref, interval,
  unique, cap, appendOnly, immutable, exclusion, maintain, viewer
} from "backend";

const M = 256, S = 256, J = 258;

const ever = (g, u) =>
  db.exists(groupMemberships.byGroupUser, [g, u]);

const active = (g, u) =>
  db.get(groupMemberships.byGroupUser, [g, u])?.active === true;

const creator = (g, u) =>
  db.get(groups, g)?.createdBy === u;

const expenseVisible = (expenseId, groupId, u) =>
  active(groupId, u) ||
  db.exists(expenseReaders.byExpenseUser, [expenseId, u]);

const validSourceKind = k =>
  k === "expense-payer" || k === "expense-share" ||
  k === "expense-fx-residual" || k === "settlement" ||
  k === "reversal" || k === "assumption" || k === "write-off";

export const groups = table({
  name: text({ max: 120 }),
  baseCurrency: text({ max: 3 }),
  createdBy: ref(users),
  createdAt: time(),
})
  .index("byCreator", ["createdBy"])
  .immutable(["baseCurrency", "createdBy", "createdAt"])
  .rules({
    read: g => ever(g.id, viewer),
    insert: g => g.createdBy === viewer,
    update: g => active(g.id, viewer),
    delete: never,
  });

export const groupMemberships = table({
  groupId: ref(groups),
  userId: ref(users),
  active: bool(),
  currentJoinedAt: time(),
})
  .unique("byGroupUser", ["groupId", "userId"])
  .index("byGroup", ["groupId", "userId"])
  .index("byGroupActive", ["groupId", "active", "userId"])
  .index("byUser", ["userId"])
  .cap({ by: "groupId", max: M })
  .immutable(["groupId", "userId"])
  .rules({
    read: m => ever(m.groupId, viewer),
    insert: m => active(m.groupId, viewer) || creator(m.groupId, viewer),
    update: m => active(m.groupId, viewer),
    delete: never,
  });

export const membershipEvents = table({
  groupId: ref(groups),
  userId: ref(users),
  joined: bool(),
  at: time(),
  causedBy: ref(users),
})
  .index("byGroupUserAt", ["groupId", "userId", "at"])
  .index("byGroupAt", ["groupId", "at"])
  .appendOnly()
  .rules({
    read: e => ever(e.groupId, viewer),
    insert: e => active(e.groupId, viewer) && e.causedBy === viewer,
    update: never,
    delete: never,
  });

export const membershipIntervals = table({
  groupId: ref(groups),
  userId: ref(users),
  joinedAt: time(),
  leftAt: time(),
  when: interval({ from: "joinedAt", to: "leftAt" }),
})
  .index("byGroupUserJoined", ["groupId", "userId", "joinedAt"])
  .exclusion({ on: ["groupId", "userId"], interval: "when" })
  .appendOnly()
  .rules({
    read: p => ever(p.groupId, viewer),
    insert: p => active(p.groupId, viewer),
    update: never,
    delete: never,
  });

export const expenses = table({
  groupId: ref(groups),
  description: text({ max: 500 }),
  amountMinor: int(),
  currency: text({ max: 3 }),
  rateNum: int(),
  rateDen: int(),
  amountBaseMinor: int(),
  payerId: ref(users),
  occurredAt: time(),
  createdAt: time(),
  createdBy: ref(users),
  reversed: bool(),
  clientRequestId: text({ max: 128 }),
})
  .index("byGroupCreated", ["groupId", "createdAt"])
  .index("byGroupOccurred", ["groupId", "occurredAt"])
  .index("byGroupReversed", ["groupId", "reversed"])
  .unique("byClientRequest", ["groupId", "clientRequestId"])
  .immutable([

    "rateDen", "amountBaseMinor", "payerId", "occurredAt",

  });

export const expenseReversals = table({

export const expenseReaders = table({

    delete: never,

export const settlements = table({
```

The following read helper is bounded and checkable. Its returned array remains bounded by `M`.

```ts
function accountsAt(db, groupId, t) {
  const accounts = db.scan(groupMemberships.byGroup, [groupId], { take: M });
  db.require(!accounts.hasMore, "GROUP_MEMBER_CAP");

  const result = [];
  for (const m of accounts) {
    if (m.active && t >= m.currentJoinedAt) {
      result.push(m);
      continue;
    }
    const old = db.scan(
      membershipIntervals.byGroupUserJoined,
      [groupId, m.userId],
      { order: "desc", take: 1, range: { lte: t } },
    );
    if (old[0]?.when.contains(t)) result.push(m);
  }
  return result;
}
```

Because v0 permits only pure/inlined helpers, `POST`, `REVERSE`, and `CLOSE` below are report macros: actual source must expand their bodies literally. They do not claim mutation composition exists.

**Posting and correction — operations 1–4**

`POST(args, splits)` expands to:

```ts
const prior = db.get(expenses.byClientRequest,
  [args.groupId, args.clientRequestId]);
if (prior) return prior.id;

const now = ctx.now();
db.require(args.occurredAt <= now, "FUTURE_EXPENSE");
db.require(active(args.groupId, ctx.viewer), "NOT_ACTIVE_MEMBER");
db.require(args.amountMinor > 0, "NON_POSITIVE_AMOUNT");
db.require(args.rateNum > 0 && args.rateDen > 0, "BAD_RATE");
db.require(splits.length > 0, "NO_SPLITS");

const eligible = accountsAt(db, args.groupId, args.occurredAt);
const eligibleIds = new Set(eligible.map(m => m.userId));
db.require(eligibleIds.has(args.payerId), "PAYER_NOT_ACTIVE_AT_OCCURRED_AT");

let shareSum = 0;
const seen = new Set();
for (const s of splits) {
  db.require(s.shareMinor > 0, "NON_POSITIVE_SHARE");
  db.require(!seen.has(s.userId), "DUPLICATE_SPLIT_USER");
  db.require(eligibleIds.has(s.userId), "SPLIT_USER_NOT_ACTIVE_AT_OCCURRED_AT");
  seen.add(s.userId);
  shareSum += s.shareMinor;
}
db.require(shareSum === args.amountMinor, "SPLITS_MUST_SUM_TO_TOTAL");

const [amountBase] = divmod(
  args.amountMinor * args.rateNum, args.rateDen);
let shareBaseSum = 0;
const converted = [];
for (const s of splits) {
  const [base] = divmod(s.shareMinor * args.rateNum, args.rateDen);
  converted.push({ ...s, shareBaseMinor: base });
  shareBaseSum += base;
}

// Correct sign: residual = Σconverted shares − converted total.
const residual = shareBaseSum - amountBase;
const deltas = new Map();
const add = (u, n) => deltas.set(u, (deltas.get(u) ?? 0) + n);
add(args.payerId, amountBase + residual);
for (const s of converted) add(s.userId, -s.shareBaseMinor);

let journalSum = 0;
for (const n of deltas.values()) journalSum += n;
db.require(journalSum === 0, "JOURNAL_DOES_NOT_BALANCE");

const expenseId = ctx.newId();
db.insert(expenses, {
  id: expenseId, ...args, amountBaseMinor: amountBase,
  createdAt: now, createdBy: ctx.viewer, reversed: false,
});
for (const m of eligible) {
  db.insert(expenseReaders, {
    expenseId, groupId: args.groupId, userId: m.userId,
    occurredAt: args.occurredAt,
  });
}
for (const s of converted) {
  db.insert(expenseSplits, {
    expenseId, groupId: args.groupId, userId: s.userId,
    shareMinor: s.shareMinor, shareBaseMinor: s.shareBaseMinor,
  });
}
db.insert(postings, {
  groupId: args.groupId, userId: args.payerId,
  amountBaseMinor: amountBase, sourceKind: "expense-payer",
  sourceId: expenseId, createdAt: now,
});
for (const s of converted) {
  db.insert(postings, {
    groupId: args.groupId, userId: s.userId,
    amountBaseMinor: -s.shareBaseMinor, sourceKind: "expense-share",
    sourceId: expenseId, createdAt: now,
  });
}
if (residual !== 0) {
  db.insert(postings, {
    groupId: args.groupId, userId: args.payerId,
    amountBaseMinor: residual, sourceKind: "expense-fx-residual",
    sourceId: expenseId, createdAt: now,
  });
}
return expenseId;
```

`postCustomSplitExpense` is `POST(args, args.splits)`, where `splits` is `Bounded<Split,S>`.

`postEqualSplitExpense` first obtains `members = accountsAt(...)`, stably sorts by `userId`, computes `[q,r] = divmod(amountMinor, members.length)`, and constructs `shareMinor = q + (index < r ? 1 : 0)`. It then textually expands `POST(args, splits)`. Using only current `role === member` would be admitted but product-wrong for backdated expenses.

`REVERSE(expenseId, requestId)` expands to:

```ts
const original = db.get(expenses, expenseId);
db.require(original, "EXPENSE_NOT_FOUND");

const retried = db.get(expenses.byClientRequest,

if (retried) return retried.id;

db.require(!original.reversed, "ALREADY_REVERSED");
```

`reverseExpense` is that expansion. `correctExpense` is one mutation containing `REVERSE(args.expenseId, request+":rev")`, followed by `POST(replacement, replacement.splits)` using `request+":new"`. Both blocks are inside one transaction; no settlement is touched. Calling two mutations from the client is not an acceptable rewrite.

**Settlement and departure — operations 5–8**

```ts
export const settlePair = mutation(SettleArgs, ({ db, ctx, args }) => {
  const old = db.get(settlements.byClientRequest,
    [args.groupId, args.clientRequestId]);
  if (old) return old.id;

  const caller = db.get(groupMemberships.byGroupUser,
    [args.groupId, ctx.viewer]);
  const from = db.get(groupMemberships.byGroupUser,
    [args.groupId, args.fromUserId]);
  const to = db.get(groupMemberships.byGroupUser,
    [args.groupId, args.toUserId]);
  const fromNet = db.get(memberBalances,
    [args.groupId, args.fromUserId])?.value ?? 0;
  const toNet = db.get(memberBalances,
    [args.groupId, args.toUserId])?.value ?? 0;

  db.require(caller?.active && from?.active && to?.active, "NOT_ACTIVE_MEMBER");
  db.require(args.fromUserId !== args.toUserId, "SELF_SETTLE");
  const [base, rem] = divmod(args.amountMinor * args.rateNum, args.rateDen);
  db.require(rem === 0 && base === args.amountBaseMinor, "FX_NOT_EXACT");
  db.require(base > 0, "NON_POSITIVE_SETTLEMENT");
  db.require(fromNet < 0 && toNet > 0, "NOT_DEBTOR_CREDITOR");
  db.require(base <= -fromNet, "OVERPAY_DEBTOR");
  db.require(base <= toNet, "OVERPAY_CREDITOR");

  const settlementId = ctx.newId(), now = ctx.now();
  db.insert(settlements, {
    id: settlementId, ...args, createdAt: now, createdBy: ctx.viewer,
    fromNetSnapshot: fromNet, toNetSnapshot: toNet,
  });
  db.insert(postings, {
    groupId: args.groupId, userId: args.fromUserId,
    amountBaseMinor: base, sourceKind: "settlement",
    sourceId: settlementId, createdAt: now,
  });
  db.insert(postings, {
    groupId: args.groupId, userId: args.toUserId,
    amountBaseMinor: -base, sourceKind: "settlement",
    sourceId: settlementId, createdAt: now,
  });
  return settlementId;
});
```

`CLOSE(mem, now)` inserts the closed interval
`[mem.currentJoinedAt, now)`, updates `mem.active=false`, and appends a
`membershipEvents{joined:false}` row.

```ts
export const leaveGroupClean = mutation({ groupId: ref(groups) },
({ db, ctx, args }) => {
  const mem = db.get(groupMemberships.byGroupUser,
    [args.groupId, ctx.viewer]);
  const net = db.get(memberBalances,
    [args.groupId, ctx.viewer])?.value ?? 0;
  db.require(mem?.active, "ALREADY_FORMER");
  db.require(net === 0, "NONZERO_BALANCE");
  const now = ctx.now();
  // literal CLOSE expansion
  db.insert(membershipIntervals, {
    groupId: args.groupId, userId: ctx.viewer,
    joinedAt: mem.currentJoinedAt, leftAt: now,
  });
  db.update(groupMemberships, mem.id, m => ({ ...m, active: false }));
  db.insert(membershipEvents, {
    groupId: args.groupId, userId: ctx.viewer,
    joined: false, at: now, causedBy: ctx.viewer,
  });
});
```

`assumeDepartingMemberBalance` point-reads both active memberships and the maintained departing net `N`; requires `assumerUserId===viewer` and `N!==0`; inserts postings `−N` for the departing member and `+N` for the assumer; then expands `CLOSE` for the departing member. The constructed journal sum is required to be zero.

`forceWriteOffToRemainingMembers` scans the cap-backed member set, point-reads maintained nets, stably sorts remaining active users, and computes allocations whose sum is **`N`**, not `−N`:

```ts
const N = db.get(memberBalances,
  [args.groupId, args.departingUserId])?.value ?? 0;
db.require(N !== 0, "NOTHING_TO_WRITE_OFF");

const accounts = db.scan(groupMemberships.byGroup,
  [args.groupId], { take: M });
db.require(!accounts.hasMore, "GROUP_MEMBER_CAP");
const others = accounts.filter(
  m => m.active && m.userId !== args.departingUserId);
db.require(others.length > 0, "NO_REMAINING_MEMBERS");

const weighted = others.map(m => {
  const net = db.get(memberBalances, [args.groupId, m.userId])?.value ?? 0;
  return { m, weight: net < 0 ? -net : net };
}).sort((a, b) => a.m.userId < b.m.userId ? -1 : 1);

let weightSum = 0;
for (const x of weighted) weightSum += x.weight;
let assigned = 0;
const allocations = [];
for (const i of literalRange(0, weighted.length)) {
  const denominator = weightSum === 0 ? weighted.length : weightSum;
  const numerator = weightSum === 0 ? N : N * weighted[i].weight;
  const [q] = divmod(numerator, denominator);
  const amount = i === weighted.length - 1 ? N - assigned : q;
  allocations.push({ userId: weighted[i].m.userId, amount });
  assigned += amount;
}
db.require(assigned === N, "WRITEOFF_ALLOCATION_BUG");

const sourceId = ctx.newId(), now = ctx.now();
db.insert(postings, {
  groupId: args.groupId, userId: args.departingUserId,
  amountBaseMinor: -N, sourceKind: "write-off", sourceId, createdAt: now,
});
for (const a of allocations) {
  db.insert(postings, {
    groupId: args.groupId, userId: a.userId,
    amountBaseMinor: a.amount, sourceKind: "write-off",
    sourceId, createdAt: now,
  });
}
// require (-N + assigned) === 0, then literal CLOSE expansion
```

`listVisibleExpenses` cannot filter after a broad row rule: hidden rows would already enter the authoritative trace. With `expenseReaders`, it becomes:

```ts
export const listVisibleExpenses = query({
  groupId: ref(groups), fromOccurredAt: time(), toOccurredAt: time(),
  after: cursor(), take: int({ max: N }),
}, ({ db, ctx, args }) => {
  const mem = db.get(groupMemberships.byGroupUser,
    [args.groupId, ctx.viewer]);
  db.require(mem, "NOT_A_MEMBER_EVER");

  if (mem.active) {
    return db.scan(expenses.byGroupOccurred, [args.groupId], {
      range: { gte: args.fromOccurredAt, lt: args.toOccurredAt },
      after: args.after, take: args.take,
    });
  }

  const readers = db.scan(
    expenseReaders.byUserGroupOccurred,
    [ctx.viewer, args.groupId],
    {
      range: { gte: args.fromOccurredAt, lt: args.toOccurredAt },
      after: args.after, take: args.take,
    },
  );
  return readers.map(r => db.get(expenses, r.expenseId));
});
```

### 6. Language delta

1. **Transaction-scoped aggregate constraints.** Add `balanced(postings,{by:"sourceId",of:"amountBaseMinor"})` and parent/child `sumEquals(expenseSplits.shareMinor, expenses.amountMinor)`. General; amends §2 constraints and §5 certificates. This makes invariants 1 and 3 bind every writer.

2. **Maintained cross-table violation sets or an audit kind.** The smallest addition for exact `reconcileGroup` is a host-maintained set of expense IDs whose maintained split total differs from the parent amount, with snapshot semantics. General; amends §§2, 4.4, and 6.

3. **Rule-side interval lookup.** Add an indexed, shape-keyed `db.existsContaining(index,prefix,t)` with bounded probe and trace semantics. General; amends §2 indexes, §3 rules, §4.2, and §6. `expenseReaders` is expressible today but costs `O(M)` writes per expense and has no completeness constraint.

4. **Executable cardinality/type spelling.** Specify bounded-list arguments, record/enum/optional columns, the API producing `All<T,N>`, literal-range spelling, and cardinality propagation through `filter`, `map`, `sort`, `Map`, and `Set`. General editorial/spec completion; amends §§2 and 4.1–4.4.

5. **Normative money arithmetic.** Define `divmod`’s signature and negative quotient/remainder law, plus widened-intermediate `mulDiv` so a valid i53 result is not refused solely because `amount*rateNum` overflowed i53. General; amends §4.5 and the value-model certificate.

6. **Effectful in-transaction composition.** Add compiler-inlined private transaction functions, or permit a mutation to invoke another named mutation without a second envelope/commit. General but ergonomic: literal inlining already admits `correctExpense`. Amends §4.1/§4.2.

The old report’s `sum`, fan-out patch, stable ordering, range scans, append-only, immutable, and maintained-balance requests are **not** deltas; v0 already contains them.

### 7. Product changes

| product change | acceptable when | cheat boundary |
|---|---|---|
| Cap lifetime group accounts and custom splits at 256 | consumer/social expense groups | organizational accounting or promised arbitrary churn/size |
| Paginate expense history and bad-integrity IDs | ordinary UI/history browsing | claiming one atomic, complete audit/export |
| Freeze base currency at group creation | normal group setup | editable draft/import workflows require pre-posting changes |

| Single currency | domestic MVP | travel/cross-border positioning; equal split still needs deterministic remainder |

Equal-splits-only is not justified by v0—the language can validate bounded custom sums. Dropping materialized balances is likewise obsolete because `maintain.sum` is native.

### 8. Where the design is wrong

1. **FX residual sign is reversed.** The design computes `gap=amountBase−shareBaseSum` and inserts `+gap`, yielding a journal total of `2*gap`. Confirmation: amount `2`, splits `1+1`, rate `1/2` produces `+1,0,0,+1`, sum `+2`. The posting must be `−gap`.

2. **Forced write-off sign is reversed.** Zeroing the departing net `N` requires posting `−N` to them and allocations totaling `+N`. The design allocates `−N`, so the journal totals `−2N` for every nonzero case. Confirmation: `N=−30` emits `+30` for the departing member and another `+30` to remaining members.

3. **Temporal visibility contradicts itself.** `addMemberWithVisibilityCutoff` says a rejoiner must not see gap expenses; `listVisibleExpenses` gives every active member the complete book, including that gap. Table rules also originally gave every former member all future rows, while `suggestedSettlements` exposes the current full net vector. Confirmation: join at `t0`, leave `t1`, another member posts at `t2`, rejoin `t3`, correct a `t0` expense at `t4`; record which expenses, splits, postings, settlements, and aggregate balances are delivered at each state.
