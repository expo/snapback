## Assessment

**Forged caller / profile writes.** Guest and ordinary principals cannot insert or update profile or transaction rows (`OIDC_SERVICE_REQUIRED`). Own-profile reads are `oidcTrustedProfiles[viewer]`; `identityProfileFor` is service-only. The helper keys the verified write with `oidcPrincipal(claims.issuer, claims.subject)`, not the admitting guest, callback `iss`, email, or app-supplied provider values (`identity.ts:500-504`). `service:worker` can still pass an arbitrary principal into `identityVerified` on first insert; that is the accepted deployment-trusted worker contract, not a hole this slice introduced.

**Issuer/sub vs principal.** Repeat settlement requires the same principal+issuer+sub (`OIDC_VERIFIED_MISMATCH`). An existing profile cannot rebind issuer/sub (`OIDC_PROFILE_BINDING`). The published helper and mint share `identity-principal.ts`, so session principal and profile key stay aligned. Quarry cannot re-hash; first insert trusts the service-supplied principal. Under the honest helper that is `f(issuer,sub)`, so `unique byPrincipal` is enough. No email uniqueness or linking.

**Retry / order / atomicity / freshness.** `identityBegin` assigns `loginOrder` from a service-only counter and `proofStartedAt` from managed `now`; callers cannot supply either. Writes take `BEGIN IMMEDIATE`, so the counter is serialized. Newer `loginOrder` upserts (including false/missing email, which clears eligibility); older completion cannot replace; equal-order replay must match source login, stamps, and email (`OIDC_PROFILE_REPLAY_MISMATCH`) and does not refresh expiry. Binding failure is in the same mutation as the transaction update, so it rolls back. Five minutes is `proofStartedAt + 300000`, evaluated as `proofExpiresAt > now` at query time, not as provider-current revocation.

**Public data.** Transactions, counters, and PKCE stay service-only. Profile rows are own-principal or service. No membership, invitation, recovery, or editable email/display field is written.

**Generic compat.** Exported transaction row and begin payload still omit recipe-private `loginOrder` / `proofStartedAt` / `verifiedPrincipal`. The verified mutation now requires derived `principal`. A pre-B1d verified write-id lacks that field and fails input binding; no receipt migration. That matches the documented fresh-login boundary.

**Evidence honesty.** Docs and JOURNAL state qualification pending, 0.2.26 CLI operator `--as/--now` (not auth/mint/provider/revocation), lost-ack as helper-double only, and 0.2.27 provider+profile path not claimed. That matches the source.
