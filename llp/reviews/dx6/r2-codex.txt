### Session input and compatibility

Seeded records preserve the actual signup session's kind alongside its
principal, token and numeric expiresAt. They can be passed directly as Session.
Online createClient accepts a legacy incomplete session literal as token-only
transport credentials: its token must be nonempty; partial principal, kind and
expiry metadata never establishes identity, refresh timing or authority. The
server resolves the bearer; session() is null and there is no refresh timer,
as for the existing token option. Complete shapes remain strictly validated
and privately snapshotted. Local/device session input remains complete-only.
E_SESSION lists every missing/invalid field without values and gives the exact
one-line online repair createClient({ url, token }). An ISO expiry in a complete
shape refuses instead of creating a NaN timer. Restored full sessions retain
the existing restore validation and server expiry semantics.

### Advances, maintenance and retained boundaries

ClockAdvance remains an object reporting now/fired/held; valueOf returns now
for arithmetic, ordering and new Date(result). This is JavaScript numeric
coercion, not strict-equality compatibility; typed callers use result.now.

For classified staging, advance(duration) preserves remaining ordinary session
lifetimes by default. The core advances valid full/read session created/expiry
fields, read caps and recoverable mint receipts by the same checked delta,
in the same transaction as existing worker-lease preservation, before publishing
the new process clock. Expired, capped, revoked or superseded authority cannot
become live. Selection uses the authority kernel and bounded pages; overflow
refuses atomically. Existing action delegated sessions and supervised service
families remain owned by the worker-lease path, without double shifting.
Historical admission timestamps are evidence, not an ongoing cap; application
deadlines/backoffs remain business time.

Preservation includes SDK custody, not just raw HTTP credentials. A staging
response for the exact request bearer can publish authoritative session expiry
and read cap beside the same locked business-time/revision snapshot, obtained
through a detached store-identity/liveness-checked authority read. No bearer,
new authority, mint, rotation or refresh is exposed. Production publishes no
such metadata. A failed detached timing read suppresses the clock sample,
including streaming-final samples, instead of publishing advanced business
time with stale credential metadata. A client reconciles only its current
bearer's matching request URL/header, monotonically increases expiry/cap and
persists through existing credential/custody fences before clock listeners run.
Rotated/logged-out credentials cannot be restored by a late response. Client
clocks are isolated, so one bearer's response cannot expire another before its
own timing is reconciled. Read startup verifies before scheduling expiry;
an expired restored metadata image requires a successful authenticated read-only
staging probe with matching viewer/scope and live timing. Production/offline
without this evidence keeps the existing expiry refusal. The local constructor
reconciles bootstrap timing before applying a restored device clock's expiry
check. Tests retain actual read clients and restore them across their old
absolute expiry, compare two independent bearers, and exercise explicit-expiry
and production controls. These headers are staging timing evidence only;
ordinary authority is still checked on every server admission. Real elapsed time still consumes
credentials. sessions:'expire' explicitly tests expiry with the existing
business clock. Dev retains its existing expiry behavior. Production rejects
all clock controls and never calls preservation. Restart keeps the persisted
credential timestamps and drops only the existing process-local business offset.
This intentional staging-only simulated jump also shifts a read family's cap;
ordinary production read-cap immutability is unchanged.

advance(duration, {drain:false}) advances time and pauses background maintenance
before releasing the writer. This covers expiry sweeps, scheduled enqueue,
queued job chunks, asset collection, view recount and delivery maintenance,
so a mutation can exercise its own deadline check. Authorization and logical
row expiry still apply to ordinary queries/mutations. The pause lasts until
host.drain(), another draining advance, or process restart. drain() uses the
same authenticated endpoint with duration:'0ms', drain:true, advancing no time
and resuming normal coalesced maintenance. eachBoundary requires drain:true.
The HTTP report includes maintenancePaused; native CLI spells these controls
clock advance D --no-drain and clock drain. Failed/ambiguous requests are never
automatically replayed. A failed drain leaves its advanced time intact, its
report explicitly incomplete, and maintenance paused. Only a successful explicit
drain resumes it. drain() advances no time and safely continues existing queued
work/checkpoints; never repeat a lost advance to obtain that recovery.

A draining advance whose saved future boundary blocks requested work refuses
E_CLOCK_HELD before clock, session or lease effects. The refusal names the
schedule, saved boundary, next window and recovery duration. Fresh staging
storage and continuing with the original offset are recovery choices; saved
markers never rewind. allowHeld:true (CLI --allow-held) explicitly accepts a
retained boundary. Intentional drain:false pauses and dev --hold-schedules are
explicit holds. not-due/initialization remains a successful reported outcome.
Control authorization/classification is checked again under the actual writer.

- The guide is tested text. Quarry store testing (LLP 3000.035 §5.1): `SNAPBACK4_EVAL_POSTGRES` is an
explicit evaluation connection. The factory owns one physical schema per worker,
restores its rows and bookkeeping, installs the compiled fixture, then opens the
ordinary engine. Mutation attempts restore a seeded snapshot; shrinking reuses
that same factory. `Database::connect_fresh()` is an opt-in test mode. Fresh and
restored outcomes must serialize to identical bytes. The local wire observer
retains SQLSTATE, message, detail and SQL statement before the public query API
converts a driver error to a refusal; it never changes the traffic.

Reads sweep every public boundary. Mutations compare every discovered position
twice on SQLite, and compare up to eight seeded positions per dimension on
Postgres (including first/last), plus the case's original budget. Sampling
counters are in `store_stats`; each selected position runs prefetch on and off.
Physical prefetch counters are separate from the exact public outcome record.
The widened generator (`src/widen.rs`) emits prefetch-reachable reads: pages
projecting `tags[.tag]` and `tags[name = .label]` (a `Get` and a unique
`Lookup` whose keys vary across rows) and a loop reading `tags[row.tag]`, so
`store_stats` reports marked reads, transferred rows, cases with a transfer
and `prefetch_consumption_witness_probes` (fewer database calls with prefetch
on: cached answers were consumed). A planted cached-hit-to-miss fault is caught
by the random corpus (LLP 3000.035 §5.1; the closed
[coverage ticket](../issues/closed/20261007-quarry-store-oracle-prefetch-coverage-gap.md)).
Heap is charged identically on every store and the device (LLP 3000.007
§20.24.5); any disagreement is a ticket candidate, never normalized into a pass.
The cluster regression asserts it finds no signature and refuses any new one.

`run-stores --seconds N` stops each worker between cases after N seconds; a case
and any shrinking already underway finish. `cases` remains the requested count,
`generated` is actual completed generation, and `time_limited_workers` reports
the early stop. Slowest-case timing includes generation, comparisons, shrinking
and artifact saving. It does not silently claim the requested million. The scheduled
runner rejects incomplete reports; its own `--hours` option instead chooses a
case count from a 256-case calibration of both campaigns, with 20% headroom and
a million-case cap. This is a sizing estimate, not a hard deadline.

Generator widening (`src/widen.rs`, LLP 3000.035 §5.1): from a stream
independent of the base generator (`generate::base`; a seed it leaves alone is
the base case byte for byte), cases gain prefetch-reachable reads, mutation
blocks (lets, `require`, `if`, several writes to `key` and `k2`, reads after
writes), a prelude of mutations `prep0..` run in order on the same store before
`run` (`Case::steps`, sometimes as the other viewer; `observe` then reads both
keys), and expiry (`expire at .until`, a clock advancing from `seeded_at`
through each step to `clock`, sweeps, `until: now + ttl`). Every oracle runs the
prelude (`execute::world`) and compares its outcomes (`prelude-*` fields;
`store-postgres-prelude`); a device acquires at the seed clock and catches up by
one sync round after the server's prelude. The prelude is emitted first so no
rewrite moves its sites. `lean::generate` narrows half the cases outside the
model (projections, expiry) back into its fragment; the rest stay named
unsupported (`shape`, `loop`, `table-expiry`). The report's `coverage` counts
each new feature (`block/*`, `prelude/*`, `projection/*`, `expire/*`, `clock/*`).

Quarry device testing (`src/devices.rs`, `src/device_writes.rs`, LLP 3000.035
§5.1 oracle 4): each case runs on a server engine and on a device of each store
(native SQLite at a file path, and memory), both brought up through the client's
own path: the `/schema` backend as JSON text, then `local.ts::syncRound` (capture
`sync_state`, `/sync` snapshot pages built as `serve_sync.rs` builds them,
`observe_store`, `apply` through `call_text`, catch-up stream). Never seed a
device store directly. Reads the device publishes without the server (`complete`
with `unknown` false, or a known refusal) compare the whole outcome record
except `seq` (and server-only `delivery`); every other read counts under a named
reason (`online-only-*`). Low ceilings reach the device only through `call`'s
`spent` ledger (`default - n`), compared at the server's boundary positions.
Writes go through `admit`: a device refusal must equal the server's, a
predicted row must equal the committed one (less its `pending` marker), and
after `settle` plus a sync round the device must answer `observe` as the server
does. `run-devices` accepts `--seconds`. Known findings are retained under
`cases/found/device-*` with a `DIAGNOSIS.md`; `tests/devices.rs` replays them
and `tests/smoke.rs` pins the fixed-seed signature set.

The Lean oracle (`run-lean`, LLP 3000.035 §5.2): `snapback4_lang::emit::lean`
translates each generated program's surface tree (never the binder's IR) to
the model's case JSON; `quarry-oracle` (`lean/Oracle.lean`, one process per
worker) answers one tagged outcome per line; the engine runs on SQLite at
default ceilings. Compared: kind, refusal code, data (tagged: an id is not a
text), `complete`, `next` presence, each side's own continuation, and a
mutation's `observe` reread. Not compared: meter fields and sites. Programs
outside the model's fragment are named unsupported reasons, never passes.
`lean::generate` adds Lean-only variants (per-effect rules, a hidden probe
target, nullable/id orders, residual filters) aimed at `lean/OPEN.md`. A
disagreement is a Rust defect, a model defect (only when a document
contradicts the model: fix the model, rerun `lean/check.sh`), or an open
point (record the engine's behaviour in `OPEN.md`); never change the model to
match the engine without a document. Findings live in
`cases/found/lean--*` with `DIAGNOSIS.md`; `tests/lean.rs` replays them and
pins the open signature set. Lean-dependent tests skip loudly without the
built model; `SNAPBACK4_REQUIRE_LEAN=1` makes that a failure.

Quarry scheduled testing: prepare a separate clean clone whose current branch
can fast-forward to `origin/main`. The runner fetches/fast-forwards it and starts
its own socket-only evaluation cluster with `fsync=off`,
`synchronous_commit=off`, `full_page_writes=off`, `shared_buffers=1GB`, and
`max_connections=200`. It builds the Lean model's `quarry-oracle` first
(`lake build` in `lean/`; a host without `lake` fails the run), then runs the
SQLite, store, device and Lean campaigns on the selected
seed window, replays shrunk findings twice, and files/appends open `issues/*.md`
tickets. Only ticket changes are committed/pushed, with three fetch/rebase
retries. State and reports live outside Git under `--state-dir`; seeds advance
only after completed work and successful owned-cluster cleanup. Dirty/diverged
trees, overlap, setup failures, partial reports and failed publication refuse.
A crash can retain the lock and cluster directory; inspect `lock/owner.json`
and the run report. Never stop a cluster by process name.

`--dry-run --cases 32` writes previews and a separate `next-seed.dry-run.json`,
never commits or pushes. Dry runs may explicitly supply `--external-postgres
'host=... user=... dbname=...'`; that cluster is neither started nor stopped by
the runner. Ambient connections do not override normal private-cluster ownership.
The installer remains an operator action; do not invoke it during development.

The Lean oracle on a scheduled host (one-time, per user, no sudo): install
elan with `curl https://raw.githubusercontent.com/leanprover/elan/master/elan-init.sh -sSf | sh -s -- -y --default-toolchain none`.
The runner finds `lake` on `PATH` or in `~/.elan/bin`; the first `lake build`
downloads the toolchain pinned in `lean/lean-toolchain` (Lean 4.34.1, no
Mathlib), so the first scheduled run needs network. Check by hand with
`(cd lean && ./check.sh)` in the runner's clone. `run.json` records the pinned
toolchain and the oracle binary's digest.
# What Snapback 4 Does Not Do

Longer than the doing-list on purpose. Moving something off it means writing one
line naming what it unblocks and taking something off the doing-list in the same
change. Nothing comes off during slice one (LLP 3000 §3: the clock is four weeks).

## The bars

The bakeoff gates in [LLP 3000 §3](../llp/3000-snapback4.explainer.md) are the
bars: the loop bar, hub acquisition within 2× the measured floor, client bytes
under the competitor-anchored budgets, the six scenarios green in the simulator
on the hub fixture. Everything not required to pass them does not exist yet.

## Not building

- **A second authoring language.** Quarry, one spelling, copied from Snapback 2 (LLP 1004, LLP 1007 §4b). TypeScript is for seeds, journeys, effect bodies and the client.
- **Byte- and step-priced certification.** No closure, heap, output or step ceilings at `check`; the certificate certifies shape, uniformity, completeness class and prediction eligibility. Resources are metered at runtime (LLP 2000.000 §6).
- **A per-query result cache.** No range receipts, validators, halos, absence evidence, coverage spans, extent facts, held directories, fact integrity or swap journals. The client replicates declared partitions with one watermark each (LLP 2000.000 §7).
- **Engine-minted ids for client inserts, grants, ID slices.** Ids are client-minted, time-ordered, 128-bit; the engine mints for its own writes.
- **The `drain` protocol, follower-tab inbox rows, `defineItems`, `withHistory`, `mutationTarget`, `receipt.source`, `local.caughtUp`, `partial` reason codes.** The card (`packages/snapback4/src/contract.ts`) is the whole client vocabulary; `why` carries the rest.
- **`retain` as a receipt rule.** `until-revoked` and `delivered-history` survive as the client's leave policy on a scope tombstone.
- **JavaScript in the data plane.** Queries and mutations run in the Rust interpreter inside the SQLite transaction, and in the same interpreter on the client (host decided at week 3 by measurement, LLP 2000.000 §9). A *job* may be the app's own Rust, hosted as wasm through the interpreter's operations under the job's meter (LLP 3000.005, the Moves line below); a query or mutation may not.
- **An embedded JS engine for effects.** The data plane never calls out. `emit` writes the effect durably in the mutation's commit and an external worker holding a service token claims, performs and settles it over the wire (`snapback4/worker`); the four reference effects run on the builder's Node (LLP 2000.000 §10, decided 2026-09-13).
- **Committed generated code; an auth mode; a supervised bundler.** As Snapback 2 (`rules/NOT-DOING.md`): types by inference, personas not modes, `SNAPBACK_URL` is the client contract.
- **A TypeScript twin of the interpreter.** Retired by the author's ruling of 2026-09-13 (LLP 3000 §7): one implementation, in Rust, on every host — the core's SQLite under the native module, memory under wasm on the web with the host persisting each commit's changes. The web pays 312,924 B gzip before the diet where the twin's tier paid 16,842; the conformance obligation between two interpreters ends. Expo Go runs the online tier.
- **More than one hosted target, an admin console, media transcoding or thumbnails, push delivery itself (a worker's), cron syntax beyond `every N at HH:MM`, vector or relevance-ranked search (word-prefix search is in: `words(..)` and `matching`), federation, multi-region, device-to-device sync, at-rest encryption claims.** After the clock, on evidence.
- **General observability beyond `why`, `trace`, `logs`, `data`, `sql`, server operation latency, and bounded client subscription inspection.** The `sql` verb is read-only inspection of the developer's own store (LLP 3000.007 §8.8), never an application surface. Separately declared application SQL reads are admitted for increment D (LLP 3000.009 §6.2, §14.4; the 2026-09-16 Moves line below), not implemented by this inspection verb.
- **A guide corpus.** The compiler's facts, one language card and keyword cards, as Snapback 2; no freshness dates. Every card's Quarry is compiled by the suite and the language card is run, so a card cannot promise a form the parser refuses.

- **Partial union delivery, two group audiences, a public branch.** A union syncs principal-column branches and at most one group branch, each a whole disjunct of the read rule (LLP 3000.036.000.000); a branch with an extra condition, a second group or a `public` branch is refused with the rewrite, never partially delivered; service grants add no device audience (LLP 3000.007 §20.6). A union does not combine with delivered history, read-through children, synced or row-keyed views, owner keys, timelines, private field owners, acquisition windows or direct/inherited expiry on content or membership scopes.
- **Exact horizon maintenance.** The horizon bounds acquisition (a snapshot, a bootstrap); the log never evicts or back-fills to hold a device's group at exactly N rows. A local read past the acquired horizon by key says `complete: false`.

- **Clock expressions in rules.** A read rule compares with `=` and `!=` only; `.expiresAt > now` remains a mutation `require`. Stored lifetimes use `not before .col` for server-controlled opening and `expire at .col` for expiry. The engine publishes opening commits; devices receive no unopened payload. The supported compositions and explicit exclusions are in LLP 3000.036.003.
- **A jobs framework.** No priorities, worker pools or dead letters: one FIFO of runs, one chunk at a time, a refused chunk parked with its refusal. Actions, effects and scheduled actions carry per-operation retries, deadlines and cancellation, and a record per external step (LLP 3000.009 §5.2; the Moves line below). Missed period boundaries while a server is down fire once on return, not once per missed period.
- **Asset processing.** No transcoding, thumbnails, rungs or HEIC: the bytes are served as uploaded; JPEG, PNG, WebP and MP4 only; image dimensions and optional MP4 duration read from the header; MP4 dimensions are not extracted.
- **Search beyond word prefixes.** One tokenizer (NFC, lowercase, alphanumeric words), one index shape (`scope, words(cols), order.., id`), one read (`matching`): every term a prefix of some word, the first term's words merged as lanes, bounded by the meter in a uniform scope, at most 32 words in an admitted non-uniform scope. No stemming, no ranking by relevance, no phrase or mid-word matching, no per-language folding, no intersection index for the second term (it filters the page).
- **An identity provider.** Guests, password accounts, service seats, and sessions a service mints for accounts the application authenticated itself. No phone, OAuth, magic links or MFA in the engine: an application's worker verifies those and mints the session.
- **No multi-server presence, no presence history or last-seen storage, no broadcast event stream, no connection-bound rows.** `connected[p]` stays server-wide, counting held polls and their 35 s grace; a live query that may read it re-runs in the background about every 5 seconds to stay current (LLP 3000.018). Typing and viewing use short-lived, authorized ephemeral tables in one server process (LLP 3000.017); they never sync or decide durable invariants. A device does not know presence and says so.

## Process not doing

- **2026-09-28 — ordinary mixed search** (LLP 3000.028 §3.3, lane OS round 1).
  Admit the SDK's bounded merge of current server rows and certified Left images
  for the proved single time-ordered word page. This removes application-owned

  recomputation pays again from consumed positions. The coordinator shares the

  new authority or additional allowance is admitted.

  lane OS). A single bare ordinary word page may derive the exact non-expiring

  requirement to repeat that audience predicate in this narrow server query.

- **No drift registries, inventories, line-pinned diagnostics registries, claim digests or frozen-record gates.** Generated projections are built, not committed.
- **No gate bound to an exact commit; no push gated on a battery.** Five blocking checks in sixty seconds, run before push; everything slower on a schedule with bounded tickets.
- **No ceiling raised in slice one.** Budgets are anchored to a competitor's measured number and recorded once in the journal.
- **No standing panel** except the two blind reviews LLP 3000 decision 4 names (partition inversion; the meter's cut on non-uniform scans). The author explicitly commissioned the one-off LLP 3000.008 panel and disjoint Astra implementation lanes on 2026-09-14; its bounded disposition is recorded in that umbrella and LLP 3000 §7.
- **No new LLP number** without first extending LLP 3000 or LLP 2000.000; no spec without running code (`rules/RULES.md`: only implemented specs bind).
- **No second session on the core** during slice one; lanes take the periphery.
- **No test matrix as the primary harness.** The simulator is; real-browser and device witnesses cover only what it cannot reach.
- **No files over 1,500 lines**, including ones copied from Snapback 2. Split on
  the way in. The one exception is the package's published documents
  (`packages/snapback4/README.md` and its linked references): the rule exists to
  keep a *source* file reviewable, and the 0.2.25 calibration measured the cost of
  applying it to a document — splitting the README was that run's single largest
  scoring loss, because the builder then had four places to look instead of one
  (LLP 3000.007 §20.19). A published document is bounded by whether a builder can
  find one way in, not by a line count; the census that enforces this rule covers
  source, and says so.

## Deliberately worse

- No compatibility with Snapback 1 or Snapback 2 apps, packages or on-disk formats.
- No API stability before the clock; every publish is `0.0.x`.
- Sparse prose documentation; the diagnostics and the recipes carry the load.
- One hosted target, one platform binary at a time. SQLite remains the default store; Postgres as a production store is being built under LLP 3000.009.001 (Moves, 2026-10-20) and is not yet a supported deployment target.

## Summary

Snapback 4 is one of two parallel candidates for the successor to Snapback 2,
and the sibling of Snapback 3, not its successor. It builds
[LLP 2000.000](./2000.000-keep-the-core-flip-two-substrates.rfc.md) as
written: the Snapback 2 core kept verbatim, two substrates flipped up front —
resources metered at runtime instead of priced statically, and a client that
replicates the viewer's declared partition instead of caching receipted
results — proved first on the hub fixture, with a deterministic simulator as
the primary harness. Snapback 3 ([LLP 2000](./2000-snapback3.rfc.md), led by
Codex / GPT-6 Astra) keeps the same two questions open and discovers their
answers in its first slice. Snapback 2 ([LLP 1000](./1000-snapback2.explainer.md))
continues as the incumbent and the control. All three are judged by one
pre-registered comparison on one clock.

This document records the author's decisions of 2026-09-12 that created the
track, restates the bet on one page so a reader can orient without the brief,
fixes the bakeoff protocol, draws the fence, and plans the first four weeks.
The design argument and its evidence stay in LLP 2000.000. Only running code
will bind (`rules/RULES.md`).

**Flip 1 — certify authorization, meter resources** (LLP 2000.000 §6). The
certificate keeps every read site's shape, uniformity, completeness class
and prediction eligibility, and stops pricing bytes and steps. A
deterministic meter charges examined rows, index entries, rule probes,
steps, heap, output and rows written as the program runs, on the server and
in the client interpreter alike. A query cut by the meter returns `capped`
with no continuation past the cut, the same observable outcome as a static
ceiling cut today; a mutation aborts with `E_BOUND` naming actual work; a
job is chunked. `check --cost` prints the structural cost class; `test`
prints measured meters on the hub fixture.

**Flip 2 — the viewer's partition is the unit of sync** (LLP 2000.000 §7).
`sync to <audience> last N by <index>` on a table makes the engine maintain,
per principal, the rows that principal may read, as a change log with a
horizon; a table without the word is online-only, and `check` says which
rule term prevented inversion. The client holds a replica of its partitions,
one watermark each, a durable outbox with client-minted ids, and the
interpreter; queries run locally and are `complete` inside the horizon.
Revocation is a scope tombstone; `until-revoked` and `delivered-history`
survive as the client's leave policy. Two client tiers — online-only
without a store, local-first with one — share one language and one server.

**The vocabulary is fixed before the mechanism** (LLP 2000.000 §8):

```ts

type Write = { state: "pending" } | { state: "sent"; seq: number } | { state: "failed"; why: Refusal };
type Link = "online" | "offline" | "signed-out";
```

A screen that needs a word not on that card is a defect in the mechanism,
not a gap in the card.

**The hub comes first** (LLP 2000.000 §11): the Clique generator's `u0001`
with 1,000 memberships, `u0500` with 500 follows, and about 100,000
messages are the first fixture; day-two changes are designed before the
day-one screen; the native client is in slice one; physical floors are
measured before targets; the simulator is the primary harness.

use crate::{RuntimeError, authority::{self, AuthorityTransaction, SessionScope}};
use super::{Engine, effects::OutboxTransaction};
use crate::metadata::MetadataReader;

pub(crate) const PAGE: usize = 128;

pub(crate) struct ClockSession {
    pub digest: String,
    pub created_at: i64,
}

pub(crate) struct ClockMint {
    pub invocation: String,
    pub intent: String,
    pub principal: String,
    pub family: String,
    pub generation: i64,
    pub expires_at: i64,
}

/// Bounded facts and exact timestamp writes, under the existing writer fence.
/// Worker-marked families are excluded from this enumeration: their timestamps
/// remain owned by the existing worker-lease primitive.
pub(crate) trait SessionClockTransaction: AuthorityTransaction {
    fn clock_sessions(&self, read: bool, after: Option<&str>) -> Result<Vec<ClockSession>, RuntimeError>;
    fn set_clock_session(&self, digest: &str, scope: SessionScope, created_at: i64, expires_at: i64, cap: Option<i64>) -> Result<(), RuntimeError>;
    fn clock_mints(&self, after: Option<(&str, &str)>) -> Result<Vec<ClockMint>, RuntimeError>;
    fn set_clock_mint(&self, invocation: &str, intent: &str, expires_at: i64) -> Result<(), RuntimeError>;
}

fn shifted(value: i64, delta: i64) -> Result<i64, RuntimeError> {
    value.checked_add(delta).ok_or_else(|| RuntimeError::Input("staging clock advance overflows a session timestamp; use a smaller advance".into()))
}

fn sessions(tx: &impl SessionClockTransaction, delta: i64, before: i64, apply: bool) -> Result<(), RuntimeError> {
    for read in [false, true] {
        let mut after = None;
        loop {
            let page = tx.clock_sessions(read, after.as_deref())?;
            if page.is_empty() { break; }
            for candidate in &page {
                let Some(session) = authority::live_session(tx, &candidate.digest, before)? else { continue; };
                // Delegated action credentials remain capped by their claim and
                // product deadline. The worker primitive owns their lease shift.
                if session.kind == "action" || (session.scope == SessionScope::Read) != read { continue; }
                let created_at = shifted(candidate.created_at, delta)?;
                let expires_at = shifted(session.expires_at, delta)?;
                let cap = session.cap_expires_at.map(|cap| shifted(cap, delta)).transpose()?;
                if apply { tx.set_clock_session(&candidate.digest, session.scope, created_at, expires_at, cap)?; }
            }
            after = page.last().map(|s| s.digest.clone());
        }
    }
    Ok(())
}

fn mints(tx: &impl SessionClockTransaction, delta: i64, before: i64, apply: bool) -> Result<(), RuntimeError> {
    let mut after: Option<(String, String)> = None;
    loop {
        let page = tx.clock_mints(after.as_ref().map(|(invocation, intent)| (invocation.as_str(), intent.as_str())))?;
        if page.is_empty() { break; }
        for mint in &page {
            if mint.expires_at <= before || authority::family_authority_expiry(tx, &mint.principal, &mint.family, mint.generation, before)?.is_none() { continue; }
            let expires_at = shifted(mint.expires_at, delta)?;
            if apply { tx.set_clock_mint(&mint.invocation, &mint.intent, expires_at)?; }
        }
        after = page.last().map(|m| (m.invocation.clone(), m.intent.clone()));
    }
    Ok(())
}

// @ref LLP 3000.000.000.001#11-wave-22-loop-repairs-dx6 — staging can preserve live credential lifetime while moving application time.
pub(crate) fn preserve(tx: &impl SessionClockTransaction, delta: i64, before: i64) -> Result<(), RuntimeError> {
    if delta < 0 { return Err(RuntimeError::Input("staging clock advance must be non-negative".into())); }
    // Validate the complete change with bounded pages before the first write.
    // The writer transaction gives both passes the same authority snapshot;
    // shifts never change token keys, scope, family or revocation generations.
    sessions(tx, delta, before, false)?;
    mints(tx, delta, before, false)?;
    mints(tx, delta, before, true)?;
    sessions(tx, delta, before, true)
}

/// Server-authoritative lifetime of the exact live bearer, without token material.
pub struct SessionTiming {
    pub expires_at: i64,
    pub cap_expires_at: Option<i64>,
}

impl Engine {
    /// Read timing from the same detached authority snapshot as store identity.
    /// HTTP invokes this only for an immutable classified staging host.
    pub fn staging_session_timing(&self, token: &str, now: i64, expected_store: &str) -> Result<Option<SessionTiming>, RuntimeError> {
        self.store.with_authority_snapshot(|tx| {
            if tx.store_identity()?.as_deref() != Some(expected_store) {
                return Err(RuntimeError::Auth("the serving store identity changed".into()));
            }
            Ok(authority::live_session(tx, &crate::identity::digest(token), now)?.map(|session| SessionTiming {
                expires_at: session.expires_at, cap_expires_at: session.cap_expires_at,
            }))
        })
    }
    /// Staging preserves credential lifetime by default; explicit expiry proofs
    /// pass false. Application deadlines and retry backoffs continue to advance.
    pub fn advance_staging_clock_at(&mut self, milliseconds: i64, before: i64, preserve_sessions: bool) -> Result<(), RuntimeError> {
        let tx = self.store.transaction()?;
        if preserve_sessions { preserve(&tx, milliseconds, before)?; }
        tx.shift_worker_leases(milliseconds, before)?;
        tx.commit()?;
        Ok(())
    }
}

/// UTC calendar text for Unix milliseconds: schedule boundaries are UTC.
pub fn utc(ms: i64) -> String {

    let doy = doe - (365 * yoe + yoe / 4 - yoe / 100);

        if old >= end { continue; }
        let periods = schedule.periods_between(old, end);
        if each_boundary && periods > (10_000 - boundaries.len()) as i64 {
            return Err(crate::dev_clock::input("--each-boundary crosses more than 10000 schedule windows; use a smaller duration or omit --each-boundary to coalesce"));
        }
        report_bytes = report_bytes.saturating_add((if each_boundary { periods as usize } else { (periods as usize).min(SKIPPED_PREVIEW + 1) }).saturating_mul(1024 + 8 * schedule.target.len()));
        if report_bytes > REPORT_BYTE_BUDGET { return Err(crate::dev_clock::input("schedule window report exceeds its byte budget; use a smaller duration")); }
        if !each_boundary { continue; }
        let mut boundary = schedule.next(old);
        while boundary <= end {
            boundaries.push((index, boundary));
            boundary = schedule.next(boundary);
        }
    }
    boundaries.sort_by_key(|(index, at)| (*at, *index));
    Ok(boundaries)
}

// @ref LLP 3000.000.000.001#11-wave-22-loop-repairs-dx6 — no silent successful advance behind retained schedule markers.
pub fn refuse_held(engine: &Engine, before: &[Option<i64>], now: i64) -> Result<(), snapback4_core::Refusal> {
    for (schedule, saved) in engine.schema().schedules.iter().zip(before) {
        if let Some(saved) = saved.filter(|saved| *saved >= schedule.boundary(now) && *saved > schedule.boundary(snapback4_core::now_ms())) {
            let due = schedule.next(saved);
            return Err(snapback4_core::Refusal::new("E_CLOCK_HELD", "clock", format!(
                "schedule {} already processed boundary {}; requested clock {} has not reached its next window {}. Nothing advanced. Advance {} or use a fresh staging deployment; allowHeld:true explicitly accepts this hold. Never rewind saved boundaries",
                schedule.name, utc(saved), utc(now), utc(due), span(due - now))).guide("clock"));
        }
    }
    Ok(())
}

fn period(schedule: &snapback4_core::schema::Schedule) -> String {
    schedule.describe()
}

/// What each schedule did on one clock advance, and why one did not fire.
/// The core fires each schedule at most once per advance, for the latest
/// boundary, and holds it while its saved boundary is ahead of the clock.
// @ref LLP 3000#7-decisions-during-execution — missed boundaries fire once; this only explains them.
pub fn schedule_report(engine: &Engine, before: &[Option<i64>], fired: &[String], now: i64, held: bool, each_boundary: bool, port: Option<u16>) -> Vec<serde_json::Value> {
    let after = saved_boundaries(engine);
    // Read only bounded summaries: job args/cursors and full error payloads
    // are irrelevant to this report and must not be loaded then replicated.
    let runs = job_summaries(engine).unwrap_or_default();
    engine.schema().schedules.iter().enumerate().map(|(index, schedule)| {
        let (old, saved) = (before.get(index).copied().flatten(), after.get(index).copied().flatten());
        let current = schedule.boundary(now);
        let next = schedule.next(current);
        let mut entry = serde_json::json!({ "name": schedule.name, "target": schedule.target, "period": period(schedule), "fired": false, "firedWindows": [], "skippedBoundaries": [], "nextBoundary": utc(next) });
        if fired.contains(&schedule.name) {
            let end = saved.unwrap_or(current);
            entry["fired"] = true.into();
            let start = schedule.previous(end);
            let window = |boundary| serde_json::json!({"periodStart": schedule.previous(boundary), "periodEnd": boundary});
            let mut windows = Vec::new();
            if each_boundary {
                if let Some(old) = old {
                    let mut at = schedule.next(old);
                    while at <= end { windows.push(window(at)); at = schedule.next(at); }
                }
            } else { windows.push(window(end)); }
            if each_boundary {
                entry["reason"] = format!("fired {} windows: {}", windows.len(), windows.iter().map(|window| format!("{} to {}", utc(window["periodStart"].as_i64().unwrap()), utc(window["periodEnd"].as_i64().unwrap()))).collect::<Vec<_>>().join("; ")).into();
            }
            entry["firedWindows"] = windows.into();
            entry["periodStart"] = start.into();
            entry["periodEnd"] = end.into();
            if !each_boundary { entry["reason"] = format!("fired for the period {} to {}", utc(start), utc(end)).into(); }
            if let Some(run) = runs.get(&schedule.target) { entry["run"] = run.clone(); }
            // @ref LLP 3000.040#24-monthly-and-yearly-schedules — calendar periods count boundaries, not milliseconds.
            let skipped = if each_boundary { 0 } else { old.map(|old| schedule.periods_between(old, end) - 1).unwrap_or(0) };
            if skipped > 0 {
                entry["skippedPeriods"] = skipped.into();
                let mut windows = Vec::new();
                let mut at = schedule.next(old.unwrap());
                while at < end && windows.len() < SKIPPED_PREVIEW {
                    let mut item = window(at);
                    let mut args = serde_json::Map::new();
                    if let Some(program) = engine.program(&schedule.target) {
                        if program.args.contains_key("periodStart") { args.insert("periodStart".into(), schedule.previous(at).into()); }
                        if program.args.contains_key("periodEnd") { args.insert("periodEnd".into(), at.into()); }
                    }
                    item["command"] = format!("snapback4 run {} '{}'{}", schedule.target, serde_json::Value::Object(args), port.map(|port| format!(" --port {port}")).unwrap_or_default()).into();
                    windows.push(item); at = schedule.next(at);
                }
                entry["skippedBoundariesOmitted"] = (skipped - windows.len() as i64).into();
                entry["skippedBoundaries"] = windows.into();
                entry["reason"] = format!("fired once, for the latest period {} to {}; {skipped} earlier period{} this advance crossed (from {}) did not run: missed boundaries fire once. Run {} with periodStart/periodEnd for an earlier period",
                    utc(start), utc(end), if skipped == 1 { "" } else { "s" }, utc(old.unwrap_or(end)), schedule.target).into();
            }
        } else if held {
            entry["holdCode"] = "disabled".into();
            entry["reason"] = "schedules are held (dev --hold-schedules or --replay); a restart without the flag resumes at the next boundary".into();
        } else if let Some(saved) = saved.filter(|saved| old.is_some() && (*saved > current || *saved == current && *saved > schedule.boundary(snapback4_core::now_ms()))) {
            let due = schedule.next(saved);
            entry["holdCode"] = "saved-boundary".into();
            entry["savedBoundary"] = saved.into();
            entry["heldUntil"] = utc(due).into();
            entry["nextBoundary"] = utc(due).into();
            entry["reason"] = format!("held by the store: boundary {} was already processed and this clock {} has not reached its next window (restarting resets the process offset, not the saved boundary). One fire per boundary. Advance {} more, or use a fresh staging deployment/store for an independent test; keep the same --clock-offset when continuing a test across serve restarts",
                utc(saved), utc(now), span(due - now)).into();
        } else if old != saved {
            entry["holdCode"] = "initialized".into();
            entry["reason"] = format!("{} started at boundary {}: a schedule fires at the boundary after the first one it sees, next {} ({} from now)",
                if old.is_none() { "this schedule" } else { "this changed schedule" }, utc(saved.unwrap_or(current)), utc(next), span(next - now)).into();
        } else {
            entry["holdCode"] = "not-due".into();
            entry["reason"] = format!("next boundary {} ({} from now; schedule times are UTC)", utc(next), span(next - now)).into();
        }
        entry
    }).collect()
}

// @ref LLP 3000.000.000.001#10-wave-20-loop-repairs-dx5 — every declared schedule has one reported outcome.
pub fn outcomes(schedules: &[serde_json::Value]) -> (Vec<serde_json::Value>, Vec<serde_json::Value>) {
    schedules.iter().cloned().partition(|schedule| schedule["fired"] == true)

/// The report never loads full error/argument payloads from retained jobs.
fn job_summaries(engine: &Engine) -> Result<std::collections::BTreeMap<String, serde_json::Value>, RuntimeError> {
    let mut summaries = std::collections::BTreeMap::new();
    for summary in engine.store().job_summaries(REPORT_ERROR_BYTES)? {
        let name = summary.name;
        if summaries.contains_key(&name) { continue; }
        let mut error = summary.error;
        let truncated = summary.error_truncated;
        if let Some(text) = &mut error && truncated {
            let mut end = REPORT_ERROR_BYTES.min(text.len());
            while !text.is_char_boundary(end) { end -= 1; }
            text.truncate(end); text.push('…');
        }
        summaries.insert(name, serde_json::json!({ "id":summary.id, "state":summary.state,
            "rowsWritten":summary.rows_written, "error":error, "errorTruncated":truncated }));
    }
    Ok(summaries)
}

/// Startup lines for schedules the store holds: their saved boundary leads the clock.
pub fn held_schedules(engine: &Engine, now: i64) -> Vec<String> {
    engine.schema().schedules.iter().zip(saved_boundaries(engine)).filter_map(|(schedule, saved)| {
        let saved = saved.filter(|saved| *saved > schedule.boundary(now))?;
        let due = schedule.next(saved);
        Some(format!("clock     schedule {} is held until {} ({} from now): its saved boundary {} is ahead of this clock; `clock advance {}` or restart with dev --resume-clock",
            schedule.name, utc(due), span(due - now), utc(saved), span(due - now)))
    }).collect()
}

/// The dev clock offset that continues a store's own time: its newest
/// recent commit stamp (or saved schedule boundary) less wall time, never negative.
pub fn resume_offset(store: &snapback4_core::store_port::AnyStore, wall: i64) -> Result<i64, RuntimeError> {
    let commit = store.recent_commit_max_at(RECENT_COMMITS as i64)?;
    let boundary = store.latest_schedule_boundary()?;
    let latest = commit.into_iter().chain(boundary).max().unwrap_or(wall);
    // Whole seconds, rounded up, so restarting twice does not drift backwards.
    Ok((latest.saturating_sub(wall).max(0) + 999) / 1_000 * 1_000)
}

pub fn has_data(engine: &Engine) -> bool {
    engine.store().inspection_has_data().unwrap_or(false)
}

    format!("clock     offset from wall time: {offset:+}ms{}", if running { " (lasts until restart)" } else { " (no running dev; inspecting against wall time)" })
}

pub fn duration(text: &str) -> Result<i64, Refusal> {

    let (number, unit) = text.split_at(split);

#[derive(Clone, Debug)]
pub struct Clock {
    dev: bool,
    base: i64,
    offset: i64,
    started: Instant,
    epoch: String,
    revision: u64,
    #[cfg(test)]
    frozen: bool,
}

impl Clock {
    pub fn new(dev: bool, offset: i64) -> Result<Self, Refusal> {
        if !dev && offset != 0 { return Err(release()); }
        Ok(Self { dev, offset, base: time(snapback4_core::now_ms().checked_add(offset))?, started: Instant::now(),
            epoch: snapback4_core::ids::mint(snapback4_core::now_ms(), &mut snapback4_core::ids::Mint::default()).map_err(|e| e.refusal())?, revision: 0, #[cfg(test)] frozen: false })
    }
    #[cfg(test)]
    pub(crate) fn freeze(&mut self, now: i64) { self.base = now; self.frozen = true; }
    pub fn now(&self) -> i64 {
        #[cfg(test)] if self.frozen { return self.base; }
        if !self.dev { return snapback4_core::now_ms(); }
        self.base.saturating_add(self.started.elapsed().as_millis().min(MAX_TIME as u128) as i64).min(MAX_TIME)
    }
    /// Identifies samples taken before/after a restart or deliberate clock jump.
    pub fn offset(&self) -> i64 { self.offset }
    pub fn revision(&self) -> String { format!("{}:{}", self.epoch, self.revision) }
    pub fn presence_now(&self) -> i64 {
        // Production grace is elapsed real time, unaffected by wall-clock corrections.
        if self.dev { self.now() } else { self.started.elapsed().as_millis().min(MAX_TIME as u128) as i64 }
    }
    /// Back to wall time: the offset `--clock-offset` and every advance added
    /// is dropped (a development reset's `{"clock":"reset"}`).
    pub fn reset(&mut self) -> Result<i64, Refusal> {
        if !self.dev { return Err(release()); }
        self.revision += 1;
        self.offset = 0;
        self.base = snapback4_core::now_ms();
        self.started = Instant::now();
        #[cfg(test)] { self.frozen = false; }
        Ok(self.base)
    }
    pub fn advance(&mut self, milliseconds: i64) -> Result<i64, Refusal> {
        if !self.dev { return Err(release()); }
        if milliseconds <= 0 { return Err(input("clock advance cannot move backwards; use a positive duration such as +2m")); }
        let next = time(self.now().checked_add(milliseconds))?;
        let offset = self.offset.checked_add(milliseconds).ok_or_else(|| input("cumulative clock offset overflow"))?;
        self.revision += 1;
        self.offset = offset;
        self.base = next;
        self.started = Instant::now();
        Ok(next)
    }
}

/// The notification's head, identity and invalidations share one read snapshot.
fn check(engine: &mut snapback4_core::engine::Engine, since: u64) -> Result<Checked, snapback4_core::error::RuntimeError,
> {
    let all_tables: Vec<_> = engine.schema().visible_tables().map(|(n,_)|n.clone()).collect();
    let schema = engine.schema().clone();
    let tx = engine.store_mut().read_transaction()?;
    let head = tx.next_seq()? - 1;
    let store_id = tx.optional_store_id()?;
    let changes = tx.commits_after(since, 500)?;
    // Advancing to the actual head must not skip invalidation beyond the
    // bounded commit page. Saturation conservatively invalidates every table.
    let mut tables = if changes.last().is_some_and(|(seq, _)| *seq < head) { all_tables }
        else { changes.into_iter().flat_map(|(_, tables)| tables).filter(|name| all_tables.contains(name)).collect() };
    tables.sort();
    tables.dedup();
    let preserved = tx.preserved_between(&schema, since, head);
    let changes = settlement_changes(tx.footprint_between(since, head), &schema, since, head);
    tx.rollback()?;
    Ok((head, store_id, tables, preserved, changes))
}

    started: bool,

impl PollResponse<'_> {
    fn heartbeat(&mut self) -> io::Result<()> {
        let request = self.request.as_mut().unwrap();
        let mut frame = String::new();
        if !self.started {
            frame.push_str("HTTP/1.1 200 OK\r\nContent-Type: application/json\r\nCache-Control: no-store, no-transform\r\nX-Accel-Buffering: no\r\nTransfer-Encoding: chunked\r\n");
            // Clock time belongs to the final body, after the hold. A buffering
            // transport must not mistake early headers for an end stamp.
            for header in cors(request).into_iter().chain(request.connection_headers()).chain(super::ephemeral_headers(self.shared)).chain(super::latency::header()) { frame.push_str(&format!("{header}\r\n")); }
            frame.push_str("\r\n");
            self.started = true;
        }
        frame.push_str("1\r\n\n\r\n");
        request.write_response_frame(frame.as_bytes())
    }

            self.request.take().unwrap().finish_stream();
        } else {
            super::latency::finished(true);
        }
    }

pub(super) fn seed(request: Request, shared: &Shared, body: &str) {
    if !shared.dev_doors() || !request.remote_addr().is_some_and(|a| a.ip().is_loopback()) {
        respond_timed(request, shared, 403, json!({ "denied": refusal_json(&Refusal::new("E_AUTH", "auth", "seeding is a development door")) }));
        return;
    }
    let refuse = |request, refusal: Refusal| respond_timed(request, shared, 400, json!({ "denied": refusal_json(&refusal.guide("personas")) }));
    let rows: Vec<Json> = match serde_json::from_str(body) {
        Ok(Json::Array(rows)) => rows,
        _ => return refuse(request, Refusal::new("E_INPUT", "input", "seed takes a JSON array of {table, row}")),
    };
    let mut engine = lock(&shared.engine);
    if let Err(why) = shared.dev_authority(&engine) { drop(engine); return respond_timed(request, shared, 403, json!({"denied":refusal_json(&why)})); }
    let now = shared.now();
    let typed = match typed_rows(engine.schema(), &rows, now) {
        Ok(typed) => typed,
        Err(refusal) => { drop(engine); return refuse(request, refusal); }
    };
    let outcome = engine.seed_at(typed, now);
    drop(engine);

            respond_timed(request, shared, 200, json!({ "seeded": count }));
        }
        Err(error) => respond_timed(request, shared, 200, json!({ "denied": refusal_json(&seed_refusal(error)) })),
    }
}

/// `/seed` rows checked against the served schema and typed, or the first problem.
fn typed_rows(schema: &snapback4_core::Schema, rows: &[Json], now: i64) -> Result<Vec<(String, snapback4_core::Value)>, Refusal> {
    let mut typed = Vec::new();
    for (index, entry) in rows.iter().enumerate() {
        let (Some(table), Some(row)) = (entry.get("table").and_then(Json::as_str), entry.get("row")) else {
            return Err(Refusal::new("E_INPUT", "input", "each seed entry is {table, row}"));
        };
        let Some(definition) = schema.table(table) else {
            return Err(Refusal::new("E_INPUT", "input", format!("unknown table {table}")));
        };
        if row.is_object() && row.get("id").is_none_or(|id| !id.is_string()) {
            return Err(missing_id(index, table));
        }
        let mut row = row.clone();
        crate::verbs::test_fixture::relative_times(definition, &mut row, now)
            .map_err(|why| Refusal::new("E_FIXTURE_TIME", "input", format!("seed row {index} ({table}): {why}")))?;
        if let Some(why) = wire::bare_principal(definition, &row) {
            return Err(Refusal::new("E_INPUT", "input", format!("seed row {index} ({table}): {why}")));
        }
        match wire::row_from_json(definition, &row) {
            Ok(value) => typed.push((table.to_owned(), value)),
            Err(why) => return Err(Refusal::new("E_INPUT", "input", format!("{table}: {why}"))),
        }
    }
    Ok(typed)
}

fn seed_refusal(error: snapback4_core::RuntimeError) -> Refusal {
    let mut refusal = error.refusal();
    // Reseeding with changed immutable values reads like a rule problem; say what happened.
    if refusal.code == "E_CONSTRAINT" && refusal.message.ends_with(" is immutable") {
        refusal.message.push_str("; /seed is an upsert by id, and a row with that id already exists with a different value in that column. Reseed it with its original value, give the row a new id, POST /dev/reset first, or restart dev with --memory for an empty store");
    }
    refusal
}

/// What `POST /dev/reset` was asked to do: the body is empty, a `/seed`
/// array, or `{"seed": [..], "clock": "reset"}` with either key optional.
#[derive(Debug, Default, PartialEq)]
struct ResetRequest { seed: Vec<Json>, clock: bool }

fn reset_request(body: &str) -> Result<ResetRequest, Refusal> {
    const SHAPE: &str = "reset takes no body, a /seed array [{table, row}, ..], or {\"seed\": [..], \"clock\": \"reset\"} with either key optional";
    if body.trim().is_empty() { return Ok(ResetRequest::default()); }
    match serde_json::from_str(body) {
        Ok(Json::Array(seed)) => Ok(ResetRequest { seed, clock: false }),
        Ok(Json::Object(fields)) => {
            let mut request = ResetRequest::default();
            for (key, value) in fields {
                match (key.as_str(), value) {
                    ("seed", Json::Array(seed)) => request.seed = seed,
                    ("clock", Json::String(clock)) if clock == "reset" => request.clock = true,
                    ("clock", Json::String(clock)) if clock == "keep" => request.clock = false,
                    ("clock", other) => return Err(crate::dev_clock::input(format!("reset's clock is \"reset\" (back to wall time) or \"keep\" (the default), not {other}"))),
                    (key, _) => return Err(Refusal::new("E_INPUT", "input", format!("{SHAPE}; got key {key:?}"))),
                }
            }
            Ok(request)
        }
        _ => Err(Refusal::new("E_INPUT", "input", SHAPE)),
    }
}

// @ref LLP 3000.007#20.25 — one transaction: empty, new identity, reseed; then the host's caches follow.
pub(super) fn reset(request: Request, shared: &Shared, body: &str) {
    if !shared.dev_doors() || !request.remote_addr().is_some_and(|a| a.ip().is_loopback()) {
        respond_timed(request, shared, 403, json!({ "denied": refusal_json(&reset_release()) }));
        return;
    }
    let started = std::time::Instant::now();
    let refuse = |request, refusal: Refusal| respond_timed(request, shared, 400, json!({ "denied": refusal_json(&refusal.guide("testing")) }));
    let asked = match reset_request(body) {
        Ok(asked) => asked,
        Err(refusal) => return refuse(request, refusal),
    };
    // Serialize with clock advances, then take the engine before the clock:
    // the order clock advance and worker claims use.
    let advance = lock(&shared.maintenance).advance.clone();
    let _advance = lock(&advance);
    let mut engine = lock(&shared.engine);
    if let Err(why) = shared.dev_authority(&engine) { drop(engine); return respond_timed(request, shared, 403, json!({"denied":refusal_json(&why)})); }
    let mut clock = lock(&shared.clock).clone();
    if asked.clock && let Err(refusal) = clock.reset() { drop(engine); return refuse(request, refusal); }
    let now = clock.now();
    // Resolve against the prospective reset clock before changing any durable state.
    let typed = match typed_rows(engine.schema(), &asked.seed, now) {
        Ok(typed) => typed,
        Err(refusal) => { drop(engine); return refuse(request, refusal); }
    };
    let reset = match engine.dev_reset_at(typed, now) {
        Ok(reset) => reset,
        Err(error) => {
            drop(engine);
            return respond_timed(request, shared, 200, json!({ "denied": refusal_json(&seed_refusal(error)) }));
        }
    };
    if asked.clock { *lock(&shared.clock) = clock; }
    *lock(&shared.dev_reset_store) = Some(reset.store_id.clone());
    // The reset committed a new identity and a new authority clock. Replace,
    // rather than max with, the retired store's cached high-water mark.
    shared.time_audience_clock.store(if engine.schema().tables.values().any(|t| t.not_before.is_some()) { now } else { i64::MIN }, std::sync::atomic::Ordering::Release);
    // Detached readers reopen; the following registry, change answers and
    // `/dev/status` forget the old identity. Wake then names the new store,
    // so every held poll returns and each client sees the replacement.
    let sites = lock(&shared.bound).refusal_sites.clone();
    lock(&shared.readers).replace(&engine, &sites);
    lock(&shared.adoption).store_id = reset.store_id.clone();
    if let Ok(reader) = snapback4_core::engine::following_history::Reader::new() { *lock(&shared.following) = reader; }
    *lock(&shared.change_answers) = Default::default();
    shared.durable_committed(&engine);
    let generation = engine.generation();
    drop(engine);
    let assets = reset.assets.len();
    if let Err(error) = reset.assets.remove_files() { snapback4_core::diagnostic!("snapback4 dev: reset left asset bytes behind: {error}"); }
    let now = shared.now();
    snapback4_core::diagnostic!("snapback4 dev: store reset (store {} → {}, seeded {}) in {} ms", reset.previous_store_id, reset.store_id, reset.seeded, started.elapsed().as_millis());
    respond_timed(request, shared, 200, json!({
        "sessionNotice":"Reset replaced the store and removed its accounts and sessions. Discard cached credentials/localStorage for this backend, sign up again and reprovision roles; use a fresh memory host per independent proof.",
        "reset": true, "seeded": reset.seeded, "generation": generation, "storeId": reset.store_id,
        "previousStoreId": reset.previous_store_id, "head": reset.seq, "assetsRemoved": assets,
        "now": now, "clockOffsetMs": lock(&shared.clock).offset(), "skewMs": now - snapback4_core::now_ms(), "ms": started.elapsed().as_millis() as u64,
    }));
}
