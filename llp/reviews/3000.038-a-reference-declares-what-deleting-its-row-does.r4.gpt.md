## Verbatim review

Revision 3 closes the effective-deadline, row-keyed-member, stale-root-image, and existence-guard findings. `Schema::delete_reservation` implements the new §5.1 meter table, including witnesses and the root reread. **The execution does not yet satisfy that reservation**, and several correctness and disclosure gaps remain.

Read-only review; no builds, edits, or commits. File paths below are relative to `snapback4/`.

1. **Blocker — restrict can miss an outside child when the root references itself.**  
   **Location:** RFC §3 step 4; `crates/snapback4-core/src/engine/write_references.rs:58`, `:71`, `:90`.

   The root enters `seen` and `visits`, but its outgoing references never enter `naming`. For `nodes.parent: nodes ?` with default restrict, let `a.parent = a` and `b.parent = a`, with `a` sorting first in the reference index. Deleting `a` computes `inside = 0`, fetches only `a`, excludes it because it belongs to the closure, and commits while leaving `b.parent` dangling.

   **Smallest fix:** populate the naming ledger from the root as well as discovered children. Alternatively, stream the probe until it finds an outside witness or exhausts the range. Lean’s `restricted` correctly includes the root in its closure exclusion; this case distinguishes the implementation from the model.

2. **Blocker — identity-only closure retention does not establish the promised heap bound.**  
   **Location:** RFC §5.1; `crates/snapback4-core/src/engine/write_references.rs:68`, `:105`, `:121`, `:137`; `crates/snapback4-core/src/schema/references.rs:254`.

   Although `reached` retains identities, `live_children` returns the entire group as `Vec<Value>`. That vector remains alive while its rows are processed. A cap-500 child with a `text <=200000` payload can retain roughly 100 MB of ASCII payload while §5.1 reserves roughly one row’s transient ceiling plus 500 identities—well below the default 16 MiB heap ceiling. The replacement meter is unbounded, so execution does not catch this.

   The retained `naming` triples also grow with **rows × outgoing references**, whereas the 384-byte scratch term grows only with rows.

   **Smallest fix:** stream bounded pages, discard each image after extracting its identity, and reread immediately before writing. Remove the per-reference naming ledger or add a schema-fixed allowance for it. The round-3 streaming finding remains open in code.

3. **High — the reply’s event count leaks whether an action changed the root.**  
   **Location:** RFC §4.2; `crates/snapback4-core/src/engine/write.rs:737`; `crates/snapback4-core/src/partition.rs:139`; `crates/snapback4-core/src/engine/columns.rs:85`.

   Give a public root `p` a maintained task count by `tasks.project`. Tasks have `project: projects on delete keep` and a separate `bucket: projects on delete cascade`; tasks are hidden from the caller.

   Compare two worlds with the same readable root image and count of one: the hidden task’s project is `p` in both, but its bucket is `q` versus `p`. In the first world, deleting `p` counts its root delete event. In the second, cascading the task first mirrors zero onto `p`, adding `(projects, p)` to `action_rows`. The event-count filter then excludes the root’s subsequent delete too. The reply distinguishes the hidden bucket association.

   **Smallest fix:** choose the root’s event-count treatment statically whenever its delete reaches a writing action. For example, exclude its identity unconditionally in that case, rather than depending on whether mirroring actually reached it.

4. **High — set-null writes can overwrite another action’s maintained-column update.**  
   **Location:** RFC §3 step 5 and §5.1; `crates/snapback4-core/src/engine/write_references.rs:105`, `:178`.

   Consider ordinary `nodes` with:
   - `category: categories ? on delete set null`, capped by category;
   - `parent: nodes ? on delete keep`;
   - a maintained count of nodes whose category is non-null, grouped by parent.

   Both `a` and `b` belong to category `c`; `a.parent = b`. The set-null scan buffers both images. Clearing `a.category` mirrors `b`’s count from one to zero. Clearing `b.category` subsequently uses its buffered count-one image and writes that value back. A plain index on the maintained count can also disagree with the stored image.

   **Smallest fix:** retain the scanned id and fetch the current image immediately before each `clear_reference`. The reservation already includes that reread.

5. **High — expiring restrict probes can exceed the reserved physical work.**  
   **Location:** RFC §5.1’s witness/amortization terms; `crates/snapback4-core/src/engine/write_references.rs:140`; `crates/snapback4-core/src/schema/references.rs:238`.

   Both deadline ranges receive the full `inside + 1` limit; only afterward are their combined results truncated.

   For a concrete counterexample, let a root cascade to 100 expiring `C` rows and one `T` row. Give `C` three ordinary restrict references to `T`. All 100 closure rows name that `T` through all three references and never expire. Another 101 live, finite-deadline rows outside the closure also name it; distribute those rows across other root groups to preserve the cascade cap.

   Each restrict reference fetches 100 never-expiring rows plus 101 finite rows. Discovery and restriction therefore fetch **704 rows before refusal**, while the complete §5.1 examined reservation is **515** for this schema. No expired backlog is visited, but the physical bound still fails.

   **Smallest fix:** pass only the remaining combined limit to the second range, or stream until the first outside witness. Preserve the schema-fixed published charge.

6. **High — the computed output reservation is never charged or checked.**  
   **Location:** RFC §5.1–§5.2; `crates/snapback4-core/src/engine/write_references.rs:32`; `crates/snapback4-lang/src/bind/reference_actions.rs:210`.

   `delete_reservation` accumulates `price[5]`, but `apply_reference_actions` omits `OutputBytes`. The compiler’s ceiling comparison omits it too. This is reachable: a permitted cascade target that is a row-keyed view’s **source** has a nonzero output price (`schema/reservations.rs:75`); only member targets are excluded.

   Such a delete reports less output work than its specified reservation and can pass admission despite exceeding the output ceiling. Inner source-plan charges disappear when the temporary meter is discarded.

   **Smallest fix:** charge `MeterKind::OutputBytes` from `price[5]` and compare it against `c.output_bytes` in `over_ceiling`.

7. **Medium — field-owned references silently receive an undocumented eligibility exception.**  
   **Location:** RFC §2.1 and §1’s integrity claim; `crates/snapback4-lang/src/bind/reference_actions.rs:62`; `crates/snapback4-core/src/schema/references.rs:372`.

   An undeclared reference with `written by` between two ordinary durable tables gets no action. Deleting its parent leaves the pointer intact, and explicit restrict is rejected. The RFC instead says every reference between those table kinds carries an action. Refusing writing actions into field-owned tables in §2.2 does not describe this separate exception.

   **Smallest fix:** explicitly exclude field-owned reference columns in §2.1 and qualify the integrity and migration claims. Preserve the privacy-motivated implementation behavior.

8. **Low — §8’s capability wording disagrees with `keep` lowering.**  
   **Location:** RFC §8; `crates/snapback4-lang/src/bind/reference_actions.rs:100`; `crates/snapback4-core/src/schema/capabilities.rs:74`.

   A schema whose ordinary references all explicitly declare keep lowers them by absence and requires no `reference-actions` capability. §8 currently says any action-carrying reference requires it and every ordinary-reference schema emitted by the compiler carries it.

   **Smallest fix:** state that keep uses legacy absence in the IR and that the capability is required when a non-keep action is emitted.

The parent authorization gate, bypass of child write rules, schema-order selection of an occupied restrict reference, static touched-table envelope, and `current_group` device proof are present. The original stale-root-image defect is closed; findings 3–4 concern separate interactions.

**Overall verdict: NOT READY.**
