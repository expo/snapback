## Findings

### 1. High — `N_WIDE_MERGE` still names the unprefixed command that Clique cannot run

**File:** `snapback4/crates/snapback4-lang/src/bind/mod.rs:261–263`

**Scenario.** The 0.2.21 builder’s first Following note was `N_WIDE_MERGE` with rewrite `snapback4 init --recipe feeds` (friction H2, `m2-check.txt`). A Clique-shaped app already has `posts` and `follows`. That command still refuses before write (`init.rs:108–123`). W6a taught `--prefix feed` and put it on `N_SPARSE_FILTER` (`reads.rs:108–110`) and on clash errors, but the relationship-merge note — the one that fired first in the calibration — is unchanged. A builder who follows the note still hits the collision and rebuilds the sparse global filter.

**Smallest fix.** Use the same command string as the sparse-filter rewrite: `` `snapback4 init --recipe feeds --prefix feed` `` (and the feeds card’s one-line adopt line if you want the first hop to match).

### 2. Medium — `N_NO_HORIZON` is suppressed for any Held read, not only whole-partition proofs

**File:** `snapback4/crates/snapback4-lang/src/bind/residency/horizons.rs:16–18`

**Scenario.** Table `archive` is `sync public` with no horizon. Eligible mutation `react` only pages `archive last 20 by byTime` (no absence proof, no insert-arm). `needs_whole_partition` is true because that page is `SiteClass::Held`. The growing-table note is omitted. Adding `last 500 by byTime` would not break prediction (the page would be `complete: false`), but the compiler no longer says so. The fixture only shows the converse (marking react/intents `server` restores four notes, `residency_notes.rs:458–461`).

**Smallest fix.** Treat a table as “needs the whole partition” only for Held *point/exists/insert-arm* sites (the comment at `:14–15`), not for ordinary pages.

### 3. Medium — lost-lease logging hides non-expiry `E_EFFECT_LEASE` and misstates the outcome

**File:** `snapback4/packages/snapback4/src/worker.ts:112–114`

**Scenario.** Worker A claims effect `E`, performs I/O, then settles. Meanwhile the lease expired and worker B already settled `E` as `sent`. A’s `/done` returns `E_EFFECT_LEASE` with “is sent and not claimed by this worker” (`effects.rs:126–128`). `runWorker` prints `effect E lease expired; the effect was requeued` at info and does not call `onError`. The effect was not requeued. The same path fires if B still holds the claim. Digest-style handlers that used `onError` as the only failure signal now miss a real settle failure; a log reader infers a retry that did not happen.

**Smallest fix.** Demote to info only when the engine says the row is `queued` (or include `denied.message`). Keep `onError` for `sent`/`running`/unknown. Do not claim “requeued” unless that is the recorded state.

### 4. Low — writes-card opener still sounds like arbitrary fixture ids work

**File:** `snapback4/crates/snapback4-lang/src/guide/writes.rs:15–19` (same sentence in README:1617–1622)

**Scenario.** The 0.2.21 replay adapter passed `mutationId: a[2]` (friction H7). `a[2]` is not 26-character Crockford; `mutate(..., { id: a[2] })` is local `E_WRITE_ID` and never hits the server record. The next sentences require `mintId()` form, so this is wording, not a logic bug. An adapter with arbitrary strings still needs its own ledger *or* must mint this form into the fixture.

**Smallest fix.** “Pass a `mintId()` you stored with the intent/fixture; arbitrary fixture strings still need an application ledger.”

### 5. Low — `N_HORIZON_GUARD` will also fire on an application uniqueness check that uses the same spelling

**File:** `snapback4/crates/snapback4-lang/src/bind/residency/horizons.rs:24–35`

**Scenario.** `require not exists tombstones[eventId] else EVENT_REMOVED` where `eventId` is an argument and `tombstones` is `sync … last 500 by byId`. The note tells the author to remove the guard “if this guard only dedupes retries” and to keep application requirements (`:34–35`, `mechanical == false`). An agent that applies the first clause anyway drops a real invariant. Not a mechanical `--fix`; residual of H3’s shape.

**Smallest fix.** Name the mutation write id vs the argument row id in the message even more sharply, or skip the note when the `else` code is not a duplicate/retry token.
