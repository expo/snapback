1. **MUST — Literal-set membership remains outside the classification fence.** [reserved.rs:214](/Users/ccheever/projects/snapback-qg-review/r2/astra/repo/snapback4/crates/snapback4-lang/src/parser/reserved.rs:214)

   `compared_words` returns no words. It recognizes membership only through the exact declaration shape `const NAME: &[&str] = &[...]`. A local array binding or `const WORDS: [&str; 1]` also escapes. A keyword admitted through these forms can remain an ordinary identifier while classification and editor coverage pass.

   **Smallest fix:** recognize inline literal-array receivers and their ordinary local/constant bindings; add negative witnesses for those forms alongside the existing constant-slice test.

2. **SHOULD — Template substitution accepts sigils that the actual expander leaves invalid.** [check.mjs:88](/Users/ccheever/projects/snapback-qg-review/r2/astra/repo/snapback4/editors/tree-sitter-quarry/check.mjs:88)

   ```quarry
   query $planted():
     return 1
   ```

   ```quarry

     return 1
   ```

   The fence substitutes `_planted` or `_TYPO_`, producing clean syntax. The actual [timeline expander:29](/Users/ccheever/projects/snapback-qg-review/r2/astra/repo/snapback4/crates/snapback4-lang/src/bind/timeline.rs:29) replaces only `@T@`, leaving these characters invalid. TextMate already scopes both sigil forms. The debug compiler confirmed syntax refusal before the fence substitution and acceptance afterward.

   **Smallest fix:** restrict substitutions to each template’s actual expansion vocabulary; enable `$name` only where the compiler implements it. Add unknown-placeholder and unsupported-local-sigil fault probes.

3. **SHOULD — An ignored line between an off-stack dedent and its destination loses recovery state.** [scanner.c:82](/Users/ccheever/projects/snapback-qg-review/r2/astra/repo/snapback4/editors/tree-sitter-quarry/src/scanner.c:82)

   Concrete input:

   ```quarry
   query q():
       return 1
   -- ignored
     return 2
   ```

   By code-path inspection, the scanner rounds the destination indentation from two spaces down to zero and emits the dedent before the comment. Processing the intervening extra clears `pending`; `laid_out` lasts only one invocation. At the two-space line, the initial-indent branch can therefore emit a new top-level block. Rust pops to zero, diagnoses the mismatch, and emits `return 2` without that new indent.

   The current regression puts the significant line directly after the preceding statement, so it misses this path. A complete tree-sitter reproduction was blocked by the sandbox.

   **Smallest fix:** preserve the completed-layout marker across blank/comment extras until the destination’s significant line is consumed. Add comment and blank-line variants of the off-stack regression.

4. **SHOULD — The new `matches!` scan treats guard strings as keyword patterns.** [reserved.rs:223](/Users/ccheever/projects/snapback-qg-review/r2/astra/repo/snapback4/crates/snapback4-lang/src/parser/reserved.rs:223)

   Concrete parser-source input:

   ```rust

       if token.site.file.ends_with("quarry"))
   ```

   The scan collects both `read` and `quarry`. The latter is a filename suffix, so a legitimate parser change using this expression fails classification or encourages adding a false keyword/exception. Every string after the first top-level comma is currently selected, including guard expressions.

   **Smallest fix:** stop unconditional pattern collection at the top-level guard `if`; let actual comparisons within the guard pass through the normal comparison rules. Add this negative witness.
