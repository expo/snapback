## Material concerns

**1. Plan §3 — cleanup runs before compaction today; incremental candidates can leak or over-eagerly delete.**  
In `PersistentRangeStore`’s enqueue path, `applySwap` (and therefore the current full mark scan) runs, then `compactSuccesses` deletes committed intents. The existing predicate (`ack[1] && !ack[2] && !state.outbox[ack[1]] && !state.rows[key]`) therefore often sees the pre-compaction outbox. Incremental cleanup that uses only apply-era changed keys will miss compaction-removed intents in that same commit; if no later swap happens to touch those keys, marks that the old scan would eventually drop can be retained forever (unbounded derived work, LLP 1019 drift). The opposite bug is treating same-commit post-compaction cleanup as “must match the existing scan” byte-for-byte and then skipping those candidates.

Resolving change: In §3, require this order on the draft: apply swap → `compactSuccesses` → assemble candidates from the post-compaction journal → run the existing predicate → persist → patch the derived index. Candidate union must include intents removed by compaction in this swap, looked up in the last committed reverse index plus any same-swap bindings. State that applying the same predicate after compaction in the same commit is an allowed tightening; eventual mark set must match the predicate, not the old scan’s next-commit delay.

**2. Plan §3 — derived index can stay quadratic if it is rebuilt.**  
“Update only changed acknowledgement keys” is the whole win. Rebuilding pending or intent→event maps from all retained marks on each ordinary commit recreates `50+100+…+N` work, because LLP 1019 keeps successful marks while the log event is held. Grouping pending identities by scanning completed batches is the same class of bug.

Resolving change: Patch the in-memory maps in O(changed keys) after durable success. Full rebuild is allowed only for cold load, explicit whole-state replacement, partition reopen, wipe, and the bounds/policy case below. Add to §6 control 2: ordinary page/ack/grant commits record zero full-history mark walks; 100 / 1,000 / 10,008 diagnostics must report candidate-visit counts, not only wall clock.

**3. Plan §3 — “bounds/program adoption removing receipt operations” is the wrong full-scan trigger.**  
Cleanup deletes a mark when `swap.bounds` is present and `_delivery.<log>.ack` is missing. `applyOutboxSwap` replaces the whole bounds map. A bounds put that is not a proven no-op on every currently retained receipt op is already a policy change under today’s scan. Detecting only “removal” from a guessed delta will leave marks that the current loop would drop.

Resolving change: Any `swap.bounds` (or program adoption that drops receipt-enabled delivery ops) that is not proven to preserve every currently retained receipt operation inspects all marks once. Do not incrementally infer preservation unless that proof is cheaper than the scan.

**4. Plan §3 / range-store excerpt — index restore must use the existing `priorIndex` catch, not a second copy of state.**

Resolving change: Snapshot the ack maps with `priorIndex`. On failed persistence, restore both. Publish the new maps only after durability, on the same serialized tail, before input listeners. Seal returns no projection; wipe clears; partition change rebuilds from that partition’s loaded `deliveryAcks` only.

**5. Plan §5 — absent owner effects must not skip `logTail`.**  
Current drain, on committed, always fetches the first drained query (`logTail`) and, if that fetch fails, leaves the intent queued (LLP 1012 §7: rows the commit produced or not at all). Engine-owned is not a proof; the plan already says receipt-maintained effects cannot be assumed empty.

Resolving change: Skip tail only when all of these hold: held schema receipt-enabled generated mutation (not `ACK_OP`); admitted generation/plan/schema identity matches the committed response; no overlay before or after this intent; `effects` is a present empty array from the same owner proof `compactSuccesses` uses. Do not fabricate watermark, coverage, fence, or query observation. Keep the request-count control as a gate: if `groups.mine` is not actually the per-ack tail, do not skip.

**6. Plan §5 — compaction overlay deletes can keep every ack “semantic.”**
