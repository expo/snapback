**1. Negative schema freeze uses `any()` over changed lifecycle columns, contradicting §10 "every affected column".**
[§10](llp/3000.036.004.000-structural-write-authority.rfc.md) lines 313–315 require schema authority to govern the actual effect "including every affected column for a negative freeze contract"; the S1 gloss is explicit ("a freeze on status cannot hide an unchecked phase"). But [`schema_scalar`](snapback4/crates/snapback4-lang/src/bind/security/creation_advice/lifecycle.rs:74) uses `effect.fields.iter().any(...)`: an update changing `{status, phase}` where only `status` is frozen counts as negative enforcement, and both call sites ([`frozen`](snapback4/crates/snapback4-lang/src/bind/security/creation_advice/lifecycle.rs:156), [`locked_approval_input`](snapback4/crates/snapback4-lang/src/bind/security/creation_advice/lifecycle.rs:98)) inherit it, suppressing `N_APPROVAL_NOT_ENFORCED` while `phase` changes unchecked. Repair: in negative mode require the changed-Enum set to be nonempty and *all* covered; keep `any()` for the positive path.

**2. Non-literal Bool stamp issuance is invisible to the receipt ledger (raw-positive pass).**
[`recording`](snapback4/crates/snapback4-lang/src/bind/security/creation_advice/lifecycle.rs:41) accepts only literal-`true` for Bool, so `approved: <arg>/<expr>` falls to [`collect` line 111](snapback4/crates/snapback4-lang/src/bind/security/derived.rs:105), lands in `uncertain`, and is then deleted by the line-167 retain (keeps only sites also in `reissues`). Time values get a `stamp_source` → `ambiguous_recordings` → persistent-unknown path; Bool has no equivalent. With zero receipts, [`consumed`](snapback4/crates/snapback4-lang/src/bind/security/challenges/executed.rs:30) evaluates the predicate on the untouched raw-positive shadow (`certain == possible == ∅` skips the unknown-forcing branch), so an entry-negative→positive `approved: flag` write with tainted inputs passes replay with no `revalidated` check — against §10 lines 369–377 ("reevaluate complete relevant Boolean checks on each changed input's replacement image"; "only the exact executed source write gets that exemption"). Repair: route non-clearing, non-same-stamp-copy Bool writes to `ambiguous_recordings` (keep pure same-stamp copies dropped — birth receipt governs them); note this may convert some corpus passes to fail-closed unknowns.

**3. Untrusted receipt intents cover `Update` only; inserts at mixed/unknown-custody sites record nothing.**
[`trace`](snapback4/crates/snapback4-lang/src/bind/security/challenges/executed.rs:100): trusted intents get `Insert+Update`, untrusted `Update` only. Mixed sites are scrubbed from `reissues` ([derived.rs:168](snapback4/crates/snapback4-lang/src/bind/security/derived.rs:167)), so a fresh insert at a mixed site (or any insert at an unknown-custody Time site) leaves no receipt and passes on the raw stamp — against S1 "shared helper sites used for both copying and recording remain unknown" and §10 lines 382–388. Repair: add `Insert` to untrusted-intent effects; per lines 77–78 this converts the pass into `unknown`, never into a refusal.

Repair: tag rejoin implications with a distinct code (precedent: [`nonnull_mode`](snapback4/crates/snapback4-lang/src/bind/security/creation_advice.rs:18) already filters `$advice`), skip that code in probe collection while retaining it in `coexec` branch sets.
