Material finding

- [039 §5.1, trigger: cascade edge qualified solely by plain single-column `unique`](llp/3000.039-a-reference-declares-what-deleting-its-row-does.rfc.md:390): the closure recurrence still reads `N(C) += cap(C, col) × N(T)`, while the amendment defines the effective bound `b(C, col)` and uses it only for `k` and `w`. A unique-only cascade therefore has no defined closure bound, and a chained cascade below it has no defined reservation, contradicting §§2.2, 5.2 and 7, which allow unique-only cascade. When both proofs exist the recurrence also ignores the declared `min(explicit cap, 1)` and over-reserves. The fix is to propagate `b(C, col)` in the `N(C)` recurrence. I verified the hashes match the snapshots and read the amendment via `git diff e82bb70b97 --` on the two documents.

What the amendment gets right

- [013 §14.7](llp/3000.013-quarry-states-intent.rfc.md:2053) authorizes before disclosing existence, returns value or authorized zero when admitted, returns `null` for both stored and absent groups when hidden, and forbids fall-through from hidden-absent to zero. The `N_MAINTAIN_AUTHORIZATION` note plus the stored/absent × authorized/unauthorized/`exists`-branch regression cover the bare-caller case.
- The unique scope is correctly stated: per-non-null-parent bound of one for required or optional references, unbounded null group, no population bound, composite excluded, `min(cap, 1)` when both exist.
- The sum-target refusal correctly explains that `delete <- deny` does not save the target because system work bypasses caller rules and another parent's cascade may still reach the child, keeping the refusal static rather than a hidden-data oracle. `N_REFERENCE_UNCHECKED` correctly states shape-only validation.
- The `N_DELETE_NEEDS_READ` proof uses only sound directions (equal trees, `allow`/`public`/true read, vacuous deny, `A and B ⇒ A`, `A ⇒ A or B`), so suppression is sound; anything unprovable keeps the note.
