## Concerns

### 1. High — 17 (a) on `upsert` distinguishes a hidden target from an absent one

**Where:** `snapback4/crates/snapback4-core/src/engine/write_target.rs` 46–77 (the same split is in `write.rs` 102–112 for by-id upsert). The named function is `refuse_hidden_immutable_patch` at 84–91.

Ruling 17 (a) is “an immutable column in a patch on an unreadable target → `NOT_FOUND` without comparison.” On `update`, miss is already `NOT_FOUND` (`write_target.rs` 69), so the hit refusal matches absence. `w1_an_immutable_patch_on_a_hidden_row_refuses_matching_and_mismatching_guesses` (`write_authority.rs` 175–185) proves that for `update`.

On `upsert`, miss is `insert_upsert` (69–77). Insert does not consult immutability (`write.rs` 323–336 only compares when `effect == Update`). A complete patch that names a required immutable column (SOURCE's `frozen`) therefore:

| World | Path | Outcome |
|---|---|---|
| Hidden, `update <- allow` | 17 (a) at line 49 | `NOT_FOUND` |
| Absent, `insert <- .owner = viewer`, patch `owner: viewer` | insert admits | `sent` |

That is existence of an unreadable row *without* applying the update. Before 17 (a), a *matching* upsert of `frozen` succeeded on both hidden and absent (`sent` / insert). 17 (a) made the matching guess fail only on the hidden hit. The rules card says the opposite (`guide/rules.md` 42).

`full` in the test schema uses `owner: 'alice'`, so Bob's insert refuses and both worlds are `NOT_FOUND`. The helper never sees `owner: viewer`.

**What would resolve it:** Stop naming immutable columns on the upsert-insert path, uniformly. The conservative form that keeps hidden = absent is a binder (or pre-lookup) refusal of immutable fields in an *upsert* patch, so hit and miss never diverge; new rows with immutable columns use `insert`; `update` keeps 17 (a) as written. Prove with `unchanged_pair` on `upsert records[key] {owner: viewer, secret: 'supplied', frozen: 'fixed', amount: 0}` through `observe`. Readable mismatch must remain named `E_CONSTRAINT`.

### 2. High — 17 (b) has the same miss-path split on `upsert … if`

**Where:** `write_target.rs` 57–58, 93–96. Binder allows a condition on `WriteOp::Update | WriteOp::Upsert` (`bind/program.rs` 643–665).

On `update`, miss is `NOT_FOUND`; `require_readable_condition` makes a hidden hit the same word without evaluating. `w1_e_conflict_current_is_withheld_and_the_code_does_not_tell_hidden_from_absent` (`write_authority.rs` 165–172) asserts Bob's matching condition is `NOT_FOUND`. That is the conservative form.

On `upsert … if`, a hidden hit returns `NOT_FOUND` at line 58; an absent miss inserts at 76 without looking at the condition. If the insert rule admits the patch, the pair is `NOT_FOUND` vs `sent`. The language card documents `update … if`, not upsert; the binder still accepts both.

**What would resolve it:** Refuse a condition on `upsert` at bind (one diagnostic, population-independent), leaving `require_readable_condition` for `update` only. Prove with a compile refusal plus `unchanged_pair` on `update … if` matching and mismatching (the matching arm should go through `observe`, not only `call` at line 171).

### 3. Low — 17 (b) matching on `update` is not proved through the observation helper

**Where:** `write_authority.rs` 171.

`unchanged_pair` covers the failing condition (`expected: 4`). The matching condition (`expected: 7`) is a single `call` asserting `NOT_FOUND`. The engine does not evaluate it (`write_target.rs` 58), so meters should match absence; the helper does not say so.

**What would resolve it:** `unchanged_pair(SOURCE, "conditional", json!({"key":"lookup","expected":7}), 7)`.
