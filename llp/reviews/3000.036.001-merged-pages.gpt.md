1. **High — §§2–3: branch distribution does not preserve short-circuit semantics.**  
   Grounding: `snapback4-core/src/engine/runner.rs:901–907`; `snapback4-lang/src/bind/intent_aggregates.rs:189–197`.  
   With `where .owner = viewer or (.assignee = viewer and 1 / n = 1)`, a row belonging to both parties skips the division today. Opening the assignee branch evaluates it and can refuse when `n = 0`. “Reads no row column” also permits fallible pin expressions evaluated before any candidate exists. The Boolean union argument assumes total predicates. **Change:** require expressions safe to move and evaluate independently, and preserve short-circuit behavior for residual predicates—or explicitly narrow eligibility to total predicates. Add overlapping-row and skipped-refusal tests.

2. **High — §§5, 8: merges can require inclusive cursors.**  
   Grounding: `snapback4-core/src/engine/shaping.rs:19–21,49–60`; `snapback4-core/src/cursor.rs:81–86`.  
   After an uncut merge materializes, an unfinished **first returned shape** records its first row’s position inclusively. Thus “merges never do” is false. Version 4, as specified, cannot represent this retry: making it exclusive skips the unfinished row; withholding continuation breaks the existing shaping contract. **Change:** encode inclusivity in the new branch token, apply inclusive bounds to every lane, and preserve no-progress detection. Test first-row and later-row shape cuts, including terminal source pages.

3. **Medium — §§2–3: eligibility must account for pins overlapping the requested order.**  
   Grounding: `snapback4-lang/src/bind/intent.rs:126–159`; `snapback4-core/src/schema.rs:920–929`.  
   A two-party page ordered `by .owner, .at` satisfies §2, but its owner lane cannot both pin `owner` and retain `owner` in its physical suffix. Lane mode deliberately leaves ordered equalities as seeks/residuals; duplicating the column in the index is forbidden. Consequently, “party pin first” and “every branch has suffix `order…, id`” cannot both hold. Added party pins can also exceed the eight-component index limit. **Change:** make actual lane-plan compatibility part of eligibility, with an explicit ordinary-scan fallback. Either exclude overlapping order/pin columns or specify constant-component cursor translation.

4. **Medium — §§6, 10: the metering and drain-cut claims do not match this merge class.**  
   Grounding: `snapback4-core/src/engine/word_merge.rs:140,150,168,176–194`; `snapback4-core/src/meter.rs:244–258`; LLP 3000.007.000 §5.5/C2b.  
   With at most eight lanes, each buffers `N+1` matches. No lane can exhaust that buffer before the merge discovers its `(N+1)`th distinct row, so the proposed positive **drain-refill-cut** test is unreachable. Also, current lazy merging charges initial head pushes and pops, but not subsequent buffer-to-heap pushes. Step exhaustion aborts; heap exhaustion clears the answer rather than returning a resumable partial page. **Change:** distinguish buffer size from examined work, specify the intended step charges, restrict resumable cuts to the applicable read-meter kinds, and replace the unreachable test with an opening-cut control.

5. **Medium — §9: C8 needs syntax/provenance and scope changes, beyond replacing one completeness predicate.**  
   Grounding: `snapback4/lean/Quarry/Eval.lean:151–154,192–199,299–304`; `snapback4-lang/src/emit/lean.rs:730–766`; `snapback4-core/src/engine/rules.rs:515–529`.  
   `pageRead` receives evaluated scalar pins and an opaque filter function. It cannot recover where-disjunctions or distinguish a syntactic `viewer` pin from an argument merely equal to the viewer. The runtime’s true-by-form analysis does distinguish them. The model must also respect the exclusion of shared helpers, mutations and other unexpanded sites. Metered merged walks have different cut/continuation behavior from the model’s single walk. **Change:** specify independent surface-level classification and retained provenance/context, and bound the union-equivalence theorem to uncut walks unless merged cut semantics are modelled.

6. **Medium — §§3, 5, 10: token rejection does not fence old engines from the new plan.**  
   Grounding: `snapback4-core/src/ir.rs:384–414`; `snapback4-core/src/engine/read.rs:1347–1353`; `snapback4-core/src/schema/capabilities.rs:51–82,130`.  
   Existing serde readers ignore unknown `branches` and `grant` fields. An older device receiving the new IR with a null cursor can execute it as an ordinary eager merge, ignore grant-lane admission semantics, and mint an older cursor. Version-4 rejection only protects requests already carrying such a token. **Change:** add a capability or program-version fence before execution, or explicitly specify and test the cursorless downgrade behavior. Include new-plan/old-device tests, not only old-decoder/new-token tests.

7. **Medium — §7: synced tables with service grants are already an exception.**  
   Grounding: `snapback4-core/src/schema.rs:685–705`; `snapback4-core/src/engine/read.rs:282–290`.  
   `read <- .owner = viewer or viewer = 'service:audit'` can sync: service disjuncts are removed from the device audience. It also qualifies for case 2. Always marking its grant lane unknown therefore turns an otherwise held owner read into server fallback. The assertion that grant-bearing union rules cannot sync overlooks this supported case. **Change:** state the service-grant exception and choose its device behavior explicitly. Test a held owner partition on both stores; either preserve its local completeness or document the intentional fallback.
