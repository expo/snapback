## What was checked

**ECMA-402 2020 NumberFormat.** JS Get/coercion order in `intl_number_format.js` matches 2020 `InitializeNumberFormat` / `SetNumberFormatDigitOptions`: CanonicalizeLocaleList, then ToObject(options), then localeMatcher → numberingSystem → style → currency (well-formed even when style is not currency) → currencyDisplay → currencySign → unit (same) → unitDisplay → CurrencyDigits only for currency style → notation → minimumIntegerDigits → Get all four digit properties → coerce only the significant pair or the fraction pair → compactDisplay always → useGrouping ToBoolean → signDisplay. Significant digits win over fraction digits; compact rounding applies only when neither pair is present. `+value` rejects BigInt (TypeError); `"".concat` rejects Symbol. `new.target === undefined` uses `new NumberFormat(...)` (2020 call-as-function). `Reflect.construct` attaches NativeState to the constructed object. Receiver checks (`assertReceiver` / `owner_from`) run before value coercion. Bound `format` closes over the instance (survives GC of other refs; handle is not a JS property). `Number.prototype.toLocaleString` / `BigInt.prototype.toLocaleString` share the same constructor+format path; BigInt stays a decimal string into `unumf_formatDecimal`. NaN is normalized to a positive canonical NaN before ICU; `-0` is preserved.

**Locale case.** RequireObjectCoercible, then ToString(receiver), then CanonicalizeLocaleList on the **entire** list, then the **first** requested tag (not a later Collator-supported fallback). UTF-16LE round-trip preserves NUL and lone surrogates. Empty strings still canonicalize locales. Private `__ibex2_intl_case` is deleted at prelude load.

**Native ownership / ABI / ICU.** Handles live in a per-runtime registry; JSI `NativeState` holds a Rust owner with `Weak<RuntimeState>`. JS object → Owner → Weak state; state → registry → ICU formatter (no cycle). ICU C++ entry points are `noexcept`/`protect` so exceptions do not cross into Rust. Case mapping uses explicit lengths, rejects interior NULs, and sizes then fills. Ops 90–98 do not collide with `Op`. Linux-only `cfg` / `build.rs` / shim install; Mac and engine-off stay independent. No new grant. Deadline code is untouched; no preemption is promised inside ICU.

**Hardening / boot.** `install_stdlib` publishes raw globals; binding HBC deletes them and installs the public surface; `harden` then freezes; production R5 would reject leftover `__ibex2_intl_*` names.

Reported focused-suite evidence is consistent with this reading (including the NaN sign-bit fix). That evidence was not re-run here.

## Optional suggestions (not blocking)

- `intl_number_format.js:143` uses live `Math.max` (and live `Boolean` / `Number`) rather than captured intrinsics. Production hardens before user code, so this is not a boot-path break. Capture them the way `Math.floor` and `String.prototype.concat` already are.
- 2020 surface details not required by this bounded completion: `NumberFormat.length` is 2 not 0; `supportedLocalesOf.length` is 2 not 1; call-as-function on a subclass uses `NumberFormat` as newTarget rather than the active function.
- Case default locale is a boot-time `Collator().resolvedOptions().locale`; NumberFormat default is live `uloc_getDefault()`. Explicit locale arguments are used everywhere that matters in the focused tests.
- `part_kind` maps every ICU exponent sign field to `exponentMinusSign` (`intl.rs:688`). Positive exponent plus, if ICU emits one, would be mis-typed.
- `make_result` in `intl_icu.cc` fails the whole format if field iteration fails after the text is already in hand, so `format()` and `formatToParts` share that failure.
- Focused compact/percent assertions are weak (`/1.2/` matches `"1200"`; `"56"` matches `"0.56%"` and `"5600%"`). The skeleton (`percent` + `scale/100`, `compact-short`) is the correct ICU 74 usage; the tests would not catch a regression.
