## 1. L26 as implemented

**Split.** Each abstract node has `data: u8` and `control: Control` (`aggregate_value.rs` 84–87). Bits are `AMBIENT=1`, `READ=2`, `ARGUMENT=4`, `UNKNOWN=8` (lines 5–8). `Value::selected` copies data and unions control, except UNKNOWN in a selector taints data (`138–144`) because that construct was not modelled. `Value::influenced` is the only path that puts bits into *data*.

**Verdict.** `columns` disqualifies a non-initializer when `fact.data & (ARGUMENT | UNKNOWN) != 0` or `fact.data & READ == 0` (`aggregate_provenance.rs` 64). Evidence requires `READ` (65). `record` sets `data: value.all() | (control.bits & UNKNOWN)` (514): ARGUMENT/READ/AMBIENT control stay out; UNKNOWN control is the documented silence hatch (`@ref` line 3; card `feeds.md` 1315–1317). Literal inserts (`initializer: insert && value.literal`, 515) do not disqualify.

That is exactly: read-derived iff data is READ, optionally AMBIENT, with no ARGUMENT and no UNKNOWN.

**Purpose (P5) vs letter.** P5 is a hand-kept count under a rule that admits everyone (LLP 3000.007 §21.3; L26 at §21.8). The like/unlike toggle is now a note: `p.score + 1` / `p.score - 1` chosen by `liked` (`l26_conditional_delta_is_control_and_toggle_message_names_both_arms`, 807–821), matching cal10 `rank.score + (1 if value else -1)` and cal12 `p.score + 1` / `max(0, p.score - 1)`.

**Caller-set program that still fires.** L26’s tests treat loop cardinality and ambient picks as control, so this notes:

```text
delta = 0
for i in range(0, amount):
  delta = delta + 1
update posts[p.id] { score: p.score + delta }
```

`range` is a scalar summary of ARGUMENT|AMBIENT (`445–448`); `loop_reads` stores `domain.data & READ` (221), so the `+ 1` accumulation does not take ARGUMENT into *data*; `p.score + delta` is READ|AMBIENT. Same for `at([0,1,…,n], amount)` added to a read. Direct `p.score + amount` is silent (`l26_selected_argument_fields_still_supply_data`, 839–852). That is the data/control split as pinned, not a missed `influenced` on the written field. A builder who spells the increment as a loop will get a note; one who writes `+ amount` will not.

**Footgun it still misses.** `mutation like(postId, delta: int): update { score: p.score + delta }` with the client passing ±1. Argument is in the value, so L26 is silent (`373–390`, `839–852`). That is the letter (`score + amount`). The calibration builders used a boolean selector, which now fires.

### Medium — toggle message drops the other arm when conditions differ

**Where:** `aggregate_provenance.rs` 67–69 and 565–570.  
**What:** `selected` keeps at most two ARGUMENT-controlled facts, then the message keeps only facts whose `choice` equals the *first* fact’s choice. `Control::union` takes `min` of choice strings (value.rs 23–26).  
**Failing scenario:** cal12 `like` (`social.q` 122–127): increment under `set and not exists likes[post, viewer]`, decrement under nested `not set`. Choices differ, so the recorded diagnostic is only `` `p.score + 1`, chosen by `set and not exists likes[post, viewer]` `` (journal 43988) — not `max(0, p.score - 1)`. L26 asked to name both arms. The synthetic `if liked / else` test passes because both arms share one condition (820).  
**Smallest fix:** join all stored selected expressions (already capped at 2), or set `choice` to the argument *name* (`set`, `liked`) rather than the full condition string. No change to `disqualified` / data bits.

### Low — generic rewrite leads with “count”

**Where:** `aggregate_provenance.rs` 578–579; cal11 `posts.parentAuthorId` message (journal 43972–43973).  
**What:** rewrite always says “keep the count in a maintain…”. For a nullable copied author the card’s pin-to-source sentence is the one that applies (`feeds.md` 1296–1298).  
**Fix (optional):** keep the shared rewrite; the card already covers non-count facts.
