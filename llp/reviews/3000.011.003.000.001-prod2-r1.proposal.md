## 1. Commission and constraints

Wave-15 fix lists 6 and 8 commission production adaptation for custom apps,
offline entry and draft survival. This amends starter §14, client §6.11 and
release-client §3. No storage, sync, session, expiry or authorization protocol
changes. Existing table rules and constraints decide each write. No version
bump or publication belongs to this lane.

## 2. Readiness and current authority

useAppReady means the current account's initial opening succeeded; it is not
permission, connectivity or continuing write admission. Once true, it stays
true for that App and signed-in viewer through release/catalog loading and
later admission warnings. Initial admission failure stays false until a later
successful sign-in/opening; a replacement app or account starts a new readiness
lifetime. Signed-out/restoring auth remains false. AppProvider's existing
app/viewer boundary still resets account-owned drafts; no stale identity is
retained to conceal revocation or store replacement.

The compiled role shell owns drafts and selection above every readiness,
role and release branch. Sticky role is a label only. Protected reads and
submission require a present, complete, fresh, non-revalidating current role
and generated operation availability, as well as initial readiness. Loading,
partial, denied, absent, stale or revalidating role evidence never licenses
protected children or a submission. SDK/server admission still handles races.
A release switch withdraws protected children while preserving the shell and
its inputs. Explicit revocation withdraws authority immediately.

## 3. Custom production plans

Preview stays read-only; apply writes only the exact compiled schema shown.
Retain bare identity insertion only when identity is absent. Bare identity
allows passwords and guests; identity guests is guests-only; password removes
guests. A guest session is a session: signup/login can replace it through
app.auth, with the ordinary account boundary; it is not a dev persona.

Keep existing blocked-roster bootstrap mutations for compatibility. Extend
planning to a table with an enum column named role and principal identity in
a unique key when no mutation/job inserts or upserts that table, even if the
advisory's approximate reachability misses it. Generate one service:ops-guarded
insert operation per declared role, with that role fixed as a literal, rather
than a caller-supplied role argument. Inputs retain all other writable required
columns and explicit principal defaults. Such provisioning is independent of
fixture values; all declared roles appear even when the current fixture uses
only one. Existing writer paths remain application policy; the planner does
not claim their role coverage. Non-roster and inherited-authority roots stay
explicit review messages. Add only the displayed independent service read and
insert branches; never bypass constraints or rewrite an application's screens.
Fresh names avoid collisions; repeated apply is idempotent once writers exist.
The whole plan must compile before any file write and retain full-source
preflight/symlink refusal. A failed proposed policy writes nothing.

The principal scan excludes every dot-directory, test directories and known
acceptance/fixture/proof/test scripts. Runtime source files under scripts still
get scanned. Findings remain bounded review hints, never a proof of complete
migration. Detect usePersonaApp, persona: and ?as= custom entry sites and point
them at guide production's account/persona recipe; do not rewrite arbitrary UI.
Upgrade names init --adapt --production for a persona-only project.

## 4. Declaration and recipe corrections

Post-baseline row and projected fields explain their optionality with
“optional: releases before N lack this column”; N is the existing configured
since_release label, not an inferred server generation. Public argument labels
retain their existing meaning. A literal string arm of a conditional joins as
its singleton enum domain; enum arms retain their union, including nullable
arms. Dynamic text still widens to text; evaluation/laziness and wire values
are unchanged. This is a precision correction, not a new syntax or IR feature.

Device-less identity createApp calls without sessionStore must produce a type
error naming sessionStore. Device/persona/readOnly forms remain valid. Complete
empty lists already classify as absent; pin that behavior in packed tests.
The client PDF recipe explicitly calls upload with {file:{...}} and executes
against the packed SDK. Other lanes own the literal wire and proof API pages
(KIT4), ordinary starter advice (DAY5), rules recipes (RULES5), and compiler
notes (LANG4).

## 5. Evidence required

H9: execute the packed AccountEntry recipe with a real persisted password
session and held data in a new browser realm, refusing all backend requests,
including auth/config, with no metadata cache. Require signed-in held UI and
no alert. Run packed production preview on hidden checkpoint/scratch and
acceptance/test files alongside a real runtime principal; only runtime findings
appear. Run preview/apply/check/idempotence on copies of three wave-15 custom
apps with persona pickers; original bytes remain untouched. Exercise each new
role mutation as service:ops and refuse outsiders. Compile and execute the
role shell across release loss/restore and stale/revoked authority, checking
input identity and values. Verify readiness with an actual live release switch,
initial failure/recovery and account/app replacement. Run affected Rust/client
suites, full client pool and packed Linux qualification; platform-sensitive
scan tests also run on the assigned Mac Studio. Record failures honestly.
