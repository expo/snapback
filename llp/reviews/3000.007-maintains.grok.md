## Findings

### High

**1. Hidden delete inspects the old image, then charges filter/key work — a new success/`E_BOUND` oracle**

- **Where:** `snapback4/crates/snapback4-core/src/engine/write.rs:149–161` (fetch, then `row_changed` → `maintain`); reservation only from `reserve_target_resolution` (`write_target.rs:35`, used by update `:76` and unique-key upsert `:98`).
- **Scenario:** Schema as in `hidden_world` (`sim/tests/maintains.rs:225–235`): `read <- .author = viewer`, `delete <- allow`, maintain `count posts where .selected by author, day(.at)` with `read <- deny`. Writer `writer` deletes `posts['hidden']` (author `owner`). World A: `selected=false`. World B: `selected=true`. Same id, same delete rule.
- **Observed vs required:** Delete loads the hidden row, then `maintain_one` evaluates the predicate and may apply one or two groups (`maintains.rs:39–51`) and contribution-index updates (`write.rs:439–456`) **without** `maintain_prepaid`. Meters, and `E_BOUND` near those meters, differ by whether the hidden predicate held. §20.9.3 requires schema-derived reservation of up to two groups **before** inspecting the hidden old image; paired worlds must match on the complete observable. The hidden matrix only runs `update posts['hidden'] {at: 86400000}` (`:231`, `:237–275`).
- **Smallest fix:** Before `fetch` in `delete`, call the same `reserve_maintains` used for update/upsert (or share `target_attempt`’s prepaid/restore). Add paired delete worlds to `hidden_filter_work` (true/false, present/absent, denied, expiring, near each ceiling).

§8.7(h) leaves delete’s **one-word** contract alone; it does not license a new filter-dependent meter channel on a hidden source delete.

### Medium

**2. Expire card never states the value-order refusal**

- **Where:** `snapback4/crates/snapback4-lang/src/guide.rs:745–759`; diagnostic is `guide("expire")` at `bind/schema.rs:549`.
- **Scenario:** Author writes `by byCount: value, id` on a maintain whose source has `expire at .until`. `check` emits `E_QUARRY_MAINTAIN_EXPIRE` and points at `guide expire`.
- **Observed vs required:** §20.9.3: register that diagnostic on the expiry card, naming the source and rewriting to a live bounded query or the ranked-table recipe. The card covers live recompute, `E_QUARRY_LIVE_MAINTAIN_PROBE`, incomplete cuts, and zero-sum candidates — not value-order.
- **Smallest fix:** One paragraph on the expire card: value-order indexes over an expiring source are refused (`E_QUARRY_MAINTAIN_EXPIRE`); use a live page or the scheduled ranked table.

**3. Hidden overflow of a filtered/keyed maintain is still a success-vs-error bit**

- **Where:** `apply_aggregate` range check (`maintains.rs:161–163`) runs after the old image is known; reservation does not cover overflow.
- **Scenario:** Hidden source row, readable or hidden target near `I53_MAX`. Filter-true update overflows (`Failed`, value-free `AggregateOverflow`); filter-false commits. Same as §17’s residual constraint channels, now with a filter.
- **Smallest fix:** If this slice claims paired-world equality including errors, reserve/fail overflow on a state-independent bound, or add the pair and document it as an §8 residual. `hidden_filter_work` never approaches `I53_MAX`.

### Low

**4. Core `MemoryRows::put` still counts every insert and ignores defaults**

- **Where:** `snapback4/crates/snapback4-core/src/rows.rs:216–233` (`index_keys` on the raw image, `written += 1` only on insert).
- **Scenario:** Test-only helper (`local::predict` fixtures). Production wasm uses `MemoryStore` (`device/src/memory.rs:410–428`), which matches SQLite.
- **Smallest fix:** Copy `MemoryStore`’s before/after `stored_index_keys` counting, or stop using `MemoryRows` for anything meter-sensitive.

**5. Adoption test never folds targets after a filter/key change**

- **Where:** `sim/tests/maintains.rs:108–117` asserts source bytes only.
- **Rebuild path is correct** (`rebuild_maintain_inner` deletes all target rows, then refolds `:70–115`). A regression that skipped rebuild would still pass this test.
- **Smallest fix:** After each adopt, call the same `fold` helper.

## Question-by-question notes

**Q1.** Insert, filter enter/exit, coalesced same-key updates, key moves, unrelated fields (`rows_written == 1` at n=1 and n=3), replay, upsert chips, overflow rollback, and expiring +1/−1 zero-sum match a fold on the server engine. Euclidean floor is `i64::div_euclid` (not truncating toward zero). Duplicate `day`/`id`/`value` names are refused. Device settlement of predicted inserts is checked on SQLite and wasm-style `MemoryStore`. Unique-key upsert of a filtered calendar group is covered by chips, not by the fold table.

**Q2.** Live reads skip expired sources, recompute from the contribution index for computed keys, and mark `complete: false` on meter cut or unheld/horizon source (`unknown_fact` at `read.rs:170–172`). They can omit a live source **only** when the meter cuts mid-scan, with `complete: false` — that is the specified incomplete answer, not a complete zero. Value-order over an expiring source is refused at bind; a successor cannot adopt a schema that does not compile.

**Q3.** Short scalar keys refuse with a page rewrite. Prefix pages, `after` cursors, first/last, and shapes are bound and tested. Rank uses `value, id` (and scoped `author, value, id`); ties follow total order; deleting the winner brings the next group; empty groups have no row. Denied readers get an empty complete page and no snapshot events. Value-index reads examine target rows only (measurement: 11 examined, no source scan).

**Q4.** Inheritance requires every audience column as a `Expr::Name` key; computed keys do not count. `online only` skips inherit and is omitted from device overlays, so a source mutation stays predictable. Missing local aggregate bases queue; they are not initialized from zero. A fully held, no-horizon inherited target may prove absence of a **new** group and start at zero — that matches a complete target, not a guessed hole.

**Q5.** Update/upsert reserve conservative steps/examined/rows/index/heap before lookup; prepaid writes do not add a secret-dependent charge; NOT_FOUND restores the mark. `N_MAINTAIN_DELTA` names filter/key/value dependencies and insert/delete, conservatively unless visibility is proved. **Delete does not reserve** (Finding 1).

**Q6.** Changed filter, calendar duration, defaults, and target indexes are reported at the maintain declaration. Activation is still one SQLite transaction with unbounded rebuild — D1 does not claim §20.9.4 fences/chunks. Filter/key identity changes trigger `rebuild_maintain`; a changed value index alone is rebuilt from existing target rows. Check and adopt agree on an overflowing filtered sum (`E_ADOPT`).

**Q7.** Maintain predicates are a separate grammar; invalid reads/calls/arithmetic stay in the AST for an expression-sited rewrite. `not` binds to a comparison (`parser/maintains.rs:5–9`; lang test `:73–82`). Cards/README: journal reports `cargo test -p snapback4-lang --test guide` green; I did not re-run. Expire card gap: Finding 2.

**Q8. Missing tests (concrete):**
- Paired hidden **delete** (and optionally unique-key delete if added later) at low limits and around observed work.
- Hidden filter-true vs filter-false **overflow** near `I53_MAX`.
- After adopt of `where .selected` → `where not .selected`, fold of `counts`/`scores`.
- Live computed expiry scalar/page on **both device stores** (sim covers server SQLite only).
- Explicit rank of an author with **no** liked posts (zero-group absence), not only as a side effect of the fold.
- Core `MemoryRows` meter parity, if that helper stays in predict tests.

Resumable adoption, write fence, check exit 2, 5M-row disk qualification, and S26 digest continuation are correctly out of slice.
