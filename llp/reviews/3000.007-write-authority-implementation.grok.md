**Verdict: READY WITH CHANGES**

The implementation is the narrowed contract, not the first-pass RFC. Target resolution is engine-private, unreadable failures share `NOT_FOUND`, the merged image of a still-hidden row never reaches `result` / `current` / the program, a device miss queues without a row, S05 still holds for insert and insert-if-absent, §5.9 admits only uniformly decided prefixes, and `/m` replay no longer returns revoked content. What remains is one S05 word that the RFC still names `E_RULE` and the code turned into `NOT_FOUND` even on a readable target, plus a handful of named tests that do not prove what their names say. Those are repairs, not a reopened channel.

## Overall assessment

Lane W built the observer rule both families asked for. The binder no longer `Get`s a unique-key target under the read rule (`snapback4/crates/snapback4-lang/src/bind/program.rs` 643–668). `Stmt::WriteTarget` looks the row up privately, applies the update rule, and only then binds a read-rule `get` (`snapback4/crates/snapback4-core/src/engine/write_target.rs` 22–69). Absence, a refused update rule, a failed `if`, an immutable mismatch, and an incomplete upsert-insert are one `Require`/`NOT_FOUND` (`write_target.rs` 9–11, 47–48; `write.rs` 104–116, 125–130, 322–323). Admission keeps uniformity and drops completeness only when `predicts == "never"` (`admission.rs` 248–256). `local::predict` raises `E_PREDICT` on any write-target miss, including a no-horizon unique-key miss (`write_target.rs` 14–19, 32; `local.rs` 62–70), and `admit` queues that class with an empty predicted set (`device.rs` 575–578).

The remaining miss is not a hidden-vs-absent wire bit. It is §8.7(f) / S05 on *another* row during an update: `check_constraints` maps a hidden unique clash to `NOT_FOUND` even when the writer can read the target (`write.rs` 296–299). That is a different word from the standing S05 `E_RULE`, and it makes `NOT_FOUND` a lie about a row the writer can `get`. Restore `E_RULE` on a readable target. The extra collapse on an *unreadable* target is disclosure-safer than (f)'s `E_RULE` (collision then looks like absence); keep it or write it into (f), but do not leave readable-target collisions as `NOT_FOUND`.

## Strengths

- **Engine-private addressing.** Unique-key and id update/upsert become one `WriteTarget` (`bind/program.rs` 643–668; `ir.rs` 116–131). `live_lookup` runs without a read check (`write_target.rs` 31; `read.rs` 67–80). The Clique binder `Get` that made a hidden unique-key upsert look absent is gone.
- **One failure word for an unreadable target.** `no_write_target()` is `Require { code: "NOT_FOUND" }` (`write_target.rs` 9–11). Update-rule false (`write.rs` 125–130), failed `if` (`write_target.rs` 47–48), immutable mismatch (`write.rs` 322–323), incomplete upsert-insert (`write.rs` 108–114), and a device miss on the server (`write_target.rs` 19) share it. `unchanged_pair` (`write_authority.rs` 86–109) compares the full `/m` body, `_ops` text, committed rows, `seq`, empty stream, empty snapshot, empty effects, and the retry.
- **Merged image stays in the engine while the row is hidden.** After the write, a valued result is `get` by id (`write_target.rs` 67–69). `old` is bound only inside `write_condition` and the env is restored (`write_target.rs` 107–119). `E_CONFLICT.current` is still a read-rule `get` (`mod.rs` 793–798); hidden condition failure never produces `Conflict`. Update authority runs before asset diagnostics (`write.rs` 132–136, 211–216).
- **Device miss is a runtime class, not a predicted `NOT_FOUND`.** `write_miss` always sets `unknown_fact` and returns `Prediction` on a device (`write_target.rs` 14–19). Upsert on a miss does not take the insert path (`write.rs` 99; `write_target.rs` 32). `predicts: "never"` refuses before the runner (`local.rs` 62–65). `admit` clears stale predicted keys (`device.rs` 575–578).
- **§5.9 is the uniform-only option this family called sufficient.** Uniformity is decided first; a never-predicting pass then skips cap/complete-group (`admission.rs` 251–256). Merges and unknown origins still fail (`admission.rs` 238–242). Non-uniform is refused at bind without consulting a store (`write_authority.rs` 346–349). Uniform-false restores the meter and stops (`read.rs` 519–524). `rows_written` still aborts at 1,024 (`write.rs` 436–438; `p2_rows_written_still_aborts_at_1024`). The pass is one transaction (`mod.rs` 761–816; `p2_the_pass_is_atomic`).
- **`N_MAINTAIN_DELTA` is a `check` note** (`bind/residency.rs` 145–156), with a sufficient implication proof, not a solver.
- **`delete` was not widened** (`write.rs` 142–155).
- **Replay of hidden writes cannot grow a row.** First `/m` for a hidden success is `result: null`; `from_receipt` drops `result`/`current` on every replay (`receipt.rs` 31–42; `serve.rs` 785–790, 870). `wa5_revoked_result_and_conflict_current_are_not_retrievable` covers a dropped original, a later owner change, scalars, and a different principal reusing the id.

## Concerns

### 1. Medium — Secondary hidden collision on a *readable* target is `NOT_FOUND`, not S05 `E_RULE`

**Where:** `snapback4/crates/snapback4-core/src/engine/write.rs` 296–299.

RFC §8.7(f) (LLP 3000.007 lines 941–944) and contract item 5: insert / insert-if-absent on a hidden unique clash stay `E_RULE`; a collision with any *other* hidden row on another index stays `E_RULE`; target authority does not transfer. The code does two things:

```296:299:snapback4/crates/snapback4-core/src/engine/write.rs
                    if effect == Effect::Update && !readable { return Err(self.no_write_target()); }
                    match self.visible_collision(table_name, &existing, effect) {
                        Err(RuntimeError::Rule { .. }) if effect == Effect::Update => return Err(self.no_write_target()),
                        result => result?,
```

The first arm is right for an unreadable target: a named `E_CONSTRAINT` would print retained unique columns of the hidden row (`wa2_retained_composite_key_never_enters_refusal` is the GPT finding this closes). The second arm also fires when `readable` is true. `wa2_secondary_hidden_collision_does_not_borrow_target_authority` (`write_authority.rs` 239–254) seeds Bob's own row as the target and Alice's hidden `amount = 0` as the other row, then asserts `NOT_FOUND`. Bob can `get` his row; `NOT_FOUND` is a lie, and it is not S05's word.

This is not a new uniqueness oracle: `E_RULE` was already the bit. It pollutes the unreadable-target failure word.

**What would resolve it:** Gate the `visible_collision` → `NOT_FOUND` map on `!readable` (or delete lines 297–299; the first arm already covers the unreadable target). Keep insert / insert-if-absent on `visible_collision` → `E_RULE` (`write.rs` 367–382, `insert_mode` 46–48). Change `wa2_secondary_hidden_collision_does_not_borrow_target_authority` to expect `E_RULE` when the target is Bob's, no index name and no Alice secret in the message, and keep `NOT_FOUND` only when the *target* is unreadable (that extra collapse is stricter than (f) and should be written into (f) if kept).

### 4. The device

Classification of an unheld write target: `E_PREDICT`, message rewritten to “the write target is not held on this device; only the server can resolve it” (`write_target.rs` 14–19). `local::predict` returns that error if `beyond_horizon` (`local.rs` 69–70) or if `predicts == "never"` (`local.rs` 62–65). `admit` (`device.rs` 575–578) sets `predictable = false` and `predicted.clear()`, then enqueues. Local query of the key is `null` after reopen (`device/tests/write_authority.rs` 51–56, 64–67). Held target still predicts (`device/tests/write_authority.rs` 80–85). Server-only pass queues even when the rows are held (`device/tests/write_authority.rs` 99–129). After `/m` `sent`, the writer's stream has no `Put`; the device snapshot does not gain the row (`write_authority.rs` 211–226; `write-authority.test.mjs` 94–118). Nothing is predicted for an unheld target: no `NOT_FOUND`, no insert image, no pending key.

### 5. §5.9 admission

Uniformity is `scan_visibility` (`rules.rs` 21–51): deciding fields pinned by the prefix, including uniformly false. `page_problem` returns `E_STRUCTURAL_FANOUT` on a non-uniform prefix **before** looking at `predicts` (`admission.rs` 251–252). A sibling non-uniform scan also refuses (`admission.rs` 252, 64–76). Only then does `predicts == "never"` drop cap, literal bound, and cursor clauses (`admission.rs` 253–256). Bind computes residency *before* admission so that class is visible (`bind/mod.rs` 59–78). Predicting mutations still need a complete capped group (`admission.rs` 257–264; `p2_a_predicting_mutation_still_refuses_e_structural_fanout`). Runtime `Cut::Abort` remains (`mod.rs` 762); on a uniform-false prefix the scan restores the meter and stops (`read.rs` 519–524), so 0 / 100 / 10_000 hidden rows in that prefix are one `sent`. `rows_written` charges per `row_changed` (`write.rs` 436–438) and aborts at 1,024; the 1,025th rolls back (`p2_rows_written_still_aborts_at_1024` asserts store unchanged). `check --cost` prints `a pass over the first N rows of <prefix> by <index>; examined ceiling <n>` (`verbs.rs` 187–195; JS test 120–125).

“Uniformly authorized” in the brief is the heading; the RFC body is “uniformly decided by the prefix.” The code admits uniformly *false* prefixes (empty page, no walk). That is the safer reading and matches this family's “also sufficient” option.
