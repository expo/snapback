## Material findings

**M1 — 039 §2.2 unique-as-cap contradicts unchanged §5.2; §5.1 reservation has no inferred value.**
Section: 039 §2.2 Requires + §7 `E_CASCADE_BOUND` vs §§3 step 5, 5.1, 5.2.
Trigger: `on delete cascade` (or `set null`) on a reference whose child has a qualifying single-column `unique <column>` and no `cap N by <column>`.
The amendment admits this via inferred cap-of-one, but §5.2 bullet 1 still orders `E_CASCADE_BOUND` for any cascade/set-null "with no `cap N by <column>`", and §5.1's `N(C) += cap(C,col)×N(T)`, `k`, `w` (plus §3 step 5 "at most its cap") never define `cap(C,col)` for the inferred case. The document both allows and refuses the same schema and leaves the reservation uncomputable. Fix: conforming §5.2 edit ("with neither … nor …"), define the `cap(C,col)=1` inference in §5.1, touch §3 step 5 wording.

**M2 — 039 §2.2 leaves the qualifying unique's nullability and null-group status undecided.**
Section: 039 §2.2 Requires (+ §7 `E_CASCADE_BOUND` row).
Trigger: optional (`?`) reference column with single-column `unique`, no cap — the mandatory shape for `set null`, allowed for `cascade`.
"Total plain `unique <column>`" is undefined in 039; the corpus uses "total" as non-nullable (013 §2.2), which would make the inferred branch unreachable for `set null` (always optional), leaving "or inferred" in the `set null` row dead. If nullable unique qualifies instead, nothing extends §2.2's null-group exemption ("a cap on a `set null` column does not count null … never proves a population bound") to the inferred bound — the exact false bounding of the null group the scope forbids. A bound is safety-critical (fixed reservation, no overflow path), so this ambiguity blocks a soundness verdict. Fix: state explicitly whether optional-column `unique` qualifies; if yes, norm per-non-null-group bound of one with unbounded null group and no population-proof use; if no, gloss "total (non-nullable)" and correct the `set null` row to explicit-cap-only.
