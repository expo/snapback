## Test gaps and residual risks (not regressions)

- **`PostgresEngine::replay` remains principal+id only** (`mod.rs:163–166`). Same shape as SQLite `Engine::replay`. A host that answered resends with `replay()` would skip `E_ID_REUSED`. Evaluation `mutate` and SQLite `serve.rs:880–886` do not use that API. Residual, pre-existing.
- **Concurrent mismatch is Serializable-only** (`conformance.rs:286`). Default Serialized is the stronger lock; untested here, not a shown hole.
- **Issue text asked for concurrent mismatching “against both stores.”** Dual-store coverage is sequential (`conformance.rs:98–147`). SQLite concurrent mismatch is not in this commit. SQLite is single-writer; sequential `work_records` already binds.
- **Admitted-refusal stored JSON is not re-parsed on Postgres.** Success redaction is asserted (`conformance.rs:116–119`). Failed receipts rely on shared `receipt()`/`from_receipt`. `racing_refused_operations_replay_one_receipt_without_advancing_head` (`conformance.rs:373–408`) checks one original and unchanged head, not `detail`/`current` bytes.
- **Version-1 test only relabels a v2 schema** (`conformance.rs:320–330`). Sufficient because `open` refuses before `_ops`; it is not a real four-column v1 fixture.
- **`applied_bound` is a Postgres copy of `replay_bound`, not a shared rusqlite `Connection` helper.** Digest and `id_reused()` are shared; NULL-tolerant SQLite behavior is correctly not copied onto `NOT NULL` v2 columns.
