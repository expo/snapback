## (b) Delight: what agents said Snapback got right (keep these in Snapback 2)

1. **Stable diagnostic codes as the primary contract.** 0001: "Diagnostics are a real contract, not an afterthought … I could assert on codes instead of scraping prose. This is the single biggest agent-DX win." 0020: "Every refusal named itself … I never had to guess *why* a call failed, only what the rule was. That is a real differentiator over poking at a typical REST backend."
2. **Fail-closed codegen that teaches.** 0016: "Codegen refused the entire bundle with `BUNDLE_UNSUPPORTED_TIME` and wrote no stale artifacts." 0017: "two of them taught me the sandbox model in five minutes … I like that the analyzer runs at authoring time, not first-request time." 0042-a2: "Codegen as a colleague. Every authoring mistake failed closed with a named diagnostic and usually a position … Three iterations to a clean 12-operation graph, none of them mysterious." 0015: "I tried an undocumented combination … and it simply worked, end to end … First `codegen ok` on the first run."
3. **Capability manifest that names what is missing.** 0001: "Building against a backend that *advertises what it can't do* is a different experience from the usual 'find out at runtime.'" 0040: "`fallbackToLive` omitted is a real pin. Preparation refuses if the target stops advertising `registered_bundle_boot_v1`."
4. **Snapshot-with-subscription, one commit cut, no prime race.** 0001: "`subscribe_live` returns the authoritative initial snapshot *in the same response* as the subscription id. No `getAllDocs` prime race." 0019: "the wire answer to 'I already have the rows you inlined' is a ~200-byte `current_as_of` envelope." 0004: "the adoption seam is ~40 lines."
5. **Realtime is a consequence of the commit, not a second system.** 0008: "the realtime delta, the read-set validation, and the durable version bump are all the same machinery as a user write — I never thought about 'realtime' as a separate system." 0018 (maintained projection): "the card is simply there in the same commit … a materially better experience than eventual-consistency materialized views."
6. **Native ephemeral state.** 0022: "Presence was the cleanest backend implementation in the comparison." 0039: "No other result was close to Cursor Garden." 0042-a2: "Typing and presence took one schema declaration each … zero write amplification, verified against the store."
7. **Membership declarations and host-owned authority.** 0015: "'Grace RSVPs and Ada's guest list updates, while Eve's subscription stays silent' required zero client or handler code." 0014: "an operation that the schema cannot prove simply does not appear in the API." 0042-a2: "Revocation is a real barrier … blanked ~1.7s after his seat was revoked."
8. **Settlement envelopes and receipts.** 0042-a2: "`changed_count: 0` plus the original id on a keyed retry made idempotency machine-checkable in one line … I never once parsed prose to learn what happened." 0044: "The A3-08 conflict evidence — exactly one commit per revision — fell out of the envelopes."
9. **Deterministic seed/reset, forced cron tick, receipted cleanup.** 0001: "Reset → seed → assert is trivial." 0038: "the test forced one tick, and the proof crossed action, mutation, durable rows, live delivery, and admin ledger without sleeping." 0043: "The versioned-seed reset finally paid off … receipted, predecessor-stream-gated."
10. **The dev lifecycle owns its server.** 0001: "Managed spawn-to-ready is ~1s against the debug binary." 0044: "The dev lifecycle (ready descriptor, `snapback.dev.v1` events, stdin-close stop) keeps making acceptance suites that own their servers trivially cheap." 0040: "zero port coordination."
11. **Fast suites.** 0043: 13 checks in 6.6 s; 0042-a2: 12 checks in ~9 s; 0044: 4.7 s; 0045: 17.7 s; 0029: ~36 s incl. 500 issues + 1,000 comments.
12. **Install-to-first-commit on the public package.** 0042-a2: "Install → first commit in under eight minutes … Nothing here needed a provider account, a region picker, or a dashboard." 0043: "Install → authoritative first read in about ten minutes."
13. **Guide intent-indexing (when the page exists).** 0015: "Cold start → capability index → scoped-roles page → rbac demo sources gave me the complete membership authoring surface … without reading runtime code for the happy path." 0027: "The required Guide pass was genuinely useful."
14. **Engine-neutral ctx seam.** 0008: "The app bundle port was almost mechanical … the ctx contract really is engine-neutral. The mutations needed zero changes." 0012: "a protocol I could implement twice … against one op table."
15. **Clean-room clients from specs + fixture corpus.** 0020: "I am the second client and it was cheap."
16. **Trusted runtime time/IDs and owner stamping.** 0017: "I never missed `Date.now()`." 0001: "Omitting the field is both shorter and more trustworthy."
17. **Honesty axes on offline.** 0043: "The honesty axis is the best I have seen on any backend; Firebase's `fromCache` is a boolean by comparison." "No frozen arm — Firebase and InstantDB included — surfaced settlement evidence this machine-checkable."
18. **Assets upload as one task.** 0041: "`assets.start({upload, file})` → `ready` … in one await. Genuinely nicer than the Convex three-step." "GPS stripping needed zero demo code."
19. **Config declared next to functions; printed setup line.** 0008: "The printed install line is the money shot."
20. **Manifest-only generated custody (post-0108).** 0038: "only deterministic `generated/artifacts.json` belongs in source control. This directly fixes the old 'commit roughly 140 KiB for a tiny backend' complaint."

## (c) Competitor mechanism comparisons (where and why they were better or worse)

### Convex
- **Better: coherence of one loop.** 0027: "Convex's best quality is coherence. Schema, functions, transactions, reactive queries, generated types, React hooks, local deployment, and auth all feel like parts of one product. The default mutation retry contract is unusually valuable." 0022: "Schema, functions, and client references formed the most coherent TypeScript loop." 0039: "Convex has a mature, installed, inferred TypeScript product loop while Snapback asks for more explicit contracts and still exposes framework/runtime edges."
- **Better: reactive by default incl. search.** 0028: "One indexed query covered initial read, native WebSocket push, reconnect, and authorization-dependent invalidation." 0037: Convex search "participate[s] in its reactive query subscription model; Snapback portable search v1 is ordinary request/response only."
- **Better: nested input validators, helper sharing, inference.** 0036/0039: `v.array(v.object(...))` at mutation boundaries; "ordinary TypeScript helpers [can] be shared."
- **Better: transactional one-off scheduling.** 0038: "`ctx.scheduler.runAfter(0, ...)` … there is still no equally obvious transactional one-off schedule primitive."
- **Better: single query composes a detail graph.** 0029: "A single transactional query composed the issue detail graph."
- **Better: hosted path and deploy key.** 0016: "`npx convex deploy` typechecked, regenerated `_generated`, pushed schema/functions/indexes, and ran without interactive login … a strong 'go to lunch' workflow." 0018: "Convex still has the materially shorter hosted path because the identity, deployment, logs, and data lifecycle are one supported product surface."
- **Better: server error locus.** 0028: "Server errors named the function, request id, classification, source file, and line, which materially shortened diagnosis."
- **Better: streaming (before LLP 0076).** 0017: "its default runtime supports response-body streaming."
- **Worse: presence is durable heartbeat rows.** 0022: presence "required a table, connection key, heartbeat mutation, time window, leave mutation, and stale-row cleanup." 0039: "cursor-rate traffic writes the durable database."
- **Worse: preloadQuery refetches.** 0004/0019: "Convex's `preloadQuery` re-executes the full query after hydration."
- **Worse: agent-mode setup still prompts; hidden flags; deployment-global schema; secrets in argv; wildcard bind.** 0027: "the CLI asked two setup questions … over a minute downloading the backend binary." 0030: "Exact local backend and site ports exist but were omitted from `convex dev --help`." 0017: "deploying either demo's dir alone would delete the other's functions … schema and functions are deployment-global." 0031: "the official local backend places a generated control credential in process argv and binds backend and site listeners to wildcard addresses."
- **Worse: no cold offline boot.** 0027: "Durable offline boot is therefore a GAP." 
- **Worse: hides gaps.** 0001: "Convex tends to hide its gaps; Snapback names them."

### Supabase
- **Better: Postgres as modeling substrate; constraints; RLS; full-text + pgvector; pg_cron; breadth in one local stack.** 0022: "Postgres was the strongest data-modeling environment." 0031: "it could compose auth, durable progress, files, semantic search, scheduling, and cancellation in one runnable target." 0015: unique compound index "is the familiar PostgreSQL/Supabase constraint shape and is materially better than a Convex-style read-before-write convention."
- **Worse: realtime is invalidation-plus-refetch, not reactive; readiness unreliable; slow locally.** 0027: "invalidation-plus-round-trip rather than a reactive query." 0029: "A channel could report `SUBSCRIBED` and still miss the first comment inserted immediately afterward on a cold stack." 0016: "a write committed between channel creation and server-side filter registration is silently never echoed … Snapback's live queries hand you read-your-own-writes from the transport." Local push 491–525 ms (0029, 0030).
- **Worse: authorization surface verbose and easy to get subtly wrong.** 0029: "Supabase made the primitives available; it did not make the whole authorization design coherent for the builder." 0027: "four tables, four groups of policies/grants, a security-definer membership helper to avoid recursive RLS, three RPC functions…"
- **Worse: no offline.** 0027: "This is an architectural product GAP, not a missing toggle."
- **Worse: prints secrets; heavy Docker; `--output env` ignored.** 0028: "`supabase start` printed privileged local development keys to the terminal." 0031: "`supabase start` always renders its final status in the pretty format, even when the global `--output env` flag is supplied." Twelve containers; Colima can't mount `/private/tmp`.
- **Worse: no preload primitive.** 0019: "you would hand-roll an endpoint … and get the `</script>` escaping right yourself."

### Firebase
- **Better: mature emulator suite; demo- projects can't reach prod; IndexedDB persistence + offline queue; Rules re-evaluated for connected listeners; local vector search.** 0027: "Firebase's offline behavior is opt-in on the web … the arm would have failed this workload without deliberate cache configuration." 0030: "Firestore Rules dependencies were re-evaluated for already-connected clients." 0031: "Local vector search was a pleasant surprise."
- **Worse: four products for one chat; rules coupled to query shape; no joins; hot transactional counter; 11–24 audit findings; hidden auxiliary ports; `fromCache` is one boolean; silent empty-cache fallback.** 0028: "A small chat needed four Firebase products." 0029: "Firestore Security Rules couple authorization to query shape." 0043 probe: "the SDK **silently fell back to an empty memory cache** … An app that missed that renders an empty notebook offline with no way to tell."

### InstantDB
- **Better: compact typed schema + live queries + optimistic transactions + IndexedDB + guest auth with no sync engine written; disposable hosted apps.** 0027: "The app code is recognizably the product, not a custom sync engine." 0029: "The disposable hosted-target flow was exceptional dogfood ergonomics: one command produced an app-scoped admin credential and a documented expiry."
- **Worse: permissions pass CLI push and fail at runtime; diagnostic names no rule; linked-permission invalidation stale 12 s; LWW capacity ambiguous to loser; signed URL usable after delete; output mixes JSON with prose; noninteractive push silently waits.** 0028: "Terse CEL rules could pass CLI push and fail only at runtime." 0029: "The diagnostic was only `Permission denied: not perms-pass?` plus an entity, not the failing rule, direction, field, or binding."

### SpacetimeDB
- **Better: reducers + caller-dependent views evict revoked rows; generated bindings; sub-second module builds; migration preflight prints a plan; schedule tables.** 0028: "Membership revocation was excellent … evicted every protected row from his already-subscribed cache. This is the exact authorization-sensitive outcome Snapback currently fails." 0029: "The additive migration was a high point. The CLI printed a concrete plan."
- **Worse: no parameterized views (durable page_result tables), no ephemeral, memory-only cache, PANIC logs for expected auth errors, generic `InternalError`, CLI vocabulary drift, `--anonymous` orphaned owner token.** 0030: "Intentional reducer rejections arrived at the SDK as a generic `InternalError`; the useful capacity or authorization diagnostic lived in the server log."

### Zero
- **Better: relational query language; shared client/server mutator removes optimistic-reducer duplication; completeness as first-class state; client-chosen IDs make optimistic create native.** 0042-triage: "`related(...)`, `whereExists(...)`, and ZQL predicates express … one composable query rather than an application-written join loop." 0043-latency: "Zero's shared client/server mutator removes optimistic reducer duplication."
- **Worse: operational width (Postgres logical replication, slots, cache, API, `.bin` in PATH); mutation errors are fulfilled result unions; loud ApplicationError logs; exposes constraint names.** 0045-private: "Snapback was materially simpler to operate: one qualified binary, generated contract, and owned state directory versus PostgreSQL plus API plus cache plus replication cleanup."

### Appwrite
- **Better: native transactions with typed 409, TablesDB one-call schema+indexes, breadth (Auth/Teams/Storage/Functions/Realtime).** **Worse: 28–29 containers, 910 MB image, 2.9 GiB; CLI/server version skew; presence 401 despite docs; concurrent subscribes only first activates; installs agent skills into the app dir.** 0027: "preserve the simplicity of one small local runtime rather than inheriting Appwrite's 28-container operational shape."

### Plain SQLite / React web baseline
- 0016: "SQLite. No contest for time-to-first-row … 'Just SQLite' wins the first hour and loses more ground with every production requirement." 0017: React web + fetch/poll "verified end-to-end on the first browser load. Fastest cell of the entire matrix to working. This is the reference point every richer stack should justify itself against."

## Cross-cutting observations for "Snapback 2, designed from scratch"

1. **The agent's loop is only as good as its worst diagnostic.** Every long correction loop in these diaries (0009's 35 min, 0011's 15 min, 0017's three rebuilds, 0044's 15-min evolution detour, 0045's silent `snapback dev`) traces to a signal that was absent, generic, or pointed at the wrong subsystem — never to a coded refusal that named the rule. The same corpus shows coded refusals resolving mistakes in one turn (0042-a2 "three iterations … none of them mysterious").
2. **Native runtime readiness must be proven by executing a handler, not by linking.** Seven consecutive diaries (0032–0038) plus 0017/0020/0022 lost their first hour to a green doctor + green bootstrap + `SNAPBACK_RUNTIME_CREATE_FAILED`.
3. **Docs, package, binary, and main drift apart within hours.** Agents held a guide that was ahead of the package (0025, 0045) or behind it (0032, 0039), a pin that a sibling repo outran in 40 minutes (0010), and a capability index that advertised a surface whose page was a GAP (0025). Snapback 2 needs one versioned truth the agent can query (`snapback guide`/capability manifest bound to the installed closure).
4. **Ceremony is paid at codegen time and reads as a colleague; ceremony paid at provision/runtime reads as a wall.** The same agents praise `BUNDLE_UNSUPPORTED_TIME` and curse `SNAPBACK_MEMBERSHIP_BATCH_UNSUPPORTED` — the difference is when it fires.
5. **The competitive floor is now InstantDB/Firebase offline + Convex coherence + Zero relations**, and Snapback's own moat — ephemeral lanes, settlement envelopes, membership invalidation, deterministic ticks, honesty facts, one-binary local ops — is repeatedly rated best-in-class *when reachable from the first-party React/Expo arm.* The recurring verdict shape is "backend: yes, enthusiastically; product on the shipped package: not yet."
