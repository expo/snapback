## Material finding

**The saved `day2-check.json` report retains plaintext readiness credentials, contradicting RFC §17 and the committed assertions.**

- [day2-check.js:80](/home/ccheever/projects/sb4-b32-dx15/snapback4/packages/snapback4/bin/day2-check.js:80) returns the whole serveCheck `receipt` into every serve-phase result, and [day2-check.js:45](/home/ccheever/projects/sb4-b32-dx15/snapback4/packages/snapback4/bin/day2-check.js:45) pushes it verbatim into `report.phases`. The failure path does the same via `error.report` at [day2-check.js:42](/home/ccheever/projects/sb4-b32-dx15/snapback4/packages/snapback4/bin/day2-check.js:42).
- That receipt includes `ready` verbatim — [proof-serve-check.ts:161](/home/ccheever/projects/sb4-b32-dx15/snapback4/packages/snapback4/src/proof-serve-check.ts:161) builds the report as `{ok, script, failures, ready, …}` with no redaction. `ready` is the serve script's first JSON line, i.e. `{backendUrl, users: host.sessions}`, and the account shape carries plaintext secrets ([proof-accounts.ts:12](/home/ccheever/projects/sb4-b32-dx15/snapback4/packages/snapback4/src/proof-accounts.ts:12): `password: string`, plus `token`).
- RFC §17 requires "Readiness credentials and client stdout are excluded from that report." Client stdout is correctly excluded (secret commands never reach the report; only a stderr log *path* is kept), but all five serve phases persist `receipt.ready` with passwords and tokens into the 0600 file the guide tells users to "read that file."
- The leak also reaches the terminal: `--json`/`--explain` print the full report ([day2-check.js:124-125](/home/ccheever/projects/sb4-b32-dx15/snapback4/packages/snapback4/bin/day2-check.js:124)), and the write-failure fallback `console.log`s it ([day2-check.js:120](/home/ccheever/projects/sb4-b32-dx15/snapback4/packages/snapback4/bin/day2-check.js:120)).
- Both committed checks assert the opposite and would fail: the DX17 test asserts `!JSON.stringify(report).includes('"password"')`, and the [publication-dx17.mjs](/home/ccheever/projects/sb4-b32-dx15/snapback4/scripts/publication-dx17.mjs) packed consumer asserts the same. Fix: strip `ready` (or at minimum credential fields) from the receipt before it enters the report, on success, callback-failure, and print paths.
