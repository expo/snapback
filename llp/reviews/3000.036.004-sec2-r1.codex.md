Three material corrections are required. Findings are from static inspection; no tests were run or files edited.

1. **MATERIAL false-refutation: the paired policy is checked before the mutation, rather than at disclosure.**  
   [§10.1](/home/ccheever/projects/sb4-b16-sec2/llp/3000.036.004-security-invariants-and-exposure.rfc.md:358) makes an output difference sufficient when both initial policies are false. [paired.rs](/home/ccheever/projects/sb4-b16-sec2/snapback4/crates/snapback4-lang/src/bind/security/challenges/paired.rs:53) implements that ordering explicitly.

   Consider an invariant requiring a current reader grant. A permitted mutation creates that grant, then reads the protected row. The present world returns the row; the absent world returns null. Both initial policies were false, but the actual read satisfies the invariant. Labeling this refuted strengthens the declared access-boundary contract into permanent secrecy after an initially unauthorized snapshot.

   **Required correction:** restrict paired mutations to a proved stable policy boundary, including protected fields, grant dependencies and implicit writes; otherwise trace authorization at each observation or report unproved. Checking only the final state is insufficient.

2. **MATERIAL false-refutation: finite repeatability does not establish deterministic paired inputs.**  
   [paired.rs](/home/ccheever/projects/sb4-b16-sec2/snapback4/crates/snapback4-lang/src/bind/security/challenges/paired.rs:46) excludes explicit `NewId`, then accepts differences that repeat once. However, natural-key upsert can mint an ID internally in [write_target.rs](/home/ccheever/projects/sb4-b16-sec2/snapback4/crates/snapback4-core/src/engine/write_target.rs:236), without `NewId` in the program IR. Minting uses independent cryptographic entropy.

   An unrelated upsert can return a Boolean comparing its minted ID against a midpoint ID at the pinned clock. Different Boolean results can repeat by chance across the four executions, producing a “counterexample” unrelated to the protected row.

   **Required correction:** couple nondeterministic inputs explicitly, including implicit minting, or conservatively exclude every operation with an uncontrolled source. Repetition may detect instability; it cannot certify determinism.

3. **MATERIAL usability/contract risk: adoption coverage omits effective owner-field authority.**  
   [adoption.rs](/home/ccheever/projects/sb4-b16-sec2/snapback4/crates/snapback4-lang/src/bind/security/adoption.rs:5) counts only the four table rules; its uncovered-exposure filter likewise removes `deny` effects. Yet an owned-only patch can bypass an ordinary denied update rule in [field_authority.rs](/home/ccheever/projects/sb4-b16-sec2/snapback4/crates/snapback4-core/src/engine/field_authority.rs:93).

   Consequently, a table with denied table rules and effective `written by` authority can receive no missing-intent note, no draft explanation, and no uncovered update entry. This contradicts §10.3’s “any effective access rule” and per-effect coverage promises.

   **Required correction:** include owner-field authority in adoption discovery and uncovered exposure reporting, retaining its column and owner predicate. Unsupported candidate forms should receive an explicit explanation rather than disappear.
