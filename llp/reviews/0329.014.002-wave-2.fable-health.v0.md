# Paper archetype, wave 2: regulated health records against LLP 0329.014.000 v0.1

**Respondent:** Claude Fable 5 · **Design under test:** `design-health.md` (codex), fixed · **Target:** LLP 0329.014.000 v0.1 incl. §9.1 and §11 · **Prediction under test:** LLP 0329.014.002 #4.

Headline. Prediction 4 named three missing schema declarations, "all new". Two are not missing. Column-level visibility is the protection-class split the design's own §7 concedes, expressible in v0 today; row versioning and hold-fenced deletion are append-only rows plus a system `schedule`, with `versioned()` and `hold()` as K6 *bindings*, not enablers. The one genuinely new item is narrower than predicted: not "reads that write" (a `mutation` already reads, writes, and returns) but **live, retained reads that audit** — the `query` kind cannot satisfy invariant 12, so 14 of this app's 15 reads are mutations and forfeit liveness and offline retention until a table-level `audited` declaration exists (L2). Two spec rules return wrong answers here: **§9.1.2 (hidden rows consume `take`) makes page length and `hasMore` a cardinality oracle** — a nurse confirms an SSN guess through the lookup-token index — and **§9.1.8's uniformity proof admits a reduction under a hoisted-false rule**, so a nurse's retention-deadline `max` silently omits the identity and restricted chains and the sweep destroys early. L1–L9 refer to §6; ⓐ marks an audited read (§3).

### 2. Schema in v0

Protection classes are tables (`contact`, `directory`, `identity`, `identityMask`, `identityToken`, `coverage`, `clinical`, `codes`, `narrative`, `restricted`); a version is a row in one class's chain and each class has its own head row. `ledger()` abbreviates `delete: never` + `immutable(all but state)` + `immutableExcept({ fields: ['state'], when: (o, n) => sys() || n.state === 'revoked' })` — spec features, abbreviated. Role helpers in rules (`adminOf`, `repOf`, `privacyOfficer`, `legalOfficer`, `releaseRole`, `privacyReviewer`, `privacyCaseOn`) are one-probe `exists` in the style of `careOk`.

```ts
import { table, id, text, int, time, interval, json, cap, appendOnly, immutable, maintain, tokens, viewer, principal, never } from 'backend'
const sys     = () => principal.kind === 'system'
const cx      = () => db.get(activeContexts, viewer)                                                   // viewer-pinned → hoisted
const grantOk = orgId => db.exists(staffGrants.byActorOrgRoleState, [viewer, orgId, cx().roleCode, 'active'])   // key from a probed row: L9a
const careOk  = pid => db.exists(careRelationships.byPatientActorState, [pid, viewer, 'active'])
const glassOk = pid => db.exists(breakGlassEpisodes.byPatientActorState, [pid, viewer, 'active'])
const cell    = (cls, action) => db.get(policyCells.byCell, [cx().policyRevisionId, cls, cx().roleCode, cx().purposeCode, action])   // deny-wins resolved at write
const may = (r, cls, action) => grantOk(r.orgId) && (
     (cell(cls, action)?.effect === 'allow' && (cell(cls, action).basis === 'none' || careOk(r.patientId) || db.exists(consentEntitlements.byPatientClassGrantee, [r.patientId, cls, viewer])))
  || (action === 'read' && cell(cls, 'emergency')?.effect === 'allow' && glassOk(r.patientId)))     // emergency allow-list never names identity/coverage/restricted

export const activeContexts = table({ id: id() /* actor */, orgId: id(), roleCode: text({ max: 32 }), purposeCode: text({ max: 32 }), policyRevisionId: id(), deviceId: id() })
  .rules({ read: c => c.id === viewer, insert: c => c.id === viewer && db.exists(staffGrants.byActorOrgRoleState, [viewer, c.orgId, c.roleCode, 'active']), update: (o, c) => o.id === viewer, delete: c => c.id === viewer })
export const policyCells = table({ id: id(), policyRevisionId: id(), orgId: id(), cls: text({ max: 16 }), roleCode: text({ max: 32 }), purposeCode: text({ max: 32 }),
    action: text({ max: 10 }) /* read|filter|write|export|emergency */, effect: text({ max: 5 }) /* allow|mask|deny */, basis: text({ max: 8 }) /* none|care|consent */ })
  .appendOnly().unique('byCell', ['policyRevisionId', 'cls', 'roleCode', 'purposeCode', 'action']).cap({ by: 'policyRevisionId', max: 2_000 })
  .rules({ read: c => grantOk(c.orgId), insert: c => adminOf(c.orgId), update: never, delete: never })
// policyRevisions (effective: interval; two approvers ≠ recorder) and policyHeads (the revision fence) follow the head/revision pattern.

// Authority facts: revisions + a head (the expected-revision fence); `state` flips by schedule at both validity ends (K5) and instantly on revocation.
export const staffGrants = table({ id: id(), grantId: id(), revisionNo: int(), actorId: id(), orgId: id(), patientId: id(), roleCode: text({ max: 32 }), validity: interval(),
    state: text({ max: 10 }), approvedBy: id(), recordedBy: id(), recordedAt: time(), supersedesId: id() }).ledger()
  .unique('byGrantRev', ['grantId', 'revisionNo']).index('byActorOrgRoleState', ['actorId', 'orgId', 'roleCode', 'state'])
  .rules({ read: g => g.actorId === viewer || adminOf(g.orgId), insert: g => adminOf(g.orgId) && g.actorId !== viewer && g.approvedBy !== viewer && db.exists(privacyApprovals.byGrantRev, [g.grantId, g.revisionNo]) })
schedule(flipValidity, { at: g => g.validity.from, key: g => [g.id, 'start'], principal: 'system' })     // L9d: two schedules per row
schedule(flipValidity, { at: g => g.validity.to,   key: g => [g.id, 'end'],   principal: 'system' })
// careRelationships (byPatientActorState) and representativeAuthorities (byPatientRepState; permittedActions: json) are the same shape.

export const consentRevisions = table({ id: id(), consentId: id(), patientId: id(), revisionNo: int(), granteeKey: text({ max: 80 }) /* actor:… | org:…:role */,
    authorization: interval(), record: interval(), state: text({ max: 16 }), revocationEffectiveAt: time({ commitTime: true }),
    artifactHash: text({ max: 64 }), recordedAt: time(), recordedBy: id(), supersedesId: id() }).ledger().unique('byConsentRev', ['consentId', 'revisionNo'])
  .rules({ read: c => patientOrRep(c) || privacyOfficer(c.patientId), insert: c => c.recordedBy === viewer && patientOrRep(c) })   // consentHeads: the revision fence; consentScopes: cap 64 per revision
// consentEntitlements(patientId, cls, granteeKey, consentRevisionId, state): index byPatientClassGrantee, cap 64 per revision; insert sys (activateConsent), flipped by revocation.

// Chart: item spine + one chain and one head per protection class; a full-snapshot row spanning classes fails under visibility (§3).
export const patientDirectory = table({ id: id() /* patient */, orgId: id(), patientId: id(), legalName: text({ max: 200 }), dob: time() })
  .index('byNameToken', tokens('legalName')).index('byOrgDob', ['orgId', 'dob']).partitioned()      // L1; rules: read may(…,'directory','read'), write may(…,'contact','write')
export const chartItems = table({ id: id(), patientId: id(), orgId: id(), recordKind: text({ max: 16 }) /* demographics|note|restrictedNote|diagnosis|medication|allergy|lab|document */, createdAt: time(), createdBy: id() })
  .index('byPatientKindCreated', ['patientId', 'recordKind', 'createdAt']).immutable(['patientId', 'orgId', 'recordKind']).partitioned()   // L1: kind in the prefix → hoisted
  .rules({ read: i => may(i, kindClass(i.recordKind), 'read'), insert: i => i.createdBy === viewer && may(i, kindClass(i.recordKind), 'write'), update: never, delete: sys })
const versionCols = { id: id(), itemId: id(), patientId: id(), orgId: id(), revisionNo: int(), parentVersionId: id(), changeKind: text({ max: 8 }), clinical: interval(),
    recordedAt: time(), recordedBy: id(), commandId: id() }

export const contactHeads = table({ id: id() /* item */, patientId: id(), orgId: id(), currentVersionId: id(), revisionNo: int() })
  .rules({ read: h => may(h, 'contact', 'read'), insert: h => may(h, 'contact', 'write'), update: (o, h) => may(o, 'contact', 'write') && h.revisionNo === o.revisionNo + 1, delete: sys })
// identityParts (ssnCiphertext), identityMasks (ssnLast4), identityTokens (token; index byOrgToken; action 'filter'), coverageParts, clinicalParts, codeParts, narrativeParts,
// restrictedParts (the design's field_label = which chain a narrative enters) repeat this shape with cls fixed, each with its own *Heads table.
// attachments: per-item rows carrying a cls column; index byItemCls ['itemId', 'cls'], partitioned — the E_NONUNIFORM_SCAN example in §3.

// clientCommands (unique byActorCommand: the dedupe), deviceAccessEvents, reviewCases (unique byEpisode), breakGlassEvents, reviewDecisions, holdEvents, destructionCertificates, tombstones, disclosureEvents, auditBatches: appendOnly.
export const accessEvents = table({ id: id(), requestId: id(), actorId: id(), patientId: id(), orgId: id(), purposeCode: text({ max: 32 }), decisionAt: time({ commitTime: true }), outcome: text({ max: 8 }),
    basisIds: json({ maxBytes: 4_096 }), policyRevisionId: id(), episodeId: id(), manifest: json({ maxBytes: 65_536 }) /* version ids + classes, no values */, manifestHash: text({ max: 64 }) })
  .appendOnly().unique('byRequest', ['requestId']).index('byOrgAt', ['orgId', 'decisionAt']).index('byEpisode', ['episodeId'])
  .rules({ read: e => privacyCaseOn(e.patientId) || sys(), insert: e => e.actorId === viewer || sys(), update: never, delete: never })   // L8: retain 'never'

export const breakGlassEpisodes = table({ id: id(), patientId: id(), orgId: id(), actorId: id(), deviceId: id(), incidentId: text({ max: 64 }), reasonText: text({ max: 2_000 }), startedAt: time({ commitTime: true }), expiresAt: time(), state: text({ max: 8 }) })
  .index('byPatientActorState', ['patientId', 'actorId', 'state']).index('byStateExpires', ['state', 'expiresAt']).index('byIdActor', ['id', 'actorId']).immutable(['patientId', 'actorId', 'deviceId', 'incidentId', 'expiresAt'])
  .rules({ read: e => e.actorId === viewer || privacyReviewer(e.orgId), insert: e => e.actorId === viewer && cell('emergency', 'start')?.effect === 'allow' && e.reasonText.length >= 20
      && db.exists(devices.byIdState, [e.deviceId, 'compliant']) && (db.get(activeEpisodes, [viewer])?.value ?? 0) === 0 && e.state === 'active', update: (o, e) => (o.actorId === viewer || sys()) && e.state !== 'active', delete: never })
maintain.count(breakGlassEpisodes, { by: ['actorId'], where: e => e.state === 'active', as: activeEpisodes })   // K2: about the caller
schedule(expireEpisode, { at: e => e.expiresAt, key: e => e.id, principal: 'system' })

export const holdScopes = table({ id: id(), holdId: id(), orgId: id(), patientId: id(), itemId: id(), recordKind: text({ max: 16 }), clinical: interval(), state: text({ max: 8 }) })
  .appendOnly().index('byPatientState', ['patientId', 'state']).index('byOrgKindState', ['orgId', 'recordKind', 'state']).cap({ by: 'patientId', max: 64 }).cap({ by: ['orgId', 'recordKind'], max: 64 })   // every hold probe is All
  .rules({ read: s => legalOfficer(s.orgId) || sys(), insert: s => legalOfficer(s.orgId), update: (o, s) => legalOfficer(o.orgId) && secondApprover(o.holdId), delete: never })
export const retentionDispositions = table({ id: id() /* item */, orgId: id(), patientId: id(), recordKind: text({ max: 16 }), triggerAt: time(), clinicalSpan: interval(), eligibleAt: time(), generation: int(), state: text({ max: 12 }) })
  .index('byOrgStateEligible', ['orgId', 'state', 'eligibleAt']).rules({ read: d => legalOfficer(d.orgId) || sys(), insert: sys, update: sys, delete: never })
export const itemDataKeys = table({ id: id() /* item */, wrappedKey: text({ max: 512 }), generation: int() }).rules({ read: sys, insert: sys, update: never, delete: sys })
// destructionJobs: cap 50 per runId; read legalOfficer|sys, insert/update sys. retentionRules: ledger(), index byJurisdictionKindState, cap 8 per (jurisdiction, kind).
```

No `channel`, `exclusion`, `tree`, `recurse`, or `readTime`. `interval` carries every validity, authorization, record, and clinical interval; rules never compare one to a clock — `state` does that work.

### 3. Operations in v0

Grouped by the design's §5; certificates are in §1; `audit(db, ctx, requestId, manifest)` is the helper shown inline in `openChart`.

**The audited read (ops 4, 9, 13 and every ⓐ operation).** First attempt, the natural spelling — `query({ patientId }, ({ db, args }) => panels(db, args.patientId))`. `check` admits it: no §9 family covers "this read must write", so the program is live, retained, and **unaudited** — a wrong answer by omission. Corrected:

```ts
export const openChart = mutation({ patientId: id(patients), requestId: id() }, ({ db, ctx, args }) => {
  if (db.get(accessEvents.byRequest, [args.requestId])) return replay(db)   // inv. 13: same version ids, re-read under current authority (≤ 300 gets)
  const out = { demographics: null, items: [] }, manifest = []
  const ch = db.get(contactHeads, args.patientId)        // null for absent and for forbidden alike
  if (ch) { out.demographics = db.get(contactParts, ch.currentVersionId); manifest.push(['contact', ch.currentVersionId]) }
  for (const it of db.scan(chartItems.byPatientKindCreated, [args.patientId, 'note'], { order: 'desc', take: 50 })) {
    const h = db.get(clinicalHeads, it.id), n = db.get(narrativeHeads, it.id); if (!h) continue
    out.items.push({ item: it, current: db.get(clinicalParts, h.currentVersionId), narrative: n && db.get(narrativeParts, n.currentVersionId) })
    manifest.push(['clinical', h.currentVersionId]); if (n) manifest.push(['narrative', n.currentVersionId]) }
  db.insert(accessEvents, { id: ctx.newId(), requestId: args.requestId, actorId: ctx.viewer, patientId: args.patientId, orgId: cx().orgId, purposeCode: cx().purposeCode,
    outcome: manifest.length ? 'allowed' : 'denied', basisIds: null /* L2: the trace knows them */, policyRevisionId: cx().policyRevisionId, episodeId: null, manifest, manifestHash: null /* L6 */ })
  return out })
// examined ≤ max(1 + 2 + 52 + 50×4, 1 + 300) = 302; probes ≤ 24, hoisted; writes 1. The insert commits before the result is serialized (§6): inv. 12 holds; a failed delivery over-audits.
```

The manifest is a loop tally *about the caller's response* (K2: caller). The `basisIds` the design wants are exactly the rows the rules probed: the trace has them and the program does not, which is why L2 has the engine write this row. The live form is refused until L2; no v0 rewrite makes a subscription audit its deltas. Other ⓐ operations: `searchPatients` (`byNameToken [term] take 50`, uniform rules, L1); `investigateAccessEvent`, whose first attempt looped over `e.basisIds` (json) → **`E_UNBOUND_LOOP`**: *json carries no cardinality; rewrite: a child table with `cap`, or `list(id(), { max: 8 })` (L9b)*; `chartAsOf`, which scans items `range lte knowledgeAt`, per item takes `clinicalParts.byItemRecorded [item] range lte K desc take 1`, keeps versions whose `clinical.contains(clinicalAt)`, and audits (examined ≤ 102 + 100×3) under today's cells (inv. 10); its `take 1 desc` is admitted because the result is returned, not written.

`lookupBySsnToken` scans `identityTokens.byOrgToken [org, token] take 5`, audits, and returns the patient ids with `hits.hasMore`. Admitted; exact for registration. For a nurse the rule hoists to *false*, yet under §9.1.2 the seven raw entries are examined and consumed, so a patient with ≥ 8 demographics revisions returns `hasMore: true` — one bit saying "a patient with this SSN exists". L1's short-circuit (hoisted-false ⇒ empty, exhausted, zero examined) closes it. Where a rule varies *within* a prefix — `attachments` scanned by item alone, `cls` per row — L1's compile-time check fires: **`E_NONUNIFORM_SCAN`** — *scan over partitioned table `attachments` examines rows whose read rule depends on `attachments.cls`, not in the prefix; page length and `hasMore` would disclose hidden rows. Rewrite: pin the class in the prefix or split the table.*

**Op 1 — authority and policy.** `changeStaffGrant` inserts a revision under its insert rule and bumps the head with `revisionNo === expected`; `replacePolicy` takes `cells: list(cell, { max: 2_000 })`, resolves deny-wins in a `Map`, and `insertEach`es. "Advance affected generations" has no program: every subscription whose rules probed a cell or grant row re-runs on the commit — the trace is the generation.

**Ops 2–3 — consent.** `issueConsent` inserts head, revision (`pendingSignature`), ≤ 64 scopes, and an outbox row; the `verifyConsentSignature` effect verifies the artifact and calls system-callable `activateConsent`, which writes ≤ 64 entitlements and sets `scheduled|active`; `revokeConsent` requires `head.revisionNo === expected`, inserts a `revoked` revision, bumps the head, flips the ≤ 64 entitlements, and stops. Its first attempt wrote `revocationEffectiveAt: Date.now()` → **`E_AMBIENT_TIME`**; `ctx.now()` is the client's intent clock, the wrong fact for inv. 9 — the column is `time({ commitTime: true })` and the program never writes it. The second attempt cancelled `disclosureJobs.byConsentState [rev, 'queued']` inline: the patient cannot read jobs, so the scan is empty and nothing is cancelled — admitted, K2 on the write side (§4). The real fence is `consent.state`, rechecked at every page; the cosmetic cancellation is a system `schedule(cancelDisclosures, { at: r => r.recordedAt, key: r => r.id, if: r => r.state === 'revoked' })` (L9d).

**Op 5 — break glass.** `startBreakGlass` inserts the episode with `expiresAt = ctx.now() + 30 min` ("or shift end": no roster fact exists, §7); the insert rule carries eligibility (emergency cell, compliant device, ≥ 20 characters, `activeEpisodes[viewer] === 0`); then a `started` event, a `mandatoryReview` outbox row, and `openChart` with `episodeId` on the access event. `may` reaches only `emergency` cells: contact and clinical open; identity, coverage, and restricted never do. `reviewSweep` (hourly, 10 episodes per run) scans `byStateExpires ['expired'] take 10`, skips when `reviewCases.byEpisode` exists (the unique index coalesces workers), links `accessEvents.byEpisode take 50` into `riskFlags`, and inserts the case — examined ≤ 12 + 10×54.

**Ops 6–7 — clinical writes and the copy-forward trap.** First attempt, op 7 as the design writes it: one `demographicsPayload` table, one spine, `{ ...cur, ...patch }` inserted as a full-snapshot successor with untouched values copied from the current row. `check` admits it, and it is wrong twice. With one payload table the nurse reads `cur.ssnCiphertext` — invariant 4 gone, and no diagnostic can see that a *column* is sensitive. With parts split by class but one spine, her successor must include an identity part she cannot insert, or omit it and leave the spine's current identity dangling — and registration's hidden revision 185 collides with her `(itemId, 186)` on the shared unique index, a sealed refusal that still says "someone changed something" (invariant 15). The only shape that closes both is **one chain and one head per class**.

`correctContact({ itemId, baseVersionId, touched: list(text, { max: 6 }), values: json, commandId })` dedupes on `clientCommands`, point-reads the contact head, its current part, and the base part, requires `cur[f] === base[f]` for each touched field (same class, same field only; six literal branches if `cur[f]` is `E_OPAQUE`, L9f), inserts `{ ...cur, ...pick(values, touched), revisionNo: head.revisionNo + 1, parentVersionId: cur.id }`, and bumps the head — examined ≤ 5, writes 4, prediction conditional (the head row is held; the unique index may refuse on a sibling's write).

An intervening SSN change touches `identityHeads`, which this program never reads: no conflict, no leak, nothing overwritten — invariant 17 by construction. `appendClinicalVersion` is the same over the clinical, narrative, and restricted chains. Every part table carries `schedule(recomputeDisposition, { at: v => v.recordedAt, key: v => v.itemId, principal: 'system' })`. The first attempt computed the retention deadline inline — `max` over `identityParts.byItemRecorded [item] take 100`, written to the disposition. `check` v0.1 admits it: the rule inputs (`viewer`, `itemId`, a class literal) are uniform over the prefix, so §9.1.8's proof passes; at run time the nurse's hoisted verdict is *false*, the page is empty, and the deadline omits the identity chain. It fails here only because `retentionDispositions.update` is `sys` — an author who lets writers maintain it gets an understated deadline and an early destruction. The route is the system schedule (§4).

**Op 8 — offline.** The packet is the retained store and the outbox is the command batch: each command is one mutation, `clientCommands` dedupes, reconnect re-authorizes before replay (§6). What v0 cannot say: identity, mask, token, coverage, restricted, and access-event rows must never be retained while contact and clinical rows may be kept eight hours (L8), and a local open must append a device-ledger row first (L2b).

**Ops 10–11 — holds and the sweep.** `activateHold` inserts the hold, ≤ 64 scopes, and an event; it cancels nothing because nothing recoverable exists.

`retentionSweep` (`every: '1s'`, system, cursor row) scans `retentionDispositions.byOrgStateEligible [org, 'retained'] range (cursor, asOf] take 50`. Per item it reads the ≤ 8 active rules (`cap` → `All`), recomputes `deadline = max(triggerAt + months(duration))` exactly under system visibility and defers if it moved; probes `holdScopes.byPatientState [patient, 'active'] take 64` and `byOrgKindState [org, kind, 'active'] take 64` (caps → `All`) with an `overlaps(scope, item)` predicate and marks `heldDeferred` on a match; otherwise inserts the `authorized` destruction job (the point of no return), deletes `itemDataKeys[item]` (cryptographic erasure in the same commit), and writes the tombstone and outbox row. Examined ≤ 52 + 50×(10 + 66 + 66 + 3) = 7,302; writes ≤ 250; `G` must sit above ~8k here — a product parameter, as the gauntlet found.

Trap 4 closes by construction: recheck, hold probes, authorization, and key deletion are one commit on one writer, so a hold commits before (the recheck sees it) or after (it sees the tombstone) — there is no unfenced delay to pause in. `months()` is a pure UTC calendar helper; `destroyExternal` is an effect on the outbox row (idempotent purge, then system-callable `recordDestructionCertificate`). `recomputeDisposition` (system, per item) scans each class chain (7 × `take 50`) to set `triggerAt`, `clinicalSpan`, `eligibleAt` — exact because the system principal sees every chain (L9c). A retention-rule revision does not bulk-recompute; the sweep recomputes each item at its old `eligibleAt` (§7).

**Op 12 — disclosure.** `createDisclosureJob` inserts the job (`consentRevisionId` added, §8 #3) and ≤ 500 immutable manifest entries. `disclosePage` runs under `system`, invoked by the transmit effect: it requires `job.state === 'queued'`, `consent.state === 'active'`, and recipient trust, scans `manifestEntries.byJobOrdinal [job] range gt cursor take 100`, per entry point-reads the version and requires `consent.record.contains(v.clinical.from)`, the scope row, and the export cell for the *job's* recorded role, then appends `handoff_started` and the access event; the effect transmits with the idempotency key and calls `recordHandoffReceipt`. Revocation before this commit is seen by the `require`; after it, the page is history; the sealed page's `contentHash` needs `hash()` (L6) before handoff.

**Audit sealing and outbox.** `sealAuditBatch`'s first attempt stamped `batchId` on 1,000 events → **`E_CONSTRAINT`** (*`accessEvents` is `appendOnly`. Rewrite: write the batch as a range row*): `auditBatches(fromEventId, toEventId, rootHash)` from a system schedule over `scan(accessEvents.byOrgAt, take 1000)`; the root hash needs L6, signing is an effect.

### 6. Language delta

Ranked by how wrong the answer is without the item, then by operations unblocked.

1. **L1 — `partitioned()` and the cardinality channel.** *What:* under §9.1.2 page length and `hasMore` are functions of hidden-row counts; invariant 6 fails for every chart list and the SSN token index is a one-bit oracle. *Smallest addition:* a table-level `partitioned()` under which (a) `check` refuses any scan whose read rule is not hoisted for its prefix — `E_NONUNIFORM_SCAN`; rewrite: put the varying column in the prefix or split the table — and (b) a hoisted-false rule short-circuits to an empty, exhausted page examining nothing, so work stays independent of hidden counts. *General.* Amends §2, §3, §9, §9.1.2–3.
2. **L2 — `audited(into)`.** *What:* a `query` cannot write, so invariant 12 forces 14 reads into mutations that are neither live nor retained, and nothing makes a read audit itself. *Smallest addition:* `table.audited(accessEvents)` — every delivery of a row from the table (initial result, subscription delta, mutation return) is preceded, in the same transaction and before serialization, by an engine-written append-only row whose manifest is the closure receipt's version list plus rule-probe ids, values excluded; a failed delivery over-audits. L2b: a local read of a retained audited row becomes an outbox intent on a device-ledger table, replayed first on reconnect. *General.* Amends §1, §5 (`auditSites`), §6. Cost: every audited delivery is a write transaction; at 3,000/s the single writer is the bound (§8 #2).
3. **§9.1.8 correction — uniform is not tautologous.** *What:* the proof admits a reduction over a scan whose rule inputs are pinned; when the hoisted verdict is *false* it runs over an empty page and writes 0 as a resource fact (the deadline; the cancellation). *Smallest addition:* when a reduction or set write over a scan is stored or returned as a resource fact and the hoisted verdict is false at run time, refuse `E_STRUCTURAL_COUNT` (sealed) instead of computing; the rewrite is unchanged (system schedule, or maintained aggregate with `readable`). *General.* Amends §9.1.8.
4. **L3 — `versioned({ history, revision })`.** *What:* invariant 16 binds by discipline. *Smallest addition:* the engine appends the preimage as a history row on every update or delete, unfiltered; programs never copy forward. *General.* Amends §2.
5. **L4 — `hold()` constraint** and **L5 — rule-side interval probe.** *What:* hold-fenced deletion is a `require` in one system mutation, and no rule can say "no active scope overlaps this row". *Smallest addition:* `hold(table, { scopes, probes, match, active })` refusing `delete`/`update` of matched rows (probes `cap`-bounded, system visibility, sealed); and `db.exists(index, key, { overlapping: row.clinical })` as a rule primitive (wave-1 #25). *General.* Amends §2, §3, §4.2.
6. **L6 — `hash(value)`** total builtin (canonical JSON or text → hex). *What:* manifest, content, and root hashes must commit before handoff; the subset cannot compute one. *General.* Amends §4.1.
7. **L7 — `callable: 'system'` and `predict: false`** on mutations (wave-1 #3). *What:* effect-invoked mutations are client-callable by default, and audited reads are "predicted" into meaningless local rows. *General.* Amends §1, §4.3, §7.
8. **L8 — per-table `retain`** (`'never' | { maxAgeMs }`), separate from the read rule (wave-1 #34). *What:* the eight-hour packet with excluded classes. *General.* Amends §6.
9. **L9 — clarifications.** (a) rule probes may take keys from probed rows; (b) `bytes({ max })` and `list(t, { max })`; (c) a schedule's system principal reads unfiltered — §7's "read elevation is never needed" is false for retention; (d) two schedules per row and an `if` guard; (e) interval `contains`/`overlaps` in programs; (f) `row[f]` for `f` from a bounded literal list.

Not needed: `channel`, `exclusion`, `tree`, `recurse`, `readTime`, a `job` kind, and a column-level rule — refuted: the split is stronger because the hidden column's index lives behind the hidden table's rule.

### 7. Product changes

| product change | what it dodges | acceptable when | a cheat when |
|---|---|---|---|
| ten fixed protection-class tables instead of per-column policy rows and per-version labels | column rules; label-driven masking | the design's own §7 concession: the matrix is stable | a policy cell names a column the schema does not partition |

Boundary as the ledger states it: legitimate when the simpler product is wanted for itself, a cheat when adopted to protect the backend while still claiming the invariant.

### 8. Where the design is wrong

1. **One revision chain per item contradicts invariant 15 and op 7.** `chart_version(item_id, revision_no)` is unique per item, payloads are full snapshots, and `changed_columns`/`parent_version_id` sit on the spine, so a nurse's phone edit after registration's SSN change must cite a parent she cannot read or collide on `(item, revision)`; either way she learns hidden activity. *Confirming observation:* registration commits revision 185 (SSN) while a nurse holds 184; her phone edit's `parent_version_id` names 185, or the write is refused as a conflict. Fix: a chain and head per protection class (§2).
2. **Commit-before-disclose at 3,000 responses/s is unstated as a storage requirement.** Op 4 makes snapshot, versions, manifest, and audit *atomic*; §6 proposes partitioned audit storage, but the audit row and the read snapshot share one transaction, so the audit store cannot be partitioned independently of the chart store — the missing sentence is "shard the chart by patient". *Confirming observation:* 3,000 audited reads/s against one single-writer store; commit rate, not read cost, is the ceiling **[inferred]**.
3. **Revocation cannot find what it must cancel, and break glass cannot find its shift.** `disclosure_job` has no consent key (consent basis is an op-12 *input*), so op 3's "cancel disclosure jobs whose handoff has not begun" has no join; invariant 14's "shift end" names a fact no table carries. *Confirming observation:* revoke consent C with a job queued under C; op 3 cancels nothing. Fix: `consentRevisionId` on the job; a `shifts` table or the §7 concession.
