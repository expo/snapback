## Findings

No introduced defect that breaks the B1b authority, selection, or logout contract.

### Test gaps (not product defects)

1. **Logout vs replacement is committed-order, not concurrent.** `bound_session.rs` 242–273 opens a second `Store` and runs logout-first then replace-first. That is enough to show the helpers do not depend on the HTTP engine mutex, and both sides use `BEGIN IMMEDIATE`. Concurrent replacement is tested at 206–222. Concurrent logout-vs-replace is not. SQLite writer locking should serialize the same invariants; this is a coverage gap, not a missing check-then-act split (logout SELECT+DELETE and mint `family_is_live`+mutate are each inside one immediate tx).

2. **HTTP does not cover live bound logout then replace.** `serve_tests.rs` 282–287 only logs out the stale pre-replacement bearer. Live family close → replace refusal is covered on the helper (`bound_session.rs` 256–259). The HTTP route is a thin call to `logout_session`.

3. **Tombstone “logout” still uses `close_session`.** `bound_session.rs` 130. That is the exact-digest helper (one token). HTTP/public logout is `logout_session`. Family-level logout is covered by the two-connection test, not by that loop.

### Pre-existing limitations (not introduced here)

- **`rotate_session` still selects the live row outside its write tx** (`identity.rs` 236–253). Refresh remains compatible with family recovery; the refresh TOCTOU shape is unchanged.
- **Legacy `/auth/session` still does not recheck the service bearer inside an IMMEDIATE tx** (`serve.rs` 1144–1146). Bound mode does (`identity.rs` 623–629). Unbound mint already required a live service credential; this slice does not claim to close that older window.
- **`kind: "action"` is still a valid custom kind** (`identity.rs` 551–560). `resolve` / `logout_session` then demand `live_claim_authority`. Bound mint inherits that footgun; OIDC-style kinds (`member`, `account`) are unaffected.
- **Protected-result contents are not enforced.** Guide/ops text require the handler to return the delivered `Session`. Core does not check `/done` payload against the binding. Correct for B1b (no complete OIDC integration).

## What is actually tight

**Selection.** `has_lease || has_binding` is the only bound trigger (`serve.rs` 467–469). Lease without `binding` fails `BoundSessionWire` (400, no row: `serve_tests.rs` 220–225). Binding without a single nonempty lease is `E_ACTION_LEASE` (200). Empty/duplicate lease headers take that path (`serve.rs` 488–490; `serve_tests.rs` 255–258). Missing both keeps `kind`/`days` coercions. Bound optionals use the same defaults via serde (`serve.rs` 440–464) and the same 1–3650 clamp in `new_session` (`identity.rs` 137).

**Mint transaction.** After `validate_custom_session` and intent/`invocationId` checks, one immediate tx: live service digest+principal+kind+expiry (`identity.rs` 623–629), `held_claim_authority` (claim id, worker, lease digest, `state='running'`, `lease_until`/`deadline`, `authority_expiry` chain including cancel/park via non-`running`), then create or recover. Ordinary replay is `E_INPUT`. Replace refuses changed inputs, expired binding, generation mismatch, or dead family, and never deletes the binding row.

**Logout.** Outer `principal_of` was removed for `/auth/logout` (`serve.rs` 804–806) so liveness is not decided before the writer tx. `logout_session` re-reads `expires_at > now`, applies action-kind `live_claim_authority`, then `DELETE` by principal+family (`identity.rs` 209–225). Auth failures map to 401 only for this path (`auth.rs` 137–140). Stale bearer cannot close a replacement (`bound_session.rs` 267–269; `serve_tests.rs` 282–287).

**OIDC classifier.** Exact ten literals; default remains `Failed` → public `E_ACTION_FAILED`. `diag.rs` 167 and `guide/codes.rs` 63–72 match that closed list. Prefix matching is not used, so `E_OIDC_UNKNOWN` cannot leak.

**Route registry.** The 1 ms wait/503 sync is gone. The live socket stays on a 2 s route wait, `wait_until(|| records == 2)` (`serve_routes/mod.rs` 254), then claim-set, settle by real id, observe 204. Product behavior unchanged.

## Risks / limits

- **Caller-supplied `now` is sampled before the engine mutex** (`serve.rs` 1137–1140). Rechecks use that timestamp. A long mutex wait could theoretically mint against a just-expired lease. Typical waits are far below claim leases (seconds); still slightly looser than sampling `now` after lock acquire, still inside the tx.
- **`wait_until` deadline is 2 s** (`serve_tests.rs` 124–129), equal to the route wait. Admission should happen at ingress, well before that. Residual flake if durable route admission is delayed until the wait bound.
- **No Postgres / production-PG claim**, no Google/OIDC protocol, no `contract.ts` helper that forces bound mode. Unbound `POST /auth/session` remains a live service privilege, as before.
