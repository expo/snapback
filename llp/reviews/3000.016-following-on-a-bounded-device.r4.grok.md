## 1. Revision-3 findings

**Fixed — High, §2.2. The old fallback (both families).** §2.2 no longer points at the existing client. A withheld query is exactly `{ loading: true }` with no `data` and no `next`, routed before the loading and server-run shortcuts: offline, or any outbox entry with `predictable && observed_seq == null`, stays that result; otherwise the server is called with the original arguments, and a transport failure stays loading. The local-commit fence in `local-reads.ts` stays.

Probe. Shape `following last 20 { *, card: posts[.post] }` at cursor C. Row 3 is a repost whose original is outside the posts floor, and an own post is predicted (`admit` leaves `predictable: true` only when prediction writes rows; a repost that queues clears it). Offline, online before acknowledgement, and acknowledged but `observed_seq == null` must all stay loading. None may publish the twenty local rows, the null card, or the server page. With no such outbox entry, the server retry uses C. Repeat with 1,020 inbox copies, floor 1,000, every card held, requesting 40 after the newest 980: the same three phases, not a 20-row local page. This has to be decided before `local.ts` sends a `loading` result to the server, which today happens above the `pending()` check.

**Fixed — Medium, §2.2. Meter cuts versus missing coverage (Astra).** A full page whose last key is still on the floor stays data, and its `next` may leave the floor. An examined-meter stop above the floor is a known prefix: partial data, continuation, `complete: false`. Heap and scalar exhaustion stay unavailable. Coverage uses the cut, not the nominal range.

Probe. Hold the newest 1,000 copies, request 40, and stop the examined meter after ten candidates still above the floor. Publish that prefix. Do not publish loading. Separately, exhaust the heap: loading, no data. A full page sitting on the floor is data; the next request is the one withheld.

**Fixed — Medium, §4. Derived floor on owned events (both).** Increment 1 no longer says to build it. `@T@Posts` stays `sync public` for every source residency.

Probe. Posts horizon N=1. Original P at time 10, a repost event at time 20. Both owned-event rows are acquired. Reposting P hits the post and `byActorPost` and can predict when the reposts absence proof allows it. A reply that is inside the posts floor but was excluded by the originals filter, or a removed original whose event row is gone, still refuses `FEED_POST_NOT_FOUND`. It must not queue. `get_inner` records a horizon miss only when that table has a horizon.

**Fixed — Medium, §2.3. Edge classification (Grok).** Post, event, and tombstone inputs follow those tables' sync. Follow and unfollow stay server sites even though `Work` is synced.

Probe. `check` on follow and unfollow still says `predicts: never`. The runtime still queues with no row (`predict` rejects an edge write before the transition). ## 2. No new defect

**Withheld page.** Offline stays loading. Online with a predicted own post, including after acknowledgement but before `observed_seq` is set, stays loading. Online with nothing predictable in the outbox retries the original arguments. A repost that failed prediction has `predictable: false`, so it does not block; a repost that did predict does, because the predicate is the flag, not the operation name. The paved home query takes a cursor, and the scan filter contains `exists`, so it is not a composed query. The merge path in `local.ts` does not apply. A by-id card miss stays undecidable. There is no time key to compare with the floor. A known null on a fully synced source stays a null card.

**Owned events.** Full sync is what makes a missing `byActorPost` row a refusal. The design no longer removes that.

**Inbox floor.** `Feed` syncs to `readerId`, and `byReaderPage` is the Following scan index, so a descending page can be known. `last 1000` is one merged suffix per reader, newest first, fixed at acquisition, with no eviction. That is what `group_rows_from` and `boundary.accept` already do. A short page that still needs copies older than a key floor is withheld whole. A group smaller than M is `whole` and is data. A full page on the floor is data. Pending backfill stays `complete: false` data, not loading.

**Repost prediction.** Necessary conditions are the post, the original event, and the tombstone, plus the existing `insert … if absent` proof. `upsert_absence` rejects every horizon, so a horizoned `reposts` table queues even when its floor is `whole`. `check` already says so. An own post is a plain insert, so a posts horizon does not block it. `online only` is a server site, so it does not predict.

**Adoption.** A sync edit, including a changed N, is `RuleChange` in `successor.rs`. The device clears boundaries and will not serve the old partition until the replacement snapshot finishes. `same_declaration` ignores source sync, so server event ids, edge epochs, and work survive. Narrowing a horizon in place would be the bug, because a point hit never consults the floor. §2.4 forbids that.

`online only` shaped pages are `runs: server`, so they never take the withheld router. That matches §2.2. There is no local null card and no predicted post to clobber. A live subscription already resolves offline to loading.
