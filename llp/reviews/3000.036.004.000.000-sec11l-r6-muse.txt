**Checked, each holds:**

- **Lifecycle**: `memory()`/open/`successor` get `None` — ordinary runtime stores byte-identical behavior. `fork_memory` shares the Arc but copies every on-disk file, so materialized/uncached/staged files stay per-world; `Drop` still removes the ephemeral dir. COW via `Arc::make_mut` on fork means a new upload clones only the sharer's map — the per-world `bytes` counter stays exact at fork and conservative after (sweeps never decrement, which fails safe toward ordinary copies).
- **Grant/placement/release/GC**: `materialize` is reachable only post-auth; denied/released/forgotten rows return `E_ASSET_UNKNOWN` before it. Sweep removes only the world's own directory files and forgets only its own ledger rows; stale cache bytes are unreachable without a ledger row, and id reuse is barred (`E_WRITE_ID_REUSE`, fresh mints).
- **Error fallback**: `capture` builds locally and installs atomically; any over-limit/non-file/non-UTF8/read error returns `Err`, the fork is dropped, and `fixture_observers` (`.ok().flatten()`) runs the original ordinary fixture — coverage and search work unchanged. `retain` swallows failures silently, leaving the ordinary file in place. Failure/success boundary is readdir-order-independent (it reduces to total > LIMIT).
- **Fork isolation**: cross-world new-upload and sweep tests assert the right directions, including descendant-of-materialized-world inheriting that world's file — consistent with "materialized files are world state."
