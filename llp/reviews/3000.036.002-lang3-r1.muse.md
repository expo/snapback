[Proof walk](//home/ccheever/projects/sb4-w14-lang3/snapback4/crates/snapback4-core/src/engine/rules/snapshots.rs:30) keeps `path` and `snapshots` across `Assign` unchanged. `Let`/`Const` capture checks global `singles`/`inputs`, but later `Assign` to the same runtime name falls into the catch-all arm at [line 62](//home/ccheever/projects/sb4-w14-lang3/snapback4/crates/snapback4-core/src/engine/rules/snapshots.rs:62), which marks scans only. It never drops path facts or snapshots.

[Pin use](//home/ccheever/projects/sb4-w14-lang3/snapback4/crates/snapback4-core/src/engine/rules/snapshots.rs:82) also takes `scan_pinned` verbatim. Sibling code filters pins to literal/viewer/unrebound args at [grant pins](//home/ccheever/projects/sb4-w14-lang3/snapback4/crates/snapback4-core/src/engine/rules.rs:242). The new proof has no such filter.

Local rebinding is legal per [rebinding](//home/ccheever/projects/sb4-w14-lang3/snapback4/crates/snapback4-lang/src/bind/program/control.rs:129). So this is reachable with locals only. No arg rebinding needed.

  t = y
  require t = viewer else NO  # path atom: t = viewer

Static view: `compare(Variable(t), Viewer)` in path equals the goal atom for `.teacher = viewer`. `entails` succeeds. The scan site enters `snapshot_decided`, so [read](//home/ccheever/projects/sb4-w14-lang3/snapback4/crates/snapback4-core/src/engine/read.rs:1239) marks it `always_visible` and [bind](//home/ccheever/projects/sb4-w14-lang3/snapback4/crates/snapback4-lang/src/bind/mod.rs:847) skips the completeness note.
