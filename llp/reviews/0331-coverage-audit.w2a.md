# Authorization coverage audit — Wave 2, first half (BI, game, health, payments)

Slice: LLP 0329.014.002 wave 2, apps 7 (BI), 5 (turn-based game), 4 (health records), 1 (payments).
Tested against: LLP 0331 §"Snapback2 synthesis" core (lines 104–420). Extension codes: the fixed X1–X20 list in the brief.

## Conventions used in this report

- **CORE** — table rule per effect over row fields / `viewer` / literals with `==`, `!=`, comparisons, `&&`, `||`, `!`, `public(reason)`, plus at most one-hop `exists` probes whose key terms are row fields, viewer, or literals. Several *independent* one-hop probes composed with `&&`/`||` in one rule are counted CORE (0331 L117: "Explicit role sets / boolean composition"); a probe whose key needs a *found* row's field is not.
- **CORE(where)** — one-hop probe with a `where` on the found row (relationship row or plain data row).
- **CORE(neg)** — negated one-hop probe.
- **CORE-with-denorm** — the paper rule chains 2+ `get`s; fixed by copying an immutable scope id onto the row.
- **X6 sub-kinds**, because the brief's X6 spans three different things: **X6(state)** = time-bounded authority lowered to a schedule-flipped status column (the rule text is `state == 'active'`, which is core; the extension is the schedule kind); **X6(interval)** = interval containment/overlap between a found row and the subject row inside a rule; **X6(arith)** = arithmetic (`old.n + 1`) inside a rule.
- **X11 sub-kinds**: **X11(a)** = a viewer-invoked named mutation reading rows the viewer cannot read (`getHidden`); **X11(b)** = `callable: 'system'` — a mutation only the runtime/effect may invoke; **X11(c)** = a schedule running under the system principal and reading rows no viewer can read.
- Line references are `file:line` in the artifacts' own numbering (`llp/reviews/...`). Quoted `||` is written `∨` inside tables to keep the markdown intact.

### App verdict — **NEEDS: X16, X3, X11(c)** (X4, X6(state) droppable)

Authorization was incidental; the app's hard problems were unbounded aggregation, disclosure cadence, and the export boundary (synthesis:119). Every relationship rule the v0 wrote is one hop. The one design-stated item 0331 cannot express is the grant-as-predicate-tree (X16), and the v0 itself declared the reduction a legitimate product change — so the app is COVERED-WITH-DENORM *as the v0 shipped it*. X3 is load-bearing but sits in the identity kernel (SDK source credentials, the OLAP replica), not the rule language. The v0 reached for an int-rank role lattice (v0:53), which 0331 explicitly refuses (L323–325 "no role hierarchy ... explicit set"); the design did not require it. Nothing here was refuted by RFC §8.

### Sprawl check

- **X16** — droppable. The v0's equality-grant product is honest (v0:262) and loses only predicate-shaped scopes; the design's own trap 2 (design:93–97) is about *filtering*, not about predicate grants.
- **X3** — load-bearing. Promise 1 (design:7, retryable SDK batches under a source credential) and protected mode in the replica (design:19) cannot run under human sessions. The rule stays core; what is needed is a principal minted from a service credential.
- **X11(c)** — load-bearing for scheduled exports (design:221) and erasure purge (design:224); a kind, not a rule construct.
- **X4** — droppable: require sign-in to download; loses non-account email recipients (design:29 already says "authenticated").
- **X6(state)** — droppable: manual revocation only; loses `valid_to` auto-expiry (no stated promise depends on it in BI).

### Sprawl check

- **X16** — droppable with a stated loss: the matrix becomes a code change with two approvers instead of a data change with two approvers (promise 13 still holds as versioned rules). Load-bearing only if orgs must edit policy without a deploy.
- **X1(viewer-pinned)** — needed only with X16; otherwise the active role is a literal per disjunct. The smallest bounded form: one `get` keyed by `[viewer]` alone, hoisted once per program, whose fields may key further probes.
- **X6(interval)** — load-bearing for promise 5 (record-coverage interval) and I22–23 (hold overlap) *if* bound as rules. The minimal extension is letting a `where` compare found-row bounds to a subject-row field.
- **X11(b,c)** — load-bearing: retention/destruction (design:201), disposition recompute, consent activation from a signature effect. Kind-level, not rule-level.
- **X9** — droppable: bind the device at episode start (v0's caller-asserted column) and give each device its own session so device revocation is session revocation; loses runtime posture gating ("compliant") as a rule input.
- **X10** — droppable to "restricted data online-only" (design:242's own concession); loses the offline packet's local ledger guarantee.
- **X6(arith)** — droppable (program check or monotone constraint).
