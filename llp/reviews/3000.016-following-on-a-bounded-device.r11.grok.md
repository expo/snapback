## 2. New defect

**High — §2.1a Activation. The repost slot's absent value is null, and an optional column does not force the device to drop its images.**

A repost slot holds an event id or null. A required column cannot store null (`validate_row` rejects it). So that slot is optional. `materialize_optional_fields` turns a missing optional into null, and null is event absence.

`keeps_literal_default_images` returns false for an optional-only diff, because it returns whether a required literal default was added. It returns true as soon as the same generation also adds any required literal default, on any table. `adopt` then keeps every row and sets `ACQUIRED` (`device.rs`). `require_acquired` does not run.

The other branch, "required and activation-derived the way a maintained column is," is the `maintained` arm in `successor.rs`. A missing maintained field reads as integer 0 (`validate.rs`, `materialize_optional_fields`). That is event absence, and it is the wrong type for a bool or an id. `birth_columns` also overwrites a private maintained column on insert.

**Scenario.** Posts are fully synced and already populated. This generation adds the event slots as optional columns and `pinned: bool default false`. Adopt. Before the re-snapshot page for post P arrives, the device still holds P with no slot. A repost of P materializes null and refuses `FEED_POST_NOT_FOUND`. The server accepts.

**Smallest change.** In §2.1a, pick one shape:

- The post slot is a required bool with no default. False means "filled and not live." Missing is not false, and it is not a maintained column.
- The repost slot is an optional id. Null means "filled and no event."
- Any diff that adds either slot makes `keeps_literal_default_images` false, including when that diff also adds a literal default. `adopt` clears source images and `ACQUIRED`.
