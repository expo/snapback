## Verbatim review

NOT READY — the core R1/R2 mechanism is sound for the cases modeled, but the design has one disclosure hardening gap, two retention races, a B1 regression, and simulator gaps that miss the hazards it claims to cover.

1. (High) §4.3 — R2 trusts an unauthenticated trailing principal. The scope's extra element `[team, "dev:alice"]` tells the device whose column-arm rows to keep. Nothing requires the device to check the trailing principal equals itself. A mismatched value (buggy server, replay across principals) makes the device keep rows naming someone else after leaving the group: rows it can no longer read, served by no-window pages as `complete`. Code today rejects length mismatch (`device.rs:1268-1274`); the new parser must strip the last element **and** fail closed on mismatch (treat as a plain scope, drop all). State this in §4.3.
2. (High) §4.3 — R2 reads the wrong image under predictions. `leave`/`scope_group` scan the device store, but a predicted owner-change overlays the committed image (`is_provisional`, `provisional_readable` in `engine/read.rs:299`; overlay bases in `device/snapshot.rs:28`). Interleaving: Alice predicts giving row R to Bob, leaves team 1, prediction is rejected. R2 sees overlay owner Bob, drops R; settlement restores the committed Alice-owned image with no further event, so R is lost while readable via the column arm. Require R2 to read committed images only and re-resolve kept rows on prediction settlement (§9 must gain this).
3. (High) §6 — the blocking suite cannot reach group-group H1. It needs create + join-team-2 + move-team (3 writes); Alice is seeded only in team 1 and blocking depth is 2. The naive implementation passes the blocking suite on exactly the hazard R1 is scoped to fix in §4.2 (mutable group-column move between two held groups). Seed Alice in both teams or promote a targeted 3-deep group-move regression into the blocking suite.
4. (High) §6 — no owner-or-roster world, although §1 lists it and §2.1 gives it a colliding spelling (prints as inferred `sync`). Empty-group scopes match every staged row (`columns` empty, `all()` true in `device/snapshot.rs:108`), R2-on-roster-leave and the `union-audience` fence for a schema that prints as plain `sync` are all untested. Add the roster-union exhaustive world.
5. (High) §2.1 — exact-agreement silently kills parent B1 narrowed sync. `sync to .owner` on an owner-or-team rule was admissible under LLP 3000.036 §1 B1 (rest server-class); here it is refused as inexact, forcing full union or `online only`. Either preserve explicit single-whole-disjunct sync with B1 completeness, or justify the removal and its migration cost. Currently §2.2 is silent on it.
6. (Medium) §4.3/§4.5 — same-commit content+membership order is load-bearing but unpinned. R2's "held image is enough" within one commit depends on content puts sorting before membership scopes in `(seq, ord)`, which today is incidental source order in `account_row_change` (content events `partition.rs:232-249` before dependent scopes `:276+`). Pin put-before-scope as an invariant in §4.5 and add a same-commit combined write (owner-move + team-move; content-move + leave) to §6, whose writes are all single-table commits.
7. (Medium) §4.2 — R1's trigger and cost are unspecified. The existing conversion fires only for field-owner tables (`partition.rs:958`); union R1 must fire on union tables without field owners, project for the recipient exactly like a `put` (`project_fields(row, Some(principal))`), and charge the same meter. Converted puts that skip meter parity are a divergence from every `put` the device may hold. Specify all three in §4.2.
8. (Medium) §5.3 — probe/count generalization drops existing guards and tests. `authorization_absence_covered` (`engine/read_auth.rs:90-110`) currently checks `DeliveredHistory` currency and witness coverage with expiry awareness; the "some arm" rule must carry those per arm, not just pinning. §6's device queries (`myTasks`, `teamTasks`, `task(id)`) omit counts and `exists`-probes, the exact sites §5.3 sends down `unknown_fact`. Add both queries to §6.
9. (Medium) §6 — the two-parties world cannot fail naive, contradicting "must fail (H1 and H2)". Two column arms dedup to one `p:` partition via the `BTreeSet` in `account_row_change` (`partition.rs:201-202`), so same-viewer column moves log no `del` and naive holds correctly. Reframe that world as a disclosure/exactness guard and add the windowed two-column pass, since §5 per-arm windows are otherwise untested for column-column unions.
10. (Low) §9 — "converge to the same rows from every watermark" needs a fixed `now`. R1 images are serve-time state, so replays at different heads legitimately differ; require the sim to serve all watermarks at one head time. Also: §7 omits `search_plan`/word scans — confirm they take the §5.3 `unknown_fact` path rather than arm certification.

Checked and sound: per-arm logging with whole-rule serve-time re-check (`group_rows_from` per-row check at `partition.rs:660`; put re-check at `:994`); no union partition; column-column moves never producing H1 by set semantics; within-commit put-then-del ordering making R1 converge to the current image; trailing-principal scopes confined to the viewer's own `p:` partition; the `union-audience` capability failing closed instead of silently holding one arm; refusing nullable column arms (which would log to no partition), named window indexes, two group arms (colliding `g:` names), public arms, read-through, aggregates/row-views, timelines, and field owners — each exclusion is needed, with §8.8 correctly conservative.
