### Independent finding

**1. High — helpers still compile `! else`, hiding caller denial**

- **Where:** `snapback2/packages/compiler/src/quarry/bound.ts:338-346` (assert binds with no `helperDepth` check). Contrast writes at `:388-389` and `new`/`commit` at `:526-534`. Lowering emits `Require` at `snapback2/packages/compiler/src/quarry/direct.ts:92-99`.
- **Trigger:** A reachable helper such as

```q
fn mustMember(c: conversations, p: principal) = memberships[c, p]! else NOT_MEMBER
query view(c: conversations):
  return mustMember(c, viewer)
```

  binds, expands into the caller, and denies with `NOT_MEMBER` without a caller `require … else CODE`.
- **Why it matters.** LLP 1018.000 §7 forbids `require` and `! else` inside helpers and keeps denial at the call site (`require isMember(...) else MEMBERSHIP_REQUIRED`). Shipped chat helpers only use `exists`/bounded reads, so the hole is unused there, but it is a production compiler path: helper expansion can inject authorization and collapse public refusal identity.
- **Fix.** In `expression()` for `assert`, if `helperDepth > 0` refuse the same way writes are refused (`E_QUARRY_UNSUPPORTED`, authored helper site + use site). Add a direct compiler case that this helper is refused and that `require isMember(...) else CODE` still compiles.
