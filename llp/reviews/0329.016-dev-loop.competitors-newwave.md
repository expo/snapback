# The new-wave backends and sync engines, as an AI agent experiences them

Research for "Snapback 2: the ideal agentic dev loop, designed from scratch." Date: 2026-08-29. Question asked of every product: **what makes its developer loop good or bad for an AI agent building an app end-to-end?**

**Method and caveats.** Primary sources (official docs, changelogs, blog posts, GitHub READMEs/issues, HN) fetched directly; ten product clusters were researched in parallel, and the full per-product notes (with every claim tagged) live in `parts/*.md` next to this file. Tags: **[v]** = verified against the cited URL; **[inferred]** = my reading of the evidence. The session's web-search budget ran out mid-way; later evidence is direct fetches of known URLs, so some "not found" claims are absence-of-evidence, not proof. Several vendors renamed things this year (Neon → Lakebase Postgres; Electric joined Neon/Databricks 2026-08-11; Databutton → riff.ai; Turso Database vs libSQL); I use the names an agent would meet in the docs today.

**The one-paragraph answer.** Every serious product in this wave has converged on the same six agent-facing mechanisms in the last 18 months: a `.md` mirror of every docs page behind `llms.txt`; an MCP server; Agent-Skills folders (often bundled as a "plugin" with the MCP config); a rules file the scaffold writes into `AGENTS.md`/`CLAUDE.md`; a one-shot, non-interactive, `--json` CLI; and cheap isolated copies of the backend (branch/namespace/temporary app) with a TTL. What separates them is *how loud failures are*, *how many processes and prerequisites stand between `create` and a running app*, and *whether the write path and the permission model are the platform's problem or the agent's*. The app-builders' scar tissue (Lovable's CVE-2025-48757, Supabase's lethal-trifecta MCP incident) points at the same thing from the other side: the default must be safe, and the verification surface must be machine-readable.

## 1. Product by product

### Zero (Rocicorp) — zero.rocicorp.dev (1.9.0, GA March 2026)

**Loop.** Postgres with `wal_level=logical` (docker run …) → `npm i @rocicorp/zero` (plus a native-build trap: pnpm/bun/yarn skip `@rocicorp/zero-sqlite3`'s postinstall unless you `rebuild`/`trust` it) → hand-write or generate `schema.ts` (`drizzle-zero generate`, `prisma-zero`) → `queries.ts` (`defineQuery` with a Zod validator because "parameters from clients are untrusted") → `mutators.ts` (`defineMutator`, same file runs on client and server; `tx.location`) → two HTTP endpoints on *your* server (`handleQueryRequest`, `handleMutateRequest` + `zeroNodePg`) → `npx zero-cache-dev` on :4848 with `ZERO_QUERY_URL`/`ZERO_MUTATE_URL`. Four processes; the tutorial restarts zero-cache twice as env vars are added. `zero-cache-dev` hot-reloads only a deprecated permissions file. Types flow from `schema.ts` via `DefaultTypes` module augmentation (no generics needed since 0.25), but Postgres DDL remains a second source of truth ("schema.ts must be a subset of the server-side schema"); new columns are invisible until a background backfill finishes. [v: https://zero.rocicorp.dev/docs/install, /docs/tutorial, /docs/schema, https://raw.githubusercontent.com/rocicorp/mono/main/packages/zero/src/zero-cache-dev.ts]

**Feedback.** Every read returns `[rows, {type:'complete'|'unknown'|'error'}]`; every write returns `{client, server}` promises that always resolve to `{type:'ok'|'error'}`. Permission denial has no error class: reads "return a query matching no rows or throw"; an endpoint 401/403 flips the whole connection to `needs-auth` and rejects all writes until a manual reconnect. Browser `__zero.inspector` and a `runAnalyzeCLI` return plans, row counts and `TEMP B-TREE` warnings as data; OTel metrics (1.8/1.9); Cloud dashboard shows backfill/replication. [v: https://zero.rocicorp.dev/docs/queries, /docs/mutators, /docs/connection, /docs/debug/inspector, /docs/debug/analyze-query-cli]

**Agent investments.** Hand-written "Key mental models" preamble in `llms.txt` that encodes the footguns (mutators run more than once, results immutable, manual reconnect after auth error); `/docs/{slug}.md` for every page; a footer pointer on every HTML page. `rocicorp/zero-skills` = three *migration* SKILL.md files with an "all query inputs are untrusted; root table must always have a permission check" rule. No MCP server, no rules file, no scaffolder (clone `hello-zero`). The strongest investment is sandboxing: `rocicorp/devcontainer-templates` — "the dev container is the sandbox for development and AI-agent work, so it must not be able to create or control containers"; Postgres is a sibling service; pinned Codex/Claude Code preinstalled. Cloud Zero is invite-only. [v: https://zero.rocicorp.dev/llms.txt, /docs/agents, https://github.com/rocicorp/zero-skills, https://github.com/rocicorp/devcontainer-templates, /docs/cloud-zero.md]

**Test / deploy / offline.** No testing docs; mutators/queries are plain functions callable under `dbProvider.transaction`. Deploy = `rocicorp/zero` image, persistent SSD, replication slot, sticky WebSockets, `ZERO_ADMIN_PASSWORD`; **not scale-to-zero** (slot + hydrated pipelines; Neon bills while idle). "Zero is not local-first"; offline writes were *removed* in Q4 2025 — "we want to educate people how to properly handle conflicts before we do." [v: https://zero.rocicorp.dev/docs/self-host, /docs/offline, https://news.ycombinator.com/item?id=43397640]

**Thesis / pain.** "Queries as the API": named queries run optimistically on the client and authoritatively on the server, where the server "can add extra filters to enforce permissions" — auth is ordinary code, not a rules language; 0.25 deprecated declarative RLS, CRUD mutators and ad-hoc client queries. Pain (from their own docs): auth-state cliff; no column defaults from Zero; no aggregates/count/JSON filters/text search/SSR; provider-dependent DDL detection (full reset on Supabase < 15.8, Fly, Render); 718 KB client. [v: https://zero.rocicorp.dev/docs/sync, /docs/release-notes/0.25, /docs/postgres-support, /docs/connecting-to-postgres, https://marmelab.com/blog/2025/02/28/zero-sync-engine.html]

### ElectricSQL + TanStack DB — electric.ax / tanstack.com/db (Electric 1.7.x, TanStack DB 0.8.x)

**Status first.** 2026-08-11: Electric joined Neon at Databricks; OSS stays Apache-2.0; **Electric Cloud is winding down**, so the 30-second on-ramp (`npx @electric-sql/start` → temporary Neon + Cloud source → `pnpm claim`) is effectively dead; self-host is the durable path. The repo tagline is now "the agent platform built on sync" (Durable Streams, StreamDB, Electric Agents). [v: https://electric.ax/blog/2026/08/11/electric-joining-databricks, https://github.com/electric-sql/electric]

**Loop (self-host golden path from their `AGENTS.md`).** `npx gitpick electric-sql/electric/tree/main/examples/tanstack-db-web-starter` → `pnpm backend:up` (compose: Postgres + Electric) → `pnpm migrate` (Drizzle) → `pnpm dev` (Caddy for HTTP/2, `caddy trust`). Prerequisites before one row syncs: `wal_level=logical`, a REPLICATION role, `GRANT CREATE ON DATABASE`, table ownership (or `ELECTRIC_MANUAL_TABLE_PUBLISHING`), `REPLICA IDENTITY FULL` per table, and `ELECTRIC_SECRET` or `ELECTRIC_INSECURE=true` (boot crashes otherwise). Concepts: a **shape** = one table + `where` + `columns` (no joins, immutable once subscribed; schema change purges shapes → clients `must-refetch`), served as an HTTP log (`GET /v1/shape?table=&offset=-1` → `up-to-date` → `live=true` long-poll; `409` = handle rotated) that CDNs can fan out. Auth is always a proxy you write (`/api/todos` copies only protocol params, sets `where="user_id = $1"` server-side). Writes: TanStack DB `onInsert/onUpdate/onDelete` handlers must persist and return `{txid}` taken from `pg_current_xact_id()` **inside the same transaction**; `awaitTxId` drops optimistic state when that txid appears in the shape log — a wrong txid stalls silently until "Timeout waiting for txId". Adding a table = six files in order. Types: Drizzle → drizzle-zod → collection `schema` (validates mutations) plus a separate `parser` for the sync path (Electric ships strings) — two un-reconciled type paths, no generator. [v: https://electric.ax/AGENTS.md, /docs/sync/guides/postgres-permissions, /docs/sync/guides/shapes, /docs/sync/api/http, https://tanstack.com/db/latest/docs/collections/electric-collection, https://github.com/electric-sql/electric/issues/3970]

**Feedback.** Machine-readable wire errors (409/414/503, `/v1/health` 202 during upgrades), `onError` (returning `undefined` stops the stream permanently — documented gotcha), `MissingHeadersError` when a proxy strips `electric-*` headers, "Detected possible fast loop" when a cache key omits `handle`, `localStorage.debug='ts/db:electric'`, collection `status` states, Prometheus slot metrics. The recurring bad surface is **silent success**: persisted collections coming up "ready, empty, and silent" (15-issue cluster), `TRUNCATE` silently unpublishing a table so later writes are lost while the shape says `up-to-date` (found by Claude, open 2026-08-25). [v: https://electric.ax/docs/sync/guides/troubleshooting, https://raw.githubusercontent.com/electric-sql/electric/main/packages/typescript-client/skills/electric-debugging/SKILL.md, https://github.com/TanStack/db/issues/1659, https://github.com/electric-sql/electric/issues/4773]

**Agent investments (the best-instrumented in this set).** `llms.txt` opens with `[!IMPORTANT] Coding agents should read AGENTS.md`; `AGENTS.md` has four ALWAYS-security rules, a Step 0–4 golden path, verbatim txid SQL, "Critical Gotchas" and **"Evolution Notes"** that de-train the old bidirectional-SQLite Electric. **Skills ship inside the npm tarballs** (`files: ["skills"]`, `library_version` pinned in frontmatter): nine for Electric, a tree for TanStack DB. The maintainer runs agent test tasks and files structured "Skill Feedback: What Worked / What Failed / Missing / Self-Corrections" issues that become doc tickets. `packages/typescript-client/SPEC.md` is a numbered-invariant state machine that tests derive from; AGENTS.md says read it first. CLI `electric` with `--json`, `ELECTRIC_API_TOKEN`, per-PR environments. No docs MCP, no cursor rules, no llms-full dump. [v: https://electric.ax/llms.txt, https://electric.ax/AGENTS.md, https://raw.githubusercontent.com/electric-sql/electric/main/packages/typescript-client/skills/electric-new-feature/SKILL.md, https://github.com/electric-sql/electric/issues/3970, https://raw.githubusercontent.com/electric-sql/electric/main/packages/typescript-client/SPEC.md]

**Test / deploy / offline.** Unit = mock `fetchClient`; integration = compose + Vitest; nothing verifies that a shape's `where` actually isolates tenants or that a handler's txid is the right one. Deploy = `electricsql/electric` image with persistent NVMe behind a request-collapsing CDN. Offline: TanStack DB `persistedCollectionOptions` (SQLite/OPFS/Expo adapters) + `@tanstack/offline-transactions` outbox; schema mismatch = full reset; a July-2026 hardening RFC names the root cause "the persistence layer and the sync adapter each own state the other one wipes." [v: https://electric.ax/docs/sync/guides/deployment, https://raw.githubusercontent.com/TanStack/db/main/packages/db/skills/db-core/persistence/SKILL.md, https://github.com/TanStack/db/issues/1659]

**Thesis / pain.** Read-path only — "Electric does not do write-path sync"; auth is "your proxy's job"; TanStack DB is "the reactive client store for your API". Pain: the write path is "hand-waved" in their own skill test; dual type paths → runtime `getTime is not a function`; skill prose steered an agent away from an explicit "with Electric" ask; a SQL injection shipped in the one server-side query surface (`order_by` AST, fixed 1.5.0). [v: https://electric.ax/docs/sync/guides/writes, https://github.com/electric-sql/electric/issues/3970, https://github.com/TanStack/db/issues/1335, https://casco.com/blog/electricsql-order-by-sql-injection]

### Jazz — jazz.tools (v2 public alpha since 2026-04-18; "classic" 0.x in maintenance)

**Loop.** `npm create jazz` prompts for framework/hosting/auth and, if hosted, "provisions an app on Jazz Cloud with env vars filled in" — **unclaimed apps are auto-deleted after 14 days**, so no account is needed to get a running backend. Generates `schema.ts` (`s.table({...})`, `s.ref("projects")` — ref columns *must* end in `Id`, enforced at runtime) and `permissions.ts` (`policy.todos.allowRead.where({ owner_id: session.user_id })`, `allowedTo.read`, `.whereOld()/.whereNew()`, magic `$canRead/$canEdit`), compiled to a **policy bundle enforced server-side**; dev plugins auto-start a local server, push schema/permission changes and inject env. Reads `useAll(q)`; writes apply locally and return a handle with `.wait({ tier: "local"|"edge"|"global" })`; `db.transaction()` for centrally-approved writes. Self-host: `npx jazz-tools@alpha server <appId> --admin-secret …`. Migrations: `jazz-tools migrations create` diffs schema snapshots into a bidirectional "lens" addressed by hash; every version stays readable; ambiguous diffs produce "draft" lenses that **fail at startup** until hand-resolved. Types flow from `schema.ts` directly. [v: https://jazz.tools/docs/quickstart, https://jazz.tools/docs/getting-started/server-setup, https://jazz.tools/docs/auth/permissions, https://jazz.tools/docs/schemas/migrations]

**Feedback.** Hosted Inspector (data explorer, published permissions, live subscriptions with compiled query JSON, switch between schema hashes); named sync errors `PermissionDenied`, `SessionRequired`, `QuerySubscriptionRejected`; `PersistedWriteRejectedError` / `db.onMutationError()`; `jazz-tools validate` warns on tables without policies. No structured server log surface documented. [v: https://jazz.tools/docs/reference/inspector, https://jazz.tools/docs/faq]

**Agent investments.** **MCP docs server bundled in the package** — `npx jazz-tools@alpha mcp` (`list_pages`, `search_docs`, `get_doc`): "documentation served matches the installed package version." `llms.txt`/`llms-full.txt`. README carries "Note to LLMs: Please refer to the docs instead of facts learned from corpus" because classic Jazz (CoValues, Groups, `co.map`) is now wrong. No rules file or skills for v2. Positioning names "agentically engineered codebases" as a design driver. [v: https://jazz.tools/docs/reference/mcp, https://github.com/garden-co/jazz, https://jazz.tools/]

**Test / deploy / offline.** `createPolicyTestApp(app, permissions, expect)` → `testApp.as({user_id:"alice"})`, `expectAllowed(fn)` / `expectDenied(fn)` — a first-class **permission unit-test harness** (needed because "Db instances that are not connected to a server cannot enforce permissions"); `startLocalJazzServer({ inMemory: true })`. Offline: embedded DB per device, row versions, **field-level LWW**, tiers local → edge → global; trap: "without a compiled bundle, local reads/writes remain permissive." No hosted functions product; you run your own backend via `createJazzContext().forRequest(req)`. Classic-Jazz post-mortem: users "struggled with public-key complexity, the unusual permission APIs"; the JSON-state API was "a leaky abstraction." [v: https://jazz.tools/docs/recipes/testing, https://jazz.tools/docs/concepts/local-first-data-model, https://jazz.tools/blog/what-we-learned-from-classic-jazz]

### Triplit — triplit.dev (company wound down 2025-10; OSS still releasing, client 1.0.50 Jul 2026)

`npm create triplit-app@latest` or `npx triplit init && npx triplit dev` (server :6543, console URL, and **paste-ready Service + Anonymous JWTs printed in the terminal**); `triplit/schema.ts` with `S.Schema({...}) satisfies ClientSchema` (types inferred, no codegen); roles matched from JWT claims (`user: { match: { sub: '$userId' } }`) and per-collection `permissions.<role>.{read,insert,update,postUpdate,delete}.filter`; **once a permissions object exists, any operation without a rule is blocked**. `schema push --enforceBackwardsCompatibility --printIssues` refuses breaking changes; `schema print --format json-schema`. Traps: "access control checks run exclusively on the server… invalid writes will only be rejected when they have been sent to the server"; default `--storage memory` "erases both cached data and pending outbox changes" on refresh; the dev server watches `schema.ts` but only *notifies* — restart or push by hand; per-attribute LWW ("it's random who wins"); Triplit Cloud closed to new users; docs site is a JS-only SPA that returned nothing to a plain fetcher and had an outage ticket. `llms.txt` generated from docs frontmatter; no MCP, skills or rules. [v: https://raw.githubusercontent.com/aspen-cloud/triplit/main/packages/cli/src/commands/dev.tsx, https://raw.githubusercontent.com/aspen-cloud/triplit/main/packages/docs/src/pages/schemas/permissions.mdx, https://raw.githubusercontent.com/aspen-cloud/triplit/main/packages/docs/src/pages/cli/schema.mdx, https://raw.githubusercontent.com/aspen-cloud/triplit/main/packages/docs/src/pages/offline-mode.mdx, https://supabase.com/blog/triplit-joins-supabase, https://hn.algolia.com/api/v1/items/40788648]

### PowerSync — powersync.com (Service 1.25, JS SDK 2.0, Sync Streams GA May 2026)

**Loop.** Source DB prep (`wal_level=logical`, `REPLICATION BYPASSRLS` role, publication) → `powersync init cloud|self-hosted` (`service.yaml`, `sync-config.yaml`) → **`powersync link cloud --create --project-id=…` creates and links an instance non-interactively** → `powersync validate` ("reports errors with line and column numbers") → `powersync deploy` → `powersync generate schema --output=ts` (**client schema generated from the deployed sync config**, TS/Kotlin/Swift/Dart/.NET) → client `PowerSyncDatabase` + a connector with `fetchCredentials()` and `uploadData()` draining `getNextCrudTransaction()` against *your* API. Sync Streams: `streams: { todos: { auto_subscribe: true, queries: ["SELECT * FROM todos WHERE owner_id = auth.user_id()"] } }` with a restricted SQL subset; generated type-safe stream wrappers. Local = docker-compose with source DB + bucket storage + service + your write API. The Jan-2026 changelog: "We're starting by revamping the PowerSync CLI which will form the foundation for our plans in this [AI agent] space." [v: https://docs.powersync.com/tools/cli.md, https://docs.powersync.com/intro/setup-guide, https://docs.powersync.com/sync/streams/queries.md, https://powersync.com/blog/powersync-changelog-january-2026]

**Feedback.** Dashboard validate+deploy, structured instance logs, service error codes (`PSYNC_S2305`); the Streams compiler "warns about queries that can silently sync rows incorrectly"; a **Sync Diagnostics app** ("what does this token see?": buckets, rows, per-table sizes, read-only SQL console); client `SyncStatus` with upload-queue size. [v: https://docs.powersync.com/usage/tools/powersync-dashboard.md, https://github.com/powersync-ja/powersync-js/tree/main/tools/diagnostics-app, https://powersync.com/blog/powersync-changelog-june-july-2026]

**Agent investments (most complete of the three).** `llms.txt`, **`.md` on any docs URL**, hosted MCP `docs.powersync.com/mcp`; `powersync-ja/agent-skills` (SKILL.md + AGENTS.md + CLAUDE.md + `.cursor/rules`) with explicit prohibitions (don't default to Supabase, don't edit `service.yaml` unasked, secrets only in `.env`) and named traps: omitting `transaction.complete()` "locks upload queues permanently," forgetting `disconnectAndClear()` on logout, defining a custom `id`, returning 4xx on validation errors; `PS_ADMIN_TOKEN` for CI; Terraform provider. [v: https://docs.powersync.com/tools/ai-tools, https://raw.githubusercontent.com/powersync-ja/agent-skills/main/skills/powersync/SKILL.md]

**Test / deploy / offline.** Unit-testing guide is Dart-only; JS has an in-memory VFS but no mock connector/sync-in-CI harness. Offline: local SQLite + sequential upload queue; server-authoritative; per-field LWW, "deletes always win"; **backend must return 2xx even for validation failures** (4xx jams the queue) and surface errors via a synced `write_conflicts` table; "no built-in CRDT support." Permissions: streams govern *downloads only* — "you are told to mirror RLS in streams" (`auth.uid()` ↔ `auth.user_id()`); writes are your backend's job. HN: "the DX is the worst by quite a margin" (Postgres + Mongo + "arcane yaml"). [v: https://docs.powersync.com/handling-writes/handling-write-validation-errors.md, https://docs.powersync.com/integrations/supabase/rls-and-sync-streams.md, https://hn.algolia.com/api/v1/items/45066070]

### Turso / libSQL / Turso Database — turso.tech (Turso Database 0.7.2, libSQL server frozen Feb 2025, `turso` CLI 1.0.32)

**Naming is a finding.** `tursodb` (Rust SQLite rewrite, beta warning dropped July 2026, "almost 100% of the code … written by AI tools"), libSQL (older C fork; server frozen; Cloud runs a proprietary server), Turso Cloud (orgs → groups → databases → tokens; `engine: "libsql" | "tursodb"`), four npm clients (`@tursodatabase/database|serverless|sync`, `@libsql/client`). Their own SKILL.md opens with "These names get confused constantly. Keep them straight." [v: https://github.com/tursodatabase/turso-mcp/blob/main/claude-code/skills/turso/SKILL.md, https://docs.turso.tech/turso-cloud.md, https://turso.tech/blog/what-happens-with-oss-in-the-age-of-ai]

**Loop.** Local, no account: `npm i @tursodatabase/database; const db = await connect("app.db")` — one file, no server, no token; `tursodb ./server.db --sync-server 0.0.0.0:8080` is a local sync server that is **protocol-identical to the cloud with no auth**. Legacy `turso dev` shells out to an external `sqld` that must be on PATH and loses data without `--db-file` (open issues #614, #873). Cloud: `turso auth login --headless`, `turso db create x [--tursodb] [--from-db y --timestamp …] [--from-file|--from-dump|--from-csv]`, `turso db tokens create x --read-only --expiration 7d`; Platform API `POST /v1/organizations/{org}/databases {"name","group","seed":{"type":"database","name":"template"}}` with `@tursodatabase/api`. Types: none of its own; Drizzle `dialect:"turso"`; **Prisma Migrate unsupported** (pipe SQL through `turso db shell`). [v: https://docs.turso.tech/local-development.md, https://docs.turso.tech/sync/local-sync-server.md, https://github.com/tursodatabase/turso-cli/issues/614, https://docs.turso.tech/api-reference/databases/create.md, https://docs.turso.tech/sdk/ts/orm/prisma.md]

**Feedback.** Dashboard "Database Analytics" (top queries by rows touched, GPT-4 "AI Insights"), `turso db inspect --queries`, `/stats` and `/usage` endpoints, audit logs on paid plans, the same `database_analytics` as an MCP tool. Errors are plain 400/409 strings; engine COMPAT gaps can produce misleading "no such table"; sync exposes only `db.stats()`. [v: https://turso.tech/blog/database-analytics-with-ai-insights, https://docs.turso.tech/api-reference/databases/stats.md, https://github.com/tursodatabase/turso/blob/main/COMPAT.md]

**Agent investments.** `llms.txt` with `.md` mirror of every page and OpenAPI. Hosted MCP `mcp.turso.ai` installed as a Claude Code/Codex/Cursor plugin: OAuth 2.1 + PKCE "fully discoverable from the server — nothing to paste"; consent screen scopes org, optionally one group, read-only/full/custom; "unscoped tokens are rejected"; the MCP layer "makes no authorization decisions of its own" — every call forwards the token to the platform API. **Tools are split by blast radius**: `read_database` (SELECT), `write_database` (refuses DELETE/DROP), `delete_from_database`, `evolve_schema`, `create_branch` (point-in-time), with destructive annotations. The shipped SKILL.md is an *ordered decision procedure* ("decide in this order") plus "if a tool returns forbidden, the token isn't scoped — don't retry; point the user at 'Connect an AI agent'." Engine-local `tursodb db --mcp` (9 tools). **AgentFS**: copy-on-write overlay filesystem whose delta is a SQLite file, `agentfs run claude|codex`, `diff`/`timeline`, per-session, sync to Cloud. **AgentID** (2026-08-26): agents get their own OIDC accounts with separate agent/owner claims. Per-agent DB guides; Adaptive forks a DB per prompt iteration (millions of DBs), Poke ~10k, CTO.new tens of thousands. [v: https://github.com/tursodatabase/turso-mcp/blob/main/claude-code/README.md, https://docs.turso.tech/agentfs/introduction.md, https://turso.tech/blog/giving-agents-their-own-turso-accounts-with-agentid, https://turso.tech/blog/turso-cloud-powers-adaptive-ai, https://turso.tech/blog/how-poke-gives-every-user-their-own-database]

**Test / deploy / offline.** Engine: seeded DST simulator, Antithesis, Quint formal models (found 10+ bugs in SQLite itself), Aristo, and **LLM agents as adversarial testers** with persona rotation against SQLite as oracle. App level: in-memory `tursodb`, branch prod for a test env. No app hosting. Offline: libSQL embedded replicas → Offline Writes beta (2025-03: "conflict resolution is not yet implemented", "no durability guarantees") → Turso Sync (2026-04): CDC push + page pull, **Last-Push-Wins**, a `transform` hook, manual retry, manual `checkpoint()`; authorization must live in per-table token scopes (`comments:data_add,data_update`) because clients sync directly. Branching = instant metadata-only CoW, no merge-back, new token per branch, manual cleanup; PITR 1–90 days. [v: https://turso.tech/blog/edgar-allan-poe, https://turso.tech/blog/turso-offline-sync-public-beta, https://docs.turso.tech/sync/conflict-resolution.md, https://docs.turso.tech/features/branching.md, https://news.ycombinator.com/item?id=43535943]

**Thesis / pain.** "Many-database architecture": an idle DB costs only storage, so give every agent/user/iteration its own; branch + PITR is the agent's undo. Pain they document: fleet schema propagation "is your problem" after Multi-DB Schemas/ATTACH were deprecated (Jan 2025) and never replaced; no GC for inactive DBs; one group on free tiers; the $1,000 corruption bounty was retired (2026-05) after "the slop machine." [v: https://turso.tech/blog/turso-for-startups-the-many-database-architecture, https://turso.tech/blog/multi-tenancy-at-scale, https://turso.tech/blog/the-wonders-of-ai]

### Cloudflare — Workers + D1 + Durable Objects + Agents SDK + Vite plugin (Agents Weeks Apr/Aug 2026)

**Loop.** `npm create cloudflare@latest -- app --type=hello-world --lang=ts -y --no-deploy` (or `--template cloudflare/agents-starter`); `wrangler.jsonc` is the paved config (the LLM prompt says use it *exclusively*); `npx wrangler types` generates `Env` + runtime types into `worker-configuration.d.ts` with `--check` as a CI gate ("do not hand-write your Env"); `wrangler dev` or `vite dev` with `@cloudflare/vite-plugin` run real workerd (HMR for Worker code) with state in `.wrangler/state/`; per-binding `"remote": true` proxies to deployed resources (GA 2025-09; not for Durable Objects). ## 3. What the app-builders (Lovable / Bolt / v0 / Replit / Databutton) learned about backends for agents

These are the lessons the builders and their backend partners have *published*, each with the mechanism that came out of it.

1. **The agent will skip or botch authorization unless the platform makes it structural.** Lovable's generated migrations "focus on getting the schema right for the app to function" and RLS was omitted or over-permissive → CVE-2025-48757 (170+ apps). Bolt's audit has a dedicated "RLS Policy Always True" finding. Supabase's own migration prompt now says a new table "MUST enable RLS even if the table is intended for public access," and its declarative-schema diff *cannot even express RLS policies*. Lesson: a per-table opt-in permission model is the wrong default for a generator; authorization has to be attached to the read/write path itself (named queries/mutations, or policies the schema tool owns). [https://www.superblocks.com/blog/lovable-vulnerabilities, https://support.bolt.new/cloud/database/security.md, https://supabase.com/docs/guides/ai-tools/ai-prompts/database-create-migration, https://supabase.com/docs/guides/local-development/declarative-database-schemas]
2. **A scanner that checks presence is not a scanner that checks effect.** Lovable's first "security scan" flagged whether RLS *existed*, not whether it blocked access; the fix was a Deep scan that looks for RLS-bypassing `SECURITY DEFINER` functions, unauthenticated edge functions, and a chat-driven "review my app's security." Supabase's advisors run in the dashboard *after* the fact. Lesson: the verification an agent needs is a *behavioral* check ("as anon, can I read row X?") run before publish and returned as data. [https://docs.lovable.dev/features/security, https://supabase.com/docs/guides/database/database-advisors]
3. **Show-then-apply migrations, saved as files, with types regenerated in the same step.** Lovable: generate SQL → show in chat → approval → execute on the project → save under `supabase/migrations/` → regenerate TS types. v0 by contrast just "generates and executes SQL" with no files or types, and Bolt users hit duplicate migrations they could not discard. Lesson: one migration primitive that is reviewable, idempotent, file-backed and type-producing; a raw `execute_sql` next to it is a footgun. [https://docs.lovable.dev/integrations/supabase, https://v0.app/docs/databases, https://x.com/tristanbob/status/1878638815998570988]
4. **Server-side code must be a first-class, deployable unit with logs the agent can read.** Both Lovable and Bolt added edge/server functions *after* launch because "payments, emails, AI features, scheduled tasks, external API calls" cannot live in the client; the loop that made them usable was "Lovable reads its logs and surfaces the error in chat." Lesson: server functions + secrets + invocation logs + a way to call a function directly are the minimum; Supabase's Evals show *Investigate* (reading logs to find a fault) is the weakest stage for every model, so logs must be structured and queryable, not a dashboard. [https://docs.lovable.dev/features/edge-functions.md, https://supabase.com/evals]
5. **Secrets are entered by the human and never read back by the agent.** Lovable: "Lovable detects it and prompts you to enter the value through a secure input… Lovable does not read stored secret values back." Lesson: a write-only secret store with a name-level API. [https://docs.lovable.dev/integrations/supabase]
6. **Rollback must include data, or it isn't rollback.** Bolt: "Version History … does not support database restores." Replit's answer is a Neon branch per checkpoint with preview-then-promote; Neon's `finalize_restore: true` keeps the connection string stable. Lesson: checkpoint = code + schema + data + agent memory, cheap enough to take on every step. [https://support.bolt.new/cloud/database.md, https://neon.com/blog/replit-app-history-powered-by-neon-branches, https://neon.com/docs/ai/ai-database-versioning]
7. **Provisioning has to be account-less or one-click, and later claimable.** v0 "provisions a new user account on that service and adds the necessary environment variables"; Supabase built a project-claim OAuth flow and Nano scale-to-zero instances for platforms; Neon built Claimable Neon (72 h TTL, claim code); Instant's Platform API creates "temporary 2-week apps." Lesson: create first, attach a human later; TTL bounds abuse. [https://v0.app/docs/databases, https://supabase.com/docs/guides/integrations/supabase-for-platforms, https://neon.com/docs/reference/neon-launchpad, https://instantdb.com/docs/platform-api.md]
8. **Auth setup is where "own Supabase" breaks: the agent can add the button but not the provider.** On a user-owned project Lovable can only add the UI; social providers must be enabled by hand in the Supabase dashboard — managed auth config, payments, custom emails are Cloud-only. Lesson: auth provider configuration needs an API the agent can drive (Neon's `provision_neon_auth`, Supabase `/config/auth`). [https://docs.lovable.dev/integrations/supabase, https://supabase.com/docs/guides/integrations/build-a-supabase-oauth-integration]
9. **One agent-usable connection, not four.** Neon's skills exist because agents pick pooled vs direct wrong for migrations; Databutton and Bolt both moved from "connect your own X" to a bundled backend because configuration overhead generated support tickets ("wiring up third-party tools like Supabase"). Lesson: a single opinionated backend wins over integration menus for generators. [https://neon.com/docs/ai/skills/neon-postgres-branches/SKILL.md, https://neon.com/blog/databutton-neon-integration, https://supabase.com/blog/bolt-cloud-launch]
10. **MCP with production credentials is a data-exfiltration channel.** The Supabase lethal-trifecta case (service_role + untrusted ticket text + a write path back to the attacker) forced read-only roles *below the model*, project scoping and feature groups — and the admission that "guardrails alone aren't enough." Convex ships prod as read-only/non-PII by default; Turso rejects unscoped tokens and splits tools by blast radius. Lesson: default to a read-only, single-deployment, non-PII credential; make destructive capabilities separate tools. [https://simonwillison.net/2025/Jul/6/supabase-mcp-lethal-trifecta/, https://supabase.com/blog/defense-in-depth-mcp, https://docs.convex.dev/ai/convex-mcp-server, https://github.com/tursodatabase/turso-mcp/blob/main/claude-code/README.md]
11. **Typecheck-in-the-loop beats prompt engineering; guidelines still add ~20%.** Chef feeds `tsc` results back to the model; Convex Evals grade by compile + deploy + tests and found curated rules lift success ~20%; Encore's benchmark found integrated typed primitives beat library composition ("the framework's defaults shape what the agent ships"). Lesson: make the correct path the least-effort, type-checked path, and ship the rules with the SDK. [https://news.convex.dev/meet-chef/, https://stack.convex.dev/convex-evals, https://encore.dev/blog/ai-benchmark]
12. **The migration path out is part of trust.** Lovable Cloud ↔ own Supabase has no migration either way and a cottage industry of 33-step guides exists; Electric Cloud's shutdown killed its quickstart. Lesson: exportability (schema + data + functions) is an agent-loop feature, not an afterthought. [https://docs.lovable.dev/features/cloud, https://github.com/CarolMonroe22/lovable-cloud-to-supabase-migration, https://electric.ax/blog/2026/08/11/electric-joining-databricks]

## 4. Ten mechanisms worth stealing for an agent-first backend, and ten mistakes to avoid

### 4a. Ten mechanisms worth stealing

1. **Every operation returns a typed status or a coded error — never a silent no-op.** Zero's `useQuery` → `{type:'complete'|'unknown'|'error'}` and `zero.mutate(...)` → `{client, server}` promises that always resolve; Cloudflare's DO reconciliation report with codes like `config_export_not_in_code`; Jazz's `PermissionDenied`/`PersistedWriteRejectedError`. The counter-examples (Electric "ready, empty, silent"; Triplit server-only rejection) show why this is first. [https://zero.rocicorp.dev/docs/mutators, https://developers.cloudflare.com/durable-objects/reference/durable-objects-migrations/, https://jazz.tools/docs/faq]
2. **The dashboard is an API: traces + call-an-endpoint + query + logs, discoverable from the terminal.** Encore's 19-tool MCP ("call it and verify that the publish is in the traces"); Cloudflare's Local Explorer, which captures OTel traces in `wrangler dev`, serves `/cdn-cgi/explorer/api` with an OpenAPI schema, and prints the hint only when an agent session is detected; Neon's `neon inspect db` ("read-only and bounded… heavy results are capped"). Supabase's evals say Investigate is the weakest stage — this is the fix. SpacetimeDB goes one step further: the database host itself serves `/v1/mcp`, so the agent's tools keep their shape from local to deployed; Appwrite's meta-MCP (`search_tools` → `call_tool` with `confirm_write=true` over 981 tools) keeps the surface small. [https://encore.dev/blog/mcp-deep-dive, https://developers.cloudflare.com/changelog/post/2026-08-04-local-tracing/, https://neon.com/blog/neon-inspect-db, https://supabase.com/evals, https://github.com/clockworklabs/SpacetimeDB/releases/tag/v2.8.1, https://github.com/appwrite/mcp/blob/main/docs/tool-surface.md]
3. **Create before identity exists, with a claim ceremony and a TTL.** Neon's Claimable protocol (anonymous assertion → 900 s bearer → credentials → `user_code` claim → `pending/accepted/reconciled` with key rotation; 72 h / 100 MB caps); Cloudflare Temporary Accounts + `wrangler deploy --temporary` returning a claim URL; Jazz's 14-day unclaimed apps; Instant's 2-week apps; Supabase's project-claim OAuth for platforms. [https://neon.com/docs/reference/neon-launchpad, https://developers.cloudflare.com/changelog/post/2026-07-14-temporary-accounts-api/, https://jazz.tools/docs/getting-started/server-setup, https://instantdb.com/docs/platform-api.md, https://supabase.com/docs/guides/integrations/supabase-for-platforms]
4. **A cheap isolated copy of the *whole* backend per task, with expiry and reset, and a two-phase migration on top of it.** Neon branches carry DB + Auth + Data API + Functions + Storage, `expires_at` (max 30 d, preserved across reset), `reset_from_parent`, and MCP `prepare_database_migration` (temp branch) / `complete_database_migration`; Encore `namespace switch --create pr:123` locally; Turso `seed:{type:"database",name,timestamp}`; Replit's checkpoint = Neon branch, restored with `finalize_restore: true` so the connection string never changes. [https://neon.com/docs/guides/branch-expiration, https://github.com/neondatabase/mcp-server-neon, https://encore.dev/docs/ts/cli/infra-namespaces, https://docs.turso.tech/features/branching.md, https://neon.com/docs/ai/ai-database-versioning]
5. **Docs as Markdown at the network layer, version-pinned, with a hand-written pitfalls preamble.** Cloudflare: any page + `/index.md` or `Accept: text/markdown` with token-count headers (7.22× fewer tokens), plus a MUST/SHALL system prompt encoding their own failure modes; Zero's "Key mental models" preamble in `llms.txt`; Wasp's `llms-0.25.txt` with a plugin hook that reads the project version first; Jazz's `npx jazz-tools mcp` serving docs "matching the installed package version." [https://developers.cloudflare.com/style-guide/how-we-docs/ai-consumability/, https://developers.cloudflare.com/workers/get-started/prompting/, https://zero.rocicorp.dev/llms.txt, https://wasp.sh/llms.txt, https://jazz.tools/docs/reference/mcp]
6. **Skills shipped inside the package, version-pinned, that encode an ordered decision procedure and prohibitions — with a feedback loop from real agent runs.** Electric/TanStack DB put `skills/` in the npm tarball with `library_version` frontmatter and file structured "Skill Feedback: What Worked / What Failed / Missing" issues; Neon's skills say "CLI > MCP > API" and "ask before replacing `DATABASE_URL`"; Turso's says "decide in this order… if forbidden, don't retry, go mint a scoped token"; PowerSync's names the traps (`transaction.complete()`, 4xx). One command installs rules + skills + MCP for the detected agent (`encore llm-rules init`, `neon init --agent`, `npx convex ai-files install`). [https://raw.githubusercontent.com/electric-sql/electric/main/packages/typescript-client/skills/electric-new-feature/SKILL.md, https://github.com/electric-sql/electric/issues/3970, https://neon.com/docs/ai/skills/neon-postgres-branches/SKILL.md, https://github.com/tursodatabase/turso-mcp/blob/main/claude-code/skills/turso/SKILL.md, https://encore.dev/docs/ts/ai-integration]
7. **Agent credentials scoped by construction, and tools split by blast radius.** Convex Agent Mode: an anonymous local backend when no key is present, or `npx convex deployment token create agent-token --save-env` valid for one dev deployment; prod MCP read-only/non-PII unless `--dangerously-enable-production-deployments`. Turso MCP: OAuth discovered from `WWW-Authenticate`, consent-time org/group/read-only scoping, "unscoped tokens are rejected," separate `read_database` / `write_database` (refuses DELETE/DROP) / `delete_from_database` / `evolve_schema` tools. Supabase's post-incident read-only Postgres *role* — enforced "below the model, where an injected prompt cannot reach." Neon's project-scoped keys and `--mint` one-time credentials. [https://docs.convex.dev/cli/agent-mode, https://docs.convex.dev/ai/convex-mcp-server, https://github.com/tursodatabase/turso-mcp/blob/main/claude-code/README.md, https://supabase.com/blog/defense-in-depth-mcp]
8. **Authorization that is (a) attached to the read/write path, not opt-in per table, and (b) unit-testable.** Zero's named queries where "the server can add extra filters"; Convex functions as the only API; Jazz's `createPolicyTestApp` → `as({user_id})` → `expectAllowed/expectDenied`; Instant's Sandbox returning per-entity permission pass/fail; Lovable's Deep scan as the behavioral check before publish. [https://zero.rocicorp.dev/docs/synced-queries, https://jazz.tools/docs/recipes/testing, https://www.instantdb.com/docs/workflow, https://docs.lovable.dev/features/security]
9. **Real infrastructure in tests, tuned for speed, plus typecheck-in-the-loop and public evals.** Encore `encore test` (fresh DBs, fsync off, in-memory FS, "never mock infra"); Cloudflare's vitest plugin running inside workerd; Chef feeding `tsc` back to the model; Convex Evals graded by tsc + ESLint + deploy + Vitest (guidelines +~20%); Supabase Evals with Build/Deploy/Investigate/Resolve; Encore's benchmark showing typed primitives beating library composition; Appwrite Arena measuring model accuracy with and without its skills (Functions and Auth weakest). [https://arena.appwrite.network/, https://encore.dev/docs/ts/develop/testing, https://developers.cloudflare.com/workers/testing/vitest-integration/get-started/write-your-first-test/, https://news.convex.dev/meet-chef/, https://github.com/get-convex/convex-evals, https://supabase.com/evals, https://encore.dev/blog/ai-benchmark]
10. **One generated, checkable artifact from one source of truth — with a preflight gate.** `wrangler types --check` fails CI when `Env` is stale ("do not hand-write your Env"); PowerSync generates the client schema *from the deployed sync config* and `powersync validate` reports line/column errors; Triplit's `schema push --enforceBackwardsCompatibility --printIssues`; Lovable regenerates TS types in the same step as applying a migration; Appwrite's `push tables` classifies in-place vs destructive column changes, treats `previousKey` as a rename, and halts before partial application; Cloudflare's Code Mode MCP exposes 2,500+ endpoints as `search` + `execute(ts)` in ~1k tokens. [https://developers.cloudflare.com/workers/wrangler/commands/workers/, https://docs.powersync.com/tools/cli.md, https://raw.githubusercontent.com/aspen-cloud/triplit/main/packages/docs/src/pages/cli/schema.mdx, https://docs.lovable.dev/integrations/supabase, https://appwrite.io/docs/tooling/command-line/tables, https://developers.cloudflare.com/agents/model-context-protocol/cloudflare/servers-for-cloudflare/index.md]

### 4b. Ten mistakes to avoid

1. **A long first minute: many processes and prerequisites before one row moves.** Zero = Postgres + zero-cache + API + UI with two cache restarts; Electric = six Postgres prerequisites plus Caddy; PowerSync = four moving parts; Encore and Supabase need Docker; Nhost's only local loop is a seven-container stack and Appwrite's self-host needs 4 GB RAM; Turso's `turso dev` shells out to an uninstalled `sqld`. Turso local (`connect("app.db")`), Jazz (`create jazz`), Instant and Convex are the one-command counter-examples. [https://zero.rocicorp.dev/docs/tutorial, https://electric.ax/docs/sync/guides/postgres-permissions, https://docs.powersync.com/tools/local-development.md, https://docs.nhost.io/getting-started/local-development/cli, https://github.com/tursodatabase/turso-cli/issues/614]
2. **Two sources of truth.** Zero's `schema.ts` must be "a subset of" Postgres DDL, with a backfill window where a column exists but querying it fails; Electric's wire `parser` vs client Zod → runtime `getTime is not a function`; Cloudflare's local D1 ≠ remote D1 ("migrated locally, empty in prod"); Wasp's SQLite-dev / Postgres-prod; Supabase's declarative diff that cannot see Studio edits or RLS. [https://zero.rocicorp.dev/docs/schema, https://github.com/electric-sql/electric/issues/3970, https://developers.cloudflare.com/d1/best-practices/local-development/, https://supabase.com/docs/guides/local-development/declarative-database-schemas]
3. **Failure that looks like success.** Electric persisted collections "ready, empty, silent" and `TRUNCATE` losing writes while reporting `up-to-date`; Zero's `needs-auth` cliff; Triplit and Jazz accepting writes locally that the server later rejects; PowerSync's queue jamming on a 4xx; Encore's `ON CONFLICT` passing SQLite stubs and failing on Postgres. An agent cannot self-correct on silence. [https://github.com/TanStack/db/issues/1659, https://github.com/electric-sql/electric/issues/4773, https://raw.githubusercontent.com/aspen-cloud/triplit/main/packages/docs/src/pages/schemas/permissions.mdx, https://docs.powersync.com/handling-writes/handling-write-validation-errors.md, https://encore.dev/blog/agent-verify-loop]
4. **Per-table, opt-in authorization the generator can skip — and two permission systems mirrored by hand.** Supabase RLS (CVE-2025-48757: 170+ Lovable apps; Bolt's "RLS Policy Always True" finding; the migration prompt's "MUST enable RLS"); PowerSync streams for reads vs RLS/backend for writes; Electric's "auth is your proxy's job"; Turso's per-table token scopes because clients sync directly. [https://www.superblocks.com/blog/lovable-vulnerabilities, https://supabase.com/docs/guides/ai-tools/ai-prompts/database-create-migration, https://docs.powersync.com/integrations/supabase/rls-and-sync-streams.md, https://electric.ax/docs/sync/guides/writes]
5. **Names, APIs and DSLs that outrun the model's memory.** Wasp's `.wasp` DSL → hallucinations → TS rewrite; Jazz v2 under the same name ("Note to LLMs…"); Neon's `neonctl→neon`, `pg.new→neon.new→Instagres→Claimable`, `toolkit` deprecated; Turso vs tursodb vs libSQL with four npm clients; Cloudflare Agents SDK 0.x with monthly breaking pins and "not accepting external pull requests"; PowerSync Sync Rules vs Streams; Convex's "knowledge cutoff problem"; Appwrite's collections→tables rename (2025-08) with both APIs alive; SpacetimeDB's package, camelCase-handle and optional-field renames all inside 2026. [https://appwrite.io/changelog/entry/2025-08-26-2, https://github.com/clockworklabs/SpacetimeDB/releases, https://wasp.sh/blog/2026/06/15/wasp-typescript-spec, https://github.com/garden-co/jazz, https://github.com/neondatabase/toolkit, https://github.com/tursodatabase/turso-mcp/blob/main/claude-code/skills/turso/SKILL.md, https://developers.cloudflare.com/changelog/product/agents/]
6. **A powerful mutation surface whose safety is a disclaimer.** Supabase MCP with `service_role` → the lethal trifecta, then "guardrails alone aren't enough"; Neon MCP "development and testing only… review every action" with an admittedly bypassable `SELECT`-prefix gate in the Eve guide; the first Turso MCP with no read-only guard. Scoping arrived after the incidents. [https://simonwillison.net/2025/Jul/6/supabase-mcp-lethal-trifecta/, https://supabase.com/blog/defense-in-depth-mcp, https://neon.com/guides/vercel-eve-neon]
7. **Metering without caps, and cleanup delegated to the caller.** Cloudflare's `setAlarm()` loop: ~930 billion row reads/day, $34,895 in 8 days with zero users, alerts watching only CPU; Neon's Vercel-managed preview branches lingering "months" and `main (old)` orphans; Turso's new-token-per-branch and no GC for inactive DBs; PowerSync/Turso manual `checkpoint()`/retry. Default the TTL and the cap. [https://news.ycombinator.com/item?id=47787042, https://neon.com/docs/guides/vercel-overview, https://turso.tech/blog/how-poke-gives-every-user-their-own-database]
8. **Rollback that leaves data behind.** Bolt: "Version History … does not support database restores"; Replit's DB restore is opt-in and never automatic for production; Jazz's hand-resolved "draft lenses" that fail at startup; Turso branches with no merge-back; SpacetimeDB cannot drop or rename a column, so its official skill's "schema conflict" recipe is `spacetime publish --delete-data=always --yes`. Checkpoints must be code + schema + data + agent memory, taken on every step. [https://support.bolt.new/cloud/database.md, https://docs.replit.com/core-concepts/agent/checkpoints-and-rollbacks, https://jazz.tools/docs/schemas/migrations, https://docs.turso.tech/features/branching.md, https://github.com/clockworklabs/SpacetimeDB/blob/master/codex-plugin/plugins/spacetimedb/skills/cli/SKILL.md]
9. **Gating the safe loop behind a plan, or binding the on-ramp to a service that can vanish.** Encore preview environments (Pro), Supabase branching (paid), Zero's invite-only Cloud; Electric Cloud's shutdown killing `@electric-sql/start`; Triplit Cloud closed and its SPA docs unreadable to fetchers; Lovable Cloud with no export path either way. [https://encore.dev/docs/platform/deploy/preview-environments, https://electric.ax/blog/2026/08/11/electric-joining-databricks, https://docs.lovable.dev/features/cloud]
10. **Shipping the easy half and calling the hard half "your problem."** Turso's Offline Writes beta with "conflict resolution is not yet implemented" and "no durability guarantees," later answered by Last-Push-Wins plus a `transform` hook; Electric's "hand-waved" write path and txid plumbing; Turso deprecating fleet schema propagation with "we'll reinvent it" (still unreinvented 19 months on); Wasp with no server-side tests; Supabase's OAuth partners needing the user's DB password for full access. [https://turso.tech/blog/turso-offline-sync-public-beta, https://electric.ax/docs/sync/guides/writes, https://turso.tech/blog/multi-tenancy-at-scale, https://wasp.sh/docs/project/testing, https://supabase.com/docs/guides/integrations/build-a-supabase-oauth-integration]

## 5. Cross-cutting observations

- **Convergence.** Most of the twenty products now ship the same kit: `llms.txt` + `.md`-per-page (Zero, Electric, Turso, Neon, Cloudflare, PowerSync, Instant, Jazz, Wasp, Supabase), an MCP server (all but Zero, Electric, Triplit, Wasp), Agent-Skills folders (Electric, TanStack DB, Neon, Supabase, Cloudflare, PowerSync, Encore, Convex, Zero, Appwrite, SpacetimeDB), increasingly bundled with the MCP config as an editor plugin whose write tools are gated (`confirm_write`, `allow_mutations=[]`, `sql.confirmed`), and a scaffold that writes `AGENTS.md`/`CLAUDE.md` (Wasp, Convex `ai-files`, Encore `llm-rules init`, Neon `init --agent`). The differentiators are elsewhere.
- **Where agents actually fail, by the vendors' own evidence.** (1) *Investigation*: Supabase Evals show Investigate at 33–67% while Build is 72–97% — reading logs/advisors to find a fault is the hard stage. (2) *Silent success*: Electric "ready, empty, silent", Zero `needs-auth` rejecting all writes, Triplit/Jazz local-permissive vs server-strict, PowerSync's 4xx-jams-the-queue. (3) *Stale knowledge*: Wasp's DSL, Jazz's rewrite, Neon's and Turso's renames, Cloudflare's monthly Agents SDK breaks, Convex's "knowledge cutoff problem" — every vendor now version-pins docs or ships them inside the package. (4) *Authorization omitted*: RLS in Supabase-backed builders; write-path permissions in Electric/PowerSync/Turso pushed to the app. [https://supabase.com/evals, https://github.com/TanStack/db/issues/1659, https://zero.rocicorp.dev/llms.txt, https://github.com/wasp-lang/wasp/issues/2630, https://stack.convex.dev/convex-evals]
- **Stats worth quoting.** "Over 80% of databases on Neon created by AI agents" (Databricks PR, 2025-05); Replit "thousands per day (more than humans)"; Supabase 200k+ databases/day, Bolt alone 600k backends; Adaptive "millions" of Turso DBs, one per prompt iteration; Cloudflare docs 7.22× fewer tokens as Markdown; Convex guidelines +~20% eval pass rate; Wasp 38% fewer tokens than Next.js for the same app; Encore 31/31 vs 24–28/31 for library-composed frameworks; Appwrite Arena top models ~97.7% with skills vs code "removed in Appwrite 1.0" without. [URLs in the product sections]
- **Two design axes matter more than any feature.** *Loudness*: does every operation return a typed status or coded error an agent can assert on (Zero, Cloudflare DO reconciliation, Jazz named errors) or does it fail quietly (Electric, Triplit)? *Distance from create to running*: one file and no server (Turso local, Instant, Jazz `create jazz`, SpacetimeDB's single-binary `spacetime dev`) versus Docker + logical replication + proxy + four processes (Zero, Electric, PowerSync, Encore, Supabase). Every builder that started on the long side (Databutton, Bolt, Lovable) eventually bundled its own backend.
- **The safety story that survived contact.** Not guardrail prompts, but structure: a read-only Postgres *role* below the model (Supabase), single-deployment scoped keys minted for the agent (Convex Agent Mode, Neon `--mint`, Instant per-app admin tokens), tools split by blast radius with consent-time scoping (Turso), egress-blocked throwaway isolates for model-written code (Cloudflare Dynamic Workers), and TTLs on everything ephemeral (Neon, Jazz, Instant, Cloudflare temporary accounts). Even so, Cloudflare's Code Mode sandbox was escaped in Aug 2026 — "the engine is not the whole boundary."
- **Academic framing.** "Supporting Our AI Overlords: Redesigning Data Systems to be Agent-First" (2025-09) characterizes agent workloads as high-scale, heterogeneous, redundant and steerable "agentic speculation," and proposes *probes* (SQL + a natural-language brief carrying phase, accuracy needs and goal), an *agentic memory store* (semantic cache of prior probe results and metadata), *sleeper agents* that proactively return join hints, why-not provenance and cost estimates, satisficing/approximate execution, multi-query sharing (<20% distinct sub-plans among 50 parallel attempts), and "versioned storage supporting massive parallel forking with fast rollbacks" — the last of which is exactly what Neon/Turso/Cloudflare have built.
