The adversarial arm checks resolve as follows:

- **Held + absent + graced:** a proven conjunction projects held to zero, retains absent/graced zero values and independent conditions, and carries held/graced deadlines. The mixed test covers this and nested guards.
- **One read feeding guard and payload:** the stored ordinary value survives; the projected value accompanies it. A direct `connected[p]` read with an open poll still returns its positive count. However, ordinary payload *evaluation cost* need not match grace—Finding 1.
- **Alias reassignment:** proof planning replaces the binding’s proof; execution replaces its value and tracking. Conditional/loop-carried assignments conservatively lose proof. There is no new reassignment regression test. [presence.rs:219](snapback4/crates/snapback4-core/src/engine/presence.rs:219), [presence.rs:253](snapback4/crates/snapback4-core/src/engine/presence.rs:253).
- **Recipient loop:** direct guards qualify per iteration; the 49-recipient fixture exercises this.
- **Emitting `else`:** a proven absence `else` can replace the ordinary `then`. Each `If` executes exactly one arm; it does not execute one emit twice. Separate complementary `If`s are different: both can emit after projection.

For the six requested lifetime cases:

| Case | Result |
|---|---|
| Poll enters between effect insertion and commit | Its registration cannot interleave under the host engine lock. If registration obtains the lock afterward, it records a post-commit reconnect. |
| Poll entered before commit and is answered by it | Its earlier registration cannot mark the future dependency. Only the subsequent poll satisfies it. |
| Two commits defer to one recipient | Each has its own effect/dependency row. An arrival marks every existing dependency whose individual deadline has not passed. |
| Restart between commit and δ | Persisted deadlines and reconnect bits survive; process-local development clock offsets still reset. |
| Reconnect after first claim | Claim deletes the dependencies transactionally, so the reconnect cannot cancel that attempt or its retries. |

1. **High — Held can exceed graced charges and change mutation outcome.**  
   **Location:** [presence.rs:117](snapback4/crates/snapback4-core/src/engine/presence.rs:117), [runner.rs:235](snapback4/crates/snapback4-core/src/engine/runner.rs:235).

   Concrete admitted composition:

   ```quarry
   effect notify
   mutation push(p: principal):
     online = exists connected[p]
     if not online:
       emit notify {}
     if online:
       emit notify {}
   ```

   At baseline, held and graced each execute one emit. After this change, held executes the projected absence emit **and** the unchanged positive-presence emit; graced executes only the first. Held therefore charges more steps and heap than graced. These are two authored emission sites, not duplicate execution of one site.

   Prefix an unconditional row insert and set the step ceiling to the graced execution’s total: graced commits the row, held refuses and rolls it back. The rollback follows [mod.rs:871](snapback4/crates/snapback4-core/src/engine/mod.rs:871).

   This also occurs with one guard and a shared payload value:

   ```quarry
   online = exists connected[p]
   if not online:
     emit notify { online: online and true }
   ```

   Preserving the payload’s ordinary boolean makes held execute the lowered assignment for `and true`; grace skips it. That setup is correctly not projected, but held consequently costs more. Boolean lowering is explicit at [expr.rs:306](snapback4/crates/snapback4-lang/src/bind/program/expr.rs:306).

   **Smallest fix:** add both composition regressions and resolve the meter contract before landing. Universal R4 cannot coexist here with unchanged positive/payload execution and unchanged graced charges. A presence-independent reservation needs an explicit adjustment to R2; hiding the additional work or changing payload values would violate the brief. R3’s permitted discrepancy must also be reported.

   The ignored six-byte conjunction defect remains pre-existing and out of scope. This change extends execution of that affected arm to held recipients; I found no evidence that it increases that particular six-byte gap. The counterexamples above are separate.

2. **High — Setup discovery can perform exponential work outside the meter.**  
   **Location:** [presence.rs:284](snapback4/crates/snapback4-core/src/engine/presence.rs:284), [presence.rs:294](snapback4/crates/snapback4-core/src/engine/presence.rs:294), [presence.rs:325](snapback4/crates/snapback4-core/src/engine/presence.rs:325).

   Concrete source shape:

   ```quarry
   effect audit
   mutation push(p: principal):
     a0 = true
     a1 = a0 = a0
     a2 = a1 = a1
     -- repeat through a30
     if a30:
       emit audit { online: exists connected[p] }
   ```

   The payload enables effects-only presence analysis. The independent guard has both proof bits set, so `needed_setups` walks its inputs despite there being no relevant boolean setup. Each equality follows the previous binding twice: approximately \(2^{30}\) visits for thirty cheap assignments. Only `$bool` guard setup has a visited flag; ordinary bindings have none.

   This walk has no meter calls and runs while mutation holds the engine lock, blocking commits, poll registrations and worker claims. Skipping independent top-level guards alone is insufficient: placing the same alias chain in an independent operand of a qualifying absence guard exposes the same repeated traversal.

   **Smallest fix:** process each binding definition/version at most once during marking, prune independent inputs, and add a bounded-work regression for this alias DAG. Keying only by variable name would mishandle reassignment.

3. **Medium — Server projection remains in the device artifact.**  
   **Location:** [presence.rs:41](snapback4/crates/snapback4-core/src/engine/presence.rs:41), [runner.rs:444](snapback4/crates/snapback4-core/src/engine/runner.rs:444), [journal:31496](snapback4/JOURNAL.md:31496).

The web device already disables that feature. Preserve the old proof/dependency machinery needed for prediction. [device Cargo.toml:17](snapback4/crates/snapback4-device/Cargo.toml:17).

   That excludes wasm, **not native devices**, which also enable SQLite. Excluding both device builds requires a separate server feature rather than treating SQLite as a complete server/device distinction.

4. **Medium, wording — Absolute promises exceed the implemented guarantee.**  
   **Location:** [effects card:61](snapback4/crates/snapback4-lang/src/guide/effects.rs:61), [README:1014](snapback4/packages/snapback4/README.md:1014).

   A next poll arriving after its dependency deadline does not cancel. An effect with a short policy deadline can become `failed` before its presence deferral ends; worker failures, cancellation and lease retries retain their existing semantics. Therefore “never dropped” cannot mean guaranteed notification delivery. The retained “prediction … pays at least their server cost” sentence is also contradicted by the explicitly ignored baseline defect.

   **Smallest fix:** describe durable admission despite a held poll, qualify cancellation with “within its window,” and replace the absolute reservation claim with the accurate statement that prediction charges safe untaken presence arms. Keep the dispatch-time pattern, which remains correctly documented.
