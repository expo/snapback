### 1. Automatic bridge trigger and compatible set are undefined

§20 says "if current-source values widen a predecessor column" then compile a bridge, refusing on "incompatible type." Prior law distinguishes static domain comparison from exact data preview, and §8 lists the closed compatible-join set (optionality union, int bounds, text bounds, enum union, asset byte-limit, list recursion; all else stays target-domain).

Fix: state the trigger is static domain comparison per §16/§8, inherit the §8 compatible-join list verbatim, and require everything else to stay refused or need authored scalar `down`. Define precedence: authored `down` wins over auto-bridge; overlapping `down` outputs still refuse per §19.1.

### 2. Atomic registry selection across deploy/rollback/forward/interruption

Manifest idea is right, but lifecycle is missing:

- Partial failure: if one predecessor bridge fails compilation, the whole deploy must refuse atomically. State it.
- Ambiguous commit: "failed deployments remove their prepared views" contradicts §16 history-authoritative recovery. Distinguish definitive refusal (remove numeric candidate/stage) from committed-or-ambiguous (preserve source for recovery). Uncommitted parents must never authorize selection, but ambiguous ones must not be GC'd.
- Supersession: "later deploys recompute" vs "rollback does not discard newest registration" leaves two live manifests. State which manifest `rollback --to N` resolves (latest committed deployment's entry for N), that bridge ids never become the `latest/current` pointer, that `releases` labels bridge vs ordinary identities, and that restart/cold/hot attach the database-selected actual bridge id with original N as provenance.
- CAS inputs: state expected-current plus activation-revision check and digest verification over bridge source/native/worker per §5.
