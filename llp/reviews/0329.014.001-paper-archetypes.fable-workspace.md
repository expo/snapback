# Paper archetype: document workspace (Vellum) against LLP 0329.014.000

**Respondent:** Claude Fable 5 · **Design:** LLP 0329.015.001 (Opus), fixed · **Target:** LLP 0329.014.000 v0.

Headline. The spec's sentence "tree … turns recursive ACL and subtree operations into one indexed read plus a bounded `patchWhere`" (§2) is **false for the rule grammar as written**: a §3 rule cannot say "the nearest self-or-ancestor grant along `path` wins, and a denial stops the walk". That gap alone refuses 20 of 29 operations. Second: a program-level subtree update runs under caller visibility, so trashing a folder hides only what the trasher can see, and `check` says nothing — K2's wrong answer on the write side. L1–L8 are §6 items.

### 2. Schema in v0

Roles are integer ranks (`text` compares by codepoint); `0` is a denial. Lines marked `// L…` are §6 deltas, **not** spec features.

```ts

// ranks: none 0 · viewer 1 · commenter 2 · editor 3 · owner 4
const wsRank   = (ws, p) => db.get(workspaceMemberships.byWsPrincipal, [ws, p])?.rank ?? 0
const isMember = ws => wsRank(ws, viewer) >= 1
const effRank  = (n, p) => wsRank(n.workspaceId, p) === 4 ? 4                        // L1: `nearest` is not in §3
  : (db.nearest(nodeGrants.byNodePrincipal, [p], { along: n.path, self: n.id })?.rank ?? wsRank(n.workspaceId, p))
const live     = n => n.trashEventId === null && n.hiddenByEventId === null
const parentOk = n => db.get(nodes, n.parentId).kind === 'folder' && db.get(nodes, n.parentId).workspaceId === n.workspaceId
const nodeRank = x => effRank(db.get(nodes, x.nodeId), viewer), rootRank = e => effRank(db.get(nodes, e.rootNodeId), viewer)
// A redemption confers nothing by itself: link, path and the minter's *current* rank are re-derived on every read (I6).
const viaLink  = n => { const r = db.get(linkRedemptions.byNodePrincipal, [n.id, viewer]); const l = r && db.get(shareLinks, r.shareLinkId)
  return live(n) && !!l && r.status === 'active' && l.status === 'active' && n.path === l.pathAtMint && effRank(n, l.minterPrincipal) >= l.rank }

  .rules({ read: w => isMember(w.id) || w.createdBy === viewer, insert: w => w.createdBy === viewer,
           update: (o, w) => wsRank(o.id, viewer) === 4, delete: never })

export const workspaceMemberships = table({ id: id(), workspaceId: ref(workspaces), principal: principal(), rank: int(),

    delete: m => (m.rank !== 4 || db.get(ownerCount, [m.workspaceId]).n > 1) && (m.principal === viewer || wsRank(m.workspaceId, viewer) === 4) })

maintain.count(workspaceMemberships, { by: ['workspaceId'], where: m => m.rank === 4, as: ownerCount })

  .rules({ read: n => isMember(n.workspaceId) && (effRank(n, viewer) >= 1 || viaLink(n)),

export const docBodies = table({ id: id(), nodeId: ref(nodes), body: text({ max: 1_000_000 }), revision: int(), updatedBy: principal(), updatedAt: time() })

export const nodeGrants = table({ id: id(), nodeId: ref(nodes), workspaceId: ref(workspaces), principal: principal(), rank: int() /* 0 = denial */,

export const trashEvents = table({ id: id(), workspaceId: ref(workspaces), rootNodeId: ref(nodes), restoreParentId: ref(nodes), trashedBy: principal(),

  .rules({ read: e => rootRank(e) >= 1, insert: e => e.trashedBy === viewer && rootRank(e) >= 3, update: (o, e) => rootRank(o) >= 3 || principal.kind === 'system', delete: never })

export const shareLinks = table({ id: id(), workspaceId: ref(workspaces), nodeId: ref(nodes), tokenHash: text({ max: 64 }), rank: int(),

    delete: never })

  .rules({ read: r => r.principal === viewer || nodeRank(r) >= 3,
    insert: r => r.principal === viewer && r.status === 'active' && db.get(shareLinks.byToken, [r.tokenHash])?.id === r.shareLinkId,   // L6 in a rule
    update: (o, r) => o.principal === r.principal && (r.principal === viewer || principal.kind === 'system'), delete: never })
schedule(expireLease, { at: r => r.leaseExpiresAt, key: r => r.id, principal: 'system' })

export const accessEvents = table({ id: id(), workspaceId: ref(workspaces), nodeId: ref(nodes), kind: text({ max: 12 }), actor: principal(),

  .appendOnly().index('byWsAt', ['workspaceId', 'at'])
```

Time never appears in a rule: link and lease expiry are `schedule` transitions on `status`, the design's own ruling; `interval` is not needed.

### 3. Operations in v0

Grouped as the design groups them; certificates are in §1.

**The gating rule.** First attempt: the design's walk as a helper — `for` over `[n.id, ...ancestorIds(n.path)].reverse()`, `get` on `byNodePrincipal`, early `return` — called from `nodes.read`. `check`: **`E_OPAQUE`** at `nodes.read` — *rule bodies are algebraic predicates; `for`/`return` are statements (§3). Rewrite: `exists`/`get` over shape keys.* No paste does it: a 32-level nested ternary over chained `get`s costs 64 probes per row, and the key clause ("fields of the row, `viewer`, literals") does not clearly admit keys from probed rows **[inferred]**. Every operation touching a node-anchored table is therefore `refused` in v0 and `plan` under L1; the code below assumes L1.

#### §3 Bootstrap and perimeter

`createWorkspace` inserts the workspace, the owner seat, and the root node (`parentId: null`; `path`/`depth` are the engine's) with `ctx.newId()`/`ctx.now()`. `inviteMember`, `acceptInvite`, `setMemberRole`, `removeMember` are one `insert`/`update`/`delete` each, keyed by `byWsPrincipal`. First attempt for the three transitions used `update: m => wsRank(m.workspaceId, viewer) === 4 || m.principal === viewer` — admitted, and it lets an invitee set themselves to rank 4. The design's seven-row transition table relates the **old** row to the **new**; §3 gives a rule one row, so `check` emits nothing — **a wrong answer, not a refusal** (L5). The last-owner guard reads `ownerCount` inside the rule: the maintained row is traced, so two concurrent "remove the other owner" commits conflict under §6 OCC.

#### §4 M1 createDocument / createFolder

```ts
export const createDocument = mutation({ parentId: id(nodes), title: text({ max: 200 }), kind: text({ max: 6 }) }, ({ db, ctx, args }) => {
  const parent = db.get(nodes, args.parentId); db.require(parent && live(parent), 'NODE_NOT_FOUND')
  db.require(args.title.trim().length >= 1, 'TITLE_INVALID')
  db.require((db.get(nodeCount, [parent.workspaceId])?.n ?? 0) < 100_000, 'WORKSPACE_NODE_LIMIT')      // per-workspace max → §7
  const nodeId = ctx.newId(), now = ctx.now()
  db.insert(nodes, { id: nodeId, workspaceId: parent.workspaceId, parentId: parent.id, kind: args.kind, title: args.title.trim(),
                     trashEventId: null, parentAtTrash: null, createdBy: ctx.viewer, createdAt: now, updatedAt: now })
  return nodeId })   // plus an empty docBodies row for kind 'doc'
```

First attempt: `Date.now()` → **`E_AMBIENT_TIME`**; `db.scan(nodes.byWorkspace, [ws], { take: 100_000 }).count()` → **`E_UNBOUND_COUNT`** with the `maintain.count` paste. Depth is `tree`, the title clash is `unique`, both sealed; parent-is-a-folder is the insert rule. `conditional`: the unique constraint can fail on a sibling the client cannot see. `renameNode`/`editDocumentBody` are one `db.update` each.

#### §4 M2 moveSubtree

```ts
export const moveSubtree = mutation({ nodeId: id(nodes), newParentId: id(nodes) }, ({ db, ctx, args }) => {
  const node = db.get(nodes, args.nodeId), target = db.get(nodes, args.newParentId)
  db.require(node && live(node) && target && live(target), 'NODE_NOT_FOUND'); db.require(node.parentId !== null, 'ROOT_IMMOVABLE')
  db.update(nodes, node.id, n => ({ parentId: target.id, updatedAt: ctx.now() }))      // cycle, depth, subtree size, path rewrite: engine
  return { moved: node.descendantCount + 1 } })                                          // plus an accessEvents row with affectedCount (L4)
```

First attempt copied the design: scan `nodes.byPath [prefix] take 5001`, `reduce` the max depth, `db.update` each descendant's `path`/`depth`. `check`: the `reduce` is a rank over rows the caller may not read → **`E_STRUCTURAL_COUNT`** (*rewrite: a maintained aggregate with declared `readable`, or let the `tree` constraint refuse*); writing `path` → **`E_CONSTRAINT`** (*tree-maintained column; write `parentId` only*). The double authorization walk is the `(old, new)` rule (L5). Concurrent `move(A→B)`/`move(B→A)` is refused at commit over authoritative state — the design's §5.5 closes by construction; `expectedParentId` is redundant with OCC on the traced row. I3 holds because the engine writes every descendant's `path` in the commit, so every subscription holding one re-runs its rules. `affectedCount` needs L4 (§4).

#### §4 M3 grantAccess · M4 revokeAccessAt

`grantAccess` is `db.require(effRank(node, args.principal) < args.rank, 'WOULD_BE_NOOP_INHERITED')` (L1 program-side) plus an upsert keyed on `byNodePrincipal`; everything else is the insert rule.

```ts
export const revokeAccessAt = mutation({ nodeId: id(nodes), principal: principal(), scope: text({ max: 9 }), acknowledgedAffected: int() }, ({ db, ctx, args }) => {
  const node = db.get(nodes, args.nodeId); db.require(node && live(node), 'NODE_NOT_FOUND')
  db.require(effRank(node, args.principal) >= 1, 'NO_ACCESS_TO_REMOVE'); db.require(wsRank(node.workspaceId, args.principal) !== 4, 'CANNOT_REVOKE_WORKSPACE_OWNER')
  const source = db.nearest(nodeGrants.byNodePrincipal, [args.principal], { along: node.path, self: node.id })
  if (args.scope === 'here') {                                              // option (b): delete a local grant, then write a rank-0 denial
    db.require(node.parentId !== null, 'DENIAL_UNSUPPORTED_AT_ROOT')
    if (source && source.nodeId === node.id) db.delete(nodeGrants, source.id)
    if (effRank(node, args.principal) === 0) return { mode: 'deleted-direct', affected: 1 }   // re-evaluated after the delete [inferred]
    db.insert(nodeGrants, { …rank: 0, origin: 'direct', originNodeId: source?.nodeId ?? null… }); return { mode: 'denied-here', affected: 1 } }
  db.require(args.scope === 'at-origin' && source, 'SCOPE_INVALID')
  const origin = db.get(nodes, source.nodeId)
  db.require(args.acknowledgedAffected === origin.descendantCount + 1, 'AFFECTED_COUNT_STALE')             // L4 + declared readable
  db.delete(nodeGrants, source.id); return { mode: 'deleted-at-origin', affected: origin.descendantCount + 1 } })
```

"Cannot grant above self", "subject is a member", "no denial for a workspace owner" and the 200-per-node cap are rule and `cap`, sealed. Option (b), denial rows, is native: negation is admitted and `nearest` returns the `0` at the nearest denial. The blast-radius number is this app's K2 item: `origin.descendantCount` counts rows the revoker cannot see and is admitted only because L4 declares `readable` and `check` records the disclosure; first attempt, `db.scan(nodes.byPath, [prefix], { take: 5001 }).count()` → **`E_STRUCTURAL_COUNT`**.

#### §4 M5 trashSubtree — the wrong answer `check` does not catch

First attempt, straight from the design:

```ts
for (const r of db.scan(nodes.byPath, [`${node.path}${node.id}/`], { take: 5_000 }))
  if (r.hiddenByEventId === null) db.update(nodes, r.id, x => ({ hiddenByEventId: evId }))
```

`check` **admits it**: `examined ≤ 5,001`, `maxRows = 5,000`, no diagnostic. But a program's `scan` is visibility-filtered. Alice, editor on `/Eng` and denied on `/Eng/Secret`, trashes `/Eng`: `/Eng/Secret/*` is never examined, stays un-hidden, and remains a live document to its own grantees inside a trashed folder. If a visible descendant carries a *lower* grant for Alice, its `update` rule fails and the whole trash aborts **[inferred]**. Neither is I4. This is K2's shape on the write side — a **structural write** over rows outside the caller's visibility — and the spec has no family for it (L2). Corrected, with `tree.inherit`:

```ts
export const trashSubtree = mutation({ nodeId: id(nodes) }, ({ db, ctx, args }) => {
  const node = db.get(nodes, args.nodeId); db.require(node && live(node), 'NODE_NOT_FOUND'); db.require(node.parentId !== null, 'ROOT_IMMOVABLE')
  const evId = ctx.newId(), now = ctx.now()
  db.insert(trashEvents, { id: evId, workspaceId: node.workspaceId, rootNodeId: node.id, restoreParentId: node.parentId, trashedBy: ctx.viewer,
                           trashedAt: now, restoredAt: null, purgeRequestedAt: null, purgedAt: null })
  db.update(nodes, node.id, n => ({ trashEventId: evId, parentAtTrash: n.parentId, updatedAt: now }))   // descendants: engine, unfiltered
  return { trashEventId: evId, hidden: node.descendantCount } })
```

Authority for hiding the subtree is the root's `update` rule, stated once — the design made the same choice implicitly with `ctx.db.elevated`. The design's revocation of links on the root is a loop over `shareLinks.byNode take 200`, exact under the cap (else `E_FANOUT`); since `viaLink` requires `live(n)` it is optional (§7).

#### §4 M6 restoreSubtree · emptyTrash

```ts
export const restoreSubtree = mutation({ trashEventId: id(trashEvents), fallbackParentId: id(nodes) }, ({ db, ctx, args }) => {
  const ev = db.get(trashEvents, args.trashEventId); db.require(ev && ev.purgeRequestedAt === null && ev.restoredAt === null, 'PURGED')
  const root = db.get(nodes, ev.rootNodeId); db.require(root && root.trashEventId === ev.id, 'TRASH_EVENT_NOT_FOUND')
  let dest = db.get(nodes, ev.restoreParentId), relocated = false          // restore-into-a-hole: refuse unless the caller chose a fallback
  if (!dest || !live(dest)) { db.require(args.fallbackParentId !== null, dest ? 'RESTORE_PARENT_TRASHED' : 'RESTORE_PARENT_GONE')
                              dest = db.get(nodes, args.fallbackParentId); relocated = true }
  db.update(nodes, root.id, n => ({ trashEventId: null, parentAtTrash: null, parentId: dest.id, updatedAt: ctx.now() }))   // hiddenByEventId re-derived; title/depth sealed
  db.update(trashEvents, ev.id, e => ({ restoredAt: ctx.now() })); return { restored: root.descendantCount + 1, relocated } })
```

I4 is the engine's: `hiddenByEventId` = nearest strict ancestor's non-null `trashEventId`, so `api-v2.md` (its own event) stays hidden while `api-v3.md` returns; restoring `api-v2.md` while `/Eng` is trashed clears its own event and it is at once hidden by `/Eng`'s. A restore parent the restorer cannot read is `null` (`RESTORE_PARENT_GONE`) — sealed and right. **emptyTrash** sets `purgeRequestedAt`; `schedule(purgeTrashEvent, { at: e => e.purgeRequestedAt, key: e => e.id, principal: 'system' })` scans `nodes.byHiddenEvent [ev.id] take 5000` (exact under L3) and deletes under `principal.kind === 'system'` — the v0-native route to an *unfiltered* structural write, asynchronous, so fine for purge and wrong for trash.

#### §4 M7 mintShareLink · M8 redeemShareLink

`mintShareLink` is one `db.insert` with `expiresAt: ctx.commitTime + args.ttlMs` — `ctx.now()` is client-bound inside a skew window and a security deadline is never caller-chosen. Rank ≤ minter's, the 50-active limit, `pathAtMint === node.path` are the insert rule. M8, first attempt: `db.get(shareLinks.byToken, [args.tokenHash])`. Admitted; `examined ≤ 1`. But `shareLinks.read` requires rank ≥ 3 on the node, so the `get` is `null` for exactly the people the feature exists for; every redemption is `LINK_INVALID` and `check` says nothing — the third silent wrong answer. Possession of a 256-bit key *is* the authorization (L6):

```ts
export const redeemShareLink = mutation({ tokenHash: text({ max: 64 }) }, ({ db, ctx, args }) => {
  const link = db.get(shareLinks.byToken, [args.tokenHash])           // bearer read; sets principal.bearerOf for this transaction
  db.require(link && link.status === 'active', 'LINK_INVALID'); db.require(link.maxUses === null || link.useCount < link.maxUses, 'LINK_EXHAUSTED')
  const node = db.get(nodes, link.nodeId); db.require(node && live(node), 'LINK_INVALID')   // readable via viaLink's bearer clause
  const lease = Math.min(link.expiresAt, ctx.commitTime + 3_600_000)      // a prior active redemption only refreshes its lease
  db.update(shareLinks, link.id, l => ({ useCount: l.useCount + 1 }))     // bearer-admitted update (L6 clause)
  db.insert(linkRedemptions, { id: ctx.newId(), shareLinkId: link.id, nodeId: link.nodeId, principal: ctx.viewer, tokenHash: args.tokenHash,
                               status: 'active', leaseExpiresAt: lease, redeemedAt: ctx.commitTime })
  return { nodeId: link.nodeId, rank: link.rank, leaseExpiresAt: lease } })
```

Two redemptions at `useCount = maxUses − 1` both trace the link row; OCC rejects one. Prediction `partial`: no closure holds the link row before the intent.

#### §4 M9 revokeShareLink · M10 expiry

`revokeShareLink` is one `db.update` to `status: 'revoked'`. First attempt copied the design's `take(1001)` loop over redemptions — admitted (the cap makes it exact) and **unnecessary**: a redemption has no authority; `viaLink` reads the link row, so it is in every link reader's trace and one write retracts every session. The bug the design calls "the single most likely in the app" cannot be written. First attempt at M10 was the sweep over `byStatusExpires` with `lte: now` → **`E_AMBIENT_TIME`** (*rewrite: `schedule(…, { at: l => l.expiresAt })`*). `expireShareLink`/`expireLease` are one `get` + one `update` under the system principal; expiry lands within one schedule period, revocation is instant — the design's own ruling.

#### §4 M11 readDocument · M12 listFolder · the queries §4 implies

```ts
export const readDocument = query({ nodeId: id(nodes) }, ({ db, ctx, args }) => {
  const n = db.get(nodes, args.nodeId); if (!n || !live(n)) return null
  const b = db.get(docBodies.byNode, [n.id]); return b && { title: n.title, body: b.body, revision: b.revision, rank: effRank(n, ctx.viewer) } })

  return { children: db.scan(nodes.byParent, [f.id], { take: 500 }).filter(live).map(k => ({ id: k.id, kind: k.kind, title: k.title })) } })
export const breadcrumbs  = query({ nodeId: id(nodes) }, ({ db, args }) =>
  recurse(db.get(nodes, args.nodeId), x => db.get(nodes, x.parentId), { depth: 32, fanout: 1 }).map(x => ({ id: x.id, title: x.title })))
```

`listTrash`, `shareDialog`, `myWorkspaces` and `auditLog` are single `scan`s (`take` 100 / 200+200 / 50 / 100) with `get` joins.

Under D-F the only schema split the diagnostic could suggest is a materialized effective-ACL table — the option (c) fan-out the design rejected — so the hoisted lowering is a requirement of the archetype. `breadcrumbs` stops at the first unreadable ancestor because each `get` passes `nodes.read` — Drive's "Shared with me" crumb for free; no `channel` or `effect` appears.

### 6. Language delta

Ranked by operations unblocked and by how wrong the answer is without it.

1. **L1 — `nearest`: a rule and program primitive over `tree` tables.** *What:* §2 promises `tree` turns recursive ACL into one indexed read; §3's grammar cannot express "nearest self-or-ancestor row along `path` wins; a denial stops the walk". 20 of 29 operations are refused. *Smallest addition:* `db.nearest(index, [key…], { along: row.path, self: row.id })` where the index's leading column is the tree's id; returns the first row found walking self → root, or `null`. Two lowerings, both in the certificate: point probes (≤ `maxDepth + 1`) and — when the key is pinned by `viewer` and a companion index `[key…, workspaceId]` under a `cap` exists — one hoisted scan plus O(depth) pure steps per row; the second is mandatory for per-child listings (§3 M12). Denials need nothing new. *General* (org charts, categories, threads). Amends §3, §4.2, §5.
2. **L2 — `tree.inherit` and the `E_STRUCTURAL_WRITE` family.** *What:* a program-level subtree update is visibility-filtered and `check` admits it (§3 M5). *Smallest addition:* `tree({ inherit: { hiddenByEventId: 'trashEventId' } })` — each row's value is the nearest *strict* ancestor's non-null source column, rewritten by the engine in the same commit as `path`, unfiltered, authorized by the root row's `update` rule. Plus `E_STRUCTURAL_WRITE`: *a write selected by a `tree` prefix scan under caller visibility; rewrite: an `inherit` column, or a `system` schedule.* *General.* Amends §2, §4.2 (K3's "bound = the scan's `take`" is not enough when the scan is structural), §9.
3. **L5 — `update: (old, new) => …` rules.** *What:* a one-row rule cannot express a transition; the membership transitions, "take it out AND put it in", and revision monotonicity all silently admit wrong writes. *Smallest addition:* `update`/`delete` rules receive the preimage; `immutable(fields)` becomes a special case. *General.* Amends §3.
4. **L6 — bearer-keyed unique index.** *What:* `get` by a secret key returns `null` to the principals a share link exists for (§3 M8); no diagnostic. *Smallest addition:* `unique(name, cols, { bearer: true })` — a point `get` with the *full* key is admitted to any principal (`scan`/`exists` refused), and `principal.bearerOf === key` is a rule input for the rest of the transaction, so the node, the redemption and `useCount` admit the bearer explicitly. Emits a security item. *General* (invites, magic links, resets). Amends §2, §3, §4.2, §5.
5. **L3 — `tree.maxSubtree` and a stated write bound.** *What:* "a bounded `patchWhere`" names no bound; `writeSites[].maxRows` for a `parentId` write is undefined; `SUBTREE_TOO_LARGE` has no home. *Smallest addition:* `maxSubtree: N`; the certificate carries `engineWrites ≤ N`; above it, sealed `E_CONSTRAINT`. *General.* Amends §2, §5.
6. **L4 — `tree.count`: maintained per-node descendant count with `readable`.** *What:* blast radius, audit `affectedCount`, `hiddenCount` are prefix aggregates no `maintain.count … by` expresses. *Smallest addition:* `count: 'descendantCount'`, ±1 on ≤ `maxDepth` ancestors per insert/delete, ±k on a move, `overflow: 'refuse'`, K2's `readable`. *General.* Amends §2.
7. **L7 — bounds from a parent row.** *What:* per-workspace `maxDepth`/`maxNodes` are columns; `cap`/`tree.maxDepth` take literals. *Smallest addition:* `max: ref(workspaces, 'maxNodes')` through the `by` key. *App-leaning*; §7 takes the product change. Amends §2.
8. **L8 — clarifications.** (a) rules may `get` a maintained aggregate (§3 lists only indexes); (b) `cap.by` may be composite; (c) a `system` principal's *reads* are unfiltered only where a `read` rule says so — §7's "read elevation is never needed to settle" is false for purge. Amends §2, §3, §7.

Not needed here: `interval`, `exclusion`, `sum`, `tokens`, `channel`, `effect`, `readTime`. The archetype exercises the tree, the rule grammar and write authority, not time or money.

### 7. Product changes

| product change | what it dodges | acceptable when | a cheat when |
|---|---|---|---|
| global `maxDepth = 32`, `maxNodes = 100,000` literals instead of per-workspace columns | L7 | one plan tier; the limits are integrity ceilings | tiers or enterprise quotas exist — then L7, not a sweep |
| link expiry "within one schedule period"; revocation instant | clock in rules | the design's own ruling with its three exclusions (legal deadline; link is the only control; window > exposure) | any of those three |
| no hidden-child count in `listFolder` | a K2 `readable` disclosure on `nodes` | the design's own ruling | shipping the static string, then adding the number without the declaration |
| trashed subtree makes links *inert* (`live(n)` in `viaLink`) instead of permanently revoking | a ≤ 200-row loop that is admitted anyway | restore should revive links | chosen to avoid the loop rather than because revival is wanted |
| redemption rows are witnesses; `revokeShareLink` is one write | fan-out on revoke, the design's "most likely bug" | always — strictly stronger | never |
| `maxUses` as a `cap` on redemptions instead of a per-link counter | L6's bearer-update clause | `maxUses` is a product constant | per-link `maxUses` is a feature |

Boundary, in the ledger's terms: legitimate when the simpler product is wanted for itself, a cheat when adopted to protect the backend while still claiming offline prediction. No row above weakens prediction; the two touching security are the design's own rulings.

### 8. Where the design is wrong

1. **I6 is not enforced by the design's own `readDocument`.** The invariant says a link stops working when the node moves or the minter loses access; M8 checks both at redeem only, and M11 accepts any `revokedAt == null` redemption without re-deriving either. A redeemer who opened the document once keeps reading after `/Eng/Specs` moves to `/Legal` until the lease ends (≤ 1 h) — the "row records a decision, the world changes, nothing re-derives it" trap the design names in §2.1. *Confirming observation:* redeem, move the node with M2, call M11 as the redeemer inside the lease: it returns the body. v0's `viaLink` closes it because the re-derivation lives in the read rule.
2. **`workspaces.nodeCount` is disclosed to every member while per-folder hidden counts are refused as an oracle.** Both count rows the reader cannot see; the design withholds the fine-grained one and syncs the coarse one to everyone. *Confirming observation:* a viewer with access to one document subscribes to the workspace row and watches `nodeCount` tick on every creation in folders they cannot see. K2's `readable` makes the author choose; the design never did.
3. **Sibling-title uniqueness collides with trash.** Trash does not reparent, so a trashed `notes.md` still holds `(parentId, 'notes.md')`; creating a new `notes.md` there is refused by the unique index — sealed, if the trashed row is invisible to the creator. The design handles the restore-time collision, not the create-while-trashed one. *Confirming observation:* M5 on `notes.md`, then M1 with the same title under the same parent → unique refusal; Drive and Notion allow it. The fix — `unique(['parentId', 'title', 'trashEventId'])` or reparenting on trash — is a product decision the design does not state.
