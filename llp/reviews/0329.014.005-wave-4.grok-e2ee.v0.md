### 2. Schema in v0

Viewer = **device id** (v1.1 identity). `openEnd = 0` means an open interval (v0 has no `optional`; v1.1 `optional` would replace sentinels). Ciphertext is `json({maxBytes})` because v0 has **no `bytes`**. `seqSpan: interval({from,to})` is used on **sequence**, not ms — **not v0 as written** (see §6). v1.1 used where marked.

#### §5.1 Link a device

**First attempt** (agent-shaped):

```ts
export const linkDevice = mutation({ /* keys, cert, expectedVersion, allGroupCommits: Unbound */ }, ({ db, args }) => {

  for (const g of db.scan(memberships.byAccountOpen, [accountId])) enroll(g) // unbound
```

**§9 diagnostic:** `E_OPAQUE` at `verify` — *rewrite: a total builtin `verifySignature(pk, msg, sig)` or a `host` identity check; do not call JS*. `E_UNBOUND_LOOP` on groups — *rewrite: CAS the account roster here; return a page of group ids; enroll with `addLinkedDevice` per group*. `E_FANOUT` if `hasMore`.

**Corrected (account atomic piece):**

```ts
export const linkDevice = mutation({
  cert: text({ max: 4096 }), signingPublicKey: text({ max: 128 }), groupInitPublicKey: text({ max: 256 }),
  expectedVersion: int(), rosterDigest: text({ max: 64 }), priorHash: text({ max: 64 }),
  accountSignature: text({ max: 256 }),
}, ({ db, ctx, args }) => {
  const actor = db.get(devices, ctx.viewer)
  db.require(actor && actor.revokedVersion === 0, 'revoked')
  const acct = db.get(accounts, actor.accountId)
  db.require(acct && acct.deviceRosterVersion === args.expectedVersion, 'stale_version')
  // MISSING: verifySignature(acct.identityPublicKey, args.cert, args.accountSignature)
  db.require(args.signingPublicKey !== actor.signingPublicKey, 'not_independent') // not crypto-strong
  const newDev = ctx.newId()
  db.update(accounts, acct.id, a => ({ ...a, deviceRosterVersion: a.deviceRosterVersion + 1 }))
  db.insert(devices, { id: newDev, accountId: acct.id, accountSignedCert: args.cert,
    signingPublicKey: args.signingPublicKey, groupInitPublicKey: args.groupInitPublicKey,
    addedVersion: args.expectedVersion + 1, revokedVersion: 0 })
  db.insert(transparencyEntries, { id: ctx.newId(), accountId: acct.id,
    deviceRosterVersion: args.expectedVersion + 1, rosterDigest: args.rosterDigest,
```

#### §5.2–5.3 Add / remove (the atomic metadata+commit write)

**First attempt:** loop current leaves, `hash(publicCommit)`, insert N control rows, N push rows.

**Corrected:**

```ts
  nonce: text({ max: 64 }),

  const prior = db.get(idempotency.byDeviceNonce, [ctx.viewer, args.nonce])
  if (prior) return { resultId: prior.resultId, replay: true } // still racy: use insertIfAbsent (v1.1)

          seqSpan: { from: x.startSequence, to: q } }))

      }

    db.require(!openLeaves.some(l => l.deviceId === ctx.viewer && l.accountId === args.targetAccountId), 'committer_not_retained')
  } else {

    for (const p of args.packages) { // max 5
      db.insert(leaves, { id: ctx.newId(), groupId: args.groupId, deviceId: p.deviceId,
        accountId: args.targetAccountId, leafIndex: 0, startEpoch: newEpoch, endEpoch: 0,
        startSequence: q + 1, endSequence: 0, seqSpan: { from: q + 1, to: 0 }, barrier: false })

  db.require(digestRoster === args.newRosterHash, 'roster_mismatch')
```

#### §5.4 Send (also reactions, receipts, FirstOpened as **the same** outer mutation)

**First attempt:**

```ts
export const sendEvent = mutation({
  groupId: id(groups), eventId: id(), nonce: text({ max: 64 }),
  epoch: int(), membershipVersion: int(), composedRosterHash: text({ max: 64 }),
  ciphertext: json(CT), ciphertextDigest: text({ max: 64 }), paddedSizeBucket: int(), blobId: id(opaqueBlobs),
}, { serialBy: a => a.groupId }, ({ db, ctx, args }) => {
  const hit = db.insertIfAbsent(idempotency, { id: ctx.newId(), deviceId: ctx.viewer, nonce: args.nonce,
    requestDigest: args.ciphertextDigest, resultId: args.eventId, committedVersion: 0 }) // v1.1
  if (hit === 'already_acted') return db.get(opaqueEvents.byId, args.eventId)
  const g = db.get(groups, args.groupId)
  db.require(g && g.state === 'active' && g.cryptoEpoch === args.epoch
    && g.membershipVersion === args.membershipVersion, 'stale_or_paused')
  db.require(g.rosterHash === args.composedRosterHash || /* removal-only rebase is LOCAL; if hash grew, client must not call */ true, 'audience')
  // The server CANNOT see whether recipients were added. Audience confirm is PV/local.
  // If we required composedRosterHash === g.rosterHash, removal-only rebase still works (hash changed too!).
  // Product: client confirms; server only checks epoch. Hash check as equality is a product-change (rejects removal-only rebase).
  db.require(args.paddedSizeBucket <= 256, 'too_big')
  const seq = g.nextSequence
  db.update(groups, g.id, x => ({ ...x, nextSequence: x.nextSequence + 1 }))
  db.insert(opaqueEvents, { id: args.eventId, groupId: args.groupId, groupSequence: seq,
    epoch: args.epoch, membershipVersion: args.membershipVersion, senderDeviceId: ctx.viewer,
    ciphertext: args.ciphertext, blobId: args.blobId, ciphertextDigest: args.ciphertextDigest,
    paddedSizeBucket: args.paddedSizeBucket, acceptedAt: ctx.commitTime, payloadAlive: true })
  db.insert(wakes, { id: ctx.newId(), groupId: args.groupId, groupSequence: seq, state: 'pending' })
  return { sequence: seq, acceptedAt: ctx.commitTime }

```

**K2:** recipient set is **not** a count; it is the historical `leaves.seqSpan.contains(seq)` (invariant 9) — never recalculated. A silent visibility-filtered insert of outbox rows would **drop** hidden siblings (trap 2). Shared log avoids that.

Prediction: **partial** — `nextSequence` and `commitTime` are commit-bound; local pending bubble is args (closed for ciphertext, partial for order). UI must keep pending until receipt. `predict: false` is honest for ordering; refusing prediction of the *bubble* is a cheat against messenger UX — the bubble is not a server row.

Draft/quote audience: **not this mutation**. See PV ops.

#### §5.6 Drain and ack

**First attempt:**

```ts
export const drainEvents = query({ groupId: id(groups), after: int(), take: int({ max: 100 }) }, ({ db, ctx, args }) =>

```

**This is the K2-class wrong answer.** v0.1 ruling 2: post-removal (and other devices’ non-entitled) rows **consume `take`**. **§9 family:** `E_SEQUENCE_VISIBILITY` (v1.1 paste) / ruling 2. **Rewrite:** pin the scan to the caller’s entitlement interval so the rule is *uniform-true*:

```ts
export const drainEvents = query({ groupId: id(groups), stintId: id(leaves), after: int(), take: int({ max: 100 }) },
  ({ db, ctx, args }) => {
    const q = db.get(queues.byStint, args.stintId)
    db.require(q && q.deviceId === ctx.viewer, 'not_your_queue')
    const end = q.entitlementEnd === 0 ? Number.MAX_SAFE_INTEGER : q.entitlementEnd
    return db.scan(opaqueEvents.byGroupSeq, [args.groupId], {
      order: 'asc', take: args.take, after: Math.max(args.after, q.entitlementStart - 1),
      range: { gte: q.entitlementStart, lte: end },
    })
  })
```

Byte limit: v0 `take` is rows. Certificate uses worst-case `paddedSizeBucket` max × take. Product-change to row pages (cheat if it silently truncates a 45-day catch-up without `hasMore`).

#### §5.7–5.10 Local decrypt, search, reaction, read, disappearance

**First attempt** (the cheat the traps name): `tokens('body')`, `mentionedAccountIds: ref[]`, `maintain.count(reactions)`, `scan(search.byToken)`, server `delete` on timer.

**§9:** not a refusal that saves you — these **admit a wrong security program**. `tokens` + inverted scan is a live retained query the operator can run. That falsifies promises 1, 12–15 and invariants 2, 12, 13.

Honest class: **premise-violation** of *rules the server can evaluate*, *one query class*, *trace = offline closure*, *store-wide fence*.

Broken looks like:
- a **second evaluation class** (deterministic reducers + FTS over plaintext the certificate never saw);
- a **guarantee that cannot hold**: receipt `exhausted` ≠ “search complete” (new device, 45-day gap, missed history transfer);
- the **fence** evicts or refuses to retain unbounded local history (`maxOfflineAge` 7d hard vs million-message desktop).

Honest outcome: **new dimension** (authority placement: content-opaque, device-authoritative partition) paved as a **new kind** `endpointReducer` / `localQuery` (`live: no` as a *server* sub, not retained, not in the twin, completeness local). Smallest addition that would make *search* a “plan”: **none on the server**. Making it a plan is the cheat.

Reaction/read/expiry **sends** reuse `sendEvent`. Optimistic emoji is an **app-authored optimistic reducer** (v0 forbids). That is required UX, not a data-plane prediction.

After-send expiry uses `acceptedAt` (metadata, OK). After-view uses `accountSync`. Server GC is 45-day custody, not the timer.

### 8. Where the design is wrong

1. **Hidden-take drain vs historical entitlement.** The design treats `OpaqueEvent` as one group log and queue access as an interval, but never states that a visibility-filtered scan of that log is an admissible implementation. Under v0.1 ruling 2 it is not: former members (and any non-uniform rule) **starve or observe `hasMore` as a hidden-traffic oracle**. Confirming observation: after removal at `q`, a drain with `take: 100` and `after: q-50` returns **0 rows** while the group continues at 5 events/s, `hasMore=true`, and pre-`q` ciphertext is still on the server.

2. **Atomic revoke barrier vs unbounded groups-per-account.** Account revoke is specified as atomic with a send barrier on *every* group that still contains the leaf; group rotations are allowed to be resumable. No bounded program can pause an unbounded reverse index in one certificate, and a job is the confidentiality gap the design itself calls a cheat. Confirming observation: an account in 2,000 groups; revoke commit returns; a send in group #1,847 is **accepted at the old epoch** and decrypts on the stolen laptop.

3. **“Complete history / complete search” is underspecified relative to 45-day custody and no operator recovery.** Promise 12’s UI states and op 7’s labels do not bind “complete” to a recoverable source after local loss. Receipt exhaustion on post-join ranges will read **complete**. Confirming observation: reinstall without vault or sibling transfer; drain `hasMore=false`; search UI = complete; a message from day −60 is absent and unrecoverable.

(Related under-spec, not counted as a fourth: whether interval close at `q` is inclusive for the removed device and how a concurrent `sendEvent`/`applyTransition` share `serialBy` at the same `nextSequence`.)
