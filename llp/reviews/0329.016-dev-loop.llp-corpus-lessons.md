### 1.2 Authoring "spellings" and profiles

The corpus counts **two authoring profiles** and, inside the default one,
several orthogonal dialect axes that multiply:

- **Explicit** (`snapback-explicit-v1`, `.mjs`): the default; "front-loaded
  declaration ceremony but made authority boundaries legible and reviewable"
  (Diary 0114).
- **Familiar** (`snapback-familiar-ts-v1`, `schema.ts` + `query()`/`mutation()`
  + `useQuery`): the Convex-familiar experiment of LLP 0252 ("hardened Convex"
  as design shorthand, "never 'Convex-compatible'"), lowered by a codegen
  adapter into the same canonical definition. Experimental and fenced by LLP
  0259 ("This RFC never makes Familiar the default"); had **no template** until
  the `familiar-react` packet appeared on 2026-08-29 (LLP 0317 O31: "every
  Familiar lane scaffolded an Explicit template and converted it by hand").
- **Tiny** (LLPs 0254–0256): a third doorway, withdrawn and tombstoned
  2026-08-15.
- Inside Explicit, LLP 0319 §2 decomposes the query family into four axes —
  implementation (declarative plan · JS handler), reactivity (one-shot · live),
  access shape (scan · search · vector · relational · graph · bounded-children),
  result shape (rows · snapshot batch) — "roughly three orthogonal axes
  flattened into a name list, so the vocabulary grows multiplicatively."
  Mutations likewise: `defineMutation` (plan IR) vs `defineJsMutation`
  (handler), plus `mutationPlan` as an *authored* expression language beside
  a JS VM (LLP 0320 §1). Handlers themselves have two lanes: inline handlers
  in the bounded subset vs "legacy compatibility: bundled handler modules"
  (`guide/getting-started/your-first-backend.md` §Legacy compatibility).

LLP 0318 (Withdrawn) states the cost plainly: "we are paying for two surfaces
and defaulting to the one that lost the only head-to-head we ran."

### 1.3 What "codegen custody" means

The word *custody* carries three distinct meanings in the corpus, and an agent
meets all three:

1. **Codegen custody of `generated/`.** Codegen owns everything under
   `snapback/generated/`; authored seams are exactly `schema.mjs`,
   `functions.mjs`, `seed.json` (LLP 0261 §3: "`snapback/generated/` is
   codegen-owned: any generated contents are accepted and never resumed or
   rewritten by `init`"). It includes: the committed `artifacts.json` review
   surface; generation identity digests that bind the runtime and client
   (`SNAPBACK_APP_BINDING_IDENTITY_MISMATCH` is a custody check); TypeScript
   handler modules erased by a pinned transform that codegen, not the runtime,
   owns (LLP 0246: "The runtime … contains no TypeScript compiler"); staging
   of candidate graphs *outside* the project root so Metro's watcher does not
   race the `.tmp-*` directory (LLP 0310 Track C); the `.snapback/generations`
   backend artifact directory that still lives in-tree (LLP 0317 F1 residual).
2. **Client credential custody.** Where the session/principal record lives
   and who may write it: durable browser custody (IndexedDB + Web Locks —
   secure contexts only, LLP 0169), memory fallback, native SecureStore /
   Keychain custody (LLP 0258), sender-constrained custody (LLP 0260), the
   "custody adoption barrier" and single-writer rules that produce
   `SNAPBACK_AUTH_STALE_RESULT` / `SNAPBACK_OUTBOX_NOT_WRITER` /
   `SNAPBACK_CLIENT_AUTH_COMMIT_REENTRANT` (LLP 0317 O17, O18, O46), and the
   dev-identity capability (LLP 0262: "dev identity assertion stops being a
   bind inference and becomes a custody proof").
3. **State-capture custody** (LLP 0228): per-operation profiles for
   snapshot/restore/clone/fork/export that decide which files are copied,
   scrubbed, rotated, shared, or refused.

The agent must reason about (1) to edit safely, (2) to make a second persona or
a full-page navigation work, and never about (3) — but the shared word makes
retrieval collide.

### 1.4 The guide / packet system and why it exists

- **Why a guide at all (LLP 0061, 2026-07-15).** "The knowledge exists, and
  authors can't find it": diary evidence that authors read Contract source
  for connection-state semantics and that "every demo re-derives the same
  starting knowledge." The remedy: "a single, current, agent-optimized map
  from intent ('I want to do X') to the paved-road technique," with runnable
  snippets verified by *execution* ("this ran", one level stronger than
  Exact's "this compiled"), an authored capability index with witnesses and
  explicit GAP rows, a pinned retrieval eval (relevant page within ~15 tool
  uses), and the corpus **embedded in the binary and always served**
  (§4a: "the server is the version authority"). The diary loop: friction a
  page should have prevented becomes a `guide-gap` ticket.
- **Why routing, not coverage (LLP 0187, 2026-08-06).** "Every replicated
  miss happened with the maximum possible documentation surface available …
  Writing more pages will not fix a failure mode in which existing, accurate
  pages are never reached." Installs the miss-to-eval rule: every replicated
  discoverability miss adds a retrieval-eval seed case.
- **Why a packet (LLP 0259, 2026-08-15).** The 2026-07/08 programs optimized
  for "never miss a capability"; by August agents "over-read, then explore
  every official-looking authoring surface, then debug closure and tooling
  seams that more prose will not cheapen." The mandated first read was ~100
  KiB (skill 14 KiB + index 24 KiB + capability index 58 KiB + a 20–55 KiB
  page) before the agent wrote a table; "The capability index is a good
  registry and a bad novel." Rung A: a template-specific, digest-checked
  start packet (≤16 KiB steering ceiling) + one named page on a trigger +
  further pages only after a structured refusal or failed `prove`.
- **Errors as docs (LLP 0193).** "every `SNAPBACK_*` refusal an authoring
  agent can trigger names the violated rule and either the fix or a
  resolving guide anchor" — audited once, then structural.
- **Measured cost anyway (LLP 0329 F5).** The 2026-08-21 eval runs all
  passed, and "the passing agents reached the correct page in 7, 11, and 12
  tool calls of a 15-call budget — before doing any work."

## 2. Lessons ledger

Format: **lesson** → evidence (LLP, section, quote) → what a from-scratch
design would do. Grouped by theme; numbering is continuous.

### A. The authoring surface

**L1 — Capability must not be a function of spelling.**
Evidence: LLP 0329 §Summary, the central claim: "**Capability is a function of
authoring form, and the mapping is invisible at the authoring site.**
Retention, live delivery, and offline replay are properties an author obtains
by choosing a spelling, and the consequence of that choice appears far from
where it was made." LLP 0329.000 §1 item 1: unanimous across three families.
From scratch: one language for the data plane in which every admitted program
gets every capability; the escape hatch is a different *kind* (effect), never a
different spelling of a query (LLP 0329.001 §2: "capability boundaries must
fall on concept boundaries").

**L2 — Admitted implies every capability; refuse, do not degrade.**
Evidence: LLP 0329.000 §1 item 4: "If the compiler accepts the program it is
live, realtime, and retainable; if those cannot be guaranteed, the program is
not a query." LLP 0329.003 §2: "Agents do not fill in matrices. They pick the
cell that compiles and document the rest as a known issue." Precondition from
LLP 0329.004: refusal is viable only if the language is expressive enough.
From scratch: a static certificate at `check` is the only gate (LLP 0329.014
§2 point 5); `partial` is an honest runtime state, never a silent
"unsupported".

**L3 — Everything derivable is derived; the author is forbidden to declare it.**
Evidence: LLP 0329 §Evidence 2: "`reads:`, `writes:`, `retainable`,
`authorityIndependent` are properties a compiler could derive from a closed
plan. They are authored because the handler alternative is opaque." LLP
0329.000 §1 item 5 (unanimous). LLP 0329.002 §1: "If the compiler can know it,
asking the agent to repeat it creates a new opportunity for contradiction."
From scratch: read/write sets, retention eligibility, invalidation keys,
indexes, the optimistic predictor, and the replay envelope are compiler
outputs; the certificate reports them beside the definition.

**L4 — Vocabulary size is an architectural constraint, not a docs problem.**
Evidence: LLP 0329 §Evidence 1 (140 names / 31 constructors / 13 flavors /
4,248 symbols); LLP 0329.001 §4: "A 178-page guide is not a documentation
problem, it is a *surface area* problem wearing a costume"; LLP 0329.003 §4:
"If you need a new `define`, you split the language. Stop." LLP 0329.002 §6
sets a budget: "two top-level exports for definition, fewer than thirty
language terms including scalar operators, and four generic client state
concepts. A new term must remove one or demonstrate that it cannot be
represented compositionally."
From scratch: a public-surface budget set before implementation; ~20–30
authoring names; the app's own table/query/mutation names are the product.

**L5 — The corpus could not converge by retrofit; simplification must be
made once at the substrate.**
Evidence: LLP 0329 §The 2026-08-27 convergence attempt: four RFCs (0318 one
profile, 0319 one constructor, 0320 plan IR as compiler output, 0323 tiered
surface) "were all **Withdrawn** after round 1 … each because review found its
premise false rather than its direction wrong. … the corpus can detect that it
has sprawled and cannot converge from where it stands." LLP 0329.014 §9: "Do
not retrofit any of this onto `define.mjs`."
From scratch: this is the license for a new substrate; the direction of the
four withdrawn RFCs is taken as settled, their retrofit method as refuted.

**L6 — Opaque handlers cannot be lifted later without changing race
outcomes.**
Evidence: LLP 0329 §Evidence 4 (on LLP 0320): "HostPlan mutations are
unconditional sequences against a client-supplied baseline while JS handlers
validate across a read-to-commit window, so 'translation can change race
outcomes,' and functions that fail to lift 'lose capability rather than just
performance.'" LLP 0329.003 §6: "The rebuild is not 'plan IR as compiler
output from JS.' The rebuild is 'JS is not in the data plane.'"
From scratch: no JS handler spelling in the data plane from day one; one
consistency model (trace-validated OCC) for every write.

**L7 — The expressiveness question comes before the affordability question,
and the answer is "restrict the computational class, not the operators".**
Evidence: LLP 0329.004 §Consequence: "can an analyzable read language express
bounded fan-out, grouped counts, multi-table derivation, and bounded graph
traversal … ?" LLP 0329.013 §Summary: "Expressiveness was never lost to
restriction. It was lost to a registry … every shape costs a Spec." LLP
0329.014 §Summary: the total property "is not algebraic closure. It is three
weaker properties — deterministic given `(snapshot, args, viewer)`, every data
access mediated by a typed, bounded, traced read API, and one semantics
executed on both server and client — plus one static gate."
From scratch: real `if`/`for` over statically bounded collections, reads only
through `get`/`scan(take)`/`exists`/`recurse`, helpers inlined; thirty-seven
paper applications needed no second query class on the server plane (LLP
0329.014.004 §Summary).

**L8 — The escape hatch was habitual on reads and structural on writes.**
Evidence: LLP 0329.005 (correcting 0329.004 F2): "45% of inline JS read
handlers use no capability the declarative surface lacks … the escape rate is
35% on reads and 74% on writes." LLP 0329.006: "A declarative mutation plan can
only read rows by primary key. Every write whose correctness depends on a
non-key lookup … must therefore be a JavaScript handler, and a JavaScript
handler forfeits optimistic prediction and cold retention." LLP 0329.010:
"every mutation step is implemented twice, and that dual implementation is
exactly why declarative plans get optimistic prediction and JS handlers do not."
From scratch: mutations get bounded non-key reads in the same language as
queries; one interpreter implements each step once and runs on both sides.

**L9 — The mutation text is the optimistic predictor; no app-authored
reducers.**
Evidence: LLP 0329.000 §1 item 6 (unanimous); LLP 0329.003 §2: "The predictor
*is* the mutation. If you need a prettier pending UI than the mutation can
produce, that is UI state, not a second mutator." LLP 0000's DK-10 record shows
Snapback 1 shipped "app-owned optimistic reducers."
From scratch: one definition executed locally for prediction and on the server
for authority; the eight intent/read states are the whole client contract.

**L10 — Ceremony survives only if it is mechanically forced and buys the
property that matters.**
Evidence: LLP 0329.003 §4: "The agent will lie in a diary and ship. Ceremony
that is not mechanically forced is decoration. Reviewable authority is worth
ceremony *if the ceremony is the row rule you had to type to compile.*" LLP
0310 F6 lists the ceremony Convex infers: "Result contracts, `reads`/`writes`/
`refusals` on every function, and asset intent names that must exist in the
same generate." Diary 0114 defends ceremony that "caught real category errors."
From scratch: the row rule is the ceremony; function-level operational
annotations do not return (open disagreement D4 in LLP 0329.000 is resolved
this way by the panel).

### B. Authorization and security

**L11 — Authorization is row rules in the schema, deny-by-default, in the
query language, and the only mechanism.**
Evidence: LLP 0329.000 §1 items 2–3 (unanimous). LLP 0329.003 §3: "Missing
rules are a compile error, not a default. Defaults are how agents get
`public-read` without meaning to." LLP 0329.014 §1: row rules are "a
*precondition* of the mechanism, not a separate preference" (a trace is
shippable only if authorization is a property of rows).
From scratch: per-effect rules (`read`/`insert`/`update(old,next)`/`delete`),
`public(reason)` conspicuous and recorded in a security receipt, no `auth:`
option on a query.

**L12 — Public access must unlock no capability, because agents route around
obstacles and document the compromise.**
Evidence: LLP 0310 P18: a lane "set conversations/members/messages
`public-read` to make its queries reachable, and said in its own diary this was
'not a production ACL'"; LLP 0329 F2: "`auth: 'public'` is simultaneously a
visibility declaration and a retention predicate. An agent that widens
visibility to obtain a capability is behaving rationally." LLP 0317 O34: three
lanes "widened its visibility to ship" although the membership spelling
existed. LLP 0329.001 §4: "a refusal must have exactly one repair, and that
repair must not be 'reduce safety.'"
From scratch: retention and liveness are per-table policy independent of
visibility; every diagnostic is forbidden from offering a weaker rule as a
repair; `public` is CI-red without an explicit allow.

**L13 — The offline design and the security failure were the same defect.**
Evidence: LLP 0329 §Evidence 3 and F2; `guide/sync/offline-and-retention.md`
cold-retains only if the query is "declarative, single-table, `auth:
'public'`, time-independent"; "the canonical local-first application — a
private conversation — falls outside the default path." LLP 0329.014.007 F7:
"Today's local-first contract is the capability matrix at its worst."
From scratch: the private conversation is wave 1's baseline case; retention is
`until-revoked | delivered-history | purge-on-block | all-owned` per table.

**L14 — Never silently degrade; state boundaries and refuse across them.**
Evidence: LLP 0315 §1: two named security profiles (`trusted-same-uid`,
`externally-rooted`) because "a single universal claim is therefore not
available to be chosen"; "**Never silently degrade.** … Falling back … would
reproduce exactly the defect LLP 0303 names — deriving authority from something
the caller can author." LLP 0262: a tunnelled loopback listener grants dev
identity; the fix is a custody proof, not a bind inference.
From scratch: dev identity and exposure are declared facts with typed refusals;
security profiles are explicit runtime declarations, not inferred from the
listener.

### C. The dev loop and lifecycle

**L15 — The dev loop is co-equal with the execution model, not downstream of
it.**
Evidence: LLP 0329.000 §2 F-B (two families against one): grok, "a closed query
language with a Metro race and an identity rebind still loses Clique"; codex,
"less confident that [the language] alone would achieve the desired benchmark
without treating that lifecycle protocol as a co-equal product." LLP 0329.014
§2 point 10 and §10: "nothing here fixes the dev loop." LLP 0329.014.004
Confidence: "Low that any of this moves the Clique scoreboard without the dev
loop." Diary 0114: "The friction that costs milestones is behavioral, not
syntactic."
From scratch: one generation identity across schema, server, generated client,
bundler, and local cache; `check` / `dev` / `verify` designed with the language,
commissioned as a parallel track (LLP 0329.014.007 F6).

**L16 — "The paved Expo loop is now harder than the data model."**
Evidence: LLP 0310 §Summary (2026-08-25 Clique on published 0.1.27): Explicit
"died after a *successful* additive schema successor:
`SNAPBACK_APP_BINDING_IDENTITY_MISMATCH`"; Familiar "greened by restarting
`snapback dev` after Metro died." LLP 0310.000 §Summary: "Snapback is now
harder to *operate* than to *author*." Its product rule: "**a legal schema
successor in the same `snapback dev` owner must leave the web client talking
to that owner.** Adding tables is not 'you pointed at a different app.'"
From scratch: schema edits never mint a new app identity (LLP 0329.003 §4
refusal list: "Schema edits that mint a new app identity"); `dev` "does not
restart the world when the model changes: subscriptions rebind, identity does
not."

**L17 — The identity race was an ordering defect between three separately
designed mechanisms, each individually correct.**
Evidence: LLP 0310.000 §The ordering defect: generate publishes the successor
graph (Metro-visible) → backend activates the successor → *only then*
`rotateBindingAfterLoad` remints; the provider "performs **one** bootstrap
exchange and **one** admission attempt, and on mismatch … *refuses* … so the
arm never re-exchanges." §Motivation: "LLP 0300 wanted Snapback to be more
like Convex: a URL, a client, a boring reload. LLP 0302 then locked identity
… Together with a remint that does not reach the web arm … they made 'I added
a table' look like 'I swapped the app.'"
From scratch: one transaction owns publish/activate/remint (LLP 0329.002 §5:
"`snap dev` should perform schema application, code generation, server start,
identity binding, and client handshake as one generation-tracked transaction.
It emits one acceptance receipt.")

**L18 — One env var is close enough to zero-config; literal zero-config cost
more than the variable it saved.**
Evidence: LLP 0300 §Summary: local Convex and Supabase "never spawn, prox[y],
or enumerate the client's bundler: the whole client contract is environment
configuration"; "This inverts LLP 0181's zero-configuration goal. The lesson of
the comparison is that *one env var is close enough to zero-config*, and the
machinery required to reach literal zero-config costs more than the one
variable it saves." LLP 0223: Convex writes `EXPO_PUBLIC_CONVEX_URL`
unprompted. LLP 0310 F3: "Convex's `ConvexProvider` is one object. This split
is Snapback-specific and cost Familiar the first hour of M1."
From scratch: the client contract is a URL (plus, at most, a publishable key);
the server never owns the bundler; one provider object.

**L19 — Generate must not kill the bundler or the boot receipt.**
Evidence: LLP 0310 F2 / Track C: codegen's `.tmp-*` under the watched tree made
Metro panic (`SNAPBACK_EXPO_METRO_EXITED`); LLP 0317 O33: "`snapback generate`
removes the application-ready receipt mid-lifecycle and breaks Expo bootstrap
until it is reminted" (503 with no explanation); O6: the sole owner and all
children "disappeared during M2 hot reload … with no causal terminal receipt."
From scratch: generated outputs staged outside watched trees and swapped
atomically; receipts written write-new-then-swap; every owner exit carries a
closure receipt naming the cause.

**L20 — The non-interactive agent invocation is the default invocation.**
Evidence: LLP 0317 O37: "Supervised `snapback dev` dies when its stdin pipe
reaches EOF; the start packet does not say so … Every non-interactive agent
runs commands over a pipe." LLP 0310 F7: the control route "needs no TTY and
no stdin," but its "verb set is one entry" (destructive `dev-fresh`) and had
"zero occurrences under `guide/`." LLP 0261 §Design: "Non-interactive first:
every prompt has a flag or a refusal; an agent must be able to run it with no
TTY."
From scratch: every lifecycle verb is an authenticated HTTP/socket control
call with `--json`; owners survive stdin EOF; no destructive verb without a
non-destructive sibling.

**L21 — Ports, pins, and template names are generated facts, not registry
archaeology.**
Evidence: LLP 0317 O1 (unscoped `snapback@0.1.29`, wrong Expo Router major,
nonexistent template name — 3 lanes), O2 (Metro's port "escaped 4287–4387
until `--port-range …`" — 3 lanes), O38 (`babel.config.js` under
`"type":"module"` breaks Metro — 2 lanes), O8 (dead starter screens in the
include set).
From scratch: the scaffold owns every compatible pin and the complete
non-interactive start command; a declared port range encompasses every child
or refuses.

**L22 — `snapback init` — adopt, never clobber; detect or refuse loudly.**
Evidence: LLP 0261 (author ruling 2026-08-15): the surface is "a new top-level
`snapback init` command — not a backend-only template mode on `snapback new`,
and not a standalone composer package"; contract: "1. Detect, or refuse
loudly … 2. Install one coherent closure … 3. Adopt, never clobber … 4. Narrow
the typecheck boundary … 5. Exit into the ordinary lifecycle"; re-running is
"a no-op report, not an error"; only `schema.mjs`, `functions.mjs`, `seed.json`
are "byte-owned authored seams"; the sibling-scaffold workaround's every step
"is mechanical, which is exactly the signature of a missing command."
From scratch: keep the ruling; the arrival state is a `create-expo-app` root,
so adoption is the primary path and scaffolding the secondary.

**L23 — Same-account multi-context and headless replay are first-party
agent surfaces, not edge cases.**
Evidence: LLP 0317 O17 (single-writer / custody-adoption races strand hooks — 3
lanes), O18 ("Replay needed unique store identities, offline-queue disablement,
per-attempt transport IDs, client closure, and separation of transport
idempotency from domain idempotency"), O46 (durable custody lost across a full
navigation), O52/O50 (the first-party replay runner injects a pagination arg
and cannot carry assets). LLP 0329.001 §4: "Agents validate by running."
From scratch: a headless client whose default is the agent's multi-persona
test topology; custody that survives a full document load by construction; a
replay runner that dispatches exactly the generated contract.

**L24 — Media bytes are assets, never structured strings, and the ceiling
must be visible before the first successor.**
Evidence: LLP 0317 O25: both sol lanes "first represented fixture media as
base64 strings and only then hit the 32 KiB structured-value ceiling, after
other M2 writes had settled"; O26: codegen emitted a capability the published
Linux runtime lacked (publication now fails closed, `f3c09fcb0`); O27: the
generated collection "exposed a large, non-obvious policy bundle before runtime
capability admission."
From scratch: `blob({maxBytes, opaque})` as a column kind under the same row
rules (LLP 0329.003 §5), size ceilings in the certificate, assets as the only
blob writer (LLP 0329.014.004 §2.1 D).

### D. Diagnostics and feedback

**L25 — Diagnostic precision is the most-loved property; cardinality is the
defect.**
Evidence: Diary 0114: "Diagnostic precision was otherwise praised repeatedly
('the platform told me exactly what was wrong every time') — the guard codes
are good." LLP 0329 F6: "The problem with diagnostics is cardinality, not
quality." LLP 0322 §Summary: "'every refusal gets a code' produced a code space
with the cardinality of the *implementation* rather than of the *contract*.
3,575 names is not a vocabulary an author learns; it is a lookup table." LLP
0329.001 §4: "3,934 distinct codes is a corpus, not a language."
From scratch: ~20 stable families (language, bound, authorization, schema,
migration, generation, sync, settlement) with structured fields, spans, nested
causes; prose and internal detail vary under a stable public category.

**L26 — Every refusal names its rule and pastes the compiling rewrite; a
warning is permission.**
Evidence: LLP 0193 bar; LLP 0178: "Refuse a statically proven contradiction at
generation. Advise on a useful but incomplete signal. Retain runtime
enforcement for both." LLP 0329.002 §5: "A warning is permission to an
agent." LLP 0310 P7 (re-dispositioned): "a design that refuses the idiomatic
spelling owes the reader the admitted one." LLP 0317 O9/O13: inline handlers
"repeatedly refused natural JavaScript," making "ordinary code a
grammar-discovery exercise."
From scratch: refusal-with-rewrite is the *whole* mechanism (LLP 0329.014.007
F3); the spike measured 8/8 realistic first attempts refused with a rewrite
that compiles; the cold-agent first-draft refusal rate is a product gate.

**L27 — Silent degradation is a defect class, not a papercut.**
Evidence: LLP 0317.000 P5: O29 (successor silently retains old
`defineAuth.minimumLength`), O35 (asset hook returns empty; live query "went
silent" at the 1,024 ceiling), O14 "share one property: nothing is emitted, so
nothing can be looked up." O35: "Silent emptiness is the worst failure mode
for an agent." LLP 0219: unmemoized hook args "saturated the main thread for
~50 minutes with *zero* console output"; a queued mutation "resolved like
success at the call site … 'the worst hours of the run.'" LLP 0316 principle:
"A missing precondition is one loud failing test, never a compile error."
From scratch: every state transition that changes what the client shows emits
a typed event on one bounded machine-readable channel; there is no empty
result without a completeness label.

**L28 — Causal observability beats documentation for behavioral bugs.**
Evidence: LLP 0317 O15: agents "could not trace hook → authority generation →
commit → invalidation publication → subscriber revision, so they tried nonce
churn, polling, skip cycles, revision rows, presence, reloads, and snapshot
mutations … the single highest-leverage row in the document." LLP 0219 §Summary:
"documentation does not catch what a runtime warning would." LLP 0317 §Priority
synthesis bundle 1: "authority and reactive causality … consumed the most
debugging time and drove semantically costly polling and public-read
fallbacks."
From scratch: the execution trace *is* the invalidation predicate, so "why
didn't this update" is answerable from an artifact (LLP 0329.014.007 F1); a
causal subscription receipt (LLP 0219.000) ships with the first client.

**L29 — Consequences must surface at the edit site, at author time, in
under a second.**
Evidence: LLP 0329.001 §4: "Agents cannot see consequences distant from the
edit site … a derived property can be reported at the declaration site; a
declared one is only checked where it's used." LLP 0329.002 §5: "`snap check
--json` should typecheck and plan a small app in roughly a second." LLP
0329.003 §4: "`check` parses, type-checks, analyzes, and emits the client in
well under 100 ms … If you cannot know retainability without running the
server, you have reintroduced the hole."
From scratch: the certificate (read sites, bounds, prediction modes,
disclosures) is emitted beside the generated client on every `check`.

**L30 — Structured diagnostics are the contract; logs are not.**
Evidence: LLP 0010 §Diagnostic Shape: "stable code; severity; subsystem;
target profile; source file and span; generated artifact path; function/
table/field/index/subscription/capability id; concise message; machine-readable
details; suggested next checks … Diagnostics must not require scraping logs."
LLP 0010 §Agent Contract lists ten questions an agent must be able to answer
(what schema is loaded … what command or file should be changed next).
From scratch: keep this contract verbatim; it was right from day one.

### E. Documentation, retrieval, and the first read

**L31 — Agents retrieve; they do not read. Budget the bytes the carrier
sends.**
Evidence: LLP 0259 §Motivation: the mandated first read was ~100 KiB;
"Heading-level 'stop here' folds do not save tokens on carriers that deliver
whole files. Budget the bytes the carrier actually sends." LLP 0329.001 §4:
"Target: the complete authoring vocabulary fits on one screen and in the
system prompt. If the guide must be large, the design failed upstream."
From scratch: a one-page grammar, a generated per-app index, a short cookbook
with test fixtures behind each entry (LLP 0329.002 §5); packets ≤ a few KiB.

**L32 — Discoverability misses are routing failures; the treadmill of seeds
is a symptom of surface size.**
Evidence: LLP 0187 §Summary: "routing failures, not coverage failures." LLP
0317 §Already-ships sweep: of 46 backlog rows, 12 already ship, 19 partially
ship, "**Only six rows are genuinely new capability work**"; "the dominant
failure mode in this corpus is a capable agent not finding a capability that
exists." LLP 0329 F5: "an eval corpus that must grow monotonically with the
surface"; retrieval-eval cases 4 and 10 are "documentation compensating for a
surface that made the wrong thing natural."
From scratch: fewer things to find; diagnostics route to the fix; "Retrieval is
the compiler" (LLP 0329.003 §4).

**L33 — Orientation is inside the clock; wrong first pages and experimental
surfaces at the front cost milestones.**
Evidence: LLP 0310 F5: "Orientation is inside the Clique clock. Wrong first
pages are not free." LLP 0259 §An experimental backend at the front of the map:
`guide/index.md` "led with the Experimental Familiar profile"; Diary 0078:
Snapback Familiar 10,098 s vs Convex 2,705 s, "The tax is **boot, surface
choice, and page size**, not missing conceptual coverage"; "The highest-leverage
next step is not more syntax."
From scratch: exactly one paved surface visible to a cold agent; experiments
live behind explicit briefs, never in the index.

**L34 — Diaries are evidence, not advice; the guide is derived, the code is
the witness.**
Evidence: LLP 0259 §Diagnosis 5: "Diaries are evidence of what happened, not
current advice. Traps must be reconciled against `main` … before they enter the
start packet." LLP 0061 §Design 5: the sophisticated-variant-only anti-pattern —
"a page teaching only the advanced variant of a capability makes the base
variant look unsupported, so the search terminates in a wrong conclusion."
LLP 0061 Goal 3: snippets execute in CI ("this ran").
From scratch: the cookbook is generated from test fixtures; the guide is
produced from the compiler's own facts (certificates, kinds) where possible.

**L35 — The parity tax of two profiles doubles every doc.**
Evidence: LLP 0317.000 §Summary: "Every guide fix authored Explicit-only is
worth half of what it appears to be worth"; P3: "Every documentation
intervention is authored for both authoring profiles or explicitly scoped to
one." LLP 0317 O32: "Familiar authors pay a translation tax on every recipe
outside one page."
From scratch: one profile; the spelling bakeoff (TS syntax vs SQL text over
the same IR) is measured before shipping, then exactly one ships (LLP 0329.014
open question 6).

**L36 — Publication lag makes landed fixes invisible to agents.**
Evidence: LLP 0310 §Still open: "Nothing above is in published 0.1.27. The
repairs reach agents only on the next publication." LLP 0259 §Product work:
"the *defect* is still present in the newest published closure 0.1.21. The
fixes are unpublished." LLP 0000 ratification 2026-08-08 / LLP 0041 posture:
"publish rapidly and often … treat landed-but-unpublished surface fixes as a
liability."
From scratch: a publication path cheap enough to run per landing; the
benchmark always runs the published pin.

### F. Client arms and custody

**L37 — The client is the complexity sink; it implements holes in the
capability matrix.**
Evidence: LLP 0329 F3: `snapback-client` + seven arm packages ≈ 212k lines,
"the same order as the entire kernel"; 746 fix-touches, the top product
hotspot; "Retention classes, authorized leases, custody, and completeness
witnesses are client-side machinery implementing a capability matrix with
holes." LLP 0008 DK-9's intent: "a result cache + cursor/epoch state + outbox,
never a relational replica."
From scratch: the client is a per-principal encrypted range store, a verdict
cache, an outbox, and an IR evaluator — measured at 7.8 KB gzip in spike S3
(LLP 0329.014.004 §7) — "the discipline is 'no holes to implement,' not a line
budget."

**L38 — Name the lifecycles; individually defensible APIs were collectively
misread.**
Evidence: LLP 0238 §Summary: "'Query' sometimes means a one-shot query and
sometimes only a live query. A mutation promise describes dispatch, not
necessarily durable settlement. A live handle looks plausibly iterable but is
actually polled and disposed." LLP 0329.002 §2: eight states — `hydrating |
fresh | stale | partial`, `predicted | queued | committed | rejected` — "It never
silently substitutes 'unsupported'."
From scratch: the eight states are the entire client contract; one hook per
framework over the same generated operation objects.

**L39 — Offline needs a compact semantic contract stated once, or leases and
custody modes accumulate one information limit at a time.**
Evidence: LLP 0329.000 §3 D2 (codex): "without a compact semantic contract for
incomplete local knowledge, revocation, provisional authority values, and
settlement, *even a perfect single constructor accumulates leases, custody
modes, and exceptions*"; the offline-revocation limit "is an *information*
limit, not a *program* limit." LLP 0329 OQ4: "What is the offline revocation
contract, stated once rather than accumulated?" LLP 0329.014.007 F11 states
the trades (not a replica; `partial` is real; OCC rejections on reconnect;
`maxOfflineAge` is a hard fence).
From scratch: revocation stated once — reconnect evicts rows held by no range;
sign-out destroys the store key; one store-wide `maxOfflineAge` (value an
author ruling: 24 h / 7 d / 30 d).

**L40 — Cut the arms; one generated TypeScript client, framework bindings as
sugar.**
Evidence: LLP 0329.003 §5: "React/Expo: a hook that calls the generated
client. Fifty lines, one package, not an arm"; "Admin clients, custody
packages, dev-identity packages as separate products. Identity rebinding is a
`dev` bug to fix, not a package to publish." LLP 0329.002 §6: "Ship one
TypeScript client and one React/Expo adapter only after the framework-neutral
contract is stable." LLP 0329.014 §9 delete list includes `snapback-umbrella`,
`-admin-client`, `-app-cli`, `-guide-embed` "as separate products [inferred]".
Tension: LLP 0000 says "Contract/Exact first; React/Expo a strong second."
From scratch: one client core; adapters are thin; the Contract/Exact seam is a
consumer of the same generated operations, not a separate arm.

### G. Method — how to run an agent-first product

**L41 — The pit-of-success standard: an `agent-error` label is evidence about
the surface.**
Evidence: LLP 0310 §Reading an agent-error label (author standard 2026-08-26):
"**When a capable agent gets something wrong, the default assumption is that
the product made the wrong thing easy — not that the agent was careless.**" A
row stays dismissed only if (1) the correct move was discoverable from the
material the lane actually had, (2) the wrong move was not the one the API,
types, or idiom made most natural, and (3) nothing cheap would have prevented
it. LLP 0317 §Summary: "when a capable agent repeatedly chooses a wrong shape,
the product should ask what made that shape natural and cheaply prevent it."
From scratch: adopt as the triage rule from week one.

**L42 — The cheapest-intervention ladder: impossible → refused at generate
time with the exact repair → route the existing page → write the page → write
the recipe.**
Evidence: LLP 0317.000 P2 (verbatim order); "The third rung is listed
explicitly because four rows in this program are failures of it." LLP 0317.000
§Measurement: "A row closed at 'wrote a page' when 'refuse it at generate time'
was available is recorded as a **partial**."
From scratch: the same ladder, with rung 1 as the design default.

**L43 — Reproduce before implementing; an accepted design is not closure;
claims are scoped to their evidence.**
Evidence: LLP 0317.000 P1 ("A reproduction is cheaper than a wrong fix plus its
revert, and four rows have already proved the failure mode"), P6 ("Every
closure claim names the platform, profile, and client arm it was proven on"),
P7 ("An accepted design is not closure … Only implemented, published behaviour
counts"). `benchmarks/protocol.md` via LLP 0317.000 Wave 5: N=1 is existence
evidence; N≥3 ratchet-eligible; "an ordering claim requires N≥8 per lane."
From scratch: keep these rules; they are why the corpus's numbers can be
trusted at all.

**L44 — The primary metric is time-to-green from an empty directory and
correction-loop count, measured by fresh agents on the published pin.**
Evidence: LLP 0329.002 §5: "The primary product metric is median time from an
empty directory to a green acceptance receipt, followed by correction-loop
count on private offline tasks. Feature count and the best run's ceiling are
secondary. Every release should be tested by fresh agents whose context
contains only the task and the small index." LLP 0186: 26m03s vs 11m15s;
LLP 0317 L18 baseline: 22 existence loops; LLP 0329.014.007 F6's two gating
numbers.
From scratch: the benchmark/diary loop "should exist in week one" (LLP
0329.001 §5), run "against Convex, Supabase, PocketBase, on the private-chat
case, not on a public counter" (LLP 0329.003 §5).

**L45 — What was loved and should survive.**
Evidence: LLP 0329 F6 and LLP 0329.014 §9 keep list: server authority; Rust +
SQLite; the measured idle profile (~13 MiB resident, zero disk writes, no
measurable CPU over 120 s — LLP 0035); typed refusals that name the repair;
"the green-receipt-or-it's-a-claim discipline"; the benchmark/diary loop;
atomic successor activation; durable ordered intent and settlement;
client-minted ids; schema-as-source-of-truth (LLP 0037); MIT. LLP 0186: "Once
past setup, Snapback's semantics *saved* agent work relative to Convex
(ephemeral typing, platform offline, typed assets)."
From scratch: these are the substrate; everything in §1.1's concept table that
is not on this list is a candidate for deletion.

## 3. Internal engineering loop lessons (building Snapback 1)

**What made it slow, by the corpus's own measurements.**

- **Git-triggered invalidation.** LLP 0316 §Baseline: `touch .git/index` →
  `cargo build -p snapback` cost **17 s**, recompiling six crates, because
  `build_identity.rs` declared `rerun-if-changed` on `.git/index`, all of
  `refs/heads/` ("shared by all 89 registered worktrees … A commit by any
  concurrent session on any branch invalidates every other session's build"),
  and `packed-refs`. Fixed by Phases 1–2 to 0.3–0.5 s.
- **Guide-tree invalidation.** `snapback-server/build.rs` rebuilt the 110k-line
  server crate on every docs edit because it embeds the guide (LLP 0316;
  LLP 0276 §What the layout gets wrong 4: `build.rs` "bundles four unrelated
  jobs"). Phase 4 leaf crates: real guide edit 18.62 → 2.17 s.
- **A linear crate tower and god files.** `types → kernel (226k) → auth →
  {sync, services, activation} → engine (125k) → server (110k) → cli →
  snapback`; `engine.rs` 44,968 lines, `server.rs` 35,219, `storage.rs`
  24,729. LLP 0316 §Summary: the god files "walked straight through [LLP
  0276] because nothing held the work to a clock." Phase 7 carves were mostly
  measured negative and discarded.
- **Link targets.** LLP 0327 §1b: "linking one integration test binary costs
  ~5 seconds regardless of the test's size"; a 42-line test → 442 MB binary;
  57 → 83 targets "grew unobserved"; `target/` 134 GB; no-op
  `cargo check --workspace --all-targets` 50.9 s. LLP 0316 Phase 5: 79 → 13
  integration link targets, executables 21.5 → 4.13 GB; nextest 41.8% faster.
- **Test currency.** Kernel lib tests `include_str!` gitignored demo outputs, so
  "the **entire kernel lib-test crate fails to compile** — 1,000+ tests
  unreachable because one test's fixture is missing" (LLP 0316 §Test
  currency).
- **The verification layer switched itself off.** LLP 0316 §The verification
  layer: `required-surface-builds` "ran 55 times on 2026-08-24, all red on a
  stale committed review manifest"; 16 pushes → 130 runs, 66 failed, 40
  cancelled; then made manual-only and "has not run since"; `local-proof`
  (180 gate `run` declarations in a 902-line script) takes 57–145 min "and
  every recent run failed." "The velocity cost here is not the minutes; it is
  that **no signal a developer can act on arrives within the landing loop**."
- **Exact-commit gating vs continuous landing.** LLP 0189 §Context: median
  commit gap ~0.1 min; the C27–C33 loop (seven candidate cuts abandoned
  because "the mandatory post-review fetch found newer main"); the derived-fork
  claim withdrawn seven hours after twelve review rounds "because wave landings
  changed nine proof/checker/metrology files inside its qualification digest.
  No fork runtime code changed"; a 433-commit red gate. "processes that gate
  landing, claims, or promotion on *complete verification bound to an exact
  commit* are structurally incompatible with this repository's landing
  cadence." LLP 0232 §Evidence: "one measured regeneration and re-verification
  cycle took 69 minutes"; ~14% of 3,372 commits were integration/regeneration
  churn; a ~10-minute pre-push battery against an ~8-minute landing interval.
- **Generated-artifact chains.** LLP 0329 §Where complexity accumulated:
  `guide/reference` is "the highest-churn path by roughly 5×: 19,938
  file-touches. It is generated. 1,645 tracked generated files … are 8.2% of
  tracked bytes but dominate churn"; commit mix `docs` 1,645 > `fix` 1,473 >
  `feat` 671; 185 scripts, 49 of them checks or gates. LLP 0316 Phase 8: 864
  governed generated artifacts. AGENTS.md: the diagnostics registry "records
  emitting *sites*, not just codes, so shifting line numbers invalidates
  `guide/reference/diagnostics-registry.json`"; "The generated artifacts also
  chain — the guide manifest embeds the registry."
- **Ticket mass.** LLP 0328 §1.1: 456 open + 1,500 closed ticket files; 324
  open filenames dated in one week; 71 `battery-*` and 21 `main-drift-*` open;
  six metadata dialects; "A flat `ls issues/` … cannot answer 'what is
  active?'" LLP 0316: "Process mass for orientation: 322 LLPs (277k lines),
  459 open tickets, 177 scripts (79k lines)."
- **Binary size and the Hermes/Ibex bootstrap.** LLP 0314: the shipped binary
  is a `--release` build with 241k–264k symbols, ~20 MB embedded guide, no fat
  LTO; "the publish path does not run" the `production` profile LLP 0276
  already defined. The debug binary is 490–533 MB. LLP 0010 §Bootstrap
  diagnostic codes: fourteen `SNAPBACK_IBEX_*` failure codes exist because
  bootstrapping means initializing `vendor/ibex`, fetching prepared Hermes
  artifacts or building them, linking, launching, qualifying a no-eval VM,
  and persisting a digest-bound readiness receipt; on macOS `DYLD_*` must be
  scrubbed and an `LC_RPATH` emitted (AGENTS.md). Memory: `cargo test` needs
  `DYLD_FRAMEWORK_PATH` or SIGABRTs; worktrees need submodule init.
- **Repository shape.** LLP 0276 §What the layout gets wrong: nine items —
  physical shape contradicting the decided architecture (a 19k-line analyzer
  over a 376 KB frozen baseline), god files, ~60 tracked root scratch
  artifacts, four-job `build.rs`, 74 link targets, four independent
  test-inventory mechanisms, a ~30-script release family with five
  "qualification" entry points, stale trees, "466 GB of stale agent
  worktrees."

**What the corpus itself says about simplifying.**

- **Measure, then change; one metric above every other goal.** LLP 0316
  §Summary: "**the Rust volume is a second-order cost; the first-order costs
  are self-inflicted and repairable in place**"; the plan "adopts exact2's
  discipline — one metric above every other goal — without its method. No
  rewrite, no `snapback2`." LLP 0327 §8: "None of these was observed anywhere,
  which is why the integration-target population grew 46% and the debug
  binary grew 45% before either was noticed."
- **Invalidate on the fact, not the proxy; expensive things in leaf crates;
  a missing precondition is one loud failing test; land each phase alone**
  (LLP 0316 §Design principles).
- **No gate may require a complete proof at an exact commit** (LLP 0189 D-6,
  LLP 0316 ruling 3). Landing gates are fast and affected; the complete
  battery runs on schedule and its reds become fix-forward tickets; claims are
  snapshots scoped to claim-relevant digests; reviews bind content, not HEAD
  (LLP 0189 D-1–D-5; LLP 0232 optimistic landing default 2026-08-13).
- **Loud refusal over silent fallback** everywhere, including in gates (memory:
  a check that degrades to a weaker check and reports green is the failure
  class).
- **Bounded working sets.** LLP 0328: a generated index, a 64-link
  `issues/current/` overlay ("a circuit breaker, not a priority model"), exact
  metadata for new tickets, one idempotent writer contract; LLP v2's
  `llp/current/` and `llp/foundation/` overlays serve the same purpose for the
  design corpus.
- **Physical boundaries that the compiler enforces** beat an analyzer with a
  ratchet (LLP 0276: "Cargo makes *absent* edges uncompilable"); but LLP 0276's
  frozen-`main` flag day was an explicit, author-held exception to the
  fast-main doctrine, and the god files survived it.
- **Delete the hole, delete the crate.** LLP 0329.003 §5: "If a crate or
  package exists to implement a capability hole, deleting the hole deletes the
  crate." LLP 0329.014 §9's delete list: the `define*` zoo, authored
  operational annotations, `AuthorizedLease`/retention classes/custody
  modes/completeness witnesses as client machinery, the profile pair, JS
  handlers as a spelling, the LLP 0157 node-class registry, Hermes/Ibex from
  the request path, several packages, "the committed generated reference
  forests and the 20 MB embedded guide."
- **Not decided but named:** whether the effect runtime needs a JS engine at
  all (LLP 0329.014 OQ8) — the largest single simplification on the table
  (LLP 0329.000 F-A: it "would remove the Ibex/V8 runtime-conformance
  contract, the LLP 0048 conformance twin, the DK-4 warm-VM pool and its
  invocation-epoch guard, and a substantial share of the LLP 0314 binary").

## 4. The standing rebuild direction (LLP 0329.x)

What has already been converged, spiked, or ruled, so the new document builds
on it rather than re-deriving it.

### 4.1 Diagnosis (LLP 0329, six findings)

F1 capability-by-authoring-form is the root defect (high); F2 the offline
design and the P18 security failure are one defect (high); F3 the client is
where it is paid for (~212k lines; high/medium-high); F4 the corpus identified
the direction (LLP 0155 move 1) and could not land it as a retrofit (high);
F5 surface size is a measured tax on the agent (7–12 of 15 tool calls;
medium-high); F6 what is loved should survive — diagnostics' precision, idle
profile, the benchmark/diary loop (high).

### 4.2 Unanimous across three model families (LLP 0329.000 §1)

1. capability-as-form is the root cause and the same defect as `public-read`;
2. authorization = row-level predicates in the schema, deny-by-default, the
   only mechanism; 3. public access unlocks no capability; 4. admitted implies
every capability — refuse, do not degrade; 5. everything derivable is derived
(including rule-only tables in the read set); 6. the mutation text is the
optimistic predictor; 7. a small closed vocabulary (~20–30 names) and error
algebra (~20 categories), no diagnostic may offer weakening authorization.

Two-against-one options: **F-A** JavaScript out of the authoritative data
plane (unevaluated against DK-5 and actions); **F-B** the dev loop is co-equal.

### 4.3 The converged design — bounded data programs (LLP 0329.014 §2, ten points)

1. One language, two program kinds (`query`, `mutation`) + `effect` and
   `channel` outside the data plane; TypeScript syntax type-checked against a
   custom `lib.d.ts` omitting `Date`, `Math.random`, `fetch`, `while`,
   recursion; modeled inputs `ctx.viewer`, `ctx.now()`, `ctx.newId()`.
2. Reads only through `get` / `scan(index, prefix, {order, take})` / `exists` /
   `recurse({depth, fanout})`; `take` required.
3. Loop domains carry static cardinality; read keys are shape expressions or
   the site is marked `computed`; rule bodies are single algebraic predicates;
   helpers inlined.
4. Row rules are the only authorization; `public(reason)` conspicuous;
   maintained aggregates are schema constructs (`maintain.count/sum … by`);
   `countCapped(K)` is the paved bounded form.
5. **Static certificate at `check`** (planHash, readSites with prefix
   templates, take, maxCalls, hoist; writeSites; maxExamined/Steps/Heap/
   Output; resultType; completeness `page|capped|maintained`; predictionSites
   `closed|conditional|partial`; indexesRequired). Refuse above ceilings.
6. **Two trace artifacts per execution**: the authoritative trace (drives OCC
   and invalidation; never leaves the server) and the client closure receipt
   (authorized rows, ranges with stop reasons, halo row, scoped verdicts).
7. The shared fact: exact local replay while `Reads ⊆ Coverage`, `partial`
   otherwise; the prediction closure per `(query, mutation)` pair.
8. **Client** = per-principal encrypted store of delivered rows indexed by
   `(table, index)` with range coverage, verdict cache, outbox, IR evaluator;
   eight states; one `maxOfflineAge`; sign-out destroys the key; the client
   "cannot issue a query the model did not name."
9. **Server** = one Rust IR interpreter inside the SQLite transaction; JS not
   in the authoritative path; rerun-on-touch is the v1 live lowering;
   Postgres is a second physical lowering.
10. **The dev loop is co-equal**: one generation identity; `check`/`dev`/
    `verify`.

Headline (LLP 0329.014.004 §Summary, v1.2): "One TypeScript-syntax language for
queries and mutations, with real control flow, in which every data access goes
through a typed, bounded, traced API; a rich schema in which authorization,
disclosure, retention, integrity, time, hierarchy, merge, and derived values are
first-class declarations the engine enforces; a static certificate of read
shape and bound as the only gate; and one execution trace that is
simultaneously the invalidation predicate, the offline closure, the OCC set,
and the completeness detector — so that every admitted program is live,
retained, authorized, and locally predictable, with no second query class."

### 4.4 What the waves and spikes established

- **Thirty-seven paper applications** (waves 1–4) needed no second query
  class on the server data plane; every residue became one of **seventeen
  schema dimensions** (A structural vs caller facts; B time is state; C
  integrity binds every writer; D missing kinds; E hierarchy; F authorization
  ≠ retention ≠ disclosure; G authority of modeled inputs; H merge; I jobs;
  J disclosure rate; K rank/maintain family; L hidden probes; M ranked-index
  read site; N principals as sets and kinds; O projections with an audience;
  P authority placement in two regimes; Q rule ownership and composition) or
  a **kind** (`schedule`, `job`, `channel`, `effect`+outbox, `exportStream`,
  identity, assets, host invoke, ranked-index site, oblivious store,
  peer-custody transaction, `formulas`/`grid`, broadcast projection,
  `replica`). Writing designs in the strict language found bugs in 10/14,
  13/13, and 8/8 designs.
- **Spike S1**: Rust interpreter over SQLite with certificate, trace, receipt;
  a receipt-only client replays a local `send` as `predicted`, survives one
  held-row delete on the halo, goes `partial` on the second and at
  computed-key sites, evicts on revocation — 7/7, no per-program special
  case. **S3**: TypeScript twin byte-identical to Rust on a 75-case corpus,
  7.8 KB gzip vs 109 KB for a read-only Rust/WASM subset (D-A settled).
  **S2**: ordinary TypeScript re-authors every S1 program to identical IR;
  8/8 realistic first attempts refused with a compiling rewrite; 66.7% of raw
  gauntlet code lowers unchanged against a 70% gate; two design gaps
  (composite write keys; a specified standard library).
- **Three "not this system" verdicts**: cryptographic double-spend
  impossibility for offline cash, remote-oracle agreement at the commit
  instant, the PIR mechanism; the vault is "this language, that runtime".

### 4.5 Keep / re-implement / delete (LLP 0329.014 §9)

Keep unchanged: Rust+SQLite authority, journal and version stream; atomic
successor activation; build identity; server transport; conformance/tools
crates; packaging/publication/scaffold/acceptance; the idle profile; durable
ordered intent and settlement (LLP 0133/0218); client-minted ids (LLP 0135);
LLP 0009's sandbox for effects; LLP 0189 cadence; LLP 0201 instrument; the
diagnostic discipline (~20 families); schema-as-source-of-truth; sign-out
destroys the key.
Re-implement as ideas: engine plan evaluators → IR interpreter; `define.mjs` →
TS-subset compiler; client/react/expo/vite → range store + evaluator + outbox
+ one hook; sync matcher → range-indexed subscriptions; LLP 0013 → `channel`;
LLP 0080 §5 → `maintain`; LLP 0157/0166 → the range store and `partial`;
LLP 0107 → eight states.
Delete: listed under §3 above.

### 4.6 Competitive and local-first posture (LLP 0329.014.007)

"As built, Snapback is a worse Convex"; under the design it makes "a claim
neither competitor can make — *every program you can write is live,
offline-capable, row-authorized, cost-certified, and locally predictable, and
the compiler pastes a rewrite when it is not.*" Materially better odds vs
Convex (F1–F4), modest direct change vs Supabase (F5), and "**none of it
counts until two numbers exist** — a cold agent's first-draft refusal rate,
and a dev loop landed alongside the language" (F6). Eight candidate
local-first improvements (hold sets + `offline: 'required'`; dependency-aware
outbox; delta resume by range version; asset bytes under the row's retention
lease; per-field `unheld`; local token-index replay; store budget with
eviction priority; cancel a queued intent + `asOf`), worked in LLP
0329.014.008.

### 4.7 Open author decisions (consolidated)

From LLP 0329.014 §Open questions: (1) the bound model for rules — static
ceiling vs index-served with reported cost (panel recommends the split);
(2) **JS out of the data plane** — overrule DK-5's device-parity posture for
queries/mutations; (3) `maxOfflineAge` — 7 d/30 d (Fable) vs 24 h/7 d (grok);
(4) time as an input relation in v1 or deferred; (5) explicit vs
compiler-decided maintenance (panel: explicit, proposed in diagnostics);
(6) spelling — TS syntax first, SQL text measured (Day-7 bakeoff);
(7) named operations only in v1; (8) does the effect runtime need a JS engine
at all.
From LLP 0329.014.004 §9: `any` with a cap as the one rule primitive; `job` as
chunked mutation or schedule continuation; `sequence` as kind or boundary.
From §Open questions (10): is `any` the one rule primitive; the checkable
predicate for "uniform-true"; schema-as-data as dimension or product boundary;
the paved broadcast subscription class; is a device-authoritative partition
*this system*; is `fresh(row, at:'commit')` the one primitive for external
authorities; does trace constancy generalize to every secrecy claim; is

From LLP 0329.014.007: which of the eight improvements are v1; whether hold

From LLP 0329.000 §3: D1 surface syntax; D2 offline revocation contract; D3

## 5. Contradictions and tensions in the corpus about the loop

1. **Familiar vs Explicit.** LLP 0252 authorizes a bounded experiment; LLP 0259
   fences Familiar out of first reads ("never makes Familiar the default");
   LLP 0318 (Withdrawn) argues for converging on a Familiar-shaped single
   profile; LLP 0310.000 lists "Merging explicit and familiar into one
   authoring profile" as a non-goal; LLP 0317 bundle 6 demands parity; Diary
   0114 finds "Explicit vs Familiar was not the clean win the 'familiar'
   framing promises"; LLP 0329 declines to rank them (LLP 0252 D7's N≥3 matrix
   "has not run"). Meanwhile a `familiar-react` full packet landed in
   `guide/start/` on 2026-08-29. The corpus is simultaneously fencing,
   paritizing, and withdrawing the second profile. Resolution the 0329 family
   proposes: one profile, decided by a measured spelling bakeoff over one IR.

2. **Guide-as-complete-map vs packet-first vs "diagnostics replace the book".**
   LLP 0061 Goal 1 requires completeness (every capability enumerated, GAP rows
   for the rest); LLP 0259 says completeness "is no longer a required *first
   read*" and budgets ~16 KiB; LLP 0329.003 says "There is no 20 MB guide in
   the install … Diagnostics replace the book"; LLP 0329.002 wants "a one-page
   grammar, a generated schema/operation index for the current app, a short
   cookbook." The retrieval eval grows monotonically by the LLP 0187 rule and
   LLP 0329 F5 reads that growth as a symptom. Unresolved: whether a
   from-scratch design keeps a served, versioned guide at all, or only a
   grammar plus diagnostics plus generated per-app facts.

3. **Optimistic landing vs proof gates.** LLP 0189/0232 rule that no gate may
   require a complete proof at an exact commit and that reds are fix-forward
   tickets; yet the corpus still carries 18 frozen-record drift gates, a 41-id
   selection policy, a 164–180-gate local proof, publication gates, and — per
   LLP 0316 — a required fast signal that was switched off and never
   restored, so "reds are fix-forward tickets" has no red to fix forward
   from. LLP 0276 suspended the fast-main doctrine for a flag day. The tension
   is between honesty machinery (LLP 0005/0010) and a landing loop agents can
   actually feel.

4. **Zero-config supervised Expo vs URL-first.** LLP 0181 (Review) makes the
   supervisor own Metro to reach literal zero-config; LLP 0300 (Implemented)
   inverts it — "one env var is close enough" — and demotes the supervised
   path from canonical; LLP 0310.000 (2026-08-26) then repairs the supervised
   path as still "a paved path" (Ruling 2); LLP 0295 D0.1 rules one canonical
   lifecycle with a fixed-origin/external-client profile beside it. Three
   lifecycles coexist; LLP 0261 binds `init` to "the ruled lifecycle."

5. **Declared reviewable authority vs derive everything.** LLP 0329 F6 keeps
   "declared reviewable authority" on the loved list and Diary 0114 credits
   ceremony with catching category errors; LLP 0329.000 item 5 and grok's D4
   say `reads:`/`writes:` are a symptom and "keeping them because ceremony
   feels safe will re-grow the matrix." LLP 0172/0274 add *more* explicit
   per-function and per-table declarations in 2026-08. The panel's resolution
   — the row rule is the only forced ceremony — is recorded but not ruled.

6. **Refuse-not-degrade vs expressiveness vs where the escape actually
   happens.** LLP 0329.000 is unanimous on refusal; LLP 0329.004 says refusal
   is viable only if expressive; LLP 0329.005 says the read escape is mostly
   habitual and the real escape is on writes (74%); LLP 0329.006 says the
   write path's point-read restriction is the cause; LLP 0329.013 says the
   loss was "a registry", not restriction. The 0329 family relocated the
   problem three times in two days before 0329.014 converged; the new document
   should state the converged position, not the intermediate ones.

7. **Copy Zero's outcomes (LLP 0155) vs named queries only (grok D3).** Grok:
   "Zero's local composable query engine *is* the architecture that forces
   client-side permissions and completeness." The panel resolved "named
   operations only in v1" on the admission axis while the store stays general
   (LLP 0329.014 OQ7) — a compromise, still an author decision.

8. **Hermes/Ibex device parity (DK-5) vs JS out of the data plane (F-A).**
   LLP 0009 DK-5's enduring posture ("device parity with Exact, capability
   security by construction, footprint, spinup") vs LLP 0329.014 §9's
   "overruled for the data plane"; LLP 0329.014.004 §9 notes the platform's
   in-commit plugins as "the one place 'JavaScript never in the authoritative
   path' is under pressure from a product."

9. **Errors-as-docs vs code cardinality.** LLP 0193 made "every refusal gets a
   code" structural; LLP 0322 (Withdrawn) found that produced implementation-
   cardinality codes; LLP 0329.014 keeps "typed refusal, one repair per family
   — ~20 families, not 3,934 codes." Whether a two-tier public/internal
   partition or a fresh ~20-family algebra is the mechanism is undecided.

10. **"The dev loop is co-equal" vs zero design for it.** Every panelist and
    both single-model documents name it; LLP 0329.014.004 §10 admits "nothing
    here fixes the dev loop"; LLP 0329.014.007 F6 says to commission it "as a
    parallel track, not a follow-on." The corpus's dev-loop knowledge lives in
    LLP 0310/0310.000/0317/0300/0302/0181/0223/0262 — repair RFCs for Snapback
    1's mechanisms — not in a from-scratch statement. This is the gap the new
    document fills.

11. **Contract/Exact first vs Expo/React as the measured product.** LLP 0000:
    "Contract/Exact first; React/Expo a strong second." Every benchmark lane
    (Clique, LLP 0201) is an Expo/React-web build; LLP 0329.003 §5 would cut
    "Contract/Exact-first plus React as a second client"; LLP 0329.014 §9 keeps
    "one hook per framework." The primary-client ruling has not been revisited
    since 2026-06-25.

12. **Pit-of-success attribution vs "correct safety boundaries".** LLP 0310's
    standard moved P5/P7/P18 from out-of-bar to Snapback obligations; LLP 0317
    §3 still admits rows that are "correct safety boundaries whose paved
    spelling was not discoverable early enough." The standard says a refusal
    the agent cannot find its way out of is a product defect; the grammar
    LLPs (0108, 0237) say the refusals are by design. A from-scratch design
    must make every refusal carry its repair so this class disappears.

13. **Retrieval treadmill vs already-ships.** LLP 0317's sweep found 40 of 46
    backlog rows already shipped or partially shipped; LLP 0317.000 re-sized
    Wave 3 to routing; LLP 0329 says the cure is "less to retrieve." Both are
    true of Snapback 1; only the second is a design principle.

14. **Publish-often vs a ~30-script release family.** LLP 0041's posture is
    rapid publication; LLP 0276 §What the layout gets wrong 7 records "five
    'qualification' entry points, four 'closure' scripts, and a publish/
    promote/fastpath split — no single documented state machine." Agents
    measured published pins that lacked landed fixes for days (LLP 0310 §Still
    open).

15. **Server embeds and serves the guide (LLP 0061 §4a) vs install weight
    (LLP 0314) vs leaf-crate invalidation (LLP 0316).** The embedded-guide
    decision is structurally right for version binding and structurally wrong
    for binary size and build invalidation; LLP 0314.001/.002 (derived guide
    bytes, compression) treat symptoms; the from-scratch question is whether
    the served artifact should be the compiler's own facts rather than prose.
