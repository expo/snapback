## 4. Concerns

1. **(Moderate) The Gate 0 cost "reference workload" is underdetermined for a day-long measurement.** Line 253–255: "Cost measured over at least one full billing day on the reference workload (one full acceptance-suite run, plus All Aboard's real meters where applicable)." One suite run takes minutes; the remaining ~24 hours are idle, so the measurement is idle-economics-dominated, and "where applicable" leaves which meters count to executor judgment. Two executors could construct materially different billing days. Resolution: specify the day's activity profile (e.g., suite runs at a fixed cadence plus measured idle, reusing the methodology already embodied in `cloudflare/test/billing-windows.mjs` and `validate-idle-measurement.mjs`) and enumerate the meters that count for the per-app attribution.
2. **(Moderate) The adversarial two-app leg has no pass criterion for its noisy-neighbor probe.** Lines 182–189 enumerate probes, and four of five are boolean (state separation, loader-name collisions, artifact/cache confusion, cross-app binding attempts), but "noisy-neighbor resource contention" is a continuous measurement with no threshold, so Gate 0 criterion 1's "pass" is not decidable on that sub-probe. Resolution: either state a contention budget (e.g., app B's p95 under app-A load ≤ N× its solo p95) or explicitly delegate the contention decision rule to the LLP 0009 reviewer's pre-signed probe list, with the rule recorded in the comparison artifact.
3. **(Minor) The recorded toolchain identity quotes caret specifiers as "the repo pins" and does not match the lockfile.** The progress note (lines 143–145) and spike README record miniflare 4.20260701.0 / workerd 1.20260707.1; `package.json` actually specifies `^4.20260701.0`/`^1.20260707.1`, and `bun.lock` resolves miniflare@**4.20260706.0** (whose own bundled workerd dependency is 1.20260706.1; the top-level workerd resolves 1.20260707.1). Since the note's stated purpose is that "the claim stays evaluable if the pins move," and the Gate 0 artifact requires toolchain identity, the recorded versions should be the resolved/runtime-reported ones. Resolution: correct the progress note to lockfile-resolved versions and require lockfile-resolved (not specifier) versions in the Gate 0 artifact's toolchain field.
4. **(Minor) Gate 0 criterion 2's "facet-local storage suffices for role-local state" has no named observable.** Lines 246–247. The handler's role-local state is not enumerated anywhere, so "suffices" is not independently decidable. Resolution: name the role-local state the candidate topology actually stores facet-locally (or state that today it is empty and the criterion is "nothing app-data-shaped leaks into facet SQLite," checkable by inspection of the facet DB after a suite run).
5. **(Minor) Phase 1's immutability proof is asserted but not named as a gate.** Line 288: "content-addressed immutability is proven (a stored hash never resolves to different bytes)" — no test is named, though the machinery half-exists in the proposed `SNAPBACK_CF_APP_ARTIFACT_HASH_MISMATCH` gate (line 315). Resolution: state that the hash-mismatch load-path gate, exercised against a deliberately corrupted fixture, is the immutability proof, making it one of the enumerated Gate 1 deliverables.
6. **(Minor) Gate 2 exit's 14-day soak has no activity floor.** Lines 396–403 define attribution and baseline capture well, but "normal All Aboard traffic" on a demo system could be near zero, letting the soak pass vacuously. Resolution: add a minimum activity condition (e.g., daily remote-runner executions against the live instance count as soak traffic) or record the limitation explicitly.
