## Transition mapping (old → new)

Policy now returns `Result<Transition<T>, RuntimeError>`. Adapter errors (`?` from SQLite / JSON parse) stay `Err` and never become a `Transition`. `apply` at `snapback4/crates/snapback4-core/src/engine/actions/steps.rs:79-85` is the only commit switch:

| Outcome | Kernel | `apply` | Matches old |
|---|---|---|---|
| New row / take-over / done replay / complete write / `park_action_step` success | `Applied` | `commit` + `Ok` | yes |
| Changed input, busy, unknown, result mismatch, complete-on-parked | `Refused` | `Err`, `Tx` drop | yes (`return Err` with no `commit`) |
| Claim/state fence miss | `ClaimLost` | `Err(lease_error())`, drop | yes |
| Begin-without-reconcile park; oversized complete | `CommitRefusal` | `commit` then `Err` | yes (`commit()?; return Err`) |
| Adapter/SQL/`Store` failure, including `finish_parked` after `park` | `Err(RuntimeError)` | `transition?` drops `Tx` | yes (park + owner finish roll back together) |

`Tx` has no custom `Drop`; it wraps `rusqlite::Transaction`, whose drop rolls back. Refusals do not need an explicit `rollback()` to match the old paths.

`CommitRefusal` vs `Refused` is not a no-op distinction on the parking paths: unreconciled begin and oversized complete both mutate the step row and call `finish` (`invalidate_session` + `_requests` park) before committing. Using `Refused` there would drop the park. Tests that observe parked owner + dead lease actually pin that.
