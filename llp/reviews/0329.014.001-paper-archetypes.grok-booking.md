```ts
export const createBooking = mutation({
  resourceId: id(resources), holderId: id(), start: time(), end: time(),
}, ({ db, ctx, args }) => {
  const r = db.get(resources, args.resourceId)
  db.require(r !== null, 'RESOURCE_NOT_FOUND')
  db.require(r.retiredAt === 0, 'RESOURCE_RETIRED')
  const me = ctx.viewer
  const holderId = args.holderId
  db.require(isMember(r.orgId), 'NOT_PERMITTED')
  db.require(holderId === me || isManager(r.orgId), 'NOT_PERMITTED')
  db.require(args.end > args.start, 'BAD_INTERVAL')
  const duration = args.end - args.start
  db.require(duration >= r.minDurationMs && duration <= r.maxDurationMs, 'DURATION_OUT_OF_RANGE')
  db.require(args.start - ctx.now() <= r.maxAdvanceMs, 'TOO_FAR_IN_ADVANCE')

  const ex = exclusionOf(r, args.start, args.end)
  const pred = db.scan(bookings.byResourceStart, [args.resourceId], {
    order: 'desc', take: 1, range: { lt: ex.exclusionEnd },
  })
  if (pred.length > 0 && pred[0].exclusionEnd > ex.exclusionStart) {
    db.require(false, 'SLOT_UNAVAILABLE') // freeAt = pred[0].exclusionEnd; sealed if we relied on exclusion alone
  }

  const live = db.get(liveByHolder, [r.orgId, holderId])
  db.require((live === null ? 0 : live.n) < 5, 'HOLDER_QUOTA_EXCEEDED')

  // I7: argument-scoped only. On-behalf cannot see other-org strikes (K2).
  db.require(holderId === me, 'CANNOT_CHECK_SUSPENSION')
  const recent = db.scan(cancellationLedger.byHolderOccurred, [holderId], {
    range: { gte: ctx.now() - 90 * 86400000 }, take: 64, order: 'desc',
  })
  db.require(!recent.hasMore, 'HOLDER_SUSPENDED') // conservative at cap
  const waived = new Set()
  for (const row of recent) if (row.kind === 'waiver') waived.add(row.offsetsLedgerId)
  let strikes = 0
  for (const row of recent)
    if ((row.kind === 'late_cancel' || row.kind === 'no_show') && !waived.has(row.id)) strikes++
  db.require(strikes < 3, 'HOLDER_SUSPENDED')

  const id = ctx.newId()
  db.insert(bookings, {
    id, orgId: r.orgId, resourceId: args.resourceId, holderId, bookedBy: me,
    status: 'confirmed', start: args.start, end: args.end,
    exclusionStart: ex.exclusionStart, exclusionEnd: ex.exclusionEnd,
    holdExpiresAt: 0, policyAnchorStart: args.start,
    cancellationCutoffMs: r.cancellationCutoffMs, lateCancelFeeCents: r.lateCancelFeeCents,
    policyVersion: r.policyVersion, seriesId: 0, occurrenceIndex: 0,
    createdAt: ctx.now(), confirmedAt: ctx.now(), cancelledAt: 0, cancelledBy: 0,
    cancelReason: '', wasLateCancel: false, checkedInAt: 0, rescheduleCount: 0,
    promotedFromWaitlistId: 0,
  })
  return id
})
```

Quota is `liveByHolder` after `expireHold`/`markEnded` have flipped status — without those schedules the maintained count is **high** (safe) while leftover future holds exist, and **high** (wrong, blocks booking) if completed rows are still `confirmed`.   const candidates = db.scan(waitlistEntries.byResourcePosition,
```ts
    [freed.resourceId, 'waiting'], { order: 'asc', take: 64 })
```

```ts
export const availabilityForDay = query({
```

### 6. Language delta

Ranked by whether this app’s central invariants stay slogans without them.

1. **Partial `exclusion` / empty-interval semantics.** `exclusion({ on, interval, where })`, and `[from,from)` does not overlap. *General* (any occupancy state machine). Amends §2 constraints. Smallest addition that actually encodes I1+I2. Total exclusion plus a sentinel key is the T3 denormalization the spec thought it had deleted.

2. **Partial `unique` / partial `cap`.** `unique(..., { where })`, `cap({ by, max, where })`. *General*. Amends §2. The `waitingKey` discriminant is a workaround, not a declaration; a total `cap` on waitlistEntries fights I2.

3. **Calendar arithmetic or a calendar kind.** `zonedLocalTimes({ tz, mask, minuteOfDay, from, to, max })` as a bounded, deterministic operator, **or** a first-class `effect` seam that is the only legal producer of `bookingSeries` occurrences. *General* for recurrence; this app is the witness. Amends §4.1 / §7. Without it I8 is unenforceable and `createSeries` is `E_OPAQUE`.

4. **`optional(t)`.** Sentinel `0` collides with epoch and with `id()`. *General*. Amends §2 column types.

5. **Conditional `immutable`.** `immutable(['policyAnchorStart'], { unless: … })` is the T2 declaration. *General* (any frozen-unless-advanced field). Amends §2. Until then T2 is a `require` every author can forget.

6. **Schedule `at` on absent/zero timestamps.** Do not enqueue when `at` is 0/open. *General*. Amends §7. Otherwise every confirmed booking enqueues `expireHold` at epoch.

7. **Channel probe budget = rule of the routing row.** One hop through `ref` to membership, or channels cannot be resource-scoped without a forged `orgId`. *General*. Amends §8.

8. **`E_STRUCTURAL_COUNT` applies to loop tallies, not only `page.count()`.** If it does not, K2 is bypassable. *General*. Amends §9. Confirm by running `let n=0; for (const r of db.scan(…)) n++` in `check`.

9. **Self-row exemption and deferral for `exclusion`.** Update-of-self and M10 two-phase should not be folklore. *General*. Amends §2 / `E_CONSTRAINT`.

10. **Cross-column FK / `check` constraints.** `bookings.orgId === resources.orgId`. *General*. Amends §2. I10 remains a `require` in every writer.

11. **Catch `E_CONSTRAINT` without aborting the transaction** (savepoint) for `skip-conflicts`. *App-specific preference*; pre-check is the v0 path. Amends §4 / §9. Do not add until skip-conflicts is shown to be more than a product mode.

Not missing, despite the original paper: range+order `scan` (§4.2), `if` conditional writes, `patchWhere`, `maintain`+`readable`, `appendOnly`, `immutable`, `schedule`/`system`, `interval` columns, `ctx.now` in mutations. ### 8. Where the design is wrong

**1. Q2’s standing formula is false under I12.**  
`aheadOfMe = waitingCount − (nextPosition − position)` simplifies to `trueAhead − withdrawnAfterMe`. Confirm: A,B,C join (positions 0,1,2); C withdraws; B asks standing. True ahead is 1; the formula returns 0. Observation: one `withdrawFromWaitlist` of a later entry changes an earlier entry’s displayed rank without any write to that entry.

**2. T1 (and the `exclusion` v0 added for this app) conflate display-liveness with exclusion-liveness, and total exclusion does not encode I1.**  
A past `confirmed` row with `blocksCalendar=true` is **not** an I1 bug: the predecessor test against a future candidate fails on `exclusionEnd`. The only clock transition that must write for I1 is **future-hold expiry** (and cancel of a future row). Confirm: overlap-check a slot next Tuesday against a last-Tuesday confirmed booking that no sweep has touched; I1 holds. Separately: insert a `cancelled` row that still carries `[exclusionStart, exclusionEnd)`; v0 `exclusion` refuses a new live booking of that slot. Confirm: I1+I2 as specified is not the constraint in §2; the author must move the key (T3).

**3. I8 is a slogan, and `confirmHold` is missing.**  
The engine never witnesses that `starts` are Mondays at 09:00 in `organizations.timezone`. Confirm: `createSeries` with `weekdayMask` Monday and `starts` that are Tuesdays commits. DST: two “weekly 09:00” instants are not a fixed millisecond period; no admitted operator produces them. Also: promotion inserts `held`, and no named mutation accepts it — the design’s state machine has an unreachable `held → confirmed` from the waitlist path. Confirm: after `offerFreedWindow`, the holder has no legal program to confirm except the unstated `confirmHold`.
