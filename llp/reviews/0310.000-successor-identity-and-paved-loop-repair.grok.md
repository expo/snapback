## 3. Concerns

### MATERIAL — Track A’s “observe the new extra” fork can bypass 0302

**Where:** Track A step 2: “Invalidate the Metro module that inlined the previous extra, *or* push a replacement extra the running bundle will observe without a full owner restart.”

**Why it matters:** 0302 is a declared-dev gate. The paved repair is: rewrite the artifacts the gate already reads (supervised receipt + bundler extra), then make the running web arm load those artifacts. “Push a replacement extra the running bundle will observe” reads as a live in-memory identity patch. That is a second declaration path. It is how an implementer “fixes” M2 without a bundle reload and accidentally lets a client handshake with an identity that is not what the receipt says — the same class of failure as weakening mismatch against a foreign backend, just homegrown.

Owner restart is correctly forbidden. Metro/bundle reload is not owner restart and is the feasible Expo mechanism (`expo-constants` / `EXPO_PUBLIC_*` extra is bundle-time). The RFC does not pick that.

**Resolve:** One mechanism, written as a constraint: recook the receipt and the extra 0302 already consults; observe via Metro/bundle reload (cache invalidate allowed); no runtime identity setter, no second extra channel. Keep the mismatch predicate unchanged (`receipt` vs generated `app`).

### MATERIAL — success-path transition can still split-brain (the reverse of F1)

**Where:** Ruling 1 “before the next client handshake”; Track A step 3 (web-arm ack); Track A step 4 (refuse *if recook fails*, before serving the new identity).

**Why it matters:** Step 4 only specifies the failure path. The success path has two illegal windows:

1. Backend already serving successor, web arm still on M1 extra → F1, which you correctly refuse.
2. Extra/receipt already recooked to M2 (and the web arm may have acked), backend still serving M1 → handshake with the new descriptor against the old serving identity. That is also a 0302 mismatch, and it is what you get if you wait for web-arm ack before flipping the backend.

“Before the next client handshake” is an invariant, not a protocol. Without a freeze (or equivalent: drop/hold the web arm until extra reload *and* successor serve are both done), implementers will order recook, ack, and activate in a way that still blanks the client. That is the 0.1.27 failure with more moving parts.

**Resolve:** Add a success-path table in Track A, for example: freeze web handshake for that arm → rewrite receipt+extra → Metro/bundle reload → activate successor → unfreeze. Any failure rolls back extra or refuses successor (your step 4). Ack is an internal checkpoint, not a license for the browser to talk mid-transition.

### minor — caller-owned canonical path is implied, not contracted

**Where:** Ruling 2 (caller-owned is canonical) vs Track A (“inside an owner that is also running Expo web / Metro”) and step 1 (“supervised integration receipt”).

**Why it matters:** If generate/successor already rewrites the project extra on disk, caller-owned 0300 is “boring reload” and Track A is correctly the supervised running-process hole. If it does not, the product rule is false for the canonical loop. The RFC never says which.

**Resolve:** One sentence: caller-owned extra on disk is rewritten by generate/successor; a client/Metro reload is the 0300 recovery; Track A is only for the owner-managed running extra/receipt.

### minor — Track B can accidentally describe two backends

**Where:** Track B1 “injects `EXPO_PUBLIC_SNAPBACK_URL` *in addition to* the supervisor origin.”

**Why it matters:** 0302 is about not sending credentials to the wrong backend. Supervisor origin plus backend origin is fine only if the supervisor is not a Snapback data/auth plane. B1 does not say that.

**Resolve:** One data/auth base URL (the backend origin). Supervisor origin is control plane only. If a mint exists, it is for that same backend origin, and it is opt-in, not boot default.

### minor — Track E control channel is specified as a path, not as a trusted interface

**Where:** Track E “unix socket or a well-known fifo next to the ready file”; recook/reload/stop children.

**Why it matters:** A world-writable socket that can recook identity or stop children is a local-dev safety hole. Fifo open/blocking/interleaving is a footgun. Calling E “straightforward” while A’s reload may travel on it undersells the surface.

**Resolve:** Unix socket, owner-only (`0600`, same uid, in the owner state dir). Fifo is non-goal or a documented fallback. Name the verb set (reload Metro, stop children, recook if not automatic). Stdin stays beside it (OQ3’s proposal).
