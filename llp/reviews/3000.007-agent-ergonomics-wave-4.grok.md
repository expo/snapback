## Findings

### 1 — High — orphan journal with no kept backend wedges open

**Where:** `snapback4/packages/snapback4/src/web.ts:306–309` (constructor), catch at `98–103`.

**Scenario:** Tab B opened a tab-scoped store (`name:tab-…`), `mutate` journaled into localStorage (so `journalStores` will list it), then the tab-scoped IndexedDB is gone or empty (IDB eviction, DevTools clearing IDB but not localStorage, or `load()` of a name that only exists as a journal key). The next open of the **primary** store:

1. `journalStores(\`${name}:tab-\`)` returns that orphan name (`web-journal.ts:45–51`).
2. `persist.load(orphan)` is `[]`.
3. `new WebDevice(null, "[]")` (`web.ts:309`) hits `Device::open_store` with no backend (`web.rs:27–37` → `device.rs:255–259`) and throws “this device has never synced”.
4. `adoptOrphans` has no inner catch; `open`’s catch discards the primary device (`web.ts:101–103`).

The viewer cannot open that origin store until the leftover `snapback4-admission:` keys are deleted. §20.4 / the writes card call storage clearing a **lost write**, not a stuck client. Primary-only journals do not hit this (restore passes the live backend).

**Smallest fix:** If `saved` has no kept backend / `device:store_id`, skip `WebDevice(null, …)` and continue the orphan loop (leave the journal). Catch constructor/recover failures per orphan so one bad name cannot fail `open`.

### 2 — Medium — published 82/41 cost is not pinned; card says “rows”

**Where:** `snapback4/crates/snapback4-lang/src/guide/feeds.md:270–272`; `packages/snapback4/README.md` (Feeds section, live-page paragraph); `crates/snapback4-sim/tests/common/following_removal.rs:125–146`.

**Scenario:** The 40-event fixture’s uncut page is 82 **examinations** and 41 **rule probes**, not 82 feed rows (41 candidates × scan + tombstone `get`). `check_cut` prints `uncut_probes` and uses `cost = uncut.metered.examined` for the sweep but never asserts `82` or `41`. Ceiling 25 is asserted incomplete, not empty. A later merge/filter change can drift the advertised numbers while tests stay green.

**Smallest fix:** Assert `uncut.metered.examined == 82`, `rule_probes == 41`, and at examined 25: `data` empty, `next` none, `complete == false`. Say “82 examinations” on the card and README, matching §20.12.

### 3 — Medium — Following cut sweep never exercises the broadcast lane

**Where:** `snapback4/crates/snapback4-sim/tests/common/following_removal.rs:109–118` (`seed_cut` → `seed(engine, 5)`); recipe lanes at `guide/feeds.md:214–216`.

**Scenario:** Following is an **eager** merge (second lane is another table with loop setup, so `lazy_merge` is false — `rules.rs:82–96`). The leak sweep only runs the inbox lane (5 followers, no `pulls`). Celebrity Following (32 pull sources, `broadcast[…]` + the same `where`) is tested for purge/fill, not for “every examined ceiling returns no removed id/body and no cut cursor”. The filter implementation is shared, but eager multi-lane collection plus `merge_can_continue` is exactly where wave 3’s cut bugs lived.

**Smallest fix:** Repeat `check_cut` on a promoted author (followers > 50) so at least one broadcast source is live during the 1..=cost sweep, on server and both device stores.

### 4 — Low — `journalStores` one bad key disables all tab-suffix journal adoption

**Where:** `snapback4/packages/snapback4/src/web-journal.ts:45–51`.

**Scenario:** `decodeURIComponent` is mapped over every `snapback4-admission:` key in one `try`. A single malformed `%` sequence throws and the function returns `[]`. Closed-tab **journal-only** orphans are then invisible to `adoptOrphans` (IDB orphans from `persist.others` still work). Own keys are `encodeURIComponent`-safe; this is same-origin pollution.

**Smallest fix:** Per-key try/catch; skip the bad key.

### 5 — Low — language card Following is not the tombstone recipe

**Where:** `snapback4/crates/snapback4-lang/src/guide.rs:363–367`.

**Scenario:** The language card now compiles merge-`where`, but the predicate is `.body != ''`. An agent that copies only that block still serves removed inbox rows (with body) until purge. The comment points at `guide feeds`; the feeds card is correct.

**Smallest fix:** Keep the toy predicate if `removedEvents` is out of schema, but say explicitly “this is syntax, not removal”.
