1. **Major — Nonce-challenge semantics: internal contradiction plus an unauthenticated rotation/DoS lever.** The doc says a lost response is recovered by presenting the retired generation and receiving "the still-current nonce" (llp lines 186–189), but the code path for both a missing proof and a wrong-nonce proof calls `fresh_challenge` → `issue_sender_nonce`, which **overwrites** the family's durable current nonce with generation+1 (sender_proof.rs:765–773, 860–869, 606–625). 4. **Concerns**

1. **Major — verification-order step 2 contradicts the document's own pre-body rule and its pinned tests.** Step 2 (lines 236-238) places the LLP 0058 forbidden-authority-field *body* check before proof-shape/verification steps 3-8 and body ingestion at step 9 (line 239), while the Summary states the server verifies the proof "before resolving the bearer or reading an application body" (lines 166-167) and the checkpoint/tests prove admission completes with a body that panics on poll (src/server.rs:23653-23751, `PanicOnPollBody`). LLP 0058's own gate requires the wire sidecar to be consumed before its field inspection (0058 lines 1075-1081), so step 2 cannot run pre-body. As written, a request with both an invalid proof and a forbidden body field must yield `SNAPBACK_AUTH_BODY_AUTH_UNSUPPORTED` per the ordering, but the implementation returns a sender-proof diagnostic without ever reading the body — the two normative texts are unimplementable together. Resolve by restating the composition: sender admission precedes body ingestion; the 0058 forbidden-field check retains its precedence *within* post-admission processing (i.e., it wins over credential resolution, not over sender admission), or explicitly change the wire order and the tests.
2. **Moderate — the `SNAPBACK_AUTH_REQUIRED` precedence rule is contradicted by a committed test.** Lines 240-244 say an absent or unparseable bearer yields `SNAPBACK_AUTH_REQUIRED`, "not a sender-proof diagnostic". The pinned test sends `Bearer malformed-session-carrier` (unparseable as a session token; `SessionBearer::parse` fails, family `None`) and asserts `SNAPBACK_AUTH_SENDER_PROOF_REQUIRED` plus a 43-char `DPoP-Nonce` (src/server.rs:23667-23696; code path src/server.rs:8391-8406 → sender_proof.rs:757-773). Either the doc means only an absent/malformed Authorization *header* (then say so — the anti-oracle rationale at lines 292-294 supports challenging format-invalid tokens), or the code and test are wrong and this belongs in the defect ledger. Right now a conformance tester cannot tell which artifact is authoritative.
3. **Moderate — the canonical-URI normalization algorithm does not describe the implementation.** Lines 244-249 specify a path "normalized by *resolving* `.`/`..` segments"; the implementation rejects any path containing `.` or `..` segments, any `%`, any `\`, or any empty segment (src/auth/deployment.rs:376-390) — it never resolves anything. Rejection is the stricter and better behavior, but a second implementation following the spec as written would accept (after resolution) requests this server refuses, and the two would compute different proof URIs for the same wire request. State the actual algorithm: reject, don't resolve.
4. **Moderate — the per-custody request-serialization rule is normative but unimplemented and untracked.** Lines 402-410 require the client to issue at most one outstanding protected request per installation and queue concurrent calls. No such queue exists around `#senderFetchJson` (packages/snapback-client/index.mjs:1985-2044; concurrent callers each sign under the same generation), and this gap appears in neither the defect ledger (lines 128-156) nor the remaining-work list (lines 121-126). Given the document's own standard — every norm the code violates gets a ledger entry — add it to one of the two lists (it also interacts with defect 5's committed-effect-observed-as-failure hazard).
5. **Minor — the retention "equivalently" parenthetical is not an equivalence.** Lines 251-254: `iat + 30 + 1` equals "first-admission time plus the full 35-second window plus one second" only when admission happens at the earliest instant (`iat − 5`); for later admissions the two formulas diverge by up to 35 s. Since the ledger (item 4) and the fix will be judged against this sentence, drop the parenthetical or state it as an upper bound. Relatedly, ledger item 4's "requires window plus skew" doesn't match the actual rule ("`iat+30+1` with exclusive purge").
6. **Minor — checkpoint header staleness and diagnostic registry.** The checkpoint is dated 2026-07-22 (line 34) but records round-1-fix events from 07-23 (e.g., the reflected-nonce gap closure, verified at index.mjs:1951-1958). Also `SNAPBACK_AUTH_SENDER_PROOF_AUTHORITY_UNAVAILABLE` is emitted (src/server.rs:8291) and specified (line 446) but is absent from LLP 0060's reserved sender-diagnostic list (0060 lines 908-910); the reservation there should grow the fourth code when this Spec is accepted.
