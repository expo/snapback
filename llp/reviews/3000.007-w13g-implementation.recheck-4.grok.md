## 1. The High

Both adapters now implement the same predicate:

```sql
SELECT EXISTS(SELECT 1 FROM _log WHERE t = ?1 AND id = ?2 AND seq > ?3 AND kind IN ('put', 'del'))
```

Postgres binds `$1..$3` (`storage.rs` 36–38; `postgres/log.rs` 29–30). The trait gloss says “any put/del row transition” (`storage.rs` 31–32). `join_completion` still discharges with `tx.written_after(&marker.table, id, selection.seq)` (`partition.rs` 707).

The old `(t, id, seq)` index is dropped and replaced on open with `_log_row_seq_kind ON _log(t, id, seq, kind)` in both adapters (`store.rs` 132–133; `postgres/mod.rs` 100). The distinct name is required: `IF NOT EXISTS` on the old name would have kept the uncovered index. `written_after_reopened_store_replaces_the_uncovered_index` opens the old shape, reopens twice, and asserts columns `["t", "id", "seq", "kind"]` and absence of `_log_row_seq` (`rows.rs` 178–192).

The query-plan pin is:

```text
SEARCH _log USING COVERING INDEX _log_row_seq_kind (t=? AND id=? AND seq>?)
```

(`rows.rs` 165.) `kind` is not in the seek tuple; it is filtered from covering index columns, so there is no table lookup. Hit and miss both assert `FullscanStep == 0` (`rows.rs` 172). That is the rare-path cost the brief asked to keep: one indexed existence probe, O(log L) plus any same-`(t,id)` index steps, no image read on a hit (`partition.rs` 703–708). Postgres is the same SQL and the same four-column index; there is no live-cluster plan pin (compile-checked only, as in prior rounds).

**Recheck-3 table against the code.** For text group `g`, `canonical_json(["g"])` is the legal content id `[{"String":"g"}]` (`recheck.rs` 181–182; `value.rs` 347–360, identity is a 144-byte bound, not a namespace). `last 2`; p1 carries that id at 1500; p2=2000; p3=3000; Charlie’s hidden `mc` is in `g` (world A) or `h` (world B); Bob joins `g`; p3→1000; then either Charlie’s `scope` (delete `mc`) or Charlie’s `join` (seed `mc` after Bob). Bob’s stream is p2/p3 only; private membership never appears (`recheck.rs` 218–222). Charlie’s private ledger is pinned as one `join` or `scope` on `t="posts"` with `id=canonical_json([group])` (`recheck.rs` 208–211). Membership events use the **content table** as `t` and `canonical_json(group)` as `id`, in the affected principal’s partition (`partition.rs` 212–216). Another principal’s membership is not in this device’s spans (`partition.rs` 578–586).

Unwritten worlds both publish one completion at p2’s 2000 key, with `payloads[0] == payloads[1]` (`recheck.rs` 231–232, 238). Local suffix is `[p2]` and incomplete/unknown when asked for two rows (`recheck.rs` 233–236). A genuine `put` or `del` of the colliding row still discharges: completion at 1000; put returns p2/p1, del returns p2/p3, both complete (`recheck.rs` 213–216, 226–236, 249–255). The same six pairings run on sqlite and memory hosts, and again through HTTP/wasm (`horizon-boundary.test.mjs` 302–351), comparing bodies after stripping `store_id`.

**They would fail on `00f439892a`.** Recheck 3’s query was `EXISTS (... t = ? AND id = ? AND seq > ?)` with no kind predicate. World A’s hidden `scope`/`join` for group `g` would have discharged p1 and published 1000; world B would have published 2000; byte-identity would fail. The new unit test asserts `join`/`scope` for the same `(t, id)` do **not** count (`rows.rs` 158–161). On the old predicate those asserts are false, and the four unwritten device tests / two unwritten wasm tests fail, matching the fix-4 red summaries (2 passed / 4 failed device; 4 pass / 2 fail wasm — the row-event controls still pass because a real `put`/`del` discharged even then).

## 2. What else is in `_log` for a `(t, id)`

`EventKind` is closed: `put`, `del`, `scope`, `join` (`partition.rs` 61–90). `parse` accepts only those four lowercase words. Production appends via `event.kind.word()` (`partition.rs` 468; `store.rs` 478–481). `_commits` is a different table.

| Writer | Kind | `(t, id)` | Can collide with a content row? | Query now |
|---|---|---|---|---|
| `row_changed` content sync | `put` / `del` | content table, row id; partitions = current / left groups | Yes — it *is* that row | **Counted** |
| `row_changed` dependent membership | `join` / `scope` | **content table**, `canonical_json(group)`; principal partition | Yes — same namespace as a legal row id | **Excluded** |
| `append` coalescing | last `put`/`del` per `(partition, table, id)` in the commit; joins/scopes kept | same | same | same |
| `group_at` / join expansion | reads `put`/`del` from the group partition; synthesizes stream `put`s at **join_seq**, and a stream `scope` for an expired predecessor | row id / group json | Stream only, not a new `_log` row; join-seq is not `seq > join_seq` | Not counted (correct) |
| Catch-up expiry synthetic | stream `scope`, `id = group` | group json | Stream only, not `_log` (`partition.rs` 608–616) | Not counted (not a row event) |
| Snapshot `group_rows` | stream `put`s of current rows | row id | Not `_log` | N/A (`join_completion` is catch-up only) |
| Tests | `append_log` of all four kinds | as written | as written | as asserted |

No fifth kind exists. A membership `join`/`scope` is the collision the High named; it is excluded. A content `put`/`del` is the row transition the device’s authorized spans carry after catch-up (`partition.rs` 139–151: puts to current partitions, dels to partitions left). `written_after` is still partition-agnostic among `put`/`del`; for a Target-audience row that sat in this group at `join_seq`, that is the same boolean as “this device will receive a later put or del for that id.”

**Wrongly retained (fail-closed)?** The query no longer counts `join`/`scope`. Those are membership transitions, not row images. The device may receive its *own* later `scope`, but that is not a write to the colliding content row. Excluding it cannot leave the device certified for a row it will not hold. Fail-closed relative to the old query is the repair.

**Hole (counts what the device does not receive)?** `put`/`del` for this `(t, id)` are that one content row (`r` is `PRIMARY KEY (t, id)`). Another principal’s hidden membership is `join`/`scope` and is no longer counted. I found no `put`/`del` the query still sees that is not a write to this row.

## 3. Leak-freedom and the argument

The journal now says the decision is a function of the delivered rows, the current readable images, and the **post-join row-event set** for this group’s table — the events the device itself receives — and that an unwritten blocker is precisely an undelivered readable row (`JOURNAL.md` 32514–32521). The `@ref` at the decision says the same (`partition.rs` 692–693). LLP 3000 §7 still holds: the wire carries current readable images or a deletion, never a withheld historical key as a published floor (`llp/3000-snapback4.explainer.md` 651–658; `partition.rs` 654–657, 713–716). Selection remains join-time (`expand_joins` 760–765; LLP 3000.007 §18.2).

The implemented rule is unchanged except for the predicate:

- `whole` publishes `"whole"` with no probe (`partition.rs` 696).
- Otherwise K starts as the oldest *delivered current* selected key (`697`). Empty delivered → no completion (`697`, `646`).
- Unselected tail walked descending; `key < oldest` breaks before any log query (`703–705`).
- Remaining candidate discharged iff `written_after` (`707`) — now row events only.
- Else fetch current; require present, readable, still in the group (`709–711`). First such is the greatest blocker; K becomes the next delivered key strictly above that historical key, or `None` (`712–714`).

**Recheck-3 pair:** both worlds unwritten at the colliding id → both 2000, identical payloads. **New pair I tried:** same current images and post-join *row* events, differing only in Charlie’s hidden `join`/`scope` target (`g` vs `h`), or in extra membership events for the colliding id: the walk may still probe, but `written_after` is false in both, so publication matches. An unwritten pair whose historical keys differ (1500 vs 1200) also has different *current* images, so it is not withheld-only. A later `put`/`del` of the colliding row is received as a row event and correctly discharges in both worlds (1000).

**Pre-existing, not this round:** if a withheld key would change the top N, the delivered *rows* differ. That is join-time selection (`expand_joins` 760–765).

Paging can still publish the end marker before a discharging `put`/`del` appears on a later page (`more` still true; `recheck.rs` 98–104). After catch-up the device holds the row. That is the existing R2 behaviour, not a new hole.
