The remaining findings are:

1. **Blocker — §§3, 4.5, 7: activation can resurrect an old child into a replacement parent.**

   At time 90, parent `p` belongs to A and expires at 100. Child `c`, with no authored expiry, captures A and 100. At 110, replace expired `p` with a parent belonging to B, expiring at 200. Leave `c` unswept. Change a captured dependency, such as the parent read rule, and activate.

   Section 7 finds a live parent and recaptures B and 200. Now `c` is live and disclosed to B. There is no hand-copied audience column to trigger the disagreement check. The lifetime argument allowed the replacement precisely because `c` was dead; recapture destroys that premise.

   Conversely, sweeping only the parent leaves an expired child that unnecessarily blocks activation as an orphan. [Activation walks physical rows](<../../snapback4/crates/snapback4-core/src/store/activation.rs:204>).

   **Smallest change:** inspect expiry under the **previous schema at one pinned activation time**, before projection or recapture. Retire previously expired affected rows transactionally; never give them a later lifetime by recapturing. Then capture live rows, rebuild, validate and publish. Filling required captures must precede the ordinary validation currently performed before the activation builder.

2. **Blocker — §§3–4, 7: imports and restores are outside the invariant.**

   Start with live `p.org = A` and live child `c` capturing A. Import a replacement image `{id: p, org: B}`. The existing import path writes parents directly with `tx.put`; it does not enforce their immutable constraints or recapture existing descendants. The result is a live child whose captures differ from its live parent. A parent-pinned verdict for B can then admit A’s child.

   Trusted restore similarly accepts stored images without relational validation. Seed batches have another complication: their anticipated target images are assembled before ordinary writes, so a three-level capture needs an explicit dependency order. See [load and restore](<../../snapback4/crates/snapback4-core/src/engine/mod.rs:1090>).

   **Smallest change:** make lifetime and capture equality structural invariants at every server ingestion boundary. Imports must preserve immutable parent inputs or undergo an explicitly defined atomic migration; new captures must be resolved ancestor-first against the final batch. Restores must validate a coherent graph under the matching schema before serving it. System authority may bypass ACLs, not these invariants.

3. **High — §§3.2, 5: clock skew breaks the device lifetime premise.**

   Parent and child expire at 100. The server is at 110; the device is at 90. The server sweeps or replaces the parent and delivers that event before sweeping the child. The device removes or replaces the parent, but still considers the old child live until its own clock reaches 100.

   This creates either a locally live orphan or live children with captures different from the newly received parent. The new single-parent verdict is unsafe in that combined state. Device queries currently use the [caller-supplied clock](<../../snapback4/crates/snapback4-device/src/device.rs:824>).

   **Smallest change:** define a monotone device expiry time that is at least the server time associated with applied authoritative changes, and apply that advancement atomically with replacement/deletion and dependent replay. Scope disconnected expiry to the device’s clock; “the same instant” across skewed offline clocks is not implementable.

4. **High — §§3, 5: unswept children disclose an earlier tenant’s population through keyed reads.**

   Compare two stores after A’s parent expires and its id is reused by B. Both have the same live B parent and no live children. One also has 1,000 unswept expired A children.

   B requests the parent-pinned page or keyed count. Both answers are empty or zero, but the latter store examines the old children and can hit a meter cut. The ordinary page and live-aggregate paths charge candidates **before skipping expired rows**. Key-only access therefore does not remove this disclosure. [Live aggregate recomputation](<../../snapback4/crates/snapback4-core/src/engine/read.rs:255>) also retains physical contributions until removal, as LLP 3000.007 §20.9.3 requires.

   **Smallest change:** refuse reuse until the old physical children and their contributions have been removed, or retain a relation discriminator that excludes them from the new parent’s seeks. Logical expiry alone is insufficient.

5. **High — §§4.4, 6: capture reservation still occurs too late for upsert.**

   Give an upsert enough allowance for ordinary target resolution but insufficient allowance for the additional capture. In the hidden-existing-child world, update authority refuses with normalized `NOT_FOUND`. In the absent-child world, §4.4’s insert-arm reservation reaches `E_BOUND`.

   The refusal table fixes returned codes after an ordinary denial; it does not fix this earlier branch-dependent resource refusal. The existing [common target reservation](<../../snapback4/crates/snapback4-core/src/engine/write_target.rs:38>) is the relevant boundary.

   **Smallest change:** reserve possible capture work **before selecting the upsert arm**, then consume it without charging twice. Include schema-bounded parent/capture heap and all necessary rule allowance; removing hit-only heap charges must not make allocations unmetered. Preserve identical `NOT_FOUND` normalization across the two worlds.

6. **High — §§5–6: parent authority is being used as child coverage and absence evidence.**

   A device fully holds an issue but acquired only ten comments through the comments’ horizon. Section 5’s “found, readable → complete” promises completeness for a request extending beyond those ten.

   The reverse operation has the same missing proof: a device holding the parent but no locally visible children can predict deleting it even though an online-only or unacquired child exists. The implicit reverse lookup is not covered by the stated parent-resolver dependency.

   **Smallest change:** say that the parent resolver establishes **authorization uniformity only**. Keep the child range’s existing [coverage and meter checks](<../../snapback4/crates/snapback4-core/src/engine/read.rs:1087>). Predict parent deletion only when every referencing child population has current, complete coverage; otherwise queue without an overlay. Register those reverse dependencies in residency and replay.

7. **High — §6: the delete refusal assumes read authority that ordinary deletion does not require.**

   Let a caller have `delete <- allow` on a parent it cannot read. With no children, deletion succeeds. With one live child, §6 returns the hidden-target refusal. That reveals whether the hidden child population is empty, even if every refusal has a fixed charge.

   The intrinsic-id [delete path checks delete authority without requiring read authority](<../../snapback4/crates/snapback4-core/src/engine/write.rs:190>). “The deleter can read the parent” therefore is not an existing guarantee.

   **Smallest change:** require parent read authority before *every* deletion attempt on a referenced parent table, including the no-children case, before probing children. State that deliberate restriction on blind deletes explicitly.

8. **Medium — §§3.2, 4.1, 5: inherited expiry needs an explicit recursive definition and classification.**

   Take grandparent G with deadline 100, parent P with `read through .g` and no authored expiry, and child C with `read through .p`. Section 3’s trigger says the parent “declares `expire at`”; P does not. Copying P’s captures alone does not specify which instant drives C’s expiry.

   This matters beyond reads: the binder and engine repeatedly classify expiry through `decl.expire` or `Table.expire`, including the [maintained-column restriction](<../../snapback4/crates/snapback4-lang/src/bind/columns.rs:44>).

   **Smallest change:** define recursively
   `deadline(C) = min(authoredDeadline(C), deadline(P))`,
   with null/absent meaning infinity. Normalize effective expiry before all admission checks. Require that same metadata to govern reads, probes, unique checks, sweep, invalidation and aggregate classification. The three-level probe must expire both P and C at 100 and reject maintained columns over either expiring source.

9. **Medium — §§2.1, 5: the child-only service exception contradicts the parent resolver.**

   The parent does not admit `service:search`, but the child declares:

   ```quarry
   read through .issue or viewer = 'service:search'
   ```

   A child point read admits the service. A parent-pinned page resolves an unreadable parent and returns empty; a keyed aggregate does likewise. Service stripping correctly protects device delivery, but does not reconcile these server answers.

   **Smallest change:** require service grants to live on the parent and be inherited in this revision. Alternatively, define the resolver’s verdict over the complete expanded child rule, including its service exception, after separately proving parent liveness.

What is sound: under a fixed schema and clock, transactional capture plus immutable references and parent inputs supports the equality proof. `insert parent; insert child; delete parent` must refuse because the reverse lookup sees the uncommitted child; deleting the child first permits deletion. Ordinary upsert updates cannot move immutable audience inputs. Jobs can use the same structural checks despite system authority. Recursive minimum deadlines then extend the proof through any acyclic chain.

Whole-rule substitution, live membership probes, exact sync admission, protected hidden fields, independent leave policies, and atomic generation publication are all appropriate. The remaining problems are enforceable boundaries and observable semantics, not a reason to abandon inherited reads.

**Overall verdict: NOT READY.**
