NOT READY. The design is coherent in shape but underspecified at every enforcement boundary it introduces. Do not implement from this revision.

Material findings, each with the fix required:

1. Point lookups are undefined. §2 adds "unique point lookups" to the interpreter with no syntax, no target-table eligibility (active only? dormant? candidate-omitted?), no miss/multi-match semantics, and no authority statement (bypass read rules under activation authority, or evaluate as some viewer?). Fix: give the lookup syntax, restrict targets to named active-table primary-key reads against the pinned pre-adoption snapshot, specify miss and non-unique both refuse E_ADOPT, and state backfill reads run under activation operator authority, bypassing row rules like retained restoration does.

2. In-place transformation is used by the evidence but absent from the language. §5 tests "same-column enum reversal," yet §2 only describes inputs as predecessor fields and outputs as candidate columns, with "all output fields evaluate against that image before any patch applies." Fix: explicitly allow output names that coincide with input names, define the read-old/write-new ordering for that case, and state whether a same-column narrowing (e.g. enum shrink) refuses E_ADOPT per §2 or hides per [retained-storage §9.1](./llp/3000.000.000-retained-storage-and-hot-release.rfc.md). The two rules currently collide on backfill-produced values.

3. Cross-backfill chaining is unspecified. "Lookups read the same pre-adoption snapshot, independent of table walk order" implies table B's backfill cannot see table A's backfill output in the same activation. Fix: state that backfills do not compose within one activation and each declaration must be self-contained, or define a deterministic multi-pass order. The fifty Wave 17 shapes must say which case they need.

4. Single-poison-row veto on both directions. Any missing/mistyped input, invalid output, uniqueness collision, post-backfill edit (§3 leave rule), or unrepresentable v2-native row refuses the entire activation/rollback. This reintroduces refusal semantics the parent RFC deliberately replaced with retain-per-row plus bridge repair ([§3](./llp/3000.000.000-retained-storage-and-hot-release.rfc.md)), and lets one user edit permanently block leaving a release. Fix: adopt the parent's bridge pattern (bridge schema + repair mutation) for each refusal class, require bounded privileged-operator diagnostics (counts plus at most five ids/values, never row contents in application refusals), and change the leave rule default to preserve edited rows and restore only untouched ones, refusing only under an explicit strict flag.

5. Forward-merge rule is ambiguous and overwrites silently. "Preserves v2 edits when predecessor inputs are unchanged; older inserts and changed predecessor inputs are caught up" does not define what an edit is (output-column edit? which columns?), what "predecessor inputs" hashes cover, or whether catch-up overwrites manual v2 edits when inputs changed. Fix: specify a per-row rule keyed on the persisted input hash — input-hash unchanged means preserve current outputs, input-hash changed or row absent from evidence means recompute — and state it before implementation. This is a silent-data-loss hole.

6. Declaration identity and generation binding are missing. "Keyed by declaration content" with "an edited declaration is a new transformation" needs a canonical digest (parent [§11](./llp/3000.000.000-retained-storage-and-hot-release.rfc.md#11-wave-11-factual-release-narration) already learned whitespace/comments must not count), and nothing binds that digest into `activation_hash` or the generation advance. A backfill-only content change may then present stale device images. Fix: define the normalized content digest, mix it into the execution identity, and state that a changed backfill population advances generation while a no-change reopen is a no-op (consistent with §9.1).

7. "Keep declarations in later releases" is unenforced with active reverse effects. Dropping a declaration triggers the §3 leave-restore path, so a silent drop is a data change. Fix: make removal explicit — either refuse activation when a prior declaration disappears without a declared `retire` intent, or state plainly that silent drops restore-or-refuse per the leave rule and test it.

8. Evidence-store lifecycle is half-specified. "Deletion clears evidence so id reuse cannot inherit" must hook into the parent's active-delete invalidation ledger ([§2](./llp/3000.000.000-retained-storage-and-hot-release.rfc.md): every authoritative delete invalidates matching edges in-transaction, rolled back on failed activation). Fix: state backfill evidence rows participate in that same transactional invalidation, not a parallel store, and that failed activation rolls evidence back with everything else.

9. Preview/receipt vocabulary is not plugged into the parent. "Deploy --check executes the same path" must name the intent (deploy vs rollback restoration, per [§10](./llp/3000.000.000-retained-storage-and-hot-release.rfc.md)), the VACUUM-INTO snapshot caveat (point-in-time plan, live writes can change it), and receipt units in the §11 disjoint vocabulary (backfill-transformed rows vs narrowed rows vs restored cells, sorted labelled samples). "Cold and hot receipts expose the same counts" needs field names.

10. Staging clock overclaims and under-gates. "No source, public argument, environment variable or HTTP call can classify a production store" contradicts [staging §1](./llp/3000.000.000.001-staging-with-real-users.rfc.md): `deploy --staging` classifies new stores. Fix wording to "no serve-time mechanism reclassifies an existing store." Further fixes: name the serve-startup refusal when `--clock-offset` meets a non-staging store and state production serve refuses clock advance even with a service session; state whether any full service seat may advance (per the §10 any-service-seat doctrine) with the operator warning; require `startServe` with `clockOffset` to refuse unless environment is staging; and specify the restart-backward-jump law for persisted timed-disclosure floors (floors never retreat below their captured value) instead of "retain their existing law."

11. Interpreter allowlist is open-ended. "Deterministic string functions" with bans on "writes, scans, time, viewer, ids" is a security boundary owned per §1 by SEC3, but unbounded. Fix: enumerate the exact function/type surface, error semantics (division by zero, overflow, byte limits — all E_ADOPT with bounded samples), and confirm the ban list covers randomness and locale-dependent comparison, with the privacy alignment from finding 4 (E_ADOPT names table/backfill/row only in privileged operator output).

12. Evidence traceability. "All fifty historical shapes" and "five copied bakeoff lanes" have no pointers to where the fifty and the five are enumerated. Fix: link the Wave 17 shape inventory and the lane sources so the claim is checkable.

When these are repaired — lookup semantics, in-place and chaining rules, merge/restore refusal policy with bridges, digest plus generation binding, evidence-transaction coupling, receipt vocabulary, and the clock gates — this will be reviewable for READY.
