A check remembers its compiler version, schema source identity, emitted API,
note counts by code and refusal counts in `.snapback4/check-surface.json`.
The first check using a different version compares that baseline with the same
project: newly added notes by code, changed generated row/operation types, and
new compiler refusals. If the source changed too, the delta says so; it does not
attribute application edits to the compiler. Missing baseline means explicitly
unavailable comparison. Compiler refusals preserve the last baseline and generated
API, so a refusal cannot erase the useful pre-upgrade record. Normal same-version
checks refresh it after successful check. A server/native qualification failure
can leave regenerated, valid Quarry types while retaining the previous baseline. JSON check output stays one
JSON object; human delta goes to stderr in that mode. Snapshot write failures
are reported and never invalidate valid product types. No store adoption, sync
or authority change is introduced.

Upgrade takes the old installed CLI's check snapshot before installation, then
invokes the newly installed CLI's check after pinning. It preserves the package
manager's dependency sections and ordinary recovery. A compiler refusal after a
successful install returns nonzero with a message distinguishing installation
from qualification; it never rolls back the packages silently. Module-only backends are projects too: all `snapback/*.q` files qualify through
the same loader; schema.q is not required. Without any Quarry source, upgrade
reports package pins only. Exact apps receive one rebuild pointer:
`bun exact.mjs snapback --rebuild` (HS owns the command and device handshake).
`guide changes` packages the release card; its version is bound to the compiler
version and its factual nullable-count examples are covered by the guide tests.

auto-apply: hidden keys remain null, authorized missing count groups return zero.

A visible form proof is opt-in with `--field LABEL --value TEXT --button LABEL`.
It fills the labelled control, presses the labelled button and observes that
click's matching durable mutation through the registered app client. After filling it arms the exact labelled button, and accepts a mutation entered while
that button's trusted Chromium click remains active (through either client or app).
A form submit event is not click evidence. The default starter calls its shared
submit command from onClick (preventing the duplicate default form action); Enter
continues to use that same command. Short microtasks that remain inside the active dispatch may submit; work after
dispatch ends may not. Finish longer asynchronous validation before enabling
submit. A private witness-only options symbol follows unapproved App calls
through readiness, so a submit/other-context continuation cannot borrow the
restored enclosing click at Client entry. It is never serialized or a client
card field. This scoped proof never attributes background
or input autosave writes to a button. Before clicking it arms a fresh observer: an existing sent status or row cannot satisfy
this proof. It waits for terminal sent and asserts the configured args when
provided; failed or timed-out custody is nonzero. No second SDK mutation is
injected. The ordinary SDK-only witness remains available without these flags.
React Native web uses keyboard events (`pressSequentially`) to settle state;
buttons use their accessible labels, not testID. Registration is flag-gated and
cleanup restores its instrumentation. Starters label their field, render write
status above the list, and supply a favicon.

then the complete PORT_LO/PORT_HI environment pair, then existing defaults.

waits for sent/failed, independently of read subscribers and mounted effects.

settlement or use the explicit custody option and saved id. Existing

relabelled sent. This amends the default hook boundary, not client.mutate,
