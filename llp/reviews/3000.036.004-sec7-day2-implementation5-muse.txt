Counterexample 1 — parent upload gate fires on an unconditional helper-validated child. RFC: "the parent upload gate requires an actual nullable-argument branch that can skip child creation; an unconditional child validated through a helper is never guessed to omit evidence." Take the CHILD shape with a required `photo` column, an unconditional `insert photos {parent:p.id, photo:checked(photo)}` where `checked` returns `photo ! else REQUIRED`, plus `invariant parents always exists photos[parent = .id]`. Trace through [`creation_advice.rs`](/home/ccheever/projects/sb4-b22-sec7/snapback4/crates/snapback4-lang/src/bind/security/creation_advice.rs:72): optional arg, `contains_asset`, `required_media` true, `parent_required` true (linked, probe matches, no sibling), `omittable_attachment` false (`asserted_argument` matches only `Expr::Assert`, never a `Call`), no dominating require — gate fires. The child always executes in the atomic mutation and provably carries media, so this is a false exit-1 gate on an RFC-blessed pattern. Same root cause also gates unconditional direct writes (`photo:photo` into a required column), which likewise cannot commit an evidence-less parent. No code path resolves helper returns in the upload check, and no test covers parent-obligation plus helper.

Counterexample 2 — `seen` dedup drops same-argument obligations at other sites. RFC: "Upload review obligations retain operation, argument, table, column and source site, including two sites in one mutation." The dropped site gets no diagnostic, no review ID, and no possible disposition. The existing test pins only the two-module case, not two sites in one mutation.
