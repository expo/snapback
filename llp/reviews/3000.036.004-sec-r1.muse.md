# Independent design review: LLP 3000.036.004 (security invariants and exposure)

Scope: reviewed the RFC text against Snapback 4 engine semantics as implemented (`snapback4/crates/snapback4-core`), plus related LLPs 3000.036, 3000.035, 3000.014, 3000.038. No files edited. All code citations below were read directly.

## What I verified in the engine (truth semantics and exposure boundaries)

- Three-valued rules exist: `Verdict { Readable, Denied, Unknown }`, `not Unknown = Unknown`, Kleene `combine` (`snapback4-core/src/engine/rules.rs:1196-1209`). Top-level `evaluate` admits only `Readable` (`:1212-1214`). The RFC's "unknown never admits, `not unknown` is unknown" matches.
- But two engine truth details the RFC does not pin: `Value` derives `PartialEq` with distinct `String` vs `Id` variants (`value.rs:20-30`), so `Id("x") != String("x")` while `RuleTerm::Viewer` is always `Id`; and `Compare` on non-ints returns `false` (`rules.rs:1333-1339`), i.e. Denied, so `not (.textcol < 5)` **admits**. A missing reference forces `missing=true`, hence `Unknown` (`:1341-1356` + `:1311`) — but only because the wrapper checks the flag after `evaluate_leaf` returns.
- The system principal passes every rule (`engine/read.rs:482-486`: `is_system() → Ok(true)`), and `timeline_may_write` bypasses writes before that. Devices additionally serve held rows **without re-evaluating the rule** (`trust_synced_read`, `read.rs:470-477, 491-493`), including unconditionally under `DeliveredHistory`.
- Update admission is not uniformly "both images": `judges_old_image()` is false for named transitions (judged as written) and for rules reading only `id`/immutable columns (judged once) (`schema/update_images.rs:46-60`). Non-audience `written_by` field authorities further narrow updates beyond the table rule (`read.rs:499-504`).

## Material findings (each blocks a soundness or security claim)

**M1. Viewer quantification silently mishandles the most powerful principal.**
§3 requires `admission => policy` for "every … viewer". The engine admits the system principal on every effect regardless of the rule. Taken literally, no restrictive invariant is ever provable; taken as "obviously exclude system", the design grants a silent exemption to an omnipotent principal with no stated justification or compensating control. Concrete fix: explicitly exclude the system principal from viewer quantification, justify it as the trusted-worker boundary, and add the compensating rule that any read claim over a table writable by a job/maintain/action/native/external path defaults to unproved (see M6).

**M2. "Device envelopes must use the same current rule" is false for held-row reads, by engine design.**
`trust_synced_read` means a revoked viewer reads delivered rows without any rule re-check until leave/withdrawal. Delivery-time admission (`put` re-checked at stream time) is not read-time admission. A proof of delivery-time implication labeled as a read proof would be unsound, not merely narrow. The RFC's "delivered history cannot establish a current-role claim" gestures at this but never draws the consequence. Concrete fix: define device-read admission as delivery-time verdict plus leave-policy/horizon bounds, and state explicitly that read invariants with current-role policies over synced tables (in particular `DeliveredHistory`) are unprovable, not provable-with-asterisk.

**M3. Update policy image-binding is unspecified, against a non-uniform engine.**
"Both images for ordinary updates" leaves three questions open: which image(s) a policy field (`.requester`) binds to, what "ordinary" excludes (named transitions must be explicit-unproved, since they are judged as written), and the once-judged optimization (immutable-input rules evaluated once — sound only because inputs provably agree, which the proof must re-establish rather than assume). Concrete fix: bind policy fields to both images wherever the column is mutable; route named transitions and once-judged rules to stated sub-cases (proved-via-immutability or unproved with reason).

**M4. Upsert (and `insert … if absent`) fall through the `write`/`delete` split.**
`write` "checks insert and update", but upsert consults both arms with a distinct refusal shape (hidden-target `NOT_FOUND` per LLP 3000.014 §6), and `judges_old_image` interacts per-arm. An implementer covering only plain insert/update leaves a reachable write path with a proved label. Concrete fix: state that `write` covers both upsert arms and `insert … if absent`, including the arm-specific refusal semantics, or require a separate declaration.

**M5. The translation-soundness argument depends on exact truth tables the RFC never specifies.**
"Sound because it includes every concrete valuation, even impossible ones" holds only if kernel and engine agree on **every possible** valuation. Under-specification: Id-vs-Text inequality, type-mismatch `Compare → false` (hence `not`-of-comparison admits), `Null = Null → true`-but-missing-flagged-Unknown, and every `Err` path (schema errors, probe/store failures) — the design needs the reviewed lemma that all error paths deny. Worse, "symmetric equality may canonicalize" affirmatively invites the dangerous reading (normalizing `Id`/`Text` into one string domain), which would diverge from the engine. The Lean obligation is likewise under-stated: "the implication property" without saying the kernel is 3-valued Kleene with deny-by-default and the theorem is `eval(admission)=Readable → eval(policy)=Readable` over all valuations. Concrete fix: pin the exact atomic truth tables against `evaluate_leaf`/`term`, prohibit cross-type canonicalization (order-only `a=b`/`b=a` is the safe reading — say so), add the error-fail-closed lemma to the reviewed Rust obligations, and state the Lean theorem exactly.

**M6. The bypass/trigger enumerations are open lists wearing closed-list language.**
"Admission includes the ordinary read rule and **every** bypass" followed by a list is read-as-exhaustive by implementers; anything genuinely missing (sequences' first-insert read authority per `N_SEQUENCE_READ`, online-only tier reads, ephemeral tables, the device `query` reply path) becomes a silent pass. Symmetrically, "read claims **affected by** opaque outputs remain unproved" needs a trigger: dataflow "affected-by" analysis that is itself incomplete silently clears tables. And §5's grant-column writer enumeration ("the insert/update writers of the probed grant columns") omits the writers that bypass rules entirely — jobs, maintains, actions, native jobs — understating exactly the privilege-escalation surface this report exists to map. Concrete fix: require a closed-world census mapping every engine read/write site to the model (or default-unproved for unlisted sites); default all job/action/native/external-touched tables to unproved absent a reviewed exact reduction; explicitly include system-principal writers in grant-column writer lists.

**M7. `always` has no temporal scope.**
"Row-integrity assertion" over what? Every committed image (insert, update, both upsert arms, import, seed, restore, activation recapture)? If checked at insert only, an update clearing `.image` violates intent under a "proved" label. Concrete fix: define `always` as quantifying over every committed row image on all ingress paths, or narrow it explicitly (e.g. insert-only) in the syntax.

**M8. Retained-history observations have no test-oracle semantics.**
§4's viewer classes and replay rule do not distinguish a revoked viewer legitimately holding retained rows (leave policy) from a disclosure. The oracle "compare admitted observations against declared intent" will either false-fail on legitimate retention or — if retention is blanket-excused — silently pass real leakage. Concrete fix: label retained observations separately and judge them against the table's leave policy, never against the current-role policy.

## Narrower-but-explicit coverage (judged sound in direction, not blocking)

Replay-mandated refutation (never a bare Boolean assignment), unproved-on-cap-exhaustion, no consistency axioms without separate argument, `now`/counts/temporal forced unproved, whole-table checking for column invariants (conservative direction: table-rule admission ⊇ field-narrowed admission, so implication still transfers), grant-creation-never-proves-current-role (conservative), unknown tables/columns as authoring errors, test isolation, and provenance retention are all fail-closed and correctly distinguished from proof. The text-minimum counting change (§6) is validation-tightening with documented tests — a behavioral change, but fail-closed and out of the proof path.

## Minor

- §5's "authentication precedes the operation" (signed-out) should cite its enforcement site rather than assert; and §4 lists an "unauthenticated" viewer class while also forbidding testing signed-out admission by inventing a principal — resolve by routing that class through the network/auth boundary only.
- `read` should state explicitly that one declaration covers every enumerated read path (point/list/view/filter/count/exists/search/sync/device), not just the direct rule.

The core idea — three-valued exhaustive implication over an overapproximating abstraction, with replay-required refutation and explicit unproved — is the right shape, and several fail-closed instincts are exactly right. But M1–M8 are not gaps in coverage; each is a place where the design as written permits a "proved" label over behavior the engine does not have. They need exact statements, not more testing.

Verdict: NOT READY
