1. **Bounded exhaustion can reveal hidden population size through `complete`.** [§10, bounded exactness](/home/ccheever/projects/sb4-w13-lang2/llp/3000.036.002-intent-aware-lints-and-bootstrap.rfc.md:468) admits any finite capped group. Consider `cap 9000`, `read <- .a = .b`, and a page where no row is readable. An empty store exhausts and returns `complete: true`; 9,000 hidden rows with unequal fields exhaust the shared 8,192-row authorization allowance and return `complete: false`. Both worlds have the same authorized answer. Smaller caps can encounter the same distinction after earlier reads or nested rule probes consume the allowance.

   **Required correction:** admit exact exhaustion only after reserving a schema-derived worst-case physical authorization bound, including nested probes, from the request’s remaining allowance. If that reservation cannot fit, return incomplete before candidate access, independently of hidden occupancy.

2. **The immutable contract leaves external IR’s hidden-target behavior unresolved.** [§10, immutable patches](/home/ccheever/projects/sb4-w13-lang2/llp/3000.036.002-intent-aware-lints-and-bootstrap.rfc.md:458) promises no silent field removal while retaining runtime constraints as the authority for external IR. Existing hidden-target semantics deliberately discard immutable fields without comparing them ([governing ruling](/home/ccheever/projects/sb4-w13-lang2/llp/3000.007-relaxed-quarry-and-explicit-residency.rfc.md:1818)). Replacing that behavior with a runtime mismatch refusal exposes existence: an otherwise permitted upsert inserts when absent but refuses when a hidden row has a different immutable value.

   **Required correction:** either enforce preservation proofs during core IR admission before target lookup, rejecting unproved patches independently of occupancy, or explicitly preserve and scope the existing hidden-target discard exception. A source-binder check alone does not settle the external-IR contract.
