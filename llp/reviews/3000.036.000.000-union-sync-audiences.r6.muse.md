**Findings**

1. **Medium — §6, `snapback4-sim/tests/union.rs`: no three-arm world (two column arms + group arm).** Every world has at most one column arm (`tasks`/`owner`, `requests`/`owner`, `buyer`/`seller` with no group). Untested as a result: R2 sparing through the *second* column arm (`spared()` in [device.rs](/tmp/union-r6-review/snapback4/crates/snapback4-device/src/device.rs:1297) loops `column_arms()`, but the model at [union.rs:748](/tmp/union-r6-review/snapback4/crates/snapback4-sim/tests/union.rs:748) and the real device only ever spare via one); a snapshot walk over three arms with three window indexes (`snapshot_page`, [partition.rs:555](/tmp/union-r6-review/snapback4/crates/snapback4-core/src/partition.rs:555)); a `del` converted by R1 for a viewer following three partitions. The code is arm-generic everywhere I read, so I expect a pass, but the RFC's central retention mechanism (spare-via-column-arm) has never run with column arms plural. *Propose:* extend the owner-or-team world with `seller: principal` in the rule and seed, or add a buyer-or-seller-or-team world; require the leave-with-spare case to spare via each column arm.

2. **Low — §5.3, `union.rs`: windowed column-only unions and windowed `exists`/counts unexercised.** The only windowed world is owner-or-team; no world puts `last N by` on a two/three-party rule, so multi-column-arm `accept()` ([boundary.rs:104](/tmp/union-r6-review/snapback4/crates/snapback4-device/src/device/boundary.rs:104)), `arm_by_window`/`by_boundary` over two column indexes ([read.rs](https://github.com) change, [boundary.rs:152](/tmp/union-r6-review/snapback4/crates/snapback4-device/src/device/boundary.rs:152)), and the per-arm snapshot cursor across two column arms never run. The windowed world also runs no `exists` or count query, so the round-4 sentence "a held readable row is a positive witness for `exists` over any index" has zero exercise (a false `complete` there would be a §5 violation, and `check_real` would flag it if a query ran). *Propose:* a windowed two-party world with `haveAny`-style `exists` and a count query in its query set.

3. **Low — §2.1/`bind_union_windows`, `snapback4-lang/src/bind/intent.rs` + `bind/schema.rs`: window map keyed by arm columns silently collides.** `sync.windows` is keyed by `need.prefix`; a column arm on `.team` and a group arm with prefix `[team]` (both `columns() == ["team"]`) overwrite each other's entry in the planning loop, so both arms bind to one window index and die later in core validation ("two arms read one window index") with a repair ("order the window by columns no arm groups by") that cannot help — no ordering fixes it. Fail-closed, but unactionable. *Propose:* refuse in the binder when two planned arms share a `columns()` key, naming the collision (or key `windows` by arm).

4. **Low — §6 wording vs `union.rs:32,117,741`: the in-test naive mode is device-R2-only.** §6 says "run against the naive implementation (partitions per arm, no R1, no R2, no commit-boundary accounting), the worlds must fail", but `SNAPBACK4_UNION_NAIVE=1` only gates `spared` in the model device; server R1, `touched_rows` accounting, and the epoch have no naive switch, and real devices always apply R2. The test-file header documents this correctly; the RFC paragraph overclaims what the flag demonstrates. *Propose:* scope the §6 sentence to the naive device (R2/H2), and record R1/accounting falsifiability as the pre-landing stash check it was.
