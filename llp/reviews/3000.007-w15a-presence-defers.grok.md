## Arm-selection rule (from the code)

On the server, each presence read still returns the live poll count (`runner.rs:755-758`). Beside that, a held read (`live > 0` and a deadline) stores projected `Count(0)` in `EffectPresence.absent`. Comparisons/`not`/`and`/`or` propagate that scalar (`presence_binary`, unary `not`). At `Stmt::If`, `presence_arm` replaces the actual boolean **only when**:

1. the site’s `plan_guards` proof says absence is necessary for that outcome (`Proof.yes` / `Proof.no`), and
2. that arm contains an `emit` (`emit_yes` / `emit_no`), **or**
3. the `if` is a lowered `$bool` setup (`temp("bool")` → `$boolN`) that `needed_setups` marked because it feeds such a guard.

Otherwise the actual boolean is kept. After a projected setup arm, the accumulator’s env value is restored to the actual short-circuit result while the projected scalar stays on `Tracked.absent` (`runner.rs:238,244-249`). Device: `presence_arm` returns `actual` immediately; `needed_setups` is not called (`presence.rs:41,114`).

**Attacks**

| Case | What happens |
|------|----------------|
| Held ∧ absent ∧ graced | All three are absence; the emit arm is taken; deps are held (δ) + graced (remaining grace); `next_at` is the max (`unconfirmed.rs:62-66`; `record` `effects.rs:84`). Independent conjuncts still have to hold (`force and not online`, `unconfirmed.rs:13,32-33`). |
| Same `connected[p]` in guard and payload | Guard may project; payload reads env or re-evaluates `Connected`, which still returns `live` (`unconfirmed.rs:10-16,37`: `online` is `true`). |
| Alias rebound before `if b` | Last `Assign` updates `Proof` and `Tracked`; a non-presence assign drops the variable (`bind_effect_value` `presence.rs:83`). Projection does not stick to a stale proof. |
| Guard in a recipient loop | Loop-carried proofs are `UNKNOWN`; a direct absence test on the binding still proves per row (`plan_guards` `253-260`). One emit per iteration. |
| `else` emits | `exists connected[p]` proves the else arm (`Proof` Gt/0 → `no`); `presence_arm` returns projected `false` and takes else (`unconfirmed.rs:15`). |

A payload cannot observe `connected` as false for an open poll: `Connected` always returns `live`, and `$bool` restore writes `Value::Bool(actual)` back into env. An emit is not taken twice: one `if` takes one arm. “Neither arm” only happens when projection does not apply and `actual` is false — unproven forms, which must stay immediate/unemitted as at the baseline (`unconfirmed.rs:108-138`).

## Races (Q4)

| Race | Outcome |
|------|---------|
| Poll enters between insert and commit | Engine lock: `presence_reconnected` cannot run until `mutate` commits (`serve.rs:1059`, `serve_changes.rs:22-27`). That arrival is post-commit and **cancels**, correctly. |
| Poll entered before commit, answered by it | Reconnect ran too early (`serve_presence/mod.rs:20-21`); open poll at claim does not satisfy (`effects.rs:143`; `mod.rs:43-52`). Healthy client must re-poll (`serve_presence/mod.rs:77-79`). |
| Two commits, same recipient | Two `_outbox` rows, two `_effect_presence` rows keyed `(principal, id)`. One reconnect updates both still inside their windows (`effects.rs:165`). |
| Restart between commit and δ | Deadlines and `reconnected` are SQLite (`unconfirmed.rs:78-104`). |
| Reconnect after claim | Claim deletes `_effect_presence` (`effects.rs:144`); later `UPDATE` matches nothing. Push is already with the worker — **sent**, not dropped. |
| δ elapses while worker is down | `next_at` stays on `_outbox`; first claim after the worker returns delivers or satisfies from the durable flag. |

“Never dropped” is true for d-05 and for every proven absence emit at commit. It is not true of `--replay` suppression (documented on the effects card) or of a reconnect after the window (the effect is then claimable).
