## Initial author position

Author assessment, written before reading Muse/Grok/Gemini conclusions (not independent review).

The plan should be a sequence of end-to-end behavioral repairs, with architecture contracts serving deletion and reuse, rather than five simultaneous abstractions. Keep two children, but 1018.001 should close around the actual existing compiler after a finite reconciliation pass, not become permanent shadow governance of 1018.000. The unheld-versus-zero seam is the highest-confidence bounded runtime opportunity and should be checked against the sparse-aggregate candidate first. Lifecycle analysis should examine transitions along that same witness, not begin with a generic reducer rewrite. The dependency proposal is worthwhile research, but do not staff the new digest until the two-write experiment identifies exact remaining blockers and an unrelated-schema case demonstrates useful benefit. Static semantic closure and dynamic touched reads are different dependencies and must not become one universal key or invalidation service.

Code spot-check: Schema::rule_hash hashes full schema plus rule; Rust client hydration also checks full schema, so a narrow rule digest does not buy selective coverage retention. engine/replay.rs compares rule identities separately, supporting a bounded replay investigation. New evidence at 0c1a538ae proves generated API row types can become error-derived any under the customer's real Expo config while printed Result looks plausible; a counterfactual import fixes this case. Compiler acceptance must reach a real package consumer with negative type checks, not stop at inferred internal types or printed declarations. Treat the existing compiler lane as repair owner; retain this witness through direct lowering.

What would change my mind: candidate already closes zero/public acquisition/cold reopen safely; census reveals no actual duplicate lifecycle state; narrowed rule identity avoids no valid queued conflicts once point and program checks remain. In those cases close or defer the respective work. Do not manufacture a new subsystem to keep a heading alive.
