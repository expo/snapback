Two changes remain necessary:

1. **High — §2.2: `online only` card dependencies do not enter the specified withheld path.**

   The [two triggers](../../llp/3000.016-following-on-a-bounded-device.rfc.md:92) cover horizon misses and inbox crossings. An `online only` source has no horizon. Its reads are nevertheless unknown—even on a hit—and the compiled query normally takes the [earlier server-run route](../../snapback4/packages/snapback4/src/local.ts:972).

   **Scenario/probe:** make posts `online only`, keep the inbox page within its floor, and perform a shaped one-shot read offline. The existing route returns a remembered answer or `E_OFFLINE`, rather than the promised `loading`. For the prediction case, keep posts synced, make reposts `online only`, and shape repost details into Following. Admit an own post that predicts. The server-run route can publish a page without that post before observation.

   **Smallest fix:** include any required `online only` card read in the withheld definition. Explicitly apply the offline/pending/transport-failure rules to these queries before server-run routing or remembered-answer recovery. Qualify “always answered by the server” accordingly. This is the unresolved part of revision 3’s fallback finding.

2. **Medium — §2.2, routing step 3: unconditional fallback conflicts with `held` queries.**

   **Scenario/probe:** declare a Following query `held`, acquire its partition, and request a page crossing the inbox floor while online with no pending prediction. Step 3 directs a server call. However, `held` queries explicitly forbid fallback: the [client helper](../../snapback4/packages/snapback4/src/local.ts:934) returns `E_OFFLINE`; an actual server call receives [ `E_QUERY_HELD` ](../../snapback4/crates/snapback4-core/src/engine/mod.rs:191). Neither produces the specified withheld result.

   **Smallest fix:** add a `held` exception before server dispatch: an unavailable held Following query remains `loading`, online or offline, until locally answerable. Preserve the prohibition on server fallback.
