## Concerns

### MATERIAL — The receipt confuses coverage with dependency

A coalesced rowless watermark establishes coverage without visible content, not semantic non-dependence; even a new disposition cannot classify V unless its meaning survives watermark collapse and content supersession.

**Resolution:** Replace `not-dependent` with `covered-no-visible-change` in the base protocol. If the optional field ships, define a narrower `matcher-skipped` finding, specify its exact per-V/range coalescing algebra, and word it as a server matcher classification.

### MATERIAL — The verdict algebra is not total or exclusive

No-V requests lack a causal result; multiple reachable combinations satisfy two conditions; React value-equality suppression generates false `applied-not-rendered`; and `shared-custody` is orthogonal.

**Resolution:** Define independent facets—settlement, attachment, authority, server coverage, client application, publication, and custody comparison—then derive one `primaryFinding` with a complete truth table. Require V for causal findings and use per-version facts rather than cumulative counters.

### MATERIAL — The receipt neither satisfies redaction nor the commissioned causal chain

The sample exposes bearer/wire identifiers, introduces a principal correlation token the parent forbids, and omits authority/query generations, invalidation publication, and subscription-generation continuity.

**Resolution:** Use scoped pseudonyms for every wire identity; remove principal and row count unless LLP 0219 explicitly accepts them; normalize nested diagnostics structurally; add authority/query/subscription generations, attachment continuity, resubscribe-after-ask, and the observed invalidation/evaluation disposition.

### MATERIAL — The detector lacks a sound eligibility interval and deadline

It can remain armed across pause, detach, offline, resubscribe, or quarantine, and the client has no specified source for the effective within-capacity end-to-end envelope.

**Resolution:** Arm only for a defined settlement class and one continuously eligible subscription generation. Suspend or terminate on every lifecycle/fence cut. Base firing on negotiated effective service values and transport allowance; otherwise emit an unbounded `coverage-pending` observation without a timed warning.

### MATERIAL — Acceptance does not yet prove O15 prevention

The proposed cases do not test the semantic distinctions, detector negative controls, all settlement/arm variants, or whether an agent actually avoids the recorded workaround spiral.

**Resolution:** Add the matrix described in answer 6, including a scored receipt-plus-guide retrieval evaluation tied to O15.

### MINOR — Several claimed current surfaces are not public as named

Direct mutation settlement exposes `version`, not `commitVersion`; `settledAt` exists on durable disposition/settled records, not every direct result. `authorizationDisposition` and `authorizationState()` exist on the runtime handle but are absent from the declared `LiveQueryHandle` interface. [[index.d.mts:408](/Users/ccheever/projects/snapback/.claude/worktrees/c1-rfc/packages/snapback-client/index.d.mts:408), [index.d.mts:918](/Users/ccheever/projects/snapback/.claude/worktrees/c1-rfc/packages/snapback-client/index.d.mts:918), [index.mjs:18489](/Users/ccheever/projects/snapback/.claude/worktrees/c1-rfc/packages/snapback-client/index.mjs:18489)]

**Resolution:** Distinguish internal held facts from supported public handle fields and define one normalized settlement input type for the receipt API.

## Suggestions

- Prefer `coverage: { through, kind, classification, exactForAskedVersion }` over `watermarkDisposition`; it forces the schema to disclose when coalescing lost exact attribution.
- Make `compareReceipts` return equality/mismatch findings for principal scope, partition, authority, and connection ownership instead of a single verdict.
- Record a per-delivery publication disposition such as `consumer-visible-change | value-equal-suppressed | no-renderer`, bound to the delivery version, rather than consulting a lifetime counter.
- Add `AbortSignal` to `explainAfter` and guarantee that disposal resolves it with a terminal lifecycle receipt.
- Keep the agent-facing explanation conservative: “the server covered V without publishing changed content” is more useful than a confident but potentially wrong dependency claim.

## Open questions

1. Can the engine preserve an exact matcher-skip classification for V across watermark coalescing and later content supersession without adding a per-commit ledger?
2. What negotiated/client-held fact defines the detector’s effective end-to-end deadline on live and polling lanes?
3. May LLP 0219 admit a process-local principal-equivalence pseudonym for custody comparison, and if so, what is its salt, lifetime, and export boundary?
4. Does “renderer” mean registry publication, listener notification, React commit, or visible DOM/native UI? Only the first two are plausibly available without new instrumentation.
5. Which settlements count as the same client’s “own write”: direct foreground results only, or also queued replay, recovered settlement, shared-store writers, and provider-managed dispatch?
