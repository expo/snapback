### 1. Empty `changes` Skip — seed/refresh false skip

**File:** `crates/snapback-kernel/src/live_matcher.rs:252`, `:272`, `:1058`

`live_subscription_match_decision` now sends `HandlerPlan::GraphQuery` into `graph_subscription_match_decision` *before* the non-graph fail-closed gates. Those gates still treat `changes.is_empty()` as `ConservativeFallback`. The graph arm does not.

On a complete capture vector, every node does `facts.max(...).unwrap_or(Skip)`. An empty change list is vacuously disjoint at every fact, so the graph outcome is **`Skip`**.

That breaks the existing live contract. Serving still documents empty `changes` as “re-evaluate from scratch”:

```30991:30994:crates/snapback-engine/src/local/engine.rs
        // Empty `changes` is the seed/refresh signal (`seed()` calls
        // `notify_live_subscriptions(&[])` with no change list): it means
        // "re-evaluate from scratch", which only the re-query + replace
        // path can honour (the matcher treats empty `changes` as affected).
```

Parent `HEAD~1` kept GraphQuery *behind* that gate, so even the fail-closed sibling woke on seed. After the first capturing evaluation, seed/unknown-changeset refresh would now leave graph subscribers on a stale result.

The unit test `graph_query_v1_no_executor_matcher_is_fail_closed_before_dependencies` still passes only because it feeds a *forged incomplete* vector, not complete captures + `[]`.

**Fix:** In `graph_subscription_match_decision`, if `changes.is_empty()` return `ConservativeFallback` (same as non-graph) *before* per-node Skip. Add a regression test with a complete root+projection vector and `changes = []`.

### 2. Incomplete backward windows — last-key prefix cutoff false skip

**Files:** `crates/snapback-engine/src/graph_evaluator.rs:1010`, `crates/snapback-kernel/src/live_matcher.rs:868`, `:899`, `:1490`, `crates/snapback-kernel/src/storage.rs:8069`

Root/parent-range matching reuses the single-table rule in `matching_limited_row_may_affect_query`: if `complete` is false, Skip iff the row’s sort key is **strictly after `boundary.last` in the Query plan’s declared order**. That rule is sound only for a **prefix of declared order**.

Graph backward pages are not that prefix. `query_graph_window_with_lookahead` walks `graph_traversal_order` (declared components flipped). The evaluator then stamps `boundary` from `rows.last()` and the matcher overwrites the honest Query `first`/`last` with **`first = last = last-row key`**:

```868:875:crates/snapback-kernel/src/live_matcher.rs
fn keyset_boundary_value(key: &crate::manifest::KeysetKeyV1, complete: bool) -> Value {
    let mut last = key
        .entries
        .iter()
        .map(|(_, value)| value.clone())
        .collect::<Vec<_>>();
    last.push(Value::String(key.id.clone()));
    json!({ "first": last, "last": last, "complete": complete })
}
```

Counterexample: declared `updatedAt DESC`, demand `direction: backward`, `take: 10`, more than 10 rows. Traversal is ASC, so the page is the 10 oldest; `rows.last()` is the *newest of those 10*. An insert that is 5th-oldest is **in the page**, but under DESC it compares `Greater` than that last key → **Skip**.

`RootRange` / `ParentRange` also omit window `direction`, so the matcher cannot recover traversal order from the capture. Frozen G2-B invocations happen to be all `forward`; the IR and G2-A still admit backward demand/literal pages, and G2-C serving will use this arm.

When `has_more` is false, `complete: true` wakes every predicate-matching row (conservative extra wake, not a false skip). The hole is **incomplete backward/suffix pages**.

**Fix:** Either (a) fail closed: `ConservativeFallback` whenever a captured range is incomplete and direction is not a proved declared-order prefix, or (b) match the captured page as a closed interval (need a real `first` and `last`, and direction or traversal order on the capture). Do not keep `first = last`. Add a `has_more` backward insert-inside-page test.
