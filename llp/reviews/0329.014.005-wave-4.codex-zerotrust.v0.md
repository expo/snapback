### 1. Coverage table

Literal verdict: Ward’s requirement that remote authorities agree at the exact commit or delivery instant is a **premise violation**. Deterministic programs can prove only that Ward held sufficiently fresh, authenticated evidence and had received no contrary fact. ### 2. Schema in v0

This uses v0.1 plus constructs explicitly tagged **[v1.1]**. Shorthand: `i=id()`, `sN=text({max:N})`, `n=int()`, `b=bool()`, `t=time()`, `ct=time({commitTime:true})`, `iv=interval()`, `jN=json({maxBytes:N})`, `o(T)=optional(T)` **[v1.1]**. Enums are bounded text plus insertion/update checks; security-relevant sets and JSON are normalized because v0 JSON is opaque.

Every rules profile names all four effects:

```ts
const AO  = (read, insert) => ({ read, insert, update: never, delete: never })
const CUR = (read, insert, update) => ({ read, insert, update, delete: never })
const sys = principal.kind === 'system'
const secops = r => activeRole(viewer, 'secops', r.facilityId)
const privacy = r => activeRole(viewer, 'privacy_officer', r.facilityId)
const owns = ownerId => ownerId === viewer
const lease = (patientId, cls) =>
  db.exists(viewLease.byViewerPatientClassState, [viewer, patientId, cls, 'open'])
const writeDecision = (decisionId, patientId, cls) =>
  db.get(decisionCore, decisionId)?.principalId === viewer &&
  db.get(decisionCore, decisionId)?.resourceId === patientId &&
  db.get(decisionCore, decisionId)?.effectiveOpClass === cls &&
  db.get(decisionCore, decisionId)?.outcome === 'allow'
```

`decisionCore.insert` additionally needs `freshAtCommit(evidence,budget)`. That predicate is deliberately **not invented**: it is language delta L1, so this faithful schema does not check today.

### 3. Operations in v0

The natural core attempt is refused:

```ts
export const authorize = mutation(args, async ({ db, ctx, args }) => {
  const idp = await fetch(IDP, args.sessionId)
  const dps = await fetch(DPS, args.deviceId)
  const risk = await fetch(RE, args.intentId)
  const t = Date.now()
  // decide and write
})
```

`E_OPAQUE: async/await and fetch are outside the bounded subset. Rewrite: perform I/O in an effect and persist bounded results through named mutations.`

`E_AMBIENT_TIME: Date.now is not modeled. Rewrite: intent-time display uses ctx.now(); security windows use server-settled commitTime.`

The smallest honest orchestration uses v1.1’s outbox, system continuation, online-only delivery, and no prediction:

```ts
export const beginAttempt = mutation({ intentId: id(), opClass: text({max:32}), resourceId: id() },
  { predict: false, delivery: 'online-only' }, ({ db, ctx, args }) => {
    db.insert(writeIntent, { id: args.intentId, principalId: ctx.viewer,
      opClass: args.opClass, patientId: args.resourceId, createdAt: ctx.now() })
    db.insert(oracleOutbox, { id: ctx.newId(), intentId: args.intentId, state: 'ready' })
  })

export const callOracles = effect(async event => {
  const facts = await callIdpDpsRiskAndLocation(event.intentId)
  await recordOracleRound({ intentId: event.intentId, facts })
})

export const finishNote = mutation({ intentId: id() },
  { phase: 'system', callable: 'system', predict: false, delivery: 'online-only' },
  ({ db, ctx, args }) => {
    const intent = db.get(writeIntent, args.intentId)
    const evidence = evidenceFor(db, intent) // five bounded indexed gets
    const ok = evidence.every(e => freshAtCommit(e, policyBudget(db, intent.opClass, e.kind),
                                                 ctx.commitTime)) // L1: absent today
    const decisionId = ctx.newId()
    db.insert(decisionCore, decision(db, intent, evidence, ok, decisionId))
    if (!ok) return { outcome: 'deny', userCode: 'DENY_AUTH', reference: ref(decisionId) }
    if (intent.amendsEntryId && db.get(chartAmendment.byPrior, intent.amendsEntryId))
      return { outcome: 'allow', conflict: latestEntryId(db, intent.amendsEntryId) }
    db.insert(chartGeneral, noteFromStoredIntent(intent, decisionId, ctx.commitTime))
    if (intent.amendsEntryId)
      db.insert(chartAmendment, { priorEntryId: intent.amendsEntryId,
                                 nextEntryId: intent.entryId, decisionId })
    return { outcome: 'allow' }
  })
```

Authorization failures are successful branches. `db.insert(deny); db.require(false, code)` is wrong because `require` rolls the denial back.

This rewrite proves only “fresh evidence at commit”; it cannot prove the remote oracle’s simultaneous state. If literal agreement remains required, `finishNote` is still not a plan.

**5.1–5.4.** `finishSession` uses the same pipeline, terminates the unique current `(principal,device)` session, and inserts session plus decision atomically. Its stated zero-second budget cannot satisfy strict `observedAt + 0 > commitTime`.

The first chart attempt, `db.scan(chartEntry.byPatient,[patient])`, is `E_UNBOUND_SCAN`; rewrite to class-separated `scan(...,{take:100,after})`. A live query with `take` is admitted but still wrong by omission: it cannot atomically recheck at delivery and write `delivery`. The honest form needs v1.1 `audited(into)` plus L2’s commit-time `deliveryGuard`; an effect is `E_EFFECT_NOT_LIVE`.

`renewLease` inserts the new lease and closes the old one in one allow branch. `ingestRevocation` inserts the durable fence first, then closes an `All≤20` active-lease set; without the schema cap, reaching `hasMore` is `E_FANOUT`. Reconciliation is a cursor schedule over 500 decisions, never the ingest transaction.

**5.5–5.9.** Note, generic order, controlled order, break-glass, delegation, policy, role, and export settlements all reuse stored immutable intent content; the client never resubmits different content after approval. Controlled order consumes `mfaConsumption` and intent atomically. `completeStepUp` verifies WebAuthn in an effect and records a request-scoped attestation; a second completion loses the unique consumption race.

Break-glass creates grant, relationship, review task, and decision together; revocation closes the grant, relationship, and capped lease set. A nonexistent MRN cannot create the fixed schema’s patient-referencing grant; §7 changes that product flow.

Expanding a service delegation into every patient relationship is `E_UNBOUND_LOOP`/`E_FANOUT`. The corrected plan inserts one interval-bounded service-scope delegation and checks it by `[delegate,service,state]`.

**5.10–5.12.** Fetching the roster inside a schedule is `E_OPAQUE`; iterating a whole facility is `E_UNBOUND_LOOP`, and a 14,000-line declared bound is likely `E_BOUND` **[inferred]**. An effect stages pages of 500 under a sealed generation; a v1.1 job validates the generation and atomically swaps the facility’s active-generation pointer. Oracle health reads maintained live-window count/rank rows. Historical oracle reconciliation is an effect followed by bounded result mutations. The sweeper uses three `take:200` scans. The nightly seven-million-lease scan is `E_UNBOUND_SCAN`; rewrite to a v1.1 job with cursor and watermark.

**5.13–5.14.** Audit pages use the declared decision indexes with `take:100`. As-known-at performs, per returned decision, `take:1 desc` probes constrained by `receivedAt≤T2` and `checkedAt≤T2`. Every audit read must use L2 audited delivery; a normal query silently violates invariant 1. A lagging replica cannot share the authoritative write transaction.

Policy, degraded-policy, forced-state, and role changes require two unique approval rows where applicable, compare full stored intent content, append the new version, close the previous validity interval, and record decision/event together.

**Other named surfaces.** `listMyPatients` reads `effectiveCare` plus `myPatientCount`; census reads `wardCensus`; review list/close use the bounded review index; logout and client-close write durable state; MDM/ADT/HR are effects that invoke bounded ingress mutations; lease close is a channel invalidation plus optional notification outbox; the warning is computed from the already-delivered expiry. Export uses v1.1 `exportStream` over an immutable, one-use manifest. No seed/fixture mutation was specified.

### 6. Language delta

1. **Commit-fresh durable evidence.** Add algebraic `fresh(row,{observedAt,receivedAt,maxAge,at:'commit'})`, with trusted ingress time, oracle-clock/skew validation, and retry re-evaluation. General; amends §§3, 4.3, 5, 6. It preserves only the labeled product boundary, not literal remote simultaneity.

2. **Audited, fenced delivery.** Extend v1.1 `audited(into)` with a commit-time delivery guard and atomic audit/counter writes before bytes become observable. General new runtime dimension; amends §§1, 3, 6.

3. **Authenticated session/device context and retention.** Add `ctx.session`, `ctx.device`, bind them into rule verdicts/receipts, dynamic per-range offline expiry, and mandatory purge at lease expiry. General; amends §§4.3 and 6. v1.1 per-table retention alone is insufficient.

4. **External orchestration package.** Adopt v1.1 transactional outbox, `phase:'system'`, scoped hidden reads, `callable:'system'`, `predict:false`, `delivery:'online-only'`, identity/WebAuthn verification, and `digest`. General; amends §§1, 4, 6, 7.

5. **Jobs and streams.** Adopt v1.1 generation-fenced jobs with cursors/watermarks and `exportStream`; add staged-generation cutover for logically atomic bulk sync. General; amends §§1 and 7.

6. **Maintained distinct/window statistics.** Add `maintain.rows`/distinct membership and maintained order statistics over schedule-flipped live sets; if `maintain.rank` cannot select p50, add `maintain.quantile`. General; amends §§2 and 4.4.

7. **Cross-row security constraints.** Add named-program/event-coupled constraints for decision-with-write, grant-with-review, interval containment/cascade, and one-use capability consumption. General; amends §2.

8. **Protection, storage, and time declarations.** Adopt v1.1 audience projections or retain physical splits, per-table retention, `versioned`, partition declarations, commit sequence/HLC, optional/enums, fixed-point geometry, and pinned zoned time. General except Ward’s partition keys; amends §§2 and 6.

9. **Sealed-flow guarantees.** Add negative-flow checks and a runtime equal-work/equal-envelope declaration for absence-sensitive refusal paths. Also let schedules declare measured `maxLateness`; at-least-once alone cannot certify five seconds. General; amends §§5, 7, 9.

The pre-registered prediction was directionally correct—mirrored evidence, freshness, labeled TOCTOU, no rule-oracle class—but incomplete. `fresh` does not solve delivery auditing, device authority, effect orchestration, or remote truth.

### 7. Product changes

| product change | what it dodges | acceptable when | when this is a cheat |
|---|---|---|---|
| Replace “oracles agree at the instant” with “Ward holds authenticated evidence within the published budget and no received contradiction” | distributed atomic commit | budgets are the actual clinical risk contract and all three times are recorded | the UI/audit still claims simultaneous remote truth |
| Measure the five-second close SLA from Ward `receivedAt`; separately publish source-to-Ward feed SLO | unknowable remote revocations | external feeds cannot join Ward’s transaction | “revoke anywhere within five seconds” remains advertised |
| Give `session.establish` a positive response-to-commit budget | impossible strict zero-age predicate | the budget is calibrated and retry rechecks it | zero is merely renamed “live” |
| Paginate chart/audit pages; use a snapshot-bound export stream | unbounded scans/output | UI does not need one atomic all-history object | “full chart” or export claims an atomic unlimited snapshot |
| Model service delegation as one scoped interval row, not per-patient expansion | unbounded fan-out | authorization checks patient service against that row | per-patient materialization/visibility is still promised |
| For unknown MRN break-glass, record a probe intent/decision, not a patient grant or relationship | impossible patient FK | existence is revealed only after audited authorization | a fake patient or distinguishable fast path is created |
| Authorize audit at the primary and bind it to a replica snapshot, or drop replica reads | cross-store atomicity | the receipt names the replica watermark and over-auditing is accepted | the product keeps claiming the replica read and primary decision were one transaction |
| Treat the sweeper as cleanup only; delivery guard is the security boundary | schedule jitter | every delivery independently checks expiry/revocation | a five-second sweeper is treated as exact authorization |

A product change is legitimate when the weaker behavior is wanted and stated. It is a cheat when made solely to obtain admission while retaining the stronger promise.

### 8. Where the design is wrong

1. **Its opening promise contradicts its algorithm.** Phase A’s remote answer and Phase B’s database commit are different instants; an oracle can change after replying while its event is delayed, and Phase B still allows. Confirm by making DPS return compliant, changing posture before commit, and withholding the DPS event.

2. **The authorization policy is incomplete and one class is mathematically impossible.** `session.establish`, `stepup.complete`, `breakglass.grant`, `write.admin-lite`, and `audit.read` are used but absent from the published policy matrix. Establishment says budget zero while requiring `observedAt + budget > commitTime`; that can never pass. Confirm by resolving `budget(session.establish,session)` and evaluating the strict predicate.

3. **Replica audit conflicts with same-transaction disclosure accounting.** Audit reads may lag on a replica, while every read must commit its decision in the same transaction as disclosure. No transaction described spans the replica snapshot and authoritative decision ledger. Confirm by identifying the atomic commit point that both selects the replica rows and appends the decision; absent such a protocol, promise 1 is false for audit reads.
