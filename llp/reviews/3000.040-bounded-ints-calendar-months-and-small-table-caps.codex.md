---

The main choices are sound: a new `IntRange` tag preserves existing `Int` serialization; bounds belong to declared slots rather than intermediate arithmetic; ordinary computed writes can correctly refuse `E_INPUT`; TypeScript `number` with bound documentation is appropriate. The month ordinal is preferable to `yyyymm`. UTC-only semantics and deferring time zones are reasonable. Whole-table caps already exist.

The RFC still needs these changes:

1. **High — §§1.3–1.4: aggregate result types and maintenance writes need explicit treatment.**  
   `bind/schema.rs::maintain_target` currently copies a sum contribution’s type onto its `value` column. Extending that recognition mechanically to `IntRange` makes two contributions of `5` to a source declared `int 1..5` produce a target declared `int 1..5` containing `10`. `engine/maintains.rs::apply_aggregate` writes directly through `tx.put`; `engine/columns.rs::mirror_column` does likewise. Neither uses ordinary row validation.

   **Smallest fix:** explicitly erase contribution bounds from sum result types, retaining unbounded `Int`. Preserve bounds on copied group keys. Specify validation or rejection for any independently bounded engine-maintained slot, including zero initialization and rebuilds. If private computed values can fail a bound, retain the existing aggregate diagnostic’s concealment of the computed number; do not expose it through generic `E_INPUT` text.

2. **High — §§1.2, 1.4: helper parameters have no enforcement boundary.**  
   `bind/program/control.rs::helper_arguments` checks assignability, emits a temporary `Let`, and inlines the helper. With the proposed `Ty::Int` erasure, this accepts a computed out-of-range value:

   ```quarry
   fn rating(x: int 1..5): x
   query example(n: int):
     return rating(n)
   ```

   Calling it with `n = 7` crosses no operation-argument or stored-column validator.

   **Smallest fix:** specify a runtime bound check at helper entry, including optional and list parameters, plus constant-call diagnostics. Its emitted representation must also reject execution on older devices.

3. **Medium — §1.6: server adoption does not establish validity of held device rows.**  
   A device can retain `stars = 0` while offline; the server repairs that row to `1`, then successfully adopts `int 1..5`. Server validation says nothing about the device’s older image or pending writes. Existing `device.rs::adopt_captured` handles this through generation reset and reacquisition, preserving the outbox.

   **Smallest fix:** replace the claimed implication with that actual lifecycle: clear incompatible images, reacquire confirmed rows, and re-evaluate pending predictions. Test tightening with stale confirmed images and pending writes on both stores.

4. **High — §§2.2, 2.5: the full-domain calendar identities contradict checked time results.**  
   For the valid timestamp `t = -9007199254740991`, the proposed calendar gives month ordinal `-3425122`, whose start is `-9007201036800000`, outside i53. At the positive endpoint, the following month starts at `9007200950400000`, also outside i53. The corresponding year identities have the same problem. Thus the stated expressions can refuse rather than yield inequalities, and the proposed runtime-domain theorems cannot hold as written.

   **Smallest fix:** distinguish mathematical calendar boundaries over unbounded integers from checked Quarry `time` results. State exactly which calls return `E_OVERFLOW`, and qualify executable identities by representability. Prove the mathematical identities and the checked conversion separately. Define astronomical year numbering, including year zero.

   Also qualify the JavaScript conversion advice: JavaScript `Date` has a narrower domain than i53 time. Both i53 endpoints produce `Invalid Date`.

5. **High — §§2.4, 6: the billing recipe does not yet establish reliable catch-up.**  
   A unique invoice key prevents duplicate invoice rows, but blindly revisiting an existing invoice refuses and parks the job chunk. Conversely, processing every missing month inside one subscription iteration can exceed the chunk budget: 8,193 missing invoices exceed the 8,192-write ceiling even after the adaptive sweep shrinks to one subscription. Further scheduled runs can repeat the same failure indefinitely.

   **Smallest fix:** provide an executable, tested recipe using guarded or `if absent` invoice creation and durable progress that bounds catch-up work across commits. Test partial completion, restart, duplicate period runs, overlapping queued runs, and a backlog exceeding one chunk. If “billing” includes an external charge, specify its provider idempotency key; invoice uniqueness alone does not deduplicate delivery.

6. **Medium — §2.4: the last-day rewrite uses the execution clock instead of the scheduled boundary.**  
   A daily job queued on January 31 but executed on February 1 sees `month(now + 1d) = month(now)` and skips the intended work. Coalescing across January 31 also loses that event.

   **Smallest fix:** base the predicate on `periodEnd`, and explain the required catch-up treatment for skipped month ends. Refusing ambiguous days 29–31 is a defensible initial policy, but the proposed rewrite is not an equivalent monthly schedule.

7. **Medium — §§3.1–3.2: the current-behavior description omits expiry exceptions.**  
   `engine/write.rs` uses a physical occupancy shortcut followed, when necessary, by a bounded **live-row** scan for expiring caps. A device refuses prediction of a capacity-consuming expiring write even when it holds the complete public table. Expired physical rows can remain, so `cap N` does not bound physical scan work to N. Meanwhile, adoption’s cap walk counts physical rows.

   **Smallest fix:** document these branches and explicitly resolve adoption’s physical-count policy versus runtime live occupancy. Test adoption with expired unswept rows. State that whole-table prediction requires complete current public coverage without a horizon; a private partition or `sync public last N` is insufficient. Clarify that 8,192 is the ordinary examined ceiling, not the maximum legal cap, and that a cap does not eliminate other meter cuts.

8. **Medium — §§2.4, 4: byte compatibility requires an explicit schedule codec rule.**  
   Merely adding `months: u32` serializes `"months": 0` into every existing fixed schedule unless it is omitted. Besides violating §4, this changes schema hashes and `digest(schedule)`, which `engine/job.rs` uses to detect schedule changes and reset their firing baseline.

   **Smallest fix:** require `serde(default, skip_serializing_if = "is_zero")`. Define calendar `offset_ms` encoding and mutually exclusive fixed/calendar shape validation. Test legacy bytes, hashes, and persisted schedule progress, plus checked `12N` conversion for yearly schedules.

9. **Medium — §§1.3, 4: fail-closed decoding is sound; the promised named error is not guaranteed.**  
   `Schema::deserialize` first calls `Wire::deserialize`, then checks capability names. An older decoder encounters an unknown `IntRange` column tag before reaching the capability check. `RuntimeError::decode` preserves `E_SCHEMA_CAPABILITY` only when the decoder’s error already starts with that prefix.

   **Smallest fix:** distinguish generic unknown-tag refusal from named capability refusal in the RFC. Do not promise retroactive error normalization on older binaries. Require recursive capability detection through optional/list columns, calendar indexes, and maintain keys, and test actual prior server/device decoders.

10. **Medium — §§1.8, 2.5, 5: the verification plan can miss shared defects or run unsupported cases.**  
    Server/device comparison cannot detect a validation bypass shared by their interpreter. The Lean emitter currently rejects `now` and computed calendar indexes. Adding scalar calendar expressions alone does not cover the promised `now` cases or independently verify stored calendar keys. Combining calendar cases with bounded columns can also make the entire Lean case unsupported.

    **Smallest fix:** require supported-case counts and coverage assertions, with separate calendar-only Lean cases. Add a pinned clock to the model’s case contract if testing `now`. Independently check stored bounded slots after successful transactions, including imports/restores and maintenance rebuilds. Exercise a complete Gregorian 400-year cycle, negative centuries/year zero, overflow refusals, and compare expression results against index/view keys. Add recursive raw-schema bound validation tests for reversed and out-of-i53 metadata.

I made no checkout changes.

**Overall verdict: NOT READY.**
