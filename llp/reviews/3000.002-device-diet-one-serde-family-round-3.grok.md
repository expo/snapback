## 2. Census — PARTLY

Listed set: all of `crates/snapback4-device/src/` except `sqlite.rs` / `ffi.rs` / `native.rs`, plus five core files (`cursor.rs`, `value.rs`, `partition.rs`, `engine/runner.rs`, `engine/components.rs`) (`wasm-codec-census.test.mjs:13-14`).

**Unlisted files the web artifact still compiles** include `json_codec.rs` (funnel, intentional), `engine/{local,read,mod,prediction,admission,write,validate,pages,receipt,rules}.rs`, `wire.rs`, `schema.rs`, `ir.rs`, `error.rs`, `rows.rs`, and the rest of always-on core. Today they have no production typed `serde_json::{from,to}_*` (confirmed). A revert of the form `serde_json::from_value::<StreamPage>` (or `Backend`, `Vec<String>`, …) in `wire.rs` or `engine/read.rs` leaves this test green. That is the hole the census exists to close: `--check-families` cannot see a fully inlined instantiation.

**The regex is evadable** (`wasm-codec-census.test.mjs:30`):

```text
/serde_json\s*::\s*(?:from_str|from_slice|from_value|from_reader|to_string|to_vec|to_value|to_writer)\b/
```

Misses `use serde_json::from_value;` then `from_value(x)`; `use serde_json as sj; sj::from_value(x)`; `use serde_json::{from_value as parse_json}`; `serde_json::to_string_pretty` / `to_vec_pretty` / `to_writer_pretty`; `Deserializer::from_str` (the shape `json_codec` itself uses at `json_codec.rs:58-61`).

**Allowlist entries are justified** (sqlite-only, exact lines, counts match). The third test does not pin those production lines; it only checks the matcher against a fake `fixture.rs`. Expanding `allow` with a real `call.rs` line would hide a revert.

In-tree sources currently use `serde_json::{Value as Json, json}` / `from_str` paths, not aliases — the hole is the net, not a present revert.

## 3. `unbounded_depth` — FIXED (host untrusted input) / PARTLY (native stack)

**Off for the web artifact.** `from_owned_text` that calls `disable_recursion_limit` is `#[cfg(not(target_arch = "wasm32"))]`; wasm uses `from_text` → `serde_json::from_str` (`json_codec.rs:56-66`). The feature is only on a target-gated dep (`crates/snapback4-core/Cargo.toml:39-40`). Workspace `resolver = "3"` (`snapback4/Cargo.toml:2`). No other `snapback4/**/Cargo.toml` enables `unbounded_depth`. Wasm device graph is `--no-default-features --features web`; core `dev-dependencies` (`snapback4-lang`) are not linked. `Cargo.lock`’s `serde_json` 1.0.151 entry lists no features; journal’s web trial of the feature grew 7,417 raw / 436 gzip, and the gated tree is 0 B vs base. Even a leaked feature would not call `disable_recursion_limit` on wasm.

**Untrusted input does not reach unlimited depth.** `json_codec::from_value` production callers are only `call.rs` `parse` (`call.rs:29-32`). `to_value` is `encoded` plus refusal envelopes (`call.rs:17,35-36,120`; `web.rs:18`). Hosts feed **text**: `WebDevice::call` → `call_text` (`web.rs:42-43`); process device → `try_call_text` (`verbs.rs:930`). Fast path and fallback both `from_text` first (`call.rs:167-175`), which keeps the 128 limit (`json_codec.rs:12-14`, asserted at `tests/codec.rs:240`). Subtrees passed to `parse` were already built under that cap. The HTTP server does not call `json_codec::from_value` / `to_value` (it still uses `serde_json::from_value` in `serve.rs` / `serve_routes.rs`, unchanged). Native `from_value`/`to_value` can stack-overflow on **programmatically** nested trees (the 160-array test at `tests/codec.rs:231-240`); that is a Rust caller, not a host JSON attacker.

## 4. Route probe and global family check — PARTLY

**Route probe** (`call.rs:29-31,173-174,187-189`; `tests/codec/route.rs:7-15`) kills the round-2 flag mutant: unique-key pages must have `PAGE_CALLS=1`, `OWNED_FALLBACKS=0`, `OWNED_CONVERSIONS=0`; duplicate `watermark` must be `1/1/1`. Counters sit on `parse` / fallback / `page_call`, not on `json_codec::from_value` itself.

**Mutant the route probe still misses.** Keep `from_text::<PageArgument>` so duplicates still fall back, and restore a second family on the success path that does not call `parse`:

```rust
use serde_json::to_value as to_tree;
fn encoded<T: serde::Serialize>(value: &T) -> Result<Json, RuntimeError> {
    to_tree(value).map_err(|e| RuntimeError::Store(e.to_string()))
}
```

`observe_store` / query `cut` / components still go through `encoded` (`call.rs:190`, `91-92`). Probe stays green. Census misses the alias. `--check-families` should refuse `serde_json::value::ser::Serializer` on `StreamPage` / `Cut` / `Coverage` unless that instantiation is fully inlined (the reason the census exists).

**Mutant the global family check still misses.** `collectFamilies` treats a deserializer as owned only if the symbol matches `serde_json::value::Value` / `value::de::\w*Deserializer` / `map::\w+` (`attribute-wasm.mjs:62-63`). Unrecognized refuse requires `Serializer|Deserializer|Read` in the name (`attribute-wasm.mjs:71`). A `from_value` instantiation mangled as `deserialize::<serde_json::Value>` (reexport, not `value::Value`) is dropped with no family and no refusal. `wasm-families.test.mjs:17-19,42` only plants `serde_json::value::Value`. Also still true by design: a fully inlined owned deserialize leaves no symbol.

The new tests do kill `Vec<String>` / only-owned types when the planted name is `serde_json::value::Value` (`wasm-families.test.mjs:37-45`).

## 5. Product behavior — PARTLY (native adapters only)

No web/host-text behavior change: wasm `from_owned_text` is still `from_text`; `call_text` / `validate_text` unchanged. `cfg(test)` counters do not ship (`call.rs:195-200`). Census, family checker, dirty pathspec (`measure-wasm.sh:9,14`), SQLite `raw_records` (`old_store.rs:141-147,164-171`) are tests/tooling.

**Native product change:** `json_codec::from_value` / `to_value` now parse with recursion limiting disabled (`json_codec.rs:56-61,80-82`). Trees deeper than 128 that previously failed with a recursion-limit error now succeed (or can overflow the stack). Process/web hosts never present such trees from attacker JSON. Query `components` on the wire is encoding-only, not a new semantic.

**Did this delta introduce a new problem?**  
No product regression on the web or on host-text native. It does introduce **false confidence**: the census is named “web-reachable” but is neither complete nor alias-safe, so a second-family revert can still leave `scripts/test.sh` green.

**Is there a regression test in this delta that would also pass without the change it claims to test?**  
Yes. `wasm-codec-census.test.mjs`’s live `web-reachable` case is already green on `76fa25a510` (funnel already in `parse`/`encoded`); it does not prove unbounded-depth gating, the conversion counters, or global family aggregation. The route probe’s fast-path `OWNED_CONVERSIONS == 0` assertions also pass if the counter is never incremented; the duplicate-key `== 1` side is what binds `parse`. Counterexample of a tight test: `owned_adapters_keep_programmatically_built_deep_trees` (`tests/codec.rs:231-240`) is red if `from_owned_text` still uses `from_text`.

## Findings

### High — census regex misses idiomatic aliases
- **File:** `snapback4/packages/snapback4/test/wasm-codec-census.test.mjs:30`
- **Scenario:** In `call.rs` `parse`, replace the body with `use serde_json::from_value; from_value(value).map_err(...)`. Blocking suite glob still runs the census; it stays green. Owned `StreamPage` / `Backend` / `Vec<String>` deserializers return. Same with `use serde_json as sj; sj::from_value(value)`.
- **Fix:** After stripping comments, fail on `use serde_json::{...from_value...}` / `use serde_json as`; also match `serde_json::from_value` after `as` aliases (or parse `use` items and resolve). Treat `to_string_pretty` / `Deserializer::from_str` the same.

### Medium — census file list is not the web-reachable set
- **File:** `snapback4/packages/snapback4/test/wasm-codec-census.test.mjs:13-14`
- **Scenario:** Add `let _: StreamPage = serde_json::from_value(v.clone()).unwrap();` in `crates/snapback4-core/src/wire.rs` (production, not the `#[cfg(test)]` module) or `engine/read.rs`. Both are linked into `--features web` wasm. Census green; if the instantiation inlines, `--check-families` is green too.
- **Fix:** Walk every `.rs` the web rustc unit compiles (`snapback4-device` + `snapback4-core` with the web cfg), excluding only `json_codec.rs` and `cfg(not(web))` files (`sqlite`/`native`/`ffi`/`postgres`). Do not hand-maintain five core paths.

### Medium — route probe counts `parse`, not owned conversion
- **File:** `snapback4/crates/snapback4-device/src/call.rs:29-31` (counter); `tests/codec/route.rs:14-15`
- **Scenario:** The `encoded` alias mutant in item 4. Unique-key and duplicate assertions stay green while `to_value` on `StreamPage`/`Cut`/`Coverage` returns.
- **Fix:** Increment the conversion cell inside every owned-tree encode/decode used on the page path (`encoded` and any `json_codec::from_value` in `try_call_text`), or assert `--check-families` from the lib test so a second family cannot hide behind `parse`.

### Medium — family classifier drops `serde_json::Value` as deserializer
- **File:** `snapback4/scripts/attribute-wasm.mjs:62-71`
- **Scenario:** Production `serde_json::from_value::<PageArgument>` whose twiggy name is `deserialize::<serde_json::Value>` (reexport). `ownedReader` requires `value::Value`; unrecognized refuse requires `Deserializer|Serializer|Read`. Symbol ignored; `checkFamilies` reports ok.
- **Fix:** Treat `serde_json::Value` (and `serde_json::Map<...>`) as owned readers; add that symbol to `wasm-families.test.mjs`.

### Low — `to_*_pretty` and `Deserializer::from_*` omitted from census
- **File:** `snapback4/packages/snapback4/test/wasm-codec-census.test.mjs:30`
- **Scenario:** `serde_json::to_string_pretty(&page)` in `web.rs` or `call.rs` adds a PrettyFormatter writer family; census green.
- **Fix:** Fold pretty/writer/deserializer constructors into the same matcher as item 1.
