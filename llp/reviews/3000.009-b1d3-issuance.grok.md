## Material

**1. Provider HTTP success body is not bounded** — `snapback4/packages/snapback4/test/fixtures/identity-recipe/invitation-issuance/resend.ts` **79–80**, **66**.

Contract requires a bounded, lifetime-bound provider response. Lifetime is handled (`untilAborted` on the POST and on `response.text()`, `redirect: "error"`, fixed `https://api.resend.com/emails`). Size is not:

- Success path fully buffers `response.text()` then `JSON.parse` with no byte cap, no `Content-Length` check, and no truncation. `providerMessageId` is capped at 100 chars (**89**) only after the entire payload is in memory.
- **409** throws `ResendUnresolved` (**66**) without `body.cancel()` (unlike the 4xx/5xx branches at **69** and **73**), so a conflict response can also keep an unbounded stream alive.

A 2xx/409 from Resend (or anything `fetch` delivered to that URL) can OOM the action worker that holds `MAIL_API_KEY`. Cap the download (small fixed limit is enough for `{ id }`), reject/retry if exceeded, and cancel the 409 body before parking.

## Advisories

- **Peak memory is still one stream chunk, not the 64 KiB cap.** `resend.ts` **55–58**: `read()` can deliver an arbitrarily large `Uint8Array` before the ceiling rejects it. It is not pushed or parsed, then cancel runs, but the worker has already allocated that chunk. A BYOB reader or copy-into-a-fixed 64 KiB buffer would make the cap memory-strict. Native fetch is usually chunked near this size; a hostile `fetch` is not.
- **`getReader()` is outside the cancel `try`.** `resend.ts` **50** vs **53–71**. If locking throws, `sendResendEmail` maps it to `Retry` and never `cancel()`s the body.
- **`releaseLock()` in `finally` (`72–73`) runs without waiting for `reader.cancel()`.** Correct for the mocks (`releaseLock` is a no-op). On a real reader, cancel-then-immediate-release is usually OK because `cancel()` starts synchronously; it is still a lock-state combination the new doubles do not model.
- **`if (!response.body) return JSON.parse("")` (`49`)** is a throw gadget for empty 200; the outer catch turns it into sanitized `Retry`, which is the right uncertainty outcome.
