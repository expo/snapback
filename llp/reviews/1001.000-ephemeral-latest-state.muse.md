## Verdict: REVISE — direction sound, needs minor clarifications before code

No redesign. The typed latest-state room with TTL, snapshots, and no asset custody is the right boundary. Fix the items below in the spec text, then implement as planned.

## Strengths

- Keeps durable rules/admission, replaces only the untyped event pipe.
- `value` reuses Quarry arg types + server-side validation; TS types explicitly not validation.
- TTL required 1–30s, compiler + generation admission double-check.
- Connection-owned entry: random public `key` + unguessable `lease`, `from` owner-derived, two tabs get separate entries.
- Whole-snapshot replacement + coalesce to newest; no delta protocol, no replay, no history.
- Stale-write fence via strictly increasing per-lease `version`.
- Continuous revocation: subscribe fence + publish-dependency removal before next frame.
- Client incarnation isolation: no rebind, no retry/queue/predict, ambiguous settles via snapshot/TTL.
- Asset exclusion preserves LLP 1006.002 boundary: channels hold no custody/bytes/cursors.

## MATERIAL concerns + minimal fixes

**M1. Lease is under-specified as auth (definite).**
Spec says lease “binds” name/args/principal/session-epoch/subscription, but `POST /set|/clear` lists only `{args,lease,version,value}`.
Fix: state `set`/`clear` must verify all four: lease equality (constant-time), calling auth principal/session-epoch equals lease binding, normalized `args` + channel name equal binding, subscription still live. Lease alone is not a bearer. Specify entropy: e.g. >=128-bit CSPRNG, collision retry. Keep lease out of `entries` as specified.

**M2. Expiry clock ambiguous (definite).**
“server-now + TTL” + “must not be extended by rollback” + wall `expiresAt` conflict.
Fix: owner stores monotonic deadline; expiry decisions use monotonic only. `expiresAt` is informational wall-clock derived at snapshot time. Sweep <=1s is best-effort; correctness comes from synchronous exclude-expired before snapshot/`set`.

**M3. Version consumption + write ordering (definite).**
“A validated command consumes its version” leaves malformed, initial value, and reorder undefined.
Fix: define initial version `1`, first use must be `1`; malformed/unknown-lease/shape errors refuse without consuming; well-formed but auth/stale-refused consumes. Add: callers must serialize `set`/`clear` per lease (`await`); concurrent same-lease writes are last-arrival-wins among increasing versions, not invocation order. Single writer per lease holds because only the lease holder writes.

**M4. Duplicate/empty validation vs parser reality (avoidable complexity).**
`serde`-style JSON maps collapse duplicates; “refuse duplicates” needs text-level detection. “Empty records refuse” needs interaction with all-optional values.
Fix: either drop duplicate-refusal and match durable-arg behavior exactly, or state channel validation runs on raw text with duplicate detection shared with durable args. Clarify `{}` refuses even if all fields optional, and compiler rejects empty `value`.

**M5. Reconnect duplication + close semantics (lifecycle, definite).**
Fresh lease on reconnect + undetected old connection bounded by TTL means brief double entries from one principal. Headless `set` retention risks leak.
Fix: document duplicates as expected; UI counts entries, dedupe by `from` if desired. State `room.close()`/last-observer-release promptly removes its own entry (not TTL wait), and StrictMode remount gets new lease/version sequence with old incarnation responses ignored.

**M6. Capacity refusal semantics (definite).**
64/room, 1024/owner, “refuses new subscriptions” needs envelope.
Fix: define exact-room = normalized `(name,args)`; refusal uses ordinary refusal envelope, terminates that child only, does not truncate snapshot. Expired values not freeing handles is correct; closed/failed must free promptly as stated.

**M7. Coalescing scope (clarification).**
“Both server and client coalesce” could read as global.
Fix: coalescing is per subscribed handle to newest whole snapshot; newest `key`/`lease` never dropped; terminal refusal supersedes pending snapshot and is never overwritten.
