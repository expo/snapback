### 1. D0.1 tie-break

Every user-index entry this engine writes is `index_keys` → components (plus a `words` token in that slot) **then the row id** (`rows.rs:124–156`). SQLite (`store.rs:408–423`), Postgres (`postgres/store.rs:289–303`), `MemoryRows` (`rows.rs:269–283`) and the device memory store (`snapback4-device/src/memory.rs:183`) all consume that. I did not find a layout that stores a unique index as components-only.

Uniqueness is a separate `live_lookup` on `index_values` without the trailing id (`write.rs:315–320`). So:

- Unique `roomId, at`: stored key is `(roomId, at, id)`; suffix after the lane prefix is `[at]`; seeking `after = [at, id]` is `encode(prefix ++ after)` which **is** the stored key; exclusive `scan_range` (`rows.rs:103–110`) works ascending and descending.
- Non-unique without `id`: same stored shape; this is the in-lane skip (`REVIEW-TICKETS.md` second probe). D0.1 on the **eager** key vector (`read.rs:766–790`) and on `Bounds.after` fixes it; `lazy_merge` already refuses this index (`rules.rs:90–95`).
- `words(..)`: each token key also appends id (`rows.rs:148–153`). Paved forms already end in a declared `id` (`search.rs:19–21`), so stored keys are `(…, at, id, appended id)`. Resume on `(at, id)` or `(at, id, appended id)` both exclusive-skip the row, because encoding is prefix-free (`key.rs:5–6,75–79`).
- Null suffix values: `T_NULL` then id (`key.rs:34,46–48`). Several nulls on a nullable unique index are several stored keys; the preferred fix distinguishes them. `lazy_merge` already excludes nullable unique indexes (`rules.rs:91–94`); eager does not, and needs the same position.
- Device memory / Postgres: same `stored_index_keys` + `scan_range`. No counterexample.

The preferred fix therefore makes “a position identifies one row across lanes” hold for **every** merge **if** eager keys, lazy `MergeHead` keys, the v1 suffix descriptor, and refill/`after` all carry that id. It does **not** hold if only `merge_lazy` changes.

The fallback is right: adding `id` to a unique index would make uniqueness `(…, id)` and stop enforcing the author’s key (`write.rs:316–320`). A second non-unique index ending in `id` is the correct rewrite.

The design must pick one encoding: **append `id` only when the suffix does not already end in `id`**, or **always append**. Always-append changes the descriptor of today’s `…, id` merge tokens (`cursor.rs:107–123` vs `suffix_after` at `schema.rs:442–444`) and contradicts D2.5’s “no token format changes.” Append-if-missing leaves paved tokens valid and only invalidates the already-wrong unique-without-`id` tokens, which D0.1 already calls acceptable.

### 2. D2.3 stop after every pop

With unique positions, the drain-cut argument in D2 Correctness holds.

- **Both batch sizes.** After a pop, the next head of *that* lane is required before another pop (`read.rs:861–870` today skips refill once `capped_at` is set and keeps popping — that is the bug). Stopping on a refill cut, including lookahead-only cuts, does not skip: resume is exclusive after last **emitted** K, and the unestablished head is after K.
- **Duplicate `id`.** GPT’s A=100 emit / B=100 dup / B refill cut / A=90 is exactly why the stop is after every pop, not after every emit. Under D0.1, B’s 100 is the same position as A’s; B’s 95 is after K.
- **`done`.** D2.2 matches the code’s lie at `read.rs:843,865` (`rows.len() < batch` even when the short read was capped). A cut short read must not be `done`.
- **`has_more`.** Still only on a unique pop at a full page (`read.rs:856–857`). A short drain-cut page uses `opened_all && drain_cut && emitted ≥ 1` instead. The unemitted `has_more` head is recovered by resume-after-K.
- **Opening vs drain.** `opened_all` false ⇒ no `next` (D3). An unopened lane can still misorder the **answer**; D correctly refuses to continue it.
- **Expiry, further terms, lane `filter`.** Survivors are selected inside `scan_prepared` before they become heads (`read.rs:585–635`). Resume re-runs those tests after K; a starved `exists` in a filter is `false` then `capped_at` breaks (`read.rs:47–50,633`) so the candidate is not emitted and is seen again after K.
- **Steps.** `Meter::step` always `E_BOUND`s (`meter.rs:166–174`). No page, so no skip/repeat across pages.
- **`next` while a head is unknown.** Only if `opened_all` were true with a missing head. Empty lanes are known-empty; a cut empty read is not `done` and fails `opened_all`.

I found no remaining drain-cut skip/repeat given D0.1.

### 3. D2.4 outcome-time merge-owner next

§20.3 (LLP 3000.007 around `2478–2486`) withholds a merge `next` for the non-uniform class even in budget. ### 4. D4 covering invariant

**(a)** is the right withheld-reason list: those holes are not repaired by following the merge cursor.

**(b)** cannot be `capped_at`’s first `(kind, site)` (`meter.rs:131–133`). During `merge_lazy`, `scan_prepared` does `meter.at(&scan.site)` (`read.rs:541`) — the **lane** site, not `merge.site` (binder allocates those separately in `bind/program.rs:512–555`). A drain cut’s first failure is already “not the merge site.” A site-string test would mark every drain-cut as (b), force `cut: null`, and make D5.7’s unshaped `'meter'` case impossible. Implement (b) as: on every Cap failure, if the runner is **not** inside the page-owning walk, set a boolean; wrap `merge_lazy` / owner `scan_prepared` (including lane filters and their reads) in that walk. `capped_at` stays the first failure for operators.

Still missing from the invariant:

- **Live aggregate cut on an emitted row** (`read.rs:612–621`): the row is returned with a partial `value`; resume-after-K never re-reads it. Not (a), not off-walk (b). Smallest fix: treat that as (a) (`cut: null`, keep `next`) or do not emit the row.
- **Heap:** `data: null`, `page = None` (`runner.rs:182–185`) — no `next`. Covered by losing the page, not by (b).
- **Output:** `charge_output` after `run` (`runner.rs:741–754`) becomes `Bound` / a refusal, not `data: null`.
- **Starved filter / rule probe inside a lane:** inside the walk; resume-after-K re-sees the candidate. Not a D4 miss.
- **Nested cursorless page in a shape:** `page_depth` is 0 for `DerivedArray` (`runner.rs:237–238,568–573` in the binder); `has_more` sets `page_overflow` (`read.rs:659–661`) → (a).
- **`nextExpiry`:** a later row’s deadline is not a hole in this page’s rows.

Shaped drain-cut pages reporting `cut: null` while keeping `next` is acceptable: D6 must not call that page complete, and the reads card already defines `cut: null` as “not disclosed here” (`reads.rs:9–13`). It **is** a regression of the precise-reason sentence for mixed device meter+horizon pages (Q6). I did not find a card, `apps/`, or `src/search.ts` that *requires* `'meter'` on a shaped cut merge; `search.rs:102–103` and the feeds “no cut continuation” line are about today’s withhold-`next`, not about `cut` letters.

## Findings

### High — D4(b) identified by meter site, not by the owner walk

**Design:** D4. **Code:** `meter.rs:131–133`, `read.rs:541`, `read.rs:807–880`, binder sites `bind/program.rs:512–555`.

**Scenario:** Twelve-lane unshaped drain-cut, no later `Get`. First Cap failure is `Examined` at a **lane** `scan.site`. A literal reading of “site other than the page owner” sets (b), so `cut: null`. D5.7’s `'meter'` assertion fails; D6 never discharges; the walk’s last page can look complete while earlier pages still advertise a hole.

**Smallest design change:** On every Cap failure, if the runner is not inside the page-owning walk, set `capped_outside_owner_walk`. Set that walk true around the owner `merge_lazy`/`scan_prepared` (lane filters included), false before the result shape. Do not compare `capped_at.1` to `merge.site`.

### High — D5.2 cannot execute D2.3’s counterexample

**Design:** D5.2. **Code:** `read.rs:840`, `read.rs:854–870`.

**Scenario:** One row, two word lanes, `last N` with `N≥1`. `lanes ≤ 8` ⇒ each opening already buffered `take+1`. Emit / dup-drop pull from those buffers; no refill, so no refill cut, so no drain-cut `next`. The test is green with D off or never sees the bug.

**Smallest design change:** Require the one-head branch: **>8** overlapping lanes (nine prefixes of the first term, or nine scopes sharing an `id`), then cut on the dup lane’s refill.

### Medium — D5.1’s numbered fixture is not a default-ceiling drain cut (plain filter)

**Design:** D5. **Code:** `read.rs:642,840`; `meter.rs:23`.

**Scenario:** Twelve lanes, `where` keeps 1/50, `last 100`, `examined = 8192`. ~5550 examined, page 1 full and `complete: true`.

**Smallest design change:** Pin `Ceilings.examined` or density so drain exceeds the remainder after an uncut opening (e.g. `last 160` at 1/50, or examined 4000), and name whether the skip is a `where` or a further search term.

### Medium — C2 / “only >8 drain-cuts” is false for filtered lazy merges

**Design:** D5 C2, D2 last sentence. **Code:** `read.rs:642,863–866`.

**Scenario:** Eight lanes, merge `where`, each lane has `take+1` matches so `done` is false, then overlapping ids exhaust a buffer and refill under a tight ceiling. That is a ≤8 drain cut; C2’s “tokens unchanged” would be wrong.

**Smallest design change:** C2 applies to **unfiltered** lazy merges whose opening returned a full batch. Add a labelled positive or an explicit exclusion for `where`.

### Medium — D0.1 vs D2.5 token descriptor

**Design:** D0.1, D2.5, D7. **Code:** `schema.rs:442–444`, `cursor.rs:107–123`, `read.rs:466–468,819`.

**Scenario:** Always-append `id` on `byAuthorTime: authorId, at, id` makes suffix `[at, id, id]`. In-flight v1 tokens fail `Descriptor`. D2.5 says no format change.

**Smallest design change:** Append `id` to the merge position **iff** the suffix does not already end in `id`. State that `decode_cursor_for` / `cursor_suffix` for merge owners use that suffix. Always-append is also correct but then D2.5 must say every merge cursor is refused once.

### Medium — live-aggregate cut on an emitted merge row

**Design:** D4 “contribution it still misses”. **Code:** `read.rs:612–621`.

**Scenario:** Drain-cut after emitting a maintain row whose `live_aggregate` already hit `capped_at`. D6 discharges `'meter'`; the partial `value` is never recomputed.

**Smallest design change:** Put this under (a) (`cut: null`, keep `next`) or do not emit a row whose aggregate was cut.

### Medium — D7 blast radius incomplete

**Design:** D7. **Code/copy:** `search.rs:102–103`, `README.md:571–572`, `bind/mod.rs:283`, `reads.rs:9`.

**Scenario:** Land D, leave `N_WIDE_MERGE` and the search/README sentence stating a meter-cut merge has no `next`.

**Smallest design change:** Update those to “opening or word cut: no `next`; uniform drain cut: `next`.” Leave the Following/eager feeds sentence and `unsafe_cursors` as they are.

### Low — heap/output lumped as `data: null`

**Design:** D4. **Code:** `runner.rs:182–185` vs `741–754`.

Heap is `data: null` / `page = None`. Output `Bound` is a query refusal. Split them in D4.

### Low — D6 discharge any `cut !== null`

**Design:** D6. **Code:** `react.tsx:133`, `read.rs:796–802`.

Engine withholds `next` on word cuts. Discharge only `'meter'` so a synthetic `words`+`next` cannot hide “narrow the term.”
