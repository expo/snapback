Four material issues need resolution before this design can support its proposed proof claims.

The propositional kernel is reasonable: the runtime already preserves unknown under negation and admits only true ([rules.rs:1197](/home/ccheever/projects/sb4-b16-sec/snapback4/crates/snapback4-core/src/engine/rules.rs:1197)). Exhaustive enumeration over independent atoms is conservative if translation preserves those semantics and includes every admission path. Explicitly unproved aggregates, temporal expressions, opaque workers, and exhausted searches are acceptable limits. The problems below concern paths that could incorrectly receive a proof.

1. **HIGH — Checking the entire table update rule is not conservative for owned-field writes.**

   RFC §2 permits a column invariant to use the entire table rule as an approximation. However, `authorize_update_fields` skips an ordinary update rule when a patch touches only fields owned by the caller; named transitions remain enforced ([field_authority.rs:73](/home/ccheever/projects/sb4-b16-sec/snapback4/crates/snapback4-core/src/engine/field_authority.rs:73)).

   Consider `role` declared `written by .principal`, with no table update rule, and an invariant restricting role writes to staff. The table rule is deny, so implication from that rule proves anything. Nevertheless, a nonstaff owner can patch their role. This can produce a false authorization proof, including for a privilege-granting column.

   **Fix:** Define admission per touched-field set, including the owner-only bypass and named-transition requirements. A whole-table approximation must overapproximate *all* effective admission paths. Until supported, affected declarations must be unproved. Require a regression with a denied ordinary update rule, an owned field, and an admitted nonstaff owner patch.

2. **HIGH — Referential actions bypass the child’s rules and are missing from effect admission.**

   Cascades delete reached children without checking their delete rules; `set null` similarly changes child references without checking the child update rule ([write_references.rs:237](/home/ccheever/projects/sb4-b16-sec/snapback4/crates/snapback4-core/src/engine/write_references.rs:237)).

   The existing cascade regression is especially concrete: Alice deletes her project and thereby deletes Bob’s hidden tasks, although the tasks’ delete rule requires their owner ([reference_actions.rs:86](/home/ccheever/projects/sb4-b16-sec/snapback4/crates/snapback4-lang/tests/reference_actions.rs:86)). An invariant `tasks.delete only .owner = viewer` is tautologically implied by that direct delete rule but does not describe the actual effects Alice can cause.

   **Fix:** Include incoming cascade and `set null` paths in invariant obligations and the audit graph. Propagate the initiating operation’s authority to the affected child image, or report the child claim unproved. These are user-triggered effects; silently treating their engine execution as exempt would contradict the table-effect contract. Add qualification cases for both actions.

3. **HIGH — Raw rule probes are an observational exposure path, beyond caller-filtered reads.**

   RFC §3 groups `exists` with ruled reads. That applies to program `exists`, but table-rule probes inspect raw target rows without applying the target’s read rule. Both the guide and implementation explicitly establish this distinction ([rules.md:139](/home/ccheever/projects/sb4-b16-sec/snapback4/crates/snapback4-lang/src/guide/rules.md:139), [witness.rs:12](/home/ccheever/projects/sb4-b16-sec/snapback4/crates/snapback4-core/src/engine/witness.rs:12)).

   A private `secrets` table can satisfy its direct owner-only invariant while another table’s read rule uses `exists secrets[...]`. Reading a marker row then reveals secret-row existence or a named-equality predicate through row-versus-null results. No distinct authored refusal codes are necessary. Listing that probe in the exposure map does not discharge the source privacy claim.

   **Fix:** Follow reverse dependencies from protected data into read/write rule probes and their observable outcomes. Treat those observations as explicit declassifications or blockers unless a sound reduction proves them permitted. Distinguish raw-rule probes from program reads in translation and generated tests.

   Also specify the observer boundary. Existing documentation acknowledges hidden candidates affecting page examined counts and meter cuts ([LLP 3000.015:138](/home/ccheever/projects/sb4-b16-sec/llp/3000.015-shared-baseline-for-snapback5.spec.md:138)). A row-disclosure proof may explicitly exclude these channels; a broader privacy proof must account for them or remain unproved.

4. **HIGH — “Current role at access” is not established by ordinary offline replicas, even without delivered history.**

   RFC §3 requires role truth at the access boundary and singles out delivered history as unproved. However, ordinary synced reads can trust previously delivered rows without reevaluating the rule ([read.rs:470](/home/ccheever/projects/sb4-b16-sec/snapback4/crates/snapback4-core/src/engine/read.rs:470)).

   Sequence: Alice acquires a membership-protected row, disconnects, another caller revokes her membership on the server, and Alice reads locally before receiving the revocation. `until-revoked` cannot enforce the latest server role before that information arrives. Rechecking a stale local membership would not establish it either.

   **Fix:** Define precisely which snapshot and boundary the claim covers. A narrower proof about server disclosure or acquisition-time authorization is viable, provided the report explicitly identifies device reads as using an earlier snapshot. If the declaration promises current server-role authorization at every device access, these paths must remain unproved unless a freshness protocol establishes that property. Require a disconnected-device revocation test with divergent server and replica state.

The RFC’s blanket prohibition on unmodeled-path proofs is appropriate, but the concrete obligations above must be specified so those paths cannot disappear during translation. None requires a complete solver: explicit, named unproved coverage is sufficient.
