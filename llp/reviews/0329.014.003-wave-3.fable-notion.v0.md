Written against LLP 0329.014.000 v0.1 (§9.1 rulings applied). Constructs from LLP 0329.014.004 are used and marked **(v1)**. ### 2. Schema in v0

**Representation.** User tables are rows, not schema: a fixed catalog and **one cell table per value kind** (`textCells`, `numberCells`, `boolCells`, `dateCells`, `selectCells`, attachments), each `unique(recordId, propertyId)` and indexed `(databaseId, propertyId, scopeId, value, recordId)` — the generic typed EAV index, ordered in the value's own type, serving single-property sorts and range filters for every property of every database: the design's "runtime index per property", materialized once, statically. Relations are one `edges` table read from both sides (invariant 6 by construction). Formulas and filters are **exploded AST rows** under `cap`, so the interpreter's loop domain is a `Page`. Numbers are scaled `int` per property (§6 item 6).

**Visibility scope.** Every content row carries `scopeId`: the nearest resource owning an ACL policy (own entries or an inheritance break). `resources` is a `tree` whose `scopeId` is an engine-propagated inherited column **(v1 `tree.inherit`)**; content rows copy it through a `ref` (§6 item 3; in v0 programs write the copy, `propagateScopeChunk` repairs it). Verdicts are folded once per `(scope, subject, action)` into `aclVerdicts` by the grant/revoke programs (deny wins through the ancestry until a break). A read rule is then *hoisted verdict for the row's scope* ∧ *one freshness probe*.

```ts
const sys = () => principal.kind === 'system'
const eff = (scope, subj, action) => { const v = db.get(aclVerdicts, [scope, subj, action]); return v === null ? 'none' : v.effect }
// Hoisted whenever `scope` is pinned by the scan prefix — true for every scope-partitioned index below.
const can = (scope, action) =>
  eff(scope, viewer, action) !== 'deny'
  && !any(groupMembers.byUserLive, [viewer, 'live'], { take: 32, where: g => eff(scope, g.groupId, action) === 'deny' })
  && (eff(scope, viewer, action) === 'allow'
      || any(groupMembers.byUserLive, [viewer, 'live'], { take: 32, where: g => eff(scope, g.groupId, action) === 'allow' }))
const fresh = c => db.get(records, c.recordId).scopeId === c.scopeId          // stale scope copy ⇒ hidden (1 probe/row)
const kindOf = p => db.get(properties, p).headKind; const epochOf = p => db.get(properties, p).headEpoch
```

**Catalog and access.** `scoped(r, w)` = read `can(row.scopeId, r)` (∧ `fresh` on copies), insert/update `can(scopeId, w)`, `delete: never`; `liveKey` is the booking partial-unique trick.

- `principals(workspaceId, kind, state)`; `groupMembers(groupId, userId, liveKey)` — unique, `byUserLive`, **`cap 32/user`** (bounds |S|).
- `resources(parentId, path, depth, breakInheritance, hasEntries, scopeId)` — `tree({ parent, path, depth, maxDepth: 32, maxSubtree: 5000, inherit: ['scopeId'] })` (v1): `scopeId` = self if break or entries, else parent's; a move needs `edit_data` on both ends.
- `aclEntries(resourceId, scopeId, subjectId, action, effect, liveKey, validTo)` — unique per `(resource, subject, action, liveKey)`, `cap 1000/resource`, `immutableExcept(['liveKey', 'validTo'])`; insert `share` (`administer` to grant administer); read admin or own.
- `aclVerdicts(scopeId, subjectId, action, effect, epoch)` — unique; `bySubjectScope`; written only via `db.run` from grant/revoke/expire; read own or admin.
- `shareLinks(resourceId, scopeId, tokenHash, actions, liveKey, expiresAt)` — `unique('byToken', ['tokenHash'], { bearer: true })` (v1); read `principal.bearerOf === l.id || can(scope, 'share')`.
- `changes(workspaceId, seq: int({ sequence }), actorId, cause)` (v1), `auditEvents(resourceId, scopeId, actorId, action, changeId, metadata json)` — `appendOnly`; read `history`.
- `pages(resourceId, scopeId, parentPageId, recordId, title, state)` `byParent`; `blocks(pageId, scopeId, parentBlockId, ordinalKey, kind, payload json, embedDatabaseId, embedViewId, embedMode)` `byPage`, `cap 2000/page` — an embed stores ids only (invariant 10).
- `databases(resourceId, scopeId, owningPageId, schemaHead, state)`; `properties(databaseId, scopeId, headRevisionId, headKind, headEpoch, state)` `cap 2000/db` (≤ 500 live); `propertyRevisions(propertyId, predecessorId, name, kind, storageEpoch, scale, state, relationId, rollupTargetPropertyId, aggregate, exposure, expressionId, config json)` `appendOnly`; `schemaMembers(databaseId, propertyId, ordinal, liveKey, fromRevision, toRevision)` `byDbLive`; `selectOptions(propertyId, label, color, ordinal, state)` `cap 500`; `relations(leftDatabaseId, leftScope, leftPropertyId, rightDatabaseId, rightScope, rightPropertyId, leftCard, rightCard, revision, rollupCapable)` — reciprocal insert needs `edit_schema` on both sides. All `scoped('view', 'edit_schema')`.

- `expressions(databaseId, resultType, volatile, nodeCount, depth, version)`; `formulaNodes(expressionId, ordinal, op, valueKind, propertyId, litText, litNum, litBool, childA, childB, childC)` — unique `(expression, ordinal)`, **`cap 500/expression`**, post-order; filters live here too — one interpreter.

// textCells (value text({ max: 8192 }), + .index('byToken', tokens('value'))), boolCells, selectCells (optionId), dateCells (start, end, allDay, tz): same shape

export const publications = table({ id: id(), rollupPropertyId: id(), relationId: id(), kind: text({ max: 8 }), leftScope: id(), rightScope: id(), publishedBy: id(), liveKey: text({ max: 32 }) })
  .unique('byPropKindLive', ['rollupPropertyId', 'kind', 'liveKey'])
  .rules({ read: p => can(p.leftScope, 'view'), insert: p => p.publishedBy === viewer && can(p.leftScope, 'administer') && can(p.rightScope, 'administer'),
           update: (o, n) => can(o.leftScope, 'administer'), delete: never })
const published = (propId, kind) => db.exists(publications.byPropKindLive, [propId, kind, 'live'])

// Viewer-visible: split by both scopes — every row of a group is readable exactly where its key is; K2 proves it.
maintain.count(edges, { by: ['relationId', 'leftRecordId', 'leftScope', 'rightScope'], where: e => e.liveKey === 'live', as: visibleEdgeCount, overflow: 'refuse' })
maintain.sum(rollupInputs, { by: ['rollupPropertyId', 'sourceRecordId', 'sourceScope', 'targetScope'], of: 'value', as: visibleRollupSum })   // + min/max (v1)
// Published structural: same inputs, no scope split; readable is conditioned on the publication row (§6 item 2).
maintain.count(edges, { by: ['relationId', 'leftRecordId'], where: e => e.liveKey === 'live', as: structuralEdgeCount, overflow: 'refuse',

maintain.sum(rollupInputs, { by: ['rollupPropertyId', 'sourceRecordId'], of: 'value', as: structuralRollupSum,

### 3. Operations in v0

Grouped by the design's §5; ops 1–3, 9, 11, 13 and the point reads are ordinary once the schema exists. Below: where `check` speaks.

#### Op 7 — Save and execute a dynamic view (the interpreter)

**First attempt** (steps 4–7 transliterated):

```ts
export const runView = query({ viewId: id(), after: text({ max: 600 }) }, ({ db, args }) => {
  const rev = headRevision(db, args.viewId)
  const rows = db.scan(records.byDb, [rev.databaseId], { take: 100, after: args.after })
  const out = []
  for (const r of rows) { const cells = db.scan(numberCells.byRecord, [r.id], { take: 500 }); if (evalFilter(db, rev.filterExpressionId, r, cells)) out.push(project(r, cells)) }
  out.sort(cmpBySorts(rev))                                                       // multi-key sort
  return { rows: out, groupCounts: tally(out), total: out.length }
})
```

```
E_BOUND        102 × 502 = 51,204 examined > G. Load only the ≤16 properties the filter/columns reference.
E_UNBOUND_LOOP evalFilter walks an AST in json — no static cardinality. Explode to formulaNodes (cap 500); loop the Page.
E_STRUCTURAL_COUNT  `groupCounts`/`total` tally rows under a non-uniform rule and return them as facts about the database.
               Rewrite: page tallies labelled `atCap`, or the structural maintained counts with declared readable.
E_COMPUTED_KEY none — every read key is a field of a traced row (view, node, record) → shape.
```

**Rewrite.** One pushdown key (first sort, or the pinned key), `merge` over the viewer's scope prefixes so every prefix is uniform-true (rulings 2–3 never fire, extents ship, local replay is exact), the interpreter over exploded nodes, residual filtering in the page:

```ts
export const runView = query({ viewId: id(), afterKey: int(), afterId: id() }, { readTime: { granularityMs: 60_000 } }, ({ db, ctx, args }) => {
  const v = db.get(views, args.viewId)
  const rev = db.get(viewRevisions.byViewRev, [v.id, v.headRevision])
  const sorts = db.scan(viewSorts.byRev, [rev.id], { take: 10 })                 // Page<10>
  const nodes = db.scan(formulaNodes.byExpr, [rev.filterExpressionId], { take: 500 })
  const refs = referencedProperties(nodes, sorts)                                 // ≤16, enforced at saveView
  const scopes = myScopes(db, v.databaseId, 'view')                              // prelude: ≤16 scope ids
  const key = sorts[0]; const prefixes = scopes.map(s => [v.databaseId, key.propertyId, s])
  const page = db.merge(numberCells.byDbPropScopeValue, prefixes, { order: key.direction, take: 50, after: [args.afterKey, args.afterId] })  // (v1)
  const out = []
  for (const c of page) {
    const r = db.get(records, c.recordId)
    const env = loadCells(db, r, refs)                                            // ≤16 point reads by kind
    const rollups = loadRollups(db, r, refs, scopes)                              // ≤4 rollups × ≤16 scope reads (maintained rows)
    const t = evalExpr(nodes, env, rollups, ctx.readTime, rev.timeZone)           // ≤500 steps; errors are typed values
    if (t.kind === 'bool' && t.value) out.push(project(r, env, rollups))
  }
  return { rows: out, hasMore: page.hasMore, groupTallies: tallyCapped(out), asOfBucket: ctx.readTime }   // tallies are page facts
})
```

Certificate: `exam ≤ 700 (prelude) + 16×52 (merge) + 50×(1+16+64) = 5,582`; rule probes ≤ 50 (`fresh`) + 16 hoisted verdicts; steps ≤ 50 × (500 + 4×500) ≈ 1.1×10^5; completeness **page**; `readTime` in the read set — the design's evaluation instant T and its "refresh at the next boundary" are this one line (local-midnight buckets need the civil-time seam, §6 item 8). Secondary sort keys order ties within the page only (§7); a pinned view merges over `pinnedKeys.byViewScopeKey` instead.

`saveView` explodes the AST into `formulaNodes` (`insertEach` ≤ 500) and refuses >16 referenced properties, >10 sorts, >5 groups. `pinView` inserts the `pinnedViews` row (cap 16) and enqueues `backfillPinnedKeys` (job); thereafter `setCells` maintains `pinnedKeys` for every pinned view referencing the edited property — ≤16 × ≤10 point reads, certified write amplification.

#### Op 6 — Rollups: the viewer-visible domain

**First attempt** (contract 4's default, read at query time):

```ts
const es = db.scan(edges.byLeft, [rel.id, r.id, 'live'], { take: 200 }); return { count: es.count(), partial: es.hasMore }
```

```
E_STRUCTURAL_COUNT  edges.read is not uniform-true for the caller (rightScope varies per row); `count()` returns a resource fact.
               Rewrite: maintain.count with a declared readable, or a caller-scoped count.
```

Neither paste is `viewer_visible`: the first is `published_structural`, the second does not exist here. The first attempt is also wrong on its own terms: hidden edges consume `take` (ruling 2), so the windowed visible count moves when a hidden edge is added — trap 1's observation fails. The admitted route is the **scope-split maintained aggregate** `visibleEdgeCount`, keyed by `(relation, source, sourceScope, targetScope)`, summed over the viewer's hoisted scope set:

```ts
const loadRollups = (db, r, refs, scopes) => refs.rollups.map(p => {
  let n = 0
  for (const s of scopes) { const m = db.get(visibleEdgeCount, [p.relationId, r.id, r.scopeId, s]); if (m !== null) n += m.value }
  return { propertyId: p.id, kind: 'int', value: n }        // exact over what the viewer can see; K point reads
})
```

This is the design's "authorization-scoped aggregate" (concession 3) per visibility *class*, not per viewer. K2: both scopes are in `by`, so every row of a group is readable exactly where the key is; no `readable`, no security item. Sum/min/max go through `rollupInputs`: `setCells` on a rollup-fed property rewrites inputs for the target's reverse edges up to `take: 200`; at `hasMore` it writes a `jobs` row and `refreshRollupInputs` finishes in chunks, OCC-fenced on `inputRev`. Published structural rollups are the second `maintain` over the same inputs, `readable` conditioned on a `publications` row that `publishStructural` inserts under `administer` on both databases; the security item is emitted once at `check`, naming that table and rule.

#### Op 5 — Add or remove relations

`addEdge`: `require` endpoints match the relation's databases and cardinality; insert with both scopes copied from the records; `edgeEvents`; `changes`. `E_CONSTRAINT` on the unique/cap is sealed — a hidden duplicate and a real one refuse identically; prediction `conditional(cap, unique)`. `removeEdge(edgeId)` flips `liveKey` on the observed edge; a hidden edge's id is unreadable, and the update rule requires `administer` when the target is not viewable. The natural first attempt for "clear this relation cell" —

```ts
for (const e of db.scan(edges.byLeft, [rel, r.id, 'live'], { take: 200 })) db.update(edges, e.id, x => ({ ...x, liveKey: e.id }))
```

— is refused `E_STRUCTURAL_WRITE` (v1). The paste is what the product wants anyway (invariant 11): per-edge removals of observed ids. Whole-list replacement is inexpressible: trap 4 cannot be written.

#### Op 8 — Grant, inherit, move, revoke

`grantAccess` inserts the entry, then recomputes the subject's verdict at the resource's scope and at every policy-bearing descendant scope inheriting through it (`resources.byPathScoped`, `take: 64`; per scope a fold over ≤ 32 ancestors with two `exists` each) → `exam ≤ 4,300`, `W ≤ 67`. At `hasMore` it refuses `E_FANOUT`; the paste enqueues `recomputeVerdictsChunk` (job). Revocation is split so lag never widens access: the `liveKey` flip and the direct verdict rewrite commit at once; only inheriting descendants lag. Subscriptions invalidate by trace, so the design's ACL epoch has no counterpart — the trace *is* the epoch. `setInheritanceBreak` and `movePage` rewrite `resources.scopeId` through `tree.inherit` (≤ `maxSubtree`, `engineWrites` certified); copies on cells and edges are repaired by `propagateScopeChunk`, during which a stale copy is *hidden* by `fresh()` rather than served under the old scope.

**Last administrator.** First attempt: `require(db.get(adminAllowCount, [resourceId]).value > 1)` before removing an allow. It passes `check` and is wrong: a `deny(administer)` on a group containing the last admin leaves the count intact and the resource ownerless. The correct predicate — *some member still holds an effective administer verdict* — is `E_UNBOUND_SCAN` over members × groups. Product-change (§7): denies may not target `administer`; the invariant is stated over allow entries.

#### Op 4 — Create or edit a record, including offline

`setCells(recordId, ops[≤25])`: per op, a stale `epoch` inserts `quarantinedOps` instead of rejecting (invariant 16); `kindOf` dispatches to the typed table (a `switch` over eight kinds — eight static sites); `head.rev !== op.baseRev` inserts `writeConflicts` with both values and leaves the head (invariant 14); otherwise `upsert` + `cellEvents`; bump `records.revision`; write `changes`. Cells are rows, so they commute by construction; **prediction is `closed`** — every key is an arg or a traced-row field, and the conflict branch is predicted too.

#### Op 10 — Comments and notifications

`createComment` inserts the comment (`can(scope, 'comment')`) and declares `phase: 'system'` (v1): the continuation reads the ≤ 20 mentioned principals and inserts a `notifications` row only where the recipient's own verdict is `allow` — a verdict for *another* principal, hidden from the author's rules, readable under the system phase and never returned. Mentions write nothing to `aclEntries` (invariant 10).

#### Op 14 — Export

`exportChunk` must page the requester's view at one watermark, re-authorizing per chunk. As a `job` it runs as `system` and sees everything; as repeated requester queries each page is its own snapshot. Refused pending §6 item 7. Import has no such problem: `parseImport` (effect) loads `importRows`; `importChunk` (`callable: 'system'`, 40 rows) validates against the pinned schema and writes cells; relations resolve in a second pass; `publishImport` flips `state`; formulas are parsed by the effect into `formulaNodes`, never executed as text.

### 6. Language delta (ranked)

1. **Viewer-relative reductions as a type.** Ruling 8 refuses the design's default aggregate and every "things I can see" count. Smallest addition: `Visible<T>` — a reduction over a non-uniform domain is admitted iff its result is typed `Visible`, never written or compared against a structural limit, and its domain is complete (`All` under `cap`, or maintained groups with uniform-true keys), never a `take` window. Amends §4.4, §9.1(8). General.
2. **Data-conditioned disclosure.** `readable` may consult a runtime row (`publications`); `check` names that table and its insert rule as the disclosing authority in the security item. This is how runtime-declared, audited publication lowers without runtime `maintain`. Amends §2 (maintained), §9 `E_DISCLOSURE`. General.
3. **Inherited columns along a `ref`** (`scopeId: inherit(records, 'recordId', 'scopeId')`), the many-to-one cousin of `tree.inherit` (v1): engine-propagated under a cap, otherwise a declared job with stale-means-hidden freshness. Without it every content table copies the scope by hand and `fresh()` costs a probe per row. Amends §2. General.
4. **`db.merge` prefixes from a traced page** (v1 takes a literal/arg list): the viewer's scope set is computed in a prelude. Amends §4.2. General.
5. **Composite `cap.by`** — edges per `(relation, source)` without a synthetic key column. Amends §2. General.
6. **Decimal value type** `decimal({ precision, scale })` with the design's rounding law, or normative `mulDiv` on scaled ints (v1 names a subset). Amends §4.5. General.
7. **Principal-bound jobs with `asOf(commitSeq)` reads**: `job({ principal: 'requester', asOf })` re-validating the requester each chunk — export, and any "as me" bulk read. Amends §7/kinds. General.
8. **Civil-time seam**: local-midnight `readTime` buckets from a tz table the interpreter can read. Known from booking/calendar. Amends §4.3.
9. **Published `maxSteps`** with loop-nest accounting (`page × nodes`); a default below ~2×10^5 makes every view with two formula columns `E_STEPS`. Amends §5.
10. **`E_STRUCTURAL_COUNT` rewrite text** should offer the scope-split maintained form as a third paste — the K2-free route whenever visibility is a row column. Amends §9.

Not needed (used as v1): `any`, `tree.inherit`, `dag`, `job`, `phase: 'system'`, `callable: 'system'`, bearer uniques, `int({ sequence })`, `E_STRUCTURAL_WRITE`. Not needed at all: runtime-declared tables, per-tenant activation, per-user-schema certificates — the certificate is per program and every tenant runs the same programs.

### 8. Where the design is wrong

1. **Structural limits leak through viewer-visible surfaces.** The design evaluates `LIMIT` (10,000 edges) and cardinality refusals against structural facts while showing viewer-relative values. *Observation:* give Lee 3 visible edges in a cell that structurally holds 10,001; Lee's rollup renders `LIMIT` instead of 3 — a hidden fact changed a visible output (invariant 9 fails). In v0 the same leak appears as `E_CONSTRAINT` on `addEdge`, which is sealed; the design must seal its `LIMIT`s the same way or compute them over visible rows.
2. **"The last administrator cannot be removed" is not a bounded predicate under group denies.** Step 2 of op 8 says "validate the resulting administrator set"; with deny-wins over groups the set is a function of every member's group closure. *Observation:* one admin who is a member of `everyone`; add `deny(administer, everyone)`; the allow-entry count is unchanged and no principal can administer the page. v0 exposes it because the only bounded spelling is over allow entries.
3. **The authorization-scoped derived cache is per viewer at scale.** `derived_result(…, authorization_scope, …)` keyed by principal is 5M × pages of rows — what the design's own §6 calls non-viable for indexes. *Observation:* 1,000 viewers open one view with one viewer-visible rollup; `derived_result` grows by 1,000 × page, not one row set. The fix is §2's scope-split aggregate: "authorization scope" must mean the visibility class, not the principal.
