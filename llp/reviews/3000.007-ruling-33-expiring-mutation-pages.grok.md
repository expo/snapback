# Assessment

**P1 is a sound disclosure relaxation.** For a uniformly decided prefix the false verdict still observes nothing (A1), and a true verdict’s abort-versus-commit bit is the same class of fact a production query already returns as `complete: false, cut: "meter"` over that prefix (A2 in spirit). Write-authority (§8.7), service seats and action sessions do not split those two viewers: scans still use the read rule; actions do not scan; services can query as the same principal. Matching, merges and non-plain indexes stay refused. Helpers are inlined before `admission::check_detail`; bound pages, `where` / `update … if` setup, shapes and hand-serialized IR all go through the same scan walk.

**P3 as written is not sound under P2.** A predicting complete-group scan walks every unswept physical candidate (`first N ≥ cap` is a live bound, §20.9.3). Device and server unswept sets differ by clock and by sweep-stream lag. Local `Cut::Abort` is not converted to “queue without a row”: `Device::admit` returns `E_BOUND` and drops the write. That is the Clique cleanup this proposal exists to enable, failing on the local-first path. Alternative A (never-predicting only) is **necessary** given P2; purge-on-access (B) and a free skip (C) are not.

The +1 examined attempt on aborting pages and write-side cap walks make test §5(b) false as a raw biconditional. That is a test-spec defect, not a new hidden-prefix channel.

# Findings

### 1. High — P3 predicting + P2 (engine unchanged) drops a write the server would commit

**Design:** §2 P2–P3, §3 A5, §4 A.  
**Code:** `snapback4-device/src/device.rs` 735–749; `engine/local.rs` 61–68; `engine/read.rs` 561–587; `engine/mod.rs` 624–664; `serve_maintenance.rs` 22.

**Scenario.** `typing` expires, `cap 50 by roomId`, predicting `for row in typing[roomId] first 50 by byRoom: delete typing[row]`. The room has 50 live rows and 9,000 unswept expired (or the device still holds them after the server swept: clock ahead, or sweep deletions not yet streamed). Device prediction charges each expired candidate and raises `E_BOUND`. `admit` only converts `RuntimeError::Prediction` (or a replay-candidate refusal) into queue-without-a-row; `E_BOUND` is returned and the outbox is unchanged. The server, already swept, would have committed. The local-first client never POSTs `/m`. Reverse skew (device clean, server dirty) is A5: pending rows, server abort, withdraw — no durable fabricate. Sweep does not need this mutation (`sweep_expired` on the host tick, 2,000 rows). `E_BOUND` is not `retryable`.

This is the Clique “clear the typing rows of a room I am in” path on a device. A5 is incomplete in one direction.

**Smallest proposal change.** Adopt **alternative A**: admit only `predicts: never` (`: server`) under P2. Predicting complete-group loops stay refused for expiring tables.  
If predicting must stay, P2 cannot: local `E_BOUND` on an expiring page must queue without a row, same as `E_PREDICT`. That is an engine/admit change, not P1.

### 2. Medium — A2 and §5(b) are false as a same-budget biconditional

**Design:** §3 A2, §5(b).  
**Code:** `engine/read.rs` 561–563, 579–587; `meter.rs` 117–136; `write.rs` 369–387; `write_target.rs` 303–306; `serve.rs` 1011–1029.

**Scenario.** Same remaining examined budget *R*, same prefix, true verdict, *K* physical candidates (live + unswept + uniform lookahead). Mutation examined = `1 + K` (attempt unit “in every world”). Query examined = *K*. At *K = R* the mutation aborts `E_BOUND` and the query is still `complete: true`. Together the two production bits identify *K =* ceiling exactly. That is still this viewer’s prefix (A3), already approximately available by composing a query that spends one examined unit first. A mutation that then inserts also re-walks the group on `cap` (`write.rs` 370–387), so abort can fire when a scan-only query would not.

**Smallest change.** Rewrite A2 and §5(b): compare after the aborting attempt unit (or give the query a one-examined prelude); use a scan-only mutation; assert `cut == "meter"`, not merely `complete: false`. No change to P1’s admitted behaviour.

### 3. Low — `RuntimeError::Bound` Display still names `actual`

**Design:** §3 A4.  
**Code:** `error.rs` 115–116 vs 245–249; `receipt.rs` 34–36.

**Scenario.** Any path that prints `error.to_string()` rather than `refusal()` would show the examined count. HTTP `/m`, `_ops` replay, and `refusal()` do not.

**Smallest change.** Landing note: wire and receipts must keep using `refusal()` / `receipt()`; do not log Display of `Bound` on a viewer-facing path. Implementing lane; no proposal behaviour change.
