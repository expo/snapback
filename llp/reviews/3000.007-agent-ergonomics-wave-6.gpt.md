## Findings

### F1 — High: an app helper can silently disable feed promotion

**Location:** [recipe.rs:99](snapback4/crates/snapback4-lang/src/recipe.rs:99), [feeds.md:166](snapback4/crates/snapback4-lang/src/guide/feeds.md:166).

An existing app can declare:

```quarry
fn count(value: json <=100000): 0
```

The renamer leaves the recipe’s `count(near)` unchanged because `count` is not a recipe declaration. The binder resolves app functions **before** builtins, and the JSON parameter accepts the page. Combined compilation therefore succeeds with changed behavior. [expr.rs:432](snapback4/crates/snapback4-lang/src/bind/program/expr.rs:432)

At 51 followers, promotion never happens. Future delivery still visits only 50 followers, silently omitting others.

**Smallest fix:** reject installation when an app declaration would shadow a builtin used by the recipe, before writing. Add this installation case and assert promotion and subsequent delivery to the 51st follower.

### F2 — High: concurrent native owners can overwrite the original queued write

**Location:** [local.ts:1062](snapback4/packages/snapback4/src/local.ts:1062).

Open two native clients on the same device store before either submits ID `X`. Concurrently submit `record({n:1}, X)` and `record({n:2}, X)` while offline.

Each client’s `MutationIds` considers `X` new. Durable admission performs prediction without checking an existing ID, then uses an outbox upsert. The second admission replaces the first entry’s arguments and minted row IDs. Both predictions can exist temporarily, while only one input remains executable. The server still applies once, but it may apply the second input and report that receipt to the first caller. [device.rs:708](snapback4/crates/snapback4-device/src/device.rs:708), [sqlite.rs:84](snapback4/crates/snapback4-device/src/sqlite.rs:84)

**Smallest fix:** make duplicate-ID comparison and admission atomic in the device transaction, before prediction. Return the original entry for equal input; refuse conflicting input without changing it. Test two already-open owners with equal and unequal inputs, including an in-flight send.

### F3 — High: reopening after receipt eviction can report failure for an already committed write

**Location:** [local.ts:1073](snapback4/packages/snapback4/src/local.ts:1073).

Submit an insert with explicit application row ID `R` and write ID `X`. After completion, finish 256 other writes, evicting `X`’s receipt. Reopen and retry the original input with `X`.

The client no longer knows `X`, so it predicts the insert again. Row `R` already exists: admission returns a constraint refusal, which becomes terminal locally. No request reaches the server’s existing replay record. Thus the documented recovery instruction returns `failed` where the server would return `sent, replayed:true`.

The eviction regression avoids this by retrying a mutation that only returns a value. [client-seams.test.mjs:179](snapback4/packages/snapback4/test/client-seams.test.mjs:179)

**Smallest fix:** allow unknown caller-ID replay candidates to reach authoritative replay before treating local prediction/validation refusal as terminal, while preserving synchronous journal capture. Add the explicit-row-ID case on both device stores, plus a guard whose condition changed after the first execution.

### F4 — Medium: `N_NO_HORIZON` still recommends a prediction-breaking horizon for rule-only live aggregates

**Location:** [horizons.rs:16](snapback4/crates/snapback4-lang/src/bind/residency/horizons.rs:16).

Consider an uncapped, publicly synced expiring table `sessions`, a maintained `liveCounts` grouped by owner, and another table with:

```quarry
insert <- exists liveCounts[.owner]
```

An eligible mutation inserts into that second table without directly reading `sessions` or `liveCounts`.

The residency collector records the write-rule probe against `liveCounts`, but does not add its expiring source. `sessions` therefore still receives `N_NO_HORIZON`. Following that advice removes prediction: runtime aggregate probes explicitly require the expiring source without a horizon. The persistent summary also misses this new dependency. [residency.rs:86](snapback4/crates/snapback4-lang/src/bind/residency.rs:86), [read.rs:102](snapback4/crates/snapback4-core/src/engine/read.rs:102)

**Smallest fix:** include live-aggregate source dependencies when collecting rule-probe residency sites. Test suppression before adding a horizon, persistent explanation afterward, and prediction on both stores.

### F5 — Medium: lost-lease handling hides handler failures and misreports terminal effects

**Location:** [worker.ts:112](snapback4/packages/snapback4/src/worker.ts:112).

A handler throws `provider unavailable` after its lease has been swept. `/failed` refuses `E_EFFECT_LEASE`; the worker neither reports the original error nor preserves it server-side, and prints only “the effect was requeued.”

That message is also false when the eighth expired attempt becomes terminal `failed`, or another worker has already settled it. `E_EFFECT_LEASE` does not establish requeue. [effects.rs:126](snapback4/crates/snapback4-core/src/engine/effects.rs:126), [effects.rs:160](snapback4/crates/snapback4-core/src/engine/effects.rs:160)

**Smallest fix:** report lease loss neutrally with the server’s cause; separately report the handler error when its settlement cannot be recorded. Change the throwing-handler test, which currently asserts that this error disappears, and add eighth-attempt and already-settled cases.

### F6 — Low: already-qualified schedule targets panic during renaming

**Location:** [recipe.rs:70](snapback4/crates/snapback4-lang/src/recipe.rs:70).

Passing valid source containing `schedule …: feed.purgeRemoved` to `prefix_module` searches for one Word token equal to `feed.purgeRemoved`. The parser accepts this qualified target, but the lexer produces separate tokens; `replace` panics. Prefixing the entire target would also produce the wrong qualification.

The current recipe avoids this because its source target is unqualified.

**Smallest fix:** handle module and operation tokens separately, rename only the appropriate declared operation, and preserve external targets. Add qualified-target tests with empty and nonempty prefixes.

**Additional missing tests:** login against a credential created under the old short-Unicode policy; private/horizon-limited app-card joins and revocation; the wired app’s celebrity/broadcast branch; same caller ID under different principals and across store replacement; and rollback after a package replacement followed by a later write failure.

Verdict: NOT READY
