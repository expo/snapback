## Verbatim review

**Verdict: READY WITH CHANGES**

I read the RFC in full (rev 7) and reviewed the snapshot read-only, with five parallel evidence passes whose claims I then spot-checked in the code myself (I cite below only what I verified or quote with its exact location; earlier review files were not consulted). I did not run the test suites.

**Finding 1 — Medium — device panics on a scope naming an unknown table** (`snapback4-device/src/device/delivery.rs:211`). `stage_left` indexes `schema.tables[&event.table]` directly, while the sibling scope paths return `Input`/`Schema` errors ([snapshot.rs](/tmp/union-r7-review/snapback4/crates/snapback4-device/src/device/snapshot.rs:77) rejects unknown tables; deferred/snapshot paths validate width). Interleaving: any page reaching `stage_left` with a `scope` event for an unknown table (malformed or hostile server input on the deferred path) panics the device instead of failing closed. Fix: resolve with `schema.table()` and return `Input`/`Schema` error.

**Finding 2 — Medium — `leave()` silently keeps rows when it has no index** ([device.rs](/tmp/union-r7-review/snapback4/crates/snapback4-device/src/device.rs:1306-1311)). Unknown table, missing `sync`, or no plain index over the audience prefix all return `Ok(())` having deleted nothing. Interleaving: a leave/drop fires on such a table while the device holds its group rows → rows survive the drain indefinitely (an `UntilRevoked` leak; the `DeliveredHistory` delegation above it is fine). Schema validation normally forces the index, so this is a backstop, but a silent backstop on a revocation path. Fix: return `Schema`/`Input` error instead of `Ok(())`, with an explicit empty-prefix (roster) branch.

**Finding 3 — Medium (collective) — six union-specific interleavings the worlds still do not reach** (`snapback4-sim/tests/union.rs`). Each needs a named world or mutation: (a) two-prefix group columns (no table syncs to two group columns); (b) roster×group interleave in one schema with cross-table commits (roster-only vs group-only worlds never combine); (c) snapshot-page sweep (drain limits 1/1000 but snapshot pages fixed at 3, follow fixed at 2); (d) bulk leave on a windowed world (the 600-spared walk runs only non-windowed); (e) epoch events on a windowed world (leave→rejoin→create asserting per-arm newest); (f) born-in-one-commit delete-reinsert (`createThenRemove`/`createThenMove` in a single commit). §4.5's retention claim leans on these worlds as evidence; add the six before claiming completeness. (Two-prefix shapes are also the exact §8a deferral — keep the deferral, but it stays a stated evidence limit.)

**Finding 4 — Low — no epoch when a group arm is removed** ([partition.rs](/tmp/union-r7-review/snapback4/crates/snapback4-core/src/partition.rs:840-842)). `changed_group_audiences` only lists tables whose *new* audience is `Target`, so union→column-arm removal records no epoch and `intervals()` stops tracking the table. Mitigated today because any `sync` change is a new generation and the device drops images and re-snapshots (§9), so I find no disclosure or reachable strand — but the ledger keeps pre-removal joins/scopes under an audience that no longer exists. Fix (hardening): epoch-bump tables losing a group audience too.

**Finding 5 — Low — invalid acquisition markers fail open into over-hold** ([boundary.rs](/tmp/union-r7-review/snapback4/crates/snapback4-device/src/device/boundary.rs:74-98) with [accept()](/tmp/union-r7-review/snapback4/crates/snapback4-device/src/device/boundary.rs:104-125)). A dropped or mispositioned marker is REPORT-logged and ignored, and `accept()` admits rows for arms with no boundary. I downgrade this deliberately: it is *not* disclosure (every installed put passes the serve-time whole-rule check) and it cannot falsely certify a page (`by_boundary` at `engine/read.rs:978-979` needs a *stored* boundary via `boundary::read`, `:152-160`). Over-hold below a floor is retention-excess that §4.5 expressly permits. Fix: keep the behavior, but say so in §5.2 and consider a counter on ignored markers so a validation bug (e.g. `arm_by_window` width mismatch on a legal group) does not hide as REPORT noise.

**Finding 6 — Low — `Sync::line()` still prints a union window by index name** ([schema.rs](/tmp/union-r7-review/snapback4/crates/snapback4-core/src/schema.rs:493-496)) while §2.1 promises column-form printing. Mitigated: admission uses `line_in` ([union.rs](/tmp/union-r7-review/snapback4/crates/snapback4-core/src/schema/union.rs:10)) and diagnostics go through `line_in`. Fix: have `line()` delegate to `line_in` for unions, or state that `line()` is index-form and `line_in` is the printable form.
