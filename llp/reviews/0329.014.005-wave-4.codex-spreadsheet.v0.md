There is no honest `closed` prediction for a complete edit-and-recalculate operation.

The wave-4 prediction is confirmed for the certificate unit and bounded fan-out, but narrowed for determinism. Harbor needs a second evaluation class—`formulas`—not a second query class. Determinism can be restored by recording calculation inputs. Exact offline evaluation of elevated/hidden precedents is a product boundary; insisting on it would make Harbor “not this system,” but the stated readable-cone local calculation does not.

No seed or fixture mutation is specified.

### 2. Schema in v0

Compact notation expands directly to v0: `I=id()`, `R(X)=ref(X)`, `Tn=text({max:n})`, `N=int()`, `B=bool()`, `TM=time()`, `Jn=json({maxBytes:n})`, and `V=interval({from:'validFrom',to:'validTo'})`. A `?` expands to `hasX:B` plus a non-null sentinel because strict v0 lacks `optional`. Enums are bounded text checked in both insert and update rules. Composite identities use a surrogate `I` plus `.unique(...)`. Float values use canonical numeric text/JSON because v0 has no real-number column.

Rules are listed as `Q[read,insert,update,delete]`. `S` means system principal; `M/O/H/E/A` mean workbook member/owner/share/structure/elevated-author point predicates. `RC/WC/EWC` mean read/write/elevated-write rectangle coverage. Those three require v1.1 `any(...,{take:500,where:contains})`; strict v0 produces `E_RULE_UNBOUNDED`. `NVR` is `never`.

`formulaSymbolEdge`, `feedOperator`, `deviceSession`, and `undoConflict` are required by named operations but absent from the fixed schema. `frozenSnapshotCell` chooses the side-table option the design leaves open. `MAX_*` values not fixed by the product—especially UDF source, op payload, comments, cache results, and feed config—remain `check` blockers rather than invented limits.

There is no applicable `tree`. No v0 `maintain.count/sum/rank` can implement arbitrary formulas stored as data. Doing so would turn user formulas into schema. `cap` enforces sheets/cells/names/grants without disclosing their counts. Intervals apply to names, ACLs, links, feed snapshots, UDF versions, and caches; authorization expiry additionally needs schedule-flipped `active` state.

### 3. Operations in v0

**1. `ReadViewport`.** The first attempt is:

```ts
db.scan(cellContent.bySheetCell, [workbookId, sheetId], { range: rectangle })
```

`E_UNBOUND_SCAN`: the rectangle has no `take`. Rewrite to at most 1,000 requested keys. `E_RULE_UNBOUNDED`: `read_acl` scans covering grants. Rewrite with capped v1.1 `any`. `E_CARDINALITY_ORACLE` under v1.1: emitting denied rows only for existing cells leaks occupancy.

```ts
export const readViewport = query({ keys: list(cellKey, { max: 1000 }) },
({ db, args }) => {
  const state = db.get(workbookState.byWorkbook, args.workbookId)
  const out = []
  for (const key of args.keys) {
    const readable = canReadCoordinate(key, viewer)
    const content = readable ? db.get(cellContent.byCoordinate, key) : null
    const value = readable ? db.get(computedCurrent.byCoordinate, key) : null
    out.push(readable
      ? { key, content, value }
      : { key, access: "denied" }) // emitted for every requested key
  }
  return { calcRunId: state.latestCalcRunId, cells: out }
})
```

This still needs the generation repair in §6; `computedCurrent` alone cannot provide a coherent historical generation.

**2–3. `EditCells` and `RecalcDirty`.** The natural first attempt is:

```ts
for (const e of edits) writeCell(e)
while (dirty.length) expandAndEvaluate(dirty)
```

Diagnostics: `E_UNBOUND_LOOP` for the closure; `E_FANOUT` when a reverse-edge page reaches `hasMore`; `E_BOUND` at up to 10m writes; `E_AMBIENT_TIME` for calculation time; `E_OPAQUE` for parsing, Tarjan, stored-code evaluation, or `Math.random`; and informational `E_COMPUTED_KEY`/`E_PARTIAL_PREDICTION` for `INDIRECT`.

The honest correction splits the bounded intent from a new kind:

```ts
export const editCells = mutation(editArgs, ({ db, ctx, args }) => {
  db.require(!db.exists(opLog.byClientId,[args.workbookId,args.clientOpId]),
             "DUPLICATE_OR_RETURN_PRIOR")
  const transformed = grid.transform(args.parentOpId, args.edits) // [new]
  writeEachSoft(transformed, e => validateAndWriteCell(db, ctx, e)) // [new]
  db.insert(opLog, makeEditOp(ctx,args,transformed))
  formulas.invalidate(args.workbookId, transformed.map(e => e.key)) // [new]
})

formulas("harborWorkbook", {                 // [new kind]
  maxCells: 10_000_000, maxDynamicWaves: 8,
  maxIterations: 1000, maxCallDepth: 512,
  authority: "per-formula", clock: "calc-run",
  randomness: "sticky-recorded", atomicGenerationSwap: true
})
```

**4. Structural operations.**

```ts
for (const c of db.scan(cellContent.bySheet,[sheetId],{take:10_000_000}))
  db.update(cellContent,c.id,x => shift(x))
```

This reaches `E_BOUND`/`E_FANOUT` and cannot couple AST, name, ACL, feed, format, comment, and spill transforms. Correction:

```ts
grid.applyStructuralOp({ sheetId, axis, atIndex, count, kind }) // [new]
formulas.invalidateStructure(workbookId, sheetId)              // [new]
```

The `grid` kind is a 2-D specialization of v1.1 `sequence`; it preserves real-reference shifts and leaves `INDIRECT` strings unchanged.

**5. `UpdateNamedRange`.**

```ts
const old = db.get(namedRange.byOpenName,[workbookId,scope,name])
if (old) db.update(namedRange,old.id,r => ({...r,validTo:ctx.now()}))
db.insert(namedRange,nextVersion)
db.insert(opLog,op)
formulas.invalidateSymbol(workbookId,"named",name) // [new]
```

Without `formulaSymbolEdge`, scanning 1.1m formulas is `E_FANOUT`.

**6. ACL grant/revoke.** A clock comparison inside the rule is `E_AMBIENT_TIME`; scanning grants is `E_RULE_UNBOUNDED`. Use schedule-flipped `active` rows and capped `any`. Granting still needs a general bounded `rect.coveredByUnion(viewer, rectangle)` predicate.

```ts
db.require(rect.coveredByUnion(viewer,args.rectangle),"ACL_ESCALATION") // [new]
db.insert(rangeAcl,args.grant); db.insert(aclEvent,event); bumpAclEpoch()
formulas.invalidateAcl(args.workbookId,{
  blockUserFormulaReadsUntilEpoch: nextEpoch
}) // [new]
```

The blocking clause is security-critical: asynchronous recomputation must not leave a readable stale secret-derived output.

**7. `BulkPaste`.** Catching rule failures is `E_OPAQUE`; ordinary writes abort the transaction.

```ts
const result = writeEachSoft(args.cells, cell => pasteCell(cell)) // [new]
db.insert(opLog,onePasteOp(result.applied))
formulas.invalidate(args.workbookId,result.appliedKeys)
return { skipped: result.deniedKeys } // sealed reasons
```

**8. `RefreshFeed`.** `mutation(async()=>fetch(...))` is `E_OPAQUE`. Use v1.1 outbox/effect composition:

```ts
schedule(enqueueFeedFetch,{at:f=>f.nextFire,key:f=>f.id,principal:"system"})
effect fetchFeed(feedId) -> {
  try { commitFeedSnapshot(parseBounded(fetchSecret(feedId), 8_000_000)) }
  catch { markFeedStale(feedId) }
}
```

`commitFeedSnapshot` scans at most 100k old feed-owned cells, writes at most 100k new cells, appends the snapshot/op, and invokes `formulas.invalidate`.

**9. Midnight and `NOW`.** A fleet scan is `E_UNBOUND_SCAN`; ambient calendar logic is `E_AMBIENT_TIME`. Use one live timer per workbook, v1.1 `zoned.*` with pinned `tzdbVersion`, and invoke the formulas kind.

**10. `MergeOfflineBatch`.**

```ts
for (const op of ops)
  for (const prior of scanAllSince(op.parentOpId)) op = transform(op,prior)
```

The history scan is `E_UNBOUND_SCAN`. Correction is a resumable grid-sequence job with explicit batch-byte and touched-cell limits, per-op idempotency, a final barrier, and one formula run. Computed values never enter the merge.

**11. `PutUdf`.** `eval(udf.sourceText)` is `E_OPAQUE`; invalidating all callers by scan is `E_FANOUT`. A host compiler validates a bounded, instruction-metered sandbox; metadata is versioned in a mutation; `formulaSymbolEdge` invalidates callers. Feed-shaped UDFs use the feed effect/cache path. The 100 ms wall-clock timeout must become deterministic fuel.

**12. Snapshots.** Copying or exporting 10m cells as one program produces `E_UNBOUND_SCAN`/`E_BOUND`. Use a v1.1 job over a sealed calculation generation, bounded shards, and a final snapshot pointer. User export is an ACL-filtered `exportStream`; the unfiltered blob is never delivered.

**13. Restore.** Rebuilding arbitrary history is likewise a job: start from a checkpoint/sealed op watermark, stage a new content generation, atomically publish it, then invoke formulas. Materialize mode writes authorized frozen values into a new grid sequence in bounded shards.

Required unnumbered surface:

```ts
export const recalcAll = mutation(..., () => formulas.recalcAll(...))
export const presence = channel(...,{publish:canReadCell,subscribe:canReadCell,ttlMs:4000})
export const listSheets = query(...db.scan(sheets.byWorkbook,[id],{take:200}))
export const undo = mutation(..., () => grid.applyInverseOrConflict(...)) // [inferred shape]
```

### 4. K2 audit

| Question | caller or resource? | required route | Would visibility filtering be wrong? |
|---|---|---|---|
| User `SUM`, `COUNT/A`, `AVERAGE`, `MIN/MAX`, `SUMIFS`, pivot/`QUERY` count | resource | formula authority must read every semantic precedent or return sealed `#PERM!` | yes |
| Elevated aggregate over salaries/margins | resource | sealed system evaluation plus declared output-cell audience/disclosure | yes |
| `RANK`, `MATCH/XLOOKUP`, first/top, `FILTER/UNIQUE/SORT` extent | resource | complete declared formula range; no page-as-population fact | yes |
| Spill height/width and collision | resource | check full readable spill rectangle; hidden collision must not distinguish occupancy | yes |
| Cell/sheet/name/grant “is full?” | resource | sealed `cap` refusal; if displayed, maintained owner-readable count | yes |
| Sheet `row_count`/`col_count` | resource, explicitly nonsecret | product-declared disclosure | no, if sheet itself is visible |
| Viewport occupancy and hidden-sheet count | resource | fixed requested keys or caller-partitioned visible projection; no range extent | yes |
| `calc_run` dirtied/evaluated/waves/iterations | resource | owner/operator projection or explicit disclosure | yes |
| Feed parsed dimensions/export totals | resource | feed operator/owner only | yes |
| Paste `skipped[]`, merge conflicts | caller | argument-scoped coordinates; denial details sealed | no |
| Synchronous threshold `seed≤20k` | resource | response timing independent of hidden cone, or coarse declared workload disclosure | yes; current timing can leak fan-out |

No conventional `maintain` is valid for spreadsheet formulas: their definitions and authority are data, not schema declarations.

### 5. Integrity audit

`C` = constraint, `R` = rule, `P` = program require, `S` = schedule, `K` = new formulas/grid runtime.

| # | Enforcement |
|---|---|

### 8. Where the design is wrong

1. `ReadViewport` leaks hidden occupancy. It enumerates only existing keys and then emits `{access:"denied"}`, revealing which unreadable coordinates are populated. Confirm by inserting one secret HR cell and comparing a contractor’s response before and after.

2. ACL revocation can leave a readable secret-derived output cached. The design immediately removes newly unreadable source cells but allows user-formula recalculation to lag. Confirm by revoking salary access during a slow calculation and immediately reading a still-visible dashboard formula; the old salary total must never appear.

3. `computed_current` cannot represent the promised calculation generations. It stores one row per cell, dirty recalculation updates only evaluated cells, and later updates destroy prior non-frozen values, yet `ReadViewport` expects every row to match a requested run. Confirm by changing one independent cell: an unchanged neighbor retains the prior `calc_run_id`; then request the previous run after another run commits. The schema cannot return either coherent graph without generation indirection.
