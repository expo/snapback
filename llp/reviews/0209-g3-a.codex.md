### MATERIAL 1 — Memo hits reuse per-subscription window-ledger state

The semantic key contains materialization, partition, authorization version, and cut, but not `advancedNodeId` or `priorWindowLedgers` ([engine.rs:909](/Users/ccheever/projects/snapback-worktrees/sbs-0209-g3/a-memoization/crates/snapback-engine/src/local/engine.rs:909), [graph_evaluator.rs:36](/Users/ccheever/projects/snapback-worktrees/sbs-0209-g3/a-memoization/crates/snapback-engine/src/graph_evaluator.rs:36)). That exclusion is intentional for identity, but those fields do affect per-lineage accounting: `next_ledgers` starts from the subscription’s prior values, advances only its selected node, and enforces cumulative limits ([graph_evaluator.rs:2629](/Users/ccheever/projects/snapback-worktrees/sbs-0209-g3/a-memoization/crates/snapback-engine/src/graph_evaluator.rs:2629)).

The memo retains and clones the entire `QueryInvocation`, including `GraphServingRegistration.window_ledgers` ([engine.rs:959](/Users/ccheever/projects/snapback-worktrees/sbs-0209-g3/a-memoization/crates/snapback-engine/src/local/engine.rs:959), [engine.rs:4579](/Users/ccheever/projects/snapback-worktrees/sbs-0209-g3/a-memoization/crates/snapback-engine/src/local/engine.rs:4579)). On delivery, that cached registration replaces the receiving subscription’s registration ([engine.rs:32358](/Users/ccheever/projects/snapback-worktrees/sbs-0209-g3/a-memoization/crates/snapback-engine/src/local/engine.rs:32358)).

Therefore, two subscriptions with the same semantic key but different valid ledger histories receive the first subscription’s ledger state. A fresh evaluation would produce different accounting. Debug builds catch this because convergence compares ledgers, but release builds skip the fresh evaluation entirely ([engine.rs:8301](/Users/ccheever/projects/snapback-worktrees/sbs-0209-g3/a-memoization/crates/snapback-engine/src/local/engine.rs:8301), [engine.rs:8458](/Users/ccheever/projects/snapback-worktrees/sbs-0209-g3/a-memoization/crates/snapback-engine/src/local/engine.rs:8458)). Release correctness thus depends on the debug oracle for this case.

The N=3 test stays green because every subscriber uses an empty prior ledger and identical advanced node ([graph_corpus_v1.rs:1133](/Users/ccheever/projects/snapback-worktrees/sbs-0209-g3/a-memoization/crates/snapback/tests/graph_corpus_v1.rs:1133)), and it inspects graph accounting only for the first subscription ([graph_corpus_v1.rs:1521](/Users/ccheever/projects/snapback-worktrees/sbs-0209-g3/a-memoization/crates/snapback/tests/graph_corpus_v1.rs:1521)).
