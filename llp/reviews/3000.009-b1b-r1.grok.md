## What this slice does

`bound_custom_session` is the new identity helper. One `Store::transaction()` (`BEGIN IMMEDIATE`, `store.rs` 183–191) rechecks the raw service bearer, then `held_claim_authority`, then either inserts session+binding or explicitly replaces the live family. HTTP `POST /auth/session` stays service-authenticated (`serve.rs` 739–742, 1063–1066). Absent `binding` still uses `custom_session` with the old kind/days defaults (`serve.rs` 1109–1113).

## Contract checks (source)

**Lost delivery must not mint a new family.** Existing `(invocation, intent)` is a primary key (`identity.rs` 38–43). A repeat without `replaceLostDelivery` is `E_INPUT` (624–626). Replacement deletes every current row of that family and inserts one token with the stored family id and original `expires_at` (637–648). Binding columns are digest/inputs/expiry/family/generation only; the core test concatenates them and asserts the raw token is absent (`bound_session.rs` 42–46).

**One immediate transaction, then mint/recover.** Service liveness, held claim, generation, binding read, and writes all sit between `store.transaction()?` and `tx.commit()?` (`identity.rs` 596–652). Errors drop `Tx` and roll back (rusqlite transaction-on-drop). Two-connection tests open a second `Store` on the same WAL file and do not take the HTTP engine mutex (`bound_session.rs` 172–221). Serialization is the SQLite write lock, not `Shared.engine`.

**Held claim is the live owner, lease, deadline, cancel, park, settle.** `held_claim_authority` (`actions.rs` 168–174) requires `claimed_by` + current `session_digest`, then `live_claim_authority` (`163–166`): `state = 'running'`, `lease_until > now`, deadline, and `authority_expiry` (transitive chain at `identity.rs` 71–100). Cancel and park both `finish()` the request off `running` and delete the claim session (`actions.rs` 138–142, 268–269, 350–361; `steps.rs` 66–68, 111). Stale lease after re-claim fails the digest match.

**Malformed present binding/outer values refuse.** HTTP: `deny_unknown_fields` Binding, intent/id checks, non-string kind, non-i64 days → 400 `E_INPUT` (`serve.rs` 1076–1097). Unbound still defaults `kind:false` / `days:"thirty"` (`serve_tests.rs` 182–185). Duplicate/missing lease → `E_ACTION_LEASE` without falling through to unbound (1099–1102, 210–214).

**Refresh vs recovery.** `rotate_session` keeps `family` (`identity.rs` 237–238). Recovery looks up `COALESCE(family, token_digest)` (630–633). Core test rotates, plants an overlapping extra family member, recovers once, and expects original expiry and a single live family row (`bound_session.rs` 58–66).

**Tombstones.** Logout, `revoke_principal` (generation bump + delete), and expiry keep the binding row and refuse replace (`identity.rs` 627–636; `bound_session.rs` 104–128). A later unbound session for the same principal is a different family and does not revive the tombstone (114–117). Changed inputs refuse and leave the first token live (48–51).

**Diagnostics.** Default `snapback4 why` prints argument/result **size + sha256** only; JSON is `--values` (`work_records.rs` 45–52, 99). HTTP error paths in the new test assert the body does not contain service token, lease, or minted token (`serve_tests.rs` 193–194, 222–223, 242). Success `/auth/session` and the caller’s collected action `result` still carry `Session` by design (`serve.rs` 1108; `actions.rs` 24).

**CLI/worker unbound helper is unchanged.** `mintSession` still POSTs `{principal, kind, days?}` with no binding (`packages/snapback4/src/worker.ts` 268–273). That is the B1a gap, not a B1b regression.

## Introduced defects

None that break this bounded contract.

The new HTTP early-outs (`return respond(...)` for bad binding/kind/days/lease/bearer at `serve.rs` 1083–1106) run **inside** `let mut engine = lock(...)` (1072–1073). In Rust, `return respond(...)` evaluates `respond` (socket write) before dropping the mutex. That is an availability footgun for a **service-authenticated** client, not a mint-semantics hole. Success and core `Err` still respond after the lock block (1118–1121).

## Test gaps (not introduced product bugs)

- **Parked invocations** are listed in the contract and ops doc. They are gated by `finish(..., "parked")` + `live_claim_authority`, same as settle/cancel, but `bound_session.rs` never parks. Settled and cancelled are tested (88–100).
- **Bound `days` 0 / negative** are integers, so HTTP accepts them; `new_session` clamps to 1..=3650 (`identity.rs` 137) while the binding stores the unclamped `days`. That is not the “legacy default on wrong types” case the tests cover. Pre-existing clamp, now persisted on the binding.
- **HTTP layer** does not repeat the two-connection revoke/replace race; the core test does (`bound_session.rs` 172–221). That matches “must not rely on the HTTP mutex.”
