## Findings

### High — “Private” is still a schema table a principal can reach

**Design:** §3.2, §3.7, §8 Visibility. **Code:** `catalog.rs` 126–139; `emit.rs` 21–28; `serve.rs` 894–909; `serve_changes.rs` 80; `verbs.rs` 192–194, 456–484, 559, 702–720; `sql.rs` 44–45; `residency.rs` 10–14; `successor.rs` 129–132; `native.rs` 585–658; `write.rs` 301–307.

**Scenario.** `likeCount: count likes by postId` generates target `$posts.likeCount` (unspellable) as `Schema.tables` + `Schema.maintains`. Then:

- `GET /schema` and `GET /` send it to every authenticated client (`serve.rs` 894–909).
- `check` prints “3 tables” for two authored tables (`verbs.rs` 192–194).
- `/changes` saturation invalidates `engine.schema().tables.keys()` (`serve_changes.rs` 80).
- `sql` builds a view (`sql.rs` 44–72); `data <name>` dumps totals (`verbs.rs` 484); `why <name>` prints rules (`verbs.rs` 702).
- `classify` reports “table … is added” (`successor.rs` 129–132).
- Native `get`/`scan` as system bypasses rules (`native.rs` 585–658; `read.rs` 245–247).
- Hand-serialized IR `Get` of that name is a read, not `refuse_engine_owned`.

Round 2 Grok 7 is not dissolved: the totals for absent and expired parents are a schema table with a reachable name. §3.7 (device skips a maintain it received) contradicts §8 (no enumeration a principal can reach), because `GET /schema` *is* the device `Backend` (`device.rs` 28–34, 858–861).

**Smallest fix.** One predicate, `visible` / not-private, used at every listing above. `GET /schema` and the device `Backend` omit private tables **and** private `Maintain` entries (device skip is then absence: `Runner::maintain` has nothing to run). Server `Schema.tables` keeps the target for `rebuild_maintain`. Core refuses `Get`/`Scan`/write of a private target for programs, native, IR, seeds — only the engine’s `tx.get`/`put`/`delete` for birth, mirror, rebuild. `sql`/`data`/`why` treat the name as unknown even when supplied. Adoption diagnostics attribute the private table to the column, not a new authored table.

### High — The new reservation must not inherit `reserve_maintains`’ early returns

**Design:** §3.2 (one reservation, before parent lookup, two mirror attempts, prepaid, origin-keyed partition charges). **Code:** `write_target.rs` 287–309, 25–37; `write.rs` 30–74, 77–119; `partition.rs` 152–153.

**Scenario.** Clique: `likes` is public, no filter, no computed key, source does not expire. Today:

```
if table.rules.read.is_uniformly_readable() || self.context.is_system() { return Ok(()); }
if !maintains.iter().any(|m| m.filter.is_some() || !m.computed.is_empty() || table.expire.is_some()) { return Ok(()); }
```

Both return before charging. `insert_mode` never calls it. Mirror `put` of `posts` then charges `Steps` through `meter.charge` because `maintain_for("posts")` is `None` (`partition.rs` 152–153). At a just-insufficient step budget: live parent → `E_BOUND`; absent parent → `sent`. That is round 1’s reservation finding, back, on the default app.

**Smallest fix.** Name a new always-on reserve (not `reserve_maintains`) that runs for every source write that feeds a maintained column, including public sources, system, and `insert_mode` / no-op `insert … if absent`. Same attempt lifetime as `target_attempt` (`write_target.rs` 12–22): set prepaid, restore on every exit. `insert_upsert` must not reserve again. Partition charging keys off `Origin::Maintained`, not `maintain_for`. Prepaid must not suppress a *declared* `maintain likeCounts` on the same source unless that work is inside the reserved ceiling.

### Medium — Birth must fill the field before `validate_row`

**Design:** §3.2 birth. **Code:** `write.rs` 30–43; `validate.rs` 20–22, 44–48.

**Scenario.** `likeCount` is required and has no authored default. `insert posts { authorId, body, at }` hits `validate_row` before any put (`write.rs` 38) and fails “likeCount is required”. Native `typed_row` + `insert` is the same path (`native.rs` 668–670).

**Smallest fix.** After submitted-field refusal and defaults, before validate: `tx.get` the private total (always charged), set the field, then validate. Engine-filled, not a submission.

### Medium — Mirror must re-read the current parent image (zeroing and two columns)

**Design:** §3.2 “when the private total changes”; §3.11 “preserving … other maintained columns”; §8 oracle (deletes, several columns). **Code:** `maintains.rs` 175–181 (delete-to-zero returns without a put), 183–191 (put).

**Scenario.** Last like deleted: `apply_aggregate` deletes the private row and returns (`maintains.rs` 175–181). If the mirror is hooked only on the put, a live parent keeps a stale nonzero. Two columns on one parent, one commit: a mirror that writes a stale whole image clobbers the other column.

**Smallest fix.** After every `apply_aggregate` return that changed the total — put *or* delete-to-zero — `tx.get` the parent, set that one field, `put`. Acceptance: last like on a live post stores 0; two columns in one commit both match the oracle.

### Medium — Activation’s first walk will refuse the new required column unless the special-case 0 is in `materialize_optional_fields` *and* `validate_row`

**Design:** §3.11. **Code:** `activation.rs` 104–109, 122–125; `schema.rs` 1273–1286; `successor.rs` 80–95, 190–191.

**Scenario.** Adding `likeCount` with no literal default: first activation walk `validate_row`s the parent (`maintain_for(parent)` is `None`, `activation.rs` 109). Missing required field fails. `assess` also validates Additive column steps (`store/successor.rs` 47, 69–72). The named `Additive` exception in `classify` is not enough by itself.

**Smallest fix.** As §3.11 already says: special-case in `materialize_optional_fields`, old-image validation, and index builds — not `ColumnDefault::Literal`. Keep `keeps_literal_default_images` false (already false when `maintains` differ, `successor.rs` 191; also false for a required non-literal add, 195–196). Trigger rebuild on parent `expire at` change in `engine/mod.rs` 432–436 (today it only watches the *source* expire). Always record the activation commit naming the parent (`engine/mod.rs` 447–449 currently skips `written == 0`).

### Medium — Stripped write result must stay an id-bearing write key

**Design:** §3.2, §8 Write results. **Code:** `bind/program.rs` 722, 752, 780–787, 678–685.

**Scenario.** Result type of insert becomes “row minus maintained columns”. `return insert posts {..}` is fine. `update (insert posts {..}) { body: … }` today requires `Ty::Row(table)` (`program.rs` 780–787). A bare `Ty::Object` breaks it. Keeping `Ty::Row` and only stripping at runtime lets `insert posts {..} { likeCount }` type-check (`shape_object` 655–657, `row_fields` 680–684) and re-opens round 2’s disclosure as a missing/zero field.

**Smallest fix.** A table-branded result type whose fields are the row minus maintained columns (id remains). Shapes and `api.ts` use that. Write-key matching accepts it. Engine strips update/upsert `get` (`write_target.rs` 165) and native insert/upsert JSON (`native.rs` 669–699). Binder omits the column from the insert object so it does not fabricate 0 (`program.rs` 859–876).

### Low — Overflow and notes must name the parent column, never the generated target

**Design:** §3.2 named exception; §3.8. **Code:** `maintains.rs` 202–205 (`maintain.target`, `"value"`); `residency.rs` 287–296 (`N_MAINTAIN_DELTA` sites `tables.{target}`).

**Scenario.** Overflow prints `$posts.likeCount` / `value`. Private maintain has `read = deny`, so `N_MAINTAIN_DELTA` is already skipped (`residency.rs` 289) — good. The new parent-reader note must not use the private name.

**Smallest fix.** Overflow uses the owning `(table, column)`. Assert error text in the paired overflow tests.

### Low — Doctor storage line

**Design:** Q3 list. **Code:** `verbs.rs` 619 (aggregate bytes/row counts, no table names).

Private rows inflate `row_count` only. No name leak. Optionally footnote that private totals are included; not required for READY.
