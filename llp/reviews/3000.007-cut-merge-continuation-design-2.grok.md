## Findings

### High — expired source rows are unnameable; walk can stall without `lossy`

**Where.** O2 witness rule; O3.3; O4 degenerate unit and `M`. Code: `read.rs:585–588` (expired rows never become a source unit), `read.rs:828` (lane source is a normal scan), `rows.rs:103–110`.

**Scenario.** `members` expire; 9,000 unswept expired memberships sit in `byPrincipalRoom` before the next live chat; examined ceiling 8,192. From `start = B` or `S(k_prev)`, opening spends the meter on expired source keys, never completes a live unit, and has no witnessed `S(k)`/`W`/`F` to name. Degenerate wants `next = ([], S(k) or F(i), OPEN)` with `lossy`, but there is no live `k`. Reusing `start` returns the same token (`M` unchanged). `Pages` then sees `last.next === page.cursor` and sets `hasMore` false (`react.tsx:95–96, 138`). Later live chats are never returned; `lossy` need not be set. Two stores that differ only in *hidden* rows still match (uniform source). Two stores that differ in unswept expired memberships diverge — that is O7.2 sweep lag — but one of them does not terminate.

**Smallest fix.** Add a source-scan progress position `P(suffix)`: exclusive bound after the last *examined* source key, live or expired. It is not a witness for `W`/`S`, is not in the digest, and is classified as sweep lag (O7.2). Degenerate/unfinished source scan emits `next = ([], P(suffix), OPEN)` with `lossy` if the unit produced no live row; `P` is strictly after the previous source bound so `M` increases. Refuse `P` that is not this merge’s source suffix types.

### High — `M` is not increased by every allowed transition (including forged/replayed tokens)

**Where.** O4 termination; O6 refusals. Code: `cursor.rs:93–98` (v3 not yet a version); `meter.rs:166–174` (steps abort, examined caps).

**Scenario.** Forged or engine-produced token `{start: S(k), end: OPEN, values: [], restarts: 0, lossy: false}` on the expired-run store. Request re-opens, fails the first unit, returns the same bytes. `lossy` is not a coordinate of `M`. `end ≤ start` does not fire (`OPEN` sorts above `S(k)`). Client following `next` loops until the SDK coincidence-stop above; a raw walker loops forever at one request’s meter each time.

**Smallest fix.** Require a successful request to return either no token or a token with `M` strictly greater than the input, and put `lossy` in the order (e.g. after `restarts`: once set, `start` must advance or the walk ends). Treat “would return the input token” as “return none, `lossy`”. Add O8.6 cases for expired-source `P` and for forged `{start, OPEN, []}`.

### Medium — D2.4 as written can be applied to every page and would break §5.6

**Where.** D2.4 (`REVIEW-DESIGN.md:82–96`). Code: `read.rs:662–668` (direct non-uniform *does* continue); `read.rs:687–695`; `mod.rs:717–726`; postgres twin `postgres/mod.rs:143–152`.

**Scenario.** Query returns a non-uniform filtered page (`notes after c first 5 by byBody where …`). Today `continues` is true when `last_rule_visible` exists, including `non_uniform` (`read.rs:666`). If outcome-build `eligible = !non_uniform` is applied to `self.page` regardless of owner, `next` disappears and §5.6 is gone. The mixed merge-then-non-uniform case is the one that *should* drop merge `next`.

**Smallest fix.** State D2.4 as: at outcome, if the page owner is a merge site, replace `page.next` with `None` unless the whole answer is uniform (server: `!non_uniform`; device: as today) and `word_cut_at` is none and the merge predicate (uncut `has_more` or `opened_all ∧ drain_cut ∧ emitted ≥ 1`) holds. Direct pages keep the `scan_prepared` contract. Same branch in `Engine::query`, `local::query`, and the postgres query path.

### Medium — D5.8 must not reuse today’s `E_CURSOR_INDEX` predicate

**Where.** D5.8; §0.1. Code: `bind/program.rs:274–277` (cursor page: ends in `id` **or unique**); merge lanes set `cursor: None` then attach the shared token (`bind/program.rs:547–551`), so merges never hit that check; `rules.rs:90–95` admits the same unique-or-id shape for lazy merge.

**Scenario.** Ticket `unique byRoomAt: roomId, at`, two lanes, `last 1`: walk returns 3 of 4, every page `complete: true` (`REVIEW-TICKETS.md:38–45`). If D5.8 is implemented as the existing unique-or-id rule, that merge still compiles, D’s uniqueness proof is false, and drain-cut continuation skips the same row.

**Smallest fix.** New merge-only check: a cursor-bearing merge’s index **suffix after the lane prefix** contains `id` (mechanical rewrite appends `id`). Direct unique-without-`id` pages stay legal. Land with D, not later.

### Medium — D5.3 / D5.6 tests can pass with D disabled or mis-state device `cut`

**Where.** D5.3, D5.6 (`REVIEW-DESIGN.md:149, 153`). Code: `read.rs:796–801` (opening cut already has no `next`); `runner.rs:111–115` (device still discloses `cut` when `non_uniform`).

**Scenario.** “Opening cut → no `next`” is true on 0.2.27. D5.6 “`cut` is null whenever the answer is the non-uniform class” is false on a device (`O7.4` already corrected this for hosts).

**Smallest fix.** Split D5.3: lookahead *drain* cut asserts `next` present (fails without D); opening cut is a paired negative. D5.6: server `cut: null` and no `next`; device keeps precise `cut` and still withholds merge `next` if `non_uniform` is set.

### Medium — zero-width shrink is refused, but the replacement transition is not defined

**Where.** O4 shrink; O8.5. Code: would encode `end ≤ start` (`REVIEW-DESIGN.md:350`).

**Scenario.** Continuation of `(S(k1), S(k10)]` no longer fits; last witnessed position that fits is `S(k1) = start`. Shrink is refused. Without the degenerate/`P` path, the request has no legal `next`.

**Smallest fix.** “A shrink with `end′ ≤ start` is the unfinished-first-unit path” (advance via `P`/`S`/`F` and set `lossy`), never a `Descriptor`/`Values` error to an honest client.

### Medium — digest is unspecified and 64-bit

**Where.** O4, O6 (`REVIEW-DESIGN.md:259–264, 336–340`).

**Scenario.** Server and wasm/native devices must recompute the same digest. A randomized or host-endian hash makes every continuation `digest-differ` → restart → `lossy`. A 64-bit collision on live source keys skips a restart and can miss a newly joined chat’s history without `lossy`.

**Smallest fix.** Specify a deterministic 128-bit hash (e.g. BLAKE2b-128 or SHA-256 truncated, canonical encoding of ordered live source keys plus fixed-lane count). Same bytes on every host.

### Low — v1 tokens on an O-eligible merge that no longer fits one read

**Where.** O5 “one window = today’s v1”; O6 v1 unchanged. Code: `decode_cursor_for` returns only suffix values (`cursor.rs:107–124`); `merge_lazy` opens every lane (`read.rs:827–849`).

**Scenario.** Client stored a v1 `next` from a merge that used to fit. After data growth, v1 still decodes; engine opens all of `L`, opening-cuts, D withholds `next`. The v3 path would have windowed.

**Smallest fix.** Treat v1 on an O-eligible merge as `(values, start=B, end=E)` and run the shrink/window machinery; do not silently fall back to a dead opening cut.

### Low — S2 will not fill an empty window-advance page when D4 has nulled `cut`

**Where.** S2 (`REVIEW-DESIGN.md:441–446`); D4. Code: fill is “newest held page is cut”.

**Scenario.** Device, horizon + window-open empty page: `cut: null`, `next` present, 0 rows. Fill does not run. User sees an empty list until `loadMore`.

**Smallest fix.** Fill when the newest page has `next` and this episode produced no new *row*, even if `cut` is null, still capped at 8 and not live-rearmed — or document that mixed empty pages need `loadMore`.

### Low — §A treats Grok F5 as closed; expired *words* are, expired *source rows* are not

**Where.** §A row “GPT 3 / Grok F5” (`REVIEW-DESIGN.md:500`).

**Smallest fix.** Re-open that row for source-scan progress (`P` above); keep the word-boundary witness rule as written.
