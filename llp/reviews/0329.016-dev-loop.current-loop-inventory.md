## 1. The paved loop, step by step

Scope: "empty directory → running app with auth + one live query + one mutation →
deployed". The canonical starter is `snapback new my-app --template react`
(`guide/start/react.md`, `guide/getting-started/the-authoring-loop.md`). The
Familiar variant (`familiar-react`) differs only in steps 4–5 and 10 (see §4).

Legend for "Generated artifacts / custody": **agent** = the agent authors and
commits it; **codegen** = written by `snapback generate`, never hand-edited;
**dev-loop** = written by `snapback dev`, gitignored; **committed-projection** =
codegen-written but committed by policy.

| | |
|---|---|

| Can go wrong (`your-first-backend.md`) | Declaring `_id/_version/_createdAt/_updatedAt` → `SNAPBACK_SCHEMA_SYSTEM_FIELD`; `_id` in an index → `SCHEMA_UNKNOWN_FIELD` (implicit trailing `_id` is added for you); enums must be 2–7 literals ≤ 64 bytes (`v.union` of one literal refused; narrowing a populated domain → `SNAPBACK_SCHEMA_ENUM_DOMAIN_BACKFILL_REQUIRED`); `v.object`/`v.array` at field position compile to an *opaque* structured value (32 KiB/value, 48 KiB/row, depth 16, 1,024 items; interiors not queryable/indexable; `v.id()` inside → `SCHEMA_STRUCTURED_ID_INTERIOR_UNSUPPORTED`); nested `v.principal()` is a snapshot, not membership; no default columns, no IDENTITY/SERIAL (GAP); base64 media in a string field is refused at seed time (`SNAPBACK_SEED_DECLARATION_INVALID`) and discouraged everywhere ("Storing media is an asset workflow, not a string-field shortcut"); no composite index containing `_version`/timestamps. |

### Step 5 — Author functions (the live query and the mutation)

| | |
|---|---|
| File | `snapback/functions.mjs` |
| Must know | **Two authoring styles "freely mixed"** plus a legacy third: (1) declarative plans — `defineQuery`, `defineLiveQuery`, `defineMutation` built from an expression algebra (`arg`, `lit`, `eq`, `asc`, `insert`, `patch`, `del`, `returnBinding`, `returnChangedCount`, …; `define.mjs` exports 140 symbols in total, 31 of them `define*`); (2) inline JS — `defineJsQuery`, `defineJsLiveQuery`, `defineJsMutation`, `defineAction` with one self-contained `handler:` plus `args`, `result: results.{documents,records,document,value}`, declared `reads`/`writes`; (3) legacy bundled `handlers.mjs` (`source`/`exportName`, "fully supported — `demos/todo` still uses it — but … the compatibility lane"). In sessions mode every function declares `auth: 'public' \| 'optional-user' \| 'authenticated'` (`auth/sessions-and-principals.md` "Choose each function's auth requirement"). Server-side scoping is `filter: [eq('userId', authUserId())]` (+ `authScopeField: 'userId'` in the todo-contract template), never a client-supplied owner. Inside a handler: `ctx.db.query(t).withIndex(n).eq(f,v).in(f,[..]).order(f,dir).collect()`, `ctx.db.get/insert/patch/delete`, `ctx.auth.userId`. |
| Can go wrong | Omitting `auth` → legacy `optional-user` + `SNAPBACK_AUTH_REQUIREMENT_IMPLICIT` warning; inline-handler subset refusals at generation (dynamic computed member access, any capture of imports/outer consts/sibling helpers, class/`this`/dynamic `import`/`eval`/`Function`, non-builder query verbs, empty `writes: []` on `defineJsMutation`); `elevatedReads:` metadata refused on inline forms; `FUNCTION_RESERVED_EXPORT`, `QUERY_UNKNOWN_FIELD`; mixing `handler` and `source/exportName` → `SNAPBACK_FUNCTION_HANDLER_FORM_INVALID`; any import in the bundled lane → `BUNDLE_UNSUPPORTED_IMPORT`; omitting `result` is "an explicit degraded `unknown` contract"; > 4,096 nodes in `app.api.queries` → generate warns, Expo boot may refuse with `SNAPBACK_REACT_ARGS_INVALID` (`start/expo-chat.md` trap 3). |
| Artifacts | agent-owned source |

### Step 11 — Make the data private (auth actually gating data)

The `react` template deliberately ships a **public** board so the provider reaches
anonymous `ready` before entry. To scope rows per user the agent changes three
places at once: schema `.visibility({ kind: 'owner', field: 'userId' })` +
`.index('by_user', ['userId'])`; live query `filter: [eq('userId', authUserId())]`,
`index: 'by_user'`, `authScopeField: 'userId'`, `auth: 'authenticated'`; mutation
`userId: authUserId()` in the plan. (`templates/todo-contract/snapback/*.mjs` is the
worked example.) The host "stamps the effective principal and refuses
application-authored owner input" for owner-scoped tables.

Can go wrong: switching `dev → sessions` on an existing database stages a new
deployment and "closes app data until the required process restart"; provisioning
is admin-token gated (`ensureApp({ intent: 'provision', requestedMode: 'sessions', … })`).
Guest entry, email-code sign-in, Apple/Google (first-party social providers is a
**design-only GAP** row), scoped roles, and agent principals are each their own
page. `auth/passwords.md` is `maturity: partial`.

### Step 15 — Deploy

**There is no paved step.** `guide/deploying/index.md` (`maturity: partial`):
"Snapback does not currently offer an end-to-end path that deploys an arbitrary
user application to any hosted target." `snapback deploy build` produces a release
with `activationEligible: false` and blocking `gaps`; Fly `deploy plan` output
"remains blocked"; Cloudflare `targets/cloudflare/deploy.sh` deploys only the two
checked-in proof apps (`notes | all-aboard`); all 17 `snapback hosted lifecycle`
verbs return `SNAPBACK_HOSTED_LIFECYCLE_CARRIER_INCOMPLETE`. Instruction to the
agent: "stop and report the relevant open ticket instead of assembling a private
path around the gates."

## 5. Cognitive-load assessment

### What an agent must hold in context to succeed on the first try (react template)

1. **Seven agent-owned files across four dialects**: two DSLs (schema/table
   builder + plan/expression algebra), JSON seed, React/TSX consumer, and the
   acceptance-journey DSL (`defineStarterAcceptance` paths + `step/until/defer`)
   plus the verify-config DSL (context `kind`/`identity` triples). The mental model
   says "You write three files"; the packet lists seven edit targets.
2. **Authority declared in three places that must agree**: table
   `.visibility({kind, field})`, function `auth:`, and the query `filter`
   `eq(field, authUserId())` + `authScopeField` — with a fourth (`authorization-review.json`
   diff) recommended before activation.
3. **Two-and-a-half function styles** and when to pick each (plan vocabulary
   vs inline handler subset vs legacy bundled), plus the inline subset's refusal
   list (no captures, no computed member access, no classes, declared `writes`).
4. **Codegen custody model**: three custody classes, an input-hash cache, the
   "commit `artifacts.json` only" rule, `.gitignore` negations,
   `codegen.policy.json` `committedProjections`, and that Vite rewrites
   `generated/` imports while Node must call `resolveGeneratedArtifact`.
5. **Dev-loop lifecycle**: attach vs managed ownership, the ready-file
   descriptor, SIGTERM/EOF semantics that differ from MCP servers, `snapback stop
   --ready-file`, the `4287-4387` range, stale env-var refusals, `CI=1` inertness,
   `.env.local` managed block.
6. **Sessions-mode state machine**: dev→sessions provisioning + restart,
   `SNAPBACK_AUTH_STARTUP_ARTIFACT_MISMATCH` if you stop/regenerate/restart,
   seed identity vs data (`SNAPBACK_SEED_MIGRATION_REQUIRED`), additive vs
   destructive schema changes (`snapback migrate` five-step loop), and the
   `reset --dev-fresh` escape hatch with its own path refusals.
7. **Client hook discipline**: identity-stable args/entries maps, query
   status states, auth-transition timing ("not in the same tick"), refuse-UI
   placement, subscription budgets, IndexedDB+Web Locks requirement.
8. **Storage bounds that are not in the type system**: enum 2–7 literals;
   32 KiB/48 KiB/depth-16/1,024-item structured limits; opaque interiors; 4,096-node
   API ceiling; 1,024-effect seed ceiling; no defaults, no identity columns.
9. **The done-oracle**: `prove` ≠ `test` ≠ `test:static` ≠ `carry:*`;
   `passed-without-acceptance` is green-but-hollow; every new function needs a
   registered path with `targetProfileId: 'local-dev-sqlite-ibex'`.
10. **The escalation protocol itself** (LLP 0259): what counts as a page, what
    counts as a budgeted lookup, the three triggers, and that the 126-row
    capability index and the 227-row surface map are "lookup, not first read".
11. **Diagnostics as documentation**: 3,597 codes, of which the golden-path
    pages name 55 and the packets 8; only 13% have a guide anchor, so
    `snapback guide <CODE>` is the intended lookup — and "match on
    `error.diagnostic.code`, never on message text."

### Bottom line

The paved Snapback 1 loop is coherent and heavily fenced: **scaffold → install →
read packet → edit 3 backend files + 1 consumer + 2 proof files → `generate` →
`dev` (×2 terminals) → `prove` → commit `artifacts.json`**, with deployment
explicitly absent. Its cost is breadth: an agent must reconcile ~10 named rule
systems (visibility/auth/scope; plan vs handler; custody; lifecycle ownership;
seed identity; sessions restart; hook identity; storage bounds; verify DSL;
escalation budget) whose interactions surface as `SNAPBACK_*` refusals rather than
as a single model. The guide compensates with a 399-word mental model, per-template
packets under 700 words, an exact-lookup channel, and a 3,597-code registry — and
is candid that 23 capabilities are GAPs, 39 pages are partial, one of two
profiles is experimental, and hosting does not exist yet.
