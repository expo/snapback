## New defects introduced by round 3

### N1 — High: non-uniform scans now distinguish hidden and absent worlds

The changed probe implementation also runs inside non-uniform scans. Its new error escapes the scan’s existing local cut handling and unwinds the entire query. The new preflight protects only point reads. [read.rs:47](snapback4/crates/snapback4-core/src/engine/read.rs:47), [read.rs:604](snapback4/crates/snapback4-core/src/engine/read.rs:604)

Concrete scenario: scan `records[] first 1`, whose rule probes `permits[owner = .owner]`; no permits exist, and the rule-probe ceiling is zero.

- **Hidden world:** one protected record reaches the failed probe; the query returns `data: null`.
- **Absent world:** no candidate reaches the probe; the query returns `data: []`.

Both are incomplete. Before round 3, both returned `[]`. Internal scan meters already differed; the **new disclosure is wire-visible result shape**. A subsequent unconditional refusal would likewise be skipped only in the hidden world.

**Coverage missing:** the new fixture scans public `items` and performs protected point lookups; it does not scan a table with a non-uniform probing read rule. [rule_probe_cut.rs:7](snapback4/crates/snapback4-sim/tests/common/rule_probe_cut.rs:7)

### N2 — Medium: a schema-adoption race can permanently reject valid wire arguments

Ordinary requests decode against a cloned `shared.bound` program, then separately lock the engine to execute. Adoption can occur between those steps. [serve.rs:851](snapback4/crates/snapback4/src/serve.rs:851), [serve.rs:929](snapback4/crates/snapback4/src/serve.rs:929)

For example, change an argument from text to a table-reference type. The same JSON string is valid under both definitions, but the old decoder produces `Value::String`; the new definition requires `Value::Id`. That artificial `E_INPUT` now becomes a permanent receipt. Previously, an exposed same-ID retry decoded under the new definition and could succeed. [wire.rs:51](snapback4/crates/snapback4-core/src/wire.rs:51), [mod.rs:736](snapback4/crates/snapback4-core/src/engine/mod.rs:736)

Batch decoding already holds the engine lock throughout. Ordinary decoding needs equivalent consistency or a generation-change retry. **Coverage missing:** the new schema tests restart between requests, rather than adopting between decoding and execution.

Authentication failures remain outside receipt creation; retryable store/transport failures remain unrecorded. Execution-time authorization refusals were already recorded before this round. The new problem is permanent rejection caused by mixed schema generations, not double application.

### N3 — Medium: a throwing settlement listener causes duplicate notifications

`emitWrite` invokes listeners without exception isolation. It now runs **before** exposure removal. If one listener observes `sent` and a later listener throws, cleanup is skipped; the flush catch schedules replay, which emits the same settlement again. A consistently throwing listener also holds successors indefinitely. [local.ts:172](snapback4/packages/snapback4/src/local.ts:172), [local.ts:960](snapback4/packages/snapback4/src/local.ts:960)

Previously, exposure was removed before notification, so this exception could not trigger that replay loop. Listener failures must not retain an already-notified terminal write. **Coverage missing:** the new once-only assertions use nonthrowing listeners.
