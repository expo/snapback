### 1. Sign or dissent

**1. DISSENT.** Replacement: One language, two data-plane kinds (`query`, `mutation`) and two kinds outside it: `effect` (I/O; writes tables only by calling named mutations; not live, not retained) and `channel` (ephemeral presence; not persisted, not in the certificate, not retained). TypeScript syntax, type-checked against a custom `lib.d.ts` (no `Date`, `Math.random`, `fetch`, `while`, recursion, dynamic table access). Result types inferred by `tsc`. Modeled inputs: `ctx.viewer`; mutation-only `ctx.now()` / `ctx.newId()` bound at intent time; query-only bucketed `ctx.readTime` when the op declares a refresh. Ambient clocks stay refused.

**2. SIGN.**

**3. SIGN.** Helpers inlined at `check`; an un-inlined helper is an opaque UDF and a refusal.

**4. SIGN.**

**5. SIGN.** Add `readTime?: { granularityMs }` when declared. Cardinality is not a cost proof.

**6. DISSENT.** Replacement: Dynamic trace per execution — ranges with stop-reason (`limit`/`exhausted`) including absences; examined viewer-visible rows including compiler-selected halo **content of row N+1 and the key of N+2**; verdicts only for rules over hidden inputs, bound to `(ruleHash, pinned inputs, principal, authEpoch)` (planHash lives on the receipt, not the fact); asserted `⊆` certificate. The trace is the invalidation predicate, the offline closure, the OCC set, and the completeness detector.

**7. SIGN.**

**8. SIGN.** Evaluator *language* is D-A, not this point.

**9. SIGN.** JS stays out of the authoritative query/mutation path. Effects keep a sandbox off the transaction (DK-5 shrinks to this).

**10. SIGN.**

**D-A Client evaluator.** **One IR, two embeddings, Expo Go is the gate.** Server is the Rust interpreter (point 9). Client is the **same bytes compiled to WASM** if they run in Expo Go / default RN without a custom native module. Hermes WASM in RN 0.84 is unverified in this pack **[inferred]**. If that gate fails — or if wasm32 misses size/startup (LLP 0129 measured 117,353 gzip WASM vs 7,615 JS **[codex r2 citing 0129]**) — v1 ships a **generated TypeScript evaluator**, not app JS, behind a frozen cross-engine corpus as a merge gate. Fable’s hydration replay (re-execute over the shipped closure, compare to the shipped result) is mandatory either way; trace `⊈` certificate is a compiler bug. A native RN module is Clique F-B and is **not** a v1 requirement. QuickJS-in-WASM is prototype-only. I recant r2’s “TS client rejected”: the identity is the IR and the value model, not the embedding.

**D-B Computed-key reads.** **Admit, mark `computed`, `partial` under prediction.** Algebra-purist refusal throws away the Convex prior. A written `mentions` (or similar) row is the *rewrite the diagnostic pastes* when the agent wants `predicted`, not a refusal of the site.

**D-C Verdict binding.** **Fable’s fact tuple, Codex’s reuse rule, Clique ships none.** Bind the fact to `(ruleHash, pinnedInputs, principal, authEpoch)` so `thread`’s membership fact serves `send` when the compiler proves identical obligation. `planHash` is on the receipt. A read fact is never write authorization without that proof (`muted-from-sending` is a different fact). **v1 specifies the object and the wire field; Clique traces contain zero verdicts** — membership is a row or an absence. First customer is `blocks`/`mutes`/admin. If Clique `check` emits a verdict, the schema hid a row the viewer should read.

**D-D `maxOfflineAge`.** **24 h engine default, 7 d hard maximum, never infinity, never per-query.** LLP 0053’s `AUTH_LEASE_DEFAULT_MS = 86_400_000` is today’s protected default **[repo fact via r2 record, not restated in the pack excerpt]**. Do not regress to unbounded “stale until reconnect.” Clique’s demo app should set 7 d. Stolen-device copies are unrecoverable at any TTL. Sign-out destroys the store key.

**D-E Halo.** **Content of N+1 plus the key of N+2.** One examined row only makes one local delete `hasMore: unknown` — a third completeness bit the UI will treat as `partial`. N+2 *content* is not v1. Invalidation fan-in is the same prefix (the next key was already the stop-reason). Trace cost: +1 row/page + 1 key. Not author-visible.

**5. M4 Edit 15 min / delete-for-everyone 1 h.** **Mutation.** Clock = `ctx.now()` bound at intent, carried in the envelope; server accepts inside a skew window and reuses it.

```ts
export const edit = mutation({ id: id(messages), body: text({ max: 2000 }) }, ({ db, ctx, args }) => {
  const m = db.get(messages, args.id);
  db.assert(m && m.authorId === ctx.viewer);
  db.assert(ctx.now() - m.at <= 15 * 60 * 1000);

export const deleteForEveryone = mutation({ id: id(messages) }, ({ db, ctx, args }) => {
  const m = db.get(messages, args.id);

**9. M6 Offline compose.** **Mutation** + runtime (outbox). Receipts are rows.

```ts
export const send = mutation(
  { cid: id(conversations), body: text({ max: 2000 }), clientId: id() },
  ({ db, ctx, args }) => {
    db.assert(db.exists(memberships.byConvUser, [args.cid, ctx.viewer]));

Recipient `delivered` is *their* mutation (device ack). `markRead` sets receipts to `read` and zeros maintained unread. Settlement re-runs the same IR; the client never authors a second predictor.

**14. M8 Multi-device offline.** Runtime contract, not a new op. Two devices, both offline, both `send`: each predicts against its own closure; `ctx.newId()`/`clientId` do not collide; neither sees the other’s rows until reconnect; server serializes both inserts; both commit if rules still pass; result is the union, ordered by intent `at` (skew-validated). Same-row `edit`: OCC on the traced version — one `committed`, one `rejected`. No CRDT, no merge of bodies. Revocation during the partition is unobservable on both; reconnect re-authorizes each outbox before replay and purges rows held by no range. Sign-out on one device destroys that store key only.

**15. Scale replay (O5).** Certificate of `thread`/`inbox`/`send` still holds (`take` is the bound; 100k rows do not raise examined entries). Rerun-and-diff hurts first on a **hot conversation with many subscribers**: each insert overlaps `messages.byConv[C]` and reruns every matching subscription (scan 50 + author nest). Second: **inbox without maintained unread** (N conversations × page scan per send). Mitigation, in order: (1) subscriptions indexed by range — only overlapping windows rerun; (2) coalesce identical `(planHash, args, principal)`; (3) `maintain` unread/counts so inbox is point-gets; (4) prepend-if-inside-desc-window as a later cheap path. IVM is year two. Do not subscribe 100k conversations; O5’s public API still goes through named ops with `take`.

### 3. The spike

One week, one program. Fail any box → do not rebuild on this design.

**Kernel (P9 + P4 + r1 grok)**

- [ ] IR ≤ ~30 node kinds + tracing `get`/`scan`/`exists`/`recurse`. Fail: a thirteenth special case for Relay/Split.
- [ ] Hand-lower `thread`, `send`, `startDM`, `boardView`, `boardSummary` as `maintain.count`, Split `ledger` as `maintain.sum`, `ancestors` recurse. Fail: cannot execute without a new query class.
- [ ] Rust interpreter inside a SQLite transaction; JS not on this path. Fail: handler in the write lane.

**Closure / prediction (r2 all three)**

- [ ] Ship trace + result to an in-process client over a range store at one version. Local `send` → `predicted`. Local delete of one held row with halo N+1 content + N+2 key → still complete, `hasMore` exact. Second delete → `partial`. Fail: invented completeness, or `partial` on the first delete.
- [ ] Delete membership → reconnect evicts rows held by no range. Fail: leak.
- [ ] `thread` with `users[author]` (shape) **and** `handles(body)` (computed). Offline `send` of a first `@bob`: author nest `predicted`, mention scan `partial` and so named in the certificate. Fail: `predicted` on the computed site, or a refusal of `if`/`for`.
- [ ] Helper wrapping `scan` still prints the bound at `check`. Fail: P9 is Convex.
- [ ] Hydration replay: re-execute over the shipped closure, byte-compare result. Fail: mismatch that is not a known corpus exemption.

**Substrate gate (D-A)**

- [ ] wasm32 of the same interpreter: size, cold start, on web V8 **and** RN Hermes/Expo Go. Pass WASM-in-Expo → WASM is v1 client. Fail Expo/Hermes/size (0129’s 117k vs 7.6k is the bar) → generated TS evaluator + corpus, **not** a native module.
- [ ] Frozen corpus (i53, UTF-8 codepoint order, no `NaN`/`-0`, Map insertion order, overflow refuse) through Rust native, WASM, and the TS twin. Fail: any divergence.

**Cost / product (r2 unread, AllOrRefuse, halo)**

- [ ] `send` into a 256-member conv with per-member `unread` maintain vs `countCapped(100)`. Record p95 write. Fail closed: unmeasured fan-out is not v1 exact unread.
- [ ] Grow a schema-uncapped `allOrRefuse(1000)` past N → `check` refuses. Schema-capped `All<T,N>` admits. Fail: seed-green, production-seal.
- [ ] Clique + Relay + Split rule sets: zero verdicts. Fail: Clique membership shipped as a boolean.

**Stop condition.** If step 4 of P9 (predicted send / partial delete / eviction) needs a per-query special case, the converged design is wrong.

### 4. What to keep from Snapback as built

Line counts and crate roles below are from the pack’s diagnosis at `main` `3e9320c0f` (16 Rust crates ~742k; 20 JS packages ~537k). Internals I did not open are **[inferred]**.

**Unchanged (carry the bytes or the exact contract)**

- SQLite single-writer transactions and the idle/server-authoritative settlement posture in `crates/snapback-engine` / `crates/snapback-server` — the rebuild is authoring+client, not storage.
- Durable ordered intent / outbox: LLP 0218, LLP 0133 — the envelope, not the JS predictor.
- LLP 0135 sequence allocation / client-minted ids reused at settlement (`ctx.newId`).
- One generation identity across schema, server, generated client, bundler, cache; `check`/`dev`/`verify` in `packages/snapback-cli` (0329.000 F-B).
- Clique / published-package benchmark loop (LLP 0129 record).
- Schema-as-source-of-truth; portable scalars; refuse `localeCompare` (0120 finding 7).
- Sign-out destroys the store key; reconnect re-authorizes before outbox replay (0053 minus leases-as-objects).

**Re-implemented as ideas**

- DK-9 (LLP 0008): client is not a replica → range-indexed store per `(table, index)` at one version + outbox.
- DK-5 (LLP 0009): capability-limited JS → **effects only**; query/mutation leave Hermes/Ibex.
- LLP 0155: Zero’s outcomes, Snapback’s authority boundary; Move 2 normalization stays gated.
- LLP 0157’s operators (`get`/`scan`/`nest`/`exists`/`maintain`/`recurse`) as IR, not a node-class product registry.
- LLP 0107 optimistic lifecycle → the eight states.
- LLP 0043 offline replay; LLP 0270 client defaults → fence + eight states, not eligibility flags.
- LLP 0120 census as the operator-coverage test (Relay/Split/Linear), not as 1,700-line profiles.
- LLP 0166 durable local bytes → the trace-backed store, not the completeness-proof machine.
- Deny-by-default row rules; `public(reason)` conspicuous (the P18 lesson).

**Deleted**

- `packages/snapback-codegen/define.mjs` (140 names, 31 `define*`, 13 query flavors) — capability-by-form.
- Authored `reads:` / `writes:` / `retainable` / `auth:` / `authorityIndependent` — derived or refused.
- `AuthorizedLease` as an author-facing object (keep a store-wide fence).
