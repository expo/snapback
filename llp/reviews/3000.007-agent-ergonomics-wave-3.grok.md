## Findings

### 1. High — `removedEvents` insert authority is “any viewer, any event id”

- **Where:** `snapback4/crates/snapback4-lang/src/guide/feeds.md:73–83` (README copy at `packages/snapback4/README.md:997` same table). Contrast paved helper `feeds.md:192–194`.
- **Scenario:** Copy the recipe, then add `mutation hide(eventId: posts): insert removedEvents { eventId, actorId: viewer }`. `insert <- .actorId = viewer` passes; `eventId: posts` only checks id shape (`guide/writes.rs:107–110`). Following immediately hides that event for every reader (`feeds.md:217–219`). Within a minute `purgeRemoved` runs as system and deletes every private `feed` copy of that `eventId` (`feeds.md:222–226`). Unique `byEvent` also blocks the real author’s `deletePost` tombstone insert. Private inbox rows stay unreadable to the attacker (the observation test still holds), but the **public hide + system purge** is the widening F3 was meant to avoid.
- **Smallest fix:** Tighten the table rule so the actor owns the source event and the row id is that event, e.g. require `exists posts[.eventId]` and `posts[.eventId].actorId = viewer` (and `.id = .eventId` if that remains the comment’s contract). Keep `removeEvent` as the only insert. Add a paired hidden/visible world test that a foreign tombstone insert is refused and does not change another reader’s inbox or Following.

### 2. Medium — W3a2’s real-document after-result is not in this commit

- **Where:** `snapback4/JOURNAL.md:15207–15211, 15294–15296`; witness still `snapback4/witness/navigation-immediate.mjs`.
- **Scenario:** The lead’s Chromium run at W3a HEAD applied **zero** writes on the two zero-delay unawaited cases (IndexedDB had not committed). W3a2’s Node model is green for those cases (`navigation-model.test.mjs:61–99`); the journal says the witness was **not** re-run in Chromium after the batch `/m` path.
- **Smallest fix:** Record the lead’s `node witness/navigation-immediate.mjs` before/after JSON for the two same-turn unawaited cases (application count, same-id requests, duplicates) against this implementation, or fold those two cases into a non-sandbox browser test the suite actually runs.

### 3. Low — language-card `following` does not hide removals

- **Where:** `snapback4/crates/snapback4-lang/src/guide.rs:219–220, 363–367`.
- **Scenario:** F2 is fixed (hybrid merge, 33 lanes, pointer to `guide feeds`). A builder who copies only the language example will still render tombstoned events until purge, because that schema has no `removedEvents` collector.
- **Smallest fix:** One comment on the language query: removal and null slots live on `snapback4 guide feeds`; do not treat this example as the full Following recipe.

### 4. Low — collapsed `N_NOT_PREDICTABLE` still lists IR sites

- **Where:** `snapback4/crates/snapback4-lang/src/bind/residency.rs:263–269` (after-text in `JOURNAL.md:14584–14588` still has `programs.createPost.0`, `programs.like.3`).
- **Scenario:** Root **causes** (which online-only table/maintain) are not dropped. Site lists can still show `programs.like.3` next to `schema.q:59:5`, so L1’s “internal path” noise is reduced, not gone.
- **Smallest fix:** Prefer source `file:line:col` in the grouped site list the same way presence diagnostics now do (`presence.rs:198–202`).

### 5. Low — LLP 3000.007 §20.4 is behind the shipped contract

- **Where:** `llp/3000.007-relaxed-quarry-and-explicit-residency.rfc.md:2419–2425` vs `guide/writes.rs:76–104`.
- **Scenario:** The spec still says the web tier “flushes pending sends on pagehide” with mutation-id dedupe. The README and writes card correctly distinguish durable oldest-head retry, ordered pre-admission best-effort, 64 KiB / 32-write caps, and loss if keepalive and admission both drop.
- **Smallest fix:** Extend §20.4 to the writes-card dispositions (including W2R1c ordered exit and W3a2 best-effort prefix) so the spec matches what builders are told.

## Test gaps (concrete)

- Rogue `insert removedEvents` for another actor’s `eventId` (finding 1).
- Chromium after-result for W3a2 same-turn unawaited 1- and 2-write cases (finding 2).
- Exit send while `ordinarySending` is a *different* id than the durable head (should stay suppressed; covered by the predicate, not by a named test).
- `N_NO_CURSOR` when `first N` equals a cap on a **different** prefix than the read’s pinned columns (logic looks right in `schema.rs:125–129`; no extra fixture).
- Negative `--clock-offset` vs device `now` on `expire at` reads (documented that client clocks do not move; not a product claim).

Paved `deletePost`/`unrepost`, private-inbox non-disclosure, both-store Following pages, clock release refusals, and online/local session card behavior look right.
