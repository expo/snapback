**High — The recommended increment cannot meet the commissioned acceptance criterion.**  
Location: [REVIEW-DESIGN.md:43](/Users/ccheever/projects/snapback-w13-review/repo/REVIEW-DESIGN.md:43), especially the exclusions at line 117.

The commissioning brief’s alternative 2 names words **so an application can narrow the prefix** ([brief:35](/Users/ccheever/projects/snapback-w13-review/repo/REVIEW-BRIEF-LANE.md:35)). This proposal gives those words exclusively to native operator outcomes, CLI output and dev stderr. An application cannot implement that interaction from its reply.

Concretely, the grader repeats the 45-word `kx*` search through the built app. It still receives 20 hits, `complete:false`, `cut:"words"` and no continuation—the recorded [calibration #13 defect](/Users/ccheever/projects/snapback-w13-review/repo/benchmarks/runs/2026-09-18-snapback4-clique-astra-0.2.29/README.md:48). There is neither a continuation reaching 45 nor a viewer-visible refusal naming words.

The builder **can** benefit when reproducing the query against dev and reading its terminal: [serve.rs:1055](/Users/ccheever/projects/snapback-w13-review/repo/snapback4/crates/snapback4/src/serve.rs:1055) actually invokes the logger there. `check` gains no corresponding repair; its existing cost report merely describes the bound ([verbs.rs:239](/Users/ccheever/projects/snapback-w13-review/repo/snapback4/crates/snapback4/src/verbs.rs:239)). A held device query does not reach that dev logger either.

**Smallest correct change:** make the user-visible mechanism the acceptance test, then choose an implementation that changes it. Keep operator advice as supplementary work. It has debugging value, but I would **not commission it alone as W14a**. The separate calibration #14 grouped-ordering defect remains separate, as the design correctly states ([#14:53](/Users/ccheever/projects/snapback-w13-review/repo/benchmarks/runs/2026-09-18-snapback4-clique-astra-0.2.30/README.md:53)).

**Medium — The disclosure comparison needs to distinguish raw words, witnessed words and hidden-dependent selection.**  
Location: [REVIEW-DESIGN.md:154](/Users/ccheever/projects/snapback-w13-review/repo/REVIEW-DESIGN.md:154) and [line 325](/Users/ccheever/projects/snapback-w13-review/repo/REVIEW-DESIGN.md:325).

The rejection of **unconditionally exposing the consumed 32 or omitted 33rd** is correct. Uniform authorization does not establish that an indexed row is unexpired. Nor does withholding the cursor undo hidden words displacing readable lanes in an admitted non-uniform scope. The design correctly acknowledges that existing limitation; [§18.6:2433](/Users/ccheever/projects/snapback-w13-review/repo/llp/3000.007-relaxed-quarry-and-explicit-residency.rfc.md:2433) explicitly retains population-dependent costs.

A readable witness removes the raw-token leak, but the proposed presence condition needs a stronger proof:

- **World A:** a uniformly authorized expiring table contains live words `kx00` through `kx44`.
- **World B:** identical readable rows, principal, time, sequence and request, plus an unswept expired row containing `kx315`.
- Both current searches admit `kx00`…`kx31`, return the same page, and report false/words/no-next. A’s 33rd word is `kx32`; B’s is `kx315`.
- “Expose the 33rd only if its fetched row passes expiry and authorization” emits `kx32` in A and nothing in B.

Thus the added field distinguishes worlds whose existing replies are identical. Saying that absence means “no witness available” does not remove the observable difference. Charging the witness can introduce further presence differences near a meter ceiling.

There **is** a safe weaker form: derive narrowing examples deterministically from text already returned to the viewer, without conditioning them on private ordinal information or remaining hidden-dependent budget. For example, an application can derive them from its returned results on every search. In the pair above, identical public data produces identical examples and presence. Those rows were already fetched, checked and charged. This is useful advice, but cannot honestly be labeled “the first omitted word” or a complete consumed-word list.

Also, discovery already fetches a row alongside its key and discards it: [read.rs:437](/Users/ccheever/projects/snapback-w13-review/repo/snapback4/crates/snapback4-core/src/engine/read.rs:437), [store.rs:413](/Users/ccheever/projects/snapback-w13-review/repo/snapback4/crates/snapback4-core/src/store.rs:413). Checking that particular witness need not add a store seek, although its examination, authorization and retained allocation must be accounted for.

**Smallest correct change:** add these paired cases and distinguish a safe result-derived suggestion from a hidden-dependent omitted-word diagnostic. Do not treat either a visibility check or explanatory absence wording as a complete non-interference proof.

**Medium — Alternative 3 is deferred without the small measurement needed to choose between the alternatives.**  
Location: [REVIEW-DESIGN.md:309](/Users/ccheever/projects/snapback-w13-review/repo/REVIEW-DESIGN.md:309).

The stated implementation concerns are substantially correct:

- `charge_lane` charges steps only for range/list sources. Generated word lanes have `source: None`; the descriptor heap charge at [read.rs:980](/Users/ccheever/projects/snapback-w13-review/repo/snapback4/crates/snapback4-core/src/engine/read.rs:980) also excludes the ordinary generated-word path.
- Accounting must cover retained word strings, owned `Scan` trees, copied scope/term/field values, evaluated prefixes and bounds, vector spare capacity, row buffers, heap heads and their keys, deduplication storage, and result construction. Merely charging `sizeof(MergeHead)` misses most ownership.
- Discovery itself currently materializes a row and key. Its transient storage must be included in the memory analysis; it is not an index-key-only API.
- Heap exhaustion raises `RuntimeError::Bound` even under a capped read ([meter.rs:185](/Users/ccheever/projects/snapback-w13-review/repo/snapback4/crates/snapback4-core/src/meter.rs:185)); it cannot be advertised as a resumable page.
- Uniform drains already support continuation after the last emission, including stopping after duplicate pops. No word frontier is needed when every head can be reopened under the row position ([read.rs:1016](/Users/ccheever/projects/snapback-w13-review/repo/snapback4/crates/snapback4-core/src/engine/read.rs:1016)). Opening failures remain terminal.

**There is no universal first failing ceiling.** Removing only 32 leaves descriptor/head allocation inadequately metered. Discovery charges one index entry per seek, including the final empty seek: an otherwise isolated scope with 16,384 words cannot finish discovery within 16,384 entries. At smaller populations, the examined ceiling can fail first during opening—roughly 8,192 one-row lanes, or 4,096 lanes with two examined candidates each, before other query costs. Proper heap accounting can fail earlier for wide descriptors, terms or rows. The design supplies no measurement deciding those cases.

For the isolated, uniformly readable **45-word, one-row-per-word fixture**, the source predicts 46 discovery charges and 45 examined rows to establish the first heads, excluding surrounding query work. That is a promising small case, not a measured result.

**Smallest correct change:** commission a bounded uniform-only prototype and measurement as the lane’s first milestone:

1. Walk the 45-word fixture completely in both directions, including ties and duplicate word membership.
2. Increase distinct words until the first ceiling, using narrow and wide rows/terms; record all counters, allocation capacity/peak, first-page and whole-walk latency.
3. Exercise opening failure, drain continuation, denied scopes and unchanged admitted non-uniform behavior on SQLite server, both device stores and wasm.
4. Measure the actual wasm delta against the pinned base and unchanged budget.

This is a bounded implementation lane with two-family review. Expanding non-uniform scopes or continuing across an opening failure would be a separate design. The existing final-answer non-uniform veto must remain ([read.rs:767](/Users/ccheever/projects/snapback-w13-review/repo/snapback4/crates/snapback4-core/src/engine/read.rs:767)).

The remaining cost and test qualifications do not independently block the operator implementation. Zero extra store calls and **O(1) incremental capture work** are sound; “one 256-byte token” bounds token content, not total allocation or encoded/logged copies. The log retains one enlarged message per existing key ([read_cost.rs:27](/Users/ccheever/projects/snapback-w13-review/repo/snapback4/crates/snapback4/src/read_cost.rs:27)). Zero web bytes is a credible **estimate** because the web build disables defaults and enables `web`, which does not enable `sqlite` ([build-wasm.sh:10](/Users/ccheever/projects/snapback-w13-review/repo/snapback4/scripts/build-wasm.sh:10), [device Cargo.toml:17](/Users/ccheever/projects/snapback-w13-review/repo/snapback4/crates/snapback4-device/Cargo.toml:17)). It still requires a build comparison. The recorded budget leaves 92 B of headroom; 433,908 B exceeds the brief’s 411,000 B by 22,908 B.

The proposed first-overflow, later-scope, precedence and reply-preservation tests are appropriate for the diagnostic. Existing controls cover [later scopes](/Users/ccheever/projects/snapback-w13-review/repo/snapback4/crates/snapback4-sim/tests/search_global/lazy.rs:88), [drain/opening cuts](/Users/ccheever/projects/snapback-w13-review/repo/snapback4/crates/snapback4-sim/tests/search_global/lazy.rs:110) and [both-cut precedence](/Users/ccheever/projects/snapback-w13-review/repo/snapback4/crates/snapback4-sim/tests/read_cut/disclosure.rs:44). New field/text assertions would fail against today’s interface; preservation assertions are controls, not new red behavior. No executed red/green evidence exists. The proposed additive native fields change neither serialized `Value` variants, cursor versions, ceilings nor corpus cases.

My recommendation to the lead is to **build alternative 3 for uniformly decided scopes**, beginning with the 45-word walk and allocation/ceiling/wasm measurement above. Preserve terminal opening failures, existing drain continuation and non-uniform disclosure rules; reclaim bytes if necessary without raising this lane’s budget. Retain alternative 2 as optional operator assistance, and use result-derived viewer suggestions only as narrowing examples. The acceptance artifact should be the grader-shaped app request reaching all 45 in order, because that directly repairs the measured failure.

Verdict: NOT READY
