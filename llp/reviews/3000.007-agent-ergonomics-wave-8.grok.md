## Findings

### 1. Medium — `snapback4 test` fails every held query

- **File:** `snapback4/crates/snapback4/src/verbs.rs:756-771`
- **Scenario:** Author copies the search card (`query searchHeld(…) held:` / language-card `heldRoom`). `snapback4 test` (or `test --residency` after loading a fixture) calls `engine.query` for every query. `E_QUERY_HELD` is family `residency`, not `rule`, so it increments `failures` and the command exits 1 for every persona.
- **Smallest fix:** If `schema.operations[name].held`, skip with `not run: {name} is held (device only)` — or run `engine::local::query` over the fixture snapshot, which is what the marker means.

### 2. Medium — adoption log is still unbounded after the first loud line

- **File:** `snapback4/crates/snapback4/src/serve_adoption.rs:52-57`
- **Scenario:** Same H8 shape: startup/watch adoption hits `E_STORE: database is locked` (or a CLI job wins the generation). First expiry sweep prints the new consequence line (`:54-55`). The next 80 expiry sweeps and 80 jobs still each print `snapback4: {name} failed: E_GENERATION: …`. Doctor is now correct (`tests/check.rs:495-515`); the file is not.
- **Smallest fix:** When `status.failure` is `Some`, do not `eprintln` per subsequent `E_STORE`/`E_GENERATION` background error (keep `repeated` as “already told you”). Optionally rate-limit any other repeating sweep error.

### 3. Low — doctor’s deferred count and `effect_counts()` are two snapshots

- **File:** `snapback4/crates/snapback4/src/verbs.rs:559-570`
- **Scenario:** A worker claims the deferred effect between `effect_counts()` and the `COUNT(*), MIN(next_at)` query. Doctor can print `1 queued` beside `0 deferred`, or the reverse, against a live host.
- **Smallest fix:** One `BEGIN`/`COMMIT` (or a single SQL statement) over counts + presence-qualified deferred min.

### 4. Low — `Engine::presence()` is a public getter with no caller

- **File:** `snapback4/crates/snapback4-core/src/engine/mod.rs:245-247`
- **Scenario:** `pub(crate) mod presence` is the right scope for the Postgres `Emission` name. The new `pub fn presence(&self)` is unused (`set_presence` is the in-tree API). It hands out `Arc<dyn Presence>` to any crate linking `snapback4-core`.
- **Smallest fix:** Drop it, or make it `pub(crate)`.
