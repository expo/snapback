## Weakest seam

The weakest seam is the conversion from an internally exact retained successor into client-applicable operations. It has no shared normative apply implementation: the server validates its retained state against fresh evaluation, while a corpus-only consumer independently interprets node patches. `ChangedRow.changed_fields` and heuristic application IDs bridge those two models without proving that serialized operations reproduce the internally attested bytes. That permits the server’s result, label, proof, and digest to all be internally correct while the client’s patched result is wrong—the precise failure mode this rung must exclude.
