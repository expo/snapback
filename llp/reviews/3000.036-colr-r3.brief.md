## 22. COLR: column read rules (0.4.35 proposal)

**Commission:** Charlie Cheever, wave-19 COLR workstream, 2026-10-19.
This replaces §21's open column-read decision. DORM owns reverse projections,
renames, dormant inspection and rollback narration; COLR changes no dormancy policy.

### 22.1 Surface and authority

An ordinary stored column may append `read <- P` to its declaration, after
its type and default. A group uses `read (notes, photo) <- P` as a table line.
Both use the existing row-read expression grammar, including readable unique
`exists` probes. Duplicate column rules and undeclared names refuse
`E_COLUMN_READ`. `id` is always row identity, never a protected column.
For example `notes: text <= 500 ? read <- .owner = viewer`.

Effective payload authority is the conjunction of the row read rule, the
column rule and any existing owner-private field gate. It cannot broaden a
row's audience. No column rule grants write authority. System maintenance
keeps its existing bypass. A missing or unreadable probe is unknown under
negation exactly as in row rules. Column rules may not depend on protected
values, including via target probe keys or residual equalities: this prevents
recursive policy and value-guessing oracles.

A denied cell is absent from whole rows and spreads, not a stored null.
Explicit field selection returns null through the existing optional-field
instruction. The Quarry type is optional and the generated TypeScript property
is optional for every audience (including formerly required protected fields).
An allowed optional null remains present as null in a whole row. Hidden and
null need not be distinguished in explicit scalar expressions. Existing hooks,
including `useQueryData`, require no extra call or policy branching.

### 22.2 Observations, planning and derivations

Projection occurs before any value reaches the program environment, response
pricing, serialization or mutation return. Expressions, transient views,
computed shapes and scalar computations therefore operate on the disclosed
image. Row existence and a count independent of a protected value retain the
row audience. A predicate over the disclosed optional value sees null when
hidden; its result cannot depend on the stored hidden value.

A protected column cannot supply an index, cursor/order/search key, unique
constraint, row lifetime, sync scope, recorded attribution or a row-rule input.
Such structural uses refuse `E_COLUMN_READ`, with a repair naming an ordinary
public key or a separate data entity. This includes inferred indexes and raw
schema admission, not only authored indexes. Sorting/grouping an in-memory
already-projected list is safe and follows ordinary optional-value semantics.
Program `exists` with a protected residual equality is refused rather than
using a raw storage predicate. Rule probes may not inspect protected keys or
residuals. Mutation transition rules may not inspect protected values to test
an unauthorized guess. Ordinary writes of supplied values are still allowed
under the row's write authority; read protection is not immutability.

Maintained views/counts/sums and maintained columns cannot consume a protected
input in their filter, group, sum or computed keys. A plain row count remains
legal. This conservative, explicit refusal prevents independent aggregate
audiences declassifying a field. Derivation over protected inputs requires a
query over disclosed rows; independent aggregate declassification is outside
this change. An ordinary maintained output column can itself carry a read
rule; derived maintenance remains system work, with projection at disclosure.

`read through` and `read through live` inherit row authority, not payload
permissions. A child's own ordinary column may have its own column rule.
Protecting a parent authority/capture field refuses as a structural use. A
column policy change is absent from capture identity and does not trigger
`E_READ_THROUGH_ADOPT`: existing children continue to inherit the same row rule.

### 22.3 Sync, device envelopes and live updates

Device schema declares a mandatory `column-read-v1` semantic capability;
older devices refuse it before executing any plan. New schemas without column
rules retain their prior byte representation and capability set.

Rules containing only row fields, viewer, literals and Boolean/equality
operators are row-local. The same projection is applied to every snapshot and
log put for its recipient. A shared log image contains no protected cells;
serve-time delivery re-fetches and projects the current row for its viewer.
Changes to owner/selector fields therefore replace or redact cells atomically
with the row update. Devices never re-materialize a hidden default. A
row-local protected cell in delivered history remains subject to the same
stored row-local projection; copied data cannot be retroactively forgotten by
a client that is offline.

A rule with a probe or reference is evaluated by the authoritative engine.
Its cell is omitted from every replica image. Read sites on that table are
server-class and the ordinary SDK fallback answers them online; offline they
are explicitly unavailable, never a complete answer with fabricated hidden
cells. A `held` query cannot certify those reads. Writes whose return or
transition needs those cells queue without prediction. This is the same
residency boundary as non-invertible row rules, scoped to column payloads;
it does not require an application side table, a second query or a new hook.
It deliberately makes no offline availability claim for policies whose
witnesses the device does not hold.

Server live queries track every column-rule probe dependency, so a grant,
role or parent change invalidates the answer even if the data row is unchanged.
Existing policy reset/expiry/sign-out fences still apply. No cell rule adds a
new result cache, partition audience or unbounded write fanout.

### 22.4 Assets, writes and refusals

Asset downloads and read-once use require owning-row read authority AND the
asset column's effective authority, including asset-list columns. Hidden
assets retain the non-oracular `E_ASSET_UNKNOWN` response and meter. Upload
placement checks insert/update authority and input shape; it does not grant
read access, and attaching an asset never returns its protected value to an
unauthorized writer. Returning an insert/upsert/update row runs the same
projection as a query. Blind write outcomes keep their existing refusal
normalization. The new declaration/structural refusal is `E_COLUMN_READ`;
ordinary denied scalar access is optional null, not a distinct refusal.

### 22.5 Invariants, audit and releases

SEC3's `invariant table.column read only P` is proved against row read AND
column read AND owner-private authority. Declared policy and intent must agree:
a column rule does not automatically mark an independently stronger invariant
proved. Unsupported observer flows retain the SEC3 proof obligations. Audit
prints each effective column audience and its server/replica residency.
A narrow 1:1 side table with a parent reference and unique parent key receives
an advisory column-rule suggestion, never an automatic rewrite.

Adding, changing or removing a column rule is a normal schema adoption; existing
values remain stored and clients rebootstrap on changed schema generations.
Rollback to a schema lacking the rule restores that schema's audience and
warns of confidentiality changes under the existing release preview policy.
A v2-only protected column becomes a dormant cell on a visible v1 row, using
ordinary retained-column storage. Old clients calling the new server receive
omitted protected fields, and generated compatibility reports must identify
newly optional fields. The DORM lane owns forward catch-up and reverse projection.

### 22.8 Exact admission and observation boundary (round-one clarification)

The supported runtime grammar is **exactly the existing read-rule grammar**:
allow/deny/public, equality/inequality over own ordinary fields/viewer/literals,
and/or/not and unique readable `exists`. `created`, ordered comparisons,
old/next image operands and reference terms are not column-read forms. A
reference-derived audience is written as an existing unique `exists` probe.
The row-local subfragment excludes `exists` entirely. No column gate may use
any field protected by either a column rule or owner-private authority, even
when another branch would establish ownership. Rule-term validation recursively
walks every Boolean arm and every probe key and residual target field, using
the bound target index's actual columns. A raw schema gets the same walk.

**Noninterference oracle:** fix schema, viewer, arguments, clock, public rows
and all policy-selector/witness values. Vary only a column's stored payload,
with its effective rule false in both worlds. Every supported application
observation (data, refusal, meter, completeness, continuation and dependency
table names) must be equal. This includes absent-vs-present-null whole-row
shapes, explicit scalars, null filters, count/exists, computed group/sort and
writes. Projecting every hidden payload to the same absent/null observation
satisfies this oracle; the public fact that the viewer is denied is not a
promise to conceal the rule or to simulate an authorized null value. Blind
writes are deliberately governed by row write authority, just as readable
fields are; apps needing narrower writes also declare `written by` or narrower
row write rules. Immutable/cap/unique/after-insert rules cannot use protected
payloads because refusal differences would test guesses; input-only text/type
validation remains legal. No existing schema without column rules changes.

The structural dependency census also includes: all timeline mappings and
predicates, receipt declarations, every maintained predicate (including
row-keyed member-side predicates), engine captures through descendants,
recorded-attribution sources, generated contribution indexes and source
sequences. A protected cell may not appear anywhere inside a rule's reference
path. Protecting a *previously* unprotected selector is checked against the
entire new schema, including already-declared child captures. Such an adoption
is invalid before storage is touched. A protected maintained output is admitted
only when it has no downstream structural users; its derivation inputs still
obey the input refusal. In-memory sort/group consumes only projected values;
physical index ordering on protected values always refuses.

**Delivery transaction:** shared pending/log images omit every column-protected
payload, even in principal partitions. Snapshot acquisition and stream serving
use their existing read transaction and re-fetch the current stored row, test
row authority, and evaluate its row-local column rules for the recipient. They
already serve current images rather than historical put bodies. Selector changes
are projected from that same current image; no independent cell log or audience
is introduced. Server-witness cells are never delivered. A device re-applies
row-local projection before pricing, returning or rebuilding defaults. Server-
witness tables are conservatively server-class for *all* application read sites,
including projections without the field; this is an intentional documented
availability tradeoff, not a claim of cell-level residency analysis. Any
mutation writing one queues without prediction; a held query with such a site
refuses `E_COLUMN_READ`. Ordinary online fallback needs no SDK policy branch.

Schema/generation replacement follows the existing device installation reset:
no old images publish under the new generation before it is installed and its
partitions acquired. This applies to adding/removing a gate and to changing
between row-local and server-witness rules. Old offline clients can retain
previously disclosed bytes (the same ordinary revocation boundary as rows);
servers never deliver newly protected bytes to an old decoder. No claim of
retroactive erasure is made for delivered history or offline clients.

Live invalidation uses the existing `Runner::rule_dependencies` and response
`tables` envelope. Every read registers the table's full column-rule witness
closure independently of evaluated arms, including empty reads. The existing
live-query dependency machinery observes those tables; no new invalidation
index or write-time fanout is needed. Probe deadlines use the existing scoped
expiry machinery; all branches prepay their static probe/scratch bounds.
Column-bearing tables cannot use actual raw-size pricing fast paths. Only
row+column-authorized results can be priced at actual payload length.

Asset denial precedes range handling and one-view consumption; a denied caller
gets the same unknown-asset envelope as an unowned id, whether the column is
scalar or an asset list. Placement remains insert/update authority plus the
existing one-home law; it confers no read authority. There are no thumbnails
or transformed asset paths in this product.

Type emission covers Rows, baseline/write rows, row shapes/objects, explicit
projections, spreads and named views. Write *input* fields retain their declared
requiredness: read optionality is not optional input. The old-client report
names an existing required field becoming optional when its read rule is added.
Old already-generated code cannot be rewritten by the server; the preview says
that it must handle omission. An intentional rollback to a wider audience keeps
the existing confidentiality warning; a new hard approval gate is not part of
this commission's normal-adoption requirement.

Audit prints the actual effective conjunction and residency per column and
includes grant writers reached from column probes. The side-table note is a
conservative advisory, only for an ordinary table with exactly one required
parent reference covered by a single-column unique key and a nonidentical read
rule; it never asserts equivalence or rewrites data automatically. The five
copied migrations explicitly backfill the new column and remove obsolete side-
table write paths; their comparison records supply the cutover evidence.

Qualification thresholds are those commissioned: Rust core/lang/CLI/sim/device/
difftest suites and full client pool all pass; `run` seeds 0–19999,
`run-devices` seeds 0–999 on SQLite and memory, and `run-lean` seeds 0–19999
introduce zero new signatures; Lean builds/checks with no sorry/new axioms;
the 200 original schemas (100 wave 15, 50 wave 16, 50 wave 18) acquire zero new
refusals; packed guide examples run unchanged; five lane copies verify row
visibility at rollback, private payload denial, allowed payloads and restored
forward cells. Unsupported SEC3 proof paths remain explicitly Unproved; they
are not hard refusals unless the schema itself violates admission above.


### 22.9 Blind asset assignment and device acquisition (Codex round one)

For every explicitly supplied asset or asset-list field whose *old cell* is
not readable by the caller, placement must require uploader ownership even
when the supplied id equals a hidden old id. It uses the existing blind-row
placement check at cell granularity. Omitted cells are retained without a new
placement authorization test. Paired tests submit an equal versus unequal
non-owned known asset id and require identical outcome and meter. Protected
immutable payloads are rejected by the §22.8 admission census.

A device cannot infer an omitted cell's value by making its selector grant
access. For every predicted insert/update/upsert on a column-bearing table,
if an unsupplied protected field would change from denied/omitted to allowed,
the prediction queues without a row. No default or null fills the gap, even
when the stored type is optional. Server settlement plus recipient projection
acquires the actual value. A supplied value can predict only when its read
policy is row-local and all ordinary write/prediction checks pass. Tests cover
selector grant, unchanged denial, ordinary private patch, and explicit supply
on both device stores.

Acceptance also covers column-policy grant/revoke/expiry without a data-row
edit; both row-local ↔ server-witness generation transitions with outstanding
predictions; and optionality through spreads, transient views, baseline and
write-result types. The RFC review record is not a claim these tests have run.
