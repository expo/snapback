## 1. The High

The eligibility test `key >= floor` is not in `partition.rs`. Join markers are created with `floor: None` (`752–753`, `769–770`). Between the pair, the stream records current readable selected keys actually pushed (`654–667`). The end marker’s floor is `join_completion` (`641–646`, `690–714`).

Rule the code implements:

- Selection is still join-time: `group_at(join_seq)`, descending by the horizon index, first N delivered, tail kept as `unselected` (`755–763`). That is §18.2 (“a join acquires the images that existed at its own commit”); current top-N is not used.
- `whole` (`rows.len() < last`, so `unselected` is empty) publishes `"whole"` even if every selected row is later gone or unreadable (`694`, `761`).
- Otherwise K starts as the oldest *delivered current* key (`695`). If that set is empty, no completion (`646`, `695`).
- A row falsifies K only if it is in that unselected tail, its join-time key is ≥ K, and its *current* image is present, readable, still in this group, and has the **same** index key (`698–709`). Then K becomes the next delivered key strictly above that falsifier (`710–712`); if none, omit the completion.
- Falsifiers come from `group_at(join_seq)`’s truncated tail, walked in the existing descending order. There is no extra index scan. The ordinary case hits `key < oldest` on the first unselected historical key and returns K without a fetch (`701–703`).
- Unchanged is conservative: same current key counts as unchanged (`707–709`). `PartitionRows` has no cheap last-write seq. A later same-key rewrite can therefore decline a still-true suffix; it cannot certify a missing unchanged row.

LLP 3000 §7’s current-readable-image rule (`llp/3000-snapback4.explainer.md` 651–658) is the catch-up contract this implements: the wire carries current readable images (or a deletion), never a withheld historical key. NOT-DOING “Exact horizon maintenance” is unchanged: nothing evicts or back-fills; a local page that would cross the published key is `complete: false`.

## 2. Leak-freedom (two worlds)

**The High’s pair.** `p1.at=100`, `p3.at=3000`, `p2.at` is 800 vs 2000; `last 2` selects `p3,p2` in both; then delete (or hide) `p2` and move `p3` to 1000.

- Unselected is `p1@100` in both (`762–763`).
- Delivered is `{key(p3@1000)}` in both: `p3` is fetched current (`654–666`); `p2` is a `del` or an unreadable skip (`657–669`).
- `join_completion`: oldest = p3@1000; p1’s join-time key is below that, so `break`; publish hex(p3@1000) in both (`695–714`).
- Join-time `at` of `p2` is overwritten before push and never compared. Marker `at` is remapped to the filtered event vector (`650`), so it is the same.

Rust compares `serde_json::to_string(&page_json(&stream))` across both stores (`recheck.rs` 30–37). Wasm compares the HTTP body after stripping `store_id` (`horizon-boundary.test.mjs` 213–219). Events, markers, and the one completion at 1000 match.

**A new pair I tried.** Same move of `p3` to 1000, `p2` still at 2500, unselected `p1` deleted in both worlds, `p1`’s *join-time* key 800 vs 1200 (both still below p2, so selection is unchanged). Oldest delivered is 1000. World 800 breaks without a fetch; world 1200 fetches, gets `None`, continues. Both publish 1000. The extra `del p1` is the same id with no old key. Payloads match.

**Pre-existing, not this round.** If the withheld key would change the top N (`p2.at=50` vs `800` with `p1.at=100`), the delivered *rows* differ. That is join-time selection / the delivered-count channel the journal already puts to the author (`JOURNAL.md` 31975–31979). It is not a regression of this fix.

## 3. Correctness

Join-time `p3=3000, p2=2000, p1=1500`, then `p3→1000`:

- Delivered `{1000, 2000}`, oldest 1000.
- `p1@1500` is unselected, current, same key, ≥ 1000 → greatest falsifier.
- Next delivered key above 1500 is 2000 (`712`). Never 1000.
- Delete p2 as well: no delivered key above 1500 → no completion (`712` returns `None`; `646` drops the end marker).

Device coverage (`read.rs` 688–704): a descending page on the horizon index is known only for `Whole` or when it stays at/after `Key(floor)`. `newest` / `above` in the control are complete iff a floor was published; `timeline` last-2 crosses and stays unknown (`recheck.rs` 64–70; wasm 238–243). p1 was never in the acquisition window, so a floor of 2000 cannot name it. A floor of 1000 would have; that is why the comparison was load-bearing, and why narrowing replaced deleting it.

`whole` on a selection of fewer than N rows is the same claim with no lower bound (`694`). Exactly-N rows all deleted, with an unselected remainder, still omit the completion (`695`) — fail-closed, and required so p1 is not certified.
