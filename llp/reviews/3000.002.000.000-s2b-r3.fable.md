**1. High — `startEpisode` executor arms the withdrawal bound with no replacement read.**
`snapback4/packages/snapback4/src/local.ts:1981-1988`. The base arrival path called `scheduleRead(watch, true, undefined, preserved, writes)` (base `local.ts:1990-1991`). The port calls only `watch.reload(...)` and `notify(watch)`. `reload` arms the non-renewing episode (`read-observation.ts:179-190`) but nothing calls `acquireRead`; the deadline callback withdraws to `{loading: true}` (`read-observation.ts:93-100`) and `onWithdrawal` only notifies subscribers (`observe-watch.ts:103`). The later `publish` schedules reads only for watches intersecting the publication's `writes`, which for a `qualified` footprint is the column footprint.
Scenario A: write footprint `items:['title']`, watch `other` reads `items:['body']` with data displayed; own `sent` reply arrives under obsolete credentials. Arrival → scope `all-columns-of-known-tables` → `other` is armed, no read. Persist → publication `{preserved: [], footprint: 'qualified'}` → `writes = {items:['title']}` → `other` does not intersect → no read. Deadline fires → `other` is withdrawn and stays `loading` until an unrelated change. Base scheduled the table-wide read at arrival. Scenario B: late own response after peer completion (phase `settled`): episode only, no publish follows → the fresh post-cut answer is withdrawn and never re-read. Rounds 14 and 16 item 2 pass only because their peer-completion read is held by `cover` and still in flight when the deadline fires. This violates LLP 3000.023 §3.1 (withdrawal with a re-read in flight).
Fix: in the `startEpisode` branch call `void scheduleRead(watch, true, undefined, effect.preserved, writes)`. A still-pending id parks the read on `journalIntersects`; the publish's read coalesces through `watch.dirty`. The "settle once" dedupe that motivated skipping it no longer exists.

**3. Medium — the `!storeRefusal` guard on `settle` re-decides a kept intent's settlement.**

Scenario: wrapper decides `retire-foreign`, kept B intent X is in flight, X's `sent` reply arrives.
