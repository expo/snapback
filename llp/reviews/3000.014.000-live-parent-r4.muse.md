## Blockers

**B1 — Receipt-scope endpoints admitted but their internal writes are unreserved. Severity: Medium (bounded-resource accounting + availability, fail-closed).**
Counterexample: table `P` is a live parent and also a receipt scope with counter `c`. `commit_receipt_counter` (`engine/receipts.rs:264`) runs on every message insert and calls `replace_authorized` on the scope row, which reaches the shared tail (`engine/write.rs:395`). Under this design that tail fires the LiveAuthority hook: up to N child rewrites plus events, none of it in any admission price (`counter_price` knows nothing of live edges) and with no operation-entry prepayment — the insert path (`engine/write.rs:251`) is the only caller, and it never reserves edge prices. Nothing in §2.1 refuses a receipt scope as an endpoint. Correctness survives (the hook fires synchronously, so copies stay fresh), and the internal meter bounds the work — but `check` under-reports the true cost of every message insert, and the design's "charge every edge before parent lookup" universal is false on this path.
Smallest repair: one §2.1 bullet refusing endpoints that participate in a receipt family in a server-mutated role (scope counter at minimum; audit runs/member-marker paths in the same edit), with `E_READ_THROUGH` and the manual-recipe rewrite. Probe rosters (`members[.dept,viewer]`) are explicitly unaffected — the refusal covers endpoints only. Alternative: compose edge prices into `counter_price` for scopes with live edges and reserve them in `commit_receipt_counter`'s existing `authorized_scratch`.

**B2 — "Same-term non-null proof" is undefined, and binder and core must implement it identically. Severity: Medium (blocks exact implementation).**
Counterexample: probe index `members[dept, alias]` is unique with `alias` optional, pinned as `[Field(dept), Viewer]`. Total iff `Viewer` counts as a same-term non-null proof; pinned as `[Field(dept), Field(nick)]` with `nick` optional, it is not under any sound reading — but the RFC never says which terms prove non-null, so two implementers (and the binder vs the core validator, which §2.1 requires to check independently) can diverge: one admits, the other refuses, or totality drifts from the existing sync admission it claims to reuse. `key_proofs.rs` contains no such concept; there is no existing referent.
Smallest repair: one sentence — a non-null proof is exactly `Viewer`, a non-null `Literal`, or `Field` of a required column, and nothing else.

**B3 — Live rows are not excluded from the historical-keep adoption path. Severity: Medium (stale authority if misread; §3 forbids the end state but §7 blesses the reuse direction).**
Counterexample: live `tasks` with dormant narrow rows; a live-to-live adoption (e.g. cap change) reuses `activate_retained`, whose `retained` set is exactly through-tables with dormant narrow rows (`store/activation.rs:217`, `store/dormant.rs` tail). Lines `engine/through_activation.rs:242` (skip correspondence) and `:290` (keep dormant values, fill only missing fields) then publish dormant dept-A copies while parent `P` has moved to dept B — the Codex-r3-3 scenario through the dormant door. §3's invariant forbids the end state and §7 says "dormant restore applies the same checks," but neither names this skip as inapplicable to live rows, and "checks" does not say restamp-or-refuse.
Smallest repair: one sentence in §7 — the retained/historical keep path never applies to live rows; dormant live rows are restamped from current parents or the activation refuses `E_READ_THROUGH_ADOPT` (missing parent included).
