## Overall

The delta does what round 2 asked. There is no alias pool: serde derive **renames and re-exports are refused at the `use`**, classification is **lexical per item**, and a `macro_rules!` **body** that carries a content representation together with a decoder, unknown, or metavariable derive is refused. The live tree is compatible with that policy (`use serde::{Deserialize, Serialize}` and `serde::de::Deserialize` as a trait path appear as-is; `WriteState` / `MutationOutcome` stay on the exact sqlite exceptions). Remaining green paths need a deliberate split of derive vs. attribute across a macro definition and its invocation — outside what this guard is for. The LLP sentence now matches the three layers. Tests import the production `census`, not a copy.

## Round-2 items

### 1. Alias pool / cross-file whitelist — **FIXED**

`decoderAliases` is gone. `deriveImports` (`snapback4/packages/snapback4/test/wasm-codec-census.mjs:112-122`) refuses a `use` whose path is `serde::(de::|ser::)?(Deserialize|Serialize)` when it is renamed **or** `pub`/`pub(…)`-re-exported. `classifyDerives` (`:126-130`) treats only the tokens `Deserialize` and `serde::Deserialize` as decoders; everything else except Serialize and a fixed non-serde set is unknown, and unknowns only matter on a representation-bearing item (`:158-164`). There is no global name set, so `use serde::Serialize as D` in one file cannot whitelist `#[derive(D)]` in another.

Tried spellings:

| Spelling | Census |
|---|---|
| `use serde as s; #[derive(s::Deserialize)]` + untagged | Red: `s::Deserialize` is unknown (`:126-130`, `:161-163`) |
| `pub(crate) use` / `pub(super) use` of the derive | Red at the import (`:114-118`; tests `:216-220`) |

## Findings

### Low — macro definition vs invocation can split derive and representation

**Where:** `snapback4/packages/snapback4/test/wasm-codec-census.mjs:153-156` (macro body) and `:158-164` (item attrs only; invocations are not items).

**Scenario.** Walked source:

```rust
macro_rules! untagged {
    ($($t:tt)*) => { #[serde(untagged)] $($t)* };
}
untagged! {
    #[derive(Deserialize)]
    enum Added { X }
}
```

The body has a content attribute and no derive (`decoder` false, `unknown` empty → buffered attrs ignored). The invocation has `#[derive(Deserialize)]` and no content attribute (`buffered` empty → no hit). Census is `[]`; rustc still builds an untagged decoder. The inverse (derive in the body, `#[serde(untagged)]` on the invocation) is the same hole. Nested `outer!` / `inner!` that split the two tokens also stay green.

**Smallest fix.** If a `macro_rules!` body has a buffered serde attr, refuse it unless the body is allowlisted — or, cheaper and less noisy, treat attributes immediately preceding a `foo! { … }` invocation as part of the expansion and join them with that macro’s body before `classifyDerives` / `bufferedAttrs`. Not required for the honest-mistake bar.

### Low — “refuse re-exports at the import” does not see globs or `extern crate`

**Where:** `deriveImports` `:117-118` (exact `Deserialize`/`Serialize` paths only; `use` only).

**Scenario.** `pub use serde::*;` in a walked prelude is green. It does **not** let `#[derive(Deserialize)] #[serde(untagged)]` stay green (lexical decoder). `extern crate serde as x; #[derive(x::Deserialize)] #[serde(untagged)]` is still red as unknown.

**Smallest fix.** Also refuse `use serde::{…*…}`, `use serde::*`, and `extern crate serde as …` if the policy text should be literal. Optional; it is not an S1b evasion.

### Low — buffering sentence is attached to every representation hit

**Where:** `wasm-codec-census.mjs:252`.

**Scenario.** `#[derive(Hash, Serialize)] #[serde(untagged)] enum LaneSource { … }` (or `#[derive(S)]` after a forbidden alias) reports “unresolvable derive Hash — Deserialize content buffering…”. There is no Deserialize.

**Smallest fix.** Append the LaneSource/buffering clause only when `decoder` is true; keep “unresolvable derive …” for unknown-only hits. Optionally put `Hash` back next to `Error` on `:125`.
