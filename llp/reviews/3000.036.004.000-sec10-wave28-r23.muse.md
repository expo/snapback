## Material blocker: `subject.rs` metadata-suffix exclusion contradicts §12 scope (unsound exemption)

`snapshot4/crates/snapback4-lang/src/bind/security/derived/subject.rs:9` (`matches()`) excludes a candidate media column when the lowercased tail merely *starts with* `approv/authoriz/consent/reason/cost/at`. §12 contracts the inference to "unambiguous same-row named typed assets (including lists), with an actual word boundary after the approval subject (CamelCase or underscore)". A prefix test is stricter than the contracted boundary test, and it fires on in-scope columns:

- Counterexample 1: `likenessCostume: image` with stamp `likenessApproved`. `same("likeness","likenessCostume")` is true (CamelCase boundary, `C` uppercase), `contains_asset()` is true, but `"costume".starts_with("cost")` exempts it. A `changeLikeness`-style edit to the costume scan with no reapproval then yields no derived freeze and no FIX. Per the contract it must be governed.
- Counterexample 2: `likenessConsentForm: image` (photo of the signed form — highly plausible in approval workflows). Boundary holds, yet `"consentform".starts_with("consent")` exempts it. Same silent miss.
- Same class: `likenessAtlas`/`likenessAttic` via the `"at"` prefix.

I traced the miss end-to-end by reading (not just the predicate): with `matches()==false`, no freeze candidate is emitted; the inspected-input path cannot compensate because the 036-pattern approval op never reads the media (that is the point of the new inference); and `approval_effects::modeled()` also skips the field since its `metadata()` uses the same `"cost"`-substring test. So the edit passes silently — a missed refusal, the unsafe direction.

The fix preserving every spec-mandated exclusion is small: compare the tail against the metadata words with full-word equality instead of prefix (`tail == "at"|"cost"|"reason"|"consent"|…`). All genuine metadata tails (`likenessAt`, `likenessCost`, `likenessReason`) are exact tails, and their types (Time/Money/Text) already fail `contains_asset()` anyway, so the prefix breadth buys nothing. Related adjacent observation (pre-existing, §11-era, non-blocking): `approval_effects::metadata()` has the same substring shape (`"costume"` counts as metadata); worth aligning in the same edit.
