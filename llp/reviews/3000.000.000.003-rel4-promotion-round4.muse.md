## Why each requirement holds

- **Stopped-source exclusion through publication.** Command lock (`command_lock`, blocking) plus owner `try_lock` are acquired before any copy and held to end of `plan()`; live owners get the exact ``snapback4 stop STAGING`` repair. DB copy uses the established read-only `VACUUM INTO` surface (same as `release_preview.rs`), never file bytes. Source is opened `SQLITE_OPEN_READ_ONLY` with no permission tightening, so the "source unchanged" claim holds (the only source-dir side effect is the standard `.release-command` lock file, which is exclusion infrastructure, not state).
- **No overwrite / nested / live-source.** Existing destinations (including empty dirs and dangling symlinks) refuse; both nest directions refuse on canonicalized paths; races are closed by `renameat2(RENAME_NOREPLACE)` / `renamex_np(RENAME_EXCL)` with no replacing fallback, and non-Linux/macOS hosts refuse.
- **Clock.** Zero-offset/unpaused/no-future-frontier is enforced twice (pre-copy `wall`, pre-commit `promotion_wall`) via `staging_clock`, whose `max(wall, recovered, floor, legacy_floor)` construction means retained future commits/schedules also refuse. Timestamps are never rebased; only provenance records wall time.
- **Quiescence.** `_jobs`/`_requests`/`_outbox` (`queued`/`running`) and `_action_steps`/`_effect_steps` (`started`) refuse; `parked`/`done` are settled history and correctly pass. Schedules are covered indirectly through the clock-frontier check.
- **Credential separation.** One transaction on the private copy: purpose check → live-guest refusal → quiescence → asset verification → `_principal_generations` bump for every principal → `DELETE FROM _sessions` / `_read_sessions` → new `store_id` → purpose `production` → `promotion_origin`. Revoking rows plus bumping generations doubly fences full rotation, read rotation (`principal_generation < current_generation` refuses), and idempotent mint rebinding (`previous.principal_generation != target_generation` refuses). `_principals`/`_credentials`/row ownership are untouched, and the tests assert same-principal password login afterwards. Expired guest *principals* remain; only their (revoked) session rows are deleted, which matches "all copied sessions revoked".
- **Releases/assets.** Release trees are copied (`.snapback4` absolute links excluded, symlinks refused), digested against source before preflight, `link_store` recreates relative links, and digested again after preflight. `releases.jsonl` is copied verbatim; migration/receipt/history tables ride the snapshot. `native::prepare` / `dev_worker::prepare_release` validate bundles read-only. Asset ids are single-component ULIDs, matching the traversal guard; every `released_at IS NULL` ledger row requires a regular file of exactly the ledger length on the copy.
- **Strict preflight on scratch.** `Engine::attach_release_at` on the reopened copy, `bound_at` compile, then `release_loop`/`enforce_release` with forced `strict` on a `.promotion-check` copy, so campaign caches can't touch captured trees; `enforce_release` enforces identically under `--check` (no preview/publish divergence).
- **Atomic publish + truthful recovery.** `durable()` flushes the whole candidate tree, `no_replace` publishes, parent dir is fsynced; post-rename sync failure reports the destination may already be complete and never deletes it. `--check` runs the identical copy/attach/security path and drops the candidate without creating the target.
- **Surface.** `cli-commands.json`, `cli_flags` (2-positional limit), synopsis/help, `main.rs` dispatch, and `--json` contracts are consistent. No version bump, push, or merge path exists. The Rust tests, core unit tests, and `publication-promote.mjs` jointly cover stopped/running source, existing/nested/raced destinations, clock refusal, security refusal, token/refresh revocation, password survival, asset bytes/homes, history equality, rollback cycles, and source-unchanged behavior.

## Adversarial cases examined and dismissed

- *Released (`released_at NOT NULL`) assets aren't byte-checked.* They are home-detached sweep-pending garbage; nothing serves them, so skipping them is correct triage, not a hole.
- *Same-length asset byte corruption during copy.* Nothing mutates candidate assets mid-promotion (preflight touches only the release-tree copy), so length + presence checks cover the realistic failure modes; no ledger content hash exists to compare against.
- *Worker `_meta` family pointers survive.* They dangle sessionlessly and are serve-time cleared; no live authority inherits them.
- *Stale `wall` passed to `attach_release_at`.* Milliseconds stale, both real-time samples; no semantic effect.
