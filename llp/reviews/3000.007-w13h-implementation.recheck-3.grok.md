## Findings

**Medium — `Record` vs `Empty` still drops the owner.**

- **Where:** `snapback4/crates/snapback4-core/src/engine/pages.rs:149–161` (`join_origin`), then `result_page` 111–117.
- **What is wrong.** `Page` vs `Empty` is now `Page(site, cursor, None)`. A **record** that carries that page, joined with `null` / `[]` / an omitted value arm, hits the `may_carry_page` catch-all and becomes `Unknown` with **no site**. Collect no longer fails on `Unknown`, but a siteless origin still cannot select a continuation. That violates the floor in §5.6:545–547 and journal 32586–32588 for this spelling, while the field-level spelling is tested.
- **Scenario.** `page = msgs[0] after c first 1 by byLane`, `ignored = page { … }`, `return { page: page, shaped: ignored } if q = 'raw' else null` (or `selected = { page, shaped: ignored } if q else null; return selected`). With `q = 'raw'` and rows `a`,`b`, the first answer is the record containing `[a]` and has no `next`.
- **Smallest correct change.** In `join_origin`, `(Record(fields), Empty) | (Empty, Record(fields))` → `Record(join_bindings(fields, ∅))`, so each page field becomes `Page(..., None)` the same way a bare page does. Add that record-level `else null`/`else []` form on all three hosts.

No Critical or High on the specified loop, `else []`, `else null` field, sibling-`Unknown`, or two-page controls. Same-lineage trim/rewind still holds. No trim-without-rewind form found.

Verdict: READY WITH CHANGES
