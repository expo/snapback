## Blocker: authored-capture has no union selection and no comparison step

[RFC §Measurement](llp/3000.036.004.000.000-production-security-replay-latency.rfc.md) requires capturing complete authored counterexamples "for every schema where either classifier observes an authored FIX, and compare those payloads too."

- [authored_witnesses.py](/home/ccheever/projects/sb4-b31-sec11l/snapback4/reports/sec11-latency/tools/authored_witnesses.py) takes a single `--survey` and selects only from it (`selected=[r for r in rows if r['checkFixes'] or ...]`). A schema that gains its first authored FIX only in the after-survey is never selected when the tool runs on the before-survey — and running it once per survey still leaves union-only lanes without a both-binaries capture pair to compare. The "either classifier" union is not expressible.
- There is no comparison counterpart: the tool writes per-schema captures plus `results.json`/`provenance.json`, but nothing diffs the before-binary and after-binary captures, so "compare those payloads too" is currently manual and unreported.

Fix (small, still in scope since measurement is in progress): accept before+after surveys (or an explicit lane union) and capture with both binaries, plus a diff step that reports every payload difference explicitly. Until then, no equivalence claim can rest on the captures. Related residual, not a blocker: derived-invariant (`$derived/`/`$enforced/`) FIX payloads stay projection-only (`site`/`predicate`/`operation`) in both tools — that matches the RFC's authored-only scope, but name it in the final claim.

## The six questions (all pass)

**Campaign threads ≡ serial.** [replay_ids::Scope](snapback4/crates/snapback4-lang/src/bind/security/challenges/replay_ids.rs) is `thread_local!`; `thread::scope` spawns fresh threads and each campaign entry creates/drops its own scope, exactly as serial calls did — counters restart at 0 either way. Budgets unchanged (`work_bounded(3072)` gate / `8192` advisory, per-thread `Campaign`), at most 3 threads (1 derived + 2 enforcement, empties skipped), all joined, reduction iterates gate-then-advisory with the identical `max_by_key` body in [witnesses.rs](snapback4/crates/snapback4/src/verbs/security/witnesses.rs). Shared inputs are all immutable refs; per-thread state (`bound` clone, forked stores, unique asset dirs via getrandom-backed `ids::mint`) keeps fixtures isolated. Owned `Value`s move through the joins, so live-only payloads stay live; cache read/write and eligibility re-application are single-threaded as before.

**Report reuse exact.** [security.rs](snapback4/crates/snapback4/src/verbs/security.rs) (`release_loop`): preflight gains `security-deploy` for production and strict staging only; `collect_with_report(..., preflight.flags.contains_key("security-deploy").then_some(&report))` passes `Some` exactly there. The reused report is `report_with_reviewed` on identical project/bound/sources/flags/empty-reviewed inputs as the old interior `super::report` recompute (`report()` is the same function with `Default::reviewed`, and the derived thread's `options+security-deploy` flags equal the preflight flags). Non-strict staging passes `None` and keeps its own production-report thread. Both source-race guards retained; gates/questions still replay; cache still excludes gate/derived. The new `current_deploy_report_reuse_keeps_the_exact_derived_witness` test in [derived_tests.rs](snapback4/crates/snapback4/src/verbs/security/derived_tests.rs) asserts `original == reused` on a derived case.

**Batching ≡ independent compilation.** [candidate_batch.rs](snapback4/crates/snapback4/src/verbs/security/witnesses/candidate_batch.rs): each distinct line becomes its own line-one `$dx11-question.q` document; `compile()` keeps same-named docs as separate `Vec<Document>` entries and `security::bind` walks them in order with no dedup, so the positional zip over the `BTreeSet`-sorted lines is sound. Site rewrite uses the same `hash()`; absence rewrite (`/dx11/`→`/sec11-absence/`) fires under the same note-code condition; duplicates map to equal clones. Any diagnostic or count mismatch falls back to the original per-line `candidate()` for every distinct line, so no invalid line suppresses another. The unit test compares full serialized invariants for duplicate and mixed valid/invalid batches.

**Backup-before-prepare retains state.** [fork.rs](snapback4/crates/snapback4-core/src/store/fork.rs): `prepare()` runs on the copied connection, so catalog/identity/read-session storage/version are read from the copied snapshot; the post-prepare catalog/identity/server overwrites are equal-valued redundancies. `page_size` is restored to the previous memory-fork default (exact old `memory()`-then-backup behavior; see `866359f975`), server mode passes `self.server` through, asset dir is fresh/unique per fork, assets byte-copied with no hard links, `ownership=None`, ephemeral stays true, `file_identity` is `None` for memory conns in both old and new paths. Admission verification still runs; no synthesized rows or host cut.

**Telemetry is deadline-safe and sink-strict.** [challenges.rs](snapback4/crates/snapback4-lang/src/bind/security/challenges.rs) `slice()` and [fork.rs](snapback4/crates/snapback4-core/src/store/fork.rs) now only take an `Instant` and push a bounded in-memory event (no file I/O, no work-budget consumption; production campaigns are `deadline=None` anyway). All sink I/O is in `Trace::drop` ([phase.rs](snapback4/crates/snapback4/src/verbs/phase.rs)), which runs at end of `main` (`_phase_trace` declared first, dropped last) with unix `O_NONBLOCK|O_NOFOLLOW` plus an `is_file()` gate — FIFOs can't block, symlinks/devices/dirs are refused (so `/dev/stdout` can't corrupt `--json` output either). Timings never touch verdicts, selection, proof, or cache keys. The unix-only sink test covers FIFO/symlink/regular + verdict equality. Both r1 code findings (sync telemetry in deadline path; missing authored payloads) are fixed in code; the r1-muse wording finding is fixed too — [compare.py](snapback4/reports/sec11-latency/tools/compare.py)'s `comparison` string now accurately describes whole-field omission (durations, `defaultCheck`/`defaultDeploy` transcripts, `summary` display lines, line counts) with no scalar scrubbing, verified against [survey.py](snapback4/reports/sec11-item1/tools/survey.py)'s row schema.
