The paper’s 14 hard ops are not 14 plans. Ops 4, 8–10, 12 have a durable half the language can almost say. What remains after `scan`+`unique`+`schedule`+`maintain` is **column-level secrecy that `check` will not refuse, intake fullness as a hidden-set count, intent-time `now` versus receive-time authority, and a dispatch rank over a visibility-filtered page.**

### 2. Schema in v0

Sentinels: no `optional` / enum / float / i64 / geo / column ACL. `UNSET` id/time = `0`. Enums → `text({ max })`. Money → `int()` minor units (i53 overflow-refuse; design asked i64). Coordinates → `int` microdegrees. `json` opaque to rules **and** indexes — do not put secrets on a jointly readable row. `never` = missing effect. No `tree`. Intervals stored for display and for schedule `at`; **write authorization is `status`**, flipped by schedule (K5, ruling 11). `cap` max is a schema constant — dynamic `capacityLimit` cannot use it.

### 6. Language delta

Ranked by whether this app’s central invariants stay slogans.

1. **Column / projection types in the type of a read.** A row that is readable is fully readable. Smallest: `project(table, ['state','eta...'])` as a first-class query result, **or** engine-maintained projections with a declared audience. *General* (every multi-party aggregate). Amends §2–§3, §6 receipts. Without this, trap 1 is an admitted plan.

2. **`callable: 'system'`.** Dispatch, settlement, payout, apply-result, freeze-round are client-callable. *General* (auction, payments). Amends §1, §7.

3. **`cap({ by, maxFrom: parent.column })` or an increment constraint** `next.n === old.n ± 1 && next.n ≤ old.limit` in rules (today: field comparisons, no arithmetic). *General* (inventory, bookings). Amends §2, §3. Dynamic restaurant capacity is otherwise a cache.

4. **`balanced(entries, { by:'txId', of:'amountMinor' })`.** *General* (ledger). Amends §2. `require` in `postSettlement` does not bind a second mutation.

5. **Transactional effect outbox.** Durable `outboxWork` is modeled; missing runtime: lease, `sent_unknown`, host invokes named mutations as `system` on inbound webhook, retry uses `stableKey`. *General*. Amends §1, §7. `effect` as “JS with I/O” is not an outbox.

6. **Geo prefix type / cell operator** as a total shape function of `(latMicro,lngMicro,tier)` so `zoneCell` is not client-supplied (skewable). Smallest: `cell(lat,lng,tier)` in shape expressions. *General* (any marketplace). Amends §4.2. Do **not** add `dist` or floats.

7. **Civil-time / IANA as an `effect` seam, not in programs** — already the kind; publish a **host** `expandIanaWindows(timezone, localIntervals) → utc interval[]` so `publishHours` is not app-specific JS. *General* (booking). Amends §4.1 / asset-seam adjacent. Clock stays out of rules (do not add `contains(now)`).

8. **`appendOnly({ except: ['status'] })` or forbid mixing flags.** Quotes/offers/grants need a schedule flip on an otherwise frozen row. Split `quoteFlags` is the workaround. *General*. Amends §2.

9. **Scan of maintained rows / eligible indexes.** Payout “positive eligible payables” cannot `scan(accountBalance)`. Smallest: `maintain` may declare a secondary index on `(group..., value)` with a `where value > 0` **status**, not a live predicate (ruling 11). *General*. Amends §2, §4.4.

10. **Receive-time `now` option, or a spec statement that I8-style products are wrong.** Today intent `now` is reused (§4.3.9). DoorDash contract 20 and I8 want the other clock. *General*. Amends §4.3. Do not silently pick one.

11. **Authenticated-but-not-`public` read.** Menu/hours for any signed-in customer is not `public(reason)` (world) and not `viewer===owner`. Workaround: `public` on discovery (security item) or denormalize onto the quote. *General*. Amends §3.

12. **Publish `G`.** Freeze-round exam≤66 is cheap; payout 502 and 200k stale-location keyed fires are not. If `G.examined=200`, the diagnostic will propose shrinking 64 — the §7 cheat. Amends §5.

13. **`int({ min, max })`, `text({ enum })` with declared transitions, `optional`.** State matrix and UNSET/epoch collision. *General*. Amends §2.

Not missing: `interval`, `schedule`, `maintain.count/sum` with `readable`, `cap` as a constant, `(old,next)`, `immutable`/`immutableExcept`, unique, `appendOnly`, `ctx.now` in mutations, Euclidean `divmod`, tokens, channels, halo/hidden-consume-take, `E_STRUCTURAL_COUNT` on explicit `page.length`.

Do **not** add `contains(now)` to rules to “fix” I13 — that reintroduces clock-gated auth (K5). Do **not** add `maintain.max` for dispatch rank (seal/hidden set). Do **not** add a shared-row column ACL as a consolation prize for skipping projections.

### 8. Where the design is wrong

Not taste. Forced by v0 spelling.

1. **I8 / contract 20 (“judged when received, device time cannot revive an expired offer”) contradicts v0 `ctx.now` (bound at intent, reused, skew-checked once).** Rules re-check grants (good). Time windows in `require(ctx.now() < expiresAt)` do not. Confirming observation: mint `respondToOffer` 1s before `expiresAt`, stay offline 60s, replay; if the engine reuses intent `now`, the unique assignment commits after expiry. The only I8-faithful spelling is schedule-flipped `offers.status` (and then a late replay fails the **rule** `status==='open'`). The design writes I8 as if the mutation clock were receive-time.

2. **Trap 1 is restated as a warning and then the schema is still one `order` row with “field grants.”** v0 has no such kind. `read` is one expression; a readable row is fully readable; `json` is not stripped. Confirming observation: admit `getOrder` from §3; as restaurant staff, the result contains `matchingState` and, if amounts were columns, `tipMinor`. If `check` emits a plan, the leak is in the language, not the UI. The design’s own §7.1 concession (projections) is the requirement; the §4 table of field groups is not implementable.

3. **I12/I13 treat intervals as write-gates and busy as self-expiring, while rules cannot see a clock and `cap` cannot see `capacityLimit`.** Named-program derivation is not authorization: `placeWhileClosed` and `setBusyWeek` are admitted extra mutations. Confirming observation: during a dated closure, insert an order with `placeWhileClosed` that does not read `openWindows`; if `orders.insert` does not probe `locations.acceptingIntake === true`, the order commits. Second: two customers `placeIntent` while `acceptingIntake` is true and `openOrders` is a cache; if both skip the increment, `intakeCount` (unreadable to them) is unused and capacity overbooks. The design never names the boolean it actually needs, and I13’s “without an expiry job” is false under the hostile-mutation model the spec chose.
