**R2-1 — High: nested conjunctions bypass the leading denial and reopen hidden-word discovery.**

An ordinary three-term Quarry rule suffices:

```quarry
read <- exists permits[.roomId, viewer] and .principal = viewer and .body = 'coffee'
```

The parser and [binder](snapback4/crates/snapback4-lang/src/bind/schema.rs:302) produce:

```text
And([And([permit, principal]), body])
```

The new [prefix selection](snapback4/crates/snapback4-core/src/engine/rules.rs:33) examines only the outer terms. The first nested `And` contains unpinned `principal`, so `take_while` stops immediately. `simplify_prefix` preserves that nesting. Consequently, even the **leading permit check** never runs before candidate or word discovery. The previous recursive extraction handled this case.

Construct W0 with an empty room `r`; W1 adds one unreadable Bob message containing `coffee`. Permits are absent in both. Keep readable rows, inputs, clock and sequence identical.

With ample budgets, all four pairs return `[]`, `complete: false`, `next: null`, no cap, no error, identical `tables = ["messages","permits"]`, and `nextExpiry: null`. The remaining meters match: `output_bytes = 12`, `rows_written = 0`.

At examined ceiling zero under Cap, only W1 caps. At ceiling one under Abort, W0 succeeds and W1 returns `E_BOUND`.

The public consequence is stronger with **33 hidden distinct `cof…` words**, followed by a second lane containing an unchanged readable coffee message. W1 reaches the [32-word limit](snapback4/crates/snapback4-core/src/engine/read.rs:402): under Cap, the existing cap causes subsequent candidate processing to stop, suppressing the readable message and its cursor; under Abort, W1 refuses while W0 returns that message.

The retained R1a regression and new N1 tests use two-term conjunctions. Neither constructs this compiler-produced nesting. Flatten conjunctions in evaluation order before selecting the leading pinned terms, and add a compiled three-term complete-envelope regression.

**Finding 10 — the decline is incomplete as written.**

The limitation concerning uncooperative editors is real, but it does not establish the README’s promise that [“a concurrent edit refuses and names the file”](snapback4/packages/snapback4/README.md:1312).

Two concrete failures remain:

- An editor saves `tables.q` after [the final comparison](snapback4/crates/snapback4/src/verbs/fix.rs:43). The next `fs::write` overwrites that save. Final compilation cannot recover it and can report success.
- An editor saves `queries.q` at the existing `observe("write")` boundary, after whole-project validation. Only the destination is subsequently checked, so a stale missing-index diagnostic still edits `tables.q`. This is directly constructible with the existing observer; the tests currently exercise that boundary only for the destination.

Declining atomic coordination is a defensible scope choice **if the contract explicitly becomes best effort**. The disposition and README should acknowledge these residuals rather than claim guaranteed concurrent-edit refusal.

N3’s documentation-only disposition is acceptable as an explicit limitation: neither host supplies the combined retained/current answer, and the documented separate-query workaround preserves both uses. The new tests accurately pin the limitation, including watches and reconnect; they are not repair regressions.

I also accept 8’s decline under the clarified no-adoption/no-row-write contract. Normal WAL coordination does not contradict that contract. The tests establish database/WAL byte preservation, not immutable sidecars.

I found no additional material defect in the SQL projection repair or self-witness simplification.
