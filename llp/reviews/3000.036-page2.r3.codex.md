PAGE2’s exact-witness admission, discovery fence, target-head frontier, shared ordering and v2 capability classification are coherent. The timed slice’s maintained/read-through/union/timeline refusals are also coherent; they need no scope expansion.

Four blocking findings affect timed disclosure:

1. **Future rows do not reserve declared unique keys.**  
   [Collision checking](/home/ccheever/projects/sb4-w10-page2/snapback4/crates/snapback4-core/src/engine/write.rs:709) calls `live_lookup`, which excludes unopened rows. Physical [index keys](/home/ccheever/projects/sb4-w10-page2/snapback4/crates/snapback4-core/src/rows.rs:147) append the row id, so storage does not independently enforce the declared natural-key uniqueness.

   **Counterexample:** A table has `unique ticket` and `not before .opensAt`. At time 0, insert two rows with different ids, identical `ticket`, and `opensAt = 100`. Both collision checks find no live row, and both inserts can succeed. This contradicts §6 and invalidates the publication predecessor proof.

   **Focused fix:** Give collision checks a physical lookup that includes future and pending rows while preserving ordinary expiry handling. Classify an unopened collision as unreadable and return the generic refusal.

2. **Ordinary Quarry updates/upserts cannot address unopened rows.**  
   The binder emits `WriteTarget` for ordinary updates/upserts. Its [resolver](/home/ccheever/projects/sb4-w10-page2/snapback4/crates/snapback4-core/src/engine/write_target.rs:209) uses `lookup_stored`, which delegates to the logical lifetime-filtered lookup.

   **Counterexample:** Store announcement `a` with `opensAt = 100`. At time 50, an authorized `update announcements[a] { opensAt: 200 }` returns `NOT_FOUND`. A by-id upsert takes the insert arm and collides with the existing physical id. The separate legacy by-id write path’s `fetch_write_target` does not repair this Quarry path.

   **Focused fix:** Route `WriteTarget` through physical target resolution. Compute readability separately using lifetime plus read authorization; conditions, returned images and diagnostics must retain their disclosure fences.

3. **Future rule witnesses change pre-boundary results through the authorization walk.**  
   [Witness enumeration](/home/ccheever/projects/sb4-w10-page2/snapback4/crates/snapback4-core/src/engine/witness.rs:136) skips inactive rows without refunding their shared authorization allowance or charging the specified inactive-row guard.

   **Counterexample:** Give tasks the rule `.visible = true or exists grants[.ticket]`. An ascending page encounters 4,500 tasks with `visible = false`, then one visible task. With no grants, the walk can reach that visible task within 8,192 physical visits. Add one future grant per preceding task: every probe remains false, but the extra witness visits exhaust the walk before the visible task. The returned data changes solely because of future rows, contrary to §2.

   **Focused fix:** Step inactive witnesses through the same refund and bounded internal guard used by scans. Ensure batch admission cannot refuse before those refunds are applied.

4. **The publication envelope does not prove whole-commit streamability.**  
   [Admission](/home/ccheever/projects/sb4-w10-page2/snapback4/crates/snapback4-core/src/schema/time_audience.rs:93) counts compact joins. [Stream delivery](/home/ccheever/projects/sb4-w10-page2/snapback4/crates/snapback4-core/src/partition.rs:1412) expands a join into the current group’s rows.

   **Counterexample:** One scheduled membership opens access to a horizon-free group containing 5,000 rows with 4,000-byte bodies. Its publication fits the join envelope, but acquisition exceeds the 16 MiB response limit. Reducing the stream limit cannot split that acquisition.

   **Focused fix:** Bound acquisition separately and explicitly specify refusal plus paged snapshot recovery. Remove the unconditional “always streamable” claim unless admission also bounds expanded acquisition bytes. Safe recovery is sufficient; mandatory product caps are unnecessary.
