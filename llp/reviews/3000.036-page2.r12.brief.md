## 15. PAGE2: ordinary exact memberships, row ids and parent owners

Wave 10 showed that §14's cap requirement excluded the ordinary membership
schema it was meant to serve:

```quarry
table members:
  parent: parents
  principal: principal
  unique parent, principal
  read <- .principal = viewer

table documents:
  owner: principal
  parent: parents
  read <- .owner = viewer or exists members[.parent, viewer]
```

`unique parent, principal` proves that the rule's point probe has at most one
witness for one document and caller. It does **not** prove that a principal has
only finitely many membership rows: fixing `principal` leaves arbitrarily many
`parent` values. PAGE2 therefore does not call this source range statically
capped. It admits the exact total-unique witness and runs the inverted
`members where .principal = viewer` discovery under the ordinary read meter.
The §14 discovery fence already gives the required failure semantics: until
the source range is known complete, no owner or membership target row is
emitted; an `examined`, `index_entries`, `rule_probes` or discovery `steps`
cut, unknown device coverage or incomplete horizon returns an empty
`complete: false` page with no continuation. `heap_bytes` exhaustion retains
the existing `E_BOUND` read refusal. Every
distinct value, evaluated prefix and dynamic lane is sized and charged through
§14's heap ledger before allocation, so an uncapped population cannot allocate
past the request ceiling. Retrying a read-meter cut may complete under a larger
budget or smaller population. It cannot skip an undiscovered lane or turn
partial discovery into a negative authorization fact.

This admission proves a safe plan, not completion for every population size.
For a caller with `K` memberships, discovery and target-head work grow with
`K`; once a read ceiling is crossed the fenced result is empty and incomplete,
so a sufficiently large audience can be temporarily unavailable under the
ordinary budget. A cap is therefore optional for correctness and remains the
product's availability bound. If an app must guarantee that the page completes
within a chosen budget, the writer that grants memberships must enforce a cap
on the fixed enrollment group (for example `principal`). A writer allowed to
grant arbitrary memberships controls `K`; point uniqueness alone does not.

A declared cap is a separate static proof only when all of its grouping
columns are fixed by the discovery scan and null exemption cannot apply. Any
maximum is admissible: a cap above the request's examined ceiling may still
cut safely under the preceding rule. A cap grouped by `parent` does not bound a
scan that fixes only `principal`; a cap grouped by `principal` does. A fully
pinned total unique remains the one-row case. Planner, bound-IR validator and
Lean emitter use these same alternatives:

1. the rule probe selects the intrinsic `id` or one declared plain unique,
   and every other probe component is an exact necessary equality;
2. either that selected point is total, the discovery itself is a fully pinned
   total unique, or a declared cap covers the fixed discovery prefix;
3. the fixed pins decide the source read rule true, and all existing index,
   key, label, descriptor, total-predicate and shared-position checks pass.

A nullable original unique is not a total point proof. It can still use PAGE
when discovery pins every column of a separate total unique, or an applicable
cap bounds its discovery group. For example, nullable `unique parent, principal`
remains the positional rule probe while required `unique principal` bounds the
inverted `principal = viewer` discovery to one row. This does not rewrite the
original probe or its null semantics: a null in that selected point retains the
ordinary result of no witness. If a cap is the only missing condition,
`N_NEVER_COMPLETE` gives the exact declaration to add, using the source's
fixed non-null columns: for the usual shape, `cap 50 by principal`; with no
fixed group, `cap 50`. The note also says that a cap is a stored write
constraint: adding it can refuse existing adoption or later inserts once that
group holds 50 live rows (and physically retained rows where cap validation
requires them), so the author should add it only when it is a real product
limit. The note is withheld when a cap cannot repair the
shape, including multiple row-dependent components, a hidden source, a
non-exact or ambiguous probe, a multi-hop target, incompatible ordering, or a
physical key bound. It must not prescribe code that still cannot plan.

The varying target column may now be the target row's own `id`:

```quarry
read <- .owner = viewer or exists shares[document = .id, principal = viewer]
```

Discovery yields document ids, and each dynamic target lane pins `id`. A
one-row id range is trivially ordered, but it still reports the page's shared
logical position, for example `.at, id`: the row supplies `.at`, and `id` is
the final tie-breaker just as in every other lane. All lanes therefore share
the existing version-4/5 cursor and frontier rules. Before any row is emitted,
the engine opens every discovered id lane and reads its one possible head. If
an `examined`, `index_entries`, `rule_probes` or `steps` cut leaves even one
unfinished lane without a head/`through`, §6's frontier is absent and the page
is empty, incomplete and has no continuation: no returned row can sort ahead
of an unread point. Only
after every point lane is exhausted or has a head can the heap emit the true
`.at, id` prefix. Heap exhaustion remains `E_BOUND` as above. The implicit
`byId` is a valid exact source point too, which admits the parent-owner form

```quarry
read <- .owner = viewer or exists offers[id = .offer, baker = viewer]
```

when `baker = viewer` decides the offer source readable. Its inverted source
scan uses or synthesizes the plain `baker, id` discovery order (within the
existing width, byte, label and ambiguity checks), discovers the caller's
offer ids in the same transaction snapshot, and target lanes pin `.offer`; it
does not require `cap N by baker`. Both forms preserve the rule's exact
witness, snapshot, expiry, device-coverage and meter requirements.

Discovery and target scans use their ordinary lifetime filter. A source row
before `not before` is not a witness and opens no lane; a future target row is
not a lane head and cannot be emitted early. PAGE contributes no lifetime
bypass or separate clock. Source and target opening commits invalidate the
ordinary watched table revisions; expiry joins the existing minimum deadline.
No opening timestamp is exported in the cursor or `nextExpiry`.

The schema requires `branch-membership-v2` when a membership operation uses a
metered discovery source or pins the target row's intrinsic `id`. The optional
operation fact preserves that classification across schema serialization;
the existing `branch-membership-v1` remains required for every membership
merge, so capped §14 plans remain v1-compatible. A v1-only engine or device
refuses a PAGE2 backend by the ordinary capability handshake instead of
applying its older admission validator or downgrading the plan to an eager
merge.

The Lean classifier admits row-`id` targets and the same three source proofs:
a total original point probe, fully pinned total-unique discovery, or an
applicable cap. The fully pinned proof is checked on the discovery pins and
does not replace a nullable original positional probe. Its logical `ownerMembership_sound` and
`ownerMembership_cover` theorems remain about the exact rule leaves; executable
examples add uncapped composite membership, row-id membership and parent-owner
pages. Native, Lean and device differential generators draw the same forms,
including source populations that cross the examined meter and must return the
empty incomplete discovery result, and id populations whose target-head phase
cuts before every lane opens. The language, simulator and both device stores
walk each form through one shared cursor and test overlap de-duplication.
