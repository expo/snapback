## New defects

### N1 — Medium: recovered completion can revert to pending and escape retention

**Location:** [writes.ts:49](snapback4/packages/snapback4/src/writes.ts:49).

Client A remembers a pending write. Client B, sharing its native device store, settles that write. A’s `write(id)` returns the durable terminal receipt, but `read()` neither replaces A’s pending entry nor marks the receipt persisted. After B settles another 256 writes, A reports the completed write as **pending again**, even though its executable outbox entry is gone.

The in-memory reproduction returned `sent`, then `pending` after eviction. Repeating this for 600 observed completions left **600 pending Map entries and zero tracked terminal entries**, despite durable history remaining at 256.

**Smallest fix:** On durable recovery, mark the ID persisted and pass the receipt through `remember()` before returning it. Add a two-owner regression asserting terminal observation, bounded memory, and `undefined` after eviction.

### N2 — Medium: an unrelated `require` erases a provably minted ID

**Location:** [inserts.rs:121](snapback4/crates/snapback4-lang/src/bind/residency/inserts.rs:121).

Every non-binding statement clears all minted aliases. On F4’s fully synced private likes table:

```quarry
mutation add(postId: id, allowed: bool):
  chosen = new
  require allowed else NOT_ALLOWED
  insert likes { id: chosen, postId, principal: viewer } if absent
```

The `require` cannot reassign `chosen`, but it deletes its mint fact. The compiler consequently reports that the insert never predicts because `byId` cannot prove absence. When `allowed` is true, the runtime still recognizes the minted ID and predicts the insert through the covered secondary unique key.

This follows directly from the lowering and analysis; I did not execute this Quarry case. The new alias tests omit an intervening `require`.

**Smallest fix:** Preserve mint facts across statements that cannot reassign them; invalidate aliases on relevant assignments or uncertain control-flow writes. Add this case to the diagnostic/runtime agreement test on both stores.
