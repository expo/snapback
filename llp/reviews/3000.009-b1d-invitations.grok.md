## Policy / security / atomicity (reachable)

- **Owner admin bootstrap, immutable owner.** Create inserts owner + admin membership + audit in one mutation (`147-156`). Owner cannot be demoted, removed, or leave (`207-233`); peer-admin removal is owner-only (`223`).

- **Hash is not the token.** Preview/accept compare `sha256(rawToken)` to stored `tokenHash` (`131`, `178`). Digest-as-token is refused in tests (`468-474`).
- **Fresh proof is mutation/query policy, not the read rule.** Metadata may be read with a stale-but-verified profile (`43`, documented). Preview/accept require `proofExpiresAt > now` (`134`, `181`) and `expiresAt > now` (`130`, `177`). That matches `identityOwnProfileEligibility` in `schema.q:70`.

- **Accept is one transaction:** pending→accepted, reservation delete, optional member insert, live `organizationMemberCounts[org] <= seatLimit`, audit (`174-192`). Capacity failure is after the tentative member insert, so a refusal rolls all of it back. Existing member skips insert and the seat check (`187-190`).
- **Expiry alignment.** Invitation uses strict `expiresAt > now`. Reservation `expire at .expiresAt` is `expiresAt <= now` (`schema.rs:267-268`). At the stored instant the unique `(organization, recipientEmail)` key is logically free; unique insert skips expired siblings (`write.rs:46-48`, `read.rs:140-162`).
- **Cross-tenant / non-escalation.** Org reads are membership-or-service (`10`). Non-members hitting record see `ORGANIZATION_NOT_FOUND` (`159-160`); members who are not admin see `ORGANIZATION_ADMIN_REQUIRED`. Query `require`s collapse missing-org and not-admin to the same code, so they do not distinguish existence. Other-tenant roster is denied (`384`). Service is the only writer of policy and capacity (`141-145`, `236-241`).
- **Projections.** `adminInvitations`, `invitationMetadata`, `invitePreview`, and audit omit `tokenHash` / `rawToken`. The page parser treats extra keys, including `tokenHash`, as unsafe (`130-134`, `196-198`).
