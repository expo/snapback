## Findings

### 1. High — A horizon device can delete a required zero-sum candidate

**Location:** [engine/maintains.rs:164](snapback4/crates/snapback4-core/src/engine/maintains.rs:164), with the occupancy check at line 131.

**Scenario:** Declare an expiring, synced source with `sync last 1`, and:

```quarry
maintain totals: sum posts of score where .selected by owner, day(.at)
  read <- .owner = viewer
```

All three selected rows belong to the same owner/day:

| Row | Score | Expires | Acquisition order |
|---|---:|---:|---|
| a | +1 | 3000 | oldest |
| b | −1 | 1000 | middle |
| c | +2 | 3000 | newest |

At time 500, the device acquires only `c`, plus the authoritative aggregate value `2`. At time 600, predict deletion of held row `c`.

**Implementation result:** Both hosts calculate the new total as zero. The server finds `a` and `b` and retains the candidate. The device’s `aggregate_source_present_inner` finds no local source and deletes the target. It never marks that negative occupancy result unknown.

At time 1000, the server’s live value becomes `1`. The device has no target candidate; its scalar lookup returns `0` with `complete: true`, bypassing the source-horizon check inside `live_aggregate`. This affects both stores.

**Required:** Partial source history cannot prove that a zero-sum candidate should disappear.

**Smallest fix:** When zero retention requires an occupancy decision, accept a local positive witness, but treat absence as unknown unless source-group coverage is complete. Otherwise queue without a predicted row.

### 2. High — Hidden-write prepayment exempts an unbounded source scan

**Location:** [engine/write_target.rs:272](snapback4/crates/snapback4-core/src/engine/write_target.rs:272), [engine/maintains.rs:131](snapback4/crates/snapback4-core/src/engine/maintains.rs:131).

**Scenario:** An expiring private source has only `byId` and its expiry index, `update <- allow`, and a hidden target:

```quarry
maintain totals: sum posts of score where .selected by owner
  read <- deny
  online only
```

Store one selected row of score `1` and 9,000 unselected rows. Blindly update the selected row to `selected: false`.

**Implementation result:** The reservation charges four aggregate examined units and enables `maintain_prepaid`. The resulting zero sum calls `aggregate_source_present_inner`. Because there is no computed key, no contribution index was generated; `source_scan` falls back to `byId`. It examines all 9,001 rows while `charge_maintain` suppresses every examined/step charge. The write can succeed despite exceeding the default 8,192 examined ceiling.

The nested 32-source-row scratch reservation is also skipped under prepayment, although the outer reservation budgets only two source images.

**Required:** A conservative reservation must upper-bound the work and temporary memory it exempts.

**Smallest fix:** Give filtered expiring maintains a selected-source contribution index too, and make physical occupancy a one-entry lookup. Include its actual worst-case buffer/work in prepayment. Do not fix this by charging a secret-dependent fallback after lookup.

### 3. High — Public subset inheritance produces falsely complete aggregate reads

**Location:** [bind/schema.rs:25](snapback4/crates/snapback4-lang/src/bind/schema.rs:25), [residency.rs:72](snapback4/crates/snapback4-lang/src/bind/residency.rs:72).

**Scenario:** A public source uses `sync to .owner`, without a horizon. A filtered maintain groups by bare `owner`, has `read <- allow`, and inherits that subset audience. Bob has one selected source; Alice’s device has completed acquisition.

Query on Alice’s device:

```quarry
return totals['bob']
```

**Implementation result:** The target is classified `held` solely because it has horizonless sync. Alice never received Bob’s aggregate. The missing target returns scalar zero with `complete: true`; a global group page similarly omits Bob while claiming completeness.

The guard against this inference exists for *upsert absence*, but not ordinary aggregate reads. See [engine/read.rs:295](snapback4/crates/snapback4-core/src/engine/read.rs:295).

**Required:** §20.9 permits local completeness only for a statically source-complete delivered group.

**Smallest fix:** Classify inherited public-subset reads as server/unknown unless their keys prove delivered-group coverage. Apply the same runtime coverage rule to scalar misses and pages. A conservative server classification for these targets is sufficient initially.

### 4. Medium — Expiring value indexes are rejected only by the Quarry binder

**Location:** [schema.rs:888](snapback4/crates/snapback4-core/src/schema.rs:888). The only expiry/value-index rejection is [bind/schema.rs:549](snapback4/crates/snapback4-lang/src/bind/schema.rs:549).

**Scenario:** Start with a valid non-expiring sum maintain indexed by `value, id`. Through the raw schema API, add expiry and its source index, then call `Engine::adopt`.

Use these groups:

- A: `+100` expires at 1000; `+1` expires at 5000.
- B: `+2` expires at 5000.

**Implementation result:** Core schema validation accepts the combination, and adoption publishes it. At time 1500, before sweeping, stored order is A=`101`, B=`2`. `last 1` visits A first, recomputes it to `1`, and returns A. The correct winner is B=`2`.

**Required:** Schema admission and adoption must reject this combination, regardless of whether the schema passed through Quarry.

**Smallest fix:** Add the cross-table expiry/value-index prohibition to core `validate_maintain`, preserving the binder’s useful diagnostic. Cover initial schema admission and successor adoption.

### 5. Medium — Maintain cursors bind neither prefix values nor generation

**Location:** [cursor.rs:22](snapback4/crates/snapback4-core/src/cursor.rs:22), validation at line 99; used by [engine/read.rs:465](snapback4/crates/snapback4-core/src/engine/read.rs:465).

**Scenario:** Obtain a cursor from:

```quarry
counts['alice'] after c first 1 by byGroup
```

Reuse it with owner `'bob'`. Alternatively, obtain a bucket cursor, adopt a changed bucket duration while retaining the same target/index/output types, and reuse it.

**Implementation result:** Both tokens are accepted. The token contains table, index, direction and typed suffix values, but no prefix values or generation. It silently seeks into the other group or rebuilt definition and can skip valid rows.

**Required:** §20.9 explicitly binds cursors to index, prefix and generation. Ordinary concurrent value changes within that generation may still move rows between pages.

**Smallest fix:** Encode and validate the evaluated prefix and active generation. Preserve cursor validity across ordinary value changes, while rejecting scope changes and adoption.

## Missing acceptance cases

- Both-store prediction of the signed-zero/horizon history in finding 1, including the subsequent clock tick.
- Hidden filtered **sum** removal with thousands of excluded sources; independently count physical scans and peak temporary ownership.
- Public subset aggregate lookups/pages for the viewer, another owner and an unpinned scope.
- Raw-schema rejection of expiring value indexes during creation and adoption.
- Cursor reuse across prefixes and generations, plus continuation using the **old cursor** after a winner changes or disappears.
- Both-store fold comparisons for updates, deletes, upserts and overflow, including target index contents and partition events. Current device maintains tests chiefly exercise count insertion, unknown bases and revocation.
- Rank expectations derived from source rows. Several rank tests sort the maintained target itself, so they verify ordering without independently verifying its totals.
