## 1. MATERIAL — §5: v4/v5 tokens do not bind lane prefix values, so changing filter args (or the viewer) between pages silently skips rows with `complete: true`

- Checked `snapback4-core/src/engine/read.rs:1344` (`next_cursor`), `branch_merge.rs:39-58` (token decode on open), `read.rs:641-645` (per-lane scope check), `cursor.rs:42-47` (`check_variant`), `ir.rs:477-485` (descriptor).
- `next_cursor` mints scope as `{variant, generation, prefix: page.prefix or []}`; both merge record sites pass `prefix: None` (`branch_merge.rs:67`, `read.rs:1469`). So a branch token carries generation plus the argument-*presence* variant, but **no prefix values**. On continuation the outer check is only `check_variant` (presence) plus `check_descriptor` (table/index/order/suffix) — arg *values* are never compared. The per-lane scope check that would catch this (`read.rs:641-645`, generation + evaluated prefix) is explicitly skipped when `scan.merge_site.is_some()`, which is true for every branch lane (`views.rs:51`); branch lanes also clear `after` (`branch_merge.rs:85`), so no lane-level cursor check runs at all.
- Concrete failing scenario, using the device test's own schema (`snapback4-device/tests/branch_merge.rs:41-60`, `query two(a: int, b: int, c: cursor ?)` over membership-guarded `cards`): page 1 with `(a=1, b=2)` returns the top rows and mints `next` = shared position `(at=6, id)`. Page 2 with `(a=9, b=2)` and that token passes both checks (same plan, same presence). The `board=9` lane opens on its new range but resumes strictly after the stale position, so every matching `board=9` row at/above it is never read — while lanes that are uniform report the page `complete`. Same for a replayed token across viewers: party pins (`viewer`) live in lane prefixes, which are likewise uncompared, unlike direct pages where `scope.prefix` mismatch refuses with `Scope`. 0.4.23 single-index pages refuse this shape (`cursor: ... different prefix or generation`); the merge silently returns wrong rows.
- The Lean model is blind to it too (`parseCursor` is a bare key; `lookahead`/`afterCursor` are purely positional), so the difftest oracles cannot catch it.
- Smallest fix: carry the evaluated per-lane prefixes in the v4/v5 scope (new optional `CursorScope` field so older decoders still refuse by version/canonical re-encode), and in `merge_branch_lanes` after `prefix_values` (`branch_merge.rs:86`) compare each lane's prefix — mismatch (or generation drift) → the existing `E_CURSOR_INDEX` restart error. Same check belongs on the eager arm's per-lane translation (`read.rs:1424-1436`). Note the `merge_site` skip at `read.rs:641` predates this RFC for older merge kinds; scoping the fix to branch tokens is enough to unblock this RFC.

## 2. MINOR — §9: Lean's same-probe arm ignores index and equalities, over-approximating the core's `implied_by`

- Checked `Eval.lean:295-297` vs `rules.rs:470-476`. Core admits the target-carries-same-probe case only with same table *and* index *and* key and disjunct-equalities ⊆ guard-equalities; Lean checks `t' == t` and disjunct-key ⊆ guard-key, ignoring index and equalities. A self-probe rule whose disjunct probes a different index with a subset key is usable in the model but rejected by `covering_grant`, so the engine falls back to the single read (incomplete for non-holders) while the model reports merged-complete. Exotic and undrawn by the generator; fix is to mirror `implied_by` in the Lean arm.

## 3. MINOR — §9: Lean's `party?`/`branchParties` lack the principal-column check

- Checked `Eval.lean:308-317` vs `intent_branches.rs:204-213` (`TypeKind::Principal` required). A rule whose load-bearing `.col = viewer` disjuncts are non-principal (bindable — `rule_operator.rs:29` restricts operators, not column kinds) with all such columns pinned is merged-and-complete in the model but declined by the planner (`parties` empty → `None`), i.e. model-complete vs engine-incomplete. Data-safe (identical rows; `complete` flag only), undrawn, latent oracle noise. Fix: thread the table decl into `party?` like `eligiblePin` already does.

## 4. MINOR — §2/§9: Lean `Expr.total` lacks `in`, which the engine admits

## Checked and found sound

- **Totality (§2.1):** the union argument holds for admitted syntax. `and`/`or`/`not` require strict `Ty::Bool` (`expr.rs:159,470-472`, `types.rs:83-85`); nullable `<`-family operands get `!= null` guards (`expr.rs:600-610`); optional `in` domains are bind errors (`control.rs:514,524`) while admitted `in` lowers to a loop over typed arrays with infallible `Eq`; field-on-null yields `Null` (`runner.rs:836,846`); arithmetic/calls/reads are excluded from `total()`. Short-circuit reordering between original and branch filters therefore cannot change error behaviour.
- **Auth before filter:** per-row authority projection (`read.rs:1138`) precedes filter eval (`1149-1177`), and `last_rule_visible` (`1148`) only covers rule-visible rows, so the frontier never positions at an unreadable row; frontier values are order-columns plus `id` of rows the caller could pin-read directly — no disclosure beyond a direct page.
- **Cut contract:** cuts (continuable meters) can only land during lane opening — a pre-cap refill implies a drained lane, which implies a full page (each duplicate pop pairs a same-page emission, so drain ≥ `take+1` pops forces ≥ `take` emissions), so the refill path is unreachable pre-return and guarded post-cap; every cut page is empty; post-cap emission is gated by the least unfinished `through` (`branch_merge.rs:141,192-199`), dropped buffers are strictly past the frontier and re-read on resume — no skip, no duplicate (the full-page return uses `last`, where all ≤ `last` was popped).
- **Cursors:** v4/v5 picked exactly for branch descriptors with canonical re-encode refusal (`cursor.rs:84-86,113-130`); foreign same-table tokens → `E_CURSOR_INDEX` on both lazy and eager arms; older engines refuse by version; 8-lane descriptors fit the 4 KiB bound; descriptor lane order is deterministic.
- **Grants:** one verdict, full-rule static probe charge on either outcome (`read.rs:212-221`); `merge_grant` is taken by the lane's own `scan_consumed` before any filter runs, with no nested reads possible inside; held grant reads the whole-`where` lane alone (a superset — §2.1), false grant skips the lane without marking non-uniform; devices decide seats and report unknown on probe guards (`branch_merge.rs:107-112`).
- **Fallback and guards:** binding failure with a grant lane rebinds the grant lane's own planned read (`views.rs:109-113`) — structurally 0.4.23's plan including its LN page guard; LN's `parent_guards` expectation change (non-holder now `complete`) is the intended case-2 improvement with identical rows; case-1 × case-2 products distribute exactly, in planner, runtime open order, and Lean's `bases × ps + grant`.
