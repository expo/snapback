### Residency boundary — not coherent as specified

1. **Row-local fragment undefined.** "Only row fields, viewer, literals and Boolean/equality" contradicts §22.1 "existing row-read expression grammar, including readable unique `exists` probes". Probes, `not`/null-unknown, ordering on own columns, `created`, three-hop references are either in or out. A rule `.owner = viewer` where `.owner` is itself protected/private, or `exists` with a key containing a protected column, is not decided.
2. **Per-recipient log image vs shared partition log.** Current substrate replicates the viewer's declared partition via a shared log plus snapshot pages. "Same projection applied to every snapshot and log put for its recipient" plus "shared log image contains no protected cells; serve-time re-fetches current row" implies either per-viewer log writes (fanout/partition change, contradicting "no new partition audience or unbounded fanout") or a stripped shared image plus per-delivery re-projection with TOCTOU/version skew. No atomicity rule for "owner/selector change replaces/redacts atomically with row update" across log vs serve path.
3. **Offline non-forgetfulness admitted but not bounded.** Row-local history "cannot be retroactively forgotten by an offline client" is honest, but then revocation/addition of a row-local rule has no offline effect, no re-bootstrap/delete rule, and no `leave`/retention interaction. The proposal claims atomic redaction and unforgettableness in the same paragraph.
4. **Server-witness residency reuses row-rule language without cell-level classifier.** "Read sites on that table are server-class" promotes whole-table reads because one cell needs a witness. That is either a large availability regression (every query on the table goes server-only) or, if intended per-cell/per-site, requires a new cell-level residency classifier, SDK fallback matrix, `held` certification rule, and prediction-queue rule that do not exist. "No extra call or policy branching" in hooks is incompatible with "offline explicitly unavailable, never complete".
5. **Capability too coarse.** Mandatory `column-read-v1` for any column rule, with old devices refusing "before executing any plan", forces row-local-only schemas to break old devices. No negotiation per fragment, no mixed-version table rule, no byte-stability proof. "New schemas without column rules retain prior bytes" does not cover add-row-local-rule vs add-probe-rule.

### Claimed supported compositions that leak or are unsound

6. **Dual encoding leaks presence.** "Denied cell absent from whole rows and spreads, not stored null" but "explicit field selection returns null through optional-field instruction" plus "allowed optional null remains present as null" creates two observables for hidden (absent vs null) depending on shape. `has-field`/`spread`/`RowShape` vs scalar `= null` distinguish hidden from true-null unless every path is normalized — proposal explicitly says they need not be distinguished in scalar expressions. Two-world noninterference must cover point/page/projection/return/asset, but §22.6 does not name the absent-vs-null distinguisher.
7. **Predicates/count over disclosed null.** "Predicate over disclosed optional sees null when hidden" plus "plain row count remains legal" means `where .notes = null` / `!= null`, `count`, grouping by the disclosed column, and in-memory sort/group partition hidden-non-null together with true-null. Row existence is already row-audience, but nullness/value-equality of a hidden cell becomes observable through counts/groups. The proposal calls this safe without a noninterference statement for null-collapsed aggregates.
8. **In-memory sort/group hand-wave.** "Sorting/grouping an already-projected list is safe" ignores group-size/ordering oracles when the adversary can write known values under row-write authority (see #11) and observe the null-group size.
9. **Read-through capture.** `read through` inherits row authority, column change "absent from capture identity", no `E_READ_THROUGH_ADOPT`. Captured parent inputs "travel with sync images but never appear in query rows". If a parent authority/capture field is later column-protected, either capture still carries it (leak through sync envelope despite "refuses as structural use" applying only to new declarations) or capture goes stale without re-adoption. Existing children "continue to inherit the same row rule" does not address in-flight captures.
10. **Live probe tracking claim.** "Server live queries track every column-rule probe dependency" is a new cell+policy invalidation index. "No new result cache, partition audience or unbounded write fanout" contradicts grant/role/parent-change invalidation "even if the data row is unchanged", plus `read through live` parent-write fanout already exists.

### Disclosure-path gaps

11. **Writes clobber protected cells.** "Ordinary writes of supplied values still allowed under row write authority; read protection is not immutability", combined with "mutation transition rules may not inspect protected values", means any row writer can blind-overwrite a cell they cannot read, with no field-authority equivalent. Existing `written_by` owner-private has patch authority + defaults; conjunction with it is stated but blind-write vs owner-patch interaction, defaults for column-protected fields, and `immutable`/`AppendOnly` interplay are missing.
12. **Assets/meter underspecified.** "Owning-row read AND asset column effective authority" does not say how asset-list columns, thumbnails, range/416, view-once, foreign-id placement, and meter/ledger fields compose. "Retain `E_ASSET_UNKNOWN` and meter" needs a meter-field noninterference rule; meter is itself a disclosure channel.
13. **Maintained/derived refusal incomplete.** Refusing protected inputs in filter/group/sum/computed keys is right, but row-keyed counts, receipt families, timelines, search indexes, vector/aggregate copies, recorded attribution, and `sync scope` inference beyond the named list are not enumerated. Current `field_authority::validate` and `observers.rs` pullback have narrower, different rules; no migration for existing private-field aggregates.
14. **Structural-use repair is not implementable as stated.** "Repair naming an ordinary public key or separate entity" cannot be generated for inferred indexes, raw-schema admission, cursor/order/search, lifetime, attribution, sync scope, and rule inputs uniformly. Cursor/order/search on disclosed-optional (null-collapsed) needs an explicit rule: refused or null-ordered.
15. **Probe/value-guarding recursion.** "May not depend on protected values, including via target probe keys or residual equalities" needs a decision procedure over inferred equalities, `exists` provenance, `created` probes, and helpers. Current `column_reads.rs` already declines large classes as unsupported; the proposal turns those declines into hard `E_COLUMN_READ` without defining the checker.

### Types, releases, invariants/audit

16. **Honest-optional types breaking and incomplete.** Making every protected property optional for every audience (including required) is honest but breaks old servers/clients: old generated types say required, new runtime omits. `emit.rs`/`compat.rs` currently optionalize only private/added/before-private; views, spreads, `RowShape`/`RowObject`, `WriteRows`, `BaselineRows`, and compatibility-report detection of "newly optional" are not specified. "No extra policy branching" in `useQueryData` is incompatible with absent-vs-null handling.
17. **Adoption/rollback.** "Normal schema adoption; clients rebootstrap on changed generations" does not address residency change (row-local ↔ server-witness) mid-release, `held` query certification change, dormant-cell (`v2-only protected column becomes dormant cell on visible v1 row`) semantics and DORM boundary, or release-preview warning content. Rollback "restores audience and warns" restores broader disclosure — the confidentiality warning needs a hard gate, not advisory.
18. **SEC3/audit.** "Proved against row AND column AND owner-private" needs the conjunction semantics under negation-unknown/missing-probe, plus proof-obligation retention for unsupported observers. "Audit prints effective audience and residency" duplicates `audit.rs` exposures without defining per-cell audience rendering, grant-writer expansion for column probes, or 1:1 side-table advisory precision (parent ref + unique parent key misses composite/soft/reference-action cases; advisory-only does not satisfy "replacing side tables" commission — no cutover/dual-write/backfill/delete-side-table plan).
19. **Required evidence unmeasurable.** Parser/group/duplicate, bypass, two-world point/page/projection/return/asset (with meter), count/exists/predicate pairs, snapshot/log/redaction + fallback on both device stores, maintained refusals, read-through adoption/rollback, proof/audit agreement, packed guide, five wave-19 migrations, 200-schema zero-false-refusal survey, suites/differential/device/Lean/Linux/wasm/docs/ref-check — lists artifacts without oracles, thresholds, seed/window, device-store matrix, or what "implemented" means when `column_reads.rs`/`observers.rs` retain unsupported sets.

The residency split (online server-witness cells, syncable row-local cells) mirrors non-invertible row rules in intent, but as written the fragment, log-vs-delivery atomicity, whole-table promotion, type/presence encoding, blind-write, capture, live-invalidation, and release stories are incoherent or leak by the proposal's own supported compositions.
