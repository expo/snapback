## What holds (source)

**Provider protocol stays in the Node helper, not the engine.** `oidcHandlers` is a packaged adapter over ordinary generated actions (`identity.ts:193-195`). Generated `server()` is a pass-through to `startServer` (`emit/server.rs:46`), so the WeakMap identity on the helper function object is preserved.

**No public mint / service client on `ServerContext`.** `IdentityRuntime` is documented as absent from `ServerContext` (`server-private.ts:4-11`). Ordinary handlers are invoked as `(args, ctx)` only (`server.ts:135-137`). `identityRuntime.mint` always hashes `issuer`+`sub` into `oidc:` (`identity-runtime.ts:67-69`, `identity-principal.ts:3-10`); it cannot mint `service:`, `guest:`, `user:`, or `dev:` because `custom_session` rejects those prefixes (`identity.rs:493, 513-516`). Adjacent `/auth/session` still requires a live **service** bearer (`serve.rs:1059-1077`, `serve.rs:400-414`). That door is pre-existing; this delta does not put it on `ctx`.

**Capability boundary.** Helper executors live in a module WeakMap (`server-private.ts:18-31`). Direct calls throw (`server-private.ts:23-25`). Wrapping `oidc.begin` in a new function makes `identityExecutor` miss and takes the thrower path — fail-closed. Package `exports` has no `"."` and no `./server-private`; `./identity` is a separate Node entry (`package.json:9-53`). `snapback4/server` imports `identity-runtime.ts` (Node `crypto` + HTTP) and **not** `identity.ts`, so `openid-client` is not on the server/client/web/react graphs. `src/client.ts`, `src/web.ts`, `src/auth.ts`, `src/react.tsx` do not import identity.

**Fixed issuer, verified `iss`/`sub` principal, no email linking.** Config requires exact issuer/redirect URLs, HTTPS unless explicit loopback HTTP (`identity.ts:124-140`). Discovery metadata must echo that issuer and expose HTTPS (or loopback HTTP) auth/token/JWKS plus `code` + `S256` (`identity.ts:160-167`). Principal is `oidc:` + SHA-256(`snapback4:oidc-principal:v1` ‖ issuer ‖ `sub`) (`identity-principal.ts:3-10`). Email is stored only as optional metadata (`identity.ts:188-190, 284-287`); there is no email lookup.

**State / nonce / PKCE / browser binding (source path).** Begin persists `state`, `nonce`, S256 verifier, binding hash, admitting principal, config fingerprint, TTL (`identity.ts:222-228, 237-241`). Complete refuses provider `error`, missing code, or malformed `iss` **before** lookup (`identity.ts:246-249`). Ownership, fingerprint, expiry, and timing-safe binding are checked **before** discovery/token (`identity.ts:253-256`). Claim is idempotent for the same invocation and exclusive otherwise (`schema.q:41-48`; helper `identity.ts:257-265`). Exchange passes `expectedState`, `expectedNonce`, `pkceCodeVerifier`, `idTokenExpected: true` (`identity.ts:276-278`). RFC 9207 `iss` is copied onto the reconstructed callback URL (`identity.ts:272-275`).

**Audience / azp / expiry (helper re-check).** After `tokens.claims()`, `minimalClaims` requires exact issuer, `aud` includes client id, `azp === clientId` when present, `azp` required when `aud` has multiple, integer `iat`/`exp`, `iat` not > now+60s or < now-600s, `exp` in the future (`identity.ts:177-187`). Signature / `alg` / nonce are **not** re-checked here; they are delegated to `openid-client` with `enableNonRepudiationChecks` (`identity.ts:199-203, 276-278`).

**Transaction recipe is service-owned.** Table read/insert/update/delete and the three mutations require `viewer = 'service:worker'` (`schema.q:22-25, 37-55`). Unique `beginInvocation` / `state`, `expire at .expiresAt`. Helper transaction I/O uses the service token, not the guest lease (`identity-runtime.ts:35-38`) — necessary because `ctx.mutate` is the caller. Actions themselves are ordinary generated actions with declared `OIDC_CLIENT_SECRET`.

**Mint step does not persist the token.** Durable mint result is `{ minted, principal, kind, expiresAt }` (`identity.ts:297-298`). Live `minted` is required to return the Session; mismatch → `E_OIDC_HANDOFF` (`identity.ts:300-303`). Uncertain mint throws `Retry` (`identity-runtime.ts:41-43`); `ctx.step` without `reconcile` parks on the next claim (`server-steps.ts:63-68`; core `steps.rs:64-68`).

**Malformed input fail-closed (source).** Control characters rejected (`identity.ts:93-94`). Non-HTTPS production and non-literal-loopback `localhost` refused at config (`identity.ts:134-140`; test `identity.test.mjs:343-348`). `error` set or missing code → `E_OIDC_CALLBACK` without token POST.

**Docs truth.** SERVER.md labels B1a preview, states `/auth/session` is not B1b, parks uncertain mint, `E_OIDC_HANDOFF` does not remint, B1b will not resume B1a parks, Google unrun, `why --values` prints stored callback/Session (`SERVER.md:43-70, 187-194`). ## Findings

### 1. Uncertain authorization-code exchange is recorded as a durable failure, not parked

**Severity:** medium (availability / §5.2 uncertainty handling). **Fail-closed for security.** Not the B1b mint gap.

Failure path:

1. `complete` admits `ctx.step("oidc.exchange", …)` (`identity.ts:267-280`).
2. `authorizationCodeGrant` throws for **any** reason: hostile JWT, `invalid_grant`, timeout, DNS, abort, lost response after the code was consumed.
3. The `catch` returns `{ ok: false }` as a **successful** step result (`identity.ts:279-280`).
4. `server-steps.ts:71-73` POSTs `/steps/oidc.exchange/done` with that result.
5. Handler throws `E_OIDC_EXCHANGE` (`identity.ts:282`), a `ServerError`/`GiveUp`, so the worker records `retry: false` (`worker.ts:173-174`).
6. A later attempt replays the completed `{ ok: false }` and never hits the token endpoint again.

Contrast with mint: fetch failure is `Retry` (`identity-runtime.ts:41-43`); the mint step is **not** completed; the next claim parks (`steps.rs:64-68`). That mint behavior is the documented B1a dependency. Exchange does the opposite: it treats unknown IdP I/O as certain failure.

Hostile tokens **should** be terminal. Transient token-endpoint I/O and cancellation during the grant should park (LLP 3000.009 §5.2 / §11.5), not settle `ok: false`. User impact: a dropped packet after the IdP consumed the code, or a deadline during the grant, permanently burns the login; a new `beginOidc` is required. No extra mint and no second token use.

Protocol-double tests only assert `E_OIDC_EXCHANGE` for hostile JWT/`invalid_grant` (`identity.test.mjs:279-307`). They do not discriminate uncertain I/O from verification failure.

### 2. IdP HTTP is not bound to the invocation abort signal

**Severity:** low. Cooperative cancellation is already the §5.1 rule; this is a missing pass-through to the one SDK the helper uses.

`discovery(…, { execute, timeout: 10 })` and `authorizationCodeGrant(…)` (`identity.ts:201-203, 276-278`) do not receive `ctx.invocation.signal`. `identity-runtime` **does** pass `lifetime.signal` for `/q`, `/m`, `/auth/session` (`identity-runtime.ts:39`). `server-context.ts:9-18` additionally wraps core fetch in `untilAborted` because some test transports ignore `signal`; `identity-runtime` does not.

Failure path: deadline/cancel fires during `authorizationCodeGrant`. The grant can still complete and consume the code; the helper then hits `assertActive` or `throwIfAborted` (`server-steps.ts:70`, `server.ts:127`) and fails/parks as in finding 1. No session is returned after abort (`server.ts:125-128`). Not a mint bypass.

`timeout: 10` cannot be interpreted from this checkout (no `openid-client` sources). If it is milliseconds, discovery is unusable; if seconds, it is a bound. Residual until the installed package is read.

### 3. `minimalClaims` does not re-check nonce or signature

**Severity:** low (defense in depth). Not a demonstrated fail-open **if** `openid-client` honors `expectedNonce` + `enableNonRepudiationChecks`.

`minimalClaims` (`identity.ts:177-187`) re-checks `iss`/`aud`/`azp`/`iat`/`exp`/`sub` shape only. Nonce and JWS are only arguments to `authorizationCodeGrant` (`identity.ts:276-278`). Removing `expectedNonce` or `enableNonRepudiationChecks` would not be caught by `minimalClaims`.

Reported protocol-double tests include `wrong-nonce`, `none`, `wrong-alg`, `unknown-kid` (`identity.test.mjs:282-293`). Those tests are the load-bearing check. I did not execute them. The `wrong-alg` HS256 case signs with a **wrong** HMAC key (`identity.test.mjs:43`), so it does **not** prove rejection of HS256 MAC with the confidential client secret. That proof is entirely the library’s non-repudiation flag, whose implementation is not in this tree.

### 4. Unknown `state` vs bad binding is a small existence oracle

Wrong `state` → `byState` is `null` → `E_OIDC_TRANSACTION` (`identity.ts:252` + `106-120`). Wrong binding / foreign principal / expiry → `E_OIDC_CALLBACK` (`identity.ts:253-255`). State is high-entropy (`randomState`, length ≥ 20). Not a practical account takeover. Unifying the code would remove the oracle. The protocol-double asserts the split (`identity.test.mjs:253-256`).
