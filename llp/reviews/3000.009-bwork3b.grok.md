## Received substantive public answer, verbatim

READY

The B3b generated arm matches the frozen contract: declaration-bound claims, a narrow effect context, current-lease status, drain-then-one-fresh-status before `/done` or `/failed`, and no top-level settlement after lost/uncertain authority or parked steps. Legacy `runWorker` claim/handler/poll shape stays separate.

No material findings.

The generated executor keeps handler completion as a tagged result or error, then `confirm()` quiesces any in-flight periodic check (loss callback still runs) and takes one bounded fresh status before either settlement kind. Early return is only for already-latched loss or `E_STEP_PARKED` / `E_STEP_RESULT`. `close()` runs in `finally` and aborts the retained signal. Stale declaration digest refuses before handler/settlement. `E_EFFECT_LEASE` reporting is opaque. GiveUp records `retry: false`; tokens and declared secret names/values are redacted. Tests for those gates are not tautologies: they pin claim-once, status counts, settlement paths, and real 10s ignored fetch/body bounds.

### Nonblocking advisories

- `packet/candidate/snapback4/packages/snapback4/src/worker.ts:332-338` — After a successful handler and `confirm()`, a thrown `/done` transport error is turned into `/failed` `{ retry: true }`. Scenario: mail already sent, `/done` resets after the core committed `sent` (or before it landed). Actions leave the lease to expire; this generated success path can requeue and run the handler again if `/done` did not commit.
- `packet/candidate/snapback4/packages/snapback4/src/server.ts:198-201` and `server-steps.ts:71-72` — Invalid/oversized step JSON throws `E_STEP_RESULT` before `/done` or `/park`, then skips parent settlement.
