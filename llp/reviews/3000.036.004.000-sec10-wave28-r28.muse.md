## F1: residual projection admits olds the projected atoms falsify

In [stage_columns.rs](/home/ccheever/projects/sb4-b26-sec10/snapback4/crates/snapback4-lang/src/bind/security/derived/stage_columns.rs) (`collect`, residual path), when full `projects()` is `None`, known atoms are substituted, the result is simplified, and the code returns `!related` without checking whether simplification already produced literal `false`. A guard such as `require d.material = 'steel' and viewer = 'service:worker'` with destination `'steel'` therefore "admits" `old = 'wood'`: substitution yields `false and <role>`, which folds to `false`, the residual scan finds no same-field member, and `!related` returns true. The guard is definitively false for that old, so this is not an unknown — it is a falsified admission.

Section 12 allows classification only for "a changing prior value allowed by the projected selected-field guards". The projected guard here demands `'steel'`; `'wood'` is not allowed by it. The code is strictly more permissive than that sentence, and the in-code comment ("an opaque condition involving this field is not evidence of a possible change") points the same way. Fully projected `Some(false)` excludes, but partially projected false admits — inconsistent.

Consequence: two role-guarded self-assignments to different states (e.g. `keepSteel`/`keepWood` with an added role conjunct, each writing back its own guarded value) accumulate two observed states and establish a spurious workflow discriminator. That expands the admission-omission surface in `admissions()` and the sibling-relax surface in [workflow.rs](/home/ccheever/projects/sb4-b26-sec10/snapback4/crates/snapback4-lang/src/bind/security/derived/workflow.rs). No fixture covers this shape; the passing tests use pure guards or genuine transitions, where a true witness exists independently. Minimal fix: return false when the substituted expression simplifies to literal `false`, else `!related`.

## F2: third-arm consumer needs neither a real change nor enforcement

The new third disjunct in `admissions()` ([stage_columns.rs](/home/ccheever/projects/sb4-b26-sec10/snapback4/crates/snapback4-lang/src/bind/security/derived/stage_columns.rs)) suppresses the freeze column-globally when some same-table `Update` writes the stage with a non-copy value and any `require` yields an approval receipt mentioning the recorded stamp. Section 12 demands "an actual same-resource transition [that] consumes that recorded approval … while changing the discriminator". The code does not check either half: a self-assignment (e.g. rewriting `status: 'proofed'` while requiring `status = 'proofed'`) counts as a changing transition, and a mention inside a disjunctive bypass (e.g. `require r.approvedAt != null or viewer = 'service:owner'`) counts as consumption, since `approval_receipts` collects from both `and`/`or` branches. A mentioning-but-not-enforcing writer plus one silent stage writer elsewhere then loses a freeze the parent revision retained. The historical fixtures only exercise conjunctively enforcing consumers, so this is latent, not demonstrated.
