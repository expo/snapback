### 1. The selection (design §3)

An acquiring join is an interval that is **open at serve time** and **not a continuous renewal**. Closed joins are dropped before any walk:

```691:709:snapback4/crates/snapback4-core/src/partition.rs
        let open = held.get(&(event.table.clone(), event.id.clone())).is_some_and(|spans| spans.iter().any(|span| span.from == event.seq && span.to.is_none() && span.expires_at.is_none_or(|expires| expires > now)));
        if !open {
            continue;
        }
        // ...
        if continuous { continue; }
        // @ref LLP 3000.007#18.2 — ruling 36: an acquisition selects the current readable rows at serve time; the boundary is the Nth delivered key by construction.
```

The walk is `group_rows_from` in the serving transaction at the stream’s `now`, with `room = usize::MAX` so a horizoned join asks for exactly N and a horizonless join asks for the whole group:

```439:478:snapback4/crates/snapback4-core/src/partition.rs
    let (index_name, remaining, dir) = match &sync.horizon {
        Some(horizon) => (horizon.by.clone(), (horizon.last as usize).saturating_sub(taken), Dir::Desc),
        None => (audience_index(table_name, table, sync)?, usize::MAX, Dir::Desc),
    };
    // ...
    let mut reader = viewer.map(|(schema, principal)| Runner::new(tx, schema, crate::Context::new(principal, BTreeMap::new()).at(now), crate::meter::Meter::new(crate::meter::Ceilings::unbounded(), crate::meter::Cut::Abort), 0));
    let mut aggregate = viewer.map(|(schema, _)| Runner::new(tx, schema, crate::Context::system().at(now), crate::meter::Meter::new(crate::meter::Ceilings::unbounded(), crate::meter::Cut::Cap), 0));
    // One extra readable row decides pagination, never selection past N.
    let target = remaining.min(room.saturating_add(1));
    // ... skip expired, live_aggregate, check_rule, then truncate to `ask`
```

On the join path `remaining.min(usize::MAX.saturating_add(1))` is N, so there is **no lookahead past the Nth**. The extra live-row seek exists only when a snapshot page has `room < remaining`. `Ceilings::unbounded()` (`meter.rs` 35–36) is `u64::MAX` on every counter: no probe budget and no early stop. The GROUP instrument confirms it: 100 stored rows, horizon 2, **2 physical rows / 2 read-rule probes / 1 scan** (`w13g_review/current.rs` 62–75).

The read check is the joining principal’s server runner, not the system runner. `Runner::new` sets `device: false` (`runner.rs` 162). `Context::new` is kind `"user"` (`engine/mod.rs` 105–107). `check_rule` returns true for every row if and only if `context.is_system()` (`read.rs` 247–249), which is `viewer == SYSTEM_PRINCIPAL` (`engine/mod.rs` 149–151). Using the system runner here would authorize hidden rows.

The end marker is the last delivered scan key (index columns plus id tie-breaker — `rows.rs` 137–140) or `"whole"` when `rows.len() < N`, including zero (`partition.rs` 715–718, 402–406). Horizonless joins push no markers (`714:727:snapback4/crates/snapback4-core/src/partition.rs`).

`join_completion`, `written_after`, `group_at`, unselected walks, delivered-set tracking, and any comparison with join-time history are gone from `partition.rs`, `partition/storage.rs`, `store.rs`, and `engine/postgres/{log,mod}.rs`.

### 2. Non-acquiring joins and the snapshot

Non-acquiring open joins are continuous renewals: after the expired-predecessor `scope` (if any), `if continuous { continue; }` expands no rows and publishes no markers (`partition.rs` 698–709). The renewal regression asserts an empty `acquisitions` list and only the two ordinary later puts (`w13g_probe.rs` 318–321). An expired predecessor still emits `scope` before the replacement acquisition (`326–328`).

A join whose interval is closed at serve time hits `if !open { continue; }` with no public/private special case. Same-commit grant and revocation produces `from == to` (`partition.rs` 583–597) and is not even added as a content span (`622–624`). The retired clause is gone from code; §18.2 names it (`llp/3000.007-relaxed-quarry-and-explicit-residency.rfc.md` 1927–1930). Native `current_join` asserts **26 puts when open, 0 when left**, for the private audience and for `read <- allow` with `retain delivered-history` (`retained_history.rs` 478–501). Wasm HTTP repeats the private pair (`horizon-boundary.test.mjs` 378–394).

The cold snapshot calls the same `group_rows_from(..., Some((schema, principal)))` (`partition.rs` 383). `live_aggregate` is the system runner (`451–452`); `check_rule` is the device principal. At a stable GROUP state, snapshot and stream floors and rows are identical (`w13g_review/current.rs` 49–58). Continuous renewal, retained re-acquisition (`boundary.rs` 82–88), continuation validation (`snapshot.rs` 129–141), and marker charging (`partition.rs` 384–385) are unchanged.
