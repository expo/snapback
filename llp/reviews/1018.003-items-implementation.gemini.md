### Recommendation: **REVISE**

The boundary design—keeping query truth intact inside `Snapshot<Result>`, adding derived item correspondence via the inert `defineItems` declaration, and eliminating all hook-driven automatic dismissals—is architecturally sound and elegant. It eliminates fragile screen-level reducers and ensures multi-reader consistency.

However, there are **material correctness and lifecycle findings** that prevent recommending `READY` at this stage. Most critically, the handling of committed creates under pagination causes all historical created rows that scroll off the head page to be permanently resurrected as pending ghost drafts.

### Material Findings

#### Finding 1: Paginated queries resurrect off-page committed creates as ghost drafts
* **Files & Lines:** `snapback2/packages/snapback2/src/client-items.ts:160–169`, `snapback2/packages/snapback2/templates/chat/shared/thread.ts:11–12`
* **Mechanism:**
  1. `threadItems.create.belongs` evaluates `query.c === null && args.conversationId === query.conversationId`. Whenever the head page (`c: null`) is viewed, every historical create for this conversation matches `belongs`.
  2. Because terminal history is retained in the outbox until explicit dismissal, all historical creates remain in `inputs.entries`.
  3. Once an older created message scrolls off the head page (e.g., 50 newer messages arrive), `item` is `undefined` (it is not in `data`).
  4. Line 163 checks:
     ```ts
     if (!contributing && (item || observation?.absent) && observed(entry, observation, binding.kind)) continue;
     ```
     Because `item` is `undefined` and `observation?.absent` is `undefined` (the message exists on the server, so it is not absent), `(item || observation?.absent)` is **false**.
  5. Line 163 therefore does not `continue`. Line 164 (`if (!item && binding.kind !== "create") continue;`) also does not `continue`.
  6. Lines 165–168 create a new item with `draft: binding.draft!(entry)` and lines 174–176 attach a pending action with `state: "committed"`.
* **Impact:** Every committed message sent in the conversation that is no longer returned within the head page's window is synthesized into `items` as a ghost draft with a permanent "awaiting delivery" spinner. As conversation history grows, the head page accumulates an ever-growing list of ghost draft items at the tail of the list.
* **Fix:**
  - A committed create must not be synthesized as a draft if the store already holds the delivered row (`state.rows[key]` with `rowSeq[key] >= entry.response.seq`).
  - In `ItemCapture`, ensure that durable row presence/delivery is exposed in `observations`.
  - In `attachItems`, remove the requirement `(item || observation?.absent)` when a valid positive observation proves that `key` was already delivered past the commit sequence (`observed(entry, observation, "create") === true`).

#### Finding 2: `useSyncExternalStore` mount re-render caused by projection slot cache mismatch
* **Files & Lines:** `snapback2/packages/snapback2/src/client-sessions.ts:301–320`, `snapback2/packages/snapback2/src/client-observed.ts:192–201`
* **Mechanism:**
  1. During React's initial render phase, `useSyncExternalStore` calls `getSnapshot()`. At this point, `subscribe()` has not yet executed, so `slot = entry.projections.get(projection.key)` is `undefined` (line 301).
  2. Line 306 executes:
     ```ts
     if (source !== entry.snapshot) { cached = projection.project(entry.snapshot, cached); source = entry.snapshot; }
     return cached;
     ```
     React renders using `cached`.
  3. During the commit phase (effect), React calls `subscribe(notify)`. Lines 314–318 execute:
     ```ts
     slot = { refs: 0, value: undefined, project: projection.project as ProjectionSlot<Snapshot>["project"] };
     this.project(entry.snapshot, slot);
     ```
     `this.project` calls `slot.project(entry.snapshot, undefined)`. Because `previous` is passed as `undefined` instead of `cached`, `projection.project` (line 196 of `client-observed.ts`) finds `before === undefined`, bypasses equality checks, and allocates a new snapshot object `{ ...current.snapshot, items: joined }`.
  4. React immediately calls `getSnapshot()` again to verify store stability during mount. Now `slot` exists, and line 304 returns `slot.value`.
  5. Because `slot.value !== cached`, React treats this as a concurrent store mutation and schedules an immediate, redundant re-render on every component mount.
* **Fix:**
  In `SharedSubscriptions.observe`, initialize `slot.value` with `cached` so that `this.project` receives `cached` as `previous` and preserves object equality:
  ```ts
  if (!slot) {
    slot = { refs: 0, value: cached, project: projection.project as ProjectionSlot<Snapshot>["project"] };
    if (slot.value === undefined) this.project(entry.snapshot, slot);
    entry.projections.set(projection.key, slot);
  }
  ```

#### Finding 3: Server-augmented fields prevent create overlay retirement in `TwinStore`
* **Files & Lines:** `snapback2/packages/snapback2/src/twin-store.ts:186–198`
* **Mechanism:**
  1. When a create overlay is applied, line 187 sets `effective = row; owners.clear();` and records `owners.set(field, { intent: entry.intent, kind: "create" })`.
  2. When the authoritative base arrives from the server, servers typically attach generated fields (e.g., `created_at`, `author_id`, `version`) that were not present in the client's optimistic create arguments.
  3. Line 197 tests:
     ```ts
     if (value && base && RowImage.is(base.row) && RowImage.equal(value, base.row)) {
       value = base.row; owners.clear();
     }
     ```
     Because `value` (the client's optimistic overlay) lacks the server's generated fields, `RowImage.equal(value, base.row)` is `false`.
  4. Line 198 sets `this.effectiveWork.set(key, ...)`.
  5. Consequently, `inputs.predicted` permanently retains `entry.intent`.
  6. In `client-items.ts:162`, `contributing` remains `true`, which permanently blocks `observed(entry, ...)` on line 163 from retiring the pending create action.
* **Fix:**
  When `base` is present and `base` sequence is at or past the create's commit sequence, `TwinStore.row` must recognize that the authoritative server row supersedes the initial create overlay, clearing `owners` without requiring byte-for-byte identity between the incomplete client draft and the server-augmented row.

#### Finding 4: Unbounded copy and serialization overhead on retained outbox history
* **Files & Lines:** `snapback2/packages/snapback2/src/query-frame.ts:17`, `snapback2/packages/snapback2/src/client-outbox-observed.ts:39, 43`, `snapback2/packages/snapback2/src/query-items.ts:85`
* **Mechanism:**
  With terminal history retained until explicit dismissal:
  1. `cloneItemPublication` (`query-frame.ts:17`) calls `structuredClone({ value, inputs: itemInputs(value) })` on every publication. This recursively deep-clones the entire historical outbox array (`inputs.entries`) on every query event.
  2. `ItemCapture.inputs()` (`query-items.ts:85`) sorts the entire outbox dictionary on every synchronous query capture (`O(N \log N)`).
  3. `observeOutbox` (`client-outbox-observed.ts:39, 43`) runs `structuredClone(entries)` and `JSON.stringify` over the entire outbox on every outbox event for every active slot.
* **Impact:** As outbox history grows over normal usage, memory churn and serialization latency increase linearly on every query publication and outbox tick.
* **Fix:**
  - `cloneItemPublication` should only deep-clone `value` and shallow-copy `ItemInputs`. `inputs.entries` is already frozen and does not need to be duplicated.
  - Maintain sorted outbox entries incrementally in `TwinStore` rather than sorting `Object.values(state.outbox)` on each capture.
  - In `observeOutbox`, use an outbox version counter or entry identity reference check rather than `JSON.stringify` on the full entries array.

### Summary Advice

Do not alter the public `defineItems` or `useQuery(..., { items })` interface; the boundary is clean, declarative, and keeps presentation logic out of application components. Address **Finding 1** (pagination resolution for off-page creates), **Finding 2** (mount-phase slot reference stability), and **Finding 3** (create overlay retirement with server-augmented fields) before qualifying the implementation for merge.
