The paper’s 14 hard ops are **not** 14 plans. Ops 1–4, 8–14 have a durable half the language can almost say. Ops 5–7 **are the axis** and are not a kind. What remains after `scan`+`cap`+`schedule`+`maintain` is **column-level secrecy, intent-time `now` on intervals, prediction that cannot be refused, a host that is not a principal, and every ladder question over `ratings`**.

### 2. Schema in v0

Sentinels: no `optional` / enum / float / bigint / blobref / column ACL. `UNSET` id/time = `0`. Enums → `text({ max })`. Rating → `int` millirating (`1500.000` → `1_500_000`). Seed → `text({ max: 32 })`. Blob refs → `text({ max: 128 })`. `json` opaque to rules, indexes, **and** (this report) programs — loadout **exploded**. `never` = missing effect. No `tree`. `interval` stored for display; **authorization is `status`**, flipped by schedule (K5, ruling 11).

### 6. Language delta

Ranked by whether Ricochet’s durable half stays slogans. Do **not** add a 30 Hz row store.

1. **Host/worker principal + capability-bearing invoke** (`callable: 'system' \| 'host'`, fence `{ table, epoch }`, secret not in the public row). Smallest: invoke API for named mutations with a principal kind other than the player, `check` refuses client calls. *General* (auction/payments). Amends §1, §3, §7. Without it Op 9 is god-mode or unreachable.

2. **Unguessable id / `hash` / HMAC** for `sessionToken`, match seed, spectator token. `ctx.newId()` is “client-mintable format” (§4.3) — not a 32-byte secret. *General*. Amends §4.2–4.3.

3. **System continuation of a viewer intent** (joinQueue must classify `matcherSanctions` without returning them). Smallest: `mutation({ phase: 'system' })` enqueued in the same commit, certificate is the pair; return type cannot name sys-only tables. *General* (sealed facts, ruling 8). Amends §4, §7, §9.1.8.

4. **`predict: false` / sensitive mutations.** Spec forbids per-query flags (§1) and also promises local prediction of every mutation. Op 12 and Op 9 violate Promise 4 if predicted. *General* (money). Amends §1, §6.

5. **Column projections / split is mandatory in `check`.** A diagnostic `E_SECRECY_MIX` when one table’s columns have different audiences (readyState vs ratingAtStart vs sessionToken vs pool). Smallest: refuse the table; paste the split. *General*. Amends §3, §9. Do not add column ACL (leaks via OCC/extents).

6. **Acceptance-time clock for windows** (or a loud `E_INTENT_NOW_WINDOW`). `ctx.now()` reused (§9.1.9) **admits** join/catalog/loadout clamps that are false at settle. Smallest: `ctx.commitTime` comparisons in mutations, or require schedule flags (K5) and **refuse** `ctx.now()` vs stored `endsAt`. *General*. Amends §4.3, §9 `E_AMBIENT_TIME`.

7. **Transactional outbox that dispatches effects.** Design’s `outbox` is a table; v0 `effect` has no trigger. Smallest: insert → at-least-once worker with row key, writes only via named mutations. *General*. Amends §1, §7.

8. **`db.run(namedMutation)`** summing certificates (allocate fail → void; cheat extract → apply). *General*. Amends §4.2.

9. **Cross-table exclusive-open** (`occupancy` iff live queue xor live participant). Unique per table is not I2. *General* (booking occupancy, payments one-open-dispute). Amends §2.

10. **Decrease floor on `maintain.sum`** (inventory available, coins). Same as payments delta 1. *General*. Amends §2. Scale here does **not** forbid a parent OCC row (2.5 settlements/s).

11. **Partial unique / `unique (cols) where liveKey=0`** as sugar for the discriminant. Used everywhere. *General*. Amends §2.

12. **Integer `exp` / ratediff lookup is product**, not language. Do not add floats. Publish **G** so take 500 is classifiable. Amends §4.5 (no), §5 (yes).

13. **Kind-conditional `cap`** (party 4 vs custom 8). Else cap 8 + `require`. *App-shaped, weakly general*. Amends §2.

14. **Reschedule `at` when the trigger row’s inputs change** (heartbeat+15s). §7 says “creates or changes”; make it normative for `at` expressions. *General*. Amends §7.

**Do not add:** `while`; clock in rules; LoS operator; `tree` for a tick ring; skip-hidden-`take`; `channel` at 30 Hz; `maintain.count(spectators)`; OT/physics in the evaluator.

Not missing: `cap` 8, `appendOnly`, `immutable`/`immutableExcept`, `(old,next)`, unique keys, `schedule`/`system`, `interval` columns, `maintain`+`readable`, channels for presence, live queries for menus, OCC on traced occupancy.

### 8. Where the design is wrong

Not taste. Forced by v0 spelling.

1. **`participants` (and `queueEntries`, and `participantResults`) are one row with three audiences.** Ready-check needs `readyState` for all eight; connect needs `sessionToken` self-only; I11 needs `ratingAtStart` self/staff; I12 needs `pool` sys-only. v0 rules are per table. Confirming observation: authorize `getMatchLobby` as a participant and dump the closure — if `ratingAtStart` or `sessionToken` or `pool` is on a row whose `read` is `inMatch`/`self`, it is in the receipt; if the tables were split as in §2, those fields are absent.

2. **Promise 11’s percentile is specified as a count over `ratings` that I11 makes self-only, and §6 treats that as a cost problem.** Under §9.1.2–3 and ruling 8 it is a **correctness** problem: a visibility-filtered `count(rating>mine)` is 0 or 1. Confirming observation: implement `getMyPercentile` as `scan(ratings.bySeasonRating, [season], { take: 1000, range: { gt: mine } }).count()`; `check` either emits `E_STRUCTURAL_COUNT` or (if admitted) returns a percentile that does not move when 10,000 higher-rated rows exist.

3. **Op 9 is a player-visible live `matches` row plus a mutation the host must call, in a language whose only principals are `viewer` and `system` and whose every client mutation is predicted.** Epoch+state on a readable row is a fence an attacker can **name**, not a capability they cannot **produce**. `db.require(sys())` is not `callable`. If the mutation is client-callable, Promise 4 is false (predicted coins) and T2 is a hostile `settleMatch`. If it is not callable, the host has no invoke path. Confirming observation: from a participant device, submit `settleMatch` with `matches.hostEpoch` from the lobby query and a forged octet; if `check` admits it, inspect whether coins appear in the local store before a receipt; if `check` refuses for `!sys()`, the orchestrator has no spec’d way to run the same body.

(Occupancy dual-write, intent-`now` vs “active at T”, and resume-vs-void are also underspecified; they are §4.3 / design §8, not this collision.)
