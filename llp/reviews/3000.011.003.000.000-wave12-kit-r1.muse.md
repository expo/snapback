## Blocking issues

**1. web-chat and social proofs use a witness global nothing installs.**
Generated `frontend-proof.mjs` calls `window.__snapback4Witness.viewer()` (chat) and `beginForm(...)` (chat/social). Only the todos starter clients call `registerWebWitness`; [web-client.ts](/home/ccheever/projects/sb4-w12-kit/snapback4/crates/snapback4/src/verbs/init/web-client.ts) (chat web) and [social/client.ts](/home/ccheever/projects/sb4-w12-kit/snapback4/crates/snapback4/src/verbs/init/social/client.ts) never do, and nothing else in the package auto-installs the global (only [witness-web.ts](/home/ccheever/projects/sb4-w12-kit/snapback4/packages/snapback4/src/witness-web.ts) references it). Expo-chat is fine ([expo-client.ts](/home/ccheever/projects/sb4-w12-kit/snapback4/crates/snapback4/src/verbs/init/expo-client.ts) registers). Repro: `init --web --template chat`, build, run the proof — the `viewer()` evaluate throws TypeError. Or statically: grep shows zero registration in the chat/social template sources. Smallest fix: mirror the todos client — import `api` and call `registerWebWitness(app, api)` in both files. This breaks "published templates get a concrete write scenario."

**2. Qualification receipts point at log directories that no longer exist.**
The kit now defaults `logsDir()` to OS scratch, but [publication-starters.mjs](/home/ccheever/projects/sb4-w12-kit/snapback4/scripts/proof-listener-audit.mjs) still records `logs: join(cwd, "logs")` and never passes an explicit `logsDir` (which the proof script doesn't forward). Repro: run `proveFrontendTwice` — `results[].logs` is absent on disk while real logs scatter in the shared tmpdir. Smallest fix: have [frontend-proof.mjs](/home/ccheever/projects/sb4-w12-kit/snapback4/crates/snapback4/src/verbs/init/frontend-proof.mjs) honor an env-provided scratch dir for all three hosts plus browser, set it per attempt in the qualification script, and record that path.

**3. `ports::environment()` rejects `LO==HI`, contradicting §1's inclusive range.**
[ports.rs](/home/ccheever/projects/sb4-w12-kit/snapback4/crates/snapback4/src/verbs/init/ports.rs) demands `lo < hi` while `portRange()` and `--port-range` accept equality, and [init.rs](/home/ccheever/projects/sb4-w12-kit/snapback4/crates/snapback4/src/verbs/init.rs) gates every `init` (even schema-only) on it. Repro: `PORT_LO=4400 PORT_HI=4400 init --web` exits 2 while `startDev` binds fine. Smallest fix: relax to `lo <= hi` to match the launchers.
