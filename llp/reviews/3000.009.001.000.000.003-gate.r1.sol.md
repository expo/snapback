## Q-A — Replace the 4,525/A gate with a competitive gate

**Ruling: replace it.** The author’s objective requires strict competitive wins. It does not require 4,525/s when both competitors lose below that rate.

The landed authoritative campaign demonstrates the distinction: restored R0 passes W4/A at **3,805/s, 5/5**, while Supabase passes **3,200/s, 5/5** and fails 3,805/s. Both fail 4,525/s. That supports a disclosed quarter-rung win, while failing the present investment gate. Conversely, **hot1/B remains tied at 2,690/s**; faster service means cannot turn that tie into a throughput win. [R0 authoritative report][r0], [RFC 003 §§8.2–10.3][rfc].

Adopt this replacement:

| Requirement | Exact criterion |
|---|---|
| Write cells | W4 disjoint, W5 exact, W5 hot1, each on A and B: **six cells** |
| Compared configurations | Restored R0, corrected flag-off main, Supabase advocate and Convex advocate; source/configuration frozen for confirmation |
| Environment | Authoritative 450b S1 topology, identical fixture and durability, existing resource limits; interleaved measurements within the same qualified quiet campaign |
| Confirmation | **Five predeclared repetitions at every deciding rung**, with all five required to pass |
| Pass | Intended-arrival p99 ≤100 ms writes /50 ms reads; errors ≤0.1%; exact durable write counts against all ACKs, including warmup |
| Strict win | Higher qualified tested rate than **each** competitor, using the ladder/tie-break procedure below |
| Tie | Equal qualified rate after the permitted tie-break; **ties do not satisfy the gate** |
| Read/exact non-regression | Preserve corrected main’s qualified rates and passing operating points, as specified below |
| CPU | Also satisfy Q-B’s constrained-PG write gate |

Keep the published √2 ladder and §9’s quarter-rung procedure:

1. Test the systems at a common set of deciding rates, including their known passing references and the next full rung. Do not stop exploring solely because an earlier, lower rung failed.
2. If systems share a highest passing full rung and fail the next full rung, test the intervening registered quarter rung for every tied system, five repetitions each.
3. If both pass or both fail that quarter rung, the result remains **tie**. Do not introduce successive outcome-selected subdivisions or substitute latency.
4. If the shared maximum is merely the highest rate tested and the systems have not failed above it, extend the full ladder, with the same procedure, to the harness’s registered 128,000/s limit. A shared pass at that limit is **tie, upper frontier untested**.
5. Report the full-ladder result and quarter-rung result separately. The present W4/A evidence is **full-ladder tie; quarter-rung win**, with the adoption-after-results disclosure retained. A quarter rung cannot reverse a full-rung loss.

**Non-regression means sustained-rate/SLO non-regression, not identical latency.** Candidate R must preserve main’s highest qualified full/quarter rate and pass every main-qualified rate in the confirmation grid. Include the known low-load write points—100, 200, 400 and 800/s—and the applicable previously passing points. Publish p50/p99 changes at matched loads; this gate does not authorize a claim that latency never increased.

For reads, requalify all six W1–W3/A–B cells against corrected main. The landed reference rates are W1 **8,000**, W2 **11,313**, W3 **16,000/s**, on both links. For exact-key writes, include the diagnostic **2,096/A and 1,678/B** challenges, but establish main’s qualification on 450b rather than importing a 450a ceiling.

Because exact/A has demonstrated intermittence, require **two predeclared five-repetition blocks** at each main-qualified exact reference, with R passing 10/10. A main failure makes that reference comparison inconclusive; it does not excuse an R failure or authorize lowering a previously established reference silently.

Remove the separate **≤6.0 ms R0** and **≤6.4 ms production** mean ceilings as promotion requirements. Keep sent means, prefix lag, loan custody and occupancy as diagnostics. Production must independently pass the competitive gate after restoration; a prototype pass supplies no transferable performance entitlement.

**Current disposition: the replacement gate is not yet passed.** The authoritative older R0 ties hot1/B, lacks the required fresh Convex/main campaign and CPU scenario, and retains an ownership failure at a lower rate. SPR8’s later passing triples do not resolve its earlier same-configuration exact-A failure. [R0][r0], [Spike R round 8][spike].

## Q-B — Replace the relative CPU stop with a competitive CPU-constrained scenario

**Postgres CPU per write matters directly to the objective.** Extra CPU can reverse a storage-bound win when Postgres has fewer CPUs, serves more tenants or receives more concurrent work. A roughly 0.474 CPU-ms/write demand would consume about one CPU-second per second at 2,110 writes/s if that demand stayed constant. That is an illustrative bound, not a capacity prediction.

**Ruling: replace the +30% stop with a measured competitive resource scenario.** Keep CPU/write and WAL/ACK reporting; retire ≤0.35 ms/write as a blocking threshold.

Use this exact additional resource profile:

- Same authoritative S1 setup, except **all private Postgres processes, including background workers, share one logical CPU and an aggregate quota of one CPU-second per wall-second**.
- Fix that CPU placement before measurement. Leave unused PG CPUs unused; retain the normal app/proxy and generator allocations.
- Preserve durability, memory, storage, connections, A/B delays and application semantics.
- Re-run restored R, corrected flag-off main, Supabase and Convex interleaved, using Q-A’s ladder and five-repetition rules.
- **Before R1–R5:** R-enabled Snapback must strictly beat both competitors in all six write cells under both the ordinary and one-CPU profiles.
- **Before default-on or an all-S1 claim:** the final configuration must strictly beat both competitors in all twelve Postgres read/write cells under both profiles, with the SDK gates below.
- A loss, tie, resource-cap breach or unresolved qualification leaves promotion blocked. A >30% CPU increase alone does not.
- Confirm CPU pressure at the disjoint-write frontier through CPU utilization/throttling evidence. If another component prevents exercising the CPU constraint, report the CPU question as unqualified.

This permits a more expensive implementation when it still wins under a scarce resource budget. It prevents a flush-bound benchmark from concealing a CPU-bound loss. It does **not** establish every tenant-count or concurrency scenario; those require their own measurements.

One evidence correction matters: the **0.146 ms/write and 104 B/ACK** comparator in Spike R round 4 is **raw PG**, not flag-off main. The same round’s main table reports approximately **0.185 ms/write and 616 B/ACK**. Match identities, loads and accounting windows before presenting a cost ratio. The underlying concern remains substantial. [Spike R rounds 4–6][spike], [RFC 003 §§8.1, 12–13][rfc].
