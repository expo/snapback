### 1. Signal-class E2EE messenger (plaintext search, quotes, member-blind admin)

**App:** Multi-device group chat whose bodies, sender keys, and “contains @you” indexes never exist in plaintext on the operator.

**Premise:** Rules the server can evaluate (and server authority over content).

**Break:** Membership can be rows; plaintext cannot. A `scan` / ranked site over bodies is a program the server cannot authorize, bound, or put in the *authoritative* trace. Dimension M’s `localReplay` alternative does not save this: that site is still *admitted by a server certificate* over a declared index. Client plaintext programs are not a subset of any server certificate. **Broken** looks like a second, client-only query class whose results are not live/OCC’d by the server trace — or else the trace itself is the plaintext leak. `seal`/`digest` were operator-held keys, not client-only sender keys rotated in the same commit as membership.

**Why not the 29:** Clique, coterie, and Twitch are server-visible logs.

**Falsify:** Paper `searchPlaintext(q)` and `removeMemberAndRotate`. The certificate has no key material to sign.

**Likely:** **new dimension** (opaque partitions + client-evaluated authority) or **not this system**. Highest P of a real second class.

### 2. Google Sheets / Excel as the live database

**App:** A workbook where each cell is a user-authored formula, one A1 edit recalculates 10⁵–10⁶ dependents, and `NOW()`/`RAND()` live inside the graph.

**Premise:** Static certificate as the gate; named operations; deterministic programs over traced bounded reads.

**Break:** Notion’s fold (one interpreter over exploded AST, `maxSteps`, ≤16 pinned views, same programs for every tenant) is a different product: one certified walker, not a million live queries. The program *is* the row, so named-operation certificates cannot be the gate. `maxSteps` stops being a refusal and becomes a wrong recalc. Collaborative cell identity is not `sequence` over text. **Broken** looks like a second evaluation class (reactive formula graph) whose bound is the workbook.

**Why not the 29:** Notion capped EAV rollups; the editor was text.

**Falsify:** One A1 edit with 100k dependents in one commit; compare `maxSteps` to a correct recalc.

**Likely:** **new kind** (formula engine outside the plane, analog of OT/`sequence`) if they keep the product; otherwise **product boundary** (visible staleness). High P that “one class” dies.

### 3. Private contact discovery / PIR mailbox (Signal CDS)

**App:** “Is this phone on the network?” / “fetch my mail” where the *query* must not be learned by the operator.

**Premise:** The trace is the offline closure, OCC set, and invalidation predicate.

**Break:** Both traces list examined rows/ranges. That list *is* the query. `independentOf` and `getHidden` stop *values* escaping into results; they do not stop the authoritative trace (or a replica receipt) from recording that you probed `users[hash(phone)]`. A `{bearer:true}` hashed unique still logs hit/miss. **Broken** is a guarantee that cannot hold: admitted programs are traced, and tracing is the disclosure.

**Why not the 29:** Dating/graph/payments hid values, not access patterns.

**Falsify:** `lookupUser(phone)` with the authoritative trace dumped — the bucket is there.

**Likely:** **new kind** that is itself the break (an untraced/crypto read site = a third class), or **not this system**. Adding the kind retracts “the trace is the closure.”

### 4. Shopify / Salesforce platform apps installing rules on the host’s `orders`

**App:** Untrusted extensions contribute programs *and* `read`/`update` predicates on tables the host owns.

**Premise:** Rules the server can evaluate as one author-time artifact.

**Break:** The schema has one rule per effect. Conjunction, override, per-row grants, and amplification quotas between apps are not an axis. Wave 3’s stored-predicate algebra assumed a *trusted* author stuffing predicates as data; Notion’s tenants run the *same* certified programs. An `any` cap that false-denies a legitimate grant is not `E_STEPS` — it is an ACL bug. **Broken** is an axis the schema cannot state: rule ownership, composition, and fairness.

**Why not the 29:** One schema author everywhere.

**Falsify:** App A and App B install conflicting `update` rules on `orders`; write the composition in v1.1 syntax.

**Likely:** **new dimension**.

### 5. Coercion-resistant / receipt-free elections

**App:** A binding vote where the voter cannot prove how they voted, including to their other devices.

**Premise:** The trace as offline closure; `audited(into)`.

**Break:** The product forbids a proof of the write. The closure receipt, halo, OCC set, and access manifest *are* a vote-selling proof. `independentOf` hides inputs from outputs; it still delivers “you read ballot X and wrote choice Y.” **Broken:** the runtime’s central object is a security bug.

**Why not the 29:** Sealed auction and prediction markets *wanted* receipts and public verifiability.

**Falsify:** Show the `cast(ballotId, choice)` closure receipt to a coercer.

**Likely:** **not this system**; **new dimension** (anti-audit / incriminating receipts) only if you insist it is in.

### 6. Delivery-versus-payment across two custodians

**App:** One trade, cash at Bank A, securities at Bank B, both legs or neither.

**Premise:** One server authority; one authoritative trace as the OCC set.

**Break:** No interpreter’s trace is a legal OCC set for both books. `effect`/`outbox` to the peer is not the same commit (`sent_unknown` is the named hole). `host invoke` settles a process *this* operator owns, not a peer who will not run your evaluator. **Broken:** a mutation that cannot be one admitted program without 2PC.

**Why not the 29:** Payments, brokerage, and prediction market are single-operator books.

**Falsify:** One `settle(tradeId)` that commits both legs, A and B distinct authorities.

**Likely:** **not this system** (DvP protocol outside), else **new kind** (sagas) that reintroduces the outbox TOCTOU.

### 7. 1Password / Bitwarden (client keys, vault usable after two years offline)

**App:** The device is the authority; the server is an encrypted backup that may never be reached.

**Premise:** Store-wide offline fence; one server authority; server-evaluated rules.

**Break:** `maxOfflineAge` (even 30d) and per-table leases that may only be *shorter* than the fence make the product illegal. `replica` still lives under the fence. The server cannot evaluate item ACL over ciphertext. OCC against a server that cannot read the row is theater. **Broken:** the fence is the wrong instrument (the unit is “the vault, unbounded”), and the eight-state machine has no legal state for “400 days offline, still read/write.”

**Why not the 29:** Photos’ `replica`/`all-owned` still assumed a server that wins; dating’s lease was shorter, not infinite.

**Falsify:** Edit an item last synced 400 days ago; name the client state.

**Likely:** **not this system**, or **new dimension** (per-partition authority + unbounded horizon).

### 8. Live external oracles in rules (device posture, IDP session, fraud score *now*)

**App:** A write is allowed only if CrowdStrike/Okta/Radar says `ok` at commit, not as of a mirrored row.

**Premise:** Deterministic programs over traced bounded reads; rules the server can evaluate (closed over `db`).

**Break:** Rules are algebraic predicates the compiler hoists into `ruleHashes`. An HTTP oracle cannot be in that closed set. Effects cannot run in rule position; host invoke is not in the SQLite transaction (“JavaScript never in the authoritative path”). Mirroring posture into a row is TOCTOU — the fact you authorized on is not the fact at commit. `ctx.random` is system-committed, not a model. **Broken:** authorization that is not a row predicate (a second rule class), or a guarantee (the rule’s inputs are the traced rows) that cannot hold.

**Why not the 29:** Events/payments authorized on principals and hidden *rows*.

**Falsify:** An `update` rule `viewer.deviceTrust === 'ok'` where trust is an out-of-db call in the same commit.

**Likely:** **new dimension** (rule oracles + freshness) or **product boundary** (mirror and accept staleness). Medium-high P of a real gap; the dump to “mirror” is tempting and wrong for the product.

### 9. Multi-region active-active inventory (one SKU, two regions taking the last unit)

**App:** Regional legal books, both accepting `reserve(sku)` without a round-trip to a home.

**Premise:** SQLite-first single-writer; one acceptance order (`serialBy`, `commitTime`).

**Break:** `serialBy(sku)` is one writer. Two regions without a home are two logs; with a home, the away side is not active-active. Cross-region OCC cannot be evaluated inside the away transaction. Postgres-as-lowering is not a second primary. **Broken:** certificate/trace/OCC assume one serial commit log.

**Why not the 29:** Uber/DoorDash/eBay were single-authority; wave 3 named this untested.

**Falsify:** Two regions `reserve(sku)` in parallel with `cap` 1; produce one `serialBy` log.

**Likely:** **new dimension** (home authority per key) in v2; **product boundary** in v1 (one home). High P of a real gap, medium P it breaks rather than waits.

### 10. Native matching / RTB (one symbol, >100k messages/s, <1 ms reject)

**App:** The hot symbol *is* the product, not a back office.

**Premise:** SQLite-first single-writer; per-op static certificate as the gate.

**Break:** Brokerage and prediction market already *modeled* matching. The scale regime is the attack: interpreter + certificate + constraint checks inside one writer *is* the latency budget. Shard-by-symbol still leaves NVDA on one core. **Broken:** the certificate is the wrong instrument (a compiled matching automaton is).

**Why not the 29:** Paper matching ignored the clock.

**Falsify:** One measurement — `insert` + cap + `serialBy` on a hot key vs the budget.

**Likely:** **not this system**. Included as the brief’s “scale regime where the certificate is the wrong instrument”; it will not grow the language.

---

**What would not make this list.** Git/Drive ReBAC, PromQL/Hex, Temporal, ActivityPub, and Ticketmaster onsale are real pressure, but the honest paper outcome is already in the design’s escape hatches (`dag` caps, `exportStream`, jobs, effects+mirrors, “not this lowering”). The ten above are the ones where using the hatch *is* the admission: a second class, a trace that is the bug, a fence that cannot be a number, or a rule that is not a row.
