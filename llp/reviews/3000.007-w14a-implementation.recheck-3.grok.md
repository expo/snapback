### Question 1 — the High

**SQLite facts.** Resident `OP_Column` (`sqlite3.c` 99667–99691) copies TEXT/BLOB that fit on the page. When `szMalloc < len+2` it calls `sqlite3VdbeMemGrow(pDest, len+2, 0)` (99681–99684). With `bPreserve = 0`, `sqlite3VdbeMemGrow` frees the old buffer and `sqlite3DbMallocRaw`s the entire new size (85763–85765). Overflow uses `OPFLAG_BYTELENARG` and does not read payload (99693–99718). `sqlite3_reset` (93685–93694) → `sqlite3VdbeReset` (91347) → `sqlite3VdbeHalt` / `closeAllCursors` (91088, 90597) → `releaseMemArray`, which frees `zMalloc` and zeroes `szMalloc` (89961–89963). Cached statements therefore allocate those buffers again on the next execution.

**Streamed preflight.** Parent `cddf0d42d6` still ran `SELECT coalesce(sum(n),0), count(*) FROM (SELECT octet_length(r.data) + length(i.k) AS n … LIMIT ?5)` and charged once after that statement finished (`store.rs` 818–824 on the parent). `ab52240718` selects the same per-row expression, same join/bounds/`ORDER BY i.k`/`LIMIT ?5` as `scan_sql` (`store.rs` 55–59, 821–823). rusqlite `query` only binds (`statement.rs` 223–226); each `Rows::next` is one `sqlite3_step` (`row.rs` 39–42, 215–220). The loop charges `2 × bytes + 64` after that step and before the next (`store.rs` 828–832). `meter.heap` is an error even under `Cut::Cap` (`meter.rs` 199–206), so `?` returns. `Rows` drop calls `sqlite3_reset` (`row.rs` 109–114, 17–22) without another step; the payload `SELECT r.data, i.k` is not reached.

**Ordering exception.** The same sentences appear in `store.rs` 811–816, the ledger row (`engine/word_heap.rs` 32), and §20.24.1 (5387–5399). They match the code: the first `step` of an execution copies at most two resident column registers (one page each) before that row’s charge; later rows copy only after the previous charge; later executions (`once` is a no-op; the payload statement; a second `scan_metered` on the same meter) copy first, then charge, bounded by that same `2 × page_size`. Reset frees registers, so those later first copies are new allocations. Nothing else in this path is copied before its allowance: `query` does not prefetch; JOIN pages are shared images; the integer length result is not a TEXT/BLOB grow.
