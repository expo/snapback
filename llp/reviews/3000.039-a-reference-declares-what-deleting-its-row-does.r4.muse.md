## 3. New findings (none blocking)

**Finding 1 — Low — §8, second bullet vs `capabilities.rs:74` and `reference_actions.rs:100-102`.** Scenario: a schema whose every reference declares `on delete keep`. The RFC says "every schema the new compiler emits with a reference between ordinary durable tables carries [the capability] (restrict is explicit in the IR)," but the compiler lowers nothing for `keep`, and the capability predicate (`any on_delete non-empty`) is false — the schema is capability-free by design, and old engines handle it identically. Smallest fix: qualify the sentence with "except a schema whose references all declare `keep`, which stays byte-identical and capability-free."

**Finding 2 — Low — §9 Lean claim vs `lean/Quarry/Write.lean:193-196`.** Scenario: two occupied restrict references; the RFC says the model implements "schema-order reporting," but `restricted` is an unordered `Bool` — the model proves refusal, not which column is named. Smallest fix: qualify §9 to "closure, restrict with closure exclusion (reporting order is an implementation property the oracle does not compare), set null, cascade."

**Finding 3 — Low — §7 `N_DELETE_NEEDS_READ` prose vs `reference_actions.rs:217-222`.** Scenario: `delete <- Deny`, or a read rule `A and B` whose conjuncts the delete rule contains separately. The code suppresses the note (vacuously / by decomposition); the prose describes neither case. Both directions are advisory-note noise only. Smallest fix: append "a denied delete, and a delete containing every conjunct of an `and` read rule, also suppress it" to the heuristic sentence.
