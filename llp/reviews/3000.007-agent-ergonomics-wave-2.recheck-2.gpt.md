## Remaining defects and new regression

### 1. Medium — B remains vulnerable between PID inspection and termination

[ witness.rs:117](snapback4/crates/snapback4/src/verbs/witness.rs:117) checks the running PID, but [witness.rs:127](snapback4/crates/snapback4/src/verbs/witness.rs:127) subsequently terminates **by bundle**.

The following interleaving still kills an unowned instance:

1. `launchctl list` reports the driver's launched PID.
2. That instance exits; another instance of the bundle launches.
3. `simctl terminate <udid> <bundle>` terminates the replacement.
4. The subsequent check no longer finds the original PID, and the driver records its termination.

Relaunch refreshes `app_pid`, and replacements present **before** inspection are correctly refused. Neither closes this window.

The replacement regression changes the PID during capture shutdown, before inspection: [witness-simctl.py:97](snapback4/crates/snapback4/tests/fixtures/witness-simctl.py:97). It does not construct replacement between inspection and termination. The reported native success establishes ordinary operation, not this ownership guarantee.

**Required:** instance-safe termination, or an explicitly revised ownership contract. Another preceding PID check does not make bundle termination atomic.

### 2. Medium — C's validation introduces rejection of a legitimate receipt

After `done`, [protocol.rs:90](snapback4/crates/snapback4/src/verbs/witness/protocol.rs:90) rejects a `between-steps` row containing only the envelope.

Yet this is valid helper usage:

```ts
await w.step("done", async () => {});
await w.receipt({});
```

My in-memory helper probe emitted:

```json
{"witness":{"at":"2026-09-15T01:48:52.143Z","step":"between-steps"}}
```

The driver rejects that row. An object whose optional fields all serialize away has the same problem. The published helper imposes no nonempty application-object requirement.

The positive trailing-receipt fixture always supplies an `app` field: [witness-simctl.py:94](snapback4/crates/snapback4/tests/fixtures/witness-simctl.py:94). No regression covers this legitimate empty receipt.

**Required:** distinguish application receipts from step completion without using application field count.

That proof can allocate heap and evaluate a membership read rule: [write_target.rs:73](snapback4/crates/snapback4-core/src/engine/write_target.rs:73).

[read.rs:47](snapback4/crates/snapback4-core/src/engine/read.rs:47) raises `E_BOUND` before unknown coverage is recorded. [local.rs:78](snapback4/crates/snapback4-core/src/engine/local.rs:78) preserves that error, and [device.rs:641](snapback4/crates/snapback4-device/src/device.rs:641) queues only `E_PREDICT`; other errors reject admission.
