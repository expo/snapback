## New findings

### N1 (High) — Fixed keys do not prove a mutation is a renewal

- **Where:** §2.2’s `renews` classifier; §2.4’s coalescing and suppression.
- **What is wrong:** An upsert keyed solely by `viewer` can still read its current row and write `n: old.n + 1`. It satisfies the stated classifier, yet suppressing an identical call loses an increment.
- **Evidence:** A compiled Quarry probe executed that operation twice through the existing interpreter and produced results `1`, then `2`. The prescribed renewal window would execute only the first call and return its result twice. The patch path performs ordinary replacement semantics ([write.rs:237](/Users/ccheever/projects/snapback-eph-review-astra/snapback4/crates/snapback4-core/src/engine/write.rs:237)).
- **Proposed change:** Keep `renews`-only coalescing, but require a conservative renewal proof covering payloads, control flow and results—not only target keys. Exclude state-dependent increments, toggles and returned values; leave such operations valid ephemeral mutations without `renews`. Add this counterexample as a negative classification test.

### N2 (High) — A retired incarnation is accepted as another new incarnation

- **Where:** §3.3, “Fencing”; §4.7’s incarnation tests.
- **What is wrong:** “A different incarnation is always accepted” permits `A:50 → B:1 → delayed A:50`. The final response reinstates a retired incarnation and can resurrect rows cleared on restart. Grok F3 is therefore only partially addressed.
- **Evidence:** The literal comparison accepts that sequence. Existing durable fencing does not rescue a restart with unchanged store identity, generation and sequence: the online request epoch advances on generation change ([client.ts:521](/Users/ccheever/projects/snapback-eph-review-astra/snapback4/packages/snapback4/src/client.ts:521)), while the local identity path ignores an unchanged identity ([local.ts:288](/Users/ccheever/projects/snapback-eph-review-astra/snapback4/packages/snapback4/src/local.ts:288)).
- **Proposed change:** Add an independent ephemeral request revision. An accepted incarnation transition advances it and invalidates outstanding ephemeral queries and polls; reject old-revision responses before considering their incarnation. Test delayed old `/q/` and `/changes` responses after accepting the replacement.

### N3 (High) — Wake publications can arrive out of commit order

- **Where:** §3.3’s wake publication; §4.3 steps 4–5.
- **What is wrong:** Releasing the hub before publishing allows commit 1 to pause, commit 2 to publish, and then commit 1 to overwrite the wake snapshot. A wake mutex prevents the check/wait race but does not establish publication order.
- **Evidence:** A deterministic protocol model produced hub epoch `2` with wake epoch `1`, losing the `viewing` invalidation from commit 2. The same interleaving can overwrite a clear/rebind notification with an old incarnation. Today’s durable publisher explicitly uses a monotone maximum ([serve.rs:1077](/Users/ccheever/projects/snapback-eph-review-astra/snapback4/crates/snapback4/src/serve.rs:1077)).
- **Proposed change:** Publish the hub’s epoch, ring and incarnation into `Wake` before releasing the hub, taking the wake mutex last. This follows the already-declared lock order; apply it to clear/rebind too. Add deterministic tests that pause a publisher across another commit and across adoption.

### N4 (Medium) — Silent reclamation changes bounded scan results without a deadline

- **Where:** §3.3’s silent-expiry justification; §§3.5/4.3’s sweeps.
- **What is wrong:** Prohibiting rule probes does not eliminate expiry-dependent scan reachability. Hidden rows can exhaust the physical authorization allowance; reclaiming them makes a later readable row reachable, although the previous answer exported no deadline.
- **Evidence:** With only `read <- .principal = viewer`, a `first 1 by byId` query returned `[]`, `nextExpiry=None` behind 8,192 hidden rows. After removing those expired rows, it returned Alice’s still-live row at the same durable sequence. The result reproduced on `MemoryRows`; hidden rows were spread across 128 principals. The relevant behavior is explicit in [read.rs:783](/Users/ccheever/projects/snapback-eph-review-astra/snapback4/crates/snapback4-core/src/engine/read.rs:783) and [authorized_point.rs:52](/Users/ccheever/projects/snapback-eph-review-astra/snapback4/crates/snapback4-core/src/engine/authorized_point.rs:52).
- **Proposed change:** Retain the rule-probe prohibition and add bounded, content-independent revalidation for incomplete ephemeral watches, including empty answers with no `nextExpiry`—for example, a fixed 500 ms refresh cadence. Do not expose hidden deadlines. Test silent reclamation without changing either notification counter.
