### 1. Position

**Conditional — yes**, if the restriction is on *computational class* rather than *operator poverty*, and if the admitted operators cover the LLP 0120 census (bounded fan-out, grouped counts, multi-table derivation, bounded graph walk). If they do not, handlers grow back and the 0329.000 design is not implementable.

The mechanism: a **bound-carrying logical IR** whose executable collections are `Page<T,N>`, `Row<T>`, or `Maintained<T>` (cardinality is a type); a compiler-derived **program-closure type** (index-range patterns, including inlined row-rules, plus an examined-entry ceiling); a runtime **snapshot-closure value** (ranges and rows actually touched, including empty ranges); the client re-executing the *same IR* against that value. Named operations are the sync unit; composition is compile-time inlining. Remainder is an **effect that writes a table** — a different kind, not a second query class.

Not Convex, not Zero, not Snapback-as-built. The 0329.000 sketches plus the operators they omitted; LLP 0157 rebuilt as operators, not a registry of products. I would build this. I would not retrofit `define.mjs`. Keep Rust+SQLite, settlement, idle, schema-as-source-of-truth, and the benchmark loop; start over authoring and the client.

### 2. The crux question (answer this explicitly)

**The claim is still true of an arbitrary deterministic function.** Shipping the recorded read set of the last execution does not refute LLP 0329.004 F3 / 0329.005 P1 for the operations that make offline *useful*. It changes what you can do with the last result.

Two artifacts. A **snapshot closure** is the index ranges (including empty ones), the rows inside them, and any opaque rule verdicts from *one* execution at snapshot `S` — a value, enough to *display* that result (you may not re-run; you have it) and to re-run the function against the same `S` with no local writes, if every `db.get` hits a shipped range. A **program closure** is a finite set of range *patterns*, a function of `(plan, args, viewer)`, independent of which rows existed at `S`, with a cardinality ceiling — a type, what you need *before* a local write to know whether re-execution stays covered.

A trace is a snapshot closure. Turning it into a program closure *is* static analysis. Using a snapshot closure as a program closure is unsound the moment control flow can demand a range the last execution did not touch. Opaque verdicts for rules whose inputs the viewer may not read are **leases under another name**: they reuse a boolean from `S`; they do not recompute it. If Clique membership needs them, the design has failed. Membership is a row the viewer may read, or an absence range on `(conversationId, viewer)`.

#### Private chat

Plan `thread(conversationId)`: rule `exists memberships.byKey({conversationId, userId: viewer()})`, then `messages.where(conversationId).order(at.desc).take(200)`.

An honest server trace at `S` ships: membership range (row or **absence**, not opaque); messages range on `(conversationId, at desc)` bound 200 plus take+1 **has-more**; the rows; the result.

**(a) Local optimistic `send` while offline.** Prediction = mutation IR against the held closure (insert rule is the membership lookup plus the write), then `thread` re-run against closure ∪ write-set. If the membership row or its absence is held, the insert rule is decidable: presence → predicted insert; absence → predicted reject. A membership revoked on the server while we are offline is not visible — we may predict success from a stale witness (information limit); settlement re-evaluates and may `rejected`. Re-running `thread`: the new row sits in the messages pattern; a `commitTime`-stamped send lands at the top of a desc window; cover holds if we have the window bound.

If `thread` were JS that did `const rows = take(200); if (rows[0].body.includes("@ai")) db.get("ai_meta", rows[0].id)`, sending `"@ai hello"` demands a range the last trace did not contain. Re-exec traps `MissingData` → `partial`. The snapshot closure does not describe what the *next* execution needs. A program closure would have required `nest({ aiMeta: m => ai_meta.byId(m.id) })` on every page row — empty ranges pre-declared. That tax makes (a) sound. Overlaying the write-set onto the last *result* without re-running the query is cheaper and wrong for any filtered view.

**(b) Local delete of one held row.** Static `Page<Message,200>` plus take+1 is a compile-time obligation to ship a boundary fact. After deleting an in-window row: sentinel "no more" → 199 is still complete; sentinel "has more" without row 201 → `partial`. We know because the *type* demanded the sentinel. A Convex-style `.take(200)` trace typically does **not** read row 201, so re-running returns 199 and looks complete. The range descriptor can carry the same sentinel only if traces are specified as **range descriptors with stop-reason** (`limit` vs `empty`) — already the encoding of `Page`. Specifying that *is* static analysis of windows.

**(c) Membership revocation while offline.** No language, trace, or lease learns this without communication — an information limit, not a program limit (Codex). Local re-exec keeps succeeding against the stale membership row; status is `stale`, never `fresh`. On reconnect the server re-evaluates the inlined rule (membership is in the *program* read set even if `thread` never names it), ships absence, client purges. Tracing also works *on reconnect*; neither helps *during* the partition. Leases expire or lie. `stale` plus reconnect-recheck deletes leases as a user-facing object.

#### Static vs tracing, and composition

Static derivation beats tracing at admission (refuse unbounded scans at `check`; LLP 0120: a Convex scan and a bounded read look identical at the authoring site), indexes, **rule inlining** (membership is in `thread`'s read set even when empty — that artifact invalidates messages on a membership write), the certificate at the definition site, local writes, keeping JS out of the data plane, Postgres graduation, and first hydrate. Tracing beats static at data-dependent extra reads (the `@ai` branch), tighter invalidation windows, authoring speed (why Convex won Linear/Relay/Split), and not needing a language spec.

**They compose: type and value of the same closure, with a subset assertion.** `check` admits a plan only if it derives a program-closure type and `examined ≤ G`. Every execution records a snapshot-closure value; **captured ranges must be ⊆ the program-closure instance** (violation = compiler bug — LLP 0120 finding 5 as insurance, not evidence). Client stores the snapshot keyed by `(plan-hash, args, viewer)` and re-executes the same IR. After a local write, cover → re-exec; not cover → `partial`; never silently complete. Dynamic windows invalidate; the static shape retains and re-executes. They do **not** compose if you skip the type — that is the crux hypothetical, a result cache plus a JS sandbox that becomes Zero the first time an agent writes a data-dependent `for`. I refuse it as the data plane.

Disagree with 0329.004's trilemma: "static derivation" was identified with Snapback's two-source unique-join; that poverty is not implied by having types. Agree with 0329.005 F1. Disagree with P1's wording that "the function does not describe what data it needs": the last *execution* can. What it cannot describe is what the next *local* execution will need.

### 3. Your proposal

**Rank 1 (build): bound-carrying algebra, named operations, compile-time composition, Rust IR both sides.** Rank 2 (reject): sealed-trace JS as a query language — Convex DX, then a 212k-line client implementing `MissingData`. Effects exist in rank 1; they are not queries.

**Admitted.** Four sorts in the model, a fifth outside it. (1) **Tables** — keys, portable scalars, refs, indexes; deny-by-default. (2) **Row rules** — same language, per effect; the only authorization. Missing rule is a `check` error. `publicData(reason)` is conspicuous, emits a security item, unlocks nothing. Rules inline as `exists`/`filter`. Recursive auth is `recurse` or `Maintained`. (3) **Named operations** — the sync unit; read vs transaction inferred; views inline at `check`; the client cannot invent a query. (4) **Named mutations** — DML + `assert` + `alloc` (sequence; write-side, LLP 0135). The mutation IR *is* the predictor. (5) **Effects** — JS/TS with I/O; not live, not retainable, not predicted; they write tables by *calling* mutations.

Operators: lookup, index-prefix `where`, `order` (`_id`-tied), `take`, `nest`, `exists`, unique-ref `with`, unique-index equijoin, `group`+`count`/`sum` on a `Page`, `maintain(count|sum)`, `recurse({along, depth, fanout})`, DML, `assert`, `alloc`; scalars; `viewer()`; `commitTime`. Sequence allocation is not a query.

`Unbound<T>` cannot execute or `count`. `Page<T,N>` executes; aggregates are exact over the page. `Row<T>` is unique lookup. `Maintained<T>` is a same-commit derived point-read. Exact-over-an-arbitrarily-growing-group is **only** `maintain`. Bare `.count()` on `Unbound` is a type error: `.take(K).count()`, `.countCapped(K)`, or `.maintainCount({by})`. `maintain*` is always explicit.

Five constraints, not a sixth. (1) No Turing-complete per-row computation. Builder callbacks run at **build time**; they cannot `if` on a runtime row. **Relational `if`/`case` in the AST is admitted** when both branches are present (`examined ≤ examined(b1)+examined(b2)`). P4's "no row-level if/for" is necessary at the callback layer, too strong in the algebra. (2) Every executing collection is bounded or maintained. Ceiling `G` (loud default 10_240) is a compile-time fact of the plan, never a function of invisible-row counts. Every filter is index-served or a ref traversal, else refuse with the index to add. (3) Schema-closed. (4) Deterministic given `(snapshot, args, viewer)` — no `now()`/`random()`/I/O; `commitTime` provisional locally; `id()` a client-safe mint reused at settlement. (5) Authorization is in the language; a query cannot widen a table rule. Drop Snapback's sixth constraint — few operators, each a specified *product*.

**Refused.** JS handlers as query/mutation spelling (LLP 0320). Unbounded scans, `now()` in reads, ad-hoc client joins with completeness, exact `min`/`max` under deletion. `maintainCount` over a protected source unless `check` proves `source.readable` is implied by the group-parent's rule (else refuse or partition per principal). No second optimistic implementation. No authored `reads:`/`writes:`/`retainable`/`auth:` on a query.

**Derived, never authored, each an IR artifact:** read/write sets (terms plus inlined rules — membership invalidates `thread` because the rule is in the plan); program-closure type (= retention eligibility: admitted ⇒ retainable; private is paved); snapshot-closure value (windows ⊆ type; invalidation and hydration); authorization witnesses (viewer-visible rows or absence — Clique must not need opaque verdicts); indexes and cost certificate (printed at `check`); optimistic prediction (mutation IR against the held closure; query IR re-run when still covered); capability certificate on the plan hash. If any cannot be produced, the program is not an operation.

Runtime states are information, not constructors: reads `hydrating | fresh | stale | partial`; intents `predicted | queued | committed | rejected`. `partial` = a nested window beyond the retained page. `stale` = disconnected last-authorized snapshot. Revocation while disconnected is unobservable; reconnect re-evaluates rules and purges. Encrypted per-principal store; sign-out destroys the key. Max offline age is a deployment policy, not an eligibility switch.

**Substrate.** JS does not run in the authoritative data path for queries or mutations. Server: Rust IR interpreter over SQLite, one serializable transaction. Client: the **same IR**, a small interpreter (WASM or compact TS) over range-descriptors → rows — not SQL, not the app's JS, not a planner. Effects: JS sandbox cold-started off the request/tx path (DK-5 shrinks to this; actions remain open against Hermes/Ibex). LLP 0320: the rebuild is "JS is not in the data plane," not "compile JS to HostPlan."

**Client: a closure cache + outbox + IR interpreter.** Not a result-only cache; not a replica. DK-9 reached by refusing ad-hoc completeness rather than punching holes in a replica. Rows sit in the cache because the IR needs them. Canonical-row reuse is later (0155 Move 2), not v1. It stays small because it no longer implements a capability matrix. The eight states above are the offline contract (Codex's second root cause). 0329.000 F-B: a closed language with a Metro race still loses Clique — `check`/`dev`/`verify` and one generation identity are co-equal with the IR.

**Postgres.** The IR is the product contract; SQLite and Postgres are physical lowerings. Portable scalars, deterministic collation (0120 finding 7: refuse `localeCompare`), serializable outcomes (`SERIALIZABLE` plus retry). `Maintained` → same-commit incremental tables. `recurse` → `WITH RECURSIVE … CYCLE` with the compile-time cap, or a maintained closure table.

**Spelling.** TS build-time builder in §4 (inferred types are half of Convex's DX gap). Restricted SQL is the same IR. Settle by a one-week census bakeoff, not taste (0329.000 D1).

**Disagreements.** F6 as a keep-list for `reads:`/`writes:`: no. Fable keeping JS in the data plane: no. 0155 Move 1 as *product* nodes: copy Zero's outcomes, not 0157's registry. 0329.003 refused a replica engine correctly and omitted nest/group/recurse from named queries incorrectly (P3). Query/query hybrid is F1 with better names.

### 4. Worked examples (concrete code, in your proposed spelling)

Callbacks construct AST. `q.id()` / `commitTime` are modeled slots. Certificates are `check` output.

#### Clique private chat

```ts
import { app, t } from "@snapback/model";

export default app(({ table, rule, op, viewer, publicData, exists }) => {
  const users = table("users", { id: t.id, handle: t.text.unique() });
  rule(users, { read: publicData("display names") });

  const conversations = table("conversations", { id: t.id, title: t.text() });
  const memberships = table("memberships", {
    conversationId: t.ref(conversations), userId: t.ref(users), joinedAt: t.commitTime,
  }, { key: ["conversationId", "userId"] });
  const messages = table("messages", {
    id: t.id, conversationId: t.ref(conversations), authorId: t.ref(users),
    body: t.text, at: t.commitTime,
  }).index("byConvo", ["conversationId", "at"]);

  const memberOf = (cid) =>
    exists(memberships.byKey({ conversationId: cid, userId: viewer() })); // Row|Absence

  rule(conversations, { read: (c) => memberOf(c.id) });
  rule(memberships, {
    read: (m) => memberOf(m.conversationId),
    insert: (m) => m.userId.eq(viewer()).or(memberOf(m.conversationId)),
    delete: (m) => m.userId.eq(viewer()),
  });
  rule(messages, {
    read: (m) => memberOf(m.conversationId),
    insert: (m) => m.authorId.eq(viewer()).and(memberOf(m.conversationId)),
    delete: (m) => m.authorId.eq(viewer()),
  });

  const thread = op({ conversationId: t.ref(conversations) }, (q) =>
    messages.where((m) => m.conversationId.eq(q.conversationId))
      .order((m) => [m.at.desc(), m.id.desc()]).take(200)
      .nest({ author: (m) => users.byId(m.authorId) }));

  const send = op({ conversationId: t.ref(conversations), body: t.text },
    (q) => messages.insert({
      id: q.id(), conversationId: q.conversationId, authorId: viewer(), body: q.body,
      // at: schema commitTime. Local provisional; server settlement delta.
    }));
  return { thread, send };
});
```

```
thread  Page<{msg, author: Row<User>}, 200>  examined ≤ 402
        indexes messages(conversation_id, at), memberships(conversation_id, user_id), users(id)
        auth memberships.byKey ∈ read set (inlined); retain/local-reexec/predict(send) yes
send    writes messages; reads memberships.byKey; examined ≤ 2
```

Cold-open is the last snapshot closure. No `auth`, no `retainable`.

### 5. Evaluation of LLP 0329.005's P4

**Right.** The trilemma's "limited" cell is an artifact of identifying static derivation with 0080/0110/0157 product poverty. The four 0120 shapes are operators, not capability ids. Cardinality-as-type is what makes "restricted" and "expressive" compatible. Named operations, compile-time inlining, query/effect, static shape + dynamic windows, client as closure cache, JS out of the data plane, capture as assertion: §3 is that architecture with the holes below filled. P0/P1/P2/P7 fail 0329.004 as P4 said. P5 is the right literature for `Maintained`/`recurse`, the wrong Clique authoring language.

**Fails or costs too much.**

1. **`Maintained` × protected sources.** Visibility-before-aggregation and "the maintained row is one number" fight. A global `cardCount` over unreadable cards leaks existence (0120 §Noninterference). Repair P4 does not pin: implication proof at `check`, refuse, or per-principal partition.
2. **Write-path coupling** of `maintainSum` on Split. Hot-key ±1 replaces scan contention (0120 named empirical expectation, unmeasured). Preimage, group-move as −1/+1, overflow, idempotent replay, rounding are a real spec.
3. **Over-refusal of row-level `if`/`for`.** Necessary for *JS callbacks* (otherwise there is no AST). Not necessary in the algebra: relational `case`/`WHERE`/`Page.forEach` with static `N` are bounded terms. Refuse data-dependent *construction* of new terms; do not refuse *selection* among already-typed terms.
4. **Rerun-and-diff.** Honest v1; 636-examined `boardView` is cheap. Per-card nests will want IVM sooner.
5. **Spec cost.** ~12 operators once *should* be cheaper than the next three profiles. Judgment, not measurement. Weak `Unbound.count` diagnostics send agents through an effect-shaped back door.
6. **Does not fix Metro, identity rebind, media.** Co-equal with the language (0329.000 F-B).

**Census bakeoff vs Convex — predicted, not measured.** Clique chat paved on both; we retain private; Convex's offline cell is **[inferred]** no. `boardView` close if the builder is TS. `boardSummary`/Split: Convex `for`; we force `maintain` or a type error. Graph: `recurse` or refuse vs unbounded walk. Capability should not lose; time-to-green Convex still wins on first paste. The 0129 holistic gap (Convex 74–79, snapback-explicit 61) was ceremony plus loop, not a shape-ceiling. **Match Convex on Clique chat if the builder looks like TS; lose a beat on Split/summary; beat Convex on private offline and inspectable bounds.**

### 6. Refusals and objections

**Cannot express:** ranked-by-model-score feeds; `now()-5min` live windows; unbounded org-chart as one callable; exact `min`/`max` under deletion; client-invented joins with completeness; recursive auth without `recurse`/`Maintained`; full-text rank / embeddings as queries; data-dependent term construction; a Convex N+1 over Unbound. Effects, pages, or refusals — not the 0120 census.

**Three strongest objections.** (1) **The effect hatch becomes the handler.** Agents route around `Unbound.count` by writing an effect that scans and writes a table. Totality of *queries* is preserved; authoring is two classes again. If `check` does not make `.maintainCount` / `.take` cheaper than `effect`, F1 returns as incentive design. (2) **Maintained aggregates on SQLite are unmeasured.** Split-at-production, four ±1s per write, single writer. If contention is bad we will be told to "just scan," then weaken the type or eat latency. (3) **A small IR interpreter still grows.** Rebase, provisional clocks, partial windows, encryption, generation identity. Freeze the offline contract in v1 or we re-accumulate leases. The states in §3 have to be the only states.

**Most likely Clique loss to Convex.** Not a missing operator. The builder looks like JS; the agent writes `rows.filter(r => …)` or a `for` over Unbound; the diagnostic is technically correct (`LANG_OPAQUE` / `E_UNBOUND`) and socially useless; the agent burns the milestone fighting the type system or copies a Convex loop into an `effect`; offline then fails because effects are not retained. Convex's Clique win was "zero wiring, a query is code." If our first error is a cardinality lecture, we lose B-scores the way Familiar lost. Repair: cookbook diagnostics, fast `check`, a `dev` that does not rebind identity. The language is necessary and not sufficient.
