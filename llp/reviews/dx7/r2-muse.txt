State explicitly that startup checkpoint retains the existing durable pause value and never clears it. Otherwise a restart after `drain:false` or failed/interrupted drain can clear the pause.
* Downgrade loses enforcement. Downgrades ignore the additive record and retain historical process-local behavior. That means a downgraded binary preserves but does not enforce the pause, so maintenance can run while paused. Required: downgraded runs must preserve the record without clearing it, and the proposal must state downgrade does not enforce pause, or fence maintenance when unknown metadata is present.

If the whole additive record plus commit stamp and schedule boundary are removed, time also rewinds to wall. State that explicitly, or place commit stamp and schedule boundary outside the removable record.

State the intended reset path explicitly: store recreation, or an explicit privileged reset. Otherwise staging time is permanently forward-only with no operator recourse.

## Rendered and scrollable text

* `overflow-x/y` interaction missing. CSS computes `visible` to `auto` when the other axis is `hidden`, `clip`, or `scroll`. Require computed-value handling per axis, otherwise independent per-axis clipping is wrong.
* `position:fixed` and `sticky` unaddressed. Fixed text inside a scrollport does not scroll with it; sticky has bounded scroll coupling. Composing scroll shifts for every descendant overcounts fixed and mishandles sticky. Require fixed to skip ancestor scroll shifts, and define sticky behavior or explicitly exclude it.

## Upgrade and gate presentation

* Ack atomicity unspecified. A refuted invariant cannot be acknowledged, records untouched, `--ack-security was not applied` reported, JSON `acknowledgmentNotApplied` carries the explanation. Specify all-or-nothing versus per-ID when one ID in a multi-ID ack is refuted, and that exit status still fails. Otherwise partial writes confuse repair.
* Old-CLI bypass unclear. An already published old CLI may print its old `E_UPGRADE` line while the new check child carries the actionable explanation. State that old-CLI upgrade cannot ack or bypass new gates and must route through the new check, or old-CLI upgrades remain a bypass lane.
* Numeric-advance scan soundness. ## Protected immutable payloads

* Delete plus re-insert bypass. Ignoring supplied protected immutable fields on update and existing-upsert without comparing stored data is correct for noninterference, and succeeding when only those fields differ avoids an oracle. But delete then insert, or delete then absent-upsert, can install a new value. State whether delete is separately authorized for these rows, or close the lane. Without this, immutability is advisory.
* Orphaned upload handling missing. No ownership or placement check runs for the ignored field because no asset is adopted. State orphan cleanup and accounting so ignored uploads do not accumulate or get adopted elsewhere.
* Validate-then-ignore failure semantics should be explicit. Validating types and bounds before ignoring means an ill-typed ignored field still fails. Confirm that is intended, and that failure messages use schema and site facts only with no stored-value comparison.
