## Findings

### 1. MATERIAL — IN-DELTA — §4.5, §5.1, §5.2

**Scenario A — old `W`, new payload.** `W` is 10 and the G6 slot for query Q holds the prefix-10 result. The publisher installs the prefix-40 payload into that slot, then release-stores `W=40`. A lock-free reader that already acquired `W=10` looks up Q and returns the prefix-40 payload. It observes commits 11–40 above its `W`. The same window exists for a promoted G5 entry whose certified generation is bumped in place before the store. Baseline G5 survives only because the validation statement rechecks revision equality. "Acquire `W` before lookup" stops a reader who sees `W=40` from using a pre-invalidation entry. It does not stop a reader who sees `W=10` from using an entry already replaced with the unpublished prefix.

**Scenario B — wakeup consumed before `W` is visible.** A held `/changes` poll has armed on `W=49`. The publisher enqueues the wakeup, the continuation, or the ordered reply, then stores `W=50`. The waiter runs, still observes 49, and sleeps. Nothing else is written, so the poll is not woken again. The subscriber misses a commit that is already below the true prefix. A server-side continuation that reads in that gap likewise builds its follow-up from the old prefix.

**Fix.** Make publication a single release sequence: invalidate, then install cache entries immutable in `(identity, W)`, then release-store `W`, and only then send replies, continuations, and `/changes` wakeups. A hit requires the entry's `W` to equal the acquired `W`. An install must fail if `W` has moved since the fill was read. Waiters recheck `W` after arming. Add that interleaving to witness 6 before R1 and R3 can serve concurrently.

### 2. MINOR — IN-DELTA — §6.6

**Scenario.** A pooled backend runs `pg_advisory_lock_shared`, then the later qualification statement refuses the token or digest. The session-level lock stays granted. A later takeover's watcher treats that backend as a live current-owner holder ("renewed owner not killed") and will not terminate it, so the exclusive token transaction never grants. Takeover fails closed and `W` never resumes.

**Fix.** Qualification failure unlocks that backend, or disconnects it, before reuse and before the watcher can classify it as the renewed owner. Cover that in witness 5.

### 3. MINOR — PRE-EXISTING — §5.1

**Scenario.** A reader binds `V` at `W=10`. Two later commits of the same row are visible in the snapshot, so `owm=20 > 10` and `sb4_stale` fires. §5.1 restarts the snapshot up to three times, then `E_STORE`. It never says the restart samples `W` again. Reusing `V=10` fails the same way on every attempt, including the witness-6 case of one row rewritten twice, and any stream that touches a row dispatched after the original sample.

**Fix.** Each restart discards the snapshot, acquires `W` again, and opens a new snapshot. Streams do this before any emission.

## Routing, budget, gates

Routing is coherent. Conflicts hold or drain. They do not run as hot SQL. Footprints stay in `U` until `W`. One sequencer does not rewind an open reservation. Per-client minima plus prefix-ordered acknowledgements give read-your-writes. Keyed work still pays a full R→O drain, and §10.3 correctly refuses default-on until keyed W4 and the 1% mix hit the same rungs.

The 4,525/s path is not credible from the measured components, and §8 does not pretend it is. Round-2 native means are 7.04–7.24 ms. Stripping the 0.805 ms mailbox and the 0.197 ms in-flight pool wait leaves about 6.04–6.24 ms, already above the 6.0 ms R0 gate, before prefix-ordered acknowledgement delay, two-image WAL, and the wider `_commits` row. Those restorations are inside the R0 gate rather than credited. The 0.4 ms to 6.4 ms is only integration margin after a 450b R0 pass. Ordered L′ remains the fallback if that gate misses. No fewer-moving-part design both sync-commits every request and shows a coherent prefix: out-of-order commits into `r` are why `W` and the two images exist, and early acknowledgement above `W` is correctly left as author question 4.

The existing stop rules catch a lost acknowledged write, a dual commit and void, a late old-owner commit, and an R0 mean above 6.0 ms. They do not catch finding 1. Witness 6 can pass with a locked reader while lock-free G6 and `/changes` still lose the race.
