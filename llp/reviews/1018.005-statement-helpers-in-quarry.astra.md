The `proc`/expression-only `fn` split is sound, but the draft needs revision before implementation. Several claims about existing compiler behavior are incorrect, and the proposed composition misses concrete scoping, certification, and validation cases. I checked the source and ran read-only probes through the current TypeScript compiler and existing Rust checker binary.

1. **MATERIAL — Explicit `return` rejection does not prevent implicit returns.**  
   [`ExpressionBinder.statements`](/Users/ccheever/projects/snapback-worktrees/clique-snapshot-impl/snapback2/packages/compiler/src/quarry/bound.ts:125) defaults `completion` to `true`, propagates it into final `if`/`match` branches, and marks final expressions as completing. [`lowerStatements`](/Users/ccheever/projects/snapback-worktrees/clique-snapshot-impl/snapback2/packages/compiler/src/quarry/direct.ts:136) then emits `Return`. A proc ending in `insert` could consequently return from its caller; a final update/upsert would additionally acquire a result read. Specify `completion=false` throughout proc bodies, separately prohibit explicit returns recursively, and define a final proc call as falling through. The rewrite should say “caller,” since queries and jobs are also allowed callers.

2. **MATERIAL — Symbol IDs do not currently make list-parameter loops hygienic.**  
   [`direct.ts:204`](/Users/ccheever/projects/snapback-worktrees/clique-snapshot-impl/snapback2/packages/compiler/src/quarry/direct.ts:204) recognizes any list-valued `BoundArgumentSymbol` and emits `ArgList { name: symbol.name }`, bypassing `lowering.bindings`. A proc parameter `xs` can therefore resolve to the caller’s `xs`, or an absent runtime name, instead of its captured actual.

   Correcting that lookup also exposes a certification limitation: a captured list inside an `if` or enclosing loop becomes an unknown population origin in [`fanout.rs::Flow::statements`](/Users/ccheever/projects/snapback-worktrees/clique-snapshot-impl/snapback2/crates/snapback2-core/src/certificate_policy/fanout.rs:186). My probe certified `if true: for x in xs: insert …`, but refused the equivalent branch containing `ys = xs; for x in ys` with `E_STRUCTURAL_FANOUT`; the same binding at operation scope certified. The promised contextual substitutability needs an explicit resolution and coverage for both branch and loop callers.

3. **MATERIAL — Jobs already permit `emit`; effect-name scope is unspecified.**  
   The draft’s assertion that a job caller refuses at `emit` is false. [`bound.ts:179`](/Users/ccheever/projects/snapback-worktrees/clique-snapshot-impl/snapback2/packages/compiler/src/quarry/bound.ts:179) rejects only queries. The existing [`digestSweep` fixture](/Users/ccheever/projects/snapback-worktrees/clique-snapshot-impl/snapback2/packages/compiler/fixtures/quarry-schedules/snapback/admin.q:3) emits, and `quarry-schedule-checks.ts` certifies it. My job probe likewise certified `_outbox` writes.

   More substantially, the binder’s effect map comes exclusively from the calling operation’s module; `functionCall` switches function/shape modules but has no effect-scope machinery. An imported proc’s `emit notify` therefore needs defined lexical resolution, including collision tests. [`placementDiagnostics`](/Users/ccheever/projects/snapback-worktrees/clique-snapshot-impl/snapback2/packages/compiler/src/quarry/index.ts:110) also currently forbids effect imports in modules without operations, preventing a natural proc-only effect helper module.

4. **MATERIAL — Joining the existing registry and statement binder omits validation passes.**  
   [`whereRepairDiagnostics`](/Users/ccheever/projects/snapback-worktrees/clique-snapshot-impl/snapback2/packages/compiler/src/quarry/where-repair.ts:9) visits only operation bodies. The binder does not reject or implement `range.where`. I verified that an existing `fn` containing `rows[] first 2 by byId where .kind = 'a'` compiles and certifies with the predicate discarded. Proc bodies must enter this pass.

   Similarly, [`catalog.ts::buildCatalog`](/Users/ccheever/projects/snapback-worktrees/clique-snapshot-impl/snapback2/packages/compiler/src/quarry/catalog.ts:73) validates channel/program parameters, but not function parameters. A duplicate-parameter `fn pick(x: int, x: int)` currently compiles and selects the second argument. Reusing that registry is insufficient for proc parameter validation. Include declaration placement, parameter validation, and body traversal explicitly.

5. **MATERIAL — General certificate parity with ordinary explicit bindings is overstated.**  
   Fresh `Const`s preserve once-only evaluation, but they are charged: my small enum-helper probe changed certification from 13 to 15 steps and 416 to 480 heap bytes, with identical write bounds. More importantly, [`functionCall`](/Users/ccheever/projects/snapback-worktrees/clique-snapshot-impl/snapback2/packages/compiler/src/quarry/bound.ts:927) replaces actual facts with the declared parameter type. Passing `[int] <=2` through a helper parameter `[int] <=50` changed a loop’s certified writes from 2 to 50 in another probe. Plain `x = value` preserves the narrower facts.

   Row-to-ID coercion also means the baseline must bind the ID, not the original row snapshot. Define parity against equivalent coercions and formal bounds, and distinguish semantic results/read-write behavior from identical resource bounds. This does not undermine the particular delivery helper.

6. **MATERIAL — Definition/use diagnostics are not inherited uniformly.**  
   Query-write rejection already uses `diagnosticSite`, but ordinary unknown names, some type checks, and refusal-code validation use raw authored sites. Query `new` and `commit` bind successfully today and fail later as `E_AMBIENT_TIME`, at the program rather than the authored expression. [`direct.ts::accessSite` and `recordLoopSource`](/Users/ccheever/projects/snapback-worktrees/clique-snapshot-impl/snapback2/packages/compiler/src/quarry/direct.ts:788) retain only `source.definition`, discarding `source.use`; `QuarryError` also labels expansions “named shape.”

   The blanket two-site diagnostic promise needs additional implementation scope and tests, especially downstream certification failures. Migration must also update the assertion in [`quarry-direct-project-checks.ts:34`](/Users/ccheever/projects/snapback-worktrees/clique-snapshot-impl/snapback2/packages/compiler/src/quarry-direct-project-checks.ts:34) that every `messages.send` loop originates in `messages.q`; the proc loop originates in `access.q`.

7. **REFUTED-RISK — The construct and refusal ownership are reasonable.**  
   `proc` clearly distinguishes a statement helper; neither `do` nor `step` fixes a demonstrated semantic problem. Keeping `fn` expression-only preserves its implemented purity boundary. A proc should not increment `helperDepth`: that would reject its writes, assertions, allocation, and mutation/job clock access. A nested `fn` must still increment it and retain every existing refusal. Actual arguments must bind before entering the callee’s scope, allowing caller-side `new` exactly once. See [`bound.ts::contextName`, `write`, and `functionCall`](/Users/ccheever/projects/snapback-worktrees/clique-snapshot-impl/snapback2/packages/compiler/src/quarry/bound.ts:528).

   Allowing a proc’s `require … else CODE` to abort its caller with `CODE` is appropriate. [LLP 1018.000 §7](/Users/ccheever/projects/snapback-worktrees/clique-snapshot-impl/llp/1018.000-composable-architecture-next-moves.research.md:402) constrains expression helpers; it does not prohibit an explicitly invoked statement block from owning a guard. Preserve the recipe’s existing caller-specific membership and authorship codes.

8. **REFUTED-RISK — Ordinary local hygiene is achievable with the existing identities.**  
   Apart from the list-loop exception above, parameter-only scope and monotonically fresh symbol IDs prevent capture in both directions, including repeated calls. Bind the proc’s outer body with `allowOuterShadow=false` to prevent redeclaring parameters; nested blocks can retain their existing shadowing rules. Give each invocation a fresh `failedBindings` set and restore scope, focal, module context, and failure state in `finally`.

   The [`recovery checkpoint`](/Users/ccheever/projects/snapback-worktrees/clique-snapshot-impl/snapback2/packages/compiler/src/quarry/bound.ts:133) journals only names published by a binding statement. It works for an invocation only if all proc-local publication stays inside that isolated scope. Restore the entire lowering binding map afterward: the current `for` branch restores its loop symbol but leaves body-local map entries behind. Fresh IDs make those entries inaccessible, but they should not become invocation exports. Clearing the incoming focal is correct; writes and shapes inside the proc establish their own focals.

9. **REFUTED-RISK — Shared expansion frames are the right budget mechanism.**  
   [`expansionFrames`, `MAX_EXPANSION_DEPTH`, and `source()`](/Users/ccheever/projects/snapback-worktrees/clique-snapshot-impl/snapback2/packages/compiler/src/quarry/bound.ts:1147) already account for mixed named expansion. Add proc identities to that same stack and charge expanded statements through the same node budget. Eight should mean nested named expansions, not eight nested `if`/`for` blocks. Nothing examined justifies a separate or larger allowance.

   One qualification: `BoundFunctionRegistry.resolve` detects traversed import cycles, and `functionCall` detects reached call cycles; the registry does not eagerly validate every unused declaration’s graph. State whether proc cycles have the same reachability-based contract.

10. **REFUTED-RISK — The recipe census, enum type, and query reachability check out.**  
    The six loops are `deliveries.post`, `unsend`, `edit`, `purgeMessage`, plus `messages.send` and `sendOncePhoto`; `sendPhoto` and `sendClip` supply the two missing sites. [`parser.ts::parseType`](/Users/ccheever/projects/snapback-worktrees/clique-snapshot-impl/snapback2/packages/compiler/src/quarry/parser.ts:573) represents enum arguments, and `assignableBoundValue` accepts variant subsets. The proposed enum exactly matches `deliveries.kind`; my enum-parameter insert probe certified.

    `conversationMembers` is reachable from a query: a probe using the actual chat schema/access module certified its bounded membership loop. A query calling `deliver` should fail when binding the insert, not before reaching the membership read. Fixture changes are mandatory: [`quarry-chat-composition-checks.ts:20`](/Users/ccheever/projects/snapback-worktrees/clique-snapshot-impl/snapback2/packages/compiler/src/quarry-chat-composition-checks.ts:20) compares `access.q`, `deliveries.q`, `groups.q`, and `messages.q` byte-for-byte.

11. **REFUTED-RISK — Existing IR can carry the implementation and twin execution.**  
    Both interpreters execute `Const`, `For`, writes, and `Require`; neither needs a runtime proc instruction. Existing helper tests already compare read sites, traced points, and once-only argument allocation. The chat composition test predicts `post` and `unsend` through `ClientStore`.

    [`certificateMaxNewIds`](/Users/ccheever/projects/snapback-worktrees/clique-snapshot-impl/snapback2/packages/snapback2/src/offline.ts:49) sums insert/upsert write bounds. Captures add no IDs; the migrated post remains 51, while photo/clip sends rise from 1 to 51. This function does **not** independently count arbitrary unused `new` expressions, so the proposed unused-argument test should also exercise real outbox allocation before claiming general prediction coverage.

    I found no fixed chat plan-hash or certificate-digest pin in the requested directories. Corpus certificates concern their own IR; `fake-owner.ts` computes hashes from its handwritten programs. Recompilation changes plan identity and requires fresh certificates, not a data-schema migration.

12. **MINOR — Guide work includes executable snippets and keyword plumbing.**  
    `quarry.md` is exactly 15,872 bytes; `grammar.md` is 3,475 of 3,584. The build enforces both limits. No current Rust test specifically requires a proc paragraph. However, adding a grammar construct row makes [`guideKeywords`](/Users/ccheever/projects/snapback-worktrees/clique-snapshot-impl/snapback2/packages/snapback2/build.mjs:545) require a defining paragraph, and [`quarry_keywords_print_grammar_and_definitions_beside_symbol_help`](/Users/ccheever/projects/snapback-worktrees/clique-snapshot-impl/snapback2/crates/snapback2/tests/guide.rs:169) requires a matching test entry.

    Replace the guide’s copied send loop/import with the proc call to recover space and preserve snippet equality; trim duplicated setup prose if needed. Preserve the Rust-pinned search and clock phrases. Update the reserved-bindings string assertion too. Incidentally, those names are documented as reserved but are **not currently rejected as bindings**: `bindingName()` just calls `word()`, and my `mutation fn(shape: int, cursor: int)` probe compiled.

13. **MINOR — No fundamental rules violation; the scope ledger remains documentary.**  
    Compile-time elaboration into existing IR fits `rules/NOT-DOING.md`: no second language, runtime compiler, recursion, or public plan algebra. A test module inside the existing compiler suite is not a sixth blocking gate. The decision names an implementer and date; the reported 1,277-line binder count is accurate, leaving 223 lines before the cap, although “roughly 200 lines” is unproven.

    Update LLP 1011 and LLP 1018.000 to record the new statement-composition scope and deliberate refusal ownership. I found no check requiring that ledger wording. The media ticket additionally requests rendered-thread assertions in browser and Expo witnesses; the draft’s real-owner assertion plus unchanged browser behavior does not fully specify that coverage.

VERDICT: REVISE — Preserve the chosen construct, but resolve completion, list-loop hygiene and certification, effect scope, validation coverage, and diagnostic guarantees before implementation.
