Specific findings:

1. Analyzer revision is required but not pinned. §19 says "witness-bearing decisions require a new analyzer revision", without naming it, without saying which codes bear witnesses, and without stating whether the bump is global or scoped. Under §17.3 and §16.5 the revision is a reviewed constant that drives invalidation. As written an implementer cannot implement "old rationales cannot silently close new evidence" correctly. Fix: pin the new revision, list the affected codes, and state the invalidation consequence for pre-existing records.
2. Witness identity and binding fields are ambiguous. §19 says identity "excludes incidental locations and wall-clock campaign results", and records "retain the displayed witness and candidate, alongside the rationale and semantic binding". It never states which witness fields (operation, caller, arguments, admitted effect, old/new image, candidate invariant) enter the ID, which enter the semantic binding, and which are stored-only. If images or arguments enter the binding, campaign nondeterminism could churn reviews. If none enter, only the global revision bump protects against stale closure. Fix: enumerate the bound fields explicitly, reusing the §17.5 construction.
3. Credential exclusion has no mechanism. "No credentials enter decision records or output" is asserted, but witnesses by definition carry caller, arguments and row images, which can contain passwords, tokens or private media. Prior sections state the same property alongside a concrete boundary. Fix: state the redaction rule (which argument/image fields are stripped or refused) and add an acceptance test asserting it.
4. Multi-ack atomicity needs a snapshot definition. Repeated and comma-separated `--ack-security` validated "completely and committed atomically under the existing lock/source race checks" is good, but family expansion is dynamic ("expands only to current advisory members"). The text never defines the snapshot the expansion and the source-digest check share. Fix: require one source digest plus analyzer revision for the whole batch, and require the output to list acked versus still-pending members so a partial family ack cannot be mistaken for full clearance.
5. Old family-alias semantics need an explicit display rule. "Previously displayed family aliases may acknowledge only their still-current original members" is the right safety property, but the resulting state (old members acked, new member pending, exit status, next command) is not specified. Since advisories are exit-0, the failure mode is silent incompleteness rather than a blocked gate. Fix: state the exact verdict and pending-member output for a partial family ack.
6. Derived-versus-refutation precedence needs an acceptance case. "Derived evidence cannot be used to override a reachable authored invariant refutation" is correct and important, but qualification does not list a test for it. Fix: add one regression where an advisory witness and a reachable refutation coexist, asserting the refutation still fails and still appears in default output.
7. Collapsed questionnaire fate is unclear. §19 "supersedes §18's default questionnaire", and §17.5 says the collapsed `N_TABLE_QUESTIONNAIRE` has no review ID and is only a human projection. It is now ambiguous whether that projection survives behind `--review`, is replaced by individual witness decisions, or is removed. Fix: state what `--review` and JSON each contain, and whether any guide or script referencing the collapsed form needs updating.
8. Qualification scope is under-specified. "Copies of all fifty schemas with baseline and SEC10 codes" is narrower than the §17.4 "inspect every new gate across 450 projects" practice, with no justification. The developer-loop bundle (refusal attribution, read-filter evidence, `usePage.loading`/`why`, starter hint, clock offset, upload guidance, `serve-check`, Expo pickers) is covered only by "targeted CLI/client regressions". Fix: name the per-item regressions, especially a non-disclosure test for refusal attribution and a completeness/freshness test for the hook projection; keep the Darwin skip as an explicit limitation as already written.

What is fine: keeping SEC10 detector and gate semantics unchanged, keeping gates individual with no bulk acknowledgment, keeping JSON complete regardless of display mode, atomic all-or-nothing multi-ack, and stating finite replay is not proof. None of the above requires a redesign, only precise amendments.
