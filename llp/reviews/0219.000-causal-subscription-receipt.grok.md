**Family:** Grok (xAI grok-4.6)

## Overall assessment

The commission is the right producer in the right channel, and the causal-chain table is the right shape of answer for O15. The RFC is not ready, because three load-bearing statements are false against the served stack:

1. The client does **not** already hold a watermark-vs-content split, so “watermark ≥ V without content at V ⇒ server-witnessed not-dependent” is not a join over existing handle fields.
2. The closed verdict order is not exclusive: `converged` eats both `applied-not-rendered` and, after any later content ≥ V, `not-dependent`.
3. `SNAPBACK_LIVE_QUERY_UNCONVERGED` as specified will fire in several healthy states (paused handles, unresolved quarantine, default headless poll).

### Answers to the author's six questions

**1. Central claim.** **Partly true on the wire, false on the handle as stated.**

LLP 0200’s four-phase program is complete and default-on (`llp/0200-live-evaluation-scheduling-and-settlement.spec.md` §6d, status still `Review`). Phase 1 landed the per-subscription watermark. The native scheduler **does** emit `current_as_of` for matcher skip **and** evaluated no-change, stamped at the commit version (`crates/snapback/tests/live_coalesce_v0.rs` `skip_and_no_change_advance_subscription_watermark`, lines 131–167). Envelope ordering is pinned (`watermark_never_overtakes_undelivered_content`, 172–204). The todo kit waits on that envelope as the skip-convergence signal (`demos/todo/tests/acceptance/headless.mjs:446–477`).

Degradations:

| Situation | `pending` | `not-dependent` | `converged` |
|---|---|---|---|
| Standalone skip/no-change `current_as_of(V)` observed | survives while watermark &lt; V | **wire-true**, but client currently treats the envelope as an **authoritative delivery** (see below) | false if content/watermark were split |
| Pending skips coalesced to one envelope at Vn | — | still true for every earlier skip Vi ≤ Vn (one latest-value watermark) | — |
| Pending skip superseded by later **content** W &gt; V (`pending_watermarks_coalesce_and_newer_content_supersedes_them`, 209–264) | — | **degrades**: no envelope at V; last content is W | **wins** under the RFC’s “content ≥ V” rule |
| Unresolved quarantine | watermarks **suppressed** server-side (`llp/0200-…spec.md:755–758`) | cannot be witnessed | cannot be witnessed |
| RQS resume `current_as_of` (token-bearing) vs scheduler watermark (no `resume`) | same `kind`; client uses one path (`packages/snapback-client/index.mjs:20432–20468`) | indistinguishable without new bookkeeping | same |

The JS client applies `current_as_of` by advancing `handle.version` **and** calling `onUpdate`, which sets `authoritativeRevision` and `lastDeliveryAtMs` (`index.mjs:18829–18841`, `20432–20468`). There is **no** `lastContentVersion` / `watermark` split in held state. React then `publishAuthoritative`s that callback (`packages/snapback-react/implementation.mjs:1742–1748`) and increments `suppressedEqualSnapshots` when the consumer-visible key is unchanged (`1232–1246`). The receipt example with `watermark: 1025` and `authoritativeRevision: 1023` is **not** current behavior.

OQ-3 (watermark wire economics / lazy watermarks) is still open in LLP 0200 §6. Today’s tests emit always; a later lazy rule would break this RFC unless the detector’s arming is the announced write-gate.

**2. Verdict set.** **Not closed, not exclusive.** States with no verdict: `explain()` with omitted `commitVersion` (guide step 1; V undefined). States that match two: `paused` + `not-attached` (pause sets `connection` to `'disconnected'` and unsubscribes, `index.mjs:21736–21761` — order saves this); `refused` + `fenced` after L19 (order saves this, correctly); **`converged` + `applied-not-rendered`** (order **kills** renderer/churn — acceptance item 3 is unreachable); **`converged` + `not-dependent`** after any later content ≥ V; `compareReceipts` of two subscriptions on **one** client (`shared-custody` vs the per-handle verdict). `authorization-suspended` / `connecting` / retained-but-live have no named verdict.

**3. Redaction / omitted O14–O15 facts.** **Leaks `connectionId` as a raw caller identifier** (forbidden by LLP 0219’s structural redaction, `llp/0219-client-dev-diagnostics-channel.rfc.md:207–213`; inspection already pseudonymizes, `index.mjs:704–718`). `function` and `argsDigest` are allowed. `rowCount` is a permitted scalar. O15 asked for hook → **authority generation** → commit → invalidation publication → subscriber revision (LLP 0317 OQ5 / O15). The receipt covers commit, watermark, fence disposition, and subscriber revision; it does **not** name authority generation. Cross-client (O14 shapes (a) and (c)) is explicitly not auto-detected; `explainAfter` with an out-of-band V is designed but **not in acceptance**.

**4. Detector soundness.** **Unsound as specified.** False fires in a healthy app: `handle.pause()` (T-UNSUB; watermark never arrives; clear conditions omit pause); unresolved `quarantine`/`delete` (server suppresses standalone watermarks); default headless `transport: 'poll'` (manual `handle.poll()` only, `index.mjs:18073–18075`, 18085 — connection is `'polling'` so it looks attached); `connecting`/`stale` if “still-attached” is not the verdict’s attached predicate. Own-write **is** well-defined on the JS client instance as `#recordMutationPhaseCost` / `__mutationCommitObservations` (`index.mjs:8691–8718`) — this instance’s settled `version`, not the principal. React/Expo ride that client. Unverified: Exact/Contract wrappers, and whether every familiar mutation path records `committedVersion`. Polling **fallback** cadence is 1.5 s (`DEFAULT_POLL_CADENCE_MS`, line 580), inside envelope+3 s grace — automatic poll fallback is probably fine; **manual** poll is not. Cross-client own-write is correctly out of automatic scope.

**5. Surfaces.** `handle.explain` / `explainAfter` / `compareReceipts` / `useSnapbackQueryReceipt` are the right agent-first split (sync join, wait-without-side-effects, pairwise custody, renderer projection). They do **not** by themselves change settlement/watermark/fence **if** they only read. Two hazards to the non-goal: (i) implementing the example receipt requires **changing what `authoritativeRevision` means** or adding last-content bookkeeping the RFC under-counts (“three scalars”); (ii) treating `suppressedEqualSnapshots` as `applied-not-rendered` would punish healthy equal snapshots (LLP 0278, `implementation.mjs:1232–1239`). Optional `current_as_of.disposition` is valid wire-v1 evolution (LLP 0093 D1, `llp/0093-client-protocol-and-native-clients.rfc.md:299–302`). Public `LiveQueryHandle` (`index.d.mts:918–971`) has no `explain`, no `authorizationDisposition` (the JS object has it at `index.mjs:18489`, types do not), and is not named `SnapbackLiveQueryHandle`.

**6. Acceptance vs “prevention landed”.** Acceptance is **mostly falsifiable but not sufficient**, and the closure sentence **misquotes** LLP 0317.000. §Measurement (`llp/0317.000-paved-loop-correction-program.rfc.md:438–455`): Wave 4 accepted design is **Routed**, not prevention landed; prevention landed is a Wave 2/3 change on `main`; P7 (`:135–137`) says only implemented, **published** behaviour counts. This RFC at Accepted cannot move O15 to prevention landed. Item 1’s `deliveryLagMs` on shapes (a) and (c) is false: those writers are the **other** client (`demos/_kit/tests/live-query-invalidation-e2e.mjs:1126–1149`, `1252–1292`), and `deliveryLagMs` only covers this client’s `__mutationCommitObservations` (`index.mjs:8798–8815`). Item 3 contradicts the verdict order. Item 4’s “paused transport” is not `handle.paused`. No `explainAfter` cross-client case. Guide + snippets (item 6) are necessary for O15’s “ladder before workarounds” but not sufficient under P7 until published implementation.

## Concerns

1. **MATERIAL — Central claim vs served handle (Design table rows 3–4; receipt example; Cost).**  
   The RFC says the client already holds “last delivered content frame version, or the `current_as_of(V)` watermark” as distinct facts, and that `authoritativeRevision` is “did the client apply it.” Served code uses one path for both (`index.mjs:18829–18841`, `20432–20468`; React `implementation.mjs:1742–1748`). Cost and hot-path only budget “last watermark version/kind/disposition (three scalars)” and never `lastContentVersion`/`lastContentKind`.  
   **Resolve:** State that v1 **adds** last-content vs last-watermark bookkeeping (four scalars, not three), and that `authoritativeRevision` / `handle.version` **keep** today’s meaning (every authoritative durable kind, including `current_as_of`). The receipt must not imply they already diverge. Pin that `not-dependent` is computed from those new fields, not from `authoritativeRevision < V`.

2. **MATERIAL — Verdict total order is not exclusive (Verdict set; Acceptance 3).**  
   `converged` requires content **≥ V** and is evaluated **before** `applied-not-rendered` and `not-dependent`. After a later matching write, a skip at V becomes `converged`. After content at V, a stale React snapshot or a live churn site never reaches `applied-not-rendered` — yet the `converged` prose says “if the UI disagrees, see `applied-not-rendered`.” Acceptance 3 is then impossible. `suppressedEqualSnapshots` as a disjunct of `applied-not-rendered` also misdiagnoses healthy equal snapshots (`implementation.mjs:1232–1239`).  
   **Resolve:** Make the predicates a partition on `(watermark, lastContent, renderer)`: e.g. lastContent ≥ V ∧ renderer (if present) ≥ V → `converged`; lastContent ≥ V ∧ renderer &lt; V or live churn site → `applied-not-rendered`; watermark ≥ V ∧ lastContent &lt; V → the no-content verdict; watermark &lt; V → `pending`. Do **not** treat `suppressedEqualSnapshots` alone as renderer failure.

3. **MATERIAL — Collapsed skip/no-change must not be named `not-dependent` (Verdict set; Server changes; OQ1).**  
   The engine already distinguishes skip vs no-change (`live_coalesce_v0.rs:141–167`; todo inspect `lastSkipped` vs watermark delivery, `headless.mjs:473–477`). The wire does not. Shipping the collapsed case under `not-dependent` plus “the query does not read the rows committed at V” is a false repair for net-no-change and for equal-snapshot evaluations (the exact “hook silent, one-shot sees the row” shape). That is not “still decisive.”  
   **Resolve:** v1 collapsed name must be honest (`evaluated-no-content` / `no-content-at-V`). Reserve `not-dependent` for `disposition: "not-dependent"` (or an equivalent engine fact). Until then the guide step is “do not poll; the server evaluated V and published no new result,” not “fix the predicate.”

4. **MATERIAL — Detector false-fires in healthy states (Channel producer; Acceptance 4).**  
   Arming is “still-attached ∧ watermark &lt; V”; fire is envelope + `liveReceiptGraceMs`; clear is watermark ≥ V or dispose. That ignores the earlier verdicts. `handle.pause()` unsubscribes and sets `disconnected` (`index.mjs:21736–21761`) — watermark will not arrive; pause is not a clear. Unresolved quarantine suppresses watermarks (`llp/0200-…spec.md:755–758`) — fence working, not a dark loop. Default headless liveQuery is **manual** poll (`index.mjs:18073–18075`) with `connection === 'polling'` after subscribe — healthy apps that poll on their own cadence, or not at all, look unconverged. Acceptance 4’s “paused transport” is not this pause API.  
   **Resolve:** Arm and fire only when `explain({ commitVersion: V })` would already be `pending`. Clear also on pause, dispose, refusal, fence, and loss of live/polling attachment. Define “own write” as this client instance’s settled mutation `version` (`MutationOutput.version`, `index.d.mts:408–444` — not `commitVersion`). Name the test injection “held drain / stalled socket,” not “paused.”

5. **MATERIAL — Redaction: raw `connectionId` (The receipt; LLP 0219).**  
   Example `subscription.connectionId` is a caller-supplied identifier (the O14 harness uses `o14_a_subscriber_${run}`, `live-query-invalidation-e2e.mjs:1139`). LLP 0219 forbids raw caller identifiers; local inspection already hashes the partition/connection (`index.mjs:704–718`, `implementation.mjs:4467–4468`).  
   **Resolve:** Pseudonymize `connectionId` the same way as `storagePartition`. Keep `subscription.id` (server-assigned). Do not put `authorizationDisposition` as a details key if the detector event rides the channel (`FORBIDDEN_DETAIL_KEY_PART` includes `authorization`, `client-diagnostics.mjs:43`).

6. **MATERIAL — Acceptance / Measurement (Acceptance 1, 3, 4; Implementation owner; LLP 0317.000 §Measurement, P7).**  
   (a) Shapes (a) and (c) cannot require `deliveryLagMs` “recorded” for that write: the subscriber is not the writer (`live-query-invalidation-e2e.mjs:1126–1149`, `1252–1292`); lag only covers this client’s commit observations (`index.mjs:8798–8815`). (b) Item 3 vs verdict order, above. (c) O15 at Accepted of this RFC is **Routed**, not “prevention landed” (`llp/0317.000-…rfc.md:135–137`, `448–454`). Prevention landed needs implemented **and published** behaviour; Proven stays Wave 5.  
   **Resolve:** Item 1: `converged` + content kind/version for (a)(b)(c); `deliveryLagMs` only for (b) (own-write). Add an `explainAfter` cross-client case with the writer’s `version`. Item 4: assert silence for not-dependent own-write, pause, and refusal; fire only on injected stalled attached drain. Rewrite the closure sentence to match §Measurement (Routed at Accepted; prevention landed at published implementation + guide).

7. **MINOR — `compareReceipts` false `shared-custody`.** Same principal + partition is true of any two receipts from one client.  
   **Resolve:** Require distinct client-instance / custody identity, not only matching digests.

8. **MINOR — `explain({ commitVersion? })` with omitted V.** Guide step 1 is bare `handle.explain()`. Closed set needs V.  
   **Resolve:** Either require V, or define omitted V as “latest own settled version on this client, else `not-attached`/`pending` with `asked: null` and no dependence verdict.”

9. **MINOR — Cited handle facts that are not public types.** `authorizationDisposition` exists on the JS handle (`index.mjs:18489`) and is tested (`authorization-invalidation.test.mjs:361–440`) but is absent from `LiveQueryHandle` (`index.d.mts:918–971`). `pendingObligationRevision` does not exist under that name (unverified as a fence-snapshot field via `authorizationState()`). Settlement carries `version`, not `commitVersion` (`index.d.mts:408–444`; `commitVersion` elsewhere is RQS/bundle).  
   **Resolve:** Project fence/refusal from existing public fields or add them to the type in this RFC; spell the asked version as `version` (alias `commitVersion` if you must).

10. **MINOR — Channel insertion of the nested receipt.** If the detector event uses `details: { receipt: {…} }`, `MAX_DETAIL_DEPTH = 2` (`client-diagnostics.mjs:8–9`, `109–110`) collapses the inner objects. A receipt-as-details-root survives because inner fields are scalars at depth 2.  
    **Resolve:** Pin “the v2 event `details` **are** the receipt” (or a flat subset: verdict, watermark, lastContentVersion, asked version, paused, connection, refusal code). New code on v2 does not need a new carrier version (OQ2 already closed as v2).

## Suggestions

- Compute the detector from the same function as `explain()`, so the console event cannot disagree with the handle.
- Put `applied-not-rendered` only on the React/Expo receipt (`renderer.arm` present). Headless `suppressedEqualSnapshots` is documented as always 0 (`index.d.mts:927–928`).
- For O15’s “authority generation” link, project the fence snapshot’s revision/episode from `authorizationState()` rather than inventing `pendingObligationRevision`.
- Keep the optional wire `disposition` in v1 schema as reserved, but do not let the collapsed client verdict pretend it is present.
- `useSnapbackQueryReceipt` should no-op (or return `not-attached`) when `useSnapbackQuery` is skipped / has no registry store, so it cannot start a subscription.
