## Blocking 1 — helper requirements ignore call actuals

`requirements()` calls `helper_guards(catalog, value, &Default::default(), 0)`: empty environment, so returned `Require` conditions keep helper **formal** names, never the call-site actuals. Both consumers treat them as established caller facts: `control.rs:302-305` (`record_advice_authorization`) and `query_branches.rs:202` (`state.gates.extend(requirements(...))`). `point_guard_safe` (`point_facts.rs:10`) accepts bare `Name`, so unbound formals pass the only gate.

Concrete false suppression:

```
fn hasOrders(x:customers): require exists orders[x] else NO
query q(x:customers, y:customers):
  hasOrders(y)
  return invoices[customer = x] last 20
```

The recorded branch fact is `exists orders[x-formal]`, which binds `$queryArg:x` and is used to prove the reader policy for a read keyed on caller `x` — but the helper established it for `y`. A sharper instance: a formal named `viewer` is never renamed by `bind_fact`/`bind`, so `fn check(viewer:principal)` called with anyone exports facts about the real caller. This violates scoped parent/child and namespace identity, and the "require-only pure helper" clause: a require-only helper is only sound with actuals substituted. Fix by threading the call's argument environment through `helper_guards` (as `expand`/`returned` already do) and rejecting conditions with unbound formals.
