## Blocker

[compare.py](snapback4/reports/sec11-latency/tools/compare.py) (`verdict()`, lines 7–12; claim repeated line 21) does not implement the exclusion the RFC promises. The RFC says timing and display strings containing temporary deployment paths are excluded. The code compares `gates`, `notes`, `reviews`, `checkFailure`, and per-mode `failure` bytes whole, with no scrubbing of embedded temp paths or timings. If the survey rows carry any run-specific path or duration inside a note `message`/`rewrite` or failure string, before/after will differ spuriously and the 800-schema gate fails closed; if rows are instead pre-normalized upstream, that normalization is unverified and the `comparison` string overclaims. Either way the RFC-promised exclusion is not evidenced in the tool. Fix by scrubbing only timing/temp-path display substrings in the comparator, or by proving the row producer already strips them — without normalizing any substantive decision field.
