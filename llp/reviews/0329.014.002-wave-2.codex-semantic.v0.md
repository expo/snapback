### 1. Coverage table

`h(N)=N+2` includes v0.1’s two-row halo. Missing product bounds are `A` operations/save, `B` blocks/note, `C` chunks/note/model, `P` placements/note, `V` visibility partitions/user, `X` devices/user, and `L` link redemptions. Consequently, formulas containing them are targets, not emitted certificates. Stated but not schema-enforced bounds are `H=5,000` held/direct notes, `R=200` team members, `S=12` artifact sources, `Q=500` snapshot items, and `F=500` migration jobs/batch.

### 2. Schema in v0

No complete admitted v0 schema exists. The closest lossless spelling below deliberately marks two absent forms: `opt(T)` and model-typed `vec`. `json({maxBytes})` can store vector bytes but cannot index or calculate with them. Every symbolic text/byte limit is also a product decision the design omitted.

  id:id(), email:t(EMAIL), displayName:t(NAME), aiAllowed:bool(), createdAt:time()

Traversed lists are normalized into capped child rows; opaque JSON lists would be unusable in rules and programs. Required maintained facts are:

```ts
maintain.sum(spendLedger, {
  by:["teamId","periodId"], of:"cents", as:teamPeriodSpend,
  readable:x=>currentMember(viewer,x.teamId) // explicit team-spend disclosure
});
maintain.count(partitionMembers, {
  by:["partitionId"], where:x=>x.state==="live", as:partitionSize,
  readable:x=>principal.kind==="system"
});
maintain.count(currentTeamMembers, {
  by:["teamId"], as:teamMemberCount, readable:x=>isTeamAdmin(viewer,x.teamId)
});
```

Migration coverage needs another durable coverage relation; rate limits need bucketed usage rows. Neither exists in the fixed design.

All rule profiles contain four effects:

- `SELF(owner)`: read/insert/update/delete only where `owner===viewer`.
- `SYSTEM`: all four require `principal.kind==="system"`.
- `NOTE_CHILD(noteId)`: read if system or `canRead(viewer,noteId)`; writes only system for derived rows, or `canEdit` for blocks.
- `SHARE`: read owner/grantee as appropriate; insert only note owner; updates may only narrow under `(old,next)` and immutable grant identity; delete never.
- `ARTIFACT`: requester may read; any other reader needs a grant **and every source readable now**; insert requester, update system, delete never.
- `SPEND`: read under the declared aggregate disclosure; insert only metered programs/system; update/delete never.

The attempted canonical rule is refused:

```ts
n.ownerId === viewer ||
db.exists(liveUserGrants.byNoteUser,[n.id,viewer]) ||
db.exists(currentTeamMembers.byTeamUser,[n.teamId,viewer]) ||
exists(teamGrantForNoteWhoseTeamContainsViewer)
```

`E_RULE_UNBOUNDED`: the final branch is an existential join over arbitrary team grants. Artifact `ARTIFACT` is likewise refused because rules cannot quantify over the capped source relation. Thus the listing cannot legally attach complete rules until §6’s authorization delta exists; making the rows `public` is not a safe rewrite.

### 3. Operations in v0

These first attempts account for the repeated diagnostics:

```ts
for (const op of args.ops) { ... }
// E_UNBOUND_LOOP: ops[] has no declared maximum.
// Rewrite: bounded argument list A.

db.scan(noteBlocks.byNoteSeq,[noteId],{})
// E_UNBOUND_SCAN. Rewrite: schema cap B + take:B + require(!page.hasMore).

db.rankedFullText(partition,terms,{take:100})
db.knn(partition,vector,{take:3000,ef:200})
// E_OPAQUE: no ranked/full-text/vector read site.
// No authorization-preserving v0 rewrite.

await provider.generate(prompt)
// E_EFFECT_NOT_LIVE: data programs cannot call out.
// Rewrite: request mutation -> effect -> completion mutation.

read: artifact => db.scan(artifactSources.byArtifact,[artifact.id],{take:12})
                         .every(s=>canRead(viewer,s.noteId))
// E_RULE_UNBOUNDED: rule bodies contain no loops.
// Rewrite: capped policy forall/maintained ACL, or requester-private artifacts.

grant.expiresAt > Date.now()
// E_AMBIENT_TIME. Rewrite: schedule flips durable state.
```

**O1–O3: editing, sync, indexing.** After declaring `A/B`, O1’s relational core is a plan:

```ts
const blocks=db.scan(noteBlocks.byNoteSeq,[args.noteId],{take:B});
db.require(!blocks.hasMore,"NOTE_TOO_LARGE");

for (const op of args.ops) {
  const old=db.get(noteBlocks,[args.noteId,op.blockId]);
  if (op.kind==="update" && old.blockVersion===op.baseVersion)
    db.update(noteBlocks,old.id,()=>({
      body:op.body, blockVersion:old.blockVersion+1,
      updatedBy:ctx.viewer, updatedAt:ctx.now()
    }));
  else if (op.kind==="update" && old.body!==op.body)
    db.insert(noteBlocks,conflictRow(ctx,old,op));
  // insert/delete/move use the same bounded point-read pattern.
}
db.update(notes,args.noteId,n=>({
  version:n.version+1, updatedAt:ctx.now(),
  contentDigest:digest(render(blocks))
}));
db.insert(noteVersions,versionRow(ctx,blocks));
```

`digest`, total fractional-sequence exhaustion, opaque full-text writes, placement enumeration, and job coalescing remain unresolved. The fixed whole mutation is therefore partial; splitting engine-owned index/outbox work from the visible block transition recovers conditional prediction.

O2 cannot be one mutation: v0 provides one transaction, while the design requires independently committed note batches followed by a non-global pull. The rewrite is repeated `saveEdit` mutations, paged read-only pulls, and bounded purge/manifest acknowledgements.

O3 is `claimEmbeddingJob` mutation → system input query → provider effect → `commitEmbeddingResult` mutation. Completion rechecks job generation, policy, deletion, and `old.noteVersion < targetVersion`. It cannot update vector indexes until the opaque-index delta lands.

**O4–O8: discovery and artifacts.** O4 initial search must at least be a mutation because it inserts a snapshot; a query cannot write. A safer new runtime operator would return an engine-owned snapshot cursor. The fixed page operation is also defective: `queryDigest` does not retain the terms needed to make current snippets, and reporting dropped, unseen page-two rows leaks cardinality. The safe normalized page is:

```ts
const s=db.get(resultSnapshots,args.snapshotId);
db.require(s?.state==="live","SNAPSHOT_EXPIRED");
const page=db.scan(resultSnapshotItems.bySnapshotRank,[s.id],
                   {take:20,after:args.after});
for (const hit of page) {
  const n=db.get(notes,hit.noteId);
  if (n!==null) output.push({noteId:n.id, matchedVersion:hit.versionAtSearch});
}
```

It returns no “N unavailable” count. O5 has no v0 correction: ANN, same-model vector typing, cross-partition merge, thresholds, top-up, and server-only replay semantics are all absent. Its cache also cannot be written from a query.

O6 requires a new client-callable, policy-gated external action. The existing rewrite—persist draft request, run effect, query result—contradicts “never persist the draft.”

O7 can reserve spend and insert a pending artifact in a mutation:

```ts
const spend=db.get(teamPeriodSpend,[team.id,team.currentPeriod]);
db.require((spend?.value??0)+MAX_COST<=team.monthlyCapCents,"CAP_EXCEEDED");
db.insert(spendLedger,reservation(ctx,team,artifactId,MAX_COST));
db.insert(aiArtifacts,pendingArtifact(ctx,artifactId,args.question));
```

The effect retrieves at most 12 authorized chunks through the missing ranked site, calls the provider, then a mutation writes normalized sources, charge, release, and final text. `MAX_COST` must be a hard provider maximum, not the design’s estimate. Summaries use the same pipeline.

O8’s program-level team check is bounded after `S=12`, `R=200`, and a one-point effective-access relation: `1+h(12)+h(200)+12×200=2617`. The artifact table’s own read rule still needs the bounded forall; checking only in the query body is too late because the closure receipt may already carry the text.

**O9–O10: authority and lifecycle.** Direct-user sharing is the admitted two-read/one-write plan. Team sharing, index placement, revocation purges, and deletion are not. The safe rewrite atomically flips the grant/note state used by rules, giving immediate online denial, then runs cursor-bounded system cleanup. This changes the fixed requirement that every purge row be inserted in the same transaction.

Links additionally need an argument-bound bearer capability. `ctx.newId()` is client-mintable and format-validated; the spec does not promise cryptographic secrecy. Link/grant expiry must be a durable scheduled transition, so the product can promise “within one schedule period,” not exact timestamp revocation.

**O11–O13: background work.** Resurfacing and saved searches are one scheduled invocation per user/search, not global scans. Their scalar pre-work is bounded; their vector/ranked work is not admitted. Migration is a cursor state machine: scan 500 notes (`502` reserved), insert at most 500 jobs, update one cursor; use maintained coverage/readiness facts for cutover; batch old-model deletion. Notification delivery and event-driven percolation are effects. No channel is needed.

Ordinary admitted UI operations are `recordOpen`, recommendation list/dismiss, direct-user share, saved-search deletion, spend-cap update, and bounded share listing. Pinning, membership administration, policy changes, and semantic saved-search creation remain refused for the reasons in §1.

### 4. K2 audit

| reduction or structural question | caller or resource? | declared route | would silent filtering be wrong? |
|---|---|---|---|
| complete block set for digest/snapshot | resource | `cap(B)` plus complete prefix scan | yes; produces false content/version |

| “20 of up to 500” | caller snapshot | capped snapshot children; never hidden total | yes if dropped unseen IDs are counted |
| related/suggest/ask rank | caller-visible corpus | partition-pinned opaque search | yes; wrong rank and shortfall |
| partition size/exact-versus-ANN choice | resource | maintained count with declared readability | yes; wrong algorithm and timing leak |
| offline “searched N notes” | caller’s device | exact local held-set count | yes if current server scope substitutes |
| activity-vector mean over ≤50 | caller | explicit user prefix | yes if global/hidden activity contributes |

All ordered scans still charge raw candidates: hidden rows consume `take`, each scan reserves `take+2`, and non-uniform rules suppress extent receipts.

### 5. Integrity audit

| invariant | enforcement |
|---|---|
| 1. current note visibility | **not enforceable** for team grants: rule join missing; expiry requires scheduled live state |
| 2. derived visibility | note-derived tables can delegate to note ACL; artifacts and opaque indexes remain unenforced |
| 3. no existence/rank leak | ordered receipt rules help; opaque ranking/timing absent; O4’s dropped count violates it |
| 4. current-version labeling | version columns plus program checks, not a binding constraint |
| 5. same embedding model | requires model-typed ranked index, absent |
| 6. older vector loses | finalizer `require`/`(old,next)` rule can enforce monotonic version |
| 7. delete/unshare freshness | state rule plus fenced cleanup; provider/index freshness remains runtime-level |
| 8. edits retain both versions | save program only; no constraint requires conflict insertion by every writer |
| 9. up-to-k snapshot | capped/unique snapshot rows enforce size/order; ranked construction absent |
| 10. honest offline scope | client-runtime contract absent |
| 11. AI opt-out prevents egress | not enforceable: no outbound-AI capability; policy can flip between check and provider call |
| 12. authorized answer evidence | bounded immutable sources help; retrieval authorization is missing |
| 13. artifact all-source ACL | **not expressible in a v0 rule** |
| 14. link lifetime/use | unique token and point `require` help; link expiry does not expire its already-created grants |
| 15. only owner widens sharing | insert/update rules plus `immutableExcept`; enforceable, except admin undelete contradicts it |
| 16. workers write only derived data | per-table rules and effect-through-mutation discipline; enforceable |
| 17. spend never exceeds cap | maintained sum helps, but fixed O6/O7 violate it and no aggregate constraint binds every write |
| 18. exact artifact provenance | capped, unique, immutable source rows after finalization |
| 19. no phantom alerts | identity/new-visibility predicate in program; opaque owner-scoped rank still missing |

v0 newly turns uniqueness, cardinality limits, mandatory four-effect authorization, immutable identities, and scheduled state transitions into engine properties. Conversely, it cannot capture the design’s opaque indexes, outbound policy, block-conflict obligation, dynamic ACL intersections, or unbounded purge/index maintenance. `appendOnly()` also conflicts with the promised eventual deletion of `noteVersions`.

### 8. Where the design is wrong

1. **Keyword search is neither complete nor privacy-safe as specified.** P3 promises every current match; O4 takes only 100 per partition and 500 overall. Its continuation stores only a digest, so it cannot recreate term-sensitive snippets, and “N unavailable” can count page-two notes the viewer never saw. Confirm with 501 matching notes, then revoke and edit matches ranked 21–40 before requesting page two.

2. **The outbound-AI boundary violates both policy and money invariants.** O6 charges `≈0.001¢` into an integer-cent ledger without reservation; O7 reserves an estimate rather than a proven maximum; policy may flip after the pre-call check. Confirm by starting calls at the spend cap and toggling AI off between claim and provider dispatch.

3. **Link expiry does not expire grants already minted through the link.** `openLink` creates a live grant without copying link expiry, while only explicit `revokeLink` cascades. Confirm by opening a link immediately before expiry and reading the note afterward.
