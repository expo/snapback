**Not tables.** The four epoch images are deliberately absent: any `table` holding them admits `db.get(image, [epoch, slot])`, which §3.0 shows is the disclosure, and their only legal writer is a whole-image rebuild. They are the oblivious kind proposed in §6 (not used here as if admitted). The design's client-local tables are device-authoritative; the v0 client is a receipt-fed twin with no place for them (row 24).

### 3. Operations in v0

#### 3.0 The two central dumps

**`lookupUser(phone)` — first attempt, as an agent writes it.** Encrypt the record, hash the number, point-get.

```ts
export const directory = table({ id: id(), e164: text({ max: 16, hashed: true }), accountId: id(), identityKey: B64,
    valid: interval({ from: 'fromEpoch', to: 'untilEpoch' }) })                       // [v1.1] hashed = keyed digest, equality only
  .unique('byE164', ['e164'], { bearer: true })                                      // [v1.1] bearer: no viewer needed
  .rules({ read: r => public('directory'), insert: n => SYS, update: (o, n) => SYS, delete: never })
export const lookupUser = query({ phone: E(16) }, ({ db, args }) => db.get(directory.byE164, [args.phone]))
```

Certificate: `readSites[{ directory, byE164, prefixTemplate: arg, take: 1, maxCalls: 1, hoist: true }]`, `maxExamined 1`, `completeness all`, `disclosures []`. **`check` admits it.**

Authoritative trace (spike record types; `h_k` is the engine's keyed digest):

```
ctx        { viewer: "dev_7f3a", principal_kind: "user", auth_epoch: 12, args: { phone: "+15551234567" } }
points     [{ site: "s0", table: "directory", index: "byE164", key: [h_k("+15551234567")], examined: true, visible: true }]
rows       [{ table: "directory", id: "acct_2b9e", row: { accountId, identityKey, fromEpoch: 4410, untilEpoch: 0 } }]
absences   []            // on a miss: [("directory", "byE164", [h_k("+15551234567")])] and rows []
rule_inputs []   examined 1   rule_probes 0   steps 3   writes {}
```

Closure receipt: `rows` as above, or `absences` naming the same key; `verdicts []`. Downstream (spec §6): the subscription is indexed at that key, so the commit that *registers* the number wakes this subscriber; the client store re-probes the key on reconnect; `audited(into)` `[v1.1]` would write the receipt as rows in the read's own commit.

What the operator learns: (1) **the number** — `ctx.args` is plaintext in the envelope; `hashed` digests the *column*, not the *argument*, under the engine's key; (2) **hit or miss** — `points[].visible` versus `absences`; (3) **who asked** — `viewer`; under `bearer` or `anon` the same `key` recurs across every address book containing that number, linking askers without inverting anything; (4) **when**, and via invalidation, that the asker is *watching* the number. Promises 1–2 and invariants 1–2 fail on the first call; the trace is a superset of the design's `query_receipts` by construction.

**Second attempt — the design's "full pass".** Read the whole image, select with an opaque share:

```ts
export const retrieveDirectory = query({ epoch: int(), share: json({ maxBytes: 4096 }) }, ({ db, args }) => {
  const img = db.scan(directorySlots.byEpochSlot, [args.epoch], { take: 134_217_728 })
  let acc = zeros(288)
  for (const s of img) acc = xorBytes(acc, maskBytes(s.cell, dpfEval(args.share, s.slotIndex)))
  return acc
})
```

Diagnostics: `E_BOUND — site s0 reserves 134,217,730 entries (take + 2) × 288 B = 36 GiB per call, above maxExamined. No rewrite preserves the product: any smaller take is a sub-image read.` `E_OPAQUE — dpfEval, xorBytes, maskBytes are outside the value model.` `maxClosureBytes — the receipt would ship 2^27 rows` (only `localReplay: false` `[v1.1]` avoids it). **Had it been admitted**, its trace is `ranges: [{ s0, directorySlots, byEpochSlot, prefix: [4410], examined_ids: <all>, stop: Exhausted }]` with `args.share` pseudorandom — *a constant, identical for every query*: traced and private. What refuses it is the ceiling, the value model, and the second server holding the other share (one server authority, unstatable in the schema) — not the trace.

**`fetchMailbox(me)` — first attempt.** A row per envelope, a capability-owner rule, an ordinary page; consume is a delete.

```ts
export const envelopes = table({ id: id(), mailboxId: id(), cell: json({ maxBytes: 4096 }), createdEpoch: int(), expiresEpoch: int() })
  .index('byMailbox', ['mailboxId', 'createdEpoch'])
  .rules({ read: e => db.exists(mailboxOwners.byMailboxDevice, [e.mailboxId, viewer]), insert: n => ANON,
           update: never, delete: o => db.exists(mailboxOwners.byMailboxDevice, [o.mailboxId, viewer]) })
export const fetchMailbox = query({ mailboxId: id() }, ({ db, args }) => db.scan(envelopes.byMailbox, [args.mailboxId], { take: 32 }))
export const consume = mutation({ ids: [id()] /* max 32 */ }, ({ db, args }) => { for (const i of args.ids) db.delete(envelopes, i) })
```

Certificate: `readSites[{ envelopes, byMailbox, prefixTemplate: arg, take: 32 (+2), hoist: true }]`, `maxExamined 34`, `maxRuleProbes 1`, `completeness page`. Admitted.

```
ctx         { viewer: "dev_7f3a", principal_kind: "user", args: { mailboxId: "mbx_91c0" } }
ranges      [{ site: "s0", table: "envelopes", index: "byMailbox", prefix: ["mbx_91c0"],
               examined_ids: ["env_a1", "env_b2", "env_c3"], visible_ids: [same], stop: Exhausted, absence: false, halo: null, n2_key: null }]
rule_inputs [{ rule_hash: "r_env_read", table: "mailboxOwners", index: "byMailboxDevice", key: ["mbx_91c0", "dev_7f3a"], result: true, hidden: false }]
examined 3   rule_probes 1   writes {}
receipt     rows: 3 envelopes; ranges: [{ s0, prefix: ["mbx_91c0"], row_ids: [3], stop: Exhausted }];
            verdicts: [{ r_env_read, digest("mbx_91c0"‖"dev_7f3a"), principal: "dev_7f3a", auth_epoch: 12, result: true }]
consume     points: [{ key: ["env_a1"] } …]  writes { envelopes: 3 }   → OCC keys; invalidation of every subscriber of prefix ["mbx_91c0"]
```

What the operator learns: **which mailbox** (`prefix`), **whether it was empty** (`stop: Exhausted` with `examined_ids: []`), **how many envelopes** (`examined`), **which device and account** (`viewer`, the rule-input key), **when** (every poll), **which envelopes were consumed and when** (`writes`, `points`), and — the subscription being a standing range on `["mbx_91c0", *]` — **the drop→fetch causal edge**: the drop commit wakes the reader, a destination-named push. Promises 3, 5, 10, 12 and invariants 1, 3, 6 fail. A `bearer` capability digest in place of `viewer` is a stable pseudonym the control plane joined to the account at registration and link (op 1 step 4, op 8 step 3).

**Verdict.** No admitted program satisfies promises 1–3, 5, 10 or 12 for these two operations, for two reasons that are not the trace. First, arguments and result are plaintext at the interpreter; the disclosure exists in `ctx.args` and `rows` before any trace is written. Second, the only programs whose trace does *not* depend on their arguments examine the whole image, which the ceiling refuses, the interpreter cannot afford at 90 k calls/s over 10 TiB, and which need a second independently operated authority (two-server) or lattice arithmetic (single-server) — neither statable in the schema. The honest outcome is a **new kind**, an *oblivious epoch-image store* (§6 item 2): its read's trace is a constant `(image, epoch)`, so the trace's four roles degenerate — invalidation is the epoch pointer, closure is nothing (`localReplay: false`), OCC is an immutable image, completeness is the size class — and its mechanism (a linear kernel over RAM-resident images; a 10 TiB rewrite every 60 s) is **not this system**, outside the plane as the OT and OLAP engines are. An *untraced* read site inside the plane is refuted as a cheat by the design's own boundary (§7.1): it deletes the audit line and leaves the interpreter's view intact.

**Prediction 5, tested.** (a) "The trace records the examined bucket, and that is the query" — *held* for every sub-image read; `points[].key` and `ranges[].prefix` above are that bucket. (b) "The guarantee cannot hold" — *held*. (c) "The honest outcome is a declared untraced read site … a third read-site class" — *refuted as the repair*: removing the trace changes nothing, because the leak precedes it; the third class exists, but is characterized by trace *constancy*, not absence, and the interpreter does not execute it. (d) "or not this system" — held for the mechanism, not the application: sixteen plans carry the control plane.

#### 3.1 Registration, recovery, tokens, devices, deletion (design ops 1, 6, 7, 8, 12)

**Op 1 `registerNumber`** — plan. SMS verification is I/O: the `smsVerifier` effect writes `smsProofs` through `recordSmsProof` (service principal); registration consumes the proof.

```ts
export const registerNumber = mutation({ e164, smsProofId, accountId: id(), phoneId: id(), deviceId: id(), attestation, lockVerifier, backupCapHash,
    directoryItem, mailboxItem, pinProof: optional(B64), resetDevices: bool() }, { callable: 'anon', predict: false }, ({ db, args }) => {
  const p = db.get(smsProofs, args.smsProofId); db.require(p !== null && p.e164 === args.e164 && p.status === 'valid', 'SMS_PROOF')
  db.update(smsProofs, p.id, x => ({ status: 'consumed' }))
  const dE = db.get(currentDirectoryEpoch, []).value, mE = db.get(currentMailboxEpoch, []).value
  const num = db.get(accountNumbers.byE164Live, [args.e164])
  if (num === null) { /* insert accounts, accountNumbers{live:true}, accountEvents */ }          // new number, or recycle after finalizeDeletion
  else { /* require status active|locked && verifyMac(lockVerifier, pinProof) [v1.1 seam]; optional device reset: scan take 5 → revoke */ }
  db.insert(devices, { … status: 'active' })                                                    // cap 5 → sealed refusal
  db.insert(pendingMix, { store: 'directory', targetEpoch: dE + 1, item: args.directoryItem, sizeClass: 's' })
  db.insert(pendingMix, { store: 'mailbox',   targetEpoch: mE + 1, item: args.mailboxItem,   sizeClass: 'm' })
})
```

Certificate: points ≤5, scan 5+2, writes ≤12; partial-unique, cap, event-coupled. Invariant 8 is the `byE164Live` partial unique plus `finalizeDeletion`: a fresh `account_id`/`phone_id` is the only insertable thing. Double registration serializes on the unique. Tokens and the sender cert are op 6.

**Op 6 `issueSendTokens`** — first attempt returns `args.blinded.map(b => voprf.evaluate('send-key', b))`. Refused: `E_OPAQUE — voprf.evaluate: keyed evaluation under a server secret is outside the value model. Rewrite: reserve in the mutation, sign in an effect keyed by voprfBatchId, complete with a named mutation.` A `day` *argument* is the intent-clock trap (`E_INTENT_TIME_WINDOW` `[v1.1]`); it is `divmod(ctx.commitTime, 86_400_000).q`. Corrected: `reserveTokens` inserts `tokenIssuance{status:'reserved'}` (cap sum ≤ 2000 → sealed `E_CONSTRAINT`, the uniform "daily limit"); the `voprfSign` effect calls `completeIssuance`, idempotent on status. Certificate: point 1, cap-sum, unique, write 1; prediction `conditional(cap)`.

**Op 7 recovery** — the backup fetch (7b) is the kind. The guess counter (7a) is a plan the HSM effect calls under the host principal: increment `pinGuesses` for `(blindedId, day)`; the sixth attempt is a *sealed* constraint refusal the HSM turns into the same padded miss; the fifth also sets `status = 'locked'` with an event row. Certificate: points 2, writes ≤3. SMS already named the account — the design concedes that; the slot is never a value in the plane.

**Op 8 `linkDevice` / `unlinkDevice`** — plans. Link: `require(owns)`, insert `devices` (cap 5; a sixth is refused uniformly), two `pendingMix` inserts; sibling notification is ordinary drops (4a). Unlink: update status, insert the rotated directory record and a 32-cell zero item for the old capability. Certificate: points ≤3, writes ≤3; prediction `conditional(cap)`.

**Op 12 `deleteAccount`** — plan (`predict: false`): `verifyMac` of the PIN proof; status → `pending_deletion`, `deleteAt = commitTime + 7 d`; revoke ≤5 devices; insert the tombstone and ≤5 zero items. `schedule(finalizeDeletion, { at: a => a.deleteAt, key: a => a.id, principal: 'system' })` flips `deleted` and clears `accountNumbers.live`, freeing the E.164 for a *new* row. Re-registration before day 7 hits the live row and fails `REGLOCK`. Certificate: points 2, scan 5+2, writes ≤13.

#### 3.2 Discovery, usernames, cover (design ops 2, 13, 14)

**Op 2a as designed** — budget charge and receipt in one authenticated transaction:

```ts
export const chargeDiscovery = mutation({ accountId: id(accounts), sizeClass: E(2), epochId: int(), connectEphemeralId: id() }, ({ db, ctx, args }) => {
  db.insert(discoveryCharges, { accountId: args.accountId, day: divmod(ctx.commitTime, 86_400_000).q, cost: COST[args.sizeClass], sizeClass: args.sizeClass })   // cap: class-uniform refusal
  db.insert(queryReceipts, { kind: 'directory', sizeClass: args.sizeClass, epochId: args.epochId, connectEphemeralId: args.connectEphemeralId })
})
```

`check` admits it. Its trace — `ctx.viewer: dev_7f3a`, `points: [accounts/acct]`, `writes: { discoveryCharges: 1, queryReceipts: 1 }` — is the join the receipt table's missing `account_id` column pretends not to exist: the commit names the account, the receipt names the connection, the connection carries the retrieval. **Admitted and wrong** (§8.2). The rewrite, **2a′**, reuses the design's own token machinery: `issueDiscoveryTickets` (authenticated; `cap({ sum })` by class cost; OPRF in an effect as op 6) and an anonymous `redeemTicket` (`insertIfAbsent` on the ticket nonce, `callable: 'host'`) the retrieval server calls before appending the receipt under `HOST`. That commit carries no viewer.

**Op 2b `retrieveDirectory`, 13a `lookupUsername`, 7b `retrieveBackup`** — premise-violation (§3.0): deterministic programs over traced bounded reads. Broken = a guarantee that cannot hold for any sub-image read, and a scale regime (2²⁷ examined per call, 40 M calls/day) where the certificate is the wrong instrument. Honest outcome: new kind; mechanism not this system.

**Op 13b `reserveUsername`** — the obvious plan, `insertIfAbsent(usernames, { name })` under a `unique`, is admitted and is a cheat: `args.name` is plaintext, and the sealed `E_CONSTRAINT` seals the conflicting *row* from the caller (§9), not the *collision* from the operator, who sees the refusal and the name. Premise-violation, same kind (an oblivious write with a private bit).

**Op 14 `coverPoll`** — premise-violation of the trace as invalidation, inverted: the plane's *live query* is precisely the destination-named standing read the design forbids (trap 6), and the v0 client has no scheduler that fires a constant-shape read whether or not anything changed. Broken = presence. Honest outcome: the kind's client half owns `poll: { every, background, jitter }` with `live: false`; the official-client obligation is a product boundary.

#### 3.3 Mail (design ops 3, 4, 5, 11)

**Op 3 `fetchMailbox`** — premise-violation (§3.0). The seam **3′ `recordReceipt`** is a one-write plan callable by `HOST`.

**Op 4a `dropEnvelope`** — plan, anonymous, atomic nonce spend plus mix enqueue:

```ts
export const dropEnvelope = mutation({ nonce: B64, tokenEpoch: int(), tokenProof: B64, item: json({ maxBytes: 8192 }) },
  { callable: 'anon', predict: false, delivery: 'online-only' }, ({ db, args }) => {                 // [v1.1] the plane's outbox never replays a stale drop
  const mE = db.get(currentMailboxEpoch, []).value
  db.require(args.tokenEpoch >= mE - 1440, 'TOKEN_EXPIRED')                                          // 24 h of 60 s epochs; no clock
  db.require(verifyMac('send-token-key', args.nonce, args.tokenProof), 'TOKEN')                       // [v1.1 seam]
  if (db.insertIfAbsent(tokenRedemptions, { nonce: args.nonce, tokenEpoch: args.tokenEpoch }) === 'inserted')   // duplicate → already_acted
    db.insert(pendingMix, { store: 'mailbox', targetEpoch: mE + 1, item: args.item, sizeClass: 'm' })
  return 'ok'                                                                                        // uniform; fullness is a private bit in the next fetch
})
```

Certificate: point 1, unique nonce, writes ≤2, and the negative claim `independentOf(accounts, accountNumbers, devices)` `[v1.1]` — invariant 4 becomes a *proven* certificate fact. Trace: `viewer: anon`, `writes { tokenRedemptions: 1, pendingMix: 1 }` — the operator learns "a class-m drop at *t* from connection *c* with nonce *n*". A DH-VOPRF token needs §6 item 7; a keyed-PRF token is `verifyMac`.

**Op 4c group send** — the natural program loops over `drops` (max 1000): admitted, `writes ≤ 2000`. But the *trace* records actuals — `writes: { tokenRedemptions: 256, pendingMix: 256 }` in one commit from one connection — "a 256-member group was just written to", the event promise 4 forbids. A static bound is not a padding guarantee. Product-change: G separate `dropEnvelope` calls on the 200 ms grid over rotating connections; or §6 item 3.

**Op 5a `enqueueConsume`** — plan: one anonymous insert of a fixed 32-cell item; cover consumes are byte-identical. **Ops 4b, 5b, 11** (mix apply, image rebuild) — premise-violation: the trace as OCC/write set, the certificate as gate over a whole image per minute. Broken = the applier's point-read by index (§8.1). Honest outcome: the kind's `job`.

### 6. Language delta

1. **Secret inputs — an `oblivious(arg)` certificate claim.** The spec has no notion of an input the server may not interpret: every arg is plaintext in the envelope, in `points[].key`, and in the result. Smallest addition: a negative claim, proven by `check`, that the trace, `steps` and `maxOutputBytes` are independent of the named argument — no branch on it, no read key derived from it, use only in total constant-cost value-model functions — else `E_SELECTOR_LEAK`. General (voting, health lookups, any secrecy app). Amends §5 and v1.1 §2.1 negative claims. Necessary, not sufficient: such programs over a 2²⁷ image are refused by ceilings — hence item 2.
2. **The oblivious store kind.** `oblivious({ cellBytes, slots, epochs: table, sizeClasses, read: { selector: 'opaque', ticket }, write: { via: pendingMix, apply: 'whole-image', period }, poll })`: epoch-pinned immutable images; a read whose certificate line is `class: oblivious, examined: |image|, trace: (image, epoch), receipt: none, localReplay: false, live: false`; writes mixed and applied by a `job` that rewrites every cell; invalidation by epoch pointer. Beside the ranked and geo sites in the certificate, but executed by an engine kernel outside the interpreter; a second authority or single-server lattice PIR is a deployment declaration, not a schema fact. General to the secrecy class; amends v1.1 §6 and §7.
3. **Padded execution.** `padTo: certificate` on a program or write site: trace and receipt report the certificate's bound, never actuals; dummies fill; `E_FANOUT` and `E_CONSTRAINT` become private bits. Closes the group-size and collision leaks (§3.2, §3.3). Secrecy class; amends §5–§6, §9.
4. **Response cadence as invocation policy.** `respond: { gridMs: 200, size: 'class' }` beside `online-only` and `predict: false`; refuses off-grid or off-size answers. Runtime axis; amends v1.1 §2.1 B.
5. **Time-bucketed sum caps.** `cap({ by, sum, max, per: '1d' })` — v1.1 has `cap({ sum })` and `rateLimit` but not their product; a program-computed `day` from `commitTime` works but leaves the bucket unchecked by the schema. General; amends v1.1 §4.
6. **Host-callable seams with negative claims** — `callable: 'host'`, `independentOf(table)`, `insertIfAbsent`, `anon`/bearer principals, `verifyMac`: **covered by v1.1**; this app is evidence they compose (4a, 3′, 10b, 9).
7. **In-transaction OPRF/blind-signature builtin.** `crypto.oprf(keyRef, blinded[] /* max */)` deterministic under a server key ref, so issuance and the budget increment are one commit (design: "Atomic: budget + issuance + VOPRF outputs"); until then issuance is mutation + effect (op 6, 2a′) with an unsigned-reservation window. General (Privacy Pass anti-abuse); amends v1.1 §2.1 D.
8. **Device-authoritative local tables and an outbox replay guard over them** (`local_contacts`; the identity-rotation refusal before replay). New dimension — authority placement — owned by wave 4 #2; noted, not proposed here.

### 8. Where the design is wrong

1. **Invariant 12 conflates I/O uniformity with selector privacy, and the design's own applier violates it.** "A single-server scheme whose work is always a full pass" is satisfied by full-scan-then-select in plaintext; the read set is uniform and the *result* set names the slot — exactly the distinction the trace model draws between `ranges[].examined_ids` and `rows`. Worse, op 4 step 3 and op 11 step 2 say the mix applier "loads the dest cell … packs the envelope … increments generation": a point-read by index in the operator's own process, the thing invariant 12 forbids "even for staff", hidden inside a job whose disk I/O happens to be the whole image. *Confirming observation:* implement op 2 as full-scan-then-select and op 11 as written; the disk log is identical for every query and epoch, while the response log and the applier's memory trace name the slot every time. The invariant must say "the selector is never in plaintext at any server" (secret-shared apply, an enclave, or client-driven write-PIR) — a stronger trust boundary than "an operator who records what was read".
2. **Discovery budget arithmetic makes cover discovery impossible, and the charge is the receipt's identity.** Op 2 charges the authenticated account in the same transaction as the receipt (§3.2): the commit joins account, connection and retrieval. Cover (op 14) fires a dummy op 2 with probability 0.1 per 45 s poll ≈ 8/h × 2000 = 16 000 budget/h against a 10 000/day cap. So cover discovery cannot be charged; if uncharged, real and cover are distinguishable, breaking promise 12 and invariant 16. *Confirming observation:* run one foreground client for an hour; count directory receipts and `discover_budget_used`. Fix: 2a′ — VOPRF discovery tickets by class with a cover allowance, redeemed anonymously.
3. **Mailbox, backup and cover retrievals have no server-checkable authorization and no budget.** Op 3's "authorization" is a MAC the *client* verifies on the response; op 14 says "none". The most expensive operation in the system — a full pass over 10 TiB, 90 k/s at peak — is open to any anonymous caller; the only budgets (invariant 10) cover discovery and sends. Writing `queryReceipts.insert` forced the question: there was nothing to write. *Confirming observation:* 1 000 anonymous clients issuing op 3 at 100/s each; the cluster saturates while no budget row moves. Fix: per-device fetch tickets (~4 k/day at the 45 s cadence) through the same unlinkable machinery; cover consumes tickets too.

A fourth, mechanical defect surfaced in §5: `e164 UNIQUE` with a new `account_id` on recycle is a constraint violation as stated; a partial unique on `live` fixes it.
