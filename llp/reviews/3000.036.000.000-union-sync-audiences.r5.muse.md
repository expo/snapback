READY WITH CHANGES

No proven disclosure break and no proven retention break, but one new retention path ships without simulator evidence, and four narrower gaps need tests or text fixes before landing.

1. High — §5, windowed pure-column unions are untested. `snapback4-sim/tests/union.rs` windows only owner-or-team (one column arm plus the group arm). The two-parties and three-parties worlds have no `last N`, so per-arm window planning for two column arms (`bind_union_windows`, `intent.rs` per-need indexes), multi-column-arm admission (`device/boundary.rs:104-125` `accept`, especially the `None if sync.is_union() => continue` / `floored` interaction), certification through either column index (`engine/read.rs:969` `by_boundary` via `arm_by_window`), and `line_in` on multi-column windows are all exercised nowhere. Concrete interleaving: `orders` with `sync last 1 by .at`, Alice buyer of an old row (below the buyer floor) and seller of a newer row — the device must reject the first put through the buyer arm yet hold the second through the seller arm, and `buys`/`sales` pages must certify independently. A sign or arm-confusion error here drops readable rows while pages say `complete`. Proposed: add a windowed two-parties world (or `last 1 by .at` variant of the three-parties world) with per-arm newest-row and certification checks mirroring the windowed owner-or-team world.

2. Medium — §4.3/§8a, multi-column group prefixes untested though relied on. The leave cursor (`device.rs:1318` `skip(group.len())`), scope width plus keeper (`device.rs:1267-1293`), snapshot resume across multi-value groups (`partition.rs:563-570`), and `arm_group` keying are all width-generic in code but no world has a group arm with two prefix columns. Proposed: add the deferred two-prefix world (e.g. `members[.team, .division, viewer]`) with a leave interleaved across a 500-row page boundary, or narrow the "arm-generic" claim in §8a to name the untested lines.

3. Medium — §4.3/§8a, roster-union leave with interleaved owners across pages untested. The 600-spared-rows test pins owner-or-team; the staff world's leave walks the whole table through the first plain index with only two requests. A staff `quit` with alternating owned/unowned rows spanning pages (spared rows advancing `bounds.after` while dropped rows are deleted under the same cursor) is the exact shape round 1 GPT finding 4 was about, applied to the roster arm. Proposed: seed ~600 owned plus ~600 unowned requests and quit, asserting exact retention and termination.

4. Medium — §9, epoch identity inputs beyond defaults lack tests. `changed_group_audiences` (`partition.rs:815-838`) keys on column types and defaults, `group_index`, target expiry, and through-identity, but only the default change has a test (`a_changed_membership_default_is_a_new_audience`). A missed input (e.g. group-index change, content-column type change) silently reuses the old ledger, so an old scope closes a rejoined group and new rows never arrive — a retention loss with no failure signal. Proposed: add one test per key input (type change, index change, through-identity change each yield the table; identical schemas yield none), or reduce the §9 claim to the tested inputs.

Proposed: add both chain tests asserting the leaving partition still receives its `del` and the final image is served once.
