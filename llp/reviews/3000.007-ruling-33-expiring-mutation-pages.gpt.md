**1. High — A2 does not cover authorization established only within the mutation.**

Design: [A2](REVIEW-DESIGN.md:68).

Concrete scenario:

- `gates` has a unique room key, `enabled: bool`, `read <- deny`, and an update rule admitting this viewer.
- An expiring table has index `(room, id)` and `read <- exists gates[room = .room, enabled = true]`.
- The only relevant mutation enables the gate, binds that room’s expiring page, disables the gate, and returns a constant.
- Compare an empty selected prefix with one containing enough expired, unswept candidates to exceed the examined ceiling. The gate starts disabled in both worlds.

P1 admits the page: pinning `room` makes its rule uniform. Hidden-target write authority permits enabling the gate, and the subsequent prefix probe reads the transaction’s modified gate. The empty world commits; the populated world aborts and rolls back. The gate is disabled in both externally observable states. The corresponding query returns an empty complete page without examining that prefix in either state.

The enabling write need not expose the gate’s image: [write_target.rs:129](snapback4/crates/snapback4-core/src/engine/write_target.rs:129) resolves it privately, [write.rs:155](snapback4/crates/snapback4-core/src/engine/write.rs:155) writes it immediately, and [read.rs:73](snapback4/crates/snapback4-core/src/engine/read.rs:73) evaluates the prefix verdict against that transaction. Failure rolls back at `engine/mod.rs:862`. Queries cannot perform the enabling write (`lang/src/guide/programs.rs:8`).

This is not a uniformity bypass. It defeats the claim that the disclosure already exists through a query available to the same viewer. Transaction-local authorization could be an explicitly accepted disclosure policy, but A2 currently substitutes query equivalence for that decision.

**Smallest conservative repair:** retain the expiry refusal when preceding program writes can change the page’s read-rule dependencies, including maintained dependencies. Alternatively, explicitly propose and obtain acceptance for the broader transaction-local disclosure contract. Never-predicting-only does not close this case.

I found no separate identity elevation through service seats or action sessions: both HTTP operation paths construct the same viewer context (`serve.rs:987`), and action sessions retain the request principal (`core/src/identity.rs:125`). Write authority alone does not bypass a page’s read rule.

**2. High — P3 can reject a server-valid write locally instead of withdrawing or withholding its prediction.**

Design: [P3](REVIEW-DESIGN.md:56), A5.

A small counterexample needs only **one** stale expired row:

1. Fully acquire a synced, horizon-free table with a cap of one per viewer.
2. Let its row expire. The server sweeps it, but delay that deletion’s delivery to the device.
3. Invoke a predicting mutation that performs 8,191 ordinary point misses on a fully held, non-expiring table, then loops over the expiring group with `first 1`.

Both hosts have the same live population: empty. The page-attempt charge brings examined work to 8,192. The server finds no candidate and succeeds. The device encounters its retained expired candidate, charges 8,193, and raises `E_BOUND`.

[local.rs:75](snapback4/crates/snapback4-core/src/engine/local.rs:75) converts bounds into prediction uncertainty only for the untaken-presence-arm case. [device.rs:744](snapback4/crates/snapback4-device/src/device.rs:744) otherwise propagates this error before inserting the outbox entry. The ordinary client reports a failed write at [local.ts:1101](snapback4/packages/snapback4/src/local.ts:1101). No server response will arrive to withdraw or correct anything.

Expired candidates do not fabricate live rows. When both executions finish at the same logical time and with equal live coverage, those candidates affect cost rather than the selected rows. The defect is the unjustified terminal local refusal.

**Smallest repair under P2:** choose alternative A. To retain P3, require device uncertainty handling for expiry-dependent meter failures, rolling back the overlay and durably queueing the intent. Cover ordinary admission, reopen and replay on both stores.

The server has no “aborting mutation is the only writer” circular dependency: its independent maintenance tick invokes the sweep (`snapback4/src/serve_maintenance.rs:22`, `:67`). Nevertheless, 2,000 rows per pass is a throughput limit, not a population or latency bound. Also, a recorded `E_BOUND` remains failed for that operation ID after sweeping (`engine/mod.rs:780`, `:883`).

**3. Medium — §5’s paired observations need a precise scan-level contract and stronger fixtures.**

Design: [landing tests](REVIEW-DESIGN.md:110).

At an identical **scan-entry** remaining examined budget of 8,192, a prefix containing exactly 8,192 expired rows makes the mutation abort and the query finish complete. The mutation alone pays the initial unit. This behavior is already explicitly pinned by `sim/tests/page_admission.rs:79`.

The iff is achievable if defined as:

> For the same snapshot, clock, evaluated scan, true uniform verdict and remaining candidate budget **after the mutation’s attempt charge**, an examined-budget failure at this scan corresponds to the query’s examined-meter cut.

Keep other ceilings nonbinding and exclude subsequent writes, constraints and output processing from that equivalence. An arbitrary mutation abort cannot be compared with a query’s generic `cut: "meter"`.

The required additions are:

- **Same addressed prefix, denied verdict:** zero versus many expired candidates, including exhausted examined/probe budgets and short-circuit rules. Another-prefix pairs would pass even if the implementation fetched denied candidates from the addressed prefix.
- **Transaction-local authorization:** the gate scenario above.
- **Both directions of device/server disagreement:** especially device-only expired candidates. The existing observation helper starts from `snapshot_at`, which filters them out.
- **Traversal coverage:** positive and negative expiring pages in bound values, helper blocks, predicates, condition setup, nested pages, shapes and serialized IR.
- **Sweep and retry:** demonstrate recovery with a fresh invocation while the original failed receipt remains unchanged.

Reason-text assertions in (c) are useful, provided the `matching` and merge fixtures are otherwise uniform, so an earlier uniformity refusal cannot satisfy them accidentally.

B adds write-side maintenance and its own observable overrun; C merely moves the threshold to a larger expired population. Neither is worth that complexity to repair these findings. A plus a clarified authorization contract is the smaller proposal.

The remaining issues are **not** limited to Low findings or implementation-only Medium adjustments: findings 1 and 2 require changes to the proposal’s admitted behavior or an explicit broader contract.

Verdict: NOT READY
