**Gaps in `presence.rs` (over-approx, not wrong rows):**

1. Any `for` in a presence-guarded arm is `a loop` even if the body is only `emit` (`251`).
2. An assignment in a presence-guarded arm is enough, even if the slot is only later emitted (`252`, test `effect_assignment`).
3. Presence as a read key/cursor/bound/filter inside an emit payload is `never` (`210–231`), stricter than “or an emit’s payload”.
4. After any `Return`/`Break`/`Continue`, `escaped` is joined into every later env and never killed (`141–148`).
5. `Expr::Block` extends caller slots on reassignment (`190`).
6. This module is mutations only (`residency.rs:28`); queries/jobs keep the old server site.

Runtime is unchanged: a device still cannot predict `NOT_FOUND` or an insert for a target it does not hold; those paths are still `E_PREDICT` / queue-without-a-row.

### 2. Binder wrap (`control.rs:113–122`)

Interpreter evaluation order, side effects, and the flat env match spilling setup into `out`. Queries and jobs still spill (`115`, `122`). `pages.rs` only plans queries (`pages.rs:19`), so query continuation analysis is unchanged.

Not identical:

- **Admission.** Setup that used to be body statements is now `Expr::Block`. `admission.rs:107` maps Block to empty `Unknown` and does not walk its body; `If` only walks arms (`178–188`). A page `for` that helpers / `and` / `??` lower into a mutation `if` condition or `emit` payload used to hit `admit()` (`190–199`) and can now skip the predicting-mutation cap check. Uniformity / matching / expiry / merge still apply via `read_structure` (`ir.rs:584`).
- **Meter / error sites.** Block statements run under prefix `"where"` (`runner.rs:400–402`), so `E_BOUND` / `E_REQUIRE` sites that were `send:N` can become `where:1` and collide across two Blocks.

**Counterexample (admission, not presence):**

```quarry
table notes:
  n: int
  unique byN: n
  public 'notes'
  sync public
  insert <- allow
effect notify
fn anyNote():
  for row in notes first 10 by byN:
    return true
  return false
mutation probe():
  insert notes { n: 1 }
  if anyNote():
    emit notify { ok: true }
```

`notes` has no group cap. Before the wrap, the inlined `for` is a top-level body statement and `admit()` refuses `E_STRUCTURAL_FANOUT` (“has no cap”). After, that `for` sits in the `if` condition Block and `admit()` never sees it. If `anyNote` instead inserted a count of that page, the device could predict a different row than the server on an incomplete population. Smallest fix: walk `Expr::Block` bodies with `statements` the way write-condition setup is already walked (`admission.rs:173–177`), from `If` conditions, `Emit` payloads, and `Let`/`Assign` values.

`pages.rs` `expression_origin` also ignores Block (`91–128`); harmless today because queries do not wrap.

### 4. §19.2 helper return

Mechanism: helpers already lower `return` to assign + `if done: break` (`control.rs:466–481`). `writes` used to treat that nested `Break` as an exit of the outer collector (`pages.rs:159–165`). Nested `Break`/`Continue` are now local; `Stmt::Return` still exits every loop.

That covers: early return in a helper `for`, `if`/`else if` (no `Break`; already worked), nested helpers, merge and matching shapes (fixture). A real `break`/`continue` on the page loop still sets `exits` (`nested_loop == false`). A program `return` inside nested loops still records `Origin::Empty` (`pages.rs:229–234`) and drops the cursor (`returnedFromLoop`).

`page_position_lost` (`read.rs:646–647`): `page.is_none() && any(filled || next)`. Wired on server, device local, native, and retained-history. Native scans set `opaque_cursor: false` (`native.rs:414`), so they do not enter `pages` and keep their old completeness class.

It does **not** depend on a hidden row: `filled` is `visible.len() == take`. Hidden rows already flow through `non_uniform` / `next`.

Residual: a dropping collector on a **short exhausted** page (`visible < take`, `next == None`) does not set `lost`. Two stored rows, `last 5`, `break` after the first → 1 row, `complete: true`, no `next`. The 5-row full scan is covered (`filled == true`).

### 5. §19.3 `==`

## Findings

### 1 — High — `snapback4/crates/snapback4-core/src/engine/admission.rs:107` (caused by `control.rs:115,122`)

**Scenario.** Mutation `probe` above: public uncapped `notes`, helper `anyNote` loops `notes first 10`, caller `if anyNote(): emit`. Inputs: empty or populated `notes`. Required: `check` refuses `E_STRUCTURAL_FANOUT` (predicting mutation page without a schema cap), as when the `for` sat in the body. Observed: the `for` is inside the condition `Expr::Block`; `admit()` never runs; if the helper wrote a count, device and server can disagree on the row.

**Smallest fix.** Walk `Expr::Block` bodies with `statements(..., false)` from `If` conditions, `Emit` payloads, and bindings, matching `WriteTarget` setup at `admission.rs:173–177`. Do not treat Block as an empty `Unknown`.

### 2 — Low — `snapback4/crates/snapback4-core/src/engine/read.rs:646`

**Scenario.** Table with 2 rows; `for i in items[] last 5: result += [i]; break; return result`. Required by the interrupted-page spirit: not `complete: true` while a scanned row was dropped. Observed: `filled` is false, `next` is `None`, `page_position_lost` is false, `complete: true`. The 5-row full page is already caught.

**Smallest fix.** Treat an unowned opaque scan that returned fewer rows than it materialized (or any unowned scan whose collector `exits`) as lost; or keep the 5-row case as the spec and add the 2-row test as a residual.

### 3 — Low — `snapback4/crates/snapback4-core/src/engine/runner.rs:400`

**Scenario.** Two mutation `if a and b:` / `??` setups. Required: distinct meter/error sites. Observed: both charge under `"where"`, so two `where:1` sites.

**Smallest fix.** Pass the enclosing statement site into Block evaluation (`"{site}.value"` already used in `presence.rs:187`) instead of the literal `"where"`.
