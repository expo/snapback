## Findings

**Medium — A page joined with a non-page still loses its owner.**

- **Where:** `snapback4/crates/snapback4-core/src/engine/pages.rs:138–142` (join) and `:100` (`result_page` collect).
- **What is wrong.** Same-page different-lineage joins now keep `Page(site, cursor, None)`. A page joined with `Empty` (the other arm is `null`, omitted, or `[]`) does not take that arm: `may_carry_page` sends it to `Origin::Unknown`. Collect treats `Unknown` as fatal for the whole origin (`fields.values().all(...)`), so `result_page` is `None` and `Plan.returns` omits the path. `Return` then publishes no continuation (`runner.rs:358–367`). That is fail-closed (no shaped rewind) but it drops the owner the static fallback was supposed to keep: “any return path whose value may carry an ambiguous page counts as carrying the raw page.”
- **Scenario.** `page = msgs[0] after c first 1 by byLane` then either `return page if q = 'raw' else []` or `selected = page if q = 'raw' else null` / `return { page: selected, shaped: ignored }`. With `q = 'raw'` and two rows, page 1 is `[a]` and has no `next`, so `[b]` is never reached. The specified High forms use `ignored` on both arms and do not hit this. A sibling `Unknown` field next to a well-joined page poisons the same way.
- **Smallest correct change.** In `join_bindings`, `Page(site, cursor, _)` vs `Empty` (either order) should become `Page(site, cursor, None)`, not `Unknown`. In `collect`, `Unknown` should not fail the record: treat it as possible-raw (clear lineages) and keep a unique sibling page site. `ambiguous_pages` should treat `Unknown` as disabling trim for any page site already in that origin. Add the `else []` / `else null` arms on all three hosts.
