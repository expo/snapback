### 13.1 Notes and declarations

A continuation (`after c` or `before c`) on the same returned page, resolving
to that query’s declared cursor, suppresses N_NO_CURSOR. Invalid cursor names
still fail binding; a cursor on a different page changes nothing. If the
planner declines an authority branch merge and falls back to an ordinary
read, it preserves the enclosing continuation (the fallback previously
dropped it). This fixes continuation execution as well as the false note;
it adds no new IR or cursor protocol.
A mandatory lookup of the same table and exact id value stored in the reference later in the same atomic mutation also suppresses
N_REFERENCE_UNCHECKED: successful return commits the entire mutation. A lookup
on only some committing paths, in an optional loop, or through a rebound input
must not suppress it. A successful return in a later iteration may bypass
the post-loop lookup: when a loop contains an escaping return, the proof
requires a lookup within the writing iteration rather than borrowing a
continuation outside that loop. The note describes a missing lookup, not a foreign key
proof: even an ordinary optional lookup is allowed to observe absence.
This supersedes LLP 3000.039 §7’s exclusion of later lookups.

E_QUARRY_SHAPE_JOIN names both row tables even in nested containers. A duplicate
table effect gets E_QUARRY_DUPLICATE_RULE with the first declaration’s site;
retain the first rule and usable table for recovery, avoiding invented unknown
tables. No invalid schema may execute. Maintained `x in [a,b]` lowers to the
existing typed equality predicates joined by `or` (empty list is false);
only scalar literal elements (including signed numeric literals) qualify.
Nonliteral containers/elements and incompatible types refuse E_QUARRY_MAINTAIN
(or an earlier, more specific source error such as E_QUARRY_SELF_EQUALITY).
Each comparison retains the existing total equality semantics: null equals null
and differs from non-null; empty lists still bind the left scalar operand and
lower to false without evaluating a new runtime operator.
There is no new predicate serialization or interpreter operation.

N_UNREADABLE_PROBE names the total unique key covering a probe when present,
without claiming that uniqueness makes a hidden row visible. N_SYNC_ORDER
states that ordinary reads need the server and cannot provide a complete
answer offline for this order; held reads stay local and incomplete.
N_IMMUTABLE_PATCH is silent when lexical resolution proves equality to a
pinned key, including bound row fields under §10’s full current-snapshot,
no-intervening-write and unconditional-establishment conditions. Pure computed
scalar locals have a stable capture identity even when not constant-evaluable.
Uncertain control flow and stale snapshots retain the note.
N_REQUIRE_REFUSED checks each human branch independently of service branches;
a service alternative in a table rule cannot discharge a human gate’s missing
role proof. A returned query predicate whose explicit alternatives include a
branch not establishing the table’s read rule gets N_QUERY_FILTERED. This is
advice about possible filtering, registered in CODES, its why page and the
review tier. It emits once per returned source page with an explicit positive
caller probe whose branch does not establish the read rule. N_CONDITIONAL_COMPLETE
and N_SPARSE_FILTER discuss different questions (authorized population coverage
and scan cost), so are retained independently, never duplicated at this source
site under the same code. Returned page origins include locals, aliases,
conditionals and containers, including bindings assigned by branches; only
actually returned origins are checked. Implicit final expressions follow
the binder’s return positions. Loop analysis retains break/continue exits
and follows finite source-origin/alias facts to a fixed point across backedges;
it does not execute the loop or unroll its runtime population. The advisory
analysis has a 512-state-transition budget per query: on exhaustion it retains
existing findings and emits N_QUERY_FILTERED naming the restricted read rules
whose caller proof was not completed. This cannot fail compilation or alter
execution. Negative caller probes can prove raw absence only under the existing
visibility proof (LLP 3000.013 §14.7); unknown conjuncts never erase positive
witnesses, and caller-visible absence never silently discharges a hidden raw
negative rule.
It is never an assertion that overlapping roles
are disjoint or a change to query results.

### 13.2 Reviewed notes

`check --ack-notes` records all current Diagnostic notes in the shareable
`snapback/check-notes.json`, only after every ordinary check succeeds.
There is no implicit acknowledgement. Errors cannot be acknowledged.
The version-1 file stores a SHA-256 digest of JSON-encoded lexically sorted
`(filename, exact UTF-8 text)` pairs for the compiler’s complete flat
`snapback/*.q` input set (including all modules, not generated files). Quarry
has no imported source outside that set. Filenames and diagnostic sites are
project-relative module names, with no machine path. It also stores reviewed diagnostic fingerprints (code, site, message,
rewrite and details). Any Quarry addition/removal/edit invalidates all entries;
a changed note also invalidates its fingerprint. A package version change alone
does not invalidate an unchanged finding. This deliberately conservative rule
makes any source rule/module change require fresh review; no external dependency
inference is claimed. Only the notes returned by the pure compiler are eligible.
Store adoption, readiness/fixture drift and residency-change findings added by
check are dynamic and excluded, even when their current message repeats.

Ordinary text prints only unreviewed notes, with a reviewed-count summary.
`--verbose` shows all notes for inspection. JSON always retains all findings in
`notes` and adds `newNotes` and `acknowledgedNotes` arrays of the same Diagnostic
objects; these are disjoint and their union equals notes, even with verbose;
automation never loses a finding. Invalid JSON or an unknown file format fails
check as E_CHECK_NOTES (exit 2) with a repair message and never automatically
overwrite that invalid file. Missing/stale entries are unreviewed and do not
count as reviewed. Notes retain ordinary success exit 0; compile errors retain
exit 1. Re-acknowledgement replaces the valid file with the current eligible set.
With --fix, acknowledgement runs only after the fixed result passes every
ordinary check in that invocation. --emit-lean and --store --release refuse
--ack-notes before work, since they do not perform the project check.
Search certificates are separate from Diagnostic notes and remain visible.
The digest comes from the exact source snapshot compiled (after fixes); a
detected editor save during ordinary checks refuses E_CHECK_NOTES rather than
acknowledging stale findings. All failed checks after compilation (including compiler, server and native
failures) retain their findings as unacknowledged. Invalid-file/source-race
JSON also retains all
compiled notes as newNotes and an empty acknowledgedNotes array.

### 13.3 Bounds and reference decision

E_CASCADE_BOUND names the enabling `delete <-` rule and its site, and offers
`delete <- deny` if that entry point is unintended; authored deletes and expiry
remain independent sources. `why` prints contextual reservation details while
ordinary check keeps arithmetic behind `--verbose`. E_QUARRY_FANOUT offers a
real product cap or resumable job, never paging an atomic mutation.
The cleanup guide (linked by writes) runs mark → chunked child cleanup → parent deletion, and an
active-row guard using an ordinary required parent lookup plus a business
require, without modifying read-through semantics.

**Decision: do not introduce a `checked` reference spelling in 0.4.32.** The
proposed annotation conflates type identity, caller-readable lookup, physical
existence, and application-active status. A mere insert/update rule desugaring
would be bypassed by jobs/fixtures and would fail to define forward references,
keep/set-null actions or adoption. Calling that a checked reference would be a
false safety promise. The supported end state (guide cleanup, its background-cleanup example
and “Active-row references with retained history”; packed-guide
qualification fixture cases cleanup and active-reference) is an explicit physical
`insert <- ... and exists parents[.parent]` and corresponding update guard,
or a caller-readable mandatory lookup plus an active-state require when that
is the application invariant. These forms are enforced today and tested in the
packed guide recipe. References otherwise retain LLP 3000.039 §4.4. A future
annotation needs a separately reviewed whole-write/whole-lifetime constraint
contract, rather than a lint opt-out. This is a deliberate rejected alternative,
not an unimplemented claim of checked-reference support. Later-lookup suppression
is a lint proof of mandatory same-target evaluation, not a rule rewrite and
not a claim about jobs or reference integrity.
