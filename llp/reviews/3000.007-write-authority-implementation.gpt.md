**Overall assessment**

The implementation improves private target resolution, device queueing, and replay sanitization, but it does **not** meet the complete disclosure contract. Remaining channels include hidden-population-dependent page aborts, retained values in constraint messages, incomplete normalization of absent versus refused upserts, and cached diagnostic content after revocation.

Reviewed commit: `32c8bf81bfe87c2f58f91a28ae29c6faec4f2c80`, against `30cf4ce809d68eb8f99c770a7cf6b98d3193708a`. All implementation citations below refer to the reviewed commit; I verified the inspected tracked files match it. This was a blind, read-only source review. I read only the GPT first-pass review, ran no tests, and changed no files. Counterexamples below are source-traced, not execution results.

**Strengths**

- **Private addressing is implemented.** Quarry lowers id and alternate-key update/upsert to `WriteTarget`; target lookup no longer uses an author-visible, read-filtered temporary. Ordinary valued results still pass through `get`. [bind/program.rs:643](snapback4/crates/snapback4-lang/src/bind/program.rs:643), [engine/write_target.rs:31](snapback4/crates/snapback4-core/src/engine/write_target.rs:31), [engine/write_target.rs:66](snapback4/crates/snapback4-core/src/engine/write_target.rs:66).
- **Unchanged foreign assets retain their established facts.** Update authorization precedes asset processing, and unchanged asset placements skip ownership revalidation. This addresses the first pass’s retained-asset-ID example. [engine/write.rs:125](snapback4/crates/snapback4-core/src/engine/write.rs:125), [engine/write.rs:211](snapback4/crates/snapback4-core/src/engine/write.rs:211).
- **The principal device path is correct.** An unheld update/upsert target raises `Prediction`; admission rolls back speculative changes, clears predicted keys, and durably queues the operation as non-predicting. Explicit or inferred `predicts: never` is enforced inside the shared interpreter. [engine/write_target.rs:14](snapback4/crates/snapback4-core/src/engine/write_target.rs:14), [device.rs:562](snapback4/crates/snapback4-device/src/device.rs:562), [engine/local.rs:59](snapback4/crates/snapback4-core/src/engine/local.rs:59).
- **No writer delivery privilege was added.** Events follow the declared audience; snapshots acquire that audience’s groups; stream catch-up checks current readability. Watermarks can advance and settle a write despite an empty writer stream. [partition.rs:109](snapback4/crates/snapback4-core/src/partition.rs:109), [partition.rs:278](snapback4/crates/snapback4-core/src/partition.rs:278), [partition.rs:546](snapback4/crates/snapback4-core/src/partition.rs:546), [device/predictions.rs:54](snapback4/crates/snapback4-device/src/device/predictions.rs:54).
- **The write ceiling and transaction boundary remain intact.** Physical source and maintained writes charge `RowsWritten`; 1,024 is allowed and attempted write 1,025 aborts. Refusals roll back the program savepoint; commit records, partition events, and effects are persisted only on success. [meter.rs:23](snapback4/crates/snapback4-core/src/meter.rs:23), [engine/write.rs:422](snapback4/crates/snapback4-core/src/engine/write.rs:422), [engine/mod.rs:776](snapback4/crates/snapback4-core/src/engine/mod.rs:776).
- **`N_MAINTAIN_DELTA` exists.** The compiler emits a conservative note unless it can establish the relevant authority relationship; the added regression demonstrates equal initial readable totals followed by different permitted deltas. [bind/residency.rs:145](snapback4/crates/snapback4-lang/src/bind/residency.rs:145), [sim write_authority.rs:440](snapback4/crates/snapback4-sim/tests/write_authority.rs:440).

**Concerns**

**1. High — uniformly classified page passes can still disclose hidden population through aborts.**

The admission change checks `scan_visibility(...).uniform`, then immediately admits a never-predicting operation. This correctly rejects an ordinary non-uniform page loop before execution and preserves complete-group requirements for predicting mutations. It does not establish that all physical work preceding the uniform verdict is population-independent. [engine/admission.rs:248](snapback4/crates/snapback4-core/src/engine/admission.rs:248), [engine/rules.rs:21](snapback4/crates/snapback4-core/src/engine/rules.rs:21).

Two concrete holes remain:

- **Word search.** A `matching` scan over an owner-pinned words index is uniform under `read <- .owner = viewer`. A never-predicting loop over another owner’s prefix is therefore admitted. `scan_words` enumerates physical words before evaluating row readability and raises `E_BOUND` upon finding a thirty-third matching word. Empty hidden state commits an empty pass; sufficiently populated hidden state aborts. The internal word merge is not classified as `Origin::Merge` at this admission boundary. [engine/read.rs:292](snapback4/crates/snapback4-core/src/engine/read.rs:292), [engine/admission.rs:97](snapback4/crates/snapback4-core/src/engine/admission.rs:97).
- **Expired rows.** A plain uniform scan charges examined rows and skips expired candidates before evaluating the uniform rule. An empty prefix and a prefix containing more than 8,192 expired rows can produce success versus `E_BOUND`, despite identical readable state. Restoring the meter after a false uniform verdict cannot help when execution never reaches that verdict. [engine/read.rs:443](snapback4/crates/snapback4-core/src/engine/read.rs:443).

The first pass’s **non-uniform read without a loop** also remains admitted when no relevant cap check is present. Merely binding or counting that page can still encounter mutation `Cut::Abort`. This is inherited, but the specifically requested bypass regression remains missing. [engine/admission.rs:62](snapback4/crates/snapback4-core/src/engine/admission.rs:62).

**What would resolve it:** either refuse these scan forms for §5.9 or establish authorization before population-dependent traversal can abort. Add paired worlds for hidden word expansion, expired populations, a hidden scan following meter-consuming work, and non-uniform scans without loops. Compare the full mutation observation, not only `rows_written`.

**2. High — absence and hidden refusal are not normalized across the whole upsert path, and their logical costs differ.**

For an existing target, the implementation performs the read-rule check, allocates/meters the merged image, and evaluates update authority. An absent update bypasses all three. No meter mark is restored around hidden refusal. A read rule containing probes therefore also introduces work absent from the missing-target path. [engine/write_target.rs:31](snapback4/crates/snapback4-core/src/engine/write_target.rs:31), [engine/read.rs:38](snapback4/crates/snapback4-core/src/engine/read.rs:38).

There is also a direct envelope counterexample:

1. Both insert and update authority refuse Bob.
2. Bob supplies a **complete** upsert patch containing an unknown or foreign asset.
3. With a hidden existing target, update authorization returns `NOT_FOUND`.
4. With no target, `insert_upsert` passes completeness validation, enters `insert`, and raises `E_ASSET_UNKNOWN` before checking insert authority.

`insert_upsert` normalizes `Input` and `Rule`, but not `Asset`. [engine/write.rs:104](snapback4/crates/snapback4-core/src/engine/write.rs:104), [engine/write.rs:31](snapback4/crates/snapback4-core/src/engine/write.rs:31), [engine/write.rs:217](snapback4/crates/snapback4-core/src/engine/write.rs:217).

The added `incompleteAsset` case exits on missing required fields in the absent world. It does not exercise this complete-patch branch. [sim write_authority.rs:188](snapback4/crates/snapback4-sim/tests/write_authority.rs:188).

**What would resolve it:** normalize unauthorized branch outcomes across validation, assets, and rules while preserving the separately required S05 collision classification. Add a complete-patch denied-upsert asset pair, and compare all meter fields for ordinary absent/hidden-denied updates. The brief’s equal timing class is unestablished; the RFC explicitly excludes constant time, and no timing measurement was performed here.

**3. High — retained hidden values can still leave through diagnostics or condition execution.**

**Cap diagnostics retain hidden keys.** A cap groups on values from the merged image and prints those values on failure. For example, with a cap over `(secret, bucket)`, an authorized patch changing only `bucket` can fail while printing the retained hidden `secret`. Two worlds differing only in that secret receive different messages. The accepted residual concerning cap **outcomes** does not establish permission to serialize retained row content. [engine/write.rs:328](snapback4/crates/snapback4-core/src/engine/write.rs:328), [engine/write.rs:357](snapback4/crates/snapback4-core/src/engine/write.rs:357).

**The condition purity check is incomplete.** `pure_expr` accepts unhandled variants through `_ => true`, including `Expr::Block` and `Expr::Shape`; `pure_scan` does not inspect the filter. Yet `Expr::Block` executes statements. A hand-authored IR condition can put an `Insert` inside a block, copy `condition.old.secret` into a readable row, and return `true`. Restoring `env` and `consts` does not roll back that write. [engine/write_target.rs:89](snapback4/crates/snapback4-core/src/engine/write_target.rs:89), [engine/write_target.rs:106](snapback4/crates/snapback4-core/src/engine/write_target.rs:106), [engine/runner.rs:393](snapback4/crates/snapback4-core/src/engine/runner.rs:393).

The current Quarry scan-filter binder enforces query placement, so I am **not** claiming that exact writing-block example is generated by ordinary Quarry. It is an engine-boundary hole in code that explicitly claims to reject writes even in hand-authored IR. [bind/program/reads.rs:46](snapback4/crates/snapback4-lang/src/bind/program/reads.rs:46).

**What would resolve it:** remove unreadable retained values from every diagnostic, including caps; make condition purity traversal exhaustive across expression and loop variants, preferably with a runtime write prohibition during condition evaluation. Add paired retained-cap-key tests and serialized-IR tests that attempt writes beneath blocks, shapes, and scan filters.

**4. High — replay strips `result` and `current`, but preserves historical row content embedded in `why`.**

The ordering is substantially improved:

1. Valued writes use a read-rule `get`; conflict recovery uses a read-rule `get` after rollback.
2. `outcome.reply(...)` is serialized into `_ops`.
3. `/m` uses that same serializer.
4. Replay reconstructs `result: Null` or `current: None`, and omits those fields from the wire.

This closes the named row/scalar result and conflict-current replay paths for new-format receipts. `_ops` remains principal-scoped. [engine/mod.rs:791](snapback4/crates/snapback4-core/src/engine/mod.rs:791), [engine/mod.rs:813](snapback4/crates/snapback4-core/src/engine/mod.rs:813), [engine/receipt.rs:13](snapback4/crates/snapback4-core/src/engine/receipt.rs:13), [store.rs:418](snapback4/crates/snapback4-core/src/store.rs:418), [serve.rs:782](snapback4/crates/snapback4/src/serve.rs:782).

However, `from_receipt` copies the entire historical `Refusal`. A readable composite-key collision can record a retained secret in `why.message`; after access is revoked, replay still returns it. The original response may have been lost. [engine/receipt.rs:36](snapback4/crates/snapback4-core/src/engine/receipt.rs:36), [engine/write.rs:301](snapback4/crates/snapback4-core/src/engine/write.rs:301).

Thus the closed ticket’s broader statement that historical read content is not retrievable is premature. [replay ticket:46](issues/closed/20260913-snapback4-ops-replay-returns-cached-content-after-revocation.md:46).

**What would resolve it:** distinguish stable execution identity from row-derived diagnostic details, sanitizing or reauthorizing the latter on replay. Add a lost-response test that produces a readable retained-key constraint message, revokes access, then retries through both `Engine::replay` and `/m`.

**5. Medium — secondary hidden collisions violate the explicitly retained S05 word.**

The implementation converts a hidden secondary collision to `NOT_FOUND`, including when the write target is readable. The absent upsert insertion branch also converts collision `Rule` errors to `NOT_FOUND`. The regression and guide intentionally expect this behavior. It contradicts §8.7(f)’s retained `E_RULE` for every other hidden row. [engine/write.rs:293](snapback4/crates/snapback4-core/src/engine/write.rs:293), [engine/write.rs:112](snapback4/crates/snapback4-core/src/engine/write.rs:112), [sim write_authority.rs:239](snapback4/crates/snapback4-sim/tests/write_authority.rs:239), [guide.rs:513](snapback4/crates/snapback4-lang/src/guide.rs:513).

Ordinary insert and insert-if-absent retain S05, and readable unique collisions now include the index name. Those parts are correct.

**What would resolve it:** preserve collision provenance so target-denial normalization cannot swallow a secondary hidden collision. Change the regression to require the complete `E_RULE` envelope for both update and upsert branches, with readable and hidden targets. Align the guide with the ruled contract.

**Observable inventory**

A writer can observe:

- HTTP status and the complete initial/replayed JSON body: state, id, success sequence/result, failure `why`, optional `current`, and `replayed`.
- Every `why` field: code, family, message, site, rewrite, guide, rule, and retryability.
- Authorized subsequent reads, maintained deltas, stream events/watermarks, snapshots and acknowledgements.
- Device pending rows, durable outbox classification, local reads, reopen/rebase behavior and settlement.
- Logical meter usage through the engine’s returned outcome, plus its indirect effect on wire success/refusal; physical latency through execution.

The serializer omits meters, written tables, and event counts from `/m`; `E_BOUND` correctly prints the ceiling rather than the actual count. That removes direct count fields, not the outcome channels above. [engine/receipt.rs:13](snapback4/crates/snapback4-core/src/engine/receipt.rs:13), [error.rs:13](snapback4/crates/snapback4-core/src/error.rs:13), [error.rs:207](snapback4/crates/snapback4-core/src/error.rs:207).

**Suggestions**

Use one observation helper for the twenty-two acceptance cases that captures the initial HTTP body, durable receipt, retry, complete meter values, committed state/effects, stream/snapshot, and both device stores. Preserve readable state and sequence history between worlds. Add controls proving execution reaches the intended branch.

The first-pass requests are partly resolved: private addressing, unchanged assets, top-level/scalar replay withholding, unheld-device queueing, basic uniform admission, and maintained-delta notes are present. Still missing are the immutable equality repair or explicit acceptance, complete validation-order coverage, non-uniform-read bypass coverage, exhaustive old-image isolation, and full paired observations. Caps, postconditions, approved maintained deltas, and ordinary near-ceiling resource outcomes remain declared residuals; I have not treated their mere existence as new blockers.

The `security.rs` split correctly distinguishes admitted ownership transfer from an old-owner guard’s refusal. `reviews.rs` and `review_corrections.rs` are unchanged in this diff. [security.rs:51](snapback4/crates/snapback4-sim/tests/security.rs:51).

**Open questions**

- Does the author intend to permit immutable-field equality searches? The regression name and first-pass resolution request say otherwise.
- Is the guide’s expansion from update-rule predicates to arbitrary condition predicates an accepted disclosure expansion?
- What measurable cost/timing classes does acceptance require, given the RFC’s explicit constant-time non-claim?

These questions do not remove the concrete diagnostic, replay, S05, and page-pass defects.
