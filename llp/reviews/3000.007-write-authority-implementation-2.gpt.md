**Concerns**

**1. High — a plain uniform hidden page still exposes population through pre-verdict exhaustion.**

`scan_prepared` charges an examined row before deciding readability. Its false-uniform meter restoration occurs only afterward. With no candidate, neither action occurs. [read.rs:443](snapback4/crates/snapback4-core/src/engine/read.rs:443), [read.rs:475](snapback4/crates/snapback4-core/src/engine/read.rs:475), [read.rs:519](snapback4/crates/snapback4-core/src/engine/read.rs:519).

A concrete pair:

1. A never-predicting mutation first reads 8,192 fixed, readable rows, consuming exactly the examined ceiling.
2. It then binds a plain, non-expiring page under another owner’s prefix and returns a constant.
3. Both page sites are uniform and admitted.
4. With zero rows under the hidden prefix, the mutation commits.
5. With one hidden row, its first examined charge raises `E_BOUND` before the false verdict can restore the meter.

This reveals hidden population without any admitted write to the hidden row. It is the page-pass channel the narrowing was meant to close, rather than a constraint outcome of an admitted hidden write.

The new “after metered work” test performs **100 arithmetic iterations**, not exhaustion of examined or rule-probe capacity. It therefore cannot catch this example. [page_admission.rs:66](snapback4/crates/snapback4-sim/tests/page_admission.rs:66).

There is also an expiry dependency gap: rejecting expiry on the scanned table does not reject a uniform read rule whose `exists` probe traverses an expiring table. `Probe::exists` calls `live_lookup`, which charges expired siblings before finding absence. A large expired probe population can abort before the page’s false verdict. [read.rs:39](snapback4/crates/snapback4-core/src/engine/read.rs:39), [read.rs:67](snapback4/crates/snapback4-core/src/engine/read.rs:67).

**What would resolve it:** establish the uniform verdict independently of candidate population before population-dependent aborts, or narrow admission further where that cannot be established. Extend `w2_a_uniform_hidden_page_after_metered_work_has_the_same_complete_observation` to exhausted examined/probe budgets, and add `w3_uniform_page_with_expiring_rule_probe_has_no_population_oracle`. Both should use the shared helper.

**2. High — hidden-refused targets can still differ from absent targets in both outcome and meter.**

`target_attempt` restores the mark only for an actual `NOT_FOUND`. Existing targets first evaluate their read rule and allocate/meter the merged image; either can raise `E_BOUND`, which bypasses restoration. Missing updates take neither path. [write_target.rs:10](snapback4/crates/snapback4-core/src/engine/write_target.rs:10), [write_target.rs:44](snapback4/crates/snapback4-core/src/engine/write_target.rs:44).

For example, hold caller inputs and readable state fixed, deny update authority, and leave enough heap capacity for the caller’s patch but insufficient capacity for a large hidden merged row. The hidden world returns `E_BOUND`; the absent world returns `NOT_FOUND`. Exhausting rule-probe capacity before a hidden target’s read-rule probe gives the same distinction, including before the immutable guard.

This also means hidden conditions may fail on merged-image allocation before reaching `require_readable_condition`. The condition is not evaluated, but its promised uniform refusal is not reached.

**What would resolve it:** make the authorization/refusal decision preserve the absent/hidden boundary under exhaustion, while retaining physical bounds. Do not merely redact the `E_BOUND` text. Extend `w2_hidden_refusal_restores_read_rule_probe_work_too` with exhausted-probe and near-heap pairs for ID update, unique update and upsert; include immutable and conditional variants. The existing test only exercises ample-budget probes. [test:575](snapback4/crates/snapback4-sim/tests/write_authority.rs:575).

The accepted residual for ordinary budget outcomes does not establish the stronger §17 claim that hidden-refused and absent attempts now have identical logical cost on every branch.

**3. High — maintained-sum overflow prints a retained hidden value in the first refusal.**

`apply_aggregate` raises `ValueError::Overflow(next)` with the computed aggregate. Its display includes that number, and `RuntimeError::refusal` preserves it. [write.rs:568](snapback4/crates/snapback4-core/src/engine/write.rs:568), [value.rs:92](snapback4/crates/snapback4-core/src/value.rs:92), [error.rs:197](snapback4/crates/snapback4-core/src/error.rs:197).

A concrete pair uses a hidden source and a hidden maintained sum:

- Destination group B already totals `I53_MAX`.
- The selected hidden row belongs to group A and retains contribution `1` in one world, `2` in the other.
- The same admitted patch changes only its group to B.
- Both mutations roll back, but their first refusals print `9007199254740992` versus `9007199254740993`.

Subtracting the known destination total reveals the retained contribution. Neither the source nor the maintain needs to be readable.

This is **diagnostic content disclosure**, not merely the accepted overflow/constraint outcome residual. The new receipt sanitization protects retry, but the first reply still leaks.

**What would resolve it:** use a value-free overflow refusal for engine-internal aggregate computation, auditing the corresponding live-aggregate overflow path too. Add `w3_hidden_maintain_overflow_never_serializes_the_retained_contribution`, with both worlds overflowing and complete first-body/receipt/retry/device comparison. The current cap and atomicity tests would not catch it.

**4. High — the asset preservation shortcut permits a hidden asset equality test.**

`with_asset_facts` preserves old facts whenever the new asset ID equals the old ID, including when that ID was explicitly supplied in the patch. It does so before upload ownership validation. `place_assets` likewise skips unchanged IDs. [write.rs:223](snapback4/crates/snapback4-core/src/engine/write.rs:223), [write.rs:269](snapback4/crates/snapback4-core/src/engine/write.rs:269).

Hold the upload registry and caller input fixed. Both hidden targets admit updates; one holds foreign asset G and the other holds foreign asset H. Submit `{photo: {id: G}}`:

- The G world preserves the placement and succeeds.
- The H world checks G’s ownership and returns `E_ASSET_UNKNOWN`.

The update-rule predicate is identical in both worlds. The outcome reveals which retained asset the target held. The current regression tests an **omitted** photo column and denied writes, not an admitted explicit matching guess. [test:289](snapback4/crates/snapback4-sim/tests/write_authority.rs:289).

**What would resolve it:** preserve omitted placements while making explicit asset assignments independent of equality with an unreadable retained placement—for example, require independently established placement authority for the supplied asset. Add `w3_explicit_foreign_asset_guess_does_not_test_hidden_placement`, plus a control retaining the existing omitted-column behavior. If this is intended as another disclosed constraint predicate, it needs an explicit author disposition.

**5. Medium — serialized IR can bypass the non-looping merge prohibition.**

The global plain-page check recognizes merges through `scan.merge_site`. The scan traversal visits `Expr::Merge` lanes but does not preserve their structural parentage. A hand-authored `Expr::Merge` with uniform plain lanes and `merge_site: None`, merely bound or returned without a loop, therefore avoids this prohibition. The separate `Origin::Merge` rejection is invoked when admitting a loop. [admission.rs:359](snapback4/crates/snapback4-core/src/engine/admission.rs:359), [ir.rs:584](snapback4/crates/snapback4-core/src/ir.rs:584), [admission.rs:245](snapback4/crates/snapback4-core/src/engine/admission.rs:245).

Ordinary Quarry supplies the marker; this finding concerns the same serialized-IR engine boundary that the condition repair explicitly protects.

**What would resolve it:** derive the merge prohibition from expression structure, not optional scan metadata. Add `w3_serialized_nonlooping_merge_without_merge_site_is_refused`. The current merge regression uses authored Quarry and a loop. [page_admission.rs:57](snapback4/crates/snapback4-sim/tests/page_admission.rs:57).

**6. Medium — §17’s complete-observation acceptance remains incomplete.**

The helper is a meaningful improvement. Comparing changed fields while separately retaining complete before/after states is appropriate for worlds whose unchanged hidden images intentionally differ. It also runs both device stores through admission, pending state, reopen and settlement. [write_observation.rs:114](snapback4/crates/snapback4-sim/tests/common/write_observation.rs:114).

However:

- `s05_a_readable_clash_still_names_the_index` remains single-world and still checks `"key"` and `"lookup"`, not the actual index name `"byKey"`. [test:127](snapback4/crates/snapback4-sim/tests/write_authority.rs:127).
- `wa5_hidden_write_replay_returns_only_sanitized_receipt` inherits a complete success pair, but its failed-receipt case remains single-world. [test:307](snapback4/crates/snapback4-sim/tests/write_authority.rs:307).
- `wa5_revoked_result_and_conflict_current_are_not_retrievable` and `w2_receipts_store_the_replay_body_before_revocation_including_diagnostics` use direct calls, without paired complete observations or both-store revocation lifecycles. [test:317](snapback4/crates/snapback4-sim/tests/write_authority.rs:317), [test:550](snapback4/crates/snapback4-sim/tests/write_authority.rs:550).
- The serialized-condition tests check selected rows and receipt content, rather than complete paired observations. [condition_authority.rs:57](snapback4/crates/snapback4-sim/tests/condition_authority.rs:57).
- Static refusal tests appropriately compare compiler observations; an operation refused at `check` has no first mutation body or receipt. They should be described as that explicit exception, rather than complete runtime-helper coverage.
- The helper uses `/m`’s serializer bytes, not actual HTTP response bytes/status. The HTTP tests provide separate coverage, but are not paired-world comparisons.

**What would resolve it:** apply the helper to the remaining runtime acceptance cases, extending it with an intervening revocation step before retry and device settlement. Assert the actual readable collision index. Add the counterexample pairs above; merely routing the current fixtures through the helper would still miss those branches.
