## Review (verbatim answer text)

Required changes (1)–(3) and (5)–(7) are in the tree and match the stated contract. Change (4) fail-closes the store it is called on, and it does not fail-close a warm HTTP reader pool after a later publication-mode change. That gap is reachable only through a future Stage R setter. It is still the obligation this round claimed to close.

## Required changes

1. **Explicit G6 skips RI.** `prepare_read_index` returns `None` when the shared grant is `configured`, `revoked`, or `uncertain` (`snapback4/crates/snapback4-core/src/engine/revision_cache_park.rs:27-30`). Proof consumption repeats that check (`revision_cache.rs:804-806`). `enable_read_grant` sets `configured` before it returns (`ownership.rs:477`), which is before engine admission (`ownership.rs:449-453`). With both flags set, startup text is “RI requested, bypassed” (`store_config.rs:239`). A configured grant never parks, so it never schedules a round.

2. **Timer start is fallible and keeps the original admission.** `Resume::park` returns the reader and drops the publication-admission lease before `OnceLock` initialization (`serve_queries.rs:63`, `serve_read_index.rs:117-131`). `Queue::new` failure is cached as `Err` and `Queue::complete` resumes ordinary G5 on the original absolute deadline (`serve_read_index.rs:96-106`, `137-138`). `submit_until` enqueues or spawns. It does not wait for a free worker. An idle timer blocks on `changed.wait` / `wait_timeout` (`serve_read_index.rs:53-55`).

3. **Blocking engine API does not hold a reader across an RI wait.** `query_materialized_search_with_request` always calls `query_cached_request(..., None)` (`engine/mod.rs:839-844`). `query_materialized_search_without_read_index` does the same (`revision_cache_park.rs:49-53`). The `allow_blocking` coordinator is gone from that signature. The memory path uses the blocking API directly (`serve_queries.rs:148`).

4. **One predicate, incompletely applied to the serving pool.** `Store::read_index_eligible` is the only gate: `SynchronousHead` with `early_release.is_none()`, otherwise false (`postgres/read_index.rs:10-14`). Enrollment, validation, and proof consumption all call it (`revision_cache_park.rs:28`, `43`; `read_index.rs:20`; `revision_cache.rs:805`). RFC 003 §14 records the W-bound V obligation before the later “pending review” list (`llp/3000.009.001.000.000.003-concurrent-disjoint-commits.rfc.md:1330-1336`). `Handle::reader` copies the mode onto a reader created after the flip (`handle.rs:62-63`). See the finding below for copies that already exist.

5. **Session facts are documented as fill-time facts under the unified revision.** The controls RFC states that RI certifies fill-time `SessionFacts` via the unified stamp, and that raw `_sessions` edits which omit the revision bump are outside the contract (`llp/3000.009.001.000.002-beating-the-postgres-controls.rfc.md:1526-1541`). The guide matches (`snapback4-lang/src/guide/release-json.md:185-196`). `connect_inner` sets `unified`, and `Tx::commit` bumps the revision for a durable unified write that has not already done so.

6. **Startup, doctor, and the guide name the active mode.** Startup selects the default RI line, `SNAPBACK4_G5_READ_INDEX=0`, `commit=early; RI bypassed`, or the G6 bypass line (`store_config.rs:215-239`). Doctor reports persisted G5 or a live G6 grant and says owner-local RI status is unconfirmed (`postgres/deployment.rs:22-29`). The guide states the Postgres HTTP default, `=0`, the 8 ms budget, blocking APIs, `commit=early`, and Stage R fail-closed (`release-json.md:168-183`).

7. **Default is on for Postgres serving, and `=0` is off.** An absent variable is on, `"1"` is on, and `"0"` or non-UTF-8 is off (`store_port.rs:143-148`). Any other explicit value refuses configuration when a store URL is present (`store_config.rs:41-44`). The flag is latched once into the cache (`revision_cache.rs:237`).

## Default-on scope

SQLite and every non-Postgres store take `read_index_eligible() == false` (`store/port/lifecycle.rs:79-83`). `commit=early` installs the E gate before readers, and the predicate requires `early_release.is_none()` (`read_index.rs:12`, `store_config.rs:216-219`). Personas and staging build the context with the revision cache disabled, so there is no cache key and no enrollment (`serve.rs:1201`). The memory store has no detached readers and uses `query_materialized_search_with_request` (`serve_queries.rs:131-148`). The blocking engine API passes `None` as the parked proof (`engine/mod.rs:844`).

## Findings

**MATERIAL, IN-DELTA.** A publication-mode change after the HTTP pool is built does not fail-close readers already copied.

`ReadPublication` is a per-store `Copy` value, default `SynchronousHead` (`postgres/store.rs:84-91`). `QueryReaders::new` snapshots factories from `engine.reader()` (`serve_readers.rs:81-82`). `prepare_population` fills the idle pool from that snapshot (`serve_readers.rs:105`). Checkout pops an idle engine unchanged, or calls `reader()` on a factory that was itself snapshotted at pool construction (`serve_readers.rs:152-167`). `enable_early_release` refuses once `self.readers` is set (`handle.rs:32-33`). `PublishedPrefix` has no such lock, and its only setter is the test hook (`store/port/fixtures.rs:29-31`).

The controls RFC says the predicate is consulted at enrollment, validation, and consumption, “so even an already completed raw-H proof is refused after a mode change” (`llp/3000.009.001.000.002-beating-the-postgres-controls.rfc.md:1594-1598`). That holds for the store that was flipped. `g5rf_publication_prefix_disables_enrollment_validation_and_saved_proof` flips that same engine, then checks a `reader()` created afterward (`revision_cache_read_index_tests.rs:195-202`). It does not cover an idle HTTP engine created before the flip.

Scenario: the pool is filled at startup under `SynchronousHead`. A later W/Stage R path sets `PublishedPrefix` on the owner the way the test hook does, and does not rebuild `QueryReaders`. Idle readers and later `factory.reader()` calls stay eligible. They can enroll and consume a saved raw-H proof while H lags W. Nothing in this checkout sets `PublishedPrefix` in production (`store.rs:86-87` is `dead_code`), so this is not a stale read on a path that runs today.

**MINOR, PRE-EXISTING.** Replacing one closed reader socket revokes the shared grant for the process. `open_owned` attaches that grant even when G6 is off (`ownership.rs:275`). `refresh_reader_connection` calls `grant.revoke()` when `refresh_closed` replaces a closed reader (`postgres/store.rs:132-135`, `pipeline.rs:304-311`). `prepare_read_index` already treated `revoked` as ineligible. This round added `configured` beside it (`revision_cache_park.rs:29`). After one dropped reader socket, later HTTP prepares take ordinary G5 until restart. That is fail-safe. It is a silent disable of the mode this round turns on by default.

No new deadlock, reader-loan hold, lease leak, panic, or resource-cap growth showed up on the paths this round changed. The timer and the flight do not lock the batch and the schedule in opposite orders. A failed timer does not occupy a reader or a publication lease while it resumes G5. Validator concurrency stays at two flights plus one timer thread. This pass did not build or run tests.

VERDICT: NOT READY
