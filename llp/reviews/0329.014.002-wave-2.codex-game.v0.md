### 2. Schema in v0

The literal design cannot be transcribed directly:

- Partial unique indexes are absent; `queue_claims` and `active_seat_claims` replace them.
- Rules are row-level, so public round state, system seed, player audit, sealed payloads, public submission markers, and rail publication are separate rows.
- `shuffle_audits` cannot be append-only and later “filled”; commitment, secret, and final audit are separate append-only tables.
- `viewerUserIds` cannot be inspected inside opaque JSON rules; viewer-specific effect copies replace it.
- v0 has no `f64`, bytes, enum, nullable, or typed tuple spelling. Hashes/nonces use canonical 64-character hex; ratings remain opaque bounded JSON and therefore cannot yet be calculated by Op 9.
- The product must still supply `B_HANDLE`, `B_PUSH_TOKEN`, and canonical JSON byte bounds. A real `check` must refuse these symbolic bounds rather than invent them.

The reusable rule objects below contain all four effects. `signed()` is a shape-keyed probe of a caller-owned principal row.

### 3. Operations in v0

`ctx.receivedAt`, `crypto.*`, `rating.glicko2FFA`, and `maintain.rank` below are proposed deltas, not invented v0 features. Capped scans use:

```ts
function capped(db, index, prefix, n) {
  const p = db.scan(index, prefix, { take: n })
  db.require(!p.hasMore, 'corrupt_over_cap')
  return p
}
```

The semantic `All<T,N>` exists in §4.4, but its constructor spelling is absent; `capped` is the explicit scan-and-cap equivalent.

**Matchmaking — Ops 1–3.**

```ts
export const EnqueueForMatch = mutation(
  { deviceId: id(devices) },
  ({ db, ctx, args }) => {
    const device = db.get(devices, args.deviceId)
    db.require(device && device.userId === ctx.viewer, 'device_not_owned')
    db.require(!db.get(activeSeatClaims.byUser, [ctx.viewer]), 'in_match')

    const current = db.get(queueClaims.byUser, [ctx.viewer])
    if (current) return db.get(queueTickets, current.ticketId)

    const rating = db.get(ratings.byUser, [ctx.viewer])
    db.require(rating, 'rating_missing')
    const ticketId = ctx.newId()
    const at = ctx.commitTime
    db.insert(queueTickets, {
      ticketId, userId: ctx.viewer, status: 'waiting',
      enqueuedAt: at, expiresAt: at + 90_000,
      waitingWhen: { from: at, to: at + 90_000 },
      bucketCenter: rating.displayRating, ratingLock: rating.state,
    })
    db.insert(queueClaims, {
      claimId: ctx.newId(), userId: ctx.viewer, ticketId,
    })
    return { ticketId, status: 'waiting' }
  }
)

export const CancelQueue = mutation({}, ({ db, ctx }) => {
  const claim = db.get(queueClaims.byUser, [ctx.viewer])
  if (!claim) {
    const seat = db.get(activeSeatClaims.byUser, [ctx.viewer])
    return seat
      ? { ok: false, code: 'already_matched', matchId: seat.matchId }
      : { ok: true }
  }
  db.update(queueTickets, claim.ticketId, () => ({ status: 'cancelled' }))
  db.delete(queueClaims, claim.claimId)
  return { ok: true }
})
```

The first schema attempt, `unique(userId) WHERE status='waiting'`, is `E_OPAQUE`; the claim-row rewrite is a plan. A read-then-insert race still needs specified transaction retry or an `insertIfAbsent(..., conflict:'already_acted')` construct; otherwise the loser receives sealed `E_CONSTRAINT`.

The bounded greedy loop in MatchmakeTick is legal, but its first complete attempt is not:

```ts
const waiting = db.scan(queueTickets.byStatusExpires, ['waiting'], {
  range: { gt: ctx.now() }, take: 2000,
})
for (const oldest of waiting) {
  // bounded nested search, oldest-first, using oldest's W
  // pack exactly six unused tickets
  const seed = crypto.randomBytes(32)       // E_OPAQUE
  const hash = crypto.sha256(seed, 'ashrail-v1') // E_OPAQUE
  // insert match, six seats/claims, round, secret, commitment
}
```

Diagnostic:

```text
E_OPAQUE: crypto.randomBytes/SHA-256 are outside the value model.
Rewrite: a modeled system-only random input plus deterministic SHA-256.
E_BOUND/E_STEPS: 2000×2000 comparisons and ≤13,324 writes exceed ordinary ceilings.
Rewrite: admitted raised ceilings or resumable one-pack orchestration.
E_FANOUT: an expired-ticket write page reached hasMore.
Rewrite: a cursor-bearing batch or per-ticket expiry schedule.
```

A further mismatch remains: the design wants each failed six-pack to abort independently and then continue; one v0 mutation is one transaction. It needs one-pack scheduled mutations or a staged-job runtime.

**Entropy and deal — Ops 4–5.**

The naïve admission uses `ctx.now()`, which v0 would wrongly admit:

```ts
db.require(ctx.now() <= round.phaseEndsAt + 250, 'phase_closed')
```

`ctx.now()` is client intent time, not authoritative ingress time. There is no current diagnostic; the required new one is:

```text
E_AUTHORITATIVE_TIME: deadline admission used intent time.
Rewrite: ctx.receivedAt plus onlineOnly/no-outbox delivery.
```

Corrected after that delta:

```ts
export const SubmitEntropy = mutation(
  { roundId: id(rounds), generation: int(), nonceHex: text({ max: 64 }) },
  { delivery: 'online-only' },
  ({ db, ctx, args }) => {
    const r = db.get(rounds, args.roundId)
    const seat = db.get(matchSeats.byMatchUser, [r.matchId, ctx.viewer])
    db.require(seat, 'not_seated')
    db.require(r.phase === 'entropy' &&
               r.generation === args.generation, 'phase_closed')
    db.require(ctx.receivedAt <= r.phaseEndsAt + 250, 'phase_closed')
    db.require(isCanonicalHex32(args.nonceHex), 'illegal_nonce')
    if (db.exists(entropyNonces.byRoundUser, [r.roundId, ctx.viewer]))
      return { ok: false, code: 'already_acted' }
    db.insert(entropyNonces, {
      nonceId: ctx.newId(), roundId: r.roundId, matchId: r.matchId,
      seatIndex: seat.seatIndex, userId: ctx.viewer,
      nonceHex: args.nonceHex, receivedAt: ctx.receivedAt,
    })
    return { ok: true }
  }
)
```

CloseEntropyAndDeal’s first Fisher–Yates attempt needs `SHA-256` and a probabilistically unbounded rejection loop, producing `E_OPAQUE`; a literal loop bound would introduce bias or a possible failed deal. After a host `crypto.sha256` and `crypto.permutation9` delta, the scheduled program is:

```ts
const r = db.get(rounds, roundId)
if (r.phase !== 'entropy' || r.generation !== expected) return
const nonces = capped(db, entropyNonces.byRound, [roundId], 6)
const seats = capped(db, matchSeats.byMatchSeat, [r.matchId], 6)
db.require(seats.length === 6, 'seat_corruption')

if (r.roundIndex === 0 && nonces.length < 4) {
  // mark match aborted; insert terminal; delete six active-seat claims;
  // insert six fresh waiting tickets and claims from seat.startRating
  // write no finish or rating row
  return
}
const secret = db.get(roundSecrets.byRound, [roundId])
const six = fillMissingNonces(
  nonces, seats,
  s => crypto.sha256(secret.serverSeedHex, 'fill',
                     r.matchId, r.roundIndex, s)
)
const combined = crypto.sha256(
  secret.serverSeedHex, ...six, r.matchId, r.roundIndex
)
const permutation = crypto.permutation9(combined)
db.insert(shuffleAudits, { /* secret, six, combined, permutation */ })
for (const slot of [0,1,2,3,4,5,6,7,8])
  db.insert(roundCards, {
    cardId: ctx.newId(), roundId, matchId: r.matchId, slot,
    dealtRole: DECK[permutation[slot]],
  })
db.update(rounds, roundId, () => ({
  phase: 'night', generation: expected + 1,
  phaseStartedAt: ctx.now(), phaseEndsAt: ctx.now() + 20_000,
}))
```

The closer must run after the `+250ms` cutoff with an ingress-ordering barrier; merely scheduling at the nominal deadline—or even exactly at `+250ms`—does not guarantee that every already-stamped request is serialized first.

**Night — Ops 6–7.**

  { matchId: id(matches) },
  ({ db, ctx, args }) => {

### 8. Where the design is wrong

1. **Grace and closer ordering contradict.** Actions are valid through `phaseEndsAt+250ms`, but closers run at `phaseEndsAt`. Confirm by delivering an ingress-stamped `+180ms` vote after the closer transaction wins; the supposedly valid vote is rejected.

2. **Season eligibility is implemented as lifetime eligibility.** The contract requires five matches this season, while the schema/rebuild use lifetime `gamesPlayed≥5` plus only one event in the season. Confirm with a veteran who has 100 lifetime games and one current-season game; the written rebuild ranks them incorrectly.

3. **The mandatory reveal pause is absent from the one-round view model.** Op 9 immediately creates the next entropy round, while GetTableView returns only one round. Confirm by reconnecting four seconds after round 0 reveal; selecting the latest round returns entropy with no way to reconstruct the required round 0 reveal.
