## Initial pass — NEEDS REVISION (`d38c7dfcf`)

1. **P1, named polls starve route verification.** Generated `startServer`
   started one long-poll action loop per ordinary/private route handler before
   its verifier loop. Thirty-two idle handlers could occupy every shared
   wait slot; immediate renewal versus verifier backoff could keep valid
   webhooks unavailable indefinitely.
2. **P2, more than 128 service routes cannot be verified.** The runtime sent
   every route name in one verification claim, while HTTP rejected more than
   128. The language imposed no corresponding registry-count limit. A valid
   large registry retried an impossible request forever.

Lead confirmed both. `7ab37426e` separates four registry-claim and four
verification-poll slots from the existing 32 legacy waits, 32 short requests
and 16 ingress waits. `1dcacbc83` selects one generated action-registry loop,
grouped by configured session lifetime, with rotating 128-name chunks; the
verifier uses a separate rotating loop. Multiple chunks wait at most one
second each. Legacy `runWorker` keeps per-name polling by default. The core
name-set selector shares the existing authority, generation, lease and
settlement path rather than creating another work lifecycle.
