## Findings

### 1. Low — `listEffects` type does not carry `satisfied`

- **Where:** `snapback4/packages/snapback4/src/worker.ts:13–22` vs `202–209`
- **Scenario:** An operator script `listEffects(url, token, "satisfied")` compiles as `Effect[]`. Runtime JSON has `state` and `result: { outcome: "presence_reconnected" }`, but the published type has neither, so a TypeScript worker cannot distinguish cancelled grace pushes from ordinary queued rows without extra casts.
- **Smallest fix:** Add optional `state` and `result` on the listing type (claim payloads can stay as they are).

### 2. Low — doctor names `satisfied` only as a count

- **Where:** `snapback4/crates/snapback4/src/verbs.rs:540–546`
- **Scenario:** After a reconnect-and-restart, `doctor` prints `effects 1 satisfied` and then only dumps `failed` rows. An operator debugging “why was this push not delivered?” has to know to `GET /effects?state=satisfied`.
- **Smallest fix:** Print the newest satisfied row the same way failed rows are printed (id, effect, `presence_reconnected`).
