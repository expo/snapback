# LLP 3000.007 §20.26 — OPS review dispositions, 2026-10-12

The implementing session adjudicated the two received blind reviews. These
dispositions do not change the existing RFC's status or accept on the author's
behalf. Original responses are preserved verbatim in the
[Muse review](./3000.007-ops-production-surfaces.muse.md) and
[fresh Codex review](./3000.007-ops-production-surfaces.codex.md).

| Finding | Disposition and evidence |
|---|---|
| Codex: CTE shadowing/forward references and schema qualification can corrupt SQL types | Fixed conservatively. Object mode refuses schema-qualified relations, CTE shadowing and unresolved declaration-order lineage; positional JSON remains supported. Regressions cover both supplied corruption examples and a forward CTE, plus parenthesized columns, derived tables, USING joins and mixed/boolean UNION. |
| Codex: bound custom-session validation still returns E_AUTH at 200 | Fixed at session_mint_wire, using the common identity error mapping. Production tests compare legacy and bound reserved-principal requests at 401/E_AUTH. Action-lease refusals retain their existing status. |
| Codex: parenthesized output names and USING lose boolean lineage | Fixed by unwrapping direct-column names and requiring all USING contributors to agree on boolean type. Covered in the SQL regression. |
| Codex: admin alias misses production bootstrap | Routed admin to deploy's First admin section, with a rendered alias-landing regression; roles/rbac still open the existing application recipe. This extends the user's explicit production aliases. |
| Codex: HTTP table overstates identity input validation | Clarified the existing identity scope/value 200/E_INPUT exception and streaming 200 behavior. Application operation statuses remain unchanged. |
| Muse: case-variant output names can drop values | Added case-insensitive duplicate-name refusal and a regression. The proposed last-key-drop mechanism does not apply directly: lowercasing is only used by the type-inference map, while JSON keys come from SQLite's actual names. Nevertheless SQLite can rename case-colliding projections, so rejecting them preserves the promised names. |
| Muse: all Auth errors might be retryable/rate-limited | No such RuntimeError::Auth case exists: error.rs constructs terminal Auth refusals; retryable store/structural errors are distinct. The dedicated auth rate-admission path still returns 429 directly, and preserved diagnostic bearer refusals still use respond_refused (401/503). Full auth/client checks cover existing paths. |
| Muse: rollback flags might not be implemented | Existing releases.rs rollback calls check_change with allow-destructive and passes allow-feed-adoption to activation. Only help text was changed, as explicitly requested; adoption behavior belongs to ROLL. |
| Muse: sign-in aliases split between cards | Unified signup/sign-up/register and login/signin on deploy; auth/headless retain the executable account-seeding recipe. Deploy explicitly links to those recipes. |
| Muse: replay current omission untested | Added current absence beside result absence. Existing receipt implementation strips both historical values; no core contract changes. |
| Additional useful regression coverage | Added fixture non-creation/isolation assertion; serve tests keep the first range port occupied, check the held chosen listener and PID, exercise equals port spelling, and bound startup reads to 20 seconds. SQL catalog object-mode behavior and recursive-CTE refusal are covered. |
| Muse: unrelated census order changes | Removed them; the only census delta is the new never-predicted grantAdmin operation. |
| Muse: published-file allowance and warning stderr | deployment/store.sqlite is a generated application deployment output, like the already allowed store paths. check warnings intentionally use stderr to preserve JSON stdout. Documented in the operator reference. |
| Muse: permission errors and non-loopback port probe race | Existing dev semantics are deliberately reused, per the task. Only loopback range listeners are handed over; wildcard binding uses the existing server listen path. No new guarantee for a held non-loopback range is claimed. |
| Muse: valued json-objects switch spelling | The documented switch is valueless. No new equals-value switch convention is introduced; port equals spelling is tested separately. |
| Muse: CTE alias arity and optional bool | SQLite prepares the original statement before inference and rejects invalid CTE alias arity. Nullable bool recovery is tested with false/null and literal defaults. |
| Existing deployment claims | Existing releases, token_live, check and server tests cover token minting, adoption and release behavior; guide Quarry compiles and the admin grant runs under ops/existing-admin/public viewers. The package's stopped-backup record remains the reference for restore. |

Validation and commits are recorded in the workstream report and journal. The
full package run also exposed a pre-existing clock test whose daily 06:00 job
changed the hourly counter; its fixture now uses a separate no-change daily
sweep, preserving the hourly restart assertion without time-of-day dependence.
