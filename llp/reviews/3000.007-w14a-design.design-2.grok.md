## Findings

### 1. High — `REVIEW-DESIGN.md:36` (table, “A full page” / non-uniform)

**Wrong:** An admitted non-uniform full page is described as `complete: false, cut: "words"`. On the server the public reason is withheld; `cut: "words"` is only the private `word_cut_at` path, and only when the 32-word bound actually fired.

```123:127:snapback4/crates/snapback4-core/src/engine/runner.rs
    pub(crate) fn read_cut(&self) -> Option<super::ReadCut> {
        if self.non_uniform && !self.device { None }
        else if self.meter.capped_at.is_some() { Some(super::ReadCut::Meter) }
        else if self.word_cut_at.is_some() { Some(super::ReadCut::Words) }
        else { None }
    }
```

The spike’s own non-uniform probe already records `public cut: null` (`REVIEW-SPIKE.md:93`; `w14a_spike/mod.rs:45`). A non-uniform page that never reached 32 words is still `complete: false` by the class (`mod.rs:737–738`) with `next` stripped by `outcome_next_cursor` (`read.rs:787`), not by a word cut.

**Scenario:** A builder (or the lane’s docs) treats a 10-word non-uniform page as `cut: "words"` and renders “narrow the term” instead of “results may be incomplete”.

**Smallest change:** Split the cell: word-bound hit → private `word_cut_at`, public `cut: null` on the server / `cut: "words"` on device and uniform-class reads; otherwise the existing never-complete class, public `cut: null`, no `next`. Keep the spike’s 33/32/null/no-next numbers as the control.

### 2. High — `read.rs:1029–1032` and `1072–1081` (charging after growth)

**Wrong:** Design §3–§4 require heads “charged **before growth**”. The spike charges descriptor/WordRead/MergeHead *before* `lanes.push` (`read.rs:1004–1022`) — then allocates the refill with `scan_prepared` and charges `rows.capacity()` / key heaps *afterwards*. `Meter::heap` on `Cut::Cap` throws `E_BOUND` only after that allocation (`meter.rs:185–191`); `Runner::run` then clears the page (`runner.rs:201–204`). That is detection after growth, not admission before it.

Also uncharged before growth, named by the spike and still unnamed as formulas in §4:

| Site | What grows | Spike charge |
|---|---|---|
| `crate::words::terms` | fold `String` + `Vec<String>` (`words.rs:45–86`) | none |
| `bounds.after = vec![Value::String(word.clone())]` | extra token + `Vec` (`read.rs:466`) | folded into the 2×`String` fudge |
| `Scan { prefix, ..scan.clone() }` | full IR clone, including the discarded original `WordPrefix` prefix, `filter`, `Bound::Arg` name, nested `after` (`read.rs:472–478`) | `sizeof(Expr)+1` if `after` exists; not a tree |
| `lane_word.clone()` per generated lane (`read.rs:1022`) | N `WordRead`s | 2 copies *per lane* (over-count of copies, under-count of N vs 2 at discovery) |
| `prefix.clone()` / `bounds.clone()` at every `scan_prepared` | live clones | geometric factor two on the *first* descriptor only |
| SQLite/memory scan buffers, malloc headers, `Vec`/`String` min capacity | process memory | none (approximate meter by contract) |

**Scenario:** A uniform scope whose live rows are large (4 KB bodies, `take+1` batch on ≤8 lanes) allocates the batch, then the heap charge throws; RSS already exceeded the 16 MiB story. At 1,000 short `kx*` words the meter reads 4,143,712 B (`REVIEW-SPIKE.md:51`); uncharged IR clones (~0.2–0.5 MB), allocator headers, and store pages sit on top of that. Heap, not the index ceiling, will fire first (~4 KB charged/word → ~4,000 words into 16 MiB).

**Smallest change:** For every fetch, charge `batch * schema-max row heap` (and the clone of prefix/bounds) *before* `scan_prepared`; on failure do not fetch. Price `scan.clone()` with `Expr` tree bytes, not `sizeof(Expr)+1`. State each site’s formula in the journal. Do not raise ceilings: earlier cuts are the point.

`merge_lazy` also gates extra charging/skip-on-cap on `word.admitted` (`read.rs:993`, `1030`) rather than `admitted && visibility.uniform`. Device trust can set `admitted` on a statically non-uniform scope (`read.rs:418`, spike §1). The 32-cap still holds in `word_lanes` (`read.rs:434`); the new skip-on-cap and heap arithmetic would still apply. Gate both on the same `metered_words` predicate.
