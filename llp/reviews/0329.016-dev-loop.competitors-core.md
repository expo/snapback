## 1. Zero-to-running loop

**Commands (React/Vite quickstart)** [VERIFIED: fetched, https://docs.convex.dev/quickstart/react]:

```bash
npm create vite@latest my-app -- --template react-ts
cd my-app && npm install convex
npx convex dev            # login (GitHub), create project, write .env.local, create convex/, keep syncing
npx convex import --table tasks sampleData.jsonl   # optional seed
npm run dev
```

Or the scaffolder: `npm create convex@latest my-app -- -t <template>` with templates `bare`, `nextjs-shadcn`, `nextjs-clerk`, `nextjs-convexauth-shadcn`, `nextjs-lucia-shadcn`, `react-vite-clerk-shadcn`, `react-vite-shadcn`; any GitHub repo can be a template (`-t owner/repo#branch`) [VERIFIED: fetched, npm README of create-convex 0.0.47]. The Convex Auth docs say the "new project" path is `npm create convex@latest` → pick React (Vite) + Convex Auth [VERIFIED: fetched, https://docs.convex.dev/auth/convex-auth].

**Concepts/files an agent must know** [VERIFIED: fetched, quickstart + https://docs.convex.dev/generated-api/ + https://docs.convex.dev/understanding/workflow]:
- `convex/schema.ts` — `defineSchema({ tasks: defineTable({ text: v.string(), isCompleted: v.boolean() }) })`. Schema is optional but drives `Doc<>`/`Id<>` types.
- `convex/*.ts` — file-based routing: `export const get = query({ args: {}, handler: async (ctx) => ctx.db.query("tasks").collect() })` in `convex/tasks.ts` becomes `api.tasks.get`.
- `convex/_generated/` — `api.js/api.d.ts` (the `api`/`internal` function-reference objects), `dataModel.d.ts` (`Doc`, `Id`, `DataModel`), `server.js/server.d.ts` (`query`, `mutation`, `action`, `internalQuery`…, `QueryCtx`/`MutationCtx`/`ActionCtx`). Regenerated by `npx convex dev` or `npx convex codegen`. As of 1.34 (2026-03-19) `npx convex ai-files install` also drops `convex/_generated/ai/guidelines.md` [VERIFIED: fetched, https://docs.convex.dev/ai].
- `.env.local` — `CONVEX_DEPLOYMENT=dev:...` plus `VITE_CONVEX_URL` / `EXPO_PUBLIC_CONVEX_URL` / `NEXT_PUBLIC_CONVEX_URL`; written automatically on first `npx convex dev` [VERIFIED: fetched, workflow page].
- `convex.json` — optional; only needed to relocate the `convex/` dir (surfaced in a monorepo bug, https://github.com/get-convex/convex-backend/issues/423) [VERIFIED: fetched].
- Client: `new ConvexReactClient(url)` + `<ConvexProvider>`; `useQuery(api.tasks.get)` returns `undefined` while loading, then live-updates.

**Local dev server** [VERIFIED: fetched, https://docs.convex.dev/cli/local-deployments; https://docs.convex.dev/cli/agent-mode; convex-js CHANGELOG]:
- "the local Convex backend runs as a subprocess of the `npx convex dev` command and exits when that command is stopped"; state lives in `./.convex/` (moved from `~/.convex` in 1.34.0, 2026-03-19). Anonymous, no-account development is supported; `npx convex login` later links it.
- Timeline: 1.23.0 (2025-04-04) "running Convex locally without an account"; 1.25.4 (2025-07-14) experimental `CONVEX_AGENT_MODE=anonymous`; 1.35.0 (2026-04-10) the CLI "defaults non-interactive commands to target an anonymous deployment if one is not configured"; 1.40.0 (2026-06-01) "Removed --local and --cloud flags from npx convex dev" in favor of `npx convex deployment select local`; 1.45.0 (2026-08-21) local deployments upgrade in place instead of snapshot export/import [VERIFIED: fetched, https://github.com/get-convex/convex-js/blob/main/CHANGELOG.md + npm dates].
- Caveats documented: no public URL for webhooks, Node actions need the exact configured Node version, logs are cleared on restart, Safari/Brave incompatibilities. The most-commented open issue on convex-backend is "Local dev server fails to start" (#96, 34 comments, May 2025: "Local backend did not start on port 3210 within 10 seconds… I wish there was an error output saying what's up"; maintainers pointed at an undocumented `CONVEX_TRACE_FILE=1`) [VERIFIED: fetched via GitHub API].
- Self-hosting is a separate path: `docker compose up`, `docker compose exec backend ./generate_admin_key.sh`, then `CONVEX_SELF_HOSTED_URL=http://127.0.0.1:3210` + `CONVEX_SELF_HOSTED_ADMIN_KEY` in `.env.local`; dashboard on :6791; SQLite default, Postgres/MySQL optional; prebuilt `./convex-local-backend` binary from releases [VERIFIED: fetched, https://raw.githubusercontent.com/get-convex/convex-backend/main/self-hosted/README.md].

**Hot reload**: `npx convex dev` "watches the local filesystem. When you change a function or the schema, the new versions are pushed to your dev deployment" and regenerates types; flags `--once`, `--until-success`, `--run <fn>`, `--run-sh`, `--typecheck <enabled|try|disable>`, `--typecheck-components`, `--codegen <enabled|disable>`, `--configure <new|existing>`, `--team`, `--project`, `--dev-deployment <cloud|local>`, `--tail-logs`, `--debug-node-apis` [VERIFIED: fetched, https://docs.convex.dev/cli].

**Minimal "todo with auth + live list + one mutation"** [INFERRED from the above + auth pages]: schema (1 file, with `...authTables` spread if Convex Auth), `convex/todos.ts` with one `query` + one `mutation` (each with `args` validators and `ctx.auth.getUserIdentity()` / `getAuthUserId(ctx)`), `convex/auth.config.ts`, `convex/auth.ts`, `convex/http.ts`, three deployment env vars (`JWT_PRIVATE_KEY`, `JWKS`, `SITE_URL`), `ConvexAuthProvider` on the client, then `useQuery`/`useMutation`. With Clerk instead: `auth.config.ts` pointing at the Clerk JWT issuer + `ConvexProviderWithClerk`. Realtime needs zero extra steps.

## 2. Feedback surfaces

**Where errors surface** [VERIFIED: fetched, https://docs.convex.dev/database/schemas; https://docs.convex.dev/cli; https://docs.convex.dev/error]:
- *Author time*: TypeScript via generated types (`Id<"users">`, `Doc<>`, typed `withIndex` field order — "The TypeScript types within `withIndex` will guide you through this"), plus `@convex-dev/eslint-plugin` 4.0.0 (2026-08-14) with rules `no-old-registered-function-syntax`, `require-argument-validators`, `explicit-table-ids`, `no-filter-in-query`, `no-collect-in-query`, `no-top-of-hour-crons`, `no-schema-import-cycle`, `import-wrong-runtime` [VERIFIED: fetched, https://docs.convex.dev/eslint; ship.convex.dev].
- *Push time*: `npx convex dev` typechecks (default on) and "The first push after a schema is added or modified will validate that all existing documents match the schema… the push will fail" if any document violates it; `schemaValidation: false` opts out. New indexes backfill on push and can block ("declare it staged… to backfill asynchronously") [VERIFIED: fetched, schemas + indexes pages + guidelines line 192].
- *Runtime*: `ConvexError` carries a `data` payload (string or object) to the client; non-`ConvexError` exceptions are redacted in prod (dev deployments "send server logs to clients") [VERIFIED: fetched, https://docs.convex.dev/functions/error-handling/application-errors; preview-deployments page]. The `/error` reference documents the OCC message verbatim — "Documents read from or written to the table [name] changed while this mutation was being run and on every subsequent retry" — and the "undefined validator" error caused by circular imports (schema.ts importing a file that imports schema.ts).
- Limits that produce runtime errors [VERIFIED: fetched, https://docs.convex.dev/production/state/limits]: 16 MiB read / 16 MiB written, 32,000 documents scanned, 16,000 written, 4,096 index ranges per transaction; 1 s for queries/mutations; 1 MiB per document; 32 indexes/table, 16 fields/index. (Older deployments reported "Too many bytes read in a single function execution (limit: 8388608 bytes)" — https://github.com/adrianhajdin/podcastr/issues/4 [SEARCH-SNIPPET-ONLY] — so the 8 MiB/16k figures in your brief are the previous generation of limits.)

**Dashboard** (dashboard.convex.dev; `npx convex dashboard`) [VERIFIED: fetched, https://docs.convex.dev/dashboard/deployments/{health,functions,logs,data}]:
- Health: failure rate, cache hit rate, scheduler lag, last deploy, and **Insights** flagging functions "exceeding transaction byte limits", "retrieving excessive documents", and write conflicts (OCC). The same data is an MCP tool (`insights`, added 1.32.0) and CLI (`npx convex insights`).
- Functions: function runner (Ctrl+`) runs queries/mutations/actions with args, "custom test queries" of arbitrary JS, and **"Act as a user"** to mock an identity; per-function invocations/errors/cache-hit/p50–p99 charts.
- Logs: per-execution time, request ID, status, duration, `console.*` output, exceptions; filters by function/status/level; "a short history" only (use log streams for retention). CLI: `npx convex logs [--prod]`; `npx convex dev --tail-logs`.
- Data: table browser, filters, inline edit, bulk edit/delete, "Create Table", schema panel with "saved and generated schemas".

**"What broke" for an agent** [INFERRED]: three separate channels — tsc output in the `convex dev` process, the push result (schema/index validation), and runtime logs (dashboard/`npx convex logs`/MCP `logs`). The Claude Code plugin's hooks exist precisely to stitch these back into the agent's turn (see §3).

## 3. Agent-specific investments

**Docs hub**: https://docs.convex.dev/ai lists rules files, per-editor plugin pages (Claude Code, Codex, Cursor, Copilot, Conductor), `cli/agent-mode`, the MCP server, Agent Skills, and the evals repo [VERIFIED: fetched].

**`npx convex ai-files {install,update,status,disable,enable,remove}`** (1.34.0, 2026-03-19): creates/maintains "a managed section in your project's `AGENTS.md`" (CLAUDE.md likewise), installs `convex/_generated/ai/guidelines.md`, and installs skills into `.agents/skills/` using vercel-labs/skills under the hood. First-week bug: it "installs the skills for every coding agent, even though I only use 2" (#423, closed) [VERIFIED: fetched, https://docs.convex.dev/ai/using-codex; GitHub API].

**Rules/guidelines**: `https://convex.link/convex_rules.txt` → latest release asset of get-convex/convex-evals (v0.389.0 at fetch time); `.mdc` variant for Cursor in `.cursor/rules`; "shipped into every `npm create convex` template" [VERIFIED: fetched, https://docs.convex.dev/ai/using-cursor; SEARCH-SNIPPET for the template claim]. Structure: Function guidelines (HTTP, validators table, registration, calling, references, pagination), Schema, Authentication, TypeScript, Full-text/Vector search, Components, Query/Mutation/Action, Scheduling/Cron, Testing, File storage [VERIFIED: fetched].

**Agent Skills** (`npx skills add get-convex/agent-skills [--all]`, into `.agents/skills/`): `/convex` (router), `/convex-quickstart`, `/convex-setup-auth`, `/convex-migration-helper`, `/convex-create-component`, `/convex-performance-audit`; invoked as `/skill` in Cursor/VS Code/Claude Code, `@skill` in Windsurf, `$skill` in Codex [VERIFIED: fetched, https://docs.convex.dev/ai/agent-skills; https://github.com/get-convex/agent-skills].

**Claude Code plugin**: `/plugin install convex@claude-plugins-official`; bundles (1) MCP tools "to securely interact with your dev deployment", (2) "Hooks & Monitors" that "keep your generated types in sync and surface errors as the agent works" — a Stack walkthrough confirms a hook that runs "after every tool use, type-checking automatically whenever the model writes or edits code" — and (3) skills + a `convex-expert` subagent "grounded in Convex's own guidelines rather than general training knowledge" that "got invoked constantly" [VERIFIED: fetched, https://docs.convex.dev/ai/using-claude-code; https://stack.convex.dev/exploring-the-new-convex-claude-code-plugin]. The sibling Cursor plugin repo (get-convex/convex-agent-plugins) shows the mechanics: 18 always-on rules (~100 KB — open issue #19 "Reduce Convex plugin rule token usage… Huge blocker"), 6 skills, `convex-advisor` + `convex-reviewer` agents, a `beforeShellExecution` pre-commit hook that **blocks commits containing `Date.now()` inside queries or chained `.filter()`**, and a `stop` hook that re-prompts if `tsc` fails (max 2 retries) [VERIFIED: fetched, https://github.com/get-convex/convex-agent-plugins].

**MCP server** (`npx -y convex@latest mcp start`, since 1.19.5 2025-03-04; stateless protocol in 1.45.0) [VERIFIED: fetched, https://docs.convex.dev/ai/convex-mcp-server; https://stack.convex.dev/convex-mcp-server]. Tools: `status` (returns an opaque deployment selector), `tables`, `data` (paginate documents), `runOneoffQuery` (sandboxed read-only JS — "Convex queries are fully sandboxed and can't write to the database, so it's safe to let the agent go wild!"), `functionSpec`, `run`, `logs`, `insights`, `envList/envGet/envSet/envRemove`. Flags: `--project-dir`, `--disable-tools data,run,envSet`, `--prod --dangerously-enable-production-deployments`, `--preview-name`. Design choice: string args and a global config "to maximize compatibility across AI agents". Known rough edges: no MCP annotations distinguishing reads from destructive tools (#424, Mar 2026, partly disputed); an invalid selector yields `"The string to be decoded is not correctly encoded."` which "LLM agents misdiagnose and escalate in unproductive directions" (#540, filed 2026-08-28) [VERIFIED: fetched, GitHub API].

**CLI Agent Mode** [VERIFIED: fetched, https://docs.convex.dev/cli/agent-mode]: activates automatically in non-interactive shells — "`npx convex` will never prompt the agent to log in"; with no `CONVEX_DEPLOY_KEY` it "defaults to provisioning a local deployment automatically". Ephemeral recipe: `npm i && npx convex dev --once`. Persistent per-agent cloud deployment:
```bash
npx convex deployment create --type dev --select team:project:dev/$USER/$(basename "$PWD") --expiration "in 5 days"
npx convex deployment token create agent-token --save-env   # writes CONVEX_DEPLOY_KEY to .env.local, scoped to that deployment
```
Related: `npx convex function-spec` (1.15.0) dumps name/type/validators/visibility; `CONVEX_AGENT_MODE=anonymous` works even when logged in (1.33.0); scoped dev tokens shipped 2026-08-13 ("#315 Scoped authorization tokens to prevent agent risk") [VERIFIED: fetched, ship.convex.dev; CHANGELOG].

**llms.txt**: https://docs.convex.dev/llms.txt is an index (31 sections, ~300 links; first line points to https://www.convex.dev/llms.txt for general info); no `llms-full.txt` observed [VERIFIED: fetched].

**Evals** (get-convex/convex-evals, `bun run evals`; 8 categories fundamentals/data modeling/queries/mutations/actions/idioms/clients/components; guidelines built by `bun run build:release`) [VERIFIED: fetched]. Published numbers: guidelines "increase the success rate… by about 20%" (Stack evals post, ~2025); later with 66 evals and ~6,000-token guidelines, Opus scored ~6% lower without them and Gemini 2.5 Pro ~2.7% lower; "actions" remained the weakest category; author leaned toward keeping guidelines [VERIFIED: fetched, https://stack.convex.dev/convex-evals; https://stack.convex.dev/ai-convex-guidelines]. The public leaderboard (https://www.convex.dev/llm-leaderboard/with-guidelines) is client-rendered; I could not extract numbers [VERIFIED: fetched, no data].

**One-shot Postgres-vs-Convex experiment** (https://www.convex.dev/ai; https://github.com/get-convex/one-shot-evals): agents (Opus 4.8, Fable, GPT-5.6-Sol, GPT-5.6-Terra) built 10 apps; "9 out of 10 apps silently corrupted data on Postgres. None of them did on Convex"; at 256 concurrent actors 72% of Postgres writes vanished vs 100% correct on Convex. Caveat acknowledged: "strong agents write" guarded `SELECT … FOR UPDATE` [VERIFIED: fetched].

**Claude Code vs Codex benchmark** (~June 2026): same PM app on Convex/Supabase/Firebase; on Convex both scored 40/40 functional with security B (Claude 27 min/$6.49, Codex ~17 min/$9.56); Supabase 40/40 but security C; Firebase timed out / 34/40 with D [VERIFIED: fetched, https://stack.convex.dev/codex-vs-claude-code].

**Chef** (chef.convex.dev; announced 2025-04-10 by CEO Jamie Turner; OSS 2025-09-17, fork of bolt.diy) [VERIFIED: fetched, https://news.convex.dev/meet-chef/; https://news.convex.dev/open-kitchen-chef-is-now-oss/]. Lessons post: type safety is "a good heuristic for correctness"; the loop is write/edit/view tools + `npx convex dev` typecheck + deploy errors; the LLM "repeatedly edited protected authentication files despite instructions not to", fixed by **programmatically refusing to persist edits** to those files; principles: good abstractions, constrain wrong decisions, correct examples, evals [VERIFIED: fetched, https://stack.convex.dev/lessons-from-building-an-ai-app-builder].

**Distinguish**: `@convex-dev/agent` is a runtime component for building LLM agents *inside* a Convex app (threads, messages, tools, RAG, workflows, playground) — not agent-developer tooling [VERIFIED: fetched, https://docs.convex.dev/agents]. `convex-helpers` adds customFunctions, zod validators, RLS, triggers, rate limits, migrations, `ConvexTestingHelper`, and `npx convex-helpers ts-api-spec` / `open-api-spec` generators; the repo ships its own `.agents/skills` [VERIFIED: fetched, https://github.com/get-convex/convex-helpers].

## 4. Testing & verification

- **convex-test** [VERIFIED: fetched, https://docs.convex.dev/testing/convex-test]: `npm i -D convex-test vitest @edge-runtime/vm`; `environment: "edge-runtime"`; `const t = convexTest(schema, import.meta.glob("./**/*.ts"))`; `t.query/mutation/action`, `t.run(ctx => …)` for raw db setup, `t.withIdentity({name:"Sarah"})`, `vi.useFakeTimers()` + `t.finishInProgressScheduledFunctions()` / `t.finishAllScheduledFunctions(vi.runAllTimers)`. Explicit non-simulation: "it doesn't have many of the behaviors of the real Convex backend" — no crons, no size/time limits, no search ranking, ID format differs, error messages differ, Edge Runtime ≠ Convex runtime ("always test new code manually to make sure it doesn't use built-ins not available in the Convex runtime"). Open issues: pnpm glob path (#48), `AsyncLocalStorage` breaks browser test envs (#122) [VERIFIED: fetched, GitHub API].
- **Real local backend** [VERIFIED: fetched, https://docs.convex.dev/testing/convex-backend; https://stack.convex.dev/testing-with-local-oss-backend]: "Limits on argument, data, query sizes are enforced"; recipe uses `just run-local-backend`, `ConvexTestingHelper` from `convex-helpers/testing`, a `clearAll` testing mutation gated by `IS_TEST`, `maxWorkers: 1`; "there's no built in way to run a scheduled function for testing or to mock out time".
- **Headless driving** [VERIFIED: fetched, CLI page]: `npx convex dev --once [--typecheck enabled]` (push + typecheck, exit), `npx convex run module:fn '{"a":1}' [--push] [--watch] [--inline-query]`, `npx convex import --table t file.jsonl`, `npx convex export --path out.zip [--include-file-storage]`, `npx convex data --limit`, `npx convex logs`, `npx convex env set K V`. CI docs are just `npm ci && npm run test` [VERIFIED: fetched, https://docs.convex.dev/testing/ci]. Combined with Agent Mode this is a fully headless loop [INFERRED].

## 5. Auth / realtime / files / offline

- **Convex Auth** (`@convex-dev/auth`, still 0.0.x and labelled "beta… may change in backward-incompatible ways"; "Convex auth v2" is on the In-Progress roadmap) [VERIFIED: fetched, https://docs.convex.dev/auth; ship.convex.dev]. Steps: `npm install @convex-dev/auth @auth/core@0.41.1` → `npx @convex-dev/auth` wizard → `...authTables` in schema → `ConvexAuthProvider`; the manual guide is 7 steps (generate `JWT_PRIVATE_KEY`/`JWKS` with `node generateKeys.mjs`, set `SITE_URL`, edit tsconfig `moduleResolution: "Bundler"`, `auth.config.ts`, `auth.ts` with `convexAuth({providers})`, `http.ts` with `auth.addHttpRoutes(http)`) [VERIFIED: fetched, https://labs.convex.dev/auth/setup; /setup/manual]. Alternatives on the auth page: Clerk ("great Next.js and React Native support"), WorkOS AuthKit, Auth0, custom OIDC; plus the Better Auth component (`@convex-dev/better-auth` 0.12.5) [VERIFIED: fetched; SEARCH-SNIPPET for Better Auth version]. Trip evidence: convex-auth #227 "went through the Next.js auth docs twice and it doesn't work… 404 for /api/auth… it'll be Clerk for now" (14 comments, users migrating to Clerk/Better Auth); the Claude-plugin walkthrough also lists "Authentication complexity remains challenging"; Chef's biggest failure mode was the LLM editing auth files [VERIFIED: fetched].
- **Realtime**: built in — `useQuery` is a subscription; "Every query is a live subscription" [VERIFIED: fetched, convex.dev/ai]. Zero extra steps.
- **Files**: 3 steps — mutation `ctx.storage.generateUploadUrl()` → client `POST` file → mutation saves `storageId`; URLs expire in 1 hour; alt single-request HTTP-action upload capped at 20 MB with CORS setup [VERIFIED: fetched, https://docs.convex.dev/file-storage/upload-files]. Guidelines flag `ctx.storage.getMetadata` as deprecated (query `_storage` instead) — a version-drift trap [VERIFIED: fetched].
- **Offline**: none as a product feature. Mutations queue while disconnected and are delivered exactly-once on reconnect; `withOptimisticUpdate` exists but "mutating objects inside of optimistic updates will corrupt the client's internal state"; the 2024-10-21 State of the Union promised to "rethink optimistic updates as more of a 'local store' that works more seamlessly with offline mode" — still not shipped; PowerSync offers an experimental Convex connector [VERIFIED: fetched, https://news.convex.dev/convex-state-of-the-union/; SEARCH-SNIPPET for PowerSync/optimistic docs].
- **Where agents trip (documented)**: `"use node"` — only actions, never in a file with queries/mutations, no cross-runtime imports (`--debug-node-apis` exists to trace this; `import-wrong-runtime` lint; Windows bug #152) [VERIFIED: fetched, https://docs.convex.dev/functions/runtimes]; `ctx.db` unavailable in actions; `Date.now()` in queries breaks cache/reactivity; `.filter()` vs `withIndex`; `.collect()` on unbounded tables; circular schema imports → "undefined validator"; `exactOptionalPropertyTypes` mismatch (#211, 24 comments); "Type instantiation is excessively deep" in monorepos (convex-js #53) [VERIFIED: fetched, GitHub API].

## 6. Deploy

- `npx convex deploy --cmd 'npm run build'` [VERIFIED: fetched, https://docs.convex.dev/production/hosting/vercel; /custom]: reads `CONVEX_DEPLOY_KEY`, sets `VITE_CONVEX_URL` (override with `--cmd-url-env-var-name`), runs the frontend build, then pushes `convex/` (typecheck, codegen, bundle, schema/index push). Flags: `--yes`, `--typecheck`, `--codegen`, `--dry-run`, `--check-build-environment`. Deploy keys are generated in the dashboard with a `deployment:deploy` permission scope.
- **Preview**: `npx convex deploy --preview-create=<name> [--preview-run=<seedFn>]` recreates a fresh deployment each time; auto-named on Vercel/Netlify/Cloudflare/GitHub Actions with a Preview Deploy Key; auto-deleted after 5 days (14 on paid plans) [VERIFIED: fetched, https://docs.convex.dev/production/hosting/preview-deployments].
- **Env vars**: `npx convex env {list,get,set,remove} [--prod] [--from-file]`; typed env is new — declare in `convex.config.ts` `defineApp({ env: {...} })` and read `env` from `_generated/server` (guidelines) [VERIFIED: fetched].
- **Parity**: one project = one prod deployment + per-developer dev deployments (cloud or local) + previews, all running the same code; the OSS backend "supports all the free-tier features" but the cloud is "optimized for scale" [VERIFIED: fetched, workflow page; self-hosted README]. Time-to-first-deploy is not published; the only latency note is index backfill blocking a deploy unless `staged: true` [VERIFIED: fetched].

## 7. Known agent pain points

- **Syntax drift is the #1 documented failure**. Convex's own evals post: models used "outdated Convex syntax (importing `cronJobs` incorrectly)", omitted `"use node"`, mishandled storage `Blob`s, imported from `convex/server` instead of `./_generated/server`, and mistyped storage IDs — attributed to "the knowledge cutoff problem" [VERIFIED: fetched, https://stack.convex.dev/convex-evals]. The old `query(async ({db}) => …)` form is why the lint rule `no-old-registered-function-syntax` and the guideline "ALWAYS include argument validators for all Convex functions" exist [VERIFIED: fetched].
- **The API keeps moving under the guidelines**: 1.31.0 (2025-12-11) changed `db.get/patch/replace/delete` to take the table name first (now enforced by `explicit-table-ids`); 1.41 added `transactionLimits`; 1.44.0 (2026-08-13) added `schema.doc()`/`schema.id()`; `crons.hourly/daily/weekly` are now forbidden ("Only use `crons.interval` or `crons.cron`") [VERIFIED: fetched, CHANGELOG + guidelines]. Every one of these invalidates pretraining knowledge, which is exactly why the guidelines file pins a version.
- **Guideline "never/always" list** (verbatim highlights) [VERIFIED: fetched]: "NEVER accept a `userId`… as a function argument for authorization purposes"; "Do NOT use plain `ConvexProvider` when authentication is needed"; "ALWAYS create [`auth.config.ts`]… Without it, `ctx.auth.getUserIdentity()` will always return `null`"; "Never use `ctx.db` inside of an action"; "Never add `"use node";` to a file that also exports queries or mutations"; "You do NOT need `"use node";` just to use `fetch()`"; "Never use `.collect().length` to count rows"; "Convex queries do NOT support `.delete()`"; "Do not read the wall clock inside a query"; "Do not store unbounded lists as an array field"; "NEVER use `any` for ctx parameters"; "Do NOT add a `compilerOptions.types` allowlist… fails typechecking with TS2688".
- **Context cost**: guidelines ≈ 6,000 tokens; the Cursor plugin's always-on rules ≈ 100 KB ("Huge blocker", #19); the guidelines author floated "shrinking guidelines to minimal viable size or replacing them with retrieval-based documentation indexes" [VERIFIED: fetched].
- **Tooling papercuts**: MCP error text that agents misread (#540), MCP WSL path issues (#303), ai-files over-installing (#423), local backend startup timeouts with no diagnostics (#96), Node-version requirement for local Node actions (#153), TS7 side-by-side typecheck (#177) [VERIFIED: fetched, GitHub API].
- **Community critiques**: HN on "It's not you, it's SQL" (2023): "Man what a well written ad"; "We… want the equivalent of Typescript for SQL"; the everything-must-be-TypeScript premise "would formerly be thought of as pretty ridiculous" [VERIFIED: fetched via Algolia, https://news.ycombinator.com/item?id=34582549]. "How Convex Works" (2024, 96 pts): lock-in/financial-risk questions answered with the OSS backend; a Convex engineer conceded "Auth story isn't as streamlined as for Firebase or Supabase" [VERIFIED: fetched, https://news.ycombinator.com/item?id=40020516]. No high-signal HN thread about LLMs hallucinating Convex APIs surfaced; the complaints live in GitHub issues and Convex's own posts [INFERRED].

## 8. Their thesis

Jamie Turner's "3 Reasons Why AI Agents Love Convex" (~Mar 2026): (1) "Everything is code with end-to-end types" — "When an agent generates something slightly wrong, it gets a type error telling it exactly what to fix"; (2) a reactive backend "enables local reasoning" — change one function without tracking dependents; (3) built-in consistency (OCC + automatic cache invalidation) removes "meta-layer knowledge" about races and caches that "LLMs cannot reliably learn from training data"; therefore "Convex agents punch above their weight" [VERIFIED: fetched, https://stack.convex.dev/why-ai-agents-love-convex]. The Chef launch framed it as the "three Cs: concurrency, consistency, and caching" that LLMs get wrong and Convex's TypeScript APIs "make disappear" [VERIFIED: fetched]. The marketing page sharpens it to a default-correctness claim: "Every mutation runs as one serializable transaction and retries on conflict, so the first thing an agent reaches for just works", versus Postgres being "quietly wrong under load, unless someone knows to add the right lock" [VERIFIED: fetched, convex.dev/ai]. Their systems essay adds "You can't test your way to correctness… good constraints, guardrails, and architecture prevent AI-generated code bloat" [VERIFIED: fetched, https://stack.convex.dev/system-design-principles-ai-agents-do-not-understand].

**What Convex-for-agents-only would look like** [INFERRED from Chef, Agent Mode, plugins, evals, and open issues]: the pieces they have been converging on since 2025 are (a) zero-login, per-agent, expiring deployments minted by one command; (b) a single `--once` command that typechecks, validates schema against live data, pushes, and exits nonzero; (c) hooks that force the typecheck/log loop back into every agent turn and *block* known anti-patterns (`Date.now()` in queries, `.filter()`) rather than advising; (d) programmatic file protection for auth wiring (Chef's lesson); (e) a read-only sandboxed query tool plus `functionSpec` so the agent inspects real state instead of guessing; (f) versioned guidelines regenerated from evals, with the unresolved tension that ~6k tokens of rules still lose ~3–6% on frontier models and cost context. The gaps they have not closed — beta auth with a 7-step manual path, an in-memory test double that admits it does not enforce limits, error strings agents misparse, an API that changes shape every few releases — are the places an agent-first design can differ.

## 5. Auth / realtime / files / offline — step counts and trip-wires

**Auth** [VERIFIED: fetched — server-side/nextjs; config]: local providers/email confirmations in `config.toml`; hosted providers configured in dashboard (drift risk); Next.js needs `@supabase/ssr`, two client factories, a proxy/middleware that calls `getClaims()` and rewrites cookies on both request and response, PKCE callback route. **Realtime** [VERIFIED: fetched — postgres-changes; authorization; troubleshooting]: `alter publication supabase_realtime add table t;` (+ `replica identity full` for old rows; RLS not applied to DELETE); RLS evaluated per subscriber ("100 subscribed users → 100 authorization checks"; Micro ≈ 30 changes/s across 500 clients; >3k subscribers → use Broadcast). Broadcast/Presence auth = RLS policies on `realtime.messages` + `config: { private: true }`. Trip-wires: table not in publication, RLS denies, filter syntax, `CHANNEL_ERROR`, duplicate channels on re-render, subscribe-then-write race. ≈3 steps for basic, 6 for private channels.

**Storage** [VERIFIED: fetched — https://supabase.com/docs/guides/storage/security/access-control]: bucket + RLS on `storage.objects` (`bucket_id = '…'`, `(storage.foldername(name))[1] = (select auth.uid())::text`); "Storage does not allow any uploads to buckets without RLS policies"; upsert needs INSERT+SELECT+UPDATE. ≈3 steps.

## 8. Their thesis, and what an agent-only Supabase would look like

**Thesis** [VERIFIED/SNIPPET — First Round interview 2026-06-25; agent-skills blog; api-keys]: "everything feels like Postgres"; "we don't like lock-in… protocols and open standards"; "code-first, Git-first… infrastructure as code inside your folder so the agent can understand"; LLMs love SQL; every feature (auth, realtime auth, storage auth) is *RLS on a Postgres table*; agents now create most databases, so the roadmap is "everything branchable", "cheap ephemeral test environments", and "self-driving databases" for agents that operate, not just build.

**Inferred agent-first Supabase** [INFERRED from MCP, skills, advisors, pg-delta, branching, RLS Tester, key redesign]:
1. State-as-files: `supabase/schemas/*.sql` (or `supabase/database/` under pg-delta) is the source of truth; `supabase db schema declarative sync --apply --name` generates migrations non-interactively [VERIFIED: fetched — https://supabase.com/changelog/44938-…pg-delta, Apr 16 2026, alpha].
2. Every mutation has a machine-checkable verdict: advisors (`get_advisors`) as a post-write lint; RLS Tester as an oracle; `db lint --fail-on`.
3. No Docker in the inner loop: hosted MCP + cheap branch per task, `reset_branch`/`rebase_branch` as undo.
4. Keys that fail loudly (401 in browser) rather than silently over-privilege.
5. Docs as tools (`search_docs`, `.md` pages), plus a ~100-line skill encoding *workflow* not API surface, because evals showed MCP-only can make the best model worse.
6. Still unsolved for them: silent RLS empty results, author-time SQL errors, type regeneration, and prompt injection through data — the structural gaps a from-scratch agentic design can close.

## 1. Zero-to-running loop

**Exact commands (empty dir → running backend + client)** [VERIFIED: fetched, https://pocketbase.io/docs/ and source]:

```sh
# 1. download the ~11–12 MB zip for your OS/arch from
#    https://github.com/pocketbase/pocketbase/releases and unzip → one binary
./pocketbase serve                       # → http://127.0.0.1:8090  (static pb_public/)
                                         #   http://127.0.0.1:8090/_/   (superuser dashboard)
                                         #   http://127.0.0.1:8090/api/ (REST-ish API)
./pocketbase superuser upsert a@b.c pass # non-interactive; "Creates, or updates if email exists"
./pocketbase migrate create "init"       # blank pb_migrations/<ts>_init.js
./pocketbase migrate collections         # snapshot current collections → migration file
npm i pocketbase                         # JS SDK
```

On first `serve`, the binary prints an installer link to create the first superuser in the browser; `superuser create|upsert|update|delete|otp|ips` are the CLI alternatives (`cmd/superuser.go`, https://github.com/pocketbase/pocketbase/blob/master/cmd/superuser.go) [VERIFIED: fetched]. The startup banner prints `Server started at …`, `REST API: …/api/`, `Dashboard: …/_/` (`apis/serve.go`) [VERIFIED: fetched].

**Files/concepts an agent must hold** [VERIFIED: fetched, https://pocketbase.io/docs/, https://pocketbase.io/docs/js-overview/, `examples/base/main.go`]:
- `pb_data/` — SQLite `data.db` + `auxiliary.db` (logs) + `storage/` + autogenerated `types.d.ts`; gitignore it.
- `pb_migrations/*.js` — JS migrations, safe to commit; `--automigrate` (default `true`) means "every collection configuration change from the Dashboard (or Web API) will generate the related migration file automatically" (https://pocketbase.io/docs/js-migrations/).
- `pb_hooks/*.pb.js` — server-side JS (goja, ES5-ish, CommonJS, "no `setTimeout`/`setInterval`"), loaded in filename sort order.
- `pb_public/` — static files (`--indexFallback` default true for SPAs).
- Concepts: collections (base / auth / view), fields (Bool, Number, Text, Email, URL, Editor, Date, Autodate, Select, File, Relation, JSON, GeoPoint), five API rules (`listRule, viewRule, createRule, updateRule, deleteRule` + `manageRule` on auth collections), hooks, migrations, superusers (https://pocketbase.io/docs/collections/).

**CLI flag surface** (from source, [VERIFIED: fetched] `pocketbase.go`, `cmd/serve.go`, `examples/base/main.go`): global `--dir` (default `./pb_data` next to the executable, or cwd under `go run`), `--dev` ("enable dev mode, aka. printing logs and sql statements to the console"; defaults to `true` under `go run`), `--encryptionEnv`, `--queryTimeout`; `serve --http` (default `127.0.0.1:8090`), `--https`, `--origins`; base build: `--hooksDir`, `--hooksWatch` (default `true`, "auto restart the app on pb_hooks file change; it has no effect on Windows"), `--hooksPool` (15), `--migrationsDir`, `--automigrate` (true), `--publicDir`, `--indexFallback`.

**Hot reload**: pb_hooks changes restart the whole process via `execve` (UNIX only; Windows prints "please restart the app manually") — `plugins/jsvm/jsvm.go` [VERIFIED: fetched]. Migrations run "automatically on `serve` within a transaction" (https://pocketbase.io/docs/js-migrations/) [VERIFIED: fetched]. There is no schema watcher: schema changes flow *from* the dashboard/API *to* migration files, not the reverse, unless you hand-write migrations and restart.

**How types flow to the client**: officially, they don't. The JS SDK is generic-typed by the caller: `pb.collection('tasks').getList<Task>(1, 20)` with a hand-written `interface Task` (https://github.com/pocketbase/js-sdk README) [VERIFIED: fetched]. Dart's `RecordModel` is dynamic (`record.get<T>('field')`) (https://github.com/pocketbase/dart-sdk README) [VERIFIED: fetched]. Community `pocketbase-typegen` reads `pb_data/data.db`, a live URL (superuser creds/token), or exported JSON and emits `XRecord`/`XResponse`/`TypedPocketBase` (https://github.com/patmood/pocketbase-typegen) [VERIFIED: fetched]; `TypedPocketBase` needs SDK ≥0.18.3 [SEARCH-SNIPPET-ONLY]. A 2023 discussion wiring typegen to collection hooks got no commitment from the maintainer to ship official types (https://github.com/pocketbase/pocketbase/discussions/1838) [VERIFIED: fetched]. The *only* first-party type surface is `pb_data/types.d.ts` for hooks, used via `/// <reference path="../pb_data/types.d.ts" />` (https://pocketbase.io/docs/js-overview/) [VERIFIED: fetched]. Go extension is fully typed (README `main.go` example) [VERIFIED: fetched].

**Minimal "todo with auth + live list + one mutation"** [VERIFIED: fetched from the docs pages cited]:
1. `users` auth collection ships built-in; create a `todos` base collection (dashboard, or `POST /api/collections` as superuser, or a migration) with `owner` relation → users.
2. Rules: `listRule`/`viewRule`/`updateRule`/`deleteRule` = `owner = @request.auth.id`; `createRule` = `@request.auth.id != "" && @request.body.owner = @request.auth.id` (https://pocketbase.io/docs/api-rules-and-filters/).
3. Client: `await pb.collection('users').authWithPassword(email, pw)`; `await pb.collection('todos').getFullList()`; `pb.collection('todos').subscribe('*', e => …)` (SSE; events filtered by the collection's ListRule); `await pb.collection('todos').create({ title, owner: pb.authStore.record.id })` (https://pocketbase.io/docs/api-realtime/, https://pocketbase.io/docs/authentication/).

## 5. Auth / realtime / files / offline — steps and trip points

**Auth** [VERIFIED: fetched, https://pocketbase.io/docs/authentication/]: built-in `users` auth collection and `_superusers`; per-collection toggles for Identity/Password, OTP, OAuth2 (15+ providers; not for `_superusers`), MFA (v0.23+, "requires two different auth methods", second call carries `mfaId`). Client: `authWithPassword`, `requestOTP`→`authWithOTP(otpId, code)`, `authWithOAuth2({provider})` (popup/all-in-one), `pb.authStore.{isValid,token,record,clear,onChange}`; tokens are stateless JWTs refreshed via `auth-refresh`. Steps for email/password: ~3 (enable in UI, one SDK call, rule string). OAuth2: add client ID/secret in UI + one call.

**Realtime** [VERIFIED: fetched, https://pocketbase.io/docs/api-realtime/]: SSE. `GET /api/realtime` returns `PB_CONNECT` + client id; `POST /api/realtime` sets subscriptions and (if `Authorization` set) binds the auth. Topics `collection/*` (gated by **ListRule**) or `collection/RECORD_ID` (gated by **ViewRule**); idle clients are disconnected after 5 minutes; view collections emit no events. Custom topics from hooks have *no* automatic auth — "you need to manually take care who can receive the event" via `$app.canAccessRecord` (https://github.com/pocketbase/pocketbase/discussions/6417) [VERIFIED: fetched]. Steps: 1 SDK call, but the rule/topic interaction is where people trip.

**Files** [VERIFIED: fetched, https://pocketbase.io/docs/files-handling/]: `file` field on a record; upload via `multipart/form-data` (`pb.collection('x').create(formData)`; `"documents+"` appends, `"documents-"` removes); URL `pb.files.getURL(record, name, {thumb:'100x250'})`; protected fields require `pb.files.getToken()` and `?token=`; storage `pb_data/storage` or S3 via Settings. ~2 steps.

**Offline**: none — no client cache, no queue, no conflict handling (README/docs mention nothing; the JS SDK's only persistence is the auth store) [VERIFIED: fetched, absence].

**Where agents trip (documented)**:
- The v0.23 break (2024-11-24): "This release introduces many Go/JSVM and Web APIs breaking changes! Existing `pb_data` will be automatically upgraded … but custom Go or JSVM (`pb_hooks`, `pb_migrations`) and JS/Dart SDK code will have to be migrated manually." (https://github.com/pocketbase/pocketbase/releases/tag/v0.23.0). JSVM rename table (https://pocketbase.io/v023upgrade/jsvm/): `$app.dao().saveRecord(r)`→`$app.save(r)`, `$app.dao().findRecordById`→`$app.findRecordById`, `onModelBeforeCreate`→`onRecordCreate` (must call `e.next()`), `onModelAfterCreate`→`onRecordAfterCreateSuccess`, `onRecordBeforeCreateRequest`/`onRecordAfterCreateRequest`→ single `onRecordCreateRequest` with `e.next()` placement deciding before/after, `onAdminsListRequest`→`onRecordsListRequest("_superusers")`, route params `:id`→`{id}`, `c.pathParam`→`e.request.pathValue`, `$apis.requireAdminAuth`→`$apis.requireSuperuserAuth`, `$apis.staticDirectoryHandler`→`$apis.static`, and initialism churn `%Json%`→`%JSON%`, `%Url%`→`%URL%` [VERIFIED: fetched]. JS SDK 0.22.0: `pb.admins`→`pb.collection("_superusers")`, `authStore.model`→`authStore.record`, `getFileUrl`/`*Url()`→`files.getURL`/`*URL()`, `CollectionModel.schema`→`fields`, `SchemaField`→`CollectionField` (https://github.com/pocketbase/js-sdk/blob/master/CHANGELOG.md) [VERIFIED: fetched]. Symptom in the wild: `pb.admins.authWithPassword()` returning 404 "File not found" (https://github.com/pocketbase/pocketbase/discussions/5822) [VERIFIED: fetched].
- Filter injection: interpolating user input into `filter:` strings is unsafe; `pb.filter("title ~ {:title}", {title})` escapes — "recommended when using the SDK in Node/Deno/Bun server-side list queries … accepting untrusted user input" (js-sdk README) [VERIFIED: fetched].
- Relation filtering was tightened twice: v0.31 "Disallow client-side filtering and sorting of relations where the collection of the last targeted relation field has superusers-only List/Search API rule"; v0.32 "extra List/Search API rules checks for the client-side `filter`/`sort` relations" — locked junction collections silently stop working through `expand`/filter (CHANGELOG_23_39.md) [VERIFIED: fetched]. Expand only returns relations "the request client can View", up to 6 levels; back-relations `comments_via_post` resolve as *multiple* unless a UNIQUE index exists (https://pocketbase.io/docs/working-with-relations/) [VERIFIED: fetched].
- All dates must be `Y-m-d H:i:s.uZ` in filters (https://pocketbase.io/docs/collections/) [VERIFIED: fetched].

## 6. Deploy

**Commands** [VERIFIED: fetched, https://pocketbase.io/docs/going-to-production/]: scp the binary + `pb_data`, `pb_hooks`, `pb_migrations` to a VPS; systemd unit with `ExecStart = /root/pb/pocketbase serve yourdomain.com` — passing a domain flips defaults to `0.0.0.0:80/443` and issues Let's Encrypt certs automatically (`cmd/serve.go` help text) [VERIFIED: fetched]. No official Docker image; docs give a minimal Dockerfile and say to mount a volume at `/pb/pb_data`. **Time to first deploy**: minutes on a VPS you already have (copy + systemd + DNS) [INFERRED from the doc]. **Preview environments**: none built in; a preview is "another copy of the binary with another `pb_data`" [INFERRED]. **Secrets**: settings (SMTP, S3, OAuth secrets) live in the DB and are encrypted only if you start with `--encryptionEnv=PB_ENCRYPTION_KEY` and "set a random 32 characters string as its value"; `GOMEMLIMIT=512MiB` recommended on small boxes [VERIFIED: fetched]. **Parity**: identical binary locally and in prod; migrations move schema; `Settings > Backups` zips `pb_data` (optionally to S3) — for 5 GB+ "consider a different backup strategy" [VERIFIED: fetched].

## 8. Their thesis — and what an agent-first PocketBase would be

**Thesis, in their words** [VERIFIED: fetched]: "Open Source realtime backend in 1 file" (repo description). "PocketBase was created to assist building self-contained applications that can run on a single server without requiring to install anything in addition … the common functionality like crud, auth, files upload, auto TLS, etc. are handled out of the box, allowing you to focus on the UI and your actual app business requirements." (https://pocketbase.io/faq). Embedded SQLite in WAL mode because "for the majority of the queries SQLite (in WAL mode) outperforms traditional databases like MySQL, MariaDB or PostgreSQL"; no cloud functions — "PocketBase could be used as a Go or JS framework"; scope is "intentionally limited"; once stable, the maintainer intends to "mark the project as 'complete'" (https://github.com/pocketbase/pocketbase/discussions/7287). The model is optimized for one human with a browser: dashboard-first schema editing, rules as strings typed into a text box, and a portable binary you scp.

**What is genuinely right for agents** [INFERRED]: one binary with zero external services means the agent's local loop *is* the production loop; a full superuser REST surface (`/api/collections`, `/api/collections/import`, `/api/batch`, `/api/logs`) means everything the dashboard does is scriptable; rules-as-filter-strings give a tiny, declarative authorization language; migrations are auto-generated so the agent never has to author schema DDL by hand; `types.d.ts` for hooks is auto-emitted.

**Where it is wrong for agents** [INFERRED]: the intended authoring path (click in the UI, let `--automigrate` write files) is backwards for an agent, which wants schema-as-code first and the UI as a read-only viewer; there is no typed client contract, so every collection is `any` unless a third-party typegen runs; rule failures degrade silently; the hook surface (goja ES5, restart-to-reload, no test harness, renamed twice) is exactly the surface LLMs get wrong; the project's own stance is hostile to AI-only use and refuses upstream agent tooling.

**PocketBase re-designed purely for agents** [INFERRED]: (1) `pb_schema.ts` as the single source of truth — collections, fields, rules, indexes in a typed DSL, with the dashboard demoted to a viewer and `migrate collections` running the other way (schema file → migration diff → apply, exit non-zero on conflict); (2) generated client types + generated typed hook signatures from that same file, shipped in the binary (no `pocketbase-typegen`); (3) rules as a checked language with a `pocketbase rules check` command that prints, per rule, the compiled SQL and a table of "who can do what" for sample principals, and an opt-in "strict" mode that returns 403 instead of 200-empty; (4) a first-party `pocketbase mcp` subcommand and `llms.txt`/single-file docs pinned to the binary's version so the agent reads docs that match the running server; (5) a hooks test runner (`pocketbase test`) that boots an in-memory app from `test_pb_data` and runs `ApiScenario`-style JSON cases against JS hooks, with `ExpectedEvents`; (6) `--dev` as structured JSON logs (request, rule evaluated, SQL, hook chain) rather than colored text; (7) stable, versioned API names with deprecation shims that *log a machine-readable warning* rather than 404 — the `pb.admins` alias in SDK 0.22 shows they already know how.

## 1. Zero-to-running loop

**Commands, empty dir → running backend + client** [VERIFIED: fetched — https://instantdb.com/docs.md, https://instantdb.com/docs/create-instant-app.md, https://instantdb.com/docs/cli.md, https://instantdb.com/docs/workflow.md]

```bash
npx instant-cli@latest login            # browser OAuth; `login -p` prints token for CI
npx create-instant-app my-app --next    # or --vite-react, Expo, vanilla TS; `--ai` prompts "describe the app"
# — or manual —
npm i @instantdb/react
npx instant-cli@latest init             # picks/creates app id; writes instant.schema.ts + instant.perms.ts (+ instant.email.ts optional)
npx instant-cli@latest push             # push schema (+ perms)
npm run dev                             # localhost:3000; the backend is hosted — nothing to start
```
`init --temp` creates an ephemeral app that auto-deletes after 24h; `init-without-files --title X` creates an app with no files (the skill uses this) [VERIFIED: fetched — cli.md, https://raw.githubusercontent.com/instantdb/skills/main/skills/instantdb/SKILL.md].

**Files/concepts** [VERIFIED: fetched — https://instantdb.com/docs/init.md, https://instantdb.com/docs/modeling-data.md, https://instantdb.com/docs/permissions.md]: exactly three authored artifacts —
- `instant.schema.ts` — `i.schema({ entities: { todos: i.entity({ text: i.string(), done: i.boolean() }) }, links: { postAuthor: { forward: { on:'posts', has:'one', label:'author' }, reverse: { on:'profiles', has:'many', label:'authoredPosts' } } }, rooms: {...} })`; attrs `i.string()|number()|boolean()|date()|json()|any()`, `.optional()`, `.unique()`, `.indexed()`; built-ins `$users`, `$files`.
- `instant.perms.ts` — CEL rules `{ todos: { allow: { view: "auth.id != null", create: "isOwner" }, bind: { isOwner: "auth.id == data.ownerId" } } } satisfies InstantRules`.
- `lib/db.ts` — `export const db = init({ appId, schema })`; env `NEXT_PUBLIC_INSTANT_APP_ID` / `VITE_INSTANT_APP_ID` / `INSTANT_APP_ID`.
Then in components: `db.useQuery({ todos: {} })` and `db.transact(db.tx.todos[id()].create({...}))`.

**Local dev server: none in the ordinary loop.** The backend is hosted; the SDK accepts `apiURI`/`websocketURI` for self-hosted instances, and self-hosting (Clojure server + Postgres, Docker, `JAVA_OPTS`) is documented as a production deployment (VPS ~$30/mo, AWS ~$600/mo+) rather than a dev/CI loop [VERIFIED: fetched — init.md, https://instantdb.com/docs/self-hosting.md]. The 24h `--temp` app and the 2-week temporary apps of the Platform SDK are the substitute for "local" [VERIFIED: fetched — cli.md, https://instantdb.com/docs/platform-api.md].

**Hot reload of schema**: two modes. (a) Schemaless by default — "new entities and attributes are created automatically when transactions reference undefined structures"; lock it with `attrs: { allow: { $default: 'false' } }` in perms before production [VERIFIED: fetched — modeling-data.md]. (b) Schema-as-code — edit `instant.schema.ts`, `push schema` shows a plan and asks "Is posts.creator created or renamed?"; CI passes `--rename old:new --yes`. **Modifications and deletions of attributes must be done in the dashboard Explorer, not the CLI** [VERIFIED: fetched — modeling-data.md, cli.md]. There are no server functions to reload (see §5).

**Type flow: pure inference, no codegen step.** `init({ schema })` types `useQuery`/`transact`; helper types `InstaQLParams<AppSchema>`, `InstaQLResult<AppSchema, Q>`, `InstaQLEntity<AppSchema,'todos'>` [VERIFIED: fetched — https://instantdb.com/docs/instaql.md].

**Minimal "todo with auth + live list + one mutation"** [VERIFIED: fetched — https://instantdb.com/docs/auth/magic-codes.md, instaql.md, instaml.md; count INFERRED]: schema (1 entity), perms (`view/create/update/delete: "auth.id != null && auth.id == data.ownerId"`), `push`, then in one component: `db.auth.sendMagicCode({email})` → `db.auth.signInWithMagicCode({email, code})`, `<db.SignedIn>/<db.SignedOut>` or `db.useAuth()` → `{isLoading,user,error}`, `db.useQuery({ todos: { $: { where: { ownerId: user.id } } } })` (live by default), `db.transact(db.tx.todos[id()].create({ text, done:false, ownerId: user.id }))`. ≈ 3 files, 3 commands, ~40 lines. No realtime setup at all: every `useQuery` is a subscription.

## 5. Auth / realtime / files / offline

(#7), "Bug: Permission file is lost" (#891, Feb 2025), "permission browser tool" request (#1658, open Sep 2025) [VERIFIED: fetched — common-mistakes.md, SKILL.md, modeling-data.md, GitHub issues listing].

## 8. Their thesis, and what an agent-only Instant would look like

**Thesis** [VERIFIED: fetched — README, next_firebase, db_browser]: "most of the schleps we face as UI engineers are actually database problems in disguise"; delightful apps (Figma/Linear/Notion) need optimistic updates + multiplayer + offline, and "Firebase's query strength… limited to document lookups", Firebase rules "get unmaintainable fast", while Supabase/Hasura "[n]either support offline-mode or optimistic updates"; so: a graph (triple-store) database in the browser, Datalog underneath, InstaQL (GraphQL-ish) on top, CEL permissions as "the only backend code you write", server as single leader with last-write-wins.

**Agent-only Instant** [INFERRED from §3 + Platform SDK]: the backend *is* two files (`schema`, `perms`) plus a hosted sync engine; the agent-facing surface is `learn` → `get-schema/get-perms` → edit → `push-*` → `query --as-*` to verify, with temp apps as disposable environments. ## 2. Feedback surfaces

- **Firestore permission denied is opaque in production** ("Missing or insufficient permissions", no reason) — the fix is local: the Emulator UI "Requests" monitor shows per-request rules evaluation with the allowing/denying line, `debug()` in rules, and a rules **coverage report** [VERIFIED: fetched — rules/emulator-setup; https://firebase.google.com/docs/rules/unit-tests].
- **Missing composite index** errors "include a direct link to create the missing index in the Firebase console" (pre-filled form) — the best "what broke → fix it" affordance in the group, but the emulator "does not track compound indexes and instead will execute any valid query", so the error appears only in production [VERIFIED: fetched — https://firebase.google.com/docs/firestore/query-data/indexing, https://firebase.google.com/docs/emulator-suite/connect_firestore].
- **Emulator fidelity gaps** (documented): no index enforcement; "does not currently implement all transaction behavior seen in production"; may allow transactions "too large" for prod; clears data on shutdown unless `--export-on-exit`; REST `DELETE /emulator/v1/projects/{id}/databases/(default)/documents` wipes data [VERIFIED: fetched — connect_firestore].
- **Functions**: `HttpsError('unauthenticated'|'permission-denied'|…)` typed codes; logs via `firebase functions:log` / Cloud Logging / MCP `functions_get_logs`; params (`defineString/defineSecret`) are "validated at deploy time" and block deploy when missing [VERIFIED: fetched — config-env, mcp-server].
- **SQL Connect**: GraphQL validation in the VS Code extension/emulator; `dataconnect_build` MCP tool compiles schema/connectors [VERIFIED: fetched — mcp-server page].
- **Dashboards**: Firebase console (+ "Gemini in Firebase" assistant), Emulator UI at :4000, Genkit Developer UI (`genkit start -- <cmd>`: flows, traces, prompts, evaluators) [VERIFIED: fetched — https://firebase.google.com/docs/ai-assistance, https://genkit.dev/docs/devtools/].
- **When errors surface**: rules — syntax at emulator load/deploy, semantics only at runtime (or in unit tests); Firestore data — never (schemaless); indexes — production runtime; Functions — TS compile + deploy-time param validation; SQL Connect — author-time in extension [INFERRED from the above].

## 8. Their thesis, and what an agent-only Firebase would look like

**Thesis** [VERIFIED: fetched — emulator-suite, ai-assistance, studio, sql-connect]: client-first — the app talks to the database directly and Security Rules *are* the backend; offline sync and Google-scale ops; and since 2025 "an agentic full-stack platform": MCP (50+ tools, prompts that generate rules *with unit tests*, `validate_security_rules`), skills (incl. a rules **auditor**), AI Studio prompt→app with default-deny rules, SQL Connect for typed relational data, Genkit for AI flows with evals.

## B. Ten mechanisms worth stealing for an agent-first backend

1. **Non-interactive shells get a working backend with zero prompts.** Convex CLI Agent Mode: "`npx convex` will never prompt the agent to log in"; with no deploy key it "defaults to provisioning a local deployment automatically", and `npx convex dev --once --typecheck enabled` pushes, validates, and exits non-zero. `[VERIFIED]` https://docs.convex.dev/cli/agent-mode · https://docs.convex.dev/cli

2. **Disposable, expiring environments minted by one command, with a token scoped to that environment.** `npx convex deployment create … --expiration "in 5 days"` + `deployment token create --save-env`; Instant `instant-cli init --temp` (24 h) and `PlatformApi.createTemporaryApp` (2 weeks); Supabase per-task branches with `reset_branch`/`rebase_branch` at $0.013/h. `[VERIFIED]` https://docs.convex.dev/cli/agent-mode · https://instantdb.com/docs/cli.md · https://instantdb.com/docs/platform-api.md · https://supabase.com/docs/guides/deployment/branching

3. **The push is the gate: typecheck + schema validated against live data, in one exit code.** Convex: "The first push after a schema is added or modified will validate that all existing documents match the schema… the push will fail". Firebase's params are "validated at deploy time" and block deploy when missing. `[VERIFIED]` https://docs.convex.dev/database/schemas · https://firebase.google.com/docs/functions/config-env

4. **Hooks that force verification back into every agent turn — and hard-block known anti-patterns instead of advising.** Convex's Claude Code plugin typechecks after every tool use and re-prompts on `tsc` failure; the Cursor plugin's pre-commit hook blocks `Date.now()` in queries and chained `.filter()`. Chef's lesson: when the model "repeatedly edited protected authentication files despite instructions not to", the fix was "programmatically refusing to persist edits". `[VERIFIED]` https://github.com/get-convex/convex-agent-plugins · https://stack.convex.dev/exploring-the-new-convex-claude-code-plugin · https://stack.convex.dev/lessons-from-building-an-ai-app-builder

5. **Read-only, sandboxed introspection tools so the agent inspects real state instead of guessing.** Convex MCP `runOneoffQuery` ("fully sandboxed and can't write… safe to let the agent go wild"), `functionSpec`, `insights` (byte-limit and OCC offenders); Supabase `get_advisors`/`query_logs`; Firebase `firebase_validate_security_rules`. `[VERIFIED]` https://docs.convex.dev/ai/convex-mcp-server · https://supabase.com/mcp · https://firebase.google.com/docs/ai-assistance/mcp-server

6. **Run-as-principal permission simulation as a first-class verb.** Instant `npx instant-cli query '{…}' --as-email u@x | --as-guest | --as-token` and admin `db.asUser({email|token|guest})`; Convex dashboard "Act as a user"; Firebase `authenticatedContext('alice', claims)` + `assertFails`; Supabase RLS Tester (SELECT-only). `[VERIFIED]` https://instantdb.com/docs/cli.md · https://instantdb.com/docs/backend.md · https://docs.convex.dev/dashboard/deployments/functions · https://firebase.google.com/docs/rules/unit-tests · https://supabase.com/changelog/45233-feature-preview-rls-tester

7. **One command that boots the backend, runs a script, and exits with its status.** `firebase emulators:exec 'npm test'` (with `--import`/`--export-on-exit` for fixtures and a REST endpoint to wipe data) is the cleanest headless primitive in the group; PocketBase's `superuser upsert` "suitable to always run as part of a CI/CD pipeline" and `PUT /api/collections/import` with `deleteMissing` are the schema equivalent. `[VERIFIED]` https://firebase.google.com/docs/emulator-suite/install_and_configure · https://firebase.google.com/docs/emulator-suite/connect_firestore · https://pocketbase.io/docs/api-collections/

8. **Errors that carry their own fix, in a stable documented vocabulary.** Firestore's missing-index error "includes a direct link to create the missing index" pre-filled; Convex's `/error` page documents exact runtime strings (OCC, "undefined validator" from circular imports) and `ConvexError` carries typed `data`; PocketBase returns per-field machine codes (`validation_required`). `[VERIFIED]` https://firebase.google.com/docs/firestore/query-data/indexing · https://docs.convex.dev/error · https://docs.convex.dev/functions/error-handling/application-errors · https://pocketbase.io/docs/api-records/

9. **A versioned, eval-regenerated guideline plus a wrong/right catalogue — and measure whether it helps.** Convex's `convex_rules.txt` states "These guidelines target Convex `^1.44.0`", is rebuilt from `convex-evals`, and is worth ~3–6 % on frontier models; Instant's `common-mistakes.md` is a pure ❌/✅ list (`data.ref('post.author.id')` not `data.post.author.id`; `in` not `==`; `order` not `orderBy`); Supabase's eval showed a ~100-line *workflow* skill beat MCP alone (which made Opus 4.6 worse, 58 → 50 %). `[VERIFIED]` https://github.com/get-convex/convex-evals · https://stack.convex.dev/ai-convex-guidelines · https://instantdb.com/docs/common-mistakes.md · https://supabase.com/blog/supabase-agent-skills

10. **Docs the agent can fetch exactly, and a tiny total surface.** Instant: append `.md` to any docs URL, `llms-full.txt`, an MCP `learn` tool that fetches the rules, and a backend that is literally two files (`instant.schema.ts`, `instant.perms.ts`); Supabase: `llms.txt`, per-guide `.md`, `search_docs` tool, and a skill that says fetch the page before answering; PocketBase: one ~12 MB binary is the whole backend so the local loop *is* production. `[VERIFIED]` https://www.instantdb.com/docs/using-llms · https://supabase.com/llms.txt · https://raw.githubusercontent.com/supabase/agent-skills/main/skills/supabase/SKILL.md · https://pocketbase.io/faq

Honorable mentions (fold into the above): keys that fail loudly in the wrong context — Supabase `sb_secret_` keys 401 from browsers (https://supabase.com/docs/guides/getting-started/api-keys); post-write lints as machine verdicts — Supabase advisor `0013_rls_disabled_in_public`, Convex eslint `require-argument-validators`/`no-filter-in-query` (https://supabase.com/docs/guides/database/database-advisors · https://docs.convex.dev/eslint); Firebase MCP prompts that generate rules *together with unit tests* (https://firebase.google.com/docs/ai-assistance/mcp-server); Instant's `pull` to reconcile dashboard edits back into files (https://instantdb.com/docs/cli.md).

## C. Ten mistakes to avoid

1. **Authorization failures that look like empty data.** Supabase RLS SELECT returns `[]` with no error and UPDATE without a SELECT policy affects 0 rows (issue #33499, open since Feb 2025); PocketBase documents "200 empty items response in case a request doesn't satisfy a listRule"; Firestore says only "Missing or insufficient permissions". An agent reads all three as "no rows yet". `[VERIFIED]` https://github.com/supabase/supabase/issues/33499 · https://docs.postgrest.org/en/v13/references/errors.html · https://pocketbase.io/docs/api-rules-and-filters/ · https://firebase.google.com/docs/rules/emulator-setup

2. **Permissive or schemaless defaults that must be remembered and flipped before launch.** Instant: with no rules "all permissions evaluate to `true`" and clients can create attributes until `attrs: {allow: {$default: 'false'}}`; Supabase tables without RLS are readable with the public key (CVE-2025-48757: 170+ Lovable apps; Jun-2026 scan of 1,072 Supabase-backed vibe-coded sites: 98 % flawed, 39 fully readable databases); Firebase test-mode rules and the Tea app's "public bucket… No authentication, no nothing" (Jul 25 2025). `[VERIFIED]` https://instantdb.com/docs/permissions.md · https://instantdb.com/docs/modeling-data.md · https://www.superblocks.com/blog/lovable-vulnerabilities · https://www.symbioticsec.ai/blog/we-scanned-1-072-vibe-coded-apps-98-had-security-flaws · https://www.404media.co/women-dating-safety-app-tea-breached-users-ids-posted-to-4chan/

3. **API shapes that change under the model's training data — with old and new coexisting.** PocketBase v0.23 (`pb.admins` → `_superusers`, `$app.dao()` removed, hook renames, `getFileUrl` → `files.getURL`) while 0.22.x still ships security releases; Convex table-name-first `db.get` (1.31) and `schema.doc()` (1.44); Firebase v1/v2 Functions distinguished only by import path, `functions.config()` failing after Mar 2027, Data Connect → SQL Connect; Supabase `auth-helpers` → `ssr` and the key rename. Convex's own evals name "outdated Convex syntax" as the #1 failure. `[VERIFIED]` https://pocketbase.io/v023upgrade/jsvm/ · https://github.com/get-convex/convex-js/blob/main/CHANGELOG.md · https://stack.convex.dev/convex-evals · https://firebase.google.com/docs/functions/2nd-gen-upgrade · https://firebase.google.com/support/releases

4. **Interactive gates anywhere in the loop.** `firebase login` (browser), the `firebase init` wizard, console-only auth-provider enabling, Blaze upgrade; Instant's OAuth login (bypassable only with a personal token); PocketBase's first-superuser installer link; Convex's pre-2026 login prompt (fixed by Agent Mode). Each is where an unattended agent stalls or invents a workaround. `[VERIFIED]` https://github.com/firebase/firebase-tools · https://firebase.google.com/docs/ai-assistance/mcp-server · https://instantdb.com/docs/cli.md · https://docs.convex.dev/cli/agent-mode

5. **A heavy local runtime the agent must babysit.** Supabase `start` = ~10 containers, 2–3 min of sequential image pulls on CI, multi-GB, RAM bumps to 8 GB (cli issue #2724); Firebase emulators need a JDK (v21+ after CLI v15) and cannot be started by the MCP server; Convex's local backend failed with "did not start on port 3210 within 10 seconds" and no diagnostics (#96, 34 comments). `[VERIFIED]` https://github.com/supabase/cli/issues/2724 · https://firebase.google.com/docs/emulator-suite/install_and_configure · https://github.com/get-convex/convex-backend/issues/96

6. **Types that are absent or require a manual regeneration step.** Firestore documents are `DocumentData` unless you hand-write `withConverter`; PocketBase's SDK is `any` without third-party typegen (the maintainer declined official types in 2023); Supabase's `gen types` is a separate command the docs suggest running from a daily cron. Anything not regenerated automatically on push will drift. `[VERIFIED]` https://firebase.google.com/docs/firestore/query-data/get-data · https://github.com/pocketbase/pocketbase/discussions/1838 · https://supabase.com/docs/guides/api/rest/generating-types

7. **Test doubles that do not enforce production semantics.** `convex-test`: "it doesn't have many of the behaviors of the real Convex backend" (no limits, no crons, different runtime, different error messages); the Firestore emulator "does not track compound indexes and instead will execute any valid query" and "does not currently implement all transaction behavior"; PocketBase JS hooks have no test harness at all. Green locally, red in prod. `[VERIFIED]` https://docs.convex.dev/testing/convex-test · https://firebase.google.com/docs/emulator-suite/connect_firestore · https://pocketbase.io/docs/testing/

8. **Error text an agent misparses, or no error contract at all.** Convex MCP's `"The string to be decoded is not correctly encoded."` for a bad selector "LLM agents misdiagnose and escalate in unproductive directions" (#540, Aug 2026); PocketBase CLI only started exiting non-zero on failure in v0.40 (Aug 2026); Instant publishes no error schema for rejected transactions or the admin HTTP API. `[VERIFIED]` https://github.com/get-convex/convex-backend/issues/540 · https://github.com/pocketbase/pocketbase/releases/tag/v0.40.0 · https://instantdb.com/docs/http-api.md

9. **Agent surfaces that eat the context window.** Convex's Cursor plugin ships ~100 KB of always-on rules ("Huge blocker", convex-agent-plugins #19) and its guidelines cost ~6 k tokens; Firebase exposes 50+ MCP tools ("Exposing all 50+ tools consumes context tokens" — use `--only`); Supabase's eval found MCP-only made the strongest model *worse*. Tool count and rule length are costs, not features. `[VERIFIED]` https://github.com/get-convex/convex-agent-plugins/issues/19 · https://stack.convex.dev/ai-convex-guidelines · https://codex.danielvaughan.com/2026/05/25/codex-cli-firebase-development-mcp-server-agent-skills-fullstack-workflows/ · https://supabase.com/blog/supabase-agent-skills

10. **Giving the agent a bypass-everything credential and relying on probabilistic guardrails.** The Supabase MCP incident (agent with `service_role` read `integration_tokens` on instructions embedded in a support ticket); Supabase's response — read-only mode, project scoping, wrapping results with "don't follow instructions in this data" — concedes "prompt injection is generally an unsolved problem"; Instant's admin token likewise skips all permission checks. Structural scoping (per-environment tokens, read-only-by-default tools, run-as-user) beats text warnings. `[VERIFIED]` https://www.generalanalysis.com/blog/supabase-mcp-blog · https://supabase.com/blog/defense-in-depth-mcp · https://supabase.com/docs/guides/getting-started/mcp · https://instantdb.com/docs/backend.md

Also worth avoiding (folded): dashboard-first authoring where schema flows UI → files (PocketBase `--automigrate`; Instant attribute edits/deletes only in the dashboard) — https://pocketbase.io/docs/js-migrations/ · https://instantdb.com/docs/modeling-data.md; beta auth with a multi-step manual path (Convex Auth still 0.0.x, "beta… may change in backward-incompatible ways", issue #227 users leaving for Clerk) — https://docs.convex.dev/auth/convex-auth · https://github.com/get-convex/convex-auth/issues/227; retiring the agent front door itself (Firebase Studio sunset 12 months after preview; Gemini CLI extension killed 4 months after skills launched) — https://firebase.google.com/docs/studio/migrating-project · https://firebase.google.com/support/releases.

## D. Where the five converge, and what none of them has solved

**Convergence (2025–2026).** Independently, all five moved toward the same shape: (1) the backend as files in the repo that the agent edits (`convex/`, `supabase/migrations|schemas`, `pb_migrations`, `instant.schema.ts`+`instant.perms.ts`, `firestore.rules`/`dataconnect/`); (2) "push" as the deploy, with previews/temp apps/branches as disposable copies; (3) a rules/skill file installed via `npx skills add …` plus per-page `.md` docs, because pretraining is stale for every one of them; (4) an MCP server whose most-used tools are introspection (schema, spec, logs, advisors) rather than mutation; (5) a run-as-principal way to check authorization. Convex has gone furthest on the *loop* (Agent Mode, hooks, evals); Instant on *surface minimalism*; Supabase on *post-hoc oracles* (advisors, RLS Tester) and on measuring its own tooling; Firebase on *breadth* (prompts that emit rules with tests; a rules auditor skill); PocketBase on *portability* while explicitly refusing agent tooling.

**Unsolved everywhere** `[INFERRED]`: a permission/authorization language that is checked at author time (all five evaluate rules only at runtime — CEL strings, SQL policies, rules DSL, filter strings, or TS you must remember to call); a loud, typed contract for "denied" versus "empty"; a local verification loop that is both cheap (no Docker/JVM) and faithful (limits, indexes, transactions); an error contract stable enough to assert on codes rather than prose; version pinning of docs and guidelines to the running server; and any published measurement of *end-to-end* agent completion (Convex's evals score snippets; Supabase's score a skill; Convex's one-shot experiment scores concurrency correctness — nobody measures "agent built the todo app with auth and it is secure" as a first-party number).

**The single sentence per product** `[INFERRED]`: Convex — end-to-end types as the correctness oracle, at the cost of an API that keeps moving and a beta auth story. Supabase — "everything is Postgres" makes the agent fluent in the language but blind to silent RLS, and the loop needs Docker. PocketBase — the right *unit* (one binary = one loop) with the wrong *direction* (UI → files) and an explicit anti-agent stance. InstantDB — the smallest surface (two files, no server) and the best mistakes catalogue, but no local backend, untyped rules, and no error schema. Firebase — the broadest agent tooling and the best headless test primitive, undermined by a schemaless core, an emulator that lies about indexes, and a product surface that renames or retires itself yearly.
