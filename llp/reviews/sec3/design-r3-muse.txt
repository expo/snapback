## Material issues and concrete repairs

**1. Whole-row temporal probe can refute a column policy (spec prohibition, must fix).**
§12 / §12.5: "A synthetic whole-row read cannot refute a projection-only column policy." `paired::run` correctly filters `i.column.is_none()`, but `timed::run` filters only `i.target=="read"` plus `has_clock`, so a column invariant with a clock policy gets the whole-row `$security.temporal` probe and an effect-`"read"` violation that `apply()` records as a refutation of the column declaration.
Repair: add `&& i.column.is_none()` to the `timed::run` filter in `snapback4/crates/snapback4-lang/src/bind/security/challenges/timed.rs`. Column-plus-clock stays covered by column worlds at the campaign clock; if multi-boundary clock sweeps for columns are wanted, add them inside `column_reads`, or record an explicit unsupported line.

**2. Silent 32-combination truncation in fixture read observers (unreported cap, must fix).**
`histories::observe` enumerates `fixture_cases(...).into_iter().take(32)` with no unsupported note when cases exceed 32. §12.5 requires caps to be reported ("no exhaustive claim is made for unvisited combinations").
Repair: bind the cases vec, and when it exceeds 32 insert `unsupported`: `"read-observer arguments capped at 32 per table/viewer; remaining combinations not covered"`.

**3. Column worlds don't try fixture principals as operation arguments (coverage gap, must fix).**
`column_reads::run_pair` builds fixture-aware `actors` for viewers but enumerates observer args via `argument_cases` (Principal args = VIEWER/OTHER only). Fixture-only principals are therefore never tried as argument values in column worlds, while every other fixture path uses `fixture_cases` with actors.
Repair: in `run_pair`, call `histories::fixture_cases(&p.args, rows, &actors, out)` instead of `argument_cases` (its built-in `Ref` handling from `rows` also subsumes the manual first-row pin loop).
