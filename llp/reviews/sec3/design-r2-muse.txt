## Material design defects (repair before READY)

1. **Privilege advisory misses `kind`-named role populations.** `risk()` returns `None` unless the roster has a literal `role` column ([privilege.rs](/home/ccheever/projects/sb4-b17-sec3/snapback4/crates/snapback4-lang/src/bind/security/privilege.rs:20)), and the trigger only fires on fields literally named `role` ([lints.rs](/home/ccheever/projects/sb4-b17-sec3/snapback4/crates/snapback4-lang/src/bind/security/lints.rs:77)). The same amendment's grant-lifetime notes accept a "role/kind column". Repair: share one role-column helper (role-or-kind, as `mutable_role` already does) between `mutable_role`, `risk()`, and the write trigger.

2. **`risk()` ignores owner-field patch authority in its admission check.** It tests only table insert/update rules ([privilege.rs](/home/ccheever/projects/sb4-b17-sec3/snapback4/crates/snapback4-lang/src/bind/security/privilege.rs:31)); a role write that succeeds via `written_by` owner patch while table rules deny reads as "not admitted" and produces no advice — yet §10.5 counts owner-patch as effective access and §11.3 demands self-conferral coverage. Repair: include field-authority admission in the admits test, or fire the note qualified as "via owner-field patch" when table rules deny but `written_by` enables the role write.

3. **Coverage/cap accounting never reaches the acceptance report.** The 512/512, 1000-row, rejected-snapshot, and declined-world strings live only in `Campaign.unsupported`, which `test` prints but `check`/`audit` drop — `report()` applies violations only ([verbs/security.rs](/home/ccheever/projects/sb4-b17-sec3/snapback4/src/verbs/security.rs:9)). §11.5 requires the caps to be reported, and a `check --json` consumer cannot distinguish "matrix fully visited" from "capped at 512". Repair: propagate campaign coverage strings into `Report` (per-verdict reasons or a coverage field) in `report()`.

4. **Declined counterfactual worlds are silently skipped.** Alternate-world construction failure in fixture column pairs ([column_reads.rs](/home/ccheever/projects/sb4-b17-sec3/snapback4/crates/snapback4-lang/src/bind/security/challenges/column_reads.rs:49)) and absent-world construction failure in fixture observation ([histories.rs](/home/ccheever/projects/sb4-b17-sec3/snapback4/crates/snapback4-lang/src/bind/security/challenges/histories.rs:66)) use bare `continue` with no unsupported entry — including the captured/recorded-field cases the spec says must stay explicitly not-covered. Repair: record a named unsupported entry (table, observer, reason) at each such `continue`.

5. **Duplicate `## 11` headings make `@ref`s ambiguous.** The SEC2 checkpoint and the SEC3 amendment are both `## 11` with `### 11.1–11.5`, so `#111/112/113` in the new code ([columns.rs](/home/ccheever/projects/sb4-b17-sec3/snapback4/crates/snapback4-lang/src/bind/security/columns.rs:3), [fork.rs](/home/ccheever/projects/sb4-b17-sec3/snapback4/crates/snapback4-core/src/store/fork.rs:4), [histories.rs](/home/ccheever/projects/sb4-b17-sec3/snapback4/crates/snapback4-lang/src/bind/security/challenges/histories.rs:2), [privilege.rs](/home/ccheever/projects/sb4-b17-sec3/snapback4/crates/snapback4-lang/src/bind/security/privilege.rs:2)) could resolve to either block. Repair: renumber the SEC3 block to `## 12` / `### 12.1–12.5` and update those four `@ref`s.
