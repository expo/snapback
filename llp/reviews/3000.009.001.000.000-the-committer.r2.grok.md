## Verdict: SOUND WITH MAJOR ISSUES

Directional spans, row-image dependencies, and re-derived limited counts match the store, and the serial stream still holds. Two rules added in this revision admit a history that replay in revision order would not: a cap or threshold refusal stays committed when a later delete makes its predicate true, and a session that expires by time while the member waits has no footprint that validation can see. Publication is specified as a validation conflict on a member, while a due opening aborts the attempt before a member exists. The overlay differential still byte-compares two live mint streams.

## New fundamental and major findings

### N1. A predicate conflict commits the stale refusal — FUNDAMENTAL — committer §4.5, read-sets §3–§4

The cap decision is `count_prefix(..., max + 1) >= max` (`engine/write.rs:733`, `767`). §4.5 records that check as `count + my_delta ≤ max` and read-sets §3 conflicts only when re-evaluation makes the predicate false. Refusals are committed results and take a receipt (§3.4).

Take a group that is already full. The pre-executed insert refuses, and the predicate is false. A delete already accepted in this batch, or committed after the snapshot, makes `count + 1 ≤ max` true. Validation accepts the member. The receipt then replays the refusal. Serial replay after the delete inserts. The same one-way rule is what §4.5 gives maintained totals that are read only to compare. The crossing direction, an insert that was allowed and no longer fits, does rerun.

### N2. Session expiry is a predicate of time, and the batch never re-evaluates it — FUNDAMENTAL — committer §3.6

`live_session` returns none when `expires_at <= now`, with no write (`authority.rs:215–217`). Action sessions also die when the claim window fails that same `now` (`authority.rs:225–226`). Logout takes `now` inside the writer transaction because time spent waiting on the lock must not keep a token live (`identity.rs:253–255`). Serve resolves the writer session under the engine lock for the same reason (`serve_identity.rs:58–60`).

§3.6 reads the session inside snapshot S and then relies on an `Auth` footprint. Expiry has no footprint. The only serial re-check specified for the batch is the receipt. A member that waits behind an administrative or long member can commit after `expires_at` and after a claim window, on a quiet key, with validation succeeding. Principal-generation revocation is a write and can carry a footprint; time expiry cannot.

### N3. A due opening aborts the attempt that was supposed to conflict with its publication — MAJOR — committer §4.2 and §6

A row that is live at `now` and still in `_time_openings` is not a hidden value. `inactive_with_pending` returns `TimeAudiencePending` (`engine/read.rs:379–395`). That error is a store failure (`error.rs:243–256`), so `mutate` rolls back and records no receipt (`engine/mod.rs:1048–1050`). There is no member for the §6 conflict to reject.

§4.2 opens S and runs the program before the publication member exists. Today's writer publishes one due opening before the program (`engine/time_audience.rs:83–120`, `132–140`) and the query loop then publishes the specific opening the attempt hit and runs again (`serve.rs:1258–1320`; `engine/mod.rs:729–730`). §6 replaces both with one publication member awaited before the snapshot. One oldest opening leaves every later due opening pending, and the aborting pre-execution never enqueues the publication that would unblock it.

### N4. The overlay differential still compares two entropy mint streams — MAJOR — overlay §6

`Mint` draws OS entropy, and clones share that stream across failed attempts (`ids.rs:8–18`, `32–37`). `Context::mint` uses an injected id only when one was supplied (`engine/mod.rs:262–266`). Overlay §6 runs the program in place on store A and pre-executed on store B, then compares the complete logical state byte for byte, including rows. Those rows contain minted ids. The new comparison has no shared transcript, so a correct overlay disagrees with itself. §3.5 fixed that for the replay oracle only.

### N5. Presence is sampled in the writer's critical section, then never again — MAJOR — committer §4.6

`connected[p]` is read through the in-process registry during the run (`engine/runner.rs:1304–1327`). Serve holds `FairMutex<Engine>` across authority, `mutate`, and commit (`serve.rs:1411–1429`), so no other durable member commits between that sample and the commit. §4.6 records the sample, does not validate it, and treats that as equivalent because presence never commits.

A pre-executed branch can therefore commit after another member whose own branch observed a later presence value. Effect deadlines are stored and enforced later at claim time (`engine/effects.rs:89–97`); this is the ordinary `connected[p]` branch that inserts one durable row or another.

## Small notes

1. Absent `index_head` decides lifetimes (`engine/witness.rs:190–196`). Read-sets §3 defines the span when a head exists. Absence is an unstopped walk of the whole bound; the section should say that.
2. A sequence ordinal is an index component (`engine/sequences.rs:193–238`). §4.1 keeps a placeholder in a key ineligible, so the §4.5 allocation path does not cover the inserts the schema-contention cell is about. §5 resolves key placeholders before validation, and §3.4 resolves them after.
3. A long member alone still holds the writer for the chunk (`engine/job.rs:242–249`). Queue time counts toward the 100 ms SLO in §7.
4. `apply_aggregate` and `mirror_column` write absolute images, and a zero sum is kept only while a source remains (`engine/maintains.rs:542–557`, `579–622`; `engine/columns.rs:70–85`). Commit-time deltas have to recompute those three decisions.
5. The allocation counter is in memory (§4.5). After a crash it has to be rebuilt from the committed `_sequences` rows. §8's fault list covers exactly-once retries and does not say this.
