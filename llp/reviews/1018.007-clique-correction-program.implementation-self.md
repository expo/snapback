## Code findings

1. **MATERIAL — Slice must not preserve a list's exact source length.**
   Initial slice commit `53e0ddd22` copied `StaticType::List.len`, but cursor
   certification treats that length as exact tuple arity. A three-element
   literal sliced to two could therefore reject a valid two-component cursor.
   Resolved in `f3d1eef40`: text keeps Text, lists keep their element type but
   lose the exact length, and unsupported source kinds become Unknown. The
   sliced-tuple regression and text/list/storage regression passed on BLACK.
2. **Shared installation review.** Inspected the public flight/inner reload
   separation, captured identity scalars, revalidation after suspended reads,
   private cold construction and synchronous publication preserving the flight.
   The focused suite covers concurrent failure/retry, later-revision readers,
   root reset and principal/epoch/program changes. No evaluation state is shared
   by this optimization. Full-browser performance remains unqualified here.
3. **Signup review.** The owner uses the existing low-ID grant issuer. The
   durable SDK proof creates three profiles immediately after signup, captures
   replay envelopes and excludes login/query/resume workarounds. Separate
   pending-grant principal custody hardening landed on the integration branch
   as `511caecdf`: validated principal stamps, mismatch/wipe disposal and
   recoverable same-principal retry. Review also caught older failed adoption
   overwriting a newer pending grant; its regression passes.
4. **Pagination review in progress.** The real persistent-carrier/React
   reproduction loses the owner cursor while the local computed-key projection
   is partial. Preserve a proven owner answer whole, not its cursor pasted onto
   different data. An initial candidate selected any complete/capped owner
   answer over local work; requested narrower selection and tests for queued
   deletion, newer remote facts, revocation and maintained-sibling invalidation.
   The initial positive 20/20/5 tests alone did not settle those boundaries.
   Integrated candidate `f4dc4411a` now requires the same owner's selection
   proof, disallows newer sequences and queued/predicted work, and excludes
   drains. Its affected tests pass. A further hypothesis about committed but
   not yet acknowledged deletion overlays was sent to the implementer. It was
   confirmed: removed overlay rows do not appear in visible predictions, and
   cold local sequence is zero. `04121a647` carries active overlay custody
   separately and preserves a committed deletion across same-principal cold
   reopen until retirement. The test stages the committed ledger result
   against a real durable carrier; it is not a timed owner crash.
5. **Recipe review in progress.** The expiry branches now pass the chosen
   deadline to a shared write helper, and Slice computes one preview for both
   storage and emission. The compiler/evaluator fixture is useful but does not
   alone prove the copied application's scheduler, reconnect eviction, media
   sends or provider idempotency. Those witnesses remain in the recipe lane.
   Rejected a proposed multi-transaction digest accumulator because membership
   and follows could change before emission; the replacement must compute from
   current relationships and record the unique period/effect atomically.
6. **MATERIAL — the digest cannot trade away the account envelope.** The
   initial recipe patch `b87870130` adds `cap 50 by principal` to memberships,
   but the source's 50 bound was only per conversation (group size). The frozen
   workload includes a 100-conversation account. Requested a corrected joint
   500-follow/100-membership certificate and owner witness; the 500/50 result
   does not qualify the required envelope. Resolved by `42062da97`: the
   corrected app certifies 500 follows and 100 memberships at 2,763,906 closure
   bytes, and a real owner journey commits 99 groups on top of a seeded
   membership before emitting the correct following-post digest. The recipe
   explicitly refuses membership 101; it does not promise an unlimited account
   or silently truncate its selection. The original per-group 50 bound stays.
7. **Execution-local hash review.** `949f2459e` caches the existing canonical
   schema-scoped hash by rule identity inside one synchronous Runner. It does
   not cache permission outcomes across executions. The focused test checks
   distinct-rule traversal counts, identical bytes from the public helper and
   recomputation by a new Runner after an externally changed rule. The schema
   is fixed during a synchronous execution; there is no new process-global
   authority cache. LLP 1012 section 6 now states this lifetime explicitly.
8. **Recipe evidence review.** The retained owner preview case originally
   claimed stored/emitted equality while reading only the stored push row.
   Corrected its label and requested the actual effect-payload assertion;
   the compiler fixture's same-value emit check is separate evidence. A quiet
   period also needs an observed completed sweep, not merely a fixed sleep
   followed by an unchanged row count. The extended owner matrix is in progress.
   Asked whether the now-smaller manual post counter permits ordinary scratch
   fields instead of coupling packed unread counts to radix 101; the current
   packing is arithmetically bounded by 100 memberships, but readable fields
   should be preferred if their certificate fits.
