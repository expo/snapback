## Problems

**FUNDAMENTAL — A receipt hit is returned before `intent_store`, so a replaced store is acknowledged as `sent`.**

§3.1's keyed order is authority, receipt lookup, head, and only then the in-memory checks. A hit returns before those checks, and the list includes the `intent_store` comparison. LLP 3000.013 requires `E_STORE_REPLACED` before execution or idempotency lookup (`3000.013.000` §store binding; today's `intent_store().and_then(replay)` at `serve.rs:1176`). A retry that names store A, served by store B which already has that `(principal, id)` receipt, takes the stored `sent` outcome. `local.ts:1139` settles `state: "sent"` as terminal. That refusal is an unknown outcome, and a false `sent` is sticky (`3000.013` §6).

The miss path compares store id only in that preflight snapshot. §7 says a snapshot is not current across the queue, and the durable-transaction check (§3.1 item 3) never repeats `intent_store`. The owner fence compares the process token, not the client's `store_id` (`store.rs:132`). A first attempt whose store is replaced while queued executes on the replacement. The post-queue check that prevents that is `serve.rs:1417`.

What resolves it: in the preflight snapshot, compare `intent_store` to that snapshot's store id before a hit may return; a mismatch is `E_STORE_REPLACED` and does not return the receipt. Repeat the comparison in the execution snapshot after the queue.

**MAJOR — The hit is an unbound `(principal, op id)` read, so `E_ID_REUSED` disappears.**

`replay_bound` (`receipts.rs:48–54`) returns `E_ID_REUSED` when the recorded operation name or wire-argument digest differs. §3.1 specifies the lookup key as `(principal, op id)` and returns that row's outcome before argument decoding. A resend of the same id with another operation or other arguments is acknowledged as the old outcome. The schema-narrowing case does not require this: the digest is of the raw wire JSON, which is available before decoding (`serve.rs:1177` passes `args_json`).

What resolves it: a hit is the bound lookup (requested name and raw wire-argument digest). A mismatch is `E_ID_REUSED` from that same snapshot, with the head taken from it.
