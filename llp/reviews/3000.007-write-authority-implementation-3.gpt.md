**Concerns, severity and resolution**

**1. High — the pinned-prefix repair opens an inverse empty/hidden population oracle.**

A uniform verdict need not be identical in an empty world and a populated world whose rows are all hidden. Consider:

`read <- not exists secrets[id = 'sentinel']`

This rule has no focal-field dependencies, so the prefix analysis classifies it as uniform. Negation is supported directly. [rules.rs:48](snapback4/crates/snapback4-core/src/engine/rules.rs:48), [bind/schema.rs:334](snapback4/crates/snapback4-lang/src/bind/schema.rs:334).

Pair two worlds with identical readable state and sequence:

- **Empty:** `secrets` has no rows.
- **Hidden:** `secrets` contains `sentinel`; its read rule denies every row.

A server mutation first spends exactly 8,192 rule probes on fixed readable work, then binds `secrets[] first 1 by byId` and returns a constant.

In the empty world, the hypothetical prefix verdict is **true**, so line 480 charges one probe and raises `E_BOUND` before discovering that no candidate exists. In the hidden world, the verdict is **false**, so line 478 returns empty without charging and the mutation succeeds. Both ordinary pages contain no readable rows. [read.rs:474](snapback4/crates/snapback4-core/src/engine/read.rs:474).

This is a population channel without an admitted hidden write. The current exhaustion test holds the probe verdict false across its populations, so it misses the inversion.

**Resolution:** normalize an empty authorized prefix with a uniformly denied prefix at exhausted budgets, while preserving verdict-before-candidate-charge ordering. Add `w4_negated_self_probe_empty_and_hidden_pages_match_at_probe_ceiling` through the shared helper, with ample-budget controls. It should compare the entire observation, including all meters.

**2. High — `created` with extra equalities escapes the static probe reservation.**

`rule_probes` counts every `RuleExpr::Created` as zero. The merged evaluator calls the metered `exists` path when a creation fact holds and extra equalities are present. [write_target.rs:208](snapback4/crates/snapback4-core/src/engine/write_target.rs:208), [rules.rs:175](snapback4/crates/snapback4-core/src/engine/rules.rs:175). The existing equality regression explicitly expects that case to consume one probe. [clique.rs:1299](snapback4/crates/snapback4-sim/tests/clique.rs:1299).

A concrete refused/refused pair:

1. Target read and update rules deny.
2. Its insert rule is `created permits[owner = viewer, enabled = true]`.
3. The mutation inserts the caller’s permit with `enabled: false`, then consumes the full probe budget through fixed readable work.
4. It upserts a target that is absent in one world and hidden in the other.

The reservation counts zero target probes and passes. The hidden hit reaches update denial and returns `NOT_FOUND`. The absent arm evaluates the creation equality, attempts another probe and returns `E_BOUND` **before establishing insert denial**. With adequate budget, both arms would refuse `NOT_FOUND`. [write.rs:116](snapback4/crates/snapback4-core/src/engine/write.rs:116), [write_target.rs:13](snapback4/crates/snapback4-core/src/engine/write_target.rs:13).

The reservation decision itself uses no hidden state; its **underestimate permits a hidden-dependent later refusal**.

**Resolution:** include metered `Created` equality checks in the static worst case. Add `w4_created_equality_upsert_reserves_before_lookup`, pairing absent/hidden denied targets at the probe ceiling and with adequate budget. Cover both private `WriteTarget` and legacy serialized upsert entry points.

**3. High — the one-unit maintain probe tests equalities against the physical, expired-inclusive total.**

`rule_probe_exists` retains the physical aggregate row in `found`. For an expiring source it establishes only that a live source witness exists, then applies extra equalities to the unchanged physical row. It never substitutes the live aggregate value. [read.rs:58](snapback4/crates/snapback4-core/src/engine/read.rs:58), [read.rs:76](snapback4/crates/snapback4-core/src/engine/read.rs:76), [read.rs:88](snapback4/crates/snapback4-core/src/engine/read.rs:88).

The ordinary live-aggregate path excludes expired contributions and replaces `value`; the rule-probe path now bypasses that behavior. [read.rs:136](snapback4/crates/snapback4-core/src/engine/read.rs:136).

For example:

- Both worlds have live contribution **2**.
- An expired hidden contribution is **1** versus **2**, producing physical totals **3** versus **4**.
- A hidden target’s update rule checks `exists sums[group = 'g', value = .amount]`.
- The same patch supplies `amount: 3`.

The current live predicate should deny both worlds. The implementation instead admits one and refuses the other, revealing an expired contribution and authorizing a write the live predicate does not grant. Generated maintains expose `value` and a total unique group key, so these extra equalities are admitted. [bind/schema.rs:517](snapback4/crates/snapback4-lang/src/bind/schema.rs:517), [bind/schema.rs:443](snapback4/crates/snapback4-lang/src/bind/schema.rs:443).

Ordinary extra equalities introduce no additional logical charge after an existence lookup. That favorable accounting does not compensate for testing the wrong value.

**Resolution:** evaluate these equalities against the live fact while retaining population-independent accounting, or statically refuse unsupported value equalities on maintains over expiring sources. Simply restoring the old metered aggregate traversal would reopen the original exhaustion problem.

Add `w4_live_maintain_probe_equalities_ignore_expired_contributions`, using the shared helper for the update pair, plus page-rule and successful live-value controls. Assert one probe regardless of expired population.

**4. Medium — complete-observation coverage still has bounded gaps.**

The main previously named runtime cases now use the helper. Remaining limitations are:

- The historical-receipt regression is single-world, with no device lifecycle. [write_authority.rs:701](snapback4/crates/snapback4-sim/tests/write_authority.rs:701).
- The scalar-result tail still uses direct calls and retries before any revocation. [write_authority.rs:358](snapback4/crates/snapback4-sim/tests/write_authority.rs:358).
- Immutable tests contain no maintain. Inspection supports preservation of immutable source values and cancellation of unchanged ordinary maintain contributions, but those fixtures do not prove the requested maintain/event boundary. Live sums can still perform an unchanged maintained write. [write.rs:473](snapback4/crates/snapback4-core/src/engine/write.rs:473).

I found no additional immutable-guess content channel: the guard removes fields before merging, and the profile test’s returned differences follow an explicit grant of read authority. It would nevertheless be inaccurate to claim that ignored patches produce no physical events; ordinary row-change processing still runs.

**Resolution:** extend the helper to distinguish a deliberately historical raw receipt from its expected sanitized replay, then add paired historical/scalar revocation lifecycles. Add `w4_ignored_immutable_patch_preserves_maintains_and_delivery`, keeping the target unreadable and checking source values, maintains, stream/snapshot and both stores. These complement the missing proving tests in concerns 1–3.
