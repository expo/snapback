## Review (verbatim answer text)

Both round-2 findings are fixed in the current tree. The shared publication-mode cell is what every read-index (RI) enrollment, validation, and proof path loads, and a closed reader socket no longer revokes that path when G6 is off.

## Publication mode

`Store::read_publication` is now one private `Arc<AtomicU8>` (`store.rs:92`). `set_read_publication` is a release store (`store.rs:125-127`). `read_index_eligible` is an acquire load that accepts only `SynchronousHead` and `early_release == None` (`store.rs:134-137`). Any other discriminant fails closed.

Every later handle clones that `Arc` rather than the old `Copy` value:

- detached readers, `handle.rs:62`
- writer slots, `handle.rs:88`
- writer reconnect replacements, `handle.rs:112`
- pipeline spare sync, `handle.rs:121`

`Store::new` / `with_connection` still starts a private cell (`store.rs:121`). Those stores are not returned until `share_read_publication` runs. HTTP idle readers and factories are `Engine::reader` → `Handle::reader` (`engine/mod.rs:498-499`, `serve_readers.rs:81-82`, `serve_readers.rs:105`, `serve_readers.rs:167`), so a factory-made reader clones the same cell the owner mutates.

The predicate is loaded again at each use, not cached:

- enrollment, `revision_cache_park.rs:28`
- validation, before the statement and after it, `read_index.rs:10` and `read_index.rs:29`
- proof consumption, before the authority callback and after `snapshot` returns, `revision_cache.rs:805` and `revision_cache.rs:817-819`

`AnyStore::read_index_eligible` only forwards to that load (`lifecycle.rs:79-82`). A `PublishedPrefix` store on the owner is therefore visible to an idle pool reader, a reader built later by a factory, and a proof that was stamped earlier. The G6 hit branch never calls this predicate; with G6 unconfigured, `Grant::read` returns no epoch (`read_grant.rs:166-170`), so that branch does not serve the raw-head proof.

Stage E is still the per-store `Option` copied at construction (`handle.rs:63`). `Handle::enable_early_release` refuses once `readers` is set (`handle.rs:32-34`), which happens before the new reader is returned (`handle.rs:57`).

## Reader-socket refresh

`refresh_reader_connection` revokes the shared grant only when `grant.configured` is set (`store.rs:151-156`). G6 cannot be turned on after `open_owned` stores `opened` (`ownership.rs:273`, `ownership.rs:451-453`), so that flag is stable for the life of the handle.

With G6 off, refresh still drops connection-local plans (`store.rs:149-157`), rebinds store id, generation, and catalog admission (`store.rs:160-185`), and `read_index_validation` then runs one new implicit statement for `_head`, `_backend`, `_meta`, and `_owner` (`read_index.rs:11-28`) via `Connection::independent` (`pipeline.rs:560-588`). The returned stamp is kept only if eligibility still holds (`read_index.rs:29`). `refresh_closed` replaces a dead reader slot (`pipeline.rs:304-311`); it does not allocate another pool.

`revoked` and `uncertain` are not cleared on that path. Terminal release still `drain()`s the grant (`ownership.rs:518-523`), which sets `revoked`. Both latches are checked at enrollment (`revision_cache_park.rs:29`) and at proof use before and after authority resolution (`revision_cache.rs:806`, `revision_cache.rs:817-819`). An in-flight proof whose resolver releases the lease, or whose grant is already uncertain, therefore cannot count as an RI hit. Other readers keep using their own fresh statement because the latch stays clear.

`Connection::is_closed` is only wider within the crate (`pipeline.rs:295`). Postgres call sites already resolved to that method.

No new stale-read, race, deadlock, leak, panic, or connection-cap defect in this delta.
