## Findings (ordered by severity)

**F1 — Read verdicts can be marked Proved despite unmodeled engine-generated existence oracles (exposure omission → false proof).** RFC §3 requires "unmodeled constraint/refusal observations remain unproved" and §2 requires both upsert arms and `insert if absent` be included with their collision/refusal observations. The implementation models only *authored* refusal differences (`N_EXISTENCE_ORACLE` lint, `Require`-program blockers in [security.rs](/home/ccheever/projects/sb4-b16-sec/snapback4/crates/snapback4-lang/src/bind/security.rs:166-171)). Engine-generated oracles have no blocker: a plain-insert unique-key collision (success vs error) and the upsert insert-vs-conflict arm both disclose existence to a caller holding insert/upsert authority without read authority. I confirmed in [write_target.rs](/home/ccheever/projects/sb4-b16-sec/snapback4/crates/snapback4-core/src/engine/write_target.rs:212-244) that the conflict arm runs real update authorization and produces caller-distinguishable outcomes. A `table.read only <policy>` invariant on such a table can therefore be reported Proved while the RFC mandates Unproved. Fix: add a blocker (read invariants on tables with unique indexes/upsert-addressable writes where insert authority exceeds read authority stay unproved), or model the observations.

**F2 — Operation challenges can fabricate the old image (false refutation, narrow trigger).** In [challenges.rs](/home/ccheever/projects/sb4-b16-sec/snapback4/crates/snapback4-lang/src/bind/security/challenges.rs:138-144) the operation challenge passes `old: Some(before)` where `before` is the seeded target-table row, even when the operation *inserted* a new row (for which old should be `None`). A policy with old-image terms judged against the wrong row can evaluate false and produce a `Refuted` verdict from a non-replay. `prove()` itself is unaffected (it requires field-free policies), so this only corrupts already-Unproved declarations — but a refutation must be a genuine replay per §4. Fix: pass `None` when the judged image is newly inserted (id not present in the seeded snapshot).
