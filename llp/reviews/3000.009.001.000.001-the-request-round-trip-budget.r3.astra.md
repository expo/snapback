**M1 — MAJOR: preflight replay now bypasses the requested store identity.**

[§3.1, lines 121–126](llp/3000.009.001.000.001-the-request-round-trip-budget.rfc.md:121) places `intent_store` after receipt lookup and explicitly returns a hit before that comparison. If a request belongs to store A but reaches store B containing the same principal/id and matching operation/arguments, this order returns B’s receipt instead of `E_STORE_REPLACED`. That receipt cannot establish the outcome of A’s intent.

This contradicts [LLP 3000.013’s store-binding contract](llp/3000.013-quarry-states-intent.rfc.md:850), the [current preflight ordering](snapback4/crates/snapback4/src/serve.rs:1176), and the existing [wrong-store replay regression assertion](snapback4/crates/snapback4/tests/serve_store/mod.rs:34).

Move the store comparison ahead of returning a bound receipt, using identity from the same authenticated preflight snapshot. Preserve replay precedence over current-schema checks and preserve `E_STORE_REPLACED` without recording a refusal receipt. Add this existing regression to §7’s required coverage; it needs no additional flight.
