## Verbatim review

**NOT READY — five MATERIAL design issues.** This was read-only; I did not consult review artifacts.

1. **Rejecting references only to dormant IDs creates an existence oracle.** [§9.1](/home/ccheever/projects/sb4-w9-rel/llp/3000.000.000-retained-storage-and-hot-release.rfc.md:127) prohibits new references to dormant rows, while [LLP 3000.039](/home/ccheever/projects/sb4-w9-rel/llp/3000.039-a-reference-declares-what-deleting-its-row-does.rfc.md:78) explicitly permits references to nonexistent or unreadable targets. A caller allowed to insert a public child can probe a private parent ID: an unknown ID succeeds, a dormant ID refuses. Generic refusal text does not hide that difference. Specify target-authority admission before inspecting dormancy, with indistinguishable outcomes for unauthorized targets, and reconcile the stronger reference policy with LLP 3000.039.

2. **Lifetime evidence can permanently strand otherwise restorable rows.** [§9.1](/home/ccheever/projects/sb4-w9-rel/llp/3000.000.000-retained-storage-and-hot-release.rfc.md:129) says invalid parent evidence keeps the entire row dormant. Two cases need different treatment:
   - A legal `on delete keep` reference was already dangling when an unrelated enum narrowing hid the row.
   - A parent was deleted while the row was dormant, but the restoration candidate removes that reference column.

   Neither requires rebinding a candidate-visible reference. The current evidence representation [marks an initially missing parent invalid](/home/ccheever/projects/sb4-w9-rel/snapback4/crates/snapback4-core/src/store/dormant.rs:91). Distinguish initially dangling references from later lifetime invalidation, and apply restoration barriers only to candidate-visible references/captures. Preserve unused evidence alongside omitted dormant cells.

3. **Predecessor expiry must precede narrowed-row hiding.** The amendment does not establish this ordering. An expired, unswept read-through row can fail a narrowed enum while the candidate removes its inherited lifetime; hiding it first prevents predecessor retirement from deleting it. A subsequent widening without that lifetime can restore it visibly. This conflicts with the existing rule that activation retires affected rows under their old deadlines. The [current activation order](/home/ccheever/projects/sb4-w9-rel/snapback4/crates/snapback4-core/src/store/activation.rs:180) runs retention before that retirement. Specify one pinned activation time and predecessor retirement before hiding, including deletion-evidence invalidation. Add this combined narrowing/lifetime-change regression.

4. **The request guard needs explicit boundaries excluding socket waits.** [§9.3](/home/ccheever/projects/sb4-w9-rel/llp/3000.000.000-retained-storage-and-hot-release.rfc.md:139) says the guard spans dispatch and precedes engine/bound/readers locks. Its natural implementation currently holds it across all of [`handle`](/home/ccheever/projects/sb4-w9-rel/snapback4/crates/snapback4/src/serve.rs:797), including [body reads](/home/ccheever/projects/sb4-w9-rel/snapback4/crates/snapback4/src/serve.rs:931) and response writes. A slow sender or non-reading client can therefore block activation. Buffer bounded input before final admission; hold the guard through release-dependent lookup, decoding, execution and reply-identity capture; release it before socket output. Body and header generations must come from that captured identity.

5. **The promised uniqueness repair can be impossible under the current release.** [§9.1](/home/ccheever/projects/sb4-w9-rel/llp/3000.000.000-retained-storage-and-hot-release.rfc.md:127) says to resolve forward conflicts under the current release. Counterexample: rollback hides row A with unique key K; an older write inserts B with K; another narrowing hides B too. Widening restores both and refuses uniqueness, but current application SQL and mutations expose neither row. Specify an executable bridge remedy: widen while temporarily removing the conflicting uniqueness constraint, restore both rows, repair through authorized mutations, then reinstate uniqueness. Diagnostics must select that remedy when current-release repair cannot reach the conflicting population.
