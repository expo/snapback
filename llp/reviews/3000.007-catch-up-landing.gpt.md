1. **High — Denied matching lanes disclose short-circuit state, including under `Cut::Cap`.**

   Files: [engine/read.rs:336](snapback4/crates/snapback4-core/src/engine/read.rs:336), [engine/read.rs:57](snapback4/crates/snapback4-core/src/engine/read.rs:57), [serve.rs:855](snapback4/crates/snapback4/src/serve.rs:855).

   Construct a messages table with unique `(roomId, principal)` and this read rule:

   ```quarry
   read <- exists messages[.roomId, viewer] and exists permits[.roomId, viewer]
   ```

   Search one explicit room lane. Permits are absent in both worlds. W0 has no message for the viewer; W1 adds one hidden message in that room. Keep readable rows, inputs, clock, and commit sequence identical. Both lane verdicts are false.

   | Observable | W0 versus W1 |
   |---|---|
   | `Cut::Cap`: rows, `complete`, `next`, `capped_at`, error | Both empty, complete, null cursor, no cap, no error |
   | `Cut::Cap`: all meter fields | Equal; denied verdict probes are not charged |
   | **Wire `tables`** | **`messages` versus `messages, permits`** |
   | `Cut::Abort`, ample budget | Same empty result; **one versus two rule probes** |
   | `Cut::Abort`, one remaining probe | **Success versus `E_BOUND`**; neither sets `capped_at` |

   The dependency list records only executed probes and is serialized publicly. The abort path also charges `probe.count`, repeating §17’s short-circuit problem.

   **Smallest fix:** register rule dependencies independently of execution branches and charge the schema-derived probe allowance for aborting verdicts. Add this complete-envelope pair, including `tables`, and the complementary `or` case. For the simpler fixed-membership denial with 0 versus 33 hidden words, inspection shows equal observables: both return before discovery; the existing test asserts only a subset of that result.

3. **High — Search execution state is not isolated from nested filter reads.**

   Files: [engine/read.rs:390](snapback4/crates/snapback4-core/src/engine/read.rs:390), [engine/read.rs:486](snapback4/crates/snapback4-core/src/engine/read.rs:486), [engine/read.rs:536](snapback4/crates/snapback4-core/src/engine/read.rs:536), [engine/read.rs:570](snapback4/crates/snapback4-core/src/engine/read.rs:570).

   A `matching 'cof car'` message scan whose `where` counts a readable members page leaves `word_filter` installed while executing that members scan. Members have no `body`; every member fails the outer search’s secondary-term test. The message is incorrectly filtered out.

   There is also an authority failure for hand-serialized IR: assign the nested hidden-table scan the outer scan’s `site`. The string-only `word_verdict` check then bypasses its read rule. A filter testing that scan’s count reveals hidden existence. Generated Quarry sites are distinct, but the engine accepts supplied programs without a site-uniqueness guard.

   **Smallest fix:** suspend both search filter and verdict state around nested filter evaluation, and bind verdict reuse to the actual word-lane execution context. Add normal Quarry nested-filter tests and a repeated-site IR negative test, including lazy word heads and both stores.

4. **High — Audience discovery reads an unmaterialized defaulted group column.**

   File: [partition.rs:224](snapback4/crates/snapback4-core/src/partition.rs:224).

   Start with a stored membership carrying `principal` but no `roomId`. Adopt `roomId: id default 'r'`, the required audience indexes, and a messages audience bound to that membership.

   The rebuilt index and rule lookup interpret the membership as belonging to `r`. However, `groups_now` reads the raw membership and turns its absent `roomId` into null, discarding the group. The server query admits messages in `r`, while snapshot acquisition and the new `held` metadata omit it.

   **Smallest fix:** materialize each membership before extracting audience fields. Audit other partition field extraction through the same helper. Add an adoption-to-snapshot regression that verifies rule admission, `held`, delivered rows, and both device stores.

5. **High — A maintain can lose its zero-valued candidate because grouping reads raw images.**

   Files: [engine/write.rs:560](snapback4/crates/snapback4-core/src/engine/write.rs:560), [engine/write.rs:578](snapback4/crates/snapback4-core/src/engine/write.rs:578).

   **Smallest fix:** materialize source images before grouping comparisons, including the analogous rule-probe source walk at [engine/read.rs:74](snapback4/crates/snapback4-core/src/engine/read.rs:74). Add the zero-crossing/expiry case and verify subsequent delivery to both stores.

8. **Medium — `SQLITE_OPEN_READ_ONLY` does not establish the promised sidecar immutability.**

   File: [store.rs:49](snapback4/crates/snapback4-core/src/store.rs:49).

   Inspect a WAL-mode store with a writable directory and missing or writable shared-memory sidecar. This connection uses SQLite’s normal WAL reader path. The pinned SQLite implementation can open/create `-shm` read-write and update shared-memory bookkeeping despite the main database being read-only.

   Required: `check` leaves no lock/WAL sidecar change. The tests verify rows, generation, sequence, and rejection of SQL writes, but not this guarantee: [tests/check.rs:35](snapback4/crates/snapback4/tests/check.rs:35).

   **Smallest fix:** use a supported sidecar-read-only opening mode and handle inability to obtain that snapshot explicitly. Test existing/missing sidecars and compare directory contents, bytes, and metadata before/after, including a live writer.

9. **Medium — Touching any left group suppresses fallback for an unrelated held-group result.**

   Files: [device/history.rs:67](snapback4/crates/snapback4-device/src/device/history.rs:67), [local.ts:658](snapback4/packages/snapback4/src/local.ts:658).

   The first read sets the query-wide `retained` cell. The returned held-room read is incomplete, but the client suppresses server fallback and returns 25 rows. The server would return all 26. This affects watches as well.

   **Smallest fix:** associate the retention override with result/read-site provenance and preserve independent unknown held-site coverage. Add the two-read query to the existing wasm/process retention client test and both-store coverage tests.

10. **Medium — Cross-file `--fix` can apply a stale diagnostic and report success against stale source.**

    Files: [verbs/fix.rs:8](snapback4/crates/snapback4/src/verbs/fix.rs:8), [verbs/fix.rs:22](snapback4/crates/snapback4/src/verbs/fix.rs:22), [verbs/fix.rs:179](snapback4/crates/snapback4/src/verbs/fix.rs:179).

    Compile a missing-index diagnostic in `queries.q` targeting a table in `tables.q`. Before application, an editor changes `queries.q`, removing or changing that read. The fixer checks only `tables.q`, inserts the obsolete index, and continues compiling its original in-memory `queries.q`. It can report success even if the actual edited query now fails compilation. A destination edit between the comparison and `fs::write` can also be overwritten.

    **Smallest fix:** validate all diagnostic inputs, not only the destination, and coordinate publication against the expected destination version. Re-read the project before reporting final compilation success. Add cross-file concurrent-edit tests; existing stale tests exercise only token repairs.
