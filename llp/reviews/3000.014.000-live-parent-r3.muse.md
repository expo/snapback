## Blocking issues

**H1 — Union sync is both claimed and refused. Severity: High.**
Counterexample: a live child whose substituted rule (after service-strip) is a union-admissible audience, or whose ordinary parent syncs to a union. §2.4 says "a single invertible or admitted union audience syncs"; §5 prices "union arms multiplied by the declared arm count"; §6 tests "union arms". But `schema/union.rs:56` refuses any through table syncing to a union ("a table that reads through its parent cannot sync to a union; use `online only`"), and `:58` refuses a child inheriting a union audience. An implementer must either leave the refusal (contradicting §§2/5/6) or amend it (undesigned audience-inheritance semantics — exactly the Codex-r1 #6 hazard class).
Smallest repair: pick one. Either add a §2 admission bullet refusing union audiences for live children (`online only`, as today), and delete union-arm pricing/tests; or specify the exact `union.rs` amendment with the inheritance proof that kept through+union refused. One sentence plus the corresponding §5/§6 edit.

**H2 — The §5 price formula is structurally short on event heap and underived. Severity: High.**
Counterexample: N=20 live children with narrow rows, `R = row_copy_ceiling(C)` ≈ 64. Formula heap `4*(N+1)*R` ≈ 5 KB. Actual per-child partition work in `account_row_change` (`partition.rs`): before/after partition sets, `prepay_field_delivery`, plus per-event encoded group metadata. The existing `reservation()` event model prices `image*2*arms + metadata*(2*arms+2*dependents)` with metadata ≈ `1024 + 4*keybytes + 4*namelen` per table — ~5 KB per child, ~100 KB total. The formula has no metadata addend, so `check` admits schemas whose legitimate parent writes then spuriously exhaust unchanged ceilings at runtime (availability failure), or the implementation silently raises effective demand against the "no ceiling raised" rule. `F+8`, `2x`, `4x` are likewise asserted, and "the existing partition event pricing helper" is unnamed (the only such logic is inline in `reservation()`), with no stated charge channel for the new `LiveAuthority` origin through `prepay_field_delivery`'s `origin == Maintained` branch.
Smallest repair: define per-child event price by naming the helper (extract or cite `reservation()` lines 160–176), add the metadata term with its table-count bound, derive each constant from the §4 operation list, and state the `LiveAuthority` charge channel. §8's boundary tests stay as the validation, but the formula must close first.

Smallest repair: a closed enumeration — refused declaration list applied identically to endpoints and every transitively probed table, the exact term-to-refusal mapping, the definition of "total", and the uniform-readability (`Public`/`Allow`) case with `F=0` — plus the accepted/refused pairs Muse-r2 already asked for.

**M2 — §4's writer coverage claims a tail without a writer inventory. Severity: Medium.**
Counterexample: an import that replaces a parent's policy fields while physical children exist must refuse (§7.1), and seed/import/system/restore writers must stamp-or-hook. The design names writers but never maps each to its mechanism (Runner tail vs insert-time stamp vs refusal), and terms like "reference-action replacements" and "system writes" match no enumerated call path; `seed_rows` (`engine/mod.rs:1315`) takes `Tx` directly, and dormant/activation paths install rows outside `row_changed`. If any bulk path bypasses the tail, copies go stale in the permissive direction with no refusal.

**M3 — The mixed-cut argument is a conditional, not an invariant. Severity: Medium.**
