## 1. Later-lookup suppression lacks same-target linkage (soundness)

§13.1 lets "a mandatory exact-id lookup later in the same atomic mutation" suppress `N_REFERENCE_UNCHECKED`, superseding [LLP 3000.039 §7](llp/3000.039-a-reference-declares-what-deleting-its-row-does.rfc.md), which explicitly states lookups "after the write do not suppress the note." The atomicity argument (earlier writes roll back on later refusal, per §11) is valid only if the later lookup observes the same reference. The stated exclusions (some-paths, optional loop, rebound input) omit this.

Correction: require the later lookup to target the same table and the same exact-id value as the stored reference (same key, no intervening rebinding of that value), nullable or asserted. A lookup of any other id must not suppress.

## 2. Continuation suppression lacks same-query linkage (soundness)

§13.1: "A declared continuation (`after c` or `before c`) suppresses N_NO_CURSOR." Unconditional on which query the continuation belongs to or whether `c` resolves.

Correction: suppress only when the continuation pages the same returned query and resolves to a declared cursor. An unresolvable continuation keeps the note alongside the existing declaration error, so a typo cannot silence a real cursor gap.

## 3. Maintained `in` has no refusal path (completeness)

§13.1 defines lowering (`or` of typed equalities, empty list is false) but "only literal-list operands accepted by the existing comparison binder qualify" states no behavior for the rest: non-literal elements, mistyped elements, heterogeneous lists, a `null` element's three-valued meaning, and how an empty list is typed.

Correction: name the refusal code for non-qualifying operands (the existing comparison-binder code, spelled out), and define `null`-element and empty-list binder semantics explicitly.

## 4. Lexical-equality silence undercuts §10's proof (soundness)

§13.1 silences `N_IMMUTABLE_PATCH` "when lexical resolution proves equality to a pinned key, including bound row fields." §10's Quiet outcome requires a current snapshot of the exact target, no intervening write, and unconditional paths; "uncertain control flow stays a note" restates only one of these. A stale snapshot's bound field could silence a real patch note.

Correction: state that bound-row-field equality inherits §10's full conditions (snapshot currency, write invalidation, unconditional establishment), with the note retained otherwise.

## 5. Ack digest scope is undefined (invalidation hole)

§13.2 fingerprints "the ordered `(filename, bytes)` Quarry source set" and claims the conservative rule "makes rule/dependency changes require fresh review." The set is undefined: which files (app `snapback/*.q` only? transitive imported Quarry? ordering? relative-path normalization for a "shareable" cross-machine file?). If a dependency's Quarry is outside the digest, the claim is false and a rule change keeps stale acks.

Correction: define the exact digested set (recommend: app Quarry plus transitively imported Quarry, lexicographic `/`-separated relative paths), and either include transitive inputs or weaken the dependency claim. Also require site normalization to relative paths in fingerprints.

## 6. Dynamic-note sentence is vacuous (soundness)

"Dynamic readiness/adoption notes must still match the whole finding" defines no mechanism. If any note depends on inputs outside the digest (deployment/store state), fingerprint matching freezes a point-in-time claim.

Correction: enumerate which notes are dynamic and exclude them from acknowledgement, or state that all notes are pure functions of the digested inputs and delete the sentence.

## 7. JSON contract is under-specified (completeness)
