1. **High — Re-acquisition certifies retained images that were not re-acquired.**  
   [boundary.rs:42](/Users/ccheever/projects/snapback-w13-review/repo/snapback4/crates/snapback4-device/src/device/boundary.rs:42), [device.rs:910](/Users/ccheever/projects/snapback-w13-review/repo/snapback4/crates/snapback4-device/src/device.rs:910), [read.rs:692](/Users/ccheever/projects/snapback-w13-review/repo/snapback4/crates/snapback4-core/src/engine/read.rs:692).

   Consider `retain delivered-history`, `last 5`, initially containing p1 and p2. The device acquires both, leaves, and retains them. While it is outside the group, p2 is deleted. On rejoin, `group_at(join_seq)` selects only p1 and sends `whole`. The missed deletion lies outside its membership intervals, and applying the join does not remove p2. History becomes `Held`, while the new boundary certifies both physical rows. A descending page of three returns p2 and p1 with `complete: true`, although the server returns only p1. On base, this exhausted horizoned page is unknown and falls back.

   Moving a retained row below the new floor during the gap has the same problem: its stale local key can remain above the floor. The existing renewal test only moves the boundary upward while adding rows.

   **Smallest correct change:** distinguish rows confirmed by the current acquisition from retained historical copies, and exclude unconfirmed copies from the current suffix without deleting their point-read history. Until that distinction exists, re-acquiring such a retained group must remain unknown rather than accepting unconditional completeness.

2. **High — The floor discloses historical values from a withheld row.**  
   [partition.rs:716](/Users/ccheever/projects/snapback-w13-review/repo/snapback4/crates/snapback4-core/src/partition.rs:716), [partition.rs:636](/Users/ccheever/projects/snapback-w13-review/repo/snapback4/crates/snapback4-core/src/partition.rs:636), [current-image authorization:647](/Users/ccheever/projects/snapback-w13-review/repo/snapback4/crates/snapback4-core/src/partition.rs:647).

   Take two histories with p1 at 100, p3 at 3000, and p2 at either 800 or 2000. Bob joins a `last 2` group, then p2 is deleted before Bob receives anything. Both streams deliver the same surviving images and deletion IDs. The new completion nevertheless exposes p2’s old ordering value through its reversible hex key. Moving p2 into a now-unreadable group similarly suppresses its image but leaves its historical floor on the wire.

   Checking that the group currently has an open membership does not authorize the selected row’s withheld data. This conflicts with [LLP 3000’s current-readable-image rule](/Users/ccheever/projects/snapback-w13-review/repo/llp/3000-snapback4.explainer.md:651). The paired-world test adds unrelated hidden rows; it does not exercise this case.

   **Smallest correct change:** suppress a keyed completion whose source row is now absent or unreadable, leaving coverage unknown, or conservatively narrow the boundary using authorized selected evidence. Add the paired stream regression. Hex-to-base64 conversion would not address disclosure.

3. **Medium — A completion does not prove that intervening snapshot pages arrived.**  
   [device.rs:527](/Users/ccheever/projects/snapback-w13-review/repo/snapback4/crates/snapback4-device/src/device.rs:527), [boundary.rs:33](/Users/ccheever/projects/snapback-w13-review/repo/snapback4/crates/snapback4-device/src/device/boundary.rs:33), [boundary.rs:95](/Users/ccheever/projects/snapback-w13-review/repo/snapback4/crates/snapback4-device/src/device/boundary.rs:95).

   With snapshot pages `[p12,p11]`, `[p10,p09]`, `[p08]`, applying the first and last pages under the same owner and watermark passes validation. An empty catch-up then publishes floor p08 with only three rows. A descending page of three returns `[p12,p11,p08]` complete, skipping p10 and p09.

   The shipped TypeScript loop requests pages sequentially, so this is a device-protocol validation gap rather than an HTTP authentication bypass. Owner and watermark checks alone cannot detect it because every snapshot page shares those values.

   **Smallest correct change:** persist the expected snapshot continuation and validate a locally captured request cursor or page ordinal before accepting subsequent rows or completions. Require the terminal snapshot page before catch-up publication.

4. **Medium — Empty-group markers bypass pagination and can make acquisition impossible.**  
   [partition.rs:338](/Users/ccheever/projects/snapback-w13-review/repo/snapback4/crates/snapback4-core/src/partition.rs:338), [partition.rs:370](/Users/ccheever/projects/snapback-w13-review/repo/snapback4/crates/snapback4-core/src/partition.rs:370), [serve.rs:655](/Users/ccheever/projects/snapback-w13-review/repo/snapback4/crates/snapback4/src/serve.rs:655).

   Page room counts only row events. An empty group consumes no room but emits two markers. For example, 5,000 empty groups with valid 1,900-byte text group keys produce over 19 MB of repeated group strings alone. The response exceeds 16 MiB. Retrying with `limit: 1` emits the same markers and fails again; there is no usable continuation.

   **Smallest correct change:** charge acquisition/group transitions against the page budget and return a cursor after bounded progress even when no row event was emitted. Keep the response ceiling unchanged.

5. **Medium — Boundary lookup adds quadratic metadata parsing to group merges.**  
   [boundary.rs:88](/Users/ccheever/projects/snapback-w13-review/repo/snapback4/crates/snapback4-device/src/device/boundary.rs:88), [boundary.rs:18](/Users/ccheever/projects/snapback-w13-review/repo/snapback4/crates/snapback4-device/src/device/boundary.rs:18), [read.rs:897](/Users/ccheever/projects/snapback-w13-review/repo/snapback4/crates/snapback4-core/src/engine/read.rs:897).

   Each scan loads and deserializes the entire boundary map. A 1,000-group merge on the horizon index therefore parses at least **338,001,000 bytes of metadata** just to open its lanes, before refills. This is a source-derived work count, not a measured latency claim. Additionally, every ordinary stream page rewrites the whole map even when no boundary changed.

   **Smallest correct change:** load boundaries once per read/prediction transaction, or store independently addressable group entries; save only changed boundary state. This also limits persistence traffic without changing the protocol.

6. **Low — Retention copy still states the superseded completeness rule.**  
   [sync.rs:135](/Users/ccheever/projects/snapback-w13-review/repo/snapback4/crates/snapback4-lang/src/guide/sync.rs:135), [README.md:1283](/Users/ccheever/projects/snapback-w13-review/repo/snapback4/packages/snapback4/README.md:1283).

   Both paragraphs say an exhausted retained horizon is incomplete and reserve complete history for unbounded groups. The implementation preserves `whole` boundaries after leave and also recognizes bounded ranges wholly above a keyed floor as complete.

   **Smallest correct change:** update both retention sentences to describe boundary-based completeness, including `whole`. Also state explicitly that legacy replies without boundaries cause conservative local fallback; they do not preserve the previous local completeness behavior.
