1. **Protected native preimages lack lifetime custody.** [backfills.rs:209](/home/ccheever/projects/snapback-sb4loop/snapback4/crates/snapback4-core/src/store/backfills.rs:209) checks only the target type. Trigger: newer `owner: parents`, down `{owner:0}`, older `owner:int`. The receipt archives the native reference without a lifetime binding. Delete/reuse the parent under the older schema; forward restores the reference onto the replacement lifetime.

2. **Down reference inputs lack private lifetime bindings.** [backfills.rs:289](/home/ccheever/projects/snapback-sb4loop/snapback4/crates/snapback4-core/src/store/backfills.rs:289). Trigger: down consumes `parent:id` from a source `parent:parents` column; the older schema changes that column to `id`. Delete/reuse the parent, then return. The unchanged ID passes dependency comparison despite its lost lifetime. Forward backfills capture private bindings; down receipts do not.

3. **Forward patches leave stale dormant-cell overlays.** [backfills.rs:570](/home/ccheever/projects/snapback-sb4loop/snapback4/crates/snapback4-core/src/store/backfills.rs:570). Retire `x=0`, then restore it with `{x:x+1}` while narrowing another column so the row becomes dormant. Later widen that column while carrying the backfill. `_dormant_values.x=0` overwrites archived `x=1`; re-entry preserves `0` as an apparent edit.

4. **Re-narrowing can replace restored native absence with an older default.** [narrowed.rs:112](/home/ccheever/projects/snapback-sb4loop/snapback4/crates/snapback4-core/src/store/narrowed.rs:112). Create sparse `x` by adding `x:int default 7`; newer down projects `{x:1}`, older schema defaults `x` to `9`. Return newer while narrowing another column. After restoration removes `x`, narrowing materializes the older default and archives `x=9`. Widening later exposes `9` instead of the native absence/default `7`.

5. **Returning rows can permanently miss down eligibility.** [backfills.rs:816](/home/ccheever/projects/snapback-sb4loop/snapback4/crates/snapback4-core/src/store/backfills.rs:816). Seed `{count:5,gate:0}`, narrow `gate` to `1..10`, then add down `{count:7}` while the row remains hidden. Widen `gate` carrying that declaration, then leave it. Carried declarations skip marking the returned row, so projection is silently skipped and `count` remains `5`.

6. **Column retirement prevents assembly of receipt-owned P cells.** [backfills.rs:153](/home/ccheever/projects/snapback-sb4loop/snapback4/crates/snapback4-core/src/store/backfills.rs:153). Newer schema omits `reason` and declares down `{reason:label}`. Roll back to a schema containing `reason`, then select another schema omitting it, then return newer. The unchanged projected cell exists in `_dormant_values`, but source assembly excludes it because newer omits the column. Physical P verification falsely reports a conflicting edit.

7. **Down lookups use stale indexes after source restoration.** [backfills.rs:278](/home/ccheever/projects/snapback-sb4loop/snapback4/crates/snapback4-core/src/store/backfills.rs:278). Narrow a dependency row out of visibility, then leave a down declaration while widening that dependency’s type. Source assembly restores the row into `r`, but its unique index remains empty. An asserted down lookup falsely refuses; an explicit nullable branch can produce the wrong result. Index rebuilding in `retire_snapshot` occurs only when expiry is due.

8. **Out-of-domain dependency edits bypass conflict detection.** [backfills.rs:160](/home/ccheever/projects/snapback-sb4loop/snapback4/crates/snapback4-core/src/store/backfills.rs:160). Newer declares `n:1..10`, with down `{x:n}`; older permits `n:0..10`. After rollback, edit `n` from `5` to `0`, leaving projected `x` unchanged. Forward skips the conflict because `0` fails newer validation, restores native `x`, and merely hides the row. A later widening exposes the conflicting pair.
