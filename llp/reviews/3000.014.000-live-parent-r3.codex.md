1. **High — §5’s heap reservation does not bound the specified index replacement.**

   Both SQLite and Postgres call [`index_write`](/home/ccheever/projects/sb4-w14-live/snapback4/crates/snapback4-core/src/rows.rs:36), which materializes every index’s old and new key vectors together, including unchanged indexes. The proposed heap term depends on `N` and `R`, but not on index count or generated key bytes.

   **Counterexample:** With `N=1`, give a small child row hundreds of distinctly named indexes over the same bounded text field. `R` and the event allowance remain essentially unchanged; the retained old/new key buffers grow with every index. The index-entry reservation can remain below its existing ceiling while those buffers exceed the proposed heap reservation. Assets and serialized private-row decoding also need bounds beyond the shallow-copy calculation in `row_copy_ceiling`.

   **Smallest precise repair:** Replace the heap formula with a schema-derived bound covering private-row decode, retained scan results, replacement images, all simultaneously retained index keys, serialization scratch and retained event bookkeeping. Alternatively, specify an index replacement algorithm that streams keys with a separately bounded working set. Give the internal prepaid ledger an explicit limit; an unbounded internal meter plus later tests does not establish this reservation.

2. **High — The source reservation and prediction fence do not yet compose through referential actions.**

   The shared `row_changed` tail is a suitable maintenance location, but it is too late to establish an indirect writer’s reservation or prediction classification. Existing [`unit_write`](/home/ccheever/projects/sb4-w14-live/snapback4/crates/snapback4-core/src/schema/references.rs:348) sums the existing reservation phases and treats `server_only` as absence of a usable fixed action price. [`action_tables`](/home/ccheever/projects/sb4-w14-live/snapback4/crates/snapback4-core/src/schema/references.rs:118) does not include live-maintenance destinations.

   **Counterexample:** A live parent also has an optional, non-authority reference with `on delete set null` and its required cap. Deleting that reference’s target rewrites the live parent indirectly. Revision 3 requires its full maintenance reservation even though this patch changes no policy field. A root delete may reach zero or several such parents. Charging live work only inside each reached parent attempt makes charges depend on that hidden population; omitting it underprices the closure. Reusing the existing `server_only` flag instead causes action admission to reject the supposedly fixed-price writer.

   **Smallest precise repair:** Define composition of `live.price` into the maximum reference-action reservation, including physical allowance, retained events and affected tables, before closure enumeration. Expand mutation prediction classification through the same conservative effect closure. Distinguish “fixed-price, server execution required” from “no fixed price available.”

3. **High — Rollback to the manual recipe can restore stale authority columns.**

   §7 specifies manual-to-live correspondence and live-to-captured recapture, but does not define live-to-manual reconciliation. Existing restoration reinstalls dormant authored cells, while the through-specific consistency checks apply only when the destination still has `Through`: [`dormant.rs`](/home/ccheever/projects/sb4-w14-live/snapback4/crates/snapback4-core/src/store/dormant.rs:500), [`through_activation.rs`](/home/ccheever/projects/sb4-w14-live/snapback4/crates/snapback4-core/src/engine/through_activation.rs:227).

   **Counterexample:** Adopt the shipped manual recipe while parent and child both name department A. Removing the authored child department column retains A in dormant storage. Live maintenance later transfers the parent and private child copies to B. Rollback restores the manual column as A. Department A still exists, so ordinary reference/type/cap validation passes; the destination has no `Through` to trigger capture comparison. The former roster regains the child.

   **Smallest precise repair:** Define the reverse transition using the predecessor’s parent/reference metadata and a destination-rule correspondence. Before dropping live captures or publishing restored authored columns, require those columns to match the current parent; otherwise refuse atomically with the bridge-release repair. Explicitly cover rollback and dormant restoration into a manual destination.

4. **High — A fixed page of 256 decoded rows is not activation memory admission.**

   The referenced through-adoption [`rows` helper](/home/ccheever/projects/sb4-w14-live/snapback4/crates/snapback4-core/src/engine/through_activation.rs:91) materializes raw decoded pages. Page count alone does not keep that work within existing heap ceilings.

   **Counterexample:** There are 256 parents, each with one child containing approximately 100 KiB of text. Every per-parent cap is satisfied, and individual operations can fit. One proposed adoption page nevertheless retains over 25 MiB of payload before accounting for decoding, parent lookups, rewritten images or indexes.

   **Smallest precise repair:** Specify adaptive, byte-admitted activation pages using the existing [`activation_walk`](/home/ccheever/projects/sb4-w14-live/snapback4/crates/snapback4-core/src/store/activation_walk.rs:12) machinery or an equivalent bounded walker. Include parent fetches and rewrite/index scratch in that page’s ledger, shrink before callbacks execute, and refuse a non-fitting singleton before writing.

5. **Medium — The claimed existing activation timeout/rollback contract is not an execution timeout.**

   [`open_engine`’s timeout](/home/ccheever/projects/sb4-w14-live/snapback4/crates/snapback4/src/store_owner.rs:186) reaches SQLite’s busy timeout. It bounds lock waiting, not activation execution. Release control explicitly says that a timed-out or disconnected peer does not cancel admitted work: [`release_control.rs`](/home/ccheever/projects/sb4-w14-live/snapback4/crates/snapback4/src/release_control.rs:275).

   **Counterexample:** A large activation acquires the writer lock and continues scanning after the operator request times out. It may later commit; the claimed timeout-triggered rollback and continued usability of the prior store have not been established.

   **Smallest precise repair:** Define an activation execution deadline, cancellation checks between bounded pages, interruption of long SQL work, and rollback before reporting deadline failure. Identify the owner of that deadline and its relationship to request disconnection.
