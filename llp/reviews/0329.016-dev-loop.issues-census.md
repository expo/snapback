### 1.2 Cause-type roll-up

- **(a) Product-design causes** dominate the agent-facing classes 2-6, 8, 9, 12: the loop's shape (file-borne multi-process state, content-addressed generated custody, prose-authority guide, a diagnostics vocabulary larger than its documentation, sessions-mode identity semantics leaking into every dev convenience, a 13-package closure) induces the ticket even when each component is correct.
- **(b) Implementation bugs** are concentrated in class 7 (live delivery) and the specific wedges in classes 3 and 13. Notably, several headline "defects" (cross-client fanout, table-query blank) were not reproduced as engine bugs; they were harness/custody artifacts or remain undiagnosed — but they still cost every lane.
- **(c) Process/verification-infra** is by far the largest by volume (classes 1, 10, 11: ~300 open, ~830 closed by overlapping slug count) and almost entirely invisible to an app-building agent. It is the direct cost of the LLP 0189/0232 frozen-record, fix-forward, claim-snapshot design running on a `main` that moves continuously.

## 5. Cross-cutting mechanisms (what a from-scratch design must not reproduce)

1. **Frozen records over a moving `main`.** The single largest ticket generator. Digests, review manifests, receipts, line-pinned registries, calendar review dates and claim snapshots are each a correct fail-closed check; together, on a `main` that moves ~50 commits per fix round, they produce hundreds of machine-minted tickets and per-lane re-derivation of the same reds. Snapback 2 should have very few committed projections, none keyed on volatile coordinates, and gates keyed on content scope.
2. **The tightest feedback in the loop is a typed refusal, but refusal -> fix is a dead end.** 17 tickets say outright that a fact was learned by refusal, probing, or reading `node_modules`; ~12% of ~2,400 codes were documented when measured; the code -> doc lookup dead-ended. The loop's design relies on refusals as the teaching surface and then under-invests in what the refusal carries.
3. **Multi-process choreography with state in sidecar files.** Backend, codegen watcher, Metro, bootstrap exchange, binding mint, `.snapback/{dev.ready,expo-supervisor,startup-artifacts}.json`: every stale sidecar, moved port, watched temp dir, or rotated digest became a ticket, and the recovery ("kill Metro", "delete the ready file", "restart the supervisor") was learned, not diagnosed.
4. **Generated code as custody artifact.** Content-addressed `generated/`, review manifests, a gitignored cache, and boot-time identity admission mean a fresh tree cannot run anything until it has regenerated, every emitter change dirties every corpus, and bundlers choke on the emitted grammar. The design choice (deployment identity is a hash of generated bytes) is sound; making the agent carry it is not.
5. **Prose authority with hand-maintained freshness.** The guide is declared the source of paved forms (CLAUDE.md), yet 45/65 pages carried stale-authority warnings and pages taught primitives the published closure lacked. Where a fact can be projected from code (script glossary, published closure, diagnostic anchors), the tickets consistently moved it there.
6. **Silent success outranks loud failure as a cost driver.** Codegen `ok` on contradictions, queued writes resolving like commits, default acceptance passing without a server, tests that cannot fail, gates masked by `| tail`. Every one of these consumed hours because nothing said anything.
7. **Published vs. in-tree.** Agents run the published closure; fixes land on `main`; tickets stay open "for the published-path bar" (`snapback init`, expo-chat fixes, guide corrections). The rapid-publish ruling (LLP 0041) exists because of this; the loop still treats publication as a ceremony (`fastpath-release-isolate-not-buildable`, `store-qualification-template-portfolio-receiptless`).
8. **Sessions-mode identity semantics leak into every dev convenience.** Reset, mint, `ensureApp`, storage partition, supervised session, signup ordering: each is correct in isolation and each surprised a builder. The correct primitive existed every time; the default did not fit the ordinary multi-persona agent case.
