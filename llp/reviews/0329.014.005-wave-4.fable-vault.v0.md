# Vault (1Password/Bitwarden-class) in v0.1 — paper archetype, wave 4 #2

Written against LLP 0329.014.000 v0.1 with the §9.1 rulings applied. Constructs from LLP 0329.014.004 v1.1 are used as if in the spec and marked **(v1)**. Ceilings are unpublished; I assume **[inferred]** `G_examined = 10,240`, `G_steps = 2×10^5`. Shorthand: `exam≤N` counts index entries with halo (`take+2`); `W≤n` writes; prefixes `a` arg, `v` viewer, `s` shape (field of a traced row). Product caps used throughout: ≤ 64 field operations and ≤ 64 parents per revision, ≤ 16 conflict domains per item, ≤ 256 recipient mailboxes per delivery (group epochs above that), ≤ 32 devices per person, ≤ 32 group bindings per principal.

The design splits into two planes, and the split is the report. **S** is the server plane — accounts, mailboxes, blobs, receipts, one timer — an ordinary v0 data plane. **D** is the device plane — every table the design encrypts, which is every table with item semantics. Premise codes in the class column: **F** store-wide offline fence · **R** rules the server evaluates · **A** one server authority · **O** trace as OCC/settlement · **C** trace as the offline closure.

### 2. Schema in v0

**S plane (ordinary data plane).** `authenticated()` is v1's authenticated-but-not-public spelling **[inferred name]**; `bytes({ maxBytes })` is v0's `json({ maxBytes })` — opaque to rules and indexes, which is exactly the point.

```ts
export const accounts = table({ id: id(), tier: text({ max: 16 }), quotaBytes: int(), createdAt: time() })
  .rules({ read: a => db.exists(accountMembers.byAccountUser, [a.id, viewer]), insert: authenticated('signup'),
           update: (o, n) => isAccountAdmin(o.id) && n.id === o.id, delete: never })
export const accountMembers = table({ accountId: ref(accounts), userId: id(), role: text({ max: 8 }) })
  .unique('byAccountUser', ['accountId', 'userId']).index('byUser', ['userId'])
  .rules({ read: m => m.userId === viewer || isAccountAdmin(m.accountId), insert: m => isAccountAdmin(m.accountId),
           update: (o, n) => isAccountAdmin(o.accountId) && n.accountId === o.accountId, delete: m => isAccountAdmin(m.accountId) })
  .constraints(cap({ by: 'accountId', max: 65536 }))
export const mailboxes = table({ id: id(), accountId: ref(accounts), kind: text({ max: 8 }) })   // device | group | recovery
  .index('byAccount', ['accountId'])
  .rules({ read: m => db.exists(mailboxGrants.byMailboxPrincipal, [m.id, viewer]), insert: m => isAccountMember(m.accountId),
           update: never, delete: m => isAccountAdmin(m.accountId) })
  .constraints(cap({ by: 'accountId', max: 262144 }))
export const mailboxGrants = table({ mailboxId: ref(mailboxes), principalId: id() })      // transport principals = devices
  .unique('byMailboxPrincipal', ['mailboxId', 'principalId'])
  .rules({ read: g => g.principalId === viewer, insert: g => isMailboxOwner(g.mailboxId), update: never, delete: g => isMailboxOwner(g.mailboxId) })
export const routeTokens = table({ token: id(), mailboxId: ref(mailboxes) })              // opaque delivery capability
  .unique('byToken', ['token'], { bearer: true })                                          // v1: possession is the rule input
  .rules({ read: never, insert: t => isMailboxOwner(t.mailboxId), update: never, delete: t => isMailboxOwner(t.mailboxId) })
export const blobs = table({
  id: id({ contentAddressed: true }),                        // §6 #4 — v0 has only random client-mintable id()
  accountId: ref(accounts), ciphertext: bytes({ maxBytes: 4_194_304 }), paddedLen: int(),
  uploadedAt: time({ commitTime: true }), gcCapHash: text({ hashed, max: 64 }),
}).rules({ read: b => db.exists(deliveries.byBlobPrincipal, [b.id, viewer]), insert: b => isAccountMember(b.accountId),
           update: never, delete: b => principal.kind === 'system' })
  .constraints(appendOnly({ except: 'gc' }), cap({ sum: 'paddedLen', by: 'accountId', maxFrom: accounts.quotaBytes }),
               check(b => b.paddedLen === b.ciphertext.byteLength && isPowerOfTwo(b.paddedLen)),
               rateLimit({ by: viewer, per: '1m', max: 600 }))
  .audited(into: fetchLog)                                   // v1: server-observed fetch activity — promise 7, not promise 19
export const deliveries = table({ id: id(), toMailboxId: ref(mailboxes), blobId: ref(blobs),
    deliverySeq: int({ sequence: by: 'toMailboxId' }),      // v1 engine sequence — a TRANSPORT cursor only; nothing on D reads it
    pointer: bytes({ maxBytes: 256 }), routeToken: id() })
  .index('byMailboxSeq', ['toMailboxId', 'deliverySeq'])
  .rules({ read: d => db.exists(mailboxGrants.byMailboxPrincipal, [d.toMailboxId, viewer]),
           insert: d => db.get(routeTokens.byToken, d.routeToken)?.mailboxId === d.toMailboxId, update: never, delete: never })
  .replica({ index: 'byMailboxSeq', order: 'asc', watermarkColumn: 'deliverySeq', maxBytes: 2 ** 34 })   // v1.1 — under the fence
maintain.sum(blobs, { by: ['accountId'], of: 'paddedLen', as: accountUsage, readable: b => isAccountAdmin(b.accountId) })  // K2 declared
export const checkpointReceipts = table({ id: id(), mailboxId: ref(mailboxes), root: text({ max: 64 }), receivedAt: time({ commitTime: true }) })
  .index('byMailbox', ['mailboxId', 'receivedAt']).rules({ read: r => hasMailbox(r.mailboxId), insert: r => hasMailbox(r.mailboxId), update: never, delete: never })
export const releaseRequests = table({ id: id(), grantRef: text({ hashed, max: 64 }), delegateMailboxId: ref(mailboxes), ownerMailboxId: ref(mailboxes),
    requestedAt: time({ commitTime: true }), vetoMs: int(), status: enum(['waiting', 'vetoed', 'released'], { transitions: { waiting: ['vetoed', 'released'] } }),
    tokenHash: optional(text({ hashed, max: 64 })) })
  .index('byOwner', ['ownerMailboxId', 'status'])
  .rules({ read: r => hasMailbox(r.delegateMailboxId) || hasMailbox(r.ownerMailboxId), insert: r => hasMailbox(r.delegateMailboxId),
           update: (o, n) => (hasMailbox(o.ownerMailboxId) && n.status === 'vetoed') || principal.kind === 'system', delete: never })
export const releaseTokens = table({ id: id(), requestId: ref(releaseRequests) }).unique('byId', ['id'], { bearer: true })
  .rules({ read: never, insert: t => principal.kind === 'system', update: never, delete: t => principal.kind === 'system' })
```

**What the server can and cannot evaluate over ciphertext rows — exactly.** It can evaluate (i) transport rules: mailbox grants and route-token possession — *who may put bytes where and take bytes from where*; (ii) plaintext-column constraints: content address equals digest (asset `verify`), padded length is a power of two, per-account byte sum under quota, rate limits, append-only with system GC; (iii) time witnessing: `commitTime` receipts and one schedule; (iv) engine transport sequences per mailbox. It cannot evaluate any item-level rule — read, edit, share, delete, admin — nor head-ness, ancestry, authorship validity, epoch membership, tombstone state, or any per-item cardinality, because none of those is a column. Item-level rules are not `E_RULE_MISSING`; they are rules on tables that do not exist on this plane. If a designer materializes them (the `editItem` first attempt in §3), `check` admits every rule and every program: **the language has no way to state that the server is not in a table's audience**, because the server is in every column's audience by construction. That is the axis the schema cannot state (§6 #1).

**D plane** — declared inside the construct that does not exist:

```ts
export const vault = partition('vault', {                    // §6 #1
  authority: 'device',        // the running replica commits; no settlement, no OCC, no `rejected`
  horizon: 'unbounded',       // no maxOfflineAge for these tables; retention is causal (key epochs), never temporal
  serverProjection: 'blobs',  // the server holds this partition only as blobs/deliveries: opaque bytes
  transports: ['mailbox', 'peer', 'bundle'],
  merge: 'dag',               // concurrent writes are heads; a resolution is a revision naming its parents
  ingest: ingestBlob,
})
// identity and governance (decrypted projections, all appendOnly): principals, identityCommits, governanceCommits(parents edge table),
// deviceCerts { id, principalId, signingKey, encryptionKey, admittedBy }, principalEpochs, vaults, items { id, vaultId, itemAlias },
// policyCommits { id, itemId, signerSet }, policyParents(child, parent), policyGrants { policyCommitId, itemId, subjectId, rights: int, historyFloor },
// effectivePolicy { itemId, subjectId, rights, policyHeads, disputed: bool }  .versioned()  // v1 — written by resolvePolicyHeads, read `asOf` a head
// removedSubjects { itemId, subjectId, atPolicyCommit }, itemKeyEpochs { id, itemId, parent }, epochAncestry(pair), envelopes, chunkRefs,
// branchBases { itemId, headId, baseId }, conflictDomains { itemId, id }, purgeBarriers, recoveryPolicies, emergencyGrants(+parents),
// auditEvents, auditParents, auditCheckpoints, deviceFrontiers { deviceId, seq }, travelProfiles, externalChangeIntents, siteReceipts,
// readEvents (telemetry), ingestQueue { blobId, state: locked|pending|…, waitingOn }, outbox { revisionId, state, perPeer: json }
export const revisions = table({
  id: id({ contentAddressed: true }), itemId: ref(items), kind: enum(['content', 'merge', 'tombstone', 'restore']),
  policyHead: ref(policyCommits), keyEpoch: ref(itemKeyEpochs), authorDeviceId: ref(deviceCerts), authorPrincipalId: ref(principals),
  authorSeq: int({ sequence: by: 'authorDeviceId', authority: 'device' }),      // §6 #5
  previousDeviceEvent: optional(id()), claimedAt: time(), signature: bytes({ maxBytes: 128 }),
  state: enum(['accepted', 'conflicted', 'staleAuthority', 'invalid']),
}).index('byItem', ['itemId', 'authorDeviceId', 'authorSeq']).unique('byAuthorSeq', ['authorDeviceId', 'authorSeq'])
  .rules({ read: r => hasRight(r.itemId, 'read'),
           insert: r => r.authorDeviceId === principal.device && r.authorPrincipalId === viewer && hasRight(r.itemId, 'edit'),
           update: (o, n) => principal.kind === 'ingest', delete: never })
  .constraints(appendOnly({ except: 'state' }), immutableExcept({ fields: ['state'], when: principal.kind === 'ingest' }),
               chain({ by: 'authorDeviceId', prev: 'previousDeviceEvent' }))                                      // §6 #5
export const revisionParents = table({ childId: ref(revisions), parentId: ref(revisions) })
  .index('byChild', ['childId']).index('byParent', ['parentId']).constraints(appendOnly(), cap({ by: 'childId', max: 64 }))
  .rules({ read: e => canReadRevision(e.childId), insert: e => canReadRevision(e.childId), update: never, delete: never })
export const fieldOps = table({ id: id(), revisionId: ref(revisions), fieldId: id(), domainId: id(), op: text({ max: 8 }),
    ciphertext: bytes({ maxBytes: 65536 }), tag: text({ max: 16 }) })
  .index('byRevision', ['revisionId']).constraints(appendOnly(), cap({ by: 'revisionId', max: 64 }))
maintain.rows(heads, { from: revisions, key: ['itemId', 'id'],
  where: r => r.state === 'accepted' && !db.exists(revisionParents.byParent, [r.id]) })        // §6 #6: negated exists in where
maintain.rows(headOpsByDomain, { from: fieldOps, join: heads, key: ['itemId', 'domainId', 'revisionId'] })
export const auditEvents = table({ id: id(), vaultId: ref(vaults), actorDeviceId: ref(deviceCerts), deviceSeq: int({ sequence: by: 'actorDeviceId', authority: 'device' }),
    action: text({ max: 16 }), itemAlias: id(), details: bytes({ maxBytes: 4096 }), policyHead: id(), mutationCommit: id(), signature: bytes({ maxBytes: 128 }) })
  .index('byDeviceSeq', ['actorDeviceId', 'deviceSeq']).constraints(appendOnly(), chain({ by: 'actorDeviceId', prev: 'mutationCommit' }))
  .rules({ read: e => isAuditor(e.vaultId) || e.actorDeviceId === principal.device, insert: e => e.actorDeviceId === principal.device, update: never, delete: never })
coupled(revisions, { onInsert: exactlyOne(auditEvents, e => e.mutationCommit === r.id) })    // v1 event-coupled: invariant 9 as a constraint
export const externalChangeIntents = table({ id: id(), itemId: ref(items), baseHeads: json({ maxBytes: 4096 }), origin: text({ max: 256 }),
    oldCandidate: bytes({ maxBytes: 4096 }), newCandidate: bytes({ maxBytes: 4096 }), remoteReceiptHash: optional(text({ hashed, max: 64 })),
    state: enum(['prepared', 'submitted', 'ambiguous', 'confirmed', 'abandoned'], { transitions: { prepared: ['submitted'], submitted: ['ambiguous', 'confirmed', 'abandoned'], ambiguous: ['confirmed', 'abandoned'] } }) })
  .constraints(coupledTransition({ to: 'confirmed', requires: exactlyOne(siteReceipts) }))    // v1 — invariant 20
```

`hasRight(item, right)` is `existsAny(effectivePolicy.byItemSubjectRight, { principalIn: viewer.bindings, key: [item, right] })` **(v1 N)** — the rule language fits device-side authorization exactly, once the rows it reads exist.

### 3. Operations in v0

**Server plane, common to every hard operation (transport).**

`uploadBlob`:

```ts
export const uploadBlob = mutation(
  { accountId: id(accounts), ciphertext: bytes({ maxBytes: 4_194_304 }),
    to: list({ mailboxId: id(mailboxes), routeToken: id(), pointer: bytes({ maxBytes: 256 }) }, { max: 256 }) },
  ({ db, ctx, args }) => {
    const slot = db.assets.verify(args.ciphertext)                          // v1 asset seam: digest, padded length, GC capability
    db.insert(blobs, { id: slot.digest, accountId: args.accountId, paddedLen: slot.paddedLen, gcCapHash: slot.gcCapHash })
    for (const t of args.to) db.insert(deliveries, { id: ctx.newId(), toMailboxId: t.mailboxId, blobId: slot.digest, pointer: t.pointer, routeToken: t.routeToken })
  })
```

`exam≤262` (256 route-token probes + unique + halo); `W≤258`; prediction `conditional(cap, unique)`. The sum-cap is the quota; `E_CONSTRAINT` is sealed. Prediction is conditional and honest: the device cannot know the account's total.

`fetchMailboxSince` — first attempt `db.scan(deliveries.byMailboxSeq, [m], { take: 250000 })` for the design's "250,000 missing objects" is refused: `E_BOUND: examined 250,002 > G_examined 10,240 (product: take 250000 + 2). Rewrite: declare replica() on deliveries.byMailboxSeq and page after the watermark.` Corrected: `db.scan(deliveries.byMailboxSeq, [args.mailboxId], { order: 'asc', after: args.after, take: 500 })`, `exam≤502`, completeness `replica`; 250k objects are 500 admitted pages. `deliverySeq` is arrival order and invariant 4 holds only because *no D-plane program reads it* — §6 #8 would let the certificate say so.

`releaseAfterVeto` (op 11, delayed mode) — first attempt:

```ts
export const canRelease = query({ requestId: id(releaseRequests) }, ({ db, ctx, args }) => {
  const r = db.get(releaseRequests, args.requestId)
  return r !== null && ctx.now() >= r.requestedAt + r.vetoMs      // E_AMBIENT_TIME
})
```

`E_AMBIENT_TIME at ctx.now(): queries have no clock; "released after the veto window" is a durable transition. Rewrite: schedule(releaseAfterVeto, { at: r => r.requestedAt + r.vetoMs, key: r => r.id, principal: 'system' }) flipping status.` Corrected:

```ts
export const releaseAfterVeto = mutation({ requestId: id(releaseRequests) }, { callable: 'system' }, ({ db, ctx, args }) => {
  const r = db.get(releaseRequests, args.requestId)
  if (r === null || r.status !== 'waiting') return                                    // vetoed meanwhile: idempotent no-op
  const token = ctx.newId()                                                            // server-minted; delivered to the delegate's mailbox as a blob by an effect
  db.update(releaseRequests, r.id, x => ({ ...x, status: 'released', tokenHash: digest(token) }))
  db.insert(releaseTokens, { id: token, requestId: r.id })
})
schedule(releaseAfterVeto, { at: r => r.requestedAt + r.vetoMs, key: r => r.id, principal: 'system', if: r => r.status === 'waiting' })
```

This is the cleanest fit in the app: invariant 17's "named trusted time witness" *is* v0's system principal with `commitTime`; the design's insistence that delayed mode is not outage-independent is exactly dimension B. Trustee mode never touches S.

**Hard op 1 — unlock, search, read, autofill offline.** `unlockKeyring` is a device seam. `searchItems` cannot be written honestly at all in v0: there is no `title` column anywhere the server can index. Written *dishonestly* — `items` with a plaintext `title: text({ max: 256 })` and `tokens('title')` — `check` admits it and promise 6 is gone. The honest form is the same query with `runsOn: 'device'` over the partition: `db.scan(items.byToken, [term], { take: 50 })` then a `heads` point read per row, `exam≤52`, evaluated by the device against its own store. **[inferred]** whether the v0 client store maintains `tokens` indexes locally; the server engine does, which is one reason the partition needs the server's storage engine on the device (§6 #1). `autofillCandidates` scans `items.byOrigin take 50`, reads `headOpsByDomain` for the credential domain, and returns `{ item, heads, conflicted: heads > 1 }` — the UI never picks (op 1's rule); the program cannot, because choosing would be a `take 1` maximum, which is ruling 8's structural fact and invariant 4's violation in one line.

**Hard op 2 — create or edit an item.** First attempt, on S, the way an agent would write it:

```ts
export const editItem = mutation(
  { itemId: id(items), baseHeads: list(id(revisions), { max: 64 }), policyHead: id(policyCommits),
    ops: list({ fieldId: id(), domainId: id(), op: text({ max: 8 }), ciphertext: bytes({ maxBytes: 65536 }), tag: text({ max: 16 }) }, { max: 64 }),
    claimedAt: time() },
  { runsOn: 'device' },
  ({ db, ctx, args }) => {
    const epoch = db.get(currentItemEpoch, [args.itemId]); db.require(epoch !== null, 'NO_EPOCH')
    for (const h of args.baseHeads) db.require(db.exists(heads.byItemHead, [args.itemId, h]), 'STALE_HEAD')
    const seq = ctx.deviceSeq()                                                     // §6 #5: device-authority sequence
    const record = canonical({ ...args, keyEpoch: epoch.id, authorDeviceId: principal.device, authorSeq: seq })
    const revId = digest(record), sig = device.sign(record)                          // §6 #2 / v1 digest
    db.insert(revisions, { id: revId, itemId: args.itemId, kind: 'content', policyHead: args.policyHead, keyEpoch: epoch.id, authorDeviceId: principal.device,
      authorPrincipalId: viewer, authorSeq: seq, previousDeviceEvent: ctx.previousDeviceEvent(), claimedAt: args.claimedAt, signature: sig, state: 'accepted' })
    for (const h of args.baseHeads) db.insert(revisionParents, { childId: revId, parentId: h })    // heads moves in this commit
    for (const o of args.ops) db.insert(fieldOps, { id: ctx.newId(), revisionId: revId, ...o })
    db.insert(auditEvents, { id: ctx.newId(), vaultId: epoch.vaultId, actorDeviceId: principal.device, deviceSeq: seq, action: 'edit',
      itemAlias: epoch.itemAlias, details: device.encrypt(epoch.auditKey, args.ops.length), policyHead: args.policyHead, mutationCommit: revId, signature: device.sign(revId) })
    db.insert(outbox, { id: ctx.newId(), revisionId: revId, state: 'queued', perPeer: {} })
  })
```

`exam≤70` (64 head probes + epoch + hoisted rule); `W≤131`; maintained amplification `heads −64/+1`. Invariant 9 — revision, dependencies, audit commitment, outbox *in one transaction* — is what a mutation *is*; the design states it as an obligation, the language makes it structural. Prediction is n/a: there is no `predicted`; the device commit is the commit.

**Hard op 3 — synchronize after any partition.** `ingestBlob`, per delivered object:

```ts
export const ingestBlob = mutation({ blobId: id(), ciphertext: bytes({ maxBytes: 4_194_304 }) }, { runsOn: 'device', callable: 'ingest' }, ({ db, ctx, args }) => {
  db.require(digest(args.ciphertext) === args.blobId, 'DIGEST')                                   // content address, verifiable on both planes
  const env = device.open(args.ciphertext)                                                         // §6 #2: { kind, record, signer } or null
  if (env === null) { db.insert(ingestQueue, { blobId: args.blobId, state: 'locked' }); return }    // invariant 14: locked, never empty
  if (env.kind !== 'revision') return ingestOther(env)                                             // policy / epoch / governance / audit: same shape
  const r = env.record
  for (const p of r.parents) if (!db.exists(revisions.byId, [p])) { db.insert(ingestQueue, { blobId: args.blobId, state: 'pending', waitingOn: p }); return }
  db.require(device.verify(r.signature, db.get(deviceCerts, r.authorDeviceId)?.signingKey), 'SIG')
  // invariant 5: capability under the policy head THE REVISION NAMES, for THE AUTHOR — neither `viewer` nor the current head
  const ok = db.evaluate(revisions.rules.insert, { as: r.authorPrincipalId, asOf: r.policyHead, row: r })   // §6 #3 — does not exist
  const removed = db.exists(removedSubjects.byItemSubject, [r.itemId, r.authorPrincipalId])
  const bridged = db.exists(epochAncestry.byPair, [r.keyEpoch, db.get(currentItemEpoch, [r.itemId])?.id])
  const state = !ok ? 'invalid' : removed && !bridged ? 'staleAuthority' : 'accepted'              // promise 16: quarantine, never silent entry
  db.insert(revisions, { ...r, state })                                                             // chain() refuses equivocation: sealed E_CONSTRAINT
  for (const p of r.parents) db.insert(revisionParents, { childId: r.id, parentId: p })
  for (const o of r.ops) db.insert(fieldOps, o)
})
```

`exam≤140`; `W≤130`. The 250k backlog is a device `job` over `ingestQueue` in 200-row chunks with a watermark **(v1)** — the certificate bounds the *program*, the job bounds the *backlog*, and neither bounds a hostile peer's flood: that is quotas and rate limits on S, as the design's §6 says.

> **The eight-state machine at day 400, with local edits — exactly.** Under v0.1 + v1.1 as written, D-plane tables *never enter* the machine: the server holds no item row, so no query it could certify returns one; `readItem` is `hydrating` from day 0 with nothing to hydrate. The machine is not wrong here — it is unreached. S-plane tables do enter it: `deliveries`/`blobs` reads are `stale` (exact over the local mailbox replica, unconfirmed) until the fence; offline uploads are `queued`. At the fence — day 1 by the v0 default, day 7 or 30 by the hard maximum; `replica` and `retain` leases sit **under** the fence (RFC §2.1 F) — the store is sealed: reads become `hydrating` with no network, pre-fence intents stay `queued` (v0 has no outbox age, §6 #9), and a post-fence edit cannot even be *predicted*, because the program's local reads are refused — there is no intent state for it; the client refuses the write. **Day 400 = reads `hydrating`, intents `queued`, and roughly 393 days of refused writes.** On reconnect the S plane recovers completely — re-authorize, evict, replay; every upload is an idempotent content-addressed append, so all `queued` become `committed`. That is the interesting half: *the blob plane survives an arbitrary partition under the ordinary contract*; only the item plane cannot live under it. With §6 #1, D-plane reads are `local(frontier)` and D-plane writes are `committed` at the device and then carry a **per-peer vector** `queued → uploaded → delivered → accepted | conflicted | staleAuthority | invalid` — six delivery states, none of them `predicted`, none of them `rejected` (invariant 10 forbids rejection). Prediction 2's "gains an `authoritative-local` state" is wrong in shape: one added state cannot carry it, because the intent half of the machine presupposes a settling authority.

**Hard op 4 — resolve content conflicts.** First attempt finds the common ancestor by walking parents:

```ts
const ancestor = recurse(args.heads, id => db.scan(revisionParents.byChild, [id], { take: 64 }).map(e => e.parentId), { depth: 4096, fanout: 64 })
```

`E_BOUND: recurse bound 1 + 64 + … + 64^4096 (ruling 6) exceeds G_examined. Rewrite: the fork point is known when the branch is created — store it (branchBases) and point-read it.` The design already says a device "retains its own branch bases"; the strict language says why. Corrected:

```ts
export const resolveConflict = mutation(
  { itemId: id(items), heads: list(id(revisions), { max: 64 }), choices: list({ domainId: id(), keepFrom: id(revisions) }, { max: 16 }),
    preserve: list(id(), { max: 16 }), ops: list(/* as editItem */, { max: 64 }), policyHead: id(policyCommits), claimedAt: time() },
  { runsOn: 'device' },
  ({ db, ctx, args }) => {
    for (const h of args.heads) db.require(db.exists(heads.byItemHead, [args.itemId, h]), 'NOT_A_HEAD')       // invariant 11: only named heads resolve
    db.require(db.get(branchBases, [args.itemId, args.heads[0]]) !== null, 'NO_BASE')
    for (const d of db.scan(conflictDomains.byItem, [args.itemId], { take: 16 })) {
      const competing = db.scan(headOpsByDomain.byItemDomain, [args.itemId, d.id], { take: 64 })
      if (competing.length > 1) db.require(args.choices.some(c => c.domainId === d.id) || args.preserve.includes(d.id), 'DOMAIN_UNRESOLVED')   // promise 13
    }
    if (args.heads.some(h => db.get(revisions, h)?.kind === 'tombstone')) db.require(args.choices.some(c => c.domainId === TOMBSTONE), 'TOMBSTONE_IS_A_DECISION')  // invariant 13
    // then editItem's tail with kind: 'merge', parents = args.heads
  })
```

`exam≤1,140` (16 × 66 + 64 + 18); `W≤131`. Determinism cuts both ways here: two devices running the *automatic* disjoint-domain merge compute identical plaintext (the TS twin is byte-identical by construction), but each emits a differently keyed, differently signed revision — §8 #2.

**Hard op 5 — grant item-level access.** `grantAccess(itemId, subjectId, rights, history, historyEpochs ≤ 64, envelopes ≤ 256, newEpoch)`: `require(hasRight(itemId, 'share'))` (also the `policyCommits` insert rule); `require(scan(headOpsByDomain.byItemUnresolved, [itemId], { take: 1 }).length === 0, 'RESOLVE_SECRET_HEADS_FIRST')` (op 5 step 2 — a `take 1` used as an *existence* test, admitted); insert the policy child over the current policy heads (≤ 8), the grant row with `historyFloor = newEpoch` for current-and-future (invariant 12), the rotated `itemKeyEpochs` row, ≤ 256 envelopes, the audit event, and the outbox intent — one commit, "granted locally; delivery pending". `exam≤300`; `W≤262`. Wrapping is `device.wrap`; the program never sees a key.

**Hard op 6 — revoke and bulk-rekey.** `revokePrincipal` signs the removal (policy or governance child), inserts `removedSubjects`, and a new root epoch: `W≤6`. `bulkRekey` first attempt loops `db.scan(items.byGroupAudience, [groupEpoch], { take: 100000 })` → `E_BOUND`, rewrite: a device `job` **(v1)** in 200-item chunks writing per-item checkpoints and a `rekeyCoverage` maintained count keyed by epoch generation; the UI shows "removed from future policy" (immediate), "new epoch active" (immediate), and coverage (the job's watermark) as three facts, which is what the design asks for and what the job kind gives.

**Hard op 7 — resolve concurrent policy changes.** `resolvePolicyConflict(itemId, headsA, headsB ≤ 8)`: merge grant/removal operations from both branches (≤ 128 rows): for each op, apply a removal; apply a grant only if the other branch carries no removal of the *same subject*; a demotion beats a promotion by `min(rights)`; group restructures whose membership diverges are written `disputed: true` at the most restrictive rights (op 7 step 3); rotate the epoch if any reader was removed. `exam≤80`; `W≤3`. Nothing in the design's rule set asks whether the op's *author* was removed in the other branch — §8 #1.

**Hard op 8 — delete, restore, purge.** Tombstone and restore are `editItem` with `kind: 'tombstone' | 'restore'` over every known head (`exam≤70`; `W≤3`); "deleted here, edited there" is two heads in `headOpsByDomain` with one tombstone — a decision, by the `require` above, never a rule. `purgeItem`: tombstone if absent, `device.destroyKey(epochIds ≤ 1,024)`, insert `purgeBarriers` (append-only, retained indefinitely), and enqueue GC capabilities that a job redeems against S's `forgetBlob` one chunk at a time. `exam≤1,030`. The barrier is why an ancient device cannot resurrect: `ingestBlob` checks `purgeBarriers` before `accepted`.

**Hard op 9 — enroll a device.** QR/proximity is product code. On the approving device: insert `deviceCerts` (non-expiring), add the device to ≤ 32 principal epochs, write the governance child, audit, outbox: `exam≤40`; `W≤5`. On the new device: hydrate = `fetchMailboxSince` pages + `ingestBacklog`; "offline ready" is the replica watermark meeting the approving device's frontier — completeness `frontier`, never a page's `hasMore=false` (wave 3's completeness axis, verbatim).

**Hard op 10 — recover.** Threshold reconstruction is a seam; then a recovery-generation governance commit, revocation of lost devices (op 6), and personal-item checkpoints (a job). Two recoveries from one generation are two governance heads with `disputed: true`, and `grantAccess` is refused while any governance head is disputed (`require`), which is the design's "pause privileged sharing" as a program fact.

**Hard op 11 — emergency access.** Trustee mode is entirely D: `exerciseEmergency` verifies coverage (`emergencyCoverage` maintained count = current epochs covered), collects ≤ 16 share rows, reconstructs via seam, installs the key, writes approvals and use events. Delayed mode is the S schedule above plus D redemption of the token blob. The design's asymmetry — outage-independent versus witness-dependent — falls out of which plane each mode touches.

**Hard op 12 — travel mode.** `enterTravelMode`: insert a travel `deviceCerts` row; the ≤ 1,000 item grants to it are a device job (each is a `grantAccess`, `W≤262`, so inline would be `E_BOUND`); `require(exists(restorationReceipts.byCapsule, [digest]))` before the switch; then one row (`activeProfile`) flips and `device.destroyKey(ordinaryKeyring)` runs *outside* the transaction — physical erasure is best-effort, as the design says; the program can only order it after the commit.

**Hard op 13 — audit checkpoints and maintenance.** `buildAuditCheckpoint` is a device job: for each named device frontier (≤ 64), scan `auditEvents.byDeviceSeq` after the frontier `take 200`, verify chains (`chain()` already refused equivocation at ingest — gaps are absences, reported), fold a Merkle root, insert `auditCheckpoints` with both parents when concurrent, then `recordCheckpointReceipt` on S. `auditReport(vaultId, frontiers ≤ 64, from, to)` scans the same index and returns `{ events, frontiers }`; its certificate completeness must be `frontier(vector)` (§6 #7), because a page reported as "events in period" is exactly the population fact wave 3 refused three times — promise 18 in the design's own words.

**Hard op 14 — change a password at an external website.** `prepareExternalChange` inserts the intent (`prepared`); the browser is a client-side effect the language does not have (the site is outside both planes); `recordSiteReceipt` + `confirmExternalChange` run in one device mutation whose transition to `confirmed` is coupled to exactly one `siteReceipts` row **(v1)** — invariant 20 as a constraint; timeout writes `ambiguous` and both candidates stay. `exam≤6`; `W≤2` each.

**Read telemetry** (`readTelemetryEvent`, promise 19) is a device mutation whose row is labeled client-reported; no construct makes it stronger — product boundary. **Sync via bundle or direct transfer** is `ingestBlob` fed by a transport other than S; the partition's `transports` is the only place this can be said.

### 6. Language delta

1. **`partition(name, { authority: 'device', horizon: 'unbounded', serverProjection: 'blobs', transports, merge: 'dag', ingest })`** with `runsOn: 'device'` on programs, `E_DEVICE_PLANE` (a server-plane program names a device-plane table) and `E_SERVER_AUDIENCE` (a device-plane table declares a plaintext server column). *What it retracts, per table it covers:* server execution, the authoritative trace as OCC and settlement, the closure receipt, `predicted`/`rejected`, and `maxOfflineAge`. *What it keeps:* the language, the static certificate (now a device-evaluator bound), the schema vocabulary including constraints and `maintain`, the rule language, and local live queries (the trace as invalidation over the device's own store). *Cost:* the device needs the server's interpreter and storage engine (index maintenance, `tokens`, `maintain`), not the 7.8 KB twin — reversing D-A's "never a native module" for this partition. **General** (E2EE messenger, private-device agent, encrypted legal workspace — three of the breaker lists). Amends §1 kinds, §5, §6, §10 D-A and D-D. **This is a new dimension, and it is not the same dimension as region or allocation**: those *delegate* a server's authority (the home region and the preallocated allowance still settle and can still refuse later); device authority is the *absence* of a settling authority, replaced by per-peer cryptographic verification. Authority placement has two regimes — delegated and cryptographic — and the wave's "one dimension, three faces" holds only for the first.
2. **Device crypto/keyring seam** — `device.open/sign/verify/wrap/unwrap/encrypt/destroyKey/random`, `ctx.deviceSeq()`, `ctx.previousDeviceEvent()` — the client-side mirror of v1's `seal/destroyKey/verifyMac/digest`. Runtime axis; without it every D program is `E_OPAQUE`. General. Amends §4.2.
3. **Rule evaluation under a named principal and policy version** — `db.evaluate(table.rules.insert, { as, asOf, row })` over `versioned()` policy rows. Rules are predicates over `viewer`; ingest must evaluate them for *the author* at *the head the revision names* (invariant 5). Construct; general (signed-log ingest, federation, wave 4 #8's cross-owner rules). Amends §3.
4. **Content-addressed ids** — `id({ contentAddressed: true })` with the engine check `id === digest(bytes)`; verifiable on both planes (assets already content-verify). Schema; general. Amends §2.
5. **Device-authority sequence and hash chain** — `int({ sequence: by, authority: 'device' })`, `chain({ by, prev })`; equivocation is a sealed `E_CONSTRAINT` at ingest. Schema; general to any signed log. Amends §2 constraints.
6. **Negated existence in `maintain.rows … where`** for derived heads (`!exists(revisionParents.byParent, [r.id])`); v0 `where` is field-only. Small; schema. Amends §2 maintained.
7. **Completeness `frontier(vector)`** beside `page|capped|maintained|all|replica`: a result labeled with the device frontiers it covers. General to DAG-replicated data; it is promise 18 and wave 3's completeness axis in one word. Amends §5.
8. **Column-level `independentOf('claimedAt')`** — v1 has table-level; invariant 4 wants the column. Small. Amends §5.
9. **`maxIntentAge` decoupled from `maxOfflineAge`** (dating asked first): S-plane uploads queued during a 400-day partition must never age out. Small. Amends §6, §10 D-D.

Not a language item: a client-side effect kind for the browser and the QR channel — product code. **Prediction 2, tested:** held on the fence being the wrong instrument, on client-side resolution, and on the server never evaluating item rules (stronger: it cannot hold an item row). Did not hold on "per-item vector clocks" — the right primitive is a hash-linked DAG with per-device sequence chains, and vector clocks are infeasible at 150,000 devices with no dead-device assumption — nor on "gains an `authoritative-local` state" (§3, op 3 box), nor on "device is one face of the region/allocation dimension" (item 1).

### 8. Where the design is wrong

1. **A concurrently removed grantor's grants merge in.** Op 7 step 1 merges "operations on unrelated subjects"; promise 14 orders removal over grant *for the same subject*. Alice (admin) grants Carol `edit` on device A while Bob removes Alice on device B, both from policy head P0. Carol is not Alice; the rule commutes them; Carol has `edit` from an actor the merged policy says was removed. Invariant 8 ("never broaden by union") is broken by the design's own commutation rule. *Observation:* two devices at P0; A grants Carol; B removes Alice; reunite; read Carol's rights. Fix: an op's author must hold the right in the *merged* policy, not the ancestor — which makes policy merge author-aware, and the strict program is where that was visible.
2. **Materialized auto-merges create equivalent sibling heads.** Op 2 says "only disjoint conflict domains may auto-merge" and op 4 step 5 creates a merge revision — it never says whether automatic merges are materialized. Every device computes the same plaintext (deterministic program), then wraps it under a fresh revision key and its own signature: N devices, N distinct content-addressed merge revisions with the same parents, and `heads` now holds N equivalent heads that the next merge must name. *Observation:* two online devices, same two disjoint heads, both auto-merge; count heads after sync. Fix: derive automatic merges at read, materialize only human resolutions — or coalesce heads by parent set, which is a rule the design does not state.
3. **Item discovery versus promise 11 is unspecified.** An authorized device must learn that item X exists. Either every delivery is per item-audience (mailbox fan-out proportional to item × audience-device — the design's own most-feared cost, with group mailboxes as the only relief) or a vault-level index encrypted under the vault key tells every member about items they cannot read. The data model hedges ("inside encrypted records when hiding grouping matters"). *Observation:* enroll a vault member with no item grants and capture their mailbox; create ten items; count deliveries. More than zero is an existence leak to the client, which promise 7 does not cover.

### 9. Confidence

- **§1–§3 (high on classes, medium on numbers):** the S/D split follows from promises 6–7 and trap 2 verbatim; certificates assume **[inferred]** ceilings and hoisting whenever the rule input is the scan prefix; the `authenticated()` spelling, `maintain.rows` with `join`, and whether the v0 client store maintains `tokens` locally are **[inferred]**. The day-400 derivation uses RFC §2.1 F's "under the store fence" and §6's eviction text as written.
- **§4 (high):** each wrong number has a one-line counterexample; the admin-without-read row depends on rights being independently grantable, which the design states.
- **§5 (medium-high):** constraint rows rely on v1's event-coupled transitions and `versioned()` as described, not measured.
- **§6 (medium-high on 1–3, medium on 4–9):** 1–3 are forced — each has an operation above that cannot be written without it; 4–9 have smaller substitutes a stricter author could fold into existing text.
- **§7–§8 (medium-high):** each cheat has a stated boundary; each design fault has an observation independent of this language, and #1 is a security finding.
- **Prediction 2:** held on direction (fence, client-side resolution, server-blind rules) and failed on form (vector clocks; one added state; one dimension with three faces). **Central question:** authority can be placed on the device only by a declaration that does not exist (§6 #1) and that, for the tables it covers, retracts five of the six premises; "no second query class" survives by the wave's definition — the server never executes these programs, so they are not queries over its data plane — and the vault shows how much work that definition does. Language: new dimension. Runtime for that partition: a second runtime, which is the honest reading of "not this system".
