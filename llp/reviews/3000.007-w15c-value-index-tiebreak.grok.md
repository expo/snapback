## Findings

### High — published README still teaches the old tie rule

**Where:** `snapback4/packages/snapback4/README.md` 443–454 (the maintains summary, earlier in the package README than the updated feeds pointer).

**What is wrong:** This paragraph still says value-order indexes “end in value, id, optionally after group fields”, that hour lanes are ordered by `` `hour, value, id` ``, and that “ties use maintained id”. That is the limit this lane exists to retire. The feeds card and the later README pointer (`1951–1953`) now say equal scores, newest post first, with `` `by byScore: hour, value, postAt, postId` ``.

**Failing scenario:** A coding agent reads the README from the top, hits the maintains summary first, copies `by byScore: hour, value, id`, and keeps a handwritten `posts.score` for newest-first ties — the calibration #12 failure this change was meant to close.

**Smallest fix:** Update that paragraph to the same rule as `maintains.md` 97–102 and the same recipe/tie sentence as `feeds.md` 879 and 923–924. Pin the corrected sentence in `w15c_cards_pin_the_interim_rule_and_newest_first_recipe` (it currently checks only the cards).

### Medium — refusal rewrite is not a pasteable scoped `by` line

**Where:** `snapback4/crates/snapback4-lang/src/bind/schema.rs` 588–589.

**What is wrong:** The rewrite is always `` `by {name}: value, {all group fields}, id; id may be omitted only when every group field is present` ``. Two problems: (1) the English clause after the semicolon is not Quarry (`;` is not a comment; comments are `--`), so a verbatim paste is a syntax error; (2) `value` is always first, so a scoped ranking such as `hour, value, postAt` is rewritten into a global ranking.

**Failing scenario:** Author writes the feeds recipe with `by byScore: hour, value, postAt` (missing `postId`). They paste the rewrite `by byScore: value, hour, postAt, postId, id`. The index compiles, then `merge trend … [h] for h in range(…)` is refused because `program.rs` 269–273 requires the lane prefix length to equal the index position of `value` (now 0, not 1).

**Smallest fix:** Put the omission clause in the message. Keep the rewrite a single `by` line that preserves the author’s columns before `value` and fills missing group fields and `id` — for that case, `by byScore: hour, value, postAt, postId`. `--fix` is not involved (`mechanical` is false).

### Low — binder admits any group-field permutation, not only a declared `by` prefix

**Where:** `schema.rs` 585–587; documented as intended by `maintains.rs` 193 (`"at, value, author, id"` is accepted for `by author, at`).

**What is true:** I cannot construct an admitted `by` line whose stored key is non-total, non-unique, or whose tail is not `value`, then trailing group fields, then `id`. `id` not last, repeats, non-group columns, and `hour, value, postAt` (missing `postId`, no `id`) are all refused. Omitting `id` only when `whole_group` is true is sound: `byGroup` is unique on the full group (`schema.rs` 573), and binding appends `id` (592) so the existing cursor path still sees an id-ending key.

**Not a landing blocker.** Mentioned because the ruling’s words are “a prefix of group fields”; the tests specify the looser reading.

**Q1, in full.** Implemented rule: any subset of group fields (any order), then `value` exactly once, then the unused group fields (any order), then `id`; `id` may be omitted iff every group field appears; nothing else; `is_plain()`; no repeats. After bind, `id` is always last. That is total (row id uniquely identifies the maintain row) and unique (one row per group). `by byScore: hour, value, postAt` is refused, as the lane decided. I could not admit a key whose merge tail is not `value` then trailing group fields then `id`. The message at 588 matches ruling 41; the rewrite does not preserve scope (finding 2).
