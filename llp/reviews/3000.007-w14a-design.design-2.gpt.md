The ordering argument is valid with its opening condition. Discovery identifies every word lane; each established head is the next qualifying row in that lane. The heap compares the ordering suffix including the row-id tie-break. After every pop—including a duplicate—the drain establishes the replacement head or stops before emitting another row. These remain live reads: membership changes, edits and new messages require the existing restart/refresh guidance. **High — Expired-word equality contradicts the proposed charging rule.**  
Location: [REVIEW-DESIGN.md:63](/Users/ccheever/projects/snapback-w13-review/repo/REVIEW-DESIGN.md:63).

Discovery ignores the fetched row and retains its indexed word. Expiry is checked only later, **after charging examined**, inside `scan_prepared`. An expired-only word therefore spends discovery, descriptor and potentially opening resources despite contributing no result. This is consistent with the existing law explicitly keeping expired-row work metered; skipping the row does not make the work disappear. [read.rs:441](/Users/ccheever/projects/snapback-w13-review/repo/snapback4/crates/snapback4-core/src/engine/read.rs:441), [read.rs:649](/Users/ccheever/projects/snapback-w13-review/repo/snapback4/crates/snapback4-core/src/engine/read.rs:649), [LLP 3000:409](/Users/ccheever/projects/snapback-w13-review/repo/llp/3000-snapback4.explainer.md:409).

Construct the expired pair as follows:

- A has the 45 live `kx*` words; B adds one unswept expired-only matching word. Keep viewer, clock, generation, commit count and live rows equal. With ample headroom, require identical production replies, including cursor bytes and `nextExpiry`.
- Repeat with index-entry ceiling **46**. A completes discovery in 46 seeks; B needs 47. The spike returns a normal first page with `next` in A and a discovery-cut empty page without `next` in B.
- At default ceilings, place sufficiently many expired-only `kxz*` words after the common live words. B eventually cuts during discovery/opening while A fits. The old 32-word traversal never reaches those added words, so this particular distinction was previously closed.

For devices, acquire the additional rows while live, then advance the query clock without sweeping or resynchronizing. A snapshot taken after expiry could remove the test population before the query.

The smallest correct change is to distinguish **result/cursor equality when both traversals fit** from **meter-boundary behavior**, explicitly permitting the existing expired-work charges. If unconditional equality is required, this needs a different discovery design and a corresponding resource-bound argument; simply omitting charges is not correct. This is an expiry contract conflict, not evidence that denied live scopes are now scanned.

A concrete failure is 1,000 words with a large nested predicate: its boxed expression tree is cloned 1,000 times before heads open, while discovery’s formula ignores that tree. Eight 4-KiB string literals alone represent roughly 32 MiB of cloned payload. Independently, large row bodies repeatedly fetched during discovery and tokenized during opening add uncharged cumulative allocation.

The measured **4.14 MB is neither peak memory nor a proven upper bound**. Source inspection cannot establish that the tiny measured fixture’s live heap exceeds it—the charges also overcount some storage—but these unpriced paths allow other 1,000-word scopes to do so.
