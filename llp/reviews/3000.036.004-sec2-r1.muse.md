None of §10 is implemented yet. That is expected for a proposal. The problems below are in the proposal text, which an implementer would reasonably read as sufficient specification.

Corroborated engine facts used below: `opened` is `not_before <= now`, null lower means open; `expired` is `deadline <= now`, null never expires. So the live predicate is `[not_before, expire)` — inclusive lower, exclusive upper. §10.2 says "half-open" without stating which end.

### 10.1 observer obligations

**M1 — Paired-world determinism: false-refutation risk (unsoundness, not conservatism).** "Different returned data or refusal code/message is a concrete counterexample" has no determinism control. Unordered scans, pagination, or map iteration order can differ between two runs for reasons unrelated to the protected row. That yields a false refutation, violating the §1/§4 contract that refutation means a replayed rule/policy violation. Explicit sorting or canonicalization plus a repeatability rule is missing.

**M2 — Paired ingress not bound to §8.1: false-refutation risk.** "Only when both worlds seed and validate" is vague. §8.1 requires actual `Engine::seed_at`, read-back of the committed image, and passing defaults, unique/final constraints, typed validation, and the exact text minimum — and snapshot-only evaluation NEVER sets refuted. §10.1 must cite that procedure verbatim for both worlds. Otherwise an implementer judging pre-seed snapshots produces fabricated refutations.

**M3 — "Policy false in both" is ambiguous: false-proof and false-refutation risk.** Which policy, evaluated where (which viewer, which row image, which clock, which world)? A policy referencing existence can be false in both worlds for different reasons. The diff can then be unrelated to the declared intent. Require: the named invariant policy, evaluated with identical viewer/clock/arguments in each world against that world's committed image, with unsupported evaluation forcing unproved.

**M4 — Ignored fields need exclusion accounting: contract risk with soundness adjacency.** Ignoring "sequence numbers, receipts, meters and timing" silently drops observations that §3 keeps in scope for census ("sequence allocation/read admission"). §3 requires every exclusion to be enumerated, not silently ignored. Ignored diffs must produce an explicit unproved-coverage note. Otherwise a real sequence-based disclosure leaves no trace.

**M5 — Authenticated-only boundary unstated: false-refutation risk.** Paired engine contexts are authenticated principals. §§3–4 require signed-out cases to run only against HTTP/auth admission and label the device/retained-history boundary separately. §10.1 must state paired worlds do not cover unauthenticated observers.

**M6 — Pullback underspecified in three places: false-proof risk.**
- Transitivity: single-step substitution with "downstream derived observers without a checked substitution stay unproved" permits stopping after one hop and claiming the proved component. Require visited-set transitive closure (the audit module already uses one) or keep the whole chain unproved.
- Typing: substitution must preserve Value variants, table/index/keys, and image (the kernel preserves these for equality canonicalization). Untyped substitution across Id/Text or images can falsely prove.
- Caps: pullback enlarges the formula, so `MAX_ATOMS`/node-cap exhaustion must yield unproved per §3. State it.

**Conservative and correct in 10.1 (not defects):** proved component never clearing another; filter not used as an assumption; no maintenance-consistency axiom in the kernel; maintenance rebuilt per world rather than seeded; engine/storage error and unsupported evaluation never refuting; passing campaign proving nothing. These are explicit conservative limits. Keep them.

### 10.2 temporal intent

**M7 — Half-open direction undefined: direct false-proof risk.** The proposal never states live iff `(not_before IS NULL OR not_before <= now) AND (expire IS NULL OR now < expire)`. An implementer flipping strictness proves intent at the exact-boundary tick where the engine hides or shows the row. Require the exact predicate plus boundary-tick tests at `at == now` for both edges, including null bounds and defaulted lower bounds.

**M8 — Probe path missing from the temporal reduction: false-proof risk.** §3 establishes that table-rule probes see raw target rows. §10.2 adds the lifetime predicate to "read admission" but never says whether probes observe non-live rows. If any probe path sees pre-open or expired rows, a direct-row lifetime proof is false for intents reachable through probes. Require the probe reduction or an unproved blocker. "Derived lifetime paths are not silently covered" is good but does not cover this.

**M9 — Between-ticks counterexample has no procedure: false-refutation risk.** It must be two engine executions of identical worlds differing only in clock (one tick before, one after the deadline), both passing the §8.1 ingress, with identical viewer/arguments. Snapshot `now` evaluation must remain banned per §8.1. As written, an implementer could evaluate `now` in the snapshot interpreter and refute from host-clock truthiness.

**M10 — Offline clock unstated: contract risk.** Server-`now` reduction says nothing about device-clock evaluation. Require offline temporal reads to stay unproved under the existing applied-server-snapshot boundary. Also unaddressed: `read_time_granularity_ms` truncation at the boundary tick.

**Conservative and correct in 10.2:** no inferred inequality arithmetic; job flag-flip establishing no exact deadline; temporal intent without a matching lifetime staying unproved. Keep these.

### 10.3 adoption

**M11 — Draft-from-rules tensions §1: material usability/contract risk.** §1's core lesson is that rules can enforce correctly while encoding the wrong policy, so intent must be independent of rules. A generated draft that "repeats existing rules as a starting point" invites tautological invariants (`admission => itself` proves trivially) and false confidence. The warning paragraph mitigates but does not constrain. The draft must be non-adoptable as-is (comments or an explicit confirmation gate, never compiled — which the proposal does state), each candidate must carry the spec-comparison checklist, and the guide must instruct rewriting from spec rather than renaming the draft.

**M12 — Note scope and draft mechanics underspecified: contract risk.**
- `N_SECURITY_INTENT` scope ("any effective access rule") contradicts the implemented scope, which excludes uniformly-readable and deny-read tables. Reconcile exactly, including deny handling and overlap with `N_BROAD_READ`.
- "Stable content rewritten only when changed" needs tracked-vs-ignored status, provenance header format, inventory interaction, and check-fails-or-not semantics for stale drafts.
- "Once per check, not suppressed by hidden state" conflicts with change-triggered emission unless content-comparison (not hidden state) is specified.
- Effect coverage lists "read/insert/delete" and omits update/write/column/always. State the full effect list or why update is excluded.

### Required corrections

1. Paired determinism: canonical payload comparison and repeatability rule; nondeterministic diffs are unproved, never refuted.
2. Bind paired ingress to the §8.1 `seed_at` plus read-back plus full-validation procedure in both worlds; restate snapshot-only never refutes and label scope as seed-ingress worlds, not reachable traces.
3. Define "policy false in both" exactly (named policy, identical viewer/clock/arguments, per-world committed image); unsupported evaluation forces unproved.
4. Record ignored sequence/receipt/meter/timing diffs as explicit unproved-coverage notes matching §3 exclusions.
5. State paired worlds are authenticated-only; signed-out and offline/device history stay separately unproved per §§3–4.
6. Pullback: transitive closure with visited set, typed substitution discipline, cap exhaustion as unproved, per-observer-path scope labels.
7. Temporal: exact `[not_before, expire)` predicate with null/default semantics, boundary-tick tests, exact comparison-reversal mapping, granularity handling.
8. Temporal probe reduction or unproved blocker; enumerate derived lifetime paths.
9. Between-ticks procedure as two engine executions; retain the snapshot-`now` ban.
10. Offline temporal reads stay unproved.
11. Draft guardrails against tautological adoption; reconcile note scope, draft tracking/staleness semantics, and full effect coverage.
