# Authorization coverage audit — WAVE 1 (six apps) against the LLP 0331 core

Auditor: Claude Fable 5 (subagent). Read-only. Sources: `llp/0331-scoped-roles-diary-feedback.research.md:104–420`; the six verbatim artifacts under `llp/reviews/0329.014.001-paper-archetypes.*`; `llp/0329.014.001-paper-archetypes.research.md` §1–§3; `llp/reviews/0329.014.001-paper-archetypes.delta-ledger.md` (authorization rows #2, #3, #10, #17, #29, #34, #37–#40, #44, #49); RFC `llp/0329.014.004-bounded-data-programs-v1-design.rfc.md` §3, §4, §8. All line numbers below are `file:line` in the named artifact.

## 0. How the core was applied (interpretation decisions, stated once)

These decisions affect verdicts; the founder can flip any of them and the rows are labeled so the effect is visible.

- **(a) Several one-hop probes joined by `&&`/`||`/`!` = CORE.** 0331's own recipe composes probes ("Explicit role sets / boolean composition"; the Clique `canConfigure`-shaped `member && (!isGroup || admin)`). X1 is assigned only when a *found row's field* keys a further probe.
- **(b) A `where` on the found row = CORE(where)** when its terms are literals or `viewer` (the brief's `role in [...]` example). When the `where` compares the found row's field to the **subject row's** field (e.g. `found.removedSequence > row.sequence`), it is marked `CORE(where)[cross-row]`; 0331 admits "comparisons over typed row state", so it is counted as core, with X6 as the fallback if the 1001+ spec restricts `where` terms to literals. Four sites in this slice depend on it (coterie cutoff, booking org equality, workspace `pathAtMint`/`parentOk`).
- **(c) X3 vs X11.** `principal.kind === 'system'` as a *rule term* is X3. A schedule, effect, or system-only callable that must read/write rows the acting viewer cannot is X11. Where a rule says `|| principal.kind === 'system'` *only* so a schedule can run, both codes are listed and the note says which subsumes which: if system programs carry a declared read/write view (the RFC's per-mutation `reads:` / `callable:'system'`), rules never mention a kind and X3 vanishes.
- **(d) Program-only `require` is not binding under 0331.** "Raw writes [are] bound by the same table rules" and "the relation table's own insert/update/delete rules bind every writer" — so an authorization requirement enforced only by a program `require` is audited on the rule that would have to carry it. Where the smallest honest fallback is "this table admits no raw client write; only named programs write it", that fallback is named **X20 (program-only write lane)** — it is not in 0331 core and not in the brief's list, so it is named here once and referenced as a *droppable* alternative, never as a primary verdict.
- **(e) X14 (retention / disclosure) rows are noted per app, never counted.**
- **(f) 0331 core already blesses one count-shaped constraint**: "a bounded last-admin invariant … must bind every writer as a relational table rule or generic transaction-final existence/count constraint." Rows that need "at least one owner remains" are marked X17 but the note records that 0331 admits the *constraint* form; the extension is a `minCount`/`atLeast` constraint, not a count term in a rule.
- **(g) Creation provenance.** Every wave-1 design spells the creator's first seat as a *permanent creator fact* (`get(scope).createdBy === viewer` or `creatorId === viewer && joinedSequence === 0`), which is exactly the post-leave self-reseat hole 0331 closes with transaction-local provenance. Those rows are CORE (0331 form is stricter than the paper's), with the paper's over-wide spelling recorded.

### App verdict — **NEEDS: X11 (X3 as its rule-term form), X1→denorm, X6**

Authorization was *incidental* for Clique: the artifact's three "where the design is wrong" items are identity/asset/effect kinds, O5 fan-in, and retention (:1010–1014); every membership/admin rule is one-hop and matches 0331's canonical recipe almost character for character. Two holes the paper left open (self-join via `m.userId === viewer` insert, self-promotion via raw update) are closed by 0331 core itself (creation provenance, `(old,next)`). **X11 alone flips M1–M4 to COVERED-WITH-DENORM**; M5–M8 need the system actor. The paper did not reach for anything the RFC refuted; its `S()` disjuncts are the pattern the RFC §8 row "§7 … schedule targets client-callable" replaced with `callable:'system'`.

### Sprawl check

- **X11** — load-bearing for the benchmark's M5/M6/M8 (disappearing messages, push jobs, trending/digest schedules). A reduced product (M1–M4 only) ships without it; that is 0331's own scope, not Clique's.
- **X3** — droppable: every `\|\| S()` exists only so a schedule/effect can write; a declared system read/write view on the mutation (X11 form) removes the kind from every rule.
- **X1** — droppable via denorm of `conversationId` onto nine child tables; cost = one immutable column each; nothing lost.
- **X6** — droppable: keep edit/delete windows program-level under X20 (program-only writes to `messages`), or accept that raw edits are unbounded in time (loses the 15m/60m frozen invariant, :960).

### Sprawl check

### App verdict — **NEEDS: X11, X6, X17 (X3 rule-term); X6/X17 droppable to X20**

Authorization was incidental — the artifact's own closing line is that booking "is a live-only interval constraint, a calendar, and a rank" (:925). The org/role model is 0331's recipe verbatim (`isManager` as an explicit set). The load-bearing gap is **X11**: three schedules plus one same-commit promotion that must read and write another holder's row on a member's behalf (B10) — the paper did not notice that its own read rule starves the promotion scan for non-managers. Everything time-shaped (B7, B8, B9) is program-only in the paper and reduces to schedule-flipped status (X11) plus `(old,next)`; the strike count needs the X17 constraint form. Two paper holes (holder self-waiver B12; raw last-owner delete B3) are closable in core. The paper reached for `ctx.now()` windows, which the RFC §8 rows on `ctx.now` refuted (intent-bound now cannot authorize).

### Sprawl check

- **X11** — load-bearing: hold/offer expiry and no-show marking are the product's clock (I4, :834); promotion-on-cancel (I5) is a named milestone (M2/M3). Reduced product: no holds (bookings are instant), no waitlist promotion (manual by managers) — the artifact's product table does not offer this, so it is a new cut.
- **X6** — droppable to X20 (program-only writes to `bookings`) or reducible to X11 + status columns; without either, late-cancel fees and the reschedule cutoff are bypassable by raw writes (loses I3, "cutoff not gameable").
- **X17** — last owner: droppable to the constraint form 0331 admits. Strikes ≥ 3: droppable to X20 (program-level only, as the paper already has it, :886).
- **X3** — droppable if system mutations declare their read/write view.

**Cross-cutting findings the founder should weigh.**

1. **The one extension that pays in this slice is X11.** Four of six apps need a system actor; the RFC's `callable:'system'` + declared per-mutation read/write view covers every instance here and removes X3 from every rule. 0331 currently says nothing about schedules at all, because its slice is Clique M1–M3.
2. **Two things 0331 core already fixes that every paper design got wrong**: creation provenance (every design used a permanent creator fact — Clique :217 even admits self-join to any conversation) and `(old,next)` (Clique :218 and coterie :108 admit raw self-promotion; auction :80 admits the losing bidder stalling the close). These were v0 gaps, not design taste.
3. **Interpretation (b) is load-bearing for coterie and touches booking/workspace.** Whether a `where` may compare the found row's field to the *subject* row's field decides coterie's former-member cutoff (K6) with no denorm route. Worth stating explicitly in the 1001+ spec.
4. **Interpretation (d) generates most of the X6/X17 rows.** If 0331 admitted a declared program-only write lane (X20 — one boolean per table), Clique C12, ledger L9, booking B7/B8/B9 and auction A9 collapse to CORE with the paper's program `require`s binding. That is a smaller extension than time-in-rules, and the RFC's `writers:` (X12 in the delta ledger) is its wider form. It is a real sprawl candidate: name it once, or refuse it and accept schedule-flipped status columns as the only time mechanism.
5. **Denorm is cheap and under-used.** Clique's nine child tables and workspace's redemption row are the only X1 sites; 0331's "denormalize the scope id" is correct for Clique (immutable parent scope) and only partially correct for workspace (revocation must stay live).
