The paper’s 14 hard ops are not 14 plans. Ops 7, 8, 12 (favorites), 10-after-seal, and the public **point reads** close. Ops 1, 3, 5-absence, 11-count, 13 are the axis: **geo+facets, reverse standing queries, bulk set-difference, and resource counts under mixed visibility.** What remains after `scan`+`cap`+`schedule`+`maintain` is **a public page-count the checker blesses, a system principal that can see embargoed facts, and json/geometry the IR cannot evaluate.**

### 2. Schema in v0

Sentinels: no `optional` / enum / float / bytes / geometry / tz type / i64. `UNSET` id/time = `0`. Enums → `text({ max })`. Money → `{currency: text({max:3}), minor: int()}` (i53; overflow refuses). Beds/baths → tenths `int`. Confidence → bps `int`. Geometry → `latMicro`/`lngMicro` `int` + `geohash` `text({max:16})`. `json` is opaque to rules, indexes, and **[inferred]** programs — predicates and `typed_record`s are **exploded**. `never` = missing effect. No `tree` (identity is a DAG). `interval` stored; **authorization is `liveKey`**, flipped by revoke/schedule (K5, ruling 11). `liveKey='live'` or row id, booking’s partial-unique trick.

Work-queue tables (`routeWork`, `absenceWork`, `expandWork`) are **not in the design**; they are the §9 paste that makes ops 2–5, 13 plans.

### 6. Language delta

Ranked by whether the catalog’s central invariants stay slogans.

1. **Spatial access path.** `geo({ srid: 4326 })` plus `db.scan(t.byGeo, { bbox, take })` (or host geohash with documented over-select). *General* (maps, delivery). Amends §2, §4.2. Without it, op 1 is product-change to cells. Smallest: engine-maintained geohash tokens on two int columns, still not a polygon.

2. **Facet / inverted-index conjunction.** `scan` one `tokens()` prefix cannot AND status∧type∧geo. Composite btree is one leading key. *General*. Amends §4.2. Smallest: `db.scanIntersect([idx1, idx2], { take })` with `take` bounding **output**, not each side — **this is the hidden-row/`take` bug for post-filters**; the spec must say whether `take` applies before or after intersection.

3. **Completeness of a public reduction.** Ruling 8 skips `public` tables, so `page.count()` is a certified catalog total. Smallest: forbid returning `page.count()` / loop tallies as a field named `total` unless completeness is `maintained`; or a `countApprox` kind. *General* (search, directories). Amends §4.4, §9 ruling 8.

4. **Host `commitSeq` / generation watermark.** Per-partition monotonic seq at commit; scans by seq; a barrier forbids consumers past an unexpanded marker (I4, I19, valuation §7.5). *General* (payments already asked). Amends §4.2, §6, §7.

5. **Standing-query posting lists as `maintain`.** `maintain.routes(revisions, { tokens, as: standingIndex })` so a change probes an index instead of a work queue the app can forget to drain. *General* (alerts). Amends §2. App emulation (tables + chunks) is correct **if** the host guarantees drain; that guarantee is item 4.

6. **Transactional effect outbox.** Lease, `sent_unknown`, inbound webhook as `system`, same idempotency key. *General*. Amends §1, §7. `effect` as “JS with I/O” is not an outbox (email/CRM/calendar/KMS/model).

7. **`callable: 'system'`.** Feed promote, evaluator, projection, destroy, valuation activate. *General*. Amends §1/§7.

8. **Per-mutation read view.** System is total; I9/I21 need “this mutation may only `get` `publicListingSnapshots`.” Smallest: `mutation({ reads: [publicListingSnapshots, …] })` certified; any other `db.get` is `E_OPAQUE`. *General* (sealed-then-revealed is the opposite pattern). Amends §4.2, §7.

9. **Crypto/PII seam.** `db.seal` / `db.destroyKey` analogous to `consumeAssetGrant`. *General* (leads, health). Amends §4.2. Until then ops 10/14 are effect+row.

10. **One-use capability kind** (decrypt, signed disclosure, signed search cursor). Or product: don’t issue tokens; re-check rows every time. *General*. Amends §1.

11. **`exclusion({ on, interval, where })` / vacate semantics.** Cancelled OH must not occupy. *General* (booking). Amends §2.

12. **Filtered `cap`.** `cap({ by, max, where: r => r.active })` for six live comparison items while retaining withdrawn. *General*. Amends §2.

13. **Addressable records, not `json` blobs.** `record({ priceMin: int(), … })` indexable/rule-visible. *General*. Amends §2. This app’s match function is otherwise not a program.

14. **Civil time.** `civil({ tz, local, offset? })` → instant or refuse nonexistent/ambiguous DST. *App-heavy, general for calendars*. Amends §2, §4.5. Workaround: client instant (product).

15. **`optional(t)`, `text({ enum, transitions })`, `bytes`, `int({ bits: 64 })`, principal kinds beyond system/viewer.** *General*. Amends §2–§4. i53 is enough for USD listing prices ($90T cliff); checksums-as-text is ugly not false.

16. **Anti-join / `except`.** Snapshot absence. Smallest: `db.scanMissing(leftIndex, rightIndex, prefix, { take })`. *General*. Amends §4.2. Chunked point-gets are the v0 paste.

17. **Publish `G`.** Cell page exam≤52 is fine; 1000-row chunks × 1–3M fan-out is an ops number, not a certificate number. If `G.examined=200`, the diagnostic will propose “smaller take” = §7 cheat (omit routes).

Not missing: `appendOnly`, `immutable`/`immutableExcept`, `(old,next)`, `unique`, `interval`, `schedule`/`system`, `public(reason)`, `maintain.count`+`readable`, `tokens()` (one token), `upsert`, asset seam as a hook, `readTime` for **display** of OH windows.

Do **not** add `maintain.count` over mixed-visibility `listingVersions` as the public facet oracle — that is I9 with a nicer name.

### 8. Where the design is wrong

Not taste. Forced by v0 spelling.

1. **`SearchDocument` / `listingVersions` as one mixed-visibility relation contradicts ruling 2–3 and I3/I9.** The paper’s op 1 step 5 applies a “visibility-denial set” **after** candidate retrieval on a table that also holds embargoed and hidden-address facts. In v0, hidden rows consume `take`, mixed ranges ship **no extent**, and local replay is `partial`. Pagination is then neither stable nor complete, and `hasMore` without an extent is a cardinality leak. Confirming observation: pin gen G, `take: 50` in a cell with 30 public + 25 embargoed; the page has ≤30 rows, `hasMore` true, receipt has no N+2 key; a second page using a forged cursor either skips public rows or, if the engine refuses extents, cannot continue. A public-only snapshot table makes the same query `exam≤52` with extents.

2. **Op 3 step 7 (“atomically insert receipt, transition, coalesced intent, and inbox”) is inconsistent with the unique key `(revision, change)` and with p99 fan-out.** Receipts are per revision; coalesce is per `(user, listing, change, reason)` across many revisions. Those cannot be one bounded transaction unless candidate revisions are capped (cheat). The v0 paste — independent receipt txs + `upsert` on the coalesce key + `E_CONSTRAINT` retry to attach `intentSources` — is a **different atomicity grain** the paper never writes down, so two evaluators can each create an inbox item if the unique key is omitted, or drop a contributing search if attach is best-effort. Confirming observation: one change, two of the user’s searches match; run two `evaluateWorkChunk` workers; count `inboxItems` (must be 1) and `intentSources` (must be 2). If `check` admits a single mutation that scans all matching routes, inspect `take` and `hasMore`.

3. **`[D]` projections (`ListingCurrent`, `SearchDocument`, `CollectionItem`, `AuthorityTerm`, `StandingRoute`) are ordinary writable rows under rules-as-authorization.** The paper calls the journals source of truth and then tells writers to update the caches in the same breath (payments trap 1). `maintain` only does counts/sums, not “current snapshot pointer.” A second mutation with an `update` rule on `listingCurrent` can point the public page at a snapshot that has no `catalogChanges` row (no alert, no history). Confirming observation: admit `patchListingCurrent(listingId, snapshotId)` that does not insert a change; the listing page shows snapshot S, search tiles include it, saved-search evaluator never runs. Same shape: `authorityTerms.liveKey='live'` without an `authorityEvents` row (I11), or `collectionItems.active=true` without an add tag (I26).

Runner-up, not counted: I11 “evaluated at commit from intervals” vs `ctx.now` bound at intent (publish offline at 16:59, replay at 17:05 after license expiry without a `liveKey` flip). Confirm with the auction/payments I21 test.
