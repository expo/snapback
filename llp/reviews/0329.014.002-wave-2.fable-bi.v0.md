# Paper archetype: analytics / BI against LLP 0329.014.000 v0.1

**Respondent:** Claude Fable 5 · **Design under test:** `arch/w2/design-bi.md` (codex), fixed · **Target:** LLP 0329.014.000 v0.1 incl. §9.1 and §11 · **Prediction under test:** LLP 0329.014.002 #7.

Headline. Prediction 7 holds in *class* — the app ends at a boundary, and what replaces the refused operations is a declared, append-only, schema-listed **export stream** — but it draws the line in the wrong place with the wrong instrument. The line is not "maintained versus ad-hoc"; it is **declared before the data arrives versus asked after it arrived**: every *definition* (cohort, funnel, retention, histogram, distinct count, budget) is maintainable at ingest by one mutation running a bounded interpreter over definition rows — nothing is "schedule-built" — and what leaves is *history*. `G` is not the wrong instrument; it draws the line, and bites hardest on the **write** side (a 250-event batch under 20 cohorts examines 11,067 entries). K2's `readable` is necessary but not sufficient: a *live* aggregate over hidden rows discloses the timing of every hidden contribution — what the design's release epochs exist to stop and `disclosures[]` cannot name. And the design's exact/protected split *is* K2's caller/resource dichotomy, found independently; its trap 2 is `E_STRUCTURAL_COUNT` in prose. L1–L9 refer to §6.

```ts
export const ingestBatch = mutation({ sourceId: id(sources), batchId: text({max:128}), bodyDigest: text({max:64}), events: array({ max: 200 }, eventShape) }, ({ db, ctx, args }) => {
  const src = db.get(sources, args.sourceId); db.require(src && src.principalId === ctx.viewer, 'SOURCE_UNAUTHORIZED')   // authority from the credential row, never the payload
  const prior = db.get(batches.byKey, [src.id, args.batchId])
  if (prior) { db.require(prior.bodyDigest === args.bodyDigest, 'BATCH_BODY_MISMATCH'); return prior }                     // identical retry: no-op with the stored receipt
  const ds = db.get(datasets, src.datasetId), defs = activeDefinitions(db, ds.id)                                         // 3 scans (take 20/10/5) + ≤ 35 gets, hoisted per batch
  let accepted = 0, duplicate = 0, rejected = 0, watermark = src.watermarkAt
  for (const e of args.events) {
    const existing = db.get(events.byKey, [ds.id, src.id, e.eventId])
    if (existing) { if (existing.payloadDigest === e.digest) { duplicate++; continue }
      db.upsert(quarantined, [src.id, e.eventId], q => conflict(q, e, ctx.now())); rejected++; continue }                // same id, different payload: quarantine, never overwrite
    const key = db.get(identityKeys.byKey, [ds.orgId, e.actorNs, e.actor])                                              // L4: the arg is digested before the probe
    const subjectId = key?.subjectId ?? ctx.newId(); if (!key) mintSubject(db, ds.orgId, e, subjectId)
    if (db.exists(tombstones.bySubject, [subjectId])) { rejected++; continue }                                           // erased subjects never re-enter (I20)
    const scopeKey = scopeOf(e.dims), day = dayOf(e.occurredAt, ds.tz, db), hourBucket = hourOf(e.occurredAt)         // dayOf: tzRules rows, hoisted per (tz, year)
    const row = db.insert(events, eventRow(ds, src, e, subjectId, scopeKey, hourBucket, day))
    for (const d of e.dims) db.insert(eventDims, dimRow(ds, row.seq, d, scopeKey, subjectId))                             // ≤ 30 writes
    db.upsert(subjectDays, [ds.id, subjectId, day], r => r ?? { datasetId: ds.id, subjectId, day, scopeKey })
    for (const c of defs.cohorts) if (matches(c.predicate, e)) db.upsert(cohortMembers, [c.id, subjectId], m => m ?? memberRow(c, subjectId, e, scopeKey, ds))   // bounded interpreter (L8b)
    for (const f of defs.funnels) advanceFunnel(db, f, subjectId, e, scopeKey, ds); for (const r of defs.retention) advanceRetention(db, r, subjectId, e, day, scopeKey, ds)
    accepted++; if (e.occurredAt > watermark) watermark = e.occurredAt
  }
  db.update(sources, src.id, s => ({ ...s, watermarkAt: watermark }))
  const receipt = { sourceId: src.id, batchId: args.batchId, bodyDigest: args.bodyDigest, accepted, duplicate, rejected }; db.insert(batches, receipt); return receipt })
// examined ≤ 8,867 (prefixes: arg, viewer, shape from arg rows; matches() steps ≤ predicate maxBytes × 200); writes ≤ 14,401; maintained ≤ 14,400; events.insert rule pinned by sourceId → 1 probe
```

#### §5.2–5.4 Definitions, policy, identity

`publishMetricVersion`: `require(base === head)`; lowering classification or widening `protectedEligible` requires `role(org, 4)`; insert version, CAS head, audit. The **historical backfill** (2b): `db.scan(events.byDsTypeTime, [ds], …)` → `E_UNBOUND_SCAN`, and the rewrite §9 pastes today — "a maintained aggregate" — is wrong for a question about history (L9); the honest rewrite is the replica (L1) writing back through `publishProjectionChunk({ rows: array({ max: 5000 }) })`, idempotent on a unique key. `publishPolicyVersion` (3) bumps `orgs.authEpoch`; the design's fencing step is *not a program*: every result row is re-authorized on every read, verdicts die with the epoch, the offline store evicts on reconnect.

#### §5.6–5.9 Funnels, cohorts, retention, drill

`advanceFunnel` (inside op 1) advances a subject's journey row on a matching next step within `windowMs`, or inserts a journey (cap 8); a late event preceding the recorded entry re-derives from `scan(events.bySubjectTime, [subject], { range: window, take: 500 })` and refuses at `hasMore`. The funnel query is point reads (`for step ≤ 12, cohortDay ≤ 90: get(funnelSteps, …)`, ex ≤ 1,081); conversion times are a `metricHistogram` over a derived `elapsedBucket` — approximate, declared.

`listCohortMembers`: `scan(cohortMembers.byCohort, [c], { take: 100 })` under `rowScope` — hidden members consume `take` (§9.1 #2), which is precisely "protected contributors may be omitted".

`advanceRetention` writes the entry witness and, on a return, a `(cohortDay, period)` witness (`period = divmod(…).q`, Euclidean). `retentionCurve({ defId, fromDay, cohorts ≤ 52 })` sums `retentionDenominator`/`retentionNumerator` rows over the caller's grants per cohort day and period, returning `null` for periods past `min(sources.watermarkAt)` — a row, not a clock. ex ≤ 1,499 at one grant (triangle); 23,613 at 16 → `E_BOUND`. Cohort day is stamped at ingest in the dataset's timezone; "current profile" breakdowns need a `subjectAttrs` probe per row — bounded for a page, unbounded for a curve — so they are the replica's. `drill` is a page over `eventDims.byDimValue` under `rowScope + notErased` (ex ≤ 702, rp ≤ 202).

#### §5.10–5.11 Save, share, load

`saveReportVersion({ reportId, baseVersion, ops: array({ max: 64 }, { path, value }) })`: `theirs = changedPaths(base, head, PATHS)` over ≤ 40 literal semantic paths; `GROUPS` couples funnel steps, window, denominator, timezone, attribution, identity mode; `require(o.path !== t && group(o.path) !== group(t), 'SEMANTIC_CONFLICT')` per `(op, theirs)` pair — disjoint paths merge, coupled ones fork; validate every referenced dimension against the caller's grants; insert the version, CAS `headVersion`. ex ≤ 19; steps bounded by `maxBytes` (L8b); prediction *closed* — the editor holds `reports[id]` and the head version; a stale base is `rejected` (the design's fork path).

`loadDashboard` reads `dashboardVersions[id, v]`, then per tile the pinned `reportVersions` row and its series (≤ 400 gets) or retention triangle: 13 × 402 + 2 × 1,432 + 1 = **8,091** — under `G` by 21%; a third retention tile refuses. Cross-tile consistency is the transaction.

#### §5.12–5.14 Export, erasure, system

`runExport` (system; `schedule(runExport, { at: s => s.nextAt, key: s => [s.id, s.generation] })` — L7): `require(holdsReportScopes(owner))`, insert the `exportRuns` claim (unique on `(schedule, occurrence, generation)`), write `nextAt = nextOccurrence(cron, tz, dstRule, tzRules)`. `renderAndDeliver` is the one **effect**: it pages `ops.exportPage({ runId, after })` — reading only through a named query as a service principal (L8a), so every page is rule-checked — seals the artifact and delivers with an idempotency key; email delivery mints a bearer `downloadLinks` row a schedule expires.

`eraseSubject`: per identity key (≤ 1,000 by `cap`) insert a `tombstones` row (`unique(requestId, subjectId)` coalesces concurrent requests) and a `purgeManifests` row; from this commit every read rule's `notErased` probe hides the subject — I20 without a fence. `purgeChunk` (`every: '10s'`, system) takes 10 manifests, per manifest `scan(events.bySubjectTime, [subject], { take: 100 })` → delete rows and witnesses (aggregates decrement in the same commit), advance `cursor` — the `job` pattern needs no kind, only L8c. `sealSnapshot` dissolves: the commit version is the snapshot, watermarks are `sources.watermarkAt`, and the accelerators are the replica's — "never authoritative facts".

### 6. Language delta

Ranked by operations unblocked and by how wrong the answer is without it.

1. **L1 — `exportStream`: the declared boundary kind.** *What:* 8 of 9 refusals are questions about history at a volume no `take` covers, and effects cannot read tables, so there is no admitted route. *Smallest addition:* a schema kind over **append-only** tables only — `exportStream(table, { to: <service principal>, columns, with, order: <sequence column>, disclosure: public(reason) })` — shipped in `seq` order, resumable by `(generation, seq)`, at-least-once, listed in the receipt as a disclosure of named columns to a named principal. *Kind, not hatch, because:* it is static (the receipt names every column that leaves); one-directional (nothing can ask the replica anything); its consumer's only read is the stream; results re-enter solely as rows written by named mutations under their own rules with unique idempotency keys. A hatch is `db.raw`, an effect that scans a table, or a "server-only query" whose result reaches a client. *General.* Amends §1, §2, §5, §9.
2. **L2 — disclosure cadence and floor on `readable`.** *What:* `readable` discloses an exact *live* number; over hidden rows its first derivative is a per-subject event log. *Smallest addition:* `readable: rule, disclose: { cadence: 'epoch' | 'live', minGroup: N }` — under `epoch` the live row is system-readable only and a compiler-generated schedule copies it to a release row each period; `minGroup` yields `null` below N (deterministic suppression, labeled as such). *General* (leaderboards, occupancy). Amends §2, §5, §9.
3. **L3 — `int({ sequence: 'groupCol' })`.** *What:* the log needs a dense monotone order per dataset for the EAV key, the stream cursor, and the design's `ingest_sequence`; `newId()` is unordered, `commitTime` ties within a batch. *Smallest addition:* engine-assigned at commit, provisional locally. *General.* Amends §2, §4.3.
4. **L4 — `text({ hashed: true })`.** *What:* identity keys must be keyed digests under a key no principal can read; there is no hash in the subset. *Smallest addition:* the engine digests on write and on point-read keys; equality only. *General.* Amends §2, §4.2.
5. **L5 — indexes over maintained rows.** *What:* "top groups" over an aggregate has no route unless the group domain is `cap`ped. *Smallest addition:* `maintain.count(…).index('byValue', [...])`, same-commit, readable under the aggregate's rule. *General.* Amends §2, §4.4.
6. **L6 — sum-cap constraint.** *What:* the budget is a `require`; another mutation inserting a ledger row can overspend. *Smallest addition:* `cap({ by, sum: 'epsMicro', max: ref(privacyPolicies, 'epsCapMicro') })` at every write. *General.* Amends §2.
7. **L7 — live schedule `at` from a row, composite key** (wave-1). Cron with DST needs no operator: `tzRules` rows plus a computed `nextAt`. Amends §7.
8. **L8 — clarifications.** (a) effects read through named queries as a service principal, never tables; (b) `json` is traversable in programs with steps bounded by `maxBytes`; (c) system-principal reads are unfiltered where the rule says so; (d) `maintain.max` is named in §4.4 and absent from §2. Amends §2, §4, §7.
9. **L9 — a third rewrite in `E_BOUND`/`E_UNBOUND_SCAN`.** *What:* the diagnostic pastes `maintain`, answering "count this from now on" to an agent asking "count this over history". *Smallest addition:* "declare it (maintain, forward) **or** export it (stream, history)". Amends §9.

Not needed: `tree`, `exclusion`, `channel`, `readTime` — every "now" here is a row.

### 8. Where the design is wrong

1. **Exact mode is trap 2 by construction, and the design never labels the population.** Promise 7 defines exact mode as "only rows the analyst may inspect"; promise 11 re-authorizes every viewer of a shared dashboard. A full-scope author shares an exact dashboard and a one-region viewer sees regional numbers under company-wide titles — trap 2, produced by two promises composed. `QueryRun` records the policy version, not the *population* (the grant set) the number summarizes. *Confirming observation:* author (all regions) saves an exact DAU tile; viewer (EU only) opens it; the tile shows EU DAU titled "DAU" with no scope label and a valid digest. v0's caller-scoped route returns `population`.
2. **The privacy budget cannot sustain the design's own dashboard count, and the missing middle mode is the one the language's boundary creates.** ε = 4 over 365 days per audience with no per-release ε stated; at any plausible cost (≥ 0.1) an audience gets ~40 *distinct* protected charts a year against §6's 2 M reports and 300 k dashboards. And the design offers nothing between "exact over my rows" and "noisy over everything," because trap 1 assumes *arbitrary filters*. Inside the v0 boundary the cell set is fixed in advance, so differencing is limited to declared cells and complements, and an exact, epoch-released, floor-suppressed disclosure (L2) is defensible there. *Confirming observation:* run the budget arithmetic from §4's defaults against §6's counts; then attempt trap 1's "excluding Alice" query against a declared cube — it has no cell to ask.
3. **Promise 15 (reproducibility) contradicts invariants 13–14 (current grants only).** A result records the policy version "needed to reproduce it," yet authorization is always current; after a revocation the result is reproducible only under the revoked policy — forbidden — or not at all. *Confirming observation:* revoke EU from an author; re-run the recorded `QueryRun` under its recorded policy version; either the digest matches (revoked authority reused) or it does not. v0 has no "reproduce under an old policy", so the promise must become "definition and cutoff are recorded; the population is whatever current grants admit."
