NOT READY

All findings are implementation defects. No separate material defect found in the §11 design statement.

1. **Adapt can replace working commands with a missing launcher.** In [init/proof.rs:193](/tmp/day4-proof-review-r2/snapback4/crates/snapback4/src/verbs/init/proof.rs:193), additions check references in the original package. Counterexample: a UI project has `"backend": "snapback4 dev --port 4400"` and no `scripts/launch.mjs`. Apply rewrites backend to `node scripts/launch.mjs backend`, but omits the launcher because the original package never referenced it. `npm run backend` then fails. Determine required additions from the resulting package.

2. **Saved-fixture inspection falsely rejects valid sequence fixtures.** [saved_fixture_drift.rs:199](/tmp/day4-proof-review-r2/snapback4/crates/snapback4/src/verbs/saved_fixture_drift.rs:199) validates a complete stored image after supplying defaults and optional fields, but omits engine-assigned sequences. Counterexample: `items` declares `pos: sequence by list`; its valid fixture row contains `id`, `list`, and `text`, with its parent supplied separately. Check warns that `items.pos` is required, although fixture loading assigns it. Adding `pos` would instead cause `E_SEQUENCE_SUPPLIED`. Validate fixture-input semantics while preserving read-only inspection.

3. **Contemporary fixture capture drops the sweep configuration.** [init/proof.rs:41](/tmp/day4-proof-review-r2/snapback4/crates/snapback4/src/verbs/init/proof.rs:41) copies only `.jsonl` files from working fixtures. Counterexample: `fixtures/test.sweep.json` selects `{"hr":["carol"]}`. Opting in or upgrading a managed proof creates saved directories without that file, so saved tests silently use the default persona sweep. This violates §11’s contemporary-fixture capture requirement; preserve the supported sweep configuration too.

4. **The opt-in preview prints an apply command that loses the opt-in.** [init/adapt.rs:379](/tmp/day4-proof-review-r2/snapback4/crates/snapback4/src/verbs/init/adapt.rs:379) always prints `snapback4 init --adapt --apply`. Counterexample: on a new web starter, `init --adapt --day2` previews saved directories and `day2:proof`; following its printed command creates neither because the preview wrote nothing and the apply invocation lacks `--day2`. Preserve that flag in the printed command.
