### 1 — Critical

It lands only on native `QueryOutcome`, `snapback4 run` JSON, and `dev`/`run` stderr. Ruling 40 asks what the tool told the person who met the bound, and whether it could have told them the repair. ### 2 — High

### 3 — High
**File:** `REVIEW-DESIGN.md:152–196, 325–331`.

**What is wrong.** §5 correctly refuses to put a raw index token on the viewer wire: discovery does not apply expiry or the read rule (`read.rs:433–446` vs `scan_prepared:637–657`), and a cursor is canonical base64url, not encryption (`cursor.rs:60–61`; §5.6:514–520). The jump from that to “no public field, even for uniform answers” skips a form that is a function of *live* rows only.

**Viewer-safe form.** On a **uniform** answer only: from the 33rd index word, walk forward, charge each index seek and the row fetch, skip `expired` rows, stop at the first live rule-visible row, and put that word on `Read` (or omit the field if none is witnessed before the meter). Non-uniform server answers keep `cut: null` and no token (existing gate, `runner.rs:123–124`).

**Two-worlds pair (uniform, expired overflow).** Schema, principal, time, memberships, **live** readable rows (`kx00`–`kx44` all live), seq, and `matching 'kx'` fixed.
- World A: no expired extras. 33rd index word is live `kx32`. Witness succeeds. Field `"kx32"`.
- World B: one unswept expired row with word `kx31z` (sorts between `kx31` and `kx32`). First 32 *live* lanes and the page are the same. Immediate-33rd witness would omit in B and include in A — that leak is why the raw token is unsafe. **Skip-expired** names live `kx32` in both. Extra work in B stays on operator meters. Production `data` / `complete` / `cut` / `next` match.

Denied-scope pair in §5 still holds (no discovery in H). Occupancy of expired words *inside* the first 32 already changes which lanes are searched; that is pre-existing, not a new channel. Remaining leak: B has so many expired overflow entries that the skip itself meter-cuts before a live word; then field presence differs. Bound the skip, or withhold the field unless the named word is independent of hidden/expired occupancy — i.e. only emit when the first omitted *live* word is also the first omitted index word (A and B both live-33rd).

**Scenario.** Uniform room, 32 live `kx00`–`kx31` plus live `kx32`, versus the same live rows plus expired `kx31z`. Raw public `kx31z` in B is a leak. Skip-expired public `kx32` is not.

**Smallest correct change.** Either adopt skip-expired witnessed naming for uniform `Read`, with this pair as a test, or keep naming operator-only **and stop claiming alternative 2 is what the brief asked**.

### 4 — Medium
**File:** `REVIEW-DESIGN.md:309–323`; `meter.rs:185–191`; `runner.rs:199–205`; `read.rs:922–930, 980–988`.

**What is wrong.** Alternative 3’s inventory is mostly right, with two corrections. (1) Query heap exhaustion is `RuntimeError::Bound`, then on `Cut::Cap` the runner **clears the page and returns null** (`runner.rs:199–205`) — incomplete, no `next`, not a viewer `E_BOUND`. (2) `charge_lane` only charges range/list sources; generated word lanes are `source: None` (`read.rs:459`) and skip the descriptor heap charge (`980–988`). Word expansion is under-metered on heap today. For the **measured 45-word uniform scope**, opening 45 heads with `lanes.len() > 8` uses `batch = 1` (`995`), so examined/index cost is small and the existing merge cursor plus drain-cut (`1038–1040`) would walk the full newest-first answer **without a new cursor version**. That is exactly #13’s probe. Expanding admitted non-uniform scopes past 32 does change later-scope meter reach (`round3.rs` / `round3.q`); leaving those at 32 is required. Wasm for deleting `MAX_WORD_LANES` is likely ~0; new heap accounting is the byte risk.

**Scenario.** Lift `MAX_WORD_LANES` on a uniform `kx00`–`kx44` room, `last 20`. Today: 20 hits, `cut: "words"`, no `next`. After: first page 20 newest of 45, `next` after the last emitted row, walk reaches all 45.

**Smallest experiment (numbers, not a product landing).** One-constant probe: set `MAX_WORD_LANES` to 10_000; run the 45-word uniform fixture on server + both device stores; record the seven counters, `complete`/`cut`/`next`, whether a walk returns 45 ids newest-first, `heap_bytes`, and wasm gzip vs this pin. Repeat at 200 and 1,000 distinct words, and with an expired overflow word. If 45 is cheap and wasm does not move, uniform-only lift is a bounded implementation lane. If opening 1,000 heads hits examined or the null-heap path, stop and write the allocation design — that is a design in itself.

### 5 — Medium
**File:** `REVIEW-DESIGN.md:210, 225–230`; `engine/mod.rs:182–190`; `build-wasm.sh:10`; `metrics/wasm-budget.json:1`.

**What is wrong.** O(1) capture of an already-decoded token (≤64 chars / 256 bytes, `words.rs:22–24`) is sound. Zero extra store calls is sound. **Zero wasm bytes is not automatic.** `word_cut_at` already lives on `QueryOutcome` and `Runner` with no `sqlite` cfg, and `read`/`runner`/`local` compile into the web device. Copying that pattern for `word_cut_word` adds a field, clone, and serde skip to wasm. The web build is `--no-default-features --features web` (`build-wasm.sh:10`; `device/Cargo.toml:21`). Zero gzip holds only if capture, the outcome field, and codec are actually `cfg`’d out of that build. The 434,000 B ratchet is confirmed: `"gzip":434000`, Repair B measured 433,908 B, 92 B headroom; 411,000 is stale relative to this pin.

**Scenario.** Implementer adds `word_cut_word: Option<String>` next to `word_cut_at` and the wasm census moves by tens of bytes, eating the 92 B headroom.

**Smallest correct change.** Gate the new field and capture with `#[cfg(feature = "sqlite")]` at every clone site (`mod.rs`, `local.rs`, `postgres/mod.rs`, `runner.rs`, `read.rs`), or drop the 0 B claim and measure.

### 6 — Low

**Smallest correct change.** Split the two gates in §2.
