---

The specification is not ready. The r5 pins themselves are represented correctly—closed skip syntax, runMutation-only action composition with a refusing runQuery stub, and no-drop callback-withIndex lowering—and the auth enum, shipped hook names, `useQueryState` identity re-export, and `client.query` divergence are sound and candid. The following material issues remain.

1. **MATERIAL — The claimed authorization does not exist.**  
   LLP 0253 says “LLP 0252 (Accepted)” ([0253:16](/Users/ccheever/projects/snapback/llp/0253-familiar-profile-v1-api.spec.md:16)), but LLP 0252 is `Review` ([0252:4](/Users/ccheever/projects/snapback/llp/0252-convex-familiar-authoring-profile.rfc.md:4)), explicitly says r5 is unreviewed ([0252:10](/Users/ccheever/projects/snapback/llp/0252-convex-familiar-authoring-profile.rfc.md:10)), and says acceptance *would* authorize the experiment ([0252:1069](/Users/ccheever/projects/snapback/llp/0252-convex-familiar-authoring-profile.rfc.md:1069)). This is an authorization/truthfulness defect, not stale editorial wording.

2. **MATERIAL — The specified normalized-equivalence witness cannot produce cross-profile equality.**  
   Familiar identity is fixed as `todos.list` ([0253:151](/Users/ccheever/projects/snapback/llp/0253-familiar-profile-v1-api.spec.md:151)), while `operationId` remains in the normalized preimage ([0253:354](/Users/ccheever/projects/snapback/llp/0253-familiar-profile-v1-api.spec.md:354)). The explicit pipeline rejects dotted names ([index.mjs:3392](/Users/ccheever/projects/snapback/packages/snapback-codegen/index.mjs:3392)) and emits names as unquoted TypeScript members ([index.mjs:13508](/Users/ccheever/projects/snapback/packages/snapback-codegen/index.mjs:13508)). Thus an explicit `listTodos` and familiar `todos.list` necessarily hash differently; the explicit profile cannot currently spell the latter.

   Independently, `semanticInput` contains `graphRecords` ([semantic-generation.mjs:324](/Users/ccheever/projects/snapback/packages/snapback-codegen/semantic-generation.mjs:324)), whose records include source-specific node names, targets, and AST digests ([semantic-generation.mjs:165](/Users/ccheever/projects/snapback/packages/snapback-codegen/semantic-generation.mjs:165)). LLP 0253 excludes only `behavior` and `authoringProfile`, so explicit `functions.mjs` and familiar `todos.ts` graph custody will also rotate the normalized ID. The open choice between admitting dots and encoding them ([0253:559](/Users/ccheever/projects/snapback/llp/0253-familiar-profile-v1-api.spec.md:559)) leaves the supposedly fixed identity contract unresolved.

3. **MATERIAL — `normalizedContractId` silently omits law-required plans and secrets.**  
   LLP 0252 requires plans, secrets, and every behavior-bearing normalized field to enter the identity ([0252:187](/Users/ccheever/projects/snapback/llp/0252-convex-familiar-authoring-profile.rfc.md:187)). LLP 0253 instead removes the entire `behavior` field and does not list plans or secrets ([0253:353](/Users/ccheever/projects/snapback/llp/0253-familiar-profile-v1-api.spec.md:353)). In the real projection, a HostPlan exists only within `behavior` ([semantic-generation.mjs:204](/Users/ccheever/projects/snapback/packages/snapback-codegen/semantic-generation.mjs:204)), and `semanticOperation` has no `uses`/secret field ([semantic-generation.mjs:222](/Users/ccheever/projects/snapback/packages/snapback-codegen/semantic-generation.mjs:222)), even though actions preserve `uses` in their canonical definition ([define.mjs:4416](/Users/ccheever/projects/snapback/packages/snapback-codegen/define.mjs:4416)).

   Concrete collisions follow: two HostPlan mutations with different steps, or two otherwise-identical actions with different secret allowlists, can receive the same `normalizedContractId`.

4. **MATERIAL — The claimed total `returns` lowering is neither total nor shape-preserving.**  
   S4.3 maps `v.doc` to `results.document` and all other values to `results.value` without conditioning on operation kind ([0253:263](/Users/ccheever/projects/snapback/llp/0253-familiar-profile-v1-api.spec.md:263)). Canonical queries admit only `documents` or `records`, while mutations/actions admit only `document` or `value` ([result-contracts.mjs:857](/Users/ccheever/projects/snapback/packages/snapback-codegen/result-contracts.mjs:857)); JS query construction enforces the same restriction ([define.mjs:3625](/Users/ccheever/projects/snapback/packages/snapback-codegen/define.mjs:3625)).

   Therefore a familiar query returning `v.doc("todos")`, `v.string()`, or `v.array(v.object(...))` cannot lower as specified. The alleged `results.records` “single-record form” also changes cardinality: query references are array-valued ([react/index.d.mts:159](/Users/ccheever/projects/snapback/packages/snapback-react/index.d.mts:159)). Finally, `v.array(..., {maxItems})` preserves a bound ([define.mjs:551](/Users/ccheever/projects/snapback/packages/snapback-codegen/define.mjs:551)), but lowering to `results.documents(table)` drops it ([define.mjs:581](/Users/ccheever/projects/snapback/packages/snapback-codegen/define.mjs:581)). The spec’s own open question concedes that this supposedly total mapping is unresolved ([0253:554](/Users/ccheever/projects/snapback/llp/0253-familiar-profile-v1-api.spec.md:554)).

5. **MATERIAL — Effect declarations disappear while effectful contexts remain available.**  
   LLP 0252 requires mutations/actions to declare effects when used and forbids inference ([0252:353](/Users/ccheever/projects/snapback/llp/0252-convex-familiar-authoring-profile.rfc.md:353)). LLP 0253’s closed key matrix omits `effects` entirely ([0253:226](/Users/ccheever/projects/snapback/llp/0253-familiar-profile-v1-api.spec.md:226)), while giving handlers the canonical contexts ([0253:289](/Users/ccheever/projects/snapback/llp/0253-familiar-profile-v1-api.spec.md:289)). The actual action context exposes `fetch` and `fetchStream` ([ctx.d.mts:287](/Users/ccheever/projects/snapback/packages/snapback-codegen/ctx.d.mts:287)), and runtime actions can perform push and fetch host operations ([ctx-bootstrap.js:1004](/Users/ccheever/projects/snapback/packages/snapback-harness/ctx-bootstrap.js:1004), [ctx-bootstrap.js:1028](/Users/ccheever/projects/snapback/packages/snapback-harness/ctx-bootstrap.js:1028)). Opaque-handler effect ceilings record only declared reads/writes, not those host effects ([effect-ceiling.mjs:303](/Users/ccheever/projects/snapback/packages/snapback-codegen/effect-ceiling.mjs:303)).

   A familiar action calling `ctx.fetch()` must therefore either execute an undeclared effect or fail for a rule absent from the API specification. Both violate D2 and Acceptance 3.

6. **MATERIAL — The promised complete disposition table is absent.**  
   The summary claims a complete table ([0253:20](/Users/ccheever/projects/snapback/llp/0253-familiar-profile-v1-api.spec.md:20)), but S4 merely refers to a nonexistent “Phase 0 disposition table” ([0253:242](/Users/ccheever/projects/snapback/llp/0253-familiar-profile-v1-api.spec.md:242)). Actual closed canonical fields include `requires`, `authorityIndependent`, `retainable`, `authScopeField`, `authorizationDependence`, `fieldBoundary`, `standardPattern`, `stream`, and `authorityCreating`, among others ([define.mjs:67](/Users/ccheever/projects/snapback/packages/snapback-codegen/define.mjs:67), [define.mjs:130](/Users/ccheever/projects/snapback/packages/snapback-codegen/define.mjs:130)); no v1 disposition is assigned to them. Deferring the table to future acceptance ([0253:518](/Users/ccheever/projects/snapback/llp/0253-familiar-profile-v1-api.spec.md:518)) does not fix the API now and violates LLP 0252’s fail-closed completeness requirement ([0252:231](/Users/ccheever/projects/snapback/llp/0252-convex-familiar-authoring-profile.rfc.md:231)).

7. **MATERIAL — Compatibility-alias ground truth and rename routing are false.**  
   LLP 0253 claims all LLP 0238 renames are recorded in `compatibilityAliases` ([0253:69](/Users/ccheever/projects/snapback/llp/0253-familiar-profile-v1-api.spec.md:69)) and relies on that data for mutation and `client.read` correction routes ([0253:463](/Users/ccheever/projects/snapback/llp/0253-familiar-profile-v1-api.spec.md:463), [0253:488](/Users/ccheever/projects/snapback/llp/0253-familiar-profile-v1-api.spec.md:488)). The manifest contains exactly one alias: `useSnapbackQuery` → `useSnapbackLiveQuery` ([client-lifecycle.mjs:227](/Users/ccheever/projects/snapback/packages/snapback-codegen/client-lifecycle.mjs:227)). There are no data rows for mutation dispatch/status, task, or `client.read`, so the promised generated corrections cannot follow those renames.

8. **MINOR — Two “Ground truth” statements overstate the current implementation.**  
   Canonical JS queries still accept the legacy `v.object` result form ([define.mjs:3625](/Users/ccheever/projects/snapback/packages/snapback-codegen/define.mjs:3625)), contrary to “must be a `results.*` contract” ([0253:45](/Users/ccheever/projects/snapback/llp/0253-familiar-profile-v1-api.spec.md:45)). Also, runtime action contexts contain a truthy `.db` whose methods throw ([ctx-bootstrap.js:890](/Users/ccheever/projects/snapback/packages/snapback-harness/ctx-bootstrap.js:890), [ctx-bootstrap.js:862](/Users/ccheever/projects/snapback/packages/snapback-harness/ctx-bootstrap.js:862)); only the generated TypeScript `ActionContext` omits it. If the familiar shim promises actual absence, it needs an allowlisted facade and an own-property test.
