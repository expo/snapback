Overall, the core S5 behavior remains sound and the delta makes the evidence substantially more honest. Two low-severity test/tooling problems remain, and the feature guard protects official artifacts but does not make the test feature intrinsically unshippable. References below are at `905a75d545`.

1. **PARTLY — production feature guard.** `release` disables debug assertions by default; `production` and `wasm` inherit it (`snapback4/Cargo.toml:16-17,30-37,41-48`). Accordingly, publication and XCFramework builds use `production` (`snapback4/scripts/publish.mjs:76-77`, `snapback4/scripts/build-xcframework.sh:20-23`), while build, measurement, and attribution use `wasm` (`snapback4/scripts/build-wasm.sh:10`, `snapback4/scripts/measure-wasm.sh:14-15`, `snapback4/scripts/attribute-wasm.mjs:144`). None enables `web-device-check`; no script or CI invocation uses release-profile `--all-features`. Legitimate repository builds are therefore safe and unbroken. However, the guard is only `not(debug_assertions)` (`snapback4/crates/snapback4-core/src/lib.rs:7-9`): a custom production profile with `debug-assertions=true`, or a dev-profile native library someone packages, can still carry the feature. The absolute “must never alter a shipped device” claim is stronger than the mechanism.

2. **FIXED — census claim and valid-program evidence.** The census regression claim is explicitly withdrawn (`snapback4/JOURNAL.md:31005`). The remaining admission witness patches the actual IR and verifies direct server validation plus both device stores (`snapback4/crates/snapback4-device/tests/device_diet.rs:10-32`); restoring device admission under the feature makes it fail (`snapback4/JOURNAL.md:31034-31038`). The valid mutation accounting comparison covers all ceilings 0–23 and exact first success at 11 on both stores (`device_diet.rs:35-53`). The feature-enabled native device suites passed 237/18/3 cases (`JOURNAL.md:30946-30952`), while the actual wasm tier exercises the malformed-policy boundary (`snapback4/packages/snapback4/test/device-diet.test.mjs:16-24`) and the broader client suite. This is sufficient scoped regression evidence plus the code argument—not an exhaustive proof for every valid program—and the delta no longer claims otherwise.

3. **PARTLY — `--check-absent`.** It now finds the intended names at arbitrary mounts and documents inlining/renaming limits (`snapback4/scripts/attribute-wasm.mjs:111-123`). But it matches those segments in every crate, not just server-only core paths. The test expressly requires `other::prefetch::walk`, `other::admission::check`, `other::log_events::put`, and unrelated `other::partition::*` paths to fail (`snapback4/packages/snapback4/test/wasm-absent.test.mjs:6-11`). That creates false failures for legitimate future web-device modules.

4. **FIXED — misleading server assertion.** The unmodified-server query is gone. The retained server assertion now calls `validate_inputs` on the patched inadmissible program itself (`snapback4/crates/snapback4-device/tests/device_diet.rs:14-18`), so it exercises the intended admission boundary.

5. **FIXED — documentation.** README states that web queries and predictions trust compiler admission, while local argument/row/rule/coverage/budget checks remain and native devices may structurally refuse (`snapback4/packages/snapback4/README.md:622-625`). Prediction now covers both query answers and predictions (`snapback4/crates/snapback4-lang/src/guide/prediction.rs:12-16`). Bounds, codes, and programs consistently identify compiling/serving hosts versus the web device (`guide/bounds.rs:43-48`, `guide/codes.rs:109-110`, `guide/programs.rs:39-47`). This matches compiler admission (`snapback4/crates/snapback4-lang/src/bind/mod.rs:97-110`), server validation (`snapback4-core/src/engine/validate.rs:117-120`), and native-versus-web device validation (`validate.rs:123-127`).

6. **PARTLY — clock test.** Before the refused call there is only the initial `+25h` offset and a rejected oversized advance (`snapback4/crates/snapback4/tests/clock.rs:297,316-317`); successful 120-second advances occur afterward (`clock.rs:331-339`). If the refused 120-second advance is mistakenly applied, `elapsed` is at least 120,000 ms and the `<60,000` assertion fails (`clock.rs:321-327`). But a correct run can still exceed 60 seconds: each HTTP read permits 30 seconds (`clock.rs:31-36`), and the first response tail plus the refused request can together approach or exceed the fixed threshold. Thus it is much less flaky, but not scheduling-independent.

7. **FIXED — Postgres experiment lock.** Its local Snapback packages are uniformly `0.2.28` (`snapback4/experiments/postgres/Cargo.lock:797-831`), matching the workspace version (`snapback4/Cargo.toml:10-12`).

**Did this delta introduce a new problem?** Yes: the generalized absence matcher now rejects legitimate same-named paths, and the replacement clock assertion retains a hard-duration false-failure boundary.

**Is there a regression test in this delta that would also pass without the change it claims to test?** No for the changed matcher, admission, and clock assertions: each is mutation-sensitive. However, the compile-error guard has no committed regression test; deleting it leaves the checked-in debug-profile feature tests green. The production-profile refusal in `JOURNAL.md:31021-31031` is manual evidence.

### Findings

- **Low — `snapback4/scripts/attribute-wasm.mjs:116`.** A legitimate client module such as `snapback4_device::transport::prefetch::next`, or a dependency path containing `admission`, makes `measure-wasm.sh` fail despite containing no prohibited server engine. Restrict matching to the `snapback4_core` namespace and then allow arbitrary internal mounting; update the synthetic tests so `other::*` paths are accepted.

- **Low — `snapback4/crates/snapback4/tests/clock.rs:327`.** Two successful but near-timeout HTTP phases, or a long process suspension, can make an unapplied advance report at least 60 seconds and fail. Compare the server interval with a bracketing monotonic `Instant` interval plus a small tolerance; a wrongly applied 120-second jump will still remain decisively larger.

- **Low — `snapback4/crates/snapback4-core/src/lib.rs:8-9`.** `cargo rustc -p snapback4-device --features web-device-check` in dev, or a custom optimized profile with debug assertions enabled, can produce a packageable native library with web policy. Either scope the guarantee explicitly to the repository’s official optimized artifact paths and add a committed negative build check, or replace the public Cargo-feature simulation with a test-only mechanism if absolute non-shippability is required.

Verdict: READY WITH CHANGES
