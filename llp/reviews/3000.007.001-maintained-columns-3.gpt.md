1. **High — A parent can become live without triggering its mirror pass.**

   **Design:** §3.11, especially the trigger list at [RFC:303](llp/3000.007.001-maintained-columns.rfc.md:303). **Code:** [schema.rs:1278](snapback4/crates/snapback4-core/src/schema.rs:1278), [schema.rs:276](snapback4/crates/snapback4-core/src/schema.rs:276), [engine/mod.rs:432](snapback4/crates/snapback4-core/src/engine/mod.rs:432).

   Concrete history: an existing parent image lacks `expiresAt`. Adopt `expiresAt: time default T`, `expire at .expiresAt`, and a maintained count, with `T` already past. The private rebuild finds one contribution; the mirror correctly skips the expired parent. Activation does not persist interpreted defaults. Next, widen `expiresAt` to optional, retaining the same default and the same `expire at` line. Missing optional fields materialize as null **before** literal-default handling, and null never expires. The parent is now live, but none of the listed triggers changed. It serves implicit zero while its private total is one.

   The same dependency-signature issue affects source interpretation: widening a missing, defaulted reference to optional changes its interpreted contribution without changing the maintain declaration or default.

   **Smallest fix:** define triggers over resolved interpretation. Mirror when the parent’s expiry field selection, type/optionality or default changes; rebuild when those properties change for a source dependency. Perform both before publishing the generation. Add the two histories above to §8.

2. **High — “The private maintain’s own work is identical” is false across hidden totals.**

   **Design:** §3.2, [RFC:146](llp/3000.007.001-maintained-columns.rfc.md:146). **Code:** [write_target.rs:287](snapback4/crates/snapback4-core/src/engine/write_target.rs:287), [maintains.rs:175](snapback4/crates/snapback4-core/src/engine/maintains.rs:175), [store.rs:413](snapback4/crates/snapback4-core/src/store.rs:413).

   Give the writer the same readable like in both worlds, with a hidden parent. In one world it is the sole contribution; in the other another principal contributes too. Deleting the writer’s like removes the private aggregate row in the first world, but changes its value in place in the second. Deletion removes its index entries; an in-place value change leaves `byId` and `byGroup` unchanged. Existing `reserve_maintains` returns early for an unfiltered, non-expiring maintain. Thus keeping that machinery’s ordinary charges beside a mirror-only reservation produces different index meters—and potentially `sent` versus `E_BOUND`.

   Reusing the existing global `maintain_prepaid` flag suppresses those private charges too. That removes this observation only by leaving their work outside the reservation as described.

   **Smallest fix:** explicitly reserve **private aggregate plus mirror** work, unconditionally per affected maintained declaration, before inspecting either state. Cover both old/new groups, private creation/deletion, scratch and mirror writes. Suppress exactly that prepaid work and restore reservation state once per outer attempt. Test `0→1`, `1→0` and nonzero→nonzero totals under each ceiling, including unfiltered sources and system calls.

   The other observation repairs are sound: receipts omit historical results, retries retrieve that sanitized receipt, `/changes` can use the unconditional public parent name, and partition-filtered streams need not disclose a parent outside the writer’s partitions. [receipt.rs:12](snapback4/crates/snapback4-core/src/engine/receipt.rs:12), [partition.rs:558](snapback4/crates/snapback4-core/src/partition.rs:558).

3. **High — An unspellable name and denied read rule do not make the private target inaccessible to application rules or native jobs.**

   **Design:** §2, §3.2 and §8 Visibility. **Code:** [schema.rs:900](snapback4/crates/snapback4-core/src/schema.rs:900), [read.rs:102](snapback4/crates/snapback4-core/src/engine/read.rs:102), [read.rs:298](snapback4/crates/snapback4-core/src/engine/read.rs:298).

   A raw schema can put an `Exists` probe of the private target’s `byGroup` in another table’s rule, including an equality against `value`. Current structural validation accepts the address, and rule probing reads it without applying the target’s read rule. This exposes the private total through an authorization outcome even when no parent exists. The proposed walk over dependencies on the **parent column** does not necessarily catch references to the private table’s ordinary `value` field.

   Separately, a native job supplies table names as strings and runs under system authority; the system read bypass defeats `Deny`. `refuse_engine_owned` protects writes, not these reads.

   **Smallest fix:** state and enforce a core invariant that application programs, native calls, rules and constraints cannot address private targets, including under system context. Validate raw schemas and IR as well as Quarry. Internal aggregate/birth/mirror operations access them through an explicitly internal path. Map refusals to the owning declaration without printing the private name.

4. **Medium — The device-schema representation and exclusion policy need one concrete definition.**

   **Design:** §3.2, §3.7, §6 and §8 Visibility. **Code:** [serve.rs:901](snapback4/crates/snapback4/src/serve.rs:901), [device.rs:28](snapback4/crates/snapback4-device/src/device.rs:28), [emit/rust.rs:15](snapback4/crates/snapback4-lang/src/emit/rust.rs:15).

   Today `/schema` sends the entire `Schema`, which the device persists and installs. Sending the proposed schema unchanged exposes every private maintain and target. Simply removing them also removes the stated owner metadata unless another representation supplies it; the device still needs to recognize unwritable maintained columns, interpret missing values and invalidate old images on relevant evolution.

   **Smallest fix:** specify a device/public schema projection containing maintained-column metadata sufficient for those duties, but no private target tables or target names. Include a derivation identity where needed to preserve generation invalidation. The server retains the complete private maintains; the device neither stores their rows nor evaluates them.

   Apply the same public-table selection to Rust generation, `/`, `/schema`, `check` counts, `--residency`, `why`, `data` error suggestions, SQL views and `/changes`’ saturated-page fallback—not just ordinary commit metadata. Adoption diagnostics should point to the owning column. Existing `N_MAINTAIN_DELTA` already skips a `Deny` target; the new parent-disclosure note must replace that silence deliberately. `doctor` should retain honest physical byte/row totals, labelled as including internal storage, rather than silently subtracting the feature’s cost.

5. **Medium — Private lowering needs explicit adaptations for null references and reserved group names.**

   **Design:** §2 and §3.2’s “same … predicate and `by`” / “unchanged” mechanism. **Code:** [maintain.rs:66](snapback4/crates/snapback4-core/src/maintain.rs:66), [maintains.rs:43](snapback4/crates/snapback4-core/src/engine/maintains.rs:43), [bind/maintains.rs:19](snapback4/crates/snapback4-lang/src/bind/maintains.rs:19).

   Existing maintains aggregate null keys. Two large positive sum contributions with null parent references can therefore overflow a private `[null]` group even though §2 says neither contributes anywhere. Also, an ordinary reference column named `value` satisfies the proposed column form but collides with the existing maintain target’s reserved numeric `value`.

   **Smallest fix:** specify the private lowering adapter: exclude null references before delta evaluation and use a collision-free internal group-field mapping. Use that identical interpretation in incremental evaluation, assessment and rebuild. Add null/non-null moves, null-group overflow controls and a reference named `value` to the oracle.

The write-result change itself does not require another architectural decision. Preserve today’s optional results for if-absent/update/upsert and native unit-returning APIs; reduced row-valued results can use a row shape retaining typed `id`. Wildcards must expand that reduced shape, and explicitly requesting the maintained field must direct the author to a rule-checked read. Generated native write/result types also need this distinction: today’s generated full-row struct requires every non-optional field. [bind/program.rs:678](snapback4/crates/snapback4-lang/src/bind/program.rs:678), [emit/rust.rs:38](snapback4/crates/snapback4-lang/src/emit/rust.rs:38).

For §7, pin the daily trace—like rate, old-post distribution, initial holdings and denominator—before applying the 10% gate. Otherwise the same mechanism can pass or fail merely by choosing a different workload. For §8, also inject failure after the private write and between two mirrors, compare watched results after interrupted catch-up/reopen, and verify SQL’s synthetic zero: its current projection recognizes literal defaults only. These are implementing-lane details; findings 1–3 are the remaining blockers.

Verdict: NOT READY
