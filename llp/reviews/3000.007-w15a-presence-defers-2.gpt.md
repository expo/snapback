**High — I1 fails beyond its sole authorized exception.**

Locations: [server assertion:75](snapback4/crates/snapback4-sim/tests/grace_effects/mod.rs:75), [device assertion:27](snapback4/crates/snapback4-device/tests/presence/unconfirmed.rs:27), and [read.rs:309](snapback4/crates/snapback4-core/src/engine/read.rs:309).

The admitted counterexample already exists: `send` in [presence_cost.q:40](snapback4/crates/snapback4-sim/tests/grace_effects/presence_cost.q:40), with 50 memberships and 49 held recipients. Its pinned vectors are:

At a rule-probe ceiling of **1**, prediction accepts while the server exhausts that field and refuses. The device trusts synced reads; the server charges their authorization checks. This is independent of the six-byte heap divergence. The tests currently assert the unequal vectors separately instead of asserting I1 between them.

This is a **pre-existing defect, not a new projection regression**, but the review brief explicitly makes an additional I1 counterexample High. The implementation’s qualification at [LLP:2376](llp/3000.007-relaxed-quarry-and-explicit-residency.rfc.md:2376) changes the stated contract.

**Smallest resolution:** explicitly revise the acceptance contract to admit this additional baseline exception, or authorize a metering repair that relaxes R1/R2. Add the corresponding both-store boundary regression. Preserving the pinned R1/R2 vectors and satisfying universal I1 are mathematically incompatible here.

**Medium — setup discovery is still quadratic for admitted program shapes.**

Location: [presence.rs:384](snapback4/crates/snapback4-core/src/engine/presence.rs:384), particularly the map clones and the `retain`/`assigns` calls through line 404.

A concrete family is:

```quarry
effect notify
mutation push(p: principal, flag: bool):
  a0 = exists connected[p]
  a1 = a0
  -- N distinct aliases, ending in aN
  if flag:
    emit notify {}
  -- N repetitions of this independent if
  if not aN:
    emit notify {}
```

These presence-derived aliases remain in `bindings`. Each independent `if` clones the entire N-entry map twice and scans it again to determine which names its arms assign. Thus an O(N)-statement program performs **Ω(N²)** setup work even though `mark_bindings` visits each definition once. Loops repeat whole-map filtering; nested arms additionally rescan their subtrees through `assigns`.

The depth-200 regressions prune all independent aliases, so they do not exercise this retained-map case. The exponential bug is fixed, but the requested linear bound is not. This extra work remains intentionally unmetered under the engine lock.

**Smallest fix:** replace whole-environment copies and per-binding subtree searches with scoped definition updates and assignment summaries computed once. Keep discovery unmetered to preserve R1/R2, and add regressions combining many live aliases with sibling guards, loops and nested arms.
