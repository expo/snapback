## Blocking defect: narrowed gate misses the manual→through fetch

`validate` fetches a parent whenever `live || edge.live.is_some() || narrowed && !history` ([authority_origin.rs](/home/ccheever/projects/sb4-w14-live/snapback4/crates/snapback4-core/src/store/authority_origin.rs:33)), via unmetered `tx.get` ([through_activation.rs](/home/ccheever/projects/sb4-w14-live/snapback4/crates/snapback4-core/src/engine/through_activation.rs:377), [store.rs](/home/ccheever/projects/sb4-w14-live/snapback4/crates/snapback4-core/src/store.rs:600)). The new gate admits only on `old-live || new-live || any-column-live-cell` ([narrowed.rs](/home/ccheever/projects/sb4-w14-live/snapback4/crates/snapback4-core/src/store/narrowed.rs:158), [authority_origin.rs](/home/ccheever/projects/sb4-w14-live/snapback4/crates/snapback4-core/src/store/authority_origin.rs:80)). For a **manual→through narrowed row with no live cells and no captured history**, the fetch fires and the gate skips. Baseline admitted unconditionally here, so this is a delta-introduced ordering regression: refuse-before-own becomes own-then-refuse.

Observed witness (`/tmp/narrowprobe`, kept for re-run): manual schema → narrow a 200 KB row → grow parent to 4 MB → captured bridge. Result: `ADOPT_ERR code=E_BOUND … largest=4194376` — the 4 MB parent was owned as a single layout *before* a later barrier refused. (With a 20 MB parent, an earlier generic walk refuses first with nothing owned; envelope never exceeded in any probe — impact is ordering, plus transient within-envelope ownership.) Small-parent case succeeds, so no availability regression, only admission ordering.

Fix: extend the narrowed gate to cover `validate`'s full fetch condition — e.g. also admit when `old.through` is none, destination has `through`, and the row lacks captured history (the history query is available: same `tx, t, id`), keeping the per-row precision the delta wants.
