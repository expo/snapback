## Finding 1 (withholds READY): full-test checkpoints lost their fresh workflow-continuation budget

Old code wrapped both setup checkpoints in `slice()` even when unbounded (`map_or(1024, ...)`). `slice()` ([challenges.rs:41-45](/home/ccheever/projects/sb4-b26-sec10/snapback4/crates/snapback4-lang/src/bind/security/challenges.rs:41)) saves, resets (`workflow_base = workflow_attempts`), and restores `workflow_base`, giving each checkpoint a fresh 512 focused-workflow budget. New `setup_checkpoint` ([challenges.rs:51-53](/home/ccheever/projects/sb4-b26-sec10/snapback4/crates/snapback4-lang/src/bind/security/challenges.rs:51)) runs `run(self)` directly when `work_remaining` is `None`, with no `workflow_base` reset.

Consequence: `workflow::run` gates on `workflow_attempts >= workflow_base + 512` ([workflow.rs:58,111](/home/ccheever/projects/sb4-b26-sec10/snapback4/crates/snapback4-lang/src/bind/security/challenges/workflow.rs:58)), and `attempt()` gates the same way ([workflow.rs:31](/home/ccheever/projects/sb4-b26-sec10/snapback4/crates/snapback4-lang/src/bind/security/challenges/workflow.rs:31)). The empty-start phase runs first and its derived replay (`workflow::direct` → `attempt`) can consume up to 512 ambient workflow attempts against the base set at `fixture_observers` entry ([challenges.rs:441,457](/home/ccheever/projects/sb4-b26-sec10/snapback4/crates/snapback4-lang/src/bind/security/challenges.rs:441)). If exhausted, every `workflow::run` call from the checkpoint's `lifecycle_observers_to` successors ([histories.rs:532](/home/ccheever/projects/sb4-b26-sec10/snapback4/crates/snapback4-lang/src/bind/security/challenges/histories.rs:532)) is an immediate no-op. A witness needing a workflow continuation from the transient pre-transition/pre-loosening root — the exact state these checkpoints exist to preserve — would be lost in full-test mode only. Bounded check/deploy paths are unaffected (slice still resets there).

Section 12 says checkpoints "retain no call/world work reservation" and keep "existing per-checkpoint directed-history ceilings," but is silent on the workflow counter. `reserve()`/attempt accounting is unchanged, so this is purely the unacknowledged loss of the per-checkpoint workflow reset.

Suggested fix (one line, preserves the no-work-reservation intent): in `setup_checkpoint`'s `None` branch, save/reset/restore `workflow_base` exactly as `slice()` does, without touching `work_remaining`. Alternatively, add one §12 sentence stating full-test checkpoints share the ambient workflow budget.
