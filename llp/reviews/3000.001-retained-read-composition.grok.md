# Blind review: Snapback 4 — composing retained and authoritative record fields

- **Reviewer:** Grok 4.6 (xAI)
- **Range:** `70a663c22` (BASELINE) → `b5a7ddde3` (IMPL_COMMIT)
- **Date:** 2026-09-17
- **Method:** read-only, no sub-agents, no `llp/reviews/`

## Overall

The commissioned slice is built: binder-proven independent record fields, mirrored coverage frames that do not reset interpreter flags, device-only `components`, and one client compose from a second local observation plus the original `POST /q/<name>`. The ticket fixture (`both()`: 25 exact left ids + 26 exact held ids online, 25+25 offline, watches, reconnect) is implemented and pinned on wasm and process.

Eligibility is conservative and I could not produce a **plan** whose fields share a write. The client compose predicate is **not** the plan’s one-sentence rule (“the host that would have answered it as its own query”). It keeps only `retained: true` fields, so a proven plan whose device-side field is complete but not `retained` (a found point read of a delivered left-group row) still takes the whole server answer and drops that row, while `check --residency` names the components. That is the blocking contract hole. Frames themselves do not change evaluation.

### 2. Frames do not change evaluation

Mid-run **reads** of coverage (not only at the end): `read.rs` 607, 614, 634 (stop after cap), 667 (scan continuation from cap/non-uniform/word), 676–684 (page loss / next), 802 (merge continue), 864 (merge refill); `runner.rs` 114–116 (`read_cut`), 255/339 (collector / returned page); `local.rs` 48–61, 85–86, 135–136; `meter.rs` first-cap. Those read **globals**.

`note` (`engine/components.rs` 38–40) writes only `Frame` when a plan exists. `begin_component` / `end_component` / `component_record` do not clear `capped_at`, `word_cut_at`, `beyond_horizon`, `page`, or the meter. `component_record` 66–82 copies `expr()`’s Object preamble (`meter.step(1)` + `read_presence_value` + field `expr` + heap) rather than adding a second charge on top of `expr()`.

Literal save/clear **would** change those mid-run branches; this implementation does not do that. Require mid-query: result is `Err`, data is not `Row`, map omitted (`local.rs` 60). Meter cap inside a later component: same global cap, same truncated data; differential covers examined 3/30 and heap/output (`device/tests/components.rs` 78–94). Production query always observes components (`call.rs` 86); `query_with_coverage` leaves `component_observation` false so `note` is a no-op.

`retained_group` now wraps `tx.retained_group` in `maintains.rs` 152 and `write_target.rs` 69; `note` is a no-op without a plan, and mutations never get one.

### 3. Per-component words

`Frame::coverage` (`engine/components.rs` 23–26): `complete` is false if unknown, non-uniform, overflow, words, presence, cap, or beyond; `retained` is `retained && !other` (beyond does **not** clear `retained`; the other causes do).

Every global coverage write I found has a `note`: `unknown_fact` (`local.rs` 141–142), `horizon_coverage` (`read.rs` 97), `retained_group` (`components.rs` 91), non-uniform (397, 554), words (427), overflow (661, 786, 878), presence (`runner.rs` 741–742), cap (begin/end/`component_record`/output charge). `page_position_lost` withholds the whole map (85). Unclean shared frame withholds the map (85). Unowned statements (guards, shared non-reading lets) run with `active = None` → shared.

`get` / `exists` (`read.rs` 281–313, `runner.rs` 530) never call `retained_group`. A found left-group row is `complete: true, retained: false`.

Return-time: if the meter is already capped, **every** remaining field, including a variable lookup of an earlier binding, is marked `capped` (`components.rs` 75). That clears `retained` on a component whose scan finished before the cap. Pinned as intended in `device/tests/components.rs` 86–90.

### 4. Client composition (`evaluateLocal`, `local.ts` 798–890)

- **Old identity / delayed reply:** `server()` returns loading on incarnation mismatch (818), `E_AUTH` if `sessionDead` (819). `close()` sets `closed = true` synchronously (1248–1250) and drops watches (1259); `post` then `{ok:false}`; second `local()` is `E_CLOSED`. Sign-out: `sessionDead` before the compose. Compose does not publish under a dead/closed identity. Token rotation with `remember=false` retries the POST (821–826). Adoption/reset bump `incarnation`; `runLocal` retries (787–791). **Untested:** rotation and store replacement (journal M3).
- **Transport failure:** `failure` returns the first local; `failed` then returns the **second** local (875–878). Plan: whole local on failure. Cache deleted at compose entry (873); `remember=false` (834).
- **Remembered whole server:** compose deletes `serverAnswers` and does not store the reply. Queries without `components` still use `remembered` on failure (812, 889).
- **Pending write:** entry and post-reply `pending()` (868, 878). If a predictable write is unobserved, local stands.
- **`held`:** compose gated on `!held` (871); `server()` denies offline for held (814).
- **Watches:** one `evaluateLocal` then one `notify` (`rerun` 918–933). Concurrent invalidation sets `dirty`, does not patch fields.
- **Dependencies:** `tables` is one `Set` mutated by first local, server JSON, and second local (856, 829). `nextExpiry` is `min` of both (886–887).
- **Without `components`:** `Object.values({})` is empty; compose skipped; `wantsServer` matches BASELINE (`!held && !retained && (denied ? unknown : complete === false)` vs old 848-era predicate). Extra `unavailable()` before the device call is the only observable delta (close/sign-out).

**Contract hole:** compose copies only `c.retained` (881–885) and enters only if `some(retained)` (871). A complete local field that would not `wantsServer` as its own query is taken from the server whenever any sibling needs the server.

### 6. Disclosure and authority

Per-component coverage is attached only to the device `query` JSON (`call.rs` 90), never to `POST /q/<name> {args}` (816). Server `Runner` has `component_observation` false and `device` false (`engine/mod.rs` 715–732). `GET /schema` now may carry `operations.*.components` (field names + statement indices). That is static compiled fact, not coverage, private sites, or cardinality.

Second local evaluation sees applied deletes, expiry, rejoin (held, not left), and until-revoked drops. Composition cannot resurrect until-revoked or expired rows once the device has dropped them. Stale in-flight server replies after rejoin are used whole when no retained component remains (plan’s no-retry rule; test `MQ rejoin`).

## Findings

### High — compose keeps `retained` fields, not “the host that would have answered this field”

**Where:** `packages/snapback4/src/local.ts` 849, 871, 881–885; `engine/read.rs` 281–313; binder `components.rs` 53–59.

**Scenario.** After leave, device holds `messages` row `left-1`. Query:

```quarry
query both():
  return {left: messages['left-1'], held: messages['held'] last 50 by byTime}
```

Binder emits a two-field plan (one Get, one Scan). `get` finds `left-1` and never calls `retained_group` → `{complete: true, unknown: false, retained: false}`. Held is unknown. `some(wantsServer) && some(retained)` is false. Whole-query fallback: server `{left: null, held: [26]}`. As its own query, `return messages['left-1']` stays on the device (`complete: true`). `check --residency` still prints `components: held, left`.

**Fix:** enter compose when `some(wantsServer) && some(!wantsServer)` (and not pending). Copy every `!wantsServer(c)` field from the second local, every `wantsServer(c)` field from the one server reply. Same predicate as 849.

### Medium — a later shared meter cap is written onto earlier field frames at `return`

**Where:** `engine/components.rs` 71–76; pinned at `device/tests/components.rs` 86–90.

**Scenario.** `both()` with `Ceilings.examined = 30`: left binding scans 25, held caps. Left’s data is the full 25. `component_record` then evaluates fields in `BTreeMap` order; after the cap it sets `capped` on **left** as well → `retained: false`. Client skips compose and shows the server’s empty left. Alone, left with examined 30 would complete.

**Fix:** note `capped` on a field only if `capped_at` flipped during that field’s `expr`, or only on `begin_component` for statements that run after the cap — not on a post-cap variable lookup. If the shared-meter rule is kept, say so on the sync card (composed reads near a ceiling may drop retained fields).

### Medium — negative tests pass if the planner is a no-op

**Where:** `snapback4-lang/tests/components.rs` 28–50; `retained-history.test.mjs` 128–138 (`MQ ineligible`).

**Scenario.** `prove` always returns `None`: `excluded_source_shapes_keep_no_plan`, `inline_cross_read_aggregate_has_no_plan`, and `MQ ineligible` (`components === undefined` plus whole-server bodies) still pass. They do not prove those shapes were classified; they prove no map was emitted.

**Fix:** keep a positive control in the same test (as `nested_sinks` does at line 70). For `MQ ineligible`, assert the compiled backend’s `schema.operations[name].components` is `[]` **and** that `both` on the same client has a nonempty map (already true in `R2 mixed result`; join them or assert `both`’s device reply has `components` in the ineligible test).

### Low — docs require `--verbose` to name components; code prints them without it

**Where:** README 1156–1157; `guide/sync.rs` 124–125; `verbs.rs` 201–204; `residency.rs` 399.

**Fix:** “`check --residency` names the proven components.”

## Did a change introduce a new problem?

At BASELINE, mixed left/held **scans** lost left rows online; that is fixed. The new problem is a **false residency signal**: `Execution.components` and `check --residency` advertise composition for any independent record, including shapes whose device-side field is complete but not `retained`. Those still take the whole server answer. That was already lost at BASELINE; it is now labelled as composed. Default-ceiling ticket scans are not slower or less durable. `GET /schema` grew an optional compiled field; query POST is unchanged.

## Regression tests that would also pass without the change they claim to test

1. **`excluded_source_shapes_keep_no_plan`** — empty is the default. Assert a sibling `both()` has `len()==2` in the same function, then empty for each excluded source.
2. **`inline_cross_read_aggregate_has_no_plan`** — same. Pair with the bind-once form that also has no plan **and** the two-field form that has a plan (already in `independent_fields_…`).
3. **`MQ ineligible`** (`retained-history.test.mjs` 128–138) — whole-server bodies and `components === undefined` are BASELINE. Assert `both` on that client has a component map, or read `operations.*.components` from the adopted backend.

`R2 mixed result` (183–228) and `r2_n3_mixed_returned_history_exposes_independent_components` would **fail** without the change (0 left vs 25; missing `components`). Those are real.
