## Primary defect: email domain splitter drops one character

In [text_samples.rs](/home/ccheever/projects/sb4-b32-sec12/snapback4/crates/snapback4-lang/src/bind/security/challenges/text_samples.rs:17), the label count is `domain_length.div_ceil(64)`. A domain of D characters with L dot-joined labels carries D − (L−1) letters, and each label holds at most 63. That requires L ≥ (D+1)/64 rounded up, not D/64. When `domain_length` is a nonzero multiple of 64, the code picks one label too few, the 63-per-label cap silently drops exactly one letter, and the emitted value is one character shorter than the computed `length`.

I mirrored the loop arithmetic outside the repo and observed: domain 63 → exact, 64 → 63 (shortfall 1), 127 → exact, 128 → 127 (shortfall 1), 189 → exact.

Reachability: total length 66 gives local 1 and domain 64; total length 130 gives local 1 and domain 128 (see [text_samples.rs](/home/ccheever/projects/sb4-b32-sec12/snapback4/crates/snapback4-lang/src/bind/security/challenges/text_samples.rs:13) for the length accounting). Length is min-driven (variant terms are tiny in every caller), so this fires exactly when an email column/argument declares minimum 66 or 130 with a permitting maximum. Both bounds are satisfiable: minimum 66 admits a 2-plus-63 address, and minimum 130 admits a 1-plus-43/42/41 address. The short sample still passes `format.matches` (a shorter valid address), so `text()` returns it; ordinary row/argument validation then rejects it for violating the minimum. Nothing unsound is ever admitted, but S1's "obey minimum, maximum and declared format together" fails and "impossible bounds remain uncovered" is wrongly extended to satisfiable bounds, surfacing as fixture/snapshot `unsupported` rather than coverage.

Fix: `let labels = (domain_length + 1).div_ceil(64);` (equivalently, keep adding labels while letters exceed 63 per label).

Test gap: the `every_declared_format_obeys_both_bounds_including_email_limits` grid uses minimums {0, 1, 3, 8, 63, 64, 65, 128, 253, 254, 255}, which never produce total lengths 66 or 130, so the test passes despite the bug. Adding 66 and 130 to the minimum grid (or asserting emitted length equals requested length wherever a sample is returned) would catch it.
