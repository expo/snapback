Three **MATERIAL blockers** remain:

1. **Early refusal finalization can deadlock on the same request-size refusal it must resolve.**  
   [RFC §3](/home/ccheever/projects/sb4-w9-media/llp/3000.038.000-durable-offline-media-intents.rfc.md:120) requires `/finish` to resend unchanged operation arguments. Both mutation delivery and `/finish` use the **1 MiB JSON request ceiling** in [serve.rs](/home/ccheever/projects/sb4-w9-media/snapback4/crates/snapback4/src/serve.rs:600); [uploads.ts](/home/ccheever/projects/sb4-w9-media/snapback4/packages/snapback4/src/uploads.ts:159) includes those arguments again.

   Admission bounds upload bytes but does not bound the placing arguments. Consequently, an admitted intent with arguments exceeding that ceiling can upload successfully, persist `begin_send`, receive an early `E_INPUT`, and then receive another size refusal from `/finish` forever. The pin and FIFO head remain unresolved; local cancellation now refuses because dispatch persisted.

   **Required design resolution:** bound the complete eventual placement and finalization envelopes before admission, or provide bounded finalization using an immutable argument digest with equivalent replay binding.

2. **Orphan adoption can silently destroy a conflicting admitted capture.**  
   [web-worker-orphans.ts](/home/ccheever/projects/sb4-w9-media/snapback4/packages/snapback4/src/web-worker-orphans.ts:52) and [web.ts](/home/ccheever/projects/sb4-w9-media/snapback4/packages/snapback4/src/web.ts:531) deduplicate transfers using only an existing-id set. When the destination already contains an id, adoption skips insertion but still marks the source entry for deletion.

   Concrete sequence: two offline tabs admit the same explicit id with different bytes or placing arguments; one becomes an orphan. Adoption deletes that orphan’s byte custody without comparing immutable input or reporting `E_WRITE_ID_REUSE`. This contradicts §2’s custody and changed-input guarantees.

   **Required design resolution:** compare original input and viewer/store binding during transfer. An identical durable destination may take custody; a conflict must preserve the source and expose a typed refusal. Transfer quota enforcement is present on the latest reread and is **not** a blocker.

3. **The recovery inventory bounds output, but not recovery work.**  
   [asset_uploads.rs](/home/ccheever/projects/sb4-w9-media/snapback4/crates/snapback4-core/src/engine/asset_uploads.rs:142) applies `LIMIT 51` after filtering historical intent rows. [store.rs](/home/ccheever/projects/sb4-w9-media/snapback4/crates/snapback4-core/src/store.rs:288) provides only the `(owner, intent)` primary key. Permanent cancelled/settled receipts—and pending rows excluded by `_ops`—can require a lifetime-sized scan while holding the engine guard.

   An in-memory SQLite probe using this query returned **zero entries** but required **4,029 VM steps for 1,000 historical cancellations** and **40,029 for 10,000**. The 128 MiB active-pin quota does not bound historical receipts.

   **Required design resolution:** maintain a transactionally updated active-pin index/set, or bound examined candidates and return a continuation even through empty filtered pages.

The remaining core design is coherent: committed byte custody precedes admission acknowledgement; readiness precedes mutation dispatch; asset dedup and cancellation tombstones share ledger transactions; pathname synchronization precedes receipt publication; ordinary mutation receipts retain at-most-once execution. Viewer/store binding, unresolved-head exit fencing, native sharing cleanup, and the public typed states have explicit owners.

One **implementation gap**, distinct from an unresolved design decision: [uploads.ts](/home/ccheever/projects/sb4-w9-media/snapback4/packages/snapback4/src/uploads.ts:193) treats a replayed `E_UPLOAD_CANCELLED` as permanently blocked. It does not implement §3’s promised automatic local settlement after server recovery cancellation.

**Verification limits:** I inspected the upload tests but did not run the integrated suites or native simulator. Missing larger-history, conflicting-orphan, oversized-finalization, and server-cancel/reopen fixtures are test gaps; the blockers above follow from concrete protocol paths and the SQL probe.
