## Scope B — Promotion design (spec §6, no implementation exists)

Confirmed: no `promote` implementation exists in the snapshot. The design amends only the §1 no-promote boundary, keeps ordinary copies staging-bound, and forbids relabel, merge, overwrite (including empty directories), nested destinations, and live sources. Snapshot-via-backup-surface, lock-holding, purpose-change-on-private-copy-first, strict preflight including unchanged source, zero-clock with frontier check, per-proof obligations, and atomic no-replacement publish are all sound.

Two material fixes required:

1. Session carryover. The design keeps "ordinary session state" and password identities but re-mints only operator/service credentials. Staging user session tokens would then authenticate against production data. Specify expiry or rotation of copied user sessions on the candidate, or justify why they cannot validate there.
2. Promotion provenance. Release ids, revisions, and events are copied verbatim, so one id will exist in two deployments. Record the staging origin, source release, and clock status in the new deployment's immutable provenance so the duplicate ids stay auditable.

Recommended: name the no-replacement publish primitive (with macOS fallback) behind the already-required raced-destination proof, and state how the command acquires the owner lock on a stopped source during the long copy.
