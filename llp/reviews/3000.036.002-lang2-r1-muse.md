NOT READY

Three material contract gaps in §10 (plus one modeling gap). All refer to the amendment text, checked against the implementation and governing documents.

1. Dormant-delete contract is unobservable and overbroad (delete-source coverage).
   - §10 promises an unbounded cascade/set-null edge with no live delete source "receives N_CASCADE_DORMANT", but `N_CASCADE_DORMANT` is only registered in `guide/codes.rs` and never emitted anywhere. A dormant edge is therefore silent, and "adding a source rechecks" has no named signal.
   - "cannot be deleted by any declared delete rule" literally includes `delete <- deny` (a declared rule that admits nobody); the implementation correctly treats deny as no source (`delete_source` requires `delete != Deny`). As written, a deny-table parent would wrongly require a cap.
   - Required corrections: (a) narrow to "any admitting (non-`deny`) delete rule"; (b) fix the emission site in the contract — one `N_CASCADE_DORMANT` at each dormant unbounded edge's column site, silenced by adding the cap — and emit it.

2. Bounded exactness omits the null-exempt-cap exclusion (boundedness).
   - LLP 3000.039 §2 states a cap on a `set null` column never proves a population bound and defers the non-null-pin recovery to §10 ("§10 records it"). §10 contains no null language at all: "a schema-enforced finite cap whose group is completely pinned" would admit a null-exempt cap, whose null group is unbounded. The validator is safe (`group_bound` respects `cap_exempts_null`), but a from-spec implementation would certify an unbounded null group complete.
   - Required correction: state that a null-exempt cap (a `cap N by col` on an `on delete set null` column) never qualifies for the exhaustion lane unless the pinned value is proved non-null; otherwise the lane stays incomplete. This is the record 039 §2 asks for.

3. Negative-membership "extra equality tests" are unconstrained (boundedness/modelability).
   - §10 extends the vacancy walk to "an exact total unique point with one varying outer column and fixed viewer/literal components, plus extra equality tests." The trailing phrase has no totality or shape constraint. The validator only admits `Field`/`Viewer`/`Literal` terms with exactly one `Field` (`vacancy_branch`), and the planner only admits `fixed_key_total` keys — a fallible or row-reading "extra test" is not an exact point.
   - Required correction: constrain extra equalities to total fixed terms (viewer, literals, and the single varying outer field), and decline anything else, matching the validator.

4. No Lean/model verdict for the two new admissions (modelability).
   - Bounded exhaustion lanes and extended (non-`id` unique) vacancy keys change page completeness, but §10's verification line ("Lean cases cover the changed semantic families") names no classifier verdict. LLP 3000.036.001 §18 explicitly mirrors each admission in the Lean surface classifier; §10 must do the same.
   - Required correction: state the Lean `decided` verdict for the bounded-exhaustion lane and for extended vacancy keys (or name them explicitly unsupported with oracle exclusion). Point lanes need no model change (plan-only, same rows) — say so explicitly so the omission is deliberate.

Verified sound and needing no change: runtime refusal on missing reservations (operator/external IR deletes fail closed via `delete_reservation: None` → `Schema` error, devices queue); cascade-only reachability traversal (set-null does not propagate deletion); `total_unique` requiring non-optional columns for point lanes; `deny` exclusion and cycle/ineligible-target refusal in core validation; v5 fencing that keeps legacy `.id` vacancy on v4.
