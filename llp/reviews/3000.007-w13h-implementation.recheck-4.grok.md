## Findings

**High — Collector promotion still promotes a nested page that is not the item or a shape of it.**

- **Where:** `snapback4/crates/snapback4-core/src/engine/pages.rs:248–252` (`OriginMode::Payload` skips `Scan`/`Merge`) and `453–472` (promotion).
- **What is wrong.** The round’s rule was: promote only when the push is the loop item or a shape of it; otherwise keep the join’s `Unknown`. The code implements a weaker rule: promote unless an *incoming* alias/field still `may_carry_page`. A nested scan is erased by the probe, so a one-to-one collector of `msgs[0] after c first 1` is assigned `Page(P, c, Some({loop}))` exactly as `bag + [page]` was on `31ec7136e1`. §5.6:556–559 blesses nested reads **inside an item’s shape**, not a payload that *is* a nested page. The journal row at 32812/32825 documents this as intended; it is not what the brief asked, and it reopens the class.
- **Scenario.** Same prelude/rows as `w13h_collector_wrapping_raw_page`, but `bag = bag + [msgs[0] after c first 1 by byLane]` **before** `ignored = page { id, preview: extra[1] first 2 }`, then `return { mystery: bag, page: ignored, shaped: ignored }`. First answer can contain `[[a]]` in `mystery` while `ignored` is starved; `next` is `ignored`’s inclusive rewind; the follow returns `a` in `mystery` again. `item { id, raw: page }` is tested and stays unpromoted; `item { id, raw: msgs[0] after c first 1 }` is an item shape (LLP-permitted) and is a separate two-shape issue — the hole here is the non-item payload.
- **Smallest correct change.** In the payload probe, keep treating the item (and field access / `Shape` of the item) as non-page, but still treat `Scan`/`Merge` as pages unless they occur inside that item shape. Refuse promotion when the ordinary origin (item cleared, scans visible) is `Page` or `Unknown`. Add the re-scan wrapping form to the shared suite, exhausted and not, on all three hosts.

No Critical. No new owner-loss on `Record` vs `Empty` or on the other `join_origin` pairs with a unique site. No trim-without-rewind form. Recheck-3 closures and the protected runtime regions are intact.

Verdict: NOT READY
