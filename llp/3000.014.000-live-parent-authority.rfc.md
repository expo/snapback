## 1. Decision and review authority

Wave 14 lanes 007, 032 and 085 ask for children readable by their parent's
current readers, including when its department or assigned principal changes.
Propose `read through live .parent`, the child's whole read rule, implemented
by compiler-owned copies maintained atomically on every parent policy write.
Unlike captured `read through`, policy inputs may change. Unlike the manual
recipe, builders neither declare the copies nor implement transfer loops.

This revision replaces **all normative text** of revisions 1 and 2. Those
revisions remain in git and their reviews remain linked in §10. There is no
parent-keyed sync scope, authority manifest, global authority counter, staged
manifest swap, extra reverse membership traversal, or new expiry algorithm.
The bounded population is the set of child rows of one parent, declared by
the builder as an ordinary product constraint. Reject shapes whose bound or
transactional maintenance cannot be proved. Do not approximate the rule.

Revision 3 is retained at `3b6df35e59`; its paired NOT READY reviews are in §10.

The LIVE workstream commission on 2026-10-17 authorizes up to five additional
paired rounds (3–7), then implementation only after both reviewers mark the
same revision READY. If not converged, leave Review and ship no partial form.
The earlier RULES4 two-round fallback remains shipped and valid until then.

## 2. Surface and admission

Example (illustrative Quarry until implemented):

```quarry
table departments:
  public 'department names'
table members:
  department: departments
  principal: principal
  unique department, principal
  immutable department, principal
  read <- .principal = viewer
  insert <- allow
  delete <- .principal = viewer
table projects:
  department: departments
  read <- exists members[.department, viewer]
  insert <- allow
  update <- allow
  sync
table tasks:
  project: projects
  body: text <= 2000
  immutable project
  cap 20 by project
  read through live .project
  insert <- allow
  update <- allow
  sync
```

The parser represents a separate live-through declaration; it is not a rule
term and cannot appear under `not`, conjuncts, or a second read declaration.
The binder produces `Through.mode = Live { max_children: N }`; old serialized
Through has default Captured mode. It maps *every* focal parent read-rule
field to the same private typed engine field used by captures today. The
compiled read rule is the **whole** parent's rule with those substitutions,
including every disjunct, predicate, literal and service grant. Its map and
mode participate in Through.identity. No hidden field is author-writable,
query-visible, in `*`, or present in generated public types.

Admission (checked both by the language binder and core schema validator):

1. Reference is required, immutable, ordinary application-table typed and
   default-free. Child has `cap N by reference` with exactly that one key;
   take the smallest matching positive N. A whole-table cap is not accepted
   as a substitute in this revision. Parent and child have no time bounds,
   no ephemeral state, no engine-generated/maintained columns, no timelines,
   no row/aggregate views sourced from either endpoint, and no field owners.
2. Parent has no Through. No captured or live table may use a live table as
   its parent. Thus captured-over-captured stays unchanged; all live/captured
   mixed edges and live-over-live are refused. One parent may have multiple
   separately capped live child tables; prices sum across those schema edges.
3. Parent RuleExpr must use only Public/Allow/Deny, direct focal scalar fields,
   viewer/literals, Eq/Ne, And/Or/Not, and ordinary Exists with total unique
   keys. Refuse created predicates, live rule-hop terms, maintained/private/
   recorded inputs, nonordinary probe targets, not-before and expiry anywhere
   in the transitive read-probe graph. Compute the graph by visited table set,
   including cycles; inspect every reached table's time declarations and
   Through/ephemeral/derived classification. A non-time membership Exists is
   accepted. An identical membership target with `expire at` is refused.
4. Sync inference uses the *entire substituted rule* and existing exact
   audience admission. Whole service disjuncts are removed only by the
   existing service-audience recognizer. A single public, principal-column or
   membership audience syncs; a union or any other noninvertible parent rule
   requires an `online only` live child. A union-synced parent may have an
   online live child, as existing union validation permits, but cannot supply
   that child with sync. No union/Through admission is widened.
   Refuse delivered-history and horizons for a live child: use all-current,
   until-revoked sync. No service-only branch creates a device audience.
5. A parent may be online only even if a child's rule is invertible. Such
   children sync via their copies as captured children do; device parent-
   pinned completeness may need server fallback if the parent is not held.

### 2.1 Closed predicate and referential-action boundary

The core validator, not only the binder, checks the following closed predicate.
Admissible rule nodes are `Allow`, `Deny`, `Public { reason }`, `Eq`, `Ne`,
`And`, `Or`, `Not`, `Exists`. Admissible terms are `Viewer`, `Literal` and
`Field` naming id or a declared ordinary scalar column; inspect every key and
extra equality term. Refuse `Reference`, `ReferenceChain`, old/next-image and
other term forms. Scalars are required/optional Id/Principal/Ref/Bool/Int/
IntRange/Time/Decimal/Money/Enum/Text/Bytes; refuse List/Json/asset terms. A
literal must have the binder-proved comparable type. Public and Allow both
have zero mapped fields. A total unique key has every nonoptional key column
pinned, or has a same-term non-null proof for each optional key argument;
A non-null proof is exactly Viewer, a non-null Literal, or Field of a required
column, and nothing else; guarded optional fields are refused for this initial
live admission rather than introducing a binder-only proof. The binder and
core apply this identical structural predicate. Fully pinned supersets keep
all extra equality checks. Core validation uses
its existing unique-probe admission, not a new interpretation of positional
arguments. Created and unsupported variants refuse before substitution.

For endpoints, the closed refused declaration set is `not_before`, `expire`,
`ephemeral`, `recorded`, `maintained`, `written_by`, `sequences`, any timeline
ownership, non-visible generated table, maintain target/source/row-key source,
and parent Through. Child Through is the one being checked. Its live reference
must use `on delete restrict` (the default). Every other authored reference on
both endpoints must have a non-writing action: Restrict or Keep. If any endpoint
`on_delete` entry is Cascade/SetNull, refuse with the field's `on delete restrict`
rewrite. This prohibits *all indirect reference-action writes into an endpoint*:
reference actions write the referencing table, and an action path reaching an
endpoint must end in such a prohibited declaration. Unrelated action graphs
remain unchanged. There is no new live-price composition through those graphs.

For every table reached via a read-rule Exists (including cycles, visited once),
refuse time bounds, Through, ephemeral/generated/derived/recorded/private-field
state by the same declaration checks; sequences on probe targets are harmless
but still refused initially. Probe indexes must be ordinary total unique keys.
Probe target read rules do not grant authority to a bare Exists, but scanning
them for this conservative transitive exclusion is intentional. Probe horizons
and leave policy are not time authority; their current device coverage rules
still apply. An absent witness cannot become true through negation unless its
absence is covered, as in the existing rule evaluator.

Child indexes may only be plain column indexes. After generation, prove each
encoded key's schema maximum (including id and separators) <=
`rows::MAX_INDEX_KEY_BYTES`; reject word/computed/contribution indexes and
unbounded/oversized key shapes, with a smaller scalar-bound or online manual
recipe rewrite. This proof applies to the hidden audience indexes as well.
Activation refuses grandfathered oversized stored keys. No policy patch can
then fail only because a hidden child forms an oversized combination.
Neither endpoint may serve as the target table of any sync audience: this
removes membership-delivery fanout from private maintenance; ordinary probe
rosters remain valid and use existing group delivery. Multiple child tables
for one parent are admitted, each independently capped and priced.
Refuse either endpoint in **any role** of a ReceiptFamily (scope/counter,
messages, members, runs or receipt source/marker), including inferred receipt
families. Audit the family's complete table-role list, not just scope. This
prevents commit_receipt_counter and allocation/marker maintenance from writing
an endpoint without a source reservation. Ordinary rule-probe rosters that
participate in no receipt family remain admitted. The refusal names the family
and endpoint role and links the manual current-roster recipe.

Accepted/refused pairs: Public parent with no focal fields / Public parent
with an expiry; nonexpiring `exists members[.department,viewer]` / same rule
with expiring members; full owner OR support rule online / that union on a
synced live child; ordinary Restrict reference / SetNull reference on the
parent; direct Field / ReferenceChain; one live edge / live parent used as a
captured parent. All refusals preserve the authored whole-rule meaning.

Use E_READ_THROUGH for unsupported shape, with the offending declaration and
an executable rewrite: add `cap N by reference` (a product limit chosen by the
builder); or keep captured semantics with immutable policy; or use the manual
current-roster transfer recipe; or online live keyed probes for rules those
probes can express. Never silently choose a cap or drop part of the rule.
`check` prints the declared cap, full fixed policy-write price and server-only
prediction fence, including the fact that a very large cap may make parent
writes exceed unchanged transaction ceilings even when no children exist.

## 3. Invariant and lifetime

For every active stored live child c with parent p:

- p exists in the same store;
- c.reference is p.id, and every private mapped field equals p's current
  corresponding field, with its declared type (null remains a value);
- the number of stored children for each (child table, reference) is <= N.

Since endpoint tables cannot expire or open later, the active physical child
population equals the ordinary cap population. Dormant rows are not active
and do not contribute until restored; restoring must revalidate the invariant
and cap before publication. No sweep or mutable inherited deadline is needed.
Child copies of deadline fields remain null, using the existing capture row
layout; unrelated ordinary/captured tables retain their current lifetime rules.

Use captured-through's existing physical-child restriction for parent delete,
including parent read authorization before occupancy. Parent id reuse remains
blocked while any physical child exists. Do not permit cascade or set-null on
the live reference, and do not weaken existing restrictions on ordinary refs.
The normal child cap is enforced on insert, upsert insert arm, insert-if-absent,
seed/import, system writes, adoption, dormant restoration and trusted restore.
A direct child update cannot change its parent or its private policy fields.

The invariant makes read-rule evaluation over copies exactly equivalent to
reading the current parent fields, for each committed server state and after
each complete language statement in a writing transaction. Exists probes stay
live (no membership copies). A membership revoke changes no child image and
uses the existing membership rule dependency and partition invalidation path.

## 4. Atomic maintenance algorithm

The binder generates a `$liveChildren` ordinary index `[reference, id]`,
distinct from the existing lifetime index. The core validator requires its
exact plain, nonunique shape, along with the cap and hidden-key maximum proof.
It is created/rebuilt before accepting writes.
Compile reverse edges once per schema: parent table -> sorted list of
(child table, reference, input map, N). This is schema-sized metadata only.

Before *any* parent target lookup/arm selection, reserve the sum of all child
edges' maximum maintenance prices, regardless of old row existence, policy
values, whether the patch mentions policy, or actual child counts. Reserve
once per source write attempt, not once per transaction (several writes to
the same parent may occur in one mutation). Upsert prepays both arms once.
All ordinary hidden-target meter restoration rules still apply.

After the authorized parent row/index write, and before the statement returns:

```
for edge in schema.reverse_live_edges[parent_table]:
    children = private_index_scan(edge, parent.id, limit=N+1)
    if children.len > N: abort entire transaction as store invariant failure
    for child in children:
        next = child with mapped engine inputs stamped from new_parent
        if next == child: continue
        replace image and all indexes using internal LiveAuthority origin
        row_changed(child, old, next, LiveAuthority)  # logs and invalidation
```

The hook is in the shared physical row-change tail, not a language operation
visitor. It covers direct update, both upsert arms, seed/import/system/restore
writers and no reference-action replacements (refused by §2.1). Delete takes the existing child
restriction rather than copying from None. Child insertion stamps current
parent inputs and requires a live readable parent, plus its own insert rule.
The transaction's uncommitted parent image is visible to that stamp. A child
inserted before a policy edit is included by the reverse index; one after it
stamps the new fields. Every subsequent program read observes the maintained
state, and any later failure rolls back rows, indexes, logs and metadata.

LiveAuthority origin may change only mapped engine inputs. It neither invokes
child authored update authority nor grants that authority to the caller. It
validates the F replaced scalars against the parent/child type map, preserving
every other validated cell and all authored constraints (which cannot name
engine fields). It replaces indexes and preserves caps, asset placements,
row-change logs and written-table dependencies. It does not run a whole-row
constraint/probe walk over unchanged private cells. No derived-data
recursion is admitted in §2. Only the core can mint this origin; client-supplied
engine fields continue to refuse before lookup. The parent write's own table
rules remain mandatory, including blind authorized writes as currently allowed.

### 4.1 Authoritative writer inventory

| Entry | Enforcement before commit |
| --- | --- |
| Direct update, upsert update, jobs/system language writes | target-attempt fixed prepayment; shared row_changed maintenance |
| Insert, insert-if-absent, upsert insert | same target-attempt prepayment for a parent; capture_insert stamps a child from this transaction's parent |
| Engine::seed/seed_at, seed_server_rows, Postgres seed | ordinary upsert path and stamp/maintenance; postbatch invariant validation |
| Engine::load Import | any Through schema routes through seed; cannot supply engine authority fields |
| Engine::load_stored_rows Restore, Postgres::load_trusted | separate bulk barrier: strip imported live inputs, install all endpoint rows privately, recalculate child inputs from installed parents, validate cap/references/indexes, then regenerate affected partition events from final images and commit |
| Activation, rollback, dormant restore | §7 before-projection/reverse-correspondence barrier and bounded rewriter; no ordinary writer-tail assumption |
| Reference-action endpoint replacement/deletion | statically refused by §2.1; a forged direct schema also refuses |
| Device imported persistent state | store identity/generation and capability checks, trusted only at existing device persistence boundary; never server authority |

Restore installs a *whole consistent image* or rejects: it cannot partially
restore a parent's old policy while leaving existing children trusted. The
bulk barrier also scans existing children not present in the restore input;
recaptures all from the final parent. It preserves historical non-live
attribution but never trusts imported live copies. Do not emit intermediate
put/del events before this validation. The retained-state account is §4.2;
there is no assumption that PendingEvents is a streaming data structure.

### 4.2 Bounded bulk-call account

For schemas containing a live edge, every server seed/import/trusted-load call
uses **one** `Ceilings::job()` Abort meter for its entire atomic input/maintenance
transaction, with ordinary source and fixed live-edge reservations. Do not use
an unbounded meter or reset it between rows/pages. An iterator is consumed only
through byte-admitted pages; before `ancestor_order`/seed_server_rows could
collect a batch Vec, reserve its serialized images, ids, deep decoded copies,
ordering slots and vector capacity against this same account. A too-large
batch returns E_BOUND and commits nothing. The cap is the existing job envelope
(8192 writes, 16384 examinations, 16 MiB heap and other job dimensions), not a
new or raised ceiling. No claim that a whole arbitrary backup fits one call.

Preserve the earliest before-image or before-audience for every distinct input
identity, *and* every existing child that may be recaptured, before installing
its first replacement. Admission includes the identity map's key/capacity,
source image D, all retained PendingEvents slots (including withdrawn slots),
row/grant position vectors and born/touched/created maps. Use a bounded collector
wrapper that reserves before every growth, and shares the bulk meter; an
allocation failure/limit aborts with E_BOUND before memory is owned. Slots
already covered by held source/edge event reservations spend those credits
instead of charging twice; the wrapper accounts any uncovered allocation
before growth, and never releases credits for still-retained storage. Coalescing
identities are keyed (table,id); repeated images retain one original boundary,
but each retained slot and temporary input copy is still charged.

After full invariant validation, regenerate only final boundary events under
the same account. Before PendingEvents::take and partition::append, reserve
the dense event vector and whole-call append/coalescing-map peak in addition
to the still-resident collector. These allocations are not free merely
because images share Arc. Compute owned image/map/key/Vec allocations with
the existing internal heap helpers before growth; retain the charge until
append consumes/drops them. Event ordinals continue monotonically across the
one transaction and preserve ordinary birth/grant/withdrawal order. A callback
page's transient heap can release; any before-image, pending event, identity or
append slot that outlives it cannot. The bounded account includes finalization,
so a 100,000-parent restore fails atomically well before retaining 100,000
boundaries/events even though every per-parent child cap is one.

For SQLite and Postgres this is the same core BulkLedger/BulkCollector around
their respective seed/load entry points and common PendingEvents/append flow;
each store still preflights its own native row/key/statement scratch. No SQL
transaction is committed early. The operator rewrite is to split the input
into coherent bounded parent-plus-children batches (each final batch passes
all reference/copy invariants), or restore an offline database image and run
ordinary destination adoption before serving. Do not suggest chunking a single
parent's transfer: if that cap's fixed write price cannot fit, it remains a
single atomic refusal. Trusting an offline database image does not waive the
ordinary opening/version/identity/adoption validation.

## 5. Reservation and accounting contract

Use the seven existing Price dimensions; ceilings do not rise. The new helper
`schema::live::edge_price` is shared by full-schema compiler/server validation;
the device only consumes the exported price. Definitions for one child edge:

- N: declared cap; F: mapped scalar count; C: stored column count.
- D: `rows::disclosed::decode_reservation(child)`; unlike row_copy_ceiling,
  this includes private decode/serialized scratch, nested values and asset
  facts. P is the same bound for the parent, prepaid by the source writer.
- K = `MAX_INDEX_KEY_BYTES`; for each plain index i with width w_i define
  `B_i = 4*K + 128*(w_i+1) + 512`. This covers an owned encoded buffer,
  geometric growth, owned scalar components (bounded by the proved encoded
  key), per-Value slots, and index vector headers. Let B=sum(B_i), W=sum(w_i),
  I=index count. All indexes, including unchanged ones, are counted.
- A is 0 if no child sync, otherwise 1 (unions are refused). L is the larger
  of the child and parent table-name byte lengths, each also bounded by the
  portable index-label gate. M=`1024+4*K+4*L` bounds partition strings, row id,
  set/map entries and event metadata. E=`2*A*D + (2*A+4)*M` is retained event
  and per-row commit-bookkeeping storage, including born/touched/created maps.
  No child table may be an audience target (§2.1), hence no dependent joins.

Define the full edge reservation:

```
steps        = (N+1) * (64 + 8*(F+C+W) + 4*A)
index_entries= 2*N*I
examined     = N+1
rows_written = N
heap         = (N+1)*(D+K+256) + 4*D + 2*B + N*E
output       = 0
rule_probes  = 0
```

The scan retains at most N+1 private decoded images plus keys/vector slots;
the singleton sentinel diagnoses corruption. Replacement needs old/new map
copy-on-write and serialization scratch (4D); `index_write` simultaneously
holds all old/new key sets (2B), even unchanged indexes. Event collector
images/bookkeeping survive the write attempt (N*E). The constant 64 covers
scan/loop/write/row_changed bookkeeping; each scalar stamp, map cell copy and
key component gets up to eight logical steps; four per audience for old/new
partition handling. No recursive rule or derived-data walk runs under this
origin, so neither extra probes nor output are priced. Asset placement is
unchanged and does not walk the upload ledger. The parent image and public
result remain paid by ordinary source-write admission, not by this edge.

Extract event metadata construction from `schema::reservations::reservation`
(the existing inline ActionEvents calculation) into shared
`schema::reservations::event_envelope`; the live helper uses the explicit
D/M bound above and checks it is at least that helper's envelope. This names
a new extraction, not an existing exported function. Fixed source prices sum
all live edges using checked arithmetic; overflow refuses schema admission.
Missing projected live prices are a device prediction refusal, never zero.

Charge every edge's full non-heap dimensions and heap reservation before parent
lookup, including no-op writes and empty populations. N*E remains reserved
until the request ends; transient scan/index/copy heap releases after the
statement. Internal LiveAuthority work runs with a separate **bounded**
`Meter::new(edge_price ceilings, Abort)` and request physical allowance;
never `Ceilings::unbounded`. Its actual consumption is private. All index,
step, row-change and partition charging routes to that meter for this origin,
including the existing `origin == Maintained` charge branches. Neither double
charge the public meter nor silently skip physical accounting. Prepay/draw
N+1 physical child examinations before the first scan; native serialized
scratch is checked under D before private materialization. If this ledger
exhausts despite a valid invariant, abort generically and report an internal
reservation bug; never expose actual child work in a public Bound.

Bounded-ledger exhaustion is a design failure to fix before qualification,
not accepted ordinary product behavior. The price above is deliberately
conservative; check prints it even when it makes a large declared cap
impractical. Boundary tests independently count operations/retained bytes,
including many narrow indexes, maximum scalar keys, assets and nested payloads.
Parent update prediction is fenced via separate `live.server_execution=true`;
do not overload existing `server_only` (which means no fixed action price).
No indirect action can write an endpoint, and the direct root parent delete
keeps its ordinary reservation plus one live attempt reservation (a fixed prepayment for all attempt shapes,
including delete; the maintenance hook itself never runs for new=None).
Delete then runs the ordinary read-authorized physical-child restriction, not
a copy loop; it never enumerates policy maintenance through an action closure. The user's chosen
cap is not inferred from any private row population.

## 6. Completeness, invalidation and device contract

Server planner uses a distinct live uniformity witness: parent-pinned pages
resolve parent authorization once as today, then rely on §3, never on
immutable-input validation. Ordinary non-parent-pinned filtering and caps stay
unchanged. Completion still needs child range/horizon coverage. A denied or
absent parent yields known empty only on the server or with device coverage;
unknown remains unknown. Aggregates sourced from either endpoint are refused
by §2 until separately designed. Assets always use the child's complete read
rule and cannot bypass current authority through a cached placement.

Both endpoint tables and every probed table are dependencies of live child
reads. Each maintenance write marks the child table written; even empty-child
transitions mark it conservatively so subscriptions reconsider empty answers.
Use existing bounded subscriber scheduling after commit (no callback loop
inside the parent transaction). Watchers reevaluate on generation changes,
parent/roster writes and device coverage publication. Private evidence stays
host-only and no hidden parent fields enter cursors or public refusals.

Sync uses ordinary audience partitions and row moves: old copy -> new copy
produces the existing remove/put sequence at one transaction commit sequence.
Roster changes use existing group join/scope handling, independent of parent
or child count. There are no authority descriptors or extra per-parent empty
scope objects. Initial acquisition is the existing snapshot plus log catch-up;
its watermark also covers concurrent copy maintenance. A grant cannot mark a
snapshot complete before ordinary catch-up reaches its image watermark.

Add required device capability `live-parent-copy-v1` before schema/data decode.
Backend projections carry mode/map/cap, indexes and source reservation even
when the parent is online only. Older devices reject via E_DEVICE_VERSION.
Parent writers with any live edges are server-only predictions, with a
schema-level fence exported before private details are projected. A mutation
that might touch such a parent queues wholly, with no partial predictions.
Child-only mutations retain existing captured-through prediction proofs,
current parent requirement, unique/cap coverage and unchanged reservation.

On devices, copied fields are the authority at the last fully applied sync
state, as with ordinary audience-bearing rows. A parent-pinned shortcut must
run the existing `captures_match` test over all held current children and
check child audience coverage before borrowing the parent's verdict. A mismatch
is Unknown/server fallback, never denial or a complete empty answer. Read
paths that do not use the shortcut evaluate the complete substituted rule.
The coverage invariant is: a stream cursor advances only over an indivisible
commit prefix (partition::stream cut-by-seq); apply commits events and coverage
in one device transaction; snapshot::stage holds all acquisition pages private
until catch-up reaches max(SNAPSHOT_IMAGES_AT); publication precedes watcher
notification. Ordinary puts may be reread at images_at beyond the cursor, as
for all existing mutable multirow tables. Such an image cannot let a pinned
live proof borrow a mismatched parent verdict: captures_match scans held
children first; absent/unknown/mismatched authority yields Unknown. Unpinned
copy-rule reads use the same delivered-row contract as ordinary audience rows,
not a cross-table uniformity proof.

New envelope tests must prove that ordinary row-move delivery cannot publish
a mixed parent/child authorization proof as fresh: incremental pages, old/new roster
overlap, repeated transfers, disconnect/crash and duplicate/reorder.
If that property needs a new delivery mechanism, this design is NOT READY;
it must be designed and independently reviewed before implementation proceeds.

The availability argument is local: a parent edit reserves and finishes at
most sum(N) child updates in one transaction or rolls back; no polling scan
restarts. Unrelated parent or roster traffic never restarts acquisition beyond
the existing partition snapshot contract. There is no new global barrier.
Persistent ordinary resource exhaustion still returns the existing refusal.

## 7. Adoption and rollback

All mode/map/parent-rule changes are schema generations. Under the existing
exclusive activation transaction, pin time, apply predecessor lifetime
retirement and destination dormant projection, then validate *before* dropping
old authored audience columns. Use adaptive byte-admitted byId keyset pages through
store/activation_walk.rs::walk_metered (maximum 256 serialized rows), with
rows::adoption::Work including parent lookup, map rewriting and index entries.
Its callback scratch adds parent D, child D and 2B from §5, on top of the
still-resident page. page_fits shrinks the page before callbacks; a singleton
that cannot fit refuses before any write. Count/samples retain fixed schema
allowance (five bounded ids per table), not a row-sized list. Check every active child's parent exists; stamp the
expected destination inputs; check cap by the generated reference index;
check destination types and all ordinary constraints. Install rewritten rows,
indexes and generation/log reset atomically only after all validations pass.
An error, storage failure or process crash rolls back the activation;
no destination generation/grants may become visible early. No long-lived
cross-request staging or new activation worker is proposed.

For the shipped manual copy recipe, infer the previous-rule-to-parent-rule
field correspondence using the existing adoption `correspondence` algorithm
in engine/through_activation.rs (including whole service disjuncts). Require
the complete previous rule to match under that bijection and each surviving
child copy to equal its current parent's field before projection. This admits
the consistent copy-column recipe without id changes. An inconsistent recipe
refuses E_READ_THROUGH_ADOPT with operator-only count/samples and bridge-release
repair; it never silently grants new readers. Captured-to-live requires the
same value agreement and preserves ids. Live-to-captured requires destination
parent policy immutability; recapture and generation replacement are atomic.
The retained/historical-keep branch of activate_retained and through_activation
**never applies to a live-mode table**, including live-to-live cap edits and
restoration of dormant narrowed rows. Restamp every restored live row from
its current parent, ignoring old live inputs, then validate all caps/types;
a missing parent or any failed constraint refuses E_READ_THROUGH_ADOPT.
Captured-only historical semantics remain unchanged. Changing caps checks
current occupancy first; dormant restore applies these same live checks. For **live-to-manual**, including rollback and a dormant authored copy,
use the predecessor Through metadata before dropping it. Structurally map the
complete destination read rule to the current parent's rule, including all
service branches. For a matching map, overwrite each mapped destination
authored cell from the current parent (explicit language-owned reconciliation,
not a trust of dormant bytes), then validate destination constraints, indexes
and rules' full correspondence. Keep unrelated dormant authored cells intact.
If no complete bijection exists, refuse E_READ_THROUGH_ADOPT and give a bridge
release rewrite preserving the live rule until the manual policy is explicit.
Thus rolling A -> live -> B -> rollback cannot restore audience A. Schema
replacement with a deliberately different manual policy is a bridge release,
not a silent rollback inference. Rollback is a fresh destination activation.

Activation is linear total work with bounded working memory; the existing
operator lock-wait timeout is **not** an execution deadline, and a client
request disconnect does not cancel admitted work. This revision adds no new
activation cancellation contract. The owner reports running until the actual
transaction succeeds or fails; a network timeout means unknown outcome,
requiring generation/store inspection before retry. SQLite error/process death
rolls back an uncommitted activation. A long activation may hold the ordinary
writer lock; do not claim continuous old-store availability during it. No
new cross-request staging, resumable worker or mutation ceiling is introduced.
Restore uses the same byte-admitted validator and final-image barrier.

### 7.1 Dormant-restoration identities are a relation

For any transition whose previous or destination schema contains a live edge,
activate a transaction-local restoration sink **before** dormant projection.
Replace the activation_*_restored_ids Vec/JSON paths in dormant.rs (table and
column restoration), narrowed.rs and release_history::finalize_restorations
with SQL inserts/selects on `_live_restored(kind, table_num, column_name, id)`;
its composite primary key deduplicates identities. Empty column_name marks
a table/narrowed-row entry. Insert ids via INSERT SELECT before deleting the
source dormant rows/cells; narrowed restoration does the same before removing
its retained-row evidence. Per-row callbacks may also insert a single bounded
identity. No table-sized SELECT result or JSON id array is materialized.

At finalization, for each schema-sized (kind, table, column) declaration,
COUNT joined active r rows and publish the same scalar restoration counts as
existing metadata; at most five sample ids come from ORDER BY id LIMIT 5.
The existing release summary keeps its external counts/format. Clear old
activation_*_restored_ids metadata at transaction start for this path and do
not parse stale predecessor JSON arrays. Live-to-manual rollback is included
even though the destination has no live edge. Nonlive transitions retain their
existing path; this change does not claim to repair all unrelated lifecycle
memory behavior.

The relation is SQLite file-backed TEMP storage in the same database
transaction (temp_store=FILE for the owned activation connection, without
changing other connection policies); never an in-memory map. Its disk size is
O(restored identities), at most one record per restored (kind,table,column,id),
with bounded identity text and schema names. The ordinary storage capacity
and SQL errors bound persistence; disk-full rolls back the activation and
all identity inserts. Reserve one relation row plus limited query/cursor/page
scratch in the activation walker before Rust owns it. A connection-local table
is emptied at entry and before successful commit; rollback/crash leaves no
published restoration counts or live authority. No relation content travels
to clients. Postgres has no release dormant support; no PG dormant claim is
added. Its live bulk paths are bounded by §4.2 instead.

Tests must exercise many parents with cap one and payloads that force page
shrinking, late bulk-limit failures after actual rewrites, repeated identities,
all three restoration kinds, rollback into a manual destination and disk-full
failure. Assert bounded Rust-owned peak, ordinary scalar summary equality and
no partially committed row/index/log/generation state.

## 9. Choice among alternatives

A live read hop alone is straightforward online but leaves delivery audience
inversion and sync catch-up unsolved. Revision 2's poll-time scopes created
unbounded manifest/staging objects and a global restart domain. A declared
child cap plus maintained copies fits existing row-move sync, preserves exact
authority and completion for accepted shapes, and puts transaction fanout under
a fixed visible product limit. An unbounded child population is deliberately
refused. This narrows accepted schemas, not the meaning of an accepted rule.
The guide must say this limit plainly and offer the manual alternative.
