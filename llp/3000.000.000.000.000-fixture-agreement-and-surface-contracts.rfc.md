## 2. Fixture semantics

Readiness checks capture one clock, clone each case's arguments, normalize statically known $literal/$$ escapes, resolve typed
time leaves using the test loader, then validate its signature. A malformed
relative time is E_FIXTURE_TIME and fails check, including in an authored input
refusal case: it is fixture syntax, not an operation refusal. Ordinary drift
remains advisory and an intentional input-refusal case remains exempt. Saved
answers cannot be evaluated statically. A census runs test before check and
requires zero N_FIXTURE_ARGUMENT_DRIFT notes for every passing fixture.

Bare strings equal to a saved alias are literals in assertions (including enum
literals). Only argument substitution diagnoses an ambiguous bare alias;
explicit $name, $name.field, $$ and $literal escapes work recursively in all
assertion forms. A future change to typed argument alias handling belongs here.

`matchSet` is an optional array assertion: actual data must be an array of equal
length admitting a bijection from expected recursive subsets to actual rows.
Duplicate multiplicity matters; overlapping subsets require maximum matching,
not a greedy scan. Nested arrays within a row retain exact order under `match`'s
existing rule. `data`, `match`, and `matchSet` may coexist and all must pass.
This makes cross-context ID ordering assertions expressible without claiming a
global mint order (LLP 3000.000.001).

`fixtures/test.sweep.json` optionally maps query names to nonempty persona arrays.
Unknown/non-query names, malformed arrays, duplicates, empty personas and
undeclared personas refuse before cases run. Unlisted queries retain the cast
sweep. An explicit `test --as` overrides the matrix for a deliberate global
probe; the matrix is still validated. Explicit case execution and expectations
are independent of this matrix. Residency continues to measure its selected
principals; this matrix only selects the query sweep.

`/seed` and `/dev/reset` resolve typed times before wire decoding. A reset uses
its prospective clock (wall time if clock reset was requested); conversion and
all validation precede the transaction. Failure leaves both data and clock
unchanged. The new store identity resets the durable time-audience floor in
that transaction and replaces the host's cached floor only after commit; it
cannot inherit a retired store's future clock. Ordinary time text/JSON remains literal. No production wire route
interprets these development-only fixture spellings.

## 3. Proof fixture loading

`loadFixtures(directory, {url, cwd?, now?, timeoutMs?})` is exported from
`snapback4/proof` and implemented in its own file. It reads sorted table JSONL
files, skips test.cases.jsonl, rejects unknown tables and malformed rows, and
returns `{table,row}[]` for reset/seed. A bounded catalog fetch supplies field
types and a bounded /dev/status fetch supplies one dev timestamp; explicit now
omits the clock fetch. Only typed optional/list time leaves resolve. Unknown
fields and row validity remain the served reset transaction's authority; the
helper never writes to the server. A caller must reload after changing schema.
No credential or process-list observation is added.

Every dev host, persisted or temporary, registers its actual loopback listener in
its canonical project's owner-only `.snapback4/dev-hosts/<instance>.json`.
Wildcard binds (`0.0.0.0` and `::`) register the corresponding IPv4/IPv6
loopback address, so they participate in discovery and ambiguity checks.
This is local discovery metadata, never a credential or a global address map.
The immutable record names project, listener, PID, lifetime, instance nonce and
initial store ID. `/dev/status` exposes the same nonce and initial store ID;
its current store ID may rotate on reset without invalidating the instance.
Before automatically selecting a host, discovery requires a held registration
lock and validates all recorded identity fields against live `/dev/status`.
Automatically discovered clock/reset/latency-reset requests to registered/current-protocol
hosts carry the instance nonce in
`x-snapback-dev-instance`; the server rejects a mismatch before changing state,
closing the status-to-control reused-port race. Explicit selections and raw HTTP
may omit it. Legacy persisted hosts without an instance field retain their
existing project/store-validated control behavior without this extra nonce fence.
Dead hosts, stale unlocked records and mismatched live replies are ignored.
Legacy persisted hosts remain discoverable through store ownership, checked
against the canonical project and current persisted store ID. Mismatched
automatic legacy hints are ignored; they cannot veto a validated registration.
Explicit URL project/identity mismatches still refuse.

Discovery gathers all validated project hosts, deduplicates addresses and
refuses multiple live candidates with their addresses and explicit selection
instructions (`--port N` for clock/reset, `--url` for doctor). It never guesses
port 4400 or prefers a persisted host over a simultaneous temporary host.
An explicit port remains an intentional selection, including dev-only refusals
from a release listener. Startup failure to register refuses before readiness.
Registration is written under a lock to a nonce-named pending file, then
atomically renamed; the serving frame retains that lock and removes only its
own inode at shutdown. Startup scans at most 128 entries and reclaims only
well-formed unlocked same-inode records, holding the lock through removal.
Malformed, oversized, unreadable, linked or nonregular entries are never deleted
by cleanup. Overflow and unreadable registry failures name the directory and
require inspection/cleanup; they cannot silently fall back to a different host.
This bounded registry uses portable file locks and loopback HTTP, with no
process enumeration. Clock success guidance names the caller's assigned range.

## 4. CLI surface contracts

A canonical per-verb table owns admitted flags and generated synopsis text used
by top-level help, verb help and usage errors. Unsupported combinations refuse
before doing work; accepted flags have observable behavior. JSON output remains
parseable on empty results; token machine modes emit only the bearer/string or
JSON object respectively and keep diagnostic text off stdout. Duplicate identity
declarations gain E_QUARRY_IDENTITY_DUPLICATE. Guide aliases preserve requested
sections; long piped cards include a section index without dropping their body.

Each new deployment release writes provenance.json with sourceHash, cliVersion,
createdAt and release number. It is audit metadata, excluded from the executable
bundle digest so redeploying unchanged bytes remains unchanged. The source hash
identifies retained Quarry sources, not an entire application or a signature;
provenance is not cryptographic attestation and older releases may lack it.

## 7. Serve and surface completion (SURF4, 2026-10-16)

Implementer: Codex, 2026-10-16, commissioned for 0.4.31. This amendment
changes serving and diagnostic presentation, not language, authorization,
expiry, adoption, sync or credential authority. KIT3 owns proof helper contracts
and clock replies; DAY4 owns adaptation advice; REG owns Expo dependency floors.

Deployment captures the conventional `snapback/server.*` entry (falling back
to `snapback/worker.*`), generated registry and its checked project import graph.
Checking uses the selected source's contracts before activation. Source copies
use the existing no-follow worker snapshot rules; host node_modules remain
installed dependencies, never release source. Each release records relative
checked-import paths so moving the deployment does not reconnect it to mutable
working source. `serve` starts this captured entry automatically; `--worker`
explicitly replaces the conventional entry, and named service entries remain
additional. Hot activation replaces automatic entry bytes under the existing
worker revision fence; explicit entries retain their existing override policy.
Absolute/file URL imports and relative imports escaping the project refuse
before activation; use relative project source or an installed package. Private
preparation uses the same descriptor-pinned no-follow capture as launches,
including checked imports under ordinary native/target directory names. Nested
package scopes retain their host-installed precedence during checking and execution.
No new credential or action-claim authority is introduced. Conventional entries
use `service:worker`; named entries use `service:<stem>`. `SNAPBACK_PROJECT_DIR`
is the stable working root in dev and the active immutable source root in serve.

Startup warns when declared actions/routes have no supervised conventional or
named entry, explicitly allowing an external handler. This is a configuration
warning, not a claim of handler liveness: registry verification and doctor remain
authoritative. The start line prints active and available working schema hashes
with labels; missing/broken working source is reported as unavailable and never
prevents serving retained source. The canonical bounded ready wait is the
published proof kit's `startServe` (`timeoutMs`), also described in serve help.
The existing first stdout URL and SNAPBACK4_READY line remain the manual signal.
On graceful stop the HTTP listener is dropped before `SNAPBACK4_SOCKET_CLOSED`
is printed; the line never claims completion of other cleanup or appears on
SIGKILL. Store ownership remains held through existing worker/control cleanup.

Runtime refusals carry a message without a repeated leading code; code, family,
site and authority semantics are unchanged. Doctor JSON adds `findings`, with
`{code,table,id,message,repair}` for E_EXPIRY_ORPHAN; the existing human lines
remain available. Repair selection and behavior are unchanged. Secret proof
stdout files hold an explanatory placeholder, never credential bytes.

CLI help/parser agreement is checked over every public verb, including value
arity, unknown flags and published synopsis parity. Remove the permanently
refused `clock --release` flag. `new/init --dry-run` validates the same plan and
prints its final file set without writes. Chat/social AppProvider gates use
useAppReady before mounting writers. Guide indexes and numeric selections use
one section census; terminal long cards include their first section and piped
cards retain the entire body before the index. Shipped cards reject internal
lane/wave labels at test time. Blind-write documentation matches the existing
NOT_FOUND explanation, without changing write behavior.

Verification: targeted CLI/process/worker/client regressions on Linux and the
commissioned Mac scratch checkout; packed starter/typecheck/ready-wait tests;
full five-crate tests, fresh client preparation and Linux qualification, root
checks, ref-check and documentation budget. Independent Muse and fresh Codex
review records and final qualification results are linked in the completion
record and WORKSTREAM-REPORT.md.
