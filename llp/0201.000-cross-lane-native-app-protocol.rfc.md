## 2. Reuse the accessibility contract

React Native `testID` is the existing automation spelling. On iOS, qualify its
actual accessibility-tree exposure in a Release build; JSX occurrence is not
proof. XCTest can target an installed app by bundle identifier and inspect its
elements ([React Native View](https://reactnative.dev/docs/view),
[Apple XCUIApplication](https://developer.apple.com/documentation/xcuiautomation/xcuiapplication)).
No coordinate scripts, label translations, screenshots-as-locators, or
backend-specific success callbacks are part of the protocol.

The existing [CONTRACT](../benchmarks/tools/social-messenger/CONTRACT.md) owns
these identifiers. Its kit owns only a subset; the lane owns routing, viewers
and other shell surfaces. This proposal does not pretend the kit implements them.

| Purpose | Existing identifiers | Native observation |
| --- | --- | --- |
| Normal sign-in | `sm-auth-email`, `sm-auth-password`, `sm-auth-submit` | Enter fixture credentials through the real UI. No injected session. |
| Conversation choice | `sm-chats-item` | Match exact accessible value `dm:bob` or the descriptor's group value; never display name. |
| History and sends | `sm-convo-bubble`, `sm-convo-input`, `sm-convo-send` | Scope by message identity, observe exact body and screen order, type/tap normally. |
| Receipts | `sm-convo-receipt` | Exact value `pending`, `sent`, `delivered`, `read`, associated with one message. |
| Ordinary media | `sm-convo-media`, `sm-media-viewer-image`, `sm-media-viewer-close` | Tap the fixture row; verify decoded pixels plus a load observation. An existing node or URI is insufficient. |
| View-once | `sm-convo-viewonce`, `sm-convo-error` | Existing values `opened`/`unopened`; observe consumed/denied state, failed reopen, and absence of media pixels. |
| Search | `sm-search-input`, `sm-search-result`, `sm-search-offline` | Exact token result, then tap and verify owning conversation. Offline label alone proves nothing. |

Repeated bubbles/results currently lack uniform stable row IDs. Native v1
adds an accessible value containing the opaque message ID to each bubble and
message result; this must not overwrite chat identity or receipt values.
Child receipts and media must remain independently discoverable; an accessible
parent must not collapse them. Unique IDs remain unique; repeated IDs must be
scoped to an identified row. The pilot tests these properties against native
trees, including nested pressables and a virtualized/offscreen row.

Navigation adds three shell IDs in the **new** contract:
`sm-nav-chats`, `sm-nav-search`, `sm-nav-back`. They navigate normally and
preserve the active client and store. A descriptor may additionally declare
ordinary deep-link routes as navigation hints, but links cannot log in, seed,
enqueue, consume assets or report success. The default driver uses the three
IDs, avoiding app-specific tab labels. The NP2 probe's tab-label adapter is
explicitly short of this proposed contract.

## 3. Minimal fixture and observation hook

Two files suffice at the app/driver boundary. They contain observations and
fixture identities, never assertion verdicts. The instrument supplies a tiny,
backend-neutral Expo helper with the revised kit; every backend gets identical
source and charged aid disclosure under LLP 0201 D6. The builder wires props
and lifecycle notifications to its actual app. No Snapback API is required.

**`native-fixture.json`** is generated by the lane's ordinary seed adapter,
outside the UI, against a new scratch backend. Version 1 requires:

```json
{
  "protocol": "clique-native/1",
  "runId": "<driver nonce>",
  "bundleId": "<built application>",
  "origin": "http://127.0.0.1:<owned port>",
  "alice": "<principal id>", "bob": "<principal id>",
  "conversationId": "<id>", "chatValue": "dm:bob",
  "history": {"messageId": "<id>", "body": "<exact synced body>"},
  "ordinary": {"messageId": "<id>", "assetId": "<id>", "sha256": "<bytes>"},
  "viewOnce": {"messageId": "<id>", "assetId": "<id>"},
  "search": {"token": "<token>", "messageId": "<id>"},
  "queuedBodies": ["<nonce>:first", "<nonce>:second"]
}
```

IDs are opaque and use the application's real seed/query paths. Credentials
are supplied separately as fixture-only environment input; never write tokens,
passwords, signed URLs, or view-once bytes to the receipt files. The driver
checks fixture results through the documented custom-client API. Fixture
creation does not count as online priming: Alice must actually sync and view
the two images in the installed app. Prime and measured phases use the same
store, credentials, binary and backend data directory.

**`native-observations.jsonl`** is an append-only stream in a run-specific app
Documents subdirectory. The supplied native helper obtains the run nonce and
relative output name from launch arguments. Every protocol relaunch must
explicitly supply the nonce; ordinary launches remain inert even after a protocol
run. A 10,000-event / 4-MiB journal cap produces a sticky overflow marker and an
unmeasured result.
It only writes below its own Documents directory. The host reads the simulator
container through `simctl get_app_container <explicit UDID> <bundle> data`.
This works while the backend is stopped; a network collector does not.

The helper assigns `runId`, `processNonce`, monotonically increasing sequence,
and monotonic elapsed time; the host records process launches and wall times.
Gaps, stale nonces, wrong identities, unsupported versions and malformed or
truncated lines prevent a pass. A new process starts a new nonce/sequence, so
process-local clocks are never compared across launches. The driver records
when each observation is received and bounds waits. Required event payloads:

| Kind | Minimal data, sourced from the running app |
| --- | --- |
| `ready` | Protocol/build identity, active principal, actual backend origin, ordinary authentication restore completed. |
| `screen` | Current route and conversation; message IDs/body hashes in rendered order, per-message receipt state. Never an independent copy of the message store. |
| `write` | UI send intent ordinal, opaque client operation ID if available, resulting message ID, body hash, observed pending/settled/refused transition. |
| `media` | Fixture asset/message ID, load/error/consumed/denied event, decoded dimensions, cache-vs-network provenance if the platform exposes it. |
| `search` | Typed token, rendered result IDs and the conversation opened by a tap. |

The helper emits React committed-render snapshots and native image `onLoad` /
`onError` observations, not merely a query result or URL assignment. Where a
backend does not expose operation IDs or media provenance it records null;
the server oracle and cold network cut establish behavior instead. Neither
schema has a `pass` property or an app-controlled "restart backend now" action.
The host decides when the two UI pending observations and matching write events
are sufficient to restart. The hook must not change retry, cache, persistence,
authorization, receipt, networking or mutation behavior.

These events are corroboration, not a trust boundary against a malicious
builder: graders receive source. Media requires video/screenshot pixel review
against the fixture as well as the event; consumed view-once media requires
source inspection that the hook is passive plus the failed reopen. The test
establishes observable refusal, not forensic absence of bytes everywhere on disk.

## 4. Generic driver and the eight steps

One instrument-owned macOS wrapper runs an external XCTest runner against any
conforming Release app. It uses an explicit leased UDID, never `booted`, and
does not activate Simulator.app. It installs the recorded `.app` and checks its
native binary/Hermes bundle digests before and after. For Snapback, the build
can use LLP 3000.030's preparation and process-custody mechanisms. This is a
new application driver, **not a current `witness ios` flag** or a rename of
that tool's SDK smoke. Other backends supply their ordinary Release build.

Operator setup supplies a backend command argv, cwd, origin and data directory;
the driver launches and owns that process. It does not kill a pre-existing
server or search by process name. Adapters declare fixture/query mappings and
routes only; they cannot emit outcomes. Hosted backends that cannot be stopped
do not conform to the exact frozen precondition: do not quietly substitute a
client offline toggle. Any future network-isolation equivalence needs its own
owner ruling and distinct protocol revision.

The existing M6 custom-client adapter also exposes one **read-only oracle
command**. Its stdin is `{protocol, runId, conversationId, queuedBodies}`;
fixture credentials arrive separately. Its stdout is raw normalized JSON:
`{principal, origin, conversationId, complete, rows:[{messageId, body,
orderKey, receiptState}]}`. It authenticates a fresh Bob session, uses network
reads against the recorded origin, exhausts ordinary history pagination, and
retains all occurrences of the nonce bodies, including duplicates. `orderKey`
is the application's authoritative within-conversation ordering tuple, not the
adapter's wall clock. It may not deduplicate, reorder by compose intent, read
Alice's local queue, or emit a verdict. Missing completeness/order information
means the oracle cannot qualify the assertion. The instrument computes counts
and order itself and the grader inspects this small adapter against the
documented API. This additional data mapping is part of the new prompt's
authoring cost; the current custom-client APIs are not already standardized.

Before measurement, the wrapper seeds, starts Alice, navigates the fixture,
waits for durable history, opens/closes ordinary media, opens/closes view-once,
and verifies revocation. A second native online reopen can check persistence
before the measured run. It then terminates Alice and stops its owned backend.

| Frozen step | Driver action and independent evidence | Assertion mapping |
| --- | --- | --- |
| 1 | Start H.264 recording; confirm recorder alive, Alice process absent and backend PID gone; repeated failed connection checks to its exact origin. Start process/log capture. | Prerequisite for all M6 native results. |
| 2 | Cold launch; wait for restored Alice; navigate chats and exact fixture; capture native tree, body/ID, and committed-render event. Continue negative origin probes. | `m6-a01` |
| 3 | Tap ordinary media under its message; require loaded decoded dimensions, fixture pixels and no successful backend traffic. | `m6-a02` |
| 4 | Inspect consumed state and attempt reopen if enabled; require denial/consumption evidence and no visible stale image or newly opened cached handle. | `m6-a04` |
| 5 | Open search, type fixture token, identify expected message, tap it; require current conversation ID to match. | `m6-a03` |
| 6 | Type body 1/send, then body 2/send via UI. At each send require visible pending receipt, one matching bubble and write event; final screen order must match composition. | `m6-a05` |
| 7 | Restart same backend command and store without terminating Alice. Observe normal write states; count each body/message exactly once and order through a fresh Bob client using documented API; Bob opens through normal web UI to trigger read. Require Alice's final native `read` values. | `m6-a06`, `m6-a07` |
| 8 | After step 7, require the driver-only native writer flush acknowledgment bound to the current process nonce before terminating Alice, then stop recording and collect the final journal. Emit assertion receipts and manifest; verify all schemas, state-machine order, counts and hashes. | Artifact validity for every reported pass. |

Bob's web UI is sufficient for this native-Alice scenario; it is explicitly
recorded as such, not a two-native-device claim. It uses the existing generic
web navigation/IDs against the same backend. Two successful send RPCs or two
local bubbles are not exactly-once proof: the fresh server query must show
one occurrence per unique nonce body and matching IDs/order. Poll through a
post-flush observation window (proposed 5 seconds) to catch a delayed duplicate;
this remains bounded evidence, not proof over all future retries. Retain every
observed transition without forcing a fake intermediate display when the UI
coalesces frames; a lifecycle event and final tree must agree.

Run M8 separately: warm offline composition, two pending bubbles, termination,
verified absence, offline relaunch of the **same installation**, both bubbles
still pending once/in order, restart backend without restarting Alice, then
the same server/Bob/read checks. Map only to `m8-a17` and `m8-a18`. M8 web
multi-device convergence and M7 remain their existing distinct obligations.

Proposed driver bounds: 30 seconds each for launch/auth/online readiness,
10 seconds per ordinary UI observation, 60 seconds for flush/read and 5 seconds
duplicate observation. These are new instrument choices to pilot and freeze,
not changes to any old timing bound. An exhausted bound records the last
observed state and attribution. An executed product failure is `fail`; setup,
unsupported protocol, unavailable simulator, or downstream blocked steps are
`not-run` with a reason. Do not give blocked steps an inferred product failure.
Retain a partial video and events on failure. Interrupted video/hash/schema
verification cannot produce a passing segment.

## 5. Artifact and grader contract

Preserve the frozen filenames `m6-ios-screen.mp4`, `m6-ios-receipts.jsonl`,
`m6-ios-run.json`, and the corresponding `m8` names. The revised receipt schema
accepts the new instrument version with the existing assertion envelope and
stable assertion IDs; it must not relabel old lines with a new version.
Observation payloads live in a separately versioned sidecar, because the
current receipt schema rejects arbitrary extra fields. The run manifest binds
its digest alongside video and receipts.

The manifest requires: instrument commit and inventory hash, native protocol
version, driver binary/source hash, fixture descriptor hash, build/Hermes hashes,
bundle ID, simulator UDID/runtime, host/Xcode version, backend argv/origin/store
identity, process start/stop/relaunch timestamps, prime observations, assertion
to event/video references, and SHA-256 of every evidence file. Exclude secrets.
Transport the complete directory to the grader; relative paths cannot escape it.

Validation precedes grading. Check identities, complete state sequence, offline
cut, no reinstall/store reset during measurement, exact fixture/result matching,
receipt schema and all digests. Raw app events cannot become passing assertion
receipts directly. Driver evidence, server observations and video must agree.
Use `supplementalExternal`, `requiredForGreen:false` exactly as today: native
does not silently become a web milestone gate. A valid product failure has
`pass:false`; absent/invalid/incomplete evidence has `pass:null` and a reason.

The grader still applies O4's published anchors: observed broken cold launch
supports 30; working reads with lost/misordered writes or incorrect receipts
supports 60; demonstrated native reads/search/ordered writes/receipts supports
90 only with the full-run M8 evidence when applicable. Interpolation remains
judgment and must cite exact assertion/video evidence. A bundle hash is build
provenance, not behavioral credit. M6-green eligibility stays; in the **new**
instrument eligible but unmeasured O4 is null with `native-unmeasured`, not a
fabricated 30. Do not renormalize it into a comparable holistic number; report
the missing dimension and profile separately. Do not rewrite historical scores.

## 6. Builder prompt and series break

Proposed symmetric prompt addition, delivered before each new-series builder:

> Use native protocol clique-native/1 from the supplied instrument. Preserve
> its test IDs and accessible values in your Release iOS app, including native
> navigation and stable message identity. Wire the supplied passive observation
> helper to the same authentication, rendered rows, media-load callbacks, sends
> and receipt state used by your ordinary UI. Your seed adapter must emit the
> fixture descriptor, and your custom-client API must let the operator inspect
> the two queued messages through the protocol's read-only raw-row oracle.
> Provide the Release build command and backend launch
> argv. Do not write a simulator driver or insert synthetic passing state. The
> operator will run the supplied native driver at M6 and M8; missing support
> remains visible in the native evidence and O4 report.

Freeze prompt, kit/helper, contract, driver, receipt/manifest schemas, grader
instructions, applicability and toolchain together; emit a new
`INSTRUMENT_COMMIT` and `INSTRUMENT.sha256`. Include helper size and integration
time in the aid and authoring accounting. Operator build/test time is a separate
measurement clock, not free builder work or an unexplained addition to web caps.
Pilot affected milestones and freeze the caps after those results, per D7.

Start a **new series**, with a conspicuous break on every trend plot. O4, overall
scores, authoring cost and native coverage are not like-for-like across it;
the new builder requirement can also alter other dimensions. Common unchanged
assertions may be presented as named descriptive subsets, never spliced into
one fitted score line. Retrofitting cal30's copy is feasibility evidence only.

## 7. Cost, alternatives, and acceptance of the instrument

Planning estimates below are **not measured per-calibration medians**. The NP2
report distinguishes its one-app preparation/runtime observations. LLP 3000.030
has historical warm build-plus-smoke medians around 2.7 minutes, but that smoke
does not execute this driver and cannot price it as already implemented.

| Work per calibration | Proposed operator budget after qualification |
| --- | --- |
| Scratch copy, descriptor/backend setup, artifact identity | 1–3 min elapsed, 1–2 min operator attention |
| Cold Release build with installed toolchain/dependencies | 5–10 min elapsed; warm builds may be shorter; retain actual value |
| Prime + eight-step M6 run | 2–4 min elapsed |
| Separate M8 queue-restart run | 1–3 min elapsed |
| Export, validation, review and cleanup | 2–4 min elapsed, 2–4 min attention |
| **Planned total** | **11–24 min elapsed; about 3–6 min attention on a successful run** |

Failures add triage; allow one retained setup rerun under the new policy,
not repeated product retries until green. Downloads, queue wait, fresh Xcode
installation and cold dependency installation are separate measured setup costs.
Estimate one implementation week (driver/helper/validator) plus two pilot days
and owner review; this is a sizing estimate, not a commitment or measured result.

Ranked choices:

1. **Adopt the full contract next version (recommended).** Price native behavior
   directly and distinguish application failures from instrument absence. Gate
   scored use on the two-app/two-backend pilot and negative controls below.
2. **Adopt partially in a new unscored pilot.** Native selector/tree inspection,
   real sign-in and cold history reduce uncertainty cheaply. Label individual
   observations; retain null native segment/O4 without the complete artifacts.
   This costs less initially but does not establish media, exactly-once flush,
   final receipts, or durable queued writes. It still changes the prompt/aid and
   therefore still needs a version and series break.
3. **Keep native unmeasured and document why.** Zero added native operator time,
   no prompt change, intact old-series comparison. Cost: preserve the reported
   **16 unscorable M6/M7 results per run**, with seven attributable to this native
   gap and nine to the separate unrun M7; also leave two M8 native results
   unmeasured. Continue publishing that limitation instead of treating Hermes
   export as native behavior or repeating a platform-deficit claim.

Before freezing, negative controls must catch: a placeholder image emitting a
false load event; replayed/stale nonce events; missing/hash-mismatched video;
non-persistent outbox erased on termination; duplicate or reversed server sends;
view-once stale pixels despite a denied event; collapsed receipt accessibility;
wrong fixture IDs and Bob's wrong conversation. A seeded broken app must fail
for behavior, a conforming known-good app must pass, and an unavailable host
must remain unmeasured. Publish every pilot failure and actual operator cost.

The NP2 prototype does not satisfy that qualification and authorizes no score.

### Round 1 — review corrections

The NI review reproductions tighten Phase 1 before independent-app qualification:
native conversation identity and history body plus a fresh post-tap screen are
required for search; final server read states corroborate both native receipt
values within 60 seconds. Pending IDs can settle to different server IDs through
write intent identity. Wrong conversation screens are application failures;
schema, process and nonce violations remain instrument errors.

Export validation checks the trusted instrument commit, source inventory, driver
source and qualified runner binary, and repeats the behavioral checks from stored
trees/server rows. Finalization validates candidate receipts in memory before
publishing success. A body descendant isolates Bob's text from kit timestamps.
These are corrections to the unscored candidate; the inherited frozen series and
Phase-2 admission gate are unchanged. Round-1 results are appended to the NI report.

### Round 2 — independent witnesses and bounded polling

The validator derives both view-once screenshot crops from the prime viewer
frame, binds the prime pixels to a hashed fixture, binds refusal to the reopen
attempt, and rejects subsequent loads until reconnection, including asynchronous
cache loads. Exported video validation decodes the actual bytes on the validating
host; unavailable decoding yields unmeasured evidence. Every read assertion now
requires native ticks, committed screen rows and server receipts to agree inside
the receipt window, with the native snapshot timestamp checked independently.
The latest committed screen may predate that window; the native snapshot and
authoritative sample measure that its retained read state still agrees.

Video validation decodes every actual sample, including both terminal samples,
and maps movie/edit endpoints onto encoded STTS/CTTS presentation intervals.
Duration headers alone are insufficient: coordinated edits to movie, track,
media and edit-list duration must still reject when samples do not cover the
declared endpoints. Image-generator requests with unconstrained time tolerances
do not establish this. A decoded frame held for a long sample duration is valid.
Timing and sample-size-table counts must match the independent decoder's frame
count, so an invented terminal timing entry cannot manufacture a decoded sample.
The Mac decoder reads compressed samples in decode order and decodes each through
VideoToolbox synchronously. Presentation-order AVAssetReader output coalesces
distinct samples with equal presentation timestamps; it cannot establish the
encoded count. Empty edit-boundary markers are not encoded samples.
After assertion/failure snapshots, terminating the app before recorder shutdown
provides a real terminal transition after a static wait; the transition is logged
outside the assertions. Earlier qualification attempts keep their original
source identities when this verifier correction changes the inventory.

Search retains only a validated destination with its own capture timestamp and
scrolls to the target history row before requiring a fresh committed screen.
Bob polls identity and exact bodies within the ten-second UI bound. The duplicate
window checks elapsed host time and actual sample span. Reference-only consumption
and ordering state are scoped to asset and conversation respectively. Round-2
qualification and all attempted runs are appended to the NI report; these fixes
do not change scored admission or qualify either Phase-2 backend.


### Round 3 — whole-process confidentiality and restart custody

The cold process may never decode/load the consumed view-once asset, including
before the reopen attempt and after reconnection. The reopen cutoff binds only
fresh refusal evidence. Refusal and native state are polled together within ten
seconds, with the load guard active throughout. The opened crop is searched over
the entire cold screenshot at its original size using normalized correlation
(0.95), which tolerates uniform brightness and contrast changes. Prime matching
retains its strict absolute-error cutoff (20/255); constant crops use RMS error
because their spatial correlation is undefined.

M8's restart capture follows verified absence and relaunch and precedes
reconnection; the relaunched process's latest committed screen at capture
corroborates the pending rows, body hashes and order. Exported validation tests
exercise this block directly, including deletion of the complete `m8-a17` block.
A successful search scroll needs the hittable target in its subsequent native
tree; the committed-screen witness remains post-tap, since scrolling need not
change the rows supplied to the passive helper. The diagnostic reference backend
rejects foreign asset IDs on send and scopes historical asset lookup to the
authorized conversation, including malformed rows already in its store.

Round-3 controls and requalification are appended to the NI report. These
instrument repairs leave Phase-2 admission and scoring disabled.

### Round 4 — sticky disclosure and scaled pixels

An observed stale image is a terminal `m6-a04` failure. The driver retains that
capture and pixel record and latches the failure before any further wait. Only
missing refusal evidence is retried; a later clean render cannot erase disclosure.
