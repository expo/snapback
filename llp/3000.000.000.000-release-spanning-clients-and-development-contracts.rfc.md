## 2. Served capabilities

The authenticated `GET /` catalog adds each operation's public argument shape
and each public table's public field shapes, from the same compiler projection
as `/schema`. No rule/program body, private field or stored row is added.
Operation existence is not authorization. Jobs remain operator-only.

Clients expose `release`, a subscription source, and React `useRelease()`.
A snapshot is loading, denied, or an immutable served generation with operation
and table maps. It is scoped to current credentials; signout, close and retired
app facades withdraw it. Subscriptions fetch the catalog even if all query gates
are closed, and poll at one second to detect quiet switches. Ordinary response
generation headers withdraw older metadata immediately and request a refresh.
Requests are bounded, serialized and discarded if their credentials changed;
responses below the highest observed generation cannot reinstall an old snapshot.
Offline/catalog failure withdraws to loading. Metadata never licenses a write;
callers still handle E_OP/E_INPUT and authored guard refusals in a switch race.

## 3. Generated compatibility

Generated operation handles gain `available(release)`: true only when that
operation's name, kind and canonical argument shape equal the generated handle.
Unready metadata returns false. Generated TypeScript modules are self-contained
at runtime: package imports are type-only. The canonical availability check is
emitted once per api.ts, with the same semantics as the SDK helper. Generated
server.ts accepts the application's imported startServer as its first argument;
the application owns runtime dependencies. This conservative check gates workflows whose
arguments changed; it does not assert that business semantics are unchanged.

Applications opt in with `snapback/client-compatibility.json`:
`{"baseline":"versions/v1","since_release":2}`. The baseline is a directory
of .q files relative to the project root, outside snapback/, preserving original
filenames and module identities. A single-file baseline also preserves its
original filename; a complete root source must be named schema.q. Schema-first
ordering matches the project compiler. Empty directories and invalid sources
refuse without replacing generated API types. The baseline must compile. Saved-source deployment resolves this configuration
and baseline at the original project root while writing contracts only into the
private candidate. Missing baselines name their absolute path, configuration and
resolution root. The shared layout is versions/v1/schema.q (original-name modules
beside it), with contemporary fixtures in versions/v1/fixtures/. Both --schema
and --source accept the version directory; single complete .q inputs remain
supported. Compatibility output deduplicates merged enum and equal value domains.
The release number is an author-supplied documentation label, not an inferred
server generation. check and dev preserve this configuration when regenerating.
Without it, existing requiredness remains. Entirely new tables retain required
row fields: the baseline cannot return a row of an absent table. Added row fields and projected result
fields become optional and carry a Since release label; older value domains
remain in result unions. Baseline nominal rows/views use separate emitted
BaselineRows/BaselineWriteRows definitions, so removed tables still typecheck.
Fields private in either source remain optional. Declared optional arguments
remain optional with or without opt-in; the Since label marks only additions.
Parameters added to an existing operation become
optional; availability still rejects a changed signature. New operations retain
their own required arguments. Rows and typed projections use the same baseline.
Keep form drafts above components keyed by release generation and gate only the
release-specific reads/actions. Render optional fields with their baseline
fallback. A dormant row is absent in this release, not proof of deletion.

## 4. Rollback safeguards

`rollback --check` performs the existing exact activation on its private coherent
snapshot, then relates dormant **row** inventories to the selected operations'
read tables, including read-rule dependencies. It names the selected release,
operation, table, dormant row count and bounded id samples. This is a conservative
dependency warning: it does not claim the dormant row would match an operation's
predicate or prove a business invariant. Existing column/index inventory units
stay distinct. Removed tables and operations retain their existing warnings.

An operator requiring a safety gate across rollback deploys a bridge that keeps
the gate's table, value domains, read audience and mutation guard; repairs or
migrates values while that guard still executes; proves refusal for the guarded
case; only then contracts source. Restoring storage cannot supply absent logic.

## 5. Fixtures and dev evidence

Case args, exact data and subset match assertions recursively resolve saved
aliases, retaining $name -> row id and $name.field semantics and literal escapes.
Unresolved aliases or paths fail with E_FIXTURE_ALIAS naming the alias. match
subsets object keys recursively; arrays require equal length and order, with
recursive element matches; scalars are exact. data remains an exact assertion.

Typed time leaves in fixture rows and case arguments accept now and now±a
positive integral duration in ms/s/m/h/d/w. One timestamp is captured per test
invocation for engine activation, seed, cases and the query sweep. Other text
fields are untouched. Malformed/overflowed times fail E_FIXTURE_TIME. Cases run
in authored order before the derived query sweep so their writes are visible.
Sweep derived program-require refusals are probes, not affirmative coverage;
explicit case expectations still control case pass/fail.

An empty viewer-keyed roster that caused a development refusal gets an empty
roster/seed hint in the private dev console, based on that engine's actual rows.
Production and the application refusal envelope gain no row-count information.
This amends LLP 3000.015 §2.1 only for host diagnostic preparation: one bounded
physical existence probe per referenced roster per request, cached across rule
and program sites. The trace collector itself still performs no reads or rule
reevaluation; the probe neither changes authorization nor the query meter.
The testing guide documents raw /seed arrays, /dev/reset wrappers and clock
advance CLI/HTTP forms. KIT owns proof-kit sections; LANG owns generic sweep
refusal wording; RULES2 owns authorization/refusal recipes.

## 6. Upgrade evidence

check --fix repairs documented fixture refusal renames only where replay against
the compiled schema reproduces the new code; hidden conflicts are not renamed
on spelling alone. It preserves unrelated JSONL bytes. Upgrade deltas persist
per-query static completeness facts and compare actual snapshots. An old snapshot
without those facts is unknown, never a manufactured improvement.

FIX28's runtime history acknowledgment also prints
`Exact device: bun exact.mjs snapback --rebuild` once after a version change when
an Exact device mount is present. Ordinary output uses stdout, JSON mode stderr;
compiler failure does not repeat an acknowledged history interval. Online Exact
mounts get no device rebuild instruction. EX7 owns Exact2's runtime/session work.
