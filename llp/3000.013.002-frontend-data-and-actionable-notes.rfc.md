## 2. A short common read

Add `useQueryData(op, args, options?)` in `snapback4/react`, shared by React
and Expo. It delegates directly to `useQuery` and returns `R | undefined`:
loading gives undefined; present, absent and partial give their exact data
(including null, empty lists, false and zero). A denied read throws
`QueryRefusal extends Error`, carrying the original typed `why: Refusal`.
An error boundary may render it; callers choosing inline refusal UI use
`useQueryResult`, which returns `{data: R | undefined, why: Refusal | null,
read: Read<R>}` without throwing. These hooks never substitute an empty list
for loading/refusal, retain previous-argument values, cache independently or
change observation ownership. `read` is the same snapshot as `useQuery`.

A data-only read does not promise completeness or freshness. It is for
screens that show the authorized rows that arrived. Pagination, absence proofs,
and actions depending on fresh or complete results continue to use `useQuery`
or `usePage` and their metadata. The precise API remains unchanged. Skipping
uses the existing typed arguments and `{skip: true}`. Required/mistyped
arguments still fail typechecking; result types come from generated operations.
`useMutation(op).run` is already a typed callable and remains unchanged.

Add `<SignedIn fallback={...} restoring={...}>...</SignedIn>` using the same
`useAuth()` snapshot as AppProvider. Signed-in children mount only in that
state; restoring defaults to null, signed-out uses fallback. The existing
AppProvider account boundary resets account-owned state. Children must be JSX
components (React elements), not eagerly invoked component functions.
No bundled login UI or new session runtime is added to the React entry.

## 3. Completeness notes

Default check output leads with a checked repair against the author's own
query when the binder provides one. Print each distinct repair body once,
including different query names sharing one explanation. Otherwise print the
specific missing pin or the analyzer limitation, never invent a complete form.
The next line states impact: displaying returned rows can keep the query;
proving absence or all matches needs completeness and the precise API.
The final line names any audience proved complete. Verbose keeps full evidence.
Within one invocation deduplicate only identical findings (code, site, message
and repair), preserving different scans at the same operation site. Deduplicate
identical repair bodies separately. Recheck output follows the existing dev
watch lifecycle; no persistent acknowledgement is introduced. No persistent suppression
file, diagnostic acceptance syntax, severity change or new check exit is added.

## 4. UTC hour of day

Keep `hour(t)` as the continuous epoch hour needed by bucket keys and ranges.
Add `hourOfDay(t)` for UTC clock hours 0 through 23. It requires one present
time, returns int, and equals floor(t / 1h).rem_euclid(24), including negative
times. Lower it to existing Calendar and integer arithmetic; no new wire enum
or device runtime requirement. Index/group-key use is outside this addition
(the repeating clock hour is not a chronological key). Existing offset forms
of hour remain unchanged. Guide examples distinguish both at a fixed instant.
Clock cap/session changes belong to KIT4.

## 5. Sweep-only deadline advisory

Add advisory `N_SWEEP_DEADLINE` for a scheduled Quarry job which compares
now (or its periodEnd argument) with a row's time column and writes a literal
status/bool, when a mutation reads that table and tests the same status/bool
but has no direct time comparison on the corresponding row deadline. This
is a conservative syntactic warning, not a proof of a vulnerability or safety.
Name job, mutation, table and deadline. Explain sweep lag and ask for an
explicit comparison of that bound row deadline with now, with the intended
opening/closing direction and equality boundary. Do not invent a guard:
opening transitions and expiry transitions have opposite directions. Do not warn on
jobs without a schedule or on mutations already comparing that row deadline.
Limit claims to direct read/loop bindings and direct writes; helper-mediated
or computed transitions may be missed, and an external time guard can cause
a false positive. No runtime behavior or authorization changes. Tests include
positive, guarded, unrelated-clock, unscheduled, opening, equality-boundary
and unrelated-table cases.

## 6. Starters and qualification

Stop emitting recipes/production into ordinary projects. Package the same
recipe sources as build artifacts under node_modules/snapback4/dist/recipes;
the guide copies from that location when explicitly requested by the builder.
The existing packed production qualification executes the exact guide commands.
Native smoke remains proof support owned by DAY5 and is attributed separately.
Every changed guide snippet runs from the installed pack; additive React hooks
get type inference, refusal, empty/partial data, skip, identity and subscription
lifecycle tests. Three evidence copies are rewritten and checked with the same
line counter without editing original lanes or dropping application features.
