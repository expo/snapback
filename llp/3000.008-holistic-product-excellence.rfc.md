## Summary

Snapback 4 has a coherent architecture and a credible path to an excellent
product. The current evidence does not yet establish consistently excellent
ergonomics, performance and operation across complete applications.

The architectural value is concrete. Membership facts govern both authorization
and distribution. Authored mutations drive authoritative execution and local
prediction. Assets, expiry, maintained values and background work participate
in the same system. One Rust interpreter runs across server and device hosts.
These choices remove substantial application machinery.

The remaining work is to make that coherence survive composition, growth and
change. Ordinary programs still meet avoidable language restrictions; data
placement has consequences that are difficult to anticipate; client contracts
sometimes require extra application coordination; performance varies by the
whole path; and the broad evidence remains incomplete.

Charlie requested this umbrella and a sub-LLP for each of those five gaps.
This is a proposal family, not an implementation claim or a promotion ruling.

## 1. What excellence means

| Quality | Observable product outcome |
| --- | --- |
| Beautiful and elegant | A product rule is expressed where it belongs and composes with reads, writes, sync and presentation without being restated in application infrastructure. |
| Ergonomic | A builder can express ordinary work, discover the supported form and correct mistakes from the package, generated types and diagnostics. |
| Performant | Useful screens, durable writes and offline readiness stay within their declared budgets on realistic devices and data shapes, including concurrent activity. |
| Dependable | Changes, reconnects, session transitions and failures have understandable outcomes, preserve the promised durability boundary and recover through the supported tools. |
| Holistically excellent | These properties hold together in substantial applications, including their next change, rather than only in isolated demonstrations. |

A small API is useful when it covers the application's needs. A documented
boundary is still an ergonomic gap if ordinary application composition repeatedly
requires an auxiliary query, duplicated bookkeeping or a transport workaround.
Conversely, a typed refusal can be excellent behavior when the requested answer
would otherwise be false, unauthorized or too expensive.

The strongest current fit is an interactive application with shared permissions,
live state and intermittent connectivity. General backend work is a separate
question to test; this proposal does not assume Quarry must become a universal
language to succeed.

## 2. Evidence and confidence

The assessment was made against the code and retained records available at
repository revision `94e7eceef4d9000278f88689018085b0e2e46390`. That identifies
the reading snapshot, not a new qualification gate.

- **Implemented foundation:** the [published surface](../snapback4/packages/snapback4/README.md)
  and [client contract](../snapback4/packages/snapback4/src/contract.ts) show
  the shared data model and explicit read/write states. The repair and security
  records linked from [LLP 3000 §9](./3000-snapback4.explainer.md#9-architecture-and-code-review-2026-09-12)
  record substantial completed corrections; those defects are not presumed open.
- **Whole-application evidence:** the [0.2.6 Clique record](../benchmarks/runs/2026-09-13-snapback4-clique-0004/README.md)
  reports Astra's completed continuous build and 167,157 settled scale actions.
  Its full-corpus browser startup was 21.446 seconds. Grok's coverage was
  incomplete, Muse was running, and independent grades and fresh M7 sessions
  were pending at this assessment. This is N=1 per builder model, with mixed
  platform, application, toolchain and execution causes.
- **Ergonomic evidence:** the [pending-shape audit](../benchmarks/runs/2026-09-13-snapback4-clique-0004/m6-pending-shape-audit.md)
  confirms that losing device metadata through an explicit shape follows the
  current contract. The builder's second-query workaround remains evidence of
  application cost. The [video report](../issues/20260913-snapback4-video-id-only-prediction-refuses.md)
  is a received differential reproduction, not an independently graded result.
- **Performance evidence:** the [HTTP record](../benchmarks/runs/snapback4-public-catalog-20260913/README.md)
  includes wins, regressions and experiments that were not adopted. The
  [startup audit](../benchmarks/runs/2026-09-13-snapback4-clique-0004/replica-startup-audit.md)
  supports a volume-sensitive whole-browser observation, not attribution to
  device apply or to the retired quadratic JavaScript store.

Confidence is high that the five gaps are meaningful product work, moderate
that the proposed changes will make complete builds routinely smooth, and
unestablished for a universal performance or production-readiness claim.

## 4. Constraints that the work preserves

The governing constraints are [LLP 3000 §7](./3000-snapback4.explainer.md#7-decisions-during-execution),
[the runtime-meter brief](./2000.000-keep-the-core-flip-two-substrates.rfc.md#6-flip-1-certify-authorization-statically-meter-resources-at-runtime),
[the client vocabulary](./2000.000-keep-the-core-flip-two-substrates.rfc.md#8-the-client-vocabulary-fixed-before-the-mechanism),
[the scope fence](../snapback4/NOT-DOING.md) and [the loop rules](../rules/RULES.md).
In particular:

- preserve server authority, one interpreter and the engine's write path;
- distinguish insufficient local knowledge from rejection by authority;
- preserve disclosure behavior, declared retention and truthful completeness;
- judge fast affected checks within the existing loop; run longer experiments
  separately, without requiring a quiet main or a complete battery at each HEAD;
- change the public card deliberately and update its generated types and guide
  together; a proposal cannot silently grant itself an API extension;
- retain the existing bakeoff thresholds and exclusions. This family adds no
  blocking check, registry, hosted target or automatic performance ratchet.

## 5. Proposed sequence

First capture the existing complete application paths and their costs using
the retained instrument. Record unresolved behavior separately from intended
contract changes; do not reopen historical defects merely because an old
ticket survives in another directory.

Next develop the ordinary-language changes, residency explanation and concrete
client repairs. Their designs can proceed together, while shared core changes
respect LLP 3000's ownership. Filtering and cursor semantics, predicted versus
authoritative results, and execution classification need explicit resolution
before the corresponding behavior is implemented.

Then publish the coherent result through the existing qualified path and run
the complete application journeys on that package. Use stage measurements to
choose subsequent performance changes; assess cheap data placement and client
initialization before inferring that the interpreter or storage engine needs
replacement. Continue fault and operational evidence beside application work.

Finally exercise a second application and a workflow that depends primarily
on server data. Preserve their actual product requirements, and record where
the model fits poorly. A successful messenger cannot settle that question.

## 6. Completion and falsification

The proposed milestone is reached when the five children have concrete
acceptance evidence, the existing loop and acquisition bars still hold, and
independent builders can construct and evolve substantial applications from
published surfaces with little platform-specific repair code. Report missing
coverage and the remaining costs separately; an aggregate grade cannot hide
failed recovery or authorization behavior.

Reconsider the scope or architecture if ordinary features keep requiring a
second application data plane, faithful partitions remain unaffordable at
realistic device scale, or successive complete builds require the same
specialized coordination after the named fixes. Evidence of those outcomes
would outweigh the simplicity of individual mechanisms.

## 7. Open decisions

The proposed priority is language, residency and client composition together,
with measurement and recovery evidence throughout. Author rulings are still
needed for the exact card additions, filtering continuation policy, residency
spelling, additional application commission and any extension of the scope
fence. The children make recommendations and isolate those choices.

Writing this family does not authorize implementing its proposals, declare
Snapback 4 promoted, or claim the pending benchmark work is complete.
