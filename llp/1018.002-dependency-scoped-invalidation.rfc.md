# LLP 1018.002: Dependency-scoped invalidation

**Type:** RFC
**Status:** Draft
**Systems:** Snapback 2 authorization evidence, schema evolution, offline replay, query engine
**Author:** Codex, commissioned by Charlie Cheever
**Implementer:** Codex owns the dependency audit and draft; a runtime implementation owner and date must be assigned at acceptance
**Date:** 2026-09-07
**Revised:** 2026-09-07 (bounded identity audit completed; disconnected-table candidate, hashing deferred); 2026-09-07 (panel: audit first, attributed conflict evidence and bounded payoff test); 2026-09-07 (initial focused proposal)
**Related:** LLP 1018, LLP 1000, LLP 1001, LLP 1002, LLP 1012

## 1. Problem and proposed first slice

An unrelated schema edit can invalidate authorization evidence used by a queued
write. The pending-client experiment in
`benchmarks/runs/2026-09-07-snapback2-evolution-diagnostic/README.md` records two
queued writes conflicting after an optional-column successor. Their immutable
envelopes drain correctly and newly issued intents commit. Current behavior is
conservative correctness, but it makes harmless evolution costly to applications.

LLP 1001 currently binds a scoped verdict to the complete schema hash and its
enclosing rule. That broad binding protects transitive read-policy dependencies,
including cycles. Removing the schema hash without replacing that protection
would be an authorization bug.

Explore a finite, authority-computed semantic dependency closure for newly minted
policy verdicts. The first possible implementation narrows only their static
policy identity. It does not redesign live-query scheduling, change data OCC,
make every successor replayable, or selectively retain all offline coverage.
The existing whole-schema identity remains the fallback wherever completeness
cannot be established. This RFC is Draft and authorizes no runtime change.
The next slice is an audit only; §3 is a conditional design hypothesis, not
the next implementation assignment. Keep current wire domains and broad binding
until a useful safe narrowing has been demonstrated and separately accepted.

## 2. Separate identities before narrowing any

| Identity | What must remain protected |
|---|---|
| Intent/replay identity | Exact queued operation, arguments, trace, grant and intent identity; terminal lookup and exactly-once settlement. |
| Data evidence | Point row digests and proved absences; ranges re-execute under existing OCC rules. |
| Static policy meaning | Enclosing rule plus every transitive policy and schema fact needed to interpret it. |
| Dynamic authority | Principal, auth epoch, pinned inputs, traced policy reads, and live session/grant checks. |
| Program/evaluator meaning | Operation interpretation, supported IR and evaluator semantics; policy equality alone says nothing about this identity. |
| Coverage/transport state | Resume generation, coverage resets, and committed/predicted query delivery ownership. |

The audit names the current producer and consumer of each identity. Reuse
existing domains; the table does not require six new hashes. Static potential
policy dependencies and the dynamic reads actually executed serve different
proofs; do not merge them into a universal dependency or invalidation framework.
In particular,
neither a policy digest nor a schema digest may substitute for the stable replay
digest used to find an already stored terminal response.

## 3. Candidate policy closure

For a particular rule, collect all statically reachable dependencies, not just
the branch exercised by the current principal. Include the enclosing normalized
rule, referenced table read policies, key/index interpretation, nominal types,
optional/null semantics, and schema facts used by certification or structural
visibility. If an entire row/schema descriptor participates in interpretation,
include it until a smaller dependency is demonstrated sound.

Walk references with a visited set and form a finite graph. A candidate digest
can hash a canonical descriptor of the reachable nodes and labeled edges; do
not recursively expand a cycle or seek a hash fixed point. Node identities,
ordering, serialization, and the semantic version domain must be explicit.
Changing any reachable node, adding/removing an edge, or changing a relevant
interpreter/certifier semantic version must change the binding. Canonicalization
may normalize representation, but must not reorder short-circuit evaluation or
erase meaningful type and policy distinctions.

For every excluded schema component, supply a concrete reason that it cannot
alter this rule's meaning, authority, disclosure, or certified behavior. Start
conservatively with whole descriptors and narrow only with evidence. An edit
that changes another table can still be relevant through a transitive policy.
An unused branch is still a dependency. Unknown dependency kinds or semantic
versions fail closed; they never mean an empty dependency set.

The authority computes and validates the closure from its schema. Clients may
carry opaque verdict identities but cannot declare dependencies or mint
authority. Existing principal/auth-epoch and input-digest binding stays intact,
as do policy traces and certification charges for transitive probes. Structural
visibility continues to depend on the active target read rule; a true runtime
verdict alone does not permit disclosure of a protected row.

The design must be reconsidered if this closure requires a second policy
interpreter or a parallel schema registry. Prefer a traversal of the existing
normalized rules and certification facts with explicit conservative fallbacks.

## 4. Replay and transition rules

Apply LLP 1012's existing order: check the live authenticated session, then look
up a stored terminal using the stable replay identity before current operation
lookup, operation-kind checks, or current-schema trace decoding. A lost commit
ack must still return the same stored terminal after operation removal.

Never rewrite a queued intent or upgrade an old opaque verdict in place. Old
evidence retains its whole-schema interpretation and may conservatively
conflict. A new verdict domain must be explicitly distinguishable; unsupported
domains fail closed. No permissive retry with stripped trace or newly minted
authority is allowed. Exact encoding and supported-domain disposition must be
settled before implementation, within the project's pre-promotion deletion
policy; no general compatibility framework is proposed.

For unsettled intents, keep FIFO ordering and existing owner-side grant checks.
A rejection settles that intent and the drain continues; transport failure
retains its bytes. The client cannot expire the fence or revise a 30-day grant
decision that belongs to the owner. A change to operation semantics still uses
the existing replay checks; this proposal promises no automatic operation
compatibility.

Retaining a policy identity does not retain an invalid row digest, prove an
unheld absence, preserve a revoked principal, or suppress a required coverage
reset. Committed history, local prediction and delivery hydration keep their
current contracts. A new policy identity alone is insufficient to promise the
two-write experiment will avoid conflicts; the identity audit must establish
which remaining checks apply before making that claim.

## 5. Evidence and sequencing

First spend one focused audit day on the identity map and a bounded payoff
argument. The existing diagnostic already names `rule:<hash>` as the rejection
site for both queued writes; their traced point is the unchanged membership,
while the added optional column belongs to messages. Preserve that attribution
and the retained trace rather than treating the cause as wholly unknown.

Identify what a narrower policy identity would actually permit with point,
program, principal/epoch, grant and coverage checks unchanged. Record one
concrete unrelated-edit case and its relevant-edit control. Do not rewrite
queued bytes, disable checks or normalize away real row changes to manufacture
success. A schema reset can remain necessary even when a queued verdict remains
valid; selective coverage retention is still outside this proposal. If this
audit cannot establish useful scope, stop with the reason and defer hashing work.

Use the existing experiment as a preservation matrix, not a new harness:

| Existing behavior | Counterfactual obligation |
|---|---|
| Two predicted envelopes replay unchanged in FIFO order | A narrowly irrelevant edit may preserve their verdicts; relevant policy/data changes still reject under current authority. |
| Reset/resume reacquires current coverage | Avoiding a verdict conflict cannot suppress necessary reset or fabricate held rows/absences. |
| Lost-ack retry after operation removal returns its stored terminal once | Keep terminal lookup ordering and stable request identity; a fresh call to the removed operation still refuses. |
| Rejection settles one intent, transport failure retains its bytes | No automatic new-intent substitution, dropped queue entry, or rewritten grant/trace. |

Only then review the closure and excluded components independently, with
explicit attention to authorization. Assign the implementation owner/date and
accept the bounded slice only after that review. Use existing tests and corpus
machinery; this proposal creates no new gate or registry. A fresh cold-builder
run remains outcome evidence, not a prerequisite for inspecting an already
demonstrated false conflict.

Required behavioral comparisons for any accepted candidate:

- An unrelated table edit preserves the new policy identity; a relevant field,
  index, policy, nominal type, or semantic-version edit invalidates it.
- Direct, transitive, cyclic, and short-circuited policy dependencies all
  invalidate correctly. Reordering a serialized descriptor cannot change
  meaning; reordering meaningful policy evaluation cannot be erased.
- Principal switch, revocation/auth-epoch change, input change, and relevant
  policy-data writes retain their authority and OCC checks. Forged, incomplete,
  unknown-version, and cross-principal evidence refuses without disclosure.
- Two queued writes retain exact bytes and FIFO settlement across successors;
  old-format evidence remains conservative; lost-ack replay after operation
  removal returns the stored terminal once. Mixed verdict domains cannot
  acquire authority by fallback.
- Rust authority and twin evidence lookup agree on supported identities; no
  local prediction invents authority or treats unavailable evidence as zero.

Record avoided false conflicts and closure construction/storage costs beside
the correctness evidence. The acceptance argument must identify exactly which
edits become non-invalidating and why. If no useful safe subset emerges, retain
the current broad binding and close the proposal with that finding.

## 6. Bounded audit completed — 2026-09-07

**Decision: retain broad binding; defer runtime hashing work.** A useful,
conservative candidate exists for edits to disconnected ordinary tables, but
that candidate does not yet solve the witnessed optional-message-column case.
This audit closes the assigned research slice. It does not accept §3 or assign
a hash implementation. A later acceptance decision needs an independently
reviewed closure and a focused counterfactual replay witness; no further survey
is assigned now.

The source baseline is `c00953e48` in the execution lane. The frozen architecture
candidate `c9803c828` was compared at the identity boundaries below. Its rule
hash still binds the whole schema, and its stable replay lookup, conflict
comparison and epoch distinctions remain the same. Its derived-index shape
and evaluator semantics have changed; therefore a candidate designed against
ordinary scalar indexes must explicitly fall back for unsupported derived
indexes, not reuse a scalar interpretation. This is a source audit, not a
new runtime experiment or an authorization proof for a proposed hash.

### Identity producers and consumers

Paths in this table are beneath `snapback2/`; function names identify the
boundary even when concurrent edits move lines.

| Identity | Producer → consumer; finding |
|---|---|
| Stable replay | `crates/snapback2/src/writer_replay.rs::execute_replayed_mutation` hashes `(op, args, ReplayEnvelope)` and queries `Store::stored_client_intent(principal, intent)` before operation, schema-dependent trace and grant checks. Equal normalized envelope content retrieves the terminal; changed content refuses reuse. This identity contains neither a predecessor program hash nor an auth epoch. Client byte preservation remains a separate obligation. |
| Current program | `crates/snapback2-core/src/registry.rs::Generation` hashes the schema and certified programs, plus schedule bindings when present. `engine/mod.rs` checks current certificate value-model version, plan hash and schema hash before executing. `writer_replay.rs` looks up and executes the current mutation. There is **no predecessor-program equality check on an unsettled replay**; this RFC must not imply one exists or promise operation compatibility. |
| Static policy | `schema.rs::Schema::rule_hash`, `engine/hashes.rs::PolicyHashes` and `packages/evaluator/src/value-runtime.ts::scopedRuleHash` all bind `(whole schema hash, enclosing rule)`. Certificates retain the schema binding too. `engine/runner_ops.rs` uses this identity for rule memoization, authoritative input traces and hidden verdict receipts; `engine/replay.rs::conflict_site` compares the queued verdict with re-derived inputs. Narrowing only `Schema::rule_hash` would leave inconsistent producers. |
| Pinned inputs and data | `crates/snapback2-core/src/offline.rs::{rule_inputs_digest,row_digest}` bind the exact table/index/key and canonical wire row. The twin mirrors these in `value-runtime.ts` and `runner.ts`. Replay decodes point keys against the current table/index types, then compares disclosed row digests or absence before verdicts. Ranges re-execute. Schema widening of a traced row can therefore remain a real point conflict independently of policy hashing. |
| Dynamic authority | Owner `runner_ops.rs::eval_rule` mints hidden verdicts with principal and epoch. `packages/evaluator/src/authority.ts::exactVerdict` and native receipt-only lookup require both, alongside rule and input identities. Replay receives a live resolved session and checks its principal against the grant. Grants intentionally outlive the minting session; a fresh session of the same principal may settle the old outbox. Cached-epoch equality is not a new grant-lifetime restriction. |
| Delivery and coverage | `crates/snapback2/src/writer_offline.rs::envelope_json` projects current generation/schema/plan and authority. `writer_resume.rs::resume` separately checks live epoch and whole generation/schema, returning `E_OFFLINE_RESET` for the latter mismatch. Client `offline-protocol.ts::{decodeDeliveryEnvelope,toClosureReceipt}` validates wire/schema facts; `offline.ts::{commitMany,resetCoverage}` rotates held coverage and reacquires the current program. A retained queued verdict must not retain old coverage or bypass this reset. |

The existing producer/consumer distinction is worth preserving: cached hidden
verdicts may supply local authority only under their exact principal/epoch,
whereas an owner replay re-derives current authority and compares an old trace.
The queued trace itself carries no principal/epoch field. Its request is
admitted under the current live session and principal-bound grant.

### What the retained failure proves

`benchmarks/runs/2026-09-07-snapback2-evolution-diagnostic/evidence/pending-client/diagnosis.log`
records both envelopes with one point, `memberships.byConversationPrincipal`,
and two rule verdicts. Both terminals identify
`rule:84ade293b0487c004706cc1da2f47246032e85cff9660237e050df1da241aa85`.
The point precedes verdict comparison in `conflict_site`; the reported rule
site preserves the observed attribution rather than speculating that the
membership digest failed. The regression in
`packages/snapback2/tests/real-owner.test.ts` adds `messages.category`, receives
a coverage reset, preserves the original envelopes, and asserts both rule-site
conflicts. Its explicit new intents and separate lost-ack/removal case remain
the preservation controls.

A whole-descriptor closure includes the subject table as well as probe targets.
Consequently the messages rule still changes when `messages.category` is added.
Even if one of the two old verdicts became reusable, all required verdicts must
match. Avoiding this particular false conflict needs field-level reasoning
about subject materialization, rule terms and certification that this first
closure deliberately does not attempt. The recorded two conflicts are not
counted as two avoided conflicts for the candidate below.

### Finite candidate and excluded-component assessment

A possible first subset is **table rules with ordinary scalar point probes**.
Start with the enclosing table/effect and its normalized rule. Include complete
subject and reachable table descriptors; follow every `Exists` branch and the
active target read rule, including cycles, and conservatively follow nominal
`Ref` targets and maintenance source/target relationships touching that set.
Keep index order, uniqueness, column kinds, optional materialization,
constraints and retention in each descriptor. A visited set over stable table
identities gives a finite closure; serialize the collected graph canonically,
without reordering rule evaluation. Traversing syntax and schema descriptors
can reuse current representations; it does not require a second interpreter.

This is deliberately less ambitious than proving every included field relevant.
All top-level `auth`, `channels`, `schedules`, `maintains` and `effects`
descriptors stay bound initially, as do the relevant value-model/certifier
semantics. Only an excluded table descriptor may vary. Global schema admission
and current program certification still run against the **whole successor**.
A reachable `Created` rule, `connected` dependency, derived index, unknown node
kind or an unaccounted schema dependency uses the existing whole-schema
fallback until separately justified. No wildcard selects an empty closure.

For the chat template, a candidate edit is adding an optional column to
`notifications` while replaying an otherwise unchanged `deliveries.post`.
The template's notifications table has only scalar columns, no references to
the chat tables and deny rules; no chat membership/message rule reads it and
no maintenance declaration connects it. Such an addition changes the current
whole-schema verdict identity but cannot change the selected rule graph,
point-key interpretation or traced membership row. The operation still uses
the current certificate, grant slice and session; resume still resets. This
is a **source-derived counterfactual**, not an observed successful replay.

The relevant-edit control is changing `memberships`' read policy or its
`byConversationPrincipal` index: both are retained dependencies and must
invalidate. Changing membership data leaves static policy meaning alone but
must still fail the existing point/authority checks as appropriate. Adding an
edge from a reachable rule to a formerly excluded table makes that table
reachable; branch short-circuiting cannot conceal the edge. With all other
schema fields retained, this gives an explicit exclusion argument for each
omitted table: no reachable policy, nominal-reference or maintenance edge
selects its descriptor, and the current whole-program certificate remains
mandatory. It does not prove selective coverage or evaluator-state retention.

### Payoff and stop

The credible payoff is avoiding verdict-only conflicts when an independently
owned part of an application evolves. The audit found no additional queued
program-generation check that would categorically erase that payoff. It also
found no measured avoided conflicts, closure cost or complete cross-language
implementation evidence. Supporting this subset would require coordinated
native hash caches, certifier output, twin lookup, explicit evidence-domain
handling and adversarial review. Existing opaque queued verdicts would remain
conservative, and the witnessed optional-message-column edit remains outside
the first subset.

That is enough to preserve the direction, but insufficient reason to introduce
another wire domain during the current compiler/client closeout. Defer that
implementation, retain the attributed failure, and revisit only with the
specific disconnected-table witness and a reviewed exclusion proof. Do not
expand this audit into a general invalidation framework or a new gate.
