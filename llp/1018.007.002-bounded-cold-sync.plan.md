## Evidence and scope

The 100-conversation probe times out during its first warm-up at 30 seconds;
0 of 20 measured samples complete. The copied JSON's sampled heap ranges from
31,472,164 to 485,345,672 bytes. The grader cites an earlier ~364 MB maximum.
The growth is evidence of pressure and churn; retained heap after GC has not
yet established a leak. The 167,157-action server replay exercises different work.

Reproduce from an empty browser context/IndexedDB in a fresh worktree with the
same corpus shape. First copy and inspect `scripts/scale-cold-probe.ts`; its
whole-navigation/auth/sync timeout must not be silently relabeled sync-only.
Separate auth, first paint, inbox drained, rows materialized, indexing and
settled heap. Count actual authorized rows, receipt extents and subscriptions;
100 conversations alone does not define the workload.
The Astra witness uses one ascending global inbox drain, not 100 independently
mounted per-conversation drains.

## Repair strategy

Implementer: Codex gpt-5.6-sol, starting 2026-09-09, sharing one store-change
lane with LLP 1018.007.000. Profile carrier save/load, coverage cloning,
projection rebuilding, local query input/index construction, and observer
refreshes per ingested page. Test a headless persistent client too, separating
React fanout from storage/twin cost.

Change the demonstrated hot path to consume committed changes once, reuse
valid per-revision inputs/indexes, and coalesce redundant evaluations. Batching
must bound queued bytes/work and preserve input order. Avoid whole-history
copies solely to read metadata. Prefer the carrier's existing indexes and swap
journal to a second cache or scheduler. Large data must not become one
uninterruptible main-thread turn.

`TwinStore.sync()` currently lacks an in-flight synchronization flight. Concurrent
first callers can all request a full snapshot and each rebuild ClientStore;
warm callers can duplicate delta copying before noticing a matching revision.
Share that flight, recheck revisions after completion, and invalidate it across
principal/program changes. Test one installed snapshot for concurrent cold
reads, one installed delta for warm reads, and a later revision arriving while
the first flight is blocked. Do not share a mutable evaluator execution between
queries merely because their source installation is shared.

Separate the public flight from the internal reset/retry loop: existing root
dictionary replacement calls `sync()` recursively, which must not wait on its
own flight. Capture principal/program/schema/authority identity and revalidate
before applying a fetched snapshot. A partition change invalidates the result
before it can mutate the current store. If rebuild work yields, build privately
and publish the completed store in one assignment. Exercise generation-reset
re-entry, account change during blocked source fetch, and no half-built
evaluation. Preserve isolation when eliminating redundant copies.

Rows, coverage, absences, watermarks, grants and terminal custody still commit
atomically. A cancelled or failed swap publishes none of them. Revocation and
successor fences invalidate any reused materialization; authority changes must
not wait indefinitely behind an optimization batch. Retained queries may not
invent complete coverage to save work. Keep the 85,000-byte runtime allocation.

## Acceptance

- The same 100-conversation account completes each cold attempt inside the
  existing 30-second whole-probe ceiling: three warm-ups and 20 measured
  attempts, with wall time and p95 recorded and no discarded failed trial.
- Record 10%, 50%, and 100% corpus checkpoints on one machine with comparable
  owner load. Report counts of copied rows, rebuilt indexes, carrier commits,
  query evaluations and peak/post-GC heap. Demonstrate removal of the measured
  superlinear amplification; a larger timeout or less seeded data is not a fix.
- After draining, close/reopen offline and read/search a never-opened thread.
  Preserve pagination and a queued send across process restart. Resume/tombstone,
  permission revocation, failed commit, and successor tests remain green.
- Add a small workload-growth regression to the existing suite based on bounded
  operation counts, plus the isolated browser qualification. Distinguish browser
  heap from the twin's per-evaluation resource limits and report both honestly.

The concrete representation change is selected after profiling; this plan does
not presuppose a memory leak, prescribe a new store budget, or authorize an
eviction policy that drops still-authorized retained history.

## Investigation and implementation record

The isolated Astra copy contains 100 conversations, 10,008 messages and 10,008
recipient log rows. The source benchmark remains read-only. The current SDK
requires a recorded four-file auth compatibility bridge because the copied
application used the published flat auth API; gateway/auth setup errors are
retained separately and are not product timing samples.

Shared installation and metadata-only reads remove duplicate source work, but
did not by themselves repair this cold workload: both the published baseline
and its controlled SDK-only patch exceeded the original 30-second bound. A
current-SDK CPU profile then identified repeated schema canonicalization and
SHA-256 inside `scopedRuleHash` as the dominant evaluator work. Commit
`949f2459e` memoizes exact hashes per rule identity for one synchronous Runner.
The regression counts canonical schema traversals, checks public-hasher parity
and verifies a new Runner recomputes after a schema-rule mutation. It introduces
neither retained authorization verdicts nor a cross-execution cache.
