## 2. Language

A top-level declaration describes one table's historical input fields and its
simultaneous output patch:

```quarry
backfill bookings vehicleClass(weight: int, length: int):
  { vehicleClass: 'commercial' if weight > 3500 else 'van' if length >= 500 else 'car' }
```

Here length is stored in centimetres. Arguments are typed historical fields;
they remain in the declaration after the candidate drops those fields. The
compiler binds arguments against their explicit types, not today's table.
The runtime validates them against each interpreted historical row. Output
names belong to candidate authoritative columns and may equal input names:
read-old/write-new. Outputs of multiple declarations on a table must be
disjoint. Names are unique per table. Durable store history keeps one
normalized definition per table/name, including gaps; changing it refuses with a
bridge/new-name repair. A new name denotes a new transformation.

The expression body is an object patch. It uses Quarry's existing arithmetic,
comparisons, null handling, conditional expressions, immutable helper expansion,
and bounded deterministic scalar builtins. Supported text additions are
`before(text, delimiter)`, `after`, `beforeLast`, `afterLast`, `startsWith`,
and `allDigits`. Splits remove the first/last exact delimiter; absent delimiter
means whole text before, empty text after. An empty split delimiter refuses.
Digits means nonempty ASCII digits. Text is Unicode, comparisons and splits
are locale independent. Existing `lower`, `trim`, `slice`, `count`, `sha256`,
`first`, `last`, `at`, `min`, `max`, exact `divide`, calendar/civil transforms
and concatenation retain their normal checked semantics. No randomness,
viewer, clock, minted ids, writes, mutation helpers or loops are admitted.
Identity `id` is never an output. Only scalar outputs are admitted, including new references. Assets, lists,
engine-owned/captured/maintained and lifetime outputs refuse, including fields
owned by a historical source lifetime even when the candidate removes that rule.
Restored narrowed rows retain their individual output ownership, captures and
reference types. Columns added by later predecessor schemas contribute their
own types/defaults only when absent from that archived definition. Overwriting an
existing reference/asset is refused: derive a new reference column so the
existing dormant reference-lifetime ledger owns retirement/restoration.

Point reads use the ordinary `members[principal = owner] ! else NOT_FOUND`
spelling. They require a unique point. A missing asserted point refuses;
ordinary nullable point reads and `exists` retain their explicit semantics.
Historical existence predicates may traverse a metered source range, needed
for wave-17 cross-tower references; they return no row collection. A meter
cut is a refusal, never false absence or an incomplete historical value.
Before evaluating any patch, each unique lookup index validates the historical
population's cardinality with bounded privileged duplicate samples. A different
simultaneous patch making candidate keys unique cannot choose an arbitrary old
match. All reads run as the trusted activation system principal, bypassing application
read rules, against the assembled historical snapshot. Dormant namespaces
remain unnameable. Candidate read indexes are built over that source snapshot
only when their component fields exist there. No JavaScript or app migration
operation receives this authority. All declarations are self-contained: they
cannot read another declaration's outputs in the same activation.

## 3. Adoption and reversibility

The existing activation writer transaction owns this sequence:

1. Assemble retained source rows/cells and their source definitions using the
   existing restoration intent. This includes narrowed rows eligible to return:
   restore their full historical images before evaluation, deferring only the
   backfill output columns' candidate-type checks. Retained reference invalidation,
   source lifetime and audience checks still apply before restoration. Retire
   source-expired lifetimes before any backfill; a transform cannot extend an
   expiry or opening boundary.
2. When leaving a declaration, restore its predecessor-visible output fields
   from saved **output preimages**, separately from its argument inputs. Save
   interpreted old values, including literal defaults/nulls, and absence.
   Added output columns use ordinary dormant retention instead. A different
   current value from both recorded output and preimage refuses with a conflict;
   untouched same-column enum renames restore their exact original value.
   Membership is per row lifetime, with normalized declaration definitions kept
   beside evidence. Removing a whole table suspends its membership rather than
   feeding transformed values back as inputs. Re-entering that declaration reads
   its original overwritten inputs and preserves its current result; selecting
   original source instead reverses it even when the immediately previous schema
   lacked the table/declaration. Ordinary active deletion clears membership.
3. Enter declarations absent from the immediately active schema. Unchanged
   carry-forward and reopening run none for ordinary active rows: candidate-native
   writes are not historical rows. Newly restored narrowed rows receive carried
   declarations too, including a declaration introduced while they were dormant. On re-entry, restored cells/rows are eligible along with
   older active rows. A native v2 row whose absent historical inputs have a
   complete valid restored output image keeps that image. Older v1 rows lacking
   outputs are filled. Declarations must accompany skipped-release source;
   no unseen intermediate transformation is implicitly inferred.
4. Evaluate every entering patch against one assembled source snapshot, with
   ordinary per-row job meters and a paged source walk. Stage output/evidence
   in SQLite temp storage before applying any patch. Recompute the patch on
   re-entry, so changed lookup values count as changed dependencies even when
   declared arguments are unchanged. Compare both saved argument values and
   computed outputs. If unchanged, preserve edited added-column cells. If
   changed, recompute only when current outputs equal the saved result or the
   reversed preimage; otherwise refuse the conflict. Never overwrite a manual
   output edit because another input happened to change. A fully reversed
   same-column output edited during absence also refuses re-entry when its
   current interpreted value equals neither preimage nor saved result, even
   with unchanged arguments. Sparse defaults count by interpreted value.
5. Apply patches and evidence together. Run ordinary narrowing/reference
   closure, projection, complete type/asset validation, indexes, uniqueness,
   caps and maintained-data rebuilds. Transformed dependencies force rebuilds
   even when their declarations did not change. Publish programs, generation
   and release in the same commit. Any error rolls everything back.

Evidence is keyed by table number, row lifetime and the SHA-256 digest of the
normalized declaration/typed IR (no diagnostic locations or whitespace).
It records declared input values, each overwritten output preimage and computed
output. Ordinary authoritative deletion/expiry deletes that row's evidence in
its transaction; id reuse cannot inherit it. Row moves to dormant storage
preserve lifetime. Backfill definitions enter schema/activation identity;
changed rows also set activation population, forcing a fresh generation and
device reacquisition. Public/device schema projections omit all backfill
metadata; devices never execute migrations. A successful evidence installation
sets `snapback4-release-store-5`, transactionally. Unaware binaries refuse that
format even when an old source is selected. Failed installation retains the
previous format. Legacy stores without backfills remain unchanged. Prune previews
backfill preimages separately, with counts, bytes and bounded ids. Explicit
prune deletes their values and keeps only per-lifetime reversal-unavailable
identities. Leaving an overwritten column then refuses with a pruned-preimage
reason: select a bridge retaining present meaning or restore a backup. Active
row deletion clears these identities too. Pruning added-column evidence does
not prevent rollback when no old-visible field needs a preimage.

Dropping a declaration has explicit semantic meaning: leave it by restoring
preimages or refusing conflicts. Keep declarations in every later source
whose view should retain their meaning. Refusals include exact affected counts
and up to five bounded privileged samples. Missing inputs/lookups, output/type
errors, arithmetic/meter errors and uniqueness/cap conflicts refuse atomically;
a widened/optional non-unique bridge plus an authorized repair mutation is the
repair path. A post-backfill-edit conflict requires keeping the current/bridge
source, deciding a truthful old representation, then repairing it before
selecting old source. No automatic fallback turns a new enum value into an old
meaning. Native v2 rows with no preimage retain the parent's existing law:
forward selection may make incompatible present values dormant; rollback
requires representability and refuses with its existing reason. This amendment
does not change REL5's rollback or restoration selection policy.

`deploy --check` uses the existing private disk snapshot, deploy direction and
restoration intent; rollback previews use rollback direction. Later live writes
can change its plan. `backfills` in both cold/hot JSON receipts and exact preview
text reports `table name transformed N rows` or `table name reversed on N rows`.
These are transformed row visits, separate from the parent's disjoint dormant
rows/cells/index entries. They are not additive counts of distinct rows across
different transformations, and do not claim a frozen production population.

Consumed historical references must retain valid parent-lifetime evidence even
when the input column is dropped. Expired predecessor/restored images are retired
before any transform, including ordinary expiry without read-through. Pruning
keeps membership-only tombstones solely for surviving lifetimes; such a tombstone
refuses re-entry requiring lost values rather than treating the row as fresh.

Re-entry retains an adoption-cohort identity with each active row receipt.
All declarations first applied in one activation, including continuously carried
declarations on tables that were never removed, read one reconstructed source
snapshot, including point/range indexes; this overlays that cohort's complete
input evidence and output preimages (including original absence) on current
images. Distinct original cohorts are evaluated separately against their
respective historical overlays, so a declaration introduced later can read an
earlier declaration's already-transformed values. Computed and retained/native output values must fit candidate scalar types and
text minimum/format constraints before narrowing; invalid generated outputs
refuse the entire adoption with affected-row samples. Patches remain staged until
all cohorts succeed, and current row images are restored before applying them.
New declarations use the current assembled predecessor snapshot. Inactive
cohorts restore their own still-omitted input interpretations, independently of
new declarations in that activation, and catch up changed authored inputs. Declared historical arguments consume retained
cells and source definitions even when the candidate omits those columns;
retained parent-lifetime bindings still apply. A native-image exception requires a birth marker for this exact declaration,
a matching fingerprint of the original non-output inputs, and valid, complete outputs;
a new declaration never skips valid old inputs merely because an older
transformation left a retained output. Receipt reference inputs use private namespaced bindings in the existing
dormant parent-lifetime ledger, independently of the live input column. A
retargeted/dropped input cannot substitute its current binding for the saved
reference. Every unchanged saved argument consumed during active or inactive
re-entry validates its private lifetime binding before program evaluation.
Bindings use each restored narrowed row's actual archived reference type
(rather than the table-wide predecessor), even when an
argument is declared as generic `id`. Existing private bindings survive
re-entry with unchanged saved inputs even after the visible column becomes
generic `id`; schema type erasure cannot recapture the same parent id. Reconstruction validates any consumed saved binding before restoring
its value. Original absence is recorded separately from the predecessor's interpreted
value. A physically missing field consumes its source default when present,
otherwise null; receipts retain that interpretation explicitly, preventing
later defaults from changing argument or lookup/index evaluation. Expired sources retire when entering or leaving the
last declaration, including restored table images.

When transformed rows become dormant, candidate output reference types supply
parent bindings even when the predecessor had no such column. Existing invalid
bindings are preserved. If a restored row becomes dormant again, only its
explicitly backfilled authoritative cells update the retained image; original
source definition, other cells and authority provenance stay intact. Forward
selection after rollback reconstructs absent added outputs for that same
declaration before evaluating its arguments, rather than feeding it its own
retained result.

Input omission is stored independently from interpreted null/default values,
both for the current physical lifetime and for each receipt. Ordinary writes
compare interpreted old/new inputs; meaningful edits end omission provenance,
while unrelated writes and default materialization do not. Receipts reconstruct
their original interpretation of omitted fields across later default changes.

Rows inserted while a declaration is active receive a private native-birth
marker keyed by its normalized definition and a hash of their input image;
no original input values are kept in that marker. The same declaration preserves
complete native images with unchanged inputs, including absent optional inputs,
constant transforms and whole-table restoration. Changed native inputs, invalid
present inputs, lost native output images or conflicting other-transform history
refuse with a bridge reason. An inactive overlapping receipt is compatible only
when every overlapping current output equals its recorded preimage; an active
or pruned conflicting history still refuses. Same-column output values belong
to the candidate type, rather than the historical input type, for native rows.
A new declaration name does not inherit another
name's birth marker. Prune retains only native fingerprints for surviving
lifetimes, alongside current omission flags; receipt absence flags are forgotten
with historical values. Delete/reset remove every marker for the ended lifetime.

Source retirement uses the ordinary engine expiry/reference-action closure
under the complete assembled predecessor schema, before any patch runs or
removed table is archived. Only surviving post-action rows enter dormant storage. Restored source
indexes and cap occupancy are rebuilt first; writing-reference groups must fit
the source reservation's live bound. Cascade and set-null effects participate
in this same transaction; restrict or retained-child blockers refuse the entire
adoption. Retired source population forces a new generation so clients cannot
keep children removed by a cascade. Authoritative set-null updates corresponding archived cells/narrowed images
to null before clearing old column bindings, while receipt input bindings remain
independent. An expired
narrowed source is exposed only inside this uncommitted lifecycle phase and
cannot reach a backfill evaluation alive.

Development reset still empties every lifetime's data/history/native/omission
markers, then reconstructs code-derived declaration/input registries from its
retained schema before reseeding; the new identity's rows receive new birth
markers. No release HTTP reset door is added.

Evidence decode is preflighted against
the existing job heap ceiling. Text preview lists private preimages separately
from dormant application rows/cells/index entries.

### Per-column transformed views

A receipt records a `retained_outputs` set independently of its declaration's
active flag. When leaving a declaration, candidate-visible transformed outputs
reverse to their preimages. Outputs absent from the candidate remain transformed
in dormant storage; their set membership survives until reversal or re-entry.
Even an inactive declaration reverses those suspended fields when a later plain
schema exposes them. Whole-table suspension keeps the transformed view intact.

Re-entry preserves the saved preimage for each still-transformed output. A
fully reversed output instead captures its actual assembled source value,
including restored dormant cells and interpreted predecessor defaults, before
applying the patch. Input history and rollback preimages are separate: an input
may retain its original omitted/null interpretation while the latest rollback
view has a literal default. Ordinary writes do not erase omission provenance
when they edit a transformed output from that same original cohort.

An inverse restoring genuine absence records a transaction-local source mask.
Later evaluation cannot fill that absence from the suspended result or a default
belonging to the output schema. The mask is dropped on every exit. Earlier
recorded cohorts' staged patches are replayed into later recorded source views;
fresh declarations still share the untouched predecessor snapshot and cannot
read each other's newly staged outputs. Every decode remains heap-admitted.

Reference arguments copy any matching ordinary cell-lifetime bindings before
restoration consumes that ledger, including transformed reference cells absent
from an archived whole-row definition. Unchanged saved inputs retain existing
private bindings; inferred current bindings cannot overwrite their invalidation.
The stable format is `snapback4-release-store-5`, with schema capability
`release-backfills-v2`. Published 0.4.33's store format 3 upgrades on first use.
Unpublished experimental format 4 and the older capability cannot silently read
this evidence layout. Package versions are not changed in this workstream.

## 4. Staging clock

Only a store durably classified staging by deploy --staging may serve with
--clock-offset. Missing/unknown classification is production. This setting
is process-local, with the same signed-duration parser and monotone elapsed
clock as dev. No serve-time mechanism can reclassify an existing production store. Restart drops the offset unless explicitly
provided again; persisted timed-disclosure floors never retreat below their captured value.

Staging exposes the existing /dev/clock/status and /dev/clock/advance only
with any full service session: these are trusted operator credentials, as for
system jobs. Production refuses even with a service token, and an explicit
production serve offset refuses with E_CLOCK_DEV_ONLY before listener startup. Account, guest, read-only and unauthenticated
requests refuse. Recheck classification and session under the engine writer
before advancing. All fixture, reset, persona and dev-job doors remain closed.
Use the same advance implementation, schedule drain and ambiguous-reply law
as dev. CLI clock advance --release DIR mints its local service authority.
startServe accepts clockOffset and exposes now()/advance() through that
operator authority; it never changes store classification. Each helper control
mints a current staging-time operator session rather than caching a credential
across arbitrary time jumps. Ordinary user sessions retain normal expiry.

Hot release activation samples `shared.now()` under its engine writer, including
the persisted disclosure floor, and passes that one time through the core's
explicit `adopt_release_at`. A live preview probes the existing filesystem owner lock independently of
HTTP bind/address hints and acquires a stopped-store lock before taking its
SQLite snapshot, retaining that lock through inspection. A rollback preview
reuses its caller's existing ownership rather than probing its own lock as a
live host.
A live preview samples time through the same-owner,
store-bound existing private status protocol; no session is minted or clock
changed. A missing existing-store ownership sidecar refuses rather than assuming a
stopped host without exclusion; ordinary rollback preview can reestablish and
reuse its canonical ownership. A revision mismatch with the private database snapshot refuses as a
racing activation. Store contents and the clock are point-in-time samples, not
a freeze of later live writes. A stopped store's cold activation/preview uses
wall time, with the existing persisted disclosure floor applied by activation.
Positive and negative staging offsets are both covered by hot/preview tests.
