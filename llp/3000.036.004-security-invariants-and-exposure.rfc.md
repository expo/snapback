## 1. Contract

The wave-16 bakeoff found rules enforced correctly but policies encoded wrongly.
A declaration of intent is independent of the rules implementing it. `check`
reports each declaration as **proved**, **refuted**, or **unproved**. Refuted
means a concrete, replayed database/rule counterexample, never merely a Boolean
assignment. Unproved names the unsupported path or incomplete search. Neither
unproved nor a finite passing test campaign may be described as proved.

Implementer: SEC in this worktree, starting 2026-10-18. The author commissioned
this semantic extension and two independent design reviews. No version bump
or publication is part of this lane. STAGE owns provisioning/password dev doors;
RULES5 owns live-parent rule semantics; FRONT owns general diagnostic triage.

## 2. Surface

Use the existing rule vocabulary rather than invent a second policy language:

```
invariant notes.read only .patient = viewer or .clinician = viewer
invariant requests.update only .requester != viewer
invariant members.role write only exists roles[viewer, role = 'owner']
invariant photos always .image != null
```

The first target is a table, the second component an effect (`read`, `insert`,
`update`, `delete`) or a column followed by `write`. `write` checks insert and
update, including both images for ordinary updates; delete authority has its
own declaration. A column invariant only concerns writes to that column, but
must include every effective admission path. Owner-only field patches bypass
an ordinary table update rule; invariants affected by `written by` stay
unproved until that bypass is modeled. An implication from a denied table
rule must never prove such an owned-field claim.
`always` is a row-integrity assertion. Predicates parse as ordinary Quarry
expressions; unsupported policy expressions are reported unproved with the
reason. Unknown tables/columns/effects are authoring errors. Multiple source
files and multiple declarations are supported. For update intent `.field` means both old and next images for mutable
columns; named transitions require an explicit reviewed reduction or stay
unproved. Once-judged immutable/id rules need a proved equal-image reduction
or stay unproved. Both upsert arms and `insert if absent` are included, with
their own collision/refusal observations. `always` quantifies over every
committed row image from insert/update/upsert and trusted seed/import/restore/
activation, not merely mutation inserts. Constraint-based row proof must use
the actual validation on every ingress, including defaults and the exact
non-whitespace minimum function, or stay unproved.

No declaration changes runtime
authority or replaces a rule. No implicit service-seat exemption is added.

The proof fragment uses bound rule predicates. A row assertion can be proved
from its required column type/constraints (not an optional type), or otherwise
remains unproved. Aggregate/transition/temporal assertions outside that fragment
remain explicitly unproved, not syntactically discarded. Syntax with `now`,
counts, or other program expressions must retain that reason. This is a safe
extension point, not a claim of a complete solver for arbitrary Quarry.

## 3. Sound proof boundary

For a table effect, prove `admission => policy` for **every database snapshot**,
row image, ordinary authenticated viewer (including service seats) and clock.
The engine system principal is explicitly outside this quantification: it is
the trusted seed/import/job boundary, never an ordinary user or an implicit
service-seat exemption. Tables touched by system/native/job/worker paths remain
unproved absent a reviewed reduction, and audit lists those writers. This overapproximates every reachable history:
an old assignment and a changed current role are independent facts. Grant
creation never proves a current role. Required role predicates must be true at
the access boundary. No fixture-specific assumption enters a proof.

Translate Boolean connectives compositionally, retaining true/false/unknown
truth for atomic predicates. Unknown never admits and `not unknown` is unknown.
Atomic facts are keyed by their full bound structure, including table, index,
keys, named equalities and old/next image. Symmetric equality may canonicalize by operand reordering only, preserving
Value variants (Id is not Text), table, index, keys, image and predicate kind;
other equalities and probes stay independent. A finite exhaustive implication
check over this abstraction is sound because it includes every concrete
valuation, even impossible ones. Cap atoms/work; cap exhaustion is unproved.
Do not add database consistency axioms without a separate soundness argument.
Never drop, assume true/false, or simplify an unsupported admission atom;
keep it opaque with its full identity or report unproved. Concrete leaf
semantics are the current `evaluate_leaf`/`term`, not stale Lean open points:
null equals null, null differs from a non-null literal, Id differs from Text,
noninteger ordered comparison returns false, and a missing live reference
marks unknown (including under negation). Missing ordinary fields currently
load null; missing reference and missing image are not conflated. Any semantic
mismatch with the independent model is named, never normalized away. Runtime
errors do not establish an admitted result; probe/storage/schema failure
cannot be used as a successful counterexample or a proof fact.

The Lean addition proves a three-valued Kleene kernel with admission only
on Readable and the exact theorem: exhaustive checking implies that for every
valuation, eval(admission) = Readable implies eval(policy) = Readable; the Quarry-to-kernel translation and runtime boundary remain reviewed
Rust obligations, not a claim of whole-platform formal verification.

For read intent, admission includes the ordinary read rule and every bypass:
- point/list/view/filter/count/exists and live refetch use ruled reads;
- sync acquisition and publication authorize at their own server snapshot. An
  offline device cannot know a later server revocation, even with until-revoked.
  A synced read invariant therefore reports the device access path unproved
  for current-server-role intent, separately from its server proof. Delivered
  history has an additional explicit retained-history blocker. No stale local
  role is treated as a current server role;
- inherited read-through rules are checked in their bound form, including
  captures; live-parent semantics remain RULES5's responsibility;
- valued write targets already reread through `get` before returning, and
  generated insert results also use an ordinary ruled read. Verify those
  reductions against the bound IR; any escaping image without that reduction
  is a blocker or must satisfy the implication `effective write admission => read intent` for that image;
  otherwise the declaration stays unproved;
- maintained aggregates/columns and row views may expose source changes under
  different rules: report such source claims unproved unless a reviewed exact
  reduction proves them; projections narrow payload only; existence/count disclosure follows the
  derived path's own rules, so each derived path needs its own reduction or
  stays unproved;
- table-rule probes see raw target rows, unlike program `exists`. Follow
  reverse dependencies into every other table's read/write rules: the presence
  of a marker row or a successful write can disclose the protected target's
  existence or named fields without returning that target. Source privacy
  intent remains unproved for such raw-probe observations unless a reviewed
  reduction proves authorization or the policy explicitly permits disclosure;
- incoming `on delete cascade` and `on delete set null` effects bypass child
  delete/update rules. Report child delete/update/column-write invariants
  unproved when affected, including transitive cascades, until initiating
  authority and child-image policy are modeled. Enumerate these edges in audit;
- asset reads inherit their owning row privacy, while upload/write authority
  belongs to insert/update intent; applicable private-field authorities must be conjoined with owning-row
  admission for asset reads;
- jobs, schedules, native jobs, actions and external effects are trusted system
  or worker boundaries. Read claims affected by opaque outputs/side effects
  remain unproved. Job writes do not prove ordinary-user write authority;
- refusal codes are observations: an authored difference between an absent
  lookup and later denial is a reported exposure. A privacy proof must not
  ignore that path. Unmodeled constraint/refusal observations remain unproved.

Observer boundary: this verifies row payload and logical existence/refusal
observations, not physical timing, runtime cost or all resource side channels.
The platform's documented examined-count/meter-cut observations are explicitly
excluded and reported as exclusions, not full noninterference. Read intent
includes all logical exposures above. A component may be proved while the
whole declaration remains unproved because another path is blocked.

The implementation must build a closed-world census of bound IR read/write
forms and schema-triggered paths. An unclassified form is a blocker, never
silently omitted. Census includes sequence allocation/read admission, online
and device query paths, ephemeral paths, owner fields, maintained writes and
referential actions. System/job/action/native/external touched tables default
unproved without a reviewed reduction, and are listed as grant-column writers.
Every `read` declaration covers all enumerated logical paths, not just its
direct rule. Authenticated viewer classes use engine operations; signed-out
cases run only against HTTP/auth admission, never a fabricated principal.
Retained-history observations are classified by leave policy and reported
separately; they cannot refute the platform's retention contract or prove a
current-role declaration. Test output names unsupported device freshness.

The report enumerates the paths checked and blockers. A proof is never awarded
just because the direct table rule passed while an indirect path is unmodeled.
Conservative rejection/notes are acceptable; false proof is not.

## 4. Counterexamples and generated tests

Generate deterministic challenges from schema types, policy atoms and fixture
rows. Use in-memory stores; never leave SQLite sidecars under target. Vary the
viewer across owner/other-user/other-role/revoked-role/unauthenticated classes,
policy literals, principal arguments and absent optional values. Existing role
rows and retained grant rows form revoked-role snapshots. Do not call an
arbitrary consistent snapshot a *reachable* application-operation sequence.

Concrete counterexamples must replay the engine's actual rule admission and
show the policy false, recording viewer, effect, row, supporting rows and rule
path. The absence of a concrete witness when implication fails is **unproved**.
Generated tests are a separate executable check, run by default `test`, with
coverage counts and named unsupported cases. They use isolated state so they
cannot corrupt the fixture business tests. For operations, derive arguments
from fixtures and schema, substitute other principals and roles, and compare
admitted effects/observations against the declared intent. Merely succeeding
as another user is not a failure when policy permits that operation. Signed-out
network admission cannot be tested by inventing a signed-in principal: label
that boundary separately. No finite campaign promises arbitrary sequence
coverage. `test` fails on replayed violations; unproved coverage is explicit.

## 5. Exposure report

`audit` and `check --audit`, both with `--json`, produce a stable structured
report. This is a conservative permission map, not a claim every listed path
is reachable. Enumerate each table/effect, row predicate, audience-readable
and owner-private columns, operations touching it, sync/asset/derived paths,
and inherited dependencies. List probes and the insert/update writers of the
probed grant columns; include transitive dependencies with a visited set.
Enumerate role alternatives found in rule probes/literals, including generic
signed-in principals and service seats. Unmodeled role predicates retain their
full expression rather than collapsing to an invented role name. Normal
`check` lists broad signed-in reads and tables with no declared intent, with
`guide security` as the next step. Do not claim `allow` admits signed-out
requests; authentication precedes the operation.

An existence-oracle advisory compares distinct authored absent/denied codes;

text. Media stays optional only when the product allows omission; required
photos use required `image` or `[image] 1..N`, with existing content validation.

## 8. Operation and general row assertions (SEC refinement)

The table effect contract is intentionally stronger than a query/mutation
contract. To state an operation-specific authority rule without overrestricting
other writers, `invariant vehicles.liftHold only exists roster[viewer, role =
'liaison']` targets the unique authored mutation `liftHold` on vehicles.
Qualified operation names are allowed; ambiguous/unknown names are errors.
Only writes to the named table by that operation are covered. Its earlier
straight-line requirements may establish admission when they bind to existing
rule predicates: positive caller-filtered existence implies raw existence,
whereas negative existence is not assumed equivalent. Branch/loop guards,
aliases, helper calls, changed viewer, prior writes, and unsupported flow remain
unproved unless separately reduced. The current conservative implementation
uses only leading straight-line requirements before any other statement, and
only requirements without negative probes or live references. These require
facts are evaluated before writes; a policy depending on a table any earlier
statement can change cannot be proved. Require-to-write stability is checked
against every intervening write. Failure to establish it is unproved. The
actual effective write rule remains an additional obligation, including the
field-owner bypass and implicit effects. No operation syntax grants authority.

General `always` expressions can still receive concrete counterexamples even
when outside the proof fragment. Preserve the original policy AST; a separate
partial concrete evaluator can judge row-local values, Boolean connectives,
comparisons, server clock and raw named-key existence over a schema-valid
snapshot. Unsupported/unknown evaluation is not false and cannot refute.
Nonunique raw existence is an explicit existential over all stored live rows,
not a fabricated unique index or a caller-filtered program read. Unmodeled
expiry/captures/derived tables block this evaluator. Snapshot-seeded violations
are labeled as such, never reachable application traces. Actual authored
operation challenges use the engine, check committed changed images and name
the operation and arguments; no-op/rolled-back or merely successful unrelated
operations cannot refute a write policy. Fixtures and generated cross-principal
role rows may supply candidates, but never proof assumptions. Multi-operation
history, HTTP and device traces remain separately named coverage obligations.

### 8.1 Exact conservative boundary (review clarification)

A snapshot-only evaluation NEVER sets refuted. A row-state counterexample must
actually execute Engine::seed_at in an in-memory engine and then read back the
committed image before judging it; defaults, unique/final constraints, typed
validation and the exact text minimum must pass. That is a replay of the trusted
seed ingress in the `always` quantification, labeled `trusted-seed ingress`,
not proof that an ordinary application sequence reaches it. Rejected seeding,
nonlive/expired/retained/captured/derived populations or unsupported validation
are unproved, never refuted. No mutation is inferred from a snapshot.

The concrete evaluator uses the typed Value and exact §3 leaf/connective
semantics; typed Id and Text stay distinct. Its partial unsupported cases
produce unknown/unsupported, never false, including under Boolean connectives.
It supports no clock/temporal expressions in this increment: `now` or temporal
comparisons remain unproved. It does not borrow the host language's truthiness.

Operation proof is confined to one atomic server mutation transaction. The
interpreter/SQLite transaction admits no concurrent application interleaving
between requirements and its writes; opaque/external work is excluded. Leading
requirements contribute only row-independent viewer/literal/positive raw-probe
facts; every probe is caller-filtered at runtime so positivity is essential.
No fact binds an old/next target field, argument alias or captured row. Policy
expressions needing those bindings stay unproved in this reduction. Reject a
require dependency if ANY operation write may touch it, including the target
write itself, both upsert arms, field-authority paths, maintains, sequences and
referential actions. Unknown/helper/opaque write sets or unclassified forms
force unproved; the absence of an explicit IR write is not an absence proof.
These are conservative blockers, not proposed rewrite/lint assumptions.

## 10. SEC2 observer and adoption amendment

Implementer: SEC2, 2026-10-18. This amendment extends, rather than weakens,
the snapshot quantification and the proved/refuted/unproved contract above.
It is a proposal until the independent reviews and implementation evidence
are recorded. STAGE owns HTTP provisioning and password dev doors; RULES5
owns live-parent semantics; FRONT owns general diagnostic triage.

### 10.1 Separate observer obligations

Report individual observer obligations as well as the whole verdict. A proved
component never clears another unresolved component. Ordinary point, scan,
planned union/projection, count, sum and existence reads consume authorized
rows; pure computation over those rows cannot reveal an unauthorized payload.
The reduction concerns logical data, not the already excluded examined-count,
meter, physical timing or the separately unproved global wire activity path.
Context changes, native programs and external workers are never pure reads.

For a maintained count or sum with ordinary bare group keys, pull the derived
read predicate back to the source row by substituting its group columns.
Prove that predicate implies the source invariant using the existing exhaustive
kernel. Do not assume the source read rule protects an explicitly broader
aggregate. Lost source fields, value-dependent derived rules, aliases,
row-keyed/private/captured maintenance, temporal contributions and downstream
derived observers without a checked substitution stay unproved with the exact
edge and an author repair. A filter can narrow contributors, but is not used
as an assumption in this first reduction. No maintenance consistency axiom is
added to the propositional kernel.

Generate paired in-memory engine worlds, identical except for one protected
row, only when both worlds seed and validate and the privacy policy is false
in both. Execute the same authored operation with identical arguments/viewer
and clock. Different returned data or refusal code/message is a concrete
logical-existence counterexample; ignore sequence numbers, receipts, meters
and timing. Keep both executions and inputs in the witness. An engine/storage
error or unsupported policy evaluation cannot refute. A passing finite paired
campaign proves nothing. Maintenance is rebuilt independently in each world;
never seed a fabricated derived value. Unsupported referential/final-existence
worlds are declined. This tests count/sum/existence, mutation returns and
collision/refusal observations without guessing which successful call is bad.

### 10.2 Temporal intent

A separate, typed clock reduction accepts Boolean combinations of ordinary
rule predicates and comparisons between server `now` and row time fields.
It adds the actual half-open lifetime predicate (nullable lower/upper bounds
included) to read admission. Clock atoms use a compiler-private identity and
cannot alias user fields. Only equivalent operand orderings canonicalize;
there is no inferred inequality arithmetic. A read opening/expiry component
can therefore be proved independently of sweep execution. Public payload is
hidden before `not before` and after `expire at`, even while physical rows
await cleanup. A job that flips a flag establishes no exact deadline: temporal
intent without a matching lifetime or dominating clock gate stays unproved
or receives an executed between-ticks counterexample. Derived lifetime paths
are not silently covered by the direct-row reduction. Offline time/revocation
retains the existing applied-server-position boundary.

### 10.3 Adoption

Normal check emits one project-level N_SECURITY_INTENT note counting tables
with any effective access rule and no invariant. Generate a separate candidate
draft in `snapback/generated/security-invariants.q.draft`, with provenance and
an explicit author-confirmation warning. It is never compiled or accepted
automatically. Candidate read/insert/delete predicates repeat existing rules
as a starting point, not inferred product intent; omit unsupported synthetic
or transition forms with an explanation. Stable content is deterministic and
rewritten only when changed. The note is once per check, not suppressed forever
by hidden state: a changed schema must remain discoverable. An invariant on
one effect does not cover another. Audit ends with conditional role/row/effect
exposures lacking a matching invariant; this is syntactic coverage, never proof
coverage. Unproved and refuted declared effects remain visible in verdicts.

Every added guide/starter form is executed against an installed tarball. The
README and start packet introduce invariants together with rules, within the
existing documentation budget. Candidate declarations require the author to
compare against the app specification, particularly current roles, grants,
counts, time and omitted evidence; copying rules alone cannot catch a wrongly
encoded specification.

### 10.4 Reduction details and review clarifications

The exact live predicate is `(lower IS NULL OR lower <= now) AND
(upper IS NULL OR now < upper)`, using materialized column defaults just as
the runtime does. Tests include equality ticks, nulls and defaults. The clock
symbol cannot be serialized as a runtime RuleTerm: its identity contains a
colon, which Quarry column names cannot contain. Reversal maps `a >= b` to
`b <= a` and `a > b` to `b < a`, without changing strictness. Only the pinned
server lifetime clock enters this theorem; a query's rounded read-time value
and a device's host clock do not establish admission. Raw probes and every
derived lifetime observer remain separate obligations/blockers. Schedules do
not constrain the time between deadline and sweep. Any between-ticks witness
must execute actual engine calls at both clocks from independently validated
seed ingress; snapshot evaluation of `now` alone never refutes.

Both paired worlds use §8.1's actual `Engine::seed_at`, committed read-back,
typed/default/unique/final-existence validation, and exact text minima. The
named read invariant is evaluated for the same viewer and hypothetical
protected row, against each world's committed snapshot and identical clock;
unknown is not false. These are seed-ingress worlds, not a reachability proof.
Engine contexts are authenticated only. HTTP signed-out and offline/device
histories remain separately labeled. Compare typed canonical object values
and engine-defined ordered arrays; do not sort away meaningful order. Decline
generated ids/opaque work, incomplete results and any observation that does
not repeat when recreating each world. Random/store-specific cursors are not
counterexamples. Explicitly record the unproved sequence/receipt/wire boundary
and excluded timing/meter boundary even when payloads agree. Only a change in
the protected row is an experimental input; other seed rows remain identical,
and referentially invalid absence worlds are declined.

Pullback preserves typed Value variants, full probe table/index/key/equality
identity and row images. Only bare identically typed group columns substitute;
derived id/value, reference and old/next fields do not. Kernel node/atom cap
exhaustion is unproved. The direct edge can be proved as a component; any
downstream derivation lacking a transitive substitution blocks the whole
declaration. Do not infer transitive privacy from that component result.

The missing-intent note includes public/allow tables and tables with any
non-deny read/insert/update/delete rule; a wholly denied table needs no note.
It is emitted once in each check result without persistent suppression state,
alongside any distinct broad-read advice. Drafts are ignored generated output,
never source or an inventory leaf; stale content is regenerated, never a check
refusal. Each candidate carries an author-confirmation comment, and the draft
header warns that copied wrong rules cannot catch themselves. Include ordinary
update candidates; explain omitted captured/transition forms. Full table
read/insert/update/delete declarations (and `write` for insert/update) cover
their corresponding effect in the syntactic audit summary; operation/column/
always assertions do not cover a whole table effect. Declared unproved or
refuted effects are still shown in the invariant verdicts.

### 10.5 Generated histories and production HTTP

Paired mutations require a stable privacy policy throughout execution: no
write to the protected table or any policy dependency, no insert/upsert/delete
(including implicit id minting), no implicit maintain/sequence/referential
writes, no assets with uncoupled ledger identities, and no opaque worker/native
context. Query logical payloads use the ordinary deterministic interpreter;
repeatability is an extra rejection check, never a proof of determinism.
Every excluded case is named unproved/not-covered. Owner-field patch authority
counts as effective access in missing-intent discovery and uncovered audit
entries, even if the table update rule denies; include the column and old-owner
predicate. Drafts explain that authority instead of inventing transition syntax.

Default test also explores short actual ordered mutation sequences from a
schema-valid focused fixture, then reads as the named ordinary viewers. The
record includes initial rows, each operation/viewer/typed argument/outcome and
the final ordinary read. Evaluate read intent in the actual post-history state,
never from a role's old grant. General `always` integrity can be refuted on
committed changed row images after an authored operation; no net image is used
to attribute per-write authority. Uncontrolled/implicit write authority still
needs boundary tracing before it can refute operation-specific write intent.
Enumerate declared personas/service seats and Cartesian enum/Boolean argument
tuples, with explicit caps and unvisited coverage; no passing bounded campaign
proves arbitrary histories. Temporal/captured/maintenance/asset-ledger fixture
histories remain not-covered until their complete replay inputs are present.

Signed-out challenges run in a private production `serve` child over the
actual schema, with no dev mode, fixtures or user credentials. Send unauthenticated
and forged-persona HTTP requests to every public query/mutation and verify
E_AUTH/401, plus closed development doors. Native/action/effect applications
requiring app-owned startup artifacts are named not-covered, not represented
by a partial schema host. Preparation/requests are bounded; kill/wait only
recorded children and remove the private temporary directory after process
exit. This qualifies auth admission, not role history or connected-device
revocation; STAGE retains ownership of staging/account provisioning.

The repaired 015 reference workflow records photo-backed placement/transfer/
adoption handoffs in the same ordinary mutation as custody changes; profile
provisioning and all pets/handoffs in its witness use authored operations.
Trusted seed is not used to manufacture the custody counterexample or repair.
General snapshot integrity still quantifies over arbitrary trusted ingress,
so the ordinary workflow test is not an all-ingress custody theorem.

A policy outside the bound rule/clock fragment is never dependency-free: paired
mutations decline it until dependency analysis of the complete retained AST
is available. The count-policy grant-before-read regression checks this
boundary explicitly. General aggregate integrity is interpreted over complete
validated raw snapshots for refutation only (count/sum and exact bounded
integer arithmetic); unsupported filters, time, captures and type coercions
remain unknown. This interpreter never supplies proof assumptions.

### 11.1 Avoid duplicate concrete searches

Installed-doc builder measurements exposed minute-long repeated searches of
already-proved direct read/required-column components. Discharge those direct
searches with the existing reviewed component result, without promoting the
whole invariant or suppressing indirect paired/temporal/history/operation
challenges. For paired experiments, compute a fixed-point observer table set
from the protected table through maintained targets, inherited readers and
all table-rule dependencies. Skip authored operations mentioning none of that
set. This prunes finite experiments only; it contributes no proof assumption
and clears no blocker. Unknown/opaque observers retain their existing limits.

Proved ordinary insert/delete components also
need no duplicate direct witness search. Update/both-image claims are not
discharged by a next-image theorem. Before the unchanged bounded enum matrix,
try one row candidate pinned to explicit policy field literals (for example a
cancelled status). This candidate is not a proof fact: typed/default/final
validation, actual engine replay and policy-false judgment are unchanged.
Preserve every previous matrix sample; failed literal seeding only declines
that extra candidate.

For ordinary updates, prove the policy over both old and next images using
`update_rule_judged => policy.old_and_next`. Substitute an OldField with its
next-image Field only for id or an explicitly engine-enforced immutable local
column: every admitted update preserves those values. Never collapse mutable
fields, reference hops or their images. This is the same immutable-image law
used by the engine's once-judged update rule; it is not a new consistency
assumption about database contents. A named transition allowing only the next
owner cannot prove an old-and-next ownership policy. Owned-field bypass and
implicit writers retain their separate blockers and concrete searches. The
reviewed two-image component may discharge duplicate ordinary update/write
searches only where no owned-field bypass exists. Actual authored operation
matrices and unresolved observer obligations still run.

### 11.2 Faithful changed-image witnesses

The installed-doc builder found a misleading synthetic update witness: its
`row` repeated the pre-update row, so replaying that apparent unchanged patch
was refused even though the generator had actually changed status away from
the forbidden old value. Synthetic writes now read back the committed target,
record the actual next image and changed patch, and decline no-op/implicit-only
updates or a missing requested column change. The old image is recorded
separately. Under the existing both-image contract, a false old-image policy
can refute an admitted changed update even when the next image satisfies it;
that is not evidence the unchanged patch was admitted. The installed security
guide now states this distinction explicitly and routes per-operation role
authority to operation-specific declarations. Scope remains schema-valid
seed ingress plus synthetic engine operation, never ordinary app reachability.

Private maintained columns add their owning table, not merely their synthetic
maintain target, to the transitive observer set. Direct-search discharge must
not skip synthesized authored-operation assertions sharing the same source
site. Variant-independent unsupported operation preconditions (opaque body,
row-image policy, ambiguous writes and unstable dependencies) are checked once
before snapshot construction, with the same explicit unsupported reason.
Neither change reduces the previously executable argument/enum matrix.

### 11.3 Actual credential revocation admission

The private production HTTP campaign now authenticates through the schema’s declared guest or password method, confirms live schema admission, rotates that bearer, confirms successor admission, and logs out all sessions. It then requires E_AUTH/401 for both retired credentials at schema, changes, sync, probe, refresh and every authored query/mutation door. Credentials never enter counterexamples or logs. Schemas without ordinary identity and applications needing external startup artifacts retain explicit missing-coverage reasons. This tests connected HTTP admission after credential revocation; it does not assert that a disconnected device erased copied bytes, or establish current-role freshness without a sync round.

The campaign transport decodes HTTP chunk framing before parsing JSON: larger production schema responses use that framing. Truncated, oversized and malformed responses fail qualification rather than becoming a claimed refusal.
