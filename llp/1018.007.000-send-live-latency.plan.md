## Evidence and diagnosis

The [program](./1018.007-clique-correction-program.plan.md#evidence-and-confidence)
records the two graders' timing and its limits. Current source provides two
specific leads: `client-outbox.ts` selects its replay log tail through
`runtime.coverage()`, cloning held rows/ranges to obtain a watermark; carrier
input notifications refresh every mounted shared query. Browser offline writes
also await durable admission and prediction, then replay and log-tail custody.
The isolated direct Node control bypasses much of this work.

Application pressure is real and must be measured: Astra subscribes separately
to receipts and reactions per bubble and runs a four-second recovery helper;
Grok's thread effect issues markRead and markDelivered for visible messages.
These are candidates for amplification, not proven explanations of each delay.
Equal snapshot data retains identity, so this is not proof of an infinite
acknowledgment loop. Astra also uses separate plain clients for receipt writes.

## Repair

Implementer: Codex gpt-5.6-sol, starting 2026-09-09, coordinated with the cold
sync lane. First reproduce a message through a real owner and browser carrier
in a fresh worktree. Instrument existing boundaries in the reproduction:
click, durable admission, prediction end, replay dispatch, owner commit,
mutation response, recipient frame arrival, recipient store commit, recipient
render, sender terminal observation. Correlate using one intent/message ID.
Use one tab and two isolated accounts before adding same-account follower tabs.

Measure quiet and 100-conversation accounts, both an idle thread and the app's
receipt load. Report queued receipt operations and logical subscriptions. Do not
infer commit time from a polling query or label all unexplained time client work.

Remove demonstrated whole-store work from watermark lookup and avoid repeated
equivalent materialization/re-evaluation inside the existing serialized owner.
Use existing committed input revisions to coalesce duplicate hydration/work.
Carrier persistence already uses journaled deltas and shared entries already
coalesce overlapping local refreshes; retain both. A focused source probe
confirms one input refresh invokes 50 callbacks with 50 mounted queries.
Broad dependency filtering from Draft LLP 1018.002 is outside this repair;
operation-name filtering is unsound. If measurement points
to owner scheduling, repair that queue explicitly; retain the attribution.
No new polling timer, bypass of IndexedDB durability, speculative committed
state, or reordering of a user's FIFO intents is part of the repair.

The watermark lookup is on the sender's settlement path after owner commit.
It cannot alone explain or repair recipient delivery. The shared performance
lane must independently qualify recipient frame/materialization/render time;
faster Pending clearance is insufficient. Audit other `coverage()` call sites
such as loadFacts/resumeSeed only when they enter the measured interval.

## Measured current-SDK settlement failure

The isolated browser investigation separates owner/recipient delivery from
sender custody. A current-SDK send reached the owner and recipient in hundreds
of milliseconds while the sender's IndexedDB intent remained queued beyond
20 seconds. The sender CPU profile was predominantly idle. A proposed
authority-revision race was **not confirmed**: stage instrumentation observed
no revision change and that inference was withdrawn.

The captured replay path instead failed while accepting its conditional
`messages.inbox` tail with `conditional reply requires immutable full-envelope
facts`. Ordinary queries supply the full-response revalidation callback when
an `unchanged` answer lacks the required immutable fact proofs. `logTail`
omitted it. Repair that missing callback through the existing same-authority
request path: one unconditional `{op,args}` read with no validator, followed by
the unchanged atomic tail-plus-terminal settlement. Preserve cancellation,
revision/principal fences and byte-identical queued custody when retry fails.
Do not add an authority retry loop, fabricate a committed UI result or depend
on an application timer to recover this ordinary send.

Tests must distinguish full tails (no additional request), successful
conditional-to-full recovery, another `unchanged` response where full evidence
was required, transport failure and interruption during revalidation. The real
browser send series still qualifies the resulting latency; the captured error
alone is a diagnosis, not a completed performance claim.

## Composed browser series

The complete isolated Astra series uses three warm-ups and 20 measured sends
with the footprint and conditional-tail repairs composed. All 20 recipients
observe the unique message without refresh. Click-relative p50/p95 are:

| Observation | p50 ms | p95 ms |
| --- | ---: | ---: |
| Send request | 46.7 | 76.6 |
| Send response | 130.5 | 168.6 |
| Recipient DOM | 109.7 | 192.8 |
| Sender Pending clearance | 3,437.1 | 6,237.5 |

Sender clearance grows from about 1.7 to 6.6 seconds across the series. Thus
recipient delivery passes this witness, but **sender latency remains open**;
the one-send diagnostic above did not qualify sustained sending. These are
client observations, not owner commit timestamps or isolated CPU attribution.

## Acceptance

- A newly enqueued ordinary send reaches replay without waiting for an unrelated
  whole-history clone or a complete re-evaluation of every mounted query.
- Real browser recipient observes each unique send without refresh; record all
  trials under the original 60-second observer ceiling and best-of-three
  benchmark window. Also report p50/p95 from 20 measured sends after three
  warm-ups. The repaired run must remove the reproduced multi-second pause;
  an unexplained but passing timeout alone is insufficient evidence.
- Sender terminal state follows the durable owner result. Unknown transport
  outcomes remain queued and replay byte-identically; exactly-once, FIFO,
  principal-switch fences and follower takeover regressions pass.
- Test recipient revocation, receipt fanout and reconnect while sends are
  active. No UI claim may get ahead of its authority/custody proof.

Use small deterministic operation-count tests for expensive work in the normal
suite and real-browser timing as retained qualification evidence. Reuse the
existing test runner and carriers; do not introduce another monitoring framework.
