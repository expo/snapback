## Result

Stage B found zero class-(a) reference-semantics errors, two class-(b) shipped
defects, and fifteen class-(c) conservative shipped/reference divergences.
There is no unclassified divergence. Twelve further axes are recorded as
harness gaps; none is reported as agreement or counted as a divergence.

The two shipped defects remain:

1. graph live-delta row patches can carry fields outside the closed projection
   into serialized frames; and
2. an established graph subscription can enter incremental graph evaluation
   after `SNAPBACK_GRAPH_EXEC_DISABLED` is raised, even though fresh graph
   execution refuses.

Both defects were reproduced through executed serving behavior and have
fix-forward filesystem tickets. The executable Stage A evaluator and its 128
frozen vectors needed no correction. LLP 0309 and LLP 0309.000 were not edited.

## Method and audited snapshot

This revision audits commit
`b2ecdc3beca6f8434f3fcfc12261cf369d0828bc` on branch
`sbs/20260826-0309-stage-b`. The executable audit is
`crates/snapback/tests/delta_semantics_stage_b_audit_v1.rs`; its graph fixture
adapter is `crates/snapback/tests/support/graph_stage_b.rs`.

The command
`cargo test -p snapback --test delta_semantics_stage_b_audit_v1` executes all
of the following in its single closed-register test:

1. DK-3 classifier families through shipped `compute_live_delta` and reference
   E0;
2. the ordered and at-cap DK-3 probes through reference E0+E3, and both
   membership forms with the identical folded parent-row change supplied to
   shipped execution and the reference E0 carrier + E6 support probe;
3. a real DK-3 subscription through add/update/delete publication, including
   reference E0 Enter/StayIn/Leave comparisons and predecessor/successor
   dependency-version assertions at every transition;
4. every one of the 17 graph disposition cases through a fresh real graph
   subscription and the case's actual mutation, or explicit subscription
   supersession for the demand-change case;
5. a case-shaped E3, E4, E4-composite, or applicable fallback evaluation built
   from each replay's actual normalized plan, predecessor retained evaluator
   state, storage change image, independently normalized arguments/auth,
   changed fields, and demand; and
6. the eligible graph outer lane, including the delivery latch, captures,
   window ledger, proof tuple, delivery observation, convergence result, and an
   established-subscription execution-disabled probe.

For every adapted graph case, the audit compares the reference verdict and
projection-scoped delta with the shipped disposition and wire operations. E3
admission is derived independently by evaluating the changed post-image
through reference E0 with the replay's normalized visibility, filters, input,
and auth; it is not copied from the shipped successor keys. The audit asserts
the resulting tag against a closed register for every executed E3 row, then
compares retained rows, membership/order, boundary, completeness bit, and
completeness label. All six adapted E3 cases have complete successor windows;
their non-comparable continuation axes are explicit gaps because the reference
retains its boundary cursor while the shipped serving state exposes no
pagination continuation. The implemented incomplete-window comparison branch
is not claimed as executed and is separately registered as a harness gap. E4
comparisons cover lookup scope/key/presence, exact full child-index scope keys
(including empty scopes), predecessor-derived root keys, child identity and row,
flattened child cardinality, and every child's row version against the shipped
retained evaluator state. A case
needing an unimplemented E5/to-many composition is a named row-level gap, never
an agreement.

The frozen `tests/conformance/graph/delta-dispositions.v1.json` file is used
only as a closed inventory and expected shipped snapshot. The audit does not
derive a row's result by reading its name or copying its frozen disposition.
There are no source-text substring assertions in the harness.

## Closed divergence register

There are **17** divergence rows: **0 class (a), 2 class (b), 15 class (c)**.

The fifteen class-(c) rows are five DK-3 rows (ordered, at-cap, membership,
narrowed contract, stale result count), nine graph disposition rows identified
in the table above, and one graph copied-capture/next-delta-latch row.

The two class-(b) rows are:

- `graph-unfiltered-retained-row-patch`: executed E3/E4 projection fields are a
  strict subset of fields observed in eligible serialized graph operations;
- `graph-exec-disabled-established-subscription`: an established subscription
  emits an incremental graph frame after the execution switch is raised.

Every divergence row in the executable register carries axis, case, shipped
behavior, reference behavior, class, and evidence. The test fails if a row is
unclassified or if the 0/2/15 totals drift.

## Class-(b) ticket reproductions

### Projection custody leak

The audit executes all three eligible graph cases, executes their E3/E4
reference forms, collects the reference `projection_fields`, then collects the
keys actually serialized in each shipped graph operation. At least one shipped
field set is strictly larger. This dynamically reproduces the ticket; source
citations explain the implementation path but are not the harness oracle.

Ticket: `issues/20260826-graph-delta-projection-custody-leak.md`.

### Established-subscription execution-disabled bypass

The audit first establishes `issueSummary`, then raises
`SNAPBACK_GRAPH_EXEC_DISABLED` only around the synchronous mutation. The
drained frame is still `live_delta`, and its delivery observation reports the
delta lane. The ticket retains code citations for the fresh check and
incremental candidacy path; the reproduction itself is executed behavior.

Ticket: `issues/20260826-graph-exec-disabled-established-delta-bypass.md`.

## Harness gaps

The audit makes no agreement claim for these unreached axes:

1. `issue-list-to-many-update`: two matched nodes require an E5/to-many
   composition adapter.
2. `issue-detail-to-many-update`: the matched bounded-to-many node requires an
   E5 adapter.
3. `list-by-id-to-many-update`: two matched nodes require an E5/to-many
   composition adapter.
4. Publication-guard internals are not observable through existing hooks. A
   successfully drained frame proves external publication, not the guard's
   internal ordering.
5. The authorized DK-3 add/update-versus-remove serving split is not
   established by this fixture. No divergence row is claimed for it.
6. The E3 complete-window continuation axis is not comparable in each of
   `issue-detail-root-update`, `issue-list-in-window-reorder`,
   `issue-list-membership-add`, `issue-summary-root-scalar-update`,
   `issue-summary-two-field-coalesced-patch`, and
   `issue-summary-order-key-move`: the reference state retains its boundary
   cursor, while the shipped retained serving state exposes no pagination
   continuation. These are six separately registered per-axis gaps.
7. The incomplete-window E3 continuation comparison branch is implemented but
   no adapted E3 replay reaches an incomplete successor window, so that branch
   is not claimed as executed.

These gaps are neither agreements nor unclassified divergences. The take-window
case is not a gap: explicit subscription supersession executes and proves that
the configuration change creates a new graph instance outside DeltaApp.
