# LLP 0309.001: Stage B delta-semantics re-derivation audit

**Type:** Research

## Result

Stage B found **no class-(a) reference-semantics error**, found two
class-(b) shipped defects, and classified every other shipped/reference
divergence as class (c). There is no unclassified divergence.

The two shipped defects are:

1. graph live-delta row patches can carry unprojected retained fields into
   serialized frames; and
2. an established graph subscription can enter incremental graph evaluation
   after `SNAPBACK_GRAPH_EXEC_DISABLED` is raised, even though fresh graph
   execution refuses.

Both have fix-forward filesystem tickets. This audit changes no runtime code.
The executable Stage A evaluator and its 128-vector corpus needed no correction.

## Method and audited snapshot

The audit was run on branch `sbs/20260826-0309-stage-b`, based on Stage A at
commit `70c81c755da3e87f24fbce31157c948a7881c6cd`. That commit contains
`tools/snapback-delta-semantics`, its 128 frozen conformance vectors, and the
existing shipped-lane corpora.

The dev-only runner is
`crates/snapback/tests/delta_semantics_stage_b_audit_v1.rs`. It does four
things:

1. adapts `QueryPlan`, prior IDs, and `ChangedRow` into reference E0 admission,
   then replays the DK-3 classifier and `live_delta_v0` families through both
   `compute_live_delta` and the reference evaluator;
2. establishes a real `LocalSnapback` live subscription and proves outer
   add/update/remove delta publication;
3. replays all 17 closed dispositions frozen by
   `graph_corpus_v1::execute_graph_delta_case`, comparing the root-window and
   to-one cases with typed E3/E4 reference forms, including projection-scoped
   emitted operations and reference next-state transitions; and
4. audits outer serving state and the four named probes against the exact
   shipped source. Source assertions are deliberate where the engine has no
   public test-support observation seam; they make those facts drift-detecting
   without introducing a forbidden Stage B runtime hook.

The classification rule is LLP 0309 §D4.2: deployed behavior is presumed
correct; a disagreement is (a) a Stage A reference error, (b) a shipped defect
that receives a fix-forward ticket, or (c) an intentional conservative
approximation recorded only for the shipped lane. The runner fails on harness
errors or an unclassified final row, not merely because a classified
disagreement exists.

## Named probe classifications

### Unfiltered `retained_row_patch` wire diff — class (b)

This candidate is confirmed. `retained_row_patch` unions every old/current row
key and includes every changed value (`graph_evaluator.rs:3588-3620`). That
unfiltered object becomes `LiveGraphDeltaWireOpV1.row` at `:3849-3867`.
`try_graph_delta_fanout` copies `delta.ops` into `LiveGraphDeltaWireV1` without
projection filtering and serializes the envelope
(`engine.rs:34618-34648`). Therefore an unprojected application or system field
that changes alongside a projected field reaches the serialized frame. This is
not merely retained evaluator state. Class (b); ticket:
`issues/20260826-graph-delta-projection-custody-leak.md`.

### DK-3 stale `result_count` — class (c)

Successful DK-3 delivery mutates `Query.rows`, applies add/remove row captures,
and advances `Query.version` (`engine.rs:34875-34917`), but never assigns
`result_count`. Consumer census found no post-delta ordinary-lane reader:
`compute_live_delta` receives only `prior_ids`; the unordered/under-limit
classifier consults their length, not `result_count`; later matcher checks use
the maintained rows and point dependencies. Graph capture validation does read
counts, but an ordinary DK-3 capture is not reused as graph retained state.

The field is stale and should not be generalized as chainable state, but it is
dead metadata for the currently admitted DK-3 follow-on path. Class (c), with a
harness gap recorded below so future consumers cannot silently upgrade this
finding.

### `SNAPBACK_GRAPH_EXEC_DISABLED` asymmetry — class (b)

Fresh graph execution checks the environment switch and refuses at
`engine.rs:42323-42344`. `try_graph_delta_fanout` checks delta policy, its
replace latch, authorization, and matched nodes at `:34454-34480`, then invokes
`evaluate_graph_delta_on` at `:34503-34510`; it never checks the switch. Thus an
established subscription can take the incremental path after the switch is
raised. Because the switch is safety-relevant serving policy, reference-form
maintainability does not authorize bypassing it. Class (b); ticket:
`issues/20260826-graph-exec-disabled-established-delta-bypass.md`.

### Authorized add/update versus remove-replace split — class (c)

At `engine.rs:34783-34790`, any remove on an auth-scoped subscription returns
to the full replacement path, while add/update may remain on DK-3. The reference
forms deliberately model semantic transitions, not durable publication
obligations. LLP 0053 §“Negative deltas are obligations; positive deltas are
best-effort” explains the consumer policy: losing a removal can retain forbidden
data indefinitely, while positive data self-heals on a later snapshot. This is
an intentional conservative serving approximation, class (c).

## Harness gaps

Two test-support gaps limited dynamic observation. Per the Stage B commission,
the audit did not add runtime hooks:

1. `evaluate_graph_delta_on` is `pub(crate)` inside `snapback-engine`, while the
   public test support exposes the apply oracle and aggregate graph delivery
   state, not a direct evaluator entrypoint. The audit therefore consumes the
   frozen output of the existing `graph_corpus_v1` executor for all 17 shipped
   cases and independently runs typed E3/E4 mirrors. The outer facts are guarded
   by exact source assertions.
2. Ordinary DK-3 `CapturedReadDependency` state is not publicly inspectable
   after delivery. The runner dynamically proves add/update/remove publication
   and source-asserts rows/version maintenance plus the absence of a
   `result_count` assignment. A future public capture observation should add a
   dynamic count-staleness regression before any consumer begins relying on the
   field.

These are observability gaps, not unclassified semantic divergences. The graph
frozen executor and the live DK-3 outer fixture still exercise the deployed
lanes; no behavior was inferred from the reference evaluator alone.
