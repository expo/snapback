# LLP 1025.003: System programs do not pay receipt custody — withdrawn after runtime audit

**Type:** RFC
**Status:** Withdrawn
**Systems:** Snapback 2 certifier, runner, jobs, timers, operator execution and cost diagnostics
**Author:** Claude Fable 5.1, for Charlie Cheever; runtime audit by Codex GPT-6 Astra
**Date:** 2026-09-12
**Revised:** 2026-09-12 (withdraw the zero-closure/full-scratch deduction after auditing actual allocations, containment and certification authority)
**Related:** [LLP 1025](./1025-digest-final-emission-at-hub-scale.research.md) §3.1 and F2, LLP 1001 §10 and §“Maintained addresses”, LLP 1012, LLP 1016 D1/D5/D6, LLP 1020, `rules/NOT-DOING.md`

## Decision

Do not implement this RFC's zero-closure exemption or subtract the entire
search/maintained closure estimate from system heap. The original premise
“no receipt is built” is false. Jobs, timer targets and operator programs
build receipts internally and validate their containment before discarding
client custody at the return boundary. More decisively, full first images
also live in the authoritative trace. Suppressing the receipt would not
release that row pool.

The user delegated assessment and implementation on 2026-09-12. The bounded
source audit below rejects the proposed accounting change; no code, budgets,
certificate semantics or cost output change in this decision. The original
acceptance explicitly required withdrawal if runtime consumers existed.

## Evidence

Audited the implementation at `8641112030` on 2026-09-12. The relevant facts
are current code behavior, not an inference from a driver method's return type.

Point misses construct receipt absences; eligible public-count misses construct a paired range and primary-ID proof, perform a primary probe, and add constraint evidence to the trace. | Absence custody is allocated and has execution work today, including in system programs. |

`Engine::custody_certificate` in
[`engine/custody.rs`](../snapback2/crates/snapback2-core/src/engine/custody.rs)
is **delivery audience/write** custody repricing. It does not suppress read
receipts or distinguish a receipt-free execution mode. Jobs, timer targets
and ordinary mutations use it because derived delivery writes still execute.

### Classification and certificate consumers

There is no context-bound `certify_system` API at this revision.
[`Generation::certify`](../snapback2/crates/snapback2-core/src/registry.rs)
uses the same `Checker::check_all` for declared programs;
[`jobs::inspect`](../snapback2/crates/snapback2-core/src/jobs.rs)
uses the ordinary checker with the job-chunk fan-out exemption.
[`timers::certify`](../snapback2/crates/snapback2-core/src/timers.rs)
also uses that checker, reserving the timer settlement write.
[`Runtime::execute_operator_at`](../snapback2/crates/snapback2-core/src/registry_operator.rs)
reuses the declared certificate; `certify_operator_program` in
[`registry_jobs.rs`](../snapback2/crates/snapback2-core/src/registry_jobs.rs)
uses generation admission for ad hoc programs.

A job is system-only by kind. A schedule target is refused by
[`writer_timers::refuse_schedule_target`](../snapback2/crates/snapback2/src/writer_timers.rs)
on client routes. But route admission is not a certificate authority type:
targets remain in the core generation's program map, while only bindings
are removed there. The current
[`writer_offline::program`](../snapback2/crates/snapback2/src/writer_offline.rs)
projection filters jobs and internal owner names. The proposed exemption
cannot safely be derived by treating those maps as equivalent. A declared
mutation invoked through `--as system` may also be client-callable; the
command's actor does not change its declaration's certificate. The draft's
client-callable/schedule-target exception is not a current route behavior:
client routes refuse every declared schedule target.

`plan_job` in `registry_jobs.rs` returns full per-chunk certificates, including
their current closure bounds, after delivery-audience repricing. It does not
execute a read body or establish a cheaper runtime allocation.
[`rehearsal.rs`](../snapback2/crates/snapback2/src/rehearsal.rs)
runs the same chunk/operator paths on the snapshot. Its side-effect report
is another meaning of “receipt”; that report's omission of client custody
does not remove the ordinary runner's internal allocations.

## Historical probe and rejected prediction

The original retained 1,000-membership fold probe reported:

| Meter/term | Bytes |
|---|---:|
| Closure | 8,691,704 |
| Maintained-address closure: pool and issuing metadata | 6,151,978 |
| Public count absence evidence | 2,539,726 |
| Heap | 9,922,698 |
| Same pooled estimate charged as search closure scratch | 6,151,978 |

These are the original probe's historical numbers, not a new measurement.
The subtraction `9,922,698 − 6,151,978 = 3,770,720` is arithmetically true
but **not a valid post-change heap prediction**: it removes the surviving
trace pool as well as receipt-specific metadata. No retained-form admission
or approximately 3.60 MiB heap claim follows from this RFC.

The old design also simultaneously proposed closure zero and predicted a
remaining “ordinary retention estimate.” Those are different contracts;
neither was implemented or qualified. Existing 4 MiB closure, 8 MiB heap,
1M-step and 1 MiB-output ceilings remain untouched.

## Narrower work that could be worthwhile later

Avoiding client-only metadata allocation on owner execution is plausible,
but it needs a separately costed implementation. Before any admission
exemption, an implementer must:

1. Separate retained execution/trace memory from receipt-only metadata and
   preserve the intermediate/loop-carried retention guard. Retain actual
   search work, delivery writes and physical constraint checks.
2. Bind any cheaper certificate to an unforgeable system execution context;
   prove that ordinary execution, replay and client program custody cannot
   reuse it. A command flag or `Mutation` kind is not that boundary.
3. Stop constructing the excluded rows/metadata/evidence on that actual
   owner path before deducting their bytes. Distinguish removing a
   receipt-specific public-count proof probe from weakening cap enforcement
   or maintained-row constraints.
4. Run the same maintained/search bodies as client and system, including
   1,000 distinct point reads, missing counts, writes, timer targets, plans
   and rehearsal. Measure retained trace/receipt allocations, preserve
   containment failures, and derive a new price from those facts.

This is a prerequisite outline, not a commissioned implementation or an
alternative admission claim. The digest recipe should proceed on its own
bounded data model and measured certificate, without depending on this
withdrawn optimization. `check --cost` must keep reporting the current
closure bound; printing `n/a` now would conceal real charged work.
