## 1. Finding and evidence

Recommend admitting a uniform plain expiring scan in the **read-only initial
statements of a never-predicting mutation**. No earlier or enclosing effect
may run. This admits the delivered-receipt program without changing its
authorization, expiration, transaction, receipt or resource rules. It does
not promise that a one-row result costs one examined row: the 10,000-message
unswept burst still refuses until enough background sweeping has finished.

Calibration #23's published 0.4.4 refusal is real: `messaging.q:68` declares
expiry; `messaging.q:127` starts `delivered`; `messaging.q:142` substitutes
1,024 unique ordinal probes. The accompanying `run-log.md:63` records the
rewrite. Inputs are in `~/sb4-intent/er-evidence/`; the refusal is copied to
[`published-diagnostic.txt`](../snapback4/experiments/er-expiring-pages/published-diagnostic.txt).
The prototype and experiments start from `f39598de7febb1f3ddea45ae350b79e0bec50104`.
They measure this checkout, not an installed npm tarball.

Orientation: the governing constraint is query/mutation resource disclosure
(LLP 2000.000 §6), uniform mutation reads (LLP 3000.007 §17), and the declined
expiry relaxation (LLP 3000.007 §21.9). LLP 3000.015 §2 supersedes the older
physical-cap interpretation in LLP 3000.013 §11.1. All are in `llp/current/`;
Snapback 1 foundation gates are outside this fence. Builder cards read:
`programs`, `prediction`, `expire`, `bounds`, and `why E_STRUCTURAL_FANOUT`.
If adopted, update those cards and LLP 3000.007 §21.9 together. Hand-off:
the supervisor's two blind reviews; no merge or publication is requested here.

## 2. What the current rule protects

Paths below are relative to `snapback4/`. Admission is in
`crates/snapback4-core/src/engine/admission.rs:88`; it checks **every** scan,
not just loop heads. Other core paths below abbreviate that crate's `src/`.
`ir.rs:632` recursively finds scans in expressions,
filters, helper blocks, shapes and write operands. The page's rule must be
uniform; expiry, words and merges are independently refused. A predicting
page loop additionally needs a complete schema-capped group
(`engine/admission.rs:308`).

| Read shape on an expiring table | Predicting, today | Never predicting, today | Under §3 |
| --- | --- | --- | --- |
| Explicit page loop | Refused | Refused | Server read-only loop admitted; a loop that writes must bind its page first |
| Bound page, including `first(page)` | Refused | Refused | Server read-only prefix admitted |
| Prefix `exists` | Refused | Refused | Same prefix rule, short-circuit at the first live match |
| `count(domain)` | Refused | Refused | Same prefix rule, complete scan or atomic refusal |
| Whole schema-capped group | Refused | Refused | Same server prefix rule; cap does not erase backlog cost |
| Complete unique-key `exists` | Admitted | Admitted | Unchanged |

The 24-case compiler matrix is in `baseline.log` and `qualification.log`.
An uncapped loop without `first` is separately `E_QUARRY_PLACEMENT`; a
schema cap supplies that missing loop bound. `count(page)` counts only that
page, whereas `count(domain)` must finish its domain.

**Examined bounds are real.** `engine/read.rs:852` charges a mutation page's
attempt; `read.rs:929` charges each physical candidate; expiry rejects it
at `read.rs:958` (and earlier image authorization). `first 1` can fetch
10,000 expired candidates before its first live result and needs live
lookahead. `exists` stops at its first live match; `count` must exhaust.
None has a page-sized physical bound. The ceilings stay 8,192 examined and
1,024 written (`meter.rs:25`); private authorization also shares an 8,192-row
physical allowance (`engine/authorized_scan.rs:6`).

**Clock divergence is real but does not alone justify this blanket rule.**
A row `(alice, ordinal=1, expiresAt=1000)` gives an admitted unique-key
prediction `true` at 999 and `false` at 1000; the instrument executes both.
The server judges at its execution clock; this is already ordinary prediction
correction. The dangerous extra case is device-only physical backlog: a
whole held group with expired unswept rows can exhaust the page's ordinary
meter while a swept server succeeds. Known-input `Bound` remains a hard
prediction error (`engine/local.rs:117`); initial admission need not enqueue
it (`snapback4-device/src/device.rs:1031`). Authorization-work exhaustion
has a separate queue path and does not solve ordinary examined exhaustion.
This proposal keeps all new scans server-only. A sync horizon still cannot
prove an absent ordinal; no completeness rule is relaxed.

**Replay is not a reason to forbid the read.** `engine/mod.rs:1005` looks up
the write id before executing the body. Success and failure both persist;
`engine/receipt.rs:29` omits historical results/current rows, including scalar
results, and sanitizes failure detail. Replaying after expiry must not execute
again or return a formerly live value. The experiment fails on the backlog,
sweeps it, replays the same unchanged failure, then succeeds with a fresh id.

**Expiry does not defeat prefix uniformity.** With
`read <- .conversation = viewer`, pinning conversation still decides the
rule. A denied Bob read of Alice's prefix fetches zero candidates with either
zero or 10,000 expired rows; the entire logical meter is identical. Membership
probes use the same fixed logical authorization reservation; an expiring
grant can change their verdict with time, but not make it row-dependent at
one execution time (`engine/read.rs:190`, `engine/read.rs:854`).

**Disclosure is the binding constraint.** Expired rows cannot supply values,
true existence, or contributions to counts (`engine/authorized_point.rs:53`).
The semantic witnesses return `[]`, `false`, `0`, and point `false`. This
does not mean physical expiry work is unobservable: current authorized queries
can be incomplete/refused under their meters. The proposal preserves that
existing snapshot-read resource envelope; it does not permit a mutation to
manufacture a new one using hidden writes.

The concrete counterexample to merely deleting the expiry guard is:

```quarry
mutation attack(): server
  update messages['target'] { conversation: viewer, expiresAt: now - 1 }
  p = first(messages where .conversation = viewer and .ordinal >= 1 and .ordinal <= 1 first 1 by .ordinal)
  require false else STOP
```

Store A has the live, unreadable `target` owned by Alice with ordinal 1;
store B differs only in retained ordinal 2. Bob may update it blindly; the
schema says `update <- allow`. With one examined unit left, A yields
`E_BOUND`, B yields `STOP`; neither page returns a row. The executable
witness bypasses admission deliberately and reproduces this pair on the
current interpreter. Production admission and the prototype refuse it.

LLP 3000.007 §21.9 supplies the other rejected-rule counterexamples: write a
hidden authorization gate on, scan, then turn it off; or write source C
whose maintained B changes a probe through A. Protecting only the explicit
read-rule tables misses the page table and transitive engine writes. Checking
only ordinary statements misses writes inside expressions and repeated
filters. A fixed point over dependencies plus precise execution order is
unnecessary if the whole beginning of the program is effect-free.

## 3. Proposed rule

Keep uniformity, plain-index and no-merge checks. For an expiring scan require
`predicts == "never"` and membership in the longest initial sequence of
top-level statements for which `read_only::statements::<false>` is true.
That existing exhaustive recursive checker (`engine/read_only.rs:6`) follows
every expression, branch, filter and loop, and rejects all row writes and
emits. Local assignments and read-only loops are allowed. An effect anywhere
in a statement ends the prefix **before that entire statement**, even in an
unreachable arm. Nothing after it regains eligibility.

Consequences: `page = ...; for row in page: write ...` works on the server;
`for row in expiringPage: write ...` must introduce that binding. Reads in
write operands bind earlier. An enclosing loop that might write is excluded,
including its first iteration. This intentionally sacrifices precision for a
small proof; no new Quarry annotation or per-table dependency closure exists.
Scan identity must be structural position/object identity, never the mutable
diagnostic site string. Admission still runs at compiler and server/native
invocation boundaries; the web trusts server admission as today.

**Soundness argument.** Before any admitted expiring scan the store equals
the transaction's initial snapshot: no application write, effect or induced
maintain can have occurred. Its prefix verdict and candidates are consequently
those of a read-only program at that same clock. All preceding read results
and subsequent branches retain the existing read/disclosure boundary. A denied
scope is decided before candidate enumeration. Expired candidates still cost
work but cannot produce values. Any cut aborts without partial writes. The
post-read phase can only consume the materialized read result; it cannot
rescan an expiring table after changing a gate or population. Prediction
does not execute this new path. Every resource and receipt rule stays in force.
This is a sufficiency argument for the existing query resource contract,
not a claim of timing noninterference or free expiry traversal.

The calibration's natural read becomes:

```quarry
mutation delivered(conversation: conversations, from: int, through: int): server
  -- Read me/chat and merge receipt intervals into low/high, without deleting.
  -- prefix is max(me.deliveredOrdinal, me.joinedOrdinal).
  if prefix + 1 < low:
    blocker = first(messages where .conversation = conversation and .ordinal > prefix and .ordinal < low first 1 by .ordinal)
    prefix = blocker.ordinal - 1 if blocker != null else low - 1
  -- Delete merged intervals, then update the prefix or insert the new run.
```

This excerpt names already-bound locals; the complete compiled program is
[`delivered.q`](../snapback4/experiments/er-expiring-pages/delivered.q).
It moves interval deletion into a second capped loop. The first live message
is the undelivered blocker; absent/expired ordinals before it may be skipped.
Finding an absent message is not evidence that a live message was delivered.
The existing interval/last-ordinal guards remain.

`exists messages where .conversation = conversation and .ordinal > prefix`
and `count(messages where .conversation = conversation)` use the same rule.
They bind before writes and either finish or refuse; an unfinished scalar
never becomes false or a partial total (`engine/read.rs:741`, `read.rs:773`).
Unique point probes and rule-language probes keep their separate semantics.
In particular, a rule's exact-index witness pays a fixed logical probe charge
but may spend the shared physical authorization allowance finding a live
witness; it is not the program's top-1 prefix scan. A maintained count read
also retains its existing live-recount and authority rules; this proposal
does not make stored, expiry-inclusive totals valid.

The existing platform ceiling is the declared examined ceiling; do not add
per-operation budget syntax or raise it. `E_BOUND` currently is **not** marked
retryable. A definitively failed write can be retried as a **new intent** after
maintenance, while an uncertain network outcome retries the same id. Generic
authorization `E_RULE` cannot be relabeled “expiry backlog”: that would reveal
which hidden authorization work ran. A new automatically retryable code is
outside this recommendation.

## 4. Options and counterexamples

| Option | Verdict, counterexample, builder form, cost on server/device |
| --- | --- |
| (a) Existing `cap K by conversation` | **Insufficient.** The live cap 4 admits three waves leaving 12 physical rows with no sweep; `engine/write.rs:475` recounts live occupants once physical occupancy reaches the cap. A new explicitly physical cap could bound unswept work, but would block inserts when all K occupants are expired. Even that bound alone leaks near an already-spent meter: 0 versus K expired rows can choose success versus abort. A sound stronger design must reserve all relevant worst-case work before lookup, including physical authorization work, without refunding by population. Builder adds a new storage-occupancy limit; inserts may await GC. It is viable in principle on server and on a device with a proved occupancy/coverage bound, but current expiring-cap writes queue (`write.rs:494`), and local occupancy is not server occupancy. Do not silently redefine `cap`. |
| (b) Sweep encountered expired rows in the transaction | **Insufficient.** Ten thousand deletes exceed the 1,024-write ceiling; rollback restores the backlog, so retry makes no progress. Unmetered deletion weakens the meter; independently committing it breaks atomicity and adds observable stream/maintain/asset work. Builder's unchanged scan cannot hide these costs. Server background sweep already provides separate bounded commits. A device cannot perform authoritative GC for the server or other replicas. |
| (c) Uniform server page with a runtime ceiling | **Recommend only with §3's read-only prefix and existing failure semantics.** Without it, `attack` and the hidden-gate program disclose private state through refusal. Prefix-only reads prevent both; no new user budget declaration is needed. Builder writes `: server` and binds reads before effects. Server work stays O(expired backlog + live candidates); normal device admission queues without executing the body. A backlog can refuse and needs maintenance, not automatic same-id retry. |
| (d) Expiry-aware ordinal access plan | **Sound direction if fully bounded, not the smallest change.** `(conversation, ordinal, expiresAt)` still walks expired ordinals; `(conversation, expiresAt, ordinal)` loses ordinal order: live ordinal 1 expiring tomorrow and ordinal 2 expiring today make expiry-first `first 1` choose 2 incorrectly. A time-based partial/live index becomes stale without writes at deadlines. A possible new plan is a fixed-depth integer-key trie with subtree maximum expiry (null means infinity), seeking only subtrees that can contain live rows. Charge a proved, population-independent upper bound on summary traversal, including misses; merely moving hidden-dependent work to the index-entry meter repeats the oracle. It needs transactional summary updates, null/overflow/deletion rules and adapters/qualification on both device and server. Builder could keep the same ordinal scan, with an index declaration or inferred plan; physical metadata and write/index work grow. No measured performance or shipping claim for this unbuilt index. |
| Skip expired rows without charging | **Rejected.** Ten million expired rows followed by one live row make a “one-row” operation unbounded. Filtering in SQL does not make those examined entries free. |
| Read a query page and pass ids as proof of absence | **Rejected for this invariant.** A truncated device horizon, incomplete query, untrusted caller, or changed membership can omit a live blocker. Selected ids are adequate only when the mutation's contract is to act on those particular reauthorized ids; they do not prove a whole ordinal gap. |
| Permit prediction because the group is capped | **Rejected here.** Expired server occupancy and held device occupancy can differ; known-input examined exhaustion can prevent initial enqueue. A small output or live cap proves neither equal work nor complete acquisition. Queue this operation; do not weaken prediction or meter semantics. |

## 5. Measurements and prototype

Reproduce using the command in
[`experiments/er-expiring-pages/README.md`](../snapback4/experiments/er-expiring-pages/README.md).
One conversation has 10,000 160-character messages expiring at time 1000;
reads run at 2000, with two live messages at ordinals 10001/10002 for
lookahead. No sweeper runs during measurement. Smaller controls have 0 or
1,000 expired rows. Rust 1.97, test profile opt-level 1, eight build jobs,
SQLite in memory and the core memory adapter, 31 warm same-process samples.
Initialization and row construction are outside timing; wrapper instrumentation
counts actual fetched images separately from logical examined charges.
These are interpreter times, not HTTP/device UI or disk-durability latencies.

| SQLite operation, 10,000 expired rows | Fetched images | Examined charge | Median / p95 |
| --- | ---: | ---: | ---: |
| Page `first 1` | 8,192 | 8,193, then E_BOUND | 37.43 / 38.10 ms |
| Prefix `exists` | 8,192 | 8,193, then E_BOUND | 39.03 / 39.63 ms |
| Whole-domain `count` | 8,192 | 8,193, then E_BOUND | 38.10 / 38.31 ms |
| One expired unique-key `exists` | 1 | 1; false | 0.005 / 0.011 ms |
| Builder's 1,024 unique probes | 1,024 | 1,024; advances 1,024 | 5.26 / 5.28 ms |

The charged failed attempt exceeds the ceiling; it is not an extra fetched
row. At a lower examined ceiling of 4,096, the page fetches 4,096 and refuses
in 18.55 / 18.78 ms. With 1,000 expired rows, the page succeeds after 1,002
fetches and 1,003 examined charges, 4.24 / 4.29 ms. The memory adapter's
10,000-backlog page also refuses after 8,192 fetches, 21.28 / 22.44 ms.
Same row counts and all seven meter fields are in `measurements.json`.

The real engine sweeper removes 10,000 rows in ten calls of at most 1,024,
101.06 ms total in this unspecialized fixture; 1,000 takes 10.34 ms. This is
one sweep timing per fixture, not a percentile, and includes index/partition
maintenance. No assets, maintained aggregates, membership audience, network
delivery or disk fsync are in this fixture. Group audience fanout and other
maintenance would add work. The post-sweep natural mutation examines 3 and
writes one acknowledgement. Under a membership rule, the full calibration
rewrite advances over 1,000 expired messages to receipt ordinal 1002,
examining 1,006 rows, 9 rule probes and one write.

The branch-only admission prototype changes two source files, adding a body
scan collector and the conservative prefix test. It leaves meters, store,
clock, receipts, rules, versions and budgets unchanged. Seven opt-in research
tests pass: the matrix/live-cap witness, backlog instrument, natural mutation
and replay, effect/IR guards, retained-ordinal oracle, semantic/clock/denied
pair, and compiled calibration rewrite. Normal `local::predict` makes zero
data fetches for the new server operation on both row stores. This is not an
end-to-end device outbox or browser qualification. Product diagnostics/cards
and existing blanket-refusal expectations are deliberately not rewritten by
this research prototype. It is **not release-ready**.

Existing checks: guide 86/86 and prefix reads 10/10 pass. Simulator
`page_admission` is 13/15: `w2_hidden_word_expansion_and_expired_populations_are_refused_at_check`
fails on its now-admitted bound expiring page, and
`w14b_expiry_rewrite_names_query_and_job_doors` expects that removed refusal.
These are deliberate policy conflicts, not green qualification. The remaining
denied-prefix, expiring-witness and word/merge checks pass. Reference audit:
518 LLP documents, 9,619 references, zero errors/unchecked. No full suite ran.

## 6. Diagnostic drafts

Each site message plus its single rewrite is at most 60 words. The general
fanout taxonomy, counterexamples, admission boundaries and cost explanation
belong in `why E_STRUCTURAL_FANOUT`, not every refusal.

- **Expiring table, predicting `delivered`:** “E_STRUCTURAL_FANOUT: delivered
  reads expiring messages by byConversationOrdinal, first 1, but may predict.
  Expired unswept rows can exceed the device's examined budget. Make delivered
  `: server` and bind this page before its first write; then apply the receipt
  changes.”
- **Matching:** “E_STRUCTURAL_FANOUT: markFound uses matching on messages by
  byTextWords inside a mutation. Word discovery has no admitted mutation work
  bound. Read this search page in a query and pass its selected ids to
  markFound, which rechecks each target before writing.”
- **Merge:** “E_STRUCTURAL_FANOUT: markShown merges multiple message prefixes
  inside a mutation; this is not one admitted plain prefix. Read the merged
  page in a query and pass its selected ids to markShown, which rechecks each
  target before writing.”

For an already-server expiry site after effects, substitute the actual
preceding effect: “delivered scans expiring messages after deleting runs.
Bind this page before the first write, then perform the deletions and updates.”
This wording must name the actual scan and statement, not infer a user's
invariant from a table name. Selected-id rewrites are inappropriate for
constraint/absence checks; keep their existing constraint-specific diagnostic.

## 7. Open questions for review

1. Does the read-only-prefix argument preserve the existing query resource
   disclosure contract across every admitted IR form and engine-induced read
   behavior? Review the recursive effect and scan walkers independently;
   specifically try the prior gate, page-table and transitive-maintain attacks.
2. Is coarse statement-prefix admission an acceptable first product rule,
   including two read/write loops for interval merging and binding outside a
   row-writing loop? It avoids the previously rejected precise effect analysis.
3. Is eventual success after the existing sweeper enough for this receipt path?
   If 10,000-row unswept success is required, commission option (d) separately;
   this proposal does not meet that stronger availability target.
4. Should a future explicit new-intent retry policy be added for E_BOUND?
   Its receipt identity and generic authorization failure must remain intact;
   this research does not change retryability.
5. Before building: qualify memory/native outbox admission, reopen, generation
   changes and serialized filters; update the affected existing refusal tests
   and builder cards; measure any web artifact delta under its unchanged budget.
