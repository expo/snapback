# LLP 3000.020: An unread count the device can certify

**Type:** RFC
**Status:** Draft
**Systems:** Snapback 4 — row-keyed views (LLP 3000.015 §3), device coverage (LLP 3000.016), the local client's server fallback, the scale certificate, `check`, the `maintains` and `expire` guide cards
**Author:** Claude Opus 5.5 (for Charlie Cheever)
**Date:** 2026-09-26
**Revised:** 2026-09-26 (revision 1: the device certifies the unread range from its window over the existing indexes; the server keeps LLP 3000.015's exact live basis; a range below the floor publishes a current-row lower bound and asks the server; after both families' NOT READY on revision 0); 2026-09-26 (revision 0)
**Related:** [LLP 3000.019](./3000.019-what-the-builder-still-wrote.rfc.md) (P5, "expiry on the device"), [LLP 3000.015](./3000.015-shared-baseline-for-snapback5.spec.md) §2–§3 (row-keyed views, the live basis, private-walk accounting), [LLP 3000.016](./3000.016-following-on-a-bounded-device.rfc.md) (acquired boundaries), [LLP 3000.013](./3000.013-quarry-states-intent.rfc.md) §14.4 (the certificate's classes), `issues/20260925-snapback4-remembered-answer-row-expiry.md`

## 1. Why

Calibration #21 charged two categories for the same gap:

- `queries_and_live` (88): "an offline coverage limitation for expiry-aware
  unread aggregates";
- `offline_sync` (91): unread badges "unavailable after a cold reload".

The builder wrote the badge as an ordinary aggregate over disappearing messages
and then duplicated its `inbox` query without counts. `main` now carries LLP
3000.015's row-keyed views, the paved unread badge (`guide maintains`, "A value
per member: Clique unread"):

```quarry
view unread: count messages by members m
  where .conversationId = m.conversationId and .ordinal > m.readUpTo
    and .senderId != m.principal and not .tombstone
```

Over an expiring source, as Clique's disappearing messages are:

- **The device counts only a whole conversation.** `device_live_count` passes
  unbounded bounds to `covered_view_source` (`engine/row_views.rs`), so a
  windowed source (`last 500 by .ordinal`) certifies only when its acquired
  boundary is `Whole`. Before that, `row_view_source_readable` requires the
  same unbounded coverage for a non-public source. Otherwise the badge reads
  `value: 0, recountPending: true`, `complete: false`. It records no unknown
  fact, so the client publishes it and never asks the server, offline or
  online.
- **The certificate misdescribes the server's read.** For a maintained value
  over an expiring source, the scale certificate prints "constant aggregate
  lookup plus unswept expired contributions" and adds the examined ceiling to
  the allowance (`scale.rs`). That describes ordinary aggregates. A row-keyed
  read certifies its whole live basis on the internal ledger, skips expired
  rows, charges one examined unit and one step, and meters no more of the walk
  (LLP 3000.015 §3, by design).

## 2. The observation

The unread predicate bounds the count from below: `.ordinal > m.readUpTo`.
Every counted row is newer than the member's watermark, so it lies in the
newest part of the conversation. A window `last N by .ordinal` holds exactly
that part. The device already builds an index on `(conversationId, ordinal,
id)` for this comparison (`maintain/row_key.rs`, `prepare_row_views`). If it
scanned only the range above the watermark, it could certify the badge whenever
its window holds the whole range. For a badge, that is almost always.

## 3. Proposal

The server does not change. It keeps LLP 3000.015's exact live-basis
certification, so counts stay exact and no writer starts failing. Everything
below is the device's read and prediction, the client's fallback, the
certificate, `check` and the guide.

### 3.1 The range

A row-keyed view's predicate is a conjunction (LLP 3000.015 §3).

- **Normalizing.** Before choosing, each conjunct comparing a source column
  `c` with a member field `f` is written with the source column first, so
  `m.readUpTo < .ordinal` is `.ordinal > m.readUpTo`. Only a lower bound on
  the source column, `.c > m.f` or `.c >= m.f`, is a candidate. An upper bound
  is not: a `last N` window holds the high suffix of the group.
- **Choosing.** The **range** is the candidate on the source's sync horizon
  order column: the first column after the horizon's audience prefix. With
  several on that column (`.ordinal > m.readUpTo and .ordinal > m.joinedAt`),
  each read scans from the greatest bound among them. A view with no candidate
  on that column has no range, and its device read keeps today's whole-group
  rule.
- **Null.** A null member operand in a read disables the range for that read.
  The conjunct stays an ordinary per-row test under Quarry's ordering, where
  null sorts below every value, and the read falls back to the whole-group rule.
- **Execution.** Every conjunct, including the chosen one, is still evaluated
  per row: own sends, tombstones and expiry keep their meaning. The scan uses
  the existing `(source_key, c, id)` index. There is no new index, and no
  adoption step unless an index definition changes.
- **`check`.** Prints the chosen range, its index, its operator and the
  horizon it certifies against, in the text and in the JSON `rowViews` object.

### 3.2 When the device certifies

The device certifies a range read exactly when all of the following hold. This
is the proof `covered_view_source` makes for a bounded scan, with one
requirement added:

- The source's current, completed acquisition covers the member's group, and
  the group is not retained history (`retained_group`).
- **The acquired boundary's group equals the scan's parent prefix.** A public
  window's empty group never certifies a parent's range: its floor is the
  newest rows of the whole table, not of this conversation.
- The horizon column after that prefix is the range column.
- The range's **encoded** lower bound, with `>` and `>=` encoded as
  `Bounds::gt`/`gte` do, is at or above the acquired full-key floor. A `>=` at
  the floor's own ordinal stays pending when a smaller id at that ordinal was
  not acquired. That is fail-closed.
- The scan finishes within the read's examined allowance.

A `Whole` boundary certifies any range. The floor is stored with the replica,
so certification holds offline and after a cold reload. The floor is fixed at
acquisition: a later expiry or deletion of the floor row neither moves nor
rebuilds it.

**Authority first, completeness second.** `row_view_source_readable` today
demands unbounded coverage for a non-public source before any count. It splits
in two:

- the current readability of the member's source group (the member row, the
  admitted audience implication), which stays as is;
- range completeness, which is the proof above.

**Prediction.** A device writer's prediction uses the same plan: the same
range, the same proof. Where it is not covered, it queues without a predicted
result, as today. Durable recount cursors, which record expiry-index positions,
are not touched.

### 3.3 When it cannot: a lower bound, and the server

When the proof fails (the watermark is below the floor, the boundary is
missing, or the group is retained), the count is pending. Its value becomes a
**lower bound**: the rows the device examined that are current (not retained
history), authorized, live and satisfying the whole predicate. The device
already holds every counted row, so this discloses nothing a `0` hid from the
member. Provisional rows and a predicted watermark carry the replica's usual
optimistic provenance. The bound is relative to the evaluated replica, not a
promise about the server. A badge shows it as `L+`.

The read also records an **unknown fact** for the range, as a horizon miss
does. So an online client asks the server, whose exact count replaces the lower
bound (`local-query.ts` already does this for unknown facts). Offline, the
lower bound stays. A covered scan that stops at the read's examined ceiling is
different: it is a known incomplete count. It publishes its partial as the
value, not `0`, and records no unknown fact, as a meter cut does today.

A pending value is a lower bound only for an expiring source's range read. A
non-expiring view's pending value is its last settled count, which is not a
lower bound after a watermark moves, and it keeps today's meaning.

### 3.4 The certificate says what a row-keyed read costs

For a row-keyed view over an expiring source, the certificate stops printing
the ordinary aggregate's sentence. It stops adding the examined ceiling for a
walk the meter does not charge. It substitutes the view's actual fields:

- **With a range.** `server: certifies the member's whole live basis on the
  internal ledger (unswept expired rows skipped), charging one examined unit
  and one step; the walk itself is not metered. device: exact when its window
  holds every row with .ordinal > m.readUpTo (the acquired floor key on this
  conversation's prefix is at or below that bound); otherwise the current rows
  it holds, pending, and online the server's count.` Class `grows`: the
  member's live group is data, not a cleanup backlog.
- **Without a range.** The same server sentence, and `device: exact only when
  it holds the whole group; otherwise pending.` Class `grows`.
- **A pure existence witness.** "Reads the member's indexed existence and
  lifetime; does not certify the count." Class `constant` for this lookup.
- **A non-expiring source.** Keeps its stored value and its current sentence.

### 3.5 The guide

- **`guide maintains`, "A value per member".** A complete example that
  compiles with no diagnostic:
  - messages `ordinal: sequence by conversationId`;
  - a membership read rule;
  - `sync to members[.conversationId] last 500 by .ordinal` on messages;
  - synced members;
  - an expiring message (`expiresAt: time ?`, `expire at .expiresAt`) whose
    time the send sets from the conversation's timer;
  - the view.

  The surrounding text says what the device certifies from that window, what a
  badge shows when the range is longer (`L+`, then the server's count online),
  and that the server certifies the whole live basis. Its "certify the whole
  live group" paragraphs are updated to match.
- **`guide expire`** and **`guide why E_QUARRY_MAINTAIN_EXPIRE`**. Both say "A
  meter cut returns the contribution examined so far, also incomplete". That
  contradicts `guide maintains` and the engine: a cut ordinary aggregate is
  `data: null, complete: false`. Split the two results: an ordinary aggregate
  cut is null, and a row-keyed range read is the pending row with its lower
  bound.

## 4. What it costs

- **No new index**, and no store migration unless an index definition changes.
- **Device work per badge.** The unread range plus its own sends and
  tombstones, instead of the whole group. The count needs no more work than
  that.
- **Behavior:**
  - A covered badge is exact offline and after a cold reload, where it read
    `0`, pending.
  - An uncovered one reads its lower bound, and online the server's count.
- **The server does not change.** Its unmetered live-basis walk remains a scale
  hole for a member whose watermark is far below the conversation's end (a
  never-opened 100,000-message chat), now stated in the certificate. Bounding
  it is a separate accounting change. It would charge the ordinary examined
  meter and return a lower bound. It would never use the request's private-walk
  allowance, whose remainder hidden rows move (both families, revision 0).

## 5. Not in this RFC

- **Remembered answers' deadlines**
  (`issues/20260925-snapback4-remembered-answer-row-expiry.md`). One expiring
  row withdraws a whole remembered server answer offline. Telling
  authorization deadlines from row-expiry deadlines needs per-row expiry in the
  answer contract.
- **Optional fields.** One withheld field still withholds a shaped row. Once
  the unread field is certified in the common case, the builder has no reason
  to split `inbox`.
- **Bounding the server's walk** (§4).

## 6. Evidence to require

All device cases run on the wasm device and the native device, memory and
SQLite.

- **Certifies.** A covered range is exact online, offline, and after a cold
  reload offline. An expiring row inside it drops out at its deadline offline.
  Own sends, tombstones, physical deletion and expiry are counted as the server
  counts them.
- **Boundaries.**
  - `>` and `>=` with ties at the floor ordinal, including an unheld smaller
    id;
  - a null watermark;
  - an empty `Whole` group;
  - a window ordered by `.at` or by a composite order that must not certify an
    ordinal range;
  - a public window that must not certify a parent range;
  - two conjuncts on `ordinal`;
  - `m.readUpTo < .ordinal` certifying as `.ordinal > m.readUpTo` does;
  - an upper bound that is not a range;
  - a null operand that does not fall through to another conjunct;
  - a watermark that moves backward below the floor.
- **Replica state.**
  - interrupted acquisition;
  - cold reopen;
  - delivered-history leave and rejoin, whose retained rows are never counted;
  - expiry or deletion of the floor row;
  - later backdated delivery.
- **Lower bound and fallback.**
  - Uncovered, the read publishes the current-row lower bound and records an
    unknown fact.
  - Online, the server's exact count replaces it; offline, it stays.
  - A covered scan cut by the examined ceiling publishes its partial and asks
    nothing.
  - A non-expiring pending value is unchanged.
- **Prediction.** Covered, a predicted count uses the range. Uncovered, it
  queues without a result. The same happens for an empty selected range.
- **Authority.** A non-public source whose member can read the group certifies
  from its window. One whose member cannot stays pending.
- **Certificate and `check`.** The sentences of §3.4, and `grows`, on the
  guide's program. The range, index and horizon appear in `check`'s text and
  JSON. A non-expiring view is unchanged.
- **Guide.** The example compiles with no note, and its device test passes.
- **Mutants.** Each must fail a test:
  - a scan that ignores the range;
  - coverage that ignores the floor, or the parent prefix;
  - `>=` read as `>` at the bound;
  - a lower bound that counts retained rows;
  - a pending value of `0`;
  - an uncovered read that records no unknown fact;
  - an upper bound treated as a range.
