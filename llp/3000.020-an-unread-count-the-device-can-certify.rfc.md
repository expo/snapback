## 1. Why

Calibration #21 charged two categories for the same gap:

- `queries_and_live` (88): "an offline coverage limitation for expiry-aware
  unread aggregates".
- `offline_sync` (91): unread badges "unavailable after a cold reload".

The builder wrote the badge as an ordinary aggregate over disappearing messages
and then duplicated its `inbox` query without counts. `main` now carries LLP
3000.015's row-keyed views, the paved unread badge (`guide maintains`, "A value
per member: Clique unread"):

```quarry
view unread: count messages by members m
  where .conversationId = m.conversationId and .ordinal > m.readUpTo
    and .senderId != m.principal and not .tombstone
```

Over an expiring source, as Clique's disappearing messages are:

- **The device counts only a whole conversation.** Two checks refuse first:
  `row_view_source_readable`'s device branch, and `device_live_count`. Both call
  `covered_view_source` (`engine/row_views.rs`) with unbounded bounds, so a
  windowed source (`last 500 by .ordinal`) certifies only when its acquired
  boundary is `Whole`. Otherwise the badge reads `value: 0,
  recountPending: true`, `complete: false`. It records no unknown fact, so that
  count alone never sends the client to the server, offline or online.
- **The certificate misdescribes the server's read.** For a maintained value
  over an expiring source, the scale certificate prints "constant aggregate
  lookup plus unswept expired contributions" and adds the examined ceiling to
  the allowance (`scale.rs`). That describes ordinary aggregates. A row-keyed
  read certifies the member's whole live basis on the internal ledger through
  the parent/expiry index. It skips expired rows, reserves one examined unit
  and one step, and does not meter the walk (LLP 3000.015 §3, by design). It
  walks a 100,000-row live group even for a member with one unread message.

## 2. The observation

The unread predicate bounds the count from below: `.ordinal > m.readUpTo`.
Every counted row is newer than the member's watermark. A window `last N by
.ordinal` holds the newest rows of each conversation, from an acquired floor
up. The device already builds an index on `(conversationId, ordinal, id)` for
this comparison (`maintain/row_key.rs`, `prepare_row_views`). When the window
holds the whole range above the watermark, the device can count that range and
certify the badge. It can do so offline and after a cold reload, whatever lies
below the floor. When the watermark is below the floor, it cannot, and says so.

## 3. Proposal

The server does not change: not its certification, its accounting, its recount
cursors, or the private-walk allowance. Counts stay exact there, and no writer
starts failing. Everything below is the device's read and prediction, the
client's fallback, the certificate, `check` and the guide.

### 3.1 The selector

A row-keyed view's predicate is a conjunction (LLP 3000.015 §3). One plan,
shared by the device read, device prediction, the certificate and `check`,
chooses how a read scans. It never uses the unused `RowKey::live_range`.

- **Normalize.** Each conjunct comparing a source column with a member field is
  written with the source column first, so `m.readUpTo < .ordinal` is
  `.ordinal > m.readUpTo`. Only a lower bound on the source column, `.c > m.f`
  or `.c >= m.f`, is a **candidate**. An upper bound stays a per-row test: a
  `last N` window holds the high suffix of a group.
- **The horizon column.** The source's sync horizon has an audience prefix and
  then its first free column. Only candidates on that column are range
  candidates. A view with none on it keeps today's whole-group rule.
- **Per read, the greatest bound.** Among the range candidates, the read scans
  from the greatest encoded lower endpoint, `scan_range` of the member's
  values. `>` and `>=` encode as `Bounds::gt` and `Bounds::gte` do. A null
  operand is the weakest bound (`> null` holds for every value), so it never
  disables a sibling. Only when every range candidate's operand is null does
  the read take the whole-group rule. A null never falls through to another
  column.
- **Residual tests.** Every conjunct, including the chosen one, is still
  evaluated per row. Own sends, tombstones and expiry keep their meaning.
- **The index.** The scan uses the existing `$view:{sourceKey}:{column}` index.
  There is no new index, and no adoption step unless a definition changes.

### 3.2 When the device certifies

- **A `Whole` boundary keeps today's path.** The live-basis scan of the
  parent/expiry index reaches live rows directly, past any expired backlog.
- **A range read** is exact when all of these hold:
  - **Authority.** The member can read the source group by the static audience
    implication: `prefix_visibility(...).uniform` with the parent pinned,
    as `covered_view_source` already computes. On the device, an expiring
    range read uses this in place of `row_view_source_readable`'s unbounded
    coverage call. A non-uniform rule still fails closed. The server branch
    and every non-expiring read keep the check they have.
  - **The acquisition covers the range.** The source's current, completed
    acquisition covers the member's group, and the group is not retained
    history (`retained_group`).
  - **The boundary is this conversation's.** The acquired boundary's group
    equals the scan's parent prefix. A public `Key` floor never certifies a
    parent's range, since it bounds the whole table. A public `Whole`
    boundary covers every parent.
  - **Same column.** The horizon column after that prefix is the range column.
  - **The encoded floor comparison.** The range's encoded lower endpoint is at
    or above the acquired full-key floor. That comparison is the rule. A `>=`
    at the floor's own value can be a false pending, and that is fail-closed.
    `>` excludes every tie there, so the unread card's `>` certifies at the
    floor.
  - **The scan finishes** within the read's allowances (`scan_room`: examined,
    steps; and heap).
- **The floor persists.** It is stored with the replica, so a certification
  holds offline and after a cold reload. It is fixed at acquisition: a later
  expiry or deletion of the floor row neither moves nor rebuilds it. A
  watermark that moves backward is checked again.

**The candidate path.** The range scan is not `view_scan` unchanged:

- An expired image in the range makes `authorize_image` return nothing, and
  `view_scan` turns that into a prediction error. The range path instead steps
  past expired images and retained-only images (`current_row` false), and
  examines them as it goes.
- It counts only current, authorized, live rows that satisfy the whole
  predicate.
- A row whose authority is unresolved keeps the read uncertain. It is never
  counted by possession.
- The deadline of every counted contribution is noted, including one counted
  into a lower bound, so the count drops a row at its expiry offline.
- Unswept expired rows cost device work on this path and can leave a count
  pending. The certificate says so.

**Sequence selection.** An ordinary scan records its dependence on provisional
sequence values (`observe_sequence_selection`, `read.rs`). The range read does
the same before it scans, including when the selected range is empty. A
mutation that refuses on the count then queues for the server's judgment
through the existing dependent-refusal conversion (`local.rs`). A mutation that
succeeds still predicts. The sender's own badge often matches nothing while
their provisional ordinal sits in the index.

**Prediction.** A device writer predicts from the same plan:

- A covered range that finishes within the writer recount bound
  (`WRITER_RECOUNT`, 1,024) predicts.
- An uncovered range, or one over that bound, queues without a predicted
  result, as today. It never stores a lower bound.
- A member whose watermark lies below the floor keeps a send unpredictable.
  That is today's fan-out rule.
- Durable recount cursors, which record expiry-index positions, are not
  touched.

### 3.3 When it cannot: a lower bound, and the server

When the proof fails, because the watermark is below the floor, the boundary is
missing, or the group is retained, the count is pending:

- **Value.** A lower bound `L`: the rows examined that are current, authorized,
  live and satisfying the whole predicate. Every counted row is already on the
  device, so `L` tells the member nothing a `0` hid except that number. It is
  a bound on the evaluated replica, not on the server; an unsynced deletion can
  make it high.
- **Provenance.** Provisional rows and a predicted watermark carry the
  replica's optimistic provenance. That provenance is not the `speculative`
  bit.
- **Flags.** `recountPending: true` and `complete: false` (`timeline_pending`),
  and an **unknown fact**, not speculative. An online client then asks the
  server whenever its existing fallback fences permit: an unobserved predicted
  write, or a `held` query, still blocks replacement. The server's exact count
  replaces `L`. Offline, `L` stays, and a badge shows `L+`. Marking it
  speculative would make offline recovery drop the row.

**A covered scan cut by its allowance** is a known incomplete count. The value
is the partial `L`, with `recountPending`, `complete: false`, no unknown fact
and not speculative. The client keeps it and does not ask, as for a meter cut
today.

**Both pending results** still refuse what refuses today:

- A pending value never satisfies a `value` probe (`witness.rs`).
- On `Cut::Abort`, `pending_view_read` still queues a device writer and refuses
  a server writer.

**Outside the lower bound.**

- **No range**, or every range operand null, keeps today's whole-group result:
  `0`, pending, no unknown fact. Extending the lower bound there is not in
  this RFC.
- **A non-expiring view's** pending value stays its last settled count, which
  is not a lower bound after a watermark moves.

### 3.4 The certificate

For a row-keyed view over an expiring source, the certificate stops printing
the ordinary aggregate's sentence and stops adding the examined ceiling for a
walk the meter does not charge. It substitutes the view's own column, operator
and member fields, and never hardcodes `readUpTo`. It adds no backlog site for
expired rows on the server path, since the server does not visit them. The
operation's class stays the worst of its sites.

**The server sentence, for every expiring count read:** "Server: certifies the
member's whole live basis on the internal ledger through the parent/expiry
index (null expiry and expiry after now; unswept expired rows are not visited),
reserving one examined unit and one step; the walk is not metered and does not
use the private-walk allowance. Member lookup, authorization and the result
cost more."

| Case | Device sentence | Class |
|---|---|---|
| A range on `.c` (`>` or `>=` `m.f`) | "Device: scans rows with `.c > m.f` (the greatest such bound when several apply), applying every other test. Exact when the member's source group is readable by its audience, the acquired boundary is this parent prefix's, the horizon's first free column is `.c`, the encoded bound is at or above the full floor key, and the scan finishes. Otherwise the current held matches, pending and incomplete, and an online client takes the server's count when permitted. A scan cut by its allowance publishes its partial and does not ask. Unswept expired rows in the range cost device work." | `grows` |
| Every range operand null, or no candidate on the horizon column | "Device: exact only with whole-group coverage and a completed live-basis scan; otherwise `0`, pending, and the client does not ask." | `grows` |
| A metadata-only existence witness (`row_view_member_exists`) | "Reads the member's indexed existence and lifetime; does not certify the count." | `constant` for this lookup |
| An expression-level `exists`, or a probe that constrains `value` | The count sentences above. | `grows` |
| A non-expiring source | The stored value. "An unfinished recount remains pending; a pending last-settled value is not a lower bound." | `constant` for this lookup |

### 3.5 `check`

The row-view line and the JSON `rowViews` object gain the plan:

- the range candidates, by column, operator and member field;
- the greatest-bound rule;
- the index (`$view:{sourceKey}:{column}`) and the horizon index;
- the fallback;
- or `null` when there is no range.

### 3.6 The guide

**`guide maintains`, "A value per member".** A complete example that compiles
with no diagnostic:

- messages carry:
  - `ordinal: sequence by conversationId`;
  - `read <- exists members[.conversationId, viewer]`;
  - `sync to members[.conversationId] last 500 by .ordinal`;
  - an expiry field (`expiresAt: time ?`) with an index whose first column is
    that field, and `expire at .expiresAt`, set by the send from the
    conversation's timer;
- members carry a sync line, since the view takes the member table's sync;
- the view.

The text says what the device certifies from that window: the unread range
inside it, exactly. It says what a badge shows when the range is longer: `L+`,
then the server's count online. It says that the server certifies the whole
live basis. The "certify the whole live group" paragraphs are updated to match,
and the stale "until `sequence by` is available" sentence goes.

**The meter-cut sentence.** "A meter cut returns the contribution examined so
far, also incomplete" appears in `guide expire` (`guide.rs`), in
`why/E_QUARRY_MAINTAIN_EXPIRE.md` and in `why/E_QUARRY_LIVE_MAINTAIN_PROBE.md`.
Replace that sentence in each: a cut ordinary aggregate is `data: null,
complete: false`. An expiring row-keyed range read that stops is the pending
row `{ value: L, recountPending: true }` with `complete: false`. Qualify their
generic "maintained view" server-cost paragraphs as ordinary aggregates.

## 4. What it costs

- **No new index**, and no store migration unless an index definition changes.
  A populated store reopened or adopted keeps the entries.
- **Device work per covered badge:**
  - the range above the watermark;
  - its own sends and tombstones;
  - any unswept expired rows in it.
- **Behavior.**
  - A covered badge is exact offline and after a cold reload, where it read
    `0`, pending.
  - An uncovered one reads `L+`, and the server's count online.
- **Not guaranteed.** Exact counts for a watermark below the floor are not
  available from the window. That needs certified aggregate information, which
  is a later RFC.
- **The server's unmetered live-basis walk remains a scale hole**, now stated
  in the certificate. Bounding it is a separate change. It would charge the
  ordinary examined meter and return a lower bound. It would never use the
  request's private-walk allowance, whose remainder hidden rows move.

## 6. Evidence to require

All device cases run on the wasm device and the native device, memory and
SQLite.

- **Certifies.**
  - A covered range is exact online, offline, and after a cold reload offline.
  - An unswept expired row in the range is stepped past, not an error, and the
    count drops a row at its `nextExpiry` offline with no deletion arriving
    from sync.
  - Own sends, tombstones and physical deletion count as the server counts
    them.
- **The selector.**
  - `>` and `>=` at the floor, with ties;
  - a null watermark, and a null sibling on the same column;
  - two conjuncts on `ordinal`, which scan from the greater;
  - `m.readUpTo < .ordinal`, which certifies as `.ordinal > m.readUpTo`;
  - an upper bound, which is not a range;
  - a candidate on another column, which does not certify;
  - a horizon leading with `.at`, which does not certify an ordinal range;
  - a composite horizon leading with `.ordinal`, which does.
- **The boundary.**
  - A public `Key` floor does not certify; a public `Whole` does.
  - Interrupted acquisition; a cold reopen.
  - A delivered-history leave and rejoin, whose retained rows are never counted.
  - Expiry or deletion of the floor row; later backdated delivery.
  - A watermark that moves backward below the floor.
  - A `Whole` group with a 9,000-row expired backlog before three live rows:
    exact through the live-basis path.
- **Authority.** A non-public membership source (`exists members[...]`)
  certifies from its window. A non-uniform rule stays pending. The server
  branch is unchanged.
- **Flags and fallback.**
  - A coverage miss is `L`, `recountPending`, `complete: false`, unknown, not
    speculative. Online, the server's count replaces it when the fences permit;
    an unobserved predicted write and a `held` query still block. Offline, `L`
    stays.
  - A covered cut is `L`, not unknown, not speculative, kept locally.
  - A pending value fails a `value` probe.
  - A non-expiring pending value is unchanged.
- **Sequences and prediction.**
  - A range read over a provisional ordinal records its selection, even when
    empty. A refusing mutation that depends on it queues; a succeeding one
    predicts.
  - A covered prediction predicts. A 1,025-row range queues, and so does an
    uncovered member, which never persists `L`.
- **The server is untouched.** 20,000 live rows and 3 unread certify 3, with
  one examined unit and one step, equal to a world with 10,000 extra unswept
  expired rows. A count-dependent writer is not `E_VIEW_KEY`. The existing
  server disclosure tests pass unchanged.
- **Measured work.** Instrument candidate visits: a covered badge with 3 unread
  in a 20,000-row group visits about 3 candidates on the device, not the group.
  Several badges share one request's allowance.
- **Certificate and `check`.** The sentences of §3.4 on the guide's program. The
  plan appears in `check`'s text and JSON. A non-expiring view is unchanged.
- **Guide.** The example compiles with no note, and its device test passes.
  Each of the three meter-cut sentences is corrected.
- **Mutants.** Each must fail a test:
  - a scan that ignores the range;
  - coverage that ignores the floor, or the parent prefix;
  - `>=` read as `>` at the bound;
  - a lower bound that counts retained or expired rows;
  - a pending value of `0` on the range path;
  - an uncovered read that records no unknown fact, or one marked speculative;
  - an upper bound treated as a range;
  - a null that disables a sibling;
  - a range path used where `Whole` holds.
