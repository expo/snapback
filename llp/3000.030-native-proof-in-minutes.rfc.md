## 1. Decision and claim

Ship **the builder's own Release simulator app, built and driven by the
witness**, including after JS/assets-only edits. The supervisor withdrew
`--repack` in round 4: repeated reviews found native inputs outside its
compatibility key, and an Xcode build graph is not completely captured by the
implemented inventories. The CLI refuses repack and points to `--build`; the
repack implementation is removed. Its design in §4 and historical protocol and
measurements in §§11–12 remain a **deferred alternative**, not a product claim.
The prebuilt host/direct-loader alternatives in §10 also remain deferred.

Run from the backend project (Expo project shown here in the same directory):

```sh
# Every milestone in either Expo starter; requires a Mac with Xcode/iOS runtime.
npm run native:smoke
# Equivalent: npx snapback4 witness ios --build . --smoke
```

`--build` feeds the existing driver. Installed-app mode,
`witness ios --bundle-id ...`, remains available and builds nothing. Both retain
the same smoke protocol, actual app client and owned backend. Build preparation
is non-GUI-safe, seals an immutable `build.json`, binds the selected installed
bundle on every launch, preserves served-generation residency facts and smoke
classification, cleans owned process groups, and keeps outputs private.
Custom linker output paths refuse before compilation, including map, dependency,
LTO and SDK-import files; resolved destinations are checked for all app/Pods targets.
Nonempty `SKIP_BUNDLING` and `SOURCEMAP_FILE` settings refuse before compilation.
The build invocation pins both empty and removes the previous product's bundle;
an exit-zero build that produces no new bundle cannot seal a receipt. Resolved
Swift and module-verifier flags are audited for every target, with `-Xcc` and
`-Xfrontend` arguments kept in their respective compiler channels. Output flag
destinations must stay canonically inside the private cache; unknown flags refuse.
Per-architecture object directories and the compilation CAS path receive the
same raw-override refusal and resolved destination check.

Five complete warm build-plus-smoke runs on the shared M5 Pro mini measured
**159.841 s median / 197.562 s nearest-rank p95** (about 2.7 / 3.3 minutes),
all passing.
Stage 0 measured **359 s cold native build/install** and **138 s warm
build/install**; smoke and setup were additional, and that CLI's GUI activation
failed. Those are not cold end-to-end proof times. §12 gives round 5's five
complete warm builds, median and nearest-rank p95. Installed Xcode/runtime,
dependencies, a booted owned simulator and the disclosed helper patch are
preconditions, not hidden downloads. No universal two-minute promise is made.

An own warm build is `application-release`: Xcode builds the current project
using its own incremental tracking. Native input/dependency inventories are
provenance, **not permission to skip Xcode**. They do not claim a hermetic build,
complete negative lookup capture or an adversarial sandbox. Full generic smoke
proves the recorded three-segment lifecycle, not M6/M8 application assertions,
physical devices, publication or benchmark admission. The title describes
native proof in minutes; a preparation receipt alone is not passing smoke.

## 3. Own Release build and native base custody

`--build <app-project>` uses that project's installed, locked Expo/RN/native
packages and its own identity, config plugins, generated providers and native
resources. It runs the necessary prebuild/pod preparation and `xcodebuild`
for **Release, iphonesimulator, arm64, Hermes, New Architecture**. Preserve
`ExpoModulesProvider`, `RCTAppDependencyProvider`, codegen and delegate
handlers generated for this application. No custom AppDelegate loader or
`expo-constants` adapter is needed. Prebuilt RN core and Hermes are already
used in stage 0; they are not a separate acceleration project.

The first supported shape is the cal25-like generated Expo application on the
stage-0 toolchain. Dependencies are already installed. Run prebuild in a
private snapshot when `ios/` must be generated; retain existing native inputs
when present. Never run destructive `prebuild --clean` over a builder's edited
`ios/`. Ambiguous workspace/scheme or unsupported custom native preparation
gets a named refusal and the manual installed-app route. Capture all local
workspace/native inputs needed by a snapshot, or refuse before building.

Use an explicit workspace, scheme, SDK/destination and a stable private
snapshot/DerivedData path per project, protected by a separate project cache
lease across UDIDs. Preserve warm intermediates; Xcode's input tracking and
the recorded source and build result establish provenance; no fingerprint
equality can bypass Xcode. Pin product/intermediate/module-cache roots on the Xcode command line, refuse
custom app output overrides (including LD_MAP_FILE_PATH,
LD_DEPENDENCY_INFO_FILE, LD_LTO_OBJECT_FILE and LD_SDK_IMPORTS_FILE), and check resolved output destinations for every
app and Pods target (including symlink parents) before compilation. Use a private
HOME for preparation so user shell startup/configuration is not a native input.
Replace the snapshot's `.xcode.env.local` entry before exclusively creating its
regular replacement; never follow a copied link when writing `NODE_BINARY`.
The output audit also covers module/precompiled-header/module-map destinations,
build-session files, compile/link response and metadata lists, prelink dependency
files, temp/object/Metal directories and relative Info.plist/dSYM output names.
Raw output overrides refuse; resolved app/Pods destinations must remain private.
Pin `CLANG_MODULES_BUILD_SESSION_FILE` in both workspace and per-project settings
queries/builds. Resolve dangling output symlinks, including missing descendants
of a dangling parent, and refuse outside targets before a producer can create them.
System-library links with missing on-disk targets remain recorded input provenance;
they do not bypass the separate private-output boundary.
Resolve path components in filesystem order: follow a symlink before applying a
following `..`, including components within the link target. Relative output names
must retain their components until resolution; lexical normalization must not hide
an outside destination.

**Threat model:** preparation's output confinement is hygiene for well-behaved
projects, not a security boundary. CocoaPods and build phases run arbitrary scripts
with the user's privileges. Private paths, settings audits and source inventories
do not sandbox those scripts or defend against a malicious project, dependency or
concurrent filesystem writer. The checks prevent the supported configuration's
accidental output redirection and detect recorded source changes; they make no
adversarial confinement claim.

Query the unmasked resolved bundling settings before pinning `SKIP_BUNDLING=`
and `SOURCEMAP_FILE=` on the build command. Nonempty values, including `0` and
whitespace, refuse. Refuse bundler command/name/config/argument overrides that
could select another producer, consume stale intermediates or redirect outputs;
the resolved Hermes path must name the pinned compiler. Before Xcode, remove
the previous product's `main.jsbundle` after checking its canonical destination.
Require a newly present bundle and successful subprocess status independently:
a failed Xcode command may leave a fully valid product behind.
Resolve
`TARGET_BUILD_DIR` plus `FULL_PRODUCT_NAME` from that invocation's build
settings and result, not the first matching app elsewhere in DerivedData.
Do not launch a stale prior app after build failure. Build processes have
their own finite, reported deadline (initial proposal: 15 minutes) separate
from the witness's 120 s **per step**. Save argv, phase timings, exit statuses
and logs. An exceeded deadline fails preparation; it does not relax assertions.

After successful preparation, copy the complete `.app` to
`<artifacts>/base.app` outside mutable DerivedData and write
`<artifacts>/build.json` beside it. Preserve both as an immutable local base.
A receipt made after the build records the resolved input snapshot, complete
native fingerprint, configuration/target, Xcode/SDK/runtime identities,
package/lock/pod digests, build log/result digests, and app inventory (§6).
Before sealing, recheck both live source and snapshot source against their initial
inventories. A snapshot-only JavaScript edit during compilation must refuse with
`E_WITNESS_PROOF`, even when live source stayed unchanged and Xcode exited zero.
Record actual Hermes engine/compiler versions and digests, HBC version,
`RCT_HERMES_V1_ENABLED`, prebuilt-core settings and architecture, rather than
assuming SDK-major compatibility. Retain the linked Snapback archive identity
where the toolchain exposes it, plus native probe/helper version.

A warm rebuild is still `application-release`: Xcode builds the current
application using valid intermediates. It creates a new immutable receipt,
even if no native compilation was necessary. Reuse of a prior native base
without that build is `application-release-repack`. A receipt-less installed
app remains usable by the legacy witness, but Info.plist alone cannot grant
it new build provenance or eligibility as a repack base.

## 4. Fingerprint-checked repack

**Deferred and withdrawn from the product in round 4.** The following is the
retained alternative design, not shipped behavior. Rounds 1–3 executed this
candidate but the round-3 review disproved its completeness. DerivedData
consumed inputs lacked producer/revalidation proof; missing macro-expanded
header probes were absent; toolchain-input revalidation lacked a detecting
test. Reopening requires addressing all findings in §12, not merely restoring
a CLI flag. The implementation, receipt reuse and repack tool invocation have
been deleted. Build records may retain positive compiler/linker provenance,
but they grant no native compatibility or repack eligibility.

`--repack <build.json>` selects a base built for this same project and native
identity. No cross-project reuse or published superset binary is admitted.
The witness verifies the base bytes and compares current native inputs with
the captured build inputs **before running repack or installing anything**.
A mismatch prints a field-by-field diff and the `--build` command. Never infer
compatibility solely from `package.json`, SDK major or `runtimeVersion`.

Use a pinned `@expo/fingerprint` implementation and record its version,
options and source list. Its API exposes hashes and source-level diffs;
its ignore/transform configuration can exclude native inputs, so equality
under arbitrary project overrides is insufficient. The first slice refuses
custom ignores/transforms that weaken coverage. [Expo Fingerprint API](https://docs.expo.dev/versions/latest/sdk/fingerprint/)

The witness's conservative native comparison also binds:

- The full resolved iOS autolinking closure, package integrities, native patches,
  local modules, the full source Pods tree, its generated iOS header target tree
  and `Podfile.lock`, codegen/autolinking inputs and architecture/Hermes
  settings. Include transitive modules and generated providers, not only the
  direct list in §2. Conflicting native resolutions or unclassified native
  inputs refuse reuse.
- Evaluated Expo config and plugin inputs/implementations, native source and
  resources, entitlements, bundle ID/schemes, permission strings, fonts and
  asset catalogs. Initially **any config change** requires `--build`; broad
  metadata rewriting is unnecessary for this JS-only slice.
- The bounded adapter resolves Xcode file/group references, source/resource
  paths, input file lists, includes and search paths, refusing inputs outside
  its covered roots. Only pinned generated shell phases, Podfile and environment
  hooks are supported; custom build scripts and scheme actions use manual
  installed-app mode. Resolve every app and Pods target, including compiler
  flags, VFS overlays, config includes, phase file lists and resource catalogs.
  Before sealing a reusable base, require compiler dependency records covering
  every source and linker records covering every compiled product. Audit both
  actual linker inputs and missing search probes; non-toolchain paths must be
  covered source roots or owned generated outputs. Persist the records and
  actual input hashes; recheck toolchain files on reuse. Missing or unknown
  coverage refuses, including old receipts without this adapter's evidence.
  Shell/Node phases and the one Expo Swift macro executable are further limited
  to their exact qualified installed dependency tree: a different dependency
  tree may build, but does not inherit repack eligibility. This deliberately
  narrows reuse rather than trusting arbitrary tool implementations to report
  every undeclared input. App codegen/autolinking customizations are excluded.
  Unqualified copy phases refuse: their destination selector can bypass ordinary
  build-directory settings even when the destination text is empty.
- The recorded toolchain and native helper compatibility. Changing native
  Snapback/Expo/RN/helper inputs requires a build. Pure JS source/assets may
  change; full locks and JS/compiler/Metro/Babel inputs are still recorded as
  provenance. An unexplained fingerprint difference conservatively rebuilds.

Take the baseline after native generation/pod resolution has stabilized, and
compare equivalent input stages later. `sourceInputs` records live pre-resolution
provenance and `inputs` records the post-pod/codegen snapshot before Xcode.
`preparedInputs` separately records Xcode's later generated changes, while
compiler/linker records bind the actual consumed files. Repack
runs private pod/codegen resolution and compares the full resolved input key,
including generated inputs, before invoking the repacker and again afterward. Generated timestamps/build outputs
must not become an excuse to ignore native source. Build/repack consume a
private snapshot with stable config/public environment; verify input hashes
before and after. A live edit or changed dynamic-config result invalidates
preparation. Record only public config and required public-value digests,
never ambient credentials. An origin change needs a newly bundled app for
`http://127.0.0.1:<port>`; simctl environment cannot rewrite inlined
`EXPO_PUBLIC_*` values.

Run the app project's locked `@expo/repack-app` 0.10.3 with explicit
source/output and `--js-bundle-only`, always writing a new `.app`. The flag
prevents the default identity/metadata rewrite, but does not replace the diff.
Record its lock integrity; do not add this Android-heavy tool to the CLI package. Expo documents that this normally
runs a fresh `expo export:embed`, then replaces JS, assets and metadata.
Therefore this path **does not consume the exact pre-existing `dist` HBC**.
Record the actual output bundle; retain the earlier export digest separately
if needed, with no assertion that they match. [Expo repack documentation](https://docs.expo.dev/build-reference/repack/)

After repack, compare inventories. Native Mach-O executables/frameworks must
be byte-identical to the base. Allow only enumerated JS/bundled-asset changes from the pinned export output;
Info.plist, Expo.plist, EXConstants, executable names and native identity stay
byte-identical in this first adapter;
record the complete changed-file list. Check bundle ID, schemes, entitlements,
permissions and public config against the base. Unknown resource/config
changes fail; neither a generic directory exclusion nor `--js-bundle-only`
is proof that the needed assets and identity were preserved.

Read `main.jsbundle` bytes: verify HBC magic/version and the recorded compiler
against the base's actual Hermes runtime, then verify real cold execution.
Record both CocoaPods and JS-export compiler identities: repack uses
`export:embed --minify false --bytecode true --unstable-transform-profile hermes`,
where Xcode uses a separate bundle phase followed by CocoaPods `hermesc -O`.
Even matching compiler/header versions do not replace cold execution.
Hermes can execute JS source; “it launched in Hermes” alone is insufficient
for the Release/HBC claim. The measured 4.16 MB bundle remains **format unknown**
until inspected. If the pinned repack path emits plain JS, try only its
supported configuration with the project's matching compiler and record that
new experiment. If HBC or resource parity cannot be established, leave repack
unavailable and use warm `--build`. Do not quietly relabel source as HBC or
invent a bytecode-conversion/loader subsystem to preserve the 13 s claim.

Initially exclude linked `expo-updates` from both prepared proof routes,
including launch selection/delegate behavior. A cached update could supersede
the embedded bundle whose bytes are hashed. Legacy installed-app mode remains
available with unknown preparation. Keep the real
app's `expo-dev-client` dependency in the own-app experiment (§5). Cold-launch
must show embedded configuration, no non-empty dev-launcher/updates manifest
superseding it, and no Metro/OTA fetch. Failure is visible, not repaired by
silently removing a dependency and continuing under the same base receipt.

## 5. Non-GUI installation, launch and witness lifecycle

Separate preparation from execution. Prefer `expo prebuild`/pod preparation
plus direct `xcodebuild`, followed by `simctl install` and the existing witness's
`simctl launch <udid> <bundle-id>`. The pinned Expo CLI's
`expo run:ios --configuration Release --device generic --no-bundler --output <private-output>`
is a build-only alternative. `--no-install` is not an installation/launch
suppression contract. The first adapter uses direct Xcode for controlled
DerivedData and exact target/product selection; it does not invoke Expo's
concrete-device install/launch path.
No `open -a Simulator`, AppleScript, GUI session or Accessibility permission
belongs in the required path. Do not blanket-ignore Expo exit 1 or use a log
substring as a replacement for a successful build process and verified output.

`expo-dev-client` explains stage 0's wrong launch URL even with Release. The
witness launches the **bundle ID directly**, never `exp+...` or a dev-server
URL. Keep the application's dependency/config unchanged for the comparison;
inspect resulting Release behavior. Verify `__DEV__ = false`, native Snapback
available, the intended bundle digest and visible JS marker, initial config,
and absence of a developer launcher/Metro dependency on every cold launch.
If direct launch still enters a launcher or selects another manifest, fail
with the observed behavior and rebuild after an explicit project correction.
A successfully installed app and a PID alone are not smoke evidence.

The existing process rules remain: explicit dedicated UDID, or exactly one
available booted simulator; no unresolved `booted` target; no stolen backend
port; stop only recorded owned PIDs. Add a per-UDID preparation/run lease so
parallel builds cannot install over another witness. Refuse a running app
before replacement. Preserve artifact reservations and failed preparation
logs/manifests. Do not clear a simulator or keychain belonging to another run.

Install once **before prime**. A fresh dedicated simulator and a disposable
nonempty fixture are the first-slice baseline. Authenticate through the app's
normal flow; no fabricated guest, session or replica. The base and repack
proofs are separate runs, each declaring fixture, authentication and reset
policy. If the second uses the first run's store, name that reuse explicitly;
it does not prove a fresh installation. Uninstall alone does not clear
SecureStore/keychain. No reset, reinstall, repack or data injection occurs
between a run's prime/offline/restart segments.

Reuse the existing smoke:

1. **Prime:** the app's own published native client authenticates and completes
   online acquisition. Record held counts, identity, generation, watermark,
   link and errors after the render pause; seed nonempty history for acceptance.
2. **Offline:** terminate and verify absence, stop the owned backend and verify
   connection refusal, then cold-launch the same installed app/store. Compare
   held counts/identity and offline link; run no-argument/all-optional queries.
   Compiler-declared device-answerable queries require data or an explained
   refusal; loading, thrown queries or uncaught errors fail. Server-only reads
   record `online-only: unavailable offline (expected)` and their actual loading
   or `E_OFFLINE`-style refusal. The owned backend compiler supplies every
   eligible query fact; missing facts fail, and results never determine residency.
   Those server-only queries must answer online in prime and restart.
3. **Restart:** terminate, advance the stopped backend with the existing
   zero-write barrier, restart it and cold-launch. Require online progress
   through that exact sequence; reread final state and require the owned PID
   alive until deliberate termination.

An online-only fallback cannot pass native smoke. Empty partitions establish
opening/lifecycle only. Smoke does not assert required-argument queries,
writes, media, search correctness or recipient read states. The application's
own `WitnessRunner`, visible UI and normal client supply deeper assertions;
no supplied runner means missing evidence, not an invented scenario.

## 6. Receipts, proof identity and refusals

Keep an external `proof.json`, whose SHA-256 identifies the preparation for
one run, and a finalized run manifest that hashes that proof plus video,
screenshots, raw receipts and logs. No artifact hashes itself. Inventory
payloads with sorted relative paths, file types/modes, byte lengths, SHA-256
and bounded relative symlink targets; reject escaping links. Preserve all
base and output bytes; verify the installed app matches the selected output
before launch and again at collection.

Seal `proof.json` before the first launch. It contains prepared inputs and
expected execution identity, not future results. Observed runtime facts,
actual backend/store observations and execution timings go into startup/raw
receipts and the finalized run manifest, checked against that immutable proof.

| Proof field | Claim |
| --- | --- |
| `proofKind` | `application-release` for the shipped build; `installed-application` for legacy receipt-less installs, with preparation unknown. `application-release-repack` and `exported-bundle-host` are historical/deferred values, not emitted by the shipped preparation route. |
| `nativeBase` | Immutable source `.app` inventory digest, executable/framework digests, `build.json` digest and native input fingerprint; null for an install with unknown preparation. |
| `executedApp` | Actual installed `.app` inventory, bundle ID/build fields, target/configuration, native probe/helper identity. For an own build it is the base; for repack it is the separately hashed output. |
| `javascript` | Actual launched bundle digest, length, HBC/compiler identity, assets/public-config digests and current JS input provenance. A previous `dist` digest is only an optional distinct source reference. |
| `transformation` | Repack tool/version/integrity, argv, source and result inventories, fingerprint comparison and changed-file list, or null for an own build. |
| `runtime` | Selected UDID, simulator type, iOS version/build, Xcode/SDK, architecture and expected Hermes/New Architecture/Release configuration; startup must corroborate it. |
| `scope` | Requested scenario and limitations, fixture/auth/reset policy, intended backend origin/store and completed preparation timings. |

The proof and raw receipts bind **both the native base app digest and actual
JS bundle digest**, plus the repacked app digest when applicable. Recheck that
binding on every relaunch. Extend the native witness startup observation to
report React Native SourceCode.scriptURL, its resolved local path, the selected
file digest and native identity along with the
run/proof digest; require the selected path to equal the verified installed
main.jsbundle before hashing, and require runtime __DEV__ false. Unknown, remote
or alternate selection, a nonempty launcher/updates manifest, or linked Updates
fails. Validate these facts before accepting steps. Do not merely
have JS echo environment strings. For a future direct host loader, distinguish
`embeddedJavascript` from `launchedExport`; the inert host JS is not the app.

Retain the strict `witness: {at, step}` envelope. Add proof observations in
an allowed application receipt field through the helper/driver contract, with
an explicit format version; changing the reserved envelope would require both
validators to change. Record failure and liveness after terminal receipts for
application scenarios as well as smoke. Hashes and lifecycle observation bind
local evidence to bytes; they do not independently attest app assertions.
Validate smoke origin, served query generation, residency facts and lifecycle
fields before marking a segment passed, and revalidate them during collection.
Keep a rejected receipt as evidence with a failed segment and its error.

Preflight reports all independent mismatches with expected/actual values,
paths and recovery. Proposed additional codes, registered with the existing
guide/tests only when implemented:

| Code | Refusal and recovery |
| --- | --- |
| `E_WITNESS_BUILD` | Prebuild/pods/Xcode failed, timed out or selected no unique product; preserve logs, correct the named input and rerun `--build`. Never launch a cached older app. |
| `E_WITNESS_NATIVE_COMPAT` | Missing base provenance or native fingerprint/config/toolchain mismatch; list the diff and use `--build`. |
| `E_WITNESS_REPACK` | Unsupported repack version/output, modified native bytes or unexpected metadata/resource changes; preserve output and use a warm build. |
| `E_WITNESS_HERMES` | Unknown bundle format, plain JS, wrong compiler/engine/HBC header or target/architecture; rebuild with the recorded Release toolchain. |
| `E_WITNESS_PROOF` | Base/output/installed/launch digest or proof binding differs; refuse execution/pass and rebuild/repack from verified inputs. |
| `E_WITNESS_ORIGIN` | Bundle or actual client origin differs from the owned backend; rebundle for the printed origin or select its matching free port. |
| `E_WITNESS_SCHEMA` | Later application-receipt projection/coverage failed; retain raw evidence and repair the scenario. |

Existing platform, simulator, input, app, backend, port, process, artifact,
receipt, step, timeout and interruption codes retain their meanings. Linux
refuses before invoking native preparation. No new repository-wide gate follows.

Withdraw round 0's universal “missing required module fails even if JS
catches it” guarantee. Native lookup cannot determine application intent:
Expo required and optional helpers share a lookup, and ordinary `expo-asset`
catches `requireNativeModule('ExpoGo')`. RN `get`/`getEnforcing` share a lookup
too; Fabric can fail at render. Optional misses are diagnostics; explicit
scenario requirements and actual assertions decide failure. An uncaught
startup error, missing native smoke attachment, fatal process exit or declared
required capability failure prevents pass. Unexecuted/caught application bugs
remain outside smoke's coverage. Own native closure equality avoids the host's
extra-module feature-detection problem; it does not prove every JS path.

refuse before preparation with a build recovery command. Repack/host artifact

a timestamped artifact directory by default (§13); explicit `--port` and

Own-build smoke retains `smoke-ios-*`; repack smoke uses `repack-smoke-ios-*`.

label. Legacy receipt-less m6/m8 invocations always emit installed-m6/m8

Host/repack results may have their own external status records
`ios-repack-m6`/`ios-host-m6` (and m8), kept **outside** the frozen
`--simulator-status` input, which accepts only its two original IDs.
Do not rename files, alias IDs, attach a repack receipt to a native `pass:true`,
or rely on extra metadata surviving ingestion. With only this alternative
evidence available, the frozen `ios-simulator-m6`/`m8` entry stays `pass:null`,

This matters because [the status normalizer](../benchmarks/tools/social-messenger/choreography/choreography.mjs)
reconstructs a fixed object and, for `pass:true`, only requires a receipt
pointer. It drops extra proof-kind fields and does not validate the movie or
assertions. A manifest disclaimer is insufficient protection against that
path. Every standalone projected assertion must carry `proofKind` and the
full proof SHA-256 in an allowed `timings[].note` text field (or
`details.reason` where appropriate). Every host/repack video and screenshot
must visibly show the proof kind and a readable short proof digest, with the
full digest in its manifest/receipts. The witness-only label must not obscure
the tested UI; it is present during recording, not a replacement edited movie.

Application runners retain their visible screen and same client. Later schema
projection takes explicit assertion objects, preserves raw protocol JSONL
separately, validates **every** projected line against the supplied closed
schema, and binds line mapping and coverage declaration. Populate the allowed
proof note before projection and check it against the driver; never add a
forbidden top-level field or strip envelopes from empty milestone rows and
call them assertions. Bind exact fixture IDs, bodies, occurrence counts,
media/cache observations, ordering and final receipt states in raw observations
and schema-allowed notes/metrics. One continuous run uses `bestOf: 1`.

M6 still needs cold-offline held history, viewed ordinary media, consumed
view-once denial with no cached open, search/open, two visible pending sends,
ordered exactly-once flush and **Bob's actual app/client open/read progression**.
A forced server-side `read` value cannot replace that observation. Finalize
video before hashing and validate the complete artifact set and coverage.
Missing observations/artifacts, wrong run IDs or failed lifecycle steps fail.

M8 remains a later driver increment: the frozen scenario starts **warm**
offline, whereas today's `--prime --relaunch` starts its scenario cold. A
versioned warm handoff must start recording before the backend stops, signal
verified offline to the same primed PID, await two pending sends and
`relaunch`, then terminate and relaunch offline without resetting storage or
sending again. Prove those exact pending bodies once/in order (`m8-a17`),
then ordered flush and final read (`m8-a18`). Existing cold restart is useful
evidence but is not this sequence. Keep schema projection, warm handoff and
benchmark admission outside the first build/repack smoke slice.

## 13. Per-milestone starter native smoke (NS round 0)

Both `init --expo` and `new --template social` generate `native:smoke` as
`snapback4 witness ios --build . --smoke`, beside `export:ios`. On a Mac with
Xcode the warm check is described as about three minutes, with actual host,
cache and timing evidence in the [NS report](../snapback4/reports/20260930-ns-native-smoke/REPORT.md).
Hermes export is packaging evidence only. Generic smoke proves an installed
Release/Hermes app, native local-store acquisition, offline cold reopen with
matching holdings, and online restart through the driver barrier. It does not
queue a mutation: pending-write replay, required-argument reads, nonempty
application history, media and M6/M8 assertions require application scenarios.

Without `--udid`, the CLI reuses only an available booted iOS device with a
matching per-user creation record (UDID, name, runtime and lane prefix) under
`$XDG_STATE_HOME/snapback4/witness/simulators`, defaulting to `~/.local/state/`.
A matching name alone establishes no ownership; missing devices, stale or
malformed records cannot authorize reuse. Records and their directory must belong
to the current user, must not be symlinks, and must not be writable by group or
others. Unsafe records are ignored with one warning per invocation; an unsafe
directory refuses new persistence before simulator creation. Reads/writes use a
verified directory handle and no-follow file opens with metadata checks; new
records are exclusive mode 0600 files and new directories mode 0700. Owned devices are ordered by numeric
runtime version, newest first. Otherwise it creates a device on the newest
available iOS runtime. Among numbered iPhones, leading digits establish the
newest generation (including suffixes such as `17e`), with the plain model
preferred to Pro/Pro Max, then suffixed variants in that generation. Compare that winner with unnumbered
models such as Air by the runtime's supported-device order, later entries first;
if the runtime supplies no such list, use the device-type list's order.
`SNAPBACK4_SMOKE_DEVICE_PREFIX` isolates a shared-host lane (NS uses `sb4-ns-`).
Explicit UDIDs still require a booted available iOS device. Selection, name,
UDID and runtime are printed and recorded in the run receipt before fallible
ownership persistence and boot steps, including failed boot/bootstatus receipts. A selected device remains for warm reuse; callers delete
its exact UDID when finished. Simulator leases still refuse concurrent owners.
Missing Xcode/runtime produces one actionable setup message before compilation.

Build mode retains the bound loopback listener from before preparation until
`dev` inherits that same descriptor; no probe/drop/rebind window precedes startup.
Each subsequent backend start also inherits its reservation. The deliberately
offline interval still closes the listener so TCP connections must be refused;
if another process binds then, restart refuses it without reclaiming the port.
At process entry, before any child (including the server-handler checker) can
spawn, dev adopts the descriptor and restores close-on-exec. An owned descriptor
closes on every startup error; interruption or timeout cannot leave the checker
holding the listener. Dev validates its loopback address and preserves the server's connection limits. The driver generates the
backend API with `check` under leases for both backend and native project (one
lease when identical), retained through execution. Check runs as an owned process
group inside the witness exit-code wrapper, with captured diagnostics and a
finite deadline; missing schema exits 1 with one actionable message and a failed
receipt. It bundles the held origin and allocates
`artifacts/native-smoke/<unix-ms>-<pid>`. Installed-app mode retains its port

## 14. Prove the heaviest account (BN, 2026-09-30)

`witness acquire --as <persona|principal> [--url URL] [--token TOKEN]
[--restart] [--runs N] [--query NAME --args JSON] [--artifacts DIR]
[--timeout 120] [--json]` runs the published SDK over `processDevice` and
this CLI's native SQLite module. It uses a fresh private temporary store
per run against an already running backend; it never opens the server store.
The package ships the Node helper in `bin/`; the binary resolves the matching
installed helper or checkout, and the npm shim passes its own helper path.
This is a device witness, not an application UI or physical-device claim.

Identity is checked before acquiring: dev personas must appear in the running
server's declared personas, exposed only by the existing fenced dev status
inspection. `/probe` returns the authenticated caller's own viewer, so a
bearer cannot label another principal's receipt. Principal mode requires a
live supplied bearer; no session is minted, rotated or revoked. Receipt format 2
uses an output allowlist, not token-pattern redaction. Server free text and codes
are dropped entirely (no separate file); any future emitted server code must match
`^[A-Z][A-Z0-9_]*$`. Only command-generated prose, local/native measurements and
command-computed hashes cross the output boundary, apart from caller-owned
principal, URL, explicit query and argument inputs. Unknown SDK/native errors
become a fixed diagnostic. No refusal echoes an argument value, including iOS
runtime selection, reservations and preparation. A necessary output locator is
explicitly labelled the command's own log or receipt path. iOS child-tool logs
remain separate raw artifacts; their prose is not forwarded into refusals.
`--token=VALUE`
is accepted like other valued acquisition flags; `--token-file` is unsupported
and refused without its value. iOS refuses unsupported equals spellings and
unknown/positional arguments without values. A raw bearer reused in a non-secret
input is refused before artifacts exist. Preflight counts in acquisition time. Automatic
query selection chooses the first zero-argument device query; explicit query
arguments are checked and the query must produce a complete local answer.
Failed receipts keep the command's own selected query and arguments, including
preflight failures. Validated engine/server codes select command-authored reasons:
E_INPUT/E_TYPE/E_FIELD mean argument rejection; E_OFFLINE/E_PREDICT or a read
without complete data mean incomplete coverage; other refusals mean query refusal.
Unknown or malformed codes get the fixed query-refusal message. Neither the
supplied code nor arbitrary refusal prose is emitted.
The first local query is issued immediately after the SDK acquired boundary;
server query fallback is blocked. This timing deliberately does not claim the
earliest screen answer during partial acquisition. Local request header/body
clocks remain; Server-Timing and all other server-provided numbers are omitted,
even if syntactically numeric. This supersedes round 0/1's server-time reporting:
a numeric header is still a channel for a server to reflect a credential.
Explicit SDK sync drives the proof; background `/changes` polls are suppressed.

After measuring acquisition and the local answer, collect `residency()` and a
native-only witness inspection of actual rows grouped by audience prefix,
persisted history, and acquisition boundaries. The inspection scans outside
the timed interval; its canonical digest includes per-group row counts and
coverage floors, not merely aggregate counts. Groups are table/group pairs
with stored rows or coverage facts, plus implicit public/principal groups.
Empty unwindowed target groups without stored facts are not counted. Thus the
receipt includes groupsByTable; applications must check the relevant table
against their envelope, rather than equating a summed group count with chats.
Both groupsByTable and residency.tables use command-computed SHA-256 keys of
UTF-8 `JSON.stringify(["witness-table", tableName])`, never server table names.
Automatic query selection uses the label `automatic device query` and a locally
computed selection digest; an explicit query/args uses the caller's own copy.
Store/generation/watermark stay private during proof comparisons. Public
stateSha256 hashes `["witness-state", storeId, generation, watermark]`;
positionSha256/serverPositionSha256 hash `["witness-position", watermark]`.
These are computed from JSON locally, never copied from supplied hash fields.
Bytes retain residency's SQLite-page/row-payload meanings, excluding WAL/SHM,
media caches and RSS. Raw coverage group keys and row payloads are not emitted.

With restart, close and await process exit, reopen the same store with every
HTTP request blocked, obtain a complete local answer and inspect coverage.
Compare acquired state, server-store identity, generation, watermark, every
group/count and persisted coverage digest, and each table's rows/payload bytes.
Time the first local answer separately from `restart.coverageVerifiedMs`, which
starts afterward and includes the coverage scan and equality check. Then
reconnect with explicit SDK sync. Every actual HTTP attempt is recorded before
transport, including failed attempts and partial failed runs. The private Node
transport notifies only the calling witness before its reused-socket retry;
the witness closes the failed sample and opens a separate sample whose `cause`
is `transport retry after reused-socket reset`. Each has its own local clocks.
The original failure stays latched even if the retry succeeds. No remote error
text enters this notification, and other callers have no receipt observer.
Host fetch instrumentation and the process-wide dispatcher remain unchanged.
Any transport, HTTP
or protocol failure invalidates the proof, even if the SDK swallows it or retries.
Validate the sync envelope; require a terminal stream page with `more: false`,
watermark equal to the server position (`images_at`), and the same position,
store and generation applied locally. Observe the native apply reply as well:
an unchanged watermark cannot substitute for successful terminal publication;
native sync validation/application refusals fail the proof. Require no row/scope events and equal
coverage again. A returned `client.sync()` promise alone proves nothing. Snapshot responses
are counted explicitly: a completely empty store at watermark zero can receive
an empty snapshot on reconnect, without downloading any held row.
Concurrent writes, generation changes and expiry therefore fail this stable
fixture proof, rather than silently moving the comparison target. This is a
cold process reopen with warm OS caches, not power-loss or disk-cache proof.

The JSON receipt reserves a new acquire.json exclusively, records all completed
runs and any failure, and states that native process and web wasm/IndexedDB
figures differ: Node speaks one JSON line per call to the `snapback4 device`
subprocess, backed by SQLite; Expo links the crate in-process. Tests delete a held SQLite row before reopening, wipe the
store, and corrupt group/boundary metadata; each must reject. CLI tests also
run the actual bounds-card shell snippet and check its receipt excerpt, plus
serve bearer identity, missing/wrong inputs and unreachable servers. No public
client contract, data-plane semantics or wasm feature is changed.
