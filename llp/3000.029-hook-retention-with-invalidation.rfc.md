## 2. Census and classification

| Transition / source | Classification and behavior |
|---|---|
| Same-key explicit/background re-read; ordinary presence sampling | Plain: retain marked `revalidating`, no time limit. |
| Local sync round / empty publication, acquisition progress without a changed dependency | Plain: retain. The publication's committed `touched` set is evidence, not receipt of a sync request. |
| Applied publication touching a read dependency (including scope tombstone, removal, changed row, horizon/window replacement) | Invalidation unless §7 proves a non-revoking public put for this query; withdraw before callbacks or async re-read. |
| Prediction/admission, settlement, rollback | Invalidation for changed dependencies; unknown footprint invalidates all. Settlements report the union of restored/replayed table effects; unknown old-host settlement effects withdraw all. |
| Online `/changes` intersects reported dependencies | Invalidation before revalidation, including membership/rule-probe dependencies. Saturated change logs already enumerate all tables. |
| Unrelated dependency writes | Plain: retain; no evidence the old answer changed. |
| Transport failure, disconnect/reconnect, exhausted obsolete responses | Plain unless another fence already invalidated: retain, mark revalidating, offline freshness false. No network can reveal an as-yet unreceived revocation. |
| Withheld/unavailable result from insufficient coverage | Plain only if no invalidation has intervened; it cannot resurrect an invalidated answer. Keep the retained answer's deadlines. |
| New arguments, query, client/backend or mount | New observation; loading until its own result (or same-key live watch). Never show data for old arguments under new arguments. |
| Credential rotation (even same principal), sign-out/account switch | Conservative invalidation; preserves credential-capture fences. Sign-out gives denial. |
| Schema installation/adoption/generation/rule change, store replacement/restore/reset, clear_rows, settle_exit, ephemeral incarnation | Invalidation; existing reset/refusal wins immediately. |
| Row/asset/answer deadline, expired in-flight candidate | Invalidation at getter and timer; never renewed by revalidation or wall-clock rollback. |
| New authoritative null, empty answer, denial or changed image | Replaces source immediately. The facade may not keep a different previous answer while checking the replacement. |
| usePage next-page acquisition | Keep the valid prefix; no old-argument suffix. First-page invalidation withdraws rows. Every getter checks all source deadlines. |
| useAsset same id/client mount | No ordinary refetch exists: retain the owned handle. Changes of id/client return loading immediately without a render of the old URL. Authority events revoke the handle and deny, never refetch a consumed once-view handle. |

This is intentionally conservative. A table change is evidence that an input to
the old answer has been replaced, not proof of a particular viewer's revocation.
Only the narrow public-put and immutable-key query proofs in §7 classify such a
write as plain revalidation. All other touched dependencies remain invalidation.
The route guarantee covers plain revalidation, not revocation or account change.

## 3. Observation policy

`Read.revalidating?: true` already exists; preserve its inferred/generated type.
Omitted `keep` and `keep: true` both retain indefinitely on plain revalidation.
`keep: false` opts out. Only `keep: true` lingers for 30 seconds without subscribers.
Freshness and coverage retain their meanings; the flag never authorizes writes.

Separate methods: `reload` marks an answer; `update` accepts a completed read
while allowing an unavailable result to leave a still-valid previous answer;
`publish`, `reset`, and `expire` are hard replacements. Invalidation runs across
all affected observations before notifying any subscriber. Scope revisions reject pre-reset work; the persistent cut fences and same-key
reply order in §7 also govern new evaluations and competing owners. No hook-owned cache
can bypass this source: React reads the live source and the facade's follower
clears its old approval synchronously on withdrawal or a different data image.

Remove the one-second episode deadline; row and server deadlines remain.
A transient failure cannot erase a still-valid answer, but neither a failure nor
a later revalidation can restore a withdrawn one. The asset hook has no refresh option or revalidation flag: it never automatically
reopens an acquired handle. Retention uses one answer per
live observation and the existing subscriber lifetime, not an accumulating cache.

## 4. Disclosure argument

The claim is relative to evidence received by the client, exactly like offline
replication. It is impossible to stop displaying at the instant an unreachable
server commits a revocation. This change promises no retained answer **after the
client processes evidence that invalidates it**, including predictions without
network traffic. It does not promise synchronous cross-network revocation.

Induction: a new observation has no answer. Every accepted answer passes the
engine, credential/store, cut, request-order and deadline checks. Plain
revalidation copies only that answer and its expiry ownership. Evidence retires
all affected dependency owners before notification and installs the persistent
fence of §8. Exact keys share replacements; overlapping shapes withdraw.
An old completion fails its attempt revision or key order; a new replica read
fails the unapplied-cut check. Server answers cross the same floor, without
clearing the replica fence. Only committed published apply discharges that fence.
A withheld result changes neither the displayed body's cut nor its deadlines;
unknown dependencies remain unknown. A current whole server replacement, empty
or nonempty, reaches all matching watches regardless of retention policy.
Transport failures carry no authority. Public-put retention requires proofs of
both the write and the query, so a public permission dependency remains revoking.
Facades and pages derive only these live sources and their original deadlines.
Permanent E_INPUT observations wait for new arguments or a hard scope reset.
A page invalidated during held fallback may need another independently metered
read; no invocation allowance or cursor law changes.

Membership removal reaches local scope/touched invalidation or online dependency
invalidation; predicted leave uses its footprint. Rule changes reset generation.
Deletion/tombstone changes the input table. Asset authority changes revoke live
handles before user callbacks; once-view URLs are never fetched a second time by
revalidation. A successful once-view delivery grants this one open view; it is
not a revocation of that same view. Closing releases it, and another opening
receives `E_ASSET_VIEWED`; there is no retained-answer bridge across mounts.
Expiry checks access as well as timers. Sign-out, account/backend
switch, store replacement/restore reset every source and its approvals. Unknown changed-input metadata fails closed. Asset GETs add an additive
`X-Snapback-Asset-Read` header containing the grant's sequence and earliest row
or rule-probe expiry, from the existing authorization transaction. The client
uses these facts solely to retire live handles, with no extra authorization
probe or meter allowance. Asset-only online clients follow `/changes` while
handles live. Any touched table conservatively invalidates their older grants;
a historical poll at/before a grant's cut does not. The legacy headerless asset
response remains readable, but has no client-side deadline certificate; its
handle still withdraws on any observed change or scope reset. Upgraded-server
expiry proof requires the new header. Returned URL copies and already decoded
pixels cannot be recalled; the claim covers live SDK handles and hook snapshots,
not application-owned byte copies. No meter/auth rule is altered.

## 7. Round 1: evidence is a fence

Round 0's induction was false: resetting a watch did not prevent a subsequent
prediction from evaluating the unapplied replica. Astra also found independent
policy watches, subset replacements and existing asset handles escaping evidence.
The round 0 qualification above is historical, not a claim for these paths.

An evidence fence has two dimensions: the observation attempt revision rejects
work already started, and a minimum applied cut rejects **new** reads of stale
replica state. Local change reports install table fences, including unknown
footprints; accepted authoritative replacements install a same-key fence.
Only a committed, published replica watermark discharges a cut. A private staged
snapshot, a prediction, settlement, receipt, or a failed sync cannot discharge it.
An unknown cut requires a completed sync requested after that evidence; an
already pending request cannot discharge it. Identity/store
changes discard the old scope and all its sources together.

Every local route (direct, watch, presence, remembered, composed and search)
checks the fence. Fenced replica execution/composition/recovery is unavailable;
a current whole server answer may replace it, provided its sequence meets the
fence. Scope/commit revision checks still reject older continuations. A server
answer never clears the replica fence. Matching observations reconcile accepted
whole authoritative data and refusals across all retention policies, with the
same sequence-then-attempt order as remembered answers. Loading and transport
failure do not broadcast authority. A nonempty subset is a replacement too.
Deadlines and input dependencies are installed before any peer callback.

Asset grants additionally belong to their asset id. A current authoritative
E_ASSET_UNKNOWN retires all grants and older in-flight acquisitions of that id,
before listeners run. Transport failure and E_ASSET_VIEWED do not revoke the
already acquired first view. Scope resets and known expiry keep their stronger
existing rules.

Ordinary writes need not be authority changes. A positive non-revocation proof
is deliberately narrow: an ordinary insert/update/upsert to a base table with
an unconditional public read rule, no expiry or inherited authority, and no
derived row lifetime. The query must separately be exactly one direct Get over
a unique immutable key, with only literal, argument or viewer key values, reading
that public base table. Public tables used by rules, authored requires, filters,
compositions or other query forms do not gain this exception. The change feed derives this from its existing bounded
commit scan and the current generation's programs; saturation, unknown programs,
deletes, jobs, seeds, and schema changes fail closed. Mutation receipts carry
their actual touched tables. They certify only their own commit: an unseen gap
withdraws conservatively. A watch can carry its proven validity through adjacent
unrelated receipts without claiming a newer displayed-body cut. Replays without
a footprint fail closed unless already covered by applied/reported evidence. On the
replica, only ordinary put events with no acquisition/snapshot and no live
prediction effects qualify. These updates still rerun queries and reconcile
replacements; only the old answer's authority remains valid while that happens.
Private/rule-dependent updates, removals, unknown footprints and deadlines still
withdraw. This covers the comparative's public profiles without weakening its
membership or deletion paths or interpreting Quarry in TypeScript.

The independent oracle advances server authorization, delivers
evidence, applies sync, and schedules competing read completions. Named regressions
cover Astra's five reproductions; deleting the local change-feed fence must fail.
Round 1 commands, full-suite failure attribution and bytes are recorded in
`reports/20260928-lv-hook-retention/round1/REPORT.md`.

Round 1 also treats a newer generation reported by a query or mutation as a scope
boundary, even with the change feed held. Online historical polls at or below an
authoritative body's cut do not withdraw it. Peer publication preserves the
ordering of a later-started refresh while preventing an older one from replacing
it. Installing a rejected response's deadlines would weaken this rule, so expiry
metadata is installed only after its reply wins the shared order.

The authority key canonicalizes JSON object keys recursively: argument property
order cannot create an independent retained owner, sequence order, or replica
fence. Observation policy still controls subscription lifetime separately.

Round 1 names these compatibility changes as part of the fence: a newer direct
read replaces live peers (including their deadlines); an older competing direct
completion may return loading; a checked whole server replacement can temporarily
replace delivered-history composition while its replica is fenced. Once the cut
is applied, the existing engine's retained-history policy decides the new read.
The provenance controls withhold both the streaming change body and sync, so they
still exercise composition without delivered invalidation. The evidence tests
instead deliver changes while holding sync and require withdrawal. No engine
rule, delivered-history grant, meter allowance or wasm ceiling changed.

Round 1's single complete run returned `== 2 failure(s) in 1200 s` (`cargo test`
and `client tests`). It ran during implementation; its 55 client failures, one
cancelled client test and one Rust failure are preserved with attribution, not
relabelled green. All 79 complete model tests passed. Final affected HTTP, client,

report; the native iOS witness still lacks a dedicated simulator on this host.


## 8. Round 2: authority follows dependencies

Round 1's same-key replacement fence was insufficient. Different arguments and
aliases can read the same revoked data. The authority unit is the dependency
table (including rule-probe tables), conservatively all tables when inputs are
unknown. An explicit empty server footprint certifies no data dependencies;
it must not be treated as missing metadata. No row-level exemption is claimed without a proof of row independence.
A withdrawn observation, reported cut, authoritative refusal, null or subset
replacement installs that dependency fence before callbacks. Exactly matching
canonical read keys share the accepted whole replacement; other affected
observations withdraw, never receiving a differently shaped answer. Observations
already validated at or beyond a known evidence cut need no withdrawal.

Every new local evaluation, remembered fallback and composed answer must satisfy
the dependency floor. A server replacement can cross it without clearing it;
only published replica apply discharges it. Cutless evidence also records an
evidence serial: only a complete sync requested after that serial may discharge
it, and a previously started completion cannot cross it. Finite cuts and unknown
cuts are independent obligations; a later known cut cannot erase an unresolved
cutless barrier. Identity, generation and store resets discard the whole scope.

Disclosure induction: no answer exists initially. Accepted local answers depend
only on tables whose evidence has been applied; accepted whole server answers
must meet every dependency floor and request barrier. Upon evidence, indexed
matching owners receive the replacement and every other affected owner withdraws
before notification. Older in-flight completions fail the dependency floor or
barrier even under a different query name. A newly opened alias cannot bypass
the same check. Withholding, transport failure and unrelated prediction cannot
clear evidence. Applying evidence allows evaluation of the newly authorized
replica. Original expiry, scope and page/facade ownership checks still apply.
This is a client-evidence claim, not instantaneous knowledge of remote changes.

Cost: live observations are indexed by canonical operation/arguments for exact
sharing and by dependency table for refresh/withdrawal. Unknown dependencies
have their own bucket. Each new table authority cut sweeps only its affected
bucket once; repeated replacements at that cut visit only exact matches.
Dependency assignments update the index and closing removes both registrations.
No result scans unrelated observations. Known unrelated mutation footprints now
avoid scheduling a refresh at all (including opt-out observations); opt-out
continues to withdraw whenever a refresh actually starts. There is no new result cache.

The public immutable-key profile proof remains narrow. Online receipts retain
an observation when its validated interval already covers both the historical
receipt and the response's current head; an unseen gap remains invalidating.
Local sync captures prediction effects by table and records admissions and
settlements during the request, so an unrelated notes prediction cannot cancel
the profiles proof. Unknown or relevant effects still cancel it.

Asset evidence compares authority cuts before request-start order (order breaks
ties and orders cutless responses). Refusals revoke only older grants and fence
older in-flight acquisitions of that id. The same ordering protects retained
media before cache mutation, including during asynchronous cache work. Scope
and deadline withdrawal remain stronger. Transport and E_ASSET_VIEWED still do
not revoke a granted first view. Change-feed public-put proofs are cached per
server generation and built directly from program objects, not name searches.

Round-2 regressions, independent overlapping-query/alias histories, cost and
mutation checks, complete-suite failures and wasm measurement are recorded in
`reports/20260928-lv-hook-retention/round2/REPORT.md`.


## 9. Round 3: complete footprints by construction

A dependency fence is sound only if its footprint covers every table on which
the read's authorization or answer can depend. Round 2 omitted read-through
parents of child point reads and non-expiring maintained sources. Its fences
therefore missed real retained owners and new local evaluations. The corrected
footprint is a compiler product, carried as `operations[name].reads` in the
compiled schema and preserved in the server's public device projection.

Start with every read site in the lowered query IR, including untaken branches,
joins, alternate indexes and inlined helper calls. Close that set over read-rule
probes, read-through parents, every maintained source, row-key membership and
parent-key authority, and the sources of maintained columns and timelines
(posts, reposts, edges, authors and all owned/work tables).
Repeat until no new table appears. Neither expiry, row occupancy, successful
authorization, local acquisition nor the runtime branch can narrow this set.
Cycles terminate through a visited set. Maintained-view sources are included
unconditionally; a source's own parents and derivations are followed in turn.
Current Quarry rejects aggregate-on-aggregate declarations; the graph closure
also handles such chains without relying on that restriction.

Private maintained-column implementation tables stay private. Their public
source dependencies are computed before private derivations are removed from
the device schema. Native queries conservatively cover every visible table,
because native code has no static Quarry read body. Raw/legacy schemas without
the footprint certificate conservatively report every schema table. An explicit
empty certificate proves a constant query; absence never means independence.
The field is additive and generated; it changes schema bytes but no authored
program, read rule, partition audience, lifetime or runtime meter allowance.

The shared Rust runner unions this footprint into reported dependencies on both
server and device, after evaluation so dependency bookkeeping cannot bypass or
change the existing word-read meter charges. Execution's expiry-specific
bookkeeping remains distinct from this unconditional published footprint.
The SDK uses the compiled footprint before executing a read, with schema closure
for older metadata, and indexes the reported footprint for existing observations.
Thus parent/source evidence reaches the existing dependency fence on every path:
matching owners receive their replacement, other dependent owners withdraw,
and a new alias cannot evaluate or publish pre-evidence state. No new authority
or row-level independence exemption is introduced.

The disclosure induction in §8 now has its missing premise. Every accepted
answer carries a superset of its complete authorization and answer inputs.
Evidence for any input therefore reaches its indexed owners and the next
read's dependency floor. Expiry and scope checks remain independent. A finite
fence at cut 10 remains in force through applies at cuts 1–9; only published
apply at/after 10 discharges it. Receiving a server replacement never does.

For the public-put proof, capture the outstanding queue's prediction tables
before requesting sync, as well as the revision used to track admissions and
settlements during the request. All captured pending ids must have known queue
entries and the pending capture must be complete. Relevant or unknown effects
cancel the proof; an outstanding notes prediction does not cancel a profiles
proof. Effects admitted between queue inspection and capture are rejected by
missing-id or revision checks. Unseen gaps, destructive events and unknown
footprints still fail closed. This extends §8's during-request treatment to
predictions already pending when capture begins.

Online mutation receipts share a validated-through cut across indexed owners.
The first receipt, an unseen gap, or an unknown footprint inspects every owner's
interval. Thereafter an adjacent receipt with a known footprint visits only its
affected buckets; unrelated owners inherit the advanced cut lazily. Covered
replays do no work. New bodies still meet the client's publication floor, and
scope/reset clears the shared receipt cut. Thus 400 adjacent unrelated receipts
over 400 owners perform 400 visits, while a subsequent gap still withdraws all
old owners. This changes traversal cost without assuming unseen commits safe.

The independent census derives graph edges from compiled schema declarations
and read roots from serialized IR, without consuming the production footprint
walker or `operations.reads`. It checks the compiler, HTTP server, process and
wasm outputs, including projected maintained-column sources. The independent
history model now generates intermediate replica applies below delivered cuts;
a named finite-fence regression additionally checks every intermediate cut and
new alias. Named real-client regressions cover transitive parent evidence,
non-expiring sums and the comparative's already-pending notes prediction.
Round-3 commands, counterfactual failures, full-suite attribution and wasm bytes
are recorded in `reports/20260928-lv-hook-retention/round3/REPORT.md`.

## 10. Round 4: ephemeral evidence has its own clock

Durable sequence equality does not prove an ephemeral answer current. Ephemeral
writes advance an epoch within a server incarnation without advancing `seq`.
An accepted whole ephemeral answer (including null, subsets and refusals) raises
the epoch floor of its compiled ephemeral dependencies. Change notifications
raise the floors of their named ephemeral tables. These floors belong to the
client scope, survive owner removal, and cover direct reads with no owner.
They are independent of the durable dependency cuts and are never discharged
by replica apply: ephemeral rows are server-only.

Before callbacks, withdraw every overlapping owner with an older ephemeral
answer. Owners already at that epoch and owners of unrelated tables remain
valid. This includes the accepting owner's previous answer: if withdrawal
retires its current fetch, its normal refresh reads again. Matching keys share
checked ephemeral replacements through the existing reconciliation path. Index
interests by table, and visit only buckets whose floor advances. A read with
unknown dependencies covers all ephemeral inputs conservatively. Withheld and
transport-failed responses cannot advance an answer's floor or displayed epoch.

Round 5 closes the discovery gap: every online query captures an incarnation
revision before dispatch, even without generated hints or a loaded schema.
Wire-provided ephemeral versions must pass the fence. Until ephemeral-specific
dependencies are known, use the returned complete table footprint, conservatively
including durable inputs. Register both the accepting observation and matching
peers receiving its replacement before they can display the answer. If even the
wire footprint is absent, the owner covers every table and meets every floor;
its poll omits the table filter. A direct-only client needs no schema discovery
or mounted owner for these checks. On schema-backed clients, missing ephemeral
operation metadata falls back to the complete read certificate filtered by
ephemeral table declarations, or all ephemeral tables without that certificate.
Missing metadata never certifies independence or permits replica caching of an
ephemeral answer. Explicit empty certificates keep their existing meaning.

Every reply must meet every relevant epoch floor, including delayed direct
reads and the final publication check after an asynchronous continuation.
Incarnations are not numerically ordered: adopting a new one retires all old
request revisions before inspecting subsequent replies, resets interests, and
starts a fresh set of floors. A buffered reply from a retired revision cannot
adopt the old incarnation again. Query evidence must not advance the change
poll's coverage cursor, since that could hide changes to other tables.

The disclosure induction therefore uses both clocks. Before evidence, retained
answers remain subject to their deadlines. Processing evidence withdraws older
overlapping answers before notification and leaves a persistent epoch floor.
Every older completion, even under a new alias or without an observation,
fails that floor; neither equal durable cuts nor replica publication releases
it. Current server answers recover normally. Original identity, generation,
request ordering, durable fences and deadlines remain independent obligations.

on online, process and wasm, independently generated ephemeral histories,
and row-keyed-view censuses covering compiler, server and device certificates.
The supervisor runs the complete landing suite; this round runs affected checks

lifetime test removes the final owner before delivering an old buffered reply,
then remounts. Evidence is in `reports/20260928-lv-hook-retention/round5/REPORT.md`.


## 11. Round 6: admission and authority are separate evidence

An HTTP admission refusal (normally `E_RATE_LIMIT`) rejects a request before evaluating the query or asset. An evaluated native refusal may use the same code and is governed by the origin classification below.
It preserves FU's code, retryability, transport causes, link state and bounded
jittered backoff; it supplies no row/asset revocation evidence. An exhausted
query returns that refusal to its direct caller without replacing matching
observations, forgetting remembered answers, raising durable fences or advancing
ephemeral floors. A mounted refresh keeps its still-authorized answer marked
revalidating, under its original deadlines. Initial and opted-out reads expose
the refusal. Terminal change-poll refusals still stop polling and surface as
FU specifies. Existing invalidation always takes precedence over retention.

An asset overload likewise leaves grants and retained media intact. A validated
`E_ASSET_UNKNOWN` carries its captured authority cut through decoding and uses
§8's grant/refusal order before revoking handles or media. `E_ASSET_VIEWED` does
not revoke an acquired first view. Credential rotation cannot justify replaying
an ambiguous once-view transfer; an obsolete success is released, and a failed
local media fallback preserves the actual download refusal/cause.

The round-6 matrix classifies every LV added/changed awaited expression, including
moved media helpers and online refresh, with transient and persistent cases beside
real FIFO custody. Existing required/optional classifications remain unchanged.
Astra's round-5 missing-certificate Low adds process/wasm regressions deleting both
`reads` and `ephemeralReads`; the fallback remains all ephemeral schema tables.
Combined qualification and failures are recorded in
`reports/20260928-lv-hook-retention/round6/REPORT.md`.

A terminal local denial contains no protected data and needs no revalidation of
its retired request signal. Online read acceptance therefore returns terminal
absence immediately when the client is closed, has lost credentials, or has a
terminal store refusal. Public return paths still choose the current terminal
refusal, and all data, live-credential and incarnation fences remain mandatory.
This avoids three stale-response waits after termination without increasing any
retry allowance or test timeout; round-6 terminal regressions pin zero waits.

Round 7 extends the same admission-refusal treatment to failures that contain no
evaluated authority. In particular, malformed HTTP 200 and 404 bodies decode to
`E_HTTP_RESPONSE`, not a server denial of the query. The direct caller, initial
observation and opted-out observation keep that diagnostic. A retained owner
keeps its original answer, dependency footprint, authority cuts, presence interval
and deadlines. Neither a matching observation nor a differently shaped alias is
withdrawn; remembered data is not deleted, and neither durable nor ephemeral
floors advance. The check precedes local cache/order mutation and ephemeral
acceptance, including the composed-search route, and online reconciliation.
Existing scope/evidence/deadline checks still win. This classification changes
neither FU's link-state rules nor its retry policy: malformed query 200/404 stays
online; malformed 5xx follows the existing offline transport path.

### Round-9 origin audit (corrects round 7)

Round 7's code exclusions were wrong: native programs pass their error codes
through unchanged, even though Quarry reserves `E_`. A native authorization
check returning `E_HTTP_RESPONSE` or `E_STORE_BUSY` is evaluated evidence. No
code, family or retryability value can substitute for a failure's origin.

`http-response.ts` attaches a private, non-enumerable origin field to refusals
it creates (`transport`, `decoder`) or receives through the HTTP admission lane
(`admission`). This field is retained with the refusal through online queries,
local fallback and composed search; it does not alter the public refusal's JSON
or generated `Refusal` contract. Publication consults that field only. Native
and other evaluated device denials have no SDK failure field and are evidence.
The HTTP decoder's 5xx/offline decision also consults decoder origin rather
than an application-controlled `E_HTTP_RESPONSE` spelling.

The server query reply explicitly carries `refusalOrigin: "evaluated"` after
opening the query transaction and capturing its cut; before that boundary it
carries `"admission"`. This origin overrides HTTP status, so an evaluated reply
is evidence even with status 503 or a code usually used for overload. The
transport recognizes the existing HTTP 429/503 admission lane when no evaluated
origin is supplied (including older servers and the connection acceptor). Other
validated HTTP refusals retain their prior checked-refusal treatment. Malformed
bodies are always decoder failures, regardless of status or claimed wire origin.
HTTP admission status is a transport outcome, not a code-string exclusion.

| Origin / outcome reaching publication | Authority treatment |
| --- | --- |
| SDK transport failure (`transport`) | No authority. Preserve the actual cause, diagnostic and existing link behavior. |
| SDK response decoding/validation failure (`decoder`) | No authority, including malformed HTTP 200/404, missing/invalid search overlap proof, and missing device search-ledger metadata. Initial/direct/opted-out reads expose the diagnostic; retained reads keep their original deadlines. |
| HTTP admission failure (`admission`) | No authority. Preserve FU's diagnostics, bounded retry/backoff and link rules. No remembered-data deletion, reconciliation, durable fence or ephemeral floor. |

## 12. Round 8: expiry retries preserve the requested page

An ordinary page retry uses that invocation's original arguments. A first-page
call with `c: null` must retry with null; it must not adopt `next` from an expired
local candidate or a discarded server reply. A subsequent call with `c: next`
must retry with that same input cursor, without advancing it or resetting it to
null. Expiry still withdraws the invalid answer before fallback, and publication
still checks deadlines and all authority fences. The returned continuation belongs
only to the accepted answer. This preserves LLP 3000.016 §2.2's original-arguments
fallback and LLP 3000.028 §3.1's existing expiry/publication fences; it does not
change §3.3's separate one-invocation mixed-search contract or meter limits.

The retention fence can retire either page's in-flight attempt when expiry
evidence arrives through `/changes`, even if a direct server reply already
reported that cut. Retrying the second invocation is therefore legitimate.
Round 1's test migration incorrectly allowed multiple requests only for page one:
it checked a combined request log as though the final request were the entire
second invocation. The supervisor's round-6 failure exposed that test assumption,
not a leaked retained cursor. No product change is needed or made in round 8.

The fixture's freeze checks run when fetch returns, while change polls can return
heartbeat headers before their final JSON body. A poll started before the freeze
can consequently deliver expiry evidence during the continuation. A controlled
replay on round-7 product bytes holds that real body until the second call has
started, processes its cut with sync still parked, and produces requests
`null, next, next` on both wasm and process. The old assertion fails on both;
the returned pages are correct. This reproduces the failure mechanism without
changing authority or manufacturing response metadata.

The revised test checks requests separately before and after starting page two.
Four deterministic cases cover direct/observed first pages on both hosts, require
the continuation retry, reject the expired local branch's cursor, and enumerate
all surviving rows exactly once, omitting an expired second-page row. Existing
withdrawal assertions still require loading while the fallback is held. The
round-8 report records reproduction, qualification, full-suite result and bytes.
