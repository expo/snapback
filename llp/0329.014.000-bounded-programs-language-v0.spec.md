## Summary

This is the language of [LLP 0329.014](./0329.014-bounded-data-programs-panel-synthesis.research.md)
§2 written down as a checkable target, with the corrections the archetype stress
test ([LLP 0329.015](./0329.015-app-archetype-stress-test.research.md)) forced:
declared aggregate disclosure (K2), interval columns and time as durable
transitions (K5), constraints that bind every write (K6), scheduled and system
authority (K7), and a host-maintained tree closure (workspace §6.2). It exists so
that two things can be run against a *fixed* target rather than a moving synthesis:
the paper-archetype exercise ([LLP 0329.014.001](./0329.014.001-paper-archetypes.research.md))
and the spike (0329.014 §8). It is a falsification target, not a product surface;
every unresolved author decision is listed in §10 with the default this document
assumes.

The design in one sentence: **one TypeScript-syntax language for queries and
mutations, whose every data access goes through a typed, bounded, traced API;
whose rules are algebraic predicates in the same language and the only
authorization; whose admission is a static certificate of read shape and bound;
and whose execution trace is simultaneously the invalidation predicate, the offline
closure, the OCC set, and the completeness detector — so that any admitted program
is live, retained, authorized, and locally predictable, with no second query class.**

## 1. Kinds

| Kind | Where | What it is | Live | Retained | Predicted |
|---|---|---|---|---|---|
| `table`, `index`, `rule`, `constraint`, `maintain`, `tree` | schema | durable relations, their access paths, their authorization, their invariants, and their derived rows | — | — | — |
| `query` | data plane | a bounded data program that reads | yes | yes | (re-executed locally) |
| `mutation` | data plane | a bounded data program that reads and writes | — | — | yes (same program runs locally) |
| `schedule` | data plane, system principal | a mutation invoked by the engine at a time or interval | — | — | — |
| `channel` | ephemeral | fan-out of transient state (typing, presence) authorized by rule expressions | yes | no | no |
| `effect` | outside the data plane | JavaScript with I/O, at-least-once, never client-callable, writes only by calling named mutations | no | no | no |

There is no other kind. In particular there is no handler, no "JS query", no
app-authored optimistic reducer, and no per-query authorization or retention flag.

## 2. Schema

```ts
import { table, id, text, int, bool, time, ref, interval, json, unique, cap, appendOnly, maintain, tree, tokens, viewer, public } from 'backend'
```

**Column types.** `id()` (client-mintable), `text({ max })` (max required),
`int()` (i53 in v0; overflow is a refused write), `bool()`, `time()` (integer
ms), `ref(table)`, `json({ maxBytes })` (opaque to rules and indexes),
`interval({ from, to })` — a validity interval on the row; `to` may be open. All
scalar comparisons are total; strings compare by codepoint; there is no locale.

**Indexes.** `.index('byX', ['a', 'b', 'at'])` — ordered composite keys; a scan
supplies a prefix of the leading columns and a range or order on the next.
`.index('byToken', tokens('body'))` — an engine-maintained inverted index; a scan
takes one token as its prefix. `.unique('byHandle', ['handle'])` — a unique index
is both an access path and a constraint.

**Constraints — permissions on operations, enforced by the engine on every
write, because there is no write path outside the language (K6).**
`unique(...)`; `cap({ by: 'resourceId', max: N })` — a schema-level cardinality
bound on a child collection, refused at the write that would exceed it (this is
what makes an exact-or-refuse read admissible: §4.4); `appendOnly()` — no
`update`/`delete` for any principal; `immutable(['amount', 'account'])` — fields
that no `update` may change; `exclusion({ on: ['resourceId'], interval: 'when' })`
— no two rows with the same `on` key may have overlapping intervals (booking's
central invariant; a schema fact, so every write checks it).

**Maintained aggregates.**

```ts
maintain.count(cards,   { by: ['columnId'],          as: cardCount,   overflow: 'refuse' })
maintain.sum(shares,    { by: ['groupId', 'userId'], of: 'amount', as: owed })
maintain.count(entries, { by: ['resourceId'], where: e => e.state === 'waiting', as: waitingCount,
                          readable: e => canReadResource(e.resourceId) })   // K2: declared disclosure
```

Semantics: same-commit maintenance generated by the compiler (insert +1, delete
−1 from the preimage, group move −1/+1, retry-idempotent, declared overflow);
online backfill on schema succession (chunked, resumable, digest-verified before
cutover). Reading one is `db.get(name, key)`. **An aggregate's own `readable` rule
is a disclosure declaration**: if omitted, the aggregate is readable exactly where
every contributing row is readable to the reader (the compiler proves it or
refuses); if present, the author is declaring that a number summarizing rows the
reader may not see is disclosed under that rule, and `check` emits a security
item naming the source table. Computing such a number silently under caller
visibility is never admitted (§9, `E_STRUCTURAL_COUNT`).

**Tree closure (workspace §6.2).** `tree({ parent: 'parentId', path: 'path', depth: 'depth', maxDepth: 32 })`
on a table declares a host-maintained materialized path: every write of
`parentId` rewrites the subtree's `path`/`depth` in the same commit, refuses
cycles and depth overflow, and exposes `byPath` as a prefix-scannable index. This
turns recursive ACL and subtree operations into one indexed read plus a bounded
`patchWhere`, both performed by the engine.

## 3. Rules

Each table declares, per effect, a single expression; missing rules are a
`check` error, not a default.

```ts
export const messages = table({ ... })
  .index('byConvTime', ['conversationId', 'at'])
  .rules({
    read:   m => db.exists(memberships.byConvUser, [m.conversationId, viewer]),
    insert: m => m.authorId === viewer && db.exists(memberships.byConvUser, [m.conversationId, viewer]),
    update: never,
    delete: m => m.authorId === viewer,
  })
```

Rule bodies are **algebraic predicates**: field comparisons, `&&`/`||`/`!`
(negation is admitted — denials are expressible), `exists`/`get` on indexes with
*shape* keys (fields of the row, `viewer`, literals), interval containment
(`m.when.contains(t)` where `t` is a shape expression), and `public(reason)`.
They contain no statements, no loops, no clock. A rule whose inputs are pinned by an
equality filter on the enclosing scan is *hoisted* and evaluated once per
execution; otherwise its per-row probe cost is reported in the certificate
(§10 D-F). Rules may reference the principal's kind: `principal.kind === 'system'`
admits scheduled mutations (§7).

`public(reason)` is the only way to make a table world-readable; it unlocks no
capability and emits a security item in the build receipt.

**Time in rules.** Rules are time-independent. Expiry, deadlines, and windows are
**durable state transitions** written by a scheduled mutation (§7) — "expires at
5:00" means "a scheduled transition flips `status` within one schedule period of
5:00, and revocation is instant" (K5; auction and workspace product rulings). A
query may additionally declare a bucketed `readTime` for display filtering (§4.3);
it never widens authorization.

## 4. Programs

### 4.1 Syntax

A TypeScript subset, type-checked by `tsc` against a custom `lib.d.ts` in which
`Date`, `Math.random`, `fetch`, `setTimeout`, `import` of anything but `backend`,
`eval`, and dynamic property access on tables do not exist. Admitted: `const`,
`let`, `if`/`else`, ternaries, `for (const x of <bounded>)`, `for` over a literal
range, `break`/`continue`, object and array literals, destructuring, template
strings, arithmetic, comparisons, `Map`/`Set`, `Array.prototype` methods with a
comparator where order matters (`sort(cmp)` is stable), pure helper functions
defined in the module (inlined at `check`). Refused with a rewrite: `while`,
recursion, `async`/`await` inside data programs, closures escaping the program,
any read outside `db`.

### 4.2 Data API

```ts
db.get(table, key)                      // Row | null   — point read, examined ≤ 1
db.get(table.byUnique, key)             // Row | null   — unique-index read
db.get(aggregateName, key)              // MaintainedRow | null
db.exists(table.byIndex, key)           // boolean
db.scan(table.byIndex, prefix, { order?: 'asc'|'desc', take: N, after?, before?, range?: { gt|gte|lt|lte } })
                                        // Page<Row, N>: an array with .hasMore; N literal or arg with declared max
db.scan(table.byToken, [term], { take }) // Page over an inverted index
recurse(seed, step, { depth: D, fanout: F })  // bounded traversal along shape-keyed reads; visited-set
db.insert(table, row); db.update(table, key, r => patch); db.upsert(table, key, r => row); db.delete(table, key)
db.require(cond, code)                  // refusal with a stable code; aborts the transaction
db.consumeAssetGrant(id) / db.media.*   // asset service seam; returns a provisional slot
```

**Bounded set writes (K3).** `for (const r of db.scan(...)) db.update(table, r.id, r => …)` is the
predicate-selected update; its bound is the scan's `take`. `patchWhere`,
`deleteWhere`, `patchEach`, `insertEach` are library forms that lower to the same
IR. There is no unbounded set write; a subtree move over a `tree` table is the
engine's maintenance, not the program's loop.

**Loop domains carry static cardinality** (0329.014 §2 rule i): a `Page<N>`, a
literal, an argument list with a declared `max`, or an array derived from a
schema-bounded column (`text({ max })`). **Read keys are shape expressions**
(rule ii) — args, `ctx.viewer`, literals, fields of rows from traced sites, total
scalar functions of those — or the read site is marked `computed` in the
certificate, which disables prediction closure for that site and nothing else.

### 4.3 Modeled inputs

`ctx.viewer` (principal id) everywhere. In mutations only: `ctx.now()` and
`ctx.newId()`, **bound at intent time**, carried in the envelope, validated by the
server (skew window, id format) and reused, so prediction and settlement agree;
`ctx.commitTime` when a schema column is declared `commitTime` (provisional
locally, settled by the server). In queries that declare
`{ readTime: { granularityMs } }`: `ctx.readTime`, a bucketed clock that enters the
read set as `clock@granule` and is re-evaluated by the server at bucket boundaries
and by the client with its own clock offline. Ambient clocks are refused.

### 4.4 Cardinality and aggregates

`Unbound<T>` is a legal intermediate and an illegal result; `Page<T,N>` executes;
`Row<T>` executes; `Maintained<T>` is a point read. `page.count()` and
`page.reduce(...)` are exact over the page; `page.countCapped()` returns
`min(n, N)` with an `atCap` flag; exact over a growing population is **only** a
maintained aggregate. `All<T,N>` (exact-or-refuse) is admitted only over a
collection whose cardinality the schema enforces with `cap`. Ranked selection —
`argMax`, `topK`, first-matching — is a loop or `sort(cmp)` over a `Page`, exact
over the page, or a maintained row for the global case (auction: "highest bid
wins" is a maintained `max` keyed by auction, or a page over `bids.byAuctionAmount desc take 1`).

### 4.5 Money and determinism

Integer arithmetic on i53 with refused overflow; `divmod` with a stable remainder
sink chosen by a deterministic tie key (ledger: "non-deterministic remainder breaks
optimistic prediction"). No floats in monetary columns (`int()` in minor units).

## 5. Certificate (emitted at `check`, beside the generated client)

```
planHash, schemaHash, ruleHashes, evaluatorVersion, valueModelVersion
readSites[{ table, index, prefixTemplate: arg|viewer|const|shape|computed, take, maxCalls, hoist }]
writeSites[{ table, kind: insert|update|delete, maxRows }]
maintainedAmplification, constraintChecks[]
maxExamined, maxIndexEntries, maxRuleProbes, maxSteps, maxHeapBytes, maxOutputBytes, maxClosureBytes
resultType (cardinality-typed), completeness: page|capped|maintained|all
predictionSites[{ transition, reads, mode: closed|conditional|partial }]
readTime?: { granularityMs }, haloRows, indexesRequired, disclosures[]   // K2 items land here
```

Admission refuses above the app's ceilings (`G` is a family — examined entries,
index entries, steps, heap, output, closure, rule probes, write amplification —
each with a loud default). Ceilings are compile-time facts of the plan, never
functions of invisible-row counts.

## 6. Execution, trace, states

The server runs the IR in one Rust interpreter inside the SQLite transaction (JS
never in the authoritative path). Every execution records an **authoritative
trace** — actual dependencies including hidden rows, ranges, and rule inputs —
used for invalidation (a commit overlapping a traced range or rule-dependency key
reruns the subscription and diffs) and OCC on multi-writer stores. The client
receives a **closure receipt** — authorized rows, visible ranges with stop reason
(`limit`/`exhausted`) and absences, projected row N+1 and the authorized key of
N+2 (or an exhaustion fact) for delete-capable pages, and scoped verdicts bound to
`(ruleHash, pinnedInputsDigest, principal, authEpoch)` for rules over hidden inputs
— never hidden range extents. Both are asserted `⊆` the certificate.

Local re-execution is exact while `Reads(P, D₀ ⊕ Δ) ⊆ Coverage(receipt ⊕ Δ)`;
otherwise `partial`, never invented. States: reads `hydrating|fresh|stale|partial`;
intents `predicted|queued|committed|rejected`. One engine-owned store-wide
`maxOfflineAge`; sign-out destroys the per-principal store key; reconnect
re-authorizes before outbox replay and evicts rows held by no range.

Client = per-principal encrypted store of delivered rows indexed by
`(table, index)` with range coverage at one version + verdict cache + outbox +
evaluator (§10 D-A) + one hook per framework. It cannot issue a query the model
did not name.

## 7. Schedules and system authority (K7)

```ts
export const closeAuction = mutation({ auctionId: id(auctions) }, ({ db, ctx, args }) => { /* settle */ })
schedule(closeAuction, { at: a => a.closesAt, key: a => a.id, principal: 'system' })
schedule(sweepExpired, { every: '1m', principal: 'system' })
```

A schedule is a durable, transactionally enqueued invocation of a named mutation
under the `system` principal: enqueue happens in the commit that creates or
changes the trigger row; execution is at-least-once with the schedule key as the
idempotency key; a run is generation-fenced (a schema successor re-validates
pending runs); rules admit it via `principal.kind === 'system'`; failures are
retried with a declared policy and surfaced as a state on the trigger row. Read
elevation is never needed to settle: the mutation's writes are bounded owner rows
selected by the schedule key, and its certificate is ordinary.

## 8. Channels

```ts
export const typing = channel({ conversationId: id(conversations) },
  { publish: a => memberOf(a.conversationId), subscribe: a => memberOf(a.conversationId), ttlMs: 4000 })
```

Ephemeral fan-out; `publish`/`subscribe` are rule expressions over durable rows
(one probe each); no persistence, no trace, no retention, no prediction. Persisting
presence as rows is a product diagnostic, not a type error.

## 9. Refusals

About twenty families, each carrying a span, the violated invariant, and one
rewrite that never weakens authorization: `E_UNBOUND_SCAN`, `E_UNBOUND_LOOP`,
`E_UNBOUND_COUNT`, `E_BOUND` (ceiling exceeded, with the product that produced the
number), `E_COMPUTED_KEY` (informational: prediction `partial` at this site),
`E_AMBIENT_TIME`, `E_OPAQUE` (a construct outside the subset), `E_RULE_MISSING`,
`E_RULE_UNBOUNDED` (with the schema-split / maintained-closure pastes),
`E_PUBLIC_IMPLICIT`, **`E_STRUCTURAL_COUNT`** (a count or sum over rows the caller
cannot read, computed under caller visibility — the K2 class; rewrite: a maintained
aggregate with a declared `readable`, or an argument-scoped count over the
caller's own rows), `E_CONSTRAINT` (unique/cap/appendOnly/immutable/exclusion
refusal at the write, sealed: it never discloses which hidden row conflicted),
`E_FANOUT` (a bounded set write whose `take` reached `hasMore`), `E_EFFECT_NOT_LIVE`,
`E_NOT_ATOMIC` (find-or-create without a unique key), `E_SCHEDULE`, `E_STEPS`,
`E_OVERFLOW`, `E_PARTIAL_PREDICTION` (informational), `E_DISCLOSURE` (informational:
a declared aggregate readable beyond its sources).

## 10. Open author decisions, with the default this spec assumes

- **D-F Bound model for rules.** *Assumed:* scans are ceiling-bounded (`take`
  required); rules are admitted when index-served, hoisted when pinned, otherwise
  reported as per-row probe cost with a runtime budget that fails closed; the
  diagnostic suggests, never requires, the schema split or maintained closure.
- **D-A Client evaluator.** *Assumed:* a generated TypeScript evaluator on every
  arm behind a frozen cross-engine corpus and the hydration replay check; the Rust
  interpreter is the reference; a Rust→WASM core may replace it on web behind a
  size gate. Never a native module in v1.
- **D-D `maxOfflineAge`.** *Assumed:* 24 h default, 7 d hard maximum, shortenable.
- **D-G Time.** *Assumed:* transitions by schedule in v0; `readTime` buckets for
  display; no clock in rules.
- **D-H Spelling.** *Assumed:* TypeScript syntax; SQL text as a second front end
  is measured, not assumed.
- **D-I Maintenance.** *Assumed:* explicit `maintain` in the schema; the compiler
  proposes it in `E_UNBOUND_COUNT`/`E_STRUCTURAL_COUNT` rewrites.

## 11. Classification rubric (for LLP 0329.014.001 and any later paper exercise)

For every operation an application needs, record:

1. **Class:** `plan` (a query or mutation in this language, with its certificate line) ·
   `refused → rewrite` (the diagnostic family and the paste that makes it a plan) ·
   `maintained` (needs a schema aggregate) · `schedule` · `channel` · `effect` ·
   `product-change` (the requirement should change; say when that is a cheat).
2. **If not a plan, what is missing**, by kind: *language construct* (a new
   operator or syntax) · *schema feature* (constraint, interval, tree, aggregate) ·
   *runtime axis* (scheduler, system authority, asset seam) · *policy declaration*
   (a disclosure the author must state) · *product* (no backend can do it as stated).
3. **K2 check** for every count/sum/rank: is it *about the caller* or *about the
   resource*? If the latter, which declared route (maintained + `readable`, or
   argument-scoped) — and would a silent visibility-filtered version have returned a
   wrong number?
4. **Integrity check:** which invariants are enforced by constraints that bind
   every write, and which remain program-level `require`s.
5. **Prediction check:** for each mutation the UI predicts, is the prediction
   `closed`, `conditional`, or `partial` under §4.2's key-provenance rule, and why.
