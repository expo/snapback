## 3. Acknowledgements proportional to changed state

Keep `deliveryAcks` as the durable source of truth. Add a private derived index
owned by `PersistentRangeStore`: pending event keys and bound intent-to-event
keys. Build it once from the loaded state, and update only changed acknowledgement
keys after successful persistence. It contains keys, not duplicate row bodies.

Pending admission selects at most the next 50 identities of one log, alongside
the number of remaining batches computed from per-log pending counts. Replace
the full pending projection with this bounded selector in the pre-promotion
custom `OutboxStore` interface and document the change. Readiness needs counts
and a next operation, not every pending identity. Empty or blocked pending work
must not enumerate held history or repeatedly regroup a large backlog. A stable
insertion-ordered pending queue per log puts accepted redelivery at the end;
unadmitted receipt selection order is not durable FIFO custody. Once admitted,
batch membership, envelope bytes and FIFO/grant accounting remain exact.

Cleanup candidates are the union of changed acknowledgement keys, changed log
row keys, and acknowledgement keys bound to changed/removed outbox intents.
Read the last committed reverse index while assembling candidates; the journal
contains the final state after success compaction. Evaluate the existing cleanup
predicate on those candidates only. A bounds/program adoption removing receipt
operations may inspect all retained marks once because it changes their governing
policy. Compare the distinct retained log names against incoming bounds: a
full sweep is needed only when a retained receipt operation is absent, including
inconsistent loaded marks; repeating preserving bounds must not rescan history. The journal records
compaction removals and per-row evictions; explicit root replacement of rows,
outbox or acknowledgement state requires a full reconciliation once. Cold load
and explicit whole-state replacement may also rebuild once.
Ordinary page/ack/grant transactions may not fall back to full-history scanning.

The index is never durable authority. Failed persistence leaves it at the prior
committed state; the journal rolls back normally. Update it synchronously after
durability and before any observers or queued readers run. Reopening or changing
partition rebuilds from that partition; wiping clears it. Sealing exposes no
projection. Reset, event eviction, terminal retry and receipt removal must match
the existing scan implementation, including the case where event and intent
disappear in different commits.
Use the existing serial store owner for both bounded selector reads and index
publication. No externally observable state/index interval is allowed. If an
index update cannot complete after durable commit, invalidate and rebuild it
before a future read; never roll back already-committed durable state.

## 4. Project admission inputs inside their existing owner

Instrument selector names in an ignored diagnostic build to attribute the
remaining `readOutbox` copy cost. The code already loads `outbox.programs()` during
every admission merely to compute `admittedMutationTargets`; this is a concrete
candidate, not proof it accounts for all sampled copy time.

Compute that small target projection within the carrier's serialized unsealed
read, using the held program, and return detached target data. Preserve existing
public detached `programs()` reads for callers that need the full program; do
not return a cached mutable program or skip current-program validation. Reuse
the existing target function, including unknown/malformed program behavior.
Prefer a private capability or narrowly documented store selector over a new
general caching abstraction. Custom carrier behavior must stay explicit.

Do not bypass normal admission for acknowledgement operations based on their
name: grant bounds, target validation and immutable envelope custody still apply.
Any other selector optimization requires measured attribution and equivalent
mutation-isolation and lifecycle tests; avoid speculative caches of dynamic
authority, grants or queue state.

`OutboxLedger.queued()` also currently detaches all terminal history before
filtering. Select queued entries inside the store before copying, keeping the
current `all()`/`outboxOrder` comparator (including createdAt and code-unit
tie-breaks), not the distinct `outboxFifo` comparator, and detached return contract. Full `all()` remains for
public work/history reads. No new retained terminal cache is needed.

## 5. Avoid redundant query work without suppressing progress

Source audit distinguishes two paths. `subscribeInputs -> queries.refresh`
performs local reevaluation only. `drainQueued -> logTail` fetches the first
persisted drained query after every committed mutation. The small `groups.mine`
drain finishes first, making it the tail fetched for each acknowledgement.
Verify this causal chain with a request-count control before measuring savings.

For an engine acknowledgement with no prediction, a matching held and committed
plan/schema identity, and an owner-reported empty observable-effects list, settle
the terminal without fetching the unrelated application tail. Identify the
operation through the held schema's receipt-enabled delivery declaration and
its generated mutation, not an arbitrary name prefix. Require matching admitted
identity; missing/mismatching identity or nonempty effects keeps the ordinary
tail path. Receipt changes may drive maintained effects; those cannot be assumed
empty merely because the mutation is engine-owned. Successful compaction still
uses its existing owner-effect proof. Do not fabricate rows, coverage, query
observation, watermark progress, or fence renewal from a mutation terminal.
Ordinary product mutation tail/failure behavior remains unchanged. Update LLP
1012's settlement text and LLP 1019 with this explicit bounded exception.
Eligibility must remain true through the serialized terminal swap: retain
principal, cancellation and coverage guards, and check the current governing
program/overlay in that turn. Changed identity or authority cannot publish a
terminal from a skipped swap. Preserve `recordTerminal` only after durable
settlement. Missing/malformed effects are not an empty list. Admitted target
identity need not have `complete: true`: generated acknowledgements have a
repeated receipt-table target, while the owner's actual effects determine the
settlement obligation. Nonempty maintained effects always keep ordinary tail
behavior.

For local observers, classify changes as semantic or item-only. Outbox and
compaction bookkeeping with no affected overlay can refresh item entries and
`compactedThrough` while preserving the current query data, receipt and clock.
Changes involving an overlay before or after settlement remain semantic.
Use the journal's changed categories and prior overlay custody, not guessed
table dependencies. Thread the distinction through the existing shared refresh
owner; a pending or in-flight semantic refresh dominates an item-only nudge.
Keep one-shot queries' current presentation-only behavior.
The store/runtime listener carries `semantic | items` (an absent kind from a
custom carrier means semantic). A pending refresh kind joins by semantic
dominance. Item nudges latch while a semantic evaluation runs without cancelling
it; afterward current item inputs are published. Semantic/direct events invalidate
stale in-flight results. An item refresh cannot overwrite a newer semantic image.
Compaction still advances `ItemInputs.compactedThrough`, so prior item snapshots
become changed; it does not advance their row observation. Alias removal is an
item change. Prior overlay custody must be captured before journal mutation.
Alternatively, make deletion of an absent journal key a no-op: a real removed
overlay is then present in the journal, and an unchanged retained overlay is
present in final state. Together those establish before/after custody without
copying the whole overlay dictionary. Do not classify the ledger's allocation
counter as a query execution clock.

Clock, auth, program/generation, reset, denial/revocation, one-use viewing,
outbox terminal and writer/follower transitions must remain observable. A stale
result from a refresh started before a later change must not publish afterward.
Coalesce only within an existing bounded turn; never delay all updates until
catch-up ends, hold a transaction across a network wait, or wait for an ack to
make already-durable content readable. If the investigation proves the groups
requests necessary, retain them with the causal explanation rather than hiding
them from the benchmark. No server-side policy-identity narrowing is included.

## 6. Verification and measurement

Use existing test files and witness scripts, with temporary diagnostic variants
under ignored run directories. Add no required check or standalone framework.
Meaningful controls:

1. Indexed acknowledgement state agrees with the former scan semantics across
   accepted delivery, duplicate/retry/redelivery, rejection/expiry, event eviction,
   intent compaction/removal, receipt removal, reset, failed persistence and reopen.
   Include both orders of event versus intent removal and same-swap removal.
2. A large retained history with a small new page visits only changed candidates;
   pending-empty reads visit no history. This is an algorithmic regression test,
   not a fragile wall-clock assertion or a claim that all acquisition is linear.
   Include a large pending backlog with constrained grants, repeated blocked
   admission/status reads, and aggregate visits across its complete drain.
3. Admission targets equal the old projection for creates, argument-derived
   targets and unsupported operations; mutating returned values cannot mutate
   the program or future admissions. Partition/seal changes and failed swaps
   cannot reuse stale derived state.
4. Public subscribed queries, items and outbox work update for relevant rows,
   terminal writes, tombstones, clocks/reset and follower transitions. Unrelated
   acknowledged history does not cause the specifically eliminated refresh.
   Controlled promises cover semantic→item and item→semantic while scheduled
   and in flight, semantic→semantic, reset/auth during either, and finite item
   bursts: latest semantic state progresses and final item state is current.
5. Preserve the same durable message hash, never-opened held thread/search,
   interrupted prefix, pending IDs/bytes, physical browser reopen, and eventual
   receipt completion. Compare foreground sends during and after catch-up.
6. The no-tail branch preserves same-envelope replay after lost response or
   failed terminal persistence; missing/mismatched identity, authored lookalikes,
   nonempty/malformed effects, and program/overlay changes between eligibility
   and the terminal swap take the conservative path or retain queued custody.

Measure baseline/candidate with identical compiler/owner, package build settings,
fixture, browser, carrier, and endpoint criterion on a checked fleet host. Start
with 100/1,000/10,008-message diagnostics to expose scaling; then clean alternating
full-size samples. Keep profiling/count hooks out of primary timing. Report
time to first useful content, complete durable content, all acknowledgements
settled, foreground admission/commit, and reopen separately. A faster content
endpoint must not conceal an unbounded acknowledgement backlog.

The primary endpoint is complete durable fixture content AND every acknowledgement
earned by that fixture durably settled. Content-only latency is secondary.
The planning target is at least 30% lower clean median at that primary endpoint;
completion below 30 seconds remains the explicit product goal. Ten alternating pairs
give a scoped median comparison, not a tail-latency qualification. Inspect
post-GC memory separately and explain added key-index cost; do not infer retained
memory from the old 604 MB endpoint. Preserve first-useful and foreground controls.
Use a 180-second cutoff and retain every attempted sample. Censored observations
remain greater-than bounds, never a median of completed runs alone; if a median
cannot be established, report the supported bound and failures. The physical
reopen control uses the same development persona and public held-query protocol
as the baseline: no bearer-UI or native performance qualification follows.
Record every failure/cutoff and avoid discarding slow samples. If 30 seconds
remains unmet, retain the goal and attribute the residual rather than accepting
a looser budget or declaring the broader research complete.

Run affected package tests, `scripts/test.sh`, canonical `measure.mjs --check`,
`ref-check`, caps and inventories. Existing unrelated failures remain reported
separately. Measure unchanged five runtime roots; pay for added state machinery
within the current allocation. New source changes receive fresh independent
code review after the plan panel.

- `DeliveryAcknowledgementIndex` maintains pending keys, per-log batch counts
  and reverse intent bindings. Reads take at most 50 event identities. The
  carrier updates the index after durability, invalidates it after a failed
  derived update, and reconciles policy/root replacement conservatively.

  the exact full-ledger comparator. Full public history/program reads remain.

  matching queued, admitted, current and committed identities. Both sides of
  the serialized apply check eligibility. Changed proofs retain queued custody

- The shared subscription owner distinguishes semantic and item refresh.
  Item publication reuses the immutable query image and observation while
  updating work and compaction. Semantic/direct events fence obsolete work;
  item nudges cannot starve a running semantic evaluation.
