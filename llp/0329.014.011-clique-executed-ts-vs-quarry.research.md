## Summary

The same day the founder asked for a Clique run, Snapback 2 ran its first —
then ran it **twice more to compare authoring surfaces**. All runs are
**diagnostic** (unpublished platform consumed as packed tarballs; media
struck from the brief per protocol rule 3), cold, blindness-fenced,
same-model. Between the runs, a real front end was built: **`quarryc`**
(`snapback2/packages/quarry`, codex-implemented in one pass, ~2.3k lines)
compiles the Quarry notation to the existing TS authoring surface, so the
unchanged packaged toolchain runs it.

**Both executed lanes went green.** TS: 20/20 acceptance, ~65 min. Quarry:
19/19 plus a self-added 8/8 headless-browser smoke, ~61 min, backend 100%
Quarry (67 certified ops; generated TS never hand-edited). Both
independently re-verified by the orchestrator (suites rerun; seeds
idempotent). Milestone-authoring wall clock split sharply — TS ~50 min
across M1–M3 versus Quarry ~16 min (+~31 min of setup/probing/UI the TS
lane spent inside milestones) — suggestive, not conclusive, at n=1 per
surface. Executed-backend size: **TS 1,211 lines / 42.0 KB vs Quarry 434
lines / 13.9 KB (3.0×)** — the third size measurement in the family (toys
2.9×, paper-vs-oracle 2.1×), now on green, executed backends of the same
app.

**The deepest result is neither speed nor size**: the two surfaces
exercised **disjoint platform paths and surfaced disjoint bug sets**, and
the Quarry lane's compiler-emitted idiom flushed out a silent-corruption
P1 the TS idiom structurally hides.

## 3. The bug-disjointness result

The TS lane's three worst frictions (filed `a119883dc`): certified output
ceiling priced from declared row maxima rather than projections; reads
inside mutations silently obeying viewer read rules (LLP 0331's actor gap
in practice — two designs burned); and three certify-green-runtime-red
gaps (`Page.hasMore`, composite cursors, Id scalar rules).

The Quarry lane hit **none of those first two** (its notation and
compiled idioms routed around them) and instead surfaced:

1. **The P1** (`issues/20260831-insert-return-reevaluates-row-expression.md`,
   orchestrator-verified in plain TS): `db.insert`'s returned row
   re-evaluates the row expression, so an inline `ctx.newId()` mints twice
   — the returned `.id` exists nowhere. Silent referential corruption, no
   refusal anywhere; the lane found it by diffing `snapback2 data` dumps.
   The todos template's hoisted-mint idiom — which the TS lane inherited —
   structurally hides it; `quarryc`'s inline-mint emission — equally legal —
   exposes it.
2. Descending-cursor `after` semantics returning the wrong half of the
   index (page 2 duplicates page 1 on any newest-first feed), compounded
   by the `E_SUCCESSOR_DESTRUCTIVE` / migration-needs-a-running-owner
   chicken-and-egg (ticket filed).
3. A `quarryc` defect of exactly the class the corpus predicts:
   branch-arm write-trace undercount — check-green, runtime-red
   (`E_TRACE_SUBSET`; ticket filed) — plus a `snapback2 test` CPU wedge on
   rule-restricted seeds (ticket filed).

The moral is structural, not anecdotal: **a second front end over the same
platform is a bug-finding instrument**, because different emitters
exercise different legal idioms. One afternoon of a second surface found a
silent-corruption P1 that the paved template idiom would have hidden
indefinitely.

## 4. Reading the comparison honestly

1. **Both surfaces ship the app.** The bounded-data-program model — not
   the spelling — did the heavy lifting both times: same green, same
   architecture convergences, same praised loop.
2. **Quarry's measured advantages held under execution**: 3.0× smaller
   authored backend, faster milestone authoring (with the n=1,
   strategy-confounded caveat: the Quarry lane front-loaded probing that
   the TS lane paid inside milestones), and zero hand-edits of generated
   code across 67 ops — `quarryc`'s sited refusals were sufficient to
   author against.
3. **Quarry's costs were real too**: the v0.2 spec promises constructs
   the platform lacks (`maintain`, `merge`), so the lane experienced the
   *language* as over-promising even though the TS lane lived under the
   identical platform limits — a spec-vs-platform honesty gap the v0.3
   spec must close; and the one compiler bug produced the only
   check-green-runtime-red moment of the Quarry run.
4. **This was one model family, one app, one day, diagnostic fences.**
   It licenses "the Quarry path is viable and cheap to keep testing," not
   "switch."

## 5. What this queues

- Fix the P1 (single-evaluation of insert row expressions, or certify-time
  refusal of impure builtins in row literals) + a packaged-consumer
  regression rung (ticket from the packing phase).
- `quarryc` branch-trace fix + fixture; desc-cursor semantics decision;
  test-runner wedge.
- The v0.3 spec (queued by .010) gains a new requirement: it must state
  *platform* capability, not design intent — the executed lane is the
  first consumer that suffered the difference.
- If the comparison is to graduate from diagnostic to instrument: publish
  the platform (author ceremony), restore media to the brief once assets
  exist, run conforming lanes per LLP 0201's protocol with real cap
  families.

## Confidence

High on both greens (independently rerun), the P1 (minimal verified repro),
and the size numbers (measured on the landed backends). Medium on the
milestone-speed split (n=1, strategy-confounded). High that the
bug-disjointness observation is real for these two lanes; medium that it
generalizes — though it is exactly what the .009/.010 loud-vs-plausible
analysis predicts.

## Open questions

1. Does the insert-return fix want single-evaluation semantics or a
   certify-time purity rule for row literals? (The value model's
   "system-committed randomness/ids as modeled inputs" argues
   single-evaluation.)
2. Should `quarryc` graduate from diagnostic tool to supported front end —
   which forces the v0.3 spec, a conformance fixture set, and a decision
   about `merge`/`maintain` platform support?
3. Is a standing two-surface lane (same brief, both front ends) worth
   institutionalizing as a platform test instrument, independent of any
   language decision?
