## Assignment questions

A role-wide read branch admitting a private column, or a payload in a related
table, can warrant an exact "assigned or any?" specification question. A required
principal column named for the admitted roster role identifies an existing
assignment hypothesis. The bounded mechanism supports the resource itself or
one direct typed parent. Multiple matching paths, optional assignment columns
and deeper joins remain uncovered; no spelling manufactures a disclosure.

A current concrete witness must execute an authored query and repeatably return
the target typed payload cell to another member of that role. Supporting rows
retain the actual caller's membership and the selected resource's assignee.
This question selects a one-query observation on that recorded initial world;
longer histories cannot borrow the initial assignee after an intervening write.
The public witness explicitly includes the actual modeled assignment principal.
Merely returning a reference/id or a synthetic policy image is insufficient.
The question is advisory: a role may deliberately have global access.

Some explicit private-column gates admit multiple roster roles and model no
assignment for those roles. The missing-model collector is limited to that
shape; a sole global role is not treated as evidence of missing assignment. In that case the question states exactly that a whole-role caller can
read the cell and asks whether an assignment constraint should exist. It must
not invent a creator, assignee or claim that the caller is "unassigned".
A private negated-audience collector finds these payload observations; its deny
hypothesis is never published as product intent or added to production
augmentation. The public candidate and summary are factual questions. If the
author models an assignment and scopes its role branch, an unrelated global
owner branch must not recreate the old missing-assignment question.

Questions with multiple admitted role alternatives choose a deterministic caller
among actual payload witnesses. This is a search/presentation choice, not a
claim that one role is intrinsically more privileged. Full role branches,
assignment relation, payload, actual observer/caller and supporting dependencies
bind the existing witness decision. The complete bound collector policy is
retained as structured hypothesis metadata even when the public candidate is
rewritten as a factual question. Audience qualifiers cannot disappear from the
witness identity. Opaque payloads remain redacted.

Only this question campaign receives an inert valid proposal for typed URL
arguments, including a creator whose URL arguments otherwise prevent an
ordinary admitted initial resource. The URL is never fetched. Normal input validation, table rules,
authored creator guards, tuple/world limits and 8,192-call question work bound
remain unchanged. Gate campaigns and normal production test inputs do not
receive this proposal. No deploy pipeline or scheduling change belongs here.

The new assignment tier uses one default line containing its actual query, caller,
payload and modeled assignee (or explicit missing model), the question and a
review command. Expanded review/JSON retains full replay and individual decisions.
For a default deploy with an unrecorded assignment card and no pending gate,
the factual card replaces the generic positive language-feature summary. The
verdict retains counts, and FIXes, refusals, test status and other cards remain
visible. Expanded review retains that feature summary. No deploy pipeline or
scheduling code changes.
A renderer replay over all frozen survey records qualifies this presentation
delta separately from the unchanged native policy/witness binary.
