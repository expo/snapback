## Context pack

Scope: question witnesses and their acknowledgments; SEC11 item 1. Governing
contracts are LLP 3000.036.004.000 §13 (current executable witness, fixed work,
canonical decision identity, explicit acceptance) and LLP 3000.037.000 §1
(default-visible witnessed questions). Both extend the current security LLP;
the Snapback 4 fence excludes the older inventory/bootstrap rules.

Names and inferred domain obligations cannot supply authority. A replay is an
example of admitted behavior, not proof of the application's intended policy.
New hypotheses stay advisory here. Existing gate selection and deployment
obligations remain governed by §13. Broader approval inference, entitlement
contracts and required-evidence gates are separate SEC11 mechanisms.

## Decision refusals

An acknowledgment must use SEC10's exact witness digest and affirmative
`permit OPERATION as CALLER` clause plus its audience/effect rationale. A failed
answer includes the current redacted replay summary as well as the usable reason
template. A rejected batch publishes no decision. Stored prose does not establish
runtime authority or override independently authored intent.

## Question candidates

Extend the bounded advisory campaign to:

- Optional asset columns/lists: an actual insert omits the column or admits an
  empty list. Nonempty requirements are hypotheses, never inferred obligations.
- Text evidence: an actual insert admits a text-typed evidence column, rather
  than requiring a verified uploaded asset. Opaque text stays redacted. The
  question does not claim text has media content or is necessarily invalid.
- Child evidence: the named transition actually proceeds without a matching
  child. Count the exact parent reference, including empty child populations.
  The executed write must change a structurally identified workflow discriminator;
  a payload-only draft edit or same-state write cannot witness this question.
- Broad roster audiences (`N_BROAD_READ`): select existing row-dependent read branches as the candidate
  narrower audience. A broader role exception may be deliberate. No principal
  column's name alone creates a read restriction. Role-specific questions wait for
  exact role/assignment candidates: excluding all staff from an owner branch
  produced irrelevant witnesses and raised default output in the first survey.
- Guard reuse: for a supported single-insert trace, reconstruct its validated
  generated fixture and execute the identical call twice. Both must succeed,
  add distinct rows, and leave the exact selected guard value unchanged. Resolve
  the mandatory direct guard read to the argument row; a sole same-table
  reference argument does not by itself establish that identity. Indirect reads,
  assignments and branching guard paths stay uncovered. A
  refused second call or idempotent effect supplies no reuse witness. Complex
  histories, loops, extra ID-mint expressions, opaque jobs/effects, asset-ledger
  transfer and ambiguous guard references remain gaps. Conditional optional
  attachment diagnostics without a leading typed table/column remain gaps.

These candidates do not join production derived obligations or become gates.
Question evidence must not compete with current gate replay's separate 3,072
work reservation. The advisory campaign keeps its existing 8,192 work limit;
repeat replay adds at most two actual calls per candidate. Both reconstruction
calls receive deterministic ordered IDs through `Context::with_ids`, reserving
the ordinary row-write ceiling; replay never falls back to entropy-based minting. No elapsed-time
verdict or unbounded second search is introduced. Existing default rendering is
reused; presentation layout belongs to DX14.

## Read payloads

A repeatably returned, compiler-typed row/column is concrete read evidence.
Record the actual query, caller, arguments and logical clock as an observed
history step, including reads on a generated fixture with no preceding mutation.
This differs from `sent`, which records a committed mutation. Search deduplication
retains its mutation-prefix key, excluding the terminal observer: recording
read evidence must not manufacture a new mutation history or spend the finite
campaign repeatedly on an unchanged prefix. Mere dependency,
paired refusal, synthetic policy failure or unsupported observation cannot
supply a typed payload witness. The effective clock is retained in serialized history and decision identity.
Earlier decisions whose identity omitted this execution input become pending
once; the new witness must be answered. Record the schema-redacted actual typed payload separately from the physical
policy image. Delivered field sets and visible typed values participate in
witness identity: exposing another field renews the decision even when the
policy row is unchanged. Raw query results stay in a live-only field excluded from serialization and
Debug output; saved reports cannot supply a new payload witness without replay.
Opaque JSON, text and assets stay redacted, including
inside structured return values. Only IDs visible in the redacted payload
join its alpha-normalization graph. Generated initialization remains explicit.

## SEC13: required evidence and time anchors

Commission: wave-32 fixes 8 and 9, Charlie Cheever, 2026-10-27. This extends
Question candidates without changing runtime admission, authored intent or the
gate registry. Like SEC11 item 1, these are default witnessed specification
questions, not inferred mandatory domain rules. A name, comment or finite replay
cannot establish whether evidence or an original-date deadline is required.

Optional media and parent creation without a separately attached media child
use current generated-fixture execution. The replay must demonstrate omission
or empty media on a committed surviving parent; an atomic repair is not absence.
Child creation questions name the exact reference and creating operation. A
safe required argument/guard or atomic child creation supplies no missing-media
witness. Default output uses the existing question card. No new campaign budget
is introduced. Missing or unsupported replays remain review coverage, never gates.

Acknowledgments of both evidence and both time families require current concrete replay
evidence and SEC10's exact digest/affirmative permission/audience-or-effect
answer. Unavailable evidence cannot be closed by generic prose or an old
unwitnessed record. Acknowledgment accepts the displayed behavior as intentional;
it neither enforces evidence nor validates English against an external spec.

Time-anchor questions correlate actual resolved comparison operands and typed
writes. A guard measuring a window from a stored time asks about every edit
that can move that time, naming the guarding and editing operations. Immutable
anchors and exact value-preserving writes are quiet. A guarded child whose
parent date can change needs either prevention of the edit once children exist
or validation of dependent windows. A self-relative reschedule must ask whether
its anchor should instead be an immutable original date. Merely repeating the
self-relative guard does not settle that question.

A time guard comparing server now to a stored time plus a fixed offset, while
the operation stores a separately supplied event time, asks whether the window
should constrain that event time instead. An equivalent check on that event
operand answers the candidate; a bound against now alone does not. This is a
structural question, not a claim to have read an external product specification.
Time questions appear by default only with actual admitted behavior. Movable
anchor witnesses must contain an update with different non-null old/new anchor values;
the trace retains the operation-entry anchor and compares it with the committed
anchor, excluding an atomic A → B → A restoration. This establishes that the
editor can move the anchor, not that every dependent
window has been violated. Event-time candidates substitute the stored event
operand for now in the observed comparison and require a replay where the
original clock comparison holds and its event substitution fails. First bookings
with no applicable prior anchor cannot supply this witness. The event boundary
judges the matching new image only, not an invalid old event that the operation
repairs; the submitted event value must survive commit. The selected anchor row and comparison remain in the evidence.
Unsupported candidates stay behind --review and cannot be acknowledged without
an evaluable current replay. No synthetic trace is an execution witness.
Unknown analysis remains coverage, not proof of safety.

The existing single-write, no-maintains/loop/opaque-execution absence
reduction and `$derived/sec11-absence/` observer remain unchanged, including
committed-row predicate re-evaluation, parent survival, liveness at the effective
clock and commit-end expiry exclusion. Creation requires a sole parent insert;
transitions require a sole parent update. Effect-free IR branches introduced by
Boolean short-circuit lowering are allowed; branches with writes, returns or
opaque effects remain unsupported. Existing typed redaction, canonical
witness-plus-code identity, generated-ID alpha normalization and current-witness
renewal apply. Opaque text/assets never become public replay values.

Candidates share the existing deterministic 8,192-work question campaign,
separate from the 3,072-work current gate reservation. There is no second search
or new replay call allowance. Event-window questions may propose at most sixteen
source numeric literals per typed numeric argument and sixteen clock samples
(server now and source-offset boundaries) for the selected event operation,
retaining ordinary samples for other operations within the same reservation. The original engine validates every argument; no program,
rule, seed row or fixture validation is rewritten. These family-local proposals
do not change the generic sampler's default behavior. The selected operation's
directed frontier prioritizes interior numeric literals paired with late event
boundaries, retaining one already role-prioritized identity/asset tuple per
pair. The ordinary eight-tuple directed cap and global work reservation remain;
other identity/asset combinations are explicitly uncovered. Ordinary engine replay uses Context::with_ids and
its normal row-write ceiling. Exhaustion is coverage. Default cards use one line
for these families; layout continues to belong to DX14. No new top-level section
or gate code is added. Structural suppression is conservative: schema Immutable
constraints, identical same-resource field expressions, and exact linked-child
absence guards can answer movable-anchor questions. Event substitution requires
the same comparison, offset and selected stored row; unrelated event guards
cannot answer it. The event predicate reduces selected point-member reads only
when named, non-null pins cover a plain unique key of the exact table. Missing,
duplicate, null or non-unique anchors remain unknown. Population reads still
return arrays; this reduction does not turn a scan into a point.
