## Context pack

Scope: question witnesses and their acknowledgments; SEC11 item 1. Governing
contracts are LLP 3000.036.004.000 §13 (current executable witness, fixed work,
canonical decision identity, explicit acceptance) and LLP 3000.037.000 §1
(default-visible witnessed questions). Both extend the current security LLP;
the Snapback 4 fence excludes the older inventory/bootstrap rules.

Names and inferred domain obligations cannot supply authority. A replay is an
example of admitted behavior, not proof of the application's intended policy.
New hypotheses stay advisory here. Existing gate selection and deployment
obligations remain governed by §13. Broader approval inference, entitlement
contracts and required-evidence gates are separate SEC11 mechanisms.

## Decision refusals

An acknowledgment must use SEC10's exact witness digest and affirmative
`permit OPERATION as CALLER` clause plus its audience/effect rationale. A failed
answer includes the current redacted replay summary as well as the usable reason
template. A rejected batch publishes no decision. Stored prose does not establish
runtime authority or override independently authored intent.

## Question candidates

Extend the bounded advisory campaign to:

- Optional asset columns/lists: an actual insert omits the column or admits an
  empty list. Nonempty requirements are hypotheses, never inferred obligations.
- Text evidence: an actual insert admits a text-typed evidence column, rather
  than requiring a verified uploaded asset. Opaque text stays redacted. The
  question does not claim text has media content or is necessarily invalid.
- Child evidence: the named transition actually proceeds without a matching
  child. Count the exact parent reference, including empty child populations.
  The executed write must change a structurally identified workflow discriminator;
  a payload-only draft edit or same-state write cannot witness this question.
- Broad roster audiences (`N_BROAD_READ`): select existing row-dependent read branches as the candidate
  narrower audience. A broader role exception may be deliberate. No principal
  column's name alone creates a read restriction. Role-specific questions wait for
  exact role/assignment candidates: excluding all staff from an owner branch
  produced irrelevant witnesses and raised default output in the first survey.
- Guard reuse: for a supported single-insert trace, reconstruct its validated
  generated fixture and execute the identical call twice. Both must succeed,
  add distinct rows, and leave the exact selected guard value unchanged. Resolve
  the mandatory direct guard read to the argument row; a sole same-table
  reference argument does not by itself establish that identity. Indirect reads,
  assignments and branching guard paths stay uncovered. A
  refused second call or idempotent effect supplies no reuse witness. Complex
  histories, loops, extra ID-mint expressions, opaque jobs/effects, asset-ledger
  transfer and ambiguous guard references remain gaps. Conditional optional
  attachment diagnostics without a leading typed table/column remain gaps.

These candidates do not join production derived obligations or become gates.
Question evidence must not compete with current gate replay's separate 3,072
work reservation. The advisory campaign keeps its existing 8,192 work limit;
repeat replay adds at most two actual calls per candidate. Both reconstruction
calls receive deterministic ordered IDs through `Context::with_ids`, reserving
the ordinary row-write ceiling; replay never falls back to entropy-based minting. No elapsed-time
verdict or unbounded second search is introduced. Existing default rendering is
reused; presentation layout belongs to DX14.

## Read payloads

A repeatably returned, compiler-typed row/column is concrete read evidence.
Record the actual query, caller, arguments and logical clock as an observed
history step, including reads on a generated fixture with no preceding mutation.
This differs from `sent`, which records a committed mutation. Search deduplication
retains its mutation-prefix key, excluding the terminal observer: recording
read evidence must not manufacture a new mutation history or spend the finite
campaign repeatedly on an unchanged prefix. Mere dependency,
paired refusal, synthetic policy failure or unsupported observation cannot
supply a typed payload witness. The effective clock is retained in serialized history and decision identity.
Earlier decisions whose identity omitted this execution input become pending
once; the new witness must be answered. Record the schema-redacted actual typed payload separately from the physical
policy image. Delivered field sets and visible typed values participate in
witness identity: exposing another field renews the decision even when the
policy row is unchanged. Raw query results stay in a live-only field excluded from serialization and
Debug output; saved reports cannot supply a new payload witness without replay.
Opaque JSON, text and assets stay redacted, including
inside structured return values. Only IDs visible in the redacted payload
join its alpha-normalization graph. Generated initialization remains explicit.

Absence replays observe a write boundary, so only a single-write operation is
supported: one parent update for child-presence transitions, or one parent
insert for optional-column/list omission. The schema must have no maintains;
the expanded operation must have no branching, loops or opaque execution.
Additional writes, cascades and maintenance can repair or erase an intermediate
observation and need final-store replay; they stay uncovered here. Regressions
execute atomic insert-then-repair, transition-then-child-insert and
transition-then-cascade calls and verify none can supply an absence question.
The optional-evidence candidate names its supported creation operation.

Absence candidates carry the dedicated `$derived/sec11-absence/` site prefix.
The actual-execution observer also requires the same parent image to survive in
the final store, remain live at the effective clock, and violate the predicate
when evaluated against committed rows. Commit-end expiry cannot witness a
missing-evidence question about a row that vanished. This final-store judgment
is isolated from authored boundary invariants and existing gates. Expiring
insert/update regressions execute successfully, observe no final parent and
produce no absence witness.
