## Summary

LLP 0310's 0.1.27 Clique diaries show Snapback is now harder to *operate*
than to *author*. This RFC repairs the paved Expo loop without weakening
LLP 0302's fail-closed identity gate.

The product rule: **a legal schema successor in the same `snapback dev`
owner must leave the web client talking to that owner.** Adding tables is
not "you pointed at a different app." Restarting Metro because generate
deleted a watched tmp file is not an acceptable recovery. Supervised Expo
web must not mint a session that hides password UI while omitting
`EXPO_PUBLIC_SNAPBACK_URL`.

Five tracks. Three are design (A, B, D). Two are straightforward product
fixes filed as tickets and only specified here (C, E). Guide drift is
tickets, not a sixth track.

## Motivation

Clique explicit on 0.1.24 and 0.1.25 greened M1–M3 (and 0.1.25 greened
through M8). The same explicit prompt on 0.1.27 greened M1, activated an
additive successor with preserved accounts, then blanked the web app with
`SNAPBACK_APP_BINDING_IDENTITY_MISMATCH` because the Expo extra still
named the M1 descriptor. Familiar greened M1–M3 only after Metro died
twice and the owner was restarted.

LLP 0300 wanted Snapback to be more like Convex: a URL, a client, a
boring reload. LLP 0302 then locked identity so a client cannot send
credentials to the wrong backend. Both are correct. Together, without a
successor recook, they made "I added a table" look like "I swapped the
app." That is the hardness the diaries are complaining about.

Convex and Supabase in the same wave had Expo/Playwright papercuts and
still reached M2 green. Only Snapback explicit stopped on identity.

## Non-goals

- Weakening `SNAPBACK_APP_BINDING_IDENTITY_MISMATCH` against a *different*
  backend, a stale supervisor, or a hosted-target swap.
- Merging explicit and familiar into one authoring profile.
- Removing `reads`/`writes`/`refusals` or `defineAuth`.
- Changing Clique's frozen typing clock (instrument; LLP 0201 / 0281).
- Multi-asset `defineCommand` (already owned by
  `issues/20260815-finish-media-happy-path.md` / LLP 0239).
- Making Node `memory` platform grow durable custody. Document the
  `expo-web` + fake-indexeddb requirement; do not invent a second store.

## Design

This RFC does **not** change the LLP 0302 mismatch predicate. It rewrites
the declaration that predicate already reads, on a proven same-owner
successor only.

### Ruling 1 — same-owner successor is not a foreign app

A legal successor of the live `snapback dev` incarnation MUST leave
every supervised Expo web arm talking to that incarnation under one
coherent identity. Split-brain (backend on successor, extra/receipt on
predecessor, or the reverse) is a product bug.

Eligibility is a trusted lineage, not “we saw an activation event”:

- live owner incarnation id
- currently committed predecessor identity
- candidate successor identity (generated `app` + backend)
- monotonic transition epoch

Stale, reordered, unmatched-predecessor, foreign-backend, and
stale-supervisor events remain `SNAPBACK_APP_BINDING_IDENTITY_MISMATCH`.
They never authorize a recook.

Recovery is in-process. Owner restart is a fallback, not the paved
path. `pkill` is never the recovery.

**Caller-owned 0300 path:** generate/successor rewrites the on-disk extra;
a client/Metro reload is the recovery. Track A is only the
owner-managed running extra/receipt.

**Sessions:** same-owner recook preserves account and session rows. An
already-authenticated principal remains authenticated after commit. It
must not be dumped onto `SNAPBACK_AUTH_SESSION_EXPIRED` as the only
path. Re-login is not the paved M2 path.

### Ruling 2 — supervised `--expo` remains a paved path

LLP 0300's caller-owned `expo start` + URL-first loop stays canonical.
This RFC does **not** amend LLP 0302 §4: a completed supervised
rendezvous still wins source selection; `url` does not become a second
binding source.

Supervised `snapback dev --expo --expo-platform web` remains a supported
convenience owner (LLP 0181 / 0299). Independent choices, decided here:

| Choice | Decision |
|---|---|
| Binding source | Supervised rendezvous remains selected (0302 §4 unchanged) |
| Data/auth URL | Inject `EXPO_PUBLIC_SNAPBACK_URL` as **that same backend origin**. Supervisor origin is control plane only, not a second Snapback data plane |
| Mint creation | On demand, not boot-eager |
| Mint adoption | Explicit opt-in (LLP 0258 / 0262). Not the default first session |
| Sign-out | Returns to anonymous/password UI. Must not crash the provider |

This RFC **amends LLP 0300 P4** (supervised Expo issuance): mint creation
is on-demand and adoption is explicit, not boot-eager issuance. It does
**not** amend LLP 0302 §4 precedence. If injecting the URL collides with
a named native-only mint invariant, record the collision in
implementation notes and stop; do not silently switch to “no URL, no
mint” (former B2).

### Ruling 3 — `touch()` fencing stays; one typing episode is one generation

Generation fencing stays, against overlapping *logical* presence rows.
One typing episode MUST reuse the generation of the first `touch()`
until `withdraw`, idle, unmount, routing-key change, or session change.
Those events MUST fence earlier in-flight publishes so a delayed
completion cannot resurrect presence. Per-keystroke `touch()` MUST NOT
start a new generation or cancel the in-flight publish of that episode.

The familiar page names `useSnapbackActivityPresence` from
`@expo/snapback-react` as the URL-first import. The Expo facade hook is
for `SnapbackExpoProvider` only. No third hook.

### Track A — prepare / commit / abort recook

**Owns P1, P12.** Ticket:
`issues/20260825-successor-expo-receipt-stale.md`.

Observation path is one mechanism: rewrite the receipt and extra that
0302 already consults, then Metro/bundle reload so the running arm loads
those artifacts. **Forbidden:** a runtime identity setter, a second extra
channel, or “push an in-memory extra the bundle will observe.”

Transition (success path):

| Step | State | What |
|---|---|---|
| 0 | idle | Owner serving predecessor. Eligibility check on the candidate. |
| 1 | freeze | Quiesce that web arm: hold new handshakes; drain or abort in-flight application requests **before** any extra rewrite (A3: no request straddles the rewrite). Invalidate existing 0302 verification episodes (a live stream MUST NOT stay verified across the flip — LLP 0302 §3 idle-swap is not a license to skip this). |
| 2 | prepared | Rewrite receipt + extra to the successor identity. Reload Metro/bundle. Web-arm ack is an *internal* checkpoint, not a license to talk. |
| 3 | committed | Activate successor so the backend serves the new identity. Unfreeze **only arms that acked**. The next application request MUST pass a fresh identity verification. Emit `snapback.expo.binding-recooked.v1` with outcome `recooked-and-acked`. |
| abort | aborted or typed-stopped | Either (a) restore **every** identity-bearing artifact (extra, receipt, Metro/bundle graph, backend serving identity) to the predecessor, reload the predecessor bundle, re-verify, then unfreeze; or (b) enter typed-stopped and do not unfreeze. Never restore extra/receipt alone against a successor generated graph or successor backend. Emit `recook-failed-successor-refused`. |

A tab that does not ack MAY be disconnected **before** any client is
allowed to talk to the successor, so commit can proceed for arms that
acked. “Unsupervised web arm” here means a non-acking tab, not the
caller-owned 0300 path. A lagging tab MUST NOT be globally unfrozen.

Guide: extend `#diagnose-a-binding-identity-mismatch` with this table.
Do not tell agents to restart unless the event is
`recook-failed-successor-refused`.

### Track B — URL visible, mint not stolen

**Owns P4.** Ticket:
`issues/20260825-supervised-expo-web-hides-password-ui.md`.

Implements Ruling 2's table. First boot shows the password form without
a URL-first workaround. `signUpWithPassword` / `signInWithPassword`
talk to the injected backend origin. Signing out an unasked mint, if
one exists, returns to that form.

### Track C — generate must not kill Metro

**Owns P3.** Ticket:
`issues/20260825-metro-exit-on-codegen-tmp.md`.

Default: write codegen temps **outside** Metro's project watch set.
Backups: Metro `blockList`, then atomic directory publish. Do not rely
on renaming a file Metro already has open.

After generate, the same owner and Metro MUST remain live and serve the
updated generated graph. Absence of `SNAPBACK_EXPO_METRO_EXITED` alone
is not enough. Owner restart is not the fix.

### Track D — one presence import; one generation per typing episode

**Owns P5, P6.** Guide ticket:
`issues/20260825-guide-gap-activity-presence-url-first.md`.
Product change is Ruling 3; the ticket is the import/docs slice.

### Track E — owner-bound control socket

**Owns P2.** Ticket:
`issues/20260825-dev-control-channel-requires-stdin.md`.

Beside stdin (humans keep stdin): a unix socket in the owner state
directory, mode `0600`, same uid as the owner, bound to that owner's
incarnation id / lifecycle receipt. Foreign, stale, or other-uid
endpoints refuse.

Verb set: `reload-metro`, `stop-children`. Recook is Track A's
automatic transition, not a client-invented identity patch. Every verb
returns an acknowledgement the agent can wait on. Fifo is a non-goal.

## Sequencing

Tracks **A, C, and E co-land**. C without A would hide F1 behind Metro
death (the Familiar accident). A without C is untestable if generate
kills Metro. A without E is untestable under `/dev/null`. B and D may
land separately. Guide tickets land with the tracks they describe.

## Closed questions (r2)

- **OQ1.** Recook in-process; abort/refuse on failure. (Track A table.)
- **OQ2.** Binding source stays supervised; URL is the same backend
  origin; mint on-demand and explicit. Former B2 is not a silent
  fallback.
- **OQ3.** Socket beside stdin.
- **OQ4.** 0302 identity includes the generated `app` descriptor the
  extra/receipt names. An additive successor that changes that
  descriptor MUST recook. This RFC does not loosen foreign-backend
  mismatch; it also does not invent a cheaper “additive schema is not
  a new app” carve-out.
- **OQ5.** Sessions remain valid across same-owner commit.
