## 1. Default verdict

Wave 30's 033 F1 had a concrete campaign witness, but its builder never opened
`--review`. Both default check and changed deploy search the existing bounded
question campaign and print every available unacknowledged witness with its
question. This is an actionable fix question, not an authored invariant
refutation or an additional gate. Gate semantics remain SEC10's responsibility.
Deploy retains witnessed virtual `$derived/` source sites even when ordinary
changed-source filtering cannot map them to an authored filename.
The check verdict and deploy’s leading verdict count gates, witnessed questions and advisories;
advisories explicitly do not block. Unwitnessed advice remains behind --review.
N_WRITE_DENIED, N_REQUIRE_HIDDEN, N_NEVER_COMPLETE and N_UNREADABLE_PROBE are
an actionable tier shown by default. The expanded security-question block leads with gates, then
witnessed questions, then other advice. A disposition lacking a witness says
that its specification rationale has not been validated by replay. Unsupported
codes say witness unavailable; supported exhausted searches say none obtained.
Neither wording promises that the acknowledged specification is true.

Existing redaction, source binding, work caps and structured evidence survive.
The existing generated cache is an optimization, never authority. A cold check
now pays the bounded witness search; measurements must include cold latency.
No witness is not evidence of safety. Default output targets median <=5 lines
for both check and deploy on the fifty wave-30 schemas; individual actionable
findings can exceed it. Deploy prints its newline-terminated security notice
without adding a blank line. Enforcement prose and JSON evidence remain intact.

## 2. Default initialization

LLP 3000.036.004.000 §10 supersedes its original "defaults count" rule.
A null or a value equal to a declared literal default initializes a column at
insert and requires no column write grant. Explicitly supplying the same
literal is equivalent to omission. This applies to insert-if-absent and the
insert arm of upsert. Table insert authority always applies. A non-default
insert value requires the grant. Changed updates, including resetting a value
to its default and edits via upsert, retain old-and-next grant checks.
Dynamic `now` and `viewer` defaults retain ordinary column authority; this
amendment grants only literal initialization, with no new wire expression.
Authored column-write intent and enforced adversarial contracts use that same
initialization predicate.
Authored whole-row presence/approval assertions remain independent obligations.

app with password sign-in, operator-only provision, online tables and writes,
no device initialization, no personas, and no todo fixtures. `--password`

existing schema init preserves it and validates an explicit password request.

new public signups have no role and cannot create notes until provisioned.

recognizes starter metadata or launcher/client wiring, independent of optional
probe scripts and package-manager version spellings. Generated UI starters offer

heartbeat; it preserves npm's exit status. It does not automatically install. Exact README recognition canonicalizes the

command only where its file exists, retaining custom prose.

## 4. Proof diagnostics and account plans

serve-check compares its requested deployment with path-only observations of
startServe in its owned script group. These observations contain no credentials
and are disposed after cleanup. A mismatch names both stores, including when
the requested store exists and is unlocked. A missing store is distinct from
a live lock, and a live lock names the resolved path and holder from the CLI's
ownership report. Other barrier failures remain explicitly unknown. No process
is signalled based on these observations. Raw script stderr and readiness stay
private. Direct arbitrary native scripts without kit observations can only
report the requested barrier's path and holder; no actual-path claim is invented.

Account plans optionally add `users` roleless accounts beside `roles`; they
return under sessions.users and never call provision. users-only plans need no
provision handle or service token. Named role `users` conflicts with this batch
and refuses. The 100-account combined cap and host-environment validation remain.
E_STAGING_PROVISION prints merged argument shapes with opaque values redacted,
and declared mutation parameter names, never passwords, tokens or raw payloads.
Credential snapshots use unique mode-0600 files so rerunning disposable staging
recipes cannot fail merely because a previous snapshot exists.

## 10. Serve lifetime and store recovery (SRV1)

Wave-33 shapes 024 and 036/017/008 require lifetime to follow the parent,
including npm above a surviving shell. Direct native dev/serve observes its
immediate parent and nearest npm ancestor using process birth identities.
Linux installs PR_SET_PDEATHSIG on entry before threads, using SIGWINCH as a
notification: the handler verifies reparenting before emitting SIGTERM. This
avoids treating the exit of a libuv spawning thread as death of its process.
A 250ms watchdog remains on Linux and Darwin, also observing npm independently
of shell survival. No host signals a caller's process group. Existing pipe-owned
keepers forward shutdown and reap the private worker/host groups they own.

The packaged wrapper and serveUntilSignal observe the same parent/npm boundary;
the latter traps SIGTERM, SIGINT and SIGHUP, awaits bounded cleanup of every host,
and removes its timer/handlers. Hosts use private groups and file logs; driver
exit cannot leave an inherited output pipe held open by its server. TOK1's idle
refusal and explicit --hold / child-only SNAPBACK4_PROBE_HOLD=1 are preserved.
Detached harness children stay alive while their launcher lives and stop on its
group SIGTERM. A detached spawn alone is not permission to survive parent death. A minimal
Linux userspace may deliberately omit /proc (the clean-distribution proof does).
Missing process-table capability is not death: direct getppid/kernel custody
and PID liveness remain, while unavailable birth/ancestor metrology is marked
unverified rather than fabricated. It never grants a store lock or authorizes a
signal. Normal Linux and Darwin retain their birth-pinned npm ancestor watches. An
initial PID-1 parent is a legitimate service/container configuration, including
npm as PID 1; lifecycle environment variables alone are not proof of orphaning.
A known supplied launcher that died still refuses before startup.

The sidecar flock remains the sole ownership authority. serve.lock retains its
three legacy address/PID lines, with bounded metadata naming a non-secret command,
process birth identity, start time and actual control directory (which may differ
from the canonical database parent for aliased stores). CLI owners publish metadata before opening
the engine too. Diagnostics report current liveness and the exact shell-quoted
`snapback4 stop <dir>` recovery. Reclaiming a dead record follows successful flock
acquisition and prints one notice. No sidecar is deleted to recover ownership. Host admission waits up to five seconds
on the actual lock, even if a dying host still answers its listener or has already
cleared its address. Recorded launch-parent birth identities let release-command
admission recognize the same cleanup window while preserving immediate hot
activation against a living owner. The wait admits no work before successful
flock acquisition; live contention still ends in the holder diagnostic.
The existing private, same-owner, database-inode-bound stop control is reused,
including a stop-only listener for persistent dev stores so their printed recovery
also works (`stop <project>/.snapback4`);
a forged/stale PID is never signalled and lock release must be observed. Missing
or broken control fails safely for a held lock, rather than guessing at a PID.

Password starters exec their Node serve driver from npm's shell, ship prod:serve
and prod:check alongside probe commands, and recommend bounded checks for
verification. Production deploy/build remains explicit. The production card's
serve section owns this wording; other day-two guide restructuring is DX16's.
Verification reproduces wrapper-only TERM/KILL, direct parent loss, inherited
`tail` pipes, group termination with harness hold, stale/forged holder hints,
lock reuse and existing TOK1 guards. Darwin execution is skipped; its native libproc birth identity and locale-fixed JavaScript ps
identity paths and private-group custody remain portable by design review.
