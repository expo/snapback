## 1. Contract

Implementer: PROOF workstream, 2026-10-14. Wave 11 fix list 1 authorizes
one published `snapback4/proof` Node module. It owns orchestration, never client
custody or backend/bundler supervision in the product. Existing `startDev(args)`
and `stopChild(child | {url, stop})` recipes remain usable as module exports.

`startDev`, `startServe(directory)`, `startStatic(directory)` and
`startVite(directory)` return `{url, pid, logs, stop}`. Options carry cwd,
environment, arguments and bounded ready/stop deadlines. Read PORT_LO/PORT_HI
at invocation: absent means an OS-assigned port; exactly one set refuses. With
both set, validate 1 <= LO <= HI <= 65535 and bind the first free port in that
inclusive range; exhaustion refuses. Qualification's occupied first port must
be skipped, never adopted. The existing native SNAPBACK4_READY line already names its direct child PID (LLP 3000.011.004.000); no new readiness log is needed. The listening process binds first and keeps that socket;
never adopt an already-serving port. Vite uses its supported JavaScript server
API in a directly spawned Node child, strict ports, the project's config and
a per-launch identity middleware. The directly spawned frontend calls its
server listen API for each candidate; no probe-and-release step exists. With
no range it calls listen on port 0, which the tested Vite API supports with
strictPort; it reads the actual retained socket address. Static hosting uses a directly spawned Node
child with traversal protection, correct wasm MIME and SPA fallback.

All child stdout/stderr go to separate files beneath `logs/`. Read complete
lines from those files, strip ANSI, bound readiness, and reject premature exit.
Native ready lines must name the directly spawned PID. To assert HTTP identity,
the kit sets a random SNAPBACK4_PROOF_ID only in the child environment;
`/auth/config` includes `proof_id` only when this variable is nonempty. It
confers no authority or bypass, and ordinary servers omit it. Both static and Vite frontend child
responses carry an `x-snapback4-proof` marker. Identity validation
precedes returning a handle. No public development door is enabled in serve.

Register every spawned child and browser process for an exit-time SIGKILL
sweep, using retained native ChildProcess handles, not process-name kills.
TERM followed by bounded KILL/reap stops a child. Every cleanup action has
its own bound and later actions still run when an earlier action fails.
`cli(args)` runs the native binary, awaits close, returns separate stdout and
stderr, and has a command deadline. It never runs npm/npx or shell strings.

`withBrowser({executablePath: process.env.CHROME}, callback)` launches Chromium
through playwright-core, closes with a bound, and registers its actual browser
process. Root needs --no-sandbox; other hosts first attempt a sandboxed launch
and retry without it only on recognized sandbox-unavailable diagnostics: "No usable sandbox", "Running as
root without --no-sandbox", "Failed to move to new namespace", "SUID sandbox",
"sandbox ... Operation not permitted", or "Failed to unshare ... Operation not
permitted". Unrelated failures never retry.
`waitForFresh` polls for nonempty changed text; `fillRN` clears and types real
keystrokes; `statusText` uses text selectors; `selectByValue` selects stable
option values. The browser executable is CHROME (when provided), undefined executablePath is omitted from launch options, then Playwright's
installed Chromium is used; an absent executable refuses at launch, with its path.
waitForFresh defaults to 30 seconds. Binary resolution is resolveBinary from
the same installed snapback4 package (override SNAPBACK4_BIN only for explicit
workspace tests); the opt-in identity requires CLI/client 0.4.28 or newer and
an older CLI omits proof_id and therefore fails the exact marker assertion; no inferred version comparison or success claim is made. cli(args) does not
invoke package managers; publication uses its existing guarded command runner.

None interprets an HTTP acknowledgement as rendered settlement.

## 2. Explicit source and aliases

`deploy dir --schema file` compiles exactly that saved Quarry file and stages
those same bytes as canonical snapback/schema.q, preserving operation names
regardless of the saved file's name. Compile diagnostics name the selected input.
This happens without swapping the working schema or generating its types.
It does not concatenate other snapback/*.q files. It allocates ordinary numeric
immutable releases, uses the same .pending-adoption marker, transaction/history,
latest selection, restoration-intent preview and no-op checks as normal deploy;
no alternate activation path or restoration bypass exists. The normal deployment path
retains multi-file behavior and activation semantics. Server/native companion source comes from the current project, while all
schema-dependent generated signatures and native builds run against the selected
schema in a private snapshot. A uniquely created snapshot project has
snapback/schema.q, captured companion source, fresh snapback/generated/
and copied native sources (target caches excluded). Host-installed node_modules
is linked into the private project; package.json preserves host module policy.
The snapshot is RAII-owned and removed on success or error; nothing is executed
through the working generated types. Its server entry is typechecked against
the fresh generated server signature before activation; its native crate builds
against fresh generated native.rs into its own native-target directory. Never reuse the working generated signature or
write selected-schema types there. Package prepared signatures and native bytes
with the captured saved source; retain the original host package installation
for dependency resolution. Standalone means no Project::locate result from the current directory/ancestors; that saved source has no companion app. Native snapshot manifests preserve their source layout and rebase only Cargo
dependency paths against the original native crate's directory. TOML parsing
covers normal, build/dev, target-specific, patch/replace and local workspace
dependency maps. Absolute paths stay equivalent; missing dependencies refuse
before compilation. Never rewrite the package's own lib/bin paths to the
working tree; those must compile against the selected private generated types.
 Missing/stale external server
import graphs fail private checking with an actionable TypeScript diagnostic. Keep saved variants outside snapback/ to avoid normal
multi-file compilation. Rollback selects an existing immutable release, never
reads the current schema. The proof `deploy` helper requires a schema path;
`rollback` requires an explicit target; `testSource` requires a source path.
`test --source file` uses the selected bytes in a memory engine (optionally
with fixtures), so it cannot adopt a working store. Diagnostics name the file.

Fixture alias arguments and assertions follow [REL3 §5](./3000.000.000.000-release-spanning-clients-and-development-contracts.rfc.md#5-fixtures-and-dev-evidence). Protocol request decoding never sees this saved-name map and accepts all ordinary literal data unchanged. Saved aliases remain explicit `$name` / `$name.field`. A bare string matching
an earlier save alias refuses with the alias name and `$name` rewrite, before
wire decoding; ordinary strings remain literals. This avoids ambiguous auto
substitution into text fields. Unknown `$name` refuses by exact name lookup, never fuzzy matching.
`$name.field` requires every field in the saved object, refusing by the missing
field's name (a non-record has no fields). A `$` appearing inside ordinary text
is literal. `$$text` escapes to the literal `$text`; `{"$literal": value}`
in a fixture argument escapes any value, including an exact bare alias name. This affects only fixture case argument substitution, not protocol decoding.
Fixture preflight/sweep excludes explicitly saved arguments as before.

## 4. Custody scope and review disposition

The registered process set uses retained handles. Static and Vite Node hosts
start in private Unix groups and launch a live Node keeper in that same group.
The host's stdin is a driver-owned liveness pipe; driver death including SIGKILL
produces EOF and terminates the host. The keeper's stdin belongs only to the
host. Host exit (including SIGKILL)
closes it; the keeper signals its own group with SIGKILL. The driver gives the host only the read end of its liveness pipe; the keeper
likewise receives only its pipe's read end. Parent write ends are close-on-exec
and never appear in child stdio or IPC descriptors; compiler stdin is its own
pipe, never these write ends. Thus descendant inheritance cannot retain a
liveness writer after its owner dies. The keeper's live membership
pins the group identity, so no observer signals a recycled negative PID.
Vite closes its compiler before normal host exit; the keeper sweeps anything
remaining after either normal or forced exit. On Windows, direct-child cleanup
remains supported; private Unix-group custody is not claimed. Browser processes
use Playwright's process ownership and close before forced stop. Native servers use their existing SNAPBACK4_SUPERVISOR_PID parent-death contract
with the proof driver's PID and already own worker cleanup. Arbitrary detached application processes are outside
this module's supported custody. Publication's existing live-keeper groups remain
the outer command owner and enforce drained groups after each proof, including
abrupt driver death. No process-name or unrelated PID kills are allowed.

## 5. Exact helper defaults

Each launch uses an independent crypto.randomUUID marker. Native children receive
that marker as SNAPBACK4_PROOF_ID; the parent requires exact equality in
/auth/config.proof_id. Frontend children receive their launch UUID, and the
parent requires the exact pid:UUID header, never mere presence. Children in a
scenario need not share a marker: independent markers prove each handle's owner.
Native hosts receive --port LO-HI (or --port 0); only the child binds and prints
its actual loopback URL. The frontend child binds internally, never by a dropped
probe. Defaults: ready 30 s; TERM grace 5 s; KILL reap 5 s; CLI/command 120 s;
each cleanup 10 s; locator/navigation/fresh signal 30 s; browser/context close
5 s each. Log files have fresh UUID names below cwd/logs, never reused.

startServe serves an immutable deployed backend directory; startStatic serves
built frontend files, not a database. command uses a caller-selected executable
and argv (normal spawn PATH lookup when not absolute), shell:false semantics,
file logs and close/deadline checks; cli uses the package resolver. Use direct
tool binaries, never npm/npx to launch proof servers. Standard starter proof
reads identity/personas from its owned dev at run time, chooses guest/password/
persona sign-in and proves the visible todo add when Task exists. With a custom
Home, it proves sign-in/readiness only; the emitted instructions require the
builder's own business assertions after replacing the screen.

Fixture substitution recursively visits JSON arrays/object values. Alias lookup
is exact and case-sensitive. A $ prefix parses the name before the first dot,
then traverses each exact field; no dot returns a saved row's id. $$ strips one
leading dollar and is terminal (no re-expansion). A sole-key {"$literal":value}
is terminal and returns value untouched. Bare fixture strings matching the saved
map refuse; the wire decoder never receives or consults that map. All other
strings, including a dollar substring, stay literal. Normal Vite/compiler
children remain in the host's private group and receive separate stdin; daemonized
processes leaving it are outside custody. The keeper handles EOF with immediate
SIGKILL of its own group; the host handles driver EOF with immediate exit. Parent
write descriptors never pass to either child, so descendants cannot hold them.
Windows has direct-child stop/exit cleanup only; no abrupt-death group guarantee.

## 6. Source and discovery boundaries

Node hosts log exactly SNAPBACK4_PROOF_READY followed by JSON with kind, url
and pid; the parent reads complete ANSI-stripped lines from that launch's files,
requires the directly spawned host PID, then asserts its exact pid:UUID HTTP
header. The handle's pid is that same host PID. Vite's inline configuration
forces loopback, the selected port and strictPort:true over project settings;
the child tries each range candidate through listen, keeping the successful
socket. Selection uses {...process.env, ...options.env} at each invocation:
explicit env entries override the process environment and nothing writes back
to it. Browser undefined executablePath is omitted; a selected missing path
refuses with that path, never switches browsers; absent Playwright Chromium
also refuses. Sandbox diagnostic matching is case-insensitive on only the
listed patterns.

Save names are nonempty and contain no dot or leading dollar; ambiguous names
refuse at fixture validation before any case executes. Fixture object keys are
never substituted. $name with no field returns the
saved record's string id when present; otherwise it returns the saved scalar,
array or object unchanged. $name.field traverses object values and refuses
missing fields by name. Sole-key $literal and $$ escapes are terminal.
The CLI never writes saved variants into snapback; normal compile still reads
all snapback/*.q exactly as before. The explicit source flag selects one complete
backend even if it lives there, including the ordinary schema.q. Isolation here
means preserving working source/generated files and using private preparation,
not preventing a builder from manually placing another module in a watched
directory. Outside-snapback archive placement remains the documented recipe.

The private native tree includes its nested crates and standalone workspace.
Every copied Cargo.toml rebases dependency paths; internal dependencies point
to copied private crates, external SDK dependencies to their original installation.
Package source paths stay private. Workspace-inherited packages without a complete
standalone workspace under snapback/native refuse before compilation with the
standalone-workspace recipe. A missing member/dependency refuses normally from
the private build without affecting working files. RAII cleans snapshots on
ordinary errors/success; abrupt SIGKILL can leave a private scratch directory,
which is not a serving process or adopted release. No crash-time filesystem
cleanup claim is made.

## 9. Wave 13: saved-version proofs (DAY3, 2026-10-16)

Implementer: Codex, 2026-10-16. This amends §§2–3 and §8 source/fixture
selection, preserving release activation, authority, retention and wire semantics.
The shared layout is versions/v1/schema.q, original-name .q modules beside it,
and versions/v1/fixtures/. --schema and --source accept that directory; a
single complete .q still uses the canonical schema namespace. Compatibility
configuration resolves from the original project, including private builds
([REL3 §3](./3000.000.000.000-release-spanning-clients-and-development-contracts.rfc.md#3-generated-compatibility)).

Absent --fixture, --source selects saved-directory fixtures, or sibling
<stem>-fixtures for legacy complete saved files. Without those it validates
only working row files whose table exists, naming every excluded table file;
it skips the entire working cases file rather than silently reinterpreting
later-release cases. Shared-table rows still refuse unknown columns. Explicit
--fixture is always strict, including unknown tables/operations. No fixtures
means an announced query-only sweep. This changes test selection, not fixture
admission, and testSource delegates exactly to this CLI path.

Init writes version directories and fixtures directories; the npm day2:proof
script passes both version paths. A marked business assertion fails until
replaced; it is invoked at v1, v2, rollback and forward, before any success
claim. Frontend proofs run their frontend's own build via command() before
starting hosts; a missing/stale dist cannot pass on cached bytes. check calls
the adaptation plan and names the inherited no-arguments script with preview
and apply commands. Preview labels additions/replacements accurately and shows
changed npm script values. Modified application files remain owned by the app.
Guards report the actual received value.

Init bakes a complete environment range after explicit --port/--web-port and
--port-range, matching every printed URL to client, README and launcher defaults.
Runtime pairs override those defaults only through npm launchers/configs;
bare dev retains its documented default unless --port is explicit. Adapt reads
managed launchers/scripts rather than inferring ports from application client
source. The Expo setup runs init before installing the adapter, so the exact
Expo dependency set exists before peer resolution. Zero-sync Expo clients use
the online tier on all platforms, without native/web device imports.

Verification: saved directory and complete-file fixture cases, strict override
negative controls, inherited-script detection/preview/application, placeholder
failure, clean-dist build, explicit-port/environment precedence, zero-sync
Expo identity and persona clients, and packed compatibility day-two roundtrip.
