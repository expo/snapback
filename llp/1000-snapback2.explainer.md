## Summary

Snapback 2 is the from-scratch successor to Snapback, built in `snapback2/`
inside this repository so that Snapback 1's code, corpus, benchmark, and
diaries are a directory away to steal from — and fenced so that none of
Snapback 1's apparatus applies to it. Its design is already written: the data
language is [LLP 0329.014.004](./0329.014.004-bounded-data-programs-v1-design.rfc.md)
(bounded data programs, static certificate, one execution trace), and the loop
is [LLP 0329.016](./0329.016-agentic-dev-loop-from-scratch.rfc.md) (one owner,
`check` under a second, personas, no silent states, publish constantly). Both
are *proposals* until code here runs them (rules/RULES.md: only implemented
specs bind). This document records the founder's decisions of 2026-08-29 that
turned them into a repository, and is the orientation root for every LLP
numbered 1000 and up.

## Decisions (author, 2026-08-29)

1. **In-repo, behind a fence.** `snapback2/` is its own Cargo workspace
   (excluded from the root workspace) and its own Bun workspace (outside the
   root `packages/*`). No Snapback 1 gate, inventory, backstop, registry, or
   script applies to it; the pre-push hook selects gates by path and selects
   none here. Snapback 2 LLPs live in the shared `llp/` numbered from 1000 so
   they can cite the 0xxx corpus.
2. **cdcstack at the root, with baselines.** `rules/RULES.md` and
   `rules/NOT-DOING.md` bind the whole repository; Snapback 1's working set
   (59 links) and oversize files are baselined so the caps bite growth only,
   and its numbers may only fall. `scripts/caps.mjs` is the check.
3. **Ibex 2, embedded now, effects only.** `snapback2-effects` depends on the
   optional `ibex2-runtime` crate pinned to expo/ibex `c8e1941f6` (an owning
   Hermes runtime that re-exports Ibex's Rust standard library and bindings —
   ibex LLP 0057/0058/0068). `hermes-lean-sys` acquires and verifies the pinned
   engine. The default build links no engine; `--features hermes` links it
   through `scripts/hermes`. Queries and mutations never reach it.
4. **Types by inference.** No generated bytes are committed; the IR,
   certificate, and client stubs are a gitignored build cache.
5. **Three client surfaces, in priority order: React web, Expo, Exact 2.**
   All three matter. **2026-09-06 session-delegated amendment:** Exact 2 waits
   until exact Unicode prefix search qualifies on React web and Expo. The user
   delegated implementation decisions in this session; the resulting trade
   brings engine-maintained `wordPrefixes` and the indexed held-row twin onto
   the doing-list and permits one conventional core `build.rs` for shared
   pinned Unicode inputs. The 2026-09-07 LLP 1018.003 item-surface amendment
   sets 84,000 bytes gzip for the same complete local runtime, with an 80,000
   working target and unchanged runtime resource limits.
   This records a current decision, not a historical author ruling. LLP 1001
   §"Unicode search foundation" and LLP 1012 §"Indexed held search" separate
   the implemented foundation from remaining integration and qualification.
6. **From scratch, building up.** The seed is spike S1's crate (5,140 lines,
   4 dependencies plus SQLite, no Ibex) with `engine.rs` split under the
   1,500-line cap; pieces of Snapback 1 are pulled over one at a time, split
   on the way in, never wholesale.
7. **Iteration speed above everything.** Few, fast tests run locally before
   push; no push gated on a battery; the complete sweep runs on a schedule;
   worktrees are named lanes, reused; the loop is measured on every run
   (`snapback2/scripts/measure.mjs` → `snapback2/metrics/loop.jsonl`) with
   budgets in `rules/RULES.md`.
8. **Publish from day one.** `snapback2/scripts/publish.mjs` builds the
   production binary and publishes the platform package plus the `snapback2`
   shim in seconds; the artifact size is a measured number.
9. **The benchmark is Snapback 1's.** `benchmarks/` (Clique M1–M8, the
   protocol in `benchmarks/protocol.md`) runs against published Snapback 2 as
   soon as `init` and `dev` exist. Promotion is the author's call.

10. **Quarry is the default authoring surface (author, 2026-08-31).**
    Backends are `snapback/*.q`, compiled by the Quarry front end inside
    the compiler (`packages/compiler/src/quarry/`, in memory, no generated
    files). The TypeScript authoring surface was deleted on 2026-09-02
    (LLP 1007 §4b, LLP 1004 amendment). Since LLP 1018.000's direct compiler
    work, Quarry binds to typed IR; TypeScript is the harness language for
    seeds, journeys, and effect bodies only. Ruling and evidence: [LLP 1004](./1004-quarry-default-surface.decision.md),
    on the executed head-to-head of LLP 0329.014.011; the ruling was
    found unimplemented by LLP 1007 §2 on 2026-09-01 and built on
    2026-09-02 (LLP 1004 §"Implementation record").

The complete local runtime's allocation is **90,000 gzip bytes**, with an
**80,000-byte target** (2026-09-10 author ruling, `rules/NOT-DOING.md`;
LLP 1018.008 §10). The measurement roots and separate package-growth checks
remain unchanged.
React/Expo implementation is not a blanket offline-bar or publication claim;
the scoped qualification records remain in LLP 1012 and the benchmark LLPs.

LLPs 1019–1021 are being implemented independently: derived delivery custody
and receipts; additive successor evolution and legible costs; effects in the
loop. Their dated implementation records distinguish landed pieces from open
work. LLP 1018.008 follows up on remaining ergonomic costs without duplicating
those commissions. Hosted provider/control-plane lanes beyond H0, Exact 2,
and the other excluded features remain governed by `rules/NOT-DOING.md`.
