## 2. Read guards

N_LOOKUP_FILTERED and N_QUERY_FILTERED inspect pure, bounded helper return
expressions before deciding a caller guard fails to establish read authority.
Reuse the existing 32-level lexical helper expansion; unresolved recursion,
effects and unsupported control flow remain opaque. A successful call's
Boolean return may supply its expanded positive witness; a negative
caller-filtered existence result must never establish raw absence. Existing
lexical fact invalidation on rebinding/writes remains authoritative. Expanded
advisory facts never enter type, presence, runtime or gate proof domains.
A role union must imply the reader union for every arm, not merely overlap it.
Before expansion, inspect every evaluated argument and reachable helper body
under a 4096-node/32-level scan bound. Preflight the substituted tree with argument/local multiplicity weights under the same 4096-node ceiling before constructing it. A discarded effectful argument cannot
supply a current witness. Distinct advisory namespaces retain lexical proof keys
and transaction invalidation without entering runtime proof domains.
A present row selected by a total non-null unique key has exactly one value of
each required finite enum (at most 32 alternatives). Safe negative witnesses can
exclude alternatives only for that same key and field. Nullable enum columns,
hidden negative probes and partial/nonunique keys do not gain exhaustiveness.
A write to an unresolved authored row target cuts saved advisory facts rather than treating its lexical name as another table. Recipient-role facts expire on potentially aliasing dependency writes. Reverse reference substitution uses the actual linked child field even when parent and child names differ.
Live captured row fields can describe the same unique row until a write,
rebinding or authority edge invalidates the advisory snapshot; hidden columns
supply no such fact.
Require-only pure helper calls also export their dominating caller-only consequences. Unsupported conjuncts weaken to true, preserving OR alternatives. Visible points may supply their scoped reader policy; a filtered negative point never supplies raw absence. Facts survive unrelated direct writes only if all referenced raw tables remain unchanged and there are no implicit maintain/lifetime dependencies.

Advisory source consistency may relate immutable child fields to immutable parent fields through a required immutable reference. Every source constructor and both upsert arms must establish the copy or an explicit equality; missing/unknown/native source ingress disables the model. Uncalled effectful helpers disable consistency inference rather than supplying an incomplete writer set. Every raw write site, including update/delete targets, must be represented. Constructor keys count as assignments. A 4096-node source/call-cost budget and bounded pure expansion cut the optional model before expensive source walking. A captured pre-write parent cannot establish a fresh copy after a potential parent write. The model is a reason to omit a source review question, never a database invariant, authority or safety proof.

A later require cannot authorize an earlier lookup. Read-through parents and
snapshot-derived caller fields must preserve resource identity.

## 3. Lifecycle questions

N_EDIT_AFTER_APPROVAL concerns edits, not fresh insertion. Upsert retains its
existing-row arm. A lifecycle guard on the selected row may use a non-default
source stage, a null approval stamp, a coalesced optional Boolean, or exclusive
branches. Represent a non-null Time symbolically, not by one sample epoch. Only proved nullness restrictions can exclude every non-null stamp; an equality or range admitting a particular non-null timestamp retains the question. Check finite enum/Boolean domains: a tautology or unrelated row/field
cannot suppress the question. Known approval/post states must be excluded;
positive approval and broad exclusions such as stage != cancelled retain the
question. A field's own null-only initialization is distinct from replacement. A captured source-stage or null-initialization condition is stale after any prior potentially aliasing write to that field; it cannot suppress a later edit question. Lifecycle columns themselves are not evidence
payload. A coalesced assignment that preserves an existing non-null payload is
not evidence replacement; direct replacement/removal remains reviewable.
Schema-enforced immutable/column update policies may answer the edit question. One-way quantification covers all source program kinds, jobs and unknown/native footprints. Only opposite branch markers at the same source condition and instantiated call chain establish exclusive paths; sequential tests and separate helper calls remain distinct. Loop backedges may execute both arms, and a later lexical write in the same iteration region can precede the next effect. Lifecycle/window freshness and one-use consumption retain the question for such possibly repeated writes; this conservative source analysis does not prove that a loop captured a fresh row on every iteration. One-way idempotent facts and clock-derived source-stage advances are not arbitrary payload replacement. Applying an immutable, linked amendment payload while atomically recording its previously null approval answers the reapproval question; unrelated, mutable, unstamped or conditionally skipped requests do not.

N_GUARD_NOT_CONSUMED does not infer single-use intent from standing role,
material, hold or parent-stage predicates. Ask about approval/consent/payment
reuse when a transition has neither consumption nor a source-stage restriction.
Consumption must invalidate the exact checked prerequisite (for example set a required Boolean false) on every path containing the effect. A same-named field on another row, skipped branch or preserving
assignment cannot answer it. Source-stage suppression requires the assigned
destination itself to be excluded, not merely some unrelated stage. Both insert
and upsert birth arms retain approval/consent/payment reuse questions.
A repeat create from an existing same-table reference remains a question when
its parent guard is left unchanged. Report once per mutation, preserving the
unproved write site. None of these reductions infer a gate or prove safety.

## 4. Operator provisioning

The guide staging recipe intentionally delegates recipient selection to the
local service:operator seat. Suppress N_ARGUMENT_GRANT only when effective
write admission (table rule and dominating requirements) implies that exact
seat, including both upsert arms and owner-field bypasses. When those bypasses are not modeled, the table rule alone cannot establish the exemption. An operation called provision alone is not
an exemption; ordinary staff callers still need the recipient question unless a dominating role lookup or exact linked stored-recipient comparison already validates that argument on every path. An unrelated lookup elsewhere in the operation does not count.
The reserved service:clock seat owns the built-in development clock door and
does not need a schema authorization mention to avoid the token warning.
Other seats retain the warning and all operation rules still apply.

## 5. Time windows

Transpose reversed comparisons without losing strict/equal boundaries. Match
exact duration shifts on the stored deadline and server clock, so
`now <= createdAt + 14d` excludes `createdAt < periodEnd - 14d`; equality overlap
retains its question. Unknown/non-affine relationships remain conservative, including a job-side
unknown offset: the question remains. Negate Boolean compositions by polarity;
never complement an approximate mask whose unknown terms were overapproximated.
Pair mutation and sweep reads by resource identity, retaining chosen-branch
guards. N_DEPENDENT_WINDOW follows the actual written reference; a stored
return/approval timestamp on that resource may define the window even if a
different column happens to contain due/deadline in its name. An ordered relationship must hold on the chosen write path, preserving Boolean polarity and every alternative; a caller-controlled OR bypass is not a bound. An explicit applicability exception on a required stored Boolean of that exact parent (for example, `not workshop.standing or scheduledAt <= workshop.restockDue`) answers whether the authored window uses the parent. This recognizes the conditional policy already written; it does not establish that the specification intended that exception. Unrelated rows, caller flags, time-presence tests and stale parent Booleans remain opaque. It must involve the caller Time actually written;
timestamp presence alone cannot answer it. A different resource or secondary
reference-key lookup cannot answer it. Missing/null optional links do not create a window. A prior potentially aliasing write to the actual reference or parent timestamp invalidates the captured comparison. Merely containing a timestamp inside an unsupported conditional or cancellation expression is not an ordered bound. Only authored, required or explicitly non-null/atomically rewritten parent time columns are window candidates; generated deadline metadata is not an independent parent obligation.

Sweeps and mutations compare finite source states and optional stamp presence, and may recognize a mutation that performs the same terminal transition or explicitly accepts the sweep destination. Source-wide monotone stamp/stage relations require complete constructors, initially null stamps, coupled non-null assignments and no reset into the sweep stage without clearing the stamp. Unknown ingress, spreads, dynamic resets and non-affine arithmetic retain questions. This is advisory relevance analysis, not a proof over imported database states. Source-only consistency never certifies seed/import/restore images: those paths remain governed by their independent runtime, schema-invariant and witness protocols. Source-oriented advice can omit a question that is already addressed across all authored constructors; that omission must never be promoted into a claim about externally supplied rows.
