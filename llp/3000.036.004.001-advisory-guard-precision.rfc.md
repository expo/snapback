## 2. Read guards

N_LOOKUP_FILTERED and N_QUERY_FILTERED inspect pure, bounded helper return
expressions before deciding a caller guard fails to establish read authority.
Reuse the existing 32-level lexical helper expansion; unresolved recursion,
effects and unsupported control flow remain opaque. A successful call's
Boolean return may supply its expanded positive witness; a negative
caller-filtered existence result must never establish raw absence. Existing
lexical fact invalidation on rebinding/writes remains authoritative. Expanded
advisory facts never enter type, presence, runtime or gate proof domains.
A role union must imply the reader union for every arm, not merely overlap it.
Before expansion, inspect every evaluated argument and reachable helper body
under a shared 4096-node/32-level bound. A discarded effectful argument cannot
supply a current witness. Distinct advisory namespaces retain lexical proof keys
and transaction invalidation without entering runtime proof domains.
A present row selected by a total non-null unique key has exactly one value of
each required finite enum (at most 32 alternatives). Safe negative witnesses can
exclude alternatives only for that same key and field. Nullable enum columns,
hidden negative probes and partial/nonunique keys do not gain exhaustiveness.
Live captured row fields can describe the same unique row until a write,
rebinding or authority edge invalidates the advisory snapshot; hidden columns
supply no such fact.
A later require cannot authorize an earlier lookup. Read-through parents and
snapshot-derived caller fields must preserve resource identity.

## 3. Lifecycle questions

N_EDIT_AFTER_APPROVAL concerns edits, not fresh insertion. Upsert retains its
existing-row arm. A lifecycle guard on the selected row may use a non-default
source stage, a null approval stamp, a coalesced optional Boolean, or exclusive
branches. Check finite enum/Boolean domains: a tautology or unrelated row/field
cannot suppress the question. Known approval/post states must be excluded;
positive approval and broad exclusions such as stage != cancelled retain the
question. A field's own null-only initialization is distinct from replacement. Lifecycle columns themselves are not evidence
payload. A coalesced assignment that preserves an existing non-null payload is
not evidence replacement; direct replacement/removal remains reviewable.
Schema-enforced immutable/column update policies may answer the edit question.

N_GUARD_NOT_CONSUMED does not infer single-use intent from standing role,
material, hold or parent-stage predicates. Ask about approval/consent/payment
reuse when a transition has neither consumption nor a source-stage restriction.
Consumption must set the exact checked Boolean false on every path containing
the effect. A same-named field on another row, skipped branch or preserving
assignment cannot answer it. Source-stage suppression requires the assigned
destination itself to be excluded, not merely some unrelated stage. Both insert
and upsert birth arms retain approval/consent/payment reuse questions.
A repeat create from an existing same-table reference remains a question when
its parent guard is left unchanged. Report once per mutation, preserving the
unproved write site. None of these reductions infer a gate or prove safety.

## 4. Operator provisioning

The guide staging recipe intentionally delegates recipient selection to the
local service:operator seat. Suppress N_ARGUMENT_GRANT only when effective
write admission (table rule and dominating requirements) implies that exact
seat, including both upsert arms and owner-field bypasses. When those bypasses are not modeled, the table rule alone cannot establish the exemption. An operation called provision alone is not
an exemption; ordinary staff callers still need the recipient question.
The reserved service:clock seat owns the built-in development clock door and
does not need a schema authorization mention to avoid the token warning.
Other seats retain the warning and all operation rules still apply.

## 5. Time windows

Transpose reversed comparisons without losing strict/equal boundaries. Match
exact duration shifts on the stored deadline and server clock, so
`now <= createdAt + 14d` excludes `createdAt < periodEnd - 14d`; equality overlap
retains its question. Unknown/non-affine relationships remain conservative, including a job-side
unknown offset: the question remains. Negate Boolean compositions by polarity;
never complement an approximate mask whose unknown terms were overapproximated.
Pair mutation and sweep reads by resource identity, retaining chosen-branch
guards. N_DEPENDENT_WINDOW follows the actual written reference; a stored
return/approval timestamp on that resource may define the window even if a
different column happens to contain due/deadline in its name. An ordered relationship must involve the caller Time actually written;
timestamp presence alone cannot answer it. A different resource or secondary
reference-key lookup cannot answer it. Missing/null optional links do not create a window.
