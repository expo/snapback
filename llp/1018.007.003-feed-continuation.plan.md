## Evidence

Astra's API walks return many pages: the grader records 263 distinct global
entries and 216 author posts. Global, Following and author views render 20 and
report no continuation. `src/Posts.tsx` passes the right `c` default to usePage;
the Quarry queries declare `c: cursor ?` and return a projected page. Both a
scroll callback and conditional Load more control are present. The UI symptom
is not sufficient evidence that FlatList is broken.

In current source, `ClientPages.refresh` reads `query.getSnapshot().next` and
derives `hasMore` from the last page. Trace the first frame through receipt
capture, local refresh, Snapshot derivation and ClientPages before assigning
the loss to any one layer. Compare direct reads, observed reads and React,
with and without offline storage, using the same projected-page query.

A source-seam reproduction already demonstrates the loss: the production
offlineView preference chooses a twin partial over a capped owner answer;
the actual Snapshot/ClientPages chain changes 20 rows with hasMore=true into
20 rows with hasMore=false. The partial was injected, so it does not establish
Astra's specific missing coverage. Existing usePage owner integration runs
without offline storage and misses this branch. Capture the actual partial
sites and issuing-query coverage before choosing between reconstruction repair
and coherent retention of the owner's still-valid answer.

The local result need not be partial: complete/capped evaluation may lack
`lastReturnedSuffix` and produce null next, or carry an operation-bound local
cursor. Capture all three cases. A partial-only fallback is not a sufficient
fix. Keep a still-valid owner capped continuation across an actual carrier
input refresh, with its result and proof, without manufacturing coverage.

## Repair

Implementer: Codex gpt-5.6-sol, starting 2026-09-09. Create at least 45 rows
for each of Global, Following and author query shapes in a fresh owner project.
Record server next, held next, local next, snapshot next and hasMore. Use the
existing real-owner/React test helpers; a fake snapshot alone cannot demonstrate
the actual defect.

Fix the layer that discards or misroutes an authorized continuation. Keep its
operation, arguments, direction, authority and generation provenance. Local
cursors cannot reach the server, and history/composite cursors cannot cross
query identities. Preserve a retained partial boundary only under LLP 1012's
existing retained proof; never mint a cursor from unknown coverage or turn a
capped result into a complete one merely to expose a button.

ClientPages continues owning its observations and rebinds successors when a
live boundary changes. Changing feed or author resets that page chain. Do not
add app-side cursor caches, guessed offsets, or a second infinite-scroll hook.

## Acceptance

The 2026-09-09 real-owner/file-carrier reproduction now isolates the reported
path. A shaped feed with a maintained like count and per-viewer `exists`
returns a capped server page at sequence 45, with a non-null owner cursor.
The held record remains capped at 45 with that cursor, 20 row IDs and the
matching held suffix. The twin instead reports partial sites
`carrier.global.2` and `carrier.global.3` (`computed-key`), omits `next`, and
the following carrier-input refresh publishes `hasMore: false` to React.
A simpler projection without those computed reads retained its continuation.
This is an executed owner/carrier witness, not the earlier injected-partial
seam probe. The repair and boundary/authority regressions remain in progress.

Render and load 20 + 20 + 5 rows through usePage. Assert exact IDs/order without
duplicates or omissions and `hasMore` true until the final page. Cover projected
page aliases, Following merge, author filtering and both omitted/explicit-null
head cursor. Check observer and React behavior after carrier input refresh.

While page two is open, insert at the head and delete around the boundary;
assert the resulting chain agrees with a direct fresh walk. Switch account,
author and generation to demonstrate stale continuations cannot leak. Add
warm/cold offline cases using only coverage actually held. Any partial/capped
limit still has its truthful status and continuation semantics.

Update existing pagination guide text only where the corrected contract needs
clarification. The isolated Astra app copy must reach its older rows without
an application workaround before closing the original symptom.

## Conservative overlay boundary

The correction preserves one exact receipt-time owner page whole, not an old
cursor attached to a changed local projection. While any prediction remains
active in the partition, including a committed removal awaiting retirement,
that fallback is unavailable. Even an apparently unrelated chat write can
therefore temporarily suppress continuation on a partial computed feed. The
guard is conservative because current row-key observations do not prove all
filter, maintained-value, rule, missing-row and range dependencies disjoint.
Do not bypass it by operation name or intersecting returned row ids.

Retain a regression for unrelated active prediction → truthful partial/no
continuation → retirement → restored 20/20/5 page chain, alongside the
removal-only negative. The original clean-outbox permanent first-page symptom
must still pass in the actual Astra copy. This plan does not promise offline
pagination through unproven computed coverage while writes remain queued.
