## Outcome and scope

Make the consequences of an ordinary application edit understandable and its
suggested repairs dependable. Reduce unnecessary certification cost only where
the actual runtime custody proves a smaller bound. Preserve safe additive
evolution and coherent client transitions.

This is the plan for [locality of application changes](./1018.008.008-locality-of-application-changes.research.md).
Implementer: Codex; commissioned 2026-09-11 after the panel disposition above.
The implementation baseline is `bf8450849`; the initial research inspected
`b47337b26`. The implementation record below separates new work from reused
proofs and research that stops without a runtime change.

LLP 1020 Part A is the implemented baseline. Keep its widening, narrowing,
maintain ownership, recurrence pricing, and `check --cost`. Its Part B `fill`
form remains deferred. Broad schema-bound policy identities also remain the
production contract. Useful diagnostics/repair changes can ship independently
of an experiment failing to establish safe semantic locality.

## L1 — Reproduce the edit and classify its consequences

In an isolated copy, adapt the retained day-two search fixture to the current
compiler/package. Compare the populated schema before and after adding
`editedAt: time ?`. Retain both full `check --cost --json` analyses and the
ordinary check verdict; do not replace the current fixture with the historical
4,199,688-byte number if today's analyzer reports something different.

Separate four causes: row/closure width, output shape, repeated reads/authority
work, and evidence/generation changes. Keep controls for a disconnected table
edit, enum widening, a larger bounded field, a reachable policy change, and an
internal helper refactor with the same executable meaning.

Record which queries changed and why, whether the old generation continues
serving during refusal, and what happens to live observations and queued
intents. Do not omit ordinary `expected_generation` or other client envelope
fields to make a compatibility example pass. Preserve exact submitted bytes.

Implement this as a small extension of `tests/check_cost.rs` and existing
Quarry/successor fixtures, not a new catalog or gate. The observed edit is the
primary useful example; synthetic cases isolate causes and validate bounds.

## L2 — Explain width and multiplicity with the existing analyzer

`certificate/search/closure.rs` already prices full row-image pools, range
metadata, references, and authority; `ByteShape` already represents diagnostic
structure. `CostTerm` feeds both successful and refused `check --cost` output.
Extend those structures only as needed to expose a reconciled decomposition:

- Which table/field bounds contribute to a row width, including optional value/null maxima,
  declared identity width, encoding overhead, and escaped maximum values.
- How many images/ranges/probes multiply that width, tied to the responsible
  operation and authored site when one exists.
- Which terms are separate serialized evidence and which represent shared
  first-image custody; do not describe their prices as interchangeable.
- The actual ceiling, total, and useful suggested rewrite, with exact integer
  accounting and explicit maximum/branch relationships.

Use `bounds.rs`, `collection_rewrite.rs`, `certificate/diagnostic.rs`,
`certificate/inspection.rs`, and `check.rs::print_cost`. Avoid a second
estimator in the CLI. A diagnostic analysis still grants no admission.
If an explanation already exists for the reproduced shape, reuse it and fix
discovery/presentation rather than adding another output field.

The builder should be able to identify the optional field's contribution and
its multiplicity from one inspection. The report need not add a new CLI verb,
persist previous certificates, or automatically run an expensive matrix of
counterfactual schemas. Comparing the before/after outputs is sufficient for
this slice. Keep `check` latency within its existing budget and all failures
reported in one run.

Suggested repairs must state their semantic consequences. Smaller pages may
preserve full reachability only when the query has valid continuation and the
client follows it. Narrower product populations, weaker authorization, or
dropping a required field are not transparent optimizations.

## L3 — Verify and reuse the completed repair audit

The [successor residual](../issues/closed/20260910-snapback2-succ-review-residuals.md)
is closed on `bf8450849`. The engine generates eleven repair families and
pins them to `exhaustive-repairs.q`; the compiler lowers and certifies that
same file. The positional Get now invokes `Checker`, and the projection union
is named `replaced_projection_ids`. These are existing implementations.

Run the existing engine and compiler checks, confirming that their predecessor
schema contexts match, including explicitly staged widening for disjoint enums.
Generation-equals-fixture plus compilation of that same fixture connects the
actual generated bytes to the compiler. Do not replace it with a direct
cross-language pipe merely because the proof has two checks.

Extend an existing test only for a demonstrated missing emitted shape, schema
context mismatch, or populated-data behavior. Keep job keys immutable/total,
retries resumable, and migration approval semantics unchanged. No new generator,
inventory, gate, or deferred `fill` form belongs to this slice. Device-work-list
dismissal remains in the recovery plan; reuse the already centralized predicate.

## L4 — Reduce one proven unnecessary cost, conditionally

After L1 attribution, select a narrow implementation only when the runtime
requires less custody than certification currently prices. A useful first
candidate is repeated point reads of the same statically identical unique key
in a read-only program: investigate whether they retain one row image but are
charged for several. Prove table, typed key, viewer, schema, and execution
identity; keep dynamic/loop/branch cases conservative unless separately proved.

This is a candidate, not an assertion that the current analyzer overprices it.
Keep probe execution, verdict envelopes, references, and other separately
serialized bytes priced even when an immutable row image is shared. Use the
actual native receipt builder and TypeScript held representation as evidence.

Likewise, a field absent from the public output may still be required in a
whole-row receipt, rule, index, or predicted operation. Do not subtract that
field from the certificate merely because an output selector omits it. If the
runtime truly needs every field in the optional-timestamp example, retain the
bound and deliver L2's explanation; changing custody representation would need
a separate reviewed design.

For any selected optimization, add maximum-width, escaping, branch/loop,
repeated-key/distinct-key, and authority controls. Native and twin execution
must remain within the same declared ceiling. Explain the semantic exclusion
that permits the saved bytes; a low measured average does not prove a bound.
Land no weakened price that lacks a runtime counterpart or proof.

## L5 — Prove evolution continuity and bound hash research

The [hot-regroup ticket](../issues/closed/20260910-snapback2-online-client-query-during-hot-regroup.md)
is also closed on the current baseline. Reuse `real-owner-successor.test.ts`'s
retained original online/offline clients and deterministic response barriers.
The atomic program-adoption fix withdraws predecessor coverage in the same
carrier swap; `supersession.test.ts` covers file/IndexedDB custody and late
older responses. Run those controls and record their actual scope. Add a fix
or barrier only if a remaining interleaving is demonstrated; a fresh client
or nondeterministic non-reproduction cannot replace these existing witnesses.

Authorization-hash narrowing remains a separate bounded experiment under
[LLP 1018.002 §7](./1018.002-dependency-scoped-invalidation.rfc.md#7-follow-up-after-the-elegance-assessment).
Its existing positive/negative matrix governs: disconnected-table and subject-
field edits, transitive/cyclic policy changes, identity/epoch changes, and
lost-ack terminal lookup. Production producer/replay/twin identities remain
unchanged in this plan. Continue to a runtime proposal only after a useful
actual application conflict is avoided with unchanged admitted bytes and all
relevant checks preserved. A contrived benefit is grounds to stop the experiment.

## Delivery and acceptance

Recommended sequence: L1 reproduction, then independent L2 cost explanation
and L3 repair-audit verification; L4 only for an attributed opportunity. L5's
existing continuity verification can proceed independently, with shared successor
files coordinated by one owner. Hash research is not a prerequisite for any
of those landings or a promised optimization.

Validation uses existing cost, successor, compiler-job, native/twin corpus,
and real-owner tests. Record operation prices before/after, populated data
preservation, actual client transitions, and full correction steps in a copied
day-two workload. A pure refactor remains a same-generation control. Measure
check latency and affected runtime/package bytes; retain all current ceilings.

Update `guide bounds`, `guide successor`, implemented LLP 1020 sections, and
the relevant diary with the behavior actually shipped. Use the ordinary fast
checks and existing longer witness path; no exact-HEAD battery gate, new
registry, or generic compatibility mechanism is introduced.

Completion of L2/L3 alone closes their specific diagnostic/repair work, not the
entire locality problem. Record L4/L5 negative results and remaining boundaries
explicitly. Follow the three-round repair rule; preserve working candidates
and do not expand authority or migration scope to force a green result.

### L2: explanations preserve the certified arithmetic

`RowFlow` keeps separate diagnostic portions for full rows and projected
values, using the same existing widths/counts/retained totals. Projection,
branch and growth operations keep their existing conservative prices.
`ByteShape` retains explicit source sites and field-bound detail; the existing
`CostTerm.source` carries the multiplier and per-value bytes to both CLI forms.
Optional values choose max(value, null reserve), not an additive presence tag.
Search pools expose declared row fields and table/id envelopes separately from
range, point and authority evidence. Exact signed adjustments reconcile even
saturated refused bounds. No ceiling or runtime custody representation changes.

The reproduced failure also exposed a diagnostic cascade: per-operation
certification kept schedule bindings but dropped their targets. One real
closure refusal consequently produced 216 spurious `E_SCHEDULE_TARGET` entries
in the full cost report. Targets now travel with bindings through the existing
generation checker. Valid operations keep their certificates; the actual
ceiling refusal remains. This grants no partial generation admission.

The existing `check_cost.rs` now carries the reduced four-table day-two query,
the exact before/after/page-19 totals, source-line/multiplier assertions, a
first-image/authority decomposition control, and the schedule-cascade regression.
Existing native growth/branch/alias/escaping executions also reconcile every
emitted byte term; a saturated refused case checks exact signed accounting.

### L3/L5 reuse and L4/hash stop

The existing engine tests for all eleven generated repair families and the
certified positional Get pass (2/2); the same fixture remains the compiler's
input. Neither the audit nor the retained-client hot-regroup barriers was
rebuilt. The independent successor/supersession suite supplies the current
live/resume, old-response and queued-byte controls described in L5.

No L4 price reduction is selected. Full-row receipt custody includes the
timestamp even when output projects it away. Native first-image sharing is
real, but subtracting repeated point-read cost also needs proof about retained
expression values, keys, references and authority. This run establishes no
useful safe reduction and adds no new custody representation.

LLP 1018.002's production hash domains remain unchanged. In particular,
`expected_generation`, exact queued envelopes and stable terminal lookup are
not bypassed to manufacture a locality result. One existing coupling remains:
the program generation digests complete certificates, including diagnostic
terms. `check --json.generation` is the schema-only hash and does not expose that
separate `program_hash`. Better diagnostic wording can change program custody on
a compiler upgrade even when schema, executable IR and certified prices are
unchanged. The same-version helper-refactor control is not a claim to have
removed that coupling.
