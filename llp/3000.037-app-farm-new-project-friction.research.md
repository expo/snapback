## Summary

The author asked for a repeated loop: build 100 new apps on the published
`snapback4`, keep a diary per app, cluster what was hard, fix every pattern,
release, and repeat. This document records wave 1 (built on 0.4.16) and the
fixes carried by 0.4.17. It is evidence about a fresh builder's first hour,
not about scale or long-lived products.

## 1. Method

- 100 app ideas, each needing a backend with at least two personas and real
  access rules (book club, potluck planner, silent auction, clinic queue, …).
- Builder per app: a coin flip between Codex `gpt-6.1-sol` (high) and Muse
  `muse-spark-1.3-contributor` (high), 51/49. Frontend per app: uniformly
  React web (Vite), Expo, or Exact2. Up to 50 builders ran at once on one
  96-core Linux host.
- Each builder installed the package from the registry, read only the shipped
  docs, guide and diagnostics, and had to reach four proofs: `check` clean,
  a fixture run, an HTTP acceptance script as each persona with asserted
  refusals, and a frontend build/typecheck.
- Each kept `DIARY.md`, a structured `friction.jsonl` (area, kind, minutes
  lost, suggested fix) and `REPORT.md`. 711 friction entries (2,617 minutes
  logged lost; 388 self-classified as the agent's own error) were clustered
  by distinct lanes affected.

The harness, briefs, diaries and the clustered analysis live outside the
repository (`~/sb4-loop/wave1/`); this document carries the conclusions.

## 2. Outcome of wave 1

- 95 of 100 finished inside the window; all 95 reached `check` clean. React
  and Expo frontends verified 30/30 and 32/32. Exact2 frontends were not
  independently re-verified (the harness re-ran `test web` without the live
  backend those tests need); the builders' own reports show them passing.
- Mean self-rating 7.8/10. Codex lanes typically finished in 5–20 minutes,
  Muse lanes in 15–40.

## 4. Exact2

Exact2-side findings (no port option for `test web`/`agent web`, `--help`
running commands, working-directory sensitivity, no backend preflight, mount
and wasm wiring) were fixed on a local Exact2 branch for the next wave and
are for that project to land.

## 5. What the harness taught

A brief that requires every builder to start and stop `dev` from a script
exposes lifecycle defects to nearly 100% of builders; that is why #1 reached
45 lanes. Shared-host hygiene (per-lane `TMPDIR`, absolute tool paths,
self-contained `frontend:proof` scripts) belongs in the harness, not the
product.

## 9. Wave 5 (built on 0.4.20): green, and a plateau

100 new ideas; Codex 53, Muse 47; React 37, Expo 30, Exact2 33. The first
wave where every lane passed every harness re-run: `check`, acceptance and
frontend proof 100/100. 0.4.20's one regression was a mislabeled button.

| | W1 | W2 | W3 | W4 | W5 |
|---|---:|---:|---:|---:|---:|
| Entries | 711 | 541 | 500 | 458 | 455 |
| Minutes lost | 2,617 | 1,686 | 1,160 | 1,037 | 1,056 |
| Mean rating | 7.80 | 8.09 | 8.28 | 8.39 | 8.36 |

Friction stopped falling. Builders log about 4.5 entries per lane however
small the friction (Codex now logs zero-minute items), and agent-error
minutes rose while everything else fell. Of the remaining minutes, the
wave-5 analysis attributes about 38% to fixable product issues, 21% to
deliberate design limits, 27% to agent error and 8% to Exact2.

0.4.21 fixed the product share: a projection shape that lost its covering
cap; `test` counting an argument-free `require` refusal as denied; unknown
keys in `test.cases.jsonl` passing silently; a staff grant inside `where`
(row-independent tests now move out of a returned page into an `if`, LLP
3000.036 §15.4); the compiled owner-or-staff rewrite printed by default;
the last `$`-prefixed internals in diagnostics (swept across all 500 farm
schemas); keyed-lookup, view-clause-order and `int 1..N` messages; a
`N_DELETE_ORPHANS` note; `dev --port A-B`; the refusal-order contradiction;
about fifteen verified one-line answers (escapes, integer division, delete
and unique-swap semantics); `--find` over all words and a sectioned language
card; `isFailed` on hooks; and a real read in the adapted `Home`.

### Decisions this loop cannot make

Each recurs every wave and is recorded in its LLP:

- A device-less durable browser write path (29 lanes in wave 5; LLP 3000.013 §6.2).
- A merged owner-or-X page and union sync audiences (LLP 3000.036.000).
- Parent delete: refuse while children exist, or declared cascade (LLP 3000.036 §15.8).
- Bounded `int`, calendar `month`/`year`, global caps for small tables, generic file assets.
- Exact2: Snapback codes in `failure().code` (Exact LLP 1109 D3).
- Open defect: `exists t where …` over a per-row read rule returns null with a visible match (`issues/20261011-snapback4-search-exists-null-with-visible-match.md`).

## 10. Wave 6 (built on 0.4.21) and what 0.4.22 changed

100 new ideas; Codex 49, Muse 51; React 28, Expo 39, Exact2 33. All harness
re-runs green again (100/100/100). 451 entries, 1,009 minutes, self-rating
8.43 (the highest), docs gaps 29.

Two 0.4.21 regressions, both in `check` notes it newly printed by default:
the owner-or-staff rewrite could drop a party (3 lanes, each named it first;
applied as written, some readers would lose rows), and `N_DELETE_ORPHANS`
ignored zero-count guards. 0.4.22 builds that rewrite from every disjunct
and prints it only once a mechanical comparison proves it returns exactly
the rule's rows (LLP 3000.036 §16.1), and accepts an unfiltered count view
as the guard. It also adds four authorization lints found by builders'
own near-misses (`N_PROBE_ONLY_READ`, `N_VACUOUS_RULE`, `N_LOOKUP_HIDDEN`,
a counter case of `N_WRITE_DENIED`; run over all 600 farm schemas, the
probe-only lint found two real leaks), separates views from tables in
`check`, collapses repeated notes, and shortens `dev` refusal lines.

On the client: `matchRead`'s `present` payload was mistyped since 0.4.20
(blocking `rows[0]`); `Outcome`, `isFailed(unknown)` and `otherwiseAll`
(one explicit token for every non-present branch, keeping LLP 3000.031 §8);
`usePersonaApp`. In the guide: piped output prints the opening and first
section, aliases land on sections, and roles/cheatsheet show the one-page
owner-or-staff form. A search `exists` over a per-row rule now answers a
readable match `true` (LLP 3000.036 §15.12; the Lean model follow-up is in
`lean/OPEN.md` C5).

Lanes per open design decision in wave 6 (§9): device-less browser writes
26; union sync audiences 14; `matchRead`'s explicit denied/partial 14
(since eased by `otherwiseAll`); parent delete 10; merged owner-or-X page 7
(+5 parent-pinned grants, runtime deferred to
`issues/closed/20261011-snapback4-prefix-decided-grants-at-run-time.md`,
implemented 2026-10-12, LLP 3000.036 §16.3); small-table
caps 6; bounded `int`, calendar months, file assets and Exact `failure().code`
0–2 each.

## 12. Wave 8 (built on 0.4.23): the first day-two lanes, and what 0.4.24 changed

Half of wave 8 was new apps (50 odd lanes, new ideas) and half was **day
two** (50 even lanes): a builder took over a wave-7 app, upgraded it to
0.4.23, deployed it with `deploy` and `serve` and real password sign-in,
evolved its schema on live data (a new table, a new required column on a
populated table, and an enum value or a tightened rule), deployed again,
rolled back and forward, and proved the whole sequence in a
`day2:proof` script the harness re-runs. Muse's plan quota ran out early,
so Codex built 92 lanes (the harness now falls back to a Meta API key for
Muse). All 100 re-runs green, including 50/50 `day2:proof`.

| | New-app lanes | Day-two lanes |
|---|---|---|
| Mean self-rating | 8.28 | 7.38 |
| Friction entries per lane | 4.7 | 7.2 |

597 entries, 1,161 minutes; entries classified as Snapback defects rose
from 6 to 31, nearly all on day-two paths the farm had never exercised.
Migration was the costliest area (212 minutes). The day-two findings, all
fixed in 0.4.24:

- **Rollback destroyed data** (all 50 lanes): `rollback` re-adopted the older
  schema destructively, deleting the newer release's tables and columns;
  rolling forward brought them back empty. 0.4.24 keeps newer storage
  dormant on rollback, restores it on roll forward, removes it only through
  an explicit, previewed `prune`, and names rows, values and repair commands
  in every refusal (LLP 3000.000.000).
- **`deploy` required stopping `serve`** (12 lanes): deploy now adopts into the
  running server atomically; a failed adoption leaves the old release
  serving, and clients re-acquire on the new generation.
- **Production surface**: `serve --port` silently ignored ranges and junk
  (30 lanes); no guide card for deploy, identity or migration (47); auth
  refusals returned HTTP 200 (17); no warning when `snapback4-expo` and core
  versions differ (18); positional `sql --json` rows (15). 0.4.24 adds
  `guide deploy`, 401/403 statuses with a status table, the Expo version
  warning, `sql --json-objects`, and the shared port parser (LLP 3000.007
  §20.26).

On the new-app side, a regression no check caught: persona apps without a
device refused every browser write (14 lanes; 12 shipped clients that
could not write, with green frontend proofs that only built). 0.4.24
journals persona browser writes too and refuses unwritable combinations at
`createApp`; the harness's frontend proof now has to perform one real
write against a live backend. Also fixed: `/dev/reset` lost schedule
priming; `check` called queries never-complete that the runtime completes
(now `N_CONDITIONAL_COMPLETE`); `test` ignored `./fixtures`; a cluster of
rule-language diagnostics.

0.4.24 also closes the remaining §9 decisions the author ruled on
2026-10-11 ("go straight to the end-game solution"): declared referential
actions (LLP 3000.039), union sync audiences, with windowed or expiring
audiences refused inside union arms after six review rounds kept finding
disclosure holes there (LLP 3000.036.000.000), merged owner-or-X pages (LLP
3000.036.001), and bounded `int`, calendar months and small-table caps (LLP
3000.040). Building it found and fixed a pre-existing paging bug: a cost cut
inside a predicate that read a referenced row skipped that row on the next
page. The integrated web device grew from 651,704 B to 679,418 B gzip.


## 13. Wave 9 (built on 0.4.24) and what 0.4.25 changed

Wave 9 repeated wave 8's split: 50 new-app lanes on new ideas and 50
day-two lanes, each taking over the wave-8 app with the previous number.
Muse's plan quota ran out again, and the harness's Meta API key fallback
carried 58 lanes on Muse (34 day-two, 24 new). Muse logs three to four
times the minutes per friction entry, so the comparisons below that matter
are Codex to Codex. All 100 re-runs passed `check`, acceptance and
`day2:proof`; 98 frontend proofs (now a real write against a live backend,
run twice) passed, and both reds were Exact storage locks and sessions.

| | New-app lanes | Day-two lanes |
|---|---|---|
| Mean self-rating | 8.24 (wave 8: 8.28) | **8.40** (7.38) |
| Codex-only rating | 8.00 (8.23) | **8.62** (7.37) |
| Friction entries per lane | 4.72 (4.70) | **4.84** (7.24) |
| Codex non-agent minutes per lane | 7.3 (5.4) | **5.6** (10.8) |

Entries classified as Snapback defects fell from 31 to 9, of which three
were real distinct bugs. 0.4.24 turned day two from the farm's weakest
phase into its strongest: no lane lost data on rollback, no deploy hit a
busy store, and the port and guide gaps (30 and 47 lanes in wave 8) were
gone. New-app ratings were flat; the Codex dip comes from harder
multi-audience ideas and the new real-write proof, not a regression.

What wave 9 found, and what 0.4.25 does about it:

- **Device skew** (12 day-two lanes, ten first-fix votes; a 0.4.24
  regression for Exact apps): a device built for the previous engine failed
  with `E_INPUT: missing field 'generation'`. Devices now send their engine
  version and capabilities, the server answers a mismatch with one
  `E_DEVICE_VERSION` refusal naming the rebuild command, and Exact stamps
  the device it builds and refuses a stale one before testing.
- **Rollback after widening** (18 lanes, the costliest day-two pattern):
  rollback refused when a newer release had written values the older type
  cannot hold. Such values now go dormant per row, hidden from the older
  release or shown through a declared fallback, and return on roll
  forward; `rollback --check` previews the plan (LLP 3000.000.000).
- **Hot activation** (14 lanes): requests in flight across a switch could
  see `E_GENERATION` or a failed reply. Activation is now request-safe;
  `deploy` and `rollback` return after `serve` has switched; identical
  source is a no-op; `--to latest` exists.
- **Owner-or-membership lists** (24 new-app lanes, the largest new-app
  pattern): `.owner = viewer or exists members[.household, viewer]` was
  never complete. The merged-page planner now merges the owner range with
  the viewer's capped membership ranges under one cursor, normalizes
  boolean guards first, and prints completeness notes as three lines (LLP
  3000.036.001).
