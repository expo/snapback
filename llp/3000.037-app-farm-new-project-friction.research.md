## Summary

The author asked for a repeated loop: build 100 new apps on the published
`snapback4`, keep a diary per app, cluster what was hard, fix every pattern,
release, and repeat. This document records wave 1 (built on 0.4.16) and the
fixes carried by 0.4.17. It is evidence about a fresh builder's first hour,
not about scale or long-lived products.

## 1. Method

- 100 app ideas, each needing a backend with at least two personas and real
  access rules (book club, potluck planner, silent auction, clinic queue, …).
- Builder per app: a coin flip between Codex `gpt-6.1-sol` (high) and Muse
  `muse-spark-1.3-contributor` (high), 51/49. Frontend per app: uniformly
  React web (Vite), Expo, or Exact2. Up to 50 builders ran at once on one
  96-core Linux host.
- Each builder installed the package from the registry, read only the shipped
  docs, guide and diagnostics, and had to reach four proofs: `check` clean,
  a fixture run, an HTTP acceptance script as each persona with asserted
  refusals, and a frontend build/typecheck.
- Each kept `DIARY.md`, a structured `friction.jsonl` (area, kind, minutes
  lost, suggested fix) and `REPORT.md`. 711 friction entries (2,617 minutes
  logged lost; 388 self-classified as the agent's own error) were clustered
  by distinct lanes affected.

The harness, briefs, diaries and the clustered analysis live outside the
repository (`~/sb4-loop/wave1/`); this document carries the conclusions.

## 2. Outcome of wave 1

- 95 of 100 finished inside the window; all 95 reached `check` clean. React
  and Expo frontends verified 30/30 and 32/32. Exact2 frontends were not
  independently re-verified (the harness re-ran `test web` without the live
  backend those tests need); the builders' own reports show them passing.
- Mean self-rating 7.8/10. Codex lanes typically finished in 5–20 minutes,
  Muse lanes in 15–40.

## 4. Exact2

Exact2-side findings (no port option for `test web`/`agent web`, `--help`
running commands, working-directory sensitivity, no backend preflight, mount
and wasm wiring) were fixed on a local Exact2 branch for the next wave and
are for that project to land.

## 5. What the harness taught

A brief that requires every builder to start and stop `dev` from a script
exposes lifecycle defects to nearly 100% of builders; that is why #1 reached
45 lanes. Shared-host hygiene (per-lane `TMPDIR`, absolute tool paths,
self-contained `frontend:proof` scripts) belongs in the harness, not the
product.

## 6. Wave 2 (built on 0.4.17) and what 0.4.18 changed

Same protocol, 100 new ideas chosen to reach more surface (jobs, uploads,
presence, feeds, search, money). Builders: Codex 43, Muse 57; frontends:
React 40, Expo 26, Exact2 34. 0.4.17 was served from a local registry.

- All 100 finished; `check` 100/100; the harness re-ran each acceptance
  script (99/100; the one red is the app's own timestamp assertion) and each
  self-contained frontend proof (92/100; all 8 reds were the harness setting
  `CI=1`, which colorized Vite's ready line past the apps' probes).
- Friction fell from 711 to 541 entries and from 2,617 to 1,686 minutes
  lost; docs gaps from 125 to 55; defects from 48 to 30; mean self-rating
  7.8 → 8.09. Twelve wave-1 patterns disappeared; the orphaned dev server
  fell from 45 lanes to 7.
- 0.4.17 introduced the top new problems, which 0.4.18 fixes:

| Wave-2 pattern | Lanes | 0.4.18 |
|---|---:|---|
| Fixtures skipped defaults, `unique`, caps and maintained views (bulk import unless a read-through table existed), while `guide testing` promised insert semantics | 28 | Fixtures load through `/seed`'s insert path; a test requires fixture and `/seed` rows to answer alike |
| `init` wrote the starter's `todos.jsonl` and cases beside a project's own schema | 19 | Never beside any existing `snapback/*.q` |
| Staff/role access never made a page complete | 17 | A readable staff grant decides the page for its holder, server only (LLP 3000.036 §12) |
| Web starter's Vite config loaded as CommonJS after `npm init -y` | 17 | `vite.config.mts`; `^` ranges from `npm i` pinned exactly |
| Client TypeScript ergonomics | 15 | `RowOf`, generic read guards, `isFailed`, app types from `snapback4/react`, a narrowed signed-in viewer (LLP 3000.013 §6.3) |
| `test.cases.jsonl` expected `complete` from queries `check` already notes can never be | 14 | A query's default expectation follows `check`'s verdict |
| Hidden rows refuse `NOT_FOUND` before the author's own code | 14 | `test`, `run` and the dev log name the refusing layer; wire messages unchanged |
| `usePage` silently needs a cursor named `c` | 13 | A type error naming the contract |
| References read with dots in rules but not in programs; `delete row` refused | 13 | `x.ref.col` reads the row; `delete row`/`update row` |
| Owner-or-X lists never complete | 12 | The note prints one complete query per party, compiled by a test |
| HTTP answer shapes | 12 | One table in `guide testing`, matched in `guide wire` |
| Persona-only schemas: the starter's guest sign-in fails; recipe web-only | 8 | A persona-picker starter; compiled web and Expo recipes |
| `init --port` left Vite on 5173 | 8 | `--web-port` (default backend port + 1) |
| Money/decimal refused in ordered insert rules | 4 | Minor-unit ordering (capability `insert-rule-order-units`) |

Still deferred, each recorded with its reason: union sync audiences (LLP
3000.036.000 §4, §6), a device-less durable browser write path (LLP 3000.013
§6.2), owner-or-X as one merged page (needs a two-index cursor), and the Lean
model for staff grants (Lean is not installed on the farm host).

## 7. Wave 3 (built on 0.4.18) and what 0.4.19 changed

100 new ideas; Codex 55, Muse 45; React 39, Expo 30, Exact2 31. All 100
finished and passed `check`; acceptance and frontend re-runs 98/100 each
(both reds were model-provider `server_error`s that ended two sessions
early; the harness now resumes such lanes). 0.4.18 introduced no
regressions, and every wave-2 regression was gone.

| | Wave 1 | Wave 2 | Wave 3 |
|---|---:|---:|---:|
| Friction entries | 711 | 541 | 500 |
| Minutes lost | 2,617 | 1,686 | 1,160 |
| Docs gaps | 125 | 55 | 33 |
| Self-reported snapback4 defects | 48 | 30 | 3 |
| Mean self-rating (/10) | 7.80 | 8.09 | 8.28 |

Part of the minute drop is the builder mix (Codex logs about 1.3 minutes
per entry, Muse 4.5). What remained was mostly fixes that stopped short and
advisory notes that disagreed with the runtime or with each other:

| Wave-3 pattern | Lanes | 0.4.19 |
|---|---:|---|
| Guide cards overflowed agents' tool output | 40 | Long cards print an opening and a section index; `--section` matches loosely, `--find`, `--full`; new `time`, `cheatsheet` and `api` cards (LLP 3000.007 §20.1) |
| Guessed starter filenames | 36 | `init` lists the files it wrote |
| `N_NEVER_COMPLETE` where the runtime answers complete (staff branches) | 12 | `check` follows the guards the runtime honours (LLP 3000.036 §13) |
| Owner-or-X lists | 19 | The note says how tests and clients treat `complete: false` |
| `N_SYNC_ORDER` caused by the compiler's own rewrites | 22 | Page and horizon rewrites agree; the note names what differs |
| Starter leftovers on the init-first path | 21 | `check` names them; `init --adapt`; `.q` files are never conflicts (LLP 3000.011.003.000 §7.2) |
| Paging notes on one-row lists | 20 | A whole unique key bounds a page |
| Client types (`UsePage`, non-null viewer, `useQuery` examples) | 19 | `UseQuery`/`UsePage`/`UseAction`, `useSignedInViewer()`, a compiled recipe and a React export index (LLP 3000.013 §6.4) |
| Expo starter audit findings | 17 | `uuid` override; remaining advisories have no patched release |
| Scripted process lifecycle | 15 | `SNAPBACK4_READY` line; the server stops when its wrapper dies, even by SIGKILL; `wrapperPid` in `/dev/status`; a `stopChild` recipe |
| Read-rule hop rewrites that failed to compile or widened access | 7 | Every printed rewrite compiles and is checked not to widen readers |

Still deferred: union sync audiences, a merged owner-or-X page, a
device-less browser write path (re-measured in LLP 3000.013 §6.2: the wasm
already loads off the first-paint path), and the Lean model for staff
grants.

## 8. Wave 4 (built on 0.4.19) and what 0.4.20 changed

100 new ideas; Codex 51, Muse 49; React 32, Expo 35, Exact2 33. `check`
100/100, acceptance re-run 100/100, frontend proof 99/100 (the red was the
app's own test racing a pending write). 458 entries, 1,037 minutes,
self-rating 8.39; docs gaps flat at 33; self-reported defects 4.

One regression from 0.4.19: `init --adapt` removed the whole `fixtures/`
directory (17 lanes). The rest were fixes that stopped short:

| Wave-4 pattern | Lanes | 0.4.20 |
|---|---:|---|
| `init --adapt` deleted `fixtures/`; `generated/` counted as a conflict; adapted screen didn't compile; stale starter fixture refused `test` | 33 | Adapt removes only named files; `snapback/generated/` is regenerable; a neutral `Home` screen that compiles; an unmodified starter fixture for a missing table is skipped with a warning (LLP 3000.011.003.000 §7.4) |
| `N_NEVER_COMPLETE` with `or` guards, pinned order columns, owner-or-X | 21 | `or` guards and pinned order columns agree with the runtime; the note leads with compiled per-role or per-party code (LLP 3000.036 §14) |
| Guide navigation by topic words | 20 | `--section <words>` prints the best-matching section; hint first; finer sections in rules, types and sync (LLP 3000.007 §20.1) |
| Two-audience and open-join sync | 17 | `guide sharing` leads with `online only` and its cost; compiled open-join recipe |
| New client types unused by builders | 16 | Starters use `UsePage`/`UseMutation`/`useSignedInViewer`; `sentResult` (LLP 3000.013 §6.5) |
| Which refusal fires first | 16 | One ordered list in `guide refusals`, verified against the engine; the `cap` sentence in `guide testing` corrected to `E_CONSTRAINT` |
| Read-rule hops inside `or` | 16 | One-hop equalities compile anywhere on online-only tables; no internal names in rewrites |
| `N_SYNC_ORDER` on unique order columns | 15 | A unique key orders fully; direction-only differences are advisory |
| End-to-end recipes requested in ~25 reports | — | `guide recipes`: roles, two-party, booking capacity, schedules, each with test cases run by a test |
| Clock catch-up undocumented | 6 | `guide time` states the coalescing rule with a compiled look-back sweep |

Exact2 (local branch): `db.send()` writes, syncs and returns the outcome in
one call; server refusal codes reach the view as `CODE: message`; offline is
`offline`. Still deferred: union sync audiences, a merged owner-or-X page,
a device-less browser write path, calendar `month()`/`year()`, and the Lean
model for staff and pinned-column grants.
