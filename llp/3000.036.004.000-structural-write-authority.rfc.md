## 1. Scope

evidence, never a guarantee of arbitrary application security. Specification

## 2. Column write authority

`c: T write <- P` conjoins P with ordinary row authority for every executed
insert with a non-null effective c, and every update changing c (including
null-to-value and value-to-null). Defaults count. Sequence-dependent grants wait for the assigned ordinal;
sequence-independent early admission may not suppress a completed-image grant. Upsert and insert-if-absent
use the same engine boundary. Equal-value updates require no column grant. Updates touching guarded or frozen
payload require readable current row/cell; hidden values never select an equality
bypass or a conditional-freeze refusal. Blind insert needs no prior payload.
P uses the ordinary read-rule grammar and current row fields. An update judges
P against both old and next images, preventing authority transfer in the patch.
System writes retain the existing trusted rule bypass. Referential actions
must not silently bypass a column guard: reject guarded set-null targets.
Freeze comparisons materialize missing optional fields as null on both images.
Older engines/devices refuse the new schema capability. Device engines
queue guarded writes before target lookup and retain the same raw-schema
validation and fail-closed rule/constraint evaluator. Serialized source reservation
plans mark guarded tables server-only. Prediction may queue
guarded writes rather than guess missing policy inputs. No budget is raised.

## 3. Conditional immutability

`immutable c when P` freezes c when P holds on the old image. Clearing approval
and replacing evidence in one patch cannot bypass it. Inserts are unaffected;
equal-value writes pass. This is a constraint, including trusted system writes,
not a grant. The condition may follow ordinary live write-rule reference hops
(e.g. `.tour.status != 'booked'`), but never named old/next operands or the
clock. Ordered current-row comparisons remain outside this initial grammar. Trusted persistence restoration remains the explicit raw-image
exception, as for existing immutable constraints; ordinary seed/system mutations
and imports enforce freezing on replacement. P uses current-row/read-rule grammar; unknown is not permission to
edit. Referential set-null cannot target a conditionally immutable column.

## 4. Asymmetry and presentation

A column-specific edit guard (including `old.c = next.c or P`) paired with an
argument-supplied create path not implying P demands individual review.
Explicit `invariant T.c update only P` acknowledges deliberately different
creation authority only when its policy matches the guard. A column write
rule provides enforcement instead. An abstract failed implication is a question,
never an exploit proof. Row-local old/next audience operands normalize to the creation image; known
creator viewer/literal/default assignments substitute into both admission and
audience before implication, so self-attribution does not create a false question.
The extractor covers unchanged-column conjunctions in an alternative arm.
Exact structural implication must first eliminate
conjunct/disjunct containment; inconsistent Boolean valuations must not cause
the dispatcher-subset false question.

Authorization and write-authority notes are never cut while lookup hygiene is
shown. Insert write intent ranks 3; the five lookup hygiene classes rank 6.

Audience extraction normalizes old/next row-local operands to the creation image and reduces identical total row-local/viewer/literal operands in equality to true (inequality to false). Live-reference operands remain unknown-capable and are never folded. Unrelated unchanged-field constraints must not manufacture a wider creator audience.

uses logical lifetime, including parent lifetime, rather than physical rows.
Missing references, unsupported forms and exhausted search remain unknown.

Other operations keep the current history clock and explicitly record temporal payload-only histories as uncovered, preserving ordinary lifecycle depth under the shared attempt cap. role/relationship rows; all remaining values stay in the bounded proposal pool
and ordinary mutation guards determine actual admission. This is search ordering,
including under disjunction/negation, never an implication assumption.
Prioritize unresolved operation intent before general roster mutations. Two validated setup checkpoints share the same 4096 directed-attempt budget: an early checkpoint before dependent/setup creators consume root state, and a stricter predecessor immediately before an admitted non-roster dependency/child change makes a known current-image intent false→true for an actual fixture actor/row. A refused opposite decision on an already-consumed parent cannot stand in for the opposite decision on a fresh parent. The 16-tuple/2048-call limits remain unchanged; failed or omitted proposals never prove safety. Every cut remains
explicit coverage, never proof.

approval for a child linked only to `pair.primary`. Self-parent links retain
their own identity without rebinding a secondary key to the selected row id.
Unknown targets are omitted, never guessed. Quoted enum values
are AST values. Population focals remain local; unresolved captured arguments
are omitted with no proof claim. Pure helper returns and dominating requirements
may be expanded; effects and unknown control flow do not supply guessed values.

Approval-table questions are scoped per creator and parent reference. A positive
matching prerequisite on a governed parent/child effect consumes that record;
reading an unrelated parent's approval, or merely querying a table, does not.
Positive `count(approvals[...])` bounds also establish a prerequisite and retain
the complete original cardinality predicate in sibling replay. Schema authority
must govern the actual effect, including every potentially changed column for a negative
freeze contract, for scalar stamps AND approval-table probes (an unchanged
copied field cannot cover another field); an empty set of freeze guards proves nothing. A read audience
alone is not write enforcement. An explicit recipient ACL is different: a
matching approval row that grants its stored principal access to the parent
row is enforced authorization, even if it does not authorize a lifecycle change.
Typed positional approval keys, named/filter keys and a keyed progress row's
parent reference retain their selected resource. A global caller-principal
approval and a typed child approval loop before its parent transition are also
actual approval use; another arbitrary row's flag is not. A parent approval
loop must dominate the actual effect in its execution path; an untaken branch
or a loop placed after it cannot discharge this question. Control transfers
(`break`, `continue`, `return`) end reachable inspection in their branch; later
unreachable requirements cannot supply use. Quantifying over no
children is legitimate vacuous parent intent, not a promise that children exist. A time field actually
bounding a write is used as a window, even when its name includes "approved".
Checked enum decision proxies remain meaningful. An approval also has actual
use when it freezes its inspected non-lifecycle input, or its negative guard
is atomically consumed while producing a linked child/payment. These data and
one-shot contracts do not come from an arbitrary lifecycle-column freeze.
A timestamp may audit an enforced Boolean decision on a related row only when
the selected reference proves the link and the Boolean write executes with the
stamp. Unrelated rows, opposite branches and zero-iteration loop possibilities
cannot establish that custody. Private expansion retains caller statement ownership for a preceding
approval loop whose parent effect is expanded from a helper. It also retains
lexical loop markers
through helper calls so this check also works when the writes live in helpers.
Actual branch identity includes its lexical site; repeated text at different

Upsert
