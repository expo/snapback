## 2. Column write authority

`c: T write <- P` conjoins P with ordinary row authority for every executed
insert with a non-null effective c, and every update changing c (including
null-to-value and value-to-null). Defaults count. Sequence-dependent grants wait for the assigned ordinal;
sequence-independent early admission may not suppress a completed-image grant. Upsert and insert-if-absent
use the same engine boundary. Equal-value updates require no column grant. Updates touching guarded or frozen
payload require readable current row/cell; hidden values never select an equality
bypass or a conditional-freeze refusal. Blind insert needs no prior payload.
P uses the ordinary read-rule grammar and current row fields. An update judges
P against both old and next images, preventing authority transfer in the patch.
System writes retain the existing trusted rule bypass. Referential actions
must not silently bypass a column guard: reject guarded set-null targets.
Freeze comparisons materialize missing optional fields as null on both images.
Older engines/devices refuse the new schema capability. Device engines
queue guarded writes before target lookup and retain the same raw-schema
validation and fail-closed rule/constraint evaluator. Serialized source reservation
plans mark guarded tables server-only. Prediction may queue
guarded writes rather than guess missing policy inputs. No budget is raised.

## 3. Conditional immutability

`immutable c when P` freezes c when P holds on the old image. Clearing approval
and replacing evidence in one patch cannot bypass it. Inserts are unaffected;
equal-value writes pass. This is a constraint, including trusted system writes,
not a grant. The condition may follow ordinary live write-rule reference hops
(e.g. `.tour.status != 'booked'`), but never named old/next operands or the
clock. Ordered current-row comparisons remain outside this initial grammar. Trusted persistence restoration remains the explicit raw-image
exception, as for existing immutable constraints; ordinary seed/system mutations
and imports enforce freezing on replacement. P uses current-row/read-rule grammar; unknown is not permission to
edit. Referential set-null cannot target a conditionally immutable column.

## 4. Asymmetry and presentation

A column-specific edit guard (including `old.c = next.c or P`) paired with an
argument-supplied create path not implying P demands individual review.
Explicit `invariant T.c update only P` acknowledges deliberately different
creation authority only when its policy matches the guard. A column write
rule provides enforcement instead. An abstract failed implication is a question,
never an exploit proof. Row-local old/next audience operands normalize to the creation image; known
creator viewer/literal/default assignments substitute into both admission and
audience before implication, so self-attribution does not create a false question.
The extractor covers unchanged-column conjunctions in an alternative arm.
Exact structural implication must first eliminate
conjunct/disjunct containment; inconsistent Boolean valuations must not cause
the dispatcher-subset false question.

Authorization and write-authority notes are never cut while lookup hygiene is
shown. Insert write intent ranks 3; the five lookup hygiene classes rank 6.

Audience extraction normalizes old/next row-local operands to the creation image and reduces identical total row-local/viewer/literal operands in equality to true (inequality to false). Live-reference operands remain unknown-capable and are never folded. Unrelated unchanged-field constraints must not manufacture a wider creator audience.

## 6. Concrete intent and loosening

Aggregate element reference hops use the population element type, never the
enclosing invariant target type. Clock, duration arithmetic and cross-row references are evaluated against each
replayed step's actual clock and raw snapshot. Read-through child existence
uses logical lifetime, including parent lifetime, rather than physical rows.
Missing references, unsupported forms and exhausted search remain unknown.
Clock expansion prioritizes operations with clock-dependent Require/Check conditions (including local aliases) or authored clock intent. Other operations keep the current history clock and explicitly record temporal payload-only histories as uncovered, preserving ordinary lifecycle depth under the shared attempt cap. Clock-advance steps never move backwards; include stored schedule boundaries
and source-duration offsets from stored Time values. Four samples retain current,
a furthest source-offset boundary and the earliest future stored boundaries.
Generated initialization postpones a consuming parent transition once when another pending creator needs that parent, allowing child setup before lifecycle state is consumed. Typed keyed reads and lowered lookup/field comparisons prioritize principal argument tuples from matching literal
role/relationship rows; all remaining values stay in the bounded proposal pool
and ordinary mutation guards determine actual admission. This is search ordering,
including under disjunction/negation, never an implication assumption.
Prioritize unresolved operation intent before general roster mutations. Two validated setup checkpoints share the same 4096 directed-attempt budget: an early checkpoint before dependent/setup creators consume root state, and a stricter predecessor immediately before an admitted non-roster dependency/child change makes a known current-image intent false→true for an actual fixture actor/row. Refused or unknown transitions cannot spend the latter. Each gets at most 1024 attempts (the second cumulative ceiling is 2048), leaving at least 2048 for the final generated fixture. These checkpoints order search only, establish no admission fact and never claim initialization reachable from empty state. Retain admitted Boolean projections across all initialization rounds. After one creator decision is admitted, prioritize not-yet-admitted Boolean projections across the remaining parent tuples before filling the second root slot. A refused opposite decision on an already-consumed parent cannot stand in for the opposite decision on a fresh parent. The 16-tuple/2048-call limits remain unchanged; failed or omitted proposals never prove safety. Every cut remains
explicit coverage, never proof.

After a successful check, retain only a local schema baseline in generated
output. Required-to-optional loosening demands an authored always/insert/write
invariant containing an explicit focal-column equality/inequality with null
(or its Boolean composition), or an
individual specification disposition at the first subsequent check. A fresh

generated state is outside the baseline guarantee; release comparison must

## 9. Integration 24 wave-26 precision

Author instruction of 2026-10-24 identifies three false production refusals
revealed after builders run the advised test campaign. These clarifications
change finite intent observations, not application admission or the proof kernel.

Authored column `write only P` judges the inserted arm as `.c = null or P`.
For a Boolean column declaring `default false`, inserting that unapproved false
value is initialization too. This exemption applies only at insertion; every
actual changed update, including removal/null or true-to-false, still judges P
against both images. Meaningful defaults such as true are not exempt. Runtime
`write <- P` remains stricter: all non-null effective defaults count, as §2 says.
Concrete predicates and rule-fragment predicates use the same insert boundary.

For a mutation named `provision` (including a module-qualified name) run by
`service:operator`, authored read intent excludes only returned roster images
witnessed at that mutation's actual executed insert/update boundary. Existing
roster recognition requires a principal-keyed global role table. A marker in the
private fixture trace identifies the exact written image; naming an operation
alone cannot exempt unrelated rows. Ordinary queries, other mutations, other
principals and non-roster results remain checked. This is an explicit trusted
provision-result scope exception, not a runtime read grant or a general theorem.

Approval-freeze proposals omit payload uses occurring only in `= null` absence
checks or comparisons of stage/status/phase/state discriminators to literal
states. Positive/non-null evidence uses remain inspected even when another use
is an absence precondition. Existing enum/Boolean/reference exclusions remain.
These are candidate-selection heuristics; absence of a candidate proves nothing.

One shared gate-code registry drives dispositions and human tiering. Every gate
must render as a review, independently of the performance-note fallback, and
presence loosening has an explicit urgent priority. A structural regression
iterates the complete registry through the actual note renderer.

A clean finite generated/fixture campaign with no authored business cases exits
successfully and explicitly reports that no business cases ran. Existing cases
skipped because saved source selects incompatible working fixtures still refuse;
proof helpers requiring actual business cases retain their independent check.
Password-only engine cases can name explicit principals; that does not qualify
HTTP authentication or replace a real-login proof.
