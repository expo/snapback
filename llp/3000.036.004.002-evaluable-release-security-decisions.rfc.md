## S2 release narrowing

A predecessor-backed change narrowing an existing column's setter/write audience,
including a new restricted setter on a new operation, requires review when an older broader creator
still actually writes a non-initialization value for an excluded caller. A gate
requires current replay of that exact creator, effect, column and excluded audience.
Setter paths are unioned before comparison. The predecessor creator must retain a caller-supplied column and equivalent
audience and normalized bound body, including companion creation payloads.
Argument renaming is normalized. Nontrivial creator refactors remain unknown.
Argument validation contracts are unchanged except optionality on a direct,
exclusively reviewed-field input: the witnessed non-null value belongs to both. Unknown predecessor guards, required point-read assertions/helper inputs, and
post-write requirements cannot establish narrowing. Source operation probes must
prove the pinned row readable before their physical existence can stand for
operation admission; private/temporal/derived probe shapes remain unknown.
An abstract failed implication is insufficient: the actual excluded creator
caller must satisfy the predecessor setter audience on unchanged, validated
authority populations; changed authority schemas/populations remain uncovered. A removed setter
alone has no surviving restriction to project onto creation, and stays uncovered;
this avoids inventing a permanent column prohibition from endpoint retirement.
A field reopened from unconditional immutability introduces its first setter;
its prior setting audience is the existing creation audience, because there was
no predecessor update endpoint. Retained immutability and conditional freeze
remain unknown. Column privacy alone is not creation admission. Existing setter
cell freezes/private ownership are unknown; creator required-read
authority must retain the same schema and must not be mutated by the creator.
A parentless deployment has authoritative absence of a predecessor and never
borrows local check history or another target's predecessor for a release gate. A static asymmetry, a new
table/creator, an edit-arm upsert, unknown implication or
an unchanged narrower edit policy alone never supplies the gate. Without a known
predecessor the existing advisory remains. The exact setter fragment is a root, non-expiring table with no maintain
relationship and no append-only declaration; delegated, temporal and derived
admission stay unknown. Current setter requirements must precede its sole write.
Each supported creator has exactly one insert/upsert site, in both revisions.
This binds the optional direct-field exception to the witnessed non-null insert;
companion creates and their distinct argument contracts remain unknown.
Sibling creation admission retains the same schema apart from the reviewed
field’s outer optionality, its write rule and its removed unconditional
immutability. Its underlying type and validation constraints remain identical.
Direct predecessor setters contain exactly one single-field update.
Setter authority dependencies cannot be modified by the setter. Local binding
inputs and admission argument validation contracts are part of creator custody.
Successful checks retain a private `.snapback4/` source baseline; deployment uses its immutable selected predecessor independently
of local cache state. The selected predecessor and successful-check baseline are
control records outside the executable/worker snapshot. A refused deployment retains its exact predecessor source selection for
the printed check/ack command, including fresh checkouts. Successful activation
advances that selection to the newly deployed sources; validation-only previews
do not advance it. Explicit creation allowance can answer the observed
asymmetry; otherwise narrow creation or declare and enforce the column write rule.

## S3 evaluated answers

A witnessed gate accepts a schema repair or a one-line Quarry intent evaluated
against its current live witness. Free text, witness/permit clauses and prose
premises cannot close it. An assertion must hold; an explicit allowance must match
the actual effect and its predicate must evaluate true. Unknown/refuted results
refuse atomically, preserving existing records. Ordinary check/audit/deploy reevaluate
answers against current evidence; saved/redacted payloads cannot establish truth.
The decision-answer grammar is `witness HASH; invariant T.target only P` or
`witness HASH; allow T.operation when P`. The latter lowers through the ordinary
Quarry invariant binder and grants no runtime authority. The decision-only
column spelling `allow T.c insert when P` lowers to column-write syntax with
an explicit insert-effect filter; it does not introduce column-insert assertions
in schema files. Printed templates are evaluated by an end-to-end regression. Exactly one bound intent
must cover the witnessed table, actual operation/effect and relevant column.
Evaluation judges actual old/next images. Population reads additionally require
all transitive dependencies to be unchanged throughout the history, including
implicit writes; dynamic populations and unsupported references stay unknown.
A non-serialized current-execution marker excludes saved campaign records from
answer evaluation. Evaluations are regenerated, displayed in `intentAnswers`,
and excluded from witness identity. Existing advisory prose remains nonblocking;
unwitnessed presence gates require a source declaration. An exact authored `always .c = null or .c != null` presence allowance is
a tautology. It must not select a stricter independent-policy rollback strategy;
nearby predicates, operation/read contracts and real independent invariants retain
their existing guarded-view rules. This is a narrowly proved no-restriction
fragment, not a prose exemption. The first gate message prints the usable template. Authored contradictions remain
unacknowledgeable. Existing advisory prose decisions retain their advisory behavior.
