## 1. Decision

Wave 12 adds five small language forms whose shared rule is that convenience
must not invent information. They use the existing interpreter, read-rule,
maintenance and transaction-fact machinery rather than parallel execution
paths.

1. `view total: count t` is a global maintained aggregate. Its group key is
   the empty tuple, so its target contains at most one physical row. Quarry
   reads it as the scalar name `total`. A readable missing row is the count
   identity, zero. A hidden row and a hidden miss are both null. Other
   aggregate kinds may use the same empty key, retaining their existing empty
   result semantics.
2. An exact successful positive-count guard proves that the same domain is
   non-empty until a
   write, a dependent-local rebind, an authority change or a control-flow
   join invalidates the fact. `min` and `max` become present only when their
   projected column is itself present; a non-empty population does not prove
   that an optional column has a non-null value. `sum` keeps its existing zero
   identity. A matching maintained-role guard may make the keyed result
   present through LLP 3000.013 §3.2's existing authority proof, but a write
   invalidates that proof. No guard turns hidden data into zero. Accepted
   comparisons are `count(domain) > k` for `k >= 0`, `>= k` or `= k` for `k
   >= 1`, and `!= 0`, plus their reversed forms.
3. `text ... format email` adds deterministic validation, not normalization.
   It accepts ASCII addresses of at most 254 bytes with exactly one `@`; a
   1–64 byte local part made from ASCII alphanumerics and
   ``.!#$%&'*+/=?^_`{|}~-`` (with neither edge nor two adjacent characters
   equal to `.`); and a 1–253 byte dot-separated domain whose 1–63 byte labels
   contain ASCII alphanumerics or interior `-`. A single domain label is
   allowed. Case and bytes are preserved. A malformed formatted argument
   refuses `E_INPUT`; inserting or updating a stored image that violates the
   declared format fails the ordinary column constraint with `E_CONSTRAINT`.
4. `search` and `matching` accept enum columns as well as text columns. Enum
   values use their declared string spelling and the existing word
   tokenizer/index. No enum coercion, hidden synonym or alternate ranking is
   added.
5. Rounded division has two explicit forms. `divide(dividend, divisor,
   rounding)` accepts a present `int`, `decimal S` or `money CUR S` dividend
   and a present `int` divisor, and keeps the dividend's type and scale.
   `divide(numerator, denominator, S, rounding)` accepts two present ints, a
   literal result scale `S` from 0 through 12, and returns `decimal S`; this is
   the direct fractional-average form. `rounding` in either form is the
   compiler-checked enum literal `toward-zero`, `away-from-zero`, `floor`,
   `ceiling`, `half-away-from-zero` or `half-even`. Division by zero refuses
   `E_DIV_ZERO`; an unrepresentable final i53 result or checked wide
   intermediate refuses `E_OVERFLOW`. Optional inputs must first be narrowed
   or coalesced; null is never treated as zero. Runtime evaluation uses signed
   integer quotient and remainder only—never floating point.

## 2. Rounded-division table

For the three-argument form let `x` be the dividend's stored integer. For the
four-argument form let `x = numerator * 10^S`, computed in a checked signed
wide integer without first imposing the i53 value bound. Let `q` be `x / d`
truncated toward zero, `r` its remainder, and `d` the divisor. When `r != 0`,
the direction away from zero is the sign of the exact quotient
(`sign(x) * sign(d)`).

| Mode | Adjustment from `q` |
| --- | --- |
| `toward-zero` | none |
| `away-from-zero` | one unit away from zero |
| `floor` | one unit toward negative infinity only for a negative exact quotient |
| `ceiling` | one unit toward positive infinity only for a positive exact quotient |
| `half-away-from-zero` | away only when `2 * abs(r) >= abs(d)` |
| `half-even` | away when greater than half; at an exact half only when `q` is odd |

The comparison is overflow-free in the implementation (it does not compute a
potentially overflowing doubled machine integer). Examples: `divide(5, 2,
'half-even') = 2`, `divide(7, 2, 'half-even') = 4`, `divide(-5, 2,
'half-away-from-zero') = -3`, `divide(5, -2, 'floor') = -3`, and
`divide(5, -2, 'ceiling') = -2`. Decimal and money values apply the same rule
to their exact stored minor-unit integer and retain their scale/currency.
The scaled form gives `divide(101, 2, 2, 'half-even') = 5050` (the decimal-2
value 50.50), `divide(1, 8, 2, 'half-even') = 12`, and
`divide(1, 8, 2, 'half-away-from-zero') = 13`; negative operands round with
the same signed rules. Scale zero is valid. Scale 12 is the maximum. Only the
rounded stored result must fit i53, so a wider intermediate such as
`divide(I53_MAX, I53_MAX, 12, 'half-even')` succeeds with
`1000000000000`.

## 3. Global maintained-view representation

The empty group is a real logical key, not a dummy author-visible column.
Physical stores still need an index component, so the generated target carries
one compiler-owned required boolean discriminator `$global = true`; its unique
`byGroup` index contains only that field. Quarry never exposes the field or
accepts it as a group key. Schema validation permits this exact target shape
only for an ungrouped maintain; user-declared empty indexes remain invalid.
Every aggregate writer uses the existing canonical maintained-row id function
over the logical empty tuple, so rebuild, activation and incremental updates
address the same row.

The scalar name lowers to a point read of that unique discriminator. It is not a
whole-table page and it consumes no arbitrary first row. Device completeness
and absence use that same unique key. Consequently public synced views can
prove readable absence and return zero, while private views retain null unless
the same authority proof that authorizes a keyed target is live.

## 4. Non-empty-domain proof

The binder records a count's canonical read domain at the instant the local
receives the count. That capture marker names the result's reaching definition
and is owned by both the result local and every stable value root used by the
read, including the transaction-state anchor. A successful positive-count
guard may publish a fact only while that exact definition marker remains live
on every owner. A later capture of the same textual domain has a different
definition and cannot revive the earlier result. The fact is keyed by the canonical
domain and matches only an identical table, selected index, keys, seeks and
filter expression after stable-value substitution.

Assignments clear the local's facts. Writes clear every count-capture marker,
the transaction anchor and all aggregate non-empty and maintained-authorization
facts. Authority changes clear the same capture markers before a later guard
can publish anything. Branch joins keep only facts present on every completing
path; loops reach the existing binding fixed point. Entering or leaving an
`as` viewer scope does not export the proof. Retained assignment origins remain
diagnostic history and are not provenance by themselves. This deliberately
misses some equivalent predicates; it must never accept a merely similar or
stale population.

The proof affects only static optionality. Runtime aggregates remain subject
to the existing meter/cut rule: no partial scalar escapes a cut. A later
write followed by an empty population therefore cannot reuse the earlier
proof, and an unauthorized maintained miss never becomes an authorized zero.

## 5. Compatibility and fences

`email` is a new closed schema enum tag and rounded division is a new closed IR
builtin tag. Older runtimes fail closed when decoding either. Existing schema
and program bytes are unchanged. Enum search and global views reuse existing
wire forms except for the deliberate one-component, compiler-owned `$global`
discriminator index; schema validation rejects that shape outside its exact
maintained target.

No feature adds JavaScript evaluation, a second interpreter, regular
expressions, floating point, unbounded scans or implicit disclosure.

## 6. Verification contract

Affected tests must cover:

- parsing, binding, schema validation and incremental maintenance of a global
  count, including zero, insert, delete and readable-versus-hidden absence;
- global-view replication and updates in both SQLite and memory device stores;
- matching count guards, mismatched domains, optional projected columns,
  branch joins, result and dependent-root rebindings, stale counts captured
  before writes, impure helper calls, authority edges, and fresh counts after
  writes;
- immediate keyed-role authorization, hidden hit/miss equivalence, readable
  zero, and invalidation by a following write;
- accepted and rejected email edge cases through both server and device
  validation;
- enum search planning, matching and replication on both stores;
- every rounding mode across positive and negative operands, exact halves,
  non-halves, result scales 0 and 12, the direct `101 / 2` decimal-2 average,
  a wide intermediate with a representable result, zero divisors and final
  i53 overflow, with no floating-point oracle;
- Lean evaluation and differential-case generation for rounded division;
  independent Lean witnesses for global-total presence/disclosure,
  count/role narrowing, email validation and enum word search; plus simulator
  and both device-store execution. Model boundaries remain explicit rather
  than reporting unsupported maintained/search execution as oracle coverage.

The guide's types, search, language and derived/maintained-view cards carry
the exact supported spellings and the presence/disclosure boundaries.
