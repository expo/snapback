## 2. Readiness and current authority

useAppReady means the current account successfully opened after this App's
initial ready settled. Initial E_ADMISSION-family failure stays false until a
later successful sign-in/opening. A new App or viewer starts a new lifetime;
signed-out/restoring remains false. Once true for the mounted account owner,
release/catalog loading and later admission warnings do not make it false.
This deliberately supersedes client §6.11's continuing-admission interpretation.
Readiness is neither permission, connectivity nor continuing write admission.
The SDK may refuse a write while readiness is true. Session revocation/store
replacement retain their synchronous identity fences; no dead viewer is kept.
AppProvider still remounts account state on app/viewer changes.

The compiled role shell owns user-authored blank drafts/selections above all
role/readiness/release branches. It retains only these user-authored values.
Protected query values belong to protected children and withdraw with them.
An application that copies protected data into editable state MUST clear that
copy when its source authority withdraws (LLP 3000.023); blank initialization
alone does not exempt a later protected copy. The examples offer no prefill or
copy-from-query path. Sticky role labels the shell only. Protected children
and submission require isPresent(role) && role.complete && role.fresh &&
!role.revalidating, initial readiness, api.myRole.available(release), and
availability of each protected operation. Loading, partial, denied, absent,
stale/revalidating role evidence never grants authority. SDK/server admission
handles races; no per-read generation field or application authority cache.

AccountEntry opens createApp with persisted session custody and the device
BEFORE GET /auth/config. Discovery metadata is cached defensively by backend URL;
missing cache selects accounts, failed refresh/cache writes never gate opening.
Cached development enables discovery only: existing loopback/server persona
admission still applies. Retired effects abort/ignore late configuration replies
and close their owned App. Offline entry does not promise a new browser profile
has data: it restores storage already held by this origin/account.

## 3. Custom production plans

No-flag init --adapt --production defaults to PREVIEW with no writes. --dry-run
also previews; ONLY --apply writes the exact displayed, compiled schema plan.
--apply plus --dry-run returns E_INPUT before planning/writing. This schema-only
mode refuses --web, --expo and --day2 with E_INPUT BEFORE planning/writing;
those flags were previously silently ignored. snapback/*.q is required. All
source bytes/source-set and source-symlink preflight remain; individual writes
are atomic, not a multi-file transaction. Failed compilation writes nothing;
a filesystem failure can report a partial application.

Add bare use identity only if no module declares identity. Bare identity allows
passwords and guests; use identity guests is guests-only; password removes guests.
A guest session is a session. When password methods are enabled, app.auth signup/
login may replace it, crossing the existing account boundary. This does not merge
work: old intents/receipts/replicas remain bound to the old principal under
existing outbox/receipt/residency bounds, neither dropped nor transferred by
signup. Only reopening that principal with its still-valid credential can resume
original IDs. Signup replaces the persisted current credential; recovery after
loss of the old guest credential is not promised. No new credential archive,
GC or flush owner is introduced. New-account views and delayed old facades cannot
observe, admit or send the guest's intents as the new principal.

Production planning keeps §14's blocked-table analysis, including dependents.
The roster predicate is EXACT: at least one column of ColumnType::Principal
(not text or optional principal) appears in a unique index's columns. Names of
principal columns need not be principal. A literal-per-role candidate additionally
has a column exactly named role of ColumnType::Enum and no compiled mutation OR
job insert/upsert path. An update/delete-only program is not an insert writer.
Only authored current compiled programs count; fixtures/tests are not writers.
Native opaque writers disable additional absence inference. Other name encodings
(user_role, roles), text owners and non-roster/inherited-authority roots receive
existing application-policy review messages, never an invented role grant.

For a writer-less enum-role roster, emit one fresh-named service:ops-guarded
insert mutation per declared variant, fixing role as a literal. Require every
writable required input and explicit target-principal input even when its
column defaults to viewer; omit maintained fields. Do not infer fixture values
or confer signup roles. Each mutation inserts ONE row and obeys every existing
constraint; roles need not coexist. UNIQUE(principal) makes a second role for
that principal fail E_UNIQUE; UNIQUE(principal,role) allows distinct roles and
still refuses duplicates. Tests distinguish these shapes. role is a syntactic
heuristic, not an assertion of authorization meaning: even typed preferences
can receive a preview of literal attribute insertion.

A blocked roster WITH an existing insert/upsert writer receives §14's generic
enum-argument bootstrap mutation and only the displayed independent service
read/insert branches; existing authored writer bodies/guards stay byte-identical.
It gets no new literal-per-role mutations. Already reachable tables receive no
additional bootstrap/seat branch. This deliberately adds operator provisioning
authority, including variants a narrow application writer does not insert.
The trusted service:ops bearer is the existing boundary: exposing its generic
provisioning authority to untrusted input is not authorized by this recipe.
Preview shows every grant; apply explicitly authorizes them. All generated
programs/rules must compile together, names avoid collisions, repeated apply is
idempotent after the new writer is reachable. Constraints are never bypassed.

The bounded principal scan does not edit screens. It skips every dot-directory,
symlink, and existing dependency/generated/store/build/fixture/version/recipe
exclusion, plus directories named test, tests, __tests__, acceptance. Lowercase
source stems split on dot/dash/underscore exclude components test, tests, spec,
acceptance, fixture, fixtures, proof, smoke. Runtime scripts remain visible.
Findings are heuristic file/line hints, not migration proof. Lines containing
usePersonaApp, ?as=, or persona followed by optional whitespace and colon point
to the account/persona recipe; comments/strings may match. Upgrade's project
action line names init --adapt --production for persona-only modules.

## 4. Declaration and recipe corrections

Post-baseline row/projected fields say “optional: releases before N lack this
column”; N is configured since_release, not inferred generation. Argument
additions retain their existing Since release N label. Ordinary conditional
inference gives a literal string its singleton enum domain ONLY alongside an
existing enum arm (including nullable enums). Plain text/text conditionals keep
text. Enum domains union; nullable contributes null; dynamic text widens to text
only when every enum variant totally fits the existing text domain. Example:
mode enum('standby','measure') projected as .mode if condition else 'standby'
retains "standby" | "measure" (plus null for nullable mode). Compatibility
codegen subsequently merges baseline domains under its existing deduplication;
BaselineRows/Rows remain separate. Evaluation and laziness are unchanged.

Present enum values support the existing text-operation inventory through a
bounded-text gate: concat (+), count, lower, trim, sha256, tokens, slice, join,
and matching ALL require every enum variant to pass text's existing forbidden-
control check. They ALL refuse a domain containing U+0001 with E_QUARRY_TYPE,
even operations such as count/hash that could produce safe outputs. Nullable
values/elements/separators still need non-null proof. upper is not a builtin.
Raw control-character enums remain valid enum values. No transformation may
launder them into a text result. Bounds use Unicode scalar counts and unchanged
per-op adjustments (lower 3×, concat sums, join cardinality/separator formula).
Transform results use existing text/int/list/bool types; raw projections retain
enums. No IR, runtime builtin, wire or meter changes.

Comparison and inferred-local compatibility recurse at CORRESPONDING VALUE
LEAVES, not whole-object bidirectional assignability. String/enum leaves are
compatible independently of bound direction/domain containment, including
explicitly disjoint domains (intentional broader comparison admission). Objects
must have EXACTLY equal key sets, including optional-valued keys; absent keys
are not optional values. Sequence compares with sequence via its item type,
not scalar; cardinality bounds can differ. Nested optionals retain existing
null compatibility. Nominal rows/references and all other kinds retain existing
bidirectional assignability; local joins still reject incompatible row kinds.
Thus opposing field bounds cannot lose valid comparison/rebinding, but differing
key sets do not acquire fields. Comparison grants no assignment authority.

Actual declared/flow types still join precise domains: conditional replacement
returns their union, unconditional replacement can narrow. Parameters cannot
be rebound. Explicit argument/column assignment uses actual enum constraints,
not the compatibility predicate. A mixed enum/text VALUE join containing an
enum variant outside text's character domain is unrepresentable and REFUSES;
it must never fall through to Unknown. This includes conditional/local flow,
min/max and nested value joins; comparison alone does not license selection.
Negative controls place each unsafe selection before explicit enum/text helpers.
Other existing Unknown policy is unchanged; no universal type-system proof.

Ordering/min/max require present OUTER operands. Nested nulls in comparable
containers retain existing Value::total_cmp semantics: null before strings;
arrays lexicographic; row/maps compare field counts then sorted keys/values.
They neither trap nor gain a new deep-null restriction. Equality preserves null
handling. Controls execute scalar/container comparisons, nested null ordering/
min, text operations, local/loop rebinding and opposing-field bounds, plus
reject unsafe text joins/builtins and invalid explicit enum arguments.

Device-less identity createApp without sessionStore must produce a type error
naming sessionStore; device/persona/readOnly forms remain valid. Complete empty
lists already classify absent; packed tests pin it. The PDF helper calls
Client.upload(bytes,{file:{type,name}}), then the app places the returned asset
id through its authorized file-column mutation. Guide snippets execute from
packed packages, not merely a workspace typecheck.
