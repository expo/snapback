## Summary

This Spec is the normative per-operator incremental semantics for
Snapback's closed query surface — Stage A of LLP 0309, commissioned
2026-08-25 (`issues/20260825-llp0309-stage-a-commission.md`). It
defines, once per elementary operator, how a change batch flows
through that operator: the typed incremental form `∂O`, its state,
its bounded read requirements, its maintain conditions, and its
`FALLBACK` verdicts. Every admitted plan's delta rule is the
composition of these forms along the plan's dataflow; rule content
for future delta-lane rungs is instantiated from this document and
checked against its executable reference evaluator, never
re-authored per node kind.

The Spec binds to the shipped IR at the granularity of code, not
prose: the seven `GraphNodeV1` kinds and four `TableVisibilityV1`
arms (`crates/snapback-types/src/manifest/graph.rs:876`,
`crates/snapback-types/src/manifest/types.rs:1246`), the six-op
`FilterExpr` conjunction with `Arg`/`Literal` values only
(`graph.rs:4621`), the `GraphProjectionValueV1` assembly arms, the
captured-dependency vocabulary (LLP 0209 §5.1;
`GraphCapturedDependencyV1`, `graph.rs:2043`), and the G3 retained
evaluation state (`EvaluationState`,
`crates/snapback-engine/src/graph_evaluator.rs:455`). §4's closure
table accounts for every variant and arm — by decomposition into
elementary forms or by named refusal — so no IR surface is silently
outside the semantics. Code citations were verified at the loop
revision (commit `fec7c118e`; inventory pass `232a82504` — enum
inventories identical).

What this Spec does **not** change: LLP 0209 §7's admission posture
(per-kind admission, one ineligible node pins the graph to replace,
`live_replace` the honest fallback), wire kinds and delivery
negotiation, the capture vocabulary except through 0209's amendment
path, authority-transition handling (the LLP 0200 fence), the
opaque-handler categorical, and the replica continuity contract
(LLP 0209 OQ-6).

**Scope freeze (declared 2026-08-25, with the r3 revision, per LLP
0010.001 §Scope freeze).** The normative surface of this Spec is
frozen: subsequent revisions make corrections and restorations
only, and any demand for new normative closure is recorded as an
obligation (§9), never folded as new prose. Post-freeze review
rounds are punch-list delta rounds.

## 1. Carriers and the form type

### 1.0 The form type, reads included

```text
∂O : (state_O, Δin, R) → Maintain(Δout, state_O') | FALLBACK(reason)
```

`R` is a **bounded read transcript**: a set of
`(request, response)` pairs whose requests come from a closed
per-operator request vocabulary — `point(index, key)` (unique
lookup, take 1), `probe(edge, scope, limit:1)` (support probe;
through form = edge range + target points), `range(index,
key-prefix, bound)` (bounded fill: a per-parent window, or a
declared-index scan keyed by a support value for the §2 lift),
`tail(window, k)` (next k rows past a boundary, read with one-row
lookahead exactly as full evaluation reads, so the response carries
its rows **and an authenticated `exhausted` bit**) — and whose
responses are **admitted rows** (post-§2 E0 of the target relation)
read under the consumer's authority at the same evaluation cut,
within the node's declared bounds, and charged to its cost
accounting. `∂O` is a pure function of `(state, Δin, R)` — purity
is over the set of pairs, never transcript order. A form that
reaches a condition requiring a request absent from `R` returns
the **domain reason its rule names for that condition** — every
rule names exactly one reason per condition, so the verdict on any
`(state, Δin, R)` is unique, and there is no separate missing-read
reason. A form never blocks, guesses, or reads ambiently. Consumers realize `R` the way the
shipped lanes already do — bounded authorized reads inside one
pinned view whose cut and authorization version were checked
(`engine.rs:34120`) — and the reference evaluator (§7.1) takes `R`
as an explicit input, so vectors can pin both the
provable-with-reads maintains and the empty-`R` fallbacks.

The defining equivalence property of every form, required on
maintain verdicts only:

```text
O(S ⊕ ΔS) = O(S) + ∂O(state_O, ΔS, R).Δout
```

where `⊕` is base-state application and `+` is the output carrier's
composition, and `R`'s responses are consistent with `S ⊕ ΔS`.
`FALLBACK(reason)` is a first-class verdict, not a failure: for the
server consumer it selects the replace path; other consumers handle
it per LLP 0309 §D3.2. The **closed reason set** is:
`missing-image`, `predicate-unanalyzable`, `rank-undecidable`,
`boundary-displacement`, `completeness-indeterminate`,
`rekey-unread`, `scope-unfilled`, `demand-identity-transition`,
`refusal-transition`, `support-unproved`, `scope-unresolved`,
`unique-violation`, `wire-unaddressable`.
Adding a reason amends this Spec (§9).

### 1.1 ΔApp — the admitted application-row change carrier (input)

A batch of committed row changes to one table, atomic per commit:

- `insert(key, post)` — post-image row.
- `update(key, post, changed_fields)` — post-image; the pre-image
  is **not** guaranteed. An empty/unavailable `changed_fields` set
  means "any field may have changed": classification proceeds by
  comparing the post-image against retained pre-images where state
  has them, else the affected form falls back (the shipped
  refusal precedent: `descendant_join_may_have_changed`,
  `graph_evaluator.rs:3170`).
- `delete(key, pre?)` — pre-image if available, else key only.

**Batch normalization:** before classification, a batch folds to
last-change-per-row-key in first-seen order — DK-3's shipped rule
(`live_matcher.rs:3581`), closing the insert-then-delete phantom-add
defect. A multi-table commit yields one folded per-table batch per
input relation, presented to multi-input forms together (§5's batch
rule). Forms consume whole folded batches.

Image direction is a carrier property (LLP 0309 §D1.1): where a form
needs a **pre-image** the carrier does not supply, retained state
must supply it — reads cannot: `R` is bound to the post-change cut
and can never recover a pre-image — or the form returns
`FALLBACK(missing-image)`; post-state facts the carrier lacks come
from `R`. Non-row production change kinds (schema,
authority, incarnation) are outside ΔApp; authority-driven
invalidation belongs to the LLP 0200 fence.

### 1.2 ΔZ — admitted-change batches (unordered relational carrier)

The internal carrier E0 emits and relational forms consume: a batch
of entries `(row_key, op: insert|update|delete, post_image | ⊥,
admit: enter|leave|stay-in|stay-out, rank_keys)` — `op` preserves
the folded ΔApp change kind, which E3's completeness rules consume
(admission tags alone cannot distinguish an inadmissible insert
from an unretained update leaving admission) — E0's classification output (§2 E0), with
signed-multiset composition when treated algebraically (an update
whose pre-image is available from state is the pair
`(-1 pre, +1 post)`).

### 1.3 ΔSeq — ranked-sequence splices (ordered/window carrier)

Output carrier for ordered, limited operators. Entries are splice
ops positioned by total-order sort key (declared order + `_id ASC`
tie-break, LLP 0209 §2.2; NULL-last independent of direction,
`live_matcher.rs:3365`; end inclusivity and comparison semantics are
inherited from the base operator — `∂O` must match `O` exactly):

- `splice-in(sort_key, row)`
- `splice-out(sort_key, row_key)`
- `patch(sort_key, row_key, post)` — rank unchanged.

Composition is sequence splicing. After batch folding, each row key
undergoes **one logical net transition** per batch, encoded as up
to a `splice-out` + `splice-in` pair (out before in, applied as one
atomic step). Ops in a frame are ordered so each op's position is
valid at the moment it is applied (application order = frame
order).

### 1.4 ΔBit — support-bit transitions (predicate carrier)

Output carrier for support forms (E6), per support scope (per parent
row; per `(parent, argument-element)` for `mode:"all"`): `0→1`,
`1→0`, or unchanged. Within a batch the net transition per scope is
derived from the **folded** support-relation changes plus state —
never last-write-wins over intermediate facts (§2 E6).

### 1.5 Wire mapping

The wire vocabulary is unchanged: `LiveGraphDeltaWireOpV1`
(`crates/snapback-types/src/live_wire.rs:352`) with
`op ∈ {add, update, remove}`, `node_id`, `root_key`, `key`,
`position`, `row`, plus the frame's `ordered_root_keys`,
`proof_tuple`, per-node and graph completeness, and `result_digest`
(`live_wire.rs:317`). Normative mapping:

- **Projection-scoped patches (custody rule).** An `update` op's
  `row` diff carries **only fields the closed projection references
  for that node** (plus nothing else — system fields included only
  if projected). Emitting unprojected retained-row fields is
  forbidden: retained rows are server-internal, and a full
  `retained_row_patch` diff can disclose fields the projection
  never shipped. The shipped lane emits the unfiltered diff
  (`graph_evaluator.rs:3328`, `:3589`) while the apply oracle
  ignores unprojected fields — Stage B classifies that as a
  class-(b) candidate (§8); this Spec's rule is the projection-safe
  lowering.
- root-window ΔSeq: `splice-in` → `add` (position = index in the
  order at application time; `row` = the **fully assembled
  projected item value** for the entering row, never the physical
  carrier row — the custody rule covers every op payload);
  `splice-out` → `remove` (position = the removed row's index at
  application time); `patch` → `update` (projection-scoped field
  diff). `ordered_root_keys` is the post-batch root order and MUST
  equal the reference evaluator's.
- to-one patches: `update` on the affected node with
  `key` = the child row key (rung 1's shipped shape). **Presence
  transitions** (`optional` only): `update` on the to-one node with
  `key` = the **parent scope row key** (no child key exists on the
  missing side), `root_key` = the root ancestor's row key,
  `position` = that root's index at application time, and `row` =
  the full new projected object value, or `null` when cleared. The
  apply oracle extension lands with the rung that instantiates
  this.
- to-many ΔSeq: the three ops scoped by `node_id` + parent
  identification, `row` on splice-in = the assembled projected item.
- ΔBit (projected exists): `update` with `node_id` = the exists
  node, `key` = the parent scope row key, `root_key` = the root
  ancestor's row key, `position` = that root's index at application
  time, `row` = the recomputed projected boolean under its
  projected name. Oracle extension per rung, as above.
- **Addressability (normative).** An op on node `N` is addressable
  by the existing fields only when the scope chain **strictly
  between `N` and the root contains no to-many** — the root's own
  splices, patches on nodes hanging off the root, and the splices
  of a to-many directly under the root qualify; **any op targeting
  a node below a to-many** (a nested to-many splice, a to-one patch
  or presence transition inside an array item, a projected exists
  inside an array item) has no immediate-parent or path identity in
  the op vocabulary and is `FALLBACK(wire-unaddressable)` —
  **recorded obligation:** a wire-path addressing amendment through
  0209 before any rung maintains below-array content. (The IR
  admits to-many under to-many and to-one/exists inside array
  items, `graph.rs:4369`, `:3240`.)
- **Ancestor-birth absorption (normative).** When an ancestor's
  `splice-in` is emitted, every descendant fill — presence objects,
  array contents, exists bits — contributes to assembling that
  ancestor's `row` payload and is **suppressed from independent
  lowering**: one frame never encodes newly-added content twice.
  Descendant ops are emitted only for scopes whose ancestor chain
  contains no node added in this batch. (Symmetrically, a removed
  ancestor's `remove` absorbs its descendants' departure — no
  separate descendant ops.)

Shipped scope note: rung 1 emits `update` only and its oracle
(`apply_graph_delta_to_result`, `graph_evaluator.rs:3411`) rejects
everything else; each rung extends the oracle with the mapping arms
it instantiates. "Maps to `live_replace`" throughout means the
consumer **selects the replace path**; what that path then emits is
its own contract (a fresh frame, or — e.g. for a
`presence:"required"` refusal — the refusal outcome, which fresh
serving surfaces as an error, `engine.rs:43098`). A delta frame
carries the same resolution-ticket and watermark obligations as any
live frame; deltas ride the data-driven lane only.

## 2. Elementary operators

The corrected inventory (this section **is** the confirmation LLP
0309 §D1.2 requires; §3 records dispositions). Forms are typed over
the §1 carriers; binary/n-ary forms take a product `Δin` (one folded
per-table batch per input) and owe every input a change term.

### E0 — Admit[visibility, filters] (the ΔApp→ΔZ adapter)

One instance per relation read. **This is where E1/E2 enter the
incremental path**: E0 consumes the folded ΔApp batch for the
relation and classifies each entry `enter | leave | stay-in |
stay-out` **with respect to the admitted relation** (visibility ∧
filters), emitting ΔZ. Typed inputs/outputs make E1/E2's
"linear" honest: they are per-row predicates; the *classification*
needs pre/post admission status, and E0 owns that.

- **is-admitted (post)** — the predicates, self-contained:
  `public-read` admits every row; `owner{field}` admits iff
  `row[field] == auth.userId` (a missing or non-string field is not
  visible to the evaluator; the matcher treats it as unknown and
  stays conservative, `live_matcher.rs:3171` — a wake-precision
  property, not a semantics difference); `membership{declaration,
  resourceField, roles}` admits iff the row's E6 support bit
  (post-batch) is 1 under the declaration's role rule — `roles:
  None` = any non-pending role, `Some(list)` = a listed role only,
  a pending membership never admits; `any-of(arms)` admits iff the
  **recomputed OR** over all its arms admits (row-local arms decide
  from the image; membership arms from their bits — a membership
  1→0 with another arm still true keeps the row admitted). Filters
  are the E2 conjunction over the post-image. An unanalyzable
  predicate value → `FALLBACK(predicate-unanalyzable)`.
- **Membership carrier re-key (fail-closed, normative)**: a
  carrier-row change that alters any membership-arm key field
  (`resourceField`, or any field a declaration's probe keys on)
  re-keys that row's support scope. Its bit at the post-change key
  must be **proved** — the E6 parent-arm probe from `R` — before
  is-admitted can be decided; membership bits are not retained
  (§6.3), so stay-in may never be assumed across a membership key
  change: without the probe the verdict is
  `FALLBACK(support-unproved)`.
- **was-admitted (pre)**: from retained state, at the grain the
  consumer retains —
  - *point/probe consumers* (to-one, principal, support probes):
    retained scope state is the complete admitted answer per scope,
    so was-admitted is decidable from state;
  - *windowed consumers* (root, to-many): the retained population
    is the **window**, not the admitted relation. E0 therefore
    emits was-**retained** (in-window), and E3 classifies against
    the boundary — a row absent from state may be either
    previously-inadmissible or beyond-boundary, and E3's rules
    never need to distinguish them for membership (both are
    "not in window"); completeness handling is E3's (below).
  - A delete of an unretained row: key-only, no pre-image —
    classification is `stay-out` for membership purposes;
    completeness effects per E3.
- **Membership-probe exception**: probe reads under the membership
  rules evaluate the declaration's own semantics and deliberately
  bypass the membership table's declared `TableVisibilityV1`
  (`types.rs:10265`, `membership_rules.rs:138`); E0 instances on
  probe relations apply the probe predicate, not the table's
  visibility.

E1 (visibility predicate) and E2 (filter predicate) are exactly the
is-admitted predicates above — row-local arms and the six-op
conjunction under SQL
three-valued logic with the matcher/SQL agreement invariant
(`live_matcher.rs:3217` ↔ `crates/snapback-kernel/src/storage.rs:14895`;
NULL actuals never match; `IS NULL` inexpressible) — but they are
**predicates consumed by E0**, not free-standing incremental forms.
Membership visibility arms decompose to E6 + the E6→membership lift
(below), OR-composed with row-local arms for `any-of`
(support-classed iff any membership arm).

### E3 — Window[order, interval, take] (ordered window)

State per instance (§6.1): the retained window rows with sort keys,
boundary keys, result count, completeness bit (`complete` = source
exhausted at last full read), continuation cursor. Input: E0's ΔZ.
Output: ΔSeq. **The batch algorithm is normative:**

1. Fold (already done by E0). For each entry **with a post-image**,
   compute its post-rank from the post-image sort keys (undecidable
   → `FALLBACK(rank-undecidable)`). A leave of a **retained** row
   (delete, or an update exiting admission/interval) takes its rank
   and pre-image from retained state; a key-only delete of an
   unretained row has no rank and needs none (step 5c).
2. **Keyed working map**: start from the retained window (key →
   image at its retained rank); remove leaves; **overlay** every
   admitted entry with post-rank inside the interval at its
   post-rank — a retained key overlaid at an unchanged rank is an
   in-place update, at a changed rank an atomic out+in; unretained
   admitted entries (in-batch inserts, previously-beyond-boundary
   rows) enter the map at their post-rank. Window membership needs
   no previously-inadmissible vs beyond-boundary distinction.
3. New window = direction-aware top-`take` of the working map after
   interval clipping. `B_old` := the retained window's boundary
   (last retained sort key); an **empty** retained window takes
   `B_old` = the interval's near end (direction-aware), so tail
   reads originate at the window start.
4. **Tail competition**: if `complete == false` and (the new window
   has fewer than `take` rows, **or any selected row ranks beyond
   `B_old`**), unseen source rows in the region past `B_old` may
   outrank the selection: a `tail(window, k)` read from `B_old`
   (k = `take` − |selected rows ranking ≤ `B_old`|) joins the
   working map and step 3 re-runs once; without it,
   `FALLBACK(boundary-displacement)`. If `complete == true` nothing
   unseen exists; the selection stands.
5. **Completeness**: `complete' = complete`, except — (a) any
   admitted **working-map row** left unselected by step 3 —
   in-batch candidates and displaced retained rows alike (it ranks
   beyond the final boundary) — proves rows beyond the window:
   `complete' = false`; (b) a tail read sets `complete'` from its
   authenticated `exhausted` bit; where (a) and (b) would disagree,
   **(a) wins** (a known unselected row proves incompleteness even
   against an exhausted tail); (c) — executable trigger, defined
   over the ΔZ `op` tags — for an **incomplete** window, any folded
   entry with `op` `delete` or `update` on an **unretained** key
   that is **not selected** into the new window makes the label
   indeterminate: it may have been the only unseen source row, and
   E0 cannot tell previously-inadmissible from beyond-boundary, so
   maintain requires a label re-proof — `tail(window, 1)` from the
   final boundary, its `exhausted` bit deciding — else
   `FALLBACK(completeness-indeterminate)`. Inserts never trigger
   (c): an unselected admitted insert is case (a), and an
   inadmissible insert cannot remove source rows.
6. Δout = the splice diff old-window → new-window over the working
   map: unchanged-rank overlays emit `patch` (projection-scoped,
   §1.5 — this is rung 1's shipped case), rank changes the atomic
   pair, enters/leaves `splice-in`/`splice-out`; state' = the new
   window's post-images, boundary, count, `complete'`, continuation
   re-derived from the new boundary.
7. **`take == 0`** (admissible: validation caps only the maximum,
   `graph.rs:5302`): the window is always empty and the label is
   the fixed shipped `Unknown`/`zero-take-unproved`
   (`graph_evaluator.rs:1117`) — every batch is a membership no-op
   maintain; no boundary logic, no reads, and no scope-birth fill
   (E5).

Backward direction mirrors boundary and clipping. Steps 1–7 are one
atomic state transition per batch; no per-entry sequencing exists
(two enters into a full window displace **two** boundary rows via
one top-`take`, never a duplicate splice-out; a boundary swap's
delete and insert meet in the same working map, the delete ranked
from state).

### E4 — KeyedLookup[index, joinOn] (unique point join)

Unique-index point read keyed by parent join values: body of
`equality-to-one`, binding/target steps of `principal-bound`,
target points of through-edges. **Bilinear.** State per scope
(= parent row): `(lookupKey, childKey | null, found, rowVersion)` —
the `parent-point`/`parent-lookup-skipped` capture vocabulary
(`graph.rs:2065`) — plus retained child rows and the parent→child
index (`EvaluationState.children`).

- **Child-side arm** — input: the child relation's **admitted ΔZ**
  (post-E0; an insert failing the child's visibility or filters
  never reaches the join — attaching it would be fail-open).
  A change to the row at a retained `childKey` patches that scope.
  An admitted enter matching a retained `lookupKey` with
  `found:false` is missing→found. A leave of a retained `childKey`
  (delete or now-inadmissible) is found→missing. A key-field change
  is leave-at-old + arrive-at-new (pre-image key from retained
  state). A second admitted row matching a `found:true` `lookupKey`
  — or two admitted in-batch enters onto one `found:false`
  `lookupKey`, where storage uniqueness admits such a batch at all
  — contradicts the unique-index proof:
  `FALLBACK(unique-violation)`.
- **Parent-side arm** — a **scope birth** (parent enters upstream)
  or a **join-value re-key** both require the same bounded read
  full evaluation performs: `point(index, newKey)` from `R`, else
  `FALLBACK(scope-unfilled)` / `FALLBACK(rekey-unread)`
  respectively. Scope death (parent leaves) destroys state, no
  read. Null/omitted join key attempts no lookup
  (`parent-lookup-skipped`); transitions in/out of null-key follow
  the arms with `found:false` semantics on the null side.
- **Birth/re-key Δout (normative).** The fill read's response IS
  the post-state answer for that scope, and it is **emitted, not
  only stored**: Δout = the diff from the scope's prior answer
  (nothing, for a birth) to the fill — a missing→found presence
  emission, a value patch, or found→missing. The child arm does
  **not** run on scopes birthed or re-keyed in this batch: `R` is
  post-cut, so in-batch child rows are already reflected in the
  fill, and running both arms would double-emit or manufacture a
  false `unique-violation` against the very row the fill attached.
- **Both-change term** (§5's batch rule): parent-arm transitions
  resolve first (scope set, keys, and their fill Δout), then the
  child arm runs against the **surviving unchanged** scopes with
  the folded child batch; the child arm never patches a scope the
  parent arm killed, birthed, or re-keyed in this batch.
- **Presence.** `optional`: found↔missing is representable (§1.5
  presence mapping). `required`: a missing child is an
  evaluation-time refusal (`SNAPBACK_GRAPH_REQUIRED_EDGE_MISSING`,
  `graph_evaluator.rs:1312`); found→missing under `required` is a
  transition into `Refused` — `FALLBACK(refusal-transition)`, never
  a patch — and missing→found (out of refusal) likewise.

### E5 — PerParentWindow (bounded to-many)

E4-style scope keying × one E3 instance per parent scope; fanout
ceiling `maxChildrenPerParent`; page from `GraphChildPageV1`. State:
per-scope E3 state (the `parent-range` capture per parent) + retained
per-scope child rows. All E3 rules apply per scope with the child
relation's admitted ΔZ. Parent-arm:

- **Demand-paged identity precedes every fill rule** (validation
  requires the interval parent set to equal the evaluated parent
  set exactly, `graph.rs:5273`): on a demand-paged node, parent
  **birth**, **death**, and **re-key** are all
  `FALLBACK(demand-identity-transition)` — `scope-unfilled` is
  reachable **only on literal pages**, so each condition has one
  reason (§1.0). The consumer's demand-identity contract, not this
  Spec, decides how the vector is renegotiated.
- **Scope birth (literal pages)** — a parent entering creates a
  window that must be **filled and emitted**, exactly as full
  evaluation fills it (`graph_evaluator.rs:1454`):
  `range(index, parent, window)` from `R`, else
  `FALLBACK(scope-unfilled)`; per E4's birth rule the fill IS Δout
  (array splice-ins for the new scope) and the child arm skips
  scopes birthed/re-keyed this batch.
- **Scope death (literal pages)** destroys state, no read — sound
  only because the parent row itself left the result (its array
  leaves with it, at the ancestor's op per §1.5 absorption).
- **Join-value re-key (literal pages)** is **one scope transition
  with Δout = the E3 splice diff old-window → fill** — the old
  children's `splice-out`s included, exactly as E4's prior→fill
  rule — never death-then-birth splice-ins, which would strand the
  old children client-side. Range read required.
- **`take == 0` pages** fill nothing, read nothing, and emit
  nothing — on birth **and** on re-key (E3 step 7; full evaluation
  performs no child query at zero take, `graph_evaluator.rs:1467`).
- Both-change ordering as in E4.

### E6 — SupportSemiJoin (exists / membership support)

Per-scope support bit; scopes per parent row (`mode:"exists"`,
membership arms), per `(parent, argument-element)` (`mode:"all"`;
the node bit is the **AND over all canonical elements** — a 0→1 on
one element flips the node bit only when every other element is
already 1). **Stateful.** Probe predicates apply E0 (with the
membership-probe exception) — a change failing the probe's
visibility/filters is no support fact.

- **Batch rule per scope**: fold the support-relation changes per
  scope first; the net bit must be provable from folded changes +
  state, else re-probe. Last-write-wins over intermediate facts is
  forbidden (delete-M1 + insert-M2 in one batch nets support 1 even
  though the last fact alone says nothing).
- **0→1**: provable from the change alone **only** for a direct
  edge on an existing scope, where a folded admitted enter matches
  the scope's probe predicate. For a **through edge**, a through-row
  enter proves the link only — the target's visible existence needs
  `probe(edge, scope)` from `R`, else `FALLBACK(support-unproved)`.
  For **`mode:"all"`**, per-element bits are **not retained** (the
  shipped evaluator early-stops at the first failed element and
  retains one aggregate boolean, `graph_evaluator.rs:1942`,
  `:2031`): any element transition needs re-probes of the
  undetermined elements from `R`, else `FALLBACK(support-unproved)`.
- **1→0**: never decidable from captures — `matched_count` comes
  from `limit:1` probes (`graph.rs:2120`) and is not a
  multiplicity; a supporting-row leave needs `probe(edge, scope)`
  from `R` (through: edge range + target points, within declared
  bounds), else `FALLBACK(support-unproved)`. Retaining true
  per-scope (and per-element) support counts is a permitted
  evaluator-internal alternative (§6's path ii), not assumed.
- **Scope attribution (fail-closed, normative)**: a support-side
  change maintains only when the affected-scope set is **provably
  complete** — the probe's join keys are equality-bound to declared
  index components, so the affected scopes are exactly the retained
  scopes whose join values match the changed row's folded images.
  Anything short of that proof is `FALLBACK(scope-unresolved)`.
  "The retained parents whose field matches" is only complete
  together with the lift below; the lift owes the rest.
- **Parent-arm (every E6 input owes a change term — direct edges
  included).** A **scope birth** (a parent row enters upstream — a
  root splice-in, an E5 fill row) or a **scope re-key** (the
  parent's probe-side join value changes; a membership carrier's
  `resourceField` changes, E0's re-key rule) requires the scope's
  bit to be **established**, never defaulted: `probe(edge, scope)`
  from `R` (per undetermined element for `mode:"all"`; edge range +
  target points for through edges), else
  `FALLBACK(support-unproved)`. Scope death destroys the bit. The
  parent-arm resolves before the support-relation arm (§5), **and
  the support-relation arm is skipped on scopes the parent-arm
  birthed or re-keyed this batch** (their bits are already
  post-cut, matching E4's skip rule); E8 / the lift emit the
  established bit for born scopes — a newborn parent's projected
  exists is never emitted as a default 0.

**The E6→membership lift (consumption side).** E6's ΔBit is
consumed two ways:

1. **Projected exists** (`exists {nodeId}` arm): E8 emits the
   boolean update. Scopes are retained parents; no lift needed.
2. **Row-membership filter** — an *unprojected* semi-join (admitted:
   the inert-node check does not require projection,
   `graph.rs:4315`; unprojected semi-joins filter their parent
   relation, `graph_evaluator.rs:2050`) or a **membership
   visibility arm**: the bit gates the *parent/carrier row's
   membership* in its relation. `1→0` removes a retained row only
   where that bit was its **sole admission**: for an unprojected
   semi-join (a conjunction) removal is unconditional; under an
   `any-of` visibility, E0 recomputes the OR and the row stays
   admitted while any other arm admits it. **`0→1` can admit rows
   not in any state** (a membership grant or edge insert makes a
   previously-rejected carrier row admissible; nothing retained it
   — invisible rows are never retained). Maintain requires reading
   the newly-admitted carrier rows: the affected-row set must be
   provably complete (equality-keyed via the declaration's
   `resourceField` / the edge's join on a declared index) and
   fetched via `range`/`point` **on that declared index, keyed by
   the changed support value** (not a per-parent window request),
   bounded by the node's declared bounds and cost ledgers, from
   `R`, else `FALLBACK(scope-unresolved)`.
   Admitted rows then flow into the consuming E0→E3/E4/E5 as
   ordinary enters. Membership-visibility bits are additionally
   **not retained** at all (`EvaluationState.exists` is populated
   only by graph semi-join evaluation, `graph_evaluator.rs:2031`) —
   §6.3 ledgers that as missing. **Composition pin:** a *windowed*
   relation filtered by an unprojected E6 also needs the pre-lift
   window state, which the shipped evaluator does not retain
   (§6.1's pre-lift row) — until that state ledger gap is resolved
   by path (ii), such plans are FALLBACK-pinned by §5's ordinary
   gap rule.

### E7 — PrincipalBind

Decomposes: optional E4 against the binding table keyed by the
principal, then E4 against the target keyed by `parentJoin` +
`principalField` = bound value (or the principal), then E0's
predicates. Three inputs with `binding` — parent, binding relation,
target relation — each owing a change term (E4's arms; both-change
per §5's parent-first order). Partition-of-one partitions `Δin`
(deltas never cross principals) but does not make the operator
state-free: state = the two E4 states + `principal-field` captures
(`partition_hash`, `field`, `value_digest`, `found`;

value must come from retained rows or `R`, never the capture
(§6.2). Class-3-only authority unchanged.

Assembly owes the frame's `result_digest` (byte-equal to a fresh

## 5. Composition and eligibility

A plan's delta rule is the composition of its nodes' decompositions
along the rooted tree + projection references — dataflow
composition over the typed carriers (E0: ΔApp→ΔZ; E3/E5: ΔZ→ΔSeq;
E4: ΔZ-product→patch/presence stream; E6: ΔZ-product→ΔBit; lift:
ΔBit→ΔZ enters; E8: everything→wire). **Batch rule for multi-input
forms**: all per-table folded batches of one commit are presented
together; parent-arm transitions (scope birth/death/re-key) resolve
before child arms; the membership lift's admitted enters join the
consuming form's batch in the same step. This order is normative —
a form must not process arms in any other order.

Eligibility is unchanged from LLP 0209 §7: conjunction with
per-kind admission. Any not-yet-admitted operator, any state-ledger
gap, or any `FALLBACK` **verdict** on the batch at hand pins the
whole graph's frame to the replace path. One frame is one graph
result. A `FALLBACK` aborts composition for the frame; partial
outputs are discarded and **no operator state transition is
applied** — state advances only on a whole-graph maintain verdict;
the replace path rebuilds all state.

Ineligibility (declared unmaintainable ⇒ replace) and comparator
divergence (§7.3) remain distinct outcomes.

**Consumer gates are not operator semantics.** The shipped lanes
wrap these forms in subscription-level gates recorded here, not
owned here: receiver-local delta negotiation
(`snapback.graph-live-delta.v1`; never memoized), the graph lane's
full exclusion of auth-scoped subscriptions (`engine.rs:33498`) vs
**DK-3's narrower rule** (authorized subscriptions may receive
add/update deltas; any removal forces replace, `engine.rs:34449`),
`force_replace` pins, the capture-freshness latch (§6.4), and the
kill switches — with one shipped asymmetry Stage B must classify:
`SNAPBACK_GRAPH_DELTA_DISABLED` gates delta candidacy
(`engine.rs:33498`), but `SNAPBACK_GRAPH_EXEC_DISABLED` is checked
only at memo/fresh execution (`engine.rs:9055`, `:41932`) — an
established subscription can still take the incremental path after
the execution switch is raised (§8).

### 7.1 Reference evaluator

One pure function per elementary form,
`(state, Δin, R) → Maintain(Δout, state') | Fallback(reason)`, plus
§5's composition and batch rule, isolated from the serving path
(packaging per OQ-1). It is the derivation artifact and the
drift-prevention mechanism (LLP 0051's one-evaluator ruling made
honest): agreement between instantiations is "shared forms, one
oracle, same corpus."

### 7.2 Vector corpus

`tests/conformance/delta-semantics-v1/` in the house
`result-transform-v1` pattern (own `corpus.manifest.json`, case

`crates/snapback/tests/delta_semantics_corpus_v1.rs`;

initial state, folded change batch, **read transcript `R`**
