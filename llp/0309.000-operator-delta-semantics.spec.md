# LLP 0309.000: Operator delta semantics for the closed query algebra

**Type:** Spec
**Status:** Draft
**Systems:** Live queries, Offline sync, Storage
**Author:** Claude Fable / Charlie Cheever
**Date:** 2026-08-25
**Revised:** 2026-08-25
**Related:** LLP 0309 (parent RFC), LLP 0008, LLP 0051, LLP 0056,

## Summary

This Spec is the normative per-operator incremental semantics for
Snapback's closed query surface — Stage A of LLP 0309, commissioned
2026-08-25 (`issues/20260825-llp0309-stage-a-commission.md`). It
defines, once per elementary operator, how a change batch flows
through that operator: the typed incremental form `∂O`, its state,
its maintain conditions, and its `FALLBACK` verdicts. Every admitted
plan's delta rule is the composition of these forms along the plan's
dataflow; rule content for future delta-lane rungs is instantiated
from this document and checked against its executable reference
evaluator, never re-authored per node kind.

The Spec binds to the shipped IR at the granularity of code, not
prose: the seven `GraphNodeV1` kinds and four `TableVisibilityV1`
arms (`crates/snapback-types/src/manifest/graph.rs:876`,
`crates/snapback-types/src/manifest/types.rs:1246`), the six-op
`FilterExpr` conjunction with `Arg`/`Literal` values only
(`graph.rs:4621`), the `GraphProjectionValueV1` assembly arms, the
captured-dependency vocabulary (LLP 0209 §5.1;
`GraphCapturedDependencyV1`, `graph.rs:2043`), and the G3 retained
evaluation state (`EvaluationState`,
`crates/snapback-engine/src/graph_evaluator.rs:455`). §4's closure
table accounts for every variant and arm — by decomposition into
elementary forms or by named refusal — so no IR surface is silently
outside the semantics.

What this Spec does **not** change: LLP 0209 §7's admission posture
(per-kind admission, one ineligible node pins the graph to replace,
`live_replace` the honest fallback), wire kinds and delivery
negotiation, the capture vocabulary except through 0209's amendment
path, authority-transition handling (the LLP 0200 fence), the
opaque-handler categorical, and the replica continuity contract
(LLP 0209 OQ-6).

## 1. Carriers

Four typed carriers appear in the forms. Composition (`+`) is defined
per carrier; the defining equivalence property of every form is

```text
O(S ⊕ ΔS) = O(S) + ∂O(state_O, ΔS).Δout        (maintain verdicts only)
```

where `⊕` is base-state application and `+` is the output carrier's
composition. `FALLBACK(reason)` is a first-class verdict, not a
failure: for the server consumer it maps to `live_replace`; other
consumers handle it per LLP 0309 §D3.2.

### 1.1 ΔApp — the admitted application-row change carrier (input)

A batch of committed row changes to one table, atomic per commit:

- `insert(key, post)` — post-image row.
- `update(key, post, changed_fields)` — post-image row; the
  pre-image is **not** guaranteed by the carrier. An empty or
  unavailable `changed_fields` set is treated as
  "any field may have changed" (the shipped rule:
  `descendant_join_may_have_changed` refuses when
  `changed_fields.is_empty()`, `graph_evaluator.rs:3170`).
- `delete(key, pre?)` — pre-image if available, else key only.

**Batch normalization:** before classification, a batch collapses to
last-change-per-row-key in first-seen order — DK-3's shipped rule
(`live_matcher.rs:3581`), which closes the insert-then-delete
phantom-add defect. A multi-row commit (e.g. a boundary swap) is one
batch, never a row at a time; forms consume whole batches.

Image direction is a carrier property (LLP 0309 §D1.1): where a form
needs an image the carrier does not supply — an interior ordered
row's prior sort key, a deleted row's join value — the state
contract (§6) must supply it via retained state or a bounded
authorized read, or the form returns `FALLBACK(missing-image)`.
Other production change kinds (schema, authority, incarnation) are
outside ΔApp and never produce maintain verdicts; authority-driven
invalidation belongs to the LLP 0200 fence, not to these forms.

### 1.2 ΔZ — Z-set batches (unordered relational carrier)

Internal carrier for unordered operators: a batch of
`(row_key, image, ±1)` entries; an update is a paired
`(-1 pre, +1 post)` once the pre-image is available from state.
Composition is signed multiset addition; entries for the same key
collapse in batch order.

### 1.3 ΔSeq — ranked-sequence splices (ordered/window carrier)

Output carrier for ordered, limited operators. Entries are splice
ops positioned by total-order sort key (declared order + `_id ASC`
tie-break, LLP 0209 §2.2; NULL-last independent of direction,
`live_matcher.rs:3365`):

- `splice-in(sort_key, row)` — insert at rank.
- `splice-out(sort_key, row_key)` — remove at rank.
- `patch(sort_key, row_key, post)` — in-place update, rank
  unchanged.

Composition is sequence splicing, not Z-set addition. A rank change
is `splice-out + splice-in` in one batch.

### 1.4 ΔBit — support-bit transitions (predicate carrier)

Output carrier for semi-join and membership-visibility forms, per
support scope (per parent row; per `(parent, argument-element)` for
`mode:"all"`): `0→1`, `1→0`, or unchanged. Composition is last-write
per scope within a batch.

### 1.5 Wire mapping

The wire vocabulary is unchanged: `LiveGraphDeltaWireOpV1`
(`crates/snapback-types/src/live_wire.rs:352`) with
`op ∈ {add, update, remove}`, `node_id`, `root_key`, `key`,
`position`, `row`, plus the frame's `ordered_root_keys`,
`proof_tuple`, per-node and graph completeness, and `result_digest`
(`live_wire.rs:317`). The normative mapping from carriers:

- root-window ΔSeq: `splice-in` → `add` with `position`;
  `splice-out` → `remove`; `patch` → `update` with the
  `retained_row_patch` field diff (`graph_evaluator.rs:3328`:
  changed fields only, removals as explicit `null`, system fields
  included). `ordered_root_keys` is the post-batch root order and
  MUST equal the reference evaluator's.
- to-one patches: `update` on the affected root's projected object
  (rung 1's shipped shape).
- to-many ΔSeq (future rung): the same three ops scoped by
  `node_id` + parent `root_key`.
- ΔBit: `update` carrying the recomputed projected `exists` value.

Shipped scope note: rung 1 emits `update` only, and its client-view
oracle (`apply_graph_delta_to_result`, `graph_evaluator.rs:3411`)
rejects `add`/`remove`; a rung instantiating the fuller mapping
extends the oracle in the same landing. A frame carries the same
resolution-ticket and watermark obligations as any live frame;
deltas ride the data-driven lane only.

## 2. Elementary operators

The corrected inventory (this section **is** the confirmation LLP
0309 §D1.2 requires; §3 records each hypothesis's disposition).
Elementary forms are unary or binary; binary forms type `Δin` as a
product — two unary arms (each using retained state of the other
side) plus a both-change arm. Composites decompose in §4; directly
typed n-ary forms give every input a change term.

### E1 — VisibilityFilter[arm] (σ_vis)

Applied at every relation read, before data filters.

- `public-read`: identity. **Linear, state-free.**
- `owner{field}`: row-local predicate `row[field] == auth.userId`.
  The principal is fixed per materialization partition, so this is a
  constant predicate over the batch. **Linear, state-free.** A row
  whose `field` is missing or non-string is not visible to the
  evaluator; the matcher treats it as unknown
  (`live_matcher.rs:3171`) and stays conservative — the form
  classifies such rows not-visible, matching evaluator behavior
  (matcher conservatism is a wake-precision property, not a
  semantics difference).
- `membership{declaration, resourceField, roles}`: **not row-local**
  — visibility of row `r` is a support predicate over the membership
  relation keyed by `r[resourceField]`, with role filtering
  (`None` roles = all non-pending; `Some(list)` = role subset).
  Decomposes to E6 against the membership declaration's relation. A
  membership-table write changes other rows' visibility with ΔApp
  empty on the carrier table; the form's `Δin` product makes the
  membership relation an explicit input. **Support class.**
- `any-of(arms)`: disjunction over `owner` and `membership` arms
  only (`types.rs:1266`). Row visibility = OR of arm bits. An
  `any-of` of owner arms only is row-local and linear; any
  membership arm makes the whole form support-classed, maintained as
  OR over E1/E6 arm outputs with a both-change term.

### E2 — Filter[p] (σ_p)

The node's `FilterExpr[]` conjunction: six ops (`Eq`, `In`, `Lt`,
`Lte`, `Gt`, `Gte`), values only `Arg` (bound at demand time, then
constant) or `Literal` (`graph.rs:4621`). **Linear, state-free.**
Predicate evaluation reuses the LLP 0051 shared evaluator and the
matcher/SQL agreement invariant unchanged: SQL three-valued logic, a
NULL actual never matches any op, `IS NULL` is inexpressible
(`live_matcher.rs:3217` ↔ `storage.rs:14895`). For a form: an
`update` whose post-image decides the predicate is classified
enter/leave/stay; a row whose predicate value is *unanalyzable* in
the delta context (matcher-side `None`) yields
`FALLBACK(predicate-unanalyzable)` — never a guessed
classification. Enter/leave classification additionally needs the
pre-image side of the question (was the row in the result?);
**membership-in-state substitutes for the missing pre-image** — the
row was retained iff it was in the node's result — so no read is
required at this operator. This is DK-3's shipped rule
(`was_member = prior_ids.contains(id)`, `live_matcher.rs:3603`),
stated once as an operator property.

### E3 — Window[order, interval, take] (ordered window)

The ordered, limited range: declared order + `_id ASC`, direction,
interval ends, take. Instantiated once at the root and per parent in
to-many. **Stateful.** State per instance (§6.1 has the ledger):
the member row set with recoverable sort keys, boundary first/last
keys, result count, completeness bit, and continuation cursor.
Classification of each incoming ΔZ entry against the window:

- **inside, sort key unchanged** → `patch` (rung 1's shipped case).
- **inside, sort key changed, both ranks inside** →
  `splice-out + splice-in` in one batch.
- **enters** (insert or update moving in; predicate-entering rows
  from E2) → `splice-in`; if the window was full
  (`result_count == take`), the displaced boundary row
  `splice-out`s — decidable entirely from state.
- **leaves** (delete, update moving out, predicate-leaving) →
  `splice-out`; if the window was full and the source is not
  exhausted (completeness bit false — rows exist beyond the
  boundary), the replacement row is **not** in state.
  **Provable-replacement condition**: a maintain verdict requires
  (i) the window was not full, or (ii) the source was exhausted
  (`complete: true` — no replacement exists), or (iii) a bounded
  authorized read of exactly the next row past the boundary is
  performed and charged. Otherwise
  `FALLBACK(boundary-displacement)`. This condition is stated once,
  here, as an operator property — per LLP 0309 §D1.2's requirement
  — and every windowed instantiation (root or per-parent) inherits
  it.
- **outside both** → no-op.

An entry whose *rank* cannot be decided (sort-key field absent from
the image and from state) is `FALLBACK(rank-undecidable)`. Backward
direction mirrors the boundary; `lower`/`upper` interval ends clip
enter/leave classification before take handling. The shipped
precedents both stop short of this form: DK-3 replaces on any
ordered or at-cap window (`live_matcher.rs:3558`), and rung 1
maintains only the sort-key-unchanged `patch` case, replacing on
any membership or order change (`graph_evaluator.rs:3704`); those
are conservative restrictions of this form, not different
semantics.

### E4 — KeyedLookup[index, joinOn] (unique point join)

Unique-index point read keyed by parent join values: the body of
`equality-to-one`, the binding and target steps of
`principal-bound`, and the target points of through-edges.
**Bilinear.** State per parent key: `(lookupKey, childKey | null,
found, rowVersion)` — exactly the `parent-point` /
`parent-lookup-skipped` capture vocabulary (`graph.rs:2065`), plus
the retained child rows and the parent→child index
(`EvaluationState.children`, `graph_evaluator.rs:459`).

- **Child-side arm** (ΔApp on the child table): a change to the row
  at a retained `childKey` patches that parent's joined value
  (rung 1's shipped case; affected parents found by reverse
  traversal of retained state — `affected_to_one_parents`,
  `graph_evaluator.rs:3216`). An insert/update whose join-field
  value matches a retained `lookupKey` with `found:false` is a
  missing→found transition; a delete of a retained `childKey` is
  found→missing. A child update that *changes the joined key field*
  is both: leave at the old key, arrive at the new — the pre-image
  key comes from retained state, since ΔApp does not guarantee it.
- **Parent-side arm** (parent row's join value changes): re-key — a
  point lookup at the new key is required; state has nothing for
  it. Maintain requires a bounded authorized point read (one unique
  probe — the same `take = 1` read full evaluation performs,
  `graph_evaluator.rs:1336`), else `FALLBACK(rekey-unread)`.
- **A null/omitted join key** attempts no lookup
  (`parent-lookup-skipped`); transitions into or out of the null-key
  state follow the arms above with `found:false` semantics on the
  null side.
- **Presence semantics (correction to the D1.2 hypothesis).**
  `presence:"optional"`: missing→found and found→missing are
  representable — the projected `object` arm transitions null ↔
  object, an `update` op. `presence:"required"`: a missing child is
  an **evaluation-time refusal**
  (`SNAPBACK_GRAPH_REQUIRED_EDGE_MISSING`), not an absent field. A
  found→missing transition under `required` therefore moves the
  materialization into `Refused` — a completeness transition, not a
  row patch — and is **never a maintain verdict**:
  `FALLBACK(refusal-transition)`; the replace path re-evaluates to
  the refusal. Missing→found under `required` (out of refusal)
  likewise.

### E5 — PerParentWindow (bounded to-many)

Composition, not a new primitive: E4-style parent keying × one E3
instance per parent, fanout ceiling `maxChildrenPerParent`, page
from `GraphChildPageV1` (literal or demand). State: per-parent E3
state (the `parent-range` capture: predicate, order, direction,
bounds, limit, result count, boundary, completeness — per parent,
so one parent cannot shadow another) plus the retained per-parent
child rows. All E3 verdicts apply per parent; additionally a
**parent-arm**: parent enter/leave creates/destroys a whole
per-parent window (assembled as an array splice at E8); a parent
join-value change re-keys the range — maintain requires the bounded
authorized range read full evaluation would do, else
`FALLBACK(rekey-unread)`. Literal pages have plan-fixed windows;
demand pages take interval/take from the demand's window vector and
are otherwise identical.

### E6 — SupportSemiJoin (exists / membership visibility)

Per-scope support bit with 0↔1 transitions. Scopes: per parent row
(`mode:"exists"`, membership visibility), per
`(parent, argument-element)` (`mode:"all"` — the node's bit is AND
over the canonicalized, deduplicated argument elements, each probed
as a per-element `Eq`; `graph_evaluator.rs:2097`). **Stateful.**

The shipped capture is `matched_count` from bounded `limit:1`
probes (`graph.rs:2110`; LLP 0209 §5.1) — **it is not a support
multiplicity**. This resolves LLP 0309 OQ-2, recorded in §3:

- **0→1**: decidable from the change alone — an insert (or entering
  update) that matches the probe predicate for a scope whose
  support bit is 0 proves support. Maintain.
- **1→0**: **not decidable from captures** — a delete of a
  supporting row where `matched_count == 1` cannot distinguish 1→0
  from 1→1, because the `limit:1` probe stopped at the first match
  and other supporting rows may exist. A maintain verdict requires
  a bounded authorized re-probe (the same probe evaluation performs
  — for a through edge, the edge-range plus target-point reads,
  within the node's declared bounds), else
  `FALLBACK(support-unproved)`. No capture amendment is required:
  the re-probe is a §6 `authorized-read` source. Retaining true
  per-scope support counts is a permitted evaluator-internal
  alternative (§6.3's third path) but is not assumed.
- A change that cannot be classified for scope membership (which
  parents' probes could it affect?) is
  `FALLBACK(scope-unresolved)`.
- **Through edges are three-input** (parent, through, target — LLP
  0309 §D1.1): each input owes a change term. Through-row changes
  re-key target probes; target-row changes flip probe outcomes;
  parent changes create/destroy scopes. Interaction terms (one
  batch touching two inputs) compose in batch order; where
  composition order cannot be established within the batch,
  `FALLBACK(interaction-unordered)`.

Filters on the semi-join (`filters`, `targetVisibility`,
through-`visibility`) apply E1/E2 inside the probe predicate. The
shipped stance — DK-3 excludes membership-gated plans fail-closed
(LLP 0067 §F2a, `live_matcher.rs:3572`), and the graph lane pins
semi-joins to replace pending the certified evaluator (LLP 0056) —
is the admission gate this form must pass, not a different
semantics.

### E7 — PrincipalBind

`principal-bound` decomposes: optional E4 against the binding table
keyed by the principal (`binding.uniqueIndex`), then E4 against the
target keyed by `parentJoin` + `principalField` = the bound value
(or the principal itself), then E1/E2. Three inputs when `binding`
is present — parent, binding relation, target relation — each owing
a change term. The **partition-of-one property partitions `Δin`**:
the effective authority partition is the principal, so a binding- or
target-row change affects at most the one principal whose partition
it is — deltas never cross principals by construction. It does not
make the operator state-free (the D1.2 hypothesis's own
correction): state is the two E4 states plus the `principal-field`
capture rows (`partition_hash`, `field`, `value_digest`, `found`;
`graph.rs:2141`). A binding-row change re-keys the target lookup —
E4 parent-arm rules apply, including the bounded-read condition;
note the capture holds only a **value digest**, so the re-key value
must come from retained rows or the authorized read, never from the
capture (§6.2). Class-3-only authority is unchanged.

### E8 — Assemble (closed projection)

The output-assembly stage, derived from child forms — never assumed
relational projection (LLP 0309 §D1.2). Per
`GraphProjectionValueV1` arm (`graph.rs:828`):

- `field {nodeId, field}` — scalar from that node's row: linear in
  the child's patch stream; identity-preserving.
- `literal` — constant; no delta ever.
- `object {nodeId, object}` — null ↔ object follows the to-one's
  found bit (E4); interior field changes are patches
  (`apply_projected_node_patch`, `graph_evaluator.rs:3363`).
- `array {scopeNodeId, item}` — the to-many node's ΔSeq splices, in
  page order, mapped to array element add/update/remove.
- `exists {nodeId}` — E6's ΔBit, emitted as an `update` of the
  projected boolean.

Assembly owes the frame's `result_digest` over the post-delta
serialized result, byte-equal to a fresh serialization, and the
projection-composition completeness label (§4.2 of LLP 0209)
recomputed from child labels.

### E9 — SearchMembership: named refusal

Not a form. The node kind has wire shape but **no admissible
instance today** — admission unconditionally refuses
(`graph.rs:4512`, `graph.rs:4942`) and the evaluator arm refuses
with `SNAPBACK_QUERY_COST_EVIDENCE_REQUIRED`
(`graph_evaluator.rs:2965`). Its invalidation facts belong to D6's
writer (LLP 0209 OQ-4). The closure table records it as **REFUSED
(named)**: if search-membership is ever admitted, this Spec gains a
form through 0209's amendment path before any delta lane may touch
it; there is nothing to fall back *from* today.

## 4. Closure table

Every `GraphNodeV1` variant and `TableVisibilityV1` arm, to
elementary decomposition or named refusal (the LLP 0309 §D1.2
closure check). Every relation-reading decomposition includes E1
(its declared visibility) before E2.

| IR surface | Decomposition |
|---|---|
| `root-window` | E1 ∘ E2 ∘ E3 (demand-paged window) |
| `equality-to-one` | E4 (child side = E1 ∘ E2 of the child relation) |
| `bounded-to-many` | E5 = E4-keying × per-parent E3 (child side = E1 ∘ E2) |
| `exists-semi-join` (direct, `exists`) | E6 over E1 ∘ E2 of the edge relation |
| `exists-semi-join` (through, `exists`) | E6 three-input: parent × (E1 ∘ E2 through) × (E1 ∘ E2 target) |
| `exists-semi-join` (`all`, either edge) | E6 per `(parent, argument-element)` scope, node bit = AND over canonical elements |
| `principal-bound` (no binding) | E7 = E4(target) ∘ E1 ∘ E2 |
| `principal-bound` (with binding) | E7 three-input: parent × E4(binding) × E4(target), each ∘ E1 ∘ E2 |
| `search-membership` | **REFUSED (named)** — E9 |
| `closed-projection` | E8 over child outputs (`field`/`literal`/`object`/`array`/`exists`) |
| visibility `public-read` | E1 identity |
| visibility `owner{field}` | E1 row-local |
| visibility `membership{…}` | E1 → E6 against the membership declaration's relation |

No other node kinds, visibility arms, or projection arms exist at
the pinned revision (commit `232a82504`); §9's amendment rule covers
additions.

## 5. Composition and eligibility

A plan's delta rule is the composition of its nodes' decompositions
along the rooted tree + projection references — dataflow
composition; bilinear forms compose over both inputs. Eligibility is
unchanged from LLP 0209 §7: **conjunction with per-kind admission**.
An operator form participates only once admitted (vectors +
convergence checks, §7); any not-yet-admitted operator in the plan,
any state-ledger gap, or any `FALLBACK` **verdict** from an admitted
form on the batch at hand pins the whole graph's frame to
`live_replace`. One frame is one graph result — never per-node
fragments.

Verdict propagation: forms compose by feeding `Δout` downstream; a
`FALLBACK` at any operator aborts composition for the frame. Partial
outputs are discarded and **operator state transitions are not
applied** — state advances only on a whole-graph maintain verdict;
the replace path rebuilds all state from the fresh evaluation.

Ineligibility (declared unmaintainable ⇒ replace, normal and
expected) and comparator divergence (maintained ≠ fresh ⇒ §7.3)
remain distinct outcomes.

**Consumer gates are not operator semantics.** The shipped lanes
wrap these forms in subscription-level gates that this Spec records
but does not own: delta delivery is negotiated per receiver
(`snapback.graph-live-delta.v1`, receiver-local across memo hits),
auth-scoped subscriptions are excluded, `force_replace` pins, the
kill switches (`SNAPBACK_GRAPH_EXEC_DISABLED`,
`SNAPBACK_GRAPH_DELTA_DISABLED`), and the capture-freshness latch
(§6.4). Stage B audits them on their own axes; derivation neither
produces nor removes them.

## 6. State ledgers (LLP 0309 §D1.3)

Judged against both precedents: the capture vocabulary
(`GraphCapturedDependencyV1`, `graph.rs:2043`; ordinary
`CapturedReadDependency`, `crates/snapback-types/src/storage.rs:304`)
and the G3 retained evaluation state (`EvaluationState`,
`graph_evaluator.rs:455`). Custody classes: everything in
`EvaluationState` (retained rows, child index, exists bits,
continuations, lookahead flags, query-output row bodies, physical
row keys) is **server-internal, deliberately non-serialized**
(`RetainedEvaluationState`, `graph_evaluator.rs:210`, with
`PartialEq` identically true and `#[serde(skip)]` on the output);
captures are attested at sync and inspection-redacted to ids,
counts, kinds, digests. **Nothing in this Spec makes any entry
eligible to cross the client custody boundary** — that stricter
claim stays gated by LLP 0190 (LLP 0309 §D3.2).

A missing or wrong-grain entry resolves by (i) capture amendment
through 0209's path, (ii) evaluator-internal retained-state addition
(not profile surface; ordinary landing discipline), or (iii) the
form stays `FALLBACK`-pinned — never silent approximation.

### 6.1 E3 — Window (root instance; per-parent instances read the same table with `parent-range` / per-parent retained children)

| Entry | Verdict | Source | Images | Custody |
|---|---|---|---|---|
| Member row set + sort keys | **have** | retained `roots` / `children` (full rows; sort keys recovered via order fields, `live_matcher.rs:3351`) | post (pre recoverable from retained row) | server-internal |

### 6.4 Outer serving state (in scope per LLP 0309 §D1.3; consumer-owned)

- **Cost ledgers** — `GraphWindowLedgerV1` per demand lineage:
  accumulated via `next_ledgers` (`graph_evaluator.rs:2719`) on
  every lane including delta (bail-to-replace on bound overflow);
  reuse-precondition for memo hits but deliberately not memo
  identity (`engine.rs:9134`). Forms do not read it; every
  maintain verdict must still pass `next_ledgers` accounting.
- **Capture freshness (graph lane)** — the shipped lane does
  **not** maintain `captured_reads` on delta: the vector is copied
  forward verbatim (`graph_evaluator.rs:3887`) and the registration
  latches `delta_requires_replace = true` (`engine.rs:34323`), so
  the next event is matcher-pinned to `ConservativeFallback` and
  takes the replace lane, which rebuilds captures. Consequently
  **at most one delta frame is emitted per replace-refreshed
  capture** in the shipped consumer. This is a consumer freshness
  policy, not operator semantics: forms define `state'`; whether a
  consumer re-attests captures incrementally (and may therefore
  chain maintain verdicts) or latches to replace is its custody
  decision, audited on Stage B's stale-capture axis. A consumer
  that chains deltas without refreshed captures MUST derive its
  matcher evidence from maintained state — silent reuse of stale
  captures for `Skip` decisions is forbidden (the shipped latch
  exists precisely to prevent it).
- **Capture freshness (DK-3 lane)** — the single-table lane
  maintains its `Query` capture partially in place: `rows` and
  `version` are updated (`engine.rs:34532`), while `order`,
  `limit`, `result_count`, and `boundary` are left at their
  original values, and delta-minted `Row` captures carry
  `result_count: None, boundary: None`. For the plans DK-3 admits
  (unordered, under-limit) `boundary` is `None` by construction;
  the stale `result_count` is a **Stage B probe target** (§8) — the
  audit classifies it, this Spec does not pre-judge it.
- **Delivery state** — `delta_enabled` (receiver-local
  negotiation), `convergence_deliveries`, `delta_requires_replace`:
  never memoized, never serialized; outside derivation.

## 7. Verification

### 7.1 Reference evaluator

Stage A ships an executable reference evaluator over §1's carriers:
one pure function per elementary form,
`(state, Δin) → Maintain(Δout, state') | Fallback(reason)`, plus
§5's composition, isolated from the serving path (no dependency
from `graph_evaluator.rs`'s serving lanes on it, none from it on
them; packaging per OQ-1). It is the derivation artifact and the
drift-prevention mechanism (the honest analogue of LLP 0051's
one-evaluator ruling): agreement between instantiations is "shared
forms, one oracle, same corpus," never prose.

### 7.2 Vector corpus

A dedicated conformance subcorpus in the house
`result-transform-v1` pattern
(`tests/conformance/data-tier/result-transform-v1/` is the
template): `tests/conformance/delta-semantics-v1/` with one case
file per operator × scenario (`NNN-operator-scenario.case.json`),
its own `corpus.manifest.json` (case schema path, per-case
`sha256`, evaluator identity), a source-of-truth generator
(`corpus-source.mjs` house style), and a Rust runner
(`crates/snapback/tests/delta_semantics_corpus_v1.rs`) that
executes every vector against the reference evaluator —
determinism-×2, compare-or-freeze under a
`SNAPBACK_FREEZE_DELTA_SEMANTICS` env var, matching the graph
corpus discipline.

Each vector pins operator, initial state, change batch, and either
`Maintain` with expected `Δout` **and expected next state**, or
`Fallback` with the expected reason (state after fallback is
rebuilt by the replace path and is not pinned). Required coverage
classes per operator: three-valued-logic edges (NULL actuals, `In`
with NULL elements, missing fields), boundary edges (full/unfull
windows, source-exhausted vs not, backward direction, interval
clipping, take-boundary displacement with and without provable
replacement), presence transitions (`optional` null↔object;
`required` refusal transitions), 0↔1 support transitions in both
directions (including the 1→1 delete that must not clear the bit),
re-key cases on every keyed form, both-change / interaction terms
for every multi-input form, batch-atomicity cases (boundary swap,
insert-then-delete collapse), and `all`-mode per-element scopes.

### 7.3 Runtime comparator

Unchanged from the shipped discipline (LLP 0309 §D4.3): DK-3's
debug convergence assertion (`engine.rs:34637`) and the graph
lane's sampling (`SNAPBACK_GRAPH_DELTA_CONVERGENCE`; debug always,
release first-4 then 1-in-64) with the landed mismatch response —
record and force replace for that event, no delta bytes crossing
publication. Persistent-divergence policy stays LLP 0309 OQ-5.

## 8. Stage B binding

The re-derivation audit (LLP 0309 §D4.2) runs shipped lanes — DK-3
single-table classification (`compute_live_delta`,
`live_matcher.rs:3541`) and G3 rung 1 (`evaluate_graph_delta_on`,
`graph_evaluator.rs:3619`) — against §7.1's evaluator on the
existing corpora (`tests/conformance/graph/corpus.v1.json`, the
frozen `delta-dispositions.v1.json`, `live_delta_v0.rs`) across
eligibility decisions, fallback verdicts, retained-state
transitions, emitted ops, and the outer axes: bounded/authorized
read effects, proof updates (`rebuild_to_one_proof`) and
composition labels, cost-ledger transitions (`next_ledgers`), and
stale-capture replacement (the §6.4 latch and DK-3's partial

probe target). Divergences classify (a) reference error / (b)
shipped defect → fix-forward ticket per LLP 0189 / (c) recorded
shipped-lane-only conservative approximation — DK-3's
ordered-window replace and rung 1's membership-change replace are
expected class (c) entries; unclassified divergence blocks Stage C.
Stage B changes no runtime code.

## 9. Amendment and instantiation rules

- A new node kind, visibility arm, projection arm, or filter op
  amends this Spec **before** any delta lane may treat it as
  eligible; absent an amendment it is unadmitted and pins to
  replace (or refuses, where admission refuses).
- Stage C instantiation (LLP 0309 OQ-3) is ruled here:
  **hand-instantiated production lanes checked against the
  reference evaluator** — no interpreter on the serving path, no
  codegen commitment; the oracle requirement is what is normative.
  A later move to generated instantiation would amend this section.
- State-ledger gaps resolve per §6's three paths — never silent
  approximation.
