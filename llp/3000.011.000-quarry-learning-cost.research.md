## 1. Problem

The recurring difficulty is learning which apparently ordinary expressions
change completeness, authority or prediction. A builder can know the product
they want and still need several compiler/guide cycles to discover its valid
representation. Syntax familiarity is only part of that cost.

## 2. Evidence

| Observation | Source and interpretation |
| --- | --- |
| App post references and recipe event references took several compiler iterations to connect. | [0.2.31 M2](../benchmarks/runs/2026-09-20-snapback4-clique-astra-0.2.31/astra/lane-diary.md). The distinction is useful; locating the correct conversion is application work. |
| A reaction query needed the conversation prefix to establish completeness under the membership rule. | The same diary, M4; also [0.2.30 M4](../benchmarks/runs/2026-09-18-snapback4-clique-astra-0.2.30/astra/lane-diary.md). An index that finds matching rows need not prove the full authorized answer. |
| Moving a profile read outside a presence-controlled effect arm restored prediction. | 0.2.31 M6 and [essay](../benchmarks/runs/2026-09-20-snapback4-clique-astra-0.2.31/astra/lane-essay.md). Understanding fallibility and control dependence was necessary to fix the shape. |
| Plausible forms such as `len`, a namespaced helper, an unsupported membership operator and an explicit upsert id were corrected. | 0.2.30 M4–M8. Familiar language habits do not transfer uniformly. |

The diaries call these author mistakes and generally praise the diagnostics.
There is no evidence here that the compiler accepted an unsafe operation or
misdiagnosed these examples. The product finding is the frequency and depth
of the concepts a cold builder must discover.

## 3. What already exists

The [prediction card](../snapback4/crates/snapback4-lang/src/guide/prediction.rs)
already documents `predicts:`, persistent summaries, `why <op>`, root causes,
horizon misses and queued writes without rows. The
[programs card](../snapback4/crates/snapback4-lang/src/guide/programs.rs)
already explains helper returns and structural fanout. `check --fix` already
repairs selected mechanical mistakes. An improvement must outperform these
tools on specific examples, rather than propose them as missing features.

The short entry README shipped in 0.2.31. This problem therefore concerns
contextual understanding after entry, not a claim that its predecessor's
documentation volume remains unchanged. The implemented language work of
LLP 3000.008.000 is retained.

## 4. Likely cause and cost

One expression participates in multiple analyses: type compatibility, rule
uniformity, device residency, fallibility and prediction. A generic guide
paragraph explains the rule, but the builder still maps it onto their helper,
argument and enclosing operation. Several individually clear messages can
leave that dependency chain implicit.

This is an interpretation to test. The latest run also compiled several
milestones on its first pass. Not every unfamiliar form deserves an alias,
language extension or automatic rewrite, and some mistakes would occur in any
new language.

## 5. Desired outcome and confidence

A builder should resolve these common cases from the diagnostic and one
relevant lookup, without reading compiler source or weakening application
policy to make a warning disappear. Repeated mistakes are high-confidence
observations; the benefit of richer contextual output is still a hypothesis.

The [child RFC](./3000.011.000.000-contextual-compiler-guidance.rfc.md)
proposes an operation-specific explanation and tested rewrite, with the
existing diagnostics as its control. More output that does not reduce
corrections would fail that proposal's purpose.
