## Summary

Three model families were given one brief — design the agent-native scale-to-zero
backend, theory first — and answered independently, none seeing another's work:

- **Claude Fable 5** — [LLP 0329.001](./0329.001-design-sketch-fable.research.md)
- **codex `gpt-5.6-sol` @ xhigh** — [LLP 0329.002](./0329.002-design-sketch-codex-sol.research.md)
- **`grok-4.6` @ xhigh** — [LLP 0329.003](./0329.003-design-sketch-grok.research.md)

Each received [LLP 0329](./0329-agent-native-rebuild-diagnosis.research.md) as the
diagnosis. This document records where they converged, where two overruled one, and
where they genuinely disagree. It is a research record of an option-space
exploration; it ratifies nothing and authorizes no implementation.

**Method and its limits.** Fable and codex ran with repository read access. Grok ran
headless with a full terminal ban and the diagnosis inlined, so it reasoned from
LLP 0329's text alone and could not verify claims against source; weight its
specific factual assertions accordingly, though its argument structure is
unaffected. Blindness is **self-attested** for all three: no sketch existed in the
tree when the first was launched, and none was shown another's output, but each
model could in principle have been influenced by shared training rather than by
independent derivation. Convergence below is therefore evidence of a natural
attractor in the design space, not proof of independent discovery.

## Findings

### 1. Unanimous

All three, independently:

1. **Capability-as-authoring-form is the root cause,** and it is the same defect as
   the `public-read` failure. No dissent.
2. **Authorization is row-level predicates in the schema, deny-by-default,** written
   in the same language as queries, and is the *only* authorization mechanism. No
   per-query auth flag.
3. **Public access must unlock no capability.** All three framed this as incentive
   design rather than policy: if widening visibility buys nothing, an
   obstacle-routing agent has no reason to do it. Grok: "public is the long way
   around." Codex additionally rejects an unconditional rule outright and requires a
   conspicuous `publicData(reason)` that emits a security item in the build receipt.
4. **Admitted implies every capability — refuse, do not degrade.** If the compiler
   accepts the program it is live, realtime, and retainable; if those cannot be
   guaranteed, the program is not a query.
5. **Everything derivable is derived, and the author is forbidden to declare it.**
   All three independently noted that a read set must include tables touched only by
   *rules* — the mechanism by which a membership change invalidates a messages query
   that never mentions memberships.
6. **The mutation text is the optimistic predictor.** One definition, executed
   locally for prediction and on the server for authority; no app-authored
   optimistic reducers.
7. **A small closed vocabulary** (~20–30 names) and a small error algebra (~20
   categories against the 3,934 codes measured in LLP 0329), with a hard rule that
   no diagnostic may offer weakening authorization as a repair.

### 2. Two families against one

Codex and grok independently corrected the Fable sketch on the same two points.

**F-A. JavaScript should not be in the data plane at all.** The Fable sketch
retained the embedded engine without examining it. Codex places "an embedded
JavaScript engine in the authoritative request and transaction path" on its remove
list, holding that a Rust IR interpreter suffices and JS should cold-start only for
out-of-band effects. Grok: *"'pick the analyzable form and make it total' is the
wrong slogan, and LLP 0320 is the proof. The rebuild is not 'plan IR as compiler
output from JS.' The rebuild is 'JS is not in the data plane.'"*

If it holds, this is the largest single simplification available: it would remove
the Ibex/V8 runtime-conformance contract, the LLP 0048 conformance twin, the DK-4
warm-VM pool and its invocation-epoch guard, and a substantial share of the
LLP 0314 binary. It is **unevaluated against** the LLP 0009 §Decision DK-5 posture
(device parity with Exact, capability security, footprint, spinup) and against
actions, which are JS by construction. Recorded as an option, not a
recommendation.

**F-B. The dev loop is co-equal with the execution model, not downstream of it.**
Grok: *"a closed query language with a Metro race and an identity rebind still loses
Clique."* Codex, independently, is "less confident that [the language] alone would
achieve the desired benchmark without treating that lifecycle protocol as a co-equal
product," and calls for one generation protocol across schema, server, generated
client, bundler, and local cache. LLP 0310's finding — "the paved Expo loop is now
harder than the data model" — supports both.

### 3. Genuine disagreements

**D1 — surface syntax.** Fable: a TypeScript builder DSL. Codex: TypeScript notation
whose callbacks run at *build time* to construct an immutable typed AST, so row
values are expression objects and a callback cannot branch on a row with a JS `if`
or hide a loop in a helper. Grok: a literal `app.model.sql` file where rules are SQL
booleans and queries restricted `SELECT`s. Grok rates this its least confident call
and states plainly that it is guessing agents will write `exists (select 1 from
memberships …)` when the diagnostic contains that snippet. All three agree the
semantics matter and the spelling matters least.

**D2 — the offline revocation contract.** Codex: an encrypted per-principal store
with the key destroyed at sign-out, an authorization epoch and dependency recheck on
reconnect, and the honest named limit that a disconnected device cannot learn it was
revoked. Grok: deliberately drop offline authorization proofs and accept "cached,
possibly revoked," while stating it has not measured the user-visible cost of that
against the client-size cost of proving otherwise. Fable: acknowledged the problem
and claimed only that it becomes one uniform mechanism rather than a matrix — the
weakest of the three positions here.

Codex argues this is a **second, independent root cause** the diagnosis missed:
without a compact semantic contract for incomplete local knowledge, revocation,
provisional authority values, and settlement, *even a perfect single constructor
accumulates leases, custody modes, and exceptions* as engineers meet the information
limits one at a time. Its distinction — that an offline device cannot learn of
revocation is an *information* limit, not a *program* limit, and conflating the two
is how eligibility switches end up attached to query syntax — is accepted into
LLP 0329's open questions.

**D3 — composition, and whether LLP 0155 is right.** The most consequential split.
Fable: composable nested views with bounded traversal. Codex: a bounded relational
algebra with a small admitted aggregate set. Grok: refuse ad-hoc composition
entirely, named admitted queries only — attacking LLP 0155 directly:

> "'copy Zero's outcomes, not its architecture' is right as a slogan and easy to
> implement as Zero. Zero's local composable query engine *is* the architecture that
> forces client-side permissions and completeness."

Grok's claim is that Snapback grew a 212k-line client precisely by approximating
Zero, and that the correct move is Replicache's named-query half rather than Zero's
local relational replica — that DK-9's "result cache, never a replica" was the right
target reached the wrong way. Given LLP 0329 F3, this deserves a hearing before
LLP 0155 move 1 is treated as settled. It is also directly complicated by
[LLP 0329.004](./0329.004-composition-expressiveness-constraint.research.md), which
neither grok nor the other two had.

**D4 — declared reviewable authority.** Grok argues against retaining it in its
current form: row rules *are* the ceremony the diaries praise, `reads:`/`writes:`
are the symptom, and "keeping them because ceremony feels safe will re-grow the
matrix." This contradicts LLP 0329 F6's keep-list framing and is recorded as an
open disagreement rather than resolved here.

## Confidence

High that the seven unanimous items describe a coherent design. Medium that
convergence is evidence of correctness rather than of shared priors — see the
self-attested blindness caveat above. Low on every specific spelling. The two
two-against-one findings are **unevaluated options**, not recommendations: F-A in
particular has not been tested against DK-5's enduring posture or against actions.

## Open questions

Carried to LLP 0329's list, in the priority order LLP 0329.004 revises:

1. Can the restricted language be expressive enough to be the only language?
2. Is row-rule authorization affordable in the planner?
3. Named queries only, or bounded composition — is the client a cache or an engine?
4. Which offline revocation contract, stated once?
5. Does the authoritative path need JS at all, given DK-5 and actions?
