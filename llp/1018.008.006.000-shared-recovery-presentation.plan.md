## Outcome and scope

Remove outbox-policy reconstruction from the composers and work lists. The SDK
owns an explicit awaitable recovery action and a shared presentation of durable
work. Applications retain draft/editor behavior, markup, and product copy.
Improve default query/status language using existing facts, while keeping stale,
partial, predicted, and confirmed values distinguishable.

The [parent problem](./1018.008.006-client-owned-sync-experience.research.md)
defines success. Proposed implementer: Codex; planning date 2026-09-11. Implementation is
commissioned for 2026-09-11 after the panel revisions. Baseline:
`bf8450849` (original draft: `b47337b26`). Existing bounded automatic recovery remains the implementation
foundation, not work to rebuild. No retry schedule, outbox order, or grant
authority changes are proposed.

## Proposed SDK changes

### Explicit recovery on the existing owner

Add `client.outbox.recover()` and expose the same action through `useOutbox()`.
The action expresses an explicit request to reconnect and resume saved work;
invoking it may clear deliberate offline mode, just as explicit `online()`
does. Reading its state, mounting a hook, or displaying a button may not.

Compose the existing `online()` and `outbox.settled()` paths under captured
authentication, partition, writer-ownership, and explicit-offline lifecycle
identities. Capture monotonic auth/operation fences, not principal equality;
A→B→A is a departure. Distinguish a new explicit-offline cut from ordinary
recovery opportunities so a newer caller does not cancel an older caller just
by joining the same work. Reuse the resume/drain flights, but give every caller its own
bounded waiter. Do not cache an expired result or share a deadline between
callers that started at different times.

Proposed result:

```ts
type RecoveryResult =
  | { settlement: OutboxSettlement; refusal?: never }
  | { refusal: Refusal; settlement?: never };
```

A settlement reports actual `stopped` and `remaining` values. A paused result
is not a claim that all work completed or reached receiving views. A refusal
preserves structured details and has no invented remaining count. No outer
success boolean or new persistent progress state is needed.

Each invocation gets one 10,000ms waiter deadline covering startup, online,
and settlement. The existing resume deadline remains unchanged. Expiry ends
only this caller's wait; shared work and durable custody continue. Use existing
`E_TRANSPORT` / `transport`, site `client.outbox.recover`, with wording that
the wait expired and saved work remains. A later call may join active work
with its own fresh deadline. Unmounting one consumer cannot cancel another.

Invalidate the waiter promptly on a real account/session departure (including
A→B→A), writer takeover, close, or a new explicit offline cut. Use existing
`E_AUTH_SUPERSEDED` for departed identity and `E_OFFLINE_LIFECYCLE` for close
or a later offline cut. Reuse the native-compatible abort helper and existing
client lifecycle notifications. A gesture may clear the offline cut present
at invocation; it must not clear a newer cut, even if startup was pending.
Guard underlying transitions before they reconnect or begin settlement, not
just returned counts. Compatible schema refresh alone is not account departure.

A follower refreshes the existing inbox and returns `followerSettlement`'s
actual paused/terminal result; it does not acquire the writer lock or clear
the writer's offline state. Use the existing settlement members, including
`writer-unresponsive`; forwarding and inbox capacity remain readiness facts.
Count only the scope this follower can establish. Unadmitted aliases stay
outstanding. Authentication and resubmitting a refused write remain explicit
application actions; recovery never uses a plain auxiliary client.

### One presentation of durable work

Reuse `observeOutbox` slots for both headless and React/Expo consumers. Add a
derived work projection alongside raw `entries` containing the existing entry,
`intentLabel(entry)`, and `dismissible(entry)`. Move their combination to the
SDK's existing read-model layer; do not store a second ledger or change the
serialized entry format. Item actions and the device-work list call the same
eligibility predicate; dismissal itself rechecks durable eligibility.

Move hook-local readiness derivation onto the observed read model so a headless
consumer obtains the same `can` for the same op, connection, and ledger facts.
Preserve operation-specific capacity demand and inert snapshot reads. Add a
connection-change input to that owner only if the current subscription does not
already notify it; do not poll the ledger for presentation.

For `useMutation`, retain `last` as the result of the last call. Add a derived
`work` lookup for its durable intent, including follower aliases, when that work
is still present. It uses the same observed slots, not an entry scan in each
component. A compacted or missing lookup is `undefined`, never a guessed
commit or delivery. The template can use `work`/`can` for current progress and
`last` for an immediate rejection. The public names are `work` and `can`; a shared index resolves both durable IDs and inbox aliases.

No action label should imply server confirmation merely because an entry was
saved locally. Keep per-view item evidence responsible for pending-indicator
retirement. The existing common-item work in LLP 1018.003.001 §5 shares this
implementation; it is not another lane with a competing presentation helper.

### Default language

Simplify template copy over `Snapshot.reason`, `freshness`, `can`, and the work
projection. Use statements about messages, saved changes, available history,
and the next useful action. Retain an inspected-details path for codes/rewrites.
Do not introduce a new status state machine, hide all cached data, or treat
`ready` as synonymous with current server confirmation.

The existing generic reason ordering remains unless a concrete rendered case
proves a change necessary. Any change to summary semantics needs its own reviewed
truth table; wording changes alone do not justify changing that precedence.

## Verification and acceptance

Extend `client-recovery`, `readiness`, `outbox`, `client-sessions`,
`chat-screens-recovery`, `snapshot`, and typing checks. Reuse real browser
IndexedDB and Expo carrier witnesses for the paths that depend on them.

Required controls:

- Concurrent headless and two mounted recovery requests share actual work but
  retain independently timed waits. A later caller may outlive an earlier timeout.
  Pure reads add no I/O.
- Logout, account replacement, close, and an explicit offline cut during the
  wait cannot publish late success or counts from another partition.
- A wait timeout preserves admitted bytes and does not report durable progress
  that never happened; a later recovery can observe the actual result.
- Missing grant, expired fence, stopped replay while transport is connected,
  follower forwarding, unresponsive writer, and a non-retryable head refusal
  retain the existing action/eligibility distinctions.
- Device-list and bubble dismissal agree, including replay clearing eligibility
  durably before a request and the changed-outcome race after rendering.
- Cold stale zero followed by a current nonzero answer remains honestly labeled;
  missing authority stays partial. No false live claim is hidden by new copy.
- New text entered during a recovery or mutation stays intact; accepted,
  refused, and cancelled editor actions remain application-owned.

Close the [recovery/dismissal](../issues/closed/20260911-snapback2-starter-recovery-and-dismissal.md)
and [status-language](../issues/closed/20260911-snapback2-starter-status-language.md)
tickets only after their rendered acceptance. Coordinate the
[refused-edit ticket](../issues/closed/20260911-snapback2-starter-retain-refused-edit.md)
as a separate template change, not SDK draft policy.

Publish current usage in `guide offline`, `guide live-query`, and the package
README; record template experience in the diary. Count both composers, root
lists, shared helpers, and observers. Retain the existing byte allocations and
normal package growth guard; measure the integrated result rather than adding
individual gzip deltas. Use affected checks and existing longer witnesses;
this plan adds no gate or registry.

## Dependencies and limits

R1/R2 can proceed independently of the page plan. Serialize overlapping
`react-core.tsx` and template integration or explicitly reconcile their shared
surface before R3. Acquisition work should not suppress the outbox transitions
this read model consumes.

Original offline-flush and aggregate reports remain separate correctness
investigations in the [0.0.21 ticket](../issues/closed/20260910-snapback2-clique-0021-findings.md).
A prettier paused state does not close a stall. If the proposed helper leaves
the same application decisions or duplicates an existing owner, simplify the
proposal before landing; do not retain a public API solely to satisfy this plan.

## Implementation record (2026-09-11)

R1–R4 are implemented in the integrated four-plan change. `observeOutbox`
derives `work` and `can` from the existing immutable ledger input; one shared
index maps durable intents and admitted inbox aliases. `useMutation.work`
resolves through that owner, while `last` remains the immediate call result.
Compaction removes the lookup instead of fabricating terminal evidence.

`client.outbox.recover()` and `useOutbox().recover()` compose the existing
resume/drain owner with per-caller deadlines and guarded settlement reads.
Authentication, offline, close, and writer-ownership cuts retire old waiters.
Ownership is part of recovery identity only: same-account takeover preserves
the work observation identity. Native abort implementations without `reason`
retain the structured refusal in the waiter. A timeout does not stop durable
work or report invented progress. Followers refresh their actual inbox state
without changing the writer's deliberate offline mode.

Both composers consume this action and `post.work`; the work lists consume the
same `label` and `dismissible` projection. Product advice explains connection,
membership, saved changes, and stopped work. Structured diagnostics remain
behind Details. The generic refused label is “Not sent”; conflict wording and
per-view confirmation evidence retain their prior distinctions.

The whole physical chat TypeScript corpus, including shared helpers and the
witness, changes from 27 files / 1,718 lines to 28 files / 1,751 lines. This is
not a line-count reduction: pagination controls, shared advice and inspected
details add UI. The concrete policy removal is four `useSnapbackClient` hook
sites reduced to zero, two Composer `online()` calls removed, and the parallel
Composer ledger scans replaced by shared `work`. Two `outbox.settled()` calls
remain in the Expo witness, where they assert test outcomes. Diary 0118 records
this distinction; no new product benchmark score is claimed.

A fresh Astra implementation review found a concurrent explicit-recovery
caller could wait through the current resume and then start a second flight.
Taking operation authority without that wait lets `performResume` join the
existing flight; the public three-caller regression proves one held request.
Grok's follow-up accepts the recovery/observation identity split and withdraws
its initial `Promise.race` unhandled-rejection concern. Actual reviews are
[recorded separately](./reviews/1018.008-four-implementations.grok.md), with
[Astra's integrated review](./reviews/1018.008-four-implementations.astra.md).

Existing tests now cover independently timed waiters, A→B→A departure, ignored
transport aborts, close and later-offline cuts, shared real resume requests,
follower aliases, native abort behavior, inert reads, shared readiness/work,
last-result stability and same-account lock transfer. The lock-transfer fixture
uses `FakeIndexedDb` and `FakeLocks`; it does not establish physical browser
persistence qualification. Both rendered arms retain draft and refusal controls.
Final integrated suite and byte measurements are recorded with the program
outcome in the parent research document.
