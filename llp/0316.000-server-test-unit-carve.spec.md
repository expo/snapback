## Summary

Phase 7 begins with the `snapback-server` lib-test unit because it is the
remaining workspace-test critical path after LLP 0316 Phase 5 removed most
integration-test links. The work proceeds as measured, independently landable
carves:

1. split `src/server/tests.rs` into same-scope per-area source fragments while
   preserving every test's exact harness name and behavior;
2. only if the first carve moves the clock, continue with one semantic
   `server.rs` transport-owner seam at a time.

No carve lands unless both the server lib-test unit duration and the warm
edit-to-test-binary wall time improve. A negative experiment is recorded in
LLP 0316 and its code is discarded.

## Motivation and baseline

LLP 0316 measured the server lib-test unit at 73.1 seconds in the first
workspace-wide timing record. The controlled Phase 7 baseline was re-measured
on 2026-08-27 at `9505981ec`, on the author's Apple Silicon machine, in the
dedicated `velocity` worktree after `cargo clean` and the required
`scripts/bootstrap-ibex-runtime` runtime qualification:

| Probe | Server lib-test unit | Command wall | User CPU | System CPU |
| --- | ---: | ---: | ---: | ---: |
| Fresh test target: `cargo test -p snapback-server --lib --no-run --timings` | 52.82 s | 131.48 s | 506.84 s | 49.65 s |
| Warm `server.rs` invalidation, same command | 7.63 s | 20.35 s | 18.68 s | 12.46 s |

The fresh command includes construction of the test-profile dependency graph;
the unit duration is Cargo's timing for `snapback_server "lib" (test)`. The
warm probe is LLP 0316's edit-to-runnable-server-test-binary metric. Both are
reported because either can expose a regression the other hides.

## Governing boundaries

- `snapback-server` remains the rank-5 `transport-adapters` owner. No carve in
  this Spec changes the workspace dependency matrix or adds an upward edge
  (LLP 0276#crates--the-rust-workspace; LLP 0225#2-dependency-direction).
- A test-source split is cosmetic and must co-migrate every path-keyed proof,
  source reader, inventory, and `@ref` affected by the move
  (LLP 0225#6-semantic-extraction-versus-cosmetic-splitting).
- The historical `module-ownership` gate was retired at LLP 0276 Phase 3. Its
  live fail-closed successor is `workspace-graph`; every carve runs that gate
  and the path/source inventories before landing.
- The public `/health` build identity remains independently stamped and may
  never claim commit/dirty facts not true of the built inputs
  (LLP 0031#server-binary-identity-on-health).
- No step touches `snapback-engine` or `snapback-kernel` source. Integration
  follows LLP 0232's optimistic-landing default and LLP 0189's affected-proof
  cadence.

## Stage A — same-scope test-source split

### Source form

`src/server/tests.rs` remains the `server::tests` module and retains shared
imports and genuinely cross-area helpers. Contiguous test families move under
`src/server/tests/` and are assembled with same-scope `include!` declarations.
They do not become nested `mod area` modules: nested modules would change every
harness name from `server::tests::<name>` to
`server::tests::<area>::<name>`, making the required before/after failing-name
comparison impossible and breaking callers that select an exact test name.

Fragments follow the production transport seams already present under
`src/server/`: core routing/health, connection and live delivery, auth and
provider routes, effects/action streams, OAuth/remote MCP, assets/media, and
operator/admin operations. A fragment owns complete items only; no function,
type, macro invocation, or `@ref` is split across files. Shared helpers stay in
the parent until one fragment is their sole consumer.

This stage changes neither visibility nor semantics. It does not perform a
repo-wide format pass.

### Stage A acceptance and stop rule

From a fresh target prepared by the same bootstrap sequence used for the
baseline:

1. `cargo test -p snapback-server --lib --no-run --timings` succeeds and its
   `snapback_server "lib" (test)` duration is lower than 52.82 seconds.
2. After a one-line-equivalent invalidation of `server.rs`, the same command
   produces a runnable test binary in less than 20.35 seconds and its unit
   duration is lower than 7.63 seconds.
3. The complete `cargo test -p snapback-server --lib --no-fail-fast` `FAILED`
   name set is byte-identical to the pre-change set. Counts alone are not
   evidence. All passing test names are also compared to prove the same-scope
   assembly kept identity.
4. Test count and test executable size do not regress.

Because run-to-run noise exists, a sub-1% apparent movement is treated as no
movement unless a second paired run reproduces it. If either required metric
does not improve, Stage A closes negative: LLP 0316 records the measured row,
the source split is discarded, and no Stage A code lands.

## Stage B — one `server.rs` owner seam per landing

Stage B starts only after Stage A's result is known. Each carve moves one
cohesive transport-owned implementation family from `server.rs` into its
existing or new `server/` module and moves the matching same-scope test
fragment with it where doing so preserves crate-private access. Candidate
order is chosen from the timing and dependency evidence, not line count:

1. connection/live delivery and its wire/admission state;
2. effect/action-stream orchestration;
3. route assembly and public health/inspection projections;
4. remaining operator or asset/media route families not already owned by an
   extracted module.

For each candidate, the implementation first records its item/dependency
closure and the affected `@ref`s. It may move only transport composition and
wire behavior; durable policy and commit authority stay in their lower owners.
Any proposed workspace edge widening stops the carve. Any same-crate
dependency-direction concern is fixed, not baselined; the retired module gate
cannot supply a waiver mechanism.

Each carve repeats Stage A's two timing probes and failing-name comparison and
gets its own LLP 0316 measurement row and landing. A carve whose improvement is
inside noise is reverted and recorded as negative. `engine.rs` and
`storage.rs` are outside this Spec.

## Verification and generated records

Every landing runs, at minimum:

- `cargo test -p snapback-server --lib --no-run --timings` under the paired
  fresh/warm measurement protocol;
- `cargo test -p snapback-server --lib --no-fail-fast`, with full failing-name
  set comparison against the exact merge base;
- `node scripts/check-workspace-graph.mjs`;
- `./ref-check --verbose`;
- `node scripts/check-local-proof-gates.mjs`;
- `node scripts/check-inventories.mjs`, inspecting its output for `FAIL` even
  when the process exits zero;
- `node scripts/check-guide.mjs`, accepting only the separately ticketed
  generated-API cold-signatures red;
- `git diff --check`.

Moving Rust shifts diagnostic emitting-site line numbers. The diagnostics
registry and chained Guide projections are regenerated in the same landing;
generated changes unrelated to the moved sites are not absorbed.

## Open questions

1. Does same-scope source partitioning reduce rustc's incremental dependency
   work enough to move the warm metric, or is the expanded lib-test unit
   effectively identical? Stage A answers by measurement and has no assumed
   positive outcome.
2. Which Stage B family has the smallest lower-owner import closure while
   removing the most code from the `server.rs` recompilation unit? The first
   Stage A timing record and rustc unit data choose it.
