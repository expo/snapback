## 2. Governing context and chosen shape

- [LLP 1012 §4](./1012-local-first-v1.spec.md#4-the-range-store): one serialized
  atomic carrier transaction, post-durability publication, partition/seal/wipe.
- [LLP 1012 §8](./1012-local-first-v1.spec.md#8-the-delivery-envelope-the-validator-and-resume):
  each envelope keeps its actual sequence, principal/auth epoch, program,
  receipt, validator and cursor; accepted intervening revocations cannot vanish.
- [LLP 1012 §7](./1012-local-first-v1.spec.md#7-writes-offline) and
  [LLP 1019 §6](./1019-derived-delivery-custody.rfc.md#6-receipts-with-receipts):
  exact durable acknowledgement obligations, grant/intent/FIFO custody,
  current membership, per-intent replay terminals and actual effects.
- [LLP 1018.004](./1018.004-truthful-and-composed-writes.decision.md): older
  durable follower requests cannot be overtaken; item observation and compacted
  aliases remain coherent.

Current API facts are the packaged `guide offline` and `guide deliver` cards.
`drain: true` admits a certified ascending cursor-paged query with pages of at most
50 rows. `OfflineRuntime.commitMany` already persists several independently
prepared deliveries in one transaction and publishes one semantic change.

Choose **bounded finite transport batches of existing envelopes**, using the
existing query and mutation HTTP routes. This obtains the bulk path without
adding a streaming framework. The live SSE channel is a latest-value,
single-slot replacement queue; it cannot carry lossless acquisition history.
Do not repurpose it. Each ordinary certified query remains bounded at 50 rows;
transport, persistence and observer boundaries can contain several executions.
The shape certificate alone does not prove arbitrary tables append-only; this
fixture's generated delivery log represents edits/removals as appended events.

## 3. Bounded query batches

Add an internal drain-batch request form to `POST /api/query?receipt=1`, used
by the first-party online drain. Ordinary public queries retain their single
envelope. Admit the operation through the same certified-log shape check used
by resume; do not offer arbitrary query batching as a new authoring surface.

Initial engineering limits: at most 16 pages, a 1 MiB full serialized-response
budget, and a 20 ms owner-work target checked between complete executions.
The latter is a fairness target, not a hard interrupt deadline for one certified
operation. Preserve that operation's existing resource limits. A legal first
page exceeding the aggregate target is returned alone within its existing
single-page ceiling (currently 5 MiB plus 4,096 bytes at the client envelope
decoder); never drop it or return a non-advancing empty batch.
Accumulate per-envelope encoded lengths once, including framing overhead.

Return ordered frames with the exact query arguments and unchanged ordinary
delivery envelope for each execution. Preserve every actual `seq`, read time,
cursor, validator, row pool and receipt. No synthetic maximum-sequence envelope
or aggregate range proof is created. Continue only through an advancing cursor
from a supported result; terminal, denied, partial or repeated-cursor behavior
must be explicit. A page/byte/time stop is transport continuation, never a
false `caughtUp` result.

One owner action executes a bounded batch without yielding inside it, and never
waits for network backpressure. Authentication/current generation are checked
before that action; no other owner mutation can interleave its page executions.
Subsequent requests go through the normal owner queue so writes, timers and
revocation can run. Reauthenticate and check current operation and generation
on every request. No long-lived SQLite snapshot is introduced. Fairness tests
queue foreground/timer/revocation work behind the batch and verify it runs at
the next ordinary owner boundary. If an implementation later introduces an
internal yield, that boundary must repeat the live checks before any next page.

The next batch is requested only after accepting the current one. No prefetch
is included in this implementation.

## 4. One local delivery transaction per chunk

A **transport batch** is one HTTP result. A **commit group** is the ordered
subset passed to one `commitMany` and persisted in one carrier transaction.
Decode the full transport batch structurally before any commit group. Prefer
one group per batch, after measuring changed-key accounting at 1/4/8/16 pages.
Cross-frame coverage, authority and contradiction checks remain inside each
existing atomic commit; full structural preflight is not their replacement.

The store journal retains at most 32 revisions / 256 KiB changed-key bytes.
Choose a group bound that avoids routinely evicting its own delta. If a wire
batch must split, each group is independently atomic: a later contradiction,
carrier failure or logout can leave earlier groups durable. Only that durable
prefix may publish, earn acknowledgements or supply resume progress. Never
imply that multiple carrier transactions roll back together. A legal page
larger than journal history commits alone and takes the existing cold-rebuild
fallback; shrinking must never wedge progress. Do not raise the journal budget.

Use the existing journal and changed-record carrier projection. Do not install
a whole database image or hold an IndexedDB transaction across a network wait.
Publish each accepted page event with its own item evidence only after
durability, sharing a single captured outbox snapshot per transport response.
Coalesce store/twin input notifications at the commit group, while every frame
participates in coverage, revocation, receipt earning and prediction contradiction.
A public callback may close or reset its subscription: recheck the lifecycle
fence between page callbacks as well as between requests. A negative between positives cannot disappear.
An owner refusal after a valid advancing prefix does not hide that prefix: publish
it and request its next cursor, where a still-current refusal surfaces. A refusal
paired with a terminal/non-advancing last page is malformed and rejects before
any persistence; an empty refused prefix throws immediately.
Repeat live lifecycle/coverage fences at every group commit.

Restart an interrupted acquisition conservatively from the existing drain's
proven position; a physical reopen may replay the prefix. Already durable rows
and exact acknowledgement bindings make that idempotent. Unfinished progress
never retires overlays or certifies exhaustion; only actual exhaustion advances
the ordinary caught-up watermark. A last frame's validator belongs to that
frame's arguments, never its next cursor. Authority replacement uses existing
coverage fences. **No new checkpoint metadata or page-chain selector ships.**

Implementation decision, 2026-09-11: a safe generated-log-only page-chain selector
was prototyped and its lineage/eviction/lifecycle controls passed. The complete
prototype measured 90,568 gzip bytes, 568 above the existing 90,000 ceiling.
Remove this optional restart optimization to fund the acquisition path, retaining
its source/tests under the ignored run for possible later work. It does not
speed first acquisition and is not required for durable correctness. Do not
weaken its checks or raise the budget to keep it. The final retained runtime
measurement remains required; this first prototype number is not qualification.

## 5. Batch acknowledgement admission and replay

Keep the existing durable event marks and ordinary generated acknowledgement
intents of at most 50 explicit event identities. A cursor or commit sequence
cannot prove that every corresponding body was disclosed and accepted. Do not
introduce `ack through cursor/seq`, skip current membership checks, or mark
receipt rows true merely because the server sent a page.

Admit up to 16 pending acknowledgement operations within one serialized store
turn and one carrier transaction. Reuse the existing target, grant, ID-range,
allocation-order and immutable envelope rules for each entry. Preserve exact
event bindings. Insufficient capacity leaves the unadmitted suffix pending;
persistence failure consumes no grant or index state. Do not reserve IDs in
an observable state outside the transaction. Older follower inbox writes and
already-admitted foreground intents retain their order. Under the existing
ledger lock, read bounds/program/grant once, capture lifecycle generation,
prepare each ordinary entry with consecutive allocation offsets, and persist
one final grant/accounting update with all entries. Recheck lifecycle before
commit; no lock is held across network I/O. Bound admission groups by actual
changed-key budget as well as count, with the same single-entry progress rule.
A product write queued during persistence/admission is a barrier to later acks.
When there are no pending acknowledgements, return before reading the follower
inbox: an extra carrier read between commit and frame publication can expose a
duplicate intermediate query snapshot. Check follower ordering before every
actual acknowledgement admission.

Add a bounded acknowledgement replay-batch form on `POST /api/mutation`.
Select only a contiguous replayable FIFO prefix of at most 16 eligible
generated acknowledgement entries; stop before an ordinary product mutation
or blocked head. Do not collect later acknowledgements around it. Recheck replay
cancellation after asynchronous trust reads and before durably clearing saved
refusal evidence; cancelling before that boundary must leave dismissal available. Preserve
each exact envelope and its own intent identity. A partial response or lost
response retries those same bytes through the existing owner ledger. Bound the
encoded request prefix below the existing 1 MiB HTTP body guard, including
framing. An individually legal ordinary request uses the single-entry path if
batch framing would exceed the guard; an already-illegal request keeps its
ordinary refusal. Unify single/many preparation rather than adding a second
replay state machine.

The owner calls ordinary replay in order, with its existing per-intent SQLite
transaction, terminal, grant accounting, real effects and `after_commit`.
There is no giant all-or-nothing server write. Return an ordered result prefix
and an explicit stopping failure where applicable. Input/schema/session/transport
failures preserve existing stop semantics; terminal rejection/conflict can
settle and continue as ordinary replay does. Generation and live authority
checks occur at the same owner boundaries as the query batch. Replay also stops
between complete intents at a 20 ms work target or 1 MiB encoded-result target.
Return an explicit continuation on a limit, distinct from execution refusal.
An executed final terminal may cross the response target; return that complete
terminal and stop, rather than omit a durable result. One terminal is therefore
the bounded overshoot, retaining ordinary operation resource limits. Response
bytes are counted incrementally, never by reserializing the growing array.

Generated-operation eligibility uses the exact engine-generated IR, not a name
prefix. Existing identical stored-terminal replay must precede current-program
eligibility, including after a successor removes receipt operations. An unknown
unsettled operation retains ordinary refusal and queued custody.

Persist the returned terminal prefix together where existing settlement rules
permit. Capture coverage revision before replay and require it to remain current
through tail acceptance and the atomic settlement. For committed entries that
need the ordinary tail, issue the existing `logTail` chooser after the prefix;
check the same principal/generation and that a returned tail's sequence reaches
the maximum committed sequence. A missing tail is permitted only in the existing
no-drained-log case. A stale tail cannot settle the affected prefix. Preserve
strict empty-actual-effects no-tail eligibility, checked for every entry in the
atomic swap; mixed prefixes use the ordinary tail path. Reject/missing/changed
identity uses the existing conservative per-entry rules.

**Settlement is not effect observation.** The ordinary chooser may return an
application log without receipt rows, or no log at all. Such a terminal may be
durably committed under existing settlement semantics while its actual effects
remain unresolved in retained history. Do not add receipt markers, treat a high
sequence as observation, compact it prematurely, or strand its queued intent
until unrelated effects arrive. Per-effect compaction still requires actual
positive/negative row evidence under LLP 1018.003.001. Record unresolved effect
count, retained terminal bytes and compaction work separately from queued ack
obligations. Notify callers only after terminal durability. A failed group keeps
its queued bytes for identical replay; it does not publish terminals.

## 6. Reduce the remaining preparation and publication work

First measure production React on the frozen baseline. Both final variants use
the same production bundling and app source; changing build mode alone cannot
be credited to the new acquisition implementation. Keep a development control
so the prior 32.554-second record remains interpretable.

Implement and measure three bounded CPU repairs alongside lifecycle batching:

1. **Prepare once under owned immutable custody.** Wire intake still validates
   every field, reference, authority and byte bound. A private nominal owned
   envelope/row image can reuse that validation and prepared keys internally;
   outward DTOs remain detached and mutable. Public `decode`/`expand`/receipt
   helpers must still reject mutated or malformed caller input. In fact
   preparation, compute canonical body comparisons only when a cache collision
   actually needs them; identical nominal immutable row images need no second
   canonicalization. Distinct bodies with the same row/seq must still compare
   exactly and refuse contradictions. Retain identity/digest validation.
2. **Build integrity indexes only when used.** Inspect the integrity-only
   `FactIndex` and its `HeldIndex` construction. Where the current code eagerly
   inserts every incoming and held fact into every schema index although only
   particular extents are examined, defer the unused derived trees until their
   first read, then keep them current under the same row updates/removals.
   This changes private in-memory construction, not the durable index schema
   or evidence rules. The exact same queried index must equal cold eager
   reconstruction, including updates before first use, rollback and removals.
   Preserve the shared positive/live physical map: first materialization includes
   both owners with their existing sequence namespaces and posting prefixes.
   Build privately before installing a tree; keep malformed cold key/descriptor
   rejection independent of lazy physical construction. Required public
   thread/search construction still finishes inside timing.
3. **Use existing proof ownership for success compaction.** Replace per-effect
   scans of all held answers with the existing index of candidate proof owners,
   using prior owners plus this swap's changed answers because the reference index
   advances after durability. Every candidate still passes the
   same `rowObservation` and negative-evidence rules; missing/stale derived
   indexing takes an exact conservative fallback. Keep unresolved effects in
   custody. This must agree with the exhaustive algorithm across row replacement,
   answer deletion, revocation, program change and cold reopen.

   Amendment, 2026-09-12: the carrier also indexes each retained committed
   intent by its remaining effect addresses. Warm transactions check changed
   outbox entries and intents reached by changed rows, row sequences, explicit
   negatives, or the row proofs of changed answers. Range evidence contributes
   through those resulting observations; range disappearance alone discharges
   nothing. A cold index, identity/supersession change, or wholesale replacement
   of an observation or custody container uses the exhaustive pass. The index
   advances only after persistence, retains no additional row bodies, and removes
   addresses as effects discharge. Reopen rebuilds it; rollback leaves its prior
   durable revision intact. Selection only narrows work: the same exact image,
   answer, negative, and program checks still decide every discharge. Differential
   mixed-revision tests compare all resulting custody with exhaustive compaction;
   carrier tests cover failed writes, first cold reads, and physical reopen.

### Profile-driven amendment — 2026-09-11

The first release-owner/production-client candidate passes exact content,
acknowledgement and physical-reopen checks but takes about 31 seconds. A G4
profile has 21.562 seconds renderer thread time despite reducing writes from
613 to 246. Its sampled `readOutbox` work is 2.849 seconds, extent bucket-key
construction 1.254 seconds inclusive, and UTF-8 generation 0.505 seconds self.
These overlap their parent costs. Both native owners are optimized release
builds; this is not a debug-owner comparison. Keep the following further
reductions subject to final measurement and independent code review:

- Outbox readiness shares one small FIFO `queuedInfo` projection containing
  identity, grant/trust timestamps and refusal metadata, rather than copying
  argument bodies for count, fence and blocked-head reads. Read pending marks
  before the queued projection so their atomic admission cannot disappear
  between reads; conservative double-counting is permitted. Fence checks reuse
  one grant-list read but retain every original per-intent trust predicate.
  Generic carriers keep their queued-list fallback. Detached full outbox reads still copy, but skip recursive proxy
  removal because this read boundary already selects committed unproxied state.
- Extent matching keeps a refcounted directory of active table/index/prefix
  widths. It forms bucket keys only where an extent exists, then applies the
  unchanged exact interval/token/containment predicate. Final owners reclaim
  empty directory entries; an exhaustive oracle checks derived results.
- The shared UTF-8 encoder feeds SHA-256 through a callback instead of
  allocating generator results per byte. Hashing remains streaming and uses
  identical bytes; the bounded cursor collects the same payload. Native
  SHA-256 vectors, padding boundaries and Unicode cases check equivalence.
- The existing nominal prepared-schema owner may retain the exact range-schema
  hash, computed with the existing `canonicalJson` encoding. Mutable or merely
  caller-frozen schemas still recompute; a schema/rule digest using another
  encoding is never substituted. Only the hash is cached, without a body mirror.
- Carrier metadata deltas already own their JSON-normalized values. Adopt those
  values directly instead of serializing them a second time. Likewise, new
  normalized swaps may install their private rows, overlays, arguments and data
  without another copy; public inputs/outputs still detach, nominal row images
  remain immutable, and journal copy-on-write still protects rollback.
- Amendment, 2026-09-12: the shared value comparator checks both external
  tags before skipping type-rank allocation and scans for equal kinds. Payload
  comparison, malformed-value checks, and differing/unknown-kind behavior stay
  unchanged. This removes repeated work during first index construction; it
  neither defers indexes past the timed first queries nor changes their keys.
- Experiment, 2026-09-12 (deferred in the combined LLP 1023 release): final
  inferred-hole enrollment forces only key/digest pairs not retained by its
  immediately preceding proof check. No extent changes between
  those passes; earlier, timed and inter-frame checks still run in full. The
  second pass preserves its original order for previously unindexed keys.
- Ordinary native indexes whose old/new typed key tuples are equal remain
  installed through a row update. Changed indexes retain ordinary replacement;
  derived-key changes use the existing derivation path. Row updates, constraints,
  authorization, trace, maintains, effects and terminal durability remain intact.

The 2026-09-12 continuation also reuses each already-fetched update/upsert
preimage and SQLite's bounded prepared-statement cache for ordinary point and
range reads. Duplicate uniqueness declarations reuse one successful probe only
within the same read-only constraint invocation, preserving every trace entry;
the next write checks again. Query item publication freezes the carrier's owned
copy-on-write outbox record once and shares that immutable version. Public
ledger reads still detach, older queries keep their original work state, and
custom carriers retain their ordinary read path. These remove repeated work;
they do not establish the acquisition target without a matched measurement.

Native stage attribution places 4.264 seconds inside 201 ordinary replay
terminals: statements 3.086, effects finalization 0.326, SQLite commit 0.606,
terminal recording 0.057 and preamble 0.012 seconds. `after_commit` is only
0.054 seconds; live invalidation/rerun is 0.006. These are elapsed, nested
scopes, not disjoint CPU or fsync measurements. Mutation execution, not an
invalidation redesign, is the justified native investigation.

The benchmark's repeated IndexedDB full-outbox reads became measurable work:
69 polls occupied 6.109 seconds of transaction lifetime in G4. That lifetime
is not additive CPU cost. Replace polling with the public drain exhaustion and
`outbox.settled()` endpoints, require `stopped: false` and `remaining: 0`, then
run the first offline queries before stopping timing. After timing, perform one
full physical read to verify exact content and every acknowledgement binding;
a mismatch invalidates the sample. Retain a same-source old/new-harness control
and use the same frozen harness for both final variants. This removes observer
work without omitting acquisition custody. Earlier samples remain diagnostics.

The source-level audit records precise ownership seams before implementation.
These are correctness-preserving reductions in duplicate work, not promised
millisecond savings. Profile the first integrated candidate and keep changes
only with attributed value and complete equivalence controls. Do not mandate a
bulk sorted AVL merge from overlapping inclusive samples: it may be considered
only after an explicit plan amendment describes its semantics and tradeoffs.

No speculative cache, second durable index schema, or required search work
moved after completion. Maintain responsive publication between bounded groups;
no whole-acquisition React suppression, blocked foreground sends or unbounded
worker queue. Unify single/many paths and delete redundant preparation to fund
all runtime code under the existing byte ceiling. If a source seam cannot prove
its invariant, omit that optimization and continue measuring the residual;
do not substitute a caller-supplied trust marker or false performance claim.

### Foreground admission amendment — 2026-09-11

The immediate first-group control exposes a pre-custody failure in V4 and V5:
a public mutation called from the first durable delivery callback waits for
recovery and returns `E_TRANSPORT` after ten seconds without admitting an
intent. The baseline control commits in under one second. The callback returns
immediately; it does not await the mutation or hold a carrier transaction.

Explicit admission currently joins a resume promise that includes whole-queue
replay after grant adoption. Faster acquisition can keep adding acknowledgement
intents to that queue. Separate the foreground wait for usable, durably adopted
capacity from that moving replay completion, using the existing recovery owner.
Cover both a demand-started flight and a foreground demand joining an already
running general recovery. Preserve current authority, program, lifecycle and
grant checks, older durable follower commands and FIFO replay. A status read
remains advisory; actual admission must still reserve capacity atomically.
General recovery retains its truthful completion and failure verdict, and no
request is sent before the foreground intent is durable.

Do not extend the timeout, bypass capacity, swallow a recovery error before
safe admission, or claim that the original slower foreground probe covered this
earlier boundary. Add a deterministic public-admission regression that holds
older replay while capacity becomes usable, then verifies admission and exact
ordered settlement. Repeat the immediate-trigger control on the repaired final
source, retain both failures, and fund any runtime growth under 90,000 bytes.
