## Summary

The supervised dev path (`snapback dev --expo`) should retire — not by
amputation, but by **capability extraction**: each of the four things it
still uniquely provides moves to a home that does not require owning the
client's bundler, and only then do deprecation and tombstone gates fire.
Until the last extraction ships, the supervised path stays supported and
maintained; the standing rule from LLP 0300 OQ5 — no new supervised-only
capability without per-capability justification — hardens into a gate.

## Diagnosis

The supervisor exists because the pre-LLP-0300 design required a trusted
**issuer**: clients refused raw URLs and accepted only bindings a live
supervisor attested over IPC. A resident issuer accretes jobs — it must
spawn Metro to know its port, proxy Metro to stabilize the origin, run a
bootstrap listener to deliver the binding, enumerate listeners to vouch for
them, mint an ambient session to be zero-config, and own leases/reapers to
clean all of that up. LLP 0300 removed the reason (the canonical path is a
URL with a standing discovery gate) but kept the residue.

The residue has a measurable cost, in three parts:

1. **A self-inflicted bug class.** Every recorded defect in this family
   exists only because the supervisor owns processes it did not need to
   own: the Metro IPv6-loopback wedge, CI watch-inertness, HMR storms
   through the proxy, listener-enumeration refusals, process-kill
   witnesses, the restart-verb binding drift (open ticket), and the
   one-mint-shared-by-every-tab defect. None of these *can* occur on the
   URL path — its bug surface is a GET and a comparison.
2. **The dual-path tax.** Every client-adjacent feature, template, guide
   page, and acceptance battery must consider two lifecycles. The 2026-08
   supervised hardening series (eight landings in two days) is evidence of
   live weight — and of ongoing spend.
3. **Vocabulary drag.** Agents that touch the supervised path must learn
   binding/rendezvous/attestation concepts the canonical path made
   unnecessary — the exact steering cost LLP 0259 and the 0300 program
   measured.

What the supervisor still uniquely provides — the reasons it is *right*
that it exists today:

- **A. Physical-Android development.** Verified `adb reverse` rules let a
  device address `127.0.0.1` while the backend stays loopback-bound. The
  URL path has no device story (LLP 0300's scope ruling).
- **B. Attested backend identity on shared hosts.** Supervised issuance
  proves the binding names the exact spawned backend. The URL path's
  trust boundary assumes a single-user host; shared/multi-user hosts are
  directed to the supervised path until signed discovery exists.
- **C. Live binding rotation across hot regenerations.** The supervisor
  re-mints the client's binding mid-session when the backend hot-loads a
  new generation; the URL path only fail-closes at the next episode.
- **D. Whole-stack loopback proof.** Pre-readiness `lsof` verification
  that every listener (Metro included) is loopback-bound and correctly
  owned. The URL path vouches only for Snapback's own listener.

The Plan's thesis: A–D are real, and none of them requires a
bundler-owning lifecycle. Each has a smaller, better home.

## Non-goals

- No supervised code is removed, weakened, or de-documented before its
  replacement ships and its gate (below) passes.
- Production/release binding admission is untouched (LLP 0300 P5).
- This Plan does not relitigate LLP 0300's decisions; it executes the
  direction OQ5 anticipated.

## The migration

### Phase R — replacement workstreams (independent; any order)

- **R1 — Device forwarding verb** (replaces A). A thin CLI surface —
  `snapback forward android [--serial <s>]` or `snapback dev
  --android-device` — that installs and verifies the `adb reverse` rule
  for the **backend** port only, reusing the existing selection/verify/
  remove machinery; Expo's own CLI already forwards Metro's port for
  itself. Acceptance: a physical-Android lane completes on the URL path
  (env var = `http://127.0.0.1:<port>` on-device) with no `--expo`.
- **R2 — Signed discovery** (replaces B). The already-ticketed future
  Spec (`issues/shelved/20260824-signed-discovery-future-spec.md`): store-held
  key signs the identity fact; fingerprint delivered out-of-band; a
  configured client refuses unsigned facts. Acceptance: a shared-host
  lane runs URL-first with server authenticity ≥ supervised issuance.
  Open problems (key carriage, replay/freshness, rotation) are that
  Spec's to solve — this Plan only sequences it.
- **R3 — Generation-change signal** (replaces C). The standing stream the
  client already holds (LLP 0302 §3) carries a "deployment generation
  changed" notice; receipt opens a new discovery episode immediately, so
  a hot regeneration re-verifies and re-binds without waiting for a
  failure. Degenerate stream-less clients already re-verify per
  operation. Acceptance: schema edit → hot reload → client continues
  against the new generation with no restart and no failed user action.
- **R4 — Listener audit verb** (replaces D). `snapback doctor
  --listeners`: on-demand `lsof` audit of the developer's whole dev
  stack — backend, any bundler, anything on the app's ports — reporting
  non-loopback binds. A diagnostic anyone can run in any mode, rather
  than a proof only one lifecycle can make. Acceptance: a
  wildcard-bound Metro is detected from a two-process setup.

### Phase D — deprecation (gated on all of R1–R4 landed)

- D1: an author ruling (amendment to LLP 0300 + this Plan's status
  advance) declares the supervised path deprecated: guides move it from
  "convenience appendix" to "deprecated, removal planned"; templates drop
  `dev:supervised`; `snapback dev --expo` prints a dated deprecation
  advisory naming the replacements.
- D2: supervised-only tickets (e.g. the restart-verb reconciliation)
  are re-triaged: fix only what keeps existing users unbroken during the
  window; close the rest as overtaken *at tombstone time, not before*.
- Per LLP 0041's posture (users are agents reading current docs; nothing
  depends on stability), the deprecation window is short — measured in
  publication cycles, not quarters.

### Phase T — tombstone (gated)

Remove the supervisor (expo-dev.mjs lifecycle, bootstrap exchange, Metro
front/attestation, lease/reaper machinery, `--expo` and its flags),
tombstone the superseded sections of LLP 0181/0223 per the corpus
convention, and retire the supervised batteries. LLP 0299's multi-owner
port-plan surfaces (`--client-port`, `--bootstrap-port`, the `client`/
`bootstrap`/`metro` owners) retire with it; the backend plan remains.

**Tombstone gates (all must hold):**

1. A full benchmark matrix — Android physical device included — completes
   every cell with zero `--expo` invocations.
2. Two consecutive publication cycles with no supervised-path fix
   landings demanded by users or batteries.
3. R2 (signed discovery) published, so the shared-host direction in
   LLP 0300's trust boundary has a live successor.

## Interim policy (in force from acceptance of this Plan)

- The LLP 0300 OQ5 line becomes a review gate: a change adding
  supervised-only capability MUST carry a written justification that it
  structurally cannot exist on the URL path.
- The supervised path stays green: its batteries remain in the canonical
  proof, and open defects in it (restart-verb drift) remain legitimate
  fix-forward work until D2 re-triages them.

## Risks

- **R1 under-delivers for devices** (adb quirks per transport). Mitigant:
  the machinery being wrapped is the already-proven supervised code path,
  re-fronted; the USB/TCP-IP selection logic moves, not changes.
- **R2 stalls** (it is the only Spec-sized item). Mitigant: phases are
  independent — D can be split to deprecate web/simulator/emulator use
  (A, C, D replaced) while shared-host guidance keeps the supervised path
  alive solely for B until R2 lands. That split is an author decision at
  D-time, not a new design.
- **Hidden dependents**: other subsystems (native checkout, dev-identity
  sidecar delivery) ride the supervisor today. Phase D's ruling must
  inventory them; any that survive retirement need their own R-item.
  Listing them is the first D1 task, deliberately not guessed at here.

## Open questions

- OQ2: At D-time, split deprecation (web/sim/emulator first, shared-host

- OQ3: Should R3's signal ride the existing live-query stream protocol or
