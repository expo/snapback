**Type:** RFC
**Status:** Draft
**Systems:** Snapback 2 Quarry compiler, diagnostics, public API inference, certification
**Author:** Codex, commissioned by Charlie Cheever
**Implementer:** Codex owns this draft and reconciliation; implementation remains with the existing architecture compiler lane pending its own review
**Date:** 2026-09-07

**Related:** LLP 1018, LLP 1000, LLP 1001, LLP 1002, LLP 1004, LLP 1011

## 1. Proposal and current work

Make one checked Quarry representation the source of executable data IR,
inferred public API types, and source diagnostics. Preserve Rust's independent
certification of executable IR. The benefit must be fewer independently
maintained interpretations of Quarry and fewer authored programs whose meaning
changes between those interpretations.

This is a focused contract for reconciling existing work, not a commission for
a competing compiler. The architecture lane already contains direct typed
lowering and removal of the generated-TypeScript data route. Its snapshot is
`2cae5d9a2` on `llp-ship/20260907-1018-architecture/integration`, including
`llp/1018.000-composable-architecture-next-moves.research.md`. That document is
available in that branch; it was not on this draft's base `0c1a538ae`. Its
implementation and qualification are separate from acceptance of this RFC.
This RFC is a finite reconciliation memo, not a second acceptance gate for that
lane. Reuse its evidence, record residual differences, then fold settled
constraints into LLP 1002/1004 and remove this document's current link when its
findings are resolved or have an active owner. Do not maintain two compiler plans.

The existing candidate's `bound-model.ts`, `bound.ts`, `bound-project.ts`,
`bound-api.ts`, and `bound-source.ts` are the starting point. First map their
responsibilities to §3, retain working decisions, and record only concrete gaps.
Do not introduce another AST, checker, or emitter merely to match this document's
terminology. A completed candidate can satisfy this proposal without new code.

LLP 1018 §5 cut typed IR from the original hygiene repair. That historical scope
decision remains accurate. This draft considers the subsequent implementation
and its deletion evidence; it does not retroactively expand that repair.

## 2. Scope and constraints

Quarry remains the single data-authoring language. The current paved form is
`snapback/schema.q` plus namespaced `.q` operations and shapes, as documented in
`snapback2/packages/snapback2/guide/quarry.md`. TypeScript remains appropriate for
effect bodies, seeds, and journeys. Removing data compilation through TypeScript
does not remove the effect checker or permit JavaScript in the data plane.

No new executable IR, runtime compiler, public authoring profile, gate, registry,
or committed generated artifact is proposed. Helper syntax and other language
extensions have their own decisions; this RFC neither commissions nor reverses
the helper work in the architecture lane. The landed resource budgets apply;
this draft grants no increase and makes no publication or cold-builder claim.

## 3. Checked representation contract

| Concern | Single owner and required information |
|---|---|
| Names | Bound declaration identity, lexical scope, table/index identity, and source location; emitted spellings cannot resolve a name differently. |
| Values | Nominal types, optionality/presence, record and list structure, numeric brands, and bounds sufficient for checking and API inference. |
| Control flow | Explicit branch joins and bounded iteration; a fact available on one branch cannot escape as unconditional knowledge. |
| Reads | Read origin, table/index/key, ordering, range/page provenance, and cardinality facts; these are distinct from a value's surface type. |
| Effects | Data read/write and effect boundaries, with the source evaluation order retained. |
| Outputs | Normalized schema and operations consumed by direct lowering and public API generation, with diagnostics referring to the same checked facts. |

These are responsibilities, not six new object hierarchies. Keep facts on the
existing structures where that is simpler. Do not infer presence, cardinality,
or authority from a printed TypeScript type. Do not infer permission to disclose
a read from the existence of a well-typed value.

Lowering must preserve once-only, left-to-right evaluation, including aliased
reads, insert results, branch conditions, and arguments later unused by an
elaboration. Fresh internal binders may differ; results, transactional changes,
read evidence, refusal ordering, and certified resource bounds may not silently
change. Type-correct input is still subject to Rust certification and runtime
authority checks. Compiler annotations are not trusted certificates.

Diagnostics continue to report independent errors at authored Quarry sites.
A failed statement must not contaminate later binding state or emit executable
artifacts. Preserve LLP 1002's recovery behavior, including suppression of
dependent cascades and independent checks after a failed declaration. Shared
facts should remove duplicated diagnosis, not reduce the useful error set.

## 4. Reconciliation and acceptance evidence

Start from the census already in the architecture record at `2cae5d9a2`:
11,788 compiler production/declaration lines removed, 4,125 added, net −7,663;
all 32 frozen repairs dispositioned as 27 CLOSED, 4 OUTSIDE-Q and 1 RETAIN,
with none pending. Those are attributed measurements of its specified snapshots,
not a new measurement here or an unqualified final-candidate claim. The later
record at `8bea2c347` reports 208 compiler checks passing at `fa4bd6aae`.

The deliverable is only the missing mapping or delta: old owner, candidate owner,
deleted production path, remaining consumer, and intentional semantic change.
Do not recount the existing census or reopen disposed repairs without changed
semantic inputs. Gross bypassed lines are not net savings; keep replacement
code, effect checking, diagnostics, generated API work and build dependencies
inside the relevant maintenance/loop comparison.

Use the existing compiler tests and shared Rust/twin corpus. Add only missing
behavioral witnesses uncovered by the mapping. The acceptance matrix covers:

- Valid composed programs: optional reads and narrowing, branch joins, shapes,
  pages through aliases, nominal references, decimal/money arithmetic, and
  bounded iteration produce matching types and executable behavior.
- Refusals: wrong-table references, missing presence, incompatible branches,
  unsupported/unbounded operations, and independent errors retain source sites
  and useful rewrites. No partial schema, program, or API artifact escapes.
- Evaluation: reads and writes are evaluated once in source order; early
  refusals roll back; Rust and twin agree on result, state, and required evidence.
- Boundaries: a real consumer of the built package receives the checked Quarry
  return shape, including negative type checks that reject invalid assignments;
  effects remain checked; direct IR still undergoes independent certification.

The [retained Expo consumer experiment](../benchmarks/runs/2026-09-06-clique-improvement/evidence/generated-api-consumer/REPORT.md)
shows why the consumer boundary matters: missing generated `Column` and
`RowOfColumns` imports yielded error-derived `any` under `skipLibCheck: true`.
A boolean row field accepted a number even though the printed outer result
looked plausible. An import-only counterfactual restored the tested type;
separate shipped declaration errors remained. Preserve that negative consumer
witness through direct lowering, using real package resolution and the relevant
customer configuration. A compiler-internal type, printed declaration, successful
positive assignment or `IsAny` assertion alone does not establish this property.

Compare source semantics, not generated text or incidental binder names. If an
old route is used as a temporary oracle, remove it from production and then
remove the comparison scaffolding when the candidate is qualified. Preserve
retained evidence of intentional semantic corrections instead of preserving an
incorrect old answer for parity.

The proposal is ready for acceptance when the mapping has no unexplained second
semantic owner, the focused matrix is green or has explicit scoped dispositions,
and the deletion/loop measurements show the intended simplification. Known
affected correctness failures must be fixed; unrelated historical failures are
reported separately. Completing this draft is not that acceptance.

## 5. Open decisions

1. Which checked facts still have two producers in the integrated candidate,
   and can the second producer be deleted without weakening diagnostics?
2. Which existing cases lack an independent semantic witness, especially
   presence joins, page provenance, and once-only evaluation?
3. Does the final compiler census demonstrate a simpler maintenance boundary
   after all replacements are counted? If not, reduce the design before adding
   another abstraction.

Resolve these against the architecture lane's actual integrated result. Do not
restart its migration or hold unrelated repairs for this draft's acceptance.
