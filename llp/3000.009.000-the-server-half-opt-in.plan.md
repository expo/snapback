## Summary

LLP 3000.009 added a server half to Snapback 4:

- actions;
- routes and webhooks;
- scheduled actions;
- managed identity;
- SQL reads and projections;
- Postgres.

Today the package puts all of it on the same default surface as the
local-first core, and the core cards carry its vocabulary.

This plan puts the server half behind one directive, `use server`, following
`use identity` and `use personas`. Without the directive, three things change:

- the server-half forms refuse, with a rewrite that adds the line;
- `guide` lists the core cards;
- the core cards teach the core.

With the directive, nothing changes.

The plan keeps the two constraints in LLP 3000.010 §7:

- service credentials stay on the core path, because Clique's effects need
  them;
- the capabilities stay integrated in one binary, one language and one
  release.

It leaves §14.7's post-Workroom retain/remove pass where it is.

This is a product change, not a score lever. The record holds one step that
happened while the guide grew (LLP 3000.010 §3), and one pre-registered
reduction that moved `setup_and_docs` (W14b, LLP 3000.007 §20.24). This plan
predicts no score effect either way.

## 1. The line

| Stays core, with no directive | Behind `use server` |
|---|---|
| Tables, rules, `sync`, retention, `expire at`, assets, search | Actions: declared results, the generated handler context, durable steps and their leases, parked-work dispositions |
| Maintains, and LLP 3000.007.003's derived forms | Routes and webhooks |
| Queries, mutations, helpers, shapes, merges | Scheduled actions: a schedule that names an action |
| `use identity` with guests and passwords; personas; presence | OIDC, trusted profiles, managed organizations and invitations, action-bound session minting |
| Jobs, chunks, and schedules of jobs | SQL reads, projections, database-owned tables |
| Effects (`effect`, `emit`); service seats (`token --service`); the worker's claim and settle; application-minted sessions (`mintSession`) | The Postgres store |

So schedules and jobs stay core, and so do effects. Actions move, and a
schedule that names an action moves with them.

Two things are left for the author to decide. Native jobs (LLP 3000.005) and
the witness verbs are neither core nor server half, and Clique uses neither.

## 2. Evidence

The evidence is LLP 3000.012 §2.6:

- By prefix, 43 of 151 diagnostic codes come from server-half families.
- `SERVER.md` is 46,564 B.
- The `actions` and `routes` cards total 25,397 B.
- Server-half forms appear in three core cards:
  - the language card's first sentence names routes, and its compiled program
    declares two actions and a route;
  - the app card's first line names actions;
  - the services card follows the service seats with action-bound session
    minting.
- Calibration #16's builder opened the services and effects cards for its push
  seam. It wrote no worker, imported neither `snapback4/worker` nor
  `snapback4/server`, and used no server-half form.

## 3. The mechanism

- **The directive.**
  - `use server` admits every form LLP 3000.009 added.
  - Managed identity may stay under `use identity`, as an `oidc` kind beside
    `guests` and `password`, if its forms stand apart from actions. Otherwise
    it moves with `use server`.
  - Without the directive, a server-half form refuses with one code, whose
    rewrite is the directive line. A builder who needs an action is then one
    step from it. The implementation chooses the code's spelling.
  - `why` explains every code, whether or not the directive is present.
- **The guide.** Bare `guide` lists the core cards, then one line naming the
  server cards and the directive. `guide actions` still answers.
- **The cards.**
  - The language and app cards list server-half forms only in a section headed
    by the directive.
  - The services card keeps service seats and application-minted sessions.
    Action-bound minting moves to the actions card or to `SERVER.md`.
  - Effects keep sharing the action step kernel in the implementation. The
    effects card continues to teach `emit`, claim, settle, retries and presence
    deferral, and links to `guide actions` only for settings the two share.
- **The package.**
  - `snapback4/worker` keeps effect claim and settle, `mintSession` and
    `revokeSessions`.
  - The action handler context lives under `snapback4/server`, which already
    exists.
  - The README's reference map keeps one row for the server half.
- **`init`.** The default, `--expo` and `--online` templates write no
  server-half file. A template that needs one writes the directive.
- **The binary.** Unchanged. This plan adds no cargo feature and no second
  package (§6).

## 4. Relationship to §14.7 and Workroom

The two are orthogonal:

- Workroom's application adds the directive.
- Whatever the post-Workroom pass removes leaves from behind the gate.
- Whatever it retains stays there.

The gate needs no Workroom result and can land first.

## 5. Sequence and acceptance

| Step | Work | Complete when |
|---|---|---|
| 1 | The directive and its refusal | every server-half form refuses without the directive and compiles with it, on both stores; the chat reference app compiles unchanged without it, as does calibration #16's backend, which uses no server-half form |
| 2 | The card edits (§3) | the guide suite passes, with every card compiling and `guide::CODES` complete; the docs budget (`scripts/docs-budget.mjs`) passes |
| 3 | The package exports and `init` | the package typecheck and the installed-consumer proof pass; Workroom's application builds with the directive, and its suites pass |
| 4 | Observation | in the next calibration's recorded lookups (`guide-*.txt`), the services card a Clique builder opens carries no action-lease text |

There is no score target. If `setup_and_docs` is read at all, it is read by
#15's rules.

## 6. Alternatives

| Alternative | Disposition |
|---|---|
| A separate npm package and a binary feature | A stronger boundary, with more publication machinery; revisit if the directive leaks |
| A documentation-only split | Leaves the forms, codes and generated types reachable with no signal |
| Removing the server half now | Would pre-empt §14.7; the author's call, not this plan's |
| A fence so builders "never learn it exists" | Withdrawn by LLP 3000.010 §7: it removed the service credentials Clique needs |
| Leaving things as they are | Leaves LLP 3000.010 §8.4's question open |
