# LLP 1006.002: Assets meet durable data at the column

**Type:** Decision
**Status:** Accepted (2026-09-08, under the user's delegated decision commission)

**Author:** Codex (GPT-6), commissioned by Charlie Cheever

## Context

The author commissioned assessing whether assets and ephemeral state should
look more like durable storage, documenting the conclusion, obtaining Grok
4.6 xhigh and Muse 1.3 xhigh sanity reviews, and implementing the chosen change.
LLP 1006 already covers the asset design. This short child records why that
boundary is retained; it does not propose another asset system.

## Decision

Keep the common path in ordinary typed mutations:

```ts
await sendPhoto.run({ conversationId, photo: file })
```

At asset-typed argument positions, the client uploads the bytes first and
substitutes the closed asset record. The ordinary mutation then validates and
claims it. Queries return that record. The owning row's read rule controls
future byte requests. Replacement, deletion and list shrink release custody
through the ordinary row mutation. A bounded list of assets is a bounded
list column. This follows LLP 1006 sections 1, 2, 6 and 7.

Keep explicit `client.upload` for progress and two-phase UX; `listUploads`
and `discardUpload` for the caller's unclaimed staging custody; and
`AssetImage`, `AssetVideo` and `useAssetUrl` for rendering and byte delivery.
They have distinct streaming, cancellation, ambiguous-outcome and garbage
collection behavior and should expose it honestly. Claimed-asset management
continues through row mutations, never a parallel asset CRUD surface.

No fake `query`/`mutation` wrapper, generic file store, asset collection API,
event channel or extra public method is introduced by this decision.

## Consequences

The data-shaped convenience call is not one atomic byte-and-row transaction:
upload completes before the mutation. Failed/ambiguous work may leave staging
custody, which the existing recovery methods expose. Releasing an asset ends
future authority through the old cell immediately but physical reclamation
has its separate lifecycle; cancellation cannot promise that no bytes arrived.
These are reasons to keep specialized recovery, not to redesign the column.

Open custody/GC correctness defects remain real work under LLP 1006 and their
existing tickets. This decision neither claims they are fixed nor makes them
prerequisites for the independent channel change. The implementation commission
changes channels (LLP 1001.000) and reconciles their docs; asset behavior remains
the existing typed-column design.
