## 1. Scope and motivation

Wave 10 fix-list #5, #7 and #15 expose disagreement between diagnostics and
execution: deliberate negative fixture tests look stale, one missing roster
produces many writer notes, and the recommended service-seat bootstrap fails
membership-grant validation. The coordinator authorizes this work and its
reviews. HS owns handshake/types, REL2 release lifecycle, DX2 starters/client
recipes, and PAGE2 general planner/rules expressiveness.

## 2. Service seats grant membership on the server

An entire positive branch `viewer = 'service:NAME'` with a nonempty name
satisfies the membership insert/update grant guard. The namespace is reserved:
accounts cannot mint it, and the operator mints a seat token against the
production store. This authority may enroll the first member or retarget a
mutable membership. An `and` branch containing that equality is likewise
restricted to the seat. An `or` requires every branch independently to prove
membership, a newly created group, or a seat. Negation, inequality, arbitrary
principal literals, and ordinary self-join remain insufficient.

Read-rule service grants already disappear before device audience inference
(LLP 3000.007 §20.6); this change adds no sync audience, capability or wire
format. Devices never hold service-seat partitions. Existing seat-session expiry and
revocation checks apply before a mutation is dispatched; no token lifecycle
changes are proposed. Only mintable service names (1–64 ASCII alphanumeric,
underscore or hyphen) qualify for production readiness; an impossible seat
keeps the root's N_NO_PRODUCTION_WRITER note rather than counting as a writer. Adding membership still
uses ordinary constraints, transactional logs and scope delivery/revocation.
An authenticated seat writes via an ordinary mutation, without system bypass.
The deploy card compiles a synced staff-roster example. The diagnostic's
inline recipe retains an already-online roster's residency and its entire
read predicate; references are resolved in the application's existing schema. Refused ordinary
self-join offers that trusted bootstrap beside the prior-member alternative,
without a redundant `(service and member) or member` rewrite. The offered
seat rule replaces the unsafe branch, never adds a seat to an otherwise
unprotected self-join.

## 4. Fixture intent and guard visibility

`check` inspects shared cases only for operations declared by the checked
schema. Signature/decoding/validation failures whose runtime code is E_INPUT
are intentional when `expect` equals E_INPUT, so emit no argument-drift note.
Malformed JSON/case metadata remain authoring errors. Unknown operations
remain a hard error in `test`, including misspellings; read-only `check`
intentionally cannot distinguish shared newer operations from misspellings.
Expectations are the existing public refusal code, without a new phase field;
the runner prints the E_INPUT message/subcause on each passing negative case
so a negative assertion is reviewable without introducing another note. Saved runtime values
remain unknown. The fixture runner recognizes decoding/signature errors as
E_INPUT too; tests cannot claim success by skipping the case.

A program `exists` sees only caller-readable rows; a table-rule probe has
authority over all rows. Keep those semantics. Add N_UNREADABLE_PROBE on
negative requirements and conditional guards over private populations unless
the pins/preceding guards prove readability. Positive `require exists` is
itself an authorization check; retain its existing N_REQUIRE_HIDDEN analysis.
To cover values later used through aliases/returned helper booleans, inspect
point-existence observations when they happen, as well as mutation/job prefix
observations. Pure query prefix/search/seek values remain ordinary visible-hit
answers; trace guard-consumed bindings through aliases/objects/possible rebinding
and check those observations with their original authority. Inputs to a
guard-consuming helper/shape are conservatively tracked too (all inputs,
rather than an unsound partial parameter-use proof), including direct expression
inputs and guarded loop domains. Row-dependent candidate filters remain intentional
visible-hit query predicates (global gates lower to whole-page conditionals
and are checked); a computed boolean field passed to a guard is
still an observation. Snapshot markers exclude names in every actual argument,
so postorder substitution cannot match a fabricated name in another argument.
Helpers/shapes reached from a requirement inspect every direct input value,
including helpers that only invert it in their returned expression. A direct
positive `require exists` remains authorization. Traverse requirement
wrappers (members, objects, calls and nested conditionals), preserving direct
positive-existence authorization. Inline shape bases are inspected independently
of named-definition discovery. Expand object/write shorthand in analysis copies
before classifying global facts, discovering effects, checking shadowing, or
excluding/substituting/validating argument names; shorthand and explicit names
must have the same scope and proof behavior. Runtime expressions stay unchanged.
Name the target read
rule and explain that negative guards cannot enforce global absence. This is
advisory; an intentionally caller-visible guard can remain unchanged.

Follow reachable helpers, named shapes and spreads. Facts cross helper scopes
only through actual arguments or viewer/literals, with fresh intermediate names
to prevent caller/formal spelling collisions. A read-only helper can receive
snapshot evidence for an expression argument; a writing helper gets only scalar
names. Successful ruled physical-row lookups prove their unambiguous indexed
row exists, omitting extra projected-field tests. Viewer has one meaning in
user text and compiler-generated recipes. Every extra read-rule equality must
resolve; none may be dropped. Never borrow a positional index's visibility
proof from another same-width index. An explicit computed/unknown index never
falls back to another index, and computed keys are not raw column pins.

Dominating facts are invalidated by writes, relevant binding changes or viewer
scope changes; an unanalysed control-flow path never proves authority. Follow
helper/shape effects conservatively through the call graph; cycles prove
nothing. Potentially writing loops cannot carry entry facts across backedges
or export prior role evidence. Binding-only loops invalidate potentially rebound
names at entry/exit, including break/continue paths. An in-loop readable guard
can reacquire proof each iteration. Inspect domain conditionals too. Before
inspecting a compound expression that may write, drop prior facts because a
later operand can observe the changed world. A standalone helper call with
non-writing arguments instead analyzes the helper's statements in order, then
drops caller evidence if it wrote. Stop at return/break/continue. Viewer scopes
inside jobs use caller reads and receive the note; surrounding system job
guards remain exempt. Use a unique/cap/final constraint for an invariant across
hidden rows; do not recommend making private rows public. Avoid duplicate notes
at one guard/target. This never changes execution or admission.

## 5. Refusals and usable rewrites

Invalid mixed positional/named bracket keys get a specific diagnostic before the
misleading id-type error. Name both consistent spellings, using source text
and the resolved key where available. For `!=` inside a probe, explain that
bracket tests are named equalities; use a pinned key with an external predicate
or a bounded program filter. Table rules remain unique point probes. Moving a test to a program filter
changes visibility to caller-readable rows; explain this explicitly.

A nullable upsert result must be checked with `! else CODE` before it supplies
a reference; `! else` refuses and rolls back the whole mutation when null; explain that the write may succeed while its resulting row is
unreadable. Keep upsert result semantics unchanged.

E_STRUCTURAL_FANOUT offers a point read by id and a publicly authorized
maintained aggregate beside the existing scoped scan/constraint/job choices.
E_JOB_CURSOR_INDEX leads with stable id order. E_SYNC never repeats an online
only edit already applied; for an inherited read-through conflict it names the
parent audience and copied-column alternative. A union parent ignores read-through children already marked `online only`
when finding a child that inherits its device audience; it names a synced child
and the copied-column alternative. This implements the existing online-only
repair without adding union capture/retention support. Every emitted concrete rewrite
is compiled against its input schema with zero errors, extending the wave-9
golden test. Advisory notes are permitted when the unchanged schema itself
already carries them; snippet guide blocks must remain note-free.

Fixture loading is operator-owned system work: preserve actual constraint
refusals, including named unique codes, rather than remapping to NOT_FOUND.
Attach table/constraint context in fixture-loader text. The same preservation applies to system-job upsert inserts: a system actor
has no hidden target, so its malformed image reports its constraint instead
of NOT_FOUND. Ordinary callers retain hidden-target/collision suppression. Readable unique conflicts return the
key's authored code when readable under the current caller at write time,
in the same transaction; hidden conflicts keep their non-disclosing answer.
Development traces name a failed read-through parent and viewer-hidden lookups
with the read-rule source. Public client refusals never disclose a hidden row
or the private clause. Do not introduce a public E_RULE variant that reveals
whether the parent exists.

## 7. Wave 11 diagnostic precision (QDIAG)

The nullable-reference lint counts a null value as needing no target lookup.
At `if arg != null`, only the null edge carries that exemption; a lookup on
the other edge must still dominate the write. Join by intersection and clear
facts on rebinding. This changes advisory output only.

Operation parameter defaults remain explicit: declare an optional parameter
and bind `value = arg ?? literal`. Refuse `= literal` with that exact idiom.
A multi-line `require` keeps `else CODE` on its closing line; the refusal names
that line and preserves the author's code. `?` precedes `on delete keep`.

Program absence checks on a row lookup (`t[key] = null`) use the unreadable
probe note too. Raw table-rule probes, including delete rules, still observe
all rows; the note's repair states that distinction. A later owner `require`
after `! else NOT_FOUND` gets a refusal-order note only when every read-rule
branch requires that same owner. A branch admitting staff or another party
can legitimately reach the custom refusal and keeps the note quiet.

A child-owner proof requires equality in every child insert branch, immutable
(or unupdatable) child owner/reference and parent owner, no maintained or
field-owned value, no opaque/job writer, no parent expiry (expiry fires no reference action), and no kept parent identity
that ordinary or cascading deletion could recreate,
and equal read rules after replacing
only that owner. No other row fields may appear in either rule. A successful
parent lookup (or a direct probe in its returned row projection) supplies the
parent-readable fact. This is advisory analysis of ordinary admitted writes;
trusted system seeds must preserve the declared application invariant. It never
changes read authority, admission or completeness.

## 8. Wave 11 contextual spellings and refusal codes (QDIAG amendment)

A required same-table row in a reference-typed column, point key, or operation
argument lowers to its `.id`. This includes an inserted snapshot and a looked-up
snapshot; it evaluates its expression once in source order, introduces no
lookup, and grants no existence or read authority. Shorthand fields get the same
projection. Cross-table rows and optional rows remain refused; an optional
upsert must be narrowed with `! else CODE` first. A generic `id` or `principal`
position does not implicitly project a row. Helper parameters retain their
existing call-site row specialization (LLP 3000.007 §5.2; the existing helper implementation specializes same-table rows at the call site): a helper called with
a row keeps its row fields, and one called with a reference must look it up.
Lists and objects receive no deep automatic projection. Explicit `.id` remains
valid. Generated API and runtime IR remain those of the explicit spelling.

Image and video bounds accept integer decimal byte units KB, MB and GB; 5MB
means 5,000,000 bytes. Overflow above u32 refuses at parsing. This is a constant
spelling, not a new value type, upload format, meter or protocol capability.

Readable secondary unique collisions with no authored `else CODE` now return
E_UNIQUE and name the declared key columns, never an internal planner index.
Authored codes still win. The intrinsic id conflict remains E_CONSTRAINT.
Hidden collisions retain E_RULE (and hidden write targets retain NOT_FOUND),
including their deliberately ambiguous public message: a rule denial, unreadable
key holder or physical authorization cut remain indistinguishable. The wording
says that a row you cannot read holds this key as one possible cause. Only the
developer-owned trace may identify the actual private clause. No new hidden
existence bit is exposed; this preserves LLP 3000 §7 and this RFC §5.

The engine/model/oracles preserve rollback, conflict order, null-key uniqueness,
if-absent behavior, device prediction and unchanged named refusal precedence.
Lean's visible secondary conflict code follows E_UNIQUE; explicit row projection
has the existing field semantics. Generated equivalent implicit/explicit sources,
Lean examples, simulator and both device stores exercise the projection and
unique conflict. Native and Lean fixed-seed runs must add no failure signatures.

A development-only check rejects an operation principal argument equal to a
bare declared persona (alice), naming dev:alice. Static principal column literals
get advisory N_PERSONA_PRINCIPAL. Production HTTP does not perform the dev argument check: arbitrary account
principals remain valid and personas confer no authority. The static note is
a compilation advisory whenever `use personas` declares the matching name,
including a production schema that retains its development cast. Developer query/test
output may count observed physical rows filtered by their read rules through
an opt-in collector, outside the wire envelope and durable receipts. It never
adds hidden counts to serve, browser responses, sync, the device or output data;
counts describe encountered rows, not the whole unreadable population.

Every service-seat E_RULE path, durable or ephemeral, for an ordinary table denial, hidden collision
or authorization exhaustion appends the same static authored table rule clause.
It never identifies which cause occurred, or copies row values. This fulfils
the seat explanation without relaxing hidden-collision ambiguity.

The independent Lean surface emitter projects known row-valued columns and
keys from its own source types. Unresolved reference expression types and row
helper specialization outside its fragment are named unsupported cases, never
accepted oracle cases: reference-expression-type and row-helper-snapshot.
The native/compiler and two-device witnesses still exercise row helper fields.

## 9. Wave 12 diagnostics and table-rule composition

### 9.1 Declaration safety and diagnostic fidelity

Quarry's binder-supplied expression inputs are reserved at every binding
declaration. `viewer`, `now`, `commit` and `new` cannot name an operation or
helper parameter, a local, or a loop variable. Refusal at the declaration is
E_QUARRY_RESERVED with a concrete rename. This is a front-end safety boundary:
the builtins keep their existing meaning and type, and no runtime lookup,
shadowing rule, IR operation or wire value changes. The reservation prevents a
valid-looking declaration from being ignored when expression binding resolves
one of these names intrinsically.

`use identity`, `use identity password` and `use identity guests` declare one
project-wide method set. A second declaration is E_QUARRY_SYNTAX at the later
site, whether it is in the same file or another file. The refusal names both
method sets and the first site. It never merges or replaces methods, so source
order and file order cannot silently change the authentication surface.

Diagnostics recognize two SQL habits without taking an ordinary language
name. `count table where predicate` says aggregates take parentheses and emits
`count(table where predicate)`. After project-wide named-shape resolution, an
unresolved trailing `desc` says `last N by .column` is already descending and
removes the suffix; a declared `shape desc` remains an ordinary shape. Tests
apply each emitted text to the diagnosed source and compile the result. When
no compatible declared key exists, a positional value whose static type is a
row/reference from another table leads with that mismatch (`secrets` cannot
key `rolls`) only if no relevant declared key accepts that table at the same
position; the repair names the declared position's expected type. Compatible
secondary keys and foreign values that fit their own composite-key position
retain ordinary ambiguity/type advice. A bad `search` field is a
fault of that field: retain the table and its valid columns in the diagnostic
catalog, omit only the unusable search entry, and avoid cascading unknown-table
errors. This recovery affects rejected-source diagnostics only.

A concrete named-update source rewrite always binds both `old` and `next`.
When the rejected unnamed rule already says `old.field`, preserve it; map a
bare `.field` in that same rule to `next.field`, while field-looking text in
string literals remains unchanged. The golden catalogue applies the whole
rewrite and recompiles, including these mixed-image cases. A
multi-line `require` lookup skips layout tokens when finding its following
`else CODE`, so its one-line repair keeps the author's exact code.

E_STRUCTURAL_FANOUT leads with a direct `.principalColumn = viewer` predicate
when the refused scan is nonuniform and one read-rule disjunct makes that the
smallest qualifying repair. Uniform expiry-specific refusals retain their
expiry repair. The
heavier point, maintained-total and constraint designs remain after it.
N_UNREADABLE_PROBE names a prior positive, dominating readable dependency on
the require/read path when one exists and states when implication is still
unproved; negated or disjunctive existence does not qualify. Fixture
argument drift is silent for every authored refusal expectation: a concrete
code and the generic `denied`, `refused` and `failed` forms may intentionally
carry invalid arguments. Malformed case structure and non-refusal expectations
still receive N_FIXTURE_ARGUMENT_DRIFT. The sweep summary calls derived
require failures "probe refusals on derived arguments (expected)".

A maintain may record an intentional aggregate delta channel with
`disclosure reviewed 'rationale'`. The rationale must be nonempty, changes no
read/write authority or runtime schema, and suppresses N_MAINTAIN_DELTA only
for that maintain. Without it, the note offers the annotation alongside the
existing restriction choices. N_DELETE_RESTRICTED points directly to the
`On delete restrict` guide section, which distinguishes keep, cascade, set-null
and restrict behavior across multi-level chains.

Acceptance covers each declaration entry, same-file and cross-file identity,
both SQL repairs, cross-table keys, invalid-search recovery, mixed old/next
rewrites, multi-line refusal codes, direct viewer advice, require/read context,
reviewed disclosure, every refusal expectation, derived-refusal output and the
delete-guide pointer. These changes preserve execution, authorization,
admission, completeness, storage and protocol semantics.

### 9.2 Table-rule composition and dead nullable lookups (RULES2)

This amendment adds advisory contradiction proofs, not authority or a new
admission gate. N_WRITE_DENIED covers an update or the update arm of an upsert
whose rule contradicts the preceding mutation require/branch conditions.
N_LOOKUP_NEVER_VISIBLE covers a nullable unique point lookup whose read rule
contradicts those conditions: null is the only result and its non-null branch
cannot execute. A failed asserted lookup remains governed by the existing
refusal-order notes. Jobs are exempt.

The proof fragment is equality/inequality of viewer, typed literals, scalar
aliases, uniquely addressed row fields and old/next images, with boolean
composition. Unnamed update rules must hold for both images; named rules bind
the images explicitly. Unknown expressions are overapproximations. Program
probes are caller-filtered reads and cannot be equated with table-rule probes;
absence of a role check never proves absence of that role. Different owners,
roles and memberships can coincide. Enumerate at most 64 alternatives; larger
formulas prove nothing. Only a satisfiable gate with an unsatisfiable
intersection emits a note. This deliberately makes no whole-language completeness
claim. Read-through, maintained lookups, field-owned patches, spreads and
ambiguous keys stay quiet.

Facts are local to statement order and branch paths. Clear all row/scalar
snapshot evidence after a write or opaque call, before compound effects,
after branches/rebinding and across loop/viewer scopes. Requirements after a
write cannot justify a note on that earlier write. Follow no opaque helpers:
this is a safe underapproximation of note reach, never a guess about effects.
Notes use source schema facts only; they add no hidden-row wire information.

Qualification: compiled guide snippets and engine execution test every recipe;
positive contradiction and negative overlap/unknown/invalidation witnesses test
the notes. Run check on read-only copies of all 100 wave-12 final schemas
before and after, report deltas by code and inspect each new firing before
claiming precision. No runtime, planner, sync, expiry, protocol or adoption
semantics change; existing simulator/device/difftest suites verify that boundary.
Fresh mutually blind Muse and Codex reviews cover this amendment and the
recipe/open-decision amendment in LLP 3000.036 §22.

Nullable lookup snapshots supply no physical field facts; only asserted
successful lookups supply them. A uniformly denied page is complete and empty;
a nonuniform scan can remain partial even when it returns no visible rows.
The testing pointer names this distinction instead of falsely promising that
physical exhaustion certifies every partly readable population. This is the
existing completeness law, not a new planner behavior.

Numeric literal terms use the binder's canonical integer value, not token
spelling (`01` and `1` are equal). Calls/writes in an if condition invalidate
entry evidence before either branch; branch-body effects alone do not erase
otherwise valid entry proofs. Regression witnesses cover an effectful condition
that changes owner before an admitted body update, and equal numeric spellings.

Named/inline shape evaluation, merge projections and object spreads are opaque effect boundaries,
including in if conditions. Their definitions can contain writing helpers;
walking only a shape's base cannot certify it read-only. Clear all entry facts
before evaluation and retain none afterwards; do not borrow stale snapshots
through a named shape or spread. Pure shapes may therefore lose note reach.

## 10. Wave 13 LANG2: bounded reads and source-level diagnostics

Commissioned by Charlie Cheever on 2026-10-16 for 0.4.30. This amendment
also amends LLP 3000.036.001 §18 and LLP 3000.039 §2's unconditional cap
requirement. RULES3 owns authorization recipes and refusal-layer prose;
LANG2 owns the completeness and language changes here.

**Point membership lanes.** A lane fixing a total unique key reads at most
one row. Other equalities filter that point; they never widen its identity
key. Authorization pins needed by a covering-index certificate remain in its prefix; that covering scan is still bounded to one row. The containing merge owns ordering, direction, deduplication and cursor.
A compiler-generated read must not be diagnosed as authored source: decline
an unplannable expansion or report the original query and its actual limits.
No generated identifier is a suggested edit.

**Reachable delete bounds.** An unbounded cascade or set-null edge is legal
when its parent cannot be deleted by any admitting (non-`deny`) delete rule, authored
program/helper delete, expiry (including inherited expiry), or a cascade
reachable from one of those sources. Each dormant unbounded edge receives N_CASCADE_DORMANT at its reference-column site; adding a cap silences it. Adding a
source rechecks the whole reachable action graph. Core schema validation checks
schema sources; program admission independently checks every IR delete,
including system jobs and externally supplied programs. Runtime deletion still
requires its complete prepaid reservation, so an operator API cannot turn a
dormant action into an unmetered write. There is no erasure declaration in the
current product; a future erasure entry point must obey that same admission.
Cycles and ineligible action targets are refused even while dormant. Structural graph traversal proves cycles; an unavailable transitive reservation can mean an uncapped dormant descendant and never by itself proves a cycle. Caps
remain hard product constraints, checked on adoption and writes. The rewrite
names a jointly fitting engine maximum as a ceiling, not a recommended product
limit, and gives the actual heap decomposition: root write heap + retained event images + 384 × (cascade identities + 1 root + 4 child-id slots + largest set-null group) + max(child write heap, four-row child page, read-through probe scratch). This is the conservative diagnostic sum computed by delete_total_reservation.

**Immutable patches (P18 coordinator revision, 2026-10-16).** Update and
upsert's conflict arm retain runtime equality: supplying an immutable value
is legal when it equals storage. Uncertainty must never become an upgrade
refusal. Analysis has three outcomes, after spread expansion:

- **Equal, quiet:** the value equals its pinned target-key component, comes
  from a current snapshot of that exact target, or equals the value of an
  unconditional successful insert of that exact identity earlier in this
  transaction, with no intervening write or uncertain control flow.
- **Changing, E_QUARRY_IMMUTABLE:** a supplied literal (including checked
  integer constant arithmetic) differs from the pinned key or the exact
  preceding insert's value; distinct minted-id captures differ; an unconsumed
  newly minted id cannot equal existing storage. Per the coordinator's clock
  ruling, a fresh `now`/read-clock value (including a constant offset) on an immutable time column is a
  refusal: it cannot preserve the original creation time on later conflicts.
  Equal local-insert/key proofs take precedence, including a timestamp reused
  within the same invocation. If a prior write could already have stored this
  invocation's clock, the conservative outcome is a note. This is a repeat-conflict diagnostic for clocks,
  not a claim that millisecond equality on one invocation is impossible.
- **Uncertain, N_IMMUTABLE_PATCH:** all remaining values, including `viewer`,
  arguments, literals without a storage invariant, stale snapshots and opaque
  control flow. The note names the column and runtime equality requirement;
  a viewer patch explains that the viewer must be the original author/owner.
  Keep the patch when that equality guard is intended. Otherwise omit the
  field from updates and branch on a readable point to insert initial values.

Pinned key components are resolved independently; an opaque sibling does not
erase a known equality or mismatch. Whole-identity proofs still need every
component. Write history conservatively spans branches, loops and expanded
helpers: losing an enclosing body never makes a possibly stored clock fresh.
Clock freshness alone never refuses inside loops or helpers called in loops:
a preceding iteration may have stored the same invocation clock. Guards or
storage-dependent/opaque setup can also constrain it to storage. Fresh-clock
refusals therefore require top-level, unguarded, scalar straight-line setup;
helper/block callers without that context receive notes. Without a proof
excluding clock reuse the outcome is a note. Zero addition/subtraction is
normalized before equality and clock checks, including exact snapshots.
Volatile captures retain binding and assignment-version identity. Compound
operands and snapshot keys resolve in their capture-time environment. Scalar
captures survive writes; storage snapshots cannot prove current values across
writes, unanalysed branches or loops. Freshness is not inferred once a write
could have consumed the minted id. Only unconditional inserts establish local
storage facts, resolved per field so an opaque mutable sibling cannot erase
a known identity or immutable value: `if absent`, an upsert's insert arm and unrelated source writers
cannot prove that a pre-existing row has their literal value. Historical,
seeded and adopted rows need not have been created by today's source. Until a
schema-enforced invariant proves otherwise, those cases receive the note.
The binder never silently discards fields. The hidden-target exception in
LLP 3000.007 §17 is unchanged: unreadable targets ignore immutable patch fields
without comparing hidden values; readable runtime mismatches still refuse.
An ordinary caller writing a table with an unconditional `read <- deny`
receives a note even for a fresh clock/id or proven mismatch: immutable fields
are ignored there. Jobs bypass that read rule and retain the refusal. Notes
state the equality requirement for readable targets, not a hidden comparison.
No native runtime, wire, device capability or wasm semantic change accompanies this
source-diagnostic revision. The Lean surface emitter now carries immutable
columns; its update model strips hidden immutable fields and checks readable
equality. The generated P18 campaign covers same/different owners, hidden
