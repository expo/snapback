## Context pack

Scope: SEC11 item 9, production `check --review` and `deploy`; gate inference
belongs to SEC11b. LLP 3000.036.004.000 §13 governs current executable witnesses,
canonical decisions and fixed work. LLP 3000.036.004.001 governs advisory replay,
committed-state judgment and delivered payloads. LLP 3000.037.000 §1 requires
witnessed questions on the default verdict. These implemented amendments extend
the security RFC in `llp/current/`; their precise eligibility remains unchanged.
LLP 0189's Snapback 4 affected selection and LLP 0232 govern verification and
integration. No new gate, domain inference or runtime permission is proposed.

The retained SEC11 production measurement missed both targets: p90 review
25.14 seconds and deploy 32.83 seconds. Initial phase traces on the slowest
wave30 schema show replay dominates binding: under concurrent survey load,
review spends 44.5 seconds in its advisory campaign and 24.7 in its derived
report, versus 0.06 binding and 0.78 constructing candidates. A syscall profile
shows roughly 208,000 opens and 191,000 file-copy calls, with one exec. These
loaded profiles attribute work; they do not qualify the latency targets.

## Exact work reuse

A production deploy's current 3,072-work report can supply derived evidence to
its own witness collector. Previously the collector reran that same report.
Only the report just computed in this invocation, for the same selected sources,
fixtures, options and unreviewed obligations, is eligible. Non-strict staging's
512-work report is ineligible; its collector still obtains the separate
production report. Existing source and decision race checks remain before
activation. No saved report, advisory file or cross-process cache supplies gate
or authored-refutation authority. Current gate evidence still replays.

Compile proposed question declarations in one ordinary compiler invocation.
Each is its own document at line one of `$dx11-question.q`, preserving expression
sites, operation resolution and canonical hashed candidate sites. Keep original
proposal ordering and duplicate occurrences after compilation. If the batch has
any diagnostic or an unexpected declaration count, use the original independent
compiler for every distinct line. No invalid declaration may suppress another
question. This changes compilation work, never eligibility, phase work or search
order. Both valid and mixed valid/invalid cases compare complete serialized
invariants against independent compilation.

## Independent campaigns

The gate, advisory and additional derived-report searches have independent fixed
work budgets and top-level replay-ID scopes. Run at most these three searches
in scoped threads, join every result, and reduce gates then advice in the same
order as before. Each search retains its complete internal order and work. No
first-finisher selection, shared budget, elapsed cut or parallelization inside
a state-dependent search is allowed. Live-only observed payloads remain live
through the joins. Production deploy may predict the static note vector and
run its current enforcement report alongside the independent question searches.
The pending evidence is an opaque type: it can finish only by matching the
actual report's complete note vector and applying that current report's derived
witnesses. A mismatch discards it and reruns collection against the actual report.
No predicted verdict enters dispositions or enforcement. Existing source and
individual-decision checks still run after joining. Production report reuse
still applies; non-strict staging
retains the additional production report.

## Fixture construction

Back up a fixture's SQLite database into a blank connection before preparing it.
The previous construction initialized the complete empty store schema and then
immediately overwrote it with that backup. The copied database receives the ordinary QPSG connection configuration;
its already-captured source metadata is copied without another catalog/identity
discovery pass. Detect copied read-session storage with the same query as the
original fork. Preserve the source's captured
catalog, activation identity, memory accounting page size and server mode. Keep a distinct ephemeral asset directory. Ordinary forks independently copy
asset files; opted-in campaign byte snapshots are described below. The copied snapshot is not re-admitted, just as the original backup-based
fork did not re-admit it. No hard links, shared mutable ledgers, synthesized
rows or host-dependent search cut are introduced.

The engine's existing fixture fork continues to retain schema, programs, clocks,
expiry, assets, ownership and ephemeral state. Supplied replay-ID scopes, every
work reservation and counterexample selection order remain unchanged. This is
construction of the same isolated world, not a store-format or planner change.

## Campaign byte snapshots

Profiling found up to 8,300 fixture forks per slow review; immutable asset file
copies dominate the remaining fork cost. Private campaign stores can retain
actual verified bytes as immutable `Arc` snapshots instead of repeatedly copying
those bytes into a new directory for every world. Ledger, rows, owner, home,
release, views and quota state still use independent SQLite backups. This cache
supplies no admission fact or decision: every actual upload and ordinary engine
call still executes, including sniffing, byte limits, ownership and placement.

Only `memory_for_campaign` opts in. Fixture observer entry may capture an owned
copy of an ordinary trusted fixture; a failed capture uses the original ordinary
fixture without changing coverage or search work. Ordinary application stores and
ordinary fixture forks retain their existing file behavior. Successful upload
publication captures its actual file bytes, then removes that private file when
possible. Failed reads, cache limits or failed unlinks retain ordinary file work.
The cache holds at most 32 MiB of byte contents and 65,536 entries per snapshot;
limits are representation fallbacks, never search cuts or changed verdicts.

Each fork has its own cache handle and file directory, sharing only immutable
byte vectors. New uploads use copy-on-write maps. Independently owned files,
including materialized or uncached files, still copy normally. After actual
asset authorization, delivery materializes a private file on demand. Denied,
released and forgotten assets cannot materialize bytes; a peer's new upload or
sweep cannot change another world's ledger or bytes. No hard links or borrowed
mutable source directories are used. Empty worlds retain verified byte snapshots
while resetting placement through the existing ledger operation.

Regressions cover source-drop and materialized-file isolation, ownership,
independent sweep/new-upload state, fresh placement, and over-limit fallback.
This adds no blob support to Postgres and changes no durable format, published
client/backend payload, public deployment cache or production asset policy.

## Measurement and qualification

`SNAPBACK4_LATENCY_TRACE` optionally names a separate JSONL destination for phase
and fixture-copy timings. Events are buffered in memory; sink I/O occurs only after command completion.
On the supported Unix hosts only regular, non-symlink files are accepted, opened without blocking on FIFOs.
Timings never enter verdicts, work selection, proof or cache keys.

Use the shipped `--profile production` build with the publication SQLite flag.
Profile the twenty slowest retained wave30 schemas, then measure all fifty
schemas with one worker and independent fresh source/fixture copies per review
and production deploy. Report p50/p90/max, executable digest, host load and
cold/warm status. Concurrent survey measurements are not unloaded latency claims.
Targets remain review p90 <10 seconds and production deploy p90 <15 seconds.

Run all 800 schemas from the declared SEC10/11 survey (waves 15,16,18–30), before
and after, including fresh production deployment and deployment after `test`.
Apply the existing classifier and compare canonical JSON bytes of all gates,
questions, witness values/decision IDs, FIX identities, refusal and test exits.
Whole measurement/display transcript fields are excluded; no scalar in a
selected decision field is scrubbed or normalized. Capture complete authored, derived and enforced
counterexamples separately for the union of schemas where either classifier
observes any FIX, and compare those payloads too. Raw supplemental captures stay
private; the report retains literal hashes and comparison results. An unchanged
baseline already differs in host-random uploaded-asset IDs. The supplemental
comparison uses compiler-derived asset column/argument types to discover those
nominal IDs, then gives only them injective ordered aliases throughout the typed
payload. Preserve all asset facts, alias/equality edges, application row IDs,
opaque strings, callers, arguments and history. Capture both raw and canonical
hashes; never describe these raw nonce-bearing payloads as literally identical.
Classifier decision/witness bytes still receive no scalar normalization. Report every difference and
any tool failure explicitly. Retain the measured source/digest and exact scope
of affected checks, source reviews and integration changes in the workstream
report. A missed target remains a miss, not a reason to reduce search coverage.
