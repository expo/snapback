## 1. Commission and governing constraints

Lane GS is commissioned to reproduce calibration #23's global search, account
for its heap, design a bounded plan before implementation, and stop at that
design if satisfying it needs a decision beyond the brief. This RFC is that
handoff, not an implemented feature or a claim that global search is fixed.

The commission supplies the concrete application need that was absent when
windowed search was shelved. The old shelving is **not** an approval veto on
this new work. Its unresolved counterexamples remain relevant:

- LLP 3000.007.000 §§2–4: a globally ordered emission needs every lane head
  established; an opening cut has no safe last-emitted-row continuation.
- LLP 3000.015 §§1–2: unreadable candidates and physical authorization work
  cannot become caller-visible rows, ordering keys or actual-size charges.
- LLP 3000.007 §20.22.5: an expired source frontier, a moving membership and
  an intra-scope word boundary defeated the previous stateless window design.
- `cursor.rs`: existing cursors encode a position, have at most 4,096 decoded
  bytes and are not authenticated search-work checkpoints.
- `meter.rs`: 8,192 examined rows, 16,384 index entries, 16 MiB heap,
  1 MiB output, 1,000,000 steps. No ceiling changes are proposed.
- `NOT-DOING.md`: no per-query result cache; no byte-priced check-time
  certificate. A new durable search session would need an explicit exception.

## 2. Reproduction changes the diagnosis

The baseline is `origin/main` at `54099bc882c529713f6e6204c5f51181f696a8ef`,
version 0.4.4. The local `main` ref is stale; this is the supplied lane's
unmodified main-source starting point. Only copies of the supplied SQLite
database and WAL are opened. Source hashes and exact measurements are in
`snapback4/reports/20260927-gs-global-search/`.

The recovered original read is `messages where not .tombstone matching q
last 20 by .at after c`, with profile/chat/peer decoration. On the final store,
it reproduces the diagnostic **exactly**: `[]`, incomplete, no cut, no next;
examined 1, heap 36, index entries 33, probes 55, steps 23, output 12.

This is **not** a 32-word overflow. `word_cut_at` is absent. In the global
coffee index, 44,100 newer entries belong to conversations the measured viewer
cannot read. `authorized_candidate` exhausts the shared physical authorization
walk before its first descending visible hit. `prepaid_scan` restores the
caller ledger; the caller's examined 1 is its fixed page reservation.
`non_uniform` makes completeness false and withholds a merged continuation.
Publishing the last hidden key would weaken the disclosure boundary.

The supplied final program already changed peer decoration: `searchPeers`
returns no peers for a group. Its page costs 907,738 heap bytes and 25,711
output bytes. Reconstructing the diagnostic-era unconditional peer shape
recovers 2,142 examined, 10,985,983 heap and 520,591 output, within 105/40 bytes
of the earlier checkpoint's heap/output. Both return 20 complete hits and a
working next page. The final store is not that earlier checkpoint.

The bare membership merge costs 554,978 heap and 8,251 output on this store.
It discovers **100 memberships** for u0500, not the corpus's 1,002 conversations.
The old decoration repeats 49 peer profiles for each of 20 messages. The
telescoping shape measurements in the report account for the entire heap:
bare 554,978; sender addition 179,990; chat addition after sender 80,780;
unconditional peers addition after both 10,170,235. Small differences between
isolated additions reflect shared collector overhead and diagnostic site names.

The existing uniform implementation is already a lazy merge. It still
materializes the membership source and retains descriptors/heads per matching
**word**, including full candidate row images. Returned shapes run only after
the selected page. Moving those shapes later would not fix this incident:
they are already later. `word_heap.rs` is an allocation allowance ledger,
with some scratch scopes released; it is neither resident RSS nor a count of
the final retained heads alone.

## 3. Proposed bounded access plan

Keep the existing authoring form:

```text
messages matching q where not .tombstone and exists members[.conversation, viewer]
  last 20 by .at after c
```

1. Discover authorized membership keys incrementally. Keep compact scope and
   progress keys, not complete membership rows or cloned expression trees.
2. Give each admitted membership a bounded cursor and at most one authorized
   head `(at, id)`. Fetch only the fields needed to authorize, test expiry and
   remaining terms, and establish that head. Keep payload/shape materialization
   on the emitted page. Preserve every source table's rule independently.
3. Merge established heads by the existing `(at, id)` order; deduplicate before
   counting emissions. Retain the current stop-on-failed-refill rule and the
   returned-shape rewind behavior.
4. Bound the inner word search too. A prefix can match arbitrarily many words
   **within one membership**. Merely wrapping today's `Vec<PreparedLane>` in
   a per-membership cursor hides, rather than removes, its growth. An inner
   cursor must either retain resumable search work outside the response or
   rescan words with a bounded best-head accumulator, charging repeated work.
   No new prefix-expanded index, unmetered scan or fixed word cap is implied.
5. Charge membership, index, head, decoder, retained state and emitted-shape
   work before allocation/access. Releasing transient scratch is valid only
   after all owners are dropped. Do not reduce ledger charges to make a number
   fit without the corresponding lifetime change.

Steps 1–3 reduce memory but **do not** satisfy the commissioned 10,000-membership
case. Discovery alone exceeds the 8,192 examined ceiling. Continuing an opening
phase is part of the algorithm, not an optional optimization.

## 4. Concrete counterexamples to an ordinary cursor

### 4.1 An unopened chat owns the newest message

There are 10,000 readable memberships, one matching message each. The first
8,192 scopes in membership order have timestamps 1–8,192; scope 10,000 has
timestamp 1,000,000. After discovering a prefix, emitting its newest rows and
continuing after that emitted timestamp either drops the actual newest row or
appends it after older rows. Returning no rows and the same ordinary position
restarts the same discovery and never progresses. This holds on an immutable
store, independently of heap optimization.

A resumable discovery cursor therefore needs **unemitted work**, not just an
output-order boundary. Ten thousand independent 26-byte row ids alone occupy
260,000 bytes before times, scope keys and encoding, far above today's 4 KiB
token. A top-20 accumulator can be smaller, but changes the algorithm to a
multi-request selection pass, not resumption of the full k-way frontier.

### 4.2 Saved heads cease to be authorized

Request A records a head from chat X, without emitting it, then cuts during
discovery. X's membership is removed before B. A token containing its saved
row cannot authorize emission, shaping, counts or ordering in B. Re-read and
re-authorize it first. If that removes the saved winner, B also needs the
unretained alternatives from earlier scopes; blindly selecting the next saved
winner does not recover a correct full page. A row edit that changes matching
or order creates the same need without a membership change.

Pinning an old snapshot alone is insufficient: it must not restore revoked
authority. A correct snapshot design must separately state current-authority
checks and invalidation/recomputation behavior.

### 4.3 Progress is not always a disclosed row position

Consider an expiring membership source with more than a read's allowance of
expired source rows before its first live membership, or a fixed word scope
whose discovery cuts inside its word expansion. There is no last emitted
message and possibly no live source-row frontier. Serializing a hidden or
expired key as an ordinary cursor invents a disclosure channel; retrying the
last visible boundary can repeat forever. The same representation problem
already underlies the measured original query's denied-row run.

This needs an explicitly authorized opaque work-state mechanism, an access
structure that avoids the hidden run, or a narrowed progress claim. It cannot
be fixed by setting `next` whenever `complete` is false.

## 5. Decision required before implementation

The brief authorizes designing a search plan, but does not choose a new
multi-request consistency/state-lifetime contract. The existing ordinary
cursor plus a leaner heap cannot provide the requested guarantee. The safe
handoff is a choice between:

1. **A retained search-work session.** Keep discovery and word frontiers in
   bounded engine-owned state; return an opaque, viewer/query/generation-bound
   handle. Decide snapshot versus revision invalidation, current authorization
   on resume, expiry, per-viewer/global admission, crash/restart behavior,
   cleanup, and equivalent native/wasm handling. Durable state must be charged
   as writes; volatile state cannot promise restart-surviving continuations.
   This also needs an explicit exception to the no-query-cache exclusion.
2. **A stateless multi-pass selection protocol.** Carry a bounded accumulator
   and discovery frontier, returning empty progress pages until global
   selection finishes. Decide authenticated/confidential work-token encoding,
   token size, revision binding and invalidation, reauthorization of saved
   winners, handling of a single over-budget scope, and whether repeated
   membership/word passes and restart-on-change meet the product's latency
   and “working next” requirements. Never claim this is today's live cursor.

Recommendation: choose the consistency and resume-lifetime contract first,
then compare these two mechanisms against it. Do not silently add durable
query state, raise cursor/meter budgets, leak a physical frontier, or promise
snapshot semantics from today's live reads. The implementation is stopped
here under the lane brief's explicit stopping condition. The measurements
are baseline evidence, not qualification of either proposed design.

## 6. Certificate and guide after the decision

The current certificate honestly says the membership/word work grows, but does
not distinguish resumable drain work from unresumable opening work. The next
implementation should classify unscoped non-uniform search, membership opening,
inner word expansion and returned shapes separately, with a code/site/rewrite.
The rewrite for non-uniform all-chat search is the explicit membership form;
the rewrite for excessive decoration is a bare hit page and separate detail
reads. Neither rewrite proves arbitrary global opening fits.

The compiler must report a structural continuation/completeness class, not
pretend to predict corpus byte costs. Only the implementation of the selected
protocol can earn a resumable-at-scale class. Add every new code to `guide::CODES`
and `why`, test the whole guide, then shorten `search_all` to the selected
contract and measured envelope. No certificate, diagnostic or card has been
changed by this research handoff.

## 7. Required implementation evidence

After §5 is decided: the calibration copy; 1,000/3,000/10,000 memberships;
one/many words per membership; dense/sparse/further-term misses; denied and
expired runs; ties; edits/removal/rejoin during opening and drain; forged,
cross-viewer, cross-query and stale-generation tokens; heap, step, output and
physical-authorization cuts at every phase; crash/resume behavior on each host.
Every partial page must either make the chosen protocol's defined progress or
produce its explicit invalidation/refusal—never silently claim resumability.
Measure p50/p95 and every meter, and distinguish an invocation's completion
from accumulated `usePage` completeness. No budget is raised.
